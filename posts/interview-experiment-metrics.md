지훈은 실험 결과를 들고 회의에 들어가, 새 모델이 CTR을 3% 올렸다고 보고했다. 팀장이 물었다. "며칠 돌렸어요?"

"이틀이요. 어제 봤을 때 유의하게 나와서 멈췄습니다." 팀장의 표정이 굳었는데, 지훈은 왜 굳었는지 몰랐다.

**실험을 언제 멈춰야 하는지는 무엇이 정할까?**

시작하기 전에 정해 둬야 한다. 결과를 보고 멈추면 그 순간 실험이 실험이 아니게 된다. 이 글은 광고 ML 면접에서 반복되는 실험·측정 질문 스물네 개를 모아, 왜 그런지를 실행되는 코드로 확인한다.

> **한 줄 요약:** 실험 질문의 절반은 "언제 멈추나"이고 나머지 절반은 "이 숫자를 믿어도 되나"다. 매일 보다가 유의할 때 멈추면, 실제 차이가 0인데도 다섯 번 중 한 번은 "차이 있다"가 나온다.

> **골라 읽는 법** — 절이 열 개이고 절마다 질문 두세 개가 있습니다.
>
> - 실험 설계(며칠·몇 건) → 첫째~셋째 절
> - 결과를 잘못 읽는 세 가지 → 넷째~여섯째 절
> - 무엇을 지표로 삼나 → 일곱째·여덟째 절
> - 어트리뷰션과 증분 → 아홉째 절
> - 지표를 못 올릴 때 → 마지막 절

## 1. "며칠 돌려야 하나"는 사실 "몇 건 모아야 하나"다

**Q. A/B 테스트를 며칠 돌려야 하나요?**

날짜로 답하면 안 된다. **필요한 표본 수를 먼저 구하고, 그것을 하루 트래픽으로 나누면 날짜가 나온다.**

필요한 표본 수는 세 가지로 정해진다. 기준 지표가 얼마인지, 얼마나 작은 차이까지 잡고 싶은지, 그리고 얼마나 확신하고 싶은지다.

```python
import math

def 표본수(기준율, 상대개선, 유의수준=0.05, 검정력=0.8):
    z_a = 1.959963985                       # 양측 5%
    z_b = 0.8416212336                      # 검정력 80%
    p1 = 기준율
    p2 = 기준율 * (1 + 상대개선)
    p_bar = (p1 + p2) / 2
    분자 = (z_a * math.sqrt(2 * p_bar * (1 - p_bar)) + z_b * math.sqrt(p1*(1-p1) + p2*(1-p2))) ** 2
    return math.ceil(분자 / (p2 - p1) ** 2)

일일노출 = 2_000_000
print(f"한 쪽에 필요한 노출 수 (유의수준 5% · 검정력 80%)")
print(f"{'기준 CTR':>10}{'+1%':>14}{'+3%':>14}{'+5%':>14}{'+10%':>14}")
for 기준 in (0.002, 0.01, 0.05):
    칸 = "".join(f"{표본수(기준, d):>14,}" for d in (0.01, 0.03, 0.05, 0.10))
    print(f"{기준:>10.1%}{칸}")

print(f"\n하루 노출 {일일노출:,}건을 반씩 나눠 쓴다면 (한 쪽 {일일노출//2:,}건/일)")
print(f"{'기준 CTR':>10}{'+1%':>12}{'+3%':>12}{'+5%':>12}{'+10%':>12}")
for 기준 in (0.002, 0.01, 0.05):
    칸 = "".join(f"{표본수(기준, d)/(일일노출/2):>11.1f}일" for d in (0.01, 0.03, 0.05, 0.10))
    print(f"{기준:>10.1%}{칸}")
```

**둘째, 잡고 싶은 차이가 절반이 되면 필요한 표본은 네 배가 된다.** 3% 개선에 8.8일이던 것이 1% 개선에서는 78.7일이 된다. 이 비례 관계를 알고 있으면 "1% 개선을 잡고 싶다"는 요구가 얼마나 비싼지 즉시 답할 수 있다.

**핵심 문장 — "며칠이 아니라 몇 건인지로 답해야 합니다. 지금 CTR과 잡고 싶은 개선폭을 알려 주시면 계산해 드리겠습니다."**

:::deep 기간을 줄이는 방법 — 실험 전 데이터를 쓴다

79일이 필요하다는 답을 받으면 대체로 "더 짧게 안 되나요"가 돌아오는데, 방법이 있기는 하다.

필요한 표본이 큰 이유는 지표가 들쭉날쭉하기 때문이다. 사용자마다 원래 씀씀이가 다르면, 실험 효과보다 그 개인차가 훨씬 크게 나온다. 그런데 **개인차는 실험 전 데이터에서 이미 알 수 있다.**

그러니 실험 전 지출로 설명되는 부분을 미리 빼고 비교하면 되고, 이 방법을 CUPED라 부른다.

```python
import random, statistics

random.seed(5)
N = 20_000
효과 = 0.03                                  # 실험군이 3% 더 쓴다

# 사용자마다 원래 씀씀이가 다르다. 실험 전 지출과 실험 중 지출은 상관이 높다.
전 = [max(0, random.lognormvariate(8, 1.0)) for _ in range(N)]
군 = [i % 2 for i in range(N)]               # 0=대조 1=실험
후 = [t * random.lognormvariate(0, 0.35) * (1 + 효과 if g else 1) for t, g in zip(전, 군)]

def 차이(값):
    a = [v for v, g in zip(값, 군) if g == 0]
    b = [v for v, g in zip(값, 군) if g == 1]
    d = statistics.mean(b) - statistics.mean(a)
    se = (statistics.variance(a)/len(a) + statistics.variance(b)/len(b)) ** 0.5
    return d, se

d1, se1 = 차이(후)                            # 그냥 비교

# CUPED — 실험 전 지출로 설명되는 부분을 빼고 비교한다
평균전, 평균후 = statistics.mean(전), statistics.mean(후)
공분산 = sum((x - 평균전) * (y - 평균후) for x, y in zip(전, 후)) / (N - 1)
세타 = 공분산 / statistics.variance(전)
보정후 = [y - 세타 * (x - 평균전) for x, y in zip(전, 후)]
d2, se2 = 차이(보정후)

상관 = 공분산 / (statistics.stdev(전) * statistics.stdev(후))
print(f"실험 전 지출과 실험 중 지출의 상관 {상관:.2f}")
print(f"{'방법':<12}{'차이':>12}{'표준오차':>12}{'차이/표준오차':>14}")
print(f"{'그냥 비교':<11}{d1:>12,.0f}{se1:>12,.0f}{d1/se1:>14.2f}")
print(f"{'CUPED':<12}{d2:>12,.0f}{se2:>12,.0f}{d2/se2:>14.2f}")
print(f"\n표준오차가 {se1/se2:.1f}배 줄었다. 같은 확신을 얻는 데 필요한 표본이 {(se2/se1)**2:.2f}배로 준다.")
```

```

방법                    차이        표준오차       차이/표준오차
그냥 비교                30         107          0.28
CUPED                139          45          3.11

표준오차가 2.4배 줄었다. 같은 확신을 얻는 데 필요한 표본이 0.18배로 준다.
```

같은 데이터인데 판정이 통째로 뒤집혔다. 그냥 비교하면 차이 대 표준오차가 0.28이라 "유의하지 않다"이고, CUPED를 쓰면 3.11이라 "유의하다"가 된다.

추정치 자체도 크게 다르다. 실제 효과는 3%이고 평균 지출을 생각하면 140 언저리인데, **그냥 비교한 30은 잡음에 묻힌 값이고 CUPED의 139가 진짜에 가깝다.**

쓸 수 있는 조건이 하나 있다. **실험 전 데이터와 실험 중 지표의 상관이 높아야 한다.** 위 예에서는 0.91이라 효과가 컸다. 신규 사용자처럼 실험 전 데이터가 없는 대상에는 못 쓴다.

면접에서 "실험 기간을 줄일 방법이 있나요"를 물으면 이것과 함께 두 가지를 더 대면 된다. 트래픽 배분을 50대 50으로 맞추는 것과, 지표의 극단값을 잘라 내는 것이다. 셋 다 **효과를 키우는 게 아니라 잡음을 줄이는** 방법이다.

**Q. 그런데 3일 만에 필요한 표본을 채웠어도 3일에 멈추면 안 된다면서요?**

맞다. 표본 수는 어디까지나 **최소** 조건이다. 주중과 주말의 행동이 다르니 최소 한 주는 채우는 것이 관행이고, 두 주를 채우면 요일 효과가 두 번 들어가 더 안전하다.

## 2. 엿보기 — "어제 유의하게 나와서 멈췄습니다"

**Q. 매일 결과를 보다가 유의해지면 멈추는 게 왜 문제인가요?**

이것이 지훈이 답 못 한 질문인데, 재 보면 답이 바로 나온다.

```python
import random, math

random.seed(99)

def 이항(n, p):
    """n 번 시행에서 성공 횟수. n 이 커서 정규 근사를 쓴다 — 한 건씩 돌리면 백 배 느리다."""
    m, s = n * p, math.sqrt(n * p * (1 - p))
    return max(0, min(n, round(random.gauss(m, s))))

def p값(a클릭, a노출, b클릭, b노출):
    p1, p2 = a클릭 / a노출, b클릭 / b노출
    p = (a클릭 + b클릭) / (a노출 + b노출)
    se = math.sqrt(p * (1 - p) * (1 / a노출 + 1 / b노출))
    if se == 0: return 1.0
    z = (p2 - p1) / se
    return 2 * (1 - 0.5 * (1 + math.erf(abs(z) / math.sqrt(2))))

CTR, 하루, 일수 = 0.01, 50_000, 14

def 한실험(엿보기):
    a = b = 0
    for 날 in range(1, 일수 + 1):
        a += 이항(하루, CTR)
        b += 이항(하루, CTR)          # A 와 B 는 실제로 똑같다
        if 엿보기 and p값(a, 하루*날, b, 하루*날) < 0.05:
            return True               # "유의하다!" 하고 멈춘다
    return (not 엿보기) and p값(a, 하루*일수, b, 하루*일수) < 0.05

반복 = 20_000
끝까지 = sum(한실험(False) for _ in range(반복))
엿보며 = sum(한실험(True) for _ in range(반복))

print(f"A 와 B 가 실제로 똑같을 때, {반복:,}번 실험해서 '차이 있다'고 결론 낸 비율")
print(f"  {'14일 다 채우고 한 번만 본다':<28}{끝까지/반복:>8.1%}")
print(f"  {'매일 보다가 유의하면 멈춘다':<28}{엿보며/반복:>8.1%}")
print("\n둘 다 진짜 차이는 0인데, 매일 엿본 쪽은 헛것을 볼 확률이 몇 배로 뛴다.")
```

```

  14일 다 채우고 한 번만 본다               5.0%
  매일 보다가 유의하면 멈춘다                21.6%

```

**A와 B가 완전히 똑같은데도 다섯 번 중 한 번은 "차이 있다"가 나온다.** 정해 둔 5%의 네 배가 넘는다.

이유는 그리 복잡하지 않다. p값은 매일 오르내리는데, 매일 보다가 낮아진 날에만 멈추면 **가장 운 좋은 날을 골라내는 것**이 된다. 열네 번의 기회를 주고 그중 하나만 걸리면 되니 확률이 올라간다.

**Q. 그러면 중간에 아예 보면 안 되나요?**

봐도 된다. **보고 나서 멈추지만 않으면 된다.** 실무에서는 두 가지 방식을 쓴다.

하나는 사고 감지용으로만 보는 것인데, 매출이 급락하거나 오류율이 튀면 즉시 멈추는데, 이것은 성공 판정이 아니라 안전장치다. 다른 하나는 중간에 멈춰도 되도록 설계된 방법을 쓰는 것이다. 순차 검정이나 베이지안 방식이 그것인데, 대신 기준을 그만큼 엄격하게 잡는다.

## 3. 지표를 여러 개 보면 생기는 일

**Q. 실험에서 지표를 스무 개 봅니다. 문제 있나요?**

있다. 앞 절과 같은 이유다. **기회를 많이 줄수록 우연히 걸릴 확률이 오른다.**

```python
import random, math

random.seed(2026)

def 이항(n, p):
    m, s = n * p, math.sqrt(n * p * (1 - p))
    return max(0, min(n, round(random.gauss(m, s))))

def p값(a, b, n):
    p1, p2 = a / n, b / n
    p = (a + b) / (2 * n)
    se = math.sqrt(p * (1 - p) * 2 / n)
    if se == 0: return 1.0
    z = (p2 - p1) / se
    return 2 * (1 - 0.5 * (1 + math.erf(abs(z) / math.sqrt(2))))

N, CTR, 반복 = 20_000, 0.01, 20_000

def 하나라도(지표수):
    return any(p값(이항(N, CTR), 이항(N, CTR), N) < 0.05 for _ in range(지표수))

print("A 와 B 가 실제로 똑같은데, 지표를 여러 개 보면")
print(f"{'동시에 보는 지표 수':>18}{'하나라도 유의할 확률':>22}{'이론값':>10}")
for k in (1, 5, 10, 20):
    친것 = sum(하나라도(k) for _ in range(반복))
    print(f"{k:>18}{친것/반복:>20.1%}{1 - 0.95**k:>10.1%}")
print("\n진짜 차이가 하나도 없는데도, 지표를 20개 보면 열에 여섯 번은 뭔가 유의하게 나온다.")
```

```
A 와 B 가 실제로 똑같은데, 지표를 여러 개 보면
       동시에 보는 지표 수           하나라도 유의할 확률       이론값
                 1                4.9%      5.0%
                 5               22.6%     22.6%
                10               40.3%     40.1%
                20               64.7%     64.2%

진짜 차이가 하나도 없는데도, 지표를 20개 보면 열에 여섯 번은 뭔가 유의하게 나온다.
```

실측이 이론값과 소수점 첫째 자리까지 맞는다. 지표 스무 개를 보면 **열에 여섯 번은 뭔가가 "유의"하게 나온다.** 진짜 차이는 하나도 없는데도.

**답의 핵심 — "주요 지표를 하나 미리 정해 두고 그것으로만 판정합니다. 나머지는 참고용으로 보되 판정에 쓰지 않습니다."**

여러 지표로 판정해야만 한다면 기준을 엄격하게 조정한다. 가장 단순한 것은 유의수준을 지표 수로 나누는 것인데, 스무 개면 0.05 대신 0.0025를 쓴다. 다만 이렇게 하면 진짜 차이도 놓치기 쉬워지니, 지표 수를 줄이는 쪽이 대체로 낫다.

## 4. 신기함 효과 — "첫날 좋았는데 나중에 사라졌다"

**Q. 실험 첫 이틀은 크게 좋았는데 일주일 뒤에는 차이가 없어졌습니다. 어느 쪽이 맞나요?**

일주일 뒤가 맞다. 새로운 것이 나오면 사용자가 일단 한 번 눌러 본다. 이것을 **신기함 효과**라 하고, 대체로 며칠 안에 사라진다.

반대 방향으로 나타나는 것도 있다. 익숙하던 것이 바뀌면 처음에는 오히려 안 좋아졌다가 적응하면서 회복하는데, 이쪽은 **적응 효과**라 부르고, UI를 바꾸는 실험에서 흔하다.

**둘 다 "초반 며칠은 믿지 않는다"로 대응한다.** 최소 기간을 정해 두는 이유가 표본 수 때문만은 아니다.

**Q. 신기함 효과인지 진짜 개선인지 어떻게 구분하나요?**

**날짜별로 효과 크기를 그려 보면 된다.** 신기함 효과라면 처음에 크고 점점 줄어 0에 수렴한다. 진짜 개선이라면 첫날부터 대체로 일정하다.

한 가지 더 쓸 수 있는 방법은 **신규 사용자와 기존 사용자를 나눠 보는 것**이다. 신기함 효과는 기존 사용자에게서만 나타나고, 그 기능을 처음 보는 신규 사용자에게는 안 나타난다. 두 집단의 효과가 크게 다르면 신기함 효과를 의심한다.

## 5. 간섭 — "A와 B가 서로 영향을 준다"

**Q. 사용자를 반으로 나눴는데 실험군의 변화가 대조군에도 영향을 줄 수 있나요? [무대: 공통]**

광고에서는 자주 그렇다. **예산과 인벤토리를 공유하기 때문이다.**

실험군에서 입찰가를 올리면 그 캠페인의 예산이 빨리 소진된다. 예산이 떨어지면 대조군에서도 그 캠페인이 안 나온다. 대조군이 순수한 "안 바꿨을 때"가 아니게 된다.

경매에서도 같은 일이 벌어진다. 실험군 광고가 더 공격적으로 입찰하면 낙찰가가 올라가고, 같은 경매에 들어간 대조군 광고의 성과가 떨어진다. **이 경우 실험 결과가 실제 효과보다 크게 나온다** — 대조군이 손해를 봤기 때문이다.

**Q. 그러면 어떻게 나눠야 하나요?**

간섭이 일어나는 단위보다 큰 단위로 나눈다. 예산이 캠페인 단위로 묶여 있으면 **캠페인 단위로 나눈다.** 사용자 단위로 나누면 같은 캠페인이 양쪽에 걸쳐 간섭이 생긴다.

지역이나 시간으로 나누는 방법도 있는데, 지역을 반으로 나눠 한쪽만 바꾸거나, 시간대를 번갈아 배정한다. 대신 **표본 단위가 커져서 필요한 기간이 훨씬 길어진다.** 캠페인이 200개면 표본이 200개인 실험이 된다.

이 절충을 말할 수 있느냐가 이 질문의 핵심이다. **"사용자 단위는 검정력이 높지만 간섭이 생기고, 캠페인 단위는 깨끗하지만 표본이 적습니다. 예산 공유가 있는지부터 확인하겠습니다."**

## 6. 유의하지 않다 — "차이가 없다는 뜻인가요"

**Q. p값이 0.3이 나왔습니다. 차이가 없다는 뜻인가요?**

아니다. **"차이가 없다"가 아니라 "차이가 있다고 말할 근거가 부족하다"다.** 이 구분을 못 하면 실험 결과를 계속 잘못 읽는다.

차이가 정말 0일 수도 있고, 차이는 있는데 표본이 모자랄 수도 있다. 둘을 구분하려면 **신뢰구간을 봐야 한다.**

신뢰구간이 [−0.2%, +0.3%]로 좁으면 "효과가 있어도 아주 작다"고 말할 수 있다. [−5%, +6%]로 넓으면 "아직 아무 말도 못 한다"가 맞다. 두 경우의 p값이 똑같이 0.3일 수 있다.

**답의 핵심 — "p값만으로는 부족합니다. 신뢰구간을 보고, 그 구간이 우리가 신경 쓰는 크기보다 좁은지를 봐야 합니다."**

**Q. 그럼 실험을 더 돌려야 하나요?**

여기서 판단이 갈린다. 더 돌리면 구간이 좁아지지만 시간이 든다. 판단 기준은 **"이 정도 크기의 효과라면 우리가 뭘 다르게 할까"**다.

1% 개선이 확인돼도 배포 안 할 거라면 1%를 잡을 만큼 오래 돌릴 이유가 없다. 반대로 0.5% 차이가 연간 수십억이면 79일을 돌릴 만하다. **먼저 "얼마부터 의미 있나"를 정하고, 그다음 기간을 정한다.**

## 7. 가드레일 — "주요 지표만 보면 안 되는 이유"

**Q. CTR만 올리면 되는 것 아닌가요?**

CTR만 보고 최적화하면 올릴 방법이 많은데, 그중 상당수가 회사에 손해다. 자극적인 소재를 위에 놓거나, 광고를 더 많이 띄우거나, 콘텐츠와 헷갈리게 만들면 CTR은 오른다.

그래서 **주요 지표 하나와 함께 "이건 나빠지면 안 된다"는 지표들을 같이 본다.** 이것을 가드레일이라 한다.

| 무엇을 지키나 | 지표 예 | 왜 |
|---|---|---|
| 사용자 경험 | 세션 길이, 재방문율, 신고 수 | 떠나면 인벤토리 자체가 준다 |
| 광고주 성과 | 전환율, 전환당 비용 | 나빠지면 광고주가 예산을 뺀다 |
| 시스템 | 응답 시간, 오류율, 타임아웃 | 느려지면 요청 자체가 줄어든다 |
| 건전성 | 예측값 분포, 예산 소진 속도 | 조용히 망가지는 것을 잡는다 |

**핵심 문장 — "주요 지표는 올리고 가드레일은 지키는지를 같이 봅니다. 가드레일이 깨지면 주요 지표가 올라도 배포 안 합니다."**

이때 3절의 다중 비교 문제가 다시 나온다. 가드레일이 열 개면 그중 하나는 우연히 나빠 보인다. 그래서 가드레일에는 **판정 기준을 다르게 둔다** — "유의하게 좋아졌나"가 아니라 "허용 범위를 넘게 나빠졌나"를 본다.

## 8. 어트리뷰션 — "이 전환은 누구 덕인가"

**Q. 한 사용자가 여러 광고를 보고 전환했습니다. 성과를 어디에 주시겠어요? [무대: 공통]**

정답이 없는 질문이고, 그래서 **규칙에 따라 답이 얼마나 달라지는지를 아는 것**이 답이다.

```python
# 어트리뷰션 — 같은 전환을 규칙에 따라 다르게 나눈다
여정 = [
    ("디스플레이", 1), ("동영상", 3), ("디스플레이", 5), ("검색광고", 9),   # 클릭 시점(일)
]
전환값 = 100_000

규칙 = {}
규칙["마지막 클릭"] = {여정[-1][0]: 전환값}
규칙["첫 클릭"]     = {여정[0][0]: 전환값}
균등 = {}
for 매체, _ in 여정:
    균등[매체] = 균등.get(매체, 0) + 전환값 / len(여정)
규칙["균등 배분"] = 균등

# 시간 가중 — 전환에 가까울수록 크게
반감기 = 3.0
가중 = [0.5 ** ((여정[-1][1] - t) / 반감기) for _, t in 여정]
합 = sum(가중)
시간 = {}
for (매체, _), w in zip(여정, 가중):
    시간[매체] = 시간.get(매체, 0) + 전환값 * w / 합
규칙["시간 가중"] = 시간

매체들 = ["디스플레이", "동영상", "검색광고"]
print("전환 한 건(10만원)을 네 규칙으로 나눠 본다")
print(f"{'규칙':<14}" + "".join(f"{m:>12}" for m in 매체들))
for 이름, 배분 in 규칙.items():
    print(f"{이름:<13}" + "".join(f"{배분.get(m, 0):>12,.0f}" for m in 매체들))

print("\n같은 전환인데 검색광고 몫이 0원에서 10만원까지 갈린다.")
print("규칙을 바꾸면 어느 매체에 예산을 더 줄지가 통째로 바뀐다.")
```

```
전환 한 건(10만원)을 네 규칙으로 나눠 본다
규칙                   디스플레이         동영상        검색광고
마지막 클릭                  0           0     100,000
첫 클릭              100,000           0           0
균등 배분              50,000      25,000      25,000
시간 가중              30,723      13,855      55,422

같은 전환인데 검색광고 몫이 0원에서 10만원까지 갈린다.
규칙을 바꾸면 어느 매체에 예산을 더 줄지가 통째로 바뀐다.
```

**같은 전환 한 건인데 검색광고 몫이 0원에서 10만원까지 갈린다.** 마지막 클릭 규칙을 쓰면 검색광고가 전부 가져가고, 첫 클릭 규칙을 쓰면 하나도 못 가져간다.

이 차이가 그대로 예산 배분으로 이어진다. 마지막 클릭만 보면 검색광고 예산을 늘리게 되는데, 검색광고는 이미 사려고 마음먹은 사람이 누르는 경우가 많다. **광고가 없었어도 살 사람에게 예산을 몰아주는 셈이 될 수 있다.**

**답의 핵심 — "어느 규칙도 정답이 아닙니다. 규칙마다 어느 매체가 유리해지는지를 알고, 예산 결정에는 다음 절의 증분 실험을 씁니다."**

## 9. 증분 — "안 했어도 일어났을 일"

**Q. 광고를 껐더니 매출이 안 떨어졌습니다. 광고가 쓸모없었나요?**

이 질문이 어트리뷰션의 근본 문제를 찌른다. 어트리뷰션은 **전환을 나누는** 규칙이지 **그 전환이 광고 덕인지**를 묻지 않는다.

**증분**은 바로 그것을 묻는 지표다. 광고를 봤을 때와 안 봤을 때의 차이가 진짜 효과다.

재는 방법은 실험밖에 없다. 일부 사용자에게는 광고를 안 보여 주고, 두 집단의 전환율을 비교한다. 광고 대신 공익광고를 띄우는 방식이 흔한데, 광고 지면 자체가 사라지는 효과를 없애기 위해서다.

**Q. 증분 실험이 그렇게 좋으면 왜 다 안 하나요?**

세 가지 이유가 있다.

**첫째, 비싸다.** 대조군에는 광고를 안 띄우니 그만큼 수익을 포기한다. 대조군을 작게 하면 검정력이 떨어져 결과를 못 믿는다.

**둘째, 오래 걸린다.** 전환은 클릭보다 훨씬 드물어서 첫째 절의 표에서 위쪽 줄에 해당한다. 기준율이 낮을수록 필요한 표본이 급격히 는다.

**셋째, 광고주가 반대한다.** "우리 광고를 일부러 안 보여 준다"는 것을 설득해야 한다.

**그래서 실무는 절충한다. 일상 운영은 어트리뷰션으로 하고, 분기에 한 번쯤 증분 실험으로 어트리뷰션이 얼마나 부풀었는지를 재서 보정한다.** 이 답을 하면 실무를 해 봤다는 신호가 된다.

## 10. 지표를 못 올릴 때

**Q. 반년 동안 실험을 열 번 했는데 다 유의하지 않았습니다. 어떻게 하시겠어요?**

이 질문은 기술이 아니라 태도를 본다. 아래 세 가지를 순서대로 확인하겠다고 답하면 형태가 갖춰진다.

**첫째, 실험이 잘못됐는지 본다.** 검정력이 모자랐을 수 있다. 첫째 절의 계산을 되짚어, 잡으려던 개선폭이 애초에 그 트래픽으로 잡을 수 있는 크기였는지 확인한다. 열 번 다 표본이 모자랐다면 실험이 아니라 계획의 문제다.

**둘째, 지표가 잘못됐는지 본다.** 바꾼 것이 실제로는 효과가 있는데 그 효과가 지표에 안 잡힐 수 있다. 예를 들어 개선이 소수의 무거운 사용자에게만 나타나면 전체 평균은 거의 안 움직인다. 이때는 **집단을 나눠 보는 것**이 답이다.

**셋째, 방향이 잘못됐는지 본다.** 열 번의 실험이 전부 같은 가정 위에 있었다면 그 가정을 의심해야 한다. 모델 성능을 올리는 실험만 했다면, 병목이 모델이 아니라 다른 데 있을 수 있다.

**답의 마무리로 붙이면 좋은 말이 있다.** "유의하지 않은 실험도 결과입니다. 이 방향으로는 효과가 크지 않다는 걸 알았으니 그만큼 다른 데 쓸 시간을 번 겁니다." 실패를 실패로만 보면 다음 실험도 같은 자리를 돈다.

## 한눈 정리

| 질문 | 답의 핵심 한 줄 |
|---|---|
| 며칠 돌려야 하나 | 며칠이 아니라 몇 건. 기준율과 개선폭에서 계산한다 |
| 개선폭이 절반이면 | 필요한 표본은 네 배가 된다 |
| 유의해지면 멈춰도 되나 | 안 된다. 진짜 차이가 0인데도 21.6%가 유의하게 나온다 |
| 중간에 보면 안 되나 | 봐도 되고 멈추면 안 된다. 사고 감지용은 별개다 |
| 지표를 스무 개 본다 | 열에 여섯 번은 뭔가 유의하다. 주요 지표를 하나 정한다 |
| 첫날 좋았는데 사라졌다 | 신기함 효과. 날짜별 효과 크기로 구분한다 |
| 실험군이 대조군에 영향을 주나 | 예산·경매를 공유하면 그렇다. 나누는 단위를 키운다 |
| p값 0.3은 차이가 없다는 뜻인가 | 아니다. 신뢰구간을 보고 폭으로 판단한다 |
| CTR만 올리면 되나 | 가드레일을 같이 본다. 깨지면 배포 안 한다 |
| 전환을 어느 매체에 주나 | 규칙마다 0원에서 10만원까지 갈린다. 예산은 증분으로 |
| 광고를 껐는데 매출이 그대로다 | 증분이 낮다는 뜻일 수 있다. 어트리뷰션과 다른 질문이다 |
| 실험이 열 번 다 실패했다 | 검정력·지표·방향 순서로 의심한다 |

## 헷갈리기 쉬운 점

- **"며칠 돌리나"에 날짜로 답하지 마라.** 표본 수를 먼저 구하고 나누는 순서를 보여야 한다.
- **유의해졌다고 멈추지 마라.** 기회를 열네 번 주면 헛것 볼 확률이 네 배가 된다.
- **"유의하지 않다"를 "차이가 없다"로 읽지 마라.** 신뢰구간의 폭이 실제 정보다.
- **지표를 많이 본다고 안전해지지 않는다.** 오히려 헛것이 늘어난다.
- **초반 며칠의 결과를 믿지 마라.** 신기함 효과와 적응 효과가 반대 방향으로 작동한다.
- **사용자 단위 분할이 항상 옳다고 생각하지 마라.** 예산이 묶여 있으면 간섭이 생긴다.
- **어트리뷰션 숫자를 효과로 읽지 마라.** 나누는 규칙일 뿐 인과가 아니다.
