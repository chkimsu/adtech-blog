# 타겟팅 모델 트랙 6편과 LLM 트랙 셋 26편, 새 카테고리 하나 — 설계

작성 2026-11-03. 사용자 승인 *"응"* (지도 페이지의 네 묶음 32편, LLM 예시 방식, 카테고리 신설, 지훈 씨 서사, 묶음 순서 전부).

이 문서는 공개 저장소에 올라갑니다. 회사 안 자료에서 가져온 것은 「무엇을 어떤 순서로 하고, 무엇을 접었고, 무엇으로 평가하나」의 구조뿐이고 이름, 숫자, 문장은 넣지 않습니다. 출처는 공개 논문과 제품 문서로 답니다.

---

## 1. 왜 만드나

글 108편 가운데 LLM, RAG, 프롬프트, 에이전트를 다룬 글이 0편입니다. 가장 가까운 글은 임베딩과 검색 4편(Two-Tower 둘, Elasticsearch 하이브리드, 임베딩 테이블 운영)입니다. 타겟팅 글은 12편이 있지만 마케터가 화면에서 보는 것(기초 7편, 카카오 1편)과 개요(심화 2편, 교차 2편)이고, 모델이 그 뒤에서 하는 일(유저 프로파일을 피처로 만들기, 관심사 분류, Lookalike 를 실제로 계산하기, 전환 예측으로 고르기, 컨텍스추얼, 자연어로 오디언스 만들기)은 없습니다.

2026년 광고 ML 공고는 이 자리를 묻습니다. 쿠팡 Ads 는 에이전틱 시스템(멀티 에이전트, ReAct, LangGraph)을 필수로 적고 업무에 RLHF, RLAIF, 지식 증류, LLM 분산 서빙을 적었습니다. 다음(Daum)은 BM25 와 Dense 결합, RAG 이해, 프롬프트 엔지니어링과 SFT 를 필수로 적고 LLM-as-a-Judge 와 Context Recall 을 업무로 적었습니다. 쿠팡플레이는 Vector Search 가 필수이고 LLM 은 우대입니다. 공개 자료 60건에서 가장 자주 나오는 기법은 LLM-as-a-Judge(12건), 에이전트와 MCP(11건), RAG 와 벡터 검색(11건), SFT 와 DPO 와 RLHF(9건), 프롬프트와 CoT(8건)입니다.

읽는 사람은 둘입니다. 광고 ML 모델링은 깊지만 LLM 을 불러 본 적이 없는 엔지니어와, 애드테크를 처음 보는 사람입니다. 둘 다 블로그의 기존 독자 규칙 그대로입니다.

## 2. 확정된 결정

| 무엇 | 어떻게 |
|---|---|
| 새 글 | 32편. 네 묶음을 이 순서로 쓴다. 타겟팅 모델 6편 → LLM 기초 9편 → LLM 광고 응용 13편 → LLM 학습 4편. 한 묶음이 끝나면 검증하고 올린 뒤 다음 묶음으로 간다 |
| 트랙 | `series` 넷을 새로 만든다. `targeting-model-track` 「타겟팅 모델 트랙」, `llm-basics-track` 「LLM 기초 트랙」, `llm-ads-track` 「LLM 광고 응용 트랙」, `llm-training-track` 「LLM 학습 트랙」 |
| 카테고리 | `data/taxonomy.json` 에 여덟째 카테고리 `LLM & Agents` 를 더한다. 태그 `LLM`, `RAG`, `Agent`, `Embedding`, `LLM Evaluation`, `Fine-tuning`, `Prompting` 을 더한다. 타겟팅 모델 6편은 `Targeting & Audience`, LLM 26편은 `LLM & Agents`(광고 응용은 글에 따라 `Targeting & Audience` 나 `Measurement & Modeling` 을 둘째 카테고리로) |
| 형식 | 모델 운영 트랙과 같다. 합쇼체, 도입 장면 → 한 줄 요약 → 본문 절 → 한눈 정리 표 → 헷갈리기 쉬운 점 → 더 깊이 보기. 절마다 카드 한 장(iframe), 계산은 표 위에 가정 한 줄과 계산식 한 줄. **실행 검증한 파이썬 1~3개**(표준 라이브러리, 하는 일과 단계와 뜻 형식, `# 출력:` 붙임). `NO_PYTHON_BY_DESIGN` 에 넣지 않는다 |
| LLM 예시 방식 | 두 겹이다. **구조를 보이는 코드는 규칙으로 만든 가짜 LLM 이 답한다**(표준 라이브러리, 글 안에서 그대로 돈다). **진짜 답이 필요한 자리는 맥의 공개 모델을 한 번 돌려 기록하고 글에 그대로 붙인다**(아래 5절). 상용 API 를 부르는 코드는 「발췌」 표시로 한 글에 한 번만 보인다. API 키는 쓰지 않는다 |
| 기록 모델 | 글을 쓰는 맥(Apple Silicon, 메모리 36GB)에 Ollama 를 설치해 `qwen3.5:27b` 하나로 고정한다(사용자 승인 2026-11-03). thinking 을 켜고 끈 두 벌을 기록한다. 글마다 모델 이름과 기록한 날짜를 한 번 적는다. 기록은 `data/llm-records/<slug>.json` 에 두고 손으로 고치지 않는다. Ollama 응답에는 thinking 토큰 수가 따로 없으므로 켠 것과 끈 것의 출력 토큰 수와 thinking 글자 수를 적는다 |
| 기록 출력과 말투 검사 | 말투 검사기는 코드 블록 안까지 세고 새 파일은 0건이어야 한다. 그래서 기록에 쓰는 프롬프트는 출력을 JSON, 영어 enum 라벨, 숫자로 받는다. 한국어 문장(카피 후보, 키워드의 이유, 거절 메시지)은 코드 블록이 아니라 산문의 「」 안에 대사로 보인다. 검사기는 고치지 않는다 |
| 카테고리 색 | `LLM & Agents` 는 `Interview & Algorithms` 처럼 테두리형으로 그리고 선은 `--oxide-bd`, 레일 글자는 `L`. 계열색 여섯은 이미 여섯 카테고리가 쓰고 있어 색을 늘리지 않는다 |
| 이야기 | 모델 운영 트랙의 **지훈 씨**가 13주째에 「자연어로 타겟팅하는 과제」를 받고 LLM 을 처음 만진다(11-01 에 올린 실시간 피처 글이 11주째, Elasticsearch 글이 12주째다). 한 주에 한 편, 시간은 앞으로만 간다. 주 수는 「13주째」처럼 숫자로 쓴다. 말로 쓴 수는 검사기가 잡는다. 광고주는 타겟팅 트랙의 **서연 씨**, 회원은 **회원 A, B, 비로그인 C** 와 행동 시퀀스 글의 **민지 씨** 그대로 |
| 무대 | LLM 기초와 학습은 `world: 'both'` 이되 두 갈래 절은 짧게 한 문단씩. 타겟팅 모델과 광고 응용은 끝에서 두 번째 절이 「담장 안 / 열린 RTB」 두 갈래(### 소제목에 배지). `worldNote`, `worldPractical` 을 채운다 |
| 카드와 놀이터 | 글마다 데크 한 장(카드 3~5장, `js/card-kit.js` 그대로, 새 CSS 없음). 묶음마다 놀이터 한 장(아래 6절). 데모 목록 `demos.html` 에 주제 「타겟팅 모델」, 「LLM」 절을 새로 만든다 |
| 낱말 | 가운뎃점 없음(쉼표). 비유 없음. 실측, 실체, 축, 가른다, 갈린다 없음. 이모지 없음. 표준 용어는 그대로 쓰고 처음에 짧은 풀이(토큰, 컨텍스트, 임베딩, RAG, tool use, MCP, LLM-as-a-Judge, SFT, DPO, 증류). 제목은 「주제어: 무엇을 알게 되나」 55자 이하 |
| 출처 | 글마다 「참고문헌」 절에 공개 논문과 제품 문서만 단다. 회사 안 시스템 이름, 숫자, 문장은 글과 카드와 주석과 커밋 메시지 어디에도 넣지 않는다. 나가기 전에 로컬에만 있는 이름 목록으로 grep 한다 |

## 5. 기록 재생과 가짜 LLM — LLM 글만의 형식

**기록 재생.** 글의 파이썬은 표준 라이브러리만으로 돌아야 하고 LLM 호출은 네트워크와 모델이 필요하므로, 진짜 출력은 한 번 기록해 재생한다. Elasticsearch 글이 기록한 응답을 그대로 다시 보이는 것과 같은 방식이다.

- `scripts/llm-record.py`(표준 라이브러리 `urllib`)가 Ollama 의 `/api/chat` 을 불러 `data/llm-records/<slug>.json` 을 쓴다. 파일에는 모델, 기록한 날짜, 파라미터, 항목마다 시스템 메시지와 사용자 메시지, 출력, thinking 토큰 수, 출력 토큰 수, 걸린 시간이 든다.
- 글은 출력을 손으로 옮겨 적지 않는다. 글에 보이는 출력은 기록 파일에서 그대로 가져온 것이고, 숫자(정답률, 바뀐 비율, 일치도)도 기록에서 계산한다.
- 기록을 쓰는 파이썬 블록은 필요한 출력을 문자열 상수로 담고 `# 기록 <slug>.json 에서 옮김` 주석을 단다. 그래서 검사기에서도 돈다.
- 다시 기록하면 파일 전체를 바꾸고 글의 숫자를 다시 맞춘다. 모델을 바꾸지 않는다.

**가짜 LLM.** 에이전트 루프, 워크플로, RAG 조립처럼 구조를 보이는 코드는 규칙으로 답하는 가짜 LLM 을 쓴다.

- 진짜 SDK 와 같은 모양으로 답한다(`stop_reason`, 내용 블록 목록, 도구 호출 블록). 다음 행동은 대화 기록을 읽어 정해진 규칙으로 고른다.
- 글마다 블록 안에 들어 있어 혼자 돈다. 공용 모듈을 만들지 않는다. 같은 글의 뒤 블록은 `# (앞 블록에 이어서 돌린다.)` 로 잇는다.
- 글은 「진짜 모델은 이 자리에서 시스템 메시지와 대화를 읽고 스스로 고른다」고 한 번 말한다.

**상용 API 코드.** 한 글에 한 번, `# (발췌 — 그대로 실행되지 않습니다.)` 표시로 보인다. 모델 이름은 문서 링크와 함께 적고 가격은 적지 않는다.

**세션 발췌.** 코딩 에이전트 글 한 편만 기록 대신 Claude Code 세션의 발췌를 쓴다. 이 블로그 저장소나 공개 랩에서 돌린 세션만 쓰고, 경로와 계정 이름은 지운다. 기록 모델 하나와 API 키 없음 규칙의 유일한 예외이고 글에 그렇게 적는다.
