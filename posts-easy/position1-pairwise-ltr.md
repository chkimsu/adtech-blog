지훈 씨는 검색광고 pCTR 모델이 하루 동안 낸 점수를 실제 클릭과 맞춰 보고 있었습니다. pCTR 은 광고가 한 번 노출됐을 때 클릭될 확률, 곧 클릭률을 모델이 예측한 값입니다. 같은 검색 안의 광고 순서를 얼마나 잘 맞혔는지 보는 AUC 는 높게 나왔습니다. AUC 는 클릭된 광고와 안 클릭된 광고를 하나씩 짝지었을 때 클릭된 쪽이 더 높은 점수를 받은 비율입니다. 그런데 노출마다 받은 점수를 더해 센 예상 클릭은 실제 클릭보다 많았고 그 차이는 2위와 3위 광고일수록 컸습니다.

옆자리 팀원은 같은 검색에서 클릭된 광고와 안 된 광고를 쌍으로 묶어 학습하는 방식을 시험하고 있었는데, 검색 단위로 측정한 순위 지표는 이 방식에서 가장 높게 나왔습니다. 하지만 그 점수에 입찰가를 곱해 순위를 다시 매겨 보니 클릭률이 낮은 광고가 1위로 올라왔습니다.

**순서를 잘 맞히는 점수가 왜 돈을 셀 때는 틀릴까요?**

지훈 씨가 본 일은 Position 1 추론에서 생깁니다. Position 1 추론은 서빙(실제 검색이 들어올 때 모델이 점수를 내는 단계)에서 모든 후보 광고를 1위에 있다고 두고 점수를 내는 방식입니다. 팀원이 본 일은 Pairwise LTR(Learning to Rank) 에서 생깁니다. Pairwise LTR 은 순위를 매기는 모델을 학습하는 방법 가운데 같은 검색 안의 광고를 쌍으로 비교해 배우는 방식입니다. 두 경우 모두 점수가 광고의 순서는 맞히지만 점수의 크기는 맞지 않습니다. 광고 시스템은 이 점수에 입찰가를 곱해 순위를 정하고 같은 점수로 예상 클릭과 광고비까지 세므로, 점수의 크기가 틀리면 순위와 돈이 같이 틀립니다.

> **한 줄 요약:** pCTR 모델은 랭커(광고 순서를 정하는 서버)가 순서를 정하기 전에 불려 위치를 모르므로 모든 후보를 1위에 두고 점수를 냅니다. 모두 같은 1위 기준이니 순서 비교는 공평하지만 점수는 1위일 때의 클릭률이라, 이 글의 가상 데이터에서 2위 광고는 그 위치의 실제 클릭률보다 1.3배, 3위 광고는 2배 크게 나옵니다. 그래서 예상 클릭과 광고비를 셀 때는 순서가 정해진 뒤 그 위치의 효과를 곱해 되돌립니다. 같은 검색 안의 쌍으로 배우는 Pairwise LTR 은 순서만 배우고 점수의 크기는 정하지 않으므로, 점수에 입찰가를 곱하는 광고에서는 그 크기 때문에 순위가 뒤집힐 수 있어 크기가 맞는 pointwise 확률(광고마다 클릭 여부를 맞히도록 학습한 확률)이나 보정 함수(점수를 클릭률로 바꾸는 함수)가 필요합니다.

> **골라 읽는 법:** 12개 절로 된 긴 글입니다. 앞 여섯 절은 Position 1 추론을, 뒤 여섯 절은 Pairwise LTR 과 지면(광고가 실리는 화면)에 따른 차이를 다룹니다. 두 부분은 따로 읽어도 됩니다.
>
> - 모든 후보를 1위로 두고 추론하는 까닭과 그렇게 낸 값이 실제보다 커지는 정도 → 1~3절
> - 커진 값을 정해진 위치의 효과로 되돌리는 법 → 4절
> - 모두 1위라는 가정이 순서까지 바꾸는 경우와 1위에 가 본 적 없는 광고의 점수 → 5~6절
> - Pairwise LTR 이 점수의 크기를 정하지 않는 까닭과 그 점수에 입찰가를 곱할 때 생기는 일 → 7~9절
> - 쌍을 만드는 학습 데이터가 한쪽으로 기우는 자리 → 10~11절
> - 담장 안(자기 지면에 자기 광고를 싣는 닫힌 생태계)과 열린 RTB(광고 자리마다 실시간 경매로 사고파는 거래) → 12절

## 1. 학습 때는 노출 로그에 위치가 있습니다

**학습에 쓰는 노출 로그(광고가 화면에 나간 기록)에는 줄마다 광고가 몇 위에 나왔는지가 적혀 있어서 pCTR 모델은 위치를 피처(모델에 넣는 입력 값)로 넣어 학습하며 광고가 1위에 있을 때의 클릭률(광고 품질)과 위치 때문에 달라지는 비율(위치 효과)을 나눠 배웁니다.**

검색 결과에 광고가 여러 개 줄을 서면 위에 있을수록 사람 눈에 먼저 닿으므로 같은 광고라도 몇 위에 놓였느냐에 따라 눌리는 정도가 다릅니다. 그래서 로그의 클릭률만 보면 광고가 좋아서 눌렸는지 위에 있어서 눌렸는지 알 수 없습니다. [Position Bias](post.html?id=position-bias-ultr) 편은 위치 때문에 생기는 이 차이를 자리 편향이라고 부르고 위치마다 사람의 눈길이 광고에 닿을 확률을 Examination 확률이라고 불렀습니다. 이 글은 1위의 Examination 확률을 1.0 으로 놓고 다른 위치의 Examination 확률을 그에 대한 비율로 나타낸 값을 위치 효과라고 부릅니다.

아래 표는 설명을 위해 만든 가상 데이터입니다. 위치 효과는 앞 글의 가상 값과 같게 2위 0.75, 3위 0.5 로 두었는데, 2위의 0.75 는 같은 광고가 2위에 가면 1위에 있을 때 클릭률의 0.75배로 클릭된다는 뜻입니다. 광고 A, B, C 는 1위에 있을 때 클릭률이 각각 5%, 4%, 3% 인 광고입니다. 이 글은 가장 잘 보이는 1위에서의 이 클릭률을 광고의 품질이라고 부릅니다. 광고 D 는 늘 4위나 그보다 아래에만 나온 광고입니다.

| 위치 | 위치 효과 | 놓인 광고 | 광고 품질 (1위일 때 클릭률) | 그 위치에서의 클릭률 |
|---|---|---|---|---|
| 1위 | 1.0 | A | 5.0% | 5.0% |
| 2위 | 0.75 | B | 4.0% | 3.0% |
| 3위 | 0.5 | C | 3.0% | 1.5% |
| 4위 | 0.3 | D | 1위 기록 없음 | 0.6% |
| 5위 | 0.15 | 없음 | | |

표의 마지막 열은 위치 효과에 광고 품질을 곱한 값입니다. 2위 B 는 품질 4.0% 에 2위의 위치 효과 0.75 를 곱해 4.0% × 0.75 = 3.0% 가 클릭되고 3위 C 는 품질 3.0% 에 3위의 0.5 를 곱해 3.0% × 0.5 = 1.5% 가 클릭됩니다. 1위 A 는 위치 효과가 1.0 이라 품질 5.0% 가 그대로 클릭률이 됩니다. D 의 품질 칸이 「1위 기록 없음」인 까닭은 6절에서 봅니다.

로그에는 이 마지막 열의 클릭률만 보이므로, B 의 3.0% 가 C 의 1.5% 의 두 배여서 로그로는 B 가 C 보다 두 배쯤 좋은 광고처럼 보입니다. 그런데 품질은 B 4.0%, C 3.0% 로 두 배만큼 차이 나지 않습니다. C 가 B 보다 한 칸 아래인 3위에 놓여 위치 효과를 0.75 대신 0.5 만 받은 탓에 로그에서는 그 차이가 두 배까지 벌어졌습니다. 위치를 피처로 넣어 학습하면 모델은 B 의 3.0% 를 품질 4.0% 와 위치 효과 0.75 의 곱으로 나눠 배웁니다. 위에 있어서 더 눌리거나 아래에 있어서 덜 눌린 몫을 위치 피처가 맡으므로 광고 ID 같은 광고 피처에는 광고 자체의 몫만 남습니다. 카드에서는 학습 로그의 B 3.0% 가 모델 안에서 B 의 품질 4.0% 와 2위의 위치 효과 0.75 로 나뉘는 흐름을 보면 됩니다.

여기까지는 학습 때의 이야기입니다. 이 모델을 서빙에 올려 점수를 물을 때는 위치 피처에 넣을 값이 없어서 문제가 생깁니다.

## 2. 서빙 때는 위치를 모르므로 모두 1위로 둡니다

**서빙에서 pCTR 모델은 랭커(광고 순서를 정하는 서버)가 순서를 정하기 전에 불리는데, 위치는 순서가 정해져야 생기고 순서는 점수가 있어야 정할 수 있으므로 모든 후보에게 똑같이 위치 1 을 넣고 점수를 묻습니다.**

1절의 모델은 위치 피처까지 받아야 점수를 내는데, 서빙에서 점수를 묻는 순간에는 그 위치가 아직 정해져 있지 않습니다. 사용자가 검색어를 입력하면 랭커는 후보 광고를 모아 순서를 정하기 전에 pCTR 모델에 점수부터 묻습니다. 랭커는 받은 점수에 입찰가를 곱해 순서를 정한 다음 그 순서대로 1위, 2위, 3위 자리에 광고를 놓는데, 위치는 이 마지막 단계에서야 생기므로 처음 점수를 묻는 시점에는 어느 광고가 몇 위에 갈지 아무도 모릅니다.

그래서 실무에서는 모든 후보의 위치 피처를 같은 값으로 채우는데, 가장 흔히 넣는 값이 1 입니다. 1 을 고르는 데는 두 가지 까닭이 있습니다. 1위는 가장 잘 보이는 자리라서 1위일 때의 클릭률은 광고의 품질로 읽기 쉽습니다. 또 위치 효과도 1위를 1.0 으로 두고 측정하므로, 위치 1 로 낸 점수에 순서가 정해진 뒤 그 위치의 효과를 곱하기만 하면 그 위치의 클릭률이 나와 뒤의 계산이 간단해집니다(4절에서 2위 B 는 4.0% × 0.75 = 3.0%). 카드는 랭커가 모든 후보를 1위로 두고 물어 받은 점수 A 5.0%, B 4.0%, C 3.0% 로 1위 A, 2위 B, 3위 C 를 정하는 흐름을 보여 줍니다.

모든 후보를 같은 위치 1 로 두니 어느 광고도 자리 덕을 보지 않아 비교가 공평합니다. 위치 효과가 모든 광고에 같은 비율로 붙는다면 위치를 몇으로 두든 모든 점수에 같은 수가 곱해질 뿐이라 순서가 같습니다. 예를 들어 A, B, C 를 모두 3위로 두고 물으면 점수는 5.0%, 4.0%, 3.0% 에 똑같이 0.5 를 곱한 2.5%, 2.0%, 1.5% 가 되어 순서가 그대로 A, B, C 이므로, 위치 1 점수로 정한 순서 A, B, C 는 어느 위치를 넣어 물어도 바뀌지 않습니다.

랭커가 남긴 로그로 나중에 점수를 다시 낼 때도 같은 사정입니다. 랭커 로그에는 화면에 노출되지 않은 후보까지 남는데 이런 후보에게는 처음부터 위치가 없으므로, 새 랭킹 규칙을 시뮬레이션하거나 오프라인 정책 평가(지난 로그로 새 정책의 결과를 미리 계산해 보는 일)를 하려고 랭커 로그를 다시 추론할 때도 위치를 1 로 고정합니다.

위치 1 점수로 매긴 순서는 이렇게 맞게 나오는데, 같은 점수를 클릭률의 크기로 읽으면 무슨 일이 생기는지 다음 절에서 봅니다.

## 3. 1위 기준 점수는 아래 위치에서 커집니다

**위치 1 로 낸 점수는 광고가 1위에 있을 때의 클릭률이라 2위와 3위로 간 광고는 실제로 그만큼 클릭되지 않으므로, 점수를 그대로 확률로 읽으면 아래 위치일수록 그 위치의 실제 클릭률보다 크게 잡힙니다.**

지훈 씨가 점수로 센 예상 클릭이 실제보다 많았고 2위와 3위 광고에서 차이가 더 컸던 까닭이 여기에 있습니다. B 는 위치 1 로 물어 받은 점수가 4.0% 인데 실제로는 2위에 놓여 위치 효과 0.75 가 곱해진 3.0% 만 클릭되므로, 점수가 실제의 4.0% ÷ 3.0% = 1.33배로 잡혀 있습니다. C 는 점수 3.0% 에 3위의 위치 효과 0.5 가 곱해져 1.5% 만 클릭되므로 3.0% ÷ 1.5% = 2배입니다. 1위에 간 A 만 위치 효과가 1.0 이라 점수 5.0% 와 실제 5.0% 가 같습니다. 배수 1.33 과 2 는 위치 효과 0.75 와 0.5 의 역수라서, 아래 위치일수록 위치 효과가 작아지는 만큼 배수가 커집니다. 카드에는 1위로 두고 낸 pCTR 막대와 실제로 간 위치의 클릭률 막대가 나란히 있어, A 에서 C 로 내려갈수록 두 막대가 벌어지는 모습이 보입니다.

광고 순서를 매길 때는 이 차이가 보이지 않습니다. AUC 는 점수의 순서만 보는 지표라, 점수가 모두 같은 비율로 커져도 순서가 그대로여서 값이 바뀌지 않습니다. 이 예에서는 배수가 1.00, 1.33, 2.00 으로 서로 다르지만 점수 5.0%, 4.0%, 3.0% 와 실제 클릭률 5.0%, 3.0%, 1.5% 가 둘 다 A, B, C 순서라서 역시 AUC 로는 차이를 볼 수 없습니다. 점수의 크기가 맞는지는 예측한 클릭의 합과 실제 클릭의 합을 나란히 놓아야 알 수 있습니다. 이 비교가 [Calibration](post.html?id=calibration) 편에서 다룬 예측 대비 실제 비율로, 두 합이 같아 비율이 1 이면 점수의 크기가 맞습니다.

그런데 점수의 크기를 쓰는 계산이 생각보다 많습니다. 광고주에게 보여 주는 예상 클릭과 예상 광고비는 점수의 크기에 노출 수와 클릭당 광고비를 곱해 셉니다. 목표 클릭당 비용(광고주가 정한 클릭 하나의 목표 금액)에 맞춰 입찰가를 정하는 자동입찰도, 랭킹 규칙을 바꿨을 때 매출이 어떻게 바뀌는지 미리 계산하는 시뮬레이션도 마찬가지입니다. 아래 코드는 이 차이가 돈으로 얼마인지 보려고 광고마다 하루 1만 번 노출되고 클릭 하나에 광고비 500원이 든다고 두고 점수를 그대로 쓴 예상과 위치 효과를 곱한 예상을 나란히 셉니다.

```python
# 하는 일: 모든 후보를 1위로 두고 낸 pCTR 과 실제로 간 위치의 클릭률을 비교하고, 하루 예상 클릭과 광고비가 얼마나 어긋나는지 센다.
# 1단계: 가상 데이터를 둔다
# 광고마다 1위에 있을 때의 클릭률(품질)과 실제로 간 위치를 적는다. 위치 효과는 1위를 1.0 으로 둔 상대값이다.
quality = {'A': 0.050, 'B': 0.040, 'C': 0.030}     # 가상 값
placed = {'A': 1, 'B': 2, 'C': 3}
pos_effect = {1: 1.00, 2: 0.75, 3: 0.50, 4: 0.30, 5: 0.15}
imps, cpc = 10_000, 500                            # 광고마다 하루 노출, 클릭당 광고비(원)
# 2단계: 위치 1 점수와 그 위치의 클릭률을 나란히 찍는다
# 서빙에서 받는 점수는 position=1 로 추론한 값이라 품질 그대로다.
print('광고 위치 pCTR(1위 기준) 그 위치 클릭률 커진 배수')
for ad, q in quality.items():
    real = q * pos_effect[placed[ad]]
    print(f'{ad}    {placed[ad]}    {q:6.1%}        {real:6.1%}        {q / real:4.2f}')
# 3단계: 하루 예상 클릭과 광고비를 비교한다
# 이 가상 세계는 클릭률을 품질 × 위치 효과로 만들었으므로, 위치 효과를 곱한 값이 실제와 같다.
for ad, q in quality.items():
    raw = imps * q
    fixed = imps * q * pos_effect[placed[ad]]
    print(f'{ad}: 점수 그대로 {raw:,.0f}번 {raw * cpc:,.0f}원 / 위치 효과를 곱하면 {fixed:,.0f}번 {fixed * cpc:,.0f}원')

# 출력:
# 2단계 뜻: 1위 A 만 점수와 그 위치의 클릭률이 같고, 2위 B 는 1.33배, 3위 C 는 2배 크게 잡혀 있다.
# 광고 위치 pCTR(1위 기준) 그 위치 클릭률 커진 배수
# A    1      5.0%          5.0%        1.00
# B    2      4.0%          3.0%        1.33
# C    3      3.0%          1.5%        2.00
# 3단계 뜻: 점수를 그대로 쓰면 B 의 하루 광고비가 20만 원으로 잡혀, 위치 효과를 곱한 15만 원보다 5만 원 많다.
# A: 점수 그대로 500번 250,000원 / 위치 효과를 곱하면 500번 250,000원
# B: 점수 그대로 400번 200,000원 / 위치 효과를 곱하면 300번 150,000원
# C: 점수 그대로 300번 150,000원 / 위치 효과를 곱하면 150번 75,000원
```

2단계에 찍힌 커진 배수는 A 1.00, B 1.33, C 2.00 으로 위에서 계산한 값과 같습니다. 3단계에서 B 는 점수를 그대로 쓰면 1만 번 × 4.0% = 400번이 클릭되어 400번 × 500원 = 200,000원이 들지만 위치 효과를 곱하면 1만 번 × 3.0% = 300번에 150,000원이 드니, 하루 광고비가 20만 원과 15만 원으로 5만 원 차이 납니다. 광고주에게 하루 20만 원어치, 클릭 400번이 날 것이라 보여 주고 실제로는 15만 원어치인 300번만 클릭되면 광고주는 예산과 기대 성과를 둘 다 잘못 잡습니다. 3위 C 는 점수를 그대로 쓴 300번, 150,000원이 위치 효과를 곱한 150번, 75,000원의 두 배라서 차이가 B 보다 더 큽니다.

그래도 위치 1 점수가 정한 순서는 맞으므로 이 점수를 버릴 수는 없습니다. 다음 절은 같은 점수를 순서와 돈 계산에 나눠 쓰는 법입니다.

## 4. 크기가 필요한 계산에는 정해진 위치의 효과를 곱합니다

**위치 1 점수 하나를 두 단계에 나눠 씁니다. 순서를 정할 때는 점수를 그대로 쓰고 순서가 정해져 위치가 생긴 뒤 돈을 셀 때는 그 위치의 효과를 곱합니다.**

점수 하나로 순서도 정하고 돈도 세야 하는데, 3절에서 보았듯 순서에는 맞는 점수가 돈 계산에서는 크게 잡힙니다. 랭커가 점수 4.0% 로 B 를 2위에 놓았다면 B 가 2위에서 받을 예상 클릭률은 점수에 2위의 위치 효과를 곱한 4.0% × 0.75 = 3.0% 이고 예상 클릭, 예상 매출, 광고비는 모두 이 3.0% 로 셉니다. 순서를 정하는 단계와 돈을 세는 단계가 나뉘어 있고 위치는 앞 단계가 끝나야 생기므로, 위치 효과는 순서가 정해진 뒤의 돈 세는 단계에서만 곱할 수 있습니다. 반대로 순서를 정하는 단계에서는 위치 효과를 곱하지 않아도 됩니다. 그 단계의 비교는 2절에서 본 대로 모든 후보를 같은 위치 1 로 두어 이미 공평합니다. 카드에는 B 의 pCTR 4.0% 가 순위를 매길 때는 그대로 쓰이고 돈을 셀 때만 2위 위치 효과 0.75 가 곱해지는 두 갈래가 그려져 있습니다.

위치 효과 표 하나로 모든 경우를 다룰 수는 없습니다. 같은 2위라도 광고가 3개 나올 때와 5개 나올 때 위치 효과가 다를 수 있고 모바일과 PC 도 다르므로, 위치 효과는 지면별로, 노출된 광고 수별로 나눠 둡니다. 값은 같은 광고를 여러 위치에 보여 준 기록으로 다시 측정하는데, 같은 광고라면 품질은 그대로이고 위치만 바뀌므로 위치마다 달라진 클릭률에서 위치 효과를 알 수 있습니다. 위치 효과를 측정하는 방법은 [Position Bias](post.html?id=position-bias-ultr) 편 4절에서 다룹니다.

광고 수를 바꾸는 시뮬레이션에서는 1위를 1.0 으로 둔 상대값만으로 부족할 때가 있습니다. 광고를 3개에서 5개로 늘리면 1위가 받던 클릭의 일부가 아래 위치로 나뉘어 1위의 클릭 자체가 줄어드는데, 상대값 표는 광고 수와 상관없이 1위를 늘 1.0 으로 두고 다른 위치를 그 비율로만 적으므로 1위에서 빠져나간 클릭을 담지 못합니다. 그래서 이런 시뮬레이션에는 광고 수마다 클릭이 위치별로 어떤 비율로 나뉘는지를 따로 측정해 둔 값을 씁니다.

여기까지는 위치 효과가 모든 광고에 같은 비율로 붙는다고 가정했습니다. 다음 절은 이 가정이 깨져 순서까지 바뀌는 경우입니다.

## 5. 위치와 광고를 함께 배우는 모델은 순서도 바꿉니다

**위치 효과가 광고마다 다르면 모두를 1위로 두고 매긴 순서와 실제 위치에서의 순서가 다를 수 있는데, DCN 처럼 피처끼리 곱한 조합을 배우는 모델은 위치와 광고의 이런 조합까지 배웁니다.**

2절에서는 위치를 몇으로 두든 순서가 같았는데, 위치 효과가 모든 광고에 같은 비율로 붙는다고 두었기 때문입니다. 이번에는 C 가 큰 이미지 광고라 3위에 놓여도 잘 보인다고 해 봅니다. 보통 광고인 A 는 3위의 위치 효과가 표대로 0.5 이지만 C 는 3위에서도 0.9 를 받는다고 둡니다. 둘 다 1위에 둔다면 위치 효과가 둘 다 1.0 이라 품질 그대로 A 5.0%, C 3.0% 로 A 가 앞섭니다. 둘 다 3위에 둔다면 A 는 5.0% × 0.5 = 2.5%, C 는 3.0% × 0.9 = 2.7% 라서 C 가 앞서는데, 2절처럼 C 의 3위 위치 효과도 0.5 였다면 C 는 1.5% 로 A 의 2.5% 보다 뒤였습니다. 위치 1 로 물으면 A 가 위인데 3위 기준으로 비교하면 C 가 위라서, 위치 1 점수로 정한 순서가 실제 위치에서의 순서와 다릅니다. 카드에서 둘 다 1위일 때와 둘 다 3위일 때 A 와 C 의 막대 높이가 뒤바뀌는 모습을 확인할 수 있습니다.

모델이 위치를 다른 피처와 따로 계산해 더하기만 한다면, 위치는 모든 광고의 점수에 같은 값을 더하거나 같은 비율을 곱할 뿐이라 위치를 몇으로 두든 순서가 같아서 이런 일이 생기지 않습니다. 그런데 DCN 처럼 피처끼리 곱해 배우는 모델은 다릅니다. DCN(Deep & Cross Network)은 층을 지날 때마다 피처끼리 곱한 조합을 쌓아 피처 조합을 직접 학습하는 모델로, [Deep CTR 모델](post.html?id=deep-ctr-models) 편에서 다뤘습니다. 이런 모델은 위치 피처와 광고 피처의 조합에서 「이미지 광고는 아래 위치에서 덜 떨어진다」는 규칙까지 배우므로 광고마다 위치 효과가 달라집니다. 그러면 위치에 넣는 고정값에 따라 순서가 달라져서, 위의 예처럼 위치 1 을 넣으면 A 가 앞서고 위치 3 을 넣으면 C 가 앞섭니다.

이런 모델에서는 위치 1 점수로 정한 순서가 최선이 아닐 수 있습니다. 후보가 적다면 후보마다 위치별 점수를 따로 내서 가장 나은 배치를 고르는 방법도 있는데, 이 방법은 추론 횟수를 위치 수만큼 늘립니다. 후보 A, B, C 마다 1위, 2위, 3위의 점수를 모두 물으면 3번이던 추론이 3 × 3 = 9번이 됩니다. 그래서 보통은 처음부터 위치 몫이 다른 피처와 섞이지 않게 모델을 짜는데, 그 구조는 다음 절에서 함께 봅니다.

1위에 한 번도 가 본 적 없는 광고에서는 이 조합 문제가 가장 크게 나옵니다.

## 6. 1위에 가 본 적 없는 광고의 점수는 짐작입니다

**학습 데이터의 1위 기록은 기존 랭킹이 1위에 올린 광고에만 있어서 한 번도 1위에 가 본 적 없는 광고를 위치 1 로 두고 물으면 모델은 본 적 없는 경우를 짐작해 점수를 냅니다.**

1절 표의 D 는 늘 4위나 그보다 아래에만 나온 광고라 품질 칸에 「1위 기록 없음」이라고 적혀 있습니다. 품질을 어림하려면 4위에서 측정한 클릭률 0.6% 를 4위의 위치 효과 0.3 으로 나눠 0.6% ÷ 0.3 = 2.0% 쯤으로 볼 수 있는데, 이 나눗셈은 D 도 4위에서 다른 광고와 같은 위치 효과 0.3 을 받는다고 가정할 때만 맞습니다. 5절의 C 처럼 D 의 위치 효과가 다른 광고와 다르다면 2.0% 도 틀린 값입니다. D 가 1위에 섰을 때 얼마나 클릭될지는 그런 기록이 한 번도 없어 누구도 알 수 없습니다. 카드는 4위와 5위 기록만 있는 D 를 1위로 두고 물을 때 모델이 짐작으로 채우는 자리를 보여 줍니다.

모델도 D 에 위치 1 을 넣고 점수를 낼 때 같은 짐작을 합니다. D 가 1위에 있던 학습 데이터가 없으니 다른 광고들이 1위에서 보인 모습을 빌려 D 의 점수를 내는데, 위치와 광고 피처를 곱해 배우는 모델일수록 위치 1 과 D 의 조합을 한 번도 보지 못한 채 짐작해야 하므로 크게 빗나가기 쉽고 실제보다 훨씬 높은 점수가 나오기도 합니다. 그렇게 높게 나온 점수로 D 가 갑자기 1위에 오르면 점수만큼 클릭되지 않는 광고가 1위 자리를 차지하므로 그날 그 자리의 클릭과 매출이 떨어집니다.

기존 랭킹이 D 를 1위에 올리지 않는 한 D 의 1위 기록은 생기지 않으므로, 같은 랭킹 아래에서 데이터를 더 모아도 이 문제는 풀리지 않습니다. 그래서 두 가지 방법을 씁니다. 하나는 트래픽(들어오는 검색 요청) 일부에서 광고 순서를 일부러 섞어 보여 주는 탐색으로, 이렇게 하면 D 같은 광고도 가끔 1위에 나가 1위 기록이 생깁니다. 다른 하나는 위치를 따로 배우는 모델 구조입니다.

위치를 따로 배우는 구조의 대표가 PAL(Position-bias Aware Learning) 입니다. PAL 은 클릭 확률을 위치에만 달린 확률(광고가 그 위치에서 눈에 띌 확률)과 위치와 상관없는 광고의 확률(눈에 띈 광고가 눌릴 확률)로 나누고 두 확률을 곱한 값이 실제 클릭에 맞도록 학습한 뒤, 서빙에서는 뒤쪽의 광고 확률만 씁니다. 이 나눔은 1절 표에서 B 의 3.0% 를 위치 효과 0.75 와 품질 4.0% 의 곱으로 본 것과 같은 꼴입니다. 서빙에서는 위치 쪽 확률을 쓰지 않으니 위치 피처에 고정값 1 을 넣을 필요도 없습니다. YouTube 의 추천 모델은 위치를 얕은 별도 층에만 넣어 학습한 뒤 서빙 때는 그 층을 빼고 점수를 냅니다. 두 구조 모두 위치 피처에 고정값을 넣는 대신 위치 몫을 처음부터 떼어 둡니다. 학습 단계에서 위치 편향을 보정하는 다른 방법은 [Position Bias](post.html?id=position-bias-ultr) 편 3~5절에 있습니다.

여기까지가 Position 1 추론 이야기입니다. 7절부터는 순서는 맞는데 점수의 크기가 틀리는 같은 문제가 학습 방식을 바꿨을 때 다른 모습으로 나오는 경우를 봅니다.

## 7. Pairwise LTR 은 같은 검색 안의 쌍으로 배웁니다

**pointwise 학습은 광고마다 눌렸는지를 맞히도록 배우고 pairwise 학습은 같은 검색 안에서 눌린 광고의 점수가 안 눌린 광고보다 높게 나오도록 배웁니다. 서빙에서는 두 방식 모두 광고 하나에 점수 하나를 냅니다.**

옆자리 팀원이 시험하던 방식이 pairwise 학습입니다. 검색 한 번에서 1위 A 만 눌리고 2위 B 와 3위 C 는 안 눌렸다면, pointwise 학습은 이 검색을 정답이 A 1, B 0, C 0 인 학습 데이터 3줄로 쓰는데 pairwise 학습은 같은 검색을 「A 가 B 보다 위」와 「A 가 C 보다 위」라는 쌍 2개로 씁니다. 손실(loss)은 모델의 예측이 정답에서 얼마나 먼지를 숫자 하나로 나타낸 값으로, 학습은 이 값을 줄이는 방향으로 모델을 고칩니다. 두 방식은 이 손실도 다른데, pointwise 는 줄마다 예측 확률이 정답 1 이나 0 과 얼마나 다른지를 보고 pairwise 는 쌍마다 두 점수의 차이를 봅니다. pairwise 손실은 「A 가 B 보다 위」인 쌍에서 A 의 점수가 B 보다 클수록 작아지므로, 학습은 눌린 A 의 점수를 안 눌린 B 와 C 보다 높이는 방향으로 움직입니다. 카드에서는 같은 검색 한 번이 pointwise 에서는 3줄, pairwise 에서는 2쌍이 되는 모습을 보면 됩니다.

pairwise 는 광고끼리의 경쟁을 배우려고 씁니다. 광고가 6개 나온 검색에서 받은 클릭은 함께 나온 다른 광고 5개를 이긴 결과인데, pointwise 는 이 클릭을 광고 2개짜리 검색에서 상대 1개를 이긴 클릭과 똑같이 정답 1 인 한 줄로 셉니다. pairwise 는 이긴 상대마다 쌍을 하나씩 만들어 6개 검색의 클릭은 쌍 5개로, 2개 검색의 클릭은 쌍 1개로 반영하므로 경쟁이 센 검색의 클릭을 더 세게 배웁니다. 요청 단위 AUC 는 검색 한 번(요청 하나) 안의 광고끼리만 비교해 순서를 측정하는 AUC 입니다. 이렇게 같은 검색 안의 경쟁을 쌍으로 배우므로, 같은 검색 안의 순서를 측정하는 요청 단위 AUC 는 pairwise 에서 높게 나오기 쉽습니다.

pairwise 는 학습 방식만 바꾸고 서빙 구조는 그대로 둘 수 있어서 실무에서 쓰기에도 좋습니다. 학습할 때는 같은 모델에 쌍의 두 광고를 하나씩 넣어(모델을 두 번 태워) 점수 2개를 얻고 그 차이로 손실을 계산합니다. 서빙할 때는 광고 하나를 한 번 태워 점수 하나를 얻으므로 pointwise 모델이 쓰던 서빙 구조를 그대로 씁니다. 대표적인 pairwise 손실은 RankNet 의 로지스틱 손실로, 8절에서 이 손실을 값으로 계산합니다. 쌍이 아니라 검색 한 번에 나온 광고 목록 전체의 순서를 한꺼번에 보는 listwise 손실도 같은 갈래에 듭니다.

문제는 이 손실이 보지 않는 데서 생깁니다.

## 8. Pairwise 손실은 점수 크기를 정하지 않습니다

**pairwise 손실은 두 점수의 차이만 보므로 모든 점수에 같은 값을 더해도 손실이 그대로라서, 학습이 끝나도 점수의 크기는 정해지지 않은 채 남습니다.**

이 절의 점수는 시그모이드에 넣기 전의 값인 로짓입니다. 시그모이드는 어떤 실수든 0 과 1 사이의 확률로 바꾸는 함수로 식이 1 / (1 + exp(-점수)) 이므로, 로짓이 0 이면 확률은 50% 가 되고 로짓이 클수록 100% 에, 작을수록 0% 에 가까워집니다.

광고 A 가 눌리고 B 는 안 눌린 쌍에서, 모델 갑은 A 에 로짓 2, B 에 0 을 주고 모델 을은 A 에 0, B 에 -2 를 준다고 하겠습니다. A 와 B 의 점수 차이는 갑이 2 - 0 = 2, 을이 0 - (-2) = 2 로 같은데 pairwise 손실은 이 차이만 받으므로 두 모델의 손실은 똑같습니다. 을은 갑의 두 점수에 똑같이 -2 를 더한 모델(2 → 0, 0 → -2)이라 모든 점수에 같은 값을 더해도 손실이 그대로인 예입니다. 손실이 같으니 학습은 갑과 을 가운데 어느 쪽이 나은지 구분하지 못합니다. 카드는 갑과 을의 점수가 높이만 다르고 차이는 똑같이 2 인 모습과 두 모델이 내는 확률을 보여 줍니다.

그런데 두 모델의 점수를 시그모이드에 넣어 확률로 바꾸면 결과가 다릅니다. 갑에서는 A 의 로짓 2 가 1 / (1 + exp(-2)) 로 88% 가 됩니다. B 의 로짓 0 은 exp(0) 이 1 이므로 1 / (1 + 1) = 50% 입니다. 을에서는 같은 계산으로 A 의 0 이 50%, B 의 -2 가 12% 가 됩니다. 같은 광고 A 를 갑은 88%, 을은 50% 로 보는데, 실제 클릭률이 5% 라면 두 값 모두 틀렸을 뿐 아니라 손실이 같으니 어느 쪽이 덜 틀렸는지도 학습이 정해 주지 않습니다. 아래 코드는 손실이 같아도 확률이 얼마나 다른지 보려고 두 모델의 손실과 확률을 찍은 뒤, 이어서 9절의 입찰 계산까지 해 봅니다.

```python
# 하는 일: pairwise 손실이 두 점수의 차이만 본다는 것을 확인하고, 손실이 같은 두 모델이 확률과 입찰 순위에서 얼마나 다른지 찍는다.
import math


# 1단계: 손실과 확률을 정한다
# 클릭된 광고 점수가 안 클릭된 광고 점수보다 클수록 손실이 작다(RankNet 의 로지스틱 손실).
def pairwise_loss(s_click, s_skip):
    return math.log(1 + math.exp(-(s_click - s_skip)))


def prob(score):
    return 1 / (1 + math.exp(-score))      # 로짓 점수를 확률로 바꾼다


# 2단계: 차이가 같은 두 모델을 비교한다
# 점수는 로짓이다. 갑과 을은 A 와 B 의 차이가 똑같이 2 다.
models = {'갑': (2.0, 0.0), '을': (0.0, -2.0)}
for name, (a, b) in models.items():
    print(f'모델 {name}: 손실 {pairwise_loss(a, b):.4f}, A {prob(a):.0%}, B {prob(b):.0%}')

# 3단계: 입찰가를 곱해 순위를 매긴다
# X 와 Y 는 같은 검색에 함께 나온 적이 없어, pairwise 가 둘의 크기를 맞춘 적이 없다.
bids = {'X': 1000, 'Y': 600}
cases = [('맞는 크기', {'X': 0.02, 'Y': 0.04}), ('pairwise 점수', {'X': 0.03, 'Y': 0.04})]
for label, ctr in cases:
    score = {ad: bids[ad] * ctr[ad] for ad in bids}
    first = max(score, key=score.get)
    print(f'{label}: X {score["X"]:.0f}, Y {score["Y"]:.0f}, 1위 {first}')

# 출력:
# 2단계 뜻: 두 모델은 손실이 0.1269 로 같지만, A 의 확률은 88% 와 50% 로 다르다.
# 모델 갑: 손실 0.1269, A 88%, B 50%
# 모델 을: 손실 0.1269, A 50%, B 12%
# 3단계 뜻: X 의 점수가 2% 에서 3% 로 커지면 순위 점수가 20 에서 30 이 되어, 1위가 Y 에서 X 로 바뀐다.
# 맞는 크기: X 20, Y 24, 1위 Y
# pairwise 점수: X 30, Y 24, 1위 X
```

2단계에 찍힌 손실은 갑과 을 모두 0.1269 입니다. `pairwise_loss` 는 클릭된 광고의 점수에서 안 클릭된 광고의 점수를 뺀 차이에 마이너스를 붙여 exp 를 계산하고 1 을 더한 뒤 로그를 취하는데, 갑과 을은 이 차이가 똑같이 2 라서 둘 다 log(1 + exp(-2)) 를 계산해 같은 0.1269 가 나옵니다. 차이가 클수록 exp(-차이) 가 0 에 가까워져 손실도 0 에 가까워지므로, 이 손실은 클릭된 광고의 점수를 안 클릭된 광고보다 높이는 방향으로 학습을 이끕니다. 같은 줄에 찍힌 확률은 A 가 88% 와 50%, B 가 50% 와 12% 로 모델마다 다릅니다. 3단계의 X 와 Y 는 9절에서 풉니다.

그러니 pairwise 점수를 확률로 쓰려면 점수를 클릭률로 바꿔 주는 보정 함수를 학습과 따로 맞춰야 합니다. 보통 시그모이드 안에 기울기와 절편 두 값을 두어 시그모이드(기울기 × 점수 + 절편) 꼴로 씁니다. 절편은 점수가 0 일 때 시그모이드에 들어가는 값이라 점수 0 인 광고의 확률을 정합니다. 절편 자체는 확률이 아니라 로짓 값입니다. 기울기는 점수가 1 만큼 커질 때 시그모이드에 들어가는 값이 얼마나 커지는지를 정하므로, 점수 차이가 확률 차이로 얼마나 크게 옮겨질지도 기울기에 달려 있습니다. 절편은 전체 클릭률에 맞추고 기울기는 검증 데이터(학습에 쓰지 않고 남겨 둔 데이터)로 맞춥니다. 갑과 을처럼 모든 점수가 같은 값만큼 옮겨져도 손실이 같으니 학습은 점수의 높낮이를 정하지 않는데, 이 높낮이를 절편이 전체 클릭률에 맞춰 정합니다. 이 보정 함수는 데이터가 바뀔 때마다 다시 맞춰야 하므로, 학습 자체가 확률을 맞추는 pointwise 와 비교하면 관리할 것이 하나 늘어납니다.

크기가 정해지지 않은 점수는 입찰가와 곱하는 순간에 가장 크게 문제가 됩니다.

## 9. 입찰가를 곱하면 검색 밖 비교가 생깁니다

**검색광고는 입찰가에 클릭 점수를 곱한 값으로 순위를 정하므로, 같은 검색 안의 순서만 맞춘 pairwise 점수에 입찰가를 곱하는 순간 서로 다른 검색에서 학습된 광고끼리 점수의 크기를 비교하게 됩니다.**

도입에서 팀원이 점수에 입찰가를 곱해 순위를 다시 매기자 클릭률이 낮은 광고가 1위로 올라온 일이 이 비교에서 생깁니다. 입찰가는 광고주가 클릭 한 번에 내겠다고 정한 금액이라 여기에 클릭 점수를 곱하면 노출 한 번에 기대되는 금액이 됩니다. 광고 X 는 입찰가 1,000원에 실제 클릭률 2%, 광고 Y 는 입찰가 600원에 실제 클릭률 4% 라고 하겠습니다. 클릭 점수의 크기가 맞다면 순위 점수(입찰가 × 클릭 점수)는 X 가 1,000 × 2% = 20, Y 가 600 × 4% = 24 라서 Y 가 1위입니다. 그런데 X 와 Y 는 그동안 같은 검색에 함께 나온 적이 없습니다. pairwise 손실은 같은 검색 안의 쌍에서만 계산되는데 X 와 Y 로는 쌍이 한 번도 만들어지지 않았으니, pairwise 는 X 와 Y 의 점수 크기를 서로 맞춰 본 적이 없습니다. 카드에서는 X 의 클릭 점수가 2% 에서 3% 로 바뀌면 순위 점수 막대가 20 에서 30 으로 길어져 1위가 Y 에서 X 로 넘어가는 모습을 보면 됩니다.

X 의 점수가 실제 클릭률 2% 대신 3% 로 나와도 X 가 나온 검색 안의 순서만 맞으면 pairwise 손실은 커지지 않으므로, 손실이 이 오차를 막지 않습니다. 이 3% 에 입찰가를 곱하면 X 의 순위 점수는 1,000 × 3% = 30 이 되어 Y 의 24 를 넘으므로 X 가 1위로 올라가는데, X 는 실제 클릭률이 2% 로 Y 의 4% 보다 낮은 광고라 그 자리의 클릭과 매출이 같이 줄어듭니다. 8절 코드의 3단계가 이 계산을 찍었습니다. 「맞는 크기」 줄에서는 X 20, Y 24 로 Y 가 1위인데, X 의 클릭 점수만 3% 로 바꾼 「pairwise 점수」 줄에서는 X 30, Y 24 로 X 가 1위가 됩니다.

배포 전에 보는 오프라인 지표도 이 차이를 잘 보지 못합니다. 요청 단위 AUC 는 pairwise 가 맞춘 같은 검색 안의 순서만 측정하므로 pairwise 에 유리하게 나옵니다. X 의 점수가 2% 든 3% 든 X 가 나온 검색 안의 순서가 맞으면 요청 단위 AUC 는 달라지지 않습니다. 그래서 입찰가를 곱해 쓰는 점수라면 요청 단위 AUC 와 함께 아래 표의 전체 AUC, 예측 합 대비 실제 합까지 세 지표를 같이 봐야, 요청 단위 AUC 는 높은데 온라인(실제 트래픽)에서 지는 모델을 배포 전에 걸러 낼 수 있습니다.

| 지표 | 무엇을 측정하나 | pairwise 점수에서는 |
|---|---|---|
| 요청 단위 AUC | 같은 검색 안의 순서 | 잘 나옵니다 |
| 전체 AUC | 검색을 섞은 순서 | 크기가 어긋나면 떨어집니다 |
| 예측 합 대비 실제 합 | 점수의 크기 | 보정 함수 없이는 맞지 않습니다 |

전체 AUC 는 검색을 섞어 모든 노출을 점수로 정렬한 순서를 측정하므로 검색마다 점수의 크기가 다르게 맞춰져 있으면 떨어집니다. 예측 합 대비 실제 합은 3절에서 본 대로 점수의 크기 자체를 측정하므로, 크기를 정하지 않는 pairwise 점수로는 보정 함수 없이 맞지 않습니다.

그래서 입찰가와 곱하는 광고 점수는 학습이 크기까지 맞추는 pointwise 확률을 기본으로 둡니다. 경쟁을 배우는 pairwise 의 장점도 함께 쓰고 싶으면 pointwise 손실에 순위 손실(pairwise 처럼 순서를 보는 손실)을 더해 함께 학습하거나, pairwise 점수 뒤에 8절의 보정 함수를 붙여 크기를 맞춥니다. 10절과 11절은 손실이 아니라 pairwise 학습 데이터 자체가 한쪽으로 기우는 자리를 봅니다.

## 10. 쌍을 만들 수 있는 검색만 남습니다

**쌍 하나를 만들려면 한 검색 안에 눌린 광고와 안 눌린 광고가 함께 있어야 하므로, 아무도 누르지 않은 검색은 학습에서 버려지고 광고가 많은 검색의 클릭은 쌍을 더 많이 만듭니다.**

클릭률이 낮은 검색광고에서는 대부분의 검색이 클릭 없이 끝나는데, 이런 검색에는 눌린 광고가 없어 쌍을 하나도 만들 수 없습니다. 검색 100번 가운데 클릭이 난 검색이 5번이라면 쌍은 그 5번에서만 나오고 나머지 100 - 5 = 95번은 학습 데이터에서 빠집니다. 학습에 쓰는 검색이 100번에서 5번으로 줄어드니 학습이 빨라진다는 장점은 있습니다. 카드는 검색 100번 가운데 클릭이 난 5번만 쌍을 만들고 아무도 누르지 않은 95번은 버려지는 모습을 보여 줍니다.

남은 검색 안에서도 검색마다 학습에 들어가는 무게가 같지 않습니다. 광고 6개 검색에서 난 클릭 하나는 안 눌린 광고 5개와 하나씩 짝을 지어 쌍 5개가 되고 광고 2개 검색에서 난 클릭 하나는 안 눌린 광고 1개와 짝을 지어 쌍 1개가 됩니다. 7절에서는 경쟁이 센 검색을 세게 배우는 것을 pairwise 의 장점으로 봤는데, 같은 일을 거꾸로 보면 쌍이 많이 나오는 광고 많은 검색 쪽으로 학습이 기운다는 뜻입니다. 카드에서 같은 클릭 하나가 광고 6개 검색에서는 쌍 5개로, 광고 2개 검색에서는 쌍 1개로 들어가는 모습을 확인할 수 있습니다.

## 11. 쌍에 위치가 섞입니다

**클릭된 광고보다 아래에 있던 광고는 사용자가 아예 보지 않았을 수 있어서 그런 광고와 만든 쌍은 광고의 차이가 아니라 위치의 차이를 배웁니다.**

쌍의 상대를 고를 때 클릭된 광고 아래에 있던 광고까지 쓰면 문제가 생기는데, 한 사람이 2위 B 를 누른 검색으로 보겠습니다. 사람이 위에서 아래로 차례로 읽는다고 가정하면, B 를 누른 사람은 B 보다 위에 있는 1위 A 를 보고 지나갔을 가능성이 높습니다. 그래서 「B 가 A 보다 위」라는 쌍은 이 사람이 A 와 B 를 다 보고 B 를 고른 결과로 볼 수 있습니다. 3위 C 는 사정이 다릅니다. 이 사람이 B 를 누르고 페이지를 떠났다면 B 아래에 있던 C 는 보지도 않았을 수 있습니다. 카드에서는 B 를 누른 사람의 검색 결과로 만든 두 쌍 가운데 「B 가 C 보다 위」가 왜 의심스러운 쌍인지 보면 됩니다.

「B 가 C 보다 위」라는 쌍을 그대로 학습하면 모델은 사용자가 C 를 보고도 누르지 않은 것으로 배웁니다. 실제로는 C 가 B 보다 아래에 놓여 눈에 닿지 않았을 뿐이니, 이 쌍은 광고 품질 대신 위치의 차이를 담습니다. 1절에서는 B 의 3.0% 와 C 의 1.5% 처럼 위치 때문에 벌어진 클릭 차이를 광고의 차이로 읽는 착시를 위치 피처로 걸러 냈는데, 그 착시가 쌍을 만드는 단계에서 다시 들어옵니다.

그래서 클릭된 광고보다 위에 있다가 건너뛴 광고만 음성으로 쓰는 방법이 있습니다. 음성은 쌍에서 클릭된 광고의 상대가 되는 안 눌린 광고입니다. Joachims 가 검색 클릭 로그로 순위를 학습하면서 쓴 방식으로, 클릭보다 위(above)에서 건너뛴(skip) 광고를 쓴다고 해서 skip-above 라고 부릅니다. B 가 눌린 이 검색이라면 skip-above 는 B 위에서 건너뛴 A 와 만든 「B 가 A 보다 위」만 남기고 B 아래의 C 와 만든 쌍은 쓰지 않아서 쌍 수는 2개에서 1개로 줄지만 남는 쌍은 두 광고를 다 본 사람의 선택입니다. 위치 효과를 알고 있다면 아래 광고와 만든 쌍을 버리지 않고 그 위치의 Examination 확률로 가중해 쓰는 방법도 있습니다. 「B 가 C 보다 위」 쌍이라면 C 가 있던 3위의 Examination 확률을 무게로 쓰므로, 1절 표의 위치 효과로 1위의 0.5배인 이 확률만큼만 쌍이 반영됩니다.

이런 치우침이 얼마나 문제가 되는지는 광고가 여러 개 줄을 서는 지면인지에 달려 있습니다.

## 12. 닫힌 생태계와 열린 RTB 에서 달라지는 점

**광고가 여러 개 줄을 서는 담장 안(닫힌 생태계) 지면에서는 이 글의 두 문제가 매일 나옵니다. 지면 하나에 광고 하나를 넣는 경우가 많은 열린 RTB 에서는 위치 문제가 덜한 대신 확률의 크기가 그대로 입찰가로 이어집니다.**

### 담장 안에서는 위치를 알고 섞어 볼 수도 있습니다 [무대: 닫힌 생태계]

닫힌 생태계(Walled Garden)는 자기 지면에 자기 광고를 싣는 플랫폼으로, 이 글이 담장 안이라고 부르는 곳입니다. 검색 결과와 피드에 광고가 여러 개 줄을 서는 이런 곳에서는 Position 1 추론과 Pairwise LTR 의 두 문제가 매일 나오지만 위치 로그가 정확하고 트래픽 일부에서 순서를 섞는 실험(6절의 탐색)도 직접 할 수 있습니다. 그래서 위치 효과를 측정하고 4절처럼 위치 1 점수를 정해진 위치의 효과로 되돌리는 일을 스스로 할 수 있습니다. 그러니 이런 곳에서 위치 효과를 곱하지 않은 예상 광고비는 직접 할 수 있는 보정을 빠뜨린 값입니다.

### 열린 RTB 에서는 확률의 크기가 곧 입찰가입니다 [무대: 열린 RTB]

열린 RTB(Real-Time Bidding)는 광고 자리가 하나 날 때마다 여러 광고주가 실시간 경매로 입찰하는 거래 방식입니다. DSP(Demand-Side Platform)는 광고주를 대신해 이 경매에 입찰하는 시스템인데, 열린 RTB 의 DSP 는 지면 하나에 광고 하나를 넣는 경우가 많아 위치 문제는 덜합니다. 대신 DSP 는 입찰가를 클릭 확률에 클릭 하나의 가치를 곱해 정하므로 확률의 크기가 그대로 입찰가가 됩니다. 클릭 하나의 가치가 같다면 확률이 1.3배 커질 때 입찰가도 1.3배 커집니다. 그래서 pairwise 처럼 학습이 크기를 정하지 않는 점수는 그대로 입찰에 쓸 수 없습니다. 8절의 갑과 을처럼 손실이 같은 두 모델이 같은 광고 A 에 88% 와 50% 를 줄 수 있으므로, 쓰려면 반드시 보정 함수를 거쳐 클릭률의 크기를 맞춥니다.

## 한눈 정리

| 질문 | 한 줄 답 |
|---|---|
| 서빙 때 위치를 왜 1 로 두나 | 점수를 물을 때는 순서가 정해지기 전이라 위치가 없습니다. 모두 같은 1위로 두면 비교가 공평합니다 |
| 1위로 둔 점수의 문제는 | 1위 기준 클릭률이라 아래 위치에서 커집니다. 이 글의 예시에서 2위 1.3배, 3위 2배 |
| 어떻게 되돌리나 | 순서가 정해진 뒤 그 위치의 효과를 곱합니다. 4.0% × 0.75 = 3.0% |
| 순서도 바뀌나 | 위치 효과가 광고마다 다르고 모델이 그 조합을 배우면 바뀔 수 있습니다 |
| 1위에 가 본 적 없는 광고는 | 점수가 짐작입니다. 탐색 트래픽과 위치를 떼어 배우는 구조로 줄입니다 |
| pairwise LTR 은 무엇을 배우나 | 같은 검색 안의 순서입니다. 점수의 크기는 정하지 않습니다 |
| 광고에서 왜 문제가 되나 | 입찰가를 곱하는 순간 다른 검색의 광고와 크기를 비교합니다 |
| 오프라인에서 무엇을 보나 | 요청 단위 AUC 와 함께 전체 AUC, 예측 합 대비 실제 합 |
| 쌍 데이터의 치우침은 | 클릭 난 검색만 남고, 광고가 많은 검색이 세게 배우고, 아래 광고와의 쌍에 위치가 섞입니다 |

## 헷갈리기 쉬운 점

- **Position 1 추론이 틀린 방법은 아닙니다.** 모든 후보를 같은 위치 1 로 두고 비교하므로 순서를 정하는 데는 맞는 방법입니다. 그 점수를 그대로 확률로 읽을 때만 틀립니다. 3절의 B 는 그렇게 읽으면 하루 광고비가 15만 원이 아닌 20만 원으로 잡힙니다.
- **AUC 가 그대로라고 크기가 맞는 것은 아닙니다.** AUC 는 점수의 순서만 측정하므로 점수가 모두 같은 비율로 커져도 순서가 그대로라 값이 같습니다. 크기는 3절처럼 예측한 클릭의 합을 실제 클릭의 합과 비교해야 보입니다.
- **위치를 아예 빼고 학습하면 더 나빠집니다.** 위치 피처가 맡아야 할 위치 몫이 광고 ID 로 새어 들어가므로, 위에 자주 나온 광고는 좋아 보이고 1절의 B 와 C 처럼 아래에 있던 광고는 품질보다 나쁘게 학습됩니다.
- **pairwise 점수에 시그모이드를 적용했다고 확률이 되지는 않습니다.** 시그모이드를 거치면 숫자는 0 과 1 사이로 나오지만 그 크기는 학습이 정한 값이 아니어서 8절의 갑과 을은 손실이 0.1269 로 같은데도 같은 광고 A 를 88% 와 50% 로 봅니다.
- **Pairwise LTR 이 나쁜 방법은 아닙니다.** 검색 결과나 피드의 순서를 다시 정하는 단계처럼 순서만 중요한 자리에는 맞는 방법입니다. 점수에 입찰가를 곱해 크기까지 쓰는 자리에서만 보정이 따로 필요합니다.
- **다른 순위 손실도 같습니다.** LambdaRank 는 쌍마다 두 광고의 자리를 맞바꾸면 NDCG(위쪽 순서를 더 무겁게 치는 순위 지표)가 얼마나 바뀌는지를 계산해 그 양으로 무게를 준 pairwise 손실입니다. softmax 손실은 검색 한 번에 나온 광고 목록 전체를 한꺼번에 보는 listwise 손실입니다. 두 손실 모두 검색 안의 순서를 배울 뿐 점수의 크기는 정하지 않아, 모든 점수에 같은 값을 더한 8절의 갑과 을을 구분하지 못합니다.

- 순위 손실과 확률 보정을 함께 쓰는 방법은 Yan 외, [Scale Calibration of Deep Ranking Models](https://doi.org/10.1145/3534678.3539072)(KDD 2022)에 정리돼 있습니다.
