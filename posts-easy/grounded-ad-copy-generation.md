모델 팀 35주째 월요일, 서연 씨가 지훈 씨에게 런솔 라이트의 상품 설명으로 검색 광고 문구를 5개 써 달라고 했습니다. 예전에 손으로 쓴 문구 하나는 설명에 없는 「가장 가벼운」을 넣었다가 심사에서 빠졌다고 합니다.

선배는 모델에게 문구를 쓰게 하되 문구마다 기댄 구절을 설명에서 그대로 옮겨 적게 하자고 했습니다. 그 구절이 정말 설명 안에 있는지는 코드가 보기로 했습니다. 다른 광고주의 설명 9개도 같이 돌렸는데, 그 가운데 2개는 인사말뿐인 글입니다.

**모델이 쓴 광고 문구가 설명에 없는 말을 하지 않았다는 것을, 사람이 하나하나 읽지 않고 어떻게 확인할까요?**

이 글은 광고주가 올린 상품 설명 같은 글을 자산 텍스트, 광고 문구를 카피라고 부릅니다. 카피가 기댄 자산의 구절은 근거입니다. 모델은 카피마다 이 근거를 답의 quote 필드에 적어 보냅니다. 게이트는 근거, 길이, 중복, 최상급 표현을 규칙으로 확인해 카피를 거르는 코드입니다. 최상급 표현은 「가장」, 「최고」처럼 무엇보다 낫다고 말하는 표현입니다. 자산에 없는 숫자나 최상급이 카피에 들어가면 그 광고는 심사(플랫폼이 광고를 내보내기 전에 검토하는 일)에서 빠지고 그 책임은 광고주가 집니다.

> **한 줄 요약:** 서연 씨의 런솔 라이트를 포함한 자산 텍스트 10개를 언어 모델 qwen3.5:27b 에 하나씩 보내 카피를 5개까지 쓰게 하면서 카피마다 기댄 구절을 자산에서 글자 그대로 옮긴 quote 를 함께 받았습니다. 답 10개는 모두 정해 둔 꼴대로 읽혔습니다. 상품의 사실 없이 인사만 적은 얇은 자산 2개에는 모델이 카피 대신 「생성 없음」을 뜻하는 no_generation 으로 답했습니다. 나머지 자산이 낸 카피 40개를 게이트에 차례로 넣자 35개가 남았습니다. 걸린 5개는 카피의 숫자가 맞았는데도 quote 에서 숫자 뒤에 공백이 끼어 자산의 글자와 달라져 모두 근거 게이트에서 걸렸습니다. 게이트는 자산과 글자가 다른 카피를 거를 뿐이라 자산의 구절을 그대로 옮긴 카피, 시스템 메시지(요청마다 모델에게 같이 보내는 할 일 설명)와 달리 「~하세요」로 끝난 카피, 「숲결 러닝화 가운데」라는 범위를 빼고 「가장 가벼운 모델」이라고 쓴 카피도 지났습니다. 과장과 말투는 다음 글이 판정으로 봅니다.

> **골라 읽는 법** — 절이 6개입니다. 절마다 있는 표나 코드나 카드만 보고 넘어가도 됩니다.
>
> - 광고주의 자산 텍스트 10개와 상품 사실이 없는 얇은 자산 2개 → 1절
> - 카피와 그 카피가 기댄 quote 를 짝으로 받는 답의 꼴 → 2절
> - 게이트 4개의 코드와 근거 게이트에 걸린 카피 5개 → 3절
> - 서연 씨 자산의 카피 5개가 받은 게이트 결과와 게이트가 보지 않는 것 → 4절
> - 카피를 쓰지 않은 답 no_generation 을 정상으로 다루는 까닭 → 5절
> - 담장 안과 열린 RTB 에서 카피를 만드는 때와 길이를 정하는 곳 → 6절

이 글의 자산 텍스트 10개는 설명을 위해 만든 가상 데이터입니다. 상품의 이름과 사실도 모두 지어낸 것이며 런솔, 모노웍스, 숲결은 이 트랙에 나오는 가상 브랜드입니다. 서연 씨의 자산(x01)은 30주째 [키워드 확장 전략](post.html?id=keyword-expansion-strategies) 편에 나온 상품 설명을 글자 그대로 가져왔습니다. 자산은 `scripts/gen-copy-data.py` 가 만들었습니다. 글의 코드 블록은 그 스크립트에 적힌 값(리터럴)을 글자 그대로 옮겼습니다. 반면 모델의 답은 지어낸 값이 아니라 2026-11-07 에 이 블로그를 쓰는 맥에서 Ollama 0.40.11 로 qwen3.5:27b 를 띄워 받은 기록입니다. Ollama 는 공개된 모델을 개인 컴퓨터에서 돌리는 도구입니다. 받은 답은 `data/llm-records/` 폴더의 `grounded-ad-copy-generation.json` 파일에 기록해 두었습니다.

## 1. 카피의 출발점인 자산 텍스트 10개

**모델은 광고주가 올린 자산 텍스트 하나만 읽고 카피를 쓰므로 카피에 들어갈 수 있는 사실은 그 글 안에 있는 것뿐입니다. 이 글의 자산 10개 가운데 8개는 상품의 사실을 적은 글이고 2개는 사실 없이 인사만 적은 얇은 자산입니다.**

카피가 자산에 없는 말을 했는지는 자산 텍스트에 어떤 사실과 숫자가 적혀 있는지 알아야 판단할 수 있습니다. 3절의 근거 게이트도 quote 와 카피의 숫자를 바로 자산 텍스트와 대조합니다.

광고주가 광고 도구에 올리는 상품 설명이 자산 텍스트입니다. 서연 씨의 x01 은 200자 안팎의 네 문장으로 되어 있습니다. 앞의 세 문장은 입문자용 러닝화라는 것, 밑창 전체에 깐 쿠션 폼, 한 짝 240g 의 무게, 넉넉한 앞코를 말합니다. 넷째 문장에는 230mm 부터 290mm 까지 5mm 단위로 나오는 사이즈와 받은 날부터 30일 안에 한 번 할 수 있는 교환이 들어 있습니다.

모델은 이 네 문장 말고는 런솔 라이트를 모르며 상품 데이터베이스나 웹을 찾아보지도 않고 받은 자산 텍스트 하나로 카피를 씁니다. 그래서 카피에 쓸 수 있는 사실도 이 네 문장에 적힌 것으로 한정됩니다.

RAG 는 질문에 맞는 문서 조각(청크)을 검색해 모델의 입력에 넣어 주고 그 조각을 보고 답하게 하는 방식입니다. 24주째 [RAG](post.html?id=rag-basics) 편은 답의 값이 받은 조각에 정말 있는지를 코드로 대조했습니다. 이 글도 같은 방식으로 대조하는데, 조각 자리에 자산 텍스트가 오고 답 자리에 카피가 옵니다.

x02 부터 x08 까지는 이 트랙의 가상 세계에 있는 다른 광고주의 상품으로, 러닝화 2개와 러닝 양말, GPS 러닝 시계, 러닝 벨트, 캠핑 의자, 제주 자유여행입니다. 글마다 120~200자이고 무게, 크기, 값, 기간 같은 숫자가 들어 있지만 건강이나 몸에 관한 효능은 넣지 않았습니다. x03(숲결 트레일 러닝화)에는 「숲결 러닝화 가운데 가장 가벼운 모델」이라는 최상급이 하나 있는데, 앞에 「숲결 러닝화 가운데」라는 범위가 붙어 있어 숲결의 러닝화 안에서 가장 가볍다는 뜻입니다.

얇은 자산은 x09 와 x10 입니다. x09 는 「달리는 아침을 응원합니다」로 시작하는 인사이고 x10 은 「새 단장을 마치고 다시 인사드립니다」로 시작하는 매장 안내입니다. 두 글 어디에도 무엇을 파는지, 값이 얼마인지, 크기가 어떤지가 없고 숫자도 하나 없습니다. 이런 글을 받은 모델이 카피를 지어내는지, 아니면 쓰지 않고 멈추는지를 보려고 두 글을 넣었습니다.

## 2. 카피마다 함께 받는 인용 구절 quote

**모델의 답은 상태 값 status 와 카피 목록으로 이루어지고 카피마다 문구 copy 와 그 문구가 기댄 구절 quote 가 짝으로 들어 있습니다. 답 10개는 모두 정해 둔 꼴(스키마)대로 읽혔고 no_generation 은 얇은 자산 2개에서만 나왔습니다. 사실을 적은 자산 8개에서는 카피가 5개씩, 모두 40개 나왔습니다.**

선배의 제안대로 모델은 카피를 쓸 때마다 기댄 구절을 자산에서 옮겨 적습니다. 그 구절이 정말 자산 안에 있는지는 코드가 확인하므로, 답에서 카피와 구절을 꺼낼 수 있게 시스템 메시지로 할 일과 답의 꼴을 정해 두었습니다.

시스템 메시지는 요청마다 모델에게 같이 보내는 할 일 설명입니다. 이 기록의 시스템 메시지는 카피를 5개까지, 카피 하나를 한국어 40자 이하로 쓰게 하고 카피마다 quote 를 붙이게 했습니다. quote 는 그 카피가 기댄 구절을 자산에서 글자 그대로 옮긴 문자열입니다. 또 구절을 옮길 때는 띄어쓰기와 문장 부호도 바꾸지 말라고 했고 카피에 든 사실은 모두 그 카피의 quote 안에 있어야 한다고 적었습니다. 숫자는 자산에 있는 숫자만 쓰고 최상급 표현은 자산에 그 말이 있을 때만 쓰게 했으며 문장 끝은 명사나 「~합니다」 꼴로 끝내게 했습니다. 전문은 글 끝의 더 깊이 보기에 있습니다.

자산에 상품의 사실이 부족해 카피를 쓸 수 없을 때는 status 를 no_generation 으로 두고 카피 목록을 비우게 했습니다. no_generation 은 「생성 없음」이라는 뜻의 값입니다. 카피를 하나라도 쓴 답은 status 가 ok 입니다.

답은 JSON 한 줄로 받았습니다. JSON 은 이름(키)과 값의 짝을 중괄호로 묶어 적는 데이터 꼴입니다. 이 답의 키는 status 와 candidates 2개이고 candidates 는 카피의 목록입니다. 목록의 항목 하나에는 copy 와 quote 두 문자열이 들어 있습니다.

근거를 구절의 글자로 받는 방식은 32주째 [LLM 라벨과 코드 랭커](post.html?id=llm-labels-code-ranker) 편과 다릅니다. 그 편은 근거를 문장 id 로 받았지만 이번에는 자산을 문장으로 나눠 보내지 않아 문장 id 가 없고 근거가 한 문장의 일부일 수도 있어서 구절의 글자를 그대로 받습니다.

스키마는 JSON 에 어떤 이름의 필드가 어떤 값으로 들어가는지 정해 둔 꼴입니다. 답을 스키마대로 읽는 방법은 22주째 [구조화 출력](post.html?id=structured-output) 편의 방법과 같습니다. 이 글은 키가 status 와 candidates 2개뿐이고 카피가 5개 이하이며 항목마다 copy 와 quote 두 문자열이 있을 때 읽은 답으로 봅니다. status 와 카피 목록이 서로 맞지 않는 답, 즉 status 가 ok 인데 카피가 하나도 없거나 no_generation 인데 카피가 있는 답은 읽지 못한 답으로 셉니다.

10번의 요청은 모두 thinking 을 끄고 temperature 0 으로 보냈습니다. thinking 은 모델이 답 앞에 풀이를 먼저 쓰는 설정으로 20주째 [LLM 모델 고르기](post.html?id=llm-model-selection) 편에서 보았습니다. temperature 는 모델이 다음 토큰(모델이 글을 나눠 읽고 쓰는 단위)을 얼마나 흔들리게 뽑을지 정하는 값입니다.

```python
def read_answer(text):
    try:
        answer = json.loads(text)
    except ValueError:
        return None
    if not (isinstance(answer, dict) and set(answer) == {'status', 'candidates'}):
        return None
    status, cands = answer['status'], answer['candidates']
    if status not in ('ok', 'no_generation') or not isinstance(cands, list) or len(cands) > 5:
        return None
    for c in cands:
        if not (isinstance(c, dict) and set(c) == {'copy', 'quote'}) or not all(isinstance(v, str) for v in c.values()):
            return None
    if (status == 'ok') != bool(cands):
        return None
    return answer


def span(values, digits=0):
    lo, hi = f'{min(values):.{digits}f}', f'{max(values):.{digits}f}'
    return lo if lo == hi else f'{lo}~{hi}'
```

## 3. 코드로 만든 게이트 4개

**카피 40개를 근거, 길이, 중복, 최상급 게이트에 차례로 넣자 35개가 남았습니다. 걸린 5개는 카피의 숫자가 모두 자산에 있었는데도 quote 에서 숫자 뒤에 공백이 끼어 자산의 글자와 달라져 근거 게이트에서 걸렸습니다. 이 기록에는 길이, 중복, 최상급 게이트에 걸린 카피가 없었습니다.**

카피 40개 가운데 자산에 없는 말을 한 카피를 사람이 하나하나 읽지 않고 고르려면 그 판단을 규칙으로 적어 코드에 맡겨야 합니다. 이 글은 그 규칙을 근거, 길이, 중복, 최상급의 게이트 4개로 나눴습니다.

근거 게이트는 두 가지를 확인합니다. quote 가 비어 있지 않으면서 자산 안에 글자 그대로 있어야 하고 카피에 든 숫자도 모두 자산에 있어야 합니다. 숫자는 쉼표를 지운 뒤 이어진 숫자 전체를 한 덩어리로 비교합니다. 그래서 「12,900」과 「12900」은 같은 숫자로 보며 자산에 1240 이 있어도 그 안의 240 은 자산에 있는 숫자로 치지 않습니다. 1240 과 240 은 다른 숫자이기 때문인데, 24주째 RAG 편이 답의 숫자를 조각에서 찾을 때 숫자의 앞뒤에 다른 숫자가 붙어 있지 않은지 본 것도 같은 까닭입니다. 카피의 숫자는 quote 와 대조하지 않고 자산 전체와 대조합니다.

길이 게이트는 카피의 len() 이 40 이하인지 봅니다. len() 은 파이썬이 문자열의 글자 수를 세는 함수로, 공백과 문장 부호도 한 글자로 셉니다.

중복 게이트는 카피를 같은 자산에서 앞서 게이트를 모두 지난 카피와 비교합니다. 비교할 때는 먼저 카피에서 공백을 모두 지우고 이웃한 두 글자씩 묶습니다. 이렇게 묶은 두 글자를 바이그램(bigram)이라고 부릅니다. 「달리기」의 바이그램은 「달리」와 「리기」 2개입니다. 띄어쓰기만 다른 두 카피를 같은 카피로 세려고 공백부터 지웁니다. 두 카피의 바이그램 집합으로는 Jaccard 를 계산합니다. Jaccard 는 두 집합의 교집합 크기를 합집합 크기로 나눈 값이라 두 집합이 같으면 1, 하나도 겹치지 않으면 0 입니다. 앞서 남은 카피 가운데 어느 하나와의 Jaccard 가 0.8 이상이면 같은 카피로 보고 거릅니다.

최상급 게이트는 최고, 최초, 1위, 유일, 가장, 국내 최대의 낱말 6개를 봅니다. 카피에 이 가운데 어느 낱말이 들어 있으면 그 낱말이 그 카피의 자산에도 있어야 지납니다.

카피는 근거부터 차례로 넣고 처음 걸린 게이트 하나에서만 셉니다. 그래서 근거에서 걸린 카피는 길이, 중복, 최상급을 거치지 않습니다. 블록의 게이트 정의는 생성기 `scripts/gen-copy-data.py` 에 있는 정의를 글자 그대로 옮겼습니다. 다음 글도 이 정의로 남은 카피를 가져갑니다.

게이트를 코드로 두면 같은 카피에는 언제나 같은 결과가 나오고 카피가 걸린 까닭도 게이트 이름 하나로 남습니다. 그러면 광고주에게도 「quote 가 자산에 없습니다」처럼 무엇을 고치면 되는지 바로 알려 줄 수 있습니다.

아래 블록은 게이트 4개를 정의하고 카피 40개를 차례로 넣어 카피마다 처음 걸린 게이트를 세려고 돌립니다. 3단계는 근거 게이트에 걸린 카피의 quote 아래에 자산의 같은 자리를 찍습니다. 4단계는 길이와 중복 게이트가 상한까지 얼마나 남았는지와 최상급 낱말이 든 카피를 찍습니다. 5단계는 손으로 만든 카피 5개로 게이트마다 걸리는 경우를 하나씩 보입니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 게이트 넷(근거, 길이, 중복, 최상급)을 차례로 지나며 카피마다 처음 걸린 게이트를 세고, 걸린 까닭과 남은 여유를 찍는다.
from collections import Counter
from itertools import combinations

# 1단계: 게이트 넷을 둔다
# 아래 정의는 scripts/gen-copy-data.py 의 것을 글자 그대로 옮겼다. 다음 판정 편도 같은 정의로 남은 카피를 가져간다.
# 근거는 quote 가 자산 안에 글자 그대로 있고, 카피의 숫자가 모두 자산에 있어야 지난다. 숫자는 쉼표를 지운 덩어리로 비교한다.
# 길이는 공백과 문장 부호를 포함한 len() 이 40 이하여야 지난다.
# 중복은 공백을 지운 뒤 글자 두 개씩 묶은 집합의 Jaccard 가, 같은 자산에서 앞서 남은 카피 모두와 0.8 보다 작아야 지난다.
# 최상급은 카피에 든 SUPERLATIVES 의 낱말이 모두 그 자산에도 있어야 지난다.
SUPERLATIVES = ['최고', '최초', '1위', '유일', '가장', '국내 최대']
NUMBER = re.compile(r'\d+(?:,\d{3})*(?:\.\d+)?')


def numbers(text):
    return {n.replace(',', '') for n in NUMBER.findall(text)}


def gate_grounding(copy, quote, asset):
    return bool(quote) and quote in asset and numbers(copy) <= numbers(asset)


def gate_length(copy, max_len=40):
    return len(copy) <= max_len


def bigrams(text):
    s = ''.join(text.split())
    return {s[i:i + 2] for i in range(len(s) - 1)}


def jaccard(a, b):
    return len(a & b) / len(a | b) if a | b else 1.0


def gate_duplicate(copy, kept):
    return all(jaccard(bigrams(copy), bigrams(k)) < 0.8 for k in kept)


def gate_superlative(copy, asset):
    return all(word in asset for word in SUPERLATIVES if word in copy)


# 2단계: 카피를 게이트에 차례로 넣는다
# judge_copies 는 카피마다 처음 걸린 게이트 하나만 적고, 다 지나면 None 을 적는다. passing_copies 는 다 지난 카피만 돌려준다.
# 중복 게이트가 비교하는 kept 는 같은 답 안에서 앞서 네 게이트를 다 지난 카피다.
def judge_copies(record, assets):
    rows = []
    for aid, text in record.items():
        answer = read_answer(text)
        if answer is None:
            continue
        asset, kept = assets[aid], []
        for n, c in enumerate(answer['candidates'], 1):
            copy, quote = c['copy'], c['quote']
            if not gate_grounding(copy, quote, asset):
                failed = 'grounding'
            elif not gate_length(copy):
                failed = 'length'
            elif not gate_duplicate(copy, kept):
                failed = 'duplicate'
            elif not gate_superlative(copy, asset):
                failed = 'superlative'
            else:
                failed = None
                kept.append(copy)
            rows.append((aid, n, copy, quote, failed))
    return rows


def passing_copies(record, assets):
    return [(aid, n, copy, quote) for aid, n, copy, quote, failed in judge_copies(record, assets) if failed is None]


rows = judge_copies(RECORD, ASSET)
kept = passing_copies(RECORD, ASSET)
failed = Counter(r[4] for r in rows)
print(f'카피 {len(rows)}개 → 근거 {failed["grounding"]}, 길이 {failed["length"]}, 중복 {failed["duplicate"]}, '
      f'최상급 {failed["superlative"]} → 남은 카피 {len(kept)}개')
left = Counter(aid for aid, n, copy, quote in kept)
print('자산마다 남은 카피: ' + ', '.join(f'{aid} {left[aid]}' for aid in ASSET if answers[aid]['status'] == 'ok'))

# 3단계: 근거 게이트에 걸린 카피를 본다
# quote 가 자산 안에 없어서인지, 카피의 숫자가 자산에 없어서인지 나눠 센다.
# 공백을 무시하고 quote 를 자산에서 찾아, 자산의 그 자리를 quote 아래에 찍는다.
def asset_span(quote, asset):
    found = re.search(r'\s*'.join(re.escape(ch) for ch in quote if not ch.isspace()), asset)
    return found.group(0) if found else None


bad = [r for r in rows if r[4] == 'grounding']
print(f'quote 가 자산 안에 없음 {sum(r[3] not in ASSET[r[0]] for r in bad)}, '
      f'카피의 숫자가 자산에 없음 {sum(not numbers(r[2]) <= numbers(ASSET[r[0]]) for r in bad)}, '
      f'공백을 무시하면 자산 안에 있음 {sum(asset_span(r[3], ASSET[r[0]]) is not None for r in bad)}')
for aid, n, copy, quote, f in bad:
    print(f'  {aid}-{n} quote 「{quote}」')
    print(f'        자산 「{asset_span(quote, ASSET[aid])}」')

# 4단계: 길이, 중복, 최상급 게이트의 여유를 본다
# 가장 긴 카피, 같은 자산 안에서 Jaccard 가 가장 큰 두 카피와 그 quote, 최상급 낱말이 든 카피와 그 낱말이 든 자산 문장을 찍는다.
aid, n, copy, quote, f = max(rows, key=lambda r: len(r[2]))
print(f'가장 긴 카피 {aid}-{n} {len(copy)}자')
best = max((jaccard(bigrams(a[2]), bigrams(b[2])), a, b) for a, b in combinations(rows, 2) if a[0] == b[0])
print(f'같은 자산 안에서 Jaccard 가 가장 큰 쌍 {best[1][0]}-{best[1][1]}, {best[2][0]}-{best[2][1]} {best[0]:.2f}, '
      f'두 카피의 quote 가 같은가 {best[1][3] == best[2][3]}')
for r in best[1:]:
    print(f'  {r[0]}-{r[1]} 「{r[2]}」 quote 「{r[3]}」')
for aid, n, copy, quote, f in rows:
    for word in SUPERLATIVES:
        if word in copy:
            sentence = next(s for s in re.split(r'(?<=\.) ', ASSET[aid]) if word in s)
            print(f'최상급 「{word}」 {aid}-{n} 「{copy}」 {f or "통과"}')
            print(f'  자산 문장 「{sentence}」')

# 5단계: 손으로 만든 카피 다섯으로 게이트를 시험한다
# x01 자산에 카피 다섯을 적은 답을 만들어 같은 함수에 넣는다. 첫 카피는 지나고, 나머지는 하나씩 다른 게이트에 걸리게 만들었다.
TESTS = [('입문자용 러닝화, 한 짝 240g', '한 짝 무게 240g 으로 가볍고'),
         ('입문자용 러닝화,한 짝 240g', '한 짝 무게 240g 으로 가볍고'),
         ('무게 200g 의 가벼운 입문자용 러닝화', '한 짝 무게 240g 으로 가볍고'),
         ('쿠션 폼을 깐 입문자용 러닝화, 230mm 부터 290mm 까지 5mm 단위로 고릅니다', '사이즈는 230mm 부터 290mm 까지 5mm 단위로 있고'),
         ('가장 가벼운 입문자용 러닝화', '입문자용 러닝화입니다')]
test = json.dumps({'status': 'ok', 'candidates': [{'copy': c, 'quote': q} for c, q in TESTS]}, ensure_ascii=False)
for aid, n, copy, quote, f in judge_copies({'x01': test}, ASSET):
    print(f'시험 {n} {f or "통과"} {len(copy)}자 「{copy}」')

# 2단계 뜻: 카피 40개 가운데 근거 게이트에서 5개가 걸려 35개가 남았고, x08 은 1개만 남았다.
# 카피 40개 → 근거 5, 길이 0, 중복 0, 최상급 0 → 남은 카피 35개
# 자산마다 남은 카피: x01 5, x02 5, x03 5, x04 4, x05 5, x06 5, x07 5, x08 1
# 3단계 뜻: 걸린 5개는 모두 quote 의 숫자 뒤에 공백이 끼어 자산의 글자와 달랐다. 카피의 숫자는 모두 자산에 있었다.
# quote 가 자산 안에 없음 5, 카피의 숫자가 자산에 없음 0, 공백을 무시하면 자산 안에 있음 5

#         자산 「출발 7일 전까지 취소하면 낸 돈을 모두 돌려 드립니다」
# 4단계 뜻: 길이와 중복은 상한에 닿지 않았고, quote 가 같은 x04 의 두 카피도 0.50 이다. x03-5 는 「가장」이 자산에 있어 지났다.
# 가장 긴 카피 x01-2 39자
# 같은 자산 안에서 Jaccard 가 가장 큰 쌍 x04-2, x04-5 0.50, 두 카피의 quote 가 같은가 True
#   x04-2 「물에 빨아도 쉽게 늘어나지 않는 러닝 전용 양말입니다」 quote 「물에 빨아도 쉽게 늘어나지 않습니다」
#   x04-5 「달릴 때 신는 러닝 전용 양말로 물에 빨아도 늘어나지 않습니다」 quote 「물에 빨아도 쉽게 늘어나지 않습니다」
# 최상급 「가장」 x03-5 「가장 가벼운 모델로 한 짝 무게는 280g 입니다」 통과
#   자산 문장 「숲결 러닝화 가운데 가장 가벼운 모델로, 한 짝 무게는 280g 입니다.」
```

2단계가 찍은 값은 카피 40개 가운데 근거 게이트에서 5개가 걸리고 길이, 중복, 최상급에서는 하나도 걸리지 않아 40개에서 5개를 뺀 35개가 남았다는 뜻입니다. 자산별로는 x04(러닝 양말)가 4개, x08(제주 자유여행)이 1개만 남았고 나머지 자산은 5개씩 그대로 남았습니다.

카피 이름은 자산 번호 뒤에 그 답의 몇째 카피인지를 붙인 것으로, x04-3 은 x04 의 셋째 카피입니다. 걸린 5개는 x04-3 하나와 x08 의 카피 4개(x08-1, x08-2, x08-4, x08-5)입니다. 3단계가 quote 아래에 찍은 자산의 같은 자리와 비교해 보면 5개 모두 quote 에서 숫자와 그 뒤의 한글 사이에 공백이 끼어 있습니다. 자산의 「2박 3일」이 quote 에서는 「2 박 3 일」로, 「12,900원」은 「12,900 원」으로 바뀌었습니다.

카피의 숫자가 자산에 없는 카피는 0개였고 공백을 무시하면 quote 5개가 모두 자산 안에 있으므로, 5개는 숫자를 틀려서가 아니라 시스템 메시지가 바꾸지 말라고 한 띄어쓰기가 quote 에서 바뀌어서 걸렸습니다. x08 에서 남은 하나는 셋째 카피로, 이 카피의 quote 「위탁 수하물은 15kg 까지 부칠 수 있고」는 자산의 글자와 같았습니다.

4단계가 찍은 값은 길이와 중복 게이트가 상한에 얼마나 가까웠는지와 최상급 낱말이 든 카피를 보여 줍니다. 가장 긴 카피는 x01-2 의 39자로 길이 상한 40자보다 한 글자 짧았습니다. 같은 자산 안에서 Jaccard 가 가장 큰 쌍은 x04-2 와 x04-5 였습니다. 두 카피는 quote 가 같았지만(True) 문장이 달라서 겹치는 바이그램이 합친 바이그램의 꼭 절반이라 Jaccard 가 0.50 이었습니다. 같은 카피로 보는 0.8 에는 한참 못 미칩니다. 「가장」이 든 카피는 x03-5 하나였는데, x03 의 자산 문장 「숲결 러닝화 가운데 가장 가벼운 모델로, 한 짝 무게는 280g 입니다.」에 「가장」이 있어 최상급 게이트를 지났습니다. 아래 표에 블록이 찍은 값을 게이트마다 모았습니다.

| 게이트 | 지나는 조건 | 이 기록에서 걸린 카피 | 블록이 함께 찍은 값 |
|---|---|---|---|
| 근거 | quote 가 자산 안에 글자 그대로, 카피의 숫자가 모두 자산에 | 5개 | 숫자가 자산에 없는 카피 0개 |
| 길이 | len() 40 이하 | 0개 | 가장 긴 카피 39자 |
| 중복 | 앞서 남은 카피와 Jaccard 0.8 미만 | 0개 | 가장 큰 Jaccard 0.50 |
| 최상급 | 카피에 든 최상급 낱말이 자산에도 있음 | 0개 | 「가장」이 든 x03-5 는 자산에 「가장」 |

5단계의 손으로 만든 카피 5개 가운데 시험 1 은 모든 게이트를 지났고 나머지 4개는 게이트 4개에 하나씩 걸렸습니다. 시험 2 「입문자용 러닝화,한 짝 240g」은 시험 1 「입문자용 러닝화, 한 짝 240g」과 쉼표 뒤의 띄어쓰기 하나만 다릅니다. 공백을 지우면 둘 다 「입문자용러닝화,한짝240g」이 되어 바이그램 집합이 같아집니다. 두 집합이 같으면 교집합과 합집합도 같으므로 Jaccard 는 1 이 되고 0.8 이상이라 시험 2 는 중복 게이트에 걸렸습니다.

시험 3 「무게 200g 의 가벼운 입문자용 러닝화」는 x01 자산에 없는 숫자 200 을 써서 근거 게이트에 걸렸습니다. 48자인 시험 4 는 40자를 넘어 길이 게이트에 걸렸습니다. 도입에 나온 예전 문구처럼 「가장 가벼운」을 넣은 시험 5 는 x01 자산에 「가장」이 없어 최상급 게이트에 걸렸습니다. 이 기록에서 0개였던 길이, 중복, 최상급 게이트도 이런 카피가 들어오면 걸러 냅니다.

그러면 숫자 뒤에 낀 공백은 어떻게 다뤄야 할까요? 공백을 무시하고 대조하면 걸린 5개가 모두 지나지만 그 대신 게이트가 자산의 글자와 다른 quote 를 받아 줍니다. 이 글은 시스템 메시지가 정한 「글자 그대로」를 지키고 걸린 카피는 까닭을 붙여 다시 쓰게 하는 방식을 택합니다. 띄어쓰기를 바꾼 quote 가 늘어나면 그때 숫자 뒤의 공백만 맞추는 규칙을 추가하는 편이 안전합니다.

## 4. 게이트를 모두 지난 서연 씨 자산의 카피 5개

**서연 씨 자산 x01 의 카피 5개는 게이트 4개를 모두 지났지만 그 가운데 3개는 quote 와 글자까지 같아 자산의 구절을 그대로 옮긴 카피였습니다. 남은 카피 35개 전체에서는 13개가 quote 와 같았고 2개는 「~하세요」로 끝났습니다.**

게이트를 지났다고 좋은 카피라는 뜻은 아니므로 서연 씨가 부탁한 런솔 라이트의 카피 5개를 게이트마다 따로 보고 문구를 하나씩 읽습니다. 그다음 남은 카피 전체에서 게이트가 보지 않는 것을 셉니다.

3절 블록에서 카피를 게이트에 넣은 함수 judge_copies 는 카피마다 처음 걸린 게이트에서 멈추므로 뒤 게이트의 결과는 남기지 않습니다. 아래 블록은 x01 의 카피마다 게이트 4개를 따로따로 돌려 지나면 O, 걸리면 X 로 찍고 quote 가 자산의 몇째 문장에서 왔는지도 찍습니다. 2단계는 한글을 두 자로 센 길이를 찍습니다. 3단계는 남은 35개에서 게이트가 보지 않는 것 2가지, 곧 quote 를 글자 그대로 쓴 카피와 「요」로 끝나는 카피를 셉니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 서연 씨 자산 x01 의 카피 다섯을 quote 와 함께 찍고 게이트 넷의 결과를 따로따로 보인 뒤, 남은 카피 전체에서 게이트가 보지 않는 것을 센다.

# 1단계: x01 의 카피를 게이트 넷에 따로따로 넣는다
# 2 블록의 judge_copies 는 처음 걸린 게이트에서 멈춘다. 여기서는 네 게이트를 모두 돌려 지나면 O, 걸리면 X 로 찍는다.
# 중복 게이트는 그 카피 앞에서 남은 카피와 비교한다. 문장 번호는 quote 가 든 자산 문장의 차례다.
asset = ASSET['x01']
sentences = re.split(r'(?<=\.) ', asset)
kept01 = []
for n, c in enumerate(answers['x01']['candidates'], 1):
    copy, quote = c['copy'], c['quote']
    marks = [gate_grounding(copy, quote, asset), gate_length(copy), gate_duplicate(copy, kept01), gate_superlative(copy, asset)]
    if all(marks):
        kept01.append(copy)
    where = next((i for i, s in enumerate(sentences, 1) if quote in s), None)
    ox = ' '.join(f'{name} {"O" if m else "X"}' for name, m in zip(['근거', '길이', '중복', '최상급'], marks))
    print(f'{n} {ox}, {len(copy)}자, 자산 문장 {where}')
    print(f'  카피 「{copy}」')
    print('  quote 카피와 같음' if copy == quote else f'  quote 「{quote}」')

# 2단계: 한글을 두 자로 세면 길이가 달라진다
# 한글 한 글자를 2, 공백과 숫자와 영문을 1 로 센다. 그렇게 센 길이로 30 이하와 90 이하에 드는 카피를 센다.
def double_width(text):
    return sum(2 if '가' <= ch <= '힣' else 1 for ch in text)


widths = [double_width(c['copy']) for c in answers['x01']['candidates']]
print('한글을 두 자로 센 길이: ' + ', '.join(map(str, widths)))
print(f'30 이하 {sum(w <= 30 for w in widths)}/{len(widths)}, 90 이하 {sum(w <= 90 for w in widths)}/{len(widths)}')

# 3단계: 남은 카피 전체에서 게이트가 보지 않는 것을 센다
# quote 를 글자 그대로 카피로 쓴 것과, 시스템 메시지의 말투 줄과 달리 「요」로 끝나는 것이다.
same = [f'{aid}-{n}' for aid, n, copy, quote in kept if copy == quote]
print(f'남은 {len(kept)}개 가운데 quote 와 글자까지 같은 카피 {len(same)}개')
yo = [(aid, n, copy, quote) for aid, n, copy, quote in kept if copy.endswith('요')]
print(f'「요」로 끝나는 카피 {len(yo)}개')
for aid, n, copy, quote in yo:
    print(f'  {aid}-{n} 「{copy}」 quote 「{quote}」')
# 출력:
# 1단계 뜻: x01 의 다섯은 네 게이트를 모두 지났고, 1, 2, 5번은 quote 와 같은 문장이다.
# 1 근거 O 길이 O 중복 O 최상급 O, 31자, 자산 문장 1
#   카피 「달리기를 처음 시작하는 사람을 위한 입문자용 러닝화입니다」
#   quote 카피와 같음
# 2 근거 O 길이 O 중복 O 최상급 O, 39자, 자산 문장 2
#   카피 「밑창 전체에 쿠션 폼을 깔아 착지할 때 발바닥에 오는 충격을 줄였습니다」
#   quote 카피와 같음
# 3 근거 O 길이 O 중복 O 최상급 O, 34자, 자산 문장 3
#   카피 「한 짝 무게 240g 으로 가볍고 앞코를 넉넉하게 만들었습니다」
#   quote 「한 짝 무게 240g 으로 가볍고, 발볼이 넓은 사람도 편하게 신도록 앞코를 넉넉하게 만들었습니다」
# 4 근거 O 길이 O 중복 O 최상급 O, 35자, 자산 문장 4
#   카피 「사이즈는 230mm 부터 290mm 까지 5mm 단위로 있습니다」
#   quote 「사이즈는 230mm 부터 290mm 까지 5mm 단위로 있고」
# 5 근거 O 길이 O 중복 O 최상급 O, 28자, 자산 문장 4
#   카피 「받은 날부터 30일 안에 한 번 교환할 수 있습니다」
#   quote 카피와 같음
# 2단계 뜻: 한글을 두 자로 세면 다섯 모두 30 을 넘고 90 안에 든다.
# 한글을 두 자로 센 길이: 56, 68, 56, 50, 46
# 30 이하 0/5, 90 이하 5/5
# 3단계 뜻: 남은 카피 가운데 13개는 quote 그대로이고, 「요」로 끝나는 x07 의 두 카피도 게이트를 지났다.
# 남은 35개 가운데 quote 와 글자까지 같은 카피 13개
# 「요」로 끝나는 카피 2개
#   x07-1 「접으면 두께 10cm 로 가볍게 들고 다니세요」 quote 「접으면 두께가 10cm 이고」
#   x07-4 「수납 가방을 함께 드려 편리하게 보관하세요」 quote 「수납 가방을 함께 드리고」
```

1단계에서 카피 5개는 게이트 4개에서 모두 O 를 받았습니다. 1번 「달리기를 처음 시작하는 사람을 위한 입문자용 러닝화입니다」는 자산 문장 1 에서 주어를 뺐습니다. 2번 「밑창 전체에 쿠션 폼을 깔아 착지할 때 발바닥에 오는 충격을 줄였습니다」는 자산 문장 2 를 그대로 옮겼으며 39자라 상한 40자보다 한 글자 짧은데, 3절 4단계가 찍은 가장 긴 카피 x01-2 가 바로 이 카피입니다. 3번 「한 짝 무게 240g 으로 가볍고 앞코를 넉넉하게 만들었습니다」는 자산 문장 3 의 가운데에 있던 「발볼이 넓은 사람도 편하게 신도록」을 뺐습니다. 4번과 5번은 자산 문장 4 를 앞뒤로 나눠 사이즈와 교환을 따로 말합니다.

| 카피 | 말하는 것 | 자산 문장 | 길이 | 한글을 두 자로 센 길이 | quote |
|---|---|---|---|---|---|
| 1 | 입문자용 러닝화 | 1 | 31자 | 56 | 카피와 같음 |
| 2 | 쿠션 폼과 착지 | 2 | 39자 | 68 | 카피와 같음 |
| 3 | 240g 과 넉넉한 앞코 | 3 | 34자 | 56 | 문장 전체 |

| 5 | 30일 안의 교환 한 번 | 4 | 28자 | 46 | 카피와 같음 |

quote 와 같은 카피 3개(1, 2, 5번)는 상품 설명의 글자를 그대로 옮긴 문구라서 근거 게이트는 반드시 지나지만 검색 결과에서 눈에 띄는 광고 문구라고 하기는 어렵습니다. 5개 모두 「~니다」로 끝나는 설명 문장이고 상품 이름 런솔 라이트는 5개 어디에도 없는데, 게이트는 이런 것을 보지 않습니다.

길이도 무엇으로 세느냐에 따라 달라집니다. 길이 게이트의 함수 gate_length 는 len() 으로 세므로 한글 한 글자와 공백 하나를 똑같이 1 로 셉니다. 그런데 Google Ads 의 반응형 검색 광고 문서는 광고 제목을 30자, 설명을 90자까지로 적었고 한국어, 일본어, 중국어 같은 2바이트 언어는 글자 하나를 두 자로 계산한다고 적었습니다. 2단계는 이 규칙대로 한글 한 글자를 2, 공백과 숫자와 영문을 1 로 세어 56, 68, 56, 50, 46 을 찍었습니다. len() 으로 28자인 5번 「받은 날부터 30일 안에 한 번 교환할 수 있습니다」는 그 가운데 한글 18자를 한 자씩 더 세어 46 이 됩니다. 이렇게 세면 가장 짧은 5번의 46 도 광고 제목 상한 30 을 넘고 가장 긴 2번의 68 도 설명 상한 90 안에 들어, 30 이하는 0/5 이고 90 이하는 5/5 입니다.

x01 밖으로 넓혀 3단계가 센 값을 보면 남은 35개 가운데 13개가 quote 와 글자까지 같았고 「요」로 끝나는 카피도 2개 남았습니다. x07(캠핑 의자)의 1번 「접으면 두께 10cm 로 가볍게 들고 다니세요」와 4번 「수납 가방을 함께 드려 편리하게 보관하세요」입니다. 시스템 메시지의 말투 줄은 문장 끝을 명사나 「~합니다」 꼴로 끝내라고 했지만 게이트 4개는 말투를 보지 않아 둘 다 지났습니다. 게다가 1번에 쓴 「가볍게」는 그 카피의 quote 「접으면 두께가 10cm 이고」에 없는 말입니다.

지금까지 본 카피는 모두 사실을 적은 자산 8개에서 나왔습니다. 5절에서는 카피를 쓰지 않은 얇은 자산 2개의 답을 봅니다.

## 5. 정상 답으로 다루는 생성 없음(no_generation)

**얇은 자산 2개의 답은 둘 다 no_generation 이었고 출력은 12 토큰씩이었습니다. 쓸 사실이 없는 자산에 카피를 쓰지 않은 이 답이 맞는 답입니다. 코드는 이 답을 실패로 세지 않고 정상인 결과로 다룹니다.**

x09 와 x10 은 시스템 메시지가 정한 꼴 그대로 `{"status": "no_generation", "candidates": []}` 한 줄로 답했습니다. 1절에서 본 대로 두 자산에는 상품도 숫자도 없었습니다. 이 기록에서 no_generation 은 얇은 자산에서만 나왔고 사실을 적은 자산 8개는 모두 ok 였습니다.

얇은 자산에도 카피를 꼭 5개 쓰라고 하면 모델은 자산에 없는 사실을 지어내거나 인사말을 그대로 카피로 옮기는 수밖에 없습니다. 지어낸 사실을 담은 카피도 quote 만 자산에서 옮겨 오고 숫자를 쓰지 않으면 근거 게이트를 지납니다. 인사말을 옮긴 카피는 quote 가 자산 안에 그대로 들어 있어 게이트 4개를 모두 지납니다. 그래서 쓸 사실이 없다는 판단은 게이트가 아니라 카피를 쓰는 모델이 해야 합니다.

코드는 no_generation 을 읽지 못한 답과도, 게이트에 걸린 카피와도 따로 셉니다. 2절 블록에서 답을 스키마대로 읽는 함수 read_answer 는 status 가 no_generation 인 답에 카피가 하나도 없어야 그 답을 읽은 답으로 봅니다. 광고 도구는 이 답을 받으면 카피 대신 정해 둔 안내 문장을 보여 줍니다. 이렇게 미리 써 두고 그대로 보여 주는 문장을 템플릿이라고 부릅니다. 안내 문장을 보이는 방식은 28주째 [자연어 → 타겟 조건](post.html?id=nl-to-targeting-query) 편이 거절 이유를 고정 템플릿으로 알린 방식과 같습니다. 안내 문장에는 무게, 크기, 값, 교환 조건처럼 적어 주면 카피가 될 사실의 종류를 적습니다.

no_generation 은 비용도 적게 듭니다. 아래 표처럼 no_generation 의 답은 ok 의 답보다 출력 토큰도 시간도 훨씬 적습니다. 다만 no_generation 이 몇 개 나오는지는 따로 지켜봐야 합니다. 사실을 적은 자산에서 no_generation 이 늘어나면 시스템 메시지가 너무 엄격하다는 신호입니다. 이 기록에서는 그런 신호가 없었고 사실을 적은 자산 8개 모두 ok 로 왔습니다.

| 자산 | 적힌 것 | status | 카피 | 출력 토큰 | 시간 |
|---|---|---|---|---|---|
| x01~x08 | 상품의 사실과 숫자 | ok | 5개씩 | 179~263 | 12.2~27.6초 |
| x09 | 달리는 아침을 응원하는 인사 | no_generation | 0개 | 12 | 1.6초 |
| x10 | 새 단장 인사와 매장 안내 | no_generation | 0개 | 12 | 1.4초 |

네 번째 카드에서는 상품 사실이 없는 자산 2개에 모델이 카피 대신 no_generation 을 낸 답과 그 답의 출력 토큰을 보면 됩니다.

## 6. 카피를 만드는 때와 길이를 정하는 곳의 무대별 차이

**자산에서 인용해 카피를 쓰고 코드가 거르는 순서는 두 무대에서 같습니다. 담장 안(한 회사가 서비스와 광고 서버를 다 가진 곳)에서는 플랫폼이 자산과 게이트와 길이 규칙을 함께 갖습니다. 열린 RTB(여러 회사가 실시간 경매로 남의 광고 자리를 사고파는 곳)에서는 광고주를 대신해 입찰하는 DSP 가 그 자리가 정한 길이에 맞는 카피를 골라 보냅니다.**

1~5절의 계산은 두 무대에서 같습니다. 두 무대는 자산을 누가 갖고 카피의 길이를 누가 정하느냐만 다릅니다. 담장 안은 닫힌 생태계라고도 부릅니다. 두 무대의 이름은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에 풀이가 있습니다.

### 담장 안: 자산과 게이트와 길이 규칙을 함께 둔 플랫폼 [무대: 닫힌 생태계]

검색 광고를 파는 플랫폼은 광고주가 올린 자산 텍스트, 광고가 실리는 자리인 지면, 광고 심사를 모두 자기가 갖습니다. 그래서 광고주가 자산을 올릴 때 카피를 만들고 게이트를 지난 카피만 광고주에게 보입니다. 걸린 카피에는 게이트 이름이 남으므로 심사 전에 무엇을 고칠지도 알려 줄 수 있습니다.

플랫폼은 회원이 검색해 요청이 들어올 때마다 카피를 만들지 않고 광고주가 자산을 올릴 때 미리 만들어 둡니다. 이 기록에서 ok 로 온 답은 자산 하나에 12.2~27.6초가 걸렸습니다. 길이 상한도 플랫폼이 정한 광고 규칙입니다. 그 규칙이 Google Ads 처럼 한국어를 두 자로 센다면 gate_length 도 그 규칙대로 세어야 합니다.

### 열린 RTB: 지면이 정한 길이에 맞는 카피를 고르는 DSP [무대: 열린 RTB]

열린 RTB 의 DSP 는 여러 매체의 네이티브 광고 지면에 입찰합니다. 네이티브 광고는 매체의 글이나 목록과 같은 모양으로 섞여 보이는 광고입니다. 입찰 요청은 광고 자리를 경매에 부치는 거래소가 지면 하나에 낼 광고를 정해 달라며 DSP 에 보내는 요청입니다.

OpenRTB 는 거래소와 DSP 가 입찰 요청과 응답을 주고받을 때 쓰는 표준 규격입니다. OpenRTB 네이티브 광고 명세 1.2 는 입찰 요청 안의 제목 자산에 len 필드를 둡니다. 여기서 자산(asset)은 네이티브 광고를 이루는 제목이나 설명 같은 요소를 가리켜 이 글의 자산 텍스트와는 뜻이 다릅니다. len 은 제목 글의 최대 길이로, 명세는 그 값으로 25, 90, 140 을 권합니다. 설명 글(desc)은 길면 거래소가 자르거나 말줄임표로 줄일 수 있다고도 적었습니다.

그래서 DSP 는 게이트를 지난 카피를 길이별로 미리 만들어 두었다가 요청의 len 에 맞는 카피를 고릅니다. 이때 gate_length 의 길이 상한 max_len(지금은 40)은 요청마다 바뀌는 값이 됩니다. 자산과 게이트는 DSP 에 있지만 길이 규칙은 지면을 가진 매체에 있습니다. 아래 표의 내용은 가상 데이터가 아니라 두 무대의 설계 차이입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 자산 텍스트를 가진 쪽 | 플랫폼 | DSP |
| 카피를 만드는 때 | 자산을 올릴 때 | 자산을 올릴 때, 길이별로 |
| 길이 상한을 정하는 쪽 | 플랫폼의 광고 규칙 | 입찰 요청마다 지면의 len |
| gate_length 의 max_len | 고정된 값 | 요청마다 다른 값 |

## 한눈 정리

| 자리 | 무엇을 보나 | 이 기록의 숫자 |
|---|---|---|
| 답 읽기 | status 와 카피 목록이 스키마대로인가 | 10/10 읽음 |
| 생성 없음 | 쓸 사실이 없으면 no_generation | x09, x10, 답은 12 토큰 |
| 근거 게이트 | quote 가 자산 안에, 숫자가 자산 안에 | 5개 걸림, 모두 숫자 뒤 공백 |
| 길이 게이트 | len() 40 이하 | 0개, 가장 긴 카피 39자 |
| 중복 게이트 | 공백을 뺀 바이그램의 Jaccard 0.8 미만 | 0개, 가장 큰 값 0.50 |
| 최상급 게이트 | 카피에 든 최상급 낱말이 자산에도 있는가 | 0개, x03-5 는 지남 |

## 헷갈리기 쉬운 점

- **인용이 있어도 카피가 과장일 수 있습니다.** 근거 게이트는 quote 가 자산 안에 있는지와 카피의 숫자가 자산에 있는지만 볼 뿐, 카피가 자산의 뜻을 넘어서는지는 보지 않습니다. x03-5 「가장 가벼운 모델로 한 짝 무게는 280g 입니다」는 자산 문장의 「숲결 러닝화 가운데」라는 범위를 빼서 무엇 가운데 가장 가벼운지가 사라졌는데, 「가장」은 자산에 있는 낱말이라 최상급 게이트도 지났습니다. x04-5 도 quote 「물에 빨아도 쉽게 늘어나지 않습니다」의 「쉽게」를 빼고 「늘어나지 않습니다」라고 단정했습니다. 공정거래위원회 고시는 「최대」, 「최고」, 「최초」 같은 절대적 표현을 부당한 광고의 예로 듭니다. 고시는 이런 표현은 사실임을 입증하고 경쟁사업자나 소비자에게 피해가 없을 때만 쓸 수 있다고 적었습니다.
- **길이는 글자 수로 셉니다.** gate_length 는 공백과 문장 부호를 포함한 len() 이 40 이하인지 보므로 한글 한 글자도 공백 하나도 똑같이 1 입니다. 같은 카피를 한국어를 두 자로 세는 Google Ads 규칙으로 세면 x01 의 카피 5개는 46~68 이 됩니다. 「40자」 같은 상한은 카피가 나갈 자리의 규칙에 맞춰 정하고 그 규칙대로 세어야 합니다.
- **게이트를 지나도 좋은 카피라는 뜻은 아닙니다.** 게이트는 자산과 다른 글자와 숫자를 거를 뿐 더 나은 카피를 고르지는 않습니다. 남은 35개를 보면 13개가 자산의 구절을 그대로 옮겼고 2개가 「~하세요」로 끝났습니다. x04 의 2번과 5번은 같은 quote 에 기댄 두 카피인데도 Jaccard 가 0.50 이라 중복 게이트를 지났습니다. 남은 카피 가운데 어느 카피를 내보낼지는 다음 36주째 [생성 문구 판정 체계](post.html?id=generated-copy-judging-system) 편에서 판정으로 정합니다.

```text
{"status": "<ok|no_generation>", "candidates": [{"copy": "<한국어 40자 이하>", "quote": "<자산에서 그대로 옮긴 구절>"}]}
```

기록은 2026-11-07 에 받았고 10번 모두 thinking 을 끄고 temperature 0, seed 7 로 보냈습니다. 「1인칭 대명사」 줄은 카피가 광고주 자신을 1인칭으로 부르는 말을 막으려고 넣었습니다. 시스템 메시지를 고쳐 다시 기록하지 않았고 답 10개는 모두 스키마대로 읽혔습니다. x07 의 「~하세요」 2개는 말투 줄을 어긴 답이지만 기록을 그대로 두고 게이트가 말투를 보지 않는 예로 씁니다. 띄어쓰기가 바뀐 quote 를 보고 시스템 메시지를 고치면, 결과를 보고 고친 프롬프트가 됩니다.

이 기록으로 말할 수 없는 것도 3가지입니다. 자산 10개에 기록 한 벌이라, 숫자 뒤의 공백이 다른 자산에서도 끼는지는 모릅니다. x01 의 「30일」처럼 그대로 옮긴 숫자도 있었습니다. 자산은 제가 쓴 가상 글이라, 실제 광고주의 글은 더 길고 문장이 더 복잡할 수 있습니다. 얇은 자산 2개가 no_generation 이었던 것도 이 두 글의 결과입니다. 상품 이름 하나만 적은 글처럼 사실이 조금 있는 자산에서는 다를 수 있습니다.
:::

:::deep 게이트 식
네 게이트를 식으로 적습니다. $c$ 는 카피, $q$ 는 quote, $A$ 는 자산 텍스트, $K$ 는 같은 자산에서 앞서 남은 카피의 집합입니다. $N(x)$ 는 글 $x$ 에 든 숫자의 집합이고 숫자는 쉼표를 지운 덩어리입니다.

$$\text{grounding}(c, q, A) = [\, q \ne \varnothing \;\wedge\; q \sqsubseteq A \;\wedge\; N(c) \subseteq N(A) \,]$$

$q \sqsubseteq A$ 는 $q$ 가 $A$ 의 이어진 부분 문자열이라는 뜻입니다. 숫자는 $N(q)$ 가 아니라 $N(A)$ 와 대조합니다.

$$\text{length}(c) = [\, |c| \le 40 \,]$$

$|c|$ 는 공백과 문장 부호를 포함한 글자 수입니다.

$$J(X, Y) = \frac{|X \cap Y|}{|X \cup Y|}, \qquad \text{duplicate}(c, K) = [\, \forall k \in K : J(B(c), B(k)) < 0.8 \,]$$

$B(x)$ 는 $x$ 에서 공백을 모두 지운 뒤 이웃한 두 글자씩 묶은 바이그램의 집합입니다.

$$\text{superlative}(c, A) = [\, \forall w \in S : w \in c \Rightarrow w \in A \,]$$

$S$ 는 최고, 최초, 1위, 유일, 가장, 국내 최대의 낱말 6개입니다. 카피는 근거, 길이, 중복, 최상급 차례로 보고 처음 거짓인 게이트에서 셉니다. $K$ 에는 네 게이트를 모두 지난 카피만 들어가서 근거에서 걸린 카피는 뒤 카피의 중복 비교에 쓰이지 않습니다.

공백을 무시하는 근거 게이트는 $q$ 와 $A$ 에서 공백을 모두 지운 뒤 부분 문자열인지 봅니다. 이 기록에서는 걸린 5개가 그 식으로 모두 지납니다. 낱말 6개는 이 글이 정한 목록이라 공정거래위원회 고시가 예로 든 「최대」와 「제일」은 들어 있지 않습니다. 「국내 최대」는 두 낱말이 이어져 있어야 걸리므로, 「업계 최대」 같은 카피는 지납니다.
:::
