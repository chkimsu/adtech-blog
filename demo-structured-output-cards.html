구조화 출력 카드 네 장

지훈 씨가 모델의 답을 받는 코드를 다시 짠 길을 카드 네 장으로 봅니다. 자유 문장으로 받은 답의 네 꼴, 필드 넷의 스키마, 검증 세 단계, 빠진 필드만 다시 묻기입니다. 요청 12건과 가짜 LLM 의 답은 규칙으로 만든 가상 데이터입니다.

파랑 = 코드가 하는 일 벽돌색 = 모델의 답 먹색 = 필드 이름과 스키마 회색 = review 로 가는 답 점선 상자 = 가상 값 (요청과 답)

FREEFORM

자유 문장으로 받은 답과 네 가지 꼴

쉽게 말하면 답 앞뒤에 설명 문장이 붙으면 글 전체로는 JSON 이 아닙니다. 필드가 빠지거나 enum 밖 값이면 읽혀도 쓸 수 없습니다.

요청 12건의 꼴은 정상 6, 설명이 붙은 답 2, 필드가 빠진 답 2, enum 밖 값 2입니다.

SCHEMA

필드 넷의 스키마와 enum

쉽게 말하면 묻기 전에 받을 필드 이름과 자료형, 받는 낱말을 먼저 적습니다. 시스템 메시지와 검증 코드가 같은 스키마를 봅니다.

필드는 넷이고, verdict 와 reason_code 는 enum 입니다.

VALIDATE

파싱과 검증 세 단계에서 남는 건수

쉽게 말하면 먼저 글에서 JSON 을 꺼내 읽고, 그다음 필수 필드와 자료형, enum 을 봅니다. 읽혔다고 통과한 것은 아닙니다.

글 전체로는 10건, 중괄호 사이만 자르면 12건이 읽히고, 검증은 8건이 통과합니다.

RETRY

빠진 필드만 다시 묻는 대화와 review

쉽게 말하면 필드가 빠지기만 한 답에는 빠진 이름만 적어 다시 묻습니다. enum 밖 값은 다시 묻지 않고 사람에게 보냅니다.

다시 묻기 2건 뒤 최종 통과는 9건, review 는 3건입니다.

현업에서는 이렇게 씁니다

  • 스키마는 한 곳에 적고 시스템 메시지와 검증 코드가 같이 씁니다. 두 곳의 꼴이 다르면 맞는 답도 틀렸다고 봅니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 구조화 출력 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 바로 앞 이야기는 프롬프트와 Chain-of-Thought 편입니다.
