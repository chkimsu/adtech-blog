모델 팀 36주째 월요일, 서연 씨가 지난주 게이트를 지난 카피 35개를 보고 물었습니다. 게이트를 다 지났으니 모두 광고주에게 보여도 되느냐는 것입니다. 지훈 씨는 「~하세요」로 끝난 카피 둘과, 범위가 빠진 「가장 가벼운」을 떠올렸습니다.

선배는 모델에게 채점 기준을 주고 카피마다 점수를 매기게 하자고 했습니다. 같은 카피를 다섯 번 물어 점수가 같은지 보고, 같은 상품의 카피 둘을 나란히 놓고 더 나은 쪽도 고르게 하자고 했습니다. 오래 생각하는 비싼 채점은 답이 흔들린 것에만 쓰기로 했습니다.

**모델에게 카피를 채점하게 하면, 그 점수를 얼마나 믿고 어디에 써야 할까요?**

카피를 채점하는 모델을 판정자라고 부릅니다. 채점표와 짝비교는 26주째 [LLM-as-a-Judge](post.html?id=llm-as-a-judge) 편에서 본 그대로입니다. 싼 판정자가 먼저 보고 헷갈리는 것만 비싼 판정자에게 넘기는 순서는 캐스케이드입니다. 잘못된 카피가 나가면 광고가 심사에서 빠지고, 판정에 드는 토큰은 카피 수만큼 늘어납니다.

> **한 줄 요약:** 35주째 편에서 게이트를 지난 카피 35개를 qwen3.5:27b 에게 채점표로 다섯 번씩 채점하게 했습니다. 28개는 다섯 번 모두 같은 점수였고, 7개가 흔들렸습니다. 판정자는 거의 4 점과 5 점만 썼는데, 그 둘이 사람 라벨과 상관없이 나뉘었습니다. 사람이 5 점을 준 27개 가운데 12개가 중앙값 4 점이었고, 2 점을 준 x03-5 와 x07-2 는 5 점이었습니다. 그래서 중앙값은 가상 사람 라벨과 16/35 가 같았지만 kappa 는 -0.00 이었습니다. 「~하세요」로 끝난 두 카피는 다섯 번 모두 4 점이라, 문장 끝을 보고 깎았는지는 알 수 없었습니다. 같은 자산의 카피 20쌍을 좌우를 바꿔 두 번씩 물으니, 14쌍은 같은 카피를 골랐고 6쌍은 두 번 다 A 자리가 이겼습니다. 흔들린 카피 1개와 바뀐 6쌍, 항목 13/75 만 thinking 을 켠 비싼 판정자에게 넘기자 4쌍의 승자가 정해졌습니다. 시간은 싼 판정자만 204.2초, 캐스케이드 3,054.6초였습니다. 비싼 판정자로 다 보면 항목당 평균 × 75개로 어림해 16,444.1초입니다. 판정은 노출 전 게이트, 오프라인 비교, 사후 원인 귀속 세 자리에 씁니다. 노출 뒤의 문제를 거슬러 찾으려면 판정 기록을 카피 id 로 이어 둡니다.

## 1. 판정은 세 겹입니다

**카피를 판정하는 자리는 셋입니다. 노출 전 게이트는 카피 하나를 내보낼지, 오프라인 비교는 어느 버전을 쓸지 정합니다. 사후 원인 귀속은 노출 뒤에 생긴 문제를 어느 단계가 놓쳤는지 찾습니다.**

35주째 편의 게이트 넷은 카피를 광고주에게 보이기 전에 돌아갑니다. 이 자리가 노출 전 게이트입니다. 카피 하나마다 내보낼지 말지를 정하고, 놓치면 문제 카피가 그대로 나갑니다. 코드 게이트는 빠르고 늘 같은 답을 내지만, 글자와 숫자만 봅니다. 이 자리에 판정자를 더하면 판정자도 카피마다 불러야 해서, 값과 시간이 카피 수만큼 듭니다.

오프라인 비교는 노출과 떨어진 자리입니다. 프롬프트나 모델을 바꾸기 전에, 정해 둔 자산으로 두 버전의 카피를 만들어 판정자에게 맡깁니다. 판정자는 점수를 매기거나 둘 가운데 나은 쪽을 고릅니다. 틀려도 사용자에게 바로 닿지 않아서, 26주째 편은 판정을 가장 먼저 들이기 좋은 자리로 꼽았습니다.

사후 원인 귀속은 노출 뒤의 자리입니다. 광고가 심사에서 빠지거나 신고가 들어오면, 그 카피가 어느 자산의 어느 quote 에서 왔는지 거슬러 찾습니다. 어느 게이트를 지났고 판정자가 몇 점을 줬는지도 찾습니다. 앞의 두 자리가 남긴 기록이 이 자리의 재료이고, 6절에서 다시 봅니다.

이 글의 기록 셋은 노출 전에 카피 35개를 판정한 것입니다. 점수는 문턱을 두면 노출 전 게이트가 되고, 짝비교는 같은 상품의 카피 가운데 무엇을 먼저 보일지 정합니다. 같은 판정자와 채점표를 오프라인 비교에도 그대로 씁니다. 그래서 한 판정자의 성질을 측정해 두면 세 자리 모두에 쓸 수 있습니다.

세 자리는 판정을 부르는 때와 틀렸을 때의 값이 다릅니다. 노출 전 게이트는 카피마다 빨라야 하고, 오프라인 비교는 버전마다 넓게 보고, 사후 원인 귀속은 문제가 생긴 카피만 깊게 봅니다. 아래 표가 세 자리를 나란히 적은 것입니다. 한 판정자를 세 자리에 똑같이 두지 않고, 자리마다 판정의 값과 오판의 크기를 맞춥니다.

|---|---|---|---|---|
| 노출 전 게이트 | 카피를 광고주에게 보이기 전 | 이 카피를 내보낼지 | 문제 카피가 나가거나 멀쩡한 카피가 막힘 | 카피마다 게이트 결과와 점수 |

## 2. 필수 항목은 통과와 탈락으로, 품질은 점수로 봅니다

**숫자와 인용처럼 어기면 안 되는 항목은 코드 게이트가 통과와 탈락으로 거릅니다. 문장 끝과 읽기 쉬움처럼 정도가 있는 항목은 채점표의 점수로 봅니다. 채점표는 필수 항목을 하나라도 어기면 2 점 이하를 주게 했습니다.**

35주째 편의 시스템 메시지는 카피의 사실이 quote 안에 있고, 숫자는 자산에 있는 것만 쓰게 했습니다. 최상급 표현은 자산에 그 말이 있을 때만 쓰고, 문장 끝은 명사나 「~합니다」 꼴로 끝내게 했습니다. 채점표는 이 넷에 검색 광고 문구로 읽기 쉬운지를 더한 다섯 요구로 썼습니다. 다만 사실 요구는 상품의 성질로 좁혀 상품의 이름과 종류는 더해도 되게 했고, 최상급 요구는 낱말이 아니라 범위를 보게 했습니다. 그 까닭은 더 깊이 보기에 있습니다. 게이트 넷은 이 가운데 앞의 셋을 글자로 봅니다.

게이트가 보지 못하는 것은 둘입니다. 하나는 같은 요구의 뜻입니다. x07-1 의 「가볍게」는 quote 「접으면 두께가 10cm 이고」에 없는 말인데, quote 는 자산 안에 있어 근거 게이트를 지났습니다. x03-5 는 「가장」이 자산에 있어 최상급 게이트를 지났지만, 자산의 「숲결 러닝화 가운데」라는 범위를 뺐습니다. 다른 하나는 문장 끝과 읽기 쉬움이고, 게이트는 길이 말고는 문장을 보지 않습니다.

채점표는 다섯 요구를 두 묶음으로 나눠 점수에 옮깁니다. 사실, 숫자, 최상급은 필수 항목이라 하나라도 어기면 2 점 이하입니다. 문장 끝과 읽기 쉬움은 품질이라 하나를 어기면 4 점, 둘 다 어기면 3 점입니다. 다섯을 다 지키면 5 점이고, 필수 항목을 둘 이상 어기면 1 점입니다. 채점표 전문은 끝의 더 깊이 보기에 있습니다.

사람 라벨 35개는 27개가 5 점, 3개가 4 점, 5개가 2 점입니다. 2 점 다섯은 x03-5 의 범위 없는 「가장」과, x04-5 가 quote 의 「쉽게」를 빼고 「늘어나지 않습니다」라고 쓴 카피입니다. 나머지 셋은 x07 의 「가볍게」, 「휴대하기 편한」, 「편리하게 보관」입니다. 4 점 셋은 조사가 빠지거나 어색하게 이어진 카피입니다. 상품의 이름이나 종류를 더한 카피는 채점표대로 어긴 것으로 보지 않았습니다.

아래 표는 다섯 요구마다 게이트와 판정자가 보는 것을 나란히 적은 것입니다. 숫자는 게이트가 이미 거른 요구라, 남은 35개는 모두 숫자 요구를 지킵니다. 판정자가 게이트 위에서 할 일은 표의 오른쪽 둘째 칸입니다. 판정자가 필수 항목을 놓치면 2 점 카피가 4~5 점을 받아 그대로 나갑니다.

| 요구 | 게이트(코드)가 보는 것 | 판정자(채점표)가 보는 것 | 이 글의 예 |
|---|---|---|---|
| 사실은 quote 안 | quote 가 자산 안에 글자 그대로 있는가 | 카피의 성질이 quote 안에 있고 뜻을 넓히지 않았는가 | x07-1 의 「가볍게」, x04-5 가 뺀 「쉽게」 |
| 숫자는 자산의 것만 | 카피의 숫자가 자산에 있는가 | 같음 | 남은 35개는 모두 지남 |
| 근거 없는 최상급 금지 | 카피에 든 최상급 낱말이 자산에도 있는가 | 자산이 같은 범위로 말하는가 | x03-5 가 뺀 「숲결 러닝화 가운데」 |

| 읽기 쉬움 | 보지 않음(길이 40자만) | 조사가 빠지거나 어색하지 않은가 | x04-1 의 빠진 조사 |

## 3. 절대 점수는 같은 카피에도 흔들립니다

**카피 35개를 temperature 0.7 로 다섯 번씩 채점하자 28개는 다섯 번 모두 같은 점수였고, 7개가 흔들렸습니다. 판정자는 거의 4 점과 5 점만 썼고, 그 둘은 사람 라벨과 상관없이 나뉘었습니다. 중앙값은 사람 라벨과 16/35 가 같았지만, kappa 는 -0.00 이었습니다.**

채점은 카피마다 다섯 번, thinking 을 끄고 temperature 0.7 로 받았습니다. seed 는 다섯 번 모두 다르게 두었습니다. 27주째 [비용, 캐시, 비결정성](post.html?id=llm-cost-cache-nondeterminism) 편에서 temperature 0 은 같은 질문에 글자까지 같은 답을, 0.7 은 두세 가지 답을 냈습니다. 이 글은 흔들림을 보려고 0.7 쪽만 받았습니다. 사용자 메시지에는 자산 텍스트와 카피와 quote 를 함께 보냈습니다.

블록은 점수 다섯을 읽어, 다섯 가운데 가장 큰 점수와 가장 작은 점수의 차이를 흔들린 폭으로 셉니다. 그리고 다섯을 정렬한 셋째 값, 곧 중앙값을 그 카피의 점수로 삼아 사람 라벨과 비교합니다. 일치율과 kappa 는 26주째 편의 `agreement_parts`, `cohen_kappa` 를 그대로 씁니다. 사람 라벨이 5 점에 몰려 있어서, 일치율만 보면 실제보다 좋아 보일 수 있기 때문입니다.

# 2단계: 카피마다 점수 다섯을 읽고 흔들린 폭을 센다
# read_score 는 LLM-as-a-Judge 편의 정의를, score_table 은 생성기의 정의를 글자 그대로 옮겼다. 읽지 못한 답은 None 이다.
# 폭은 다섯 가운데 가장 큰 점수에서 가장 작은 점수를 뺀 값이다. 다섯이 모두 같으면 0 이다.
def read_score(text):
    try:
        obj = json.loads(text)
    except ValueError:
        return None
    if not isinstance(obj, dict) or list(obj) != ['score']:
        return None
    s = obj['score']
    return s if isinstance(s, int) and not isinstance(s, bool) and 1 <= s <= 5 else None


def score_table(record, ids, runs=5):
    return {cid: [read_score(record[cid if r == 1 else f'{cid}|off|{r}']) for r in range(1, runs + 1)] for cid in ids}


# 읽지 못한 답(None)은 틀린 답으로 친다. 폭, 중앙값, 평균을 셀 때는 0 점으로 바꿔, 폭은 커지고 1~5 점인 사람 라벨과는 맞지 않게 한다.
def as_points(five):
    return [0 if s is None else s for s in five]

# 3단계: 다섯의 중앙값을 사람 라벨과 비교한다
# 중앙값은 다섯을 정렬한 셋째 값이다. agreement_parts 와 cohen_kappa 는 LLM-as-a-Judge 편의 정의를 글자 그대로 옮겼다.
# 점수에 순서를 두지 않는 가중치 없는 kappa 이고, 표는 줄이 사람 라벨, 칸이 중앙값이다.
# 마지막 줄은 같은 중앙값들을 사람 라벨이 높은 카피부터 차례대로 다시 준 경우의 kappa 다. 4 점과 5 점만 쓴 것과, 그 둘이 어느 카피에 갔는지를 나눠 본다.
def agreement_parts(a, b):
    n = len(a)
    observed = sum(x == y for x, y in zip(a, b)) / n
    expected = sum((a.count(c) / n) * (b.count(c) / n) for c in sorted(set(a) | set(b)))
    return observed, expected

    observed, expected = agreement_parts(a, b)

## 5. 싼 판정자를 먼저 쓰고 흔들린 것만 넘깁니다

**점수가 2 점 흔들린 카피 1개와 승자가 바뀐 6쌍만 thinking 을 켠 비싼 판정자에게 넘겼습니다. 항목 75개 가운데 13개입니다. 비싼 판정자는 6쌍 가운데 4쌍에서 좌우를 바꿔도 같은 카피를 골랐고, 한 건에 평균 219.3초가 걸렸습니다.**

캐스케이드는 모두를 싼 판정자에게 먼저 보이고, 답을 믿기 어려운 것만 비싼 판정자에게 넘기는 순서입니다. 31주째 [관심사 사전 만들기](post.html?id=interest-audience-library) 편이 투표 둘의 답이 다른 키워드만 심판에게 보낸 것과 같은 모양입니다. 이 글은 믿기 어려운 것을 둘로 정했습니다. 점수 다섯의 가장 큰 값과 가장 작은 값이 2 이상 차이 나는 카피와, 좌우를 바꾸면 승자가 바뀐 쌍입니다.

비싼 판정자에게는 같은 시스템 메시지와 사용자 메시지를 thinking 켬, temperature 0 으로 보냈습니다. 카피는 점수를 한 번, 쌍은 좌우를 바꿔 두 번 다시 봅니다. 고르는 함수 `uncertain` 은 생성기의 것을 그대로 옮겼고, 생성기는 같은 함수로 두 기록에서 캐스케이드 프롬프트를 만들었습니다. 비싼 판정자로 전부 볼 때의 값은 기록이 없어서, 넘긴 항목의 평균에 전체 항목 75개를 곱해 어림합니다.

# 카피는 점수를 한 번, 쌍은 좌우를 바꿔 두 번 다시 보므로 항목 수는 카피 수 + 쌍 수 × 2 다. 문턱 gap 을 바꾸면 넘기는 카피 수가 달라진다.

    pairs = [p for p, (ab, ba) in verdicts.items() if ab is None or ba is None or ab == ba]
    return copies, pairs

## 6. 온라인 CTR 이 못 잡는 것은 사후 원인 귀속이 봅니다

**카피를 내보낸 뒤의 CTR 은 클릭이 많았는지를 알려 줄 뿐, 카피가 사실인지는 알려 주지 않습니다. 심사 거절과 신고는 CTR 에 보이지 않고 늦게 따로 옵니다. 그래서 노출 로그의 카피 id 에서 자산, quote, 게이트, 판정 기록까지 거슬러 가는 길을 미리 남깁니다.**

온라인 CTR 은 카피를 실제로 노출해 클릭을 세는 값입니다. 같은 상품의 카피 둘을 나눠 노출하면 CTR 이 높은 쪽을 고를 수 있고, [모델 온라인 A/B 설계](post.html?id=model-ab-testing) 편의 온라인 실험이 그 방법입니다. 그런데 CTR 은 사람이 눌렀는지만 셉니다. x04-5 처럼 「쉽게」를 빼고 「늘어나지 않습니다」라고 단정한 카피는, 덜 조심스러운 문구라 클릭을 더 받을 수도 있습니다.

CTR 이 보지 못하는 일은 셋입니다. 심사에서 빠진 광고는 노출이 없어 CTR 자체가 없습니다. 소비자 신고나 반품은 며칠 뒤에 클릭 로그가 아닌 곳으로 옵니다. 판정자의 모델이나 채점표가 바뀌어 점수 분포가 달라진 것도 CTR 에는 보이지 않습니다. 셋 다 드물고 늦게 오는 일이라, 노출마다 세는 값으로는 잡히지 않습니다.

사후 원인 귀속은 문제가 생긴 카피 하나에서 거꾸로 올라갑니다. 노출 로그의 카피 id 로 그 카피의 자산과 quote 를 찾고, 어느 게이트를 지났는지와 판정자가 몇 점을 줬는지를 봅니다. 그 판정자의 모델과 채점표도 함께 봅니다. 여기의 귀속은 전환을 광고에 나눠 주는 [어트리뷰션](post.html?id=attribution-basics)과 다른 말로, 문제의 원인을 단계에 돌리는 일입니다.

이 글의 기록이 그 예입니다. x07-2 「무게 1.9kg 으로 휴대하기 편한 캠핑 의자」는 사람이 2 점을 준 카피입니다. 이 카피는 게이트 넷을 모두 지났고, 싼 판정자에게서 다섯 번 모두 5 점을 받았습니다. 이 카피에 신고가 오면, 근거 게이트가 quote 밖의 「휴대하기 편한」을 보지 않았고 판정자도 깎지 않았다는 것을 기록에서 찾게 됩니다. 게이트가 놓쳤으면 게이트를 고치고, 판정자가 놓쳤으면 그 카피를 사람 라벨에 더해 판정자를 다시 측정합니다.

그래서 노출 전 게이트와 오프라인 비교는 판정 결과와 함께 판정자의 버전을 남깁니다. 같은 카피라도 판정자의 모델, 채점표, temperature 가 바뀌면 점수가 달라지기 때문입니다. 3절의 x01-3 은 같은 판정자와 같은 채점표로도 5 점과 3 점을 오갔습니다. 아래 표는 노출 뒤에 생기는 일마다 CTR 에 보이는지와 거슬러 올라갈 때 쓰는 기록입니다.

| 노출 뒤에 생기는 일 | CTR 에 보이나 | 거슬러 올라갈 때 쓰는 기록 |
|---|---|---|
| 근거 없는 최상급으로 심사에서 빠짐 | 안 보임, 빠진 광고는 노출이 없음 | 카피 id, quote, 최상급 게이트 결과, 판정 점수 |
| 단정한 카피에 클릭이 몰림 | CTR 이 오히려 오를 수 있음 | 판정 점수와 사람의 재검토 |
| 소비자 신고나 반품 | 안 보임, 며칠 뒤 따로 옴 | 노출 로그의 카피 id 와 자산 버전 |
| 판정자를 바꾼 뒤 점수 분포가 달라짐 | 안 보임 | 판정자의 모델, 채점표 버전, temperature |

## 7. 두 무대는 판정 기록을 잇는 범위가 다릅니다

**세 겹의 판정은 두 무대가 같습니다. 다른 것은 노출 뒤의 신호가 판정 기록과 한 회사 안에서 이어지느냐입니다. 담장 안은 카피 id 하나로 잇고, 열린 RTB 의 DSP 는 입찰의 creative id 와 거래소의 통지로 잇습니다.**

두 무대의 이름은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에서 풀었습니다. 1~5절의 셈은 두 무대가 같고, 6절의 사후 원인 귀속에 쓰는 신호가 어디에 모이는지가 다릅니다.

### 담장 안에서는 노출 뒤 신호와 판정 기록을 카피 id 로 잇습니다 [무대: 닫힌 생태계]

담장 안의 플랫폼은 카피를 만들고, 게이트와 판정자에 넣고, 자기 지면에 노출합니다. 클릭과 전환, 심사 결과와 신고도 같은 회사 안에 쌓입니다. 그래서 노출 로그의 카피 id 하나로 판정 기록까지 이어 볼 수 있습니다.

오프라인 비교의 사람 라벨도 플랫폼이 모읍니다. 사후 원인 귀속에서 찾은 카피를 사람 라벨에 더하면, 다음 판정자를 그 카피로 다시 측정할 수 있습니다. 판정자를 바꿀 때도 같은 카피 묶음으로 옛 판정자와 새 판정자를 나란히 측정합니다.

### 열린 RTB 에서는 creative id 와 거래소의 통지로 잇습니다 [무대: 열린 RTB]

열린 RTB 의 DSP 는 카피를 만들고 판정한 뒤 입찰 응답에 담아 보냅니다. OpenRTB 2.6 의 입찰 객체에는 crid 필드가 있고, 명세는 이것을 광고 품질 검사를 돕는 creative id 라고 적었습니다. 거래소는 입찰이 이기면 낙찰 통지 주소(nurl)를, 과금이 되면 과금 통지 주소(burl)를 부릅니다. 두 주소는 DSP 가 입찰에 적어 보낸 것입니다.

그래서 DSP 는 자기 입찰 로그의 crid 와 두 통지를 이어, 어느 카피가 이겼고 과금되었는지 압니다. 명세는 낙찰 통지가 노출이나 과금까지 뜻하지는 않는다고 적었습니다. 진 입찰을 알리는 패찰 통지(lurl)는 거래소 정책에 따라 지원하지 않을 수 있다고도 적었습니다. 거래소와 매체 쪽의 심사 결과나 신고는 DSP 에 오지 않을 수 있습니다. 아래 표는 가상 데이터가 아니라 두 무대의 설계 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 카피를 만들고 판정하는 쪽 | 플랫폼 | DSP |
| 노출 전 검사 | 플랫폼의 게이트와 판정자 | DSP 의 게이트와 판정자, 거래소의 광고 품질 검사 |
| 노출 뒤에 받는 신호 | 클릭, 전환, 심사 결과, 신고를 한 회사 안에서 | 낙찰 통지(nurl), 과금 통지(burl), DSP 가 따로 측정하는 클릭 |
| 원인 귀속의 키 | 카피 id | 입찰의 crid |

| 짝비교 | 같은 쌍을 좌우를 바꿔 두 번 | 같은 카피 14쌍, 바뀜 6쌍(모두 A 두 번) |
| 사람 승자 | 사람 점수가 높은 쪽, 같으면 뺌 | 5쌍 가운데 맞음 3, 바뀜 2, 뺀 쌍 15 |
| 캐스케이드 | 흔들린 카피와 바뀐 쌍만 비싼 판정자에게 | 항목 13/75, 바뀐 6쌍 가운데 4쌍이 정해짐 |
| 캐스케이드 뒤 | 정해진 쌍과 사람 승자와 맞은 쌍 | 18/20, 사람 승자가 있는 5쌍 가운데 4쌍 |
| 세 방식의 시간 | 싼 판정자만, 캐스케이드, 다 볼 때(하한, 평균 × 75개) | 204.2초, 3,054.6초, 7,322.0초와 16,444.1초 |

## 헷갈리기 쉬운 점

- **점수 평균과 짝비교 승률은 다른 값입니다.** 평균은 카피 하나를 혼자 놓고 매긴 점수의 평균이고, 승률은 같은 자산의 다른 카피와 나란히 놓았을 때 이긴 몫입니다. x01-1 은 다섯 번 모두 4 점이라 평균 4.0 이었고, x01-3 은 평균 4.6 이었습니다. 그런데 둘을 나란히 놓자 판정자는 두 번 다 x01-1 을 골랐습니다. 평균이 높은 카피가 짝비교에서도 이긴다고 볼 수 없어서, 두 값은 따로 적습니다.
- **캐스케이드의 문턱은 비용과 오판의 교환입니다.** 문턱을 2 에서 1 로 낮추면 넘기는 카피가 1개에서 7개로 늘어, 비싼 판정자의 토큰과 시간이 그만큼 늡니다. 3 으로 올리면 넘기는 카피가 0개라, 5 점과 3 점을 오간 x01-3 도 싼 판정자의 중앙값으로 정해집니다. 문턱은 비싼 판정 한 번의 값과, 나쁜 카피를 내보냈을 때의 값을 비교해 정합니다.
- **CTR 이 오른 카피가 좋은 카피라는 뜻은 아닙니다.** CTR 은 누른 사람의 몫만 셉니다. 근거 없이 단정한 카피는 클릭을 더 받을 수 있지만, 심사 거절과 신고로 늦게 돌아옵니다. 그래서 CTR 로 고르기 전에 노출 전 게이트와 판정이 먼저 거르고, 노출 뒤에는 사후 원인 귀속이 CTR 밖의 신호를 봅니다.

## 더 깊이 보기

:::deep 채점표 전문과 사람 라벨을 매긴 방법
판정 기록 셋에 보낸 시스템 메시지입니다. 채점표와 두 물음의 답 꼴을 함께 적었습니다. 캐스케이드 기록은 점수를 다시 볼 카피와 승자를 다시 볼 쌍이 한 파일에 들어가는데, 프롬프트 파일의 시스템 메시지는 하나뿐입니다. 그래서 세 기록 모두 이 메시지 하나를 쓰고, 싼 판정자와 비싼 판정자의 차이는 thinking 과 temperature 입니다.

```text
너는 검색 광고 카피를 채점하는 검수자다. 광고주의 자산 텍스트와, 그 자산으로 쓴 카피와 quote 를 받는다.
quote 는 카피가 기댄 구절을 자산 텍스트에서 옮긴 것이다. 카피는 아래 다섯 요구로 본다.
1. 카피가 말하는 상품의 성질(무게, 크기, 기능, 조건 같은 것)은 모두 quote 안에 있다. quote 에 없는 성질이나 꾸밈말을 더하지 않았고, quote 의 뜻을 넓히지 않았다. 상품의 이름과 종류는 자산에 있으면 더해도 된다.
2. 카피의 숫자는 모두 자산 텍스트에 있는 숫자다.
3. 최고, 최초, 1위, 유일, 가장, 국내 최대 같은 최상급 표현은 자산이 같은 범위로 말할 때만 쓴다.
4. 문장 끝은 명사나 「~합니다」 꼴이다.
5. 검색 광고 문구로 읽기 쉽다. 한 번 읽어 뜻이 들어오고, 조사가 빠져 끊기거나 낱말이 어색하게 이어지지 않는다.
점수는 1~5 의 정수다.
5: 다섯 요구를 모두 지켰다.
4: 1, 2, 3 은 지켰고, 4 와 5 가운데 하나를 어겼다.
3: 1, 2, 3 은 지켰고, 4 와 5 를 둘 다 어겼다.
2: 1, 2, 3 가운데 하나를 어겼다.
1: 1, 2, 3 가운데 둘 이상을 어겼다.
사용자 메시지에 카피가 하나 있으면 그 카피의 점수를 매겨 아래 꼴의 JSON 한 줄로만 답한다.
{"score": <1~5 의 정수>}
사용자 메시지에 카피 A 와 카피 B 가 있으면 다섯 요구로 보아 더 나은 쪽을 골라 아래 꼴의 JSON 한 줄로만 답한다. 둘이 비슷해도 하나를 고른다.
{"winner": "<A|B>"}
설명이나 다른 글은 붙이지 않는다.
```

점수를 물을 때 사용자 메시지는 「자산 텍스트:」, 「카피:」, 「quote:」 아래에 각각을 적은 글입니다. 짝비교는 「카피 A:」와 「카피 B:」 아래에 카피를 적고, 카피마다 quote 를 붙였습니다. 프롬프트 파일은 `scripts/gen-copy-data.py --prompts <슬러그>` 가 씁니다. `--check` 는 세 파일과 기록을 다시 대조합니다. 기록하기 전에 35개 밖의 카피 둘, 곧 게이트에 걸린 x08-1 과 x08-2 로 답의 꼴부터 봤습니다. 두 답이 모두 읽혀서 채점표를 고치지 않았고, 점수를 본 뒤에도 고치지 않았습니다.

채점표의 요구 1 은 35주째 편의 「카피의 사실은 모두 quote 안」을 상품의 성질로 좁혀 적었습니다. 상품의 이름과 종류는 더해도 된다고 밝혔습니다. 무엇을 파는지 말하는 것까지 quote 밖의 사실로 치면, 이름이 든 문장을 quote 로 옮긴 카피만 이름을 쓸 수 있습니다. 사람 라벨은 이 채점표대로 제가 매겼습니다. quote 가 든 자산 문장의 주어를 되살린 카피, 곧 x03-3 의 겉감과 x05-4 의 화면은 요구 1 을 어긴 것으로 보지 않았습니다. 「선택 가능」처럼 명사로 끝나는 짧은 꼴은 읽기 쉬움을 어긴 것으로 보지 않았습니다.

이 기록으로 말할 수 없는 것도 셋입니다. 사람 라벨은 한 사람이 매긴 가상 값이라, 다른 사람이 매기면 4 점과 5 점의 경계가 달라질 수 있습니다. 점수는 temperature 0.7 로만 받아서, temperature 0 에서 같은 카피의 점수가 얼마나 같은지는 이 글에 없습니다. 판정자도 카피를 쓴 모델과 같은 qwen3.5:27b 라, 자기가 쓴 글에 점수를 더 주는 편향을 따로 볼 수 없습니다.
:::

:::deep 캐스케이드 규칙과 비용 어림의 가정
비싼 판정자에게 넘기는 규칙은 둘입니다. 카피는 점수 다섯의 가장 큰 값과 가장 작은 값이 2 이상 차이 나거나, 다섯 가운데 읽지 못한 답이 하나라도 있으면 넘깁니다. 쌍은 두 답이 같은 자리, 곧 둘 다 A 나 둘 다 B 이거나, 읽지 못한 답이 들어 있으면 넘깁니다. 이 기록에는 읽지 못한 답이 없어서, 넘긴 것은 폭이 2 인 카피와 승자가 바뀐 쌍뿐입니다.

넘긴 카피는 점수를 물은 사용자 메시지 그대로 한 번 보냅니다. 넘긴 쌍은 -ab 와 -ba 두 사용자 메시지를 그대로 보내, 비싼 판정자도 좌우를 바꿔 두 번 묻습니다. 모두 thinking 켬, temperature 0, seed 7 이고, 항목 id 는 앞 두 기록의 것을 그대로 씁니다. 캐스케이드 프롬프트 파일은 생성기가 두 기록을 읽어 만듭니다. `--check` 는 지금 있는 두 기록에서 이 파일을 다시 만들어 글자까지 대조합니다. 고른 것이 0개면 생성기는 이 파일을 만들지 않고, `--check` 는 파일과 기록이 둘 다 없어야 통과합니다.

이 기록에서 넘긴 것은 카피 x01-3 하나와 쌍 여섯의 좌우 두 번, 모두 13건입니다. 쌍은 x01-1-2, x03-1-2, x02-1-3, x05-1-3, x06-1-3, x04-1-5 입니다. 비싼 판정자 한 건은 97.6~478.0초로, 13건 모두 기록 도구의 시간 제한 600초 안에 답이 왔습니다. 그래서 다시 보내거나 나눠 보낸 항목은 없습니다.

비싼 판정자로 전부 볼 때의 값은 기록하지 않았습니다. 그래서 넘긴 항목의 입력 토큰, 출력 토큰, 시간의 평균에 전체 항목 75개를 곱해 어림합니다. 전체 항목은 카피 35개를 한 번씩, 쌍 20개를 좌우 두 번씩 보는 경우입니다. 넘긴 항목은 판정이 흔들린 것이라, 흔들리지 않은 항목은 thinking 이 더 짧거나 길 수 있습니다. 블록 3 은 평균이 필요 없는 하한도 찍습니다. 어느 항목도 넘긴 13건 가운데 가장 빠른 한 건보다 빠르지 않다고 치고, 그 한 건의 시간에 75개를 곱한 값입니다. 넘긴 항목은 쌍이 많아 입력도 쌍의 사용자 메시지 쪽에 가깝습니다.
