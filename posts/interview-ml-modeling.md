지훈은 면접에서 "CTR 예측 모델을 어떻게 만들겠나"를 받았다. 준비한 대로 잘 답했다. 피처를 나열하고, 모델을 고르고, AUC로 평가하겠다고 했다.

면접관이 물었다. "AUC가 0.72에서 0.75로 올랐는데 매출은 그대로예요. 왜 그럴까요?" 지훈은 답을 못 했다.

**면접이 실제로 보는 것은 무엇일까?**

지식이 아니다. 답을 아는지가 아니라 **틀렸을 때 어떻게 알아채는지**를 본다. 이 글은 광고 ML 면접에서 반복해서 나오는 질문 스물여덟 개를 모아, 답만이 아니라 그 답이 왜 그런지를 실행되는 코드로 확인한다.

> **한 줄 요약:** 대부분의 질문은 "이 지표가 좋아졌는데 왜 돈이 안 벌리나"의 변형이다. 답은 거의 항상 **줄 세우기와 값 맞추기가 다른 일이기 때문**이다. AUC는 줄 세우기만 재고, 광고는 값도 맞아야 한다.

> **골라 읽는 법** — 절이 열 개이고 절마다 질문 두세 개가 있습니다.
>
> - 답하는 틀만 → 첫째 절
> - 지표 질문(AUC·보정·불균형) → 둘째~넷째 절
> - 데이터 함정 → 다섯째·여섯째 절
> - 모델 선택과 랭킹 → 일곱째~아홉째 절
> - 모르는 걸 물었을 때 → 마지막 절

---

## 1. 면접은 답이 아니라 판단 과정을 본다

**같은 답이라도 "왜 그렇게 판단했나"가 붙으면 다른 답이 된다.**

경력 면접에서 정답이 정해진 질문은 드물다. "어떤 모델을 쓰겠나"에 XGBoost라고 답하면 반쯤 맞은 것이다. "지금 데이터가 하루 2억 건이고 피처가 대부분 범주형이라 GBDT가 낫다"까지 말해야 온전히 맞은 답이 된다.

그래서 어떤 질문이든 세 가지를 순서대로 붙이면 형태가 갖춰진다.

**첫째, 전제를 확인한다.** "하루 요청이 몇 건인가요", "응답 시간 예산이 얼마인가요"를 되묻는 것은 시간 끌기가 아니라 답의 일부다. 전제 없이 나온 답은 어느 상황에서도 안 맞는다.

**둘째, 하나를 고르고 그 이유를 댄다.** 후보를 나열만 하면 "판단을 못 한다"로 읽힌다. 트레이드오프를 말하되 결론을 낸다.

**셋째, 어떻게 틀렸는지 알아낼지를 말한다.** 이 부분이 경력 지원자와 신입 지원자를 가르는 자리다. "배포 후 COPC를 시간대별로 보고 1에서 벗어나면 되돌립니다"까지 말하면 실무를 해 봤다는 신호가 된다.

> **면접관이 듣고 싶은 것** — 아래 모든 답안에서 굵게 표시한 문장이 그 답의 핵심입니다. 나머지는 그 문장을 뒷받침하는 근거이니, 시간이 없으면 굵은 문장만 말해도 됩니다.

## 2. 불균형 — "CTR이 0.2%인데 어떻게 학습하나"

**Q. 클릭이 전체의 0.2%밖에 안 됩니다. 어떻게 학습하시겠어요?**

먼저 정확도를 쓰지 않는다는 것부터 말해야 한다. 왜 그런지는 재 보면 바로 나온다.

```python
import random

random.seed(20260815)
N = 100_000
CTR = 0.002                                    # 0.2% — 광고에서 흔한 값

라벨 = [1 if random.random() < CTR else 0 for _ in range(N)]
클릭수 = sum(라벨)

예측A = [0.0] * N                              # 무조건 "안 누른다"
예측B = [min(0.999, max(0.001, (0.006 if y else 0.0015) + random.gauss(0, 0.001))) for y in 라벨]

def 정확도(pred):
    return sum((p >= 0.5) == (y == 1) for p, y in zip(pred, 라벨)) / N

print(f"노출 {N:,}건 · 클릭 {클릭수:,}건 ({클릭수/N:.3%})")
print(f"{'모델':<26}{'정확도':>10}")
print(f"{'A: 전부 안 누른다고 답':<24}{정확도(예측A):>10.4%}")
print(f"{'B: 실제로 구분하는 모델':<24}{정확도(예측B):>10.4%}")
print("\n둘 다 99.8% 다. 정확도로는 두 모델을 가를 수 없다.")
```

```
노출 100,000건 · 클릭 202건 (0.202%)
모델                               정확도
A: 전부 안 누른다고 답            99.7980%
B: 실제로 구분하는 모델            99.7980%

둘 다 99.8% 다. 정확도로는 두 모델을 가를 수 없다.
```

**아무것도 안 하는 모델이 99.8%를 받는다.** 이 한 줄이 답의 출발점이다. 정확도 대신 로그로스와 AUC를 보고, 광고에서는 보정까지 함께 본다고 말한다.

학습 자체는 어떻게 할까. **다운샘플링이 실무의 기본이다.** 안 누른 데이터를 일정 비율만 남겨서 학습 데이터를 줄이면 학습이 훨씬 빨라진다. 신호가 클릭 쪽에 있으니 클릭은 전부 남긴다.

**Q. 다운샘플링하면 예측값이 실제보다 커지지 않나요?**

커진다. 그리고 **그것을 되돌리는 것까지가 다운샘플링이다.** 이 되묻기를 못 하면 실무 경험이 없는 것으로 읽힌다.

```python
import random

random.seed(7)
N, CTR = 500_000, 0.002
라벨 = [1 if random.random() < CTR else 0 for _ in range(N)]
클릭 = sum(라벨)
비클릭 = N - 클릭

r = 0.05                                    # 안 누른 건을 5% 만 남긴다
남긴비클릭 = int(비클릭 * r)
샘플크기 = 클릭 + 남긴비클릭

원래CTR = 클릭 / N
샘플CTR = 클릭 / 샘플크기

print(f"원본      노출 {N:>9,}  클릭 {클릭:>6,}  CTR {원래CTR:.4%}")
print(f"5% 샘플링 노출 {샘플크기:>9,}  클릭 {클릭:>6,}  CTR {샘플CTR:.4%}")
print(f"→ 샘플에서 CTR 이 {샘플CTR/원래CTR:.1f}배로 부푼다\n")

def 되돌리기(p, r):
    return p / (p + (1 - p) / r)

print(f"{'샘플에서 모델이 낸 값':>20}{'그대로 쓰면':>12}{'되돌리면':>12}")
for p in (0.01, 0.03, 0.05, 0.1):
    print(f"{p:>20.3f}{p:>12.4f}{되돌리기(p, r):>12.4f}")

print(f"\n샘플 평균 {샘플CTR:.4f} 를 되돌리면 {되돌리기(샘플CTR, r):.5f} · 원래 CTR {원래CTR:.5f}")
print("두 값이 같다 — 공식이 맞다는 뜻이다.")
```

```
원본      노출   500,000  클릭  1,005  CTR 0.2010%
5% 샘플링 노출    25,954  클릭  1,005  CTR 3.8722%
→ 샘플에서 CTR 이 19.3배로 부푼다

        샘플에서 모델이 낸 값      그대로 쓰면        되돌리면
               0.010      0.0100      0.0005
               0.030      0.0300      0.0015
               0.050      0.0500      0.0026
               0.100      0.1000      0.0055

샘플 평균 0.0387 를 되돌리면 0.00201 · 원래 CTR 0.00201
두 값이 같다 — 공식이 맞다는 뜻이다.
```

되돌리는 식은 `p / (p + (1-p)/r)` 이고, `r` 이 남긴 비율이다. 보정을 빼먹으면 예측값이 **19배로 부푼 채** 입찰에 들어간다.

**여기서 무슨 일이 벌어지는지까지 말하면 좋다.** 입찰가는 대체로 예측 확률에 비례하니, 19배 부푼 값으로 입찰하면 광고비를 그만큼 더 쓴다. 모델 지표는 멀쩡한데 비용만 터지는 사고가 이렇게 난다.

## 3. AUC — "지표는 올랐는데 매출이 그대로다"

**Q. 오프라인 AUC가 0.72에서 0.75로 올랐는데 A/B 테스트에서 매출이 안 움직였습니다. 왜일까요?**

이 질문이 이 글의 중심이다. 답은 하나로 요약된다. **AUC는 줄 세우기만 재고, 값이 맞는지는 안 잰다.**

세 모델을 만들어 비교해 보면 분명해진다.

```python
import random, math, bisect

random.seed(20260815)
N = 200_000

# 노출마다 "진짜 클릭 확률"이 있고, 라벨은 그 확률로 뽑힌다.
진짜 = [min(0.05, max(0.0002, random.lognormvariate(-6.4, 0.9))) for _ in range(N)]
라벨 = [1 if random.random() < p else 0 for p in 진짜]
평균 = sum(라벨) / N

예측A = [평균] * N                                              # 전부 평균값만 답한다
예측B = [min(0.5, max(1e-5, p * math.exp(random.gauss(0, 0.35)))) for p in 진짜]
예측C = [min(0.9, p * 3) for p in 예측B]                        # B 와 순위는 같고 값만 3배

def auc(pred):
    양 = sorted(p for p, y in zip(pred, 라벨) if y == 1)
    음 = sorted(p for p, y in zip(pred, 라벨) if y == 0)
    합 = 0.0
    for p in 양:
        아래 = bisect.bisect_left(음, p)
        같음 = bisect.bisect_right(음, p) - 아래
        합 += 아래 + 같음 / 2
    return 합 / (len(양) * len(음))

def 로그로스(pred):
    return -sum(math.log(p) if y else math.log(1 - p) for p, y in zip(pred, 라벨)) / N

def copc(pred):
    return sum(라벨) / sum(pred)

print(f"노출 {N:,}건 · 클릭 {sum(라벨):,}건 ({평균:.3%})")
print(f"{'모델':<30}{'AUC':>8}{'로그로스':>12}{'COPC':>9}")
for 이름, p in (("A: 평균값만 답한다", 예측A),
                ("B: 구분도 하고 값도 맞다", 예측B),
                ("C: B 와 순위 같고 값만 3배", 예측C)):
    print(f"{이름:<28}{auc(p):>8.4f}{로그로스(p):>12.5f}{copc(p):>9.3f}")

print("\nCOPC = 실제 클릭 ÷ 예측 합. 1 이면 잘 맞고, 1 보다 작으면 과대예측이다.")
print("C 는 AUC 가 B 와 똑같은데 COPC 만 어긋났다 — 줄 세우기는 같고 값이 틀렸다.")
```

```
노출 200,000건 · 클릭 501건 (0.251%)
모델                                 AUC        로그로스     COPC
A: 평균값만 답한다                   0.5000     0.01751    1.000
B: 구분도 하고 값도 맞다               0.7180     0.01667    0.952
C: B 와 순위 같고 값만 3배            0.7180     0.01922    0.317

COPC = 실제 클릭 ÷ 예측 합. 1 이면 잘 맞고, 1 보다 작으면 과대예측이다.
C 는 AUC 가 B 와 똑같은데 COPC 만 어긋났다 — 줄 세우기는 같고 값이 틀렸다.
```

표를 세로로 읽어 보자. **A는 AUC가 0.5로 최악인데 COPC는 1.000으로 완벽하다.** 아무것도 구분 못 하지만 평균은 정확히 맞혔기 때문이다.

**C는 AUC가 B와 소수점까지 같은데 COPC가 0.317이다.** 예측값을 3배로 부풀렸지만 순서는 그대로라 AUC가 안 움직였다. 이 모델을 배포하면 광고비를 3배 쓴다.

**답의 핵심 문장은 이것이다 — "AUC가 올랐다는 것은 줄 세우기가 좋아졌다는 뜻이고, 매출은 값이 맞아야 움직입니다. 보정 지표를 같이 봐야 합니다."**

여기까지 말하면 대체로 꼬리 질문이 온다. "그럼 로그로스를 보면 되나요?" 위 표에서 로그로스는 셋을 제대로 갈랐다. B가 가장 낮고 C가 가장 높다. **로그로스는 줄 세우기와 값 맞추기를 둘 다 반영하지만, 어느 쪽이 문제인지는 알려 주지 않는다.** 그래서 AUC와 COPC를 나란히 본다.

## 4. 보정 — "확률이 실제와 다르면 뭐가 문제인가"

**Q. 모델이 낸 값이 실제 확률과 다르면 구체적으로 무엇이 깨지나요?**

세 가지가 순서대로 깨진다.

**첫째, 입찰가가 틀린다.** 광고 입찰가는 대체로 예상 클릭 확률에 클릭당 가치를 곱해 만든다. 확률이 두 배로 부풀면 입찰가도 두 배가 되어 필요 이상으로 비싸게 낙찰받는다.

**둘째, 예산 배분이 틀린다.** 어느 캠페인에 얼마를 쓸지 정할 때 예상 성과를 쓴다. 캠페인마다 부푼 정도가 다르면 배분 자체가 어긋난다.

**셋째, 사람이 모델을 못 믿게 된다.** "예상 전환 100건"이라 했는데 실제가 60건이면, 다음부터 아무도 그 숫자를 안 본다.

**Q. 보정은 어떻게 하나요?**

가장 단순한 것은 상수 하나를 곱하는 것이다. 최근 기간의 COPC를 구해 예측값에 곱하면 평균은 맞는다. 다만 이것은 **평균만** 맞추는 방법이라, 구간별로 어긋난 것은 못 잡는다.

구간별로 보려면 예측값을 열 개쯤 구간으로 나누고 구간마다 실제 비율과 비교한다. 낮은 구간에서는 과소예측하고 높은 구간에서는 과대예측하는 꼴이 흔하다. 이때는 구간별 보정이나 Platt scaling·isotonic regression을 쓴다.

**답에 반드시 붙여야 할 말이 하나 있다.** "보정은 배포 전에 한 번 하고 끝나는 것이 아니라 계속 재야 합니다." 시장이 변하면 어제 맞던 보정이 오늘 어긋난다. COPC를 시간대별로 대시보드에 올려 두고 1에서 벗어나면 알림이 가게 하는 것이 실무의 기본형이다.

:::deep 왜 다운샘플링만으로 보정이 안 끝나나

2절의 되돌리기 공식은 **정확히 이론대로 뽑았을 때만** 맞는다. 실제로는 어긋나는 이유가 몇 가지 있다.

먼저 샘플링 비율이 균일하지 않은 경우다. 트래픽이 많은 시간대만 더 많이 버리거나, 특정 지면에서만 다른 비율로 뽑으면 되돌리기 상수도 달라야 한다. 하나의 `r` 로 되돌리면 그 차이만큼 어긋난다.

둘째로 모델 자체의 편향이 남아 있다. 되돌리기는 샘플링 때문에 생긴 치우침만 없앤다. 모델이 원래부터 특정 구간을 과대예측하고 있었다면 그것은 그대로 남는다.

셋째로 지연 전환이다. 전환은 클릭 후 며칠 뒤에도 일어난다. 학습 시점에 아직 안 일어난 전환이 라벨에서 0으로 들어가면 모델은 실제보다 낮게 배운다. 이 경우 되돌리기를 정확히 해도 COPC가 1을 넘는다.

**면접에서 "COPC가 1.15인데 원인이 뭘까요"를 물으면 이 셋을 후보로 대면 된다.** 그리고 어떻게 구분할지까지 말한다 — 지연 전환이면 관측 기간을 늘렸을 때 COPC가 1로 수렴하고, 샘플링 문제면 지면별로 COPC가 갈린다.
:::

## 5. 데이터 누수 — "오프라인은 좋은데 온라인이 나쁘다"

**Q. 검증 AUC는 좋은데 배포하면 성능이 뚝 떨어집니다. 어디를 보시겠어요?**

가장 먼저 볼 곳은 **데이터를 어떻게 나눴는지**다. 시간이 있는 데이터를 무작위로 나누면 미래가 학습에 섞인다.

```python
import random, bisect

random.seed(11)
N = 60_000                                   # 30일치, 하루 2,000건

def auc(pred, 라벨):
    양 = sorted(p for p, y in zip(pred, 라벨) if y == 1)
    음 = sorted(p for p, y in zip(pred, 라벨) if y == 0)
    합 = 0.0
    for p in 양:
        아래 = bisect.bisect_left(음, p); 같음 = bisect.bisect_right(음, p) - 아래
        합 += 아래 + 같음 / 2
    return 합 / (len(양) * len(음))

# 날마다 인기 소재가 바뀐다
데이터 = []
for i in range(N):
    날 = i // 2000
    소재 = random.randrange(50)
    인기 = (소재 == (날 * 7) % 50)
    데이터.append((날, 소재, 1 if random.random() < (0.20 if 인기 else 0.03) else 0))

# 피처: "그 날 그 소재의 CTR" — 실무에서 흔히 쓰는 일자별 통계
def 학습(train):
    표 = {}
    for 날, 소재, y in train:
        n, c = 표.get((날, 소재), (0, 0))
        표[(날, 소재)] = (n + 1, c + y)
    평균 = sum(y for _, _, y in train) / len(train)
    return {k: (c + 20 * 평균) / (n + 20) for k, (n, c) in 표.items()}, 평균

섞은것 = 데이터[:]
random.shuffle(섞은것)
경계 = int(N * 0.8)
표1, 평균1 = 학습(섞은것[:경계])
검증1 = 섞은것[경계:]
a1 = auc([표1.get((d, s), 평균1) for d, s, _ in 검증1], [y for _, _, y in 검증1])

앞 = [d for d in 데이터 if d[0] < 24]
뒤 = [d for d in 데이터 if d[0] >= 24]
표2, 평균2 = 학습(앞)
a2 = auc([표2.get((d, s), 평균2) for d, s, _ in 뒤], [y for _, _, y in 뒤])

print(f"피처: 그 날 그 소재의 CTR")
print(f"{'나누는 방법':<24}{'검증 AUC':>10}")
print(f"{'무작위로 8:2':<23}{a1:>10.4f}")
print(f"{'날짜로 24일 / 6일':<22}{a2:>10.4f}")
print(f"\n같은 데이터, 같은 코드인데 {a1-a2:.3f} 만큼 벌어진다.")
print("무작위로 나누면 검증에 쓸 날의 통계가 학습에 들어간다 — 답을 미리 본 셈이다.")
print("서비스에서는 오늘 통계를 오늘 쓸 수 없으니, 실제 성능은 아래쪽에 가깝다.")
```

```

나누는 방법                      검증 AUC
무작위로 8:2                   0.5576
날짜로 24일 / 6일              0.5000

같은 데이터, 같은 코드인데 0.058 만큼 벌어진다.
무작위로 나누면 검증에 쓸 날의 통계가 학습에 들어간다 — 답을 미리 본 셈이다.
서비스에서는 오늘 통계를 오늘 쓸 수 없으니, 실제 성능은 아래쪽에 가깝다.
```

두 줄의 차이가 곧 **가짜 성능**이다. 아래쪽 0.5000이 정직한 값이고, 이 피처는 사실 예측에 아무 도움이 안 된다.

**답의 핵심 문장 — "시간이 있는 데이터는 반드시 시간으로 나눕니다. 무작위로 나누면 서비스에서 못 쓰는 정보가 검증에 들어갑니다."**

**Q. 누수인지 아닌지 어떻게 구분하나요?**

기준은 하나다. **"서빙 시점에 이 값을 실제로 알 수 있나?"** 이것만 물으면 대부분 걸러진다.

- 그 날의 소재별 CTR → 오늘 요청을 처리할 때는 오늘 통계가 아직 없다. 누수다.
- 사용자의 최근 30일 클릭 수 → 어제까지로 계산했다면 안전하다. 오늘 것을 포함하면 누수다.
- 전환 금액 → 전환이 일어난 뒤에만 안다. 전환 예측 피처로 쓰면 누수다.

## 6. 피처 — "어떤 피처를 쓰겠나"

**Q. CTR 예측에 어떤 피처를 쓰시겠어요?**

나열만 하면 점수가 안 나온다. **묶어서 말하고 각 묶음이 무엇을 잡는지 붙인다.**

| 묶음 | 예 | 무엇을 잡나 |
|---|---|---|
| 광고 쪽 | 소재 id, 업종, 크기, 텍스트 길이 | 이 광고 자체가 원래 잘 눌리나 |
| 지면 쪽 | 지면 id, 위치, 화면 크기 | 이 자리가 원래 잘 눌리나 |
| 사용자 쪽 | 관심사, 최근 행동, 재방문 여부 | 이 사람이 이런 광고를 좋아하나 |
| 맥락 | 시간대, 요일, 기기 | 지금이 눌릴 때인가 |
| 교차 | 사용자 관심사 × 광고 업종 | 이 조합이 맞나 |

**마지막 줄이 핵심이다.** 앞의 네 묶음은 각각 "평균적으로 잘 눌리나"만 잡는다. 개인화는 교차에서 나온다. GBDT는 교차를 어느 정도 스스로 찾지만, 카디널리티가 큰 범주형끼리의 교차는 임베딩 쪽이 낫다.

**Q. 피처를 하나 더 넣을지 말지 어떻게 정하나요?**

세 가지를 본다. 오프라인 지표가 얼마나 오르나, 서빙에서 그 값을 제때 가져올 수 있나, 그리고 **그 피처가 없을 때 무너지지 않나**.

세 번째가 실무에서 자주 빠지는 것이다. 사용자 프로필 조회가 30ms 걸리는데 예산이 15ms면 그 피처는 못 쓴다. 쓰더라도 조회가 실패했을 때의 기본값을 정해 둬야 하고, 그 기본값으로도 모델이 크게 안 망가지는지 확인해야 한다.

## 7. 모델 선택 — "왜 딥러닝이 아닌가"

**Q. 요즘 다 딥러닝 쓰는데 왜 GBDT를 쓰시겠어요?**

되받아쳐야 할 질문이다. **"둘 다 씁니다. 어디에 쓰느냐가 다릅니다."**

| | GBDT | 딥러닝 |
|---|---|---|
| 잘하는 것 | 수치형·저카디널리티 범주형, 표 형태 데이터 | 고카디널리티 id, 임베딩, 순서 있는 행동 |
| 학습 | 빠르고 튜닝이 쉽다 | 느리고 손이 많이 간다 |
| 서빙 | 트리 수만큼 비용 | 행렬 곱 — GPU면 빠르다 |
| 해석 | 피처 중요도가 바로 나온다 | 따로 도구가 필요하다 |
| 갱신 | 대체로 전체 재학습 | 이어서 학습하기 쉽다 |

**실무의 답은 대체로 "구조가 정해진 피처는 GBDT, id 계열은 임베딩"이다.** 사용자 id나 소재 id처럼 값이 수백만 개인 것을 GBDT에 넣으면 트리가 감당을 못 한다.

한 가지 더 붙이면 좋은 것이 있다. **처음부터 큰 모델로 시작하지 않는다.** 로지스틱 회귀로 기준선을 만들고, 그것보다 얼마나 나아지는지로 다음 모델을 판단한다. 기준선이 없으면 "0.75가 좋은 건가"를 아무도 모른다.

## 8. 랭킹 — "왜 pCTR로만 줄 세우면 안 되나"

**Q. 클릭 확률이 가장 높은 광고를 위에 놓으면 되지 않나요? [무대: 공통]**

안 된다. **광고주가 내는 돈이 광고마다 다르기 때문이다.**

클릭 확률이 5%인데 클릭당 100원인 광고와, 1%인데 2,000원인 광고가 있다면 뒤엣것이 스무 배 낫다. 그래서 확률과 금액을 곱한 값으로 줄을 세우는데, 이것이 eCPM이다.

여기까지는 대부분 답한다. 한 단계 더 들어가면 갈린다.

**Q. 그러면 eCPM만 최대로 하면 되나요?**

당장은 그렇고 길게 보면 아니다. 세 가지를 같이 봐야 한다.

**첫째, 사용자 경험이다.** 돈만 보고 줄 세우면 관련 없는 광고가 계속 뜨고, 사용자가 떠나면 인벤토리 자체가 준다. 그래서 품질 점수를 곱하거나 하한을 둔다.

**둘째, 다양성이다.** 같은 광고주 소재가 화면을 채우면 클릭률이 떨어진다. 같은 캠페인은 하나만, 같은 업종은 둘까지 같은 규칙을 넣는다.

**셋째, 탐색이다.** 새 소재는 데이터가 없어 예측이 낮게 나오고, 낮게 나오니 안 뜨고, 안 뜨니 영영 데이터가 안 쌓인다. 이 고리를 끊으려면 일정 비율을 새 소재에 배정해야 한다.

**핵심 문장 — "eCPM은 이번 요청의 기대 수익이고, 랭킹은 그것과 장기 수익의 절충입니다."** 이 문장이 나오면 대체로 다음 주제로 넘어간다.

## 9. 지연과 피드백 — "전환은 며칠 뒤에 일어난다"

**Q. 클릭하고 사흘 뒤에 구매하는 사람이 있습니다. 학습을 어떻게 하시겠어요?**

이 질문은 답이 딱 떨어지지 않아서 판단을 보기 좋다.

**문제부터 정확히 말한다.** 어제 클릭한 건 중 아직 전환 안 한 것을 0으로 놓고 배우면, 실제로는 내일 전환할 것까지 0으로 배운다. 모델은 전환율을 실제보다 낮게 본다.

**선택지는 셋이다.**

기다리는 방법이 가장 단순하다. 관측 창을 사흘로 잡고 사흘 지난 데이터만 학습에 쓴다. 라벨은 정확해지지만 모델이 항상 사흘 늦는다. 소재가 빨리 바뀌는 곳에서는 이 지연이 더 손해다.

바로 쓰되 보정하는 방법도 있다. 아직 전환 안 한 건을 0으로 넣되, 시간이 지나면 전환할 확률을 따로 모델링해 가중치를 준다. 구현이 복잡한 대신 지연이 없다.

둘을 섞는 방법이 실무에서 흔하다. **빠른 모델은 짧은 창으로 자주 갱신하고, 보정 상수는 긴 창으로 천천히 맞춘다.** 여기까지 말하면 "왜 그렇게 나눴나"가 이어지는데, 답은 "줄 세우기는 최신 데이터가 중요하고 값 맞추기는 정확한 라벨이 중요해서"다.

**Q. 모델이 자기가 만든 데이터로 다시 배우는 문제는 어떻게 보시나요?**

모델이 높게 본 광고만 노출되니, 다음 학습 데이터에는 그 광고만 있다. 낮게 본 광고는 영영 기회를 못 받아 예측을 고칠 데이터가 안 쌓인다.

**답의 핵심은 "일정 비율을 무작위로 노출해 편향 없는 데이터를 확보합니다"이다.** 그 비율만큼 단기 수익을 포기하는 대신, 그 데이터로 모델을 고칠 수 있다. 비율을 얼마로 할지는 실험으로 정하는데 보통 한 자릿수 퍼센트다.

## 10. 모르는 것을 물었을 때

**모르는 것을 아는 척하는 것이 면접에서 가장 큰 감점이다.**

경력 면접에서는 모르는 질문이 반드시 나온다. 면접관도 그것을 안다. 보는 것은 지식의 넓이가 아니라 **모르는 상황에서 어떻게 하는지**다.

세 단계로 답하면 된다. **먼저 모른다고 말한다.** "그건 안 다뤄 봤습니다"를 먼저 말하면 뒤에 오는 추측이 추측으로 정확히 전달된다.

**그다음 아는 것과 연결한다.** "다만 비슷한 걸 해 본 적이 있는데, 그때는 이랬습니다"로 이어 간다. 완전히 새로운 문제여도 원리를 아는 것에서 유추할 수 있다.

**마지막으로 어떻게 알아낼지 말한다.** "이건 데이터를 먼저 보고 판단할 문제인 것 같습니다. 저라면 먼저 이걸 재 보겠습니다"까지 가면, 모른다는 답이 오히려 좋은 답이 된다.

반대로 하지 말아야 할 것도 분명하다. 들어 본 용어를 나열하는 것, 질문을 자기가 아는 주제로 돌리는 것, "상황에 따라 다릅니다"로 끝내고 결론을 안 내는 것이다. 셋 다 "판단을 못 한다"로 읽힌다.

## 한눈 정리

| 질문 | 답의 핵심 한 줄 |
|---|---|
| CTR 0.2%를 어떻게 학습하나 | 정확도를 버리고, 다운샘플링하되 되돌리기까지 한다 |
| 다운샘플링하면 값이 부풀지 않나 | `p / (p + (1-p)/r)` 로 되돌린다. 안 하면 19배 부푼다 |
| AUC는 올랐는데 매출이 그대로다 | AUC는 줄 세우기만 잰다. 보정 지표를 같이 본다 |
| 확률이 실제와 다르면 뭐가 문제인가 | 입찰가·예산 배분·모델 신뢰가 순서대로 깨진다 |
| 보정은 어떻게 하나 | 상수 곱은 평균만 맞춘다. 구간별로 재고 계속 감시한다 |
| 오프라인은 좋은데 온라인이 나쁘다 | 데이터를 시간으로 나눴는지부터 본다 |
| 누수인지 어떻게 아나 | "서빙 시점에 이 값을 알 수 있나"만 묻는다 |
| 어떤 피처를 쓰겠나 | 다섯 묶음으로 말하고, 개인화는 교차에서 나온다고 붙인다 |
| 왜 딥러닝이 아닌가 | 둘 다 쓴다. 구조화 피처는 GBDT, id 계열은 임베딩 |
| pCTR로만 줄 세우면 안 되나 | 금액이 다르다. eCPM 뒤에 품질·다양성·탐색을 붙인다 |
| 전환이 며칠 뒤에 온다 | 빠른 모델은 짧은 창, 보정은 긴 창으로 나눈다 |
| 모델이 자기 데이터로 배운다 | 일정 비율을 무작위로 노출해 편향 없는 데이터를 만든다 |
| 모르는 걸 물었다 | 모른다고 먼저 말하고, 아는 것과 잇고, 알아낼 방법을 말한다 |

## 헷갈리기 쉬운 점

- **AUC가 높으면 좋은 모델이라고 말하지 마라.** AUC 0.5인 모델이 COPC 1.000일 수 있고, AUC가 같은 두 모델의 COPC가 세 배 차이 날 수 있다.
- **다운샘플링을 말하면서 되돌리기를 빼먹지 마라.** 이 한 쌍은 항상 같이 나온다.
- **"상황에 따라 다릅니다"로 끝내지 마라.** 어떤 상황이면 어느 쪽인지까지 말해야 답이 된다.
- **피처를 나열만 하지 마라.** 묶음과 그 묶음이 잡는 것을 붙여야 한다.
- **검증 데이터를 무작위로 나누지 마라.** 시간이 있는 데이터에서는 그 자체가 누수다.
- **오프라인 지표만으로 배포를 결정하지 마라.** 오프라인과 온라인이 어긋나는 이유를 설명할 수 있어야 한다.
- **모르는 것을 추측으로 채우지 마라.** 추측이라고 말하고 하는 추측은 감점이 아니다.
