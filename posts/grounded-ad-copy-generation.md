모델 팀 35주째 월요일, 서연 씨가 지훈 씨에게 런솔 라이트의 상품 설명으로 검색 광고 문구를 5개 써 달라고 했습니다. 예전에 손으로 쓴 문구 하나는 설명에 없는 「가장 가벼운」을 넣었다가 심사에서 빠졌다고 합니다.

선배는 모델에게 문구를 쓰게 하되, 문구마다 기댄 구절을 설명에서 그대로 옮겨 적게 하자고 했습니다. 그 구절이 정말 설명 안에 있는지는 코드가 보기로 했습니다. 다른 광고주의 설명 9개도 같이 돌렸고, 그 가운데 둘은 인사말뿐인 글입니다.

**모델이 쓴 광고 문구가 설명에 없는 말을 하지 않았다는 것을, 사람이 하나하나 읽지 않고 어떻게 확인할까요?**

광고주가 올린 상품 설명 같은 글을 자산 텍스트, 광고 문구를 카피라고 부릅니다. 카피가 기댄 구절은 근거이고, 이 글은 그 구절을 quote 필드로 받습니다. 근거와 길이, 중복, 최상급 표현을 규칙으로 보는 코드는 게이트입니다. 설명에 없는 숫자나 최상급이 나가면 광고가 심사에서 빠지고, 그 책임은 광고주가 집니다.

> **한 줄 요약:** 서연 씨의 런솔 라이트를 포함한 광고주 자산 10개를 qwen3.5:27b 에 하나씩 주고, 카피를 5개까지 받았습니다. 카피마다 그 카피가 기댄 자산의 구절을 quote 로 같이 받았습니다. 답 10개는 모두 스키마대로 읽혔고, 상품 사실이 없는 얇은 자산 둘은 no_generation 으로 왔습니다. 나머지 8개가 낸 카피 40개를 근거, 길이, 중복, 최상급 게이트에 차례로 넣자 35개가 남았습니다. 걸린 5개는 모두 근거 게이트였고, quote 의 숫자 뒤에 공백이 끼어 자산의 글자와 달랐습니다. 남은 35개 가운데 13개는 quote 를 그대로 옮긴 문장이었고, 2개는 시스템 메시지와 달리 「~하세요」로 끝났습니다. 숲결 러닝화 가운데 가장 가볍다는 자산의 문장은 범위가 빠진 카피가 되었는데도 최상급 게이트를 지났습니다. 게이트는 자산과 글자가 다른 카피를 거르고, 과장과 말투는 다음 글의 판정이 봅니다.

> **골라 읽는 법** — 절이 6개입니다. 절마다 표나 코드나 카드가 있어 그것만 보고 넘어가도 됩니다.
>
> - 자산 텍스트 10개와 얇은 자산 둘 → 1절
> - 카피와 quote 를 함께 받는 답의 꼴 → 2절
> - 게이트 넷의 코드와 걸린 카피 5개 → 3절
> - 서연 씨 자산의 카피 다섯과 게이트 결과 → 4절
> - 카피를 쓰지 않은 답, no_generation → 5절
> - 담장 안과 열린 RTB 에서 카피를 만드는 때와 길이 → 6절

이 글의 자산 텍스트 10개는 설명을 위해 만든 가상 데이터입니다. 상품의 이름과 사실도 모두 가상이고, 런솔, 모노웍스, 숲결은 이 트랙의 가상 브랜드입니다. 서연 씨의 자산(x01)은 30주째 [키워드 확장 전략](post.html?id=keyword-expansion-strategies) 편의 상품 설명 그대로입니다. 자산은 `scripts/gen-copy-data.py` 가 만들고, 블록은 그 리터럴을 글자 그대로 옮겼습니다. 모델의 답은 지어낸 값이 아닙니다. 2026-11-07 에 이 블로그를 쓰는 맥에서 Ollama 0.40.11 로 qwen3.5:27b 를 띄워 기록했습니다. 기록 파일은 `data/llm-records/` 의 `grounded-ad-copy-generation.json` 입니다. 카드 속 파랑은 자산 텍스트와 게이트를 지난 카피, 벽돌색은 모델의 답입니다. 회색은 게이트에 걸리거나 카피를 쓰지 않은 자리, 점선 상자는 시스템 메시지와 게이트의 조건입니다.

## 1. 카피는 자산 텍스트에서 출발합니다

**모델은 광고주가 올린 자산 텍스트 하나만 읽고 카피를 씁니다. 자산 10개 가운데 8개는 상품의 사실을 적은 글이고, 2개는 사실 없이 인사만 적은 얇은 자산입니다.**

자산 텍스트는 광고주가 광고 도구에 올리는 상품 설명입니다. 서연 씨의 x01 은 200자 안팎의 네 문장입니다. 입문자용이라는 것, 밑창 전체의 쿠션 폼, 한 짝 240g 의 무게, 넉넉한 앞코가 앞의 세 문장에 있습니다. 넷째 문장은 230mm 부터 290mm 까지 5mm 단위의 사이즈와, 받은 날부터 30일 안의 교환 한 번입니다.

모델은 이 글 말고는 런솔 라이트를 모릅니다. 상품 데이터베이스나 웹을 찾아보지 않고, 받은 자산 텍스트 하나로 카피를 씁니다. 그래서 카피에 들어갈 수 있는 사실은 이 네 문장 안에 있는 것뿐입니다. 24주째 [RAG](post.html?id=rag-basics) 편이 검색한 조각을 입력에 넣고, 답의 값이 조각에 있는지 코드로 대조한 것과 같은 자리입니다. 여기서는 자산 텍스트가 조각이고 카피가 답입니다.

x02 부터 x08 까지는 이 트랙의 가상 세계에 있는 다른 광고주의 상품입니다. 러닝화 둘, 러닝 양말, GPS 러닝 시계, 러닝 벨트, 캠핑 의자, 제주 자유여행이고, 글마다 120~200자입니다. 무게, 크기, 값, 기간 같은 숫자가 들어 있고, 건강이나 몸에 관한 효능은 넣지 않았습니다. x03 에는 「숲결 러닝화 가운데 가장 가벼운 모델」이라는, 범위를 단 최상급이 하나 있습니다.

## 2. 카피마다 인용 구절을 같이 받습니다

**답은 status 와 카피 목록이고, 카피마다 copy 와 quote 를 받습니다. 답 10개는 모두 스키마대로 읽혔고, no_generation 은 얇은 자산 둘뿐이었습니다. 사실을 적은 자산 8개는 카피를 5개씩, 모두 40개 냈습니다.**

시스템 메시지는 카피를 5개까지, 한 카피를 한국어 40자 이하로 쓰게 했습니다. 카피마다 quote 를 붙이게 했는데, quote 는 그 카피가 기댄 구절을 자산에서 글자 그대로 옮긴 것입니다. 띄어쓰기와 문장 부호도 바꾸지 말고, 카피의 사실은 모두 quote 안에 있어야 한다고 적었습니다. 숫자는 자산에 있는 것만, 최상급 표현은 자산에 그 말이 있을 때만 쓰게 했습니다. 문장 끝은 명사나 「~합니다」 꼴로 끝내게 했고, 전문은 끝의 더 깊이 보기에 있습니다.

사실이 부족해 카피를 쓸 수 없으면 status 를 no_generation 으로 두고 카피 목록을 비우게 했습니다. no_generation 은 생성 없음이라는 뜻의 값입니다. 답의 꼴은 JSON 한 줄이고, 키는 status 와 candidates 둘입니다. candidates 의 항목마다 copy 와 quote 두 문자열이 있습니다. 32주째 [LLM 라벨과 코드 랭커](post.html?id=llm-labels-code-ranker) 편은 근거를 문장 id 로 받았습니다. 이번에는 자산을 문장으로 나눠 보내지 않았고 근거가 문장의 일부일 수 있어서, 구절의 글자를 그대로 받습니다.

답을 스키마대로 읽는 법은 22주째 [구조화 출력](post.html?id=structured-output) 편과 같습니다. 키가 둘뿐이고 카피가 5개 이하이며, 항목마다 두 문자열이어야 읽은 답입니다. status 가 ok 인데 카피가 없거나, no_generation 인데 카피가 있으면 읽지 못한 답으로 셉니다. 10번 모두 thinking 을 끄고 temperature 0 으로 보냈습니다. thinking 은 모델이 답 앞에 풀이를 먼저 쓰는 설정이고, 20주째 [LLM 모델 고르기](post.html?id=llm-model-selection) 편에서 보았습니다.

이 트랙의 다른 기록은 출력을 영어 라벨과 숫자로만 받았습니다. 이 기록만 copy 와 quote 두 값이 한국어이고, 나머지 값은 영어입니다. 한국어 카피는 아래 블록의 RECORD 줄에 기록 그대로 들어 있습니다.

## 3. 게이트 넷은 코드입니다

**카피 40개를 근거, 길이, 중복, 최상급 차례로 넣자 35개가 남았습니다. 걸린 5개는 모두 근거 게이트였고, 숫자는 맞았지만 quote 의 숫자 뒤에 공백이 끼어 자산의 글자와 달랐습니다. 길이, 중복, 최상급 게이트에 걸린 카피는 이 기록에 없었습니다.**

근거 게이트는 두 가지를 봅니다. quote 가 비어 있지 않고 자산 안에 글자 그대로 있어야 하고, 카피의 숫자가 모두 자산에 있어야 합니다. 숫자는 쉼표를 지우고 한 덩어리로 비교해서, 12,900 과 12900 은 같고 1240 안의 240 은 찾지 않습니다. RAG 편의 근거 대조가 숫자의 앞뒤를 본 것과 같은 까닭입니다. 숫자는 quote 가 아니라 자산 전체와 대조합니다.

길이 게이트는 공백과 문장 부호를 포함한 len() 이 40 이하인지 봅니다. 중복 게이트는 카피를 같은 자산에서 앞서 남은 카피와 비교합니다. 공백을 모두 지운 뒤 이웃한 두 글자씩 묶은 조각을 만드는데, 이 조각을 바이그램(bigram)이라고 부릅니다. 두 카피의 바이그램 집합으로 Jaccard 를 잽니다. Jaccard 는 교집합의 크기를 합집합의 크기로 나눈 값이고, 0.8 이상이면 같은 카피로 봅니다. 공백을 지우는 것은 띄어쓰기만 다른 두 카피를 같은 카피로 세기 위해서입니다.

최상급 게이트는 낱말 여섯을 봅니다. 최고, 최초, 1위, 유일, 가장, 국내 최대 가운데 카피에 든 낱말이 그 자산에도 있어야 지납니다. 카피는 근거부터 차례로 넣고, 처음 걸린 게이트 하나에서만 셉니다. 블록의 게이트 정의는 생성기 `scripts/gen-copy-data.py` 의 것을 글자 그대로 옮겼습니다. 다음 글도 같은 정의로 남은 카피를 가져갑니다.

게이트를 코드로 두면 같은 카피에 늘 같은 결과가 나오고, 걸린 까닭이 게이트 이름 하나로 남습니다. 그래서 광고주에게 「quote 가 자산에 없습니다」처럼 고칠 곳을 바로 알려 줄 수 있습니다. 블록의 5단계는 손으로 만든 카피 다섯으로 게이트마다 걸리는 경우를 하나씩 보입니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 게이트 넷(근거, 길이, 중복, 최상급)을 차례로 지나며 카피마다 처음 걸린 게이트를 세고, 걸린 까닭과 남은 여유를 찍는다.
from collections import Counter
from itertools import combinations

# 1단계: 게이트 넷을 둔다
# 아래 정의는 scripts/gen-copy-data.py 의 것을 글자 그대로 옮겼다. 다음 판정 편도 같은 정의로 남은 카피를 가져간다.
# 근거는 quote 가 자산 안에 글자 그대로 있고, 카피의 숫자가 모두 자산에 있어야 지난다. 숫자는 쉼표를 지운 덩어리로 비교한다.
# 길이는 공백과 문장 부호를 포함한 len() 이 40 이하여야 지난다.
# 중복은 공백을 지운 뒤 글자 두 개씩 묶은 집합의 Jaccard 가, 같은 자산에서 앞서 남은 카피 모두와 0.8 보다 작아야 지난다.
# 최상급은 카피에 든 SUPERLATIVES 의 낱말이 모두 그 자산에도 있어야 지난다.
SUPERLATIVES = ['최고', '최초', '1위', '유일', '가장', '국내 최대']
NUMBER = re.compile(r'\d+(?:,\d{3})*(?:\.\d+)?')


def numbers(text):
    return {n.replace(',', '') for n in NUMBER.findall(text)}


def gate_grounding(copy, quote, asset):
    return bool(quote) and quote in asset and numbers(copy) <= numbers(asset)


def gate_length(copy, max_len=40):
    return len(copy) <= max_len


def bigrams(text):
    s = ''.join(text.split())
    return {s[i:i + 2] for i in range(len(s) - 1)}


def jaccard(a, b):
    return len(a & b) / len(a | b) if a | b else 1.0


def gate_duplicate(copy, kept):
    return all(jaccard(bigrams(copy), bigrams(k)) < 0.8 for k in kept)


def gate_superlative(copy, asset):
    return all(word in asset for word in SUPERLATIVES if word in copy)


# 2단계: 카피를 게이트에 차례로 넣는다
# judge_copies 는 카피마다 처음 걸린 게이트 하나만 적고, 다 지나면 None 을 적는다. passing_copies 는 다 지난 카피만 돌려준다.
# 중복 게이트가 비교하는 kept 는 같은 답 안에서 앞서 네 게이트를 다 지난 카피다.
def judge_copies(record, assets):
    rows = []
    for aid, text in record.items():
        answer = read_answer(text)
        if answer is None:
            continue
        asset, kept = assets[aid], []
        for n, c in enumerate(answer['candidates'], 1):
            copy, quote = c['copy'], c['quote']
            if not gate_grounding(copy, quote, asset):
                failed = 'grounding'
            elif not gate_length(copy):
                failed = 'length'
            elif not gate_duplicate(copy, kept):
                failed = 'duplicate'
            elif not gate_superlative(copy, asset):
                failed = 'superlative'
            else:
                failed = None
                kept.append(copy)
            rows.append((aid, n, copy, quote, failed))
    return rows


def passing_copies(record, assets):
    return [(aid, n, copy, quote) for aid, n, copy, quote, failed in judge_copies(record, assets) if failed is None]


rows = judge_copies(RECORD, ASSET)
kept = passing_copies(RECORD, ASSET)
failed = Counter(r[4] for r in rows)
print(f'카피 {len(rows)}개 → 근거 {failed["grounding"]}, 길이 {failed["length"]}, 중복 {failed["duplicate"]}, '
      f'최상급 {failed["superlative"]} → 남은 카피 {len(kept)}개')
left = Counter(aid for aid, n, copy, quote in kept)
print('자산마다 남은 카피: ' + ', '.join(f'{aid} {left[aid]}' for aid in ASSET if answers[aid]['status'] == 'ok'))

# 3단계: 근거 게이트에 걸린 카피를 본다
# quote 가 자산 안에 없어서인지, 카피의 숫자가 자산에 없어서인지 나눠 센다.
# 공백을 무시하고 quote 를 자산에서 찾아, 자산의 그 자리를 quote 아래에 찍는다.
def asset_span(quote, asset):
    found = re.search(r'\s*'.join(re.escape(ch) for ch in quote if not ch.isspace()), asset)
    return found.group(0) if found else None


bad = [r for r in rows if r[4] == 'grounding']
print(f'quote 가 자산 안에 없음 {sum(r[3] not in ASSET[r[0]] for r in bad)}, '
      f'카피의 숫자가 자산에 없음 {sum(not numbers(r[2]) <= numbers(ASSET[r[0]]) for r in bad)}, '
      f'공백을 무시하면 자산 안에 있음 {sum(asset_span(r[3], ASSET[r[0]]) is not None for r in bad)}')
for aid, n, copy, quote, f in bad:
    print(f'  {aid}-{n} quote 「{quote}」')
    print(f'        자산 「{asset_span(quote, ASSET[aid])}」')

# 4단계: 길이, 중복, 최상급 게이트의 여유를 본다
# 가장 긴 카피, 같은 자산 안에서 Jaccard 가 가장 큰 두 카피와 그 quote, 최상급 낱말이 든 카피와 그 낱말이 든 자산 문장을 찍는다.
aid, n, copy, quote, f = max(rows, key=lambda r: len(r[2]))
print(f'가장 긴 카피 {aid}-{n} {len(copy)}자')
best = max((jaccard(bigrams(a[2]), bigrams(b[2])), a, b) for a, b in combinations(rows, 2) if a[0] == b[0])
print(f'같은 자산 안에서 Jaccard 가 가장 큰 쌍 {best[1][0]}-{best[1][1]}, {best[2][0]}-{best[2][1]} {best[0]:.2f}, '
      f'두 카피의 quote 가 같은가 {best[1][3] == best[2][3]}')
for r in best[1:]:
    print(f'  {r[0]}-{r[1]} 「{r[2]}」 quote 「{r[3]}」')
for aid, n, copy, quote, f in rows:
    for word in SUPERLATIVES:
        if word in copy:
            sentence = next(s for s in re.split(r'(?<=\.) ', ASSET[aid]) if word in s)
            print(f'최상급 「{word}」 {aid}-{n} 「{copy}」 {f or "통과"}')
            print(f'  자산 문장 「{sentence}」')

# 5단계: 손으로 만든 카피 다섯으로 게이트를 시험한다
# x01 자산에 카피 다섯을 적은 답을 만들어 같은 함수에 넣는다. 첫 카피는 지나고, 나머지는 하나씩 다른 게이트에 걸리게 만들었다.
TESTS = [('입문자용 러닝화, 한 짝 240g', '한 짝 무게 240g 으로 가볍고'),
         ('입문자용 러닝화,한 짝 240g', '한 짝 무게 240g 으로 가볍고'),
         ('무게 200g 의 가벼운 입문자용 러닝화', '한 짝 무게 240g 으로 가볍고'),
         ('쿠션 폼을 깐 입문자용 러닝화, 230mm 부터 290mm 까지 5mm 단위로 고릅니다', '사이즈는 230mm 부터 290mm 까지 5mm 단위로 있고'),
         ('가장 가벼운 입문자용 러닝화', '입문자용 러닝화입니다')]
test = json.dumps({'status': 'ok', 'candidates': [{'copy': c, 'quote': q} for c, q in TESTS]}, ensure_ascii=False)
for aid, n, copy, quote, f in judge_copies({'x01': test}, ASSET):
    print(f'시험 {n} {f or "통과"} {len(copy)}자 「{copy}」')

# 2단계 뜻: 카피 40개 가운데 근거 게이트에서 5개가 걸려 35개가 남았고, x08 은 1개만 남았다.
```

## 4. 서연 씨 자산의 카피 다섯은 모두 게이트를 지났습니다

**x01 의 카피 다섯은 네 게이트를 모두 지났습니다. 다섯 가운데 셋은 quote 와 글자까지 같아, 자산의 문장을 그대로 옮긴 것입니다. 남은 35개 전체에서는 13개가 그랬고, 2개는 「~하세요」로 끝났습니다.**

3절의 judge_copies 는 처음 걸린 게이트에서 멈춥니다. 아래 블록은 x01 의 카피마다 네 게이트를 따로따로 돌려, 지나면 O, 걸리면 X 로 찍습니다. quote 가 자산의 몇째 문장에서 왔는지도 찍습니다. 2단계는 한글을 두 자로 센 길이를, 3단계는 남은 35개에서 게이트가 보지 않는 것을 셉니다.


## 5. 생성 없음도 정상 답입니다

**얇은 자산 둘은 no_generation 으로 왔고, 답은 둘 다 12 토큰이었습니다. 쓸 사실이 없는 자산에 카피를 쓰지 않은 것이 맞는 답이고, 코드는 이 답을 실패가 아니라 정상인 결과로 다룹니다.**

x09 와 x10 의 답은 `{"status": "no_generation", "candidates": []}` 한 줄이었습니다. 시스템 메시지가 정한 꼴 그대로이고, 1절에서 본 대로 두 자산에는 상품도 숫자도 없습니다. 사실을 적은 자산 8개는 모두 ok 였으니, 이 기록에서 no_generation 은 얇은 자산에만 나왔습니다.

카피를 꼭 5개 쓰라고 하면 모델이 할 수 있는 것은 둘입니다. 자산에 없는 사실을 지어내거나, 인사말을 그대로 카피로 옮기는 것입니다. 지어낸 사실도 quote 만 자산에서 옮기고 숫자가 없으면 근거 게이트를 지납니다. 인사말을 옮긴 카피는 quote 가 자산 안에 있어 게이트 넷을 모두 지납니다. 그래서 쓸 사실이 없다는 판단은 게이트가 아니라 카피를 쓰는 쪽이 해야 합니다.

코드는 no_generation 을 읽지 못한 답이나 게이트에 걸린 카피와 따로 셉니다. 2절 블록의 read_answer 는 no_generation 에 카피가 없어야 읽은 답으로 봅니다. 광고 도구는 이 답을 받으면 카피 대신 정해 둔 안내 문장을 보입니다. 28주째 [자연어 → 타겟 조건](post.html?id=nl-to-targeting-query) 편이 거절 이유를 고정 템플릿으로 알린 것과 같은 방식입니다. 안내에는 무게, 크기, 값, 교환 조건처럼 적어 주면 카피가 될 사실의 종류를 적습니다.

no_generation 은 비용도 적게 듭니다. 아래 표에서 보듯 no_generation 의 답은 ok 의 답보다 출력 토큰도 시간도 훨씬 적습니다. 다만 no_generation 의 수는 따로 지켜봐야 합니다. 사실을 적은 자산에서 no_generation 이 늘면 시스템 메시지가 너무 엄격하다는 신호입니다. 이 기록에서는 사실을 적은 8개가 모두 ok 였습니다.

## 6. 카피를 만드는 때와 길이를 정하는 쪽이 무대마다 다릅니다

**자산에서 인용해 쓰고 코드가 거르는 순서는 두 무대가 같습니다. 담장 안은 플랫폼이 자산과 게이트와 길이 규칙을 함께 갖고, 열린 RTB 의 DSP 는 지면이 정한 길이에 맞는 카피를 골라 보냅니다.**

두 무대의 이름은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에서 풀었습니다. 1~5절의 셈은 두 무대가 같고, 다른 것은 자산을 누가 갖고 카피의 길이를 누가 정하느냐입니다.

### 담장 안에서는 플랫폼이 자산과 게이트와 길이 규칙을 함께 둡니다 [무대: 닫힌 생태계]

검색 광고를 파는 플랫폼은 광고주가 올린 자산 텍스트와 광고 지면과 심사를 모두 갖습니다. 그래서 광고주가 자산을 올릴 때 카피를 만들고, 게이트를 지난 카피만 광고주에게 보입니다. 걸린 카피에는 게이트 이름이 남아, 심사 전에 무엇을 고칠지 알려 줄 수 있습니다.

카피는 검색 요청이 올 때가 아니라 자산을 올릴 때 만듭니다. 이 기록에서 카피를 낸 답은 자산 하나에 12.2~27.6초가 걸렸습니다. 길이 상한도 플랫폼이 정한 규칙입니다. Google Ads 처럼 한국어를 두 자로 세는 곳이면, gate_length 도 그 규칙대로 세어야 합니다.

### 열린 RTB 에서는 지면이 정한 길이에 맞는 카피를 고릅니다 [무대: 열린 RTB]

열린 RTB 의 DSP 는 여러 매체의 네이티브 광고 지면에 입찰합니다. OpenRTB 네이티브 광고 명세 1.2 는 입찰 요청의 제목 자산에 len 필드를 둡니다. len 은 제목 글의 최대 길이이고, 명세는 25, 90, 140 을 권합니다. 설명 글(desc)은 길면 거래소가 자르거나 말줄임표로 줄일 수 있다고 적었습니다.

그래서 DSP 는 게이트를 지난 카피를 길이별로 미리 갖고 있다가, 요청의 len 에 맞는 것을 고릅니다. gate_length 의 max_len 이 요청마다 바뀌는 값이 됩니다. 자산과 게이트는 DSP 쪽에 있고, 길이 규칙은 지면을 가진 매체 쪽에 있습니다. 아래 표는 가상 데이터가 아니라 두 무대의 설계 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 자산 텍스트를 가진 쪽 | 플랫폼 | DSP |
| 카피를 만드는 때 | 자산을 올릴 때 | 자산을 올릴 때, 길이별로 |
| 길이 상한을 정하는 쪽 | 플랫폼의 광고 규칙 | 입찰 요청마다 지면의 len |
| gate_length 의 max_len | 고정된 값 | 요청마다 다른 값 |

## 헷갈리기 쉬운 점

- **인용이 있어도 카피가 과장일 수 있습니다.** 근거 게이트는 quote 가 자산 안에 있는지 볼 뿐, 카피가 자산의 뜻을 넘는지는 보지 않습니다. x03-5 「가장 가벼운 모델로 한 짝 무게는 280g 입니다」는 자산의 「숲결 러닝화 가운데」라는 범위를 뺐습니다. 「가장」이 자산에 있으니 최상급 게이트도 지났습니다. x04-5 는 quote 「물에 빨아도 쉽게 늘어나지 않습니다」에서 「쉽게」를 빼고 「늘어나지 않습니다」라고 썼습니다. 공정거래위원회 고시는 「최대」, 「최고」, 「최초」 같은 절대적 표현을, 사실임을 입증할 수 있을 때 쓸 수 있다고 적었습니다.
- **길이는 글자 수로 셉니다.** gate_length 는 공백과 문장 부호를 포함한 len() 이 40 이하인지 봅니다. 한글 한 글자도, 공백 하나도 1 입니다. 같은 카피를 한국어를 두 자로 세는 Google Ads 규칙으로 세면, x01 의 다섯은 46~68 이 됩니다. 「40자」는 카피가 나갈 자리의 규칙으로 정하고 그 규칙대로 세어야 합니다.
- **게이트를 지나도 좋은 카피라는 뜻은 아닙니다.** 게이트는 자산과 다른 글자와 숫자를 거를 뿐, 나은 카피를 고르지는 않습니다. 남은 35개 가운데 13개는 자산의 문장 그대로였고, 2개는 「~하세요」로 끝났습니다. x04 의 2번과 5번은 같은 quote 에 기댄 두 카피인데, Jaccard 0.50 이라 중복 게이트를 지났습니다. 남은 카피 가운데 무엇을 내보낼지는 다음 36주째 편이 판정으로 정합니다.

:::deep 시스템 메시지 전문과 기록한 방법
기록에 보낸 시스템 메시지입니다. 사용자 메시지는 「자산 텍스트:」 줄 아래에 자산 하나를 적은 글입니다. 프롬프트 파일은 `scripts/gen-copy-data.py --prompts grounded-ad-copy-generation` 이 씁니다. `--check` 는 프롬프트 파일 전체와 기록, 글의 ASSETS 리터럴과 게이트 정의를 다시 대조합니다.

```text
너는 검색 광고의 카피를 쓰는 작성자다. 광고주가 준 자산 텍스트 하나를 읽고, 그 자산에 적힌 사실만으로 광고 카피를 쓴다.
카피는 5개까지 쓴다. 카피 하나는 한국어 40자 이하다.
카피마다 quote 를 붙인다. quote 는 그 카피가 기대는 구절을 자산 텍스트에서 글자 그대로 옮긴 것이다. 띄어쓰기와 문장 부호도 바꾸지 않는다.
카피의 사실은 모두 그 카피의 quote 안에 있어야 한다. quote 에 없는 사실을 카피에 더하지 않는다.
숫자는 자산 텍스트에 있는 숫자만 쓴다. 할인율, 순위, 기간 같은 숫자를 새로 만들지 않는다.
최고, 최초, 1위, 유일, 가장, 국내 최대 같은 최상급 표현은 자산 텍스트에 그 말이 있을 때만 쓴다.
자산 텍스트에 상품의 사실이 부족해 카피를 쓸 수 없으면 status 를 no_generation 으로 두고 candidates 를 빈 목록으로 둔다. 카피를 하나라도 쓰면 status 는 ok 다.
카피의 문장 끝은 명사나 「~합니다」 꼴로 끝낸다.
카피에는 가운뎃점, 이모지, 1인칭 대명사를 쓰지 않는다. 숫자는 아라비아 숫자로 쓴다.
답은 아래 꼴의 JSON 한 줄로만 쓴다. 설명이나 다른 글은 붙이지 않는다.
{"status": "<ok|no_generation>", "candidates": [{"copy": "<한국어 40자 이하>", "quote": "<자산에서 그대로 옮긴 구절>"}]}
```

기록은 2026-11-07 에 받았고, 10번 모두 thinking 을 끄고 temperature 0, seed 7 로 보냈습니다. 「1인칭 대명사」 줄은 카피가 광고주 자신을 1인칭으로 부르는 말을 막으려고 넣었습니다. 시스템 메시지를 고쳐 다시 기록하지 않았습니다. 이 블로그는 기준 답이 스키마대로 읽히지 않을 때만 시스템 메시지를 고칩니다. 이번 답은 10개 모두 읽혔습니다. x07 의 「~하세요」 둘이나 띄어쓰기가 바뀐 quote 를 보고 고치면, 결과를 보고 고친 프롬프트가 됩니다.

이 기록으로 말할 수 없는 것도 셋입니다. 자산 10개에 기록 한 벌이라, 숫자 뒤의 공백이 다른 자산에서도 끼는지는 모릅니다. x01 의 「30일」처럼 그대로 옮긴 숫자도 있었습니다. 자산은 제가 쓴 가상 글이라, 실제 광고주의 글은 더 길고 문장이 더 복잡할 수 있습니다. 얇은 자산 둘이 no_generation 이었던 것도 이 두 글의 결과입니다. 상품 이름 하나만 적은 글처럼 사실이 조금 있는 자산에서는 다를 수 있습니다.

:::deep 게이트 식
네 게이트를 식으로 적습니다. $c$ 는 카피, $q$ 는 quote, $A$ 는 자산 텍스트, $K$ 는 같은 자산에서 앞서 남은 카피의 집합입니다. $N(x)$ 는 글 $x$ 에 든 숫자의 집합이고, 숫자는 쉼표를 지운 덩어리입니다.

$$\text{grounding}(c, q, A) = [\, q \ne \varnothing \;\wedge\; q \sqsubseteq A \;\wedge\; N(c) \subseteq N(A) \,]$$

$q \sqsubseteq A$ 는 $q$ 가 $A$ 의 이어진 부분 문자열이라는 뜻입니다. 숫자는 $N(q)$ 가 아니라 $N(A)$ 와 대조합니다.

$$\text{length}(c) = [\, |c| \le 40 \,]$$

$|c|$ 는 공백과 문장 부호를 포함한 글자 수입니다.

$$J(X, Y) = \frac{|X \cap Y|}{|X \cup Y|}, \qquad \text{duplicate}(c, K) = [\, \forall k \in K : J(B(c), B(k)) < 0.8 \,]$$

$B(x)$ 는 $x$ 에서 공백을 모두 지운 뒤 이웃한 두 글자씩 묶은 바이그램의 집합입니다.

$$\text{superlative}(c, A) = [\, \forall w \in S : w \in c \Rightarrow w \in A \,]$$

$S$ 는 최고, 최초, 1위, 유일, 가장, 국내 최대의 여섯 낱말입니다. 카피는 근거, 길이, 중복, 최상급 차례로 보고, 처음 거짓인 게이트에서 셉니다. $K$ 에는 네 게이트를 모두 지난 카피만 들어가서, 근거에서 걸린 카피는 뒤 카피의 중복 비교에 쓰이지 않습니다.

공백을 무시하는 근거 게이트는 $q$ 와 $A$ 에서 공백을 모두 지운 뒤 부분 문자열인지 봅니다. 이 기록에서는 걸린 5개가 그 식으로 모두 지납니다. 낱말 여섯은 이 글이 정한 목록이라, 공정거래위원회 고시가 예로 든 「제일」은 들어 있지 않습니다.
:::
