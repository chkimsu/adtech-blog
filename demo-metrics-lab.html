지표 실험실

같은 표본 하나에서 AUC · GAUC · LogLoss · NE · COPC 를 동시에 잽니다. 슬라이더 넷을 밀면 다섯 숫자가 각자 다른 방향으로 움직입니다. 요청 간 난이도 편차를 키우면 전체 AUC 는 오르는데 GAUC 는 제자리인 것을 그 자리에서 봅니다.

이 데모가 보여주는 것지표 다섯 개를 같은 표본 위에서 동시에 냅니다. 슬라이더를 밀 때 어느 지표가 반응하고 어느 지표가 꿈쩍도 안 하는지가 바로 보입니다. 왼쪽 ROC 곡선 두 개는 전체 AUC 와 GAUC 가 벌어지는 폭을 그림으로 보여 줍니다.
왜 알아야 하나전체 AUC 는 서로 다른 요청에서 온 노출끼리도 짝을 짓습니다. 경매는 그 짝을 안 씁니다. 한 요청 안에서만 줄을 세우기 때문입니다. 그래서 AUC 가 올라도 매출이 안 움직이는 배포가 나옵니다.
    이렇게 해보세요 — 5분
  1. 기본값 그대로 봅니다. 전체 AUC 0.7413, GAUC 0.6177. 간격이 0.1236입니다. 오른쪽 카드에서 요청 하나 안의 순위도 같이 봅니다.
  2. 요청 간 난이도 편차를 1.40까지 밉니다. AUC 는 0.8311로 0.09 올라가는데 GAUC 는 0.6287로 0.011 움직이고 맙니다. 두 곡선 사이가 벌어지는 것을 보세요.
  3. 기본으로를 누른 뒤 이번에는 요청 안 분별력을 75%로 올립니다. AUC 0.7776, GAUC 0.6818 — 이번에는 둘이 같이 오릅니다. 경매가 실제로 쓰는 개선은 이쪽입니다.
  4. 보정 배수를 3.00으로 밉니다. 순위 지표는 그대로인데 NE 가 1.2535, COPC 가 0.342가 됩니다. NE 가 1을 넘으면 기저 CTR 만 답하는 상수 모델보다 못하다는 뜻입니다.
이 화면의 축척과 기준
  • 요청 12,000건 × 자리 5개 = 노출 60,000건이 기본값입니다. 기저 CTR 은 2.5%로, 글 3절이 쓰는 자리당 CTR 과 같은 값입니다.
  • 모델은 요청 수준 차이를 그대로 봅니다. 지면·시간대 같은 요청 단위 신호는 맞힌다고 두고, 요청 안에서 광고를 가르는 능력만 분별력 슬라이더가 정합니다. 그래서 요청 간 편차를 키우면 전체 AUC 만 오릅니다.
  • 보정 배수 1.00 이면 예측 총합이 실제 클릭 수와 정확히 맞습니다. 평균은 맞게 학습됐다고 두고, 슬라이더가 거기서 얼마나 밀어내는지를 봅니다.
  • 예측은 0.99 에서 자릅니다. 배수를 3까지 올리면 잘린 예측이 동점을 만들어 AUC·GAUC 의 넷째 자리가 조금 움직입니다. 순위가 바뀐 것이 아니라 동점이 생긴 것입니다.
  • 아래 두 슬라이더는 성격이 다릅니다. 분별력·보정 배수는 모델을 바꾸고, 요청 간 편차·요청당 광고 수는 평가 표본을 바꿉니다. 표본이 바뀌면 "기존 모델 대비" 문턱은 견줄 자리가 없어져 배지가 표본이 다름으로 바뀝니다. NE 절댓값과 COPC 범위는 표본이 달라도 그대로 유효합니다 — 그러라고 있는 지표입니다.
  • 이 화면의 숫자는 이 표본이 낸 값입니다. 글 1절 배포 표의 AUC 0.7412 · GAUC 0.6180 · NE 0.9031 · COPC 1.012 와는 다른 표본입니다. 기본값을 그 근처에 놓아 뒀을 뿐입니다.

ROC 곡선 두 개

위 곡선은 노출 전체를 한 통에 부어 그린 것이고, 아래 점선은 요청마다 따로 그린 곡선을 짝 수로 가중해 평균한 것입니다. 두 곡선 사이 면적이 요청을 가로지른 짝이 만든 몫입니다.

      이 데모에서 알게 된 3가지

      1. 전체 AUC 는 요청을 가로지른 짝까지 점수로 쳐 준다 — 요청 간 편차만 0에서 1.40 으로 올리면 AUC 는 0.6115 에서 0.8311 로 0.22 오르는데, 모델의 요청 안 능력은 한 줄도 안 바뀌었다. GAUC 는 0.6133 에서 0.6287 로 0.015 움직이고 만다.
      2. 보정 배수는 순위 지표에 안 보인다 — 예측에 3을 곱해도 AUC 와 GAUC 는 넷째 자리만 흔들린다. 그 사이 NE 는 0.9303 에서 1.2535 로, COPC 는 1.002 에서 0.342 로 간다. 크기를 재는 지표가 따로 있어야 하는 이유다.
      3. GAUC 는 요청 대부분을 버린다 — 자리 5개에 자리당 CTR 2.5% 면 요청의 88.1% 가 클릭 0건이라 짝을 못 만든다. 오른쪽 카드에서 r-8a90 이나 r-7c08 을 보면 그 요청이 어떻게 생겼는지 나온다.

      현업에서는 이렇게 씁니다

      배포 게이트는 지표 목록이 아니라 문턱과 행동의 짝입니다. 넘으면 무엇을 할지 미리 안 정해 두면 게이트가 아닙니다. 위 지표 칸의 배지가 글 8절 게이트를 그대로 옮긴 것입니다.

      • GAUC 로 순위를 봅니다: 기존 대비 -0.001 아래로 떨어지면 배포를 멈춥니다. 문턱 값 자체는 근거가 없습니다. 같은 모델을 시드만 바꿔 다섯 번 학습해 GAUC 가 얼마나 흔들리는지 먼저 재고, 그 흔들림보다 큰 값을 문턱으로 잡습니다.
      • NE 로 크기를 봅니다: 기존 대비 +0.5% 이상이면 중단이고, 절댓값이 1.0 을 넘으면 즉시 중단입니다. NE 1.0 은 "보통"이 아니라 기저 CTR 만 답하는 상수 모델과 같다는 뜻입니다.
      • COPC 로 총합을 봅니다: 전체가 0.97~1.03 밖이면 중단, 지면별 최악이 0.90~1.10 밖이면 경고 후 검토입니다. 예측 평균이 학습 기간 실제 CTR 대비 ±3% 를 벗어나면 다운샘플링 보정을 빠뜨린 것이라 즉시 중단합니다.
      • 전체 AUC 는 기록만 합니다: 문턱을 안 겁니다. 다만 0.74 에서 0.62 로 뚝 떨어지면 피처 파이프라인이 깨진 신호라 계속 찍어 둡니다. 작은 개선을 판정하는 자리에는 못 씁니다.
      • 서빙 p99 는 12ms 예산입니다: 초과하면 배포 중단입니다. 늦은 응답은 없던 응답이라 지표가 아무리 좋아도 소용이 없습니다.
