지훈 씨는 DCN-V2 로 pCTR 모델을 학습해 본 적이 있습니다. 성별, 나이대, 시간대, 지면, 광고 번호를 넣고, 행동 정보는 「최근 클릭 수」 같은 숫자로 미리 세어 넣었습니다. 그런데 [DIN 모델 구조](post.html?id=din-architecture) 글을 읽고 나니 헷갈리기 시작했습니다.

다른 사람이 정리해 준 모델 계보에는 「Wide & Deep → DeepFM → DCN」, 「DIN → DIEN → BST」, 「ESMM → MMoE → PLE」 세 줄이 있었습니다. 세 줄이 서로 대신하는 모델인지, 같이 쓰는 모델인지 알 수 없었습니다. DCN 만 써 온 자기 모델에 DIN 을 쓰려면 무엇을 바꿔야 하는지도 몰랐습니다.

**DCN 만 쓰던 pCTR 모델과, 앞에 DIN 모듈을 더한 모델은 정확히 어디가 다르고, 학습과 서빙에서 무엇이 달라질까요?**

답은 pCTR 모델 한 개 안에 자리가 셋 있다는 데서 시작합니다. ① 행동 기록을 벡터 하나로 줄이는 자리, ② 피처를 섞는 자리, ③ 확률을 내는 자리입니다. 세 줄의 계보는 이 세 자리에 하나씩 대응합니다. DCN 은 ②에, DIN 은 ①에 들어가므로, DIN 모듈을 더하는 일은 DCN 앞에 모듈 하나를 끼우는 일입니다.

> **한 줄 요약:** pCTR 모델은 ① 행동 기록 정리, ② 피처 섞기, ③ 답 내기의 세 자리로 이루어지고 세 자리는 한 신경망의 층이라 맨 끝의 정답으로 함께 학습됩니다. 정답은 출력이 하나면 클릭, 멀티태스크면 클릭과 전환입니다. DIN, DCN, MMoE 는 서로 겨루지 않고 각자 다른 자리에 들어갑니다. DCN 만 쓰던 모델에 DIN 모듈을 더하면 DCN 과 출력, 손실은 그대로이고, 행동 원본 목록이 더 들어가 광고마다 다른 관심 벡터가 됩니다. 미리 센 숫자는 빼지 않고 함께 둘 수 있습니다. 대가는 데이터 준비와 서빙 계산이고, 후보 800개에 행동 50개면 요청 한 건에 가중치 계산이 40,000번입니다.

> **골라 읽는 법** — 절이 7개인 글입니다. 1절 앞에 이 글의 예시를 푼 표가 먼저 있습니다.
>
> - 세 자리와 모델 계보가 어떻게 맞물리나 → 1절
> - DCN 만 쓸 때와 DIN 모듈을 더할 때의 구조 → 2절
> - 행동 정보, 학습, 서빙에서 달라지는 것 → 3~5절
> - ①을 붙이는 두 방법과 언제 더하나 → 6~7절

이 글의 행동과 광고, 숫자는 전부 설명을 위한 가상 값이고 DIN 모델 구조 글과 같습니다. 그림 속 색은 넷입니다. 파랑은 ① 행동 기록 정리, 회색은 ② 피처 섞기, 벽돌색은 ③ 답 내기, 먹색은 관심 벡터와 pCTR 입니다. 구조와 학습 방식은 두 무대가 같아서 글 전체를 공통으로 읽으면 됩니다.

행동 넷과 광고 둘은 DIN 모델 구조 글의 예시 표와 같은 값입니다. 행동 벡터와 광고 벡터는 4차원이고, 네 값은 [러닝 쪽, 커피 쪽, 카테고리, 얼마나 최근인가] 로 읽으면 됩니다. 800 과 50 은 계산의 크기를 보이려고 정한 설명용 값이고, 실제 서비스의 값이 아닙니다.

| 무엇 | 예시 |
|---|---|
| 행동 기록 | 오늘 행동 넷: 러닝화 A 클릭, 러닝화 B 클릭, 커피 원두 구매, 러닝 양말 클릭 |
| 그 밖의 피처 | 30대, 아이폰, 주말 저녁 |
| 후보 광고 | 러닝화 광고, 커피머신 광고 |
| 800 | 요청 한 건에 점수를 매기는 후보 광고 수 (설명용) |
| 50 | DIN 모듈에 넣으려고 잘라 쓰는 최근 행동 수 (설명용) |

민지 씨의 행동 넷 가운데 셋은 러닝이고 하나는 커피입니다. 이 비율이 DCN 만 쓰는 모델에서는 「러닝 3회, 커피 1회」라는 숫자가 되고, DIN 모듈에서는 광고마다 다른 가중치가 됩니다.

①번 자리는 사람마다 길이가 다른 행동 기록을 고정 길이 벡터 하나로 줄입니다. 평균, DIN, DIEN, BST 가 이 자리에서 겨룹니다. ②번 자리는 그 벡터와 성별, 시간대, 기기, 광고 같은 피처를 이어 붙여 섞습니다. MLP, DeepFM, DCN 이 이 자리의 모델입니다. ③번 자리는 섞인 벡터로 확률을 냅니다. 출력 하나, ESMM, MMoE, PLE 가 이 자리의 선택지입니다.

그림 위 버튼으로 ①을 평균과 DIN 사이에서, ③을 출력 하나와 멀티태스크 사이에서 바꿔 볼 수 있습니다. 어느 쪽을 바꿔도 ②는 그대로입니다. 그래서 「DIN 이 좋은가 DCN 이 좋은가」는 맞지 않는 물음입니다. 같은 자리에 들어가는 모델끼리만 비교합니다.

세 자리는 따로 학습하는 부품이 아니라 신경망 하나의 층입니다. 정답이 직접 닿는 곳은 맨 끝 ③뿐이고, 거기서 생긴 오차가 ② → ① → 임베딩 순서로 거꾸로 전해집니다. 그 길에 있는 층이 모두 같은 정답으로 함께 고쳐집니다. 출력 헤드가 하나면 정답은 클릭이고, 멀티태스크면 클릭과 전환입니다. 이것을 end-to-end 학습이라고 부릅니다. ①을 모델 밖의 다른 모델로 미리 계산해 넣는 방법도 있는데, 그때 ①은 따로 학습됩니다(6절).

## 2. DCN 만 쓸 때와 DIN 모듈을 더할 때: 다른 모듈은 하나

**DCN 만 쓰는 모델에는 ①번 자리를 맡는 층이 모델 안에 없습니다. 행동 기록은 모델 밖에서 미리 센 숫자로 줄여 넣습니다. DIN 모듈을 더하면 그 일을 모델 안의 층이 하고, DCN 과 출력 헤드는 그대로입니다.**

왼쪽 모델은 입력을 임베딩으로 바꾼 뒤 곧바로 DCN-V2 에 넣습니다. 행동 정보가 없는 것은 아닙니다. 「최근 행동 4회, 러닝 3회, 커피 1회」처럼 사람이 미리 센 숫자가 피처 하나씩으로 들어갑니다. 숫자 피처는 다른 피처와 똑같이 DCN 에서 섞입니다.

오른쪽 모델은 행동을 원본 목록으로 받습니다. 행동 하나하나가 임베딩에서 벡터가 되고, 더한 모듈이 후보 광고를 보고 행동마다 가중치를 매겨 관심 벡터 하나로 줄입니다. 그 관심 벡터가 다른 피처와 이어 붙어 DCN-V2 로 들어갑니다. DCN-V2 의 구조와 출력 헤드, 손실 함수는 왼쪽과 똑같습니다.

## 3. 행동 정보가 들어가는 모양: 미리 센 숫자와 광고마다 다른 벡터

**사용자 한 사람 단위로 미리 센 숫자는 어느 광고 앞에서나 같습니다. DIN 모듈의 관심 벡터는 광고가 바뀌면 값이 바뀝니다.**

| 무엇 | DCN 만 | DIN 모듈 + DCN |
|---|---|---|
| 넣는 값 | 미리 센 숫자: 행동 4회, 러닝 3회, 커피 1회 | 행동 넷을 하나씩, 행동마다 벡터 |
| 광고를 보나 | 안 봅니다. 사용자 단위로 센 숫자는 어느 광고 앞에서나 같습니다 | 봅니다. 러닝화 광고 앞에서는 커피 원두의 가중치가 0 |
| 누가 정하나 | 사람이 집계 규칙을 정합니다 (기간, 카테고리) | 가중치를 모델이 클릭을 보고 배웁니다 |
| 잃는 것 | 어떤 행동이 이 광고와 맞는지 | 계산량. 후보마다 가중치를 다시 계산합니다 |

미리 센 숫자로도 「러닝 관심이 크다」는 것은 모델에 전해집니다. DCN 은 그 숫자를 광고 카테고리와 곱해 「러닝 3회 × 러닝화 광고」 같은 조합도 만들 수 있습니다. 다만 그 조합은 사람이 정해 둔 카테고리 안에서만 생깁니다. 「러닝 3회」에는 무엇을 언제 눌렀는지가 남지 않습니다. 2시간 전의 러닝 양말 클릭과 12시간 전의 러닝화 클릭이 똑같이 1회로 세어집니다.

DIN 모듈은 행동 벡터와 광고 벡터를 직접 비교해 가중치를 냅니다. 러닝화 광고 앞에서는 러닝 행동 셋이 1.95, 1.845, 2.4 를 받고 커피 원두는 0 을 받습니다. 커피머신 광고 앞에서는 커피 원두가 2.062, 러닝 양말이 0.413 을 받습니다. 아래 코드가 두 모델에 들어가는 행동 정보를 나란히 계산합니다.

```python
# DCN 만 쓰는 모델과 DIN 모듈을 더한 모델에 들어가는 행동 정보를 나란히 만든다.
# 숫자는 DIN 모델 구조 글과 같은 가상 값이다. 표준 라이브러리만 쓴다.
BEHAVIORS = [  # (이름, 종류, 카테고리, 4차원 벡터)
    ("러닝화 A", "클릭", "러닝", [0.9, 0.1, 0.8, 0.2]),
    ("러닝화 B", "클릭", "러닝", [0.8, 0.2, 0.8, 0.2]),
    ("커피 원두", "구매", "커피", [0.1, 0.9, -0.7, 0.5]),
    ("러닝 양말", "클릭", "러닝", [0.7, 0.1, 0.6, 0.9]),
]
ADS = {"러닝화 광고": [0.85, 0.15, 0.8, 0.9], "커피머신 광고": [0.15, 0.8, -0.7, 0.9]}


def counted_features(behaviors):
    """DCN 만 쓰는 모델: 사람이 정한 규칙으로 미리 센 숫자. 광고를 보지 않는다."""
    return {"행동 수": len(behaviors),
            "러닝 수": sum(b[2] == "러닝" for b in behaviors),
            "커피 수": sum(b[2] == "커피" for b in behaviors)}


def din_slot(behaviors, ad):
    """DIN 모듈: 행동마다 광고와 비교해 가중치를 내고 곱해 더한다. 가중치를 내는 신경망은 학습이 끝났다고 놓는다."""
    w = [1.5 * max(0.0, sum(a * b for a, b in zip(e, ad)) - 0.3) for *_, e in behaviors]
    user = [round(sum(wi * b[3][k] for wi, b in zip(w, behaviors)), 3) for k in range(4)]
    return [round(x, 3) for x in w], user


for ad, v in ADS.items():
    print(f"[{ad}]")
    print("  DCN 만 :", counted_features(BEHAVIORS))
    w, user = din_slot(BEHAVIORS, v)
    print("  DIN 모듈 : 가중치", w, "관심 벡터", user)

CANDIDATES, KEEP = 800, 50          # 설명용 값
print(f"요청 한 건의 가중치 계산: {CANDIDATES} × {KEEP} = {CANDIDATES * KEEP:,}번")

# 출력:
# [러닝화 광고]
#   DCN 만 : {'행동 수': 4, '러닝 수': 3, '커피 수': 1}
#   DIN 모듈 : 가중치 [1.95, 1.845, 0.0, 2.4] 관심 벡터 [4.911, 0.804, 4.476, 2.919]
# [커피머신 광고]
#   DCN 만 : {'행동 수': 4, '러닝 수': 3, '커피 수': 1}
#   DIN 모듈 : 가중치 [0.0, 0.0, 2.062, 0.413] 관심 벡터 [0.495, 1.897, -1.196, 1.403]
# 요청 한 건의 가중치 계산: 800 × 50 = 40,000번
```

DCN 만 쓰는 쪽의 숫자는 두 광고 앞에서 {행동 4, 러닝 3, 커피 1} 로 똑같습니다. DIN 모듈의 관심 벡터는 러닝화 광고 앞에서 첫 번째 값이 4.911, 커피머신 광고 앞에서 둘째 값이 1.897 로 서로 다릅니다. 같은 기록이 광고마다 다른 입력이 되어 DCN-V2 로 들어갑니다.

### 행동 정보를 넣는 세 가지 방법

**실무에서는 행동 정보를 통계 숫자로 넣는 방법, 행동 목록을 임베딩으로 넣는 방법, 둘을 같이 넣는 방법이 다 쓰입니다. 셋 다 ① 자리를 채우는 방법이고, 그 뒤의 DCN 과 출력 헤드는 같습니다.**

위의 「DCN 만」 열은 사용자 한 사람 단위로 센 숫자라 어느 광고 앞에서나 같았습니다. 그런데 통계 숫자도 세는 단위를 「사용자 × 광고주」처럼 광고 쪽과 짝지으면 광고마다 다른 값이 됩니다. 실무의 통계 피처는 이렇게 단위를 여러 개 두는 경우가 많습니다.

| 방법 | ① 자리에 넣는 것 | 광고마다 바뀌나 | 미리 계산 |
|---|---|---|---|
| 통계 숫자 | 정해 둔 기간의 노출 수, 클릭 수, 전환 수. 세는 단위는 사용자, 사용자 × 광고주, 사용자 × 카테고리 등 | 단위에 광고 쪽이 들어 있으면 바뀝니다 | 됩니다. 주기적으로 세어 키-값 저장소에 두고 요청 때 읽습니다 |
| 행동 목록 + attention | 최근 행동 N개의 상품, 카테고리, 시간 간격을 하나씩 임베딩으로 찾은 목록. 광고를 보고 가중치를 매겨 더합니다 | 바뀝니다 | 안 됩니다. 후보마다 다시 계산합니다 |
| 둘 다 | 통계 피처는 그대로 두고 행동 목록과 attention 모듈을 더합니다 | 바뀝니다 | 통계 숫자만 미리 둡니다 |

통계 숫자와 행동 목록은 행동에서 무엇을 남기느냐가 다릅니다. 통계 숫자는 「몇 번」을 남기고, 행동 목록은 「무엇을 언제」를 남깁니다. 어느 쪽이든 나이대, 지면, 광고주 번호 같은 범주 값은 똑같이 임베딩으로 들어갑니다.

통계 숫자는 사람이 정한 단위 안의 관계만 압니다. 민지 씨가 다른 광고주의 러닝 양말을 누른 일은 「사용자 × 이 러닝화 광고주」 숫자에 잡히지 않습니다. 「사용자 × 카테고리」 단위를 따로 세면 잡히지만, 그런 단위는 사람이 미리 정해야 합니다. 행동 목록은 누른 상품 자체를 들고 가므로, 광고주가 달라도 비슷한 상품이면 그 관련을 모델이 배웁니다. 대신 서빙 계산이 행동 수만큼 늘어납니다.

통계 숫자로 시작한 모델이라면 통계 피처는 그대로 두고 행동 목록을 더해 볼 수 있습니다. 통계 피처를 빼지 않고 더하면, 비교 실험에서 차이가 새로 더한 모듈에서 왔다고 말할 수 있습니다.

## 4. 학습: 방식은 같고 데이터 준비가 늘어납니다

**손실, 옵티마이저, 보정은 그대로 둘 수 있습니다. 바뀌는 곳은 데이터를 만드는 단계와 모델 앞부분입니다.**

| 무엇 | DCN 만 | DIN 모듈 + DCN |
|---|---|---|
| 정답과 손실 | 클릭 1 또는 0, BCE (LogLoss) | 같습니다 |
| 학습 방식 | 한 모델 전체를 한 번에 | 같습니다. 더한 모듈도 같은 클릭 신호로 함께 배웁니다 |
| 데이터 한 줄 | 노출 한 건 + 미리 센 숫자 피처 | 노출 한 건 + 그 시각까지의 최근 행동 목록 |
| 길이 맞추기 | 필요 없습니다 | 목록 길이가 사람마다 달라 빈칸 채우기(padding)와 mask 가 필요합니다 |
| 조심할 것 | 숫자에 노출 시각 뒤의 행동이 섞이지 않게 | 목록에 노출 시각 뒤의 행동이 섞이지 않게. 같은 주의가 행동 하나하나로 늘어납니다 |

학습 데이터 한 줄의 모양이 가장 크게 바뀝니다. DCN 만 쓰는 모델은 집계 테이블을 노출 로그에 붙이면 끝납니다. DIN 모듈을 더하면 노출 한 건마다 「그 노출 직전까지의 최근 행동 50개」 목록을 만들어 붙여야 합니다. 노출 시각 뒤의 행동이 목록에 들어가면 모델이 정답을 미리 보고 배우게 되므로, 시각을 행동 하나하나에서 확인합니다.

목록 길이는 사람마다 다릅니다. 행동이 셋뿐인 사람도 있고 50개를 넘는 사람도 있습니다. 배치 안에서는 가장 긴 길이에 맞춰 빈칸을 채우고, 빈칸의 가중치를 0 으로 만드는 mask 를 같이 넘깁니다. 이 과정은 [DIN 모델 구조](post.html?id=din-architecture) 글의 코드 마지막 부분에서 손으로 볼 수 있습니다.

## 5. 서빙: 요청 한 건의 계산이 늘어납니다

**DIN 모듈의 관심 벡터는 광고마다 달라 미리 만들어 둘 수 없습니다. 후보 수만큼, 행동 수만큼 가중치 계산이 늘어납니다.**

| 무엇 | DCN 만 | DIN 모듈 + DCN |
|---|---|---|
| 요청 때 읽는 것 | 미리 센 숫자 피처 몇 개 | 최근 행동 목록 |
| 후보 800개일 때 | DCN 을 800번 | 가중치 계산 800 × 50 = 40,000번과 DCN 800번 |
| 행동 수를 정하는 것 | 해당 없음 | 목록을 잘라 응답 시간 안에 맞춥니다 |
| 미리 계산 | 숫자는 미리 세어 두면 됩니다 | 관심 벡터는 광고마다 달라 미리 못 둡니다 |

가중치를 내는 신경망은 작아서 한 번의 계산은 가볍습니다. 그래도 후보와 행동의 곱만큼 돌기 때문에 요청 한 건에 수만 번이 됩니다. 그래서 몇 개의 행동까지 넣을지가 서빙에서 가장 먼저 정하는 값이 됩니다. 행동이 수만 개로 길면 관련 있는 행동을 먼저 고른 뒤 같은 계산을 하고, 그 방법은 [행동 시퀀스 Attention](post.html?id=behavior-sequence-attention) 글의 뒷부분에 있습니다.

## 6. ①을 붙이는 두 방법: 모델 안의 층, 미리 뽑은 피처

**①번 자리는 모델 안의 층으로 둘 수도 있고, 따로 미리 계산해 피처로 넣을 수도 있습니다. 벡터가 광고에 따라 바뀌느냐가 고르는 기준입니다.**

DIN 모듈은 왼쪽 방법만 됩니다. 관심 벡터가 광고마다 달라서, 요청 때 광고 하나마다 ①부터 다시 계산합니다. 학습도 한 모델 안에서 함께 합니다.

오른쪽 방법은 광고와 상관없는 사용자 벡터를 쓸 때입니다. 사용자 임베딩 모델을 정해 둔 주기로 따로 돌려 사용자마다 벡터 하나를 저장소에 둡니다. 랭킹 모델은 요청 때 그 벡터를 피처 하나로 읽기만 합니다. 빠르지만 광고에 맞춰 바뀌지 않으므로, 2절 왼쪽의 미리 센 숫자와 성격이 같습니다.

③번 자리에도 고르는 법이 셋 있습니다. 클릭만 맞히면 출력 헤드 하나로 충분합니다. 전환도 맞혀야 하면 pCTR 모델과 pCVR 모델을 따로 두거나, ②까지를 함께 쓰고 ③에서 클릭 헤드와 전환 헤드로 나눕니다. 뒤쪽이 멀티태스크이고, ESMM 은 클릭한 노출로만 전환을 배우는 편향을, MMoE 와 PLE 는 두 과제가 서로의 학습을 방해하는 문제를 다룹니다. 자세한 것은 [Multi-Task Learning](post.html?id=multi-task-learning) 글에 있습니다.

## 7. 언제 더하나: DCN 은 두고 앞 모듈만 바꿔 봅니다

**DIN 은 DCN 을 대신하지 않습니다. DCN 앞에 모듈 하나를 더하는 것이고, 실험도 그 모듈만 바꿔서 합니다.**

| 이럴 때 | 판단 |
|---|---|
| 관심이 여러 개이고 카테고리 규칙으로 잘 안 나뉜다 | 더할 만합니다. 미리 센 숫자는 사람이 정한 카테고리만큼만 관심을 나눕니다 |
| 행동 로그가 행동 하나 단위로 남아 있다 | 더할 수 있습니다. 목록을 만들 재료가 있습니다 |
| 집계 숫자로 「이 광고와 맞는 행동」이 안 잡힌다 | 더할 만합니다. 그 일을 DIN 모듈이 합니다 |
| 응답 시간 여유가 없다 | 미룹니다. 행동 수를 줄이거나 먼저 고르는 단계를 둡니다 |
| 행동 로그가 집계로만 남는다 | 미룹니다. 목록을 만들 재료가 없습니다 |

비교 실험은 DCN-V2 와 출력 헤드, 손실을 그대로 두고 ①번 자리만 바꿉니다. 미리 센 숫자만 쓰는 모델과, 같은 숫자에 DIN 모듈을 더한 모델을 같은 기간의 데이터로 학습합니다. 그래야 성능 차이가 그 모듈에서 왔다고 말할 수 있습니다. 미리 센 숫자를 함께 넣어 두면, DIN 모듈이 집계로 이미 잡히던 것 위에 무엇을 더하는지도 볼 수 있습니다.

## 한눈 정리

| 질문 | 답 |
|---|---|
| 계보 세 줄은 대신 쓰는 관계인가 | 아닙니다. 모델 한 개 안의 세 자리에 하나씩 들어갑니다 |
| DIN 은 어느 자리인가 | ① 행동 기록 정리. DCN 은 ② 피처 섞기 |
| DCN 만 쓰던 모델에 더하면 바뀌는 곳 | ①번 자리 하나. DCN, 출력, 손실은 그대로 |
| 따로 학습하나 | 아닙니다. 같은 정답으로 세 자리를 함께. ①을 미리 뽑아 넣을 때만 따로 |
| 행동 정보의 모양 | DCN 만은 미리 센 숫자 {4, 3, 1}. DIN 모듈은 광고마다 다른 관심 벡터 |
| 대가 | 행동 목록 데이터 준비, 요청 한 건에 가중치 계산 800 × 50 = 40,000번 |

## 헷갈리기 쉬운 점

- **DIN 과 DCN 은 비교할 대상이 아닙니다.** 다른 자리에 들어가므로 한 모델에 둘 다 넣습니다.
- **DCN 만 쓰는 모델에도 행동 정보는 들어갑니다.** 사람이 정한 단위로 미리 센 숫자가 들어갑니다. 광고 쪽과 짝지어 세지 않은 숫자는 광고에 따라 바뀌지 않습니다.
- **DIN 모듈은 따로 학습해 넣는 부품이 아닙니다.** 같은 모델 안의 층이라 DCN 과 같은 정답으로 함께 배웁니다.
- **관심 벡터는 미리 뽑아 둘 수 없습니다.** 광고마다 값이 다르기 때문입니다. 미리 뽑아 넣는 것은 광고와 상관없는 사용자 임베딩입니다.
- **계보의 화살표는 같은 자리 안에서만 이어집니다.** DeepFM 다음이 DCN 인 것도, ESMM 다음이 MMoE 인 것도 아닙니다.
