새벽 3시, 서버가 죽었다는 알람이 울립니다. 당직자(그 시간에 장애 대응을 맡은 사람)가 서버를 재시작하자 5분 뒤 서비스가 정상으로 돌아옵니다.

같은 새벽에 난 사고가 하나 더 있습니다. 랭킹 모델(광고 후보마다 점수를 매겨 순서를 정하는 모델)이 입력으로 받는 피처(모델에 넣는 값) 하나가 어제부터 빈 값으로 들어오는데도 모델은 오류를 내지 않습니다. 요청마다 200 OK(요청을 정상으로 처리했다는 HTTP 응답)로 답하면서 그럴듯한 숫자를 내놓지만 그 숫자가 틀렸습니다. 알람은 한 번도 울리지 않고 대시보드도 정상을 뜻하는 초록색이라 3주가 지나서야 리포트에서 매출이 8% 빠진 것을 발견합니다.

> 한 줄 요약: 모델 장애는 오류를 내지 않습니다. 그래서 **입력, 예측, 라벨(광고를 본 뒤 실제로 일어난 결과를 적은 기록), 비즈니스 지표를 층으로 나눠 측정하고 광고 자리(지면)나 기기로 트래픽을 나눈 세그먼트별로 쪼개 보며 알람은 「몇 번 연달아 기준을 벗어났나」로 걸어야 합니다.** 이 글의 시뮬레이션에서 예측값의 평균은 결과가 다 들어오기를 기다린 라벨보다 7일 먼저 사고를 잡았습니다. 가상 데이터에서 실제 클릭을 예측 클릭으로 나눈 값은 전체로 1.000 이었지만 지면별로는 0.42~1.50 으로 흩어져 있었습니다.

드리프트(입력 데이터나 세상이 학습 때와 달라지는 현상)의 종류와 재학습 전략은 [Online Learning과 지연 피드백](post.html?id=online-learning-delayed-feedback) 편에서 다뤘습니다. 이 글은 그보다 한 단계 앞에서 **재학습 버튼을 누를 때가 됐다는 것을 어떻게 아는지**만 봅니다.

## 1. 오류를 내는 서버 장애와 조용히 나빠지는 모델

**서버 장애는 요청 실패로 바로 보이지만 모델 장애는 모든 요청이 성공한 것처럼 보입니다. 이 차이 때문에 모델 감시는 서버 감시와 설계부터 달라집니다.**

도입의 서버 사고는 알람이 울려 5분 만에 끝났지만 피처 사고는 3주 동안 아무도 몰랐습니다.

서버가 죽으면 500 응답(서버 안에서 오류가 났다는 HTTP 응답)이 한꺼번에 많이 나오고 처리하지 못한 요청이 큐(처리를 기다리는 요청을 담아 두는 대기열)에 쌓입니다. 감시 도구는 원래 이렇게 시스템이 「동작하지 않는」 상태를 잡도록 만들어져 있습니다. 모델이 나빠질 때는 반대로 실패하는 것이 하나도 없습니다. 요청은 모두 성공하고 응답 지연(요청 하나에 답하는 데 걸리는 시간)도 평소와 같으며 예측값도 형식만 보면 멀쩡해서 「동작하지 않음」을 찾는 감시 도구에는 아무것도 걸리지 않습니다. 그사이 예측 숫자만 조용히 현실과 달라집니다.

그래서 모델 사고는 감시 도구보다 **돈에서 먼저 보입니다.** pCTR(predicted Click-Through Rate)은 모델이 예측한 클릭률(CTR, 광고가 노출된 횟수 가운데 클릭된 비율)입니다. 광고 자리를 사려고 부르는 금액인 입찰가는 이 pCTR 을 바탕으로 계산합니다. pCTR 이 실제 클릭률보다 낮게 나오면 입찰가도 따라 낮아져 경매에서 이기는 낙찰이 줄고 낙찰이 준 만큼 광고가 유저 화면에 보이는 노출도 줄어 쓰지 못한 예산이 남습니다. 반대로 pCTR 이 높게 나오면 노출을 비싸게 사지만 그 값에 맞는 성과가 나오지 않습니다. 어느 쪽이든 며칠 뒤 정산 리포트(광고비와 성과를 집계한 보고서)에서야 발견하는데, 그때는 이미 손실이 확정된 뒤입니다.

게다가 모델은 **부분적으로만 나빠집니다.** 전체 평균은 끝까지 멀쩡해 보이는데, 왜 그런지는 5절에서 숫자로 따라갑니다. 그래서 모델 감시는 **「모델이 어제와 같은 세상에서 어제와 같은 판단을 하고 있나」**를 묻습니다.

## 3. 입력이 얼마나 달라졌는지 숫자 하나로 나타내는 PSI

**PSI(Population Stability Index)는 「학습 때 보던 입력이 오늘도 같은 모양으로 들어오는가」를 숫자 하나로 요약하는 지수이고 라벨이 필요 없어서 가장 빠른 신호입니다.**

2절 표의 1층 입력을 지켜보려면 학습 때 들어오던 값과 오늘 들어오는 값이 얼마나 다른지를 숫자로 나타내야 합니다. PSI 는 이 차이를 세 단계로 계산합니다. 먼저 피처 값의 범위를 구간(bin)으로 나누고 학습 데이터와 오늘 데이터가 구간마다 몇 % 씩 들어 있는지 비율을 셉니다. 다음으로 구간마다 두 비율의 차이에 로그비(한 비율을 다른 비율로 나눈 값의 자연로그)를 곱한 뒤 마지막으로 그 값을 모든 구간에 걸쳐 더합니다.

$$\mathrm{PSI} = \sum_{i=1}^{k} (a_i - b_i)\,\ln\frac{a_i}{b_i}$$

$b_i$ 는 학습 때 $i$ 번 구간에 든 비율이고 $a_i$ 는 오늘 같은 구간에 든 비율이며 $k$ 는 구간 수입니다. 오늘 비율이 학습 때보다 크면 $a_i - b_i$ 와 $\ln(a_i/b_i)$ 가 둘 다 양수이고 작으면 둘 다 음수라서 구간마다 곱한 값은 늘 0 이상이므로, 모든 구간의 비율이 학습 때와 같으면 PSI 는 0 이고 비율이 달라질수록 PSI 가 커집니다.

아래 표는 요청이 어느 지면(광고가 걸리는 자리)에서 왔는지를 나타내는 피처를 뉴스 피드부터 기타까지 5구간으로 나눠 계산한 **가상 데이터**입니다.

| 지면 유형 | 학습 때 $b_i$ | 오늘 $a_i$ | $a_i - b_i$ | $\ln(a_i/b_i)$ | 항의 값 |
|---|---|---|---|---|---|
| 뉴스 피드 | 40% | 28% | -0.12 | -0.357 | 0.0428 |
| 검색 상단 | 25% | 22% | -0.03 | -0.128 | 0.0038 |
| 앱 배너 | 20% | 33% | +0.13 | +0.501 | 0.0651 |
| 동영상 | 10% | 12% | +0.02 | +0.182 | 0.0036 |
| 기타 | 5% | 5% | 0.00 | 0.000 | 0.0000 |
| **합** | 100% | 100% | | | **0.115** |

표의 PSI 는 0.115 입니다. 앱 배너 줄을 따라가면 학습 때 20% 이던 비율이 오늘 33% 로 늘어 차이 $a_i - b_i$ 가 +0.13 이고 로그비가 +0.501 이므로 두 값을 곱한 항의 값은 0.0651 입니다. 뉴스 피드는 40% 에서 28% 로 줄어 차이(-0.12)와 로그비(-0.357)가 둘 다 음수라서 곱한 항의 값이 양수 0.0428 이 됩니다. 다섯 줄의 항을 모두 더한 0.115 가운데 앱 배너 한 줄의 0.0651 이 절반을 넘습니다. 이렇게 **어느 구간이 원인인지까지 알려 준다는 점**이 PSI 의 장점입니다.

아래 코드는 두 가지를 보려고 돌립니다. 첫째는 입력의 평균이 조금씩 밀릴 때 PSI 가 얼마가 되고 그때 구간별 비율이 실제로 몇 %p(퍼센트포인트, 두 비율의 차이를 % 단위로 적은 값) 달라지는지입니다. 둘째는 사고가 없어도 표본이 작으면 PSI 가 얼마나 올라가는지입니다.

피처는 평균 0, 표준편차(값이 평균에서 흩어진 정도) 1 인 「유저의 최근 7일 광고 반응 점수」 하나라고 둡니다. 구간은 학습 표본을 같은 개수씩 담는 십분위(10개 구간)로 나눕니다. 오늘 데이터를 오늘 데이터의 십분위로 다시 자르면 오늘 비율도 구간마다 10% 가 되어 학습 때의 10% 와 늘 같으므로 PSI 가 늘 0 이 됩니다. 그래서 구간 경계는 학습 때 한 번만 정해 모델과 함께 저장합니다.

```python
# 하는 일: 학습 때 본 피처 하나의 십분위 경계로 PSI(Population Stability Index)를 재, 평균이 밀린 정도와 표본 크기에 따라 값이 어떻게 달라지는지 본다.
import random
import math

random.seed(42)  # 돌릴 때마다 같은 결과가 나오게 고정

# 1단계: 경계와 비율, PSI 를 구하는 함수를 만든다
# PSI 는 학습 때 본 입력과 오늘 입력이 얼마나 다른지를 한 숫자로 나타낸다. 경계는 학습 표본의 십분위로 한 번만 정한다.
def make_edges(sample, n_bins=10):
    """학습 표본을 같은 개수씩 담는 십분위로 자르고 그 경계만 돌려준다."""
    s = sorted(sample)
    # 경계는 학습 때 한 번만 정하고 모델과 함께 저장한다. 매일 다시 자르면 PSI가 늘 0이 된다.
    return [s[len(s) * i // n_bins] for i in range(1, n_bins)]

def to_shares(sample, edges):
    """표본을 구간별 '비율'로 바꾼다. PSI는 개수가 아니라 비율로 측정한다."""
    counts = [0] * (len(edges) + 1)
    for x in sample:
        k = 0
        while k < len(edges) and x >= edges[k]:
            k += 1                       # x가 몇 번째 구간인지 찾는다
        counts[k] += 1
    return [c / len(sample) for c in counts]

def psi(base, now, floor=1e-4):
    """구간마다 (오늘비율 - 학습비율) x ln(오늘비율/학습비율) 을 더한다."""
    total = 0.0
    for b, a in zip(base, now):
        b, a = max(b, floor), max(a, floor)   # 비율 0이면 로그가 발산하므로 바닥을 깐다
        total += (a - b) * math.log(a / b)
    return total

# 2단계: 학습 때 본 피처의 경계와 비율을 정한다
# 학습 때 본 피처 하나를 '유저의 최근 7일 광고 반응 점수'라 하자(평균 0, 표준편차 1).
N = 200_000
train = [random.gauss(0.0, 1.0) for _ in range(N)]
edges = make_edges(train, 10)
base = to_shares(train, edges)

# 3단계: 평균이 밀린 네 경우를 같은 경계로 측정한다
# 오늘 입력의 평균이 조금씩 밀린 네 경우다. PSI 와 함께, PSI 가 감추는 구간별 실제 차이도 찍는다.
print("평균이동   PSI    구간별최대차이  10%에서 2%p 이상 벗어난 구간")
for shift in (0.10, 0.23, 0.40, 0.57):
    now = to_shares([random.gauss(shift, 1.0) for _ in range(N)], edges)
    max_gap = max(abs(a - b) * 100 for b, a in zip(base, now))   # PSI가 감추는 실제 차이
    off = sum(1 for a in now if abs(a - 0.10) > 0.02)            # 10%에서 크게 벗어난 구간 수
    print(f"  {shift:+.2f}   {psi(base, now):.3f}      {max_gap:4.1f}%p        {off}개 / 10개")

# 4단계: 사고가 없을 때 표본 크기별 PSI 를 측정한다
# 사고가 없어도 표본이 작으면 PSI 가 저절로 올라간다. 임계값의 함정이 여기다.
print()
print("표본크기   사고가 없는데도 나오는 PSI (같은 분포에서 20번 뽑아 비교)")
for n in (100, 300, 1_000, 10_000, 200_000):
    vals = sorted(psi(base, to_shares([random.gauss(0.0, 1.0) for _ in range(n)], edges))
                  for _ in range(20))
    print(f"{n:7d}    평균 {sum(vals) / len(vals):.3f}   최댓값 {vals[-1]:.3f}")

# 출력:
# 3단계 뜻: 평균이 +0.10 밀리면 PSI 가 0.009 로 조용하고, +0.23 이면 0.050 에 구간별 최대 4.5%p 차이다. +0.57 이면 0.303 으로 구간 8개가 10% 에서 2%p 넘게 벗어난다.
# 평균이동   PSI    구간별최대차이  10%에서 2%p 이상 벗어난 구간
#   +0.10   0.009       1.7%p        0개 / 10개
#   +0.23   0.050       4.5%p        4개 / 10개
#   +0.40   0.149       8.7%p        6개 / 10개
#   +0.57   0.303      13.6%p        8개 / 10개
# 4단계 뜻: 같은 분포끼리 비교해도 표본이 100 이면 PSI 평균이 0.098, 최댓값이 0.169 로 나온다. 표본이 10000 이면 평균 0.001 로 줄어든다.
#
# 표본크기   사고가 없는데도 나오는 PSI (같은 분포에서 20번 뽑아 비교)
#     100    평균 0.098   최댓값 0.169
#     300    평균 0.029   최댓값 0.065
#    1000    평균 0.009   최댓값 0.019
#   10000    평균 0.001   최댓값 0.002
#  200000    평균 0.000   최댓값 0.000
```

3단계 표에서 평균이 +0.10 밀린 경우는 PSI 가 0.009 이고 구간별 최대 차이가 1.7%p 라 거의 조용합니다. 평균이 +0.23 밀린 경우의 **PSI 0.05 는 구간별 차이가 최대 4.5%p 인 상태**로, 십분위 하나가 10% 에서 14.5% 가 된 정도입니다. 같은 방식으로 읽으면 **0.15 는 최대 8.7%p**, **0.30 은 최대 13.6%p** 차이입니다. 평균이 +0.57 밀려 PSI 가 0.303 이 되면 10개 구간 가운데 8개가 10% 에서 2%p 넘게 벗어납니다.

PSI 에 흔히 쓰는 임계값(넘으면 알람을 울리는 기준값)은 **0.1 과 0.25** 입니다. 0.1 미만이면 안정, 0.25 를 넘으면 조치가 필요한 상태로 봅니다. 이 두 값은 신용 스코어링(대출 심사에서 신청자의 신용 점수를 매기는 일) 업계의 관행일 뿐 통계적으로 유도한 값이 아닙니다. 이 임계값은 두 가지 면에서 틀립니다.

첫째로 구간 수를 늘리면 같은 분포 차이에서도 PSI 가 크게 나오므로 임계값을 정할 때는 구간 수도 함께 고정해야 합니다.

둘째로 **표본이 작으면 사고가 없어도 PSI 가 올라갑니다.** 4단계는 학습 때와 같은 분포에서 표본을 20번씩 새로 뽑아 PSI 를 계산하므로, 찍힌 값은 모두 사고 없이 표본 크기가 유한해서 생긴 값입니다. 그런데도 표본이 100건이면 PSI 평균이 0.098, 최댓값이 0.169 였고 표본이 10000건이면 평균이 0.001 로 줄었습니다. 평균 0.098 이 임계값 0.1 에 거의 닿아 있어서 표본 100건에 0.1 을 걸면 아무 일이 없어도 알람이 절반쯤 울립니다. 트래픽을 지면이나 기기 같은 기준으로 나눈 부분을 세그먼트라고 부릅니다. 세그먼트 하나의 표본은 전체보다 작으므로 세그먼트별 PSI 에는 「표본이 몇 건 이상일 때만 판정한다」는 최소 표본 수 조건을 반드시 붙여야 합니다.

### PSI 가 못 잡는 변화

**PSI 는 입력이 달라졌는지만 보고 입력과 정답의 관계가 달라졌는지는 보지 못합니다.**

경쟁사가 같은 지면에 더 좋은 소재(광고 이미지와 문구)를 많이 내보내기 시작했다고 해 봅시다. 우리 쪽 입력은 그대로라서 PSI 는 0 에 가깝게 나옵니다. 그런데 같은 입력에서 실제 CTR 이 달라졌는데도 모델은 예전 CTR 을 계속 예측하므로 COPC 는 1 에서 크게 벗어납니다. 그래서 PSI 하나로는 부족합니다.

또 PSI 는 피처를 하나씩 따로 측정하므로 **여러 피처를 함께 본 결합 분포(joint distribution)의 변화도 보지 못합니다.** 봇 트래픽(사람이 아닌 프로그램이 보내는 요청)처럼 「새벽에 PC 로 들어오는 요청」만 10배가 되면 이 변화는 시간대와 기기를 함께 봐야 보이므로, 피처마다 따로 계산한 PSI 는 모두 조용합니다.

## 4. 라벨을 기다리지 않는 예측 분포 감시

**라벨은 나중에 오지만 예측값은 지금 바로 있으므로, 예측값의 평균과 분위수를 보면 라벨을 기다리는 것보다 며칠 빨리 사고를 알 수 있습니다.**

3절의 PSI 가 1층 입력을 봤다면 이 절은 2층 출력, 곧 모델이 내놓은 예측값을 봅니다. 예측 분포에서 볼 숫자는 5가지로, 예측 평균, 중위수(예측값을 크기순으로 늘어놓았을 때 한가운데 값), 상위 1% 와 하위 1%(위와 아래에서 1% 자리에 오는 값), 그리고 피처가 비어 기본값으로 대체된 요청의 비율입니다.

평균과 함께 분위수를 보는 데는 까닭이 있습니다. 피처가 전부 비면 모델은 요청이 달라도 거의 같은 숫자만 내놓으므로, 예측 평균은 멀쩡한데 상위 1% 와 하위 1% 가 평균 근처로 모여 분위수가 붕괴합니다.

아래 코드는 60일 시뮬레이션에서 40일차에 피처가 깨지는 사고를 만든 뒤 감시 방식 3가지가 사고를 며칠 만에 잡는지, 사고 전에 오탐(사고가 없는데 울린 알람)을 몇 건 내는지 비교합니다. 사고가 나면 모델의 예측 평균은 2.00% 에서 1.56% 로, 진짜 전환율(CVR, 클릭 가운데 전환으로 이어진 비율)은 2.00% 에서 1.40% 로 떨어집니다. 하루 클릭은 2만 건입니다. 전환은 클릭한 날 한꺼번에 오지 않고 지연 곡선(클릭 뒤 며칠째에 전환이 얼마씩 도착하는지 나타낸 비율)을 따라 클릭한 날부터 7일 뒤까지 나눠 도착합니다.

감시 방식은 3가지입니다. **예측 평균**은 라벨 없이 그날 예측값의 평균을 그날 봅니다. **확정 윈도우**는 전환이 다 들어와 라벨이 확정된(확정 라벨) 7일 전 클릭만 모아 전환율을 봅니다. 여기서 윈도우는 지표를 계산할 때 모으는 데이터의 범위입니다. 성숙도는 클릭 뒤 일정 시간이 지났을 때 전체 전환 가운데 이미 도착한 몫입니다. **성숙도 보정**은 어제 클릭에서 지금까지 도착한 전환을 「하루 지나면 57% 는 온다」는 고정 가정으로 나눠 다 도착했을 때의 전환율을 미리 추정합니다. 세 방식 모두 기준선(평소 값으로 삼는 비교 기준) 2.00% 보다 10% 넘게 낮은 날을 위반으로 세고 최근 3일 가운데 2일 이상이 위반이면 알람을 울립니다.

```python
# 하는 일: 60일 가운데 40일차에 사고가 나는 시뮬레이션으로, 예측 평균 감시, 성숙도 보정 감시, 7일 확정 감시가 사고를 며칠 만에 잡고 오탐이 몇 건인지 비교한다.
import random
import math

random.seed(42)

# 1단계: 사고 전후의 전환율과 예측, 전환 지연 곡선, 감시 기준을 둔다
# 40일차에 피처가 깨져 예측 평균이 2.00% 에서 1.56% 로, 진짜 전환율이 2.00% 에서 1.40% 로 떨어진다.
DAYS, INCIDENT, CLICKS = 60, 40, 20_000   # 60일 시뮬, 40일차에 사고, 하루 클릭 2만
CVR_OK, CVR_BAD = 0.0200, 0.0140          # 진짜 전환율 2.00% -> 1.40%
PRED_OK, PRED_BAD = 0.0200, 0.0156        # 모델 예측 평균 2.00% -> 1.56%
# 클릭 뒤 k일째 도착하는 전환 비율. 금요일과 토요일 클릭은 결제가 주말 뒤로 밀려 앞쪽이 느리다.
DELAY_WEEKDAY = [0.37, 0.23, 0.15, 0.10, 0.06, 0.04, 0.03, 0.02]   # 합 1.00
DELAY_WEEKEND = [0.28, 0.18, 0.16, 0.13, 0.10, 0.07, 0.05, 0.03]   # 합 1.00
MATURITY_1D = 0.57      # 감시 코드가 쓰는 '하루 지나면 57%는 온다'는 고정 가정
BASELINE, TOL = 0.0200, 0.10   # 기준선 2.00%, 기준선보다 10% 이상 낮으면 그날은 위반

# 2단계: 날마다 전환이 도착하는 과정과 예측 평균을 만든다
# binom 은 numpy 없이 이항 표본을 흉내 내고, curve 는 금요일과 토요일 클릭에 느린 곡선을 준다.
def binom(n, p):
    """이항 표본을 정규근사로 뽑는다. numpy 없이 표본 노이즈만 흉내낸다."""
    return max(0, round(random.gauss(n * p, math.sqrt(n * p * (1 - p)))))

def curve(day):
    """그 날 클릭의 지연 곡선. 0=월요일이므로 금(4), 토(5)가 느린 곡선을 쓴다."""
    return DELAY_WEEKEND if day % 7 in (4, 5) else DELAY_WEEKDAY

# 날마다 진짜 전환 수를 뽑고, 지연 곡선에 따라 도착일로 흘려 놓는다.
arrived = [[0.0] * (DAYS + 8) for _ in range(DAYS)]    # arrived[클릭일][도착일]
pred_mean = [0.0] * DAYS
for d in range(DAYS):
    conv = binom(CLICKS, CVR_BAD if d >= INCIDENT else CVR_OK)
    for k, share in enumerate(curve(d)):
        arrived[d][d + k] = conv * share
    base = PRED_BAD if d >= INCIDENT else PRED_OK
    pred_mean[d] = base + random.gauss(0, 0.00008)      # 예측 평균은 흔들림이 아주 작다

# 3단계: 감시 방식 세 가지를 함수로 만든다
# 예측 평균은 그날 바로 보고, 확정 윈도우는 7일 전 클릭을, 성숙도 보정은 어제 클릭을 도착률 57% 로 나눠 본다.
def cum(click_day, upto):
    """click_day에 누른 클릭 중 upto 날까지 도착한 전환 수."""
    return sum(arrived[click_day][:upto + 1])

# 감시 방식 세 가지. 각 함수는 관측일 D에서 '지금 볼 수 있는 값'만 돌려준다.
def watch_pred(D):
    return pred_mean[D]                                # 라벨이 없어도 그날 값을 그날 본다

def watch_settled(D):
    d = D - 7                                          # 7일 지나 전환이 다 들어온 클릭일
    return None if d < 0 else cum(d, D) / CLICKS

def watch_corrected(D):
    d = D - 1                                          # 어제 클릭을 도착률로 나눠 되돌린다
    return None if d < 0 else cum(d, D) / (CLICKS * MATURITY_1D)

# 4단계: 감시 방식마다 알람을 울려 본다
# 최근 3일 가운데 2일이 기준선보다 10% 이상 낮으면 알람이다.
def run(name, fn):
    """최근 3일 중 2일이 위반이면 알람. 연달아 울린 것은 한 건으로 묶어 센다."""
    bad = []
    for D in range(DAYS):
        v = fn(D)
        bad.append(v is not None and v < BASELINE * (1 - TOL))
    fired = [D for D in range(2, DAYS) if sum(bad[D - 2:D + 1]) >= 2]
    after = [D for D in fired if D >= INCIDENT]
    false_events = sum(1 for D in fired if D < INCIDENT and (D - 1) not in fired)
    day = f"{after[0]}일차" if after else "-"
    lag = f"{after[0] - INCIDENT}일 뒤" if after else "못 잡음"
    print(f"{name:22s} {day:>7s}  {lag:>7s}   사고 전 오탐 {false_events}건")

print("감시 방식                 알람일   사고 후   (60일 시뮬, 사고는 40일차)")
run("예측 평균 (라벨 불필요)", watch_pred)
run("성숙도 보정 (어제 윈도우)", watch_corrected)
run("확정 윈도우 (7일 대기)", watch_settled)

# 5단계: 관측일마다 세 방식이 본 숫자를 나란히 찍는다
print()
print("관측일  예측평균   보정CVR   확정CVR")
for D in (39, 40, 41, 45, 47, 48):
    s = watch_settled(D)
    print(f"{D:5d}   {watch_pred(D) * 100:6.3f}%   {watch_corrected(D) * 100:6.3f}%   "
          f"{'-' if s is None else format(s * 100, '6.3f') + '%'}")

# 출력:
# 4단계 뜻: 예측 평균은 사고 1일 뒤인 41일차에 오탐 없이 잡는다. 성숙도 보정도 41일차에 잡지만 사고 전 오탐이 5건이고, 확정 윈도우는 8일 뒤인 48일차에야 잡는다.
# 감시 방식                 알람일   사고 후   (60일 시뮬, 사고는 40일차)
# 예측 평균 (라벨 불필요)            41일차     1일 뒤   사고 전 오탐 0건
# 성숙도 보정 (어제 윈도우)           41일차     1일 뒤   사고 전 오탐 5건
# 확정 윈도우 (7일 대기)            48일차     8일 뒤   사고 전 오탐 0건
# 5단계 뜻: 40일차에 예측 평균은 이미 1.558% 로 내려왔는데, 확정 CVR 은 아직 사고 전 클릭을 보느라 2.005% 로 멀쩡하다. 확정 CVR 은 47일차에야 1.340% 로 떨어진다.
#
# 관측일  예측평균   보정CVR   확정CVR
#    39    2.006%    2.205%    2.095%
#    40    1.558%    1.610%    2.005%
#    41    1.551%    1.081%    1.970%
#    45    1.567%    1.495%    2.095%
#    47    1.563%    1.150%    1.340%
#    48    1.560%    1.190%    1.245%
```

**4단계 표에서 예측 평균은 사고 1일 뒤인 41일차에 오탐 없이, 확정 라벨은 8일 뒤인 48일차에야 사고를 잡아 7일 차이가 납니다.** 그 7일 동안은 잘못된 입찰가로 광고를 계속 삽니다.

예측 평균도 사고 당일인 40일차에는 위반이 하루뿐이라 알람이 울리지 않고 이틀째 위반인 41일차에 「최근 3일 가운데 2일」 조건을 채워 울립니다. 확정 라벨이 늦는 까닭은 5단계 표에서 보입니다. 40일차에 예측 평균은 이미 1.558% 로 내려왔지만 확정 윈도우가 40일차에 보는 클릭은 7일 전인 33일차의 사고 전 클릭이라 확정 CVR 은 2.005% 로 멀쩡합니다. 확정 CVR 은 40일차 클릭이 확정되는 47일차에야 1.340% 로 떨어집니다. 알람은 위반이 이틀째가 되는 48일차에 울립니다.

5단계 표의 가운데 열 「보정CVR」은 세 번째 방식인 **성숙도 보정**의 값입니다. 이 방식도 41일차에 사고를 잡아 빠르지만 사고 전 40일 동안 오탐이 5건 나왔습니다.

오탐은 지연 곡선이 요일마다 달라서 생깁니다. 금요일과 토요일이 아닌 날의 클릭은 전환의 0.37 이 클릭한 날, 0.23 이 다음 날 도착해 하루 뒤에는 57% 가정보다 조금 많이 와 있습니다. 금요일과 토요일 클릭은 결제가 주말 뒤로 밀려 같은 이틀 동안 0.28 과 0.18 만 도착하므로 57% 로 나눈 보정 CVR 이 기준선보다 10% 넘게 낮게 나옵니다. 5단계 표의 40일차 보정 CVR 1.610% 도 사고 전인 39일차 클릭, 곧 금요일 클릭을 57% 로 나눈 값입니다. 금요일 클릭과 토요일 클릭을 보는 이틀은 매주 연달아 위반이 되어 「3일 가운데 2일」 조건을 채우므로 사고 전 오탐 5건이 이렇게 생깁니다.

그래서 실무에서는 **예측 분포를 1차 감시로 쓰고 확정 라벨은 최종 검산으로** 씁니다.

### 라벨이 빨리 오고 세그먼트가 확실한 담장 안 [무대: 닫힌 생태계]

**담장 안(한 회사가 광고 지면과 광고 서버를 함께 가진 닫힌 생태계)에서는 라벨이 빨리 오고 세그먼트 기준이 흔들리지 않는 대신 지면 하나의 비중이 큽니다.**

광고주를 대신해 광고 자리를 사는 플랫폼을 DSP(Demand-Side Platform)라고 부릅니다. 담장 안 DSP 는 노출, 클릭, 전환 로그가 모두 자사 서버에 남으므로 전환이 사라지는 유실이 사실상 없고 전환이 도착하기까지의 지연도 짧습니다. 유저가 로그인해서 쓰는 서비스라 세그먼트 기준도 흔들리지 않습니다. 담장 안에서는 COPC 를 15분 윈도우로 지면×기기 조합마다 걸고 전환도 클릭 뒤 6시간이 지나면 성숙했다고 보고 판단합니다.

대신 지면 수가 적어 지면 하나가 전체에서 차지하는 비중이 크므로, 큰 지면 하나가 흔들리면 전체 지표가 같이 흔들려 다른 지면에서 난 이상이 그 움직임 뒤에 숨습니다.

### 성숙 대기 시간부터 정해야 하는 열린 RTB [무대: 열린 RTB]

**열린 RTB(Real-Time Bidding, 노출 한 번마다 여러 회사가 실시간 경매로 광고 자리를 사고파는 시장)에서는 전환이 늦게 오고 일부는 아예 오지 않으므로 알람을 걸기 전에 성숙 대기 시간부터 정해야 합니다.**

열린 RTB 는 담장 안과 반대입니다. 유저가 광고를 클릭한 뒤의 전환은 광고주 서버나 MMP(Mobile Measurement Partner, 앱 설치와 전환을 측정해 주는 회사)가 **포스트백**(전환이 일어났다고 알려 주는 서버 간 호출)을 보내 줘야 알 수 있는데, 이 포스트백은 늦게 오고 일부는 끝내 오지 않습니다.

알람보다 먼저 정하는 **성숙 대기 시간**은 「클릭 뒤 며칠이 지나면 그 클릭의 전환 수를 믿는다」는 기준을 광고주 유형별로 고정한 값입니다. 게임 앱 설치는 하루, 보험 상담은 7일처럼 광고주 유형마다 그 기간이 다릅니다.

늦게 오는 전환은 지표를 작게 보이게 하는데, 끝내 오지 않는 전환까지 늦게 오는 전환처럼 성숙도로 나누면 이번에는 반대로 지표가 커집니다. 그래서 **영구 유실률**(끝내 오지 않는 전환의 비율)은 지연과 따로 추정합니다([Negative Sampling과 편향](post.html?id=negative-sampling-bias) 참고).

## 5. 전체 지표는 멀쩡한데 한 지면만 크게 나빠지는 경우

**전체 지표에서는 과대예측(예측이 실제보다 많음)과 과소예측(예측이 실제보다 적음)이 서로를 지우므로, 전체 숫자만 보는 감시는 일부 지면에서만 난 반쪽 사고를 모두 놓칩니다.**

1절에서 모델은 부분적으로만 나빠지는데 전체 평균은 끝까지 멀쩡해 보인다고 했습니다. 이 절은 그 상황을 지면 6곳의 숫자로 따라갑니다. COPC 는 2절에서 풀었듯이 실제 클릭을 예측 클릭으로 나눈 값입니다. 1 보다 크면 실제 클릭이 예측보다 많았으니 모델이 적게 예측한 과소예측입니다. 1 보다 작으면 반대로 많게 예측한 과대예측입니다.

정의와 보정 기법은 [Calibration](post.html?id=calibration) 편에서 다뤘으므로 여기서는 **COPC 를 어느 단위로 집계하는지**만 봅니다. 아래 표는 **가상 데이터**입니다. 지면마다 노출에 예측 CTR 을 곱하면 예측 클릭이, 실제 CTR 을 곱하면 실제 클릭이 나옵니다.

| 지면 | 노출 | 예측 CTR | 실제 CTR | COPC | 클릭 차이 |
|---|---|---|---|---|---|
| 뉴스 피드 | 4,000,000 | 2.00% | 1.90% | 0.950 | -4,000 |
| 검색 상단 | 1,500,000 | 5.00% | 5.73% | 1.146 | +10,950 |
| 앱 배너 | 2,000,000 | 1.00% | 0.62% | 0.620 | -7,600 |
| 동영상 인스트림 | 800,000 | 0.80% | 1.20% | 1.500 | +3,200 |
| 쇼핑 추천 | 1,200,000 | 3.00% | 3.15% | 1.050 | +1,800 |
| 신규 지면 X | 300,000 | 2.50% | 1.05% | 0.420 | -4,350 |
| **합계** | **9,800,000** | | | **1.000** | **0** |

합계 줄의 전체 COPC 1.000 만 보면 보정이 정확히 맞은 모델처럼 보입니다. 그런데 지면별 COPC 는 신규 지면 X 의 0.420 부터 동영상 인스트림의 1.500 까지 흩어져 있습니다. 앱 배너는 노출 2,000,000 에 예측 CTR 1.00% 를 곱한 20,000 클릭을 기대했지만 실제 CTR 0.62% 로는 12,400 클릭만 나와 클릭을 7,600건 과하게 기대했습니다(COPC 0.620). 검색 상단은 반대로 예측한 75,000 클릭보다 실제 85,950 클릭이 많아 10,950건을 놓쳤습니다(COPC 1.146). 이렇게 과하게 기대한 몫과 놓친 몫이 서로를 지운 결과가 전체 COPC 1.000 입니다.

심슨의 역설(그룹별로 본 경향이 그룹을 합치면 반대로 뒤집히는 현상)에서는 **방향이 뒤집히지만** 여기서는 오차가 **상쇄되어 사라집니다.** 방향이 뒤집히면 숫자가 이상해서 누군가 알아채지만 오차가 사라지면 아무도 이상하다고 느끼지 못합니다.

아래 코드는 표의 지면 6곳으로 네 가지를 계산합니다. 2단계는 지면별 COPC 와 합계를, 3단계는 과대예측 몫과 과소예측 몫을, 4단계는 전체 지표 대신 대시보드에 올릴 숫자를 구합니다. 5단계는 세그먼트를 잘게 쪼갤 때 사고가 없어도 COPC 가 흔들리는 폭(바닥 노이즈)을 측정합니다.

```python
# 하는 일: 지면 6곳의 예측 클릭과 실제 클릭으로, 전체 COPC 는 1.000 인데 지면별로는 0.42 에서 1.50 으로 흩어지는 상황을 계산하고 무엇을 대신 올릴지 본다.
import math

# 1단계: 지면 6곳의 예측과 실제를 둔다
# COPC 는 실제 클릭 / 예측 클릭이다. 1 보다 크면 모델이 과소예측한 것이다.
# 가상 데이터: (지면 이름, 노출 수, 예측 CTR, 실제 CTR)
placements = [
    ("뉴스 피드",     4_000_000, 0.0200, 0.0190),
    ("검색 상단",     1_500_000, 0.0500, 0.0573),
    ("앱 배너",       2_000_000, 0.0100, 0.0062),
    ("동영상 인스트림",  800_000, 0.0080, 0.0120),
    ("쇼핑 추천",     1_200_000, 0.0300, 0.0315),
    ("신규 지면 X",     300_000, 0.0250, 0.0105),
]
# 지면마다 (이름, 노출, 예측 클릭, 실제 클릭, COPC)로 펼친다.
rows = [(n, imp, imp * pc, imp * ac, ac / pc) for n, imp, pc, ac in placements]
total_pred = sum(r[2] for r in rows)
total_act = sum(r[3] for r in rows)

# 2단계: 지면별 COPC 와 합계를 찍는다
print("지면              예측클릭    실제클릭   COPC   차이(클릭)")
for name, imp, pred, act, copc in rows:
    print(f"{name:14s} {pred:9,.0f} {act:10,.0f}  {copc:5.3f}  {act - pred:+9,.0f}")
print(f"{'합계':14s} {total_pred:9,.0f} {total_act:10,.0f}  {total_act / total_pred:5.3f}")

# 3단계: 과대예측 몫과 과소예측 몫을 센다
# 합계가 멀쩡해 보이는 이유는 두 몫이 서로를 지우기 때문이다.
over = sum(r[2] - r[3] for r in rows if r[4] < 1)      # 예측이 실제보다 많았던 클릭 수
under = sum(r[3] - r[2] for r in rows if r[4] > 1)     # 예측이 실제보다 적었던 클릭 수
print()
print(f"과대예측 합계 {over:,.0f} 클릭 / 과소예측 합계 {under:,.0f} 클릭")
print(f"전체 예측 클릭의 {over / total_pred * 100:.1f}%가 엉뚱한 지면에 더해져 있다")

# 4단계: 전체 지표 대신 올릴 숫자를 구한다
# 가중 절대 편차는 상쇄가 일어나지 않는다.
wmad = sum(r[2] / total_pred * abs(r[4] - 1) for r in rows)   # 예측 클릭을 가중치로 쓴다
worst = max(rows, key=lambda r: abs(r[4] - 1))
breach = [r for r in rows if abs(r[4] - 1) > 0.10]            # 10% 넘게 틀어진 지면
print()
print(f"전체 COPC 편차          : {abs(total_act / total_pred - 1) * 100:.1f}%  (알람 안 울림)")
print(f"가중 평균 절대 편차     : {wmad * 100:.1f}%  (알람 울림)")
print(f"최악 세그먼트           : {worst[0]} COPC {worst[4]:.3f}")
print(f"10% 넘게 틀어진 지면    : {len(breach)}개, "
      f"예측 클릭의 {sum(r[2] for r in breach) / total_pred * 100:.1f}%")

# 5단계: 세그먼트를 잘게 쪼갤 때의 바닥 노이즈를 측정한다
# 실제 클릭이 포아송이면 COPC의 표준편차는 대략 1/sqrt(예측 클릭 수)다.
print()
print("예측클릭   COPC 노이즈 폭(95%)   10% 임계값이 잡는 것")
for n in (100, 400, 10_000):
    band = 1.96 / math.sqrt(n)
    print(f"{n:8,d}   +-{band * 100:5.1f}%            {'노이즈' if band > 0.10 else '실제 이상'}")
print(f"임계값 10%가 노이즈에 안 걸리는 최소 클릭 수: {math.ceil((1.96 / 0.10) ** 2):,d}건")

# 출력:
# 2단계 뜻: 합계는 예측 224,900 과 실제 224,900 이 같아 COPC 1.000 이다. 지면별로는 신규 지면 X 0.420 부터 동영상 인스트림 1.500 까지 흩어진다.
# 지면              예측클릭    실제클릭   COPC   차이(클릭)
# 뉴스 피드             80,000     76,000  0.950     -4,000
# 검색 상단             75,000     85,950  1.146    +10,950
# 앱 배너              20,000     12,400  0.620     -7,600
# 동영상 인스트림           6,400      9,600  1.500     +3,200
# 쇼핑 추천             36,000     37,800  1.050     +1,800
# 신규 지면 X            7,500      3,150  0.420     -4,350
# 합계               224,900    224,900  1.000
# 3단계 뜻: 과대예측한 클릭 15,950 과 과소예측한 클릭 15,950 이 서로를 지운다. 전체 예측 클릭의 7.1% 가 엉뚱한 지면에 더해져 있다.
#
# 과대예측 합계 15,950 클릭 / 과소예측 합계 15,950 클릭
# 전체 예측 클릭의 7.1%가 엉뚱한 지면에 더해져 있다
# 4단계 뜻: 전체 COPC 편차는 0.0% 인데 가중 평균 절대 편차는 14.2% 다. 10% 넘게 틀어진 지면이 4개이고, 예측 클릭의 48.4% 를 차지한다.
#
# 전체 COPC 편차          : 0.0%  (알람 안 울림)
# 가중 평균 절대 편차     : 14.2%  (알람 울림)
# 최악 세그먼트           : 신규 지면 X COPC 0.420
# 10% 넘게 틀어진 지면    : 4개, 예측 클릭의 48.4%
# 5단계 뜻: 예측 클릭이 100건이면 아무 일이 없어도 COPC 가 +- 19.6% 안에서 흔들려, 10% 임계값은 노이즈를 측정한다. 노이즈에 안 걸리려면 예측 클릭이 385건은 있어야 한다.
#
# 예측클릭   COPC 노이즈 폭(95%)   10% 임계값이 잡는 것
#      100   +- 19.6%            노이즈
#      400   +-  9.8%            실제 이상
#   10,000   +-  2.0%            실제 이상
# 임계값 10%가 노이즈에 안 걸리는 최소 클릭 수: 385건
```

3단계가 찍은 대로 과대예측한 클릭 15,950 과 과소예측한 클릭 15,950 이 서로를 지웁니다. 과대예측한 15,950 클릭은 전체 예측 클릭 224,900 의 7.1% 로, 그만큼이 엉뚱한 지면에 더해져 있습니다.

**전체 COPC 편차는 0.0% 인데 가중 평균 절대 편차는 14.2% 입니다.** 가중 평균 절대 편차는 지면마다 COPC 가 1 에서 벗어난 폭의 절대값을 그 지면의 예측 클릭을 가중치로 평균한 값이라, 위로 벗어난 폭과 아래로 벗어난 폭이 모두 양수로 더해져 상쇄가 일어나지 않습니다. 이 평균은 지면별 클릭 차이의 절대값을 모두 더해 전체 예측 클릭으로 나눈 값과 같아서 이 표에서는 (15,950 + 15,950) ÷ 224,900 = 14.2% 입니다. 대시보드에 전체 지표를 하나만 올릴 수 있다면 전체 COPC 보다 이 숫자가 낫습니다. 4단계는 이 밖에도 COPC 가 1 에서 10% 넘게 틀어진 지면이 4개이고 이 4개가 예측 클릭의 48.4% 를 차지하며 가장 크게 틀어진 최악 세그먼트는 신규 지면 X(COPC 0.420)라고 찍습니다.

**예측 클릭이 385건이 안 되는 세그먼트에 10% 임계값을 걸면 사고가 아니라 노이즈를 측정합니다.** 실제 클릭 수가 포아송 분포(일정한 비율로 드물게 일어나는 사건의 횟수가 따르는 분포)를 따르면 COPC 의 표준편차는 대략 1/√(예측 클릭 수) 이고 95% 범위는 1 을 중심으로 위아래 그 1.96배까지입니다. 예측 클릭이 100건이면 1.96 을 √100 인 10 으로 나눈 ±19.6% 안에서 COPC 가 아무 일 없이도 흔들리므로 10% 임계값은 사고 대신 노이즈를 잡습니다. 노이즈 폭이 10% 보다 좁아지려면 1.96 ÷ √(예측 클릭) 이 0.10 보다 작아야 하므로 예측 클릭이 (1.96 ÷ 0.10)² 을 올림한 385건은 있어야 합니다. 5단계 표에서도 예측 클릭 400건은 ±9.8% 로 10% 안에 들어와 「실제 이상」으로 나옵니다.

그래서 실무에서는 세그먼트를 이렇게 제한합니다.

- 세그먼트를 나누는 기준은 3개까지만 씁니다.
- 기준을 조합한 세그먼트는 트래픽 상위 30~50개만 감시합니다.
- 세그먼트마다 예측 클릭 1,000건 이상을 판정 조건으로 둡니다.

## 6. 알람 설계의 설정 4가지

**알람이 너무 민감하면 아무도 보지 않고 너무 둔하면 사고를 늦게 압니다.**

그 사이에서 알람의 감도는 설정 4가지로 정합니다. **임계값**은 지표가 기준에서 얼마나 벗어나면 위반으로 볼지 정한 값이고 **연속 위반 규칙**은 위반이 몇 번 연달아 나와야 알람을 울릴지 정한 규칙입니다. **최소 표본 조건**은 표본이 충분한 윈도우만 판정하게 하는 조건이고 **억제 규칙**은 알람이 울려도 사람을 부르지 않는 경우를 정한 규칙입니다.

이 가운데 앞의 두 가지인 임계값과 연속 위반 규칙을 바꿔 가며 교환비(오탐을 줄이는 대가로 사고를 얼마나 놓치거나 늦게 잡는지)를 측정해 봅니다.

코드는 30일 동안 1시간마다 COPC 를 하나씩 계산한 감시 윈도우 720개를 만들고 그 사이에 사고 8건을 넣습니다. 4건은 COPC 낙폭이 -7% 인 작은 사고이고 4건은 -16% 인 큰 사고입니다. 대시보드 값에는 사고가 아니어도 트래픽 구성(믹스)이 시간마다 바뀌어 생기는 흔들림과 클릭 수가 유한해서 생기는 표본 노이즈가 더해집니다. 사고 윈도우가 아닌데 울린 알람은 오탐으로 세되 연달아 울린 것은 한 건으로 묶습니다. 사고 도중이나 끝난 뒤 2시간 안에 울렸으면 그 사고를 적발한 것으로 봅니다. 감지 지연은 사고가 시작된 때부터 첫 알람까지 걸린 시간입니다. 4단계는 임계값 6가지를 비교합니다. 5단계는 임계값을 5% 로 고정한 채 「몇 번 연달아 위반해야 부를지」만 바꿉니다.

```python
# 하는 일: 사고 8건이 섞인 30일치 시간당 COPC 에 임계값과 '연속 몇 번' 규칙을 바꿔 가며 알람을 걸어, 오탐과 적발, 감지 지연을 비교한다.
import random
import math

random.seed(42)

# 1단계: 30일치 감시 윈도우와 사고 8건을 둔다
# 지표는 시간당 COPC(실제 클릭 / 예측 클릭)이고, 정상이면 1.00 근처다.
DAYS, PER_DAY = 30, 24
N = DAYS * PER_DAY                       # 감시 윈도우 720개 = 30일 x 시간당 1개
PRED_CLICKS = 4_000                      # 윈도우 하나에 담기는 예측 클릭 수
MIX_SD = 0.030                           # 트래픽 믹스가 시간마다 흔들리는 폭(사고 아님)
SAMPLE_SD = 1 / math.sqrt(PRED_CLICKS)   # 클릭 수가 유한해서 생기는 표본 노이즈
# 실제로 일어난 사고 8건: (시작 윈도우, 지속 윈도우 수, COPC 낙폭). 절반은 -7%, 절반은 -16%다.
INCIDENTS = [(72, 6, 0.07), (180, 6, 0.16), (300, 6, 0.07), (408, 6, 0.16),
             (504, 6, 0.07), (576, 6, 0.16), (636, 6, 0.07), (684, 6, 0.16)]

# 2단계: 진짜 COPC 와 대시보드에 찍히는 값을 만든다
# 사고 윈도우에서는 진짜 COPC 를 낙폭만큼 낮춘다.
truth = [1.0] * N                        # 사고가 없을 때의 진짜 COPC
incident_windows = set()
for start, length, drop in INCIDENTS:
    for i in range(start, start + length):
        truth[i] -= drop
        incident_windows.add(i)

# 대시보드에 찍히는 값 = 진짜 값 + 믹스 변동 + 표본 노이즈
observed = [truth[i] + random.gauss(0, MIX_SD) + random.gauss(0, SAMPLE_SD)
            for i in range(N)]

# 3단계: 규칙마다 오탐과 적발, 감지 지연을 세는 함수를 만든다
# 임계값 th 를 넘는 윈도우를 위반으로 보고, 최근 span 개 가운데 need 개가 위반이면 울린다.
def score(th, need=1, span=1):
    """임계값 th, '최근 윈도우 span개 중 need개 위반' 규칙일 때의 오탐, 적발, 감지 지연."""
    breach = [abs(v - 1.0) > th for v in observed]
    fired = [i for i in range(span - 1, N) if sum(breach[i - span + 1:i + 1]) >= need]
    fset = set(fired)
    # 사고 윈도우가 아닌데 울린 것은 오탐. 연달아 울린 것은 한 건으로 묶는다.
    false_events = sum(1 for i in fired
                       if i not in incident_windows and (i - 1) not in fset)
    small = big = 0
    lags = []
    for start, length, drop in INCIDENTS:
        # 사고 윈도우 안이나 끝난 뒤 2시간 안에 울렸으면 그 사고를 잡은 것으로 본다.
        hit = [i for i in fired if start <= i < start + length + 2]
        if hit:
            lags.append(hit[0] - start)
            if drop < 0.10:
                small += 1               # 작은 사고(-7%)를 잡은 횟수
            else:
                big += 1                 # 큰 사고(-16%)를 잡은 횟수
    lag = f"{sum(lags) / len(lags):.1f}시간" if lags else "-"
    return false_events, small, big, lag

# 4단계: 임계값 여섯 가지를 비교한다
print(f"윈도우 {N}개(30일), 사고 8건, 사고 윈도우 {len(incident_windows)}개")
print("임계값  오탐  하루알람   작은사고(-7%)  큰사고(-16%)  평균감지")
for th in (0.03, 0.05, 0.08, 0.10, 0.15, 0.20):
    fe, small, big, lag = score(th)
    print(f" {th:.2f}  {fe:4d}건  {fe / DAYS:5.2f}회   {small:6d}/4건      "
          f"{big:4d}/4건    {lag:>6s}")

# 5단계: 임계값을 5% 로 고정하고 규칙만 바꾼다
# '몇 번 연달아 위반해야 부를까'만 바꿔 본다.
print()
print("임계값 5% 고정, 알람 규칙만 교체")
print("규칙          오탐   작은사고  큰사고  평균감지")
for name, need, span in (("1회 즉시", 1, 1), ("3회 중 2회", 2, 3),
                         ("3회 연속", 3, 3), ("6회 중 4회", 4, 6)):
    fe, small, big, lag = score(0.05, need, span)
    print(f"{name:11s} {fe:4d}건   {small:4d}/4건  {big:3d}/4건  {lag:>6s}")

# 출력:
# 4단계 뜻: 임계값 0.03 은 사고를 다 잡지만 오탐이 153건, 하루 5.10회다. 0.08 은 하루 0.47회에 사고 8건을 다 잡고, 0.15 는 오탐이 없지만 작은 사고를 0/4건 잡는다.
# 윈도우 720개(30일), 사고 8건, 사고 윈도우 48개
# 임계값  오탐  하루알람   작은사고(-7%)  큰사고(-16%)  평균감지
#  0.03   153건   5.10회        4/4건         4/4건     0.1시간
#  0.05    80건   2.67회        4/4건         4/4건     0.2시간
#  0.08    14건   0.47회        4/4건         4/4건     0.6시간
#  0.10     1건   0.03회        3/4건         4/4건     0.4시간
#  0.15     0건   0.00회        0/4건         4/4건     0.0시간
#  0.20     0건   0.00회        0/4건         3/4건     2.7시간
# 5단계 뜻: 임계값 5% 에서 1회 즉시는 오탐 80건이고, 3회 중 2회는 26건으로 줄면서 작은 사고와 큰 사고를 4/4건씩 다 잡고 평균 1.1시간에 감지한다. 3회 연속은 오탐 0건이지만 작은 사고 하나를 놓친다.
#
# 임계값 5% 고정, 알람 규칙만 교체
# 규칙          오탐   작은사고  큰사고  평균감지
# 1회 즉시         80건      4/4건    4/4건   0.2시간
# 3회 중 2회       26건      4/4건    4/4건   1.1시간
# 3회 연속          0건      3/4건    4/4건   2.3시간
# 6회 중 4회        1건      3/4건    4/4건   2.9시간
```

4단계 표에서 **임계값 3% 는 하루 5.1번 울립니다.** 작은 사고와 큰 사고를 4건씩 모두 잡지만 한 달에 153번 울리는 알람을 계속 볼 사람은 없습니다. **임계값 15% 는 오탐이 0건이지만** 작은 사고의 낙폭 -7% 가 기준 15% 에 한참 못 미쳐 **작은 사고 4건을 모두 놓칩니다.** 이 데이터에서는 8% 가 균형이 가장 좋아 오탐이 14건(하루 0.47번)이면서 사고 8건을 모두 잡았습니다. 다만 8% 는 이 시뮬레이션에서 나온 값이라 숫자 자체보다 **이 표를 자기 데이터로 만들어 보는 습관**이 더 쓸모 있습니다.

5단계 표는 임계값을 5% 로 그대로 두고 규칙만 바꾼 결과입니다. **1회 즉시는 오탐이 80건이고 3회 연속은 0건입니다.** 대신 3회 연속은 위반이 세 번 연달아 나올 때까지 기다리므로 평균 감지가 0.2시간에서 2.3시간으로 늘고 작은 사고 하나를 놓칩니다(3/4건). 가장 많이 쓰이는 규칙은 그 중간인 「3회 중 2회」로, 최근 윈도우 3개 가운데 2개 이상이 위반이면 당직자를 부르는(호출하는) 규칙입니다. 이 규칙은 오탐을 80건에서 26건으로 3분의 1 로 줄이면서도 사고 8건을 모두 잡고 평균 1.1시간에 감지합니다.

**최소 표본 조건**으로는 3, 5절에서 계산한 조건을 그대로 씁니다. 표본이 모자란 윈도우는 지표를 0 으로 찍지 않고 「판정 불가」로 남깁니다. **억제 규칙**으로는 두 경우를 정합니다. 배포 직후 30분은 지표가 원래 흔들리므로 그동안의 알람을 억제합니다. 상위 지표가 이미 울렸으면 함께 울린 하위 지표의 알람은 묶어서 한 번에 보냅니다.

어제 값과 비교하는 「전일 대비」는 요일마다 지표가 달라지는 요일 효과에 걸리므로, 알람이 비교하는 기준선은 같은 요일 같은 시간의 최근 4주 값의 중위수로 잡습니다.

:::deep 지표 50개를 매일 볼 때 반드시 나는 오탐
지표 12개를 세그먼트 20개로 나누면 판정할 칸이 240칸이 되고 칸마다 하루 24개 윈도우를 판정하므로 하루 판정은 5,760번입니다. 윈도우 하나에서 오탐이 날 확률은 0.3% 로 잡아 봅니다. 0.3% 는 3시그마(값이 평균에서 표준편차의 3배 넘게 벗어나는 경우)에 대응하는 흔한 값입니다. 그러면 하루 기대 오탐은 5,760번의 0.3% 인 **17.3건**이라 사고가 없는 날에도 알람이 17번 울립니다. 이 오탐은 감시 품질이 나빠서가 아니라 판정 횟수를 곱해서 생기는 곱셈 문제입니다.

오탐을 줄이는 방법은 3가지입니다. 첫째로 **판정 수를 줄여** 당직자 호출까지 이어지는 지표를 3~5개로 제한합니다. 둘째로 **임계값을 올립니다.** 윈도우 하나의 오탐 확률이 0.03% 가 되도록 올리면 하루 5,760번 판정해도 오탐은 1.7건입니다. 셋째로 **연속 규칙을 추가합니다.** 「3회 연속」 규칙이면 윈도우 3개가 연달아 오탐이어야 알람이 울리므로 유효 오탐 확률(규칙을 거친 뒤 알람이 잘못 울릴 확률)이 세제곱으로 줄어 사실상 0 이 됩니다.

본페로니 보정(Bonferroni correction)은 판정 수만큼 허용 오탐 확률을 나눠 기준을 엄격하게 하는 방법입니다. 지표들은 서로 독립이 아니어서 같은 사고가 여러 지표를 함께 움직이므로 본페로니 보정은 그대로 쓰기 어렵습니다. 그래서 실무에서는 알람을 계층으로 나눕니다. 당직자를 부르는 호출은 비즈니스 영향이 확인된 소수 지표에만 겁니다. 사람을 부르지 않고 알림만 남기는 경고는 층마다 대표 지표에만 겁니다. 나머지 지표는 조회용으로만 둡니다.

## 7. 감시 대시보드에 올릴 숫자

**대시보드에는 모든 숫자가 아니라 당직자가 새벽에 3분 안에 읽을 수 있는 숫자를 올려야 합니다.**

그래서 화면은 세 장으로 나눠 첫 장만 보고도 더 볼지 말지 정할 수 있게 만듭니다. 첫 장은 **요약**입니다. 예측 평균 변화율(4절), 피처 PSI 최댓값(3절), 최근 확정 윈도우 COPC(4절), 세그먼트 가중 평균 절대 편차(5절), 노출량 변화율의 5가지만 크게 두고 세 가지 색으로 칠하는데, 빨강이 하나도 없으면 더 볼 필요가 없어야 합니다. 둘째 장은 **층별 상세**로, 2절의 네 층을 세로로 쌓고 층마다 최근 24시간 추이를 그려 어느 층에서 지표가 처음 꺾였는지 찾는 화면입니다. 셋째 장은 **세그먼트 히트맵**(칸마다 값을 색으로 칠한 표)으로, 가로축에 지면, 세로축에 시간을 두고 칸의 색으로 COPC 편차를 보여 줍니다. 5절에서 본 지면별 편차가 이 화면에서는 색으로 보입니다.

층마다 올릴 지표와 처음 시작할 임계값은 아래 표와 같습니다. 집계 단위는 지표를 한 번 계산할 때 묶는 범위(「지면 × 1시간」이면 지면마다 1시간치)이고 갱신은 값을 다시 계산하는 주기이며 등급은 위반했을 때 경고만 보내는지 당직자를 호출하는지입니다.

| 층 | 지표 | 집계 단위 | 갱신 | 시작 임계값 | 등급 |
|---|---|---|---|---|---|
| 입력 | 피처별 PSI | 지면 × 1시간 | 15분 | 0.10 / 0.25 | 경고, 호출 |
| 입력 | 결측, 기본값 대체율 | 피처 × 1시간 | 5분 | 평소의 3배 | 호출 |
| 출력 | 예측 평균, 분위수 | 모델 × 15분 | 5분 | 평균 ±8% | 호출 |
| 라벨 | COPC | 지면 × 1시간 | 15분 | ±8%, 3회 중 2회 | 호출 |
| 라벨 | 가중 평균 절대 편차 | 전체 | 1시간 | 10% | 경고 |
| 비즈니스 | 노출량, 소진율 | 캠페인 유형 × 1시간 | 15분 | -15% | 경고 |

표의 PSI 임계값 0.10 과 0.25 는 3절에서 본 흔히 쓰는 값이고 COPC 의 ±8% 는 6절에서 균형이 가장 좋았던 임계값이며 「3회 중 2회」는 6절에서 가장 많이 쓰인다고 한 규칙입니다.

대시보드에 무엇을 **올리지 않을지도** 정해야 합니다. AUC(Area Under the ROC Curve)는 클릭한 노출과 클릭하지 않은 노출을 짝지었을 때 클릭한 노출의 예측이 더 높은 비율입니다. AUC 를 매시간 계산하는 대시보드는 계산 비용이 크고 한 시간치 표본으로는 값이 크게 흔들려 읽을 수 없어서 대개 실패합니다. 마지막으로 주 1회는 팀이 함께 대시보드를 살펴보는 시간을 두기를 권합니다. 알람에 걸리지 않은 느린 열화(조금씩 진행되는 성능 저하)는 그 자리에서 눈에 띕니다.

## 한눈 정리

| 질문 | 답 | 근거가 되는 숫자 |
|---|---|---|
| 무엇을 먼저 보나 | 라벨이 필요 없는 입력, 예측 층 | 확정 라벨보다 7일 빠름(4절) |
| PSI를 언제 믿을 수 없나 | 표본이 작을 때, 관계만 변했을 때 | 표본 100건이면 사고 없이도 0.098 |
| 전체 지표만 보면 왜 위험한가 | 과대, 과소예측이 서로 지워지므로 | 전체 1.000, 지면별 0.42~1.50 |
| 세그먼트는 얼마나 쪼개나 | 예측 클릭 1,000건 이상만 | 385건 미만은 10% 임계값이 노이즈 |
| 오탐을 어떻게 줄이나 | 임계값과 연속 위반 규칙 | 3회 중 2회로 오탐 80건 → 26건 |

## 헷갈리기 쉬운 점

**"PSI 가 낮으면 모델이 건강하다."** 그렇지 않습니다. PSI 는 입력만 보므로 입력은 그대로인데 세상의 반응이 바뀌면 PSI 가 0 에 가깝게 나와도 모델은 틀립니다. 낮은 PSI 는 모델이 건강하기 위한 필요조건일 뿐 충분조건이 아닙니다.

**"전체 지표가 정상이면 세그먼트도 정상이다."** 그렇지 않습니다. 5절이 반례로, 전체 COPC 는 1.000 이었지만 예측 클릭의 48.4% 를 차지하는 지면 4곳의 COPC 가 1 에서 10% 넘게 틀어져 있었습니다.

**"라벨 기반 지표는 정확하니 이 지표만 보면 된다."** 정확하지만 늦습니다. 4절에서 확정 라벨은 40일차에 난 사고를 8일 뒤인 48일차에야 알렸습니다. 정확한 지표와 빠른 지표가 둘 다 필요합니다.

**"드리프트가 감지되면 바로 재학습하면 된다."** 재학습은 여러 조치 가운데 하나일 뿐입니다. 원인이 피처 파이프라인 사고일 때 재학습하면 오염된 데이터가 학습에 들어갑니다. 그래서 원인이 있는 층을 2절의 순서로 먼저 확인한 뒤 롤백(이전 모델로 되돌리는 조치), 재보정(예측 확률을 실제 비율에 다시 맞추는 조치), 재학습 가운데에서 고릅니다.
