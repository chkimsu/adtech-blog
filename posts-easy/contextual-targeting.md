모델 팀 17주째 월요일, 지훈 씨는 비로그인 C 의 광고 요청 한 줄을 열었습니다. 회원 번호 칸은 비었고 C 가 읽던 지면(광고가 실리는 페이지)의 주소만 있었습니다. 그 지면 「10km 완주, 처음이라면 먼저 볼 것」에 나간 광고는 카페였습니다.

서연 씨의 러닝화 광고는 번호 6001 이 붙은 회원에게만 나가도록 정해져 있어서 회원 번호가 없는 C 에게는 후보조차 되지 못했습니다. 선배는 사람 대신 글을 보라며 방법 3가지를 비교해 보자고 했습니다. 사람이 낱말을 적어 둔 사전, 지면의 낱말을 세어 숫자로 비교하는 방법, 글을 읽고 답을 써 주는 언어 모델입니다.

**번호가 없는 사람에게 지금 읽는 지면의 글만으로 광고를 고를 수 있을까요?**

이렇게 사람 대신 지면의 글을 보고 광고를 고르는 방식을 컨텍스추얼 타겟팅(contextual targeting)이라고 부릅니다. 선배가 말한 셋째 방법의 언어 모델은 줄여서 LLM 이라고 부릅니다. 번호가 없는 요청에서는 지면의 글을 읽은 결과가 광고비가 갈 곳을 정하는데, 글의 주제를 잘못 읽으면 러닝 지면에 여행 광고가 나가거나 러닝화 광고가 나갈 수 있던 자리를 놓칩니다.

> **한 줄 요약:** 회원 번호가 없는 비로그인 C 에게 광고를 고를 근거는 지금 읽는 지면의 글뿐이라, 가상 지면 50개에 지면의 주제 이름인 카테고리를 붙이는 방법 3가지를 비교합니다. 카테고리마다 낱말을 적어 둔 사전은 33개를 맞히지만 사전의 낱말이 없는 10개는 라벨 없이 비워 둡니다. 낱말마다 얼마나 드문지를 곱해 센 숫자 목록을 카테고리 평균과 비교하는 TF-IDF 는 빈칸 없이 34개를 맞히지만 여러 지면에 되풀이되는 문장 틀의 낱말에 끌려 틀리기도 합니다. 두 방법에는 제목을 따르는 기준이 없어서 제목과 첫 문단이 다른 이야기인 지면 10개에서 제목의 카테고리를 붙인 지면이 사전은 3개, TF-IDF 는 0개입니다. LLM 은 할 일을 적어 보낸 글에 「제목을 따른다」고 적어 두었는데도 그런 지면 10개 가운데 6개에서 첫 문단을 따랐고 50개 전체로는 43개를 맞힙니다. 답 앞에 풀이를 길게 쓰게 하는 thinking 을 켜고 그 10개를 다시 물으면 10개 모두 제목을 따르지만 thinking 을 끄고 물었을 때보다 모델이 써 낸 글 조각(토큰)은 풀이까지 합쳐 106배, 걸린 시간은 46배로 늘어납니다.

> **골라 읽는 법** — 절은 7개입니다. 절마다 있는 표나 코드나 카드만 보고 넘어가도 됩니다.
>
> - 회원 번호가 없는 비로그인 C 의 요청에 남는 것 → 1절
> - 가상 지면 50개와 카테고리 10개, 제목을 따르는 사람 라벨 → 2절
> - 키워드 사전으로 붙인 라벨과 비워 둔 지면 → 3절
> - 낱말을 세어 카테고리 평균과 비교하는 TF-IDF → 4절
> - 기록해 둔 LLM 의 답과 thinking 을 켰을 때의 토큰과 시간 → 5절
> - 세 방법의 비교와 비로그인 C 에게 나가는 광고 → 6절
> - 담장 안과 열린 RTB 에서 카테고리를 붙이는 때와 쓰는 법 → 7절

이 글의 지면 50개와 낱말 사전, 광고를 붙이는 카테고리 규칙은 모두 설명을 위해 만든 가상 데이터입니다. 지면은 `scripts/gen-context-pages.py` 의 생성기가 만들었습니다. 3절 코드의 1단계가 그 생성기와 글자까지 같은 코드라서 5절에서 LLM 에 보낸 지면 50개도 3절 코드가 만든 지면과 같습니다. 다만 LLM 의 답은 지어내지 않았습니다. 2026-11-04 에 이 블로그를 쓰는 맥에서 Ollama 로 qwen3.5:27b 를 띄워 답을 한꺼번에 기록했습니다. 글은 기록 파일 `data/llm-records/contextual-targeting.json` 에 남은 답을 그대로 옮겨 씁니다. Ollama 는 공개된 모델을 개인 컴퓨터에서 돌리는 도구입니다. 회원 A 와 비로그인 C, 광고 3개는 [후보풀 여덟 질문](post.html?id=candidate-pool-questions) 편에 나온 그대로입니다.

## 1. 번호 없이 지면 글만 남는 비로그인 C 의 요청

**로그인한 회원 A 의 광고 요청에는 회원 번호와 그 회원에게 붙은 번호 4개가 담기지만 비로그인 C 의 요청에는 지면 주소만 담깁니다. 그래서 C 에게 광고를 고를 근거는 그 주소에 있는 글뿐이라 C 에게 광고를 고르는 일은 그 글에 주제 이름을 붙이는 데서 시작합니다.**

C 가 로그인하지 않았으므로 지훈 씨가 연 요청에는 회원 번호 칸이 비어 있었습니다. 회원 번호가 빠지면 요청에서 무엇이 함께 빠지는지 로그인한 회원 A 의 요청과 나란히 놓고 보겠습니다.

광고 요청은 화면에 광고 자리가 하나 빌 때마다 광고 서버로 오는 요청 한 건으로, 누가 보고 있는지와 어디서 보고 있는지가 함께 담깁니다. 회원 A 는 로그인했으니 요청에 회원 번호가 담기고 광고 서버는 그 번호로 A 에게 붙은 세그먼트를 찾습니다. 세그먼트는 조건이 같은 회원 무리에 붙인 번호입니다. 회원 A 에게는 러닝 317, 여행 402, 카페 905, 유사타겟 6001 이 붙어 있는데, 유사타겟은 닮은 회원을 모은 세그먼트입니다.

비로그인 C 는 로그인하지 않아 요청에 회원 번호 대신 쿠키만 담깁니다. 쿠키는 브라우저에 남겨 두는 작은 식별 값인데, C 의 쿠키는 회원 번호와 이어져 있지 않아 광고 서버가 쿠키로는 세그먼트를 찾을 수 없고 C 에게는 붙은 번호가 하나도 없습니다. 13주째 [유저 프로파일 피처](post.html?id=user-profile-features) 편이 회원마다 30일 행동을 숫자 8개로 줄여 만든 벡터(숫자를 차례로 늘어놓은 목록)도 C 에게는 없어서 그 편은 「C 에게는 요청 안의 정보로 광고를 고른다」며 C 의 경우를 뒤로 미뤄 두었습니다. 이 글은 그 미뤄 둔 경우를 다룹니다.

번호가 없으면 세그먼트를 조건으로 건 광고는 C 에게 나갈 수 없습니다. [후보풀 여덟 질문](post.html?id=candidate-pool-questions) 편에서는 러닝화는 6001, 여행사는 402 가 붙은 사람에게만 나가고 카페만 조건이 없었기 때문에 C 가 꺼낸 후보(조건이 맞아 C 에게 내보낼 수 있는 광고)는 카페 하나였습니다. C 가 러닝 지면을 읽든 여행 지면을 읽든 꺼낸 후보는 늘 같은 카페 광고였습니다. 그래서 지훈 씨가 연 요청에서도 러닝 지면 「10km 완주, 처음이라면 먼저 볼 것」에 카페 광고가 나갔습니다.

C 의 요청에도 지면은 남아 있습니다. 지면은 광고가 실리는 웹 페이지나 앱 화면이고 요청에는 그 주소가 담기므로, 주소에 있는 글을 읽어 주제 이름을 붙여 두면 번호가 없어도 사람 대신 광고가 실릴 자리를 보고 광고를 고를 수 있습니다. 지면에 붙이는 주제 이름을 카테고리라고 부릅니다. 지면 하나에 붙은 카테고리 이름 하나는 그 지면의 라벨이라고 부릅니다. 컨텍스추얼 타겟팅의 컨텍스트(context)는 이렇게 광고 둘레에 있는 내용으로, 이 글에서는 지면의 글을 뜻합니다.

아래 표는 회원 A 와 비로그인 C 의 요청에 담긴 것을 줄마다 나란히 적었습니다. 두 사람이 다른 칸은 회원 번호, 세그먼트, 30일 행동 벡터처럼 사람에 대한 줄에 몰려 있습니다. C 의 요청에는 지면 주소와 글 한 줄만 남습니다.

| 요청에 담긴 것 | 회원 A | 비로그인 C |
|---|---|---|
| 회원 번호 | 있음, 로그인 | 없음, 쿠키만 |
| 세그먼트 | 317, 402, 905, 6001 | 없음 |
| 30일 행동 벡터 (13주째) | 8차원 | 없음 |
| 지면 주소와 글 | 있음 | 있음 |
| 꺼낸 후보 (후보풀 여덟 질문 편) | 러닝화, 여행사, 카페 | 카페 하나 |

C 의 요청에 남은 지면 한 줄로 광고를 고르려면 지면마다 카테고리를 붙이는 방법이 있어야 합니다. 2절에서는 방법 3가지를 같은 조건에서 비교하려고 지면 50개를 만듭니다.

## 2. 제목의 카테고리를 사람 라벨로 둔 지면 50개와 카테고리 10개

**세 방법을 비교하려고 카테고리 10개에 5개씩, 제목 한 줄과 첫 문단 두 문장으로 된 가상 지면 50개를 만들었습니다. 사람이 붙인 라벨은 제목의 카테고리입니다. 앞 10개는 첫 문단이 다른 카테고리의 이야기라 어느 쪽을 따를지 헷갈리는 지면입니다.**

세 방법이 붙인 라벨이 맞았는지 세려면 지면마다 정답으로 쓸 라벨이 있어야 하므로, 사람이 지면을 읽고 붙인 라벨을 정답으로 두고 사람 라벨이라고 부릅니다. 사람 라벨은 그 지면의 제목이 말하는 카테고리입니다. 도입에서 C 가 읽던 지면은 p014 로, 제목은 「10km 완주, 처음이라면 먼저 볼 것」이고 첫 문단은 스포츠 워치와 농구 결승, 인터벌 훈련 이야기라 사람 라벨은 sports 입니다. 코드와 LLM 의 답에서 같은 이름을 쓰려고 라벨은 14주째처럼 영어 소문자로 정해 둔 10개 가운데 하나로 둡니다.

카테고리 10개는 광고 업계의 표준 목록에서 가져왔습니다. IAB Tech Lab 은 광고 업계의 표준을 만드는 단체입니다. 이 단체가 지면의 주제를 적을 때 쓰라고 만든 표준 목록이 IAB Content Taxonomy 입니다. Content Taxonomy 3.1 버전은 맨 위 단계에 범주 37개를 두는데, 이 글은 그 가운데 10개를 골라 이름을 짧게 줄였고 health 하나만 Healthy Living 과 Medical Health 두 범주를 합쳐 만들었습니다.

지면은 생성기(지면을 만드는 코드)가 문장 틀에 명사를 끼워 넣어 만듭니다. 틀은 「…, 처음이라면 먼저 볼 것」이나 「… 한 달 기록」처럼 명사 하나가 들어갈 자리가 있는 제목 틀 5개와, 첫 문단의 첫 문장 틀 5개, 둘째 문장 틀 5개입니다. 카테고리마다 명사를 12개씩 적어 두었습니다. 지면 하나에는 제목에 명사 1개와 첫 문단에 명사 3개가 들어가며 한 카테고리의 지면 5개는 제목 명사가 서로 다릅니다. 명사 12개 가운데 4개에만 그 카테고리의 사전 낱말이 들어 있는데, 사전은 3절에서 쓸 낱말 목록으로 카테고리마다 사람이 적어 둔 낱말 4개입니다. 아래 표의 「명사 12개 가운데 넷」 열에서는 앞의 2개가 사전 낱말이 든 명사로, sports 의 「러닝화」에는 사전 낱말 「러닝」이 들어 있고 「10km 완주」에는 들어 있지 않습니다.

앞 10개는 카테고리마다 1개씩 일부러 헷갈리게 만든 지면입니다. 제목의 명사만 그 카테고리에서 가져오고 첫 문단의 명사 3개는 표의 마지막 열에 적은 다른 카테고리에서 가져왔습니다. p008 은 제목이 travel 의 명사로 만든 「여권 사진, 처음이라면 먼저 볼 것」인데 첫 문단은 sports 의 명사인 수영 대회와 10km 완주, 인터벌 훈련 이야기입니다. 이런 지면은 제목이 그 지면의 주제라고 보고 사람 라벨을 제목의 카테고리인 travel 로 붙였습니다.

제목을 따른다는 기준은 글에서 저절로 나오지 않고 사람이 정했습니다. 3절의 사전과 4절의 방법은 낱말이 제목에 있었는지 첫 문단에 있었는지를 보지 않으므로 이 기준을 쓸 수 없습니다. 5절의 LLM 에는 할 일을 적어 보내는 글인 프롬프트(prompt)에 기준을 적어 알려 줍니다. LLM 은 프롬프트를 토큰(token)이라는 글 조각으로 나눠 읽고 답도 토큰을 하나씩 이어 붙여 씁니다. 세 방법이 어떻게 다른지는 헷갈리는 10개에서 가장 잘 보입니다.

아래 표는 라벨마다 뜻, 대응하는 IAB 3.1 상위 범주와 그 ID, 명사 12개 가운데 4개, 그 카테고리의 헷갈리는 지면이 첫 문단의 명사를 가져온 카테고리를 적었습니다.

## 3. 낱말이 보이면 붙이고 없으면 비워 두는 키워드 사전

**카테고리마다 사람이 낱말 4개를 적어 둔 사전을 위에서부터 살펴보고 처음 맞는 카테고리를 붙이면, 지면 50개 가운데 33개를 맞히고 7개를 틀리고 10개는 맞는 낱말이 없어 비워 둡니다. 비워 둔 10개에는 C 가 읽던 러닝 지면 p014 도 들어 있습니다.**

선배가 말한 첫째 방법은 카테고리마다 사람이 낱말 목록을 적어 두고 지면에서 그 낱말을 찾는 키워드 사전입니다. sports 에는 「러닝」, 「마라톤」, 「축구」, 「야구」 4개가 적혀 있고 카테고리 10개를 합하면 사전의 낱말은 40개입니다. 지면의 제목이나 첫 문단에 어떤 카테고리의 낱말이 하나라도 들어 있으면 그 카테고리를 붙이는데, 사전을 2절 표의 차례대로 automotive 부터 travel 까지 살펴보다가 처음 맞는 카테고리에서 멈추므로 두 카테고리의 낱말이 함께 들어 있으면 위쪽 카테고리가 붙습니다. 40개 가운데 하나도 들어 있지 않으면 라벨을 비워 둡니다.

아래 코드는 2절의 지면 50개를 만들고 사전으로 라벨을 붙여 사람 라벨과 몇 개가 같은지 보려고 돌립니다. 1단계는 2절에서 설명한 생성기로 지면을 만듭니다. 2단계에서 사전으로 라벨을 붙여 맞힌 지면과 틀린 지면, 라벨이 빈 지면을 센 다음 3단계에서 헷갈리는 지면에 어느 쪽 카테고리를 붙였는지와 틀린 지면마다 까닭을 셉니다.

```python
# 하는 일: 가상 지면 50개를 만들고, 카테고리마다 낱말 4개를 적은 사전으로 라벨을 붙여 사람 라벨과 비교한다.
import random
from collections import Counter

# 1단계: 지면 50개를 만든다
# 제목 틀 5개, 첫 문단의 두 문장 틀 5개씩, 카테고리마다 명사 12개로 만든다. scripts/gen-context-pages.py 의 생성기와 같은 코드다.
LABELS = ['automotive', 'business', 'education', 'family', 'food',
          'health', 'hobbies', 'sports', 'style', 'travel']
# 카테고리마다 명사 12개. 앞의 4개에는 그 카테고리의 사전 낱말이 들어 있고 뒤의 8개에는 없다.
NOUNS = {
    'automotive': ['자동차 보험', '차량 점검', '초보 운전', '주차 보조', '엔진 오일', '타이어 교체',
                   '블랙박스', '셀프 세차', '연비', '전기차 충전', '하이브리드 세단', '경차 유지비'],
    'business': ['경제 전망', '주식 시장', '1인 창업', '기준 금리', '연말정산', '환율',
                 '스타트업 투자', '부동산 시장', '분기 실적', '퇴직 연금', '물가', '법인 설립'],
    'education': ['코딩 교육', '수능 준비', '영어 학원', '온라인 강의', '토익 점수', '자격증 시험',
                  '대학 입시', '논술 첨삭', '내신 성적', '유학 준비', '교과서', '학점 관리'],
    'family': ['육아휴직', '아이 간식', '가족 모임', '부모 교육', '이유식', '어린이집',
               '돌잔치', '유모차', '키즈카페', '결혼 준비', '기저귀', '신혼집'],
    'food': ['집밥 요리', '동네 맛집', '김치찌개 레시피', '디저트 카페', '스페셜티 커피', '밀키트',
             '제철 과일', '수제 버거', '떡볶이', '브런치', '비빔밥', '크루아상'],
    'health': ['건강 검진', '병원 예약', '다이어트 식단', '허리 통증', '혈압 관리', '감기 예방',
               '비타민 D', '독감 접종', '면역력', '불면증', '스트레칭', '안구 건조'],
    'hobbies': ['주말 취미', '필름 사진', '가죽 공방', '악기 연습', '뜨개질', '프라모델',
                '바다 낚시', '화분 키우기', '캘리그라피', '보드게임', '레고', '드론 촬영'],
    'sports': ['러닝화', '하프 마라톤', '축구 중계', '프로 야구', '10km 완주', '골프 레슨',
               '테니스 라켓', '수영 대회', '인터벌 훈련', '스포츠 워치', '농구 결승', '클라이밍'],
    'style': ['가을 패션', '화장품 성분', '출근 코디', '스킨케어 루틴', '트렌치코트', '선크림',
              '립스틱', '청바지 핏', '헤어 스타일', '향수', '네일 아트', '가죽 가방'],
    'travel': ['제주 여행', '항공권 특가', '호텔 조식', '숙소 예약', '오사카 3박', '환전',
               '렌터카', '공항 라운지', '면세점', '여권 사진', '게스트하우스', '유심 칩'],
}
TITLES = ['{a}, 처음이라면 먼저 볼 것', '{a} 한 달 기록', '요즘 많이 묻는 {a} 이야기',

FIRSTS = ['지난주부터 {b}, {c} 정보를 모아 읽고 있다.', '{b}, {c} 이야기가 나오면 질문이 꼭 따라온다.',
          '주말마다 {b}, {c} 후기를 찾아본다.', '처음에는 {b} 하나만 보다가 {c} 쪽으로 범위를 넓혔다.',
          '회사 동료가 {b}, {c} 얘기를 꺼내서 비교해 봤다.']
SECONDS = ['오늘은 {d} 이야기까지 함께 정리한다.', '{d} 쪽도 짧게 적어 둔다.',
           '마지막에는 {d} 경험을 덧붙인다.', '읽은 사람이 많이 물은 {d} 내용도 넣었다.',
           '{d} 후기는 아래에 따로 모았다.']
# 헷갈리는 지면 10개. 카테고리마다 하나는 첫 문단의 명사 셋을 여기 적은 카테고리에서 가져온다.
MIXED = {'automotive': 'travel', 'business': 'food', 'education': 'business', 'family': 'travel',
         'food': 'health', 'health': 'sports', 'hobbies': 'style', 'sports': 'health',
         'style': 'sports', 'travel': 'sports'}


def make_pages():
    """지면 50개. 사람 라벨은 제목의 카테고리다. 앞 10개는 카테고리마다 하나씩 둔 헷갈리는 지면이다."""
    rng = random.Random(7 + 7)                 # 7 + 1 부터 7 + 6 은 트랙의 다른 글이 쓴다
    mixed, clear = [], []
    for label in LABELS:
        for k, a in enumerate(rng.sample(NOUNS[label], 5)):    # 지면 5개의 제목 명사는 서로 다르다
            other = MIXED[label] if k == 0 else None
            pool = NOUNS[other] if other else [n for n in NOUNS[label] if n != a]
            b, c, d = rng.sample(pool, 3)
            page = {'label': label, 'mixed': other,
                    'title': rng.choice(TITLES).format(a=a),
                    'text': rng.choice(FIRSTS).format(b=b, c=c) + ' ' + rng.choice(SECONDS).format(d=d)}
            (mixed if other else clear).append(page)
    rng.shuffle(mixed)
    rng.shuffle(clear)
    pages = mixed + clear
    for i, page in enumerate(pages, 1):
        page['id'] = 'p%03d' % i
    return pages


pages = make_pages()
mixed = [p for p in pages if p['mixed']]
print(f'지면 {len(pages)}개: 카테고리 {len(LABELS)}개 × 5개, 그중 헷갈리는 지면 {len(mixed)}개({mixed[0]["id"]}~{mixed[-1]["id"]})')
for p in (pages[36], pages[7]):                # p037, p008
    note = f' (첫 문단의 명사는 {p["mixed"]})' if p['mixed'] else ''
    print(f'{p["id"]} 사람 라벨 {p["label"]}{note}: {p["title"]} / {p["text"]}')

# 2단계: 키워드 사전으로 라벨을 붙인다
# 카테고리마다 사람이 적어 둔 낱말 4개다. LABELS 의 차례로 순회해 처음 맞는 카테고리를 붙이고, 하나도 안 맞으면 None 이다.
KEYWORDS = {
    'automotive': ['자동차', '차량', '운전', '주차'], 'business': ['경제', '주식', '창업', '금리'],
    'education': ['교육', '수능', '학원', '강의'], 'family': ['육아', '아이', '가족', '부모'],
    'food': ['요리', '맛집', '레시피', '카페'], 'health': ['건강', '병원', '다이어트', '통증'],
    'hobbies': ['취미', '사진', '공방', '악기'], 'sports': ['러닝', '마라톤', '축구', '야구'],
    'style': ['패션', '화장품', '코디', '스킨케어'], 'travel': ['여행', '항공권', '호텔', '숙소'],
}


def keyword_label(page):
    text = page['title'] + ' ' + page['text']
    for label in LABELS:                       # 사전의 차례는 LABELS 의 차례다
        if any(word in text for word in KEYWORDS[label]):
            return label
    return None


keyword = {p['id']: keyword_label(p) for p in pages}
right = sum(keyword[p['id']] == p['label'] for p in pages)
none = sum(keyword[p['id']] is None for p in pages)
print(f'키워드 50개: 맞힘 {right}개, 틀림 {len(pages) - right - none}개, 라벨 없음 {none}개')
for i in ('p014', 'p018', 'p008'):             # 라벨 없음, 사전의 차례, 낱말 안의 키워드
    p = pages[int(i[1:]) - 1]
    print(f'{p["id"]} 사람 {p["label"]}, 키워드 {keyword[p["id"]]}: {p["title"]} / {p["text"]}')

# 3단계: 헷갈리는 지면과 틀린 까닭을 센다
# 헷갈리는 지면은 제목의 카테고리(사람 라벨)와 첫 문단의 카테고리 가운데 어느 쪽을 붙였는지 따로 센다.
PLACES = ['제목의 카테고리', '첫 문단의 카테고리', '그 밖', '라벨 없음']


def place(p, guess):
    if guess[p['id']] == p['label']:
        return PLACES[0]
    if guess[p['id']] is None:
        return PLACES[3]
    return PLACES[1] if guess[p['id']] == p['mixed'] else PLACES[2]


def split(arts, guess):
    n = Counter(place(p, guess) for p in arts)
    return ', '.join(f'{k} {n[k]}개' for k in PLACES if n[k])


def why_wrong(p):
    text = p['title'] + ' ' + p['text']
    if any(word in text for word in KEYWORDS[p['label']]):
        return '제 낱말도 있는데 사전의 위쪽이 먼저 맞음'
    if keyword[p['id']] == p['mixed']:
        return '첫 문단에 다른 카테고리의 낱말만 있음'
    return '제 명사 안에 다른 카테고리의 낱말이 들어 있음'


clear = [p for p in pages if not p['mixed']]
c_right = sum(keyword[p['id']] == p['label'] for p in clear)
c_none = sum(keyword[p['id']] is None for p in clear)
print(f'헷갈리지 않는 지면 {len(clear)}개: 맞힘 {c_right}개, 틀림 {len(clear) - c_right - c_none}개, 라벨 없음 {c_none}개')
print(f'헷갈리는 지면 {len(mixed)}개: {split(mixed, keyword)}')
wrong = [p for p in pages if keyword[p['id']] not in (None, p['label'])]
print(f'틀림 {len(wrong)}개의 까닭:', ', '.join(f'{why} {n}개' for why, n in Counter(why_wrong(p) for p in wrong).most_common()))

# 1단계 뜻: 50개 중 앞 10개가 헷갈리는 지면이다. p008 은 제목이 여행인데 첫 문단의 명사 셋은 sports 에서 왔다.
# 지면 50개: 카테고리 10개 × 5개, 그중 헷갈리는 지면 10개(p001~p010)
# p037 사람 라벨 sports: 러닝화, 처음이라면 먼저 볼 것 / 10km 완주, 수영 대회 이야기가 나오면 질문이 꼭 따라온다. 스포츠 워치 쪽도 짧게 적어 둔다.
# p008 사람 라벨 travel (첫 문단의 명사는 sports): 여권 사진, 처음이라면 먼저 볼 것 / 수영 대회, 10km 완주 이야기가 나오면 질문이 꼭 따라온다. 오늘은 인터벌 훈련 이야기까지 함께 정리한다.
# 2단계 뜻: 사전이 붙인 40개 중 33개가 맞는다. 세 지면은 라벨이 빈 러닝 지면, 사전의 차례에 걸린 지면, 명사 안의 「사진」에 걸린 지면이다.
# 키워드 50개: 맞힘 33개, 틀림 7개, 라벨 없음 10개
# p014 사람 sports, 키워드 None: 10km 완주, 처음이라면 먼저 볼 것 / 지난주부터 스포츠 워치, 농구 결승 정보를 모아 읽고 있다. 읽은 사람이 많이 물은 인터벌 훈련 내용도 넣었다.
# p018 사람 family, 키워드 education: 부모 교육, 처음이라면 먼저 볼 것 / 지난주부터 결혼 준비, 돌잔치 정보를 모아 읽고 있다. 어린이집 쪽도 짧게 적어 둔다.
# p008 사람 travel, 키워드 hobbies: 여권 사진, 처음이라면 먼저 볼 것 / 수영 대회, 10km 완주 이야기가 나오면 질문이 꼭 따라온다. 오늘은 인터벌 훈련 이야기까지 함께 정리한다.
# 3단계 뜻: 헷갈리지 않는 40개는 틀린 것보다 비운 것이 많고, 헷갈리는 10개는 제목의 카테고리를 붙인 것이 3개뿐이다.
# 헷갈리지 않는 지면 40개: 맞힘 30개, 틀림 2개, 라벨 없음 8개
# 헷갈리는 지면 10개: 제목의 카테고리 3개, 첫 문단의 카테고리 4개, 그 밖 1개, 라벨 없음 2개
# 틀림 7개의 까닭: 첫 문단에 다른 카테고리의 낱말만 있음 4개, 제 낱말도 있는데 사전의 위쪽이 먼저 맞음 2개, 제 명사 안에 다른 카테고리의 낱말이 들어 있음 1개
```

2단계가 찍은 「맞힘 33개, 틀림 7개, 라벨 없음 10개」를 더하면 33 + 7 + 10 = 50개입니다. 사전은 라벨을 붙인 40개 가운데 33개에 사람 라벨과 같은 라벨을 붙였습니다. 라벨이 빈 10개는 사전의 낱말 40개가 하나도 들어 있지 않은 지면입니다. C 가 읽던 p014 는 「10km 완주」, 「스포츠 워치」, 「농구 결승」, 「인터벌 훈련」으로 운동 이야기를 하지만 sports 의 낱말 「러닝」, 「마라톤」, 「축구」, 「야구」가 하나도 없고 다른 카테고리의 낱말도 없어서 사전을 travel 까지 살펴도 맞는 카테고리가 없습니다. 그래서 이 지면에 러닝화 광고를 붙이려면 사람이 사전에 「완주」나 「인터벌」을 더 적어야 합니다.

3단계의 마지막 줄은 틀린 7개를 까닭 3가지로 나눕니다. 4개는 첫 문단에 다른 카테고리의 낱말만 있던 헷갈리는 지면이라 첫 문단의 카테고리가 붙었습니다. 2개는 「부모 교육」이 든 family 지면으로, 「부모」는 family 의 낱말이고 「교육」은 education 의 낱말이라 두 카테고리가 다 맞는데 사전에서 education 이 family 보다 위라 education 이 먼저 맞았습니다. 그중 p018 을 사전의 차례대로 살펴보면 automotive 와 business 의 낱말은 없고 셋째인 education 의 「교육」이 「부모 교육」 안에서 맞아 거기서 멈춥니다. 나머지 1개는 여권 사진 지면 p008 로, travel 의 명사 「여권 사진」 안에 든 「사진」이 hobbies 의 낱말이라 hobbies 가 붙었습니다. 「부모 교육」과 「여권 사진」은 이런 경우를 보이려고 일부러 명사 목록에 넣은 명사입니다.

3단계의 앞 두 줄은 지면을 헷갈리지 않는 지면과 헷갈리는 지면으로 나눠 셉니다. 헷갈리지 않는 40개는 30개를 맞히고 2개를 틀리고 8개를 비워(30 + 2 + 8 = 40) 틀린 지면보다 비운 지면이 많습니다. 헷갈리는 10개는 제목의 카테고리 3개, 첫 문단의 카테고리 4개, 그 밖 1개, 라벨 없음 2개인데, 제목의 카테고리를 붙인 3개는 모두 제목의 명사에 그 카테고리의 사전 낱말이 들어 있던 지면입니다. 사전은 낱말이 제목에 있었는지 첫 문단에 있었는지를 보지 않으므로 제목에 사전의 낱말이 없으면 첫 문단의 낱말을 따르거나 라벨을 비웁니다.

빈칸을 줄이려면 사람이 사전에 낱말을 계속 추가해야 하는데, 「인터벌」을 추가해도 「클라이밍」 같은 운동 명사가 또 남습니다. 4절의 방법은 사람이 낱말을 고르는 대신 지면에 나온 낱말을 모두 셉니다. 낱말마다 지면 안에 나온 횟수에 그 낱말이 얼마나 드문지를 곱한 값을 TF-IDF 라고 부릅니다. 4절은 지면을 낱말마다 TF-IDF 를 적은 숫자 목록인 벡터로 바꾸고 카테고리마다 지면 벡터를 평균한 중심과 방향이 얼마나 같은지를 코사인으로 비교합니다.

## 4. 빈칸은 메우지만 틀의 낱말에 끌리는 TF-IDF 벡터와 중심의 코사인

**지면의 낱말을 모두 세어 만든 TF-IDF 벡터를 카테고리 중심과 비교하면 지면 50개에 빈칸 없이 라벨을 붙여 34개를 맞힙니다. 사전이 비워 둔 10개 가운데 7개를 맞히지만 그 대신 여러 지면에 되풀이되는 틀의 낱말에 끌려 틀리기도 합니다. 헷갈리는 10개에서는 제목을 따른 지면이 하나도 없습니다.**

3절의 사전은 사람이 적어 둔 낱말 40개만 보므로 C 가 읽던 p014 처럼 그 낱말이 하나도 없는 지면 10개에 라벨을 붙이지 못했습니다. 선배가 말한 둘째 방법은 사람이 낱말을 고르지 않고 지면에 나온 낱말을 모두 세어 숫자로 바꾸므로, 어느 카테고리의 지면과든 낱말이 하나라도 겹치면 라벨이 붙습니다.

TF-IDF 는 지면 하나 안에서 낱말 하나에 매기는 점수이고 TF 와 IDF 를 곱해 구합니다. TF(term frequency)는 그 낱말이 그 지면 안에 나온 횟수입니다. IDF(inverse document frequency)는 log(50 ÷ 그 낱말이 나온 지면 수)라서 낱말이 여러 지면에 두루 나올수록 작아집니다. 로그는 자연로그이고 50 은 지면 수입니다. C 가 읽던 p014 로 계산해 보면 「인터벌」은 50개 가운데 지면 4개에만 나와 IDF 가 log(50 ÷ 4) = 2.53 이고 p014 안에는 한 번 나오므로 TF-IDF 도 1 × 2.53 = 2.53 입니다. 반면 문장 틀에 들어 있는 낱말 「읽고」는 지면 9개에 나와 IDF 가 log(50 ÷ 9) = 1.71 로 「인터벌」보다 작습니다. 이렇게 여러 지면에 두루 나오는 낱말일수록 점수가 낮아집니다.

1단계가 찍은 대로 지면 50개에 나온 낱말은 모두 234종류라서 지면 하나는 낱말마다 자리를 하나씩 둔 234자리 숫자 목록이 됩니다. 그 지면에 들어 있는 낱말의 자리에는 TF-IDF 를, 들어 있지 않은 낱말의 자리에는 0 을 적으므로 p014 는 자기 낱말 23개의 자리에만 0 이 아닌 값이 들어갑니다. 글을 이렇게 숫자 벡터로 바꾼 것을 임베딩(embedding)이라고 부릅니다. [Elasticsearch 하이브리드 검색](post.html?id=elasticsearch-hybrid-retrieval) 편은 학습한 모델로 문장을 384차원 벡터(숫자 384개짜리 벡터)로 바꿨는데, 거기의 384 는 모델이 정한 자리 수이고 여기의 234 는 낱말 수입니다. TF-IDF 벡터는 그 384차원 문장 임베딩의 단순한 형태로 자리 하나가 낱말 하나라서 두 지면은 같은 낱말을 함께 써야만 가까워집니다.

카테고리의 중심 벡터는 그 카테고리에 든 지면 벡터를 자리마다 평균한 벡터입니다. 지면 하나를 분류할 때는 그 지면을 빼고 남은 4개로 중심을 만듭니다. 분류할 지면이 중심에 들어 있으면 중심에도 그 지면의 낱말이 들어 있어 자기 카테고리와 더 닮아 보이므로, 중심에 들어 있지 않은 새 지면을 분류할 때보다 잘 맞는 것처럼 보입니다. 코사인(cosine)은 두 벡터의 방향이 얼마나 같은지를 나타내는 값입니다. 방향이 같으면 1, 겹치는 낱말이 하나도 없으면 0 이라 1 에 가까울수록 두 벡터가 닮았습니다. 그래서 지면마다 카테고리 10개의 중심과 코사인을 구해 가장 큰 카테고리를 붙입니다. 모든 카테고리의 코사인이 0 이면 라벨을 비웁니다.

아래 코드는 지면 50개를 TF-IDF 벡터로 바꾸고 카테고리 중심과의 코사인으로 라벨을 붙여, 사전이 비워 둔 지면과 사전이 맞힌 지면에서 결과가 어떻게 달라지는지 보려고 돌립니다. 1단계가 TF-IDF 벡터를, 2단계가 카테고리 중심을, 3단계가 코사인과 라벨을 계산합니다.

# 하는 일: 지면 50개를 TF-IDF 벡터로 바꾸고, 카테고리 중심 벡터와 코사인이 가장 큰 카테고리를 붙인다.
import math

# 띄어쓰기로 자르고 쉼표와 마침표를 뗀다. 낱말마다 지면 안의 횟수(TF)에 log(50 ÷ 그 낱말이 든 지면 수)(IDF)를 곱한다.
def words(page):
    return [w.strip(',.') for w in (page['title'] + ' ' + page['text']).split()]


df = Counter(w for p in pages for w in set(words(p)))
idf = {w: math.log(len(pages) / n) for w, n in df.items()}


def tfidf(page):
    return {w: n * idf[w] for w, n in Counter(words(page)).items()}


vec = {p['id']: tfidf(p) for p in pages}
ex = pages[13]                                 # p014, 키워드 사전이 비워 둔 러닝 지면
print(f'낱말 종류 {len(df)}개. {ex["id"]} 의 낱말 {len(vec[ex["id"]])}개')

# 그 카테고리 지면의 벡터를 평균한다. 지면 하나를 분류할 때는 그 지면을 빼고 남은 4개로 만든다.
def centroid(label, skip):
    members = [vec[p['id']] for p in pages if p['label'] == label and p['id'] != skip]
    out = {}
    for v in members:
        for w, x in v.items():
            out[w] = out.get(w, 0.0) + x / len(members)
    return out


# 3단계: 코사인이 가장 큰 카테고리를 붙인다
# 코사인은 두 벡터의 방향이 같으면 1, 겹치는 낱말이 없으면 0 이다. 모든 카테고리가 0 이면 라벨을 비운다.
def cosine(u, v):
    dot = math.fsum(x * v.get(w, 0.0) for w, x in u.items())
    norm = math.sqrt(math.fsum(x * x for x in u.values())) * math.sqrt(math.fsum(x * x for x in v.values()))
    return dot / norm if norm else 0.0

    best = max(LABELS, key=cos[p['id']].get)
    emb[p['id']] = best if cos[p['id']][best] > 0 else None
right = sum(emb[p['id']] == p['label'] for p in pages)
print(f'TF-IDF 50개: 맞힘 {right}개, 틀림 {sum(emb[p["id"]] not in (None, p["label"]) for p in pages)}개, '
      f'라벨 없음 {sum(emb[p["id"]] is None for p in pages)}개')


def pull(p, label):                            # 그 중심 쪽 코사인을 가장 많이 올린 낱말. 넷째와 값이 같은 낱말은 함께 둔다
    c = centroid(label, p['id'])
    part = {w: round(x * c.get(w, 0.0), 9) for w, x in vec[p['id']].items()}
    cut = sorted(part.values(), reverse=True)[3]
    return [w for w in sorted(part, key=lambda w: -part[w]) if part[w] >= cut]


top = sorted(LABELS, key=lambda label: -cos[ex['id']][label])[:3]
print(f'{ex["id"]} 의 코사인:', ', '.join(f'{label} {cos[ex["id"]][label]:.3f} '
                                        f'({math.degrees(math.acos(cos[ex["id"]][label])):.0f}도)' for label in top))

print(f'헷갈리지 않는 지면 {len(clear)}개: 맞힘 {c_right}개 / 헷갈리는 지면 {len(mixed)}개: {split(mixed, emb)}')

hit = [p for p in pages if keyword[p['id']] == p['label']]
print(f'키워드가 비워 둔 {len(empty)}개 가운데 TF-IDF 가 맞힌 지면 {sum(emb[p["id"]] == p["label"] for p in empty)}개, '
      f'키워드가 맞힌 {len(hit)}개 가운데 TF-IDF 가 틀린 지면 {sum(emb[p["id"]] != p["label"] for p in hit)}개')
bad = pages[30]                                # p031, TF-IDF 가 틀린 자동차 지면
got = emb[bad['id']]
print(f'{bad["id"]} 사람 {bad["label"]}, TF-IDF {got} {cos[bad["id"]][got]:.3f} '
      f'(사람 라벨 쪽 {cos[bad["id"]][bad["label"]]:.3f}): {bad["title"]} / {bad["text"]}')

# p031 사람 automotive, TF-IDF health 0.203 (사람 라벨 쪽 0.185): 주차 보조 한 달 기록 / 지난주부터 초보 운전, 전기차 충전 정보를 모아 읽고 있다. 오늘은 타이어 교체 이야기까지 함께 정리한다.

34개는 제목 틀과 첫 문장 틀, 둘째 문장 틀을 5개씩만 돌려 쓰는 짧은 가상 지면에서 중심을 지면 4개로 만들어 얻은 값입니다. 실제 지면에도 메뉴나 관련 기사처럼 사이트마다 되풀이되는 글이 붙어 있어서 실제 지면에 이 방법을 쓸 때는 본문만 뽑아 쓰는 일이 먼저입니다.

헷갈리는 10개는 하나도 제목의 카테고리를 붙이지 못하고 7개에 첫 문단의 카테고리, 3개에 그 밖의 카테고리를 붙였습니다. 글을 낱말로 자른 뒤 낱말의 순서와 자리는 버리고 횟수만 남긴 표현을 단어 가방(bag of words)이라고 부르는데, TF-IDF 벡터도 낱말마다 횟수에 IDF 를 곱한 값만 남기므로 단어 가방입니다. 그래서 TF-IDF 벡터에는 낱말이 제목에 있었는지 첫 문단에 있었는지가 남지 않아 명사가 1개인 제목보다 명사가 3개 든 첫 문단 쪽으로 기웁니다. 5절의 LLM 은 「제목을 따른다」는 기준을 글로 읽을 수 있습니다. LLM 에는 답을 쓰기 전에 풀이를 토큰으로 길게 써 보게 하는 thinking 모드도 있습니다.

## 5. 한 프롬프트로 50개를 물은 LLM 분류와 thinking 을 켰을 때 달라지는 것

**같은 프롬프트로 지면 50개를 하나씩 물으면 LLM 은 43개를 맞힙니다. 헷갈리지 않는 40개에서는 하나만 틀리지만 헷갈리는 10개 가운데 6개는 프롬프트에 「제목을 따른다」는 줄이 있는데도 첫 문단을 따릅니다. 그 10개를 thinking 을 켜고 다시 물으면 10개 모두 제목을 따르는 대신, 모델이 써 낸 토큰은 풀이까지 합쳐 thinking 을 껐을 때의 106배가 되고 걸린 시간은 46배가 됩니다.**

3절과 4절의 두 방법은 낱말이 어디에 있었는지를 보지 않아 사람이 정한 기준을 쓸 수 없었으므로 헷갈리는 10개에서 제목의 카테고리를 붙인 지면이 3개와 0개에 그쳤습니다. 선배가 말한 셋째 방법인 LLM 은 할 일을 글로 적어 보내면 그 글을 읽고 답하므로 기준도 글로 알려 줄 수 있습니다.

LLM 에 보내는 요청 한 건은 두 부분으로 되어 있습니다. 시스템 메시지(system message)는 모든 요청에 똑같이 함께 가는 할 일 설명입니다. 사용자 메시지(user message)는 요청마다 바뀌는 부분으로, 지면 하나의 제목과 첫 문단을 담습니다. 그래서 절 제목에서 한 프롬프트로 50개를 물었다는 말은 같은 시스템 메시지를 붙여 지면 50개를 하나씩 따로 물었다는 뜻입니다. 시스템 메시지에는 LLM 이 지면 분류기라는 것, 제목을 따른다는 기준, 카테고리 10개마다 한 줄 풀이, 답은 JSON 한 줄로만 쓰라는 것을 적었습니다. JSON 은 `{"label": "sports"}` 처럼 이름과 값을 중괄호 안에 적는 형식이라 코드가 답에서 라벨을 바로 읽어 냅니다.

시스템 메시지의 둘째 줄 「제목과 첫 문단이 서로 다른 주제를 말하면 제목의 주제를 고른다」가 2절에서 사람이 정한 기준을 옮긴 줄입니다. 14주째 [관심사 분류](post.html?id=interest-classification) 편에서는 이 기준을 프롬프트에 적지 않아 헷갈리는 글 20건 가운데 16건에서 LLM 이 첫 문장을 따랐습니다. 그래서 이번에는 시스템 메시지에 기준을 적어 보냈습니다. LLM 은 다음 토큰을 고를 때 후보 토큰마다 점수를 매기는데, temperature 는 점수가 낮은 토큰에도 얼마나 기회를 줄지 정하는 값이라 0 이면 늘 점수가 가장 높은 토큰을 고릅니다. seed 는 토큰을 뽑을 때 쓰는 난수의 시작값입니다. 이 글은 지면 50개를 thinking 을 끄고 temperature 0 과 seed 7 로 한 번씩 물었습니다.

헷갈리는 10개는 thinking 을 켜고 한 번 더 물었습니다. Ollama 의 응답에는 thinking 으로 쓴 토큰 수가 따로 없어서 풀이까지 들어 있는 출력 토큰 수와 풀이의 글자 수를 대신 기록했습니다. 풀이 글 자체는 기록에 남기지 않았습니다. 같은 seed 와 temperature 0 으로 앞 3개 지면의 답 6개를 다시 기록해 보면 라벨은 모두 같지만 thinking 을 켠 답은 풀이의 길이가 달라지기도 해서 thinking 을 켠 답의 토큰 수와 걸린 시간은 한 번 기록한 값으로 읽습니다. 또 이 기록의 첫 요청은 thinking 을 끈 다른 요청보다 오래 걸렸고 그 시간이 끈 쪽의 걸린 시간에 들어 있어서 아래 코드의 3단계는 그 요청을 뺀 비율도 따로 셉니다.

## 6. 세 방법의 비교와 광고 3개가 붙는 지면

**지면 50개에서 맞힌 수는 사전 33개, TF-IDF 34개, LLM 43개이고 세 방법이 틀리는 지면이 서로 다릅니다. 광고 3개를 카테고리 규칙으로 붙이면 비로그인 C 가 본 지면 6개 가운데 세 방법이 같은 광고를 고른 지면은 하나뿐입니다.**

세 방법의 라벨이 C 에게 나가는 광고를 어떻게 바꾸는지 보려고 카테고리마다 광고를 붙이는 규칙을 가상으로 정했습니다. 서연 씨의 러닝화는 sports 지면에, 여행사는 travel 지면에, 카페는 food 지면에 붙고 그 밖의 카테고리나 라벨이 빈 지면에는 3개 모두 붙지 않습니다. 후보풀 편에서는 조건이 없어 누구에게나 나가던 카페도 여기서는 food 지면에만 붙는다고 둡니다. 아래 표는 50개 가운데 C 가 오늘 본 지면으로 설명을 위해 고른 6개에, 5절 코드의 4단계가 세 방법의 라벨로 붙인 광고를 적었습니다. 코드는 사전을 「키워드」라는 이름으로 찍습니다.

| 지면 (C 가 본 6개) | 사람 라벨과 광고 | 사전의 광고 | TF-IDF 의 광고 | LLM 의 광고 |
|---|---|---|---|---|
| p037 러닝화, 처음이라면 먼저 볼 것 | sports, 러닝화 | 러닝화 | 러닝화 | 러닝화 |
| p014 10km 완주, 처음이라면 먼저 볼 것 | sports, 러닝화 | 없음 | 러닝화 | 러닝화 |

표에서는 2가지를 보면 됩니다. 첫째, 사전의 손해는 틀린 광고보다 광고를 붙이지 못한 빈자리에서 나옵니다. 사전이 붙인 광고 2개(p037 의 러닝화, p020 의 카페)는 모두 사람 라벨의 광고와 같지만 p014 와 p047, p008 에는 사람 라벨로는 러닝화나 여행사가 붙을 수 있었는데도 아무 광고도 붙이지 못했습니다. 둘째, TF-IDF 와 thinking 을 끈 LLM 은 첫 문단 쪽으로 기울어서 첫 문단이 운동 이야기인 p008 과 p010 에는 사람 라벨과 달라도 러닝화를 붙입니다.

4단계의 50개 전체 줄을 보면 러닝화가 붙는 지면 수도 방법마다 다릅니다. 사전은 러닝화를 2개에만 붙이고 둘 다 sports 지면이라 틀리게 붙인 곳은 없지만 sports 지면 5개 가운데 3개를 놓칩니다. TF-IDF 는 8개, LLM 은 7개에 러닝화를 붙이고 그 가운데 sports 지면은 둘 다 4개라, TF-IDF 는 8 − 4 = 4개, LLM 은 7 − 4 = 3개를 sports 가 아닌 지면에 붙였습니다. LLM 의 3개는 모두 첫 문단이 운동 이야기인 헷갈리는 지면입니다. TF-IDF 에는 같은 3개와 함께 첫 문단이 패션 이야기인 취미 지면 p007 이 들어 있습니다.

그렇다고 어느 방법이 서연 씨에게 나은지가 정확도(사람 라벨과 같은 라벨을 붙인 지면의 비율)로 정해지지는 않습니다. p008 은 사람 라벨이 travel 이라 러닝화를 붙이면 틀린 것으로 세지만 그 지면을 읽는 사람은 첫 문단에서 수영 대회와 10km 완주 이야기를 읽고 있습니다. 러닝화가 그 자리에서 더 팔리는지는 지면마다 클릭과 구매를 따로 측정해야 압니다.

LLM 의 43개는 카테고리 10개짜리 가상 지면에서 나온 값입니다. Kamen(2025)은 IAB 2.2 의 여러 단계로 내려가는 분류에서 사람이 라벨을 붙인 8,660개를 LLM 10개에 같은 프롬프트로 물었습니다. LLM 10개의 평균 정확도는 34% 였습니다. 카테고리가 많아지고 단계가 깊어지면 같은 LLM 이라도 이 글과는 다른 문제를 풉니다.

비용도 다릅니다. 사전과 TF-IDF 는 사전에서 낱말을 찾고 덧셈을 몇 번 하는 계산이라 지면 하나에 시간이 거의 들지 않지만 LLM 은 헷갈리는 10개에서 지면 하나에 평균 1.06초가 걸렸고 thinking 을 켜면 평균 48.82초가 걸렸습니다. 끈 쪽 평균에는 첫 요청의 2.2초가 들어 있습니다. 다만 지면의 카테고리는 처음 볼 때 한 번 붙여 두고 다시 쓰므로 광고 요청이 올 때마다 LLM 을 부를 일은 없습니다.

## 7. 회원 번호와 지면을 같이 쓰는 담장 안, 지면만으로 고르는 일이 많은 열린 RTB

**남의 지면에 나갈 광고를 실시간 경매로 사는 열린 RTB 에서는 사람을 알아볼 쿠키가 없는 요청이 늘어나 지면의 카테고리만으로 광고를 고르는 일이 많아집니다. 한 회사가 서비스와 광고 서버를 모두 가진 담장 안에서는 로그인한 회원에게 회원 번호와 지면의 카테고리를 함께 쓰고 비로그인 요청에만 카테고리 하나로 고릅니다.**

1~6절의 계산은 어느 무대에서나 같지만 지면이 누구 것인지와 카테고리를 언제 누가 붙이는지는 무대에 따라 다릅니다. 담장 안은 한 회사가 서비스와 광고 서버를 모두 가진 곳입니다. 열린 RTB 는 여러 회사가 실시간 경매로 남의 지면에 나갈 광고를 사고파는 곳입니다.

### 회원 번호와 지면을 같이 쓰는 담장 안 [무대: 닫힌 생태계]

담장 안에서는 지면도 그 회사 서비스에 올라온 글이므로 글이 올라올 때 카테고리를 한 번 붙여 글 정보와 함께 저장해 둡니다. 14주째에 글마다 관심사 라벨을 붙여 저장하던 단계와 같습니다. 그러면 회원 A 가 sports 지면을 읽을 때는 A 의 세그먼트 317 과 지면의 sports 를 같이 쓸 수 있지만 비로그인 C 가 같은 지면을 읽을 때는 sports 하나만 남습니다.

LLM 도 글이 올라올 때 한 번만 부릅니다. 5절에서 thinking 을 켠 답은 지면 하나에 수십 초가 걸렸으므로 thinking 은 따로 고른 지면에만 켭니다. 카테고리를 다시 붙이면 그 지면에 나가던 광고가 바뀌므로, 다시 붙이기 전에 카테고리가 바뀌는 지면이 몇 개인지 먼저 셉니다.

### 지면만 남는 요청이 많은 열린 RTB [무대: 열린 RTB]

열린 RTB 에서 광고를 사는 회사의 시스템을 DSP 라고 부릅니다. 광고 자리가 날 때마다 DSP 에 오는 입찰 요청에는 지면 주소 `site.page` 와 매체(지면을 가진 회사)가 적은 카테고리 `site.cat`, `site.pagecat` 이 담기는데, 카테고리는 IAB Content Taxonomy 의 ID 로 적고 그 ID 가 어느 버전의 것인지는 `cattax` 에 적습니다. 브라우저가 다른 회사의 쿠키를 막았거나 사용자가 쿠키를 지운 요청에는 사람을 알아볼 값이 없으므로, 그런 요청에서는 지면만으로 광고를 고르게 됩니다.

그런데 매체가 적은 카테고리는 비어 있거나 사이트 전체에 하나만 붙어 있기도 합니다. 그래서 DSP 는 처음 본 주소의 지면을 따로 읽어 카테고리를 붙이고 다음 요청에서 바로 꺼내 쓰도록 캐시(한 번 구한 값을 저장해 두고 다시 쓰는 곳)에 저장해 둡니다. 입찰 응답은 100ms 안팎에 돌려줘야 하므로 입찰 요청을 받은 그 자리에서는 LLM 을 부르지 않습니다. Amazon Ads 의 과학자들은 2025년 기고에서 「키워드가 지면에 있으면 광고를 보인다」는 방식을 넘어 LLM 으로 지면의 내용을 읽는다고 적었습니다.

아래 표는 두 무대에서 달라지는 것을 줄마다 적었습니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 지면 | 우리 서비스의 글 | 남의 지면, 입찰 요청에 주소로 온다 |
| 카테고리를 붙이는 때 | 글이 올라올 때 한 번 | 처음 본 주소를 미리 읽고 캐시 |
| 카테고리 이름 | 우리가 정한 목록 | IAB Content Taxonomy 의 ID, 버전은 cattax |
| 사람에 대한 값 | 로그인하면 회원 번호와 세그먼트 | 쿠키, 없으면 지면뿐 |
| LLM 을 부르는 때 | 글이 올라올 때 | 처음 본 주소를 읽을 때 |

이 글은 지면에 카테고리 이름을 붙였습니다. 다음 편인 18주째의 자연어 오디언스는 「러닝화 살 사람」 같은 한 문장을 LLM 이 조건과 명단으로 바꾸는 자리를 봅니다.

## 한눈 정리

| 자리 | 무엇을 하나 | 숫자 |
|---|---|---|
| 지면 50개 | 카테고리 10개에 5개씩, 사람 라벨은 제목의 카테고리 | 헷갈리는 지면 10개 (p001~p010) |
| 키워드 사전 | 낱말 40개를 위에서부터 살펴보고 처음 맞는 카테고리 | 50개 중 33개 맞힘, 10개 비움 |
| TF-IDF | 낱말 234개 자리의 벡터와 카테고리 중심의 코사인 | 50개 중 34개 맞힘, 헷갈리는 10개는 0개 |
| LLM, thinking 끔 | 시스템 메시지 하나로 50개를 하나씩 | 50개 중 43개, 헷갈리는 10개 중 4개 |
| LLM, thinking 켬 | 헷갈리는 10개를 한 번 더 | 10개 모두 맞힘, 출력 토큰 106배, 시간 46배 |
| 광고 셋 | sports 러닝화, travel 여행사, food 카페 | 러닝화가 붙은 지면은 사전 2개, TF-IDF 8개, LLM 7개 |

## 헷갈리기 쉬운 점

- **컨텍스추얼 타겟팅은 사람 대신 광고가 실릴 자리를 보고 고릅니다.** 카테고리는 지면에 붙으므로 같은 지면을 보는 사람은 누구든 같은 카테고리를 받습니다. C 가 러닝 지면을 읽으면 러닝화가 후보가 되지만 C 가 러닝을 좋아하는 사람인지는 여전히 모릅니다. 회원 A 의 317 은 A 의 30일 행동 기록에서 나온 번호이고 sports 는 지금 읽는 지면 하나의 글에서 나온 이름입니다.
- **분류 정확도와 광고 성과는 서로 다른 값입니다.** 정확도는 붙인 라벨이 사람 라벨과 같은지를 세고 광고 성과는 그 자리에서 클릭과 구매가 나는지를 세므로, p008 처럼 첫 문단이 운동 이야기인 travel 지면에 러닝화를 붙이면 정확도로는 틀린 답이지만 성과는 따로 측정하기 전까지 알 수 없습니다.
- **thinking 의 비용은 켠 요청마다 붙는데, 이 기록에서 정확도가 달라진 지면은 헷갈리는 지면입니다.** thinking 은 헷갈리는 10개 가운데 6개의 라벨을 제목의 카테고리로 고쳤습니다. 그 대신 그 10개에서 출력 토큰은 106배, 걸린 시간은 46배가 되었습니다. 헷갈리지 않는 40개에서는 thinking 을 켜 보지 않았는데, 그 40개는 끈 답이 이미 39개를 맞혀 켜서 더 맞힐 수 있는 지면이 많아야 1개이고 켰다가 맞던 답이 바뀔 수도 있습니다. 그래서 thinking 을 켤 지면을 고르는 기준부터 정하고 그 지면에서 따로 측정합니다.

## 더 깊이 보기

:::deep TF-IDF 와 코사인의 식
지면 $d$ 안에서 낱말 $w$ 가 나온 횟수를 $\mathrm{tf}(w, d)$ 라고 둡니다. 낱말 $w$ 가 나온 지면 수는 $\mathrm{df}(w)$ 입니다. 지면 수는 $N = 50$ 입니다.

$$x_{d,w} = \mathrm{tf}(w, d) \cdot \ln\frac{N}{\mathrm{df}(w)}$$

로그는 자연로그입니다. 「인터벌」은 $\mathrm{df} = 4$ 라서 $\ln(50/4) = 2.53$ 입니다. 「읽고」는 $\mathrm{df} = 9$ 라서 $\ln(50/9) = 1.71$ 입니다. 50개 모두에 나온 낱말이 있다면 $\ln 1 = 0$ 이라 벡터에서 빠집니다.

카테고리 $k$ 의 지면 모임을 $S_k$ 라고 하면, 지면 $d$ 를 분류할 때 쓰는 중심은 $d$ 를 뺀 평균입니다.

$$c_k^{(-d)} = \frac{1}{|S_k \setminus \{d\}|} \sum_{d' \in S_k \setminus \{d\}} x_{d'}$$

$$\cos(x_d, c) = \frac{\sum_w x_{d,w}\, c_w}{\lVert x_d \rVert \, \lVert c \rVert}, \qquad \hat{k} = \arg\max_k \cos\big(x_d, c_k^{(-d)}\big)$$

TF-IDF 의 값은 모두 0 이상이라 코사인은 0 에서 1 사이이고, 각도는 0 도에서 90 도 사이입니다. p014 의 sports 코사인 0.373 은 $\arccos 0.373$ 이라 68도입니다. 「러닝화」와 「운동화」처럼 뜻이 가까워도 낱말이 다르면 자리가 달라서, 코사인에 아무것도 더하지 않습니다. 학습한 문장 임베딩은 이런 두 낱말을 가까운 방향에 둡니다.

scikit-learn 의 `TfidfVectorizer` 는 기본값이 조금 다릅니다. IDF 로 $\ln\frac{1 + N}{1 + \mathrm{df}} + 1$ 을 써서 모든 지면에 나온 낱말도 0 이 되지 않습니다. 그리고 벡터마다 길이를 1 로 맞춥니다. 그래서 같은 지면이라도 이 글과 값이 다르게 나옵니다.
:::

:::deep IAB Content Taxonomy 와 이 글의 카테고리 10개
IAB Tech Lab 은 Content Taxonomy 3.1 을 TSV 파일, 곧 탭으로 칸을 나눈 표로 공개합니다. 그 파일을 세어 보면 카테고리가 704개입니다. 카테고리는 4단계까지 내려갑니다. 맨 위 단계가 37개, 둘째 단계가 323개, 셋째 단계가 275개, 넷째 단계가 69개입니다. 2절 표의 ID 는 이 파일의 번호입니다.

IAB 3.1 에서 러닝은 Sports 아래에 없습니다. Healthy Living 아래 Fitness and Exercise 의 Running and Jogging 입니다. 캠핑도 Hobbies & Interests 가 아니라 Travel 아래 Travel Type 의 Camping 입니다. 그래서 러닝화 광고주가 IAB ID 로 지면을 고를 때 Sports 하나만 고르면 러닝 지면을 놓칠 수 있습니다. 이 글의 가상 규칙이 sports 하나에 러닝화를 붙인 것은 설명을 위해 줄인 것입니다.

입찰 요청의 `cattax` 값은 AdCOM 1.0 의 목록을 따릅니다. AdCOM 은 OpenRTB 가 같이 쓰는 IAB Tech Lab 의 공통 목록 명세입니다. 그 목록에서 7 은 Content Taxonomy 3.0, 9 는 3.1 입니다. 값을 적지 않으면 Content Category Taxonomy 1.0 으로 봅니다. 1.0 은 지금은 쓰지 말라고 적혀 있고 ID 의 꼴도 달라서, 같은 Sports 라도 버전마다 ID 가 다릅니다.
