BentoML 카드 네 장

모델 파일 하나가 요청에 답하는 서비스가 되기까지, 사람이 정하는 자리 하나가 카드 한 장입니다. 점이 흐르는 방향이 데이터가 가는 방향입니다. 숫자는 설명용 가상 값입니다.

파랑 = 놓여 있는 것 (모델 파일, 저장소, 이미지) 벽돌색 = 지금 오는 요청과 값을 치르는 자리 먹색 = 서비스와 서버 회색 = 만드는 작업 (굳히기, 묶기) 점선 = 적어 둔 것 (설정, 태그) 점 = 지금 가고 있는 것

SEVEN BY HAND

직접 짜면 만들어야 하는 것 일곱

쉽게 말하면 모델에 숫자를 넣어 답을 받는 계산은 코드 몇 줄입니다. 그것을 요청으로 받고, 죽지 않게 지키고, 바꿔 달 수 있게 만드는 일이 나머지 전부입니다.

일곱을 더하면 1,370줄 이고 설정과 시험까지 1,800줄입니다. 그중 모델마다 다른 것은 후보를 한 텐서로 만드는 한 덩어리뿐입니다.

ONE SERVICE FILE

서비스 파일 한 장에 적는 것

쉽게 말하면 클래스 하나에 표시 두 개를 붙입니다. 클래스에 붙은 것이 「이것이 서비스다」이고 함수에 붙은 것이 「이 함수가 주소 하나다」입니다. 나머지는 도구가 같이 붙입니다.

내가 쓰는 것은 40줄 입니다. 앞 카드의 일곱 중 여섯을 도구가 갖고 있고, 남는 하나는 요청을 숫자 묶음으로 바꾸는 코드입니다.

BUILD AND CONTAINERIZE

굳히면 이미지 한 장이 된다

쉽게 말하면 서비스 파일과 모델과 라이브러리 목록을 한 묶음으로 굳히고, 그것을 도커 이미지로 바꿉니다. 굳히고 나면 어느 서버에서 열어도 같은 것이 나옵니다.

직접 짠 쪽은 1.1GB 에 모델이 이미지 밖이고, 도구 쪽은 1.4GB 에 모델이 이미지 안입니다. 모델만 바꿔도 이미지를 다시 만들어야 합니다.

WHEN BATCHING PAYS

모아 보내기가 값을 하는 자리

쉽게 말하면 요청 여럿을 한 묶음으로 모아 모델에 한 번만 넣습니다. 얻는 것은 건당 계산이 줄어드는 몫이고, 치르는 것은 모이기를 기다리는 시간입니다.

요청 하나에 후보가 800건이면 묶어도 건당 3% 밖에 안 줍니다. 요청 하나가 작고 자주 올 때만 78% 가 줍니다.

현업에서는 이렇게 씁니다

  • 새 모델을 띄우자는 말이 나오면 세 가지를 먼저 묻습니다. 예산이 밀리초인가 초인가, 요청이 초당 몇 건인가, 이런 모델이 앞으로 몇 개 더 생기나.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 BentoML 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 직접 짜면 어떤 모양인지는 추론 서버 편입니다.
