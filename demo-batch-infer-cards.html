배치 추론 카드 세 장

요청이 오기 전에 미리 계산해 두는 자리 하나가 카드 한 장입니다. 점이 흐르는 방향이 데이터가 가는 방향이고, 점이 몰려서 지나가면 하루 한 번 배치입니다. 숫자는 설명용 가상 값입니다.

파랑 = 놓여 있는 데이터 (표, 저장소) 벽돌색 = 지금 오는 것 (요청) 먹색 = 서버 회색 = 만드는 작업 (배치) 점 = 지금 가고 있는 데이터

PRECOMPUTE

새벽에 미리 만든다

쉽게 말하면 회원마다 숫자 묶음 하나를 만드는 계산을 요청이 올 때마다 하지 않고, 새벽에 한 번 전원 몫을 만들어 저장소에 놓아 둡니다. 요청 때는 꺼내 쓰기만 합니다.

회원 1,400만 명의 벡터가 64차원에 3.58GB 이고 워커 8개로 25분입니다. 같은 사람이 하루 16.3번 요청하니 요청마다 계산하면 38배 더 듭니다.

CACHE HIT

활성 12% 가 요청 80%

쉽게 말하면 회원 전원의 벡터를 메모리에 올릴지, 자주 오는 사람 것만 올릴지를 고르는 일입니다. 못 찾은 요청은 그 자리에서 계산하므로 느려집니다.

전원을 올리면 3,584MB 에 요청당 0.20ms 이고, 활성만 올리면 430MB 에 0.56ms 입니다. 아예 안 올리면 매번 계산이라 2.00ms 입니다.

COST PER MONTH

CPU 와 GPU 의 한 달 값

쉽게 말하면 초당 요청 수와 서버 한 대가 감당하는 양으로 필요한 대수가 나오고, 대수에 시간당 값을 곱하면 한 달 비용이 나옵니다. GPU 는 대수가 적은 대신 한 대 값이 비쌉니다.

CPU 12대가 한 달 4,147,200원, GPU 는 2대에 예비 1대라 8,208,000원 입니다. 이 규모에서는 CPU 가 절반 값이고, GPU 는 예비 한 대가 비용을 정합니다.

현업에서는 이렇게 씁니다

  • 「미리 계산해 두면 안 되나」를 들으면 세 가지를 봅니다. 그 값이 얼마나 자주 바뀌나, 미리 만들면 몇 GB 인가, 못 찾았을 때 그 자리에서 계산할 수 있나.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 배치 추론과 실시간 추론 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 대수와 비용을 직접 움직여 보려면 서빙 비용 계산기입니다.
