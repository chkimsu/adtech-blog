민지가 운동화를 샀다. ₩89,000. 그런데 지난 2주를 되짚어 보면, 민지는 인스타에서 그 광고를 세 번 봤고, 유튜브에서 한 번 스쳤고, 네이버 검색광고를 한 번 눌렀고, 어제는 인스타 광고를 눌러 상세 페이지까지 봤다. 그리고 오늘 회사 PC에서 브랜드 이름을 검색해 들어와 결제했다.

**이 ₩89,000은 누구 공일까?**

그걸 정하는 일이 **어트리뷰션(Attribution, 기여도 분석)**이다. 답에 따라 다음 달 광고비를 어디에 더 쓸지가 갈리니, 광고판에서 가장 '정치적인' 숫자다.

> 한 줄 요약: 어트리뷰션은 **하나의 전환을 거쳐 온 광고들에게 '공'을 나눠 주는 규칙**이다. 규칙이 바뀌면 성적표가 통째로 바뀐다. 그리고 그 성적표는 "광고가 정말 매출을 늘렸나"와는 **다른 질문**의 답이다.

---

## 1. 여정은 이렇게 생겼다

**광고는 본 즉시 사지 않는다. 며칠에 걸쳐 여러 접점을 거친 뒤 산다.** 그래서 전환 하나에 후보가 여럿 붙는다.

말로만 하면 감이 안 오니, 민지의 2주를 로그 표로 펼쳐 놓자. 실제 측정 도구가 보는 것도 이런 모양의 줄들이다.

| # | 날짜 | 채널 | 유형 | 기기 |
|---|---|---|---|---|
| 1 | 3/04 | 인스타그램 | 노출 | 폰 |
| 2 | 3/05 | 인스타그램 | 노출 | 폰 |
| 3 | 3/07 | 유튜브 | 노출 | 폰 |
| 4 | 3/09 | 네이버 검색광고 | **클릭** | 폰 |
| 5 | 3/11 | 인스타그램 | **클릭** | 폰 |
| 6 | 3/12 | 브랜드 검색광고 | **클릭** | PC |
| 7 | 3/12 | 직접 방문 | — | PC |
| 8 | 3/12 | **구매 ₩89,000** | 전환 | PC |

노출 3번, 클릭 3번, 전환 1번. 여기서 두 가지를 미리 봐 두자.

첫째, **클릭과 노출은 다르게 취급된다.** 대부분의 규칙은 클릭에만 공을 준다. 보기만 한 광고에도 공을 줄지(뷰스루)는 규칙이 또 갈리는 별개 문제라, 아래 계산에서는 클릭 3건만 대상으로 삼는다.

둘째, **6번에서 기기가 폰에서 PC로 바뀐다.** 이 한 줄이 뒤에서 무대를 가르는 결정적 차이가 된다(5·6절). 지금은 "같은 사람인데 다른 기기에서 샀다"는 사실만 기억하자.

## 2. 같은 여정, 다섯 개의 성적표

**'정답'은 없고 '규칙'만 있다. 그리고 규칙을 바꾸면 같은 여정에서 정반대의 성적표가 나온다.**

민지의 클릭 3개에 ₩89,000을 나눠 보자. 흔히 쓰이는 다섯 규칙을 같은 데이터에 그대로 적용한 결과다.

| 규칙 | 네이버 검색 (3/09) | 인스타 (3/11) | 브랜드 검색 (3/12) |
|---|---|---|---|
| **라스트클릭** | 0% · ₩0 | 0% · ₩0 | **100% · ₩89,000** |
| **퍼스트클릭** | **100% · ₩89,000** | 0% · ₩0 | 0% · ₩0 |
| **선형(균등)** | 33.3% · ₩29,667 | 33.3% · ₩29,667 | 33.3% · ₩29,667 |
| **시간감쇠**(반감기 7일) | 28.1% · ₩24,966 | 34.2% · ₩30,433 | 37.8% · ₩33,601 |
| **U자형**(40/20/40) | 40% · ₩35,600 | 20% · ₩17,800 | 40% · ₩35,600 |

표의 첫 줄과 둘째 줄을 나란히 보자. **네이버 검색광고 담당자의 성과는 규칙이 라스트클릭이면 ₩0, 퍼스트클릭이면 ₩89,000이다.** 같은 사람, 같은 여정, 같은 매출인데 성적표가 정반대다. 그래서 "우리 채널이 매출 얼마를 만들었다"는 말은, 어떤 규칙으로 센 건지 밝히지 않으면 아무 뜻이 없다.

각 규칙의 속뜻은 이렇다.

- **라스트클릭**은 "마지막에 문을 열어준 사람"에게 전부 준다. 가장 흔하고 가장 단순하다. 문제는 브랜드 검색광고처럼 **이미 살 마음을 먹은 사람이 마지막에 누르는 자리**가 늘 이긴다는 점이다. 인지를 만든 앞단은 계속 과소평가되고, 예산은 뒤로만 쏠린다.
- **퍼스트클릭**은 그 반대로 "처음 알게 해준 사람"에게 전부 준다. 신규 고객을 늘리는 캠페인을 볼 때 쓸모가 있지만, 마지막에 결정을 도운 접점이 통째로 지워진다.
- **선형**은 거쳐 온 모두에게 똑같이 나눈다. 공평해 보이지만, 스쳐 간 접점과 결정적이었던 접점을 같은 값으로 센다.
- **시간감쇠**는 전환에 가까운 접점을 더 인정한다. 반감기 7일이라면 7일 전 접점은 절반의 공만 받는다. 민지의 경우 가중치가 `2^(-3/7)=0.743`, `2^(-1/7)=0.906`, `2^0=1.0`이 되고, 이 셋을 합(2.649)으로 나눠 비율을 얻는다.
- **U자형**은 첫 접점과 마지막 접점에 각 40%, 중간에 남은 20%를 나눈다. "알게 해준 공"과 "닫아준 공"을 둘 다 인정하자는 타협이다.

라스트클릭 외의 나머지를 묶어 **멀티터치(MTA, Multi-Touch Attribution)**라고 부른다. 여러 접점에 나눠 준다는 뜻일 뿐, 어떻게 나눌지는 위처럼 갈린다.

## 3. 파이썬으로 직접 나눠 보기

**규칙은 결국 '가중치를 어떻게 만들까'의 문제다.** 코드로 보면 다섯 규칙의 차이가 함수 다섯 개 차이뿐이라는 게 드러난다.

아래 코드는 표준 라이브러리만 쓴다. 그대로 복사해 돌리면 2절의 표가 그대로 출력된다.

```python
# 민지의 2주 여정에 어트리뷰션 규칙 5개를 각각 적용해 매출을 나눠 본다.
# 표준 라이브러리만 쓰니 그대로 복붙해 돌려볼 수 있다.
from datetime import date

REVENUE = 89_000        # 전환 1건의 매출(원)
CONV_DAY = date(2026, 3, 12)   # 구매가 일어난 날
HALF_LIFE_DAYS = 7      # 시간감쇠 반감기: 7일 전 접점은 절반의 공만 받는다

# 여정 로그. 크레딧은 '클릭'에만 준다(노출 기여는 규칙이 또 갈리므로 여기선 제외).
touchpoints = [
    {"day": date(2026, 3,  4), "channel": "인스타그램",     "kind": "impression"},
    {"day": date(2026, 3,  5), "channel": "인스타그램",     "kind": "impression"},
    {"day": date(2026, 3,  7), "channel": "유튜브",         "kind": "impression"},
    {"day": date(2026, 3,  9), "channel": "네이버 검색광고", "kind": "click"},
    {"day": date(2026, 3, 11), "channel": "인스타그램",     "kind": "click"},
    {"day": date(2026, 3, 12), "channel": "브랜드 검색광고", "kind": "click"},
]
clicks = [t for t in touchpoints if t["kind"] == "click"]   # 크레딧 대상 3건

def last_click(n):                      # 마지막 클릭이 전부 가져간다
    return [0.0] * (n - 1) + [1.0]

def first_click(n):                     # 첫 클릭이 전부 가져간다
    return [1.0] + [0.0] * (n - 1)

def linear(n):                          # 거쳐 온 모두에게 똑같이
    return [1.0 / n] * n

def time_decay(days_before):            # 전환에 가까울수록 더 — 반감기 7일
    w = [0.5 ** (d / HALF_LIFE_DAYS) for d in days_before]
    total = sum(w)
    return [x / total for x in w]       # 합이 1이 되도록 정규화

def u_shaped(n):                        # 첫·마지막을 40%씩, 중간은 남은 20%를 나눠
    if n == 1:
        return [1.0]
    if n == 2:
        return [0.5, 0.5]
    mid = [0.2 / (n - 2)] * (n - 2)
    return [0.4] + mid + [0.4]

n = len(clicks)
days_before = [(CONV_DAY - t["day"]).days for t in clicks]   # [3, 1, 0]

rules = {
    "라스트클릭":   last_click(n),
    "퍼스트클릭":   first_click(n),
    "선형(균등)":   linear(n),
    "시간감쇠(7일)": time_decay(days_before),
    "U자형(40/20/40)": u_shaped(n),
}

for name, weights in rules.items():
    cells = " | ".join(f"{w*100:5.1f}% {round(w*REVENUE):>8,}원" for w in weights)
    # 어떤 규칙이든 배분의 합은 매출과 같아야 한다 — 규칙의 기본 성질
    assert abs(sum(w * REVENUE for w in weights) - REVENUE) < 1e-6
    print(f"{name:<18}{cells}")

# 출력:
# 라스트클릭               0.0%        0원 |   0.0%        0원 | 100.0%   89,000원
# 퍼스트클릭             100.0%   89,000원 |   0.0%        0원 |   0.0%        0원
# 선형(균등)             33.3%   29,667원 |  33.3%   29,667원 |  33.3%   29,667원
# 시간감쇠(7일)           28.1%   24,966원 |  34.2%   30,433원 |  37.8%   33,601원
# U자형(40/20/40)      40.0%   35,600원 |  20.0%   17,800원 |  40.0%   35,600원
```

코드에서 눈여겨볼 곳은 두 군데다.

하나는 `time_decay`의 마지막 줄, **합으로 나눠 정규화하는 부분**이다. 가중치를 만드는 규칙은 얼마든 자유롭게 정할 수 있지만, 마지막에 합이 1이 되도록 맞춰야 매출이 정확히 다 배분된다. 그래서 아래 `assert` 한 줄로 검산한다 — 배분 규칙이 지켜야 하는 최소 성질이다.

다른 하나는 `clicks` 필터다. 노출 3건을 여기서 걸러내는 순간 이미 하나의 정책 결정을 한 셈이다. 뷰스루를 인정하는 회사는 이 줄을 바꾸고, 그러면 2절의 표 전체가 다시 움직인다. **어트리뷰션 숫자를 볼 때 "무엇을 접점으로 셌나"부터 물어야 하는 이유다.**

## 4. 윈도우 — 며칠까지 인정할까

**규칙보다 먼저 정해지는 게 있다. "며칠 안의 접점까지 셀까"다. 이 값만 만져도 채널 성적이 통째로 바뀐다.**

광고를 본/누른 뒤 며칠 안의 구매까지 그 광고 공으로 칠지 정하는 게 **어트리뷰션 윈도우**다. 흔한 기본값은 **클릭 후 7일, 노출 후 1일**이다.

민지의 여정에 윈도우만 바꿔 보자. 클릭 윈도우를 7일에서 2일로 줄이면, 3/09 클릭(전환 3일 전)이 창밖으로 밀려난다.

| 클릭 윈도우 | 인정되는 클릭 | 선형 배분 결과 |
|---|---|---|
| 7일 (흔한 기본) | 3개 | ₩29,667 × 3 |
| **2일** | 2개 (인스타·브랜드검색) | **₩44,500 × 2** |
| 1일 | 1개 (브랜드검색) | ₩89,000 |

**네이버 검색광고의 성과가 ₩29,667에서 ₩0으로 사라졌다.** 규칙은 손도 대지 않았고, 세는 기간만 이틀로 줄였을 뿐이다.

노출 윈도우도 같은 일을 한다. 노출 후 1일을 걸면 3/04~3/07 노출 3건은 전부 창밖이다. 만약 이 브랜드가 "인스타 노출이 인지를 만들었다"고 주장하고 싶다면 노출 윈도우를 7일로 늘려야 하고, 그러면 인스타의 성과가 갑자기 커진다.

그래서 실무에서 성과를 비교할 때는 규칙·윈도우·접점 정의 **세 가지가 같은지** 먼저 맞춰야 한다. 세팅이 다른 두 리포트의 ROAS를 나란히 놓고 "A채널이 더 좋다"고 말하는 건, 자와 줄자를 섞어 쓰고 길이를 비교하는 것과 같다.

## 5. 담장 안에서는 어떻게 잇는가 [무대: 닫힌 생태계]

**한 회사가 노출·클릭·구매를 모두 자기 로그로 갖고 있으면, 여정을 잇는 일은 조인 한 번으로 끝난다.**

네이버·카카오처럼 닫힌 생태계에서는 사용자가 로그인해 있다. 그래서 1절 로그의 6번 줄 — 폰에서 PC로 기기가 바뀐 그 지점 — 이 자연스럽게 이어진다. 기기가 아니라 **사람** 단위로 여정을 보기 때문이다.

이점은 세 가지다. 노출·클릭·전환이 한 회사 로그에 있으니 **조인이 깨끗하다.** 클릭하지 않고 보기만 한 노출(뷰스루)도 정확히 알 수 있어 **인지 기여를 잴 수 있다.** 그리고 광고를 보여줄지 말지를 플랫폼이 직접 정하니, 뒤에서 볼 홀드아웃 실험(7절)을 **깔끔하게 설계할 수 있다.**

대신 결정적인 한계가 있다. **자기 채널만 보인다.** 우리 안에서 라스트클릭 100%를 받은 접점이 있어도, 그 사람이 밖에서 유튜브 광고를 열 번 봤는지는 알 수 없다. 담장 안의 성적표는 정확하지만, **범위가 담장까지**다. 그래서 채널 간 예산 배분을 결정할 때는 담장 안 어트리뷰션만으로 답이 나오지 않고, 결국 실험이 필요해진다.

## 6. 열린 RTB에서는 왜 지저분한가 [무대: 열린 RTB]

**여정 조각이 여러 회사에 흩어져 있으면, 그걸 꿰매는 일 자체가 기술이 된다. 그리고 그 실이 요즘 계속 끊긴다.**

열린 RTB에서는 노출은 A 거래소, 클릭은 B 매체, 구매는 광고주 사이트에서 일어난다. 이 조각들을 하나의 사람에게 묶으려면 쿠키나 광고 식별자, 또는 전문 측정업체가 필요하다. 앱에서는 **MMP(Mobile Measurement Partner)** — AppsFlyer·Adjust, 국내에서는 Airbridge — 가 그 역할을 하고, 웹에서는 픽셀·태그(Meta Pixel, Google Analytics 4)가 한다.

문제는 그 실이 끊기고 있다는 점이다. 서드파티 쿠키가 축소되고, iOS는 ATT(앱 추적 동의)로 식별자 접근을 막았다. 대신 애플이 주는 SKAdNetwork는 **집계된 요약만** 돌려준다 — 누가 어떤 광고를 보고 샀는지가 아니라, "이 캠페인에서 전환 몇 건" 수준이다.

만약 민지의 여정이 이 세계에서 벌어졌다면 어땠을까. **3/11 폰에서의 클릭과 3/12 PC에서의 구매는 서로 다른 사람으로 보일 수 있다.** 그러면 인스타 클릭의 공은 아무에게도 가지 않고, 브랜드 검색광고가 "새로 나타난 사람이 바로 산 것"으로 기록된다. 여정을 못 이으면 어트리뷰션은 조용히 마지막 접점 쪽으로 쏠린다.

그래서 이 세계의 측정은 사람 단위 추적에서 **집계·모델 기반**으로 옮겨가는 중이다. 규칙을 정교하게 다듬는 일보다, 아예 다른 질문을 던지는 쪽이 더 믿을 만해졌다 — 다음 절이 그 질문이다.

## 7. 함정 — 어트리뷰션은 '진짜 효과'가 아니다

**어트리뷰션은 이미 일어난 전환의 공을 나누는 회계다. "광고가 없었어도 그 사람이 샀을까"는 전혀 다른 질문이다.**

이 차이를 숫자로 보자. 10만 명에게는 광고를 보여주고, 비슷한 10만 명에게는 일부러 보여주지 않는다(**홀드아웃**). 그리고 두 집단의 구매율을 비교한다.

| 그룹 | 사람 수 | 광고 노출 | 구매자 수 | 구매율 |
|---|---|---|---|---|
| 노출군 | 100,000 | O | 2,500 | 2.50% |
| 대조군(홀드아웃) | 100,000 | X | 2,000 | 2.00% |

라스트클릭이 광고 공으로 잡는 건 **2,500건**이다. 그런데 광고를 아예 안 본 대조군에서도 **2,000명이 샀다.** 이 사람들은 광고가 없어도 살 사람이었다.

그렇다면 광고가 실제로 만든 건 **2,500 − 2,000 = 500건**이다. 이 500건을 **증분(Incrementality)**이라 부른다. 회계는 2,500건이라 말하고 실제는 500건이니, **5배 과대**다.

이 차이가 예산 결정을 뒤집는다. 광고비 ₩10,000,000을 썼다고 하면,

- 겉보기 CPA = 10,000,000 ÷ 2,500 = **₩4,000**
- 증분 CPA = 10,000,000 ÷ 500 = **₩20,000**

₩4,000이면 "더 부어야 한다"가 답이고, ₩20,000이면 "이 캠페인은 접자"가 답일 수 있다. 같은 캠페인, 같은 데이터인데 결론이 정반대다.

왜 이런 일이 생기는지는 라스트클릭의 구조를 보면 자명하다. **이미 살 마음을 먹고 브랜드 이름을 검색한 사람에게 마지막으로 보인 광고**가 공을 100% 가져간다. 그 광고는 매출을 늘린 게 아니라, 어차피 일어날 매출에 도장을 찍은 것에 가깝다. 그래서 브랜드 검색광고를 끊어 보면 매출이 그만큼 줄지 않는 경우가 흔하다.

:::deep 더 깊이 — 증분을 파이썬으로 계산하기
위 표에서 증분·lift·증분 CPA를 계산하고, 그 차이가 우연일 가능성까지 대충 재 본다. 표준 라이브러리만 쓴다.

```python
# 홀드아웃 실험 결과로 '광고가 실제로 만든 전환'을 계산한다.
# 어트리뷰션(회계)이 말하는 숫자와 얼마나 다른지 나란히 본다.
import math

n_exposed,  buy_exposed  = 100_000, 2_500   # 노출군: 광고를 봤다
n_control,  buy_control  = 100_000, 2_000   # 대조군: 일부러 안 보여줬다(홀드아웃)
SPEND = 10_000_000                          # 이 캠페인에 쓴 광고비(원)

p_e = buy_exposed / n_exposed               # 0.025
p_c = buy_control / n_control               # 0.020

incremental = buy_exposed - buy_control * (n_exposed / n_control)  # 두 군 크기가 같으면 단순 차이
lift = (p_e - p_c) / p_c                    # 대조군 대비 몇 % 더 샀나

# 겉보기 CPA는 라스트클릭이 잡은 전환 전부(2,500)를 광고 공으로 치고 계산한다.
cpa_apparent    = SPEND / buy_exposed
cpa_incremental = SPEND / incremental

# 차이가 우연일 확률도 대충 본다: 두 비율 차이의 표준오차(정규 근사)
se = math.sqrt(p_e * (1 - p_e) / n_exposed + p_c * (1 - p_c) / n_control)
z  = (p_e - p_c) / se                       # |z| >= 1.96 이면 95% 수준에서 유의

print(f"증분 전환      {incremental:,.0f}건  (어트리뷰션이 말하는 건수: {buy_exposed:,}건)")
print(f"과대 배수      {buy_exposed / incremental:.1f}배")
print(f"증분율(lift)   {lift:+.1%}")
print(f"겉보기 CPA     {cpa_apparent:,.0f}원")
print(f"증분 CPA       {cpa_incremental:,.0f}원")
print(f"z = {z:.2f}")

# 출력:
# 증분 전환      500건  (어트리뷰션이 말하는 건수: 2,500건)
# 과대 배수      5.0배
# 증분율(lift)   +25.0%
# 겉보기 CPA     4,000원
# 증분 CPA       20,000원
# z = 7.54
```

`z = 7.54`는 이 차이가 우연으로 생길 가능성이 사실상 없다는 뜻이다(95% 기준은 1.96). 다만 이 검정이 말해 주는 건 "차이가 있다"까지다. 두 집단이 애초에 비슷했는지는 무작위 배정이 보장해야 하고, 그게 깨지면 z값이 아무리 커도 의미가 없다.
:::

:::deep 더 깊이 — 규칙을 사람이 고르지 않는 방법 (Shapley value)
지금까지의 규칙은 전부 사람이 정한 것이다. 왜 40/20/40인가? 왜 반감기가 7일인가? 근거는 대개 관행이다.

데이터로 정하려면 질문을 이렇게 바꾼다. **"그 접점이 있었을 때와 없었을 때, 전환 확률이 얼마나 달랐나?"** 협조적 게임이론의 Shapley value가 이 아이디어를 정식화한다. 접점 $i$의 기여는 가능한 모든 접점 조합에 대해, $i$가 들어올 때의 전환 확률 증가분을 평균한 값이다.

$$\phi_i = \sum_{S \subseteq N \setminus \{i\}} \frac{|S|!\,(|N|-|S|-1)!}{|N|!}\bigl[v(S \cup \{i\}) - v(S)\bigr]$$

여기서 $v(S)$는 접점 집합 $S$만 거친 사람들의 전환 확률이다. 문제는 $S$의 개수가 $2^{|N|}$로 폭발한다는 점이다. 접점 종류가 20개면 백만 개가 넘는 조합을 봐야 한다.

그래서 실무에서는 근사한다. 조합을 무작위로 표본추출하거나, 여정을 상태 전이로 보고 마르코프 체인에서 각 상태를 제거했을 때의 전환율 하락(removal effect)으로 대신 계산한다. 이런 방식을 묶어 **데이터 주도 어트리뷰션(DDA)**이라 부르고, 구글 애즈의 기본 모델도 이 계열이다.

다만 이것도 어트리뷰션이라는 한계는 그대로다. 관측된 여정 안에서 공을 더 정교하게 나눌 뿐, "광고가 없었다면"이라는 반사실은 여전히 실험만 답할 수 있다.
:::

## 9. 헷갈리기 쉬운 점

- **라스트클릭은 '진실'이 아니라 '규칙'이다.** 가장 흔할 뿐, 가장 정확한 게 아니다. 기본값이라 아무도 고르지 않았는데 모두가 쓰고 있다.
- **어트리뷰션 ≠ 증분.** 공을 100% 받았다고 매출을 늘린 게 아니다. 이 글의 예시에서는 5배가 부풀었다.
- **윈도우를 밝히지 않은 성과 비교는 성립하지 않는다.** 규칙·윈도우·접점 정의가 같은지부터 맞춰야 한다.
- **겉보기 CPA와 증분 CPA는 다른 숫자다.** 리포트에 CPA가 한 개만 적혀 있으면 거의 항상 겉보기 쪽이다.
- **뷰스루(보기만 한 광고)를 셀지부터 규칙이 갈린다.** 코드의 `clicks` 필터 한 줄이 그 정책이었다.
- **여정을 못 이으면 조용히 마지막 접점으로 쏠린다.** 기기·브라우저가 갈릴 때 특히 그렇다 — 숫자가 틀렸다고 알려 주지 않는다.
