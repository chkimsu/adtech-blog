자연어 오디언스 카드 네 장

광고주가 번호 대신 「러닝화 살 사람」 같은 문장을 적으면, 문장은 판정, 조건 추출, 필터, 명단 크기를 지나 회원 수가 됩니다. 세 요청의 판정, 문장 조각이 된 조건, 표본에서 남는 회원, LLM 과 코드가 맡는 일을 한 장씩 봅니다. 표본은 설명용 가상 값이고 LLM 의 답은 한 번 기록한 값입니다.

벽돌색 = LLM 이 쓴 답 (판정, 조건) 파랑 = 코드가 하는 일과 표본 회원 회색 = 빠진 부분과 명단을 만들지 않는 답 점선 상자 = 사람이 미리 적어 둔 글 (시스템 메시지, 템플릿)

INTENT

세 요청과 판정. LLM 이 JSON 의 verdict 필드에 적는다

쉽게 말하면 판정은 받을 수 있는 요청인지 정하는 일입니다. 전부 조건으로 옮길 수 있으면 지원, 일부만 옮길 수 있으면 일부 지원, 옮길 수 없거나 옮기면 안 되면 불가입니다.

러닝화 요청은 supported, 건강 상태 요청은 unsupported 입니다. 캠핑 요청은 일부 지원이어야 했지만 기준 답은 unsupported 였고, thinking 을 켠 답이 partial 입니다.

SLOTS

문장 조각이 필드, 비교, 값의 조건이 된다

쉽게 말하면 조건 하나는 필드 이름, 비교, 값 셋입니다. 조건이 여럿이면 모두 맞는 회원을 고르고, 필드로 옮기지 못한 조각은 조건에 넣지 않고 따로 적습니다.

「러닝화 살 사람」은 search_running_shoes >= 1 하나가 됩니다. 캠핑 요청의 「30대」는 나이 조건 둘, 「캠핑 용품 본」은 검색 조건 하나가 됩니다.

QUERY

조건 JSON 이 쿼리가 되고 표본에서 남는 회원을 센다

쉽게 말하면 코드가 조건마다 「필드 비교 값」을 쓰고 AND 로 이어 쿼리를 만듭니다. 표본 2,000명에서 맞는 회원을 세고 7,000을 곱하면 전체 회원으로 옮겨집니다.

러닝화 요청은 표본 63명, 캠핑 요청의 조건 셋은 59명입니다. 59명은 「우리 광고 안 본」을 빼고 센 수입니다.

LLM AND CODE

LLM 이 맡는 두 일과 코드가 맡는 네 일

쉽게 말하면 문장을 읽어야 하는 판정과 조건 추출은 LLM 이 합니다. 같은 입력에 늘 같은 답이 나와야 하는 검사, 쿼리, 명단 크기, 응답은 코드가 합니다.

답 19개에 코드가 고른 응답은 명단 8개, 검토 5개, 템플릿 6개입니다. 거절 문장은 LLM 이 쓰지 않고 템플릿 한 문장에서 나옵니다.

현업에서는 이렇게 씁니다

  • 자연어로 오디언스를 만든다는 이야기를 들으면 세 가지를 묻습니다. LLM 이 쓸 수 있는 필드 목록은 어디에 적혀 있나, 판정과 조건을 코드가 다시 검사하나, 거절 문장은 누가 쓰나.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 자연어 오디언스 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 「살 사람」을 확률로 고르는 자리는 전환 예측으로 타겟 고르기 편입니다.
