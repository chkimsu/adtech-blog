모델 팀 41주째 월요일, 지훈 씨는 카피를 쓰는 모델을 직접 고치게 되었습니다. 40주째에는 실험 하나를 계획부터 마무리까지 프로그램에게 맡겼는데, 이번에는 모델의 숫자를 바꿉니다.

지훈 씨 손에는 서연 씨 러닝화에 쓴 카피 12개와 둘 가운데 나은 쪽을 정한 기록 20개가 있습니다. 코드 검사에 걸린 카피와 지난 카피, 채점하는 모델이 고른 쪽, 광고주가 고쳐 쓴 문장이 섞여 있습니다. 선배는 좋은 카피만 골라 따라 쓰게 하면 나쁜 카피도 같이 늘 수 있다고 말했습니다.

**좋은 카피와 나쁜 카피를 짝지어 보여 주면, 모델은 어느 쪽으로 얼마나 움직이고 언제 멈춰야 할까요?**

좋은 답 하나를 그대로 따라 쓰게 하는 학습을 SFT, 둘 가운데 고른 쪽으로 모델을 미는 학습을 DPO 라고 부릅니다. 고른 쪽 chosen 과 고르지 않은 쪽 rejected 를 묶어 선호 쌍이라고 부릅니다. 학습한 모델이 쓴 카피는 광고주에게 바로 보입니다. 카피가 심사에서 빠지면 그 광고는 나가지 않습니다.

> **한 줄 요약:** 좋은 카피 하나를 따라 쓰게 하는 SFT 로 학습하면 나쁜 카피가 그 카피와 같은 낱말을 쓸 때 나쁜 카피가 나올 확률도 같이 오를 수 있습니다. 이 글의 두 카피는 낱말 5개 가운데 3개가 같아서 SFT 한 걸음에 두 카피의 확률이 함께 올랐습니다. 좋은 카피와 나쁜 카피를 짝지어 배우는 DPO 는 같은 시작점에서 한 걸음에 chosen 을 올리고 rejected 를 내렸습니다. 모델이 학습을 시작할 때보다 나쁜 카피 쪽으로 더 기운 쌍일수록 DPO 는 그 쌍을 더 세게 밉니다. 다만 학습이 줄이는 값(손실)은 짝지은 카피만 보므로, 늘 긴 카피를 고르는 채점 모델의 쌍이 섞인 이 글의 데이터로 오래 학습하자 쌍에 없는 긴 카피가 확률을 가져갔습니다. 그 사이 코드 검사를 모두 지나는 카피가 나올 확률(통과율)은 0.597 까지 올랐다가 0.008 로 떨어졌으므로, 통과율이 가장 높았던 체크포인트(학습 도중 저장한 가중치)로 되돌립니다. 고칠 가중치의 수는 원래 행렬을 고정하고 작은 행렬 2개만 학습하는 LoRA 로 줄입니다.

> **골라 읽는 법** — 절이 7개입니다. 절마다 있는 표나 코드나 카드만 보고 넘어가도 됩니다.
>
> - SFT 한 걸음(학습 스텝 한 번)과 DPO 한 걸음의 차이 → 1절
> - 선호 쌍 20개를 모으는 출처 3곳 → 2절
> - 로그 확률 4개로 세는 DPO 손실 → 3절
> - 틀린 쌍을 더 세게 미는 기울기와 β → 4절
> - 오래 학습하면 떨어지는 통과율과 체크포인트 → 5절
> - 고칠 가중치를 줄이는 LoRA → 6절
> - 담장 안과 열린 RTB 에서 쌍을 모으는 곳 → 7절

이 글의 카피 후보 12개와 선호 쌍 20개, 두 모델이 카피마다 준 로그 확률은 설명을 위해 만든 가상 데이터입니다. 후보와 쌍은 `scripts/gen-training-data.py` 가 만들었습니다. 블록 2 는 그 스크립트에 적힌 값(리터럴)을 글자 그대로 옮겼습니다. 카피는 35주째 [광고 카피 생성](post.html?id=grounded-ad-copy-generation) 편에 나온 서연 씨 러닝화 자산(광고주가 준 상품 설명)에 맞춰 썼습니다. 쌍은 그 편과 36주째 편의 기록에서 뽑지 않았고 쌍을 모으는 세 출처를 흉내 냈습니다. 이 글은 언어 모델을 호출하지 않습니다. 숫자는 논문에서 옮긴 수치를 빼면 모두 이 글의 파이썬 블록 3개가 찍었습니다. 두 모델과 로그 확률은 1절에서 풉니다.

## 1. 좋은 답 하나를 따라 쓰게 하는 SFT

**SFT 는 좋은 답 하나가 나올 확률을 올리는 학습이지만 나쁜 답이 좋은 답과 같은 낱말을 쓰면 나쁜 답의 확률도 같이 오를 수 있습니다. 토큰(모델이 글을 읽고 쓰는 조각) 12개짜리 모델에서 SFT 로 한 걸음 가자 로그 확률(0 에 가까울수록 그 카피가 잘 나옵니다)이 chosen 은 -12.425 에서 -11.121 로 올랐고 토큰 5개 가운데 3개가 chosen 과 같은 rejected 도 -12.425 에서 -12.121 로 올랐습니다. 같은 시작점에서 DPO 한 걸음은 chosen 을 올리고 rejected 를 내렸습니다.**

도입에서 선배는 좋은 카피만 골라 따라 쓰게 하면 나쁜 카피도 같이 늘 수 있다고 했습니다. 토큰 12개짜리 작은 모델에서 SFT 와 DPO 로 한 걸음씩 가 보면 그 일이 왜 생기는지와 DPO 가 무엇이 다른지 숫자로 확인할 수 있습니다.

토큰은 모델이 글을 읽고 쓰는 조각입니다. 이 절의 작은 모델은 카피를 공백으로 나눈 낱말 하나를 토큰 하나로 씁니다(토큰은 19주째 [LLM 호출 한 번](post.html?id=llm-first-call) 편에서 처음 보았습니다). 모델이 카피 하나를 쓸 확률은 토큰마다 「앞 토큰 다음에 그 토큰이 나올 확률」을 모두 곱한 값입니다. 1 보다 작은 확률을 여러 번 곱하면 0 에 아주 가까워지므로 곱하는 대신 확률마다 로그를 취해 더한 값을 쓰는데, 이 값을 로그 확률이라고 부릅니다. 확률이 1 이면 로그는 0 이고 확률이 작을수록 로그는 더 큰 음수가 되므로, 로그 확률이 0 에 가까울수록 모델이 그 카피를 쓸 확률이 높습니다.

블록 1 의 모델은 다음 토큰의 확률이 앞 토큰과 상관없는 가장 작은 언어 모델인 유니그램이라, 카피의 확률은 카피에 든 토큰 각각의 확률을 곱한 값입니다. 어휘의 토큰 12개마다 점수가 하나씩 있는데 이 점수를 로짓이라고 부릅니다. 소프트맥스는 로짓마다 e 를 그 로짓만큼 거듭제곱한 값(지수)을 구한 뒤 그 합 Z 로 나눠 합이 1 인 확률로 바꾸는 함수입니다. 로짓 12개를 넣으면 확률 12개가 나옵니다(소프트맥스는 [Two-Tower 학습](post.html?id=two-tower-training) 편에서 처음 풀었습니다). 토큰 하나의 확률이 「e 를 로짓만큼 거듭제곱한 값 ÷ Z」이므로 로그를 취하면 「그 토큰의 로짓 - log Z」가 되며 카피의 로그 확률은 이 값을 토큰마다 더한 값입니다. 로짓이 모두 0 인 시작점에서는 토큰 12개의 확률이 모두 0.083 으로 같고 토큰 하나의 로그 확률이 -2.485 라서, 토큰 5개인 두 카피의 로그 확률은 -2.485 를 5번 더한 -12.425 로 같습니다.

SFT(supervised fine-tuning)는 좋은 답을 정답으로 주고 그 답의 로그 확률을 올리는 학습입니다. 손실(loss)은 학습이 줄이려는 값입니다. SFT 의 손실은 chosen 의 로그 확률에 음수 부호를 붙인 값이라 chosen 하나만 봅니다. 기울기는 로짓을 조금 움직일 때 로그 확률이 얼마나 바뀌는지를 토큰마다 적은 값입니다. 로그 확률을 로짓으로 미분하면 토큰마다 「카피에 든 횟수 - 카피 길이 × 확률」이 나옵니다. 앞 항은 그 토큰이 카피에 든 횟수만큼 로짓 합이 오르는 몫입니다. 뒤 항은 그 토큰의 로짓이 오르면 Z 가 커져 카피의 토큰마다 빼는 log Z 가 함께 커지는 몫이라, 카피에 없는 토큰의 기울기는 음수입니다. 학습률은 기울기에 곱해 한 번에 얼마나 움직일지 정하는 값입니다. 블록은 학습률 0.5 를 곱해 기울기의 절반만큼 로짓을 옮깁니다. 이렇게 기울기를 한 번 구해 로짓을 한 번 옮기는 것을 한 걸음(학습 스텝)이라고 부릅니다.

DPO(direct preference optimization)는 chosen 과 rejected 를 함께 보며 chosen 의 기울기에서 rejected 의 기울기를 뺀 방향으로 갑니다. DPO 에는 모델이 2개 나옵니다. 학습하는 동안 고정해 두고 비교의 기준으로 쓰는 모델을 참조 모델, 학습하는 모델을 정책이라고 부릅니다. 블록 1 은 로짓이 모두 0 인 시작점을 참조 모델로 두고 정책도 그 점에서 출발시킵니다.

블록 1 은 두 카피 「240g 쿠션 폼 입문자용 러닝화」(chosen)와 「가장 가벼운 쿠션 폼 러닝화」(rejected)로 SFT 한 걸음과 DPO 한 걸음을 간 뒤 두 카피의 로그 확률과 토큰 12개의 로짓이 움직인 양을 찍습니다. 두 카피는 토큰 5개 가운데 쿠션, 폼, 러닝화 3개를 같이 씁니다.

```python
# 하는 일: 토큰 12개짜리 유니그램 모델에서 SFT 한 걸음과 DPO 한 걸음을 가고, 두 카피의 로그 확률과 토큰 점수가 움직인 양을 찍는다.
import math

# 1단계: 어휘, 두 카피, 시작 점수를 둔다
# 유니그램은 다음 토큰의 확률이 앞 토큰과 상관없는 가장 작은 언어 모델이다. 토큰 점수(로짓)는 모두 0 에서 시작한다.
# 두 카피는 공백으로 나눈 토큰 다섯씩이고, 쿠션, 폼, 러닝화 셋이 두 카피에 같이 든다.
VOCAB = ['240g', '쿠션', '폼', '입문자용', '러닝화', '가장', '가벼운', '한', '짝', '1위', '편한', '교환']
CHOSEN = '240g 쿠션 폼 입문자용 러닝화'.split()
REJECTED = '가장 가벼운 쿠션 폼 러닝화'.split()
SHARED = [t for t in CHOSEN if t in REJECTED]
start = {t: 0.0 for t in VOCAB}


def probs(score):
    # 소프트맥스. 가장 큰 점수를 빼고 지수를 취해 넘치지 않게 한 뒤, 합이 1 이 되게 나눈다.
    top = max(score.values())
    e = {k: math.exp(v - top) for k, v in score.items()}
    total = sum(e.values())
    return {k: v / total for k, v in e.items()}


def seq_logp(score, tokens):
    # 카피의 로그 확률은 토큰 로그 확률의 합이다.
    p = probs(score)
    return sum(math.log(p[t]) for t in tokens)


def seq_grad(score, tokens):
    # seq_logp 를 토큰 점수로 미분한 값. 토큰마다 「카피에 든 횟수 - 카피 길이 × 확률」이다.
    p = probs(score)
    return {t: tokens.count(t) - len(tokens) * p[t] for t in VOCAB}


def change(x):
    # 점수 변화를 소수 셋째 자리로 적는다. 0 이 되면 부호 없이 0.000 이다.
    return '0.000' if round(x, 3) == 0 else f'{x:+.3f}'


p0 = probs(start)
print(f'어휘 {len(VOCAB)}개, 토큰 하나의 확률 {p0["240g"]:.3f}, 로그 확률 {math.log(p0["240g"]):.3f}')
print(f'시작 chosen {seq_logp(start, CHOSEN):.3f}, rejected {seq_logp(start, REJECTED):.3f}')

# 2단계: SFT 로 한 걸음 간다
# SFT 의 손실은 chosen 하나만 본다. chosen 의 로그 확률을 올리는 기울기에 학습률 0.5 를 곱한 만큼 토큰 점수를 옮긴다.
# 로그 확률은 「토큰 점수 - log Z」의 합이다. Z 는 점수 12개의 지수를 더한 값이다.
grad = seq_grad(start, CHOSEN)
sft = {t: start[t] + 0.5 * grad[t] for t in VOCAB}
print(f'SFT 한 걸음(학습률 0.5) 뒤 chosen {seq_logp(sft, CHOSEN):.3f}, rejected {seq_logp(sft, REJECTED):.3f}')
moved = sum(sft[t] - start[t] for t in REJECTED)
log_z = math.log(sum(math.exp(v) for v in sft.values())) - math.log(sum(math.exp(v) for v in start.values()))
print(f'rejected 의 토큰 점수 합 {moved:+.3f}, log Z 가 늘어난 몫 5 × {log_z:.3f} = {5 * log_z:.3f}')


# 3단계: DPO 로 한 걸음 간다
# 같은 시작점을 참조 모델로 두고, 정책도 그 점에서 출발한다. margin 은 β × (chosen 의 로그 비율 - rejected 의 로그 비율) 이다.
# 로그 비율은 정책의 로그 확률 - 참조 모델의 로그 확률이다. 손실은 -log σ(margin), 무게는 σ(-margin) 이다.
# 손실을 줄이는 방향은 토큰마다 β × 무게 × (chosen 의 기울기 - rejected 의 기울기) 이고, 학습률 5.0 을 곱해 간다.
def sigmoid(x):
    # 큰 |x| 에서도 넘치지 않게 부호에 따라 식을 고른다.
    if x >= 0:
        return 1 / (1 + math.exp(-x))
    e = math.exp(x)
    return e / (1 + e)


def softplus(x):
    # log(1 + e^x). -log σ(m) 은 softplus(-m) 이다. 큰 x 에서 넘치지 않게 x + log(1 + e^-x) 로 센다.
    return x + math.log1p(math.exp(-x)) if x > 0 else math.log1p(math.exp(x))


def dpo_step(policy, ref, chosen, rejected, beta, lr):
    ratio_w = seq_logp(policy, chosen) - seq_logp(ref, chosen)
    ratio_l = seq_logp(policy, rejected) - seq_logp(ref, rejected)
    margin = beta * (ratio_w - ratio_l)
    weight = sigmoid(-margin)
    gw, gl = seq_grad(policy, chosen), seq_grad(policy, rejected)
    new = {t: policy[t] + lr * beta * weight * (gw[t] - gl[t]) for t in VOCAB}
    return new, margin, softplus(-margin), weight


dpo, margin, loss, weight = dpo_step(start, start, CHOSEN, REJECTED, beta=0.1, lr=5.0)
print(f'DPO 한 걸음(β 0.1, 학습률 5.0) 전 margin {margin:.3f}, 손실 {loss:.3f}, 무게 {weight:.3f}')
print(f'DPO 뒤 chosen {seq_logp(dpo, CHOSEN):.3f}, rejected {seq_logp(dpo, REJECTED):.3f}')

# 4단계: 두 걸음의 토큰 점수 변화를 비교한다
# 줄마다 토큰 하나다. 두 카피에 든 횟수와, 두 걸음이 그 토큰의 점수를 옮긴 양을 적는다.
for t in VOCAB:
    print(f'{t}: chosen {CHOSEN.count(t)}번, rejected {REJECTED.count(t)}번, '
          f'SFT {change(sft[t] - start[t])}, DPO {change(dpo[t] - start[t])}')

# 5단계: 공유 토큰의 DPO 기울기를 나눠 본다
# 토큰 하나의 DPO 기울기는 β × 무게 × ((chosen 횟수 - rejected 횟수) - (chosen 길이 - rejected 길이) × 확률) 이다.
# 두 카피의 길이가 같으면 확률 항이 지워지고, 두 카피에 한 번씩 든 공유 토큰은 횟수 항도 0 이다.
for t in SHARED:
    count_part = CHOSEN.count(t) - REJECTED.count(t)
    prob_part = (len(CHOSEN) - len(REJECTED)) * p0[t]
    print(f'{t}: 횟수 항 {count_part}, 확률 항 ({len(CHOSEN)} - {len(REJECTED)}) × {p0[t]:.3f} = {prob_part:.3f}, '
          f'DPO 변화 {change(dpo[t] - start[t])}')
longer = REJECTED + ['1위']
moved_long = dpo_step(start, start, CHOSEN, longer, beta=0.1, lr=5.0)[0]
print(f'rejected 끝에 1위 를 붙여 토큰 {len(longer)}개로 늘리면 공유 토큰의 DPO 변화 '
      + ', '.join(f'{t} {change(moved_long[t] - start[t])}' for t in SHARED))
# 출력:
# 1단계 뜻: 로짓이 모두 0 이라 토큰 확률이 같고, 토큰 다섯인 두 카피의 로그 확률도 같다.
# 어휘 12개, 토큰 하나의 확률 0.083, 로그 확률 -2.485
# 시작 chosen -12.425, rejected -12.425
# 2단계 뜻: SFT 의 손실은 chosen 하나만 보지만, 공유 토큰 셋 때문에 rejected 의 로짓 합도 올라 rejected 도 올랐다.
# SFT 한 걸음(학습률 0.5) 뒤 chosen -11.121, rejected -12.121
# rejected 의 토큰 점수 합 +0.458, log Z 가 늘어난 몫 5 × 0.031 = 0.155

# 쿠션: 횟수 항 0, 확률 항 (5 - 5) × 0.083 = 0.000, DPO 변화 0.000
# 폼: 횟수 항 0, 확률 항 (5 - 5) × 0.083 = 0.000, DPO 변화 0.000
# 러닝화: 횟수 항 0, 확률 항 (5 - 5) × 0.083 = 0.000, DPO 변화 0.000
# rejected 끝에 1위 를 붙여 토큰 6개로 늘리면 공유 토큰의 DPO 변화 쿠션 +0.021, 폼 +0.021, 러닝화 +0.021
```

4단계에 찍힌 SFT 의 변화는 기울기의 부호를 그대로 따릅니다. 기울기 「카피에 든 횟수 - 카피 길이 × 확률」은 chosen 에 든 토큰 5개에서 「1 - 5 × 0.083」으로 양수이고 chosen 에 없는 토큰 7개에서 「0 - 5 × 0.083」으로 음수이므로, 학습률 0.5 를 곱해 옮기자 chosen 의 토큰 5개는 로짓이 0.292 씩 오르고 나머지 7개는 0.208 씩 내려갔습니다. 그래서 chosen 의 로그 확률은 -12.425 에서 -11.121 로 올랐습니다.

rejected 의 토큰 5개 가운데 쿠션, 폼, 러닝화 3개는 chosen 에도 들어 0.292 씩 올랐고 「가장」과 「가벼운」 2개만 0.208 씩 내려갔으므로, rejected 의 로짓 합은 0.458 올랐습니다. 카피의 로그 확률은 이 로짓 합에서 log Z 를 토큰 수만큼 뺀 값입니다. 그 빼는 몫은 log Z 가 늘어난 0.031 에 토큰 수 5 를 곱한 0.155 만 늘었으므로(2단계의 둘째 줄), 로짓 합이 0.458 오른 rejected 의 로그 확률은 SFT 의 손실이 chosen 하나만 보는데도 -12.425 에서 -12.121 로 올랐습니다. 이 예에서는 좋은 카피만 따라 쓰게 했는데도 그 카피와 낱말을 함께 쓰는 나쁜 카피가 선배의 말대로 같이 올라갔습니다.

DPO 한 걸음 전에는 정책과 참조 모델이 같아서 margin(정책이 참조 모델에서 출발해 rejected 보다 chosen 쪽으로 얼마나 더 움직였는지 측정하는 값)이 0.000 입니다. 그때 손실은 0.693 이고 무게(쌍마다 기울기에 곱해지는 가중치)는 0.500 입니다. margin 을 셀 때 곱하는 값 β 는 0.1 입니다. margin, 손실, 무게를 세는 식은 3절에서, β 의 크기는 4절에서 다시 봅니다.

DPO 한 걸음(β 0.1, 학습률 5.0) 뒤 chosen 은 -12.425 에서 -11.977 로 오르고 rejected 는 -12.977 로 내려갔습니다. SFT 는 토큰 12개의 로짓을 모두 옮겼지만 DPO 는 chosen 에만 든 240g 과 입문자용(+0.250), rejected 에만 든 「가장」과 「가벼운」(-0.250) 4개만 옮겼습니다. DPO 한 걸음은 토큰마다 「chosen 의 기울기 - rejected 의 기울기」에 β, 무게, 학습률을 곱한 만큼 로짓을 옮깁니다. 240g 은 이 차이에서 「길이 × 확률」 항이 지워지고 횟수 항 1 만 남으므로 0.1 × 0.500 × 5.0 을 곱한 +0.250 만큼 움직였고 「가장」과 「가벼운」은 횟수 항의 부호가 반대라 같은 크기로 내려갔습니다.

두 카피에 같이 든 쿠션, 폼, 러닝화(공유 토큰)는 두 카피의 길이가 5 로 같아 「길이 × 확률」 항이 지워지고 두 카피에 한 번씩 들어 횟수 항도 0 이므로, DPO 한 걸음에서 0.000 움직였습니다. 같은 세 토큰을 0.292 씩 올려 rejected 까지 끌어올린 SFT 와 다릅니다. rejected 끝에 「1위」를 붙여 토큰 6개로 늘리면 두 카피의 길이가 달라 「길이 × 확률」 항이 (5 - 6) × 0.083 으로 음수가 됩니다. 공유 토큰은 횟수 항이 0 이고 기울기의 차이에서 이 음수 항을 빼므로 0.083 이 남습니다. 여기에 0.1 × 0.500 × 5.0 을 곱한 0.021 씩 공유 토큰 3개가 모두 오릅니다(5단계). 2절부터는 길이가 서로 다른 카피의 쌍을 다룹니다.

## 2. 세 곳에서 모은 선호 쌍 20개

**선호 쌍은 게이트(코드 검사), 판정자(채점 모델)가 두 카피를 나란히 놓고 고르는 짝비교, 광고주 편집 세 곳에서 모으는데, 출처마다 chosen 을 정하는 법이 달라 쌍이 가르치는 것도 다릅니다. 이 글의 쌍 20개는 게이트 6쌍, 판정자 8쌍, 광고주 편집 6쌍입니다. 판정자 쌍은 늘 긴 카피를 고르는 판정자를 흉내 내 만들었으므로 chosen 이 rejected 보다 평균 14.4자 깁니다.**

DPO 의 손실은 선호 쌍만 보므로 모델은 쌍이 가르치는 것을 배웁니다. 그런데 쌍이 가르치는 것은 출처마다 달라서 어느 출처의 쌍을 얼마나 섞었는지에 따라 학습 결과가 달라질 수 있습니다.

후보 12개는 서연 씨 러닝화 자산 하나에 쓴 카피입니다. 게이트는 카피를 코드로 검사해 통과와 탈락을 정하는 규칙입니다. 이 글은 35주째 편의 게이트 4개 가운데 길이 게이트, 최상급 게이트, 근거 게이트의 숫자 대조를 씁니다. 길이 게이트는 40자 이하인 카피만, 숫자 대조는 카피의 숫자가 모두 자산에 있는 카피만, 최상급 게이트는 근거 없는 최상급(자산에 없는 「가장」이나 「1위」 같은 낱말)이 없는 카피만 통과시킵니다. 세 게이트를 모두 지난 c01 부터 c05 까지 5개를 통과 후보라고 부릅니다. c06(「한 짝 240g 으로 가볍고 밑창 전체에 쿠션 폼을 깐, 처음 달리는 사람을 위한 러닝화」)과 c07(「한 짝 240g 에 앞코가 넉넉하고 밑창 전체에 쿠션 폼을 깐 입문자용 러닝화」)은 숫자가 맞고 최상급도 없지만 40자를 넘어 길이 게이트에만 걸립니다.

글자 수 차이는 쌍마다 chosen 의 글자 수에서 rejected 의 글자 수를 뺀 값입니다. 이 글은 이 값을 출처마다 평균해 비교합니다. 게이트 쌍은 통과한 카피를 chosen, 숫자나 최상급에 걸린 카피를 rejected 로 둡니다. 자산에 없는 중량 220g 을 쓴 c08 과 「가장 가벼운」으로 시작하는 c09(「가장 가벼운 입문자용 러닝화 런솔 라이트」)가 rejected 에 들어갑니다. 게이트는 코드라 쌍을 많이 만들 수 있지만 숫자와 최상급 낱말만 보고 chosen 과 rejected 를 정하므로 쌍이 가르치는 것도 숫자와 낱말 몇 개입니다. 6쌍의 글자 수 차이는 평균 +0.2자라 길이와는 거의 상관이 없습니다.

판정자는 카피를 채점하는 모델입니다. 판정자 쌍은 게이트를 둘 다 지난 카피 2개를 판정자에게 나란히 보이고 나은 쪽을 고르게 한 쌍입니다. 이렇게 두 카피를 나란히 놓고 고르는 방식을 짝비교라고 부르며 26주째 [LLM-as-a-Judge](post.html?id=llm-as-a-judge) 편에서 처음 보았습니다. 이 글의 판정자 쌍 8개는 늘 긴 카피를 고르는 판정자를 흉내 낸 가상 쌍이라 chosen 이 rejected 보다 평균 14.4자 깁니다. 두 카피 모두 게이트를 지나 숫자 일치와 최상급이 같으므로 이 쌍은 길이를 가르칩니다.

```python
print(f'후보 {len(COPY_POOL)}개, 선호 쌍 {len(PREF_PAIRS)}개')
for s in SOURCES:
    diffs = [POOL[w][2] - POOL[l][2] for pid, w, l, src in PREF_PAIRS if src == s]
    print(f'{s} {len(diffs)}쌍, chosen - rejected 글자 수 평균 {sum(diffs) / len(diffs):+.1f}')


# 3단계: 쌍마다 margin, 손실, 무게를 센다
# margin 은 β × ((정책 chosen - 참조 chosen) - (정책 rejected - 참조 rejected)) 다. 두 괄호가 두 카피의 로그 비율이다.
# 손실은 -log σ(margin), 무게는 σ(-margin) 이다. 무게는 이 쌍의 기울기에 곱해지는 몫이다.
def dpo_numbers(pol_w, pol_l, ref_w, ref_l, beta=0.1):
    margin = beta * ((pol_w - ref_w) - (pol_l - ref_l))
    return margin, softplus(-margin), sigmoid(-margin)

    m, loss, wt = dpo_numbers(cw[6], cl[6], cw[5], cl[5], beta=BETA)
    rows.append((pid, m, loss, wt))
    print(f'{pid} {src} {w}>{l} 정책 {cw[6]:.1f} {cl[6]:.1f} 참조 {cw[5]:.1f} {cl[5]:.1f} margin {m:+.3f} 손실 {loss:.3f} 무게 {wt:.3f}')

# 5단계: 평균 손실과 margin 이 음수인 쌍을 본다
# margin 이 음수면 정책이 참조 모델보다 rejected 쪽으로 더 기운 쌍이다.
neg = [r[0] for r in rows if r[1] < 0]

# 정책과 참조 모델의 표는 그대로 두고 β 만 바꾼다. 무게는 5단계의 margin 음수 쌍과 나머지로도 나눠 평균을 낸다.

          f'평균 무게 {sum(v[2] for v in nums.values()) / len(nums):.3f} '
          f'(음수 {len(weights_neg)}쌍 {sum(weights_neg) / len(weights_neg):.3f}, '
```

## 3. 로그 확률 4개로 세는 DPO 손실

**쌍 하나의 DPO 손실은 정책과 참조 모델이 chosen 과 rejected 에 준 로그 확률 4개로 셉니다. 카피마다 정책의 값에서 참조 모델의 값을 빼면 로그 비율(정책이 참조 모델보다 그 카피를 더 쓰게 된 정도) 2개가 되고 두 로그 비율의 차이에 β 를 곱한 margin 이 손실과 무게를 정합니다.**

DPO 가 쌍 하나를 얼마나 세게 밀지는 정책이 참조 모델에서 출발해 chosen 과 rejected 가운데 어느 쪽으로 더 움직였는지에 달려 있습니다. 아래에서는 그 움직임을 로그 확률 4개로 세는 차례를 d02 의 값으로 한 단계씩 따라갑니다.

로그 비율은 정책의 로그 확률에서 참조 모델의 로그 확률을 뺀 값입니다. 로그의 차이는 비율의 로그와 같으므로 두 모델이 그 카피에 준 확률의 비율에 로그를 취한 값이기도 합니다. 로그 비율이 0 보다 크면 정책이 참조 모델보다 그 카피를 더 쓰게 되었다는 뜻입니다. margin 은 chosen 의 로그 비율에서 rejected 의 로그 비율을 빼고 β 0.1 을 곱한 값이라, 정책이 참조 모델에서 출발해 rejected 보다 chosen 쪽으로 더 움직였으면 양수이고 chosen 보다 rejected 쪽으로 더 움직였으면 음수입니다.

σ 는 어떤 값이든 0 과 1 사이의 값으로 바꾸는 시그모이드 함수입니다. 0 을 넣으면 0.5 가 나오고 큰 값을 넣을수록 1 에 가까워집니다. 손실은 -log σ(margin) 이므로 margin 이 0 이면 -log 0.5 인 0.693 입니다. margin 이 클수록 σ(margin) 이 1 에 가까워져 손실은 0 에 가까워집니다. 무게는 σ(-margin) 이라 margin 이 음수면 σ 안에 양수가 들어가 0.5 보다 큽니다.

보상은 카피가 얼마나 좋은지 매긴 점수입니다. DPO 논문은 β × 로그 비율을 정책과 참조 모델이 정하는 암묵적 보상이라고 불렀습니다. DPO 는 카피마다 점수를 내는 보상 모델을 따로 학습하지 않고 정책의 로그 확률로 두 카피의 보상 차이를 셉니다.

d02 는 게이트 쌍으로 chosen 이 c03(「밑창 전체에 쿠션 폼을 깐 입문자용 러닝화」), rejected 가 최상급 카피 c09 입니다. c03 의 로그 비율은 정책 -16.4 에서 참조 -18.3 을 뺀 +1.9 이고 c09 의 로그 비율은 정책 -14.0 에서 참조 -16.7 을 뺀 +2.7 이라, 정책은 두 카피를 모두 참조 모델보다 더 쓰게 되었지만 최상급 카피 c09 쪽으로 더 움직였습니다. 그래서 두 로그 비율의 차이는 +1.9 에서 +2.7 을 뺀 -0.8 이고 여기에 β 0.1 을 곱한 margin 은 -0.080 입니다. 손실 -log σ(-0.080) 은 margin 이 0 일 때의 0.693 보다 큰 0.734 이고 무게 σ(-margin) 은 0.5 보다 큰 0.520 입니다.

d07 은 판정자 쌍으로 chosen 이 c04(「한 짝 240g 에 쿠션 폼을 깐, 처음 달리는 사람을 위한 러닝화」), rejected 가 그보다 짧은 c01(「입문자용 러닝화 런솔 라이트」)입니다. 정책이 rejected c01 에 준 로그 확률 -16.7 이 chosen c04 의 -17.4 보다 높아 정책은 rejected 쪽을 더 높은 확률로 씁니다. 그래도 margin 의 부호는 정책이 어느 카피를 더 쓰는지가 아니라 참조 모델에서 어느 쪽으로 더 움직였는지를 말합니다. c04 의 로그 비율은 정책 -17.4 에서 참조 -20.5 를 뺀 +3.1 로 c01 의 +1.4(정책 -16.7, 참조 -18.1)보다 크므로, 차이 +1.7 에 β 0.1 을 곱한 d07 의 margin 은 +0.170 입니다.

표에서 d01 과 d16 은 정책이 참조 모델보다 chosen c02 를 더 쓰고(로그 비율 +2.6) rejected 는 덜 쓰는(-1.6 과 -2.1) 쌍이라, 두 로그 비율의 차이 +4.2 와 +4.7 에 β 를 곱한 margin 이 +0.420 과 +0.470 으로 큽니다. 그래서 손실은 0.693 보다 작은 0.505 와 0.486 입니다. d08 은 판정자 쌍인데 rejected c02 의 로그 비율이 +2.6 으로 chosen c05 의 +2.3 보다 조금 커서 차이 -0.3 에 β 를 곱한 margin 이 -0.030 입니다.

## 4. 틀린 쌍을 더 세게 미는 기울기와 β

**DPO 의 기울기에는 쌍마다 무게 σ(-margin) 이 곱해집니다. 정책이 rejected 쪽으로 더 움직인 쌍(틀린 쌍)은 margin 이 음수라 무게가 0.5 보다 커서 더 세게 밀립니다. β 를 키우면 margin 의 크기가 β 에 비례해 커지므로 틀린 쌍과 나머지 쌍의 무게 차이가 더 벌어집니다.**

무게를 빼고 모든 쌍을 같은 몫으로 밀면 margin 이 이미 양수인 쌍도 틀린 쌍만큼 밀립니다. DPO 논문은 이렇게 무게를 뺀 단순한 방법이 언어 모델을 망가뜨릴 수 있다고 적었습니다.

쌍 하나의 기울기는 chosen 의 로그 확률을 올리고 rejected 의 로그 확률을 내리는 방향이며 그 크기에 β 와 무게 σ(-margin) 이 곱해집니다. DPO 논문은 이 무게를 암묵적 보상이 쌍의 순서를 얼마나 틀리게 매기는지로 풀었습니다. 암묵적 보상이 rejected 를 chosen 보다 높게 매길수록 margin 이 더 작은 음수가 되어 무게가 1 에 가까워집니다.

β 0.1 에서 margin 이 음수인 쌍은 d02, d05, d08, d20 4개입니다. d02, d05, d20 은 rejected 가 모두 최상급 카피 c09 인데, 가상 정책 표에서 c09 의 로그 비율 +2.7 이 세 쌍의 chosen c03, c01, c05 의 로그 비율 +1.9, +1.4, +2.3 보다 커서 margin 이 음수가 되었습니다. d08 은 3절에서 본 대로 정책이 rejected c02 쪽으로 조금 더 움직인 판정자 쌍입니다. 이 4쌍의 무게 평균은 0.517 로 나머지 16쌍의 0.441 보다 커서 같은 β 와 학습률에서도 틀린 쌍이 더 세게 밀립니다. 20쌍의 평균 손실은 0.613 입니다.

β 는 margin 을 셀 때 곱해지므로 같은 정책 표에서도 β 를 키우면 margin 의 크기가 β 에 비례해 커지고 σ(-margin) 은 0.5 에서 더 멀어집니다. 그래서 β 0.01 에서는 margin 이 0 에 가까워 margin 음수 4쌍과 나머지 16쌍의 무게 평균이 0.502 와 0.494 로 거의 같은데, β 1.0 에서는 0.662 와 0.154 로 벌어집니다. 블록 2 의 6단계가 β 값 4개로 같은 20쌍을 다시 셉니다.

| β | 평균 손실 | 평균 무게 | margin 음수 4쌍(d02, d05, d08, d20)의 무게 | 나머지 16쌍의 무게 |
|---|---|---|---|---|
| 0.01 | 0.684 | 0.496 | 0.502 | 0.494 |
| 0.1 | 0.613 | 0.457 | 0.517 | 0.441 |
| 0.5 | 0.431 | 0.325 | 0.586 | 0.260 |
| 1.0 | 0.370 | 0.256 | 0.662 | 0.154 |

학습률은 모든 쌍의 걸음을 같은 배수로 키우거나 줄이지만 β 는 모든 쌍의 기울기 앞에 곱해지는 데다 시그모이드 안에도 들어가므로, 쌍 사이의 무게 차이까지 바꿉니다. 평균 손실도 β 에 따라 0.684 에서 0.370 까지 달라지므로 β 가 다른 실행끼리는 손실 값을 서로 비교하지 않습니다. DPO 논문은 β 를 정책이 참조 모델에서 얼마나 벗어날지 정하는 값으로 두었습니다. 실험에서는 따로 적지 않으면 β 0.1 을 썼습니다.

## 5. 오래 학습하면 떨어지는 통과율과 체크포인트

**피처 3개(카피의 글자 수, 숫자 일치, 최상급)의 가중치를 DPO 로 300걸음 학습하자 손실은 0.693 에서 0.354 로 한 번도 오르지 않고 줄었습니다. 그런데 통과율(게이트를 모두 지나는 카피가 나올 확률)은 50걸음에 0.597 로 가장 높았다가 300걸음에 0.008 이 되었는데, 늘 긴 카피를 chosen 으로 둔 판정자 쌍이 글자 수 가중치를 키워 확률이 쌍에 없는 긴 카피 c06, c07 로 옮겨 갔기 때문입니다.**

손실이 줄면 학습이 잘되고 있다고 보기 쉽지만 DPO 의 손실은 쌍 20개의 margin 만 봅니다. 그래서 도입의 물음 가운데 「언제 멈춰야 할까요?」는 손실만으로 답할 수 없습니다. 블록 3 은 학습을 직접 돌리며 손실과 함께 통과율을 찍습니다.

2절과 3절의 정책 열은 DPO 를 조금 돌린 정책을 흉내 낸 가상 표였지만 블록 3 은 그 표를 쓰지 않고 참조 모델에서 다시 시작해 직접 학습합니다. 피처 φ 는 카피를 숫자로 나타낸 값 3개로, 글자 수를 10 으로 나눈 값, 숫자 일치(카피의 숫자가 모두 자산에 있으면 1), 근거 없는 최상급(있으면 1)입니다. 가중치 θ 는 피처마다 하나씩 있는 글자 수 가중치, 숫자 일치 가중치, 최상급 가중치 3개입니다. 정책이 카피마다 매기는 점수는 참조 로그 확률에 θ 와 φ 를 피처마다 곱해 더한 내적 `dot(θ, φ)` 를 더한 값입니다. 그래서 θ = 0 인 시작점에서 정책은 참조 모델과 같습니다. 글자 수 가중치가 양수면 긴 카피일수록 점수가 오르고 최상급 가중치가 음수면 최상급 카피의 점수가 내려갑니다. 확률은 이 점수를 후보 12개 안에서만 소프트맥스로 나눈 값이라 실제 모델이 모든 카피에 두는 확률과 다릅니다.

피처 차이 Δφ 는 쌍마다 chosen 의 피처에서 rejected 의 피처를 뺀 값입니다. 정책의 점수에 든 참조 로그 확률은 로그 비율을 셀 때 빠지고 두 카피에 똑같이 붙는 log Z 는 두 로그 비율의 차이에서 지워지므로, 쌍 하나의 margin 은 Δφ 만 남은 β `dot(θ, Δφ)` 입니다. 블록은 손실을 줄이는 방향으로 θ 를 학습률 2.0 으로 300걸음 옮기면서 25걸음마다 체크포인트를 남깁니다. 체크포인트는 학습 중간의 가중치를 저장해 둔 것이라 나중에 그 걸음의 θ 로 되돌릴 수 있습니다.

통과율은 정책이 카피를 하나 쓸 때 통과 후보(c01 부터 c05 까지)가 나올 확률의 합입니다. 카피를 뽑아서 센 값이 아니라 후보 12개에 둔 확률로 센 기댓값이며 0걸음에는 0.255 입니다. 평균 글자 수도 같은 확률로 셉니다. KL 발산(KL divergence)은 정책의 확률이 참조 모델에서 얼마나 멀어졌는지 측정하는 값으로 두 확률이 같으면 0 이고 멀어질수록 커집니다.

블록 3 은 이 학습을 돌려 25걸음마다 손실, θ, 통과율, c06 과 c07 의 확률 합, 평균 글자 수, KL 을 찍은 뒤 판정자 쌍을 뺀 12쌍으로도 다시 학습해 비교합니다. 마지막 6단계는 6절에서 쓸 LoRA 의 가중치 수를 셉니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 참조 모델에서 다시 시작해 가중치 셋을 DPO 로 300걸음 학습하며, 손실과 통과율(후보 12개에 둔 확률로 센 기댓값)을 25걸음마다 찍는다.

# 1단계: 피처, 통과 후보, 쌍의 피처 차이를 둔다
# 피처 φ 는 (글자 수 / 10, 숫자 일치, 근거 없는 최상급) 이다. 통과는 게이트 셋(40자 이하, 숫자 일치 1, 최상급 0)을 모두 지난 것이다.
# 쌍마다 Δφ = φ(chosen) - φ(rejected) 를 두고, 출처별과 전체와 판정자 쌍을 뺀 12쌍의 평균을 낸다. 학습은 이 Δφ 만 본다.
def phi(c):
    return (c[2] / 10, c[3], c[4])


def dot(a, b):
    return sum(x * y for x, y in zip(a, b))


PASS = [c[0] for c in COPY_POOL if c[2] <= 40 and c[3] == 1 and c[4] == 0]
WINNERS = sorted({w for pid, w, l, src in PREF_PAIRS})
DELTA = {pid: tuple(a - b for a, b in zip(phi(POOL[w]), phi(POOL[l]))) for pid, w, l, src in PREF_PAIRS}
print('통과(40자 이하, 숫자 일치 1, 최상급 0) 후보 ' + ', '.join(PASS) + ' / chosen 으로 나온 후보 ' + ', '.join(WINNERS))
for cid in ('c06', 'c07'):
    c = POOL[cid]
    seen = sum(cid in (w, l) for pid, w, l, src in PREF_PAIRS)
    print(f'{cid}: {c[2]}자, 숫자 일치 {c[3]}, 최상급 {c[4]}, 쌍에 나온 수 {seen}')
groups = {s: [p[0] for p in PREF_PAIRS if p[3] == s] for s in SOURCES}
groups['전체'] = [p[0] for p in PREF_PAIRS]
groups['판정자 쌍 뺌'] = [p[0] for p in PREF_PAIRS if p[3] != 'judge']
for name, ids in groups.items():
    print(f'Δφ 평균 {name} {len(ids)}쌍 (' + ', '.join(f'{sum(DELTA[i][j] for i in ids) / len(ids):+.3f}' for j in range(3)) + ')')


# 2단계: 정책, 손실, 기울기를 둔다
# 정책은 「참조 로그 확률 + dot(θ, φ)」를 후보 12개 안에서만 소프트맥스로 나눈 확률이다. θ = 0 이면 참조 모델과 같다.
# 쌍 하나의 margin 은 β dot(θ, Δφ) 다. 두 후보를 나누는 log Z 가 같아 쌍 안에서 지워진다.
# 손실을 줄이는 방향은 쌍 20개 평균 β σ(-β dot(θ, Δφ)) Δφ 이고, 여기에 학습률 2.0 을 곱해 θ 를 옮긴다.
def policy(theta):
    return probs({c[0]: c[5] + dot(theta, phi(c)) for c in COPY_POOL})


def loss_of(theta):
    return sum(softplus(-BETA * dot(theta, d)) for d in DELTA.values()) / len(DELTA)


def direction(theta):
    return [sum(BETA * sigmoid(-BETA * dot(theta, d)) * d[j] for d in DELTA.values()) / len(DELTA) for j in range(3)]


REF = policy((0.0, 0.0, 0.0))


# 3단계: 300걸음을 가며 25걸음마다 체크포인트를 남긴다
# 통과율과 평균 글자 수는 후보 12개에 둔 확률로 센 기댓값이다. KL 은 Σ 정책 × log(정책 / 참조) 다.
# 맞힌 쌍은 margin 이 0 보다 큰 쌍이다. 손실은 체크포인트가 아닌 걸음까지 모두 적어 둔다.
def checkpoint(step, theta):
    pi = policy(theta)
    return {'step': step, 'theta': tuple(theta), 'loss': loss_of(theta),
            'pass': sum(pi[k] for k in PASS), 'long': pi['c06'] + pi['c07'],
            'chars': sum(pi[c[0]] * c[2] for c in COPY_POOL),
            'kl': sum(pi[k] * math.log(pi[k] / REF[k]) for k in pi),
            'right': sum(dot(theta, d) > 0 for d in DELTA.values()), 'top': max(pi, key=pi.get)}


theta = [0.0, 0.0, 0.0]
losses, saved = [], []
for step in range(301):
    losses.append(loss_of(theta))
    if step % 25 == 0:
        saved.append(checkpoint(step, theta))
    if step < 300:
        theta = [t + 2.0 * g for t, g in zip(theta, direction(theta))]
print('φ = (글자 수 / 10, 숫자 일치, 최상급), 학습률 2.0 으로 300걸음, 25걸음마다 체크포인트')
print('열: 걸음, 손실, θ(글자, 숫자, 최상급), 통과율, c06+c07 확률, 평균 글자 수, KL, 확률이 가장 큰 후보')
for s in saved:
    a, b, c = s['theta']
    print(f"{s['step']:3d} 손실 {s['loss']:.3f} θ {a:+.2f} {b:+.2f} {c:+.2f} 통과율 {s['pass']:.3f} "
          f"c06+c07 {s['long']:.3f} 글자 {s['chars']:.1f} KL {s['kl']:.2f} {s['top']}")
print(f'손실이 앞 걸음보다 줄지 않은 걸음 {sum(b >= a for a, b in zip(losses, losses[1:]))}개 (300걸음 가운데)')

# 4단계: 통과율이 가장 높은 체크포인트로 되돌린다
# 체크포인트 13개 가운데 통과율이 가장 높은 것을 고른다. 통과율이 같으면 앞의 것을 둔다. 고른 θ 를 theta 에 다시 넣고 통과율을 다시 센다.
best = saved[0]
for s in saved[1:]:
    if s['pass'] > best['pass']:
        best = s
for s in (best, saved[-1]):
    print(f"{s['step']}걸음: 통과율 {s['pass']:.3f}, 손실 {s['loss']:.3f}, 맞힌 쌍 {s['right']}/{len(DELTA)}, KL {s['kl']:.2f}")
theta = list(best['theta'])
restored = policy(theta)
print(f"{best['step']}걸음의 θ (" + ', '.join(f'{v:+.2f}' for v in theta) + ') 로 되돌렸다. '
      f"되돌린 θ 의 통과율 {sum(restored[k] for k in PASS):.3f}, 손실 {loss_of(theta):.3f}")

# 5단계: 글자 수 가중치를 출처별로 나누고, 판정자 쌍을 뺀 12쌍으로 다시 학습한다
# train 은 3단계와 같은 식과 차례로 θ 를 300걸음 옮기고, 걸음마다 글자 수 칸에 더한 양을 쌍의 출처별로 모은다.
# 쌍 20개로 돌리면 3단계의 300걸음 θ 와 같은 θ 가 나온다. NO_JUDGE 는 PREF_PAIRS 에서 판정자 쌍 8개를 뺀 새 목록이다.
def train(pairs, steps=300):
    th, share = [0.0, 0.0, 0.0], {s: 0.0 for s in SOURCES}
    for _ in range(steps):
        push = {pid: BETA * sigmoid(-BETA * dot(th, DELTA[pid])) for pid, w, l, src in pairs}
        for pid, w, l, src in pairs:
            share[src] += 2.0 * (push[pid] * DELTA[pid][0] / len(pairs))
        th = [t + 2.0 * (sum(push[pid] * DELTA[pid][j] for pid, w, l, src in pairs) / len(pairs)) for j, t in enumerate(th)]
    return th, share


th20, share = train(PREF_PAIRS)
print('쌍 20개로 다시 돌린 θ (' + ', '.join(f'{v:+.2f}' for v in th20) + f") 는 3단계의 300걸음 θ 와 같은가 {tuple(th20) == saved[-1]['theta']}")
print(f'글자 수 가중치 {th20[0]:+.2f} 의 출처별 몫 ' + ', '.join(f'{s} {share[s]:+.2f}' for s in SOURCES))
NO_JUDGE = [p for p in PREF_PAIRS if p[3] != 'judge']
th12, _ = train(NO_JUDGE)
pi12 = policy(th12)
print(f'판정자 쌍을 뺀 {len(NO_JUDGE)}쌍으로 300걸음 θ (' + ', '.join(f'{v:+.2f}' for v in th12) + f'), '
      f"통과율 {sum(pi12[k] for k in PASS):.3f}, c06+c07 {pi12['c06'] + pi12['c07']:.3f}, 확률이 가장 큰 후보 {max(pi12, key=pi12.get)}")

# 6단계: LoRA 가 학습할 가중치 수를 센다
# LoRA 는 d × k 행렬 W0 를 고정하고 B(d × r) 와 A(r × k) 만 학습한다. 행렬 하나에서 학습할 수는 r × (d + k) 다.
D = K = 4096
print(f'{D} × {K} 행렬 하나의 가중치 {D * K:,}개')
for r in (4, 8, 16):
    n = r * (D + K)
    print(f'r {r}: {r} × ({D} + {K}) = {n:,}개, 행렬의 {n / (D * K):.2%}')
print(f'이 블록이 학습한 가중치 {len(theta)}개 (θ 의 글자, 숫자, 최상급)')
# 출력:
# 1단계 뜻: 통과 후보는 chosen 으로 나온 후보와 같고, c06 과 c07 은 쌍에 없으며, Δφ 의 글자 수 칸은 판정자 쌍만 크게 양수다.
# 통과(40자 이하, 숫자 일치 1, 최상급 0) 후보 c01, c02, c03, c04, c05 / chosen 으로 나온 후보 c01, c02, c03, c04, c05
# c06: 49자, 숫자 일치 1, 최상급 0, 쌍에 나온 수 0
# c07: 43자, 숫자 일치 1, 최상급 0, 쌍에 나온 수 0
# Δφ 평균 gate 6쌍 (+0.017, +0.667, -0.500)
# Δφ 평균 judge 8쌍 (+1.438, +0.000, +0.000)
# Δφ 평균 edit 6쌍 (-0.383, +0.500, -0.833)
# Δφ 평균 전체 20쌍 (+0.465, +0.350, -0.400)
```

## 6. 고칠 가중치를 줄이는 LoRA

**LoRA 는 원래 행렬을 고정하고 작은 행렬 2개의 곱만 학습해 더하므로 고칠 가중치가 줄어듭니다. 4096 × 4096 행렬 하나에서 작은 행렬의 크기를 정하는 r 이 4, 8, 16 이면 학습할 가중치는 32,768개, 65,536개, 131,072개로 행렬 전체의 0.20%, 0.39%, 0.78% 입니다.**

이미 학습한 모델을 새 일에 맞춰 더 학습하는 것을 파인튜닝이라고 부르며 SFT 와 DPO 도 파인튜닝입니다. 블록 3 은 참조 모델의 로그 확률을 고정하고 θ 3개만 학습했지만 실제 언어 모델은 가중치가 행렬 단위로 모여 있어서 4096 × 4096 행렬 하나만 해도 가중치가 16,777,216개입니다. 기울기로 가중치를 옮기는 옵티마이저가 Adam 이면 모든 가중치를 고칠 때 가중치마다 Adam 의 상태도 메모리에 둡니다. 고친 모델을 저장할 때도 원래 모델만큼의 크기가 듭니다.

LoRA(Low-Rank Adaptation)는 원래 행렬 W0 를 고정하고 그 변화를 행렬 2개의 곱 BA 로 적어 B 와 A 만 학습합니다. 논문은 W0 가 d × k 일 때 B 를 d × r, A 를 r × k 로 두었는데, r 은 B 의 열 수이자 A 의 행 수이며 d 와 k 보다 훨씬 작게 잡았습니다. A 는 무작위 가우시안(정규분포에서 뽑은 값), B 는 0 으로 시작하므로 학습을 시작할 때 BA 는 0 입니다. 그래서 첫 걸음의 모델은 원래 모델과 같습니다. 학습은 내내 B 와 A 만 고칩니다.

행렬 하나에서 학습할 가중치 수는 B 의 d × r 개와 A 의 r × k 개를 더한 r × (d + k) 입니다. 4096 × 4096 행렬에서 r 이 8 이면 8 × (4096 + 4096) = 65,536개로 행렬 전체 16,777,216개의 0.39% 입니다. 이 수는 r 에 비례하므로 r 을 두 배로 늘리면 학습할 가중치 수도 두 배가 됩니다(블록 3 의 6단계).

| r | 학습할 가중치 수 | 4096 × 4096 행렬의 몫 |
|---|---|---|
| 4 | 32,768 | 0.20% |
| 8 | 65,536 | 0.39% |
| 16 | 131,072 | 0.78% |
| 행렬 전체 | 16,777,216 | |
| 블록 3 의 θ | 3 | |

논문은 GPT-3 175B 를 Adam 으로 파인튜닝할 때와 비교해 학습 가중치 수는 10,000배, GPU 메모리는 3배 줄일 수 있다고 적었습니다. 같은 GPT-3 175B 에서 학습 중 GPU 메모리(VRAM)는 1.2TB 에서 350GB 로 줄었고 체크포인트는 350GB 에서 35MB 로 약 10,000배 작아졌다고 적었습니다. 체크포인트 크기의 수치는 r 4 로 셀프 어텐션의 행렬 4개 가운데 query 와 value 2개만 바꾼 조건입니다. 블록의 0.39% 는 행렬 하나에서 센 몫이고 논문의 수치는 모델 전체에서 측정한 값이라 두 값은 따로 읽습니다.

LoRA 는 손실이 아니라 어느 가중치를 고칠지를 바꾸므로 SFT 의 손실도 DPO 의 손실도 그대로 쓰고 그 기울기로 B 와 A 만 고칩니다. 블록 3 도 같은 방식으로 참조 모델의 값을 고정하고 θ 만 고쳤습니다. 논문은 배포한 뒤에도 B 와 A 만 바꿔 끼워 다른 과제로 옮길 수 있다고 적었습니다.

## 7. 두 무대에서 쌍을 모으는 곳

**SFT 와 DPO 의 셈은 광고가 나가는 두 무대에서 같지만 선호 쌍의 출처 3곳을 한 회사 안에 모을 수 있는지는 무대마다 다릅니다. 한 회사가 지면까지 가진 담장 안은 광고주 편집과 심사 결과가 같은 회사에 쌓이는데, 여러 회사가 실시간 경매로 지면을 사고파는 열린 RTB 에서는 광고를 사는 DSP 가 지면을 가진 매체의 심사 결과를 받지 못할 수 있습니다.**

한 회사가 서비스와 광고 서버를 다 가진 곳을 담장 안이라고 부릅니다. 여러 회사가 실시간 경매(RTB, real-time bidding)로 남의 지면에 광고를 사고파는 곳은 열린 RTB 라고 부릅니다. 두 무대의 이름은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에서 처음 풀었습니다. 1~6절의 셈은 어느 무대에서나 같으므로, 아래 두 절은 2절의 쌍 출처 3곳 가운데 어디까지를 한 회사 안에서 모을 수 있는지만 봅니다.

### 담장 안: 한 회사에 모이는 쌍의 출처 3곳 [무대: 닫힌 생태계]

담장 안의 플랫폼은 카피를 만들어 게이트와 판정자에 넣은 뒤 자기 지면에 노출합니다. 광고주가 카피를 고친 기록과 심사에서 빠진 카피도 같은 회사에 쌓이므로 게이트 쌍, 판정자 쌍, 편집 쌍을 한 곳에서 모으고 쌍마다 출처를 적어 둘 수 있습니다. 출처를 적어 두면 2절의 출처별 글자 수 차이처럼 쌍이 가르치는 버릇도 학습 전에 셀 수 있습니다.

### 열린 RTB: 줄어드는 쌍의 출처 [무대: 열린 RTB]

DSP(광고주 편에서 입찰로 지면을 사는 플랫폼)는 카피를 만들고 판정한 뒤 입찰 응답에 담아 보내므로 게이트 쌍과 판정자 쌍은 DSP 안에서 만들 수 있습니다. 다만 36주째 [생성 문구 판정 체계](post.html?id=generated-copy-judging-system) 편에서 본 것처럼 매체(지면을 가진 회사) 쪽의 심사 결과는 DSP 에 오지 않을 수 있습니다. 그러면 심사에서 빠진 카피로 쌍을 만들기 어렵습니다. 판정자 쌍의 몫이 커지면 5절에서 판정자 쌍이 글자 수 가중치를 키웠듯이 판정자의 버릇이 학습에 더 크게 들어갈 수 있습니다.

| β | 무게 차이 | β 1.0 에서 0.662 와 0.154 |
| 과최적화 | 300걸음의 손실과 통과율 | 손실 0.693 → 0.354, 통과율 0.255 → 0.597 → 0.008 |
| 판정자 쌍의 몫 | 글자 수 가중치의 출처별 몫, 빼고 다시 학습 | 판정자 +11.67, 게이트 -0.48, 편집 -4.12, 12쌍이면 통과율 1.000 |
| 되돌리기 | 통과율이 가장 높은 체크포인트 | 50걸음, θ (+2.01, +1.66, -1.90) |
| LoRA | r × (d + k) | r 8 이면 65,536개, 0.39% |

## 헷갈리기 쉬운 점

- **DPO 손실이 줄어도 카피가 좋아진 것은 아닙니다.** 손실은 쌍 20개의 margin 만 보고 쌍에 없는 카피의 확률은 보지 않으므로, 블록 3 의 손실은 300걸음 가운데 한 번도 오르지 않았는데도 통과율은 50걸음 뒤로 떨어졌습니다. 그래서 체크포인트는 손실이 아니라 통과율처럼 따로 측정한 값으로 고릅니다.
- **DPO 는 chosen 의 확률을 올리는 것이 아니라 두 로그 비율의 차이를 벌립니다.** 블록 3 에서 chosen 으로 나온 후보는 c01 부터 c05 까지로 통과 후보 5개와 같습니다. 그런데 300걸음에 맞힌 쌍이 20/20 이 되는 사이 쌍에 없는 c06 과 c07 이 확률을 가져가서 5개의 확률 합인 통과율은 0.255 에서 0.008 로 줄었습니다.
- **β 는 학습률이 아닙니다.** 학습률은 모든 쌍의 걸음을 같은 배수로 바꾸지만 β 는 기울기 앞에 곱해지는 데다 시그모이드 안에서 margin 까지 바꾸므로, β 1.0 에서는 margin 음수 4쌍의 무게가 0.662, 나머지가 0.154 로 벌어집니다. 평균 손실도 β 에 따라 0.684 에서 0.370 까지 달라져서 β 가 다른 실행끼리는 손실을 비교하지 않습니다.

## 더 깊이 보기

:::deep DPO 손실과 기울기의 식
DPO 논문의 식 7 은 선호 쌍 데이터셋 $\mathcal{D}$ 에 대한 기댓값으로 손실을 적습니다. 프롬프트는 $x$, chosen 은 $y_w$, rejected 는 $y_l$ 입니다. 정책은 $\pi_\theta$, 참조 모델은 $\pi_{\mathrm{ref}}$ 로 적습니다. 아래 첫 식이 쌍 하나의 항이고 둘째 식이 식 7 입니다.

$$\ell(x, y_w, y_l) = -\log \sigma\left(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\mathrm{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\mathrm{ref}}(y_l \mid x)}\right)$$

$$\mathcal{L}_{\mathrm{DPO}} = \mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}}\big[\ell(x, y_w, y_l)\big]$$

괄호 안이 블록의 margin 이고 블록 2 와 3 은 쌍 20개의 항을 평균합니다. 논문은 아래의 $\hat r_\theta$ 를 암묵적 보상이라 부르고 4절에서 기울기를 그 아래처럼 적었습니다.

$$\hat r_\theta(x, y) = \beta \log \frac{\pi_\theta(y \mid x)}{\pi_{\mathrm{ref}}(y \mid x)}$$

$$\nabla_\theta \mathcal{L}_{\mathrm{DPO}} = -\beta\, \mathbb{E}\Big[\sigma\big(\hat r_\theta(x, y_l) - \hat r_\theta(x, y_w)\big)\big(\nabla_\theta \log \pi_\theta(y_w \mid x) - \nabla_\theta \log \pi_\theta(y_l \mid x)\big)\Big]$$

σ 항이 블록의 무게 σ(-margin) 이고 암묵적 보상이 rejected 를 더 높게 매길수록 커집니다. 블록 3 의 정책은 아래와 같아서 margin 을 세면 $\log Z(\theta)$ 가 쌍 안에서 지워집니다.

$$\log \pi_\theta(c) = \log \pi_{\mathrm{ref}}(c) + \mathrm{dot}(\theta, \phi(c)) - \log Z(\theta)$$

그래서 margin 은 β dot(θ, Δφ) 입니다. 손실을 줄이는 방향은 쌍마다 β σ(-β dot(θ, Δφ)) Δφ 를 구해 평균한 값입니다.
:::

:::deep SFT 손실과 토큰 점수의 기울기
SFT 의 손실은 chosen 의 음의 로그 확률 $-\log \pi(y_w)$ 입니다. 유니그램에서 토큰 $k$ 의 확률은 로짓 $z_k$ 로 아래처럼 적고 카피 $y$ 의 로그 확률은 그 아래입니다.

$$p_k = \frac{e^{z_k}}{Z}, \qquad Z = \sum_j e^{z_j}$$

$$\log \pi(y) = \sum_{t \in y} z_t - |y| \log Z$$

$n_k(y)$ 는 카피 $y$ 에 토큰 $k$ 가 든 횟수, $|y|$ 는 카피의 토큰 수입니다. 로그 확률을 로짓 $z_k$ 로 미분하면 아래가 나옵니다.

$$\frac{\partial \log \pi(y)}{\partial z_k} = n_k(y) - |y|\, p_k$$

SFT 한 걸음은 이 값에 학습률 $\eta$ 를 곱해 더하고 블록의 $\eta$ 는 0.5 입니다. DPO 한 걸음에서 토큰 $k$ 의 로짓이 움직이는 양은 아래이고 블록의 $\eta$ 는 5.0, $m$ 은 margin 입니다.

$$\eta\, \beta\, \sigma(-m) \Big[\big(n_k(y_w) - n_k(y_l)\big) - \big(|y_w| - |y_l|\big)\, p_k\Big]$$

두 카피의 토큰 수가 같으면 둘째 항이 0 이 되고 두 카피에 같은 횟수로 든 토큰은 첫째 항도 0 입니다.
:::

:::deep LoRA 의 식
LoRA 논문의 식 3 은 원래 행렬 $W_0$ 를 지나는 입력 $x$ 의 출력을 아래처럼 적습니다. $W_0$ 는 d × k 행렬입니다.

$$h = W_0 x + \Delta W x = W_0 x + B A x, \qquad B \in \mathbb{R}^{d \times r},\ A \in \mathbb{R}^{r \times k}$$

학습하는 동안 $W_0$ 는 기울기를 받지 않고 $A$ 와 $B$ 만 고칩니다. 논문은 $\Delta W x$ 에 α / r 을 곱하고 α 는 처음 시도한 r 로 두고 다시 맞추지 않았다고 적었습니다. 학습할 수는 d × r 과 r × k 를 더한 r × (d + k) 이고 d 와 k 가 4096, r 이 8 이면 65,536 입니다. 배포할 때는 $W_0 + BA$ 를 미리 계산해 두어서 추론 지연이 늘지 않는다고 적었습니다.
:::

- Hu, E. J., Shen, Y., Wallis, P., et al. (2021). *LoRA: Low-Rank Adaptation of Large Language Models*. arXiv:2106.09685. [arxiv.org](https://arxiv.org/abs/2106.09685). 사전 학습한 가중치를 고정하고, 층마다 학습할 저랭크 행렬의 곱 BA 를 더하는 방법입니다. A 는 무작위 가우시안, B 는 0 으로 시작해 학습을 시작할 때 BA 는 0 입니다. - Christiano, P., Leike, J., Brown, T. B., et al. (2017). *Deep reinforcement learning from human preferences*. arXiv:1706.03741. [arxiv.org](https://arxiv.org/abs/1706.03741). 사람이 짧은 영상 조각 둘 가운데 나은 쪽을 고르면, 그 선택으로 보상 함수를 배우는 방법입니다. 조각을 고를 확률이 조각에 걸친 예측 보상 합의 지수에 비례한다고 두었고, Bradley-Terry 모델을 따릅니다.
