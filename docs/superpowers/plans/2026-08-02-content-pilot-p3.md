## ⚠ 전역 규칙 (3편 모두, 어기면 리뷰에서 반려)

1. **숫자는 전부 검증한다.** 본문에 등장하는 모든 계산은 (a) 이 계획서의 표에 있는 값이거나 (b) 함께 넣는 파이썬 코드를 **실제로 실행해 얻은 출력**이어야 한다. 어림짐작으로 쓴 숫자 금지. 코드 실행은 `python3 /tmp/.../snippet.py` 로 하고, 출력과 본문 표가 일치하는지 대조해 보고에 붙인다.
2. **파이썬 예제는 표준 라이브러리만** (numpy는 설치돼 있지만 독자가 복붙해 바로 돌리게 하려면 stdlib이 안전하다. `math`·`random`·`collections` 정도만). 시드 고정. 20~60줄.
3. **모든 코드에 상세 주석.** 블록 맨 위에 "이 코드가 뭘 하는지" 2~3줄, 주요 줄마다 무엇을+왜, 마지막에 `# 출력:` 으로 실제 출력 붙이기. 주석이 P1에서 세이지 그린으로 보이니 주석 자체가 설명 본문 역할을 한다.
4. **섹션 규칙**: 모든 `##` 섹션은 **굵은 요약 한 줄 + 상세 2~4문단**. 한두 줄로 끝나는 섹션 금지. 전개 순서는 비유/그림 → 구체 숫자 → 왜 그런가 → 실무에선.
5. **쉬운 말.** 한 문장 = 한 생각. 전문용어는 처음 나올 때 괄호로 풀고, 영어 약어는 풀네임을 한 번은 준다. 콤마로 길게 잇지 말 것.
6. **무대 표기**: 무대가 갈리는 섹션 제목 끝에 `[무대: 열린 RTB]` / `[무대: 닫힌 생태계]` / `[무대: 공통]`. 헤딩당 1개, 제목 없이 마커만 쓰지 말 것.
7. **수식 안에 한글 금지** (`\text{}`로 감싸거나 수식 밖으로). KaTeX 콘솔 경고가 나면 실패로 본다.
8. **데모 임베드 문법은 MARKDOWN_GUIDE.md의 규칙을 정확히 지킬 것** — 블록 앞뒤 빈 줄 필수, 블록 내부 빈 줄 금지, 블록 안에 `$`·`**` 금지.
9. 기존 글의 좋은 관례는 유지: 도입 장면 → `> 한 줄 요약:` → 본문 → 한눈 정리 표 → 헷갈리기 쉬운 점 → 더 깊이 보기. 등장인물(민지)·존댓말/평서문 톤도 그 글의 기존 톤을 따른다.
10. `git`: 브랜치 `feat/p3-content`, identity repo-local `chkimsu`, **push 금지**. 글 1편 = 커밋 1개.

- [ ] **Step 1.6: 함정 — 어트리뷰션 ≠ 진짜 효과 (증분)**

가데이터 홀드아웃 실험 표:

| 그룹 | 사람 수 | 광고 노출 | 구매자 수 | 구매율 |
|---|---|---|---|---|
| 노출군 | 100,000 | O | 2,500 | 2.50% |
| 대조군(홀드아웃) | 100,000 | X | 2,000 | 2.00% |

- 라스트클릭이 광고 공으로 잡는 건 2,500건. 하지만 광고가 없어도 2,000명은 샀다.
- **증분 = 2,500 − 2,000 = 500건.** 광고가 실제로 만든 건 500건인데 회계는 2,500건이라 말한다 — **5배 과대.**
- 증분율(lift) = 500 / 2,000 = **+25%**. iROAS를 계산할 땐 분자에 2,500이 아니라 500을 넣어야 한다.
- 이 숫자로 CPA도 다시 계산해 보인다: 광고비 ₩10,000,000이면 겉보기 CPA = 10,000,000/2,500 = ₩4,000, 증분 CPA = 10,000,000/500 = **₩20,000**. 다섯 배 차이가 예산 결정을 뒤집는다.

- [ ] **Step 2.5: pCVR·무대·함정 섹션**

- `## pCVR — 클릭 다음의 '살 확률'`: 기존 2줄을 확장. 목표가 전환이면 `가치 × pCTR × pCVR`. 여기에 §2.1의 D 광고를 전환 목표로 바꿔 다시 계산해 보이기(전환 가치 ₩30,000, pCVR 0.35% → 노출 1회 기대 ₩30,000×2.8%×0.35% = ₩2.94 → eCPM ₩2,940). **이 값은 검산됨.**
- `## 담장 안의 pCTR [무대: 닫힌 생태계]`: 로그인 데이터로 사람을 알고 시작한다. 지면·소재·유저가 모두 한 회사 것이라 피처가 풍부하고 로그 조인이 깨끗하다. 대신 자기 트래픽 안에서만 배우니 **밖의 분포는 모른다**.
- `## 열린 RTB의 pCTR [무대: 열린 RTB]`: 남의 지면 신호와 쿠키만으로 맞혀야 한다. 요청마다 지면·유저가 바뀌고, 패찰하면 결과를 못 본다(관측 편향). cold start가 상수처럼 따라온다.
- `## 함정 — 보여준 광고만 배운다`: 노출된 것만 로그가 남는다(선택 편향). 안 보여준 광고는 영원히 배울 기회가 없다 → 탐색(exploration)이 필요한 이유. 기존 negative-sampling-bias 글로 연결.

- [ ] **Step 3.2: Waterfall이 흘리는 돈 — 숫자로**

- Waterfall: 1순위 A에게 먼저 묻는다 → ₩1,000으로 바닥값 ₩900을 넘김 → **즉시 팔림.** 뒤의 D(₩1,420)는 아예 물어보지도 않았다.

- 이 손해가 구조적인 이유: 순서는 과거 평균 단가로 정하는데, **지금 이 노출**을 누가 제일 비싸게 살지는 매번 다르다. 순서가 곧 손해다.
- 정직하게 덧붙일 것: 이 예시는 한 번의 극단 케이스이고, 업계에서 보고되는 평균 개선은 +10~30%다.
