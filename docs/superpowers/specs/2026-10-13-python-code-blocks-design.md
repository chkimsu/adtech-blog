# 파이썬 코드 블록 개편 — 하는 일, 단계, 뜻 — 설계

사용자 요청 *"이게 무슨 코드인지, 코드의 각 부분은 뭘 하는지 눈에 잘 안들어와"*, *"단순히 코드를 보여주고 주석을 잘 쓰는것만으로는 안돼"*. 보이는 모양, 쓰는 방식, 그리는 코드와 검사와 옮기는 순서를 차례로 확인받았습니다 (*"응 다섯 다 그대로 가자"*, *"응"*, *"응"*).

확정 시안은 같은 폴더의 두 화면입니다.

| 파일 | 확정안 |
|---|---|
| `2026-10-13-python-code-blocks-mock-width.html` | 2번 「본문 여백까지 넓힘」 |
| `2026-10-13-python-code-blocks-mock-phone.html` | 3번 「화면 끝까지, 줄바꿈」 |

> 시안의 「이 모양으로」 버튼은 고르던 화면의 흔적이라 눌러도 아무 일이 없습니다. 넓은 화면 시안의 휴대폰 규칙(600px 이하에서 옆으로 밀기)은 휴대폰 시안 3번(접기)으로 바뀌었습니다.

---

## 1. 왜 바꾸나

- 지금 파이썬 블록은 코드와 주석이 한 덩어리로 보입니다. 주석은 세이지 그린 기울임꼴이라 코드보다 흐리게 읽힙니다.

- 블록이 하는 일, 어느 줄이 어느 단계인지, 출력 줄이 어느 코드에서 나왔고 무슨 뜻인지를 독자가 직접 맞춰야 합니다.

- 출력은 블록 끝의 `# 출력:` 주석(166개)이거나 블록 바로 아래 별도 블록(58개)에 있습니다. 어느 쪽에도 출력 줄의 뜻을 적는 자리가 없습니다.

- 휴대폰(390px)에서는 코드 줄 폭으로 세어 보면 75% 가 끝이 잘립니다. 휴대폰용 글 칸 여백(24px) 규칙이 스타일 파일 맨 끝의 넓은 화면 값(51.2px)에 덮어써지는 것도 원인입니다.

## 2. 끝났다고 볼 기준

| # | 기준 |
|---|---|
| 1 | 블록 맨 위에서 그 코드가 하는 일을 한 줄로 읽습니다 |
| 2 | 단계마다 번호, 제목, 풀이가 코드 왼쪽에 있습니다. 좁은 화면에서는 코드 위에 있습니다 |
| 3 | 출력 줄마다 그 줄을 찍은 단계 번호와 뜻이 붙어 있습니다. 단계나 출력에 마우스를 올리면 같은 번호끼리 밝아집니다 |
| 4 | 주석이 코드보다 먼저 눈에 들어옵니다. 연한 초록 기울임꼴은 새 블록에 없습니다 |
| 5 | 옆으로 밀어야 보이는 코드 줄과 출력 줄이 없습니다. 선 글자로 그린 그림 블록만 예외입니다 |
| 6 | 코드는 지금처럼 복사해 그대로 돌아갑니다. 적힌 출력은 실제로 돌린 결과와 같고, 검사가 이것을 지킵니다 |

**범위**

- `posts/*.md` 의 파이썬 블록 247개(85편)

- 파이썬이 아닌 블록 166개는 폭과 줄 접기만 바꿉니다. 이 가운데 58개는 파이썬 블록의 출력이라, 옮기면서 그 파이썬 블록 안으로 들어갑니다

**범위 밖**

- 블록 뒤 본문. 출력 숫자를 다시 풀어 쓴 문단도 그대로 둡니다. 출력을 고치는 4개 블록에서 본문에 같은 숫자가 있을 때만 같이 고칩니다

- mermaid 그림, 데모 페이지 안의 코드

- 실행되는 코드 줄 자체. 출력이 적힌 것과 다른 4개 블록은 예외입니다

## 4. 화면

### 4-1. 블록의 짜임

| 자리 | 무엇이 오나 |
|---|---|
| 머리 | 라벨 「이 코드가 하는 일」, 상태 라벨(5-2), 언어 이름, Copy 버튼. 그 아래 하는 일 한 줄을 굵게 |
| 몸통 | 단계마다 한 행. 왼쪽 설명 칸에 번호 배지, 굵은 제목, 풀이. 오른쪽 코드 칸. 첫 단계 앞의 줄(import 등)은 설명 칸이 빈 행 |
| 출력 | 「출력」 탭과 괄호 안 글(예: `torch 2.7, CPU`). 열 머리 「단계, 찍힌 줄, 뜻」. 묶음마다 번호 배지, 찍힌 줄, 뜻 |

값은 시안을 그대로 옮깁니다.

| 부품 | 값 |
|---|---|
| 블록 | 테두리 1px `--rule`, 위 2px `--ink`, 바탕 `--plate`. 넓힌 블록은 좌우 테두리를 빼고 글 칸 테두리를 씁니다 |
| 머리 | 바탕 `--paper`, 아래 1px `--rule`. 하는 일 18px 굵게 `--ink` |
| 설명 칸 | 260px, 바탕 `--paper`, 오른쪽 1px `--rule`. 제목 15.5px `--ink`, 풀이 14.5px `--ink2` |
| 번호 배지 | 모노 12px 600, 바탕 `--navy`, 글자 `--paper`. 출력 쪽 배지는 바탕 `--navy-bg`, 글자 `--navy`, 테두리 `--navy-bd` |
| 코드 줄 | IBM Plex Mono 14.4px, 줄 간격 1.75, 글자 `--ink2` |
| 출력 영역 | 위 2px `--ink`, 바탕 `--paper`. 탭은 모노 12.5px 바탕 `--ink` 글자 `--paper`. 찍힌 줄 모노 14px `--ink`, 뜻 14.5px `--ink2` |

### 4-2. 주석이 가는 자리

| 주석 | 화면 |
|---|---|
| `# N단계:` 바로 아래 이어진 주석 줄 | 설명 칸의 풀이 |
| 줄 끝 주석 `x = 1  # …` | 그 줄 끝의 메모. 한 블록의 메모는 세로로 줄을 맞춥니다 |
| 단계 안에서 코드 줄 사이에 있는 주석 줄 | 그 자리의 메모. 들여쓰기를 따릅니다 |

- 같은 들여쓰기로 이어진 주석 줄은 공백 하나로 이어 메모 하나로 그립니다. `#` 만 있는 줄에서 메모를 나눕니다.

- 메모 모양은 본문 서체 13.5px, 글자 `--ink`, 바탕 `--navy-bg`, 왼쪽 2px `--navy` 선입니다.

- 줄 끝 메모를 세울 자리는 라틴 글자 폭(`ch`) 단위로 정합니다. 코드 칸에 들어가는 글자 수를 `cap` 이라 하면 `nc = min(메모가 달린 줄 중 가장 긴 줄 폭 + 2, cap − 22)` 입니다.

- 폭이 `nc − 2` 를 넘는 줄의 메모는 그 줄 아래로 내립니다. 내린 메모도 그 줄 들여쓰기에 맞춥니다.

- 블록 폭이 600px 이하이면 메모를 모두 줄 아래로 내립니다.

- 줄 폭은 그 기기에서 그려진 폭으로 셉니다. 라틴 글자 100개와 한글 100개를 숨겨 두고 재서 한글 한 자가 라틴 글자 몇 개 폭인지 구합니다. 맥의 Chrome 에서는 1.44자 폭이었고 서체마다 다릅니다.

### 4-3. 줄 접기

- 코드 칸보다 긴 줄은 접습니다. 공백은 원래 접히는 자리입니다. 여기에 점, 쉼표, 여는 괄호 뒤를 `<wbr>` 로 더합니다. 바로 닫히는 빈 괄호 `()`, `[]` 사이와 문자열, 숫자 안에는 더하지 않습니다. `overflow-wrap: anywhere` 는 마지막 수단으로 둡니다. 그래서 `param|eters` 처럼 낱말 가운데서 끊기지 않습니다.

- 접힌 뒷줄은 그 줄 들여쓰기에서 4자 더 들어갑니다(내어쓰기). 접힌 줄 왼쪽에는 2px `--navy` 막대를 붙입니다.

- 접혔는지는 그 줄 높이가 줄 간격의 1.5배를 넘는지로 봅니다. `getClientRects` 는 글자 조각마다 상자를 돌려줘서 쓰지 않습니다.

- 찍힌 줄도 같은 규칙으로 접습니다. 접는 자리는 공백이고, 공백 없는 긴 덩어리만 아무 데서나 접습니다.

### 4-4. 코드 색

| 토큰 | 무엇 |
|---|---|
| `--ink`, 굵기 600 | 키워드, `def` 와 `class` 뒤의 이름 |
| `--ink2` | 나머지 코드, 내장 함수 |
| `--series-6` | 문자열 |
| `--series-5` | 숫자 |

- 새 블록에는 hljs 색과 세이지 기울임꼴을 쓰지 않습니다. 주석은 코드 안에 글자로 남지 않고 메모와 풀이가 됩니다.

- 새 hex 값은 없습니다. 모두 토큰이라 다크 화면에서 토큰을 따라 바뀝니다.

- 계열색(`--series-*`)은 지금 차트 전용으로 적혀 있습니다. 글쓰기 규칙 문서의 디자인 절과 `check-design.js` 머리 주석에 「코드 블록의 문자열과 숫자」를 더합니다.

### 4-5. 폭, 쌓임, 휴대폰

| 조건 | 모양 |
|---|---|
| 블록 폭 926px 초과 | 설명 칸과 코드가 나란히 |
| 블록 폭 926px 이하 | 설명이 단계마다 코드 위. 설명 줄은 바탕 `--navy-bg`, 왼쪽 3px `--navy`, 제목이 배지 옆에 한 줄로. 빈 설명 칸은 숨깁니다 |
| 블록 폭 600px 이하 | 위와 같고, 메모는 모두 줄 아래. 출력 묶음은 번호와 찍힌 줄 두 열, 뜻은 찍힌 줄 아래 |

- 쌓임은 블록에 거는 container query 로 정합니다 (`container: cb / inline-size`). 화면 폭이 아니라 블록 폭을 봅니다.

- 잰 글 칸 폭은 1440 화면 1053px(나란히), 1280 화면 893px(쌓임), 1024 화면 917px(쌓임, 사이드바 접힘)입니다.

- `.post-content` 에 `--post-pad` 를 두고 블록은 `margin-inline: calc(-1 * var(--post-pad))` 로 넓힙니다. `.post-content` 바로 아래 자식인 블록만 넓힙니다. 인용 안의 블록(git-practical-guide 의 2개)은 그대로 둡니다.

- 접는 절(`:::deep`) 안의 블록은 접는 절 안쪽 끝까지 넓힙니다. 접는 절은 안의 것에 좌우 1.1rem 여백을 주는데, 블록에서만 그 여백을 뺍니다. 파이썬 블록 11개가 접는 절 안에 있고, 시안의 two-tower 블록도 그중 하나입니다. 1440 화면에서 그 블록 폭은 947px 이라 설명 칸과 코드가 나란히 섭니다.

- 접힌 절 안의 블록은 처음 그릴 때 폭이 0 입니다. 펼치면 `ResizeObserver` 가 폭을 다시 재서 배치를 잡습니다.

- 768px 이하에서는 `--post-pad` 를 24px 로 둡니다. 글 칸을 감싼 `.container` 의 좌우 여백을 0 으로 하고 글 칸의 좌우 테두리를 뺍니다. 그래서 글 칸이 화면을 채웁니다. 이 규칙은 스타일 파일 맨 끝 디자인 블록 뒤에 둬서 넓은 화면 값을 이기게 합니다.

- 휴대폰 여백 수정은 모든 글의 휴대폰 화면을 바꿉니다. 390 화면에서 글 문단이 342px 이 됩니다.

### 4-6. 같은 번호 밝히기

- 단계 행이나 출력 묶음에 마우스를 올리면, 같은 블록에서 번호가 같은 단계 행과 출력 묶음을 `--navy-bg` 로 밝힙니다. 밝아진 행의 메모 바탕은 `--paper` 로 바꿉니다.

- 터치 기기에서는 이 기능 없이 번호 배지로만 잇습니다.

### 4-7. 파이썬이 아닌 블록, 옮기기 전 블록, Copy

- 파이썬이 아닌 블록은 지금 hljs 색을 그대로 둡니다. hljs 가 만든 HTML 을 줄마다 나눠 4-3 과 같은 내어쓰기 접기와 막대를 붙입니다.

- 선 글자(U+2500~U+259F)가 한 줄이라도 있는 블록은 접지 않고 지금처럼 옆으로 밉니다. 지금 auto-bidding-pacing, feature-store-serving, model-serving-architecture 의 3개입니다.

- 「하는 일」 줄이 없는 파이썬 블록(옮기기 전)과 규칙에 맞지 않아 읽지 못한 블록은 지금 모양(hljs, 세이지 주석, 옆으로 밀기) 그대로 그리고 폭만 넓힙니다.

- Copy 버튼은 모든 블록에서 마크다운 원문을 그대로 복사합니다. 지금은 화면에 그려진 글자를 복사합니다.

## 5. 쓰는 방식

### 5-1. 표시

| 표시 | 꼴 | 어디에 | 화면 |
|---|---|---|---|
| 상태 | 5-2 의 세 가지 | 블록 맨 위, 하는 일 줄 앞. 0개 이상 | 머리의 상태 라벨 |
| 하는 일 | `# 하는 일: <한 줄>` | 상태 표시 다음 첫 줄. 블록에 하나 | 머리의 굵은 한 줄 |
| 단계 | `# <N>단계: <제목>` | 들여쓰기 없는 줄. N 은 1부터 하나씩 늘어납니다 | 설명 칸의 번호와 제목 |
| 단계 풀이 | 단계 줄 바로 아래 이어진 `# …` 줄 | 단계 줄과 첫 코드 줄 사이 | 설명 칸의 풀이 |
| 출력 | `# 출력:` 또는 `# 출력 (<괄호 안 글>):` | 들여쓰기 없는 줄. 이 줄부터 블록 끝까지가 출력 영역입니다 | 출력 탭과 괄호 안 글 |
| 뜻 | `# <N>단계 뜻: <뜻>` 또는 `# 뜻: <뜻>` | 출력 영역 안. 아래 찍힌 줄들의 머리 | 묶음의 번호 배지와 뜻 |
| 찍힌 줄 | `# <찍힌 그대로>`, 빈 줄은 `#` | 뜻 줄 아래 | 찍힌 줄 |

- 표시는 주석일 때만 표시입니다. 여러 줄 문자열 안에 `# 1단계:` 가 있어도 표시가 아닙니다.

- 단계 풀이가 여러 줄이면 공백 하나로 이어 한 문단으로 그립니다. `#` 만 있는 줄은 문단을 나눕니다. 빈 줄을 만나면 풀이가 끝납니다.

- 단계가 하나도 없으면 단계 없는 블록입니다. 하는 일 줄 다음부터 코드가 한 행으로 그려집니다.

- 행의 맨 앞과 맨 끝 빈 줄은 그리지 않습니다. 행 안의 빈 줄은 그대로 둡니다.

- 출력 영역 안의 줄은 모두 들여쓰기 없는 `#` 로 시작합니다. 찍힌 줄은 앞의 `# ` 두 글자를 뗀 나머지이고, `#` 한 글자만 있는 줄은 빈 줄입니다.

- 묶음 맨 앞과 맨 끝의 빈 찍힌 줄은 화면에 그리지 않습니다. `print()` 나 `\n` 으로 찍은 빈 줄이 묶음 경계에 걸리는 일이 많아서입니다. 실행 검사는 빈 줄까지 비교합니다.

- 출력 줄 뒤에 코드 줄이 오면 안 됩니다. 지금 블록 247개에는 그런 블록이 없습니다.

- 뜻 줄의 번호는 그 아래 줄들을 찍은 단계입니다. 첫 단계 앞의 코드가 찍은 줄은 번호 없이 `# 뜻:` 으로 씁니다. 단계 없는 블록의 뜻 줄에는 번호가 없습니다.

- 출력 머리의 괄호 안 글에 「돌릴 때마다」가 들어가면 실행 검사가 숫자를 빼고 비교합니다. 시간을 재는 블록은 `# 출력 (시간은 돌릴 때마다 다르다):` 로 씁니다.

- 찍힌 줄 가운데 `[` 로 시작하는 줄이 45줄(`[A/B] 소재A: …`) 있고, `←` 나 `<-` 가 든 줄이 16줄 있습니다. 그래서 뜻 줄은 기호가 아니라 「뜻」이라는 낱말로 알아봅니다. 찍힌 줄 가운데 「N단계」나 「뜻」으로 시작하는 줄은 지금 없습니다.

### 5-2. 상태 표시

| 꼴 | 뜻 | 라벨 | 실행 검사 |
|---|---|---|---|
| `# (<무엇> — 그대로 실행되지 않습니다.)` | 그대로는 안 돈다. 지금 쓰는 `# (의사코드 — 그대로 실행되지 않습니다.)` 가 이 꼴입니다 | `<무엇>` (예: 의사코드, 발췌) | 건너뜁니다 |
| `# (앞 블록에 이어서 돌린다.)` | 같은 글의 앞 블록들을 먼저 돌려야 돈다 | 「앞 블록에 이어서」 | 앞 블록들을 같은 프로세스에서 먼저 돌립니다 |
| `# (<글 id> 글의 코드에 이어서 돌린다.)` | 다른 글의 코드를 먼저 돌려야 돈다 | 「앞 글에 이어서」, 그 글로 가는 링크 | 그 글의 블록들을 먼저 돌립니다 |

- 지금 의사코드 6개는 첫 줄이 이미 이 꼴이라 그대로 두고, 그 다음 줄에 하는 일을 씁니다.

- 상태 표시 자리에 이 셋이 아닌 괄호 줄이 오거나, 하는 일 줄이 다른 자리에 있으면 형식 검사가 잡습니다.

### 5-3. 예

시안의 two-tower 블록을 이 방식으로 쓴 것입니다. 가운데는 줄였습니다.

```python
# 하는 일: 가짜 광고 200개로 두 타워를 300번 학습하고, 학습에 안 쓴 클릭 2,000건으로 Recall@10 을 잰다.
import torch
import torch.nn as nn
import torch.nn.functional as F

# 1단계: 가짜 광고 200개를 만든다
# 광고마다 정보 16개와 인기를 둔다. 인기가 앞 순위에 쏠려야 인기 보정이 하는 일이 보인다.
torch.manual_seed(0)
N_ADS, D_IN, D = 200, 16, 32                     # 광고 수, 입력 차원, 벡터 길이 (가상 값)
...

# 4단계: 두 타워를 300번 학습한다
# 배치 256건의 점수표에 인기 보정과 accidental hit 제거를 넣고, 대각선을 정답으로 손실을 줄인다.
member_tower, ad_tower = Tower(), Tower()
...

# 출력 (torch 2.7, CPU):
# 4단계 뜻: 학습 전 손실이다. log 256 = 5.55 보다 큰 것은 인기 보정이 점수마다 다른 값을 더한 뒤라서다.
# step   0  손실 8.245
# 4단계 뜻: 처음 100번에 4분의 1 아래로 줄고, 그 뒤로는 천천히 준다.
# step 100  손실 1.950
# step 200  손실 1.847
# step 300  손실 1.692
# 5단계 뜻: 누른 광고가 상위 10개 안에 든 비율이다. 모두에게 같은 10개를 준 기준선의 두 배 가까이다.
# Recall@10  two-tower 0.932  클릭 많은 순 0.496
```

### 5-4. 쓰는 규칙

- 블록 안의 글(하는 일, 단계 제목, 풀이, 메모, 뜻)은 지금 주석처럼 평서체(`~한다`, `~이다`)로 씁니다. 상태 표시는 5-2 의 글 그대로 씁니다.

- 하는 일은 무엇을 얼마나 해서 무엇을 재는지 한 문장으로 씁니다.

- 단계 제목은 `가짜 광고 200개를 만든다` 처럼 동사로 끝나는 짧은 말로 씁니다. 풀이는 이 단계가 왜 있는지, 무엇을 보면 되는지 한두 문장입니다.

- 단계는 읽는 사람이 나눠 읽을 자리에만 둡니다. 본체가 짧고 한 가지 일만 하면 단계 없이 씁니다.

- 뜻은 그 줄이 보여 주는 것과 숫자가 왜 그 값인지를 한두 문장으로 씁니다. 본문이 이미 길게 풀었으면 한 줄 요약으로 둡니다.

- 여러 줄을 한 뜻으로 묶어도 됩니다. 20줄짜리 표도 뜻 하나면 됩니다. 뜻 줄 없이 찍힌 줄은 둘 수 없습니다.

- 말투 검사는 코드 블록 안도 셉니다. 해요체, 쓰지 않는 낱말, 가운뎃점, 말로 쓴 숫자, 지어낸 말(예: 「출력 칸」) 규칙이 블록 안 글에도 걸립니다.

## 6. 그리는 코드

### 6-1. `js/code-steps.js` (새 파일)

| 함수 | 하는 일 |
|---|---|
| `scan(src)` | 파이썬 토크나이저. 줄마다 토큰 목록(주석, 문자열, 숫자, 키워드, 정의 이름, 내장 함수, 이름, 기호, 공백)을 돌려줍니다. 삼중 따옴표 문자열과 백슬래시 줄 이음 상태를 다음 줄로 넘깁니다. 문자열 접두사(r, b, f, u 와 그 조합)와 이스케이프를 다룹니다. f-string 안의 중괄호는 문자열로 둡니다 |
| `parse(src)` | 5장 규칙으로 블록을 읽어 `{ format, ok, errors, labels, head, pre, steps, out }` 을 돌려줍니다. 하는 일 줄이 없으면 `format: 'legacy'` 입니다. `errors` 는 `{ line, msg }` 목록입니다 |
| `render(model, src)` | 블록 HTML 문자열을 만듭니다. 원문은 블록의 `data-src` 에 HTML 이스케이프해 넣습니다. 코드 줄마다 들여쓰기(`--ind`), 라틴 글자 수와 넓은 글자 수, 메모를 붙입니다 |
| `mount(root)` | root 안의 블록마다 줄 폭을 재서 메모 자리, 메모 내리기, 접힘 막대, 출력 묶음 모양을 정합니다. 같은 번호 밝히기를 겁니다. `ResizeObserver` 와 `document.fonts.ready` 에서 다시 잽니다 |
| `splitLines(html, raw)` | hljs 가 만든 HTML 을 줄마다 나눕니다. 줄 끝에서 열린 span 을 닫고 다음 줄 앞에서 다시 엽니다. 파이썬이 아닌 블록의 줄 접기에 씁니다 |

- 브라우저에서는 `window.CodeSteps`, node 에서는 `module.exports` 로 내보냅니다. 검사 스크립트가 같은 파일을 읽어서 화면과 검사가 같은 규칙을 씁니다.

- 바깥 라이브러리를 쓰지 않습니다.

- 클래스 이름은 모두 `cb-` 로 시작합니다. 시안의 `.badge`, `.exp`, `.code` 같은 짧은 이름은 다른 부품과 겹치기 쉬워서 그대로 쓰지 않습니다.

- 출력 묶음 모양: 찍힌 줄 가운데 가장 긴 줄 폭 + 2 를 `oc` 라 합니다. `oc` 가 출력 영역 폭의 60% 이하이면 번호, 찍힌 줄(폭 `oc`), 뜻 세 열로 그립니다. 넘으면 블록 전체를 번호와 찍힌 줄 두 열로 두고 뜻을 찍힌 줄 아래에 둡니다. 묶음마다 다르게 하지 않고 블록 하나에 한 모양입니다. 블록 폭 600px 이하에서는 늘 두 열입니다.

### 6-2. `js/main.js`

- marked 의 `code()` 렌더러에서 언어가 python 이면 `CodeSteps.parse(text)` 를 부릅니다. `format` 이 steps 이고 `ok` 이면 `CodeSteps.render` 결과를 돌려줍니다. 아니면 지금 길(hljs)로 그립니다.

- 지금 길로 그리는 `<code>` 에도 원문을 `data-src` 로 붙입니다.

- `enhanceCodeBlocks` 는 새 블록(`.cb`)을 건너뜁니다. 새 블록은 머리와 Copy 를 스스로 갖습니다. 나머지 블록의 Copy 는 `data-src` 를 복사합니다. Copy 동작(「Copied!」 2초, 클립보드가 안 되면 textarea 로)은 함수 하나로 묶어 두 쪽이 같이 씁니다.

- 파이썬이 아닌 블록(mermaid 제외)은 `splitLines` 로 줄을 나눕니다. 선 글자가 있는 블록에는 접지 않는 표시를 붙입니다. 옮기기 전 파이썬 블록은 나누지 않습니다.

- 본문을 넣은 뒤 `CodeSteps.mount(contentContainer)` 를 부릅니다.

- 본문의 용어 풀이(`autoLinkGlossary`)와 수식 렌더러(KaTeX auto-render)는 `<pre>` 와 `<code>` 만 건너뜁니다. 새 블록은 `div` 로 그리므로 둘 다 `.cb` 를 건너뛰게 합니다. 파이썬 블록 5개에 `$` 가 있습니다.

- 글자 폭을 재는 숨은 글자(라틴 100자, 한글 100자)는 크기 0 인 상자 안에 둡니다. 한글 100자는 1,200px 이 넘어서, 그냥 두면 페이지가 옆으로 넘칩니다.

> `js/main.js` 에는 NUL 바이트가 있습니다. 찾을 때는 `grep -a` 를 쓰고, 고칠 때는 파일을 통째로 다시 쓰지 않습니다.

### 6-3. `post.html`, `css/style.css`

- `post.html` 에서 `js/main.js` 앞에 `js/code-steps.js` 를 싣습니다. 글 본문을 그리는 페이지는 `post.html` 하나입니다. `index.html` 과 `home.html` 은 marked 와 `js/main.js` 를 싣지만 글 본문을 그리지 않습니다. 그래서 `js/main.js` 는 `CodeSteps` 가 있는지 보고 부릅니다.

- 스타일은 `css/style.css` 맨 끝 「신문 위의 청사진」 블록 뒤에 「코드 블록」 묶음으로 더합니다. 위쪽 옛 규칙을 덮어쓰는 자리입니다. 휴대폰 여백 바로잡기도 같은 자리에 둡니다.

- 모서리 0, 그림자 없음, 색은 토큰만 씁니다.

## 7. 검사

### 7-1. 형식 검사 — `scripts/check-code-blocks.js` (node, CI)

모든 글의 파이썬 블록을 `CodeSteps.parse` 로 읽습니다. 하는 일 줄이 있는 블록에서 아래를 하나라도 어기면 실패합니다.

- 하는 일 줄이 상태 표시 다음 첫 줄에 있고 비어 있지 않다

- 상태 표시는 5-2 의 세 꼴 가운데 하나다

- 단계 표시는 들여쓰기 없이 줄 맨 앞에 있고, 번호가 1부터 하나씩 늘어나며, 제목이 비어 있지 않다

- 들여쓰기 없이 `# 출력` 으로 시작하는 줄은 5-1 의 출력 표시 꼴이다. `# 출력 예시:` 같은 다른 꼴은 실패합니다

- 출력 표시 뒤에 코드 줄이 없고, 출력 영역의 줄이 모두 들여쓰기 없는 `#` 로 시작한다

- 출력 영역의 첫 줄이 뜻 줄이다. 모든 찍힌 줄이 어떤 뜻 줄 아래에 있다

- 뜻 줄마다 찍힌 줄이 하나 이상 있다

- 뜻 줄의 번호가 블록에 있는 단계다. 단계 없는 블록의 뜻 줄에는 번호가 없다

옛 형식 블록은 글마다 수를 셉니다.

- 기준표 `scripts/code-blocks-baseline.json` 에 글마다 옛 형식 블록 수를 적어 둡니다.

- 기준표보다 늘거나, 기준표에 없는 글에 옛 형식 블록이 있으면 실패합니다. 새 글은 처음부터 새 형식이어야 합니다.

- 글을 옮긴 뒤 `--update` 로 기준표를 다시 적습니다. 다 옮기면 기준표가 비고, 옛 형식 블록이 하나만 있어도 실패합니다.

단위 테스트 `scripts/test-code-steps.js` 를 같이 둡니다. 문자열 안의 `#`, 여러 줄 문자열 안의 표시, f-string, 같은 줄의 문자열과 줄 끝 주석, 빈 찍힌 줄 `#`, 뜻 없는 찍힌 줄, 건너뛴 단계 번호, 출력 뒤 코드, `splitLines` 의 span 닫고 다시 열기를 다룹니다.

### 7-2. 실행 검사 — `scripts/check-python-outputs.py` (파이썬 3.9 이상, 표준 라이브러리만)

- 하는 일 줄이 있는 블록만 돌립니다. 옛 형식 블록은 `--legacy` 를 줄 때만 돌립니다(옮길 때 로컬에서 씁니다).

- 「그대로 실행되지 않습니다」 블록은 건너뜁니다.

- 독립 블록은 블록마다 새 프로세스에서 돌립니다.

- 이어지는 블록은 한 프로세스에서 앞 코드를 먼저 돌린 뒤 돌립니다. 앞 코드는 이 순서입니다. 그 글의 블록 가운데 「글의 코드에 이어서」 표시가 하나라도 있으면 그 다른 글의 블록들을 먼저 돌립니다. 그다음 이 글의 앞 블록들을 차례로 돌립니다. 「그대로 실행되지 않습니다」 블록은 빼고, 앞 코드의 출력은 버립니다. 앞 코드가 라이브러리가 없어 멈추면 그 블록도 「건너뜀(라이브러리 없음)」입니다.

- stdout 과 stderr 를 쓴 순서대로 모읍니다. unittest 처럼 stderr 에 쓰는 블록이 있습니다.

- 찍힌 줄마다, 그 줄을 쓸 때 실행 중이던 블록의 모듈 최상위 문장 줄 번호를 적습니다. 그 줄 번호가 속한 단계가 그 줄을 찍은 단계입니다. 함수 안의 `print` 는 그 함수를 부른 최상위 문장의 단계가 됩니다. two-tower 블록으로 해 보니 손실 줄은 4단계, Recall 줄은 5단계로 맞게 나뉘었습니다.

- 찍힌 줄과 적힌 줄을 글자까지 비교합니다. 줄 끝 공백만 뺍니다. 출력 머리에 「돌릴 때마다」가 있으면 양쪽에서 숫자를 지우고 공백을 하나로 줄인 뒤 비교합니다.

- 뜻 줄의 번호와 그 아래 줄들을 찍은 단계가 같아야 합니다. 번호 없는 뜻 줄 아래 줄은 첫 단계 앞의 코드가 찍어야 합니다. 단계 없는 블록은 단계를 보지 않습니다.

- import 할 수 없는 라이브러리(`ModuleNotFoundError`)가 나오면 「건너뜀(라이브러리 없음)」으로 알리고 실패로 치지 않습니다. 그 밖의 예외, 120초 넘김, 비교가 틀리면 실패입니다.

- `PYTHONHASHSEED=0` 으로 돌립니다. 247개를 시드 0 과 1 로 두 번씩 돌려 보니, 시간을 재는 8개 말고는 출력이 같았습니다.

- 끝에 `통과 N, 건너뜀 N(라이브러리 없음 N, 실행 안 됨 N), 실패 N` 을 찍습니다. 기본은 4개씩 동시에 돌리고, `--jobs` 로 바꿉니다.

**CI 와 로컬**

- CI 에는 표준 라이브러리만 있습니다. numpy, torch 같은 라이브러리를 쓰는 블록 16개(numpy 12, sklearn 3, scipy 3, pyspark 2, torch 2, 그 밖 6종 1개씩, 한 블록이 여럿을 쓰기도 합니다)는 CI 에서 건너뜁니다.

- 로컬에서 돌리면 설치된 라이브러리만큼 더 돕니다. 지금 로컬에는 torch 2.7.0, numpy 1.26.4 가 있습니다. pyspark 처럼 로컬에도 없는 라이브러리를 쓰는 블록은 로컬에서도 건너뛰고, 건너뛴 블록은 이름을 찍습니다.

- 옵션은 넷입니다. `--legacy` 는 옛 형식 블록도 돌립니다. `--post <id>` 는 글 하나만 돌립니다. `--jobs <n>` 은 동시에 돌릴 수입니다. `--root <폴더>` 는 그 폴더의 `posts/` 를 읽습니다(시험용).

- 시험 `scripts/test-python-outputs.py` 가 임시 폴더에 작은 글을 만들어 통과, 실패, 건너뜀을 확인합니다. CI 에서 같이 돌립니다.

- 로컬에서 247개를 8개씩 동시에 돌리니 48초 걸렸습니다. 블록 하나가 가장 오래 걸린 것은 34초(privacy-signal-loss)였습니다.

- CI 의 파이썬은 `actions/setup-python` 으로 로컬과 같은 3.9 에 맞춥니다. 3.9 를 받을 수 없으면 CI 기본 버전으로 247개를 먼저 돌려 출력이 다른 블록이 없는지 보고 정합니다.

- `validate.yml` 에 단계 넷(형식 검사, 단위 테스트, 실행 검사, 실행 검사 시험)을 더합니다.
