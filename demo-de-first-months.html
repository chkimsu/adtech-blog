데이터 엔지니어 첫 6개월 카드 여섯 장

어느 데이터 플랫폼 팀에 새로 온 사람의 커밋 428개를 폴더별로 늘어놓았습니다. 첫 달은 수급 DAG, 둘째 달은 SQL 모델, 넷째 달은 실시간 잡, 여섯째 달은 배포였습니다. 숫자는 실제로 센 값이고 이름과 경로는 전부 바꾼 것입니다.

파랑 = 데이터가 놓인 자리 (원천, 표, 파일, 토픽) 벽돌색 = 시키는 것 (Airflow, DAG, workflow) 먹색 = 사람이 쓴 정의 (YAML, SQL, Java) 회색 = 실행 엔진 (Spark, Kyuubi, Flink) 점 = 지금 가고 있는 데이터, 코드

MAP

저장소는 네 층

쉽게 말하면 이 저장소는 「매일 몇 시에 어디서 데이터를 가져와 어떤 표로 만들어 어디에 놓나」를 코드로 적어 둔 곳입니다. 가져오는 것, 표로 만드는 것, 클러스터에 말을 거는 부품, 들어오는 대로 처리하는 것이 각각 폴더 하나입니다.

파일 수가 가장 많은 층은 SQL 모델 267장입니다. 실제 로직이 거기 있고, 파이썬 DAG 는 언제 어떤 순서로 돌리나만 적습니다.

EXTRACT

첫 달, 수급 DAG 한 장

쉽게 말하면 남의 저장소에 있는 표 하나를 매일 새벽 우리 창고에 복사하는 일입니다. 어디서 읽고 어디에 쓰나를 YAML 에 적고, 언제 도나를 파이썬에 적습니다. 나머지는 팀이 만들어 둔 도구가 합니다.

새로 온 사람이 쓴 것은 34줄인데 2주 동안 커밋 47개가 붙었습니다. 원천 접속, 이름 규칙, 스케줄, 배포 길을 처음 밟느라 규칙마다 한 번씩 걸립니다.

DBT MODEL

SQL 한 장이 표 한 개

쉽게 말하면 「이 표는 저 표에서 이렇게 골라 만든다」를 SQL 로 적어 두면 도구가 그 SQL 을 순서대로 돌려 표를 만들어 줍니다. 어느 것을 먼저 돌릴지는 SQL 안에서 다른 표를 부르는 자리를 보고 도구가 알아냅니다.

머리말 주석에 옛 자바 배치의 어느 메서드가 이 표를 만들었는지 적혀 있습니다. 옛 배치를 옮기는 중인 팀이라 모델마다 그 주석이 있습니다.

OPERATOR

Airflow 의 손

쉽게 말하면 Airflow 는 「몇 시에 무엇을 하라」만 알고, 실제로 SQL 을 보내거나 파일을 옮기는 손은 오퍼레이터입니다. 표준 오퍼레이터로 안 되는 상대가 있으면 손을 직접 만듭니다.

이 팀은 오퍼레이터 16개를 직접 만들었습니다. 새로 온 사람의 다섯째 달 커밋이 여기 몰립니다. 남이 만든 부품 위에서 쓰다가 부품 자체를 고치는 쪽으로 올라간 달입니다.

STREAMING

들어오는 대로 받아 묶는 잡

쉽게 말하면 배치는 하루 한 번 표를 만들지만, 이 잡은 로그가 들어오는 대로 받아 10초 기다렸다가 같은 재생 건끼리 묶어 내보냅니다. 늦게 온 로그는 10분까지 받아 차이만 다시 내보냅니다.

원천 저장소에서 읽어 오는 표준 커넥터가 없어서 Java 18개로 직접 만들었습니다. 새로 온 사람의 가장 깊은 코드가 여기 있고, 4월 한 달 이 폴더를 161번 바꿨습니다.

SHIP

코드가 서버에 닿는 길

쉽게 말하면 코드를 고치면 바로 서버에 올리지 않습니다. PR 을 올리고, 동료가 읽고, 고치고, 머지되면 workflow 가 자동으로 배포합니다. 새로 온 사람이 8월에 만든 것이 그 마지막 단계입니다.

커밋 428개 중 리뷰 반영이 21개이고, 팀의 최근 60일 머지 116건 중 115건에 사람 승인이 있었습니다. 리뷰가 형식이 아닙니다.

현업에서는 이렇게 씁니다

  • 데이터 팀에 요청서를 낼 때 「이 DB 에서 매일 가져와 주세요」는 수급 DAG 하나이고, 「이 로그로 이 표를 만들어 주세요」는 SQL 모델 한 장입니다. 어느 층의 일을 부탁하는지 알면 대화가 짧아집니다.
  • 카드를 누르면 위 해설 칸에 그 층에서 자주 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 데이터 엔지니어 첫 6개월 글에 이 카드들이 절마다 한 장씩 들어 있습니다. 여섯 달 월별 표와 새로 온 사람이 하는 일 다섯 가지도 거기 있습니다.
