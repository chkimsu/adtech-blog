메서드별 요청과 응답 보기

같은 주소 /v1/posts 에 GET, POST, PUT, PATCH, DELETE 를 바꿔 보내 봅니다. 보낸 요청 원문, 돌아온 응답 원문, 서버 쪽 데이터가 어떻게 달라지는지 그 자리에서 보입니다.

1. 눌러 보기

왼쪽에서 메서드와 주소를 고르고 보내기를 누르면 오른쪽에 응답이 옵니다. 아래 서버 데이터 표에서 새로 생긴 줄, 바뀐 줄, 지워진 줄이 표시됩니다. 이 서버는 이 페이지 안에서만 도는 가짜 서버라 마음껏 눌러도 됩니다.

2. 다섯 메서드 한눈에

위에서 눌러 본 것을 표 하나로 모았습니다. 잘 되면 오는 상태 코드는 이 데모의 서버가 돌려주는 값이고, 실제 서버도 대개 같습니다.

메서드시키는 일본문을 보내나잘 되면 오는 상태서버 데이터가 바뀌나같은 요청을 두 번 보내면

PUT 과 PATCH 의 차이는 위 데모에서 12번 글의 likes 칸을 보면 드러납니다. PATCH 로 제목만 고치면 likes 가 그대로인데, PUT 으로 제목과 저자만 보내면 likes 가 0 으로 돌아갑니다. PUT 은 「이 내용으로 통째로 교체」라서 안 보낸 칸이 사라지기 때문입니다.

현업에서는 이렇게 씁니다

진짜 서버에 보내고 응답을 눈으로 보는 방법은 셋입니다. 셋 다 위 데모와 같은 것을 보여 줍니다.

  • 브라우저 개발자 도구 — 아무 웹사이트에서 F12 를 누르고 Network 탭을 엽니다. 페이지가 보내는 요청이 한 줄씩 쌓이고, 한 줄을 누르면 Headers, Payload, Response 가 나옵니다. 위 「지금까지 보낸 요청」 표와 같은 모양입니다.
  • 터미널의 curl — -i 를 붙이면 상태 줄과 헤더까지 같이 찍힙니다. 아래는 연습용 공개 서버에 보내는 예입니다. 이 서버는 어떤 메서드를 보내도 받아 주지만 데이터를 실제로 바꾸지는 않습니다.
  • Postman, Insomnia 같은 도구 — 화면에서 메서드를 고르고 주소와 본문을 채워 보내기를 누릅니다. 위 데모의 왼쪽 칸이 그 도구의 화면과 같은 구성입니다.
# 하나 받기
curl -i https://jsonplaceholder.typicode.com/posts/1

# 새로 만들기 — 본문을 실어 보내므로 Content-Type 헤더를 같이 줍니다
curl -i -X POST https://jsonplaceholder.typicode.com/posts \
  -H "Content-Type: application/json" \
  -d '{"title":"첫 글","body":"내용","userId":1}'

# 일부만 고치기
curl -i -X PATCH https://jsonplaceholder.typicode.com/posts/1 \
  -H "Content-Type: application/json" \
  -d '{"title":"제목만 바꿨습니다"}'

# 지우기 — 본문 없이 200 이 옵니다 (204 를 주는 서버도 많습니다)
curl -i -X DELETE https://jsonplaceholder.typicode.com/posts/1

메서드가 무엇인지, 왜 POST 로 보냈는데 데이터가 돌아오는지는 API 기초 글 3절과 4절에 있습니다. 상태 코드를 어디까지 외워야 하는지도 그 글에 있습니다.
