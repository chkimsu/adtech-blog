지훈은 앞의 세 편에서 배열 문제를 풀고 넘어왔습니다. 그런데 이번 문제는 입력부터 배열이 아니라 "각 사원의 상사 번호가 주어진다"는 문장으로 시작했습니다.

지훈은 이 자료를 배열로 옮겨 보려 했지만 사원 한 명 밑에 부하가 여럿 있고 그 부하 밑에 또 부하가 있어서 사원들을 순서대로 한 줄로 늘어놓을 수가 없었습니다.

**한 줄로 늘어놓을 수 없는 자료는 어떻게 다룰까요?**

한 사람 밑으로 여러 사람이 갈라져 내려가는 이런 모양을 **트리**(tree)라고 부릅니다. 이 글은 먼저 트리를 코드에 담는 법과 순회하는 법을 다룹니다. 순회(traversal)는 트리에 든 값을 하나도 빠뜨리지 않고 한 번씩 방문한다는 뜻입니다. 이어서 트리 모양을 배열 하나에 담은 **힙**(heap)으로 넘어가 힙이 왜 "가장 작은 것 하나"를 꺼내는 일에 강한지 살펴봅니다.

> **한 줄 요약:** 트리는 위로는 부모가 하나뿐이고 아래로는 여러 갈래로 나뉘어 내려가는 구조입니다. 순회 방법은 네 가지인데 그중 세 가지는 재귀(함수가 자기 자신을 다시 부르는 방식) 코드에서 세 줄의 순서만 다릅니다. 힙은 트리처럼 생겼지만 코드로는 배열 하나이고 값 전체를 정렬하지 않은 채 최솟값 하나만 꺼낼 때 씁니다.

> **골라 읽는 법** — 절이 10개입니다.
>
> - 트리를 코드에 담는 법과 순회하는 법 → 1~4절
> - 이진 탐색 트리(왼쪽에 작은 값, 오른쪽에 큰 값을 두는 트리)와 그 함정 → 5절, 6절
> - 힙만 → 7절부터
> - 실무에서 바로 쓰는 파이썬 힙 사용법 → 9절

---

## 1. 트리 — 부모는 하나, 자식은 여럿

**트리는 위로 이어진 부모가 하나뿐이고 아래로만 갈라져 내려가는 구조입니다.**

지훈이 받은 사원 자료가 바로 이런 모양입니다. 사원 한 명에게 상사는 한 명뿐이지만 상사 한 명 밑에는 부하가 여럿 있을 수 있습니다. 트리 용어로는 바로 위의 상사를 **부모**, 바로 밑의 부하를 **자식**이라고 부릅니다. 맨 위에는 상사가 없는 사람이 한 명 있는데 트리에서는 이 사람을 **뿌리**(root)라고 부릅니다. 밑에 아무도 없는 사람은 **잎**(leaf)입니다.

그림 왼쪽의 0층부터 3층까지는 뿌리에서 몇 단계 내려왔는지를 센 층 번호라서 뿌리 8 이 0층에, 그 자식 3 과 10 이 1층에 있습니다. **높이**(height)는 뿌리에서 가장 먼 잎까지 내려가는 층의 수인데, 이 트리에서 가장 먼 잎 4, 7, 13 이 3층에 있으므로 높이는 3 입니다. 높이가 왜 중요한지는 5절에서 나옵니다.

트리를 코드에 담는 방법은 간단합니다. 그림의 동그라미 하나를 **마디**(Node)라고 합니다. 마디마다 값 하나와 왼쪽 자식, 오른쪽 자식을 가리킬 자리 2개를 두고 부모 마디의 그 자리에 자식 마디를 넣어 두 마디를 연결합니다. 아래 코드는 그림의 트리를 이 방식으로 연결해 만든 다음 그림대로 연결됐는지 보려고 뿌리와 두 자식의 값을 찍습니다.

```python
# 하는 일: 값 9개로 이진 트리 하나를 만들고 뿌리와 두 자식을 찍는다.
# 1단계: 마디를 만든다
# 마디 하나는 값 하나와, 왼쪽과 오른쪽 자식을 가리킬 자리 둘을 갖는다.
class Node:
    def __init__(self, val):
        self.val, self.left, self.right = val, None, None

# 2단계: 그림의 트리를 잇고 뿌리를 찍는다
# 뿌리 8 의 왼쪽은 3, 오른쪽은 10 이다. 3 아래에 1 과 6, 6 아래에 4 와 7 이 있고, 10 의 오른쪽에 14, 14 의 왼쪽에 13 이 있다.
def build():
    n = {v: Node(v) for v in (8, 3, 10, 1, 6, 14, 4, 7, 13)}
    n[8].left,  n[8].right  = n[3], n[10]
    n[3].left,  n[3].right  = n[1], n[6]
    n[6].left,  n[6].right  = n[4], n[7]
    n[10].right = n[14]
    n[14].left  = n[13]
    return n[8]

root = build()
print(f"뿌리 {root.val}, 왼쪽 {root.left.val}, 오른쪽 {root.right.val}")

# 출력:
# 2단계 뜻: 뿌리 8 의 왼쪽 자식이 3, 오른쪽 자식이 10 이다.
# 뿌리 8, 왼쪽 3, 오른쪽 10
```

찍힌 `뿌리 8, 왼쪽 3, 오른쪽 10` 은 그림의 0층과 1층 그대로입니다. 코드에서 `left` 나 `right` 가 `None` 이면 그 방향에는 자식이 없다는 뜻인데, `build()` 는 1 의 `left` 와 `right` 를 한 번도 채우지 않아 둘 다 처음 값 `None` 으로 남으므로 1 은 잎입니다.

## 2. 순회 순서 세 가지

**트리 순회 코드는 세 줄로 되어 있는데, 그 세 줄의 차례만 바꾸면 값이 나오는 순서가 세 가지로 달라집니다.**

배열은 왼쪽 끝에서 오른쪽 끝으로 가는 한 가지 순서로 순회하면 되지만 트리는 마디마다 아래가 왼쪽과 오른쪽으로 갈라지므로 어느 쪽을 언제 볼지 순서를 정해야 합니다. 한 마디 밑으로 갈라져 나간 부분을 **갈래**라고 부르는데, 왼쪽 갈래는 왼쪽 자식 하나만이 아니라 왼쪽 자식과 그 밑에 달린 마디 전부를 가리킵니다(표준 용어로는 서브트리). 아래 세 순서는 모두 왼쪽 갈래를 오른쪽 갈래보다 먼저 보기 때문에, 지금 보고 있는 마디(목록의 「나」)를 언제 처리하느냐만 정하면 나머지 차례는 따라옵니다.

- 나를 먼저, 그다음 왼쪽 갈래, 마지막에 오른쪽 갈래 → **전위**(preorder)
- 왼쪽 갈래를 먼저, 그다음 나, 마지막에 오른쪽 갈래 → **중위**(inorder)
- 왼쪽 갈래와 오른쪽 갈래를 먼저, 나는 맨 마지막 → **후위**(postorder)

아래 코드는 1절의 트리를 세 순서로 순회해 값이 나오는 차례를 찍습니다. 세 함수는 함수 안에서 자기 자신을 다시 부르는 **재귀** 함수라서 `전위(t.left, out)` 를 한 번 부르면 왼쪽 갈래 전체가 같은 전위 순서로 처리됩니다. 자식이 없는 자리(`None`)에 닿으면 `if t:` 조건이 거짓이라 아무것도 하지 않고 돌아옵니다. 함수마다 「나를 적기」(`out.append(t.val)`), 「왼쪽 순회」, 「오른쪽 순회」 세 줄을 세미콜론(;)으로 연결해 한 줄에 적었습니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 1절의 트리를 전위, 중위, 후위 세 순서로 순회해 값을 찍는다.
# 1단계: 세 순서를 만든다
# 세 함수는 나를 적기, 왼쪽 순회하기, 오른쪽 순회하기 세 일의 순서만 다르다.
def 전위(t, out):
    if t: out.append(t.val); 전위(t.left, out); 전위(t.right, out)

def 중위(t, out):
    if t: 중위(t.left, out); out.append(t.val); 중위(t.right, out)

def 후위(t, out):
    if t: 후위(t.left, out); 후위(t.right, out); out.append(t.val)

# 2단계: 1절의 트리를 세 순서로 순회한다
for 이름, fn in (("전위 (뿌리 먼저)", 전위), ("중위 (왼쪽 먼저)", 중위), ("후위 (뿌리 나중)", 후위)):
    out = []
    fn(root, out)
    print(f"{이름:<18}{out}")

# 출력:
# 2단계 뜻: 중위 결과만 정렬돼 있다. 뿌리 8 이 전위에서는 맨 앞에, 후위에서는 맨 뒤에 온다.
# 전위 (뿌리 먼저)        [8, 3, 1, 6, 4, 7, 10, 14, 13]
# 중위 (왼쪽 먼저)        [1, 3, 4, 6, 7, 8, 10, 13, 14]
# 후위 (뿌리 나중)        [1, 4, 7, 6, 3, 13, 14, 10, 8]
```

세 결과에는 같은 값 9개가 들어 있지만 나오는 차례는 모두 다릅니다. 전위 `[8, 3, 1, 6, 4, 7, 10, 14, 13]` 은 8 을 먼저 적은 뒤 왼쪽 갈래로 내려가 3, 1, 6, 4, 7 을 다 적고 나서야 오른쪽 갈래의 10, 14, 13 으로 넘어갑니다. 후위 `[1, 4, 7, 6, 3, 13, 14, 10, 8]` 은 자식을 다 적어야 나를 적으므로 뿌리 8 이 맨 끝에 나옵니다. **중위 `[1, 3, 4, 6, 7, 8, 10, 13, 14]` 는 작은 값부터 정렬된 순서입니다.** 이 결과가 우연이 아닌 까닭은 5절에서 다룹니다.

세 순서는 쓰이는 곳도 다릅니다. 전위는 뿌리가 맨 앞에 나와 결과를 앞에서부터 읽으면서 트리를 위에서 아래로 다시 만들 수 있으므로 트리를 그대로 복사하거나 파일로 저장할 때 씁니다. 후위는 폴더 크기 계산이나 트리 삭제처럼 자식을 모두 처리해야 부모를 처리할 수 있는 일에 씁니다.

:::deep 재귀 대신 스택으로 쓰는 전위 순회

위의 세 함수는 재귀로 짰는데, 파이썬은 재귀를 깊게 하지 못하므로(4절) 같은 순회를 스택으로 바꿔 쓰기도 합니다. 스택은 앞 편에서 본 자료구조로, 마지막에 넣은 것을 가장 먼저 꺼냅니다.

아래 코드는 재귀 없이 스택 하나로도 전위 순서가 나오는지 보려고 돌립니다. 스택에서 마디를 하나 꺼내 값을 적을 때마다 그 마디의 오른쪽 자식을 먼저 넣고 왼쪽 자식을 나중에 넣는데, 스택은 마지막에 넣은 것부터 꺼내므로 이렇게 넣어야 왼쪽 자식이 먼저 나옵니다. 처음에 뿌리 8 을 꺼내 적은 뒤 10 과 3 을 차례로 넣으면, 다음에 꺼내는 값은 나중에 넣은 3 입니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 1절의 트리를 재귀 없이 스택 하나로 전위 순서로 순회한다.
def 전위_스택(root):
    out, 스택 = [], [root]
    while 스택:
        t = 스택.pop()
        if not t: continue
        out.append(t.val)
        스택.append(t.right)      # 오른쪽을 먼저 넣어야
        스택.append(t.left)       # 왼쪽이 먼저 나온다
    return out

print(전위_스택(root))

# 출력:
# 뜻: 재귀로 순회한 전위 결과와 같다. 오른쪽을 먼저 넣어야 왼쪽이 먼저 나온다.
# [8, 3, 1, 6, 4, 7, 10, 14, 13]
```

찍힌 `[8, 3, 1, 6, 4, 7, 10, 14, 13]` 은 재귀로 얻은 전위 결과와 같습니다. 재귀도 속으로는 함수 호출을 쌓아 두는 스택을 쓰는데 그 스택을 파이썬이 대신 관리해 줄 뿐이므로, 재귀를 스택으로 바꾸면 그 관리를 내가 직접 맡습니다.

중위와 후위도 스택으로 바꿀 수는 있지만 코드가 눈에 띄게 복잡해집니다. 코딩 테스트에서는 스택으로 바꾸기보다 4절에서 볼 재귀 한계(파이썬이 허용하는 재귀 깊이의 상한)를 올리는 편이 대체로 빠르고 안전합니다.
:::

## 3. 층별 순회와 큐

**문제가 "몇 층인가", "각 층에 무엇이 있나"를 물으면 재귀 대신 큐를 써서 한 층씩 순회합니다.**

2절의 세 순회는 한 갈래를 맨 아래까지 내려간 다음에야 옆 갈래로 옮겨 가므로 같은 층의 값이 결과 여기저기에 흩어집니다. 전위 결과 `[8, 3, 1, 6, 4, 7, 10, 14, 13]` 에서도 3 을 적은 뒤 3 의 갈래를 끝까지 내려가 2층의 1, 6 과 3층의 4, 7 을 먼저 적기 때문에, 같은 1층인 3 과 10 사이에 이 네 값이 끼어 있습니다.

층별로 보려면 먼저 만난 마디를 먼저 처리해야 하므로 먼저 넣은 것을 먼저 꺼내는 자료구조인 **큐**(queue)를 씁니다. 파이썬에서는 앞 편에서 본 `deque` 가 큐 역할을 하는데, `append` 로 뒤에 넣고 `popleft` 로 앞에서 꺼냅니다. 지금 층의 마디를 하나씩 꺼내면서 그 자식들을 큐 뒤에 넣으면, 지금 층을 다 꺼냈을 때 큐에는 다음 층의 마디만 남습니다. 아래 코드는 층마다 큐에서 꺼낸 것, 새로 넣은 것, 그 층을 다 꺼낸 뒤의 큐 상태를 한 줄씩 찍어 이 과정을 보여 줍니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 1절의 트리를 큐로 한 층씩 순회하며, 층마다 꺼낸 것과 넣은 것과 큐 상태를 찍는다.
from collections import deque

큐, 층 = deque([root]), 0
print(f"{'층':<4}{'큐에서 꺼낸 것':<16}{'큐에 넣은 것':<16}{'큐 상태'}")
while 큐:
    이번층, 넣은것 = [], []
    for _ in range(len(큐)):          # 지금 큐에 있는 만큼만 꺼낸다 = 한 층
        t = 큐.popleft()
        이번층.append(t.val)
        for c in (t.left, t.right):
            if c:
                큐.append(c); 넣은것.append(c.val)
    print(f"{층:<4}{str(이번층):<16}{str(넣은것):<16}{[x.val for x in 큐]}")
    층 += 1

# 출력:
# 뜻: 반복문에 들어가기 전의 큐 길이가 그 층의 크기다. 그만큼만 꺼내니 층마다 한 줄씩 나온다.
# 층   큐에서 꺼낸 것        큐에 넣은 것         큐 상태
# 0   [8]             [3, 10]         [3, 10]
# 1   [3, 10]         [1, 6, 14]      [1, 6, 14]
# 2   [1, 6, 14]      [4, 7, 13]      [4, 7, 13]
# 3   [4, 7, 13]      []              []
```

표는 층마다 한 줄씩 찍혔습니다. 0층 차례에는 큐에 `[8]` 만 있어 8 을 꺼내면서 자식 3 과 10 을 넣었습니다. 1층 차례가 시작될 때는 큐 길이가 2 라서 3 과 10 두 개만 꺼내므로, 그사이에 넣은 1, 6, 14 는 다음 층 차례로 남습니다. 마지막 3층 차례에 꺼낸 4, 7, 13 은 모두 잎이라 새로 넣을 자식이 없으므로 큐가 `[]` 로 비면서 반복이 끝납니다. **안쪽 `for` 반복문에 들어가기 직전의 큐 길이가 그 층에 있는 마디 수입니다.** 층을 나누는 일은 `for _ in range(len(큐))` 한 줄이 맡는데, 이 줄이 없으면 층 경계가 사라져 전체가 한 줄로 나옵니다.

가까운 층부터 한 층씩 넓혀 가며 보는 이 방식을 **너비 우선 탐색**(BFS)이라고 부릅니다. 다음 편의 그래프(마디와 마디를 선으로 연결한 구조)에서도 이 방식을 그대로 다시 씁니다. 그래프에서는 갈라진 길이 다시 만나 같은 마디에 두 번 닿을 수 있어 이미 본 마디에 방문 표시를 해 두지만 트리는 갈래가 되돌아오지 않는 그래프라 방문 표시를 하지 않아도 된다는 점만 다릅니다.

## 4. 재귀 깊이 — 파이썬의 기본 한계 1000

**트리가 깊으면 재귀가 오류를 내며 죽습니다. 코딩 테스트에서 원인을 못 찾고 헤매는 일이 바로 이 오류에서 생깁니다.**

재귀 깊이는 함수가 자기 자신을 부른 뒤 아직 끝나지 않고 쌓여 있는 호출의 수입니다. 파이썬은 이 깊이에 기본값 1000 의 한계를 두고 그보다 깊어지면 `RecursionError` 를 냅니다. 2절의 순회 함수는 한 층 내려갈 때마다 쌓인 호출이 하나씩 늘어나므로, 트리의 높이가 이 한계만큼 깊으면 그 순회 코드가 그대로 죽습니다.

아래 코드는 기본 한계를 찍은 다음 한계 안쪽인 깊이 900 과 바깥쪽인 깊이 3000 을 돌려 보고 마지막으로 한계를 10,000 으로 올려 3000 을 한 번 더 돌립니다. `깊이(n)` 은 n 을 1 씩 줄이며 0 이 될 때까지 자기 자신을 부르므로 n 이 클수록 쌓이는 호출도 그만큼 많아집니다.

```python
# 하는 일: 파이썬의 재귀 한계를 확인하고, 깊이 900 과 3000 의 재귀를 기본 한계에서 돌린 뒤, 한계를 올려 3000 을 다시 돌려 본다.
import sys

print("파이썬 기본 재귀 한계", sys.getrecursionlimit())

# 1단계: 깊이 n 까지 재귀하는 함수를 만든다
def 깊이(n):
    if n == 0: return 0
    return 1 + 깊이(n - 1)

# 2단계: 기본 한계에서 900 과 3000 을 돌린다
for n in (900, 3000):
    try:
        print(f"깊이 {n:>5} → {깊이(n)}")
    except RecursionError:
        print(f"깊이 {n:>5} → RecursionError")

# 3단계: 한계를 10,000 으로 올려 다시 돌린다
sys.setrecursionlimit(10_000)
print("한계를 10,000 으로 올린 뒤")
print(f"깊이  3000 → {깊이(3000)}")

# 출력:
# 뜻: 기본 한계는 1000 이다.
# 파이썬 기본 재귀 한계 1000
# 2단계 뜻: 깊이 900 은 한계 안이라 돌고, 3000 은 한계를 넘어 RecursionError 가 난다.
# 깊이   900 → 900
# 깊이  3000 → RecursionError
# 3단계 뜻: 한계를 올리면 같은 깊이 3000 이 돈다.
# 한계를 10,000 으로 올린 뒤
# 깊이  3000 → 3000
```

첫 줄에 찍힌 기본 한계는 1000 입니다. 깊이 900 은 이 한계 안이라 끝까지 돌아 900 을 돌려주었지만 깊이 3000 은 한계를 넘어 `RecursionError` 가 났습니다. 한계를 10,000 으로 올리자 같은 깊이 3000 도 끝까지 돌아 3000 이 찍혔습니다.

값이 십만 개인 문제에서 트리가 한 줄로 늘어지면 재귀 깊이가 십만이 되므로, 코딩 테스트에서는 코드 맨 위에 `sys.setrecursionlimit(10**6)` 을 적어 한계를 미리 크게 올려 두는 관행이 있습니다.

다만 한계를 올린다고 재귀를 끝없이 깊게 할 수는 없습니다. 재귀는 호출할 때마다 실제 메모리를 쓰므로 너무 깊어지면 `RecursionError` 가 나는 대신 프로그램 전체가 죽습니다. **깊이가 수십만을 넘길 것 같으면 재귀를 아예 스택(마지막에 넣은 것부터 꺼내는 자료구조)으로 바꾸는 편이 안전합니다.** 전위 순회를 스택으로 바꾼 코드는 2절 끝의 접은 글에 있습니다.

## 5. 이진 탐색 트리 — 왼쪽은 작은 값, 오른쪽은 큰 값

**어느 마디에서 보아도 왼쪽 갈래의 값은 모두 그 마디보다 작고 오른쪽 갈래의 값은 모두 그 마디보다 크면 그 트리는 이진 탐색 트리입니다.**

먼저 1절의 트리가 이 규칙을 지키는지 두 마디에서 확인해 보겠습니다. 뿌리 8 의 왼쪽 갈래에는 8 보다 작은 1, 3, 4, 6, 7 만 있고 오른쪽 갈래에는 8 보다 큰 10, 13, 14 만 있습니다. 마디 3 에서도 왼쪽 갈래는 3 보다 작은 1 하나이고 오른쪽 갈래는 3 보다 큰 4, 6, 7 입니다.

이 규칙을 지키기만 하면 따로 비용을 들이지 않고도 두 가지를 얻습니다. 첫째는 2절에서 본 대로 **중위로 순회하면 정렬된 순서가 나온다**는 점입니다. 중위는 어느 마디에서나 왼쪽 갈래를 다 적고 나서 자기를 적고 그다음 오른쪽 갈래를 적는데, 이진 탐색 트리에서는 왼쪽 갈래가 모두 자기보다 작고 오른쪽 갈래가 모두 자기보다 크므로 뿌리 8 에서는 1, 3, 4, 6, 7 이 먼저 다 나온 뒤에 8 이 나오고 그다음 10, 13, 14 가 나옵니다. 같은 일이 모든 마디에서 일어나 결과 전체가 작은 값부터 차례로 나옵니다.

둘째가 이 절의 본론으로, 값을 찾을 때 **마디 하나와 비교할 때마다 그 마디의 한쪽 갈래를 남김없이 후보에서 뺄 수 있습니다.** 13 을 찾으며 뿌리 8 과 비교하면 13 이 더 크므로, 8 보다 작은 값만 모인 왼쪽 갈래의 1, 3, 4, 6, 7 은 더 볼 필요가 없습니다. 앞 편의 이분 탐색은 정렬된 배열의 가운데 값과 비교해 찾을 범위를 절반씩 줄이는 방법인데, 이진 탐색 트리의 찾기는 같은 구조를 배열 대신 트리 위에서 씁니다.

아래 코드는 같은 값 9개를 두 가지 순서로 넣어 이진 탐색 트리 2개를 만든 다음, 두 트리에서 13 을 찾을 때까지 회차(마디 하나와 비교한 횟수)마다 지금 마디와 갈 방향을 찍습니다. 넣기 함수는 넣을 값이 지금 마디보다 작으면 왼쪽으로, 작지 않으면 오른쪽으로 내려가다가 빈자리(`None`)를 만나면 그 자리에 새 마디를 만듭니다. 트리 하나는 1절의 그림과 같은 순서 `(8, 3, 10, 1, 6, 14, 4, 7, 13)` 으로, 다른 하나는 정렬된 순서 `(1, 3, 4, 6, 7, 8, 10, 13, 14)` 로 넣습니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 같은 값 9개를 두 순서로 이진 탐색 트리에 넣고, 13 을 찾는 데 몇 회 걸리는지 비교한다.
# 1단계: 넣기와 찾기를 만든다
# 작으면 왼쪽, 크면 오른쪽으로 내려간다. 찾기는 회차마다 지금 마디와 갈 방향을 찍는다.
def 넣기(t, v):
    if t is None: return Node(v)
    if v < t.val: t.left  = 넣기(t.left, v)
    else:         t.right = 넣기(t.right, v)
    return t

def 찾기(t, v):
    회차 = 0
    while t:
        회차 += 1
        방향 = "찾음" if v == t.val else ("왼쪽" if v < t.val else "오른쪽")
        기호 = '=' if v == t.val else ('<' if v < t.val else '>')
        print(f"  {회차}회  지금 {t.val:>2}  {v} {기호} {t.val}  → {방향}")
        if v == t.val: return 회차
        t = t.left if v < t.val else t.right
    print(f"  {회차}회  더 갈 곳이 없다 → 없음")
    return -1

# 2단계: 같은 값을 두 순서로 넣는다
# 하나는 1절의 그림과 같은 순서로, 하나는 정렬된 순서로 넣는다.
균형 = None
for v in (8, 3, 10, 1, 6, 14, 4, 7, 13):
    균형 = 넣기(균형, v)

한줄 = None
for v in (1, 3, 4, 6, 7, 8, 10, 13, 14):       # 정렬된 순서로 넣는다
    한줄 = 넣기(한줄, v)

# 3단계: 두 트리에서 13 을 찾는다
print("균형 잡힌 트리에서 13 찾기")
a = 찾기(균형, 13)
print("\n정렬된 순서로 넣어 한 줄이 된 트리에서 13 찾기")
b = 찾기(한줄, 13)
print(f"\n같은 값 아홉 개인데 {a}회 vs {b}회")

# 출력:
# 3단계 뜻: 균형 잡힌 트리에서는 비교할 때마다 갈래 하나를 버려 4회 만에 찾는다.
# 균형 잡힌 트리에서 13 찾기
#   1회  지금  8  13 > 8  → 오른쪽
#   2회  지금 10  13 > 10  → 오른쪽
#   3회  지금 14  13 < 14  → 왼쪽
#   4회  지금 13  13 = 13  → 찾음
# 3단계 뜻: 정렬된 순서로 넣으면 오른쪽으로만 이어진 한 줄이 되어, 앞에서부터 스캔하듯이 8회가 걸린다.
#
# 정렬된 순서로 넣어 한 줄이 된 트리에서 13 찾기
#   1회  지금  1  13 > 1  → 오른쪽
#   2회  지금  3  13 > 3  → 오른쪽
#   3회  지금  4  13 > 4  → 오른쪽
#   4회  지금  6  13 > 6  → 오른쪽
#   5회  지금  7  13 > 7  → 오른쪽
#   6회  지금  8  13 > 8  → 오른쪽
#   7회  지금 10  13 > 10  → 오른쪽
#   8회  지금 13  13 = 13  → 찾음
# 3단계 뜻: 같은 값인데 넣은 순서만 달라 회차가 두 배가 됐다.
#
# 같은 값 아홉 개인데 4회 vs 8회
```

출력에서 「균형 잡힌 트리」는 1절의 그림과 같은 순서로 넣은 트리인데, 갈래가 한쪽으로 쏠리지 않고 양쪽으로 퍼져 있어 이렇게 부릅니다. 이 트리에서 13 을 찾을 때는 8 보다 커서 오른쪽, 10 보다 커서 오른쪽, 14 보다 작아서 왼쪽으로 내려간 뒤 4회째에 13 을 찾았습니다. 비교할 때마다 갈래 하나를 버렸으므로 값 9개 가운데 8, 10, 14, 13 의 4개만 보고 끝났습니다. 정렬된 순서로 넣어 한 줄이 된 트리에서는 1, 3, 4, 6, 7, 8, 10 을 차례로 모두 지난 뒤 8회째에야 13 에 닿았습니다. 같은 값으로 만든 두 트리의 회차가 왜 이렇게 다른지는 다음 절에서 봅니다.

## 6. 한 줄로 늘어진 트리와 자가 균형 트리

**같은 값 9개를 같은 넣기 코드로 넣었는데도 넣은 순서 하나 때문에 13 을 찾는 회차가 4회와 8회로 두 배 차이 났습니다.**

정렬된 순서로 넣으면 새 값이 언제나 앞서 넣은 모든 값보다 커서 넣기 코드가 마디마다 새 값을 오른쪽으로 보내므로, 새 값은 매번 오른쪽 맨 끝에 붙습니다. 그러면 왼쪽 갈래가 하나도 생기지 않아 트리가 아니라 그냥 한 줄로 연결된 마디들이 됩니다.

실무의 데이터베이스나 표준 라이브러리는 값을 넣을 때마다 트리 모양을 스스로 다시 고르게 맞추는 **자가 균형**(self-balancing) 트리를 씁니다. 레드-블랙 트리나 AVL 트리라는 이름이 이런 자가 균형 트리를 가리킵니다. 두 트리는 한쪽 갈래가 너무 깊어지면 회전(부모와 자식 마디의 위아래 자리를 바꾸는 연산)으로 그쪽을 낮춘다는 원리로 동작하지만 구현이 길어서 코딩 테스트에서 직접 짜는 일은 거의 없습니다.

**그래서 코딩 테스트에서는 이진 탐색 트리를 직접 짜서 쓰지 않습니다.** 정렬된 상태에서 값을 찾는 일은 앞 편의 `bisect`(정렬된 리스트에서 값이 들어갈 자리를 이분 탐색으로 찾는 파이썬 모듈)로, 값을 넣고 빼면서 최솟값만 필요한 일은 다음 절의 힙으로 풉니다. 이진 탐색 트리는 이 두 도구의 배경 지식으로 알아 두는 편이 실속 있습니다.

## 7. 힙 — 최솟값 하나를 빨리 꺼내는 구조

**힙은 값 전체를 정렬하지 않은 채 가장 작은 값 하나만 빠르게 꺼내도록 만든 구조입니다.**

값이 계속 들어오는데 들어올 때마다 "지금까지 중 가장 작은 것"을 꺼내야 하는 문제를 생각해 보겠습니다. 값 n 개를 정렬하는 데는 O(n log n) 이 드는데, 값이 하나 들어올 때마다 정렬을 다시 하면 이 비용을 매번 치러야 해서 감당할 수 없습니다.

힙은 이 일 하나에 맞춘 구조입니다. 값 넣기와 최솟값 빼기는 각각 O(log n) 인데, 왜 그런지는 다음 절에서 칸 번호로 따라가 봅니다. 최솟값은 늘 맨 앞인 `힙[0]` 에 있으므로 **최솟값을 보기만 할 때는 O(1)** 로, 값이 몇 개든 한 번에 끝납니다. 그 대신 다른 일은 잘 못합니다. 힙은 맨 앞이 최솟값이라는 것만 보장하고 둘째, 셋째로 작은 값이 어디에 있는지는 정하지 않으므로 "세 번째로 작은 값"을 물으면 답을 모릅니다.

`heapq` 는 평범한 파이썬 리스트를 힙으로 다루게 해 주는 표준 라이브러리 모듈입니다. 아래 코드는 값 8개를 `heapq.heappush` 로 하나씩 넣을 때마다 힙 안쪽의 리스트와 맨 앞 값을 찍은 다음, 마지막에 `heapq.heappop` 으로 작은 것부터 모두 꺼내 정렬한 결과와 같은지 확인합니다.

```python
# 하는 일: 값 8개를 힙에 하나씩 넣으며 힙 안쪽과 맨 앞을 찍고, 작은 것부터 모두 꺼내 정렬한 것과 비교한다.
import heapq

# 1단계: 값을 하나씩 힙에 넣는다
값 = [23, 5, 38, 2, 45, 8, 16, 12]
힙 = []
print(f"{'넣는 값':<8}{'힙 안쪽(리스트 그대로)':<34}{'맨 앞(가장 작은 값)'}")
for v in 값:
    heapq.heappush(힙, v)
    print(f"{v:<8}{str(힙):<34}{힙[0]}")

# 2단계: 작은 것부터 모두 꺼낸다
print()
print("작은 것부터 꺼내기")
꺼낸것 = []
while 힙:
    꺼낸것.append(heapq.heappop(힙))
print(" ", 꺼낸것)
print(" 정렬한 것과 같나:", 꺼낸것 == sorted(값))

# 출력:
# 1단계 뜻: 힙 안쪽은 정렬돼 있지 않지만 맨 앞은 늘 가장 작은 값이다. 2 가 들어온 뒤로 맨 앞은 2 다.
# 넣는 값    힙 안쪽(리스트 그대로)                     맨 앞(가장 작은 값)
# 23      [23]                              23
# 5       [5, 23]                           5
# 38      [5, 23, 38]                       5
# 2       [2, 5, 38, 23]                    2
# 45      [2, 5, 38, 23, 45]                2
# 8       [2, 5, 8, 23, 45, 38]             2
# 16      [2, 5, 8, 23, 45, 38, 16]         2
# 12      [2, 5, 8, 12, 45, 38, 16, 23]     2
# 2단계 뜻: 하나씩 꺼내면 작은 것부터 나와 정렬한 것과 같다.
#
# 작은 것부터 꺼내기
#   [2, 5, 8, 12, 16, 23, 38, 45]
#  정렬한 것과 같나: True
```

표의 가운데 열에서 보듯 힙 안쪽의 리스트는 **정렬된 상태가 아닙니다.** 마지막 줄의 `[2, 5, 8, 12, 45, 38, 16, 23]` 을 보면 45 가 38 보다 앞 칸에 있습니다. 그래도 오른쪽 열의 맨 앞 값은 늘 그때까지 들어온 값 가운데 가장 작은 값이라 2 가 들어오는 순간 5 에서 2 로 바뀌었고 그 뒤로 45, 8, 16, 12 가 들어와도 2 그대로였습니다. 작은 것부터 모두 꺼낸 결과도 `[2, 5, 8, 12, 16, 23, 38, 45]` 로 정렬한 결과와 같아 `True` 가 찍혔습니다.

힙의 값어치는 완전히 정렬한 상태와 아무 정리도 하지 않은 상태의 중간이라는 데서 나옵니다. 값이 들어올 때마다 완전히 정렬하면 비용이 크고 아무 정리도 하지 않으면 최솟값이 필요할 때마다 다시 찾아야 하는데, 힙은 **"맨 앞만 최솟값"이라는 약한 규칙만 지키는 대신 넣기와 빼기를 O(log n) 으로 싸게 합니다.**

## 8. 배열로 담은 힙 — 칸 번호로 계산하는 부모와 자식

**힙은 그림으로는 트리지만 코드에는 마디끼리 연결하는 선이 없으며 부모와 자식의 자리는 칸 번호로 계산합니다.**

그래서 7절에서 힙을 찍었을 때도 마디가 아니라 리스트가 나왔습니다. 칸 번호는 리스트의 0 번부터 세는 인덱스인데, 칸 `i` 에 있는 값의 왼쪽 자식은 `2i+1` 번 칸, 오른쪽 자식은 `2i+2` 번 칸, 부모는 `(i-1)//2` 번 칸에 있습니다(`//` 는 나머지를 버리고 몫만 남기는 나눗셈입니다). 이 세 계산이 1절의 `left`, `right` 자리 대신 부모와 자식을 찾아 주므로 `Node` 클래스를 따로 만들 필요가 없습니다. 아래 코드는 7절의 힙 8칸에서 칸마다 부모 칸과 두 자식 칸을 계산해 찍고 부모 값이 내 값 이하인지도 확인합니다.

```python
# 하는 일: 7절의 힙 8칸에서 칸 번호로 부모와 자식 칸을 계산해 찍고, 부모 값이 내 값 이하인지 본다.
힙 = [2, 5, 8, 12, 45, 38, 16, 23]

print(f"{'칸':<4}{'값':<5}{'부모 칸':<9}{'왼쪽 자식':<11}{'오른쪽 자식':<12}{'부모 값 ≤ 내 값'}")
for i, v in enumerate(힙):
    부모 = (i - 1) // 2 if i > 0 else None
    왼, 오 = 2*i + 1, 2*i + 2
    왼 = 왼 if 왼 < len(힙) else None
    오 = 오 if 오 < len(힙) else None
    지킴 = "-" if 부모 is None else ("예" if 힙[부모] <= v else "아니오")
    print(f"{i:<4}{v:<5}{str(부모):<9}{str(왼):<11}{str(오):<12}{지킴}")

print("\n칸 번호만으로 부모, 자식을 계산하니 연결선을 따로 안 들고 있어도 된다.")

# 출력:
# 뜻: 칸 i 의 자식은 2i+1, 2i+2 이고 부모는 (i-1)//2 다. 뿌리인 0번 칸을 뺀 모든 칸에서 부모 값이 내 값 이하라 힙 규칙을 지킨다.
# 칸   값    부모 칸     왼쪽 자식      오른쪽 자식      부모 값 ≤ 내 값
# 0   2    None     1          2           -
# 1   5    0        3          4           예
# 2   8    0        5          6           예
# 3   12   1        7          None        예
# 4   45   1        None       None        예
# 5   38   2        None       None        예
# 6   16   2        None       None        예
# 7   23   3        None       None        예
# 뜻: 연결선 없이 계산만으로 트리를 오간다.
#
# 칸 번호만으로 부모, 자식을 계산하니 연결선을 따로 안 들고 있어도 된다.
```

표의 1번 칸(값 5)을 따라가 보면 왼쪽 자식은 `2*1+1 = 3` 번 칸의 12, 오른쪽 자식은 `2*1+2 = 4` 번 칸의 45 입니다. 부모는 `(1-1)//2 = 0` 번 칸의 2 인데 2 가 5 이하라서 마지막 열에 「예」가 찍혔습니다. 3번 칸(값 12)의 오른쪽 자식 자리는 `2*3+2 = 8` 번 칸이지만 리스트가 0 번부터 7 번까지 8칸뿐이라 `None` 이 찍혔습니다. 뿌리인 0 번 칸을 뺀 모든 칸이 「예」라서 이 리스트는 부모 값이 내 값 이하라는 힙 규칙을 지킵니다.

힙은 늘 **위 층부터, 같은 층에서는 왼쪽부터 빈틈없이 채운** 모양을 유지하므로 층을 차례로 늘어놓아 배열에 담아도 칸 번호 계산이 맞습니다. 그 증거로 7절 출력에서 값을 하나 넣을 때마다 리스트가 `[23]`, `[5, 23]`, `[5, 23, 38]` 처럼 한 칸씩만 길어졌고 중간에 빈칸이 생긴 적이 없습니다. 이렇게 빈틈없이 채운 이진 트리를 완전 이진 트리(complete binary tree)라고 부릅니다.

넣기와 빼기가 O(log n) 인 까닭도 칸 번호에서 나옵니다. 넣기는 새 값을 맨 끝 칸에 붙인 다음 부모 칸의 값과 비교해 새 값이 더 작으면 두 칸의 값을 맞바꾸며 위로 올립니다. 7절에서 마지막으로 12 를 넣을 때 12 는 7번 칸에 붙은 뒤 부모인 3번 칸의 23 보다 작아 자리를 바꿨고 다음 부모인 1번 칸의 5 보다는 커서 거기서 멈췄습니다. 그래서 7절 표의 마지막 두 줄을 보면 3번 칸에 있던 23 이 7번 칸으로 내려가 있고 그 자리에 12 가 들어가 있습니다. 부모 칸으로 한 번 올라갈 때마다 칸 번호가 7, 3, 1, 0 처럼 대략 반으로 줄어드므로 올라가는 횟수는 트리의 높이를 넘지 않는데, 빈틈없이 채운 힙은 6절의 균형 잡힌 트리처럼 높이가 대략 log n 이라 넣기가 O(log n) 입니다.

## 9. 실전 heapq — 최대 힙, 튜플, 상위 K

**파이썬 3.13 까지의 `heapq` 에는 작은 것부터 꺼내는 최소 힙만 있어서 다른 순서가 필요하면 넣는 값의 모양을 바꿔 해결합니다.**

큰 것부터 꺼내는 최대 힙 함수 `heappush_max`, `heappop_max` 는 3.14 에서 처음 들어왔습니다. 다만 채점 환경(제출한 코드를 돌려 채점하는 곳)의 파이썬 판을 모를 때는 어느 판에서나 통하는 부호 뒤집기를 씁니다.

부호 뒤집기는 값 `v` 대신 `-v` 를 넣는 방법입니다. 부호를 뒤집으면 큰 값일수록 작은 값이 되므로 최소 힙에서는 원래 값이 큰 것부터 나옵니다. 꺼낸 값의 부호를 한 번 더 뒤집으면 원래 값으로 돌아옵니다. 값에 딸린 정보가 있으면 `(순위, 이름)` 처럼 튜플로 묶어 넣습니다. 튜플끼리는 첫 원소부터 비교하고 첫 원소가 같을 때만 다음 원소로 넘어가므로, 맨 앞에 둔 원소가 정렬 기준이 됩니다. 아래 코드는 값 5개를 부호를 뒤집어 넣어 큰 것부터 꺼낸 다음, 순위와 이름을 튜플로 묶은 작업 4개를 급한 것부터, 다시 말해 순위 숫자가 작은 것부터 꺼냅니다.

```python
# 하는 일: heapq 로 값 5개를 큰 것부터 꺼내고, 순위와 이름을 묶은 작업 4개를 급한 것부터 꺼낸다.
import heapq

값 = [23, 5, 38, 2, 45]

# 1단계: 부호를 뒤집어 큰 것부터 꺼낸다
# heappop 은 작은 것부터만 꺼낸다. 큰 것부터 꺼내려면 부호를 뒤집는다.
최대힙 = []
for v in 값:
    heapq.heappush(최대힙, -v)
print("큰 것부터", [-heapq.heappop(최대힙) for _ in range(len(값))])

# 2단계: 튜플로 묶어 급한 것부터 꺼낸다
# 값 말고 딸린 정보도 같이 넣으려면 튜플로 묶어 넣는다. 튜플은 앞 원소부터 비교하니 맨 앞에 순위를 둔다.
작업 = [(2, "리포트"), (1, "장애 대응"), (3, "회의"), (1, "배포 롤백")]
h = []
for 순위, 이름 in 작업:
    heapq.heappush(h, (순위, 이름))
print("급한 것부터")
while h:
    순위, 이름 = heapq.heappop(h)
    print(f"  {순위}순위  {이름}")

# 출력:
# 1단계 뜻: -v 로 넣고 꺼낼 때 다시 뒤집으니 큰 것부터 나온다.
# 큰 것부터 [45, 38, 23, 5, 2]
# 2단계 뜻: 튜플은 앞 원소부터 비교하니 순위 숫자가 작은 것부터 나온다. 순위가 같은 둘은 이름의 가나다순으로 배포 롤백이 먼저다.
# 급한 것부터
#   1순위  배포 롤백
#   1순위  장애 대응
#   2순위  리포트
#   3순위  회의
```

첫 줄에는 `[45, 38, 23, 5, 2]` 가 큰 것부터 찍혔습니다. 가장 큰 45 는 부호가 뒤집혀 들어가면 넣은 값 가운데 가장 작은 값이 되므로 맨 먼저 나오는데, 꺼낼 때 부호를 다시 뒤집으므로 45 로 찍힙니다. 작업 목록에서는 1순위가 2개인데, 순위가 같으면 튜플 비교가 둘째 원소인 이름으로 넘어가 가나다순으로 비교하므로 "배포 롤백"이 "장애 대응"보다 먼저 나왔습니다.

**넣은 차례를 그대로 지키고 싶으면 `(순위, 들어온 번호, 이름)` 처럼 들어온 번호를 둘째 원소로 하나 더 둡니다.** 들어온 번호는 작업마다 다른 값이라 순위가 같아도 비교가 이름까지 가지 않고 먼저 넣은 작업이 먼저 나옵니다. 이 둘째 원소를 빼면 순위가 같은 작업끼리 다시 이름으로 비교해 넣은 차례가 아니라 가나다순으로 나와 버립니다.

힙이 가장 자주 쓰이는 곳은 "값이 아주 많은데 큰 것 K개만 필요한" 문제입니다. 아래 코드는 값 200,000개에서 큰 것 10개를 세 가지 방법으로 구해 걸린 시간을 측정하고 세 답이 같은지 확인합니다. 세 방법 가운데 전부 정렬은 200,000개를 모두 큰 순서로 정렬한 뒤 앞의 10개를 잘라 냅니다. 직접 짠 힙은 10칸만 들고 있다가 11개가 되는 순간 가장 작은 것을 버립니다. 세 번째는 표준 라이브러리 함수 `heapq.nlargest` 입니다. 출력의 「들고 있는 칸」 열은 방법마다 한꺼번에 들고 있는 값의 개수입니다.

```python
# 하는 일: 값 20만 개에서 큰 것 10개를 전부 정렬, 직접 짠 힙, heapq.nlargest 세 방법으로 구해 걸린 시간을 비교한다.
import heapq, random, time

random.seed(7)
값 = [random.randint(1, 1_000_000) for _ in range(200_000)]
K = 10

# 1단계: 세 방법을 만든다
# 직접 짠 힙은 10칸만 들고 있다가 11개가 되면 가장 작은 것을 버린다.
def 측정(fn):
    t = time.perf_counter()
    r = fn()
    return (time.perf_counter() - t) * 1000, r

def 전부정렬():
    return sorted(값, reverse=True)[:K]

def 힙K칸():
    h = []
    for v in 값:
        heapq.heappush(h, v)
        if len(h) > K:
            heapq.heappop(h)       # 가장 작은 것을 버린다
    return sorted(h, reverse=True)

def nlargest():
    return heapq.nlargest(K, 값)

# 2단계: 세 방법을 측정하고 답을 비교한다
print(f"값 {len(값):,}개 중 큰 것 {K}개")
print(f"{'방법':<16}{'시간(ms)':>10}{'들고 있는 칸':>14}")
답 = []
for 이름, fn, 칸 in (("전부 정렬", 전부정렬, f"{len(값):,}"),
                    ("힙 K칸 직접", 힙K칸, str(K)),
                    ("heapq.nlargest", nlargest, str(K))):
    ms, r = 측정(fn)
    답.append(r)
    print(f"{이름:<16}{ms:>10.1f}{칸:>14}")
print(f"\n세 답이 모두 같나 {답[0] == 답[1] == 답[2]}")

# 출력 (시간은 돌릴 때마다 다르다):
# 2단계 뜻: 직접 짠 힙은 10칸만 들고도 31.9밀리초로, 200,000칸을 들고 전부 정렬한 21.9밀리초보다 느리다. nlargest 는 2.2밀리초로 셋 가운데 가장 빠르고, 세 답은 같다.
# 값 200,000개 중 큰 것 10개
# 방법                  시간(ms)       들고 있는 칸
# 전부 정렬                 21.9       200,000
# 힙 K칸 직접               31.9            10
# heapq.nlargest         2.2            10
#
# 세 답이 모두 같나 True
```

이번 출력의 시간은 전부 정렬 21.9밀리초, 직접 짠 힙 31.9밀리초, `nlargest` 2.2밀리초였고 세 답은 모두 같았습니다(`True`). 밀리초 값은 기계마다 다르지만 **이 출력에서는 직접 짠 힙이 전부 정렬보다 느립니다.** 직접 짠 힙은 10칸만 들고 계산 횟수도 적으니 더 빠를 것 같은데 결과가 반대로 나온 데는 까닭이 있습니다. 파이썬의 `sorted` 는 C 언어로 짜여 있는 반면 직접 짠 반복문은 파이썬이 한 줄씩 실행하므로, 직접 짠 힙의 계산 횟수가 적어도 계산 한 번의 비용이 훨씬 비쌉니다.

그런데 어느 쪽이 빠른지는 파이썬 판에 따라 뒤집힙니다. 같은 코드를 판마다 세 번씩 돌려 본 결과 3.9 에서는 직접 짠 힙이 32~35밀리초 걸려 22밀리초인 정렬보다 느렸습니다. 반면 반복문이 빨라진 3.12~3.15 에서는 직접 짠 힙이 14~19밀리초로 21~22밀리초인 정렬보다 빨랐습니다. 돌려 본 판에서는 모두 `nlargest` 가 가장 빨랐습니다.

`nlargest` 가 2.2밀리초로 압도적으로 빠른 데는 다른 까닭이 있습니다. `nlargest` 역시 파이썬으로 짠 함수인데, 값이 하나 올 때마다 지금까지 고른 K개 가운데 가장 작은 값과 한 번만 비교하고 그보다 크지 않은 대부분의 값은 그냥 지나갑니다. 반면 직접 짠 힙은 값 200,000개를 하나도 빼놓지 않고 하나씩 힙에 넣으며 K개를 넘을 때마다 하나를 다시 뺍니다.

이 측정에서 가져갈 결론은 두 가지입니다. **첫째, 같은 일을 하는 표준 라이브러리 함수가 있으면 파이썬에서는 그 함수가 직접 짠 반복문보다 거의 항상 빠릅니다.** **둘째, 그래도 직접 짠 힙에는 들고 있는 칸이 K개뿐이라는 값어치가 있습니다.** 출력의 「들고 있는 칸」 열에서 전부 정렬은 200,000칸을 들고 있어야 하지만 직접 짠 힙은 10칸이면 되므로, 값이 파일에서 한 줄씩 들어와 전부 담을 수 없을 때 이 점이 쓸모가 있습니다.

## 10. 상황별 자료구조 선택

**어느 자료구조를 쓸지는 입력이 어떤 모양인지와 문제가 무엇을 묻는지를 보고 정합니다.**

자료구조를 고르기 전에 입력이 트리 모양인지부터 확인합니다. 지훈이 받은 문제의 "상사"처럼 "부모", "폴더", "조상" 같은 말로 위아래 관계가 주어지면 그 입력은 트리입니다. 트리라면 문제가 층을 물을 때 3절처럼 큐로 층별 순회를 합니다. 자식을 모두 처리해야 부모를 처리할 수 있는 일이면 2절의 후위 순회를 씁니다.

값이 정렬된 상태에서 찾는 일이라면 6절에서 본 대로 이진 탐색 트리를 직접 만들지 말고 **앞 편의 `bisect`** 를 씁니다. 다만 파이썬 리스트는 가운데에 값을 넣는 데 O(n) 이 들어 넣기가 잦으면 불리한데, 코딩 테스트 범위에서는 이 방식으로도 대체로 통과합니다.

값이 계속 들어오는 동안 **최솟값이나 최댓값 하나만** 거듭 필요하다면 힙을 씁니다. "가장 급한 작업", "가장 가까운 점", "지금까지 중 K번째"를 묻는 문제가 모두 이런 모양입니다. 다음 편에서 다룰 최단 경로 알고리즘(그래프에서 두 마디 사이의 가장 짧은 경로를 찾는 방법)도 안에서 힙을 씁니다.

마지막으로 재귀를 쓸 때는 재귀가 얼마나 깊어질지부터 따져 봅니다. **입력 크기가 만을 넘으면 코드 맨 위에 `sys.setrecursionlimit` 을 적어 두는 습관을 들여야 합니다.**

## 한눈 정리

| 상황 | 쓸 것 | 왜 |
|---|---|---|
| 트리를 그대로 저장하거나 복사한다 | 전위 순회 | 뿌리부터 나와 위에서 아래로 다시 만든다 |
| 이진 탐색 트리를 정렬된 순서로 본다 | 중위 순회 | 왼쪽, 나, 오른쪽 순서가 곧 크기 순서 |
| 자식을 다 처리해야 부모를 처리한다 | 후위 순회 | 폴더 크기, 트리 삭제 |
| "몇 층인가", "각 층에 무엇이" | 큐로 층별 순회 | 반복문 전의 큐 길이가 그 층의 크기 |
| 재귀가 깊어질 것 같다 | `sys.setrecursionlimit` | 기본 한계가 1000뿐 |
| 정렬된 값에서 찾기, 넣기 | `bisect` | 이진 탐색 트리를 직접 안 짜도 된다 |
| 최솟값 하나만 반복해서 꺼낸다 | `heapq` | 넣기, 빼기 O(log n), 최솟값 보기 O(1) |
| 큰 것부터 꺼낸다 | 부호를 뒤집어 넣는다 | 파이썬 3.13 까지는 최소 힙만 준다 |
| 값에 정보를 붙여 넣는다 | 튜플 `(기준, 순번, 값)` | 앞 원소부터 비교하니 둘째 원소를 빼면 안 된다 |
| 아주 많은 값 중 상위 K개 | `heapq.nlargest` | 값 대부분을 한 번 비교하고 지나가 직접 짠 힙보다 빠르다 |

## 헷갈리기 쉬운 점

- **이진 탐색 트리의 찾기가 늘 O(log n) 은 아닙니다.** 값을 정렬된 순서로 넣으면 트리가 한 줄로 늘어져 찾기가 O(n) 이 되는데, 이 글에서도 같은 값 9개로 만든 두 트리가 13 을 찾는 데 4회와 8회로 차이가 났습니다.
- **중위 순회로 정렬된 순서가 나오려면 그 트리가 이진 탐색 트리여야 합니다.** 왼쪽은 작고 오른쪽은 크다는 규칙이 없는 이진 트리를 중위로 순회하면 값이 그냥 뒤섞인 순서로 나옵니다.
- **힙 안쪽의 리스트는 정렬된 상태가 아닙니다.** 맨 앞 칸만 최솟값으로 정해져 있고 둘째로 작은 값이 어느 칸에 있는지는 정해져 있지 않습니다.
- **파이썬 3.13 까지의 `heapq` 에는 최대 힙이 없습니다.** 그래서 부호를 뒤집어 넣는데, 문자열은 부호를 뒤집을 수 없으므로 값이 문자열이면 정렬 기준을 따로 만들어야 합니다. 3.14 부터는 `heappush_max` 에 문자열을 그대로 넣을 수 있지만 채점 환경의 파이썬이 그보다 낮은 판이면 이 함수를 쓸 수 없습니다.
- **튜플에서 둘째 원소(들어온 번호)를 빼면 안 됩니다.** 첫 원소가 같을 때 비교가 둘째 원소로 넘어가는데, 그 자리에 서로 비교할 수 없는 값이 오면 오류가 납니다.
- **직접 짠 힙이 `sorted` 보다 빠르다고 단정하면 안 됩니다.** 9절에서 같은 코드를 돌려 보니 3.9 에서는 직접 짠 힙이 정렬보다 느렸고 3.12~3.15 에서는 빨랐습니다. 직접 짠 힙의 값어치는 속도보다 **들고 있는 칸이 K개뿐**이라는 데 있습니다.
- **재귀 한계를 올려도 재귀를 끝없이 깊게 할 수는 없습니다.** 재귀는 호출할 때마다 실제 메모리를 쓰므로 너무 깊어지면 오류 대신 프로그램 전체가 죽습니다.
