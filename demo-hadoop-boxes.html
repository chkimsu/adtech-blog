하둡 상자 그림 여섯 장

상자 하나가 서버 한 대입니다. 상자에 적힌 글자는 그 서버에서 돌아가는 프로그램(역할)입니다. 이 두 가지만 잡으면 그림 여섯 장이 다 읽힙니다. 주소와 숫자는 설명용 예시입니다.

상자 = 서버 한 대 파랑 상자 = 내 접속 주소가 직접 가리키는 것 회색 네모 = 데이터 조각 벽돌색 네모 = 계산 조각 점선 = 목록 (데이터가 아니라 어디에 무엇이 있다는 기록)

1클러스터는 서버 여러 대입니다

한 클러스터에 상자가 수십에서 수백 개 있고, 상자마다 맡은 역할이 적혀 있습니다.

위 두 줄은 역할이 하나씩인 서버들입니다. 맨 아래 워커 상자에는 역할이 둘 붙어 있습니다. DataNode 는 데이터를 담고, NodeManager 는 계산을 합니다. 같은 상자에 둘이 있어서 데이터가 있는 자리에서 바로 계산할 수 있습니다.

2HDFS: 파일을 조각내서 여러 상자에 넣습니다

큰 파일 하나가 128 MB 조각으로 나뉘어 워커 상자들에 세 벌씩 흩어집니다. NameNode 는 어느 조각이 어느 상자에 있는지 목록만 갖습니다.

NameNode 상자 안에는 데이터가 없습니다. 목록만 있습니다. 워커 상자 하나가 꺼져도 같은 조각이 다른 두 상자에 있어서 파일은 살아 있습니다. hdfs://…:8020/경로 라는 주소는 이 NameNode 에게 「이 경로의 조각들이 어디 있나」를 묻는 주소입니다.

3YARN: 계산할 자리를 나눠 줍니다

쿼리 하나가 계산 조각 여러 개로 나뉩니다. ResourceManager 가 큐(줄)에서 CPU 와 메모리를 떼어 워커 상자의 NodeManager 에 조각을 얹습니다.

큐는 서버가 아닙니다. ResourceManager 안에서 자원을 나누는 줄입니다. 주소 끝의 tez.queue.name=analytics 는 「내 쿼리는 analytics 줄에서 자원을 받아라」는 뜻입니다. 그 줄이 가득 차면 쿼리는 줄에서 기다립니다. 계산 조각은 데이터 조각이 있는 상자에 먼저 얹힙니다.

4Hive: 서버 둘, 목록 하나

HiveServer2 는 SQL 을 받는 서버입니다. Metastore 는 테이블 이름, 컬럼, 파일 위치의 목록을 가진 서버입니다. 데이터는 둘 다 갖고 있지 않습니다.

내가 SQL 을 보내면 HiveServer2 가 Metastore 에 「ad_click 은 어떤 컬럼이고 파일은 어디 있나」를 묻습니다. 답은 HDFS 경로입니다. 그 경로의 조각들을 워커 상자들이 읽어서 셉니다. Metastore 뒤에는 그 목록을 실제로 저장하는 보통의 관계형 DB 상자(MySQL 같은 것)가 하나 더 있습니다.

5주소 한 줄이 가리키는 상자

주소에 적힌 다섯 서버는 HiveServer2 가 아니라 ZooKeeper 입니다. ZooKeeper 상자 안의 목록에 「지금 살아 있는 HiveServer2」 가 적혀 있습니다.

그래서 HiveServer2 를 늘리거나 바꿔도 내 주소는 그대로입니다. ZooKeeper 가 다섯 대인 것은 같은 목록을 다섯 벌 갖고 있다가 셋만 살아 있어도 답하려는 것입니다. ; 로 이어진 조각은 접속 조건이고, ? 뒤 한 조각만 Hive 설정(큐)입니다.

6쿼리 한 건이 지나는 길

내가 주소로 직접 가는 곳은 ZooKeeper 와 HiveServer2 두 곳입니다. 나머지는 상자들끼리 서로 압니다.

1 ZooKeeper 에 「HiveServer2 어디 있어」를 묻고, 2 살아 있는 하나(hs2-a)를 받습니다. 3 hs2-a 에 계정과 SQL 을 보냅니다. 4 hs2-a 가 Metastore 에 컬럼과 파일 위치를 묻고, 5 ResourceManager 의 analytics 줄에서 자원을 받습니다. 6 워커 상자들에 계산 조각이 얹혀 데이터 조각을 읽고 셉니다. 7 결과가 hs2-a 를 거쳐 나에게 돌아옵니다.

현업에서는 이렇게 씁니다

  • 접속 주소를 받으면 세 가지만 찾습니다. 서버 목록이 ZooKeeper 인지(serviceDiscoveryMode=zooKeeper), 목록 폴더 이름(zooKeeperNamespace), 그리고 물음표 뒤의 큐 이름입니다. 나머지는 접속 조건입니다.
  • 터미널에서는 beeline 으로 붙습니다. 주소 전체를 따옴표로 감쌉니다. 세미콜론과 물음표가 셸에 잡히기 때문입니다.
  • 안 될 때는 번호 순서로 봅니다. ZooKeeper 에 못 붙으면 1, 목록이 비었으면 2, 계정 오류면 3, 테이블 없음이면 4, 큐 권한이면 5, 파일 읽기 권한이면 6 과 7 입니다.
beeline -u "jdbc:hive2://zk1.example.com:2181,zk2.example.com:2181,zk3.example.com:2181/;serviceDiscoveryMode=zooKeeper;zooKeeperNamespace=hiveserver2;transportMode=http;httpPath=cliservice?tez.queue.name=analytics" -n analyst -p
