지훈 씨는 면접에서 "CTR 예측 모델을 어떻게 만들겠나"라는 질문을 받고 준비해 간 대로 잘 답했습니다. CTR(Click-Through Rate)은 광고가 노출된 횟수 가운데 클릭이 난 비율입니다. CTR 예측 모델은 노출 하나하나가 클릭될 확률을 미리 내놓습니다. 지훈 씨는 쓸 피처(모델이 예측에 쓰는 입력 값)를 나열하고 모델을 하나 고른 뒤 AUC 로 평가하겠다고 말했습니다. AUC 는 클릭한 노출과 안 누른 노출로 만들 수 있는 모든 짝 가운데 모델이 클릭한 쪽에 더 높은 값을 준 짝의 비율입니다. AUC 가 0.5 면 모델이 두 노출을 전혀 구분하지 못하고 1 에 가까울수록 클릭할 노출을 위에 잘 놓습니다.

그러자 면접관이 되물었습니다. "AUC가 0.72에서 0.75로 올랐는데 매출은 그대로예요. 왜 그럴까요?" 지훈 씨는 이 질문에 답하지 못했습니다.

**면접이 실제로 보는 것은 무엇일까요?**

답은 지식이 아닙니다. 면접관은 지원자가 답을 아는지가 아니라 **틀렸을 때 어떻게 알아채는지**를 봅니다. 이 글은 광고 ML 면접에서 되풀이해 나오는 질문 14개를 모아 답과 함께 그 답이 왜 맞는지를 직접 실행되는 코드로 확인합니다.

> **한 줄 요약:** 면접 질문은 대부분 "이 지표가 좋아졌는데 왜 돈이 안 벌리나"를 모양만 바꾼 질문이며 그 답은 거의 항상 **순위 매기기(클릭할 노출을 위에 놓는 일)와 값 맞추기(예측 확률을 실제 비율에 맞추는 일)가 서로 다른 일이라는 데** 있습니다. AUC 는 순위 매기기만 측정하는데, 광고는 대체로 예측값을 입찰가 계산에 그대로 쓰므로 값까지 맞아야 합니다.

> **골라 읽는 법** — 절은 10개이고 절마다 면접 질문이 한두 개씩 있습니다.
>
> - 어떤 질문에나 붙이는 답의 틀만 → 1절
> - 지표 질문(AUC, 보정, 불균형) → 2절부터 4절까지
> - 데이터의 함정 → 5절과 6절
> - 모델 선택과 랭킹 → 7절부터 9절까지
> - 모르는 것을 물었을 때 → 마지막 10절

## 1. 답보다 판단 과정을 보는 면접

**답 하나에 "왜 그렇게 판단했나"를 붙이면 같은 답도 다른 답이 됩니다. 전제 확인, 하나를 고른 이유, 틀렸을 때 알아낼 방법의 3단계를 차례로 붙이면 어떤 질문에서든 답의 형태가 갖춰집니다.**

경력 면접에서는 정답이 하나로 정해진 질문이 드뭅니다. 예를 들어 "어떤 모델을 쓰겠나"라는 질문에 XGBoost 라고만 답하면 반쯤 맞은 답입니다. XGBoost 는 GBDT 를 구현한 라이브러리 가운데 하나입니다. GBDT(Gradient Boosted Decision Trees)는 결정 트리(조건에 따라 데이터를 가지처럼 나눠 예측하는 모델)를 여러 개 차례로 학습하면서 앞의 트리들이 틀린 만큼을 다음 트리가 고쳐 나가는 모델입니다.

같은 질문에 "지금 데이터가 하루 2억 건이고 피처가 대부분 범주형이라 GBDT가 낫다"까지 말해야 온전히 맞은 답이 되는데, 이 답에는 데이터의 크기와 피처의 종류라는 전제와 그 전제에서 GBDT 를 고른 이유가 함께 들어 있습니다. 범주형 피처는 업종이나 기기처럼 숫자의 크기가 아니라 정해진 종류 가운데 하나를 값으로 갖는 피처입니다.

답에 붙이는 3가지는 아래 순서를 따릅니다.

**첫째, 전제를 확인합니다.** "하루 요청이 몇 건인가요", "응답 시간 예산이 얼마인가요"처럼 되묻는 말은 시간을 끄는 것이 아니라 답의 일부입니다. 응답 시간 예산은 요청 하나에 답을 돌려줘야 하는 시간의 한도로, 6절에서 피처를 쓸 수 있는지 정하는 기준으로 다시 나옵니다. 같은 질문도 상황에 따라 맞는 답이 달라지므로 전제 없이 내놓은 답은 어느 상황에서도 맞지 않습니다.

**둘째, 하나를 고르고 그 이유를 댑니다.** 후보만 늘어놓으면 면접관에게 "판단을 못 한다"로 읽힙니다. 트레이드오프(하나를 고를 때 얻는 것과 잃는 것)는 말하되 결론은 하나로 냅니다.

**셋째, 답이 틀렸을 때 어떻게 알아낼지를 말합니다.** 경력 지원자와 신입 지원자의 답은 이 단계에서 차이가 납니다. "배포 후 COPC를 시간대별로 보고 1에서 벗어나면 되돌립니다"까지 말하면 실무를 해 봤다는 신호가 되는데, 이 문장에는 배포 뒤에 무엇을 보고(시간대별 COPC) 언제 움직이고(1에서 벗어날 때) 무엇을 할지(배포를 되돌리기)가 모두 들어 있습니다. COPC 는 실제 클릭 수를 모델이 낸 예측 확률의 합으로 나눈 값입니다. 1 이면 예측과 실제가 맞고 1 보다 작으면 모델이 실제보다 크게 예측한 과대예측입니다. COPC 는 3절에서 세 모델로 직접 계산해 봅니다.

> **면접관이 듣고 싶은 것** — 아래 모든 답안에서 굵게 표시한 문장이 그 답의 중심이고 나머지는 그 문장을 받치는 근거이므로, 시간이 없으면 굵은 문장만 말해도 됩니다.

## 2. 불균형 — CTR 0.2% 데이터의 학습

**클릭이 0.2% 뿐인 데이터에서는 아무것도 하지 않는 모델도 정확도 99.8% 를 받으므로 정확도로 모델을 평가하지 않습니다. 학습은 안 누른 노출을 일부만 남기는 다운샘플링으로 빠르게 하되, 그 탓에 커진 예측값을 되돌리는 데까지가 다운샘플링입니다.**

클릭한 노출과 안 누른 노출처럼 모델이 구분해야 할 두 무리의 수가 크게 차이 나는 상태를 클래스 불균형이라고 부릅니다. 아래 첫 질문은 이 불균형을 어떻게 다루는지 묻습니다. 뒤에 나올 코드의 주석에 적힌 대로 CTR 0.2% 는 광고에서 흔한 값입니다.

**Q. 클릭이 전체의 0.2%밖에 안 됩니다. 어떻게 학습하시겠습니까?**

답은 학습 방법보다 먼저 정확도를 평가에 쓰지 않는다는 말부터 해야 합니다. 정확도(accuracy)는 전체 노출 가운데 모델의 판정이 실제와 맞은 비율입니다. 확률을 내는 모델은 임계값을 하나 정해 예측값이 그 이상이면 「누른다」, 그보다 작으면 「안 누른다」로 판정한 뒤 정확도를 셉니다. 왜 정확도를 쓰지 않는지는 측정해 보면 바로 나옵니다.

아래 코드는 CTR 0.2% 인 노출 10만 건에서 임계값 0.5 로 두 모델의 정확도를 비교합니다. 모델 A 는 모든 노출에 0 을 내서 전부 안 누른다고 답하고 모델 B 는 클릭한 노출에 0.006 근처, 안 누른 노출에 0.0015 근처의 값을 내서 두 노출을 실제로 구분합니다.

```python
# 하는 일: CTR 0.2% 인 노출 10만 건에서 전부 안 누른다고 답하는 모델 A 와 실제로 구분하는 모델 B 의 정확도를 비교한다.
import random

random.seed(20260815)

# 1단계: 노출 10만 건의 클릭 라벨을 만든다
N = 100_000
CTR = 0.002                                    # 0.2% — 광고에서 흔한 값

라벨 = [1 if random.random() < CTR else 0 for _ in range(N)]
클릭수 = sum(라벨)

# 2단계: 두 모델의 예측을 만든다
예측A = [0.0] * N                              # 무조건 "안 누른다"
예측B = [min(0.999, max(0.001, (0.006 if y else 0.0015) + random.gauss(0, 0.001))) for y in 라벨]

# 3단계: 임계값 0.5 로 두 모델의 정확도를 비교한다
# B 의 예측값은 모두 0.5 보다 작아서, B 도 전부 안 누른다고 답한 것과 같아진다.
def 정확도(pred):
    return sum((p >= 0.5) == (y == 1) for p, y in zip(pred, 라벨)) / N

print(f"노출 {N:,}건, 클릭 {클릭수:,}건 ({클릭수/N:.3%})")
print(f"{'모델':<26}{'정확도':>10}")
print(f"{'A: 전부 안 누른다고 답':<24}{정확도(예측A):>10.4%}")
print(f"{'B: 실제로 구분하는 모델':<24}{정확도(예측B):>10.4%}")
print("\n둘 다 99.8% 다. 정확도로는 두 모델을 나눌 수 없다.")

# 출력:
# 3단계 뜻: 클릭이 202건(0.202%)뿐이라 전부 안 누른다고 답해도 정확도가 99.7980% 이고, B 도 같은 99.7980% 다. 정확도로는 두 모델을 나눌 수 없다.
# 노출 100,000건, 클릭 202건 (0.202%)
# 모델                               정확도
# A: 전부 안 누른다고 답            99.7980%
# B: 실제로 구분하는 모델            99.7980%
#
# 둘 다 99.8% 다. 정확도로는 두 모델을 나눌 수 없다.
```

찍힌 값을 보면 노출 100,000건 가운데 클릭은 202건(0.202%)이라, A 처럼 전부 안 누른다고 답하면 클릭 202건만 틀리고 나머지는 모두 맞아 정확도가 99.7980% 입니다. B 는 클릭한 노출에 더 높은 값을 주지만 그 값도 모두 0.5 보다 작아 임계값 0.5 에서는 모든 노출이 「안 누른다」로 판정되므로 A 와 똑같은 99.7980% 를 받습니다. 실제로 구분하는 B 와 아무것도 구분하지 못하는 A 가 똑같이 99.8% 이므로 정확도로는 두 모델을 나눌 수 없습니다.

**아무것도 하지 않는 모델이 정확도 99.8% 를 받습니다.** 답은 이 한 줄에서 출발해 정확도 대신 로그로스와 AUC 를 보고 광고에서는 보정까지 함께 본다고 이어 갑니다. 로그로스(log loss)는 노출마다 실제 결과에 모델이 준 확률의 로그를 구해 평균한 뒤 부호를 바꾼 값입니다. 클릭한 노출에 낮은 확률을 주거나 안 누른 노출에 높은 확률을 줄수록 값이 커지므로 로그로스가 낮을수록 좋습니다. 보정(calibration)은 모델이 낸 확률이 실제로 일어나는 비율과 맞도록 하는 일이며 3절과 4절에서 다룹니다.

평가 지표를 정했으면 다음은 학습 방법입니다. **실무에서는 다운샘플링으로 학습하는 것이 기본입니다.** 다운샘플링(downsampling)은 안 누른 노출을 일정 비율만 남기고 나머지를 버려 학습 데이터를 줄이는 방법입니다. 학습 데이터가 줄어드는 만큼 학습이 훨씬 빨라집니다. 모델이 배울 신호는 클릭 쪽에 있으므로 클릭한 노출은 하나도 버리지 않고 전부 남깁니다.

**Q. 다운샘플링하면 예측값이 실제보다 커지지 않습니까?**

커집니다. 그리고 **커진 값을 되돌리는 것까지가 다운샘플링입니다.** 면접관의 이 되묻기에 답하지 못하면 실무 경험이 없는 지원자로 읽힙니다.

안 누른 노출만 줄이면 클릭 수는 그대로인 채 전체 노출 수만 줄어 샘플의 CTR 이 커지므로, 그 샘플로 학습한 모델도 커진 CTR 에 맞춘 값을 냅니다. 아래 코드는 CTR 0.2% 인 노출 50만 건에서 안 누른 노출을 5% 만 남기면 CTR 이 몇 배로 커지는지 본 다음 되돌리는 공식으로 원래 CTR 을 되찾는지 확인합니다.

```python
# 하는 일: CTR 0.2% 인 노출 50만 건에서 안 누른 건을 5% 만 남기면 CTR 이 몇 배로 커지는지 보고, 되돌리는 공식으로 원래 CTR 을 되찾는다.
import random

random.seed(7)

# 1단계: 노출 50만 건의 클릭 라벨을 만든다
N, CTR = 500_000, 0.002
라벨 = [1 if random.random() < CTR else 0 for _ in range(N)]
클릭 = sum(라벨)
비클릭 = N - 클릭

# 2단계: 안 누른 건을 5% 만 남기고 CTR 을 비교한다
r = 0.05                                    # 안 누른 건을 5% 만 남긴다
남긴비클릭 = int(비클릭 * r)
샘플크기 = 클릭 + 남긴비클릭

원래CTR = 클릭 / N
샘플CTR = 클릭 / 샘플크기

print(f"원본      노출 {N:>9,}  클릭 {클릭:>6,}  CTR {원래CTR:.4%}")
print(f"5% 샘플링 노출 {샘플크기:>9,}  클릭 {클릭:>6,}  CTR {샘플CTR:.4%}")
print(f"→ 샘플에서 CTR 이 {샘플CTR/원래CTR:.1f}배로 커진다\n")

# 3단계: 샘플에서 낸 값을 되돌리는 함수로 원래 CTR 을 되찾는다
def 되돌리기(p, r):
    return p / (p + (1 - p) / r)

print(f"{'샘플에서 모델이 낸 값':>20}{'그대로 쓰면':>12}{'되돌리면':>12}")
for p in (0.01, 0.03, 0.05, 0.1):
    print(f"{p:>20.3f}{p:>12.4f}{되돌리기(p, r):>12.4f}")

print(f"\n샘플 평균 {샘플CTR:.4f} 를 되돌리면 {되돌리기(샘플CTR, r):.5f}, 원래 CTR {원래CTR:.5f}")
print("두 값이 같다 — 공식이 맞다는 뜻이다.")

# 출력:
# 2단계 뜻: 원본 CTR 0.2010% 가 5% 샘플링 뒤에는 3.8722% 로, 19.3배 커진다.
# 원본      노출   500,000  클릭  1,005  CTR 0.2010%
# 5% 샘플링 노출    25,954  클릭  1,005  CTR 3.8722%
# → 샘플에서 CTR 이 19.3배로 커진다
#
# 3단계 뜻: 샘플에서 0.010 을 낸 모델은 되돌리면 0.0005 다. 샘플 평균 0.0387 을 되돌린 0.00201 이 원래 CTR 0.00201 과 같다.
#         샘플에서 모델이 낸 값      그대로 쓰면        되돌리면
#                0.010      0.0100      0.0005
#                0.030      0.0300      0.0015
#                0.050      0.0500      0.0026
#                0.100      0.1000      0.0055
#
# 샘플 평균 0.0387 를 되돌리면 0.00201, 원래 CTR 0.00201
# 두 값이 같다 — 공식이 맞다는 뜻이다.
```

2단계 출력을 보면 클릭 1,005건은 그대로 두고 안 누른 노출만 5% 를 남기자 노출이 500,000건에서 25,954건으로 줄었습니다. 같은 클릭 수를 훨씬 작은 노출 수로 나누므로 CTR 은 0.2010% 에서 3.8722% 로 19.3배 커졌습니다.

되돌리는 식은 `p / (p + (1-p)/r)` 입니다. `p` 는 샘플로 학습한 모델이 낸 값이고 `r` 은 안 누른 노출을 남긴 비율로 여기서는 0.05 입니다. 분모의 `(1-p)/r` 은 샘플에서 안 누른 몫인 `1-p` 를 남긴 비율 `r` 로 나눠 버리기 전의 크기로 되돌린 값이라, `p` 를 `p + (1-p)/r` 로 나누면 안 누른 노출을 버리지 않았을 때의 클릭 비율이 나옵니다. 3단계 표의 첫 줄에서 보듯 샘플에서 모델이 0.010 을 냈다면 `p` 에 0.010, `r` 에 0.05 를 넣어 0.0005 가 나오며 0.100 을 냈다면 0.0055 가 나옵니다. 마지막 줄은 샘플 전체의 평균 0.0387 을 같은 식에 넣은 값인데, 되돌린 0.00201 이 원래 CTR 0.00201 과 같으므로 공식이 맞습니다.

이 되돌리기 보정을 빼먹으면 모델의 예측값이 샘플의 CTR 처럼 **19배로 커진 채** 입찰에 들어갑니다.

**답에는 그 결과로 무슨 일이 벌어지는지까지 붙이면 좋습니다.** 입찰가는 대체로 예측 확률에 비례해 정해지므로 19배 커진 값으로 입찰하면 광고비도 그만큼 더 씁니다. 이렇게 모델 지표는 멀쩡한데 비용만 크게 느는 사고가 납니다. 예측값이 19배로 커져도 모델 지표가 멀쩡한 까닭은 3절에서 세 모델을 비교하며 봅니다.

## 3. AUC — 오른 지표와 그대로인 매출

**AUC 는 순위 매기기만 측정하고 값이 맞는지는 측정하지 않으므로 예측값을 모두 3배로 키운 모델도 AUC 가 그대로입니다. 매출은 값이 맞아야 움직이므로 COPC 같은 보정 지표를 AUC 와 함께 봅니다.**

도입에서 지훈 씨가 답하지 못한 질문이 바로 아래 질문이며 이 글의 중심도 이 질문입니다.

**Q. 오프라인 AUC가 0.72에서 0.75로 올랐는데 A/B 테스트에서 매출이 안 움직였습니다. 왜일까요?**

오프라인 AUC 는 서비스에 내보내기 전에 모아 둔 로그로 계산한 AUC 입니다. A/B 테스트는 사용자를 두 무리로 나눠 한쪽에는 기존 모델을, 다른 쪽에는 새 모델을 적용해 결과를 비교하는 실험입니다. 답을 한 문장으로 쓰면 이렇습니다. **AUC 는 순위 매기기만 측정하고 값이 맞는지는 측정하지 않습니다.**

아래 코드는 노출 20만 건에서 세 모델을 만들어 AUC, 로그로스, COPC 세 지표로 비교합니다. 코드는 노출마다 진짜 클릭 확률을 정하고 그 확률로 클릭 라벨(클릭이 났으면 1, 아니면 0)을 뽑습니다. 모델 A 는 모든 노출에 평균 클릭률 하나만 답하고 모델 B 는 노출마다 진짜 클릭 확률에 가까운 값을 내며 모델 C 는 B 의 예측값을 모두 3배로 키워 순위는 B 와 같고 값만 다릅니다.

```python
# 하는 일: 노출 20만 건에서 평균값만 답하는 모델 A, 구분도 하고 값도 맞는 모델 B, B 와 순위는 같고 값만 3배인 모델 C 를 AUC, 로그로스, COPC 로 비교한다.
import random, math, bisect

random.seed(20260815)
N = 200_000

# 1단계: 노출마다 진짜 클릭 확률과 라벨을 만든다
# 노출마다 "진짜 클릭 확률"이 있고, 라벨은 그 확률로 뽑힌다.
진짜 = [min(0.05, max(0.0002, random.lognormvariate(-6.4, 0.9))) for _ in range(N)]
라벨 = [1 if random.random() < p else 0 for p in 진짜]
평균 = sum(라벨) / N

# 2단계: 세 모델의 예측을 만든다
예측A = [평균] * N                                              # 전부 평균값만 답한다
예측B = [min(0.5, max(1e-5, p * math.exp(random.gauss(0, 0.35)))) for p in 진짜]
예측C = [min(0.9, p * 3) for p in 예측B]                        # B 와 순위는 같고 값만 3배

# 3단계: AUC, 로그로스, COPC 함수를 만든다
def auc(pred):
    양 = sorted(p for p, y in zip(pred, 라벨) if y == 1)
    음 = sorted(p for p, y in zip(pred, 라벨) if y == 0)
    합 = 0.0
    for p in 양:
        아래 = bisect.bisect_left(음, p)
        같음 = bisect.bisect_right(음, p) - 아래
        합 += 아래 + 같음 / 2
    return 합 / (len(양) * len(음))

def 로그로스(pred):
    return -sum(math.log(p) if y else math.log(1 - p) for p, y in zip(pred, 라벨)) / N

def copc(pred):
    return sum(라벨) / sum(pred)

# 4단계: 세 모델을 세 지표로 비교한다
print(f"노출 {N:,}건, 클릭 {sum(라벨):,}건 ({평균:.3%})")
print(f"{'모델':<30}{'AUC':>8}{'로그로스':>12}{'COPC':>9}")
for 이름, p in (("A: 평균값만 답한다", 예측A),
                ("B: 구분도 하고 값도 맞다", 예측B),
                ("C: B 와 순위 같고 값만 3배", 예측C)):
    print(f"{이름:<28}{auc(p):>8.4f}{로그로스(p):>12.5f}{copc(p):>9.3f}")

print("\nCOPC = 실제 클릭 ÷ 예측 합. 1 이면 잘 맞고, 1 보다 작으면 과대예측이다.")
print("C 는 AUC 가 B 와 똑같은데 COPC 만 어긋났다 — 순위 매기기는 같고 값이 틀렸다.")

# 출력:
# 4단계 뜻: 클릭률 0.251% 인 노출 200,000건에서 B 와 C 는 AUC 가 0.7180 으로 똑같지만, COPC 는 B 가 0.952, C 가 0.317 이고 로그로스도 C 가 0.01922 로 가장 나쁘다.
# 노출 200,000건, 클릭 501건 (0.251%)
# 모델                                 AUC        로그로스     COPC
# A: 평균값만 답한다                   0.5000     0.01751    1.000
# B: 구분도 하고 값도 맞다               0.7180     0.01667    0.952
# C: B 와 순위 같고 값만 3배            0.7180     0.01922    0.317
#
# COPC = 실제 클릭 ÷ 예측 합. 1 이면 잘 맞고, 1 보다 작으면 과대예측이다.
# C 는 AUC 가 B 와 똑같은데 COPC 만 어긋났다 — 순위 매기기는 같고 값이 틀렸다.
```

표를 세로로 읽어 봅니다. 노출 200,000건 가운데 클릭은 501건(0.251%)입니다.

**A 는 AUC 가 0.5 로 셋 가운데 가장 나쁜데 COPC 는 1.000 으로 정확히 1 입니다.** A 는 모든 노출에 같은 값을 주므로 클릭한 노출과 안 누른 노출을 전혀 구분하지 못해 AUC 가 0.5000 이지만 그 같은 값이 실제 평균 클릭률이라 예측 합이 실제 클릭 수와 같아져 COPC 가 1.000 이 됩니다. B 는 AUC 가 0.7180 으로 클릭할 노출을 위에 잘 놓고 COPC 도 0.952 로 1 에 가까워 값도 맞습니다.

**C 는 AUC 가 B 와 소수점까지 같은 0.7180 인데 COPC 는 0.317 입니다.** C 는 B 의 예측값을 3배로 키웠을 뿐이라 어느 노출이 어느 노출보다 위에 있는지가 바뀌지 않아 AUC 가 움직이지 않았습니다. 반면 COPC 는 예측 합이 3배로 커지면서 B 의 0.952 에서 약 3분의 1 인 0.317 로 떨어졌습니다. 2절에서 본 대로 입찰가는 대체로 예측 확률에 비례하므로 이 모델을 배포하면 광고비를 3배 씁니다.

## 4. 보정 — 실제 확률과 다른 예측값

**예측값이 실제 확률과 다르면 입찰가, 예산 배분, 모델 신뢰가 이 순서로 깨집니다. 상수 하나를 곱하는 보정은 평균만 맞추므로 구간별로 측정해 고치며 배포한 뒤에도 COPC 를 계속 측정합니다.**

3절의 C 처럼 순위는 맞는데 값이 틀린 모델을 배포하면 무엇이 잘못되는지, 그리고 그 값을 어떻게 고치는지를 아래 두 질문이 묻습니다.

**Q. 모델이 낸 값이 실제 확률과 다르면 구체적으로 무엇이 깨집니까?**

입찰가, 예산 배분, 사람의 신뢰 세 가지가 이 순서로 깨집니다.

**첫째, 입찰가가 틀립니다.** 광고 입찰가는 대체로 예상 클릭 확률에 클릭당 가치를 곱해 만들므로, 확률을 실제의 두 배로 예측하면 입찰가도 두 배가 되어 필요 이상으로 비싸게 낙찰받습니다. 낙찰은 경매에서 이겨 그 자리에 광고를 내보내게 되는 일입니다.

**둘째, 예산 배분이 틀립니다.** 어느 캠페인에 얼마를 쓸지는 캠페인마다 예상되는 성과를 보고 정하는데, 예측값이 커진 정도가 캠페인마다 다르면 캠페인끼리 비교한 예상 성과가 서로 다른 비율로 틀려 배분 자체가 틀어집니다. 캠페인은 광고주가 하나의 목표와 예산으로 운영하는 광고들의 단위입니다.

**셋째, 사람이 모델을 믿지 못하게 됩니다.** 모델이 "예상 전환 100건"이라고 했는데 실제 전환이 60건에 그치면 다음부터는 아무도 그 숫자를 보지 않습니다. 전환은 광고를 클릭한 사람이 구매나 가입처럼 광고주가 바란 행동까지 한 일을 말합니다.

**Q. 보정은 어떻게 합니까?**

가장 단순한 보정은 최근 기간의 COPC 를 구해 모든 예측값에 곱하는 방법입니다. 3절의 C 에 COPC 0.317 을 곱하면 예측 합이 실제 클릭 501건과 같아져 COPC 가 1 이 되므로 평균은 맞습니다. 다만 상수 하나는 모든 예측값을 같은 비율로 키우거나 줄이므로 이 방법은 **평균만** 맞출 뿐 구간마다 다르게 틀린 예측은 잡지 못합니다.

구간별로 보려면 노출을 예측값 크기에 따라 10개쯤의 구간으로 나누고 구간마다 모델이 낸 평균 예측과 실제 클릭 비율을 비교합니다. 낮은 구간에서는 실제보다 작게 예측하는 과소예측이, 높은 구간에서는 실제보다 크게 예측하는 과대예측이 함께 나타나는 꼴이 흔합니다. 이런 모델은 낮은 구간의 값은 키우고 높은 구간의 값은 줄여야 하므로 상수 하나로는 맞출 수 없습니다. 이때는 구간별 보정이나 Platt scaling, isotonic regression 을 씁니다.

구간별 보정은 구간마다 보정값을 따로 정해 그 구간의 예측에 적용합니다. Platt scaling 은 모델의 점수를 시그모이드 함수(어떤 값이든 0 과 1 사이로 바꾸는 함수)에 넣어 확률로 바꾸되 시그모이드의 기울기와 위치를 실제 결과에 맞춰 학습하는 방법입니다. isotonic regression 은 곡선 모양을 미리 정하지 않고 데이터에 맞춘 계단 모양 함수로 예측을 바꿉니다. 계단이 내려가지 않으므로 예측의 순서를 뒤집지 않습니다.

**답에는 반드시 이 말을 붙입니다.** "보정은 배포 전에 한 번 하고 끝나는 것이 아니라 계속 측정해야 합니다." 시장이 변하면 어제 맞던 보정이 오늘은 맞지 않으므로, COPC 를 시간대별로 대시보드에 띄워 두고 1 에서 벗어나면 알림이 가게 하는 것이 실무의 기본형입니다.

:::deep 되돌리기 공식만으로 보정이 끝나지 않는 까닭

2절의 되돌리기 공식은 안 누른 노출을 **정확히 이론대로 뽑았을 때만** 맞습니다. 실제 데이터에서는 공식을 적용한 뒤에도 예측이 실제와 맞지 않는 까닭이 몇 가지 있습니다.

첫째는 샘플링 비율이 고르지 않은 경우입니다. 트래픽(들어오는 요청의 양)이 많은 시간대에서만 안 누른 노출을 더 많이 버리거나 특정 지면(광고가 실리는 화면 속 자리)에서만 다른 비율로 뽑았다면, 그 시간대와 지면은 남긴 비율이 다르므로 되돌리기 상수도 달라야 합니다. 그런데도 `r` 하나로 전부 되돌리면 비율이 다른 만큼 값이 틀립니다.

둘째는 모델 자체의 편향(한쪽으로 치우친 예측)이 남아 있는 경우입니다. 되돌리기는 샘플링 때문에 생긴 치우침만 없애므로, 모델이 원래부터 특정 구간을 과대예측하고 있었다면 그 과대예측은 되돌린 뒤에도 그대로 남습니다.

셋째는 지연 전환입니다. 전환은 클릭하고 며칠 뒤에도 일어나므로 학습하는 시점에 아직 일어나지 않은 전환은 라벨에 0 으로 들어가 모델이 전환율을 실제보다 낮게 배웁니다. 그러면 되돌리기를 정확히 해도 예측이 실제보다 작아 COPC 가 1 을 넘습니다.

**면접에서 "COPC가 1.15인데 원인이 뭘까요"라고 물으면 이 세 가지를 후보로 대면 됩니다.** COPC 1.15 는 실제가 예측 합보다 15% 많다는 뜻이라 모델이 실제보다 작게 예측하고 있습니다. 그리고 세 후보를 어떻게 구분할지까지 말합니다. 지연 전환이 원인이면 관측 기간(전환을 기다렸다가 라벨을 정하는 기간)을 늘렸을 때 COPC 가 1 로 수렴합니다. 샘플링 비율이 문제라면 지면별로 COPC 가 서로 다릅니다.

## 5. 데이터 누수 — 오프라인과 온라인 성능 차이

**오프라인 검증은 좋은데 배포하면 성능이 떨어질 때는 데이터를 어떻게 나눴는지부터 봅니다. 시간이 있는 데이터를 무작위로 나누면 서비스에서는 아직 알 수 없는 정보가 학습에 섞이므로, 시간이 있는 데이터는 시간으로 나누고 피처마다 실제 요청을 처리하는 순간에 그 값을 알 수 있는지 묻습니다.**

오프라인 성능은 모아 둔 로그로 계산한 검증 성능이고 온라인 성능은 배포한 모델이 실제 서비스에서 내는 성능입니다. 아래 질문은 두 성능이 크게 다를 때 어디부터 볼지를 묻습니다.

**Q. 검증 AUC는 좋은데 배포하면 성능이 뚝 떨어집니다. 어디를 보시겠습니까?**

가장 먼저 **데이터를 어떻게 나눴는지**를 봅니다. 검증 데이터(validation data)는 학습에 쓰지 않고 떼어 둔 데이터로 모델이 처음 보는 데이터에서도 잘 맞히는지 확인하는 데 씁니다. 그런데 날짜가 있는 로그를 무작위로 섞어 나누면 검증할 노출과 같은 날이나 그 뒤의 기록이 학습 데이터에 섞여 미래가 학습에 들어갑니다.

아래 코드는 날마다 인기 소재가 바뀌는 30일치 로그 6만 건(하루 2,000건)에서 「그 날 그 소재의 CTR」을 피처로 쓸 때, 무작위로 나눈 검증과 날짜로 나눈 검증의 AUC 를 비교합니다. 소재는 광고에 쓰는 이미지와 문구 하나하나입니다. 로그에는 소재가 50개 있고 날마다 그중 1개만 인기 소재가 되어 클릭 확률이 0.20 이며 나머지 소재는 0.03 입니다. 피처 값은 학습 데이터에서 (날, 소재) 조합마다 계산한 CTR 로, 코드 주석대로 실무에서 흔히 쓰는 일자별 통계입니다. 검증할 노출의 조합이 학습 데이터에 없으면 학습 데이터 전체의 평균 CTR 을 대신 씁니다.

```python
# 하는 일: 날마다 인기 소재가 바뀌는 30일치 로그 6만 건에서 「그 날 그 소재의 CTR」 피처를 쓸 때, 무작위로 나눈 검증과 날짜로 나눈 검증의 AUC 를 비교한다.
import random, bisect

random.seed(11)
N = 60_000                                   # 30일치, 하루 2,000건

# 1단계: AUC 함수를 만든다
def auc(pred, 라벨):
    양 = sorted(p for p, y in zip(pred, 라벨) if y == 1)
    음 = sorted(p for p, y in zip(pred, 라벨) if y == 0)
    합 = 0.0
    for p in 양:
        아래 = bisect.bisect_left(음, p); 같음 = bisect.bisect_right(음, p) - 아래
        합 += 아래 + 같음 / 2
    return 합 / (len(양) * len(음))

# 2단계: 날마다 인기 소재가 바뀌는 로그 6만 건을 만든다
데이터 = []
for i in range(N):
    날 = i // 2000
    소재 = random.randrange(50)
    인기 = (소재 == (날 * 7) % 50)
    데이터.append((날, 소재, 1 if random.random() < (0.20 if 인기 else 0.03) else 0))

# 3단계: 그 날 그 소재의 CTR 표를 학습하는 함수를 만든다
# 피처는 "그 날 그 소재의 CTR" 이다. 실무에서 흔히 쓰는 일자별 통계다.
def 학습(train):
    표 = {}
    for 날, 소재, y in train:
        n, c = 표.get((날, 소재), (0, 0))
        표[(날, 소재)] = (n + 1, c + y)
    평균 = sum(y for _, _, y in train) / len(train)
    return {k: (c + 20 * 평균) / (n + 20) for k, (n, c) in 표.items()}, 평균

# 4단계: 무작위로 8:2 로 나눠 검증한다
섞은것 = 데이터[:]
random.shuffle(섞은것)
경계 = int(N * 0.8)
표1, 평균1 = 학습(섞은것[:경계])
검증1 = 섞은것[경계:]
a1 = auc([표1.get((d, s), 평균1) for d, s, _ in 검증1], [y for _, _, y in 검증1])

# 5단계: 날짜로 24일과 6일로 나눠 검증한다
앞 = [d for d in 데이터 if d[0] < 24]
뒤 = [d for d in 데이터 if d[0] >= 24]
표2, 평균2 = 학습(앞)
a2 = auc([표2.get((d, s), 평균2) for d, s, _ in 뒤], [y for _, _, y in 뒤])

# 6단계: 두 검증 AUC 를 비교한다
print(f"피처: 그 날 그 소재의 CTR")
print(f"{'나누는 방법':<24}{'검증 AUC':>10}")
print(f"{'무작위로 8:2':<23}{a1:>10.4f}")
print(f"{'날짜로 24일 / 6일':<22}{a2:>10.4f}")
print(f"\n같은 데이터, 같은 코드인데 {a1-a2:.3f} 만큼 벌어진다.")
print("무작위로 나누면 검증에 쓸 날의 통계가 학습에 들어간다 — 답을 미리 본 것이다.")
print("서비스에서는 오늘 통계를 오늘 쓸 수 없으니, 실제 성능은 아래쪽에 가깝다.")

# 출력:
# 6단계 뜻: 무작위로 나누면 검증 AUC 가 0.5576 이지만 날짜로 나누면 0.5000 이라 0.058 만큼 벌어진다. 무작위 분할은 검증에 쓸 날의 통계를 학습에서 미리 본 것이다.
# 피처: 그 날 그 소재의 CTR
# 나누는 방법                      검증 AUC
# 무작위로 8:2                   0.5576
# 날짜로 24일 / 6일              0.5000
#
# 같은 데이터, 같은 코드인데 0.058 만큼 벌어진다.
# 무작위로 나누면 검증에 쓸 날의 통계가 학습에 들어간다 — 답을 미리 본 것이다.
# 서비스에서는 오늘 통계를 오늘 쓸 수 없으니, 실제 성능은 아래쪽에 가깝다.
```

6단계 출력에서 무작위로 8:2 로 나눈 검증 AUC 는 0.5576 이고 앞 24일로 학습해 뒤 6일로 검증한 AUC 는 0.5000 이라, 같은 데이터와 같은 코드인데 0.058 만큼 차이가 납니다. 무작위로 나누면 검증하는 노출과 같은 날, 같은 소재의 다른 노출이 학습 데이터에 들어가므로 피처 표에 그 날의 인기 소재가 이미 높은 CTR 로 적혀 있어 모델이 답을 미리 본 채로 검증을 받습니다. 날짜로 나누면 검증하는 뒤 6일의 (날, 소재) 조합은 앞 24일의 표에 하나도 없으므로 모든 검증 노출이 같은 평균값을 받습니다. 모든 노출에 같은 값을 주는 모델은 3절의 A 처럼 AUC 가 0.5 이므로 0.5000 이 나옵니다.

두 AUC 의 차이 0.058 이 **가짜 성능**입니다. 서비스에서는 오늘 요청을 처리할 때 오늘의 통계를 아직 쓸 수 없으므로 실제 성능에 가까운 정직한 값은 아래쪽 0.5000 입니다. 이 피처는 사실 예측에 아무 도움이 되지 않습니다. 이처럼 서비스에서는 알 수 없는 정보가 학습이나 검증에 섞여 검증 성능을 서비스에서 나올 성능보다 좋게 보이게 하는 문제를 데이터 누수(data leakage)라고 부릅니다.

면접에서는 이 두 문장으로 답합니다. **"시간이 있는 데이터는 반드시 시간으로 나눕니다. 무작위로 나누면 서비스에서 못 쓰는 정보가 검증에 들어갑니다."**

**Q. 누수인지 아닌지 어떻게 구분합니까?**

기준은 하나뿐입니다. **"서빙 시점에 이 값을 실제로 알 수 있나?"** 서빙은 배포한 모델이 실제 요청을 받아 예측을 돌려주는 일이고 서빙 시점은 그 요청을 처리하는 순간이라, 피처마다 그 순간에 값이 이미 있는지만 물어도 누수는 대부분 걸러집니다.

- 그 날의 소재별 CTR → 오늘 요청을 처리하는 순간에는 오늘의 통계가 아직 없으므로 누수입니다.
- 사용자의 최근 30일 클릭 수 → 어제까지의 기록으로 계산했다면 서빙 시점에도 알 수 있어 안전하지만 오늘의 기록까지 넣으면 첫 줄과 같은 까닭으로 누수가 됩니다.
- 전환 금액 → 전환이 일어난 뒤에야 알 수 있는 값이라 전환을 예측하는 피처로 쓰면 누수입니다.

## 6. 피처 — 그룹과 교차

**피처는 나열하지 않고 그룹으로 나눠 말하면서 그룹마다 무엇을 잡는지 붙이며 개인화는 교차 피처(두 피처의 값을 짝지은 피처)에서 나온다고 말합니다. 피처를 하나 더 넣을지는 오프라인 지표가 얼마나 오르는지, 서빙에서 제때 가져올 수 있는지, 빠졌을 때 성능이 크게 떨어지지 않는지 3가지로 정합니다.**

**Q. CTR 예측에 어떤 피처를 쓰시겠습니까?**

생각나는 피처를 늘어놓기만 하면 점수가 나오지 않습니다. **피처를 그룹으로 묶어서 말하고 그룹마다 무엇을 잡는지 붙입니다.** 아래 표는 그룹 5개와 그룹마다 들어가는 피처의 예, 그 그룹이 잡는 것을 보여 줍니다. 지면은 광고가 실리는 화면 속 자리입니다.

| 그룹 | 예 | 무엇을 잡나 |
|---|---|---|
| 광고 쪽 | 소재 id, 업종, 크기, 텍스트 길이 | 이 광고 자체가 원래 잘 눌리나 |
| 지면 쪽 | 지면 id, 위치, 화면 크기 | 이 자리가 원래 잘 눌리나 |
| 사용자 쪽 | 관심사, 최근 행동, 재방문 여부 | 이 사람이 이런 광고를 좋아하나 |
| 맥락 | 시간대, 요일, 기기 | 지금이 눌릴 때인가 |
| 교차 | 사용자 관심사 × 광고 업종 | 이 조합이 맞나 |

**답에서 꼭 말해야 하는 줄은 마지막 교차입니다.** 앞의 네 그룹은 광고, 지면, 사용자, 맥락을 각각 따로 보므로 「평균적으로 잘 눌리나」만 잡습니다. 같은 광고라도 보는 사람에 따라 예측이 달라지는 개인화는 「사용자 관심사 × 광고 업종」처럼 두 피처의 값을 짝지은 교차 피처에서 나옵니다.

트리는 한 피처로 데이터를 나눈 뒤 그 안에서 다른 피처로 다시 나누므로 GBDT 는 교차를 어느 정도 스스로 찾습니다. 그래도 카디널리티(범주형 피처가 가질 수 있는 서로 다른 값의 개수)가 큰 범주형끼리의 교차는 임베딩 쪽이 나은데, 7절에서 보듯 값이 수백만 개인 id 는 트리가 감당하지 못하기 때문입니다. 임베딩(embedding)은 사용자 id 나 소재 id 같은 값 하나하나에 학습되는 숫자 벡터를 하나씩 주는 방법입니다.

**Q. 피처를 하나 더 넣을지 말지 어떻게 정합니까?**

세 가지를 봅니다. 그 피처를 넣었을 때 오프라인 지표가 얼마나 오르는지, 서빙할 때 그 값을 제때 가져올 수 있는지, 그리고 **그 피처가 빠졌을 때 성능이 크게 떨어지지 않는지**입니다.

실무에서는 세 번째 기준을 자주 빠뜨립니다. 사용자 프로필(관심사나 최근 행동 같은 사용자 정보) 조회가 30ms 걸리는데 응답 시간 예산이 15ms 라면 조회가 예산을 넘으므로 그 피처는 쓸 수 없습니다. 쓰더라도 조회가 실패했을 때 넣을 기본값을 정해 두고 그 기본값으로도 모델이 크게 망가지지 않는지 확인해야 합니다.

## 7. 모델 선택 — GBDT 와 딥러닝

**"왜 딥러닝이 아닌가"에는 둘 다 쓰되 쓰는 곳이 다르다고 답합니다. 실무에서는 대체로 구조가 정해진 피처는 GBDT 로, id 계열은 임베딩으로 다룹니다. 처음에는 단순한 로지스틱 회귀로 기준선(비교의 출발점)부터 만듭니다.**

**Q. 요즘 다 딥러닝 쓰는데 왜 GBDT를 쓰시겠습니까?**

딥러닝은 층을 여러 개 쌓은 신경망으로 학습하는 방법입니다. 이 질문은 되받아쳐서 이렇게 답합니다. **"둘 다 씁니다. 어디에 쓰느냐가 다릅니다."**

아래 표는 두 모델을 잘하는 것, 학습, 서빙, 해석, 갱신 5가지로 비교합니다. 첫 줄의 수치형은 텍스트 길이처럼 크기가 있는 숫자 값입니다. 저카디널리티 범주형은 값의 종류가 적은 범주형이고 고카디널리티 id 는 사용자 id 처럼 값의 종류가 아주 많은 id 입니다. 순서 있는 행동은 사용자가 차례로 남긴 행동 기록입니다.

| | GBDT | 딥러닝 |
|---|---|---|
| 잘하는 것 | 수치형, 저카디널리티 범주형, 표 형태 데이터 | 고카디널리티 id, 임베딩, 순서 있는 행동 |
| 학습 | 빠르고 튜닝이 쉽다 | 느리고 손이 많이 간다 |
| 서빙 | 트리 수만큼 비용 | 행렬 곱 — GPU면 빠르다 |
| 해석 | 피처 중요도가 바로 나온다 | 따로 도구가 필요하다 |
| 갱신 | 대체로 전체 재학습 | 이어서 학습하기 쉽다 |

**실무에서는 대체로 "구조가 정해진 피처는 GBDT, id 계열은 임베딩"으로 답합니다.** 구조가 정해진 피처는 수치형이나 저카디널리티 범주형처럼 표의 첫 줄에서 GBDT 가 잘하는 피처입니다. 사용자 id 나 소재 id 처럼 값이 수백만 개인 피처를 GBDT 에 넣으면 트리가 감당하지 못하므로 이런 id 계열은 임베딩으로 다룹니다.

답에 하나 더 붙이면 좋은 말도 있습니다. **큰 모델로 처음부터 시작하지 않습니다.** 먼저 로지스틱 회귀로 기준선을 만들고 다음 모델은 그 기준선보다 얼마나 나아지는지로 판단합니다. 로지스틱 회귀는 피처마다 가중치를 곱해 더한 값을 시그모이드 함수로 0 과 1 사이의 확률로 바꾸는 단순한 모델입니다. 기준선이 없으면 "0.75가 좋은 건가"를 아무도 모릅니다. 같은 데이터에서 로지스틱 회귀가 얼마를 내는지 알아야 0.75 가 그보다 나은지 말할 수 있습니다.

## 8. 랭킹 — pCTR 순위와 eCPM

**광고주가 내는 돈이 광고마다 다르므로 순위는 클릭 확률만이 아니라 확률과 금액을 곱한 eCPM 으로 매깁니다. eCPM 은 이번 요청의 기대 수익이라 당장은 eCPM 을 최대로 하면 되지만 길게 보면 사용자 경험, 다양성, 탐색을 함께 봐서 장기 수익과 절충합니다.**

pCTR(predicted CTR)은 모델이 예측한 클릭 확률입니다. 아래 질문은 이 값이 가장 높은 광고를 맨 위에 놓으면 되는지를 묻습니다.

**Q. 클릭 확률이 가장 높은 광고를 위에 놓으면 되지 않습니까? [무대: 공통]**

**광고주가 내는 돈이 광고마다 다르므로 안 됩니다.**

클릭 확률이 5% 이고 클릭당 100원을 내는 광고와 클릭 확률이 1% 이고 클릭당 2,000원을 내는 광고를 비교해 봅니다. 노출 한 번에서 기대하는 돈은 앞 광고가 0.05 × 100원 = 5원, 뒤 광고가 0.01 × 2,000원 = 20원이라 클릭 확률이 더 낮은 뒤 광고가 4배 낫습니다. 그래서 순위는 클릭 확률에 금액을 곱한 값으로 매기는데, 이 값이 eCPM 입니다.

지원자 대부분이 여기까지는 답합니다. 답의 차이는 한 단계 더 들어간 다음 질문에서 납니다.

**Q. 그러면 eCPM만 최대로 하면 됩니까?**

당장은 그렇지만 길게 보면 그렇지 않으므로 아래 세 가지를 함께 봐야 합니다.

**첫째, 사용자 경험입니다.** 돈만 보고 순위를 매기면 관련 없는 광고가 계속 뜨고 사용자가 떠나면 인벤토리(광고를 보여 줄 수 있는 노출의 양) 자체가 줄어듭니다. 그래서 eCPM 에 품질 점수(광고가 사용자에게 얼마나 관련 있고 좋은지 매긴 점수)를 곱하거나 품질 점수에 하한을 둡니다.

**둘째, 다양성입니다.** 같은 광고주의 소재가 화면을 채우면 클릭률이 떨어집니다. 그래서 「같은 캠페인은 1개만, 같은 업종은 2개까지」 같은 규칙을 넣습니다.

**셋째, 탐색입니다.** 새 소재는 데이터가 없어 예측이 낮게 나오는데 예측이 낮으니 화면에 뜨지 않고 뜨지 않으니 데이터가 영영 쌓이지 않습니다. 이 고리를 끊으려면 노출의 일정 비율을 새 소재에 따로 배정해야 합니다. 데이터가 적은 소재에 이렇게 기회를 주는 일을 탐색이라고 부릅니다.

앞의 내용은 이 한 문장으로 줄일 수 있습니다. **"eCPM은 이번 요청의 기대 수익이고, 랭킹은 그것과 장기 수익의 절충입니다."** 이번 요청에서 기대하는 수익이 eCPM 이고 위 세 가지는 길게 보는 수익을 위해 함께 보는 것이므로, 랭킹은 두 수익 사이의 절충이라는 뜻입니다. 면접에서 이 문장이 나오면 대체로 다음 주제로 넘어갑니다.

## 9. 지연 전환과 피드백 루프

**전환이 며칠 뒤에 오면 아직 오지 않은 전환이 0 으로 학습되어 모델이 전환율을 실제보다 낮게 보는데, 실무에서는 빠른 모델을 짧은 기간의 데이터로 자주 갱신하고 보정 상수는 긴 기간의 데이터로 천천히 맞추는 방법이 흔합니다. 모델이 자기가 만든 데이터로 다시 배우는 문제에는 일정 비율을 무작위로 노출해 편향 없는 데이터를 확보합니다.**

**Q. 클릭하고 사흘 뒤에 구매하는 사람이 있습니다. 학습을 어떻게 하시겠습니까?**

이 질문에는 딱 떨어지는 답이 없어서 면접관이 지원자의 판단을 보기에 좋습니다.

**먼저 문제를 정확히 말합니다.** 어제 클릭한 건 가운데 아직 전환하지 않은 건을 0 으로 놓고 배우면 실제로는 내일 전환할 건까지 0 으로 배우므로, 모델은 전환율을 실제보다 낮게 봅니다.

**선택지는 3가지입니다.**

가장 단순한 선택지는 기다리는 방법입니다. 관측 창(클릭 뒤 전환이 오기를 기다려 주는 기간)을 사흘로 잡고 클릭한 지 사흘이 지난 데이터만 학습에 쓰면 그 사이에 온 전환이 라벨에 모두 들어가 라벨은 정확해지지만 모델은 사흘 지난 데이터로만 배우므로 언제나 사흘 늦습니다. 소재가 빨리 바뀌는 곳에서는 이 지연이 더 큰 손해입니다.

둘째 선택지는 데이터를 바로 쓰되 보정하는 방법입니다. 아직 전환하지 않은 건을 0 으로 넣되 그 건이 시간이 지나 전환할 확률을 따로 모델링해 가중치를 주는데, 구현이 복잡한 대신 기다리지 않으므로 지연이 없습니다.

셋째로 앞의 두 가지를 섞는 방식이 실무에서 흔합니다. **빠른 모델은 짧은 창으로 자주 갱신하고 보정 상수는 긴 창으로 천천히 맞춥니다.** 창은 학습에 쓰는 데이터를 모으고 전환을 기다리는 기간이라, 짧은 창은 최신 데이터를 빨리 쓰고 긴 창은 전환을 오래 기다려 라벨이 정확합니다. 보정 상수는 4절에서 모든 예측값에 곱한 COPC 같은 상수입니다.

여기까지 말하면 면접관이 "왜 그렇게 나눴나"를 이어서 묻는데, 답은 "줄 세우기는 최신 데이터가 중요하고 값 맞추기는 정확한 라벨이 중요해서"입니다. 3절에서 나눈 두 가지 일 가운데 줄 세우기는 최신 데이터로 자주 갱신하는 빠른 모델에, 값 맞추기는 정확한 라벨로 천천히 맞추는 보정 상수에 맡긴다는 뜻입니다.

**Q. 모델이 자기가 만든 데이터로 다시 배우는 문제는 어떻게 보십니까?**

모델이 높게 예측한 광고만 노출되므로 다음 학습 데이터에는 그 광고들의 기록만 남습니다. 낮게 예측한 광고는 노출될 기회를 영영 받지 못해 예측을 고칠 데이터가 쌓이지 않습니다. 이렇게 모델의 결정이 다음 학습 데이터를 정하고 그 데이터가 다시 모델을 만드는 고리를 피드백 루프라고 부릅니다.

답의 중심은 아래 문장입니다. **"일정 비율을 무작위로 노출해 편향 없는 데이터를 확보합니다."** 노출의 일정 비율을 모델의 예측과 상관없이 무작위로 고른 광고에 쓰면 모델이 낮게 본 광고의 기록도 쌓입니다. 그 비율만큼 단기 수익을 포기하는 대신 그 데이터로 모델을 고칠 수 있습니다. 비율은 실험으로 정하는데 보통 한 자릿수 퍼센트입니다.

## 10. 모르는 질문에 답하는 3단계

**모르는 것을 아는 척하면 면접에서 가장 크게 감점되므로, 모른다고 먼저 말하고 아는 것과 연결한 뒤 어떻게 알아낼지를 말합니다.**

경력 면접에서는 모르는 질문이 반드시 나오고 면접관도 그 사실을 압니다. 면접관은 지원자의 지식이 얼마나 넓은지가 아니라 **모르는 상황에서 어떻게 하는지**를 봅니다.

답은 3단계로 합니다. **먼저 모른다고 말합니다.** "그건 안 다뤄 봤습니다"라고 먼저 말해 두면 면접관은 뒤에 이어지는 말을 지원자가 아는 사실이 아니라 추측으로 정확히 받아들입니다.

**그다음 아는 것과 연결합니다.** "다만 비슷한 걸 해 본 적이 있는데, 그때는 이랬습니다"로 이어 가면 완전히 새로운 문제여도 원리를 아는 문제에서 출발해 유추할 수 있습니다.

**마지막으로 어떻게 알아낼지 말합니다.** "이건 데이터를 먼저 보고 판단할 문제인 것 같습니다. 저라면 먼저 이걸 측정해 보겠습니다"까지 말하면 모르는 것을 알아낼 방법까지 내놓은 답이라 모른다는 답이 오히려 좋은 답이 됩니다.

반대로 하지 말아야 할 일 3가지도 분명합니다. 들어 본 용어를 늘어놓는 일, 질문을 자기가 아는 주제로 돌리는 일, "상황에 따라 다릅니다"로 끝내고 결론을 내지 않는 일입니다. 1절에서 후보만 늘어놓은 답이 그랬듯 세 가지 모두 면접관에게 "판단을 못 한다"로 읽힙니다.

## 한눈 정리

| 질문 | 답의 핵심 한 줄 |
|---|---|
| CTR 0.2%를 어떻게 학습하나 | 정확도를 버리고 다운샘플링하되 되돌리기까지 합니다 |
| 다운샘플링하면 값이 커지지 않나 | `p / (p + (1-p)/r)` 로 되돌립니다. 안 하면 19배 커집니다 |
| AUC는 올랐는데 매출이 그대로다 | AUC는 순위 매기기만 측정합니다. 보정 지표를 같이 봅니다 |
| 확률이 실제와 다르면 뭐가 문제인가 | 입찰가, 예산 배분, 모델 신뢰가 순서대로 깨집니다 |
| 보정은 어떻게 하나 | 상수 곱은 평균만 맞춥니다. 구간별로 측정하고 계속 감시합니다 |
| 오프라인은 좋은데 온라인이 나쁘다 | 데이터를 시간으로 나눴는지부터 봅니다 |
| 누수인지 어떻게 아나 | "서빙 시점에 이 값을 알 수 있나"만 묻습니다 |
| 어떤 피처를 쓰겠나 | 5개 그룹으로 말하고 개인화는 교차에서 나온다고 붙입니다 |
| 왜 딥러닝이 아닌가 | 둘 다 씁니다. 구조화 피처는 GBDT, id 계열은 임베딩 |
| pCTR로만 순위를 매기면 안 되나 | 금액이 다릅니다. eCPM 뒤에 품질, 다양성, 탐색을 붙입니다 |
| 전환이 며칠 뒤에 온다 | 빠른 모델은 짧은 창, 보정은 긴 창으로 나눕니다 |
| 모델이 자기 데이터로 배운다 | 일정 비율을 무작위로 노출해 편향 없는 데이터를 만듭니다 |
| 모르는 걸 물었다 | 모른다고 먼저 말하고 아는 것과 연결한 뒤 알아낼 방법을 말합니다 |

## 헷갈리기 쉬운 점

- **AUC 가 높다는 이유만으로 좋은 모델이라고 말하지 않습니다.** AUC 0.5 인 모델이 COPC 1.000 일 수 있고 AUC 가 같은 두 모델의 COPC 가 세 배 차이 날 수 있는데, 3절의 A 와 B, C 가 그랬습니다.
- **다운샘플링을 말하면 되돌리기도 함께 말합니다.** 2절에서 보았듯 되돌리지 않으면 예측값이 19배로 커진 채 입찰에 들어가므로 두 가지는 언제나 한 쌍으로 나옵니다.
- **"상황에 따라 다릅니다"만으로는 답이 되지 않습니다.** 어떤 상황이면 어느 쪽인지까지 말해야 1절의 둘째 단계처럼 결론이 있는 답이 됩니다.
- **피처를 나열만 해서는 점수가 나오지 않습니다.** 6절의 표처럼 그룹으로 나누고 그룹마다 무엇을 잡는지를 붙여야 합니다.
- **시간이 있는 데이터를 무작위로 나눈 검증은 그 자체가 누수입니다.** 5절에서는 무작위로 나눈 검증 AUC 가 날짜로 나눈 검증보다 0.058 높게 나왔습니다.
- **배포는 오프라인 지표만으로 정하지 않습니다.** 오프라인과 온라인 결과가 달라지는 이유를 설명할 수 있어야 합니다.
- **모르는 것을 추측으로 채우지 않습니다.** 추측이라고 먼저 밝히고 하는 추측은 감점되지 않습니다.
