LLM 유저 임베딩 카드 네 장

회원의 30일 문서를 새벽에 64차원 벡터로 바꿔 두고, 광고 랭커가 요청 때 그 벡터를 피처로 읽는 자리를 한 장씩 봅니다. 새벽 배치, 피처 스토어의 키와 벡터, 랭커가 읽는 피처, 예산 8ms 와 LLM 호출입니다. 회원과 광고, 가짜 클릭은 설명용 가상 값이고, LLM 호출의 시간과 토큰은 qwen3.5:27b 의 기록입니다.

파랑 = 놓여 있는 데이터 (문서, 벡터, 피처 스토어) 벽돌색 = 지금 오는 것 (요청, 코사인, LLM 호출) 먹색 = 모델과 서버 회색 = 만드는 작업 (새벽 배치)과 비교할 기준값 점선 상자 = 적어 둔 것 (낱말마다 인코더가 정한 버킷)

NIGHTLY BATCH

새벽 배치

쉽게 말하면 회원마다 문서를 벡터로 한 번 바꾸고, 새벽에 한꺼번에 피처 스토어에 넣어 둡니다.

회원 2,000명의 문서를 한 번에 64차원 벡터로 바꿨습니다. 회원 1,400만 명이면 3,584,000,000바이트, 3.58GB 입니다.

FEATURE STORE

피처 스토어의 키와 벡터

쉽게 말하면 키는 회원 번호이고 값은 벡터와 만든 시각입니다. 랭커는 요청 때 키로 읽기만 합니다.

회원 A 의 벡터는 64개 값 가운데 6개만 0 이 아닙니다. 가장 큰 값 0.676 은 러닝화의 버킷입니다.

RANKER FEATURES

랭커가 읽는 피처

쉽게 말하면 기본 피처 셋에 유저 벡터와 광고 벡터의 코사인 하나를 더해 클릭 확률을 매깁니다.

시험 회원 400명에서 AUC 는 0.637 에서 0.670 으로 올랐습니다. 숨은 관심을 그대로 알아도 AUC 는 0.738 입니다.

8MS BUDGET

예산 8ms 와 실시간 호출

쉽게 말하면 LLM 호출 한 번이 랭커의 예산 전부보다 훨씬 깁니다. 그래서 LLM 은 새벽 배치에만 둡니다.

thinking 을 끈 호출도 1,114ms 로 예산의 139배입니다. 노출마다 부르면 하루 9,302,400원 이상이고, 새벽 배치는 낙관적으로 어림해 6,425원입니다.

현업에서는 이렇게 씁니다

  • 유저 벡터를 랭커에 넣을 때는 세 가지를 묻습니다. 언제 만든 벡터인가, 같은 버전의 광고 벡터와 맞추는가, 벡터가 없는 요청은 어떻게 매기는가.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 LLM 유저 임베딩을 pCTR 피처로 편에 이 카드들이 절마다 들어 있습니다. 회원과 문서는 유저를 문서로 편에서 왔습니다.
