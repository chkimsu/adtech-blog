오늘 아침 한 광고주가 새 소재(광고에 실제로 보이는 이미지와 문구) 열 개를 올렸습니다. 방금 올라온 소재라 노출도 클릭도 아직 한 번도 없습니다. 그런데 이 광고들을 랭킹(어떤 광고를 먼저 보여 줄지 정하는 순위)에 넣으려면 pCTR 이 있어야 합니다. CTR(Click-Through Rate)은 노출 가운데 실제로 클릭이 난 비율이고 pCTR 은 광고가 한 번 노출됐을 때 클릭될 확률을 모델이 미리 예측한 값입니다. 광고 순위를 매기는 점수인 eCPM(노출 1,000회당 기대 수익)은 pCTR × 입찰가 × 1,000 으로 계산하므로 pCTR 이 없으면 eCPM 을 낼 수 없고 순위도 매길 수 없습니다.

pCTR 을 「모르니까 0」으로 두면 eCPM 도 0 이 되어 이 광고는 영원히 노출을 받지 못합니다. 노출이 없으면 클릭 데이터가 쌓이지 않고 데이터가 없으면 pCTR 은 계속 0 에 머무르므로 **모르는 상태가 스스로를 유지합니다.**

그렇다면 노출도 클릭도 없는 새 광고에는 처음에 어떤 pCTR 을 줘야 할까요? 이 글은 그 첫 숫자를 만드는 방법을 다룹니다.

> 한 줄 요약: 이력(노출과 클릭 기록)이 0 인 광고의 pCTR 은 **비슷한 광고들의 이력을 빌려서** 만듭니다. 얼마나 세게 빌릴지는 사람이 임의로 정하지 않고 **같은 계층(같은 광고주, 같은 업종처럼 새 광고가 속한 범위) 안 광고들이 얼마나 비슷한가**에서 계산합니다.

먼저 이 글이 맡는 범위를 밝혀 둡니다. 콜드스타트(cold start)는 이처럼 이력이 없는 새 광고를 어떻게 다룰지의 문제입니다. 여기에는 질문이 두 가지 있습니다. 하나는 「**이 광고에 노출을 얼마나 줘서 알아볼까**」를 정하는 탐색(exploration)이고 다른 하나는 「**지금 당장 이 광고에 어떤 숫자를 줄까**」를 정하는 예측입니다. 탐색 쪽 질문은 [탐색과 활용](post.html?id=exploration-exploitation) 편에서 다룹니다. 그 글에는 탐색에 비용을 얼마나 쓰는지와 함께 ε-greedy 와 밴딧(bandit)이 이 질문에 어떻게 답하는지가 나옵니다. ε-greedy 는 작은 확률 ε 로 광고를 무작위로 골라 보여 주는 방법이고 밴딧은 광고마다 쌓인 결과를 보며 노출 비율을 계속 고치는 방법입니다.

**이 글은 두 질문 가운데 뒤의 예측만 다룹니다.** 노출을 얼마나 줄지와 상관없이 랭킹에 넣을 pCTR 은 새 광고가 올라온 지금 바로 있어야 하므로 아래에서는 그 숫자를 만드는 계산을 보여 줍니다.

## 1. 새 광고에 있는 정보와 없는 정보

**새 광고에는 이 광고 자신의 성과 이력만 없을 뿐 누가 올렸는지, 어떤 업종인지, 어떻게 생겼는지, 어디에 나갈지는 이미 알려져 있어서 비슷한 광고들의 이력을 빌려 올 수 있습니다. 빌려 올 계층은 여러 개이고 새 광고와 가까운 계층일수록 더 정확하지만 표본(평균을 계산하는 데 쓰는 데이터)이 적습니다.**

아침에 올라온 소재 열 개에 「모르니까 0」 대신 줄 숫자를 찾으려면 새 광고에 무엇이 없고 무엇이 있는지부터 따져 봐야 합니다. 없는 것만 세면 아무것도 모르는 광고처럼 보이지만 실제로 새 광고에는 꽤 많은 정보가 이미 있습니다.

- 광고를 **누가 올렸는지** 압니다. 같은 광고주가 먼저 내보낸 다른 광고들에는 이력이 쌓여 있습니다.
- 광고가 **어떤 업종인지** 압니다. 같은 카테고리(업종 분류)의 광고들에도 이력이 있습니다.
- 광고가 **어떻게 생겼는지** 압니다. 이미지 크기, 영상 길이, 제목 글자 수, 랜딩 페이지(광고를 누르면 열리는 페이지) 종류는 소재에서 바로 읽힙니다.
- 광고가 **어디에 나갈지** 압니다. 타겟 지면(광고가 실리는 앱 화면이나 웹 페이지의 자리)과 세그먼트(광고를 보여 줄 유저 그룹)가 캠페인(광고주가 예산을 들여 광고를 집행하는 단위) 설정에 들어 있습니다.

그래서 새 광고는 완전히 모르는 상태가 아니며 **비슷한 광고들의 이력을 빌려 오면 됩니다.** 빌려 올 범위는 넓은 것부터 전체, 카테고리, 광고주, 캠페인, 소재 그룹(한 캠페인 안에서 소재를 나눠 모은 단위)까지 여러 단계로 나뉩니다. 이 글은 그 단계 하나하나를 계층이라고 부릅니다. 가까운 계층일수록 새 광고와 비슷한 광고들이라 더 정확하지만 가까울수록 그 계층에 쌓인 표본은 적습니다. 정확도를 얻는 만큼 표본을 잃는 이 맞바꿈(trade-off)이 이 글 전체의 주제입니다.

| 빌려 올 계층 | 표본 크기 (노출 수) | 새 광고와의 유사성 | 언제 쓰나 |
|---|---|---|---|
| 전체 평균 | 매우 큼 (수억 노출) | 낮음 | 아무 정보도 없을 때의 최후 수단 |
| 카테고리 평균 | 큼 (수천만) | 중간 | 광고주가 처음 들어왔을 때 |
| **광고주 평균** | 중간 (수십만~수백만) | 높음 | **대개 여기가 균형점** |
| 캠페인 평균 | 작음 (수만) | 매우 높음 | 같은 캠페인에 소재가 여러 개일 때 |
| 소재 그룹 평균 | 매우 작음 (수천) | 가장 높음 | 표본이 부족해 오히려 불안정 |

표의 값은 가상 데이터 기준이고 실제 값은 인벤토리(광고를 실을 수 있는 지면과 노출 전체) 규모에 따라 달라집니다. 표를 아래에서 위로 읽으면 맞바꿈이 보이는데, **아래로 내려갈수록 새 광고와 비슷해지지만 표본이 줄고 위로 올라갈수록 표본은 넉넉하지만 새 광고와 거리가 먼 광고들의 값이 됩니다.** 그래서 새 광고와 가장 비슷한 맨 아래 소재 그룹 평균도 표본이 수천 노출뿐이라 오히려 불안정합니다.

### 계층별 평균 CTR 비교

「가까운 계층이 더 정확하다」는 말은 듣기에는 당연하지만 계층을 바꿀 때 값이 실제로 얼마나 달라지는지는 숫자로 확인해야 압니다. 아래 코드는 가상 데이터를 씁니다. 광고주 3곳(패션몰A, 게임사B, 보험사C)이 이미 가진 광고들의 노출과 클릭으로 2단계에서 전체 평균 CTR 과 광고주별 평균 CTR 을 구한 뒤 3단계에서 이력이 0 인 새 광고에 전체에서 빌린 값과 광고주에서 빌린 값을 나란히 찍어 차이를 비교합니다.

```python
# 하는 일: 광고주 3곳의 광고 이력으로 전체와 광고주별 평균 CTR 을 구하고, 이력이 0 인 새 광고에 어느 계층의 값을 빌려 줄지 비교한다.

# 1단계: 광고주 3곳의 광고 이력을 둔다
# 새 광고는 노출도 클릭도 없는데, 랭킹에 넣으려면 숫자가 있어야 한다. 실무의 답은 계층을 타고 빌려 오는 것이다(전체 → 카테고리 → 광고주 → 이 광고).
# 가상 데이터: 광고주 3곳, 각자 광고 여러 개. (노출, 클릭)
DATA = {
    "패션몰A": [("A-1", 50_000, 1_250), ("A-2", 30_000, 690), ("A-3", 20_000, 500)],
    "게임사B": [("B-1", 80_000, 800), ("B-2", 40_000, 360)],
    "보험사C": [("C-1", 60_000, 300), ("C-2", 25_000, 150), ("C-3", 15_000, 75)],
}

# 2단계: 전체와 광고주별 평균 CTR 을 구해 찍는다
def ctr(imp, clk):
    return clk / imp if imp else 0.0

total_imp = total_clk = 0
adv_stats = {}
for adv, ads in DATA.items():
    i = sum(a[1] for a in ads)
    c = sum(a[2] for a in ads)
    adv_stats[adv] = (i, c)
    total_imp += i
    total_clk += c
global_ctr = ctr(total_imp, total_clk)

print(f"전체 평균 CTR  {global_ctr:.3%}  (노출 {total_imp:,}, 클릭 {total_clk:,})")
print("\n광고주별 평균 CTR")
for adv, (i, c) in adv_stats.items():
    print(f"  {adv:<8} {ctr(i, c):.3%}  (광고 {len(DATA[adv])}개)")
print()

# 3단계: 새 광고에 줄 사전 CTR 을 계층별로 비교한다
# "모르니까 0" 은 영원히 노출을 못 받는다는 뜻이고, "모르니까 평균" 은 너무 거칠다.
# 같은 광고주의 다른 광고들이 얼마나 비슷한지가 '빌려도 되는가'를 결정한다.
print("새 광고에 줄 사전 CTR (계층별로 빌릴 때)")
print(f"{'새 광고':<14}{'전체에서':>10}{'광고주에서':>12}{'차이':>10}")
for adv in DATA:
    a_ctr = ctr(*adv_stats[adv])
    print(f"{adv + '의 새 광고':<14}{global_ctr:>9.3%}{a_ctr:>11.3%}{(a_ctr/global_ctr - 1)*100:>+9.1f}%")
print()
print("→ 광고주마다 CTR이 2.4%와 0.5%로 4.6배 차이 난다.")
print("→ 전체 평균을 주면 보험사 새 광고는 2.5배 과대평가, 패션몰 새 광고는 절반 가까이 과소평가된다.")
print("→ 그래서 가능한 한 가까운 계층에서 빌려야 한다.")

# 출력:
# 2단계 뜻: 세 광고주의 광고를 합친 전체 평균 CTR 은 1.289% 다. 광고주별로는 패션몰A 2.440%, 게임사B 0.967%, 보험사C 0.525% 로 크게 다르다.
# 전체 평균 CTR  1.289%  (노출 320,000, 클릭 4,125)
#
# 광고주별 평균 CTR
#   패션몰A     2.440%  (광고 3개)
#   게임사B     0.967%  (광고 2개)
#   보험사C     0.525%  (광고 3개)
#
# 3단계 뜻: 전체 평균 1.289% 를 그대로 주면 패션몰A 의 새 광고는 광고주 평균보다 낮게, 보험사C 의 새 광고는 높게 시작한다. 광고주에서 빌린 값은 전체에서 빌린 값과 +89.3% 에서 -59.3% 까지 차이 난다.
# 새 광고에 줄 사전 CTR (계층별로 빌릴 때)
# 새 광고                전체에서       광고주에서        차이
# 패션몰A의 새 광고       1.289%     2.440%    +89.3%
# 게임사B의 새 광고       1.289%     0.967%    -25.0%
# 보험사C의 새 광고       1.289%     0.525%    -59.3%
#
# → 광고주마다 CTR이 2.4%와 0.5%로 4.6배 차이 난다.
# → 전체 평균을 주면 보험사 새 광고는 2.5배 과대평가, 패션몰 새 광고는 절반 가까이 과소평가된다.
# → 그래서 가능한 한 가까운 계층에서 빌려야 한다.
```

2단계 출력을 보면 세 광고주의 광고를 모두 합친 전체 평균 CTR 은 1.29% 인데 광고주별로 따로 구한 평균 CTR 은 패션몰A 2.44%, 게임사B 0.97%, 보험사C 0.53% 로 크게 다릅니다. **가장 높은 패션몰A 가 가장 낮은 보험사C 의 4.6배입니다.**

어느 계층에서 빌리느냐에 따라 새 광고의 시작 숫자가 이만큼 달라집니다. 3단계 출력의 사전 CTR 은 이 광고의 데이터를 보기 전에 다른 광고들에서 빌려 와 쓰는 CTR 입니다. 전체 평균을 새 광고의 사전 CTR 로 그대로 주면 보험사C 의 새 광고는 광고주 평균의 2.5배(1.289% ÷ 0.525%)로 높게 시작하고 패션몰A 의 새 광고는 광고주 평균의 절반 가까이(1.289% ÷ 2.440%)로 낮게 시작합니다. 표의 차이 칸은 광고주에서 빌린 값이 전체에서 빌린 값보다 몇 % 높거나 낮은지를 적은 값으로 패션몰A 가 +89.3%, 게임사B 가 -25.0%, 보험사C 가 -59.3% 입니다. 그래서 코드의 마지막 줄처럼 가능한 한 가까운 계층에서 빌려야 합니다.

새 광고를 높게 시작시키면 노출을 많이 받아 빨리 배우므로 오히려 낫다고 생각할 수도 있습니다. 그런데 **그 노출은 다른 광고가 받았을 자리에서 나옵니다.** 과대평가된 광고가 노출을 가져가는 동안 진짜 좋은 광고는 순위에서 밀립니다. 또 노출 단위로 과금한다면 광고주는 성과 없는 노출에도 돈을 냅니다.

## 2. 빌려 온 숫자에서 자기 데이터로 옮겨 가는 수축 [무대: 공통]

**노출이 적을 때의 관측 CTR(이 광고의 클릭 ÷ 노출)에는 운의 영향이 클 수 있어서 수축은 빌려 온 사전 CTR 과 관측 CTR 을 노출 수에 따라 섞어 추정합니다. 빌려 온 값을 가상 노출 몇 회로 칠지 정한 사전 강도가 자기 데이터를 믿기 시작하는 문턱입니다. 사전 강도가 약하면 같은 광고의 추정이 운에 따라 흔들리고 세면 좋은 광고를 오래 못 알아봅니다.**

1절의 방법으로 빌려 온 사전 CTR 로 새 광고를 시작했다고 합시다. 그 뒤 노출 100회에 클릭 4번이 들어왔다면 이 광고의 관측 CTR 은 4% 인데, 이제 pCTR 을 4% 로 바꿔야 할까요?

노출 100회는 판단하기에 너무 적습니다. 진짜 CTR(광고가 실제로 가진 클릭 확률)이 2% 인 광고도 100번 가운데 4번 클릭될 수 있으므로 **관측 CTR 을 그대로 믿으면 운으로 나온 클릭을 광고의 실력으로 착각합니다.**

그래서 실무에서는 빌려 온 사전 CTR 과 이 광고의 관측 CTR 두 숫자를 섞어 씁니다. 노출이 적을 때는 사전 CTR 쪽에 무게를 두고 노출이 쌓일수록 관측 CTR 쪽으로 무게를 옮깁니다. 관측 CTR 을 사전 CTR 쪽으로 끌어당긴다는 뜻에서 이 방법을 **수축(shrinkage)** 이라고 부릅니다.

계산도 간단합니다. 관측 CTR 을 구하는 클릭 ÷ 노출에서 분자와 분모에 가상의 숫자를 더하기만 하면 됩니다.

$$\hat{p} = \frac{\text{클릭} + \alpha}{\text{노출} + \alpha + \beta}$$

$\hat{p}$ 는 수축으로 얻은 추정 CTR 이고 아래 코드는 이 값을 수축 CTR 이라는 이름으로 찍습니다. α 와 β 는 사전확률(이 광고의 데이터를 보기 전에 갖고 있던 CTR 정보)을 **가상의 클릭과 노출로 바꿔 놓은 값**이며 α 는 가상 클릭 수, α + β 는 가상 노출 수입니다. 사전 CTR 2% 를 「노출 500회쯤 본 것으로 치자」고 정하면 α 는 2% × 500 = 10, β 는 500 - 10 = 490 이 되어 새 광고는 노출 500회에 클릭 10번을 이미 본 상태로 시작합니다. 그래서 이 광고의 실제 노출이 500회에 이르기 전까지는 가상 노출 500회가 실제와 가상을 합친 노출의 절반 이상을 차지하므로 추정값에서도 절반 이상의 비중을 갖습니다.

이 가상 노출 수 α + β 를 이 글은 **사전 강도**라고 부릅니다. 사전 강도가 클수록 실제 노출이 더 많이 쌓여야 관측 CTR 이 추정을 이끌 수 있으므로 이 숫자 하나가 「이 광고 자신의 데이터를 언제부터 믿을지」를 정합니다.

### 노출이 쌓일 때의 수축 CTR 변화

사전 강도 500 이 실제로 어떻게 작용하는지 보려고 아래 코드를 돌립니다. 사전 CTR 2% 를 사전 강도 500 으로 빌린 새 광고가 사실은 진짜 CTR 5% 인 좋은 광고라고 할 때 2단계는 노출이 0회에서 100,000회까지 쌓이는 동안 수축 CTR 이 5% 에 얼마나 빨리 다가가는지 찍습니다. 이때 클릭은 노출마다 딱 기대만큼(노출 × 5%) 났다고 가정합니다. 4단계는 사전 강도를 50, 200, 500, 2,000 과 10,000 의 다섯 가지로 바꿔 가며 같은 조건의 새 광고 2,000개를 시뮬레이션(가정한 조건으로 무작위 결과를 여러 번 만들어 보는 계산)해서 추정이 평균적으로 얼마나 틀리고 얼마나 흔들리는지 비교합니다.

```python
# 하는 일: 사전 CTR 2% 를 사전 강도 500 으로 빌린 새 광고가 노출을 받을수록 수축 CTR 이 진짜 CTR 5% 에 다가가는 과정을 보고, 사전 강도 다섯 가지의 오차와 흔들림을 비교한다.

# 1단계: 사전 CTR 과 사전 강도를 α, β 로 바꾼다
# 노출 100회에 클릭 4번이면 CTR 4% 인가. 표본이 100회면 우연히 4번 눌릴 수도 있어 사전확률 쪽으로 끌어당긴다. 이것이 수축이고, 베타-이항 모형으로 추정 CTR = (클릭 + α) / (노출 + α + β) 한 줄에 담긴다. α, β 는 사전확률을 가상의 노출과 클릭으로 바꾼 값이라, 사전 CTR = α / (α + β), 사전 강도 = α + β(가상 노출 수)다.
PRIOR_CTR = 0.02        # 광고주 평균에서 빌린 사전 CTR 2%
STRENGTH = 500          # 사전 강도 = 가상 노출 500회로 치겠다

alpha = PRIOR_CTR * STRENGTH
beta = STRENGTH - alpha
print(f"사전 CTR {PRIOR_CTR:.1%}, 사전 강도 {STRENGTH}회  →  α={alpha:.0f}, β={beta:.0f}")
print("  (\"노출 500회에 클릭 10번 본 셈으로 시작한다\"는 뜻)\n")

# 2단계: 진짜 CTR 5% 인 광고가 노출을 쌓는 과정을 본다
# 노출마다 딱 기대만큼 눌렸다고 두고, 추정값에서 사전확률이 차지하는 몫도 찍는다.
def shrunk(clicks, imps, a=alpha, b=beta):
    return (clicks + a) / (imps + a + b)

# 진짜 CTR이 5%인 좋은 광고가 들어왔다고 하자. 노출이 쌓이는 과정을 본다.
TRUE = 0.05
print(f"진짜 CTR {TRUE:.0%}인 광고가 들어왔을 때")
print(f"{'노출':>8}{'클릭':>6}{'날것 CTR':>11}{'수축 CTR':>11}{'사전 비중':>11}")
for imps in (0, 50, 200, 1_000, 5_000, 20_000, 100_000):
    clicks = round(imps * TRUE)                    # 딱 기대만큼 눌렸다고 가정
    raw = clicks / imps if imps else float('nan')
    s = shrunk(clicks, imps)
    prior_weight = STRENGTH / (imps + STRENGTH)    # 추정값에서 사전확률이 차지하는 몫
    raw_txt = f"{raw:.3%}" if imps else "   —"
    print(f"{imps:>8,}{clicks:>6,}{raw_txt:>11}{s:>10.3%}{prior_weight:>10.1%}")
print()

# 3단계: 사전 비중이 절반으로 떨어지는 지점을 찍는다
# 자기 데이터가 절반을 넘는 때는 노출이 사전 강도를 넘는 순간이다.
print(f"사전확률의 비중이 절반으로 떨어지는 지점  노출 {STRENGTH:,}회")
print("  → 사전 강도가 곧 '자기 데이터를 믿기 시작하는 문턱'이다.\n")

# 4단계: 사전 강도 다섯 가지로 새 광고 2,000개를 굴린다
# 위 표는 "딱 기대만큼 눌렸다"고 가정했다. 실제로는 운이 섞인다.
# 그래서 새 광고 2,000개를 굴려 오차의 크기와 흔들림을 함께 본다.
import random
random.seed(42)

TRIALS = 2_000
IMPS = 1_000            # 새 광고마다 노출 1,000회를 준다

print(f"새 광고 {TRIALS:,}개를 노출 {IMPS:,}회씩 굴렸을 때 (진짜 CTR {TRUE:.0%})")
print(f"{'사전 강도':>10}{'평균 추정':>11}{'평균 오차':>11}{'흔들림(표준편차)':>18}{'최악':>9}")
for st in (50, 200, 500, 2_000, 10_000):
    a = PRIOR_CTR * st
    b = st - a
    ests = []
    for _ in range(TRIALS):
        clicks = sum(1 for _ in range(IMPS) if random.random() < TRUE)
        ests.append(shrunk(clicks, IMPS, a, b))
    mean = sum(ests) / TRIALS
    var = sum((e - mean) ** 2 for e in ests) / TRIALS
    sd = var ** 0.5
    worst = max(abs(e - TRUE) for e in ests)
    print(f"{st:>10,}{mean:>10.3%}{(mean/TRUE-1)*100:>+10.1f}%{sd:>17.4%}{worst:>8.2%}")

# 5단계: 읽는 법을 찍는다
print()
print("→ 강도가 약하면 평균은 진짜에 가깝지만 흔들림이 크다. 같은 광고가 운에 따라 크게 다르게 평가된다.")
print("→ 강도가 세면 흔들림은 작아지지만 평균이 사전확률 쪽으로 눌린다. 좋은 광고를 오래 못 알아본다.")
print("→ 노출을 못 받으면 데이터도 안 쌓이니, 과소평가는 스스로를 강화한다. 이게 콜드스타트의 덤이다.")
print("→ 그래서 강도는 '이 계층 안에서 광고들이 얼마나 비슷한가'로 정한다. 비슷할수록 세게 빌려도 된다.")

# 출력:
# 1단계 뜻: 사전 CTR 2.0% 를 강도 500 으로 빌리면 α=10, β=490 이다. 노출 500회에 클릭 10번을 본 셈으로 시작한다.
# 사전 CTR 2.0%, 사전 강도 500회  →  α=10, β=490
#   ("노출 500회에 클릭 10번 본 셈으로 시작한다"는 뜻)
#
# 2단계 뜻: 노출 0회에는 사전 CTR 2.000% 그대로이고, 200회에서도 사전 비중이 71.4% 라 2.857% 에 머문다. 노출이 쌓일수록 진짜 값 쪽으로 붙어 100,000회에 4.985% 가 된다.
# 진짜 CTR 5%인 광고가 들어왔을 때
#       노출    클릭     날것 CTR     수축 CTR      사전 비중
#        0     0          —    2.000%    100.0%
#       50     2     4.000%    2.182%     90.9%
#      200    10     5.000%    2.857%     71.4%
#    1,000    50     5.000%    4.000%     33.3%
#    5,000   250     5.000%    4.727%      9.1%
#   20,000 1,000     5.000%    4.927%      2.4%
#  100,000 5,000     5.000%    4.985%      0.5%
#
# 3단계 뜻: 노출이 사전 강도 500회를 넘으면 사전확률의 비중이 절반 아래로 떨어진다.
# 사전확률의 비중이 절반으로 떨어지는 지점  노출 500회
#   → 사전 강도가 곧 '자기 데이터를 믿기 시작하는 문턱'이다.
#
# 4단계 뜻: 강도 50 은 평균 오차 -3.0% 로 정확하지만 흔들림이 0.6565% 로 크다. 강도 10,000 은 흔들림이 0.0631% 로 작지만 평균이 2.274%(-54.5%)까지 눌린다.
# 새 광고 2,000개를 노출 1,000회씩 굴렸을 때 (진짜 CTR 5%)
#      사전 강도      평균 추정      평균 오차         흔들림(표준편차)       최악
#         50    4.851%      -3.0%          0.6565%   2.24%
#        200    4.513%      -9.7%          0.5780%   2.25%
#        500    3.980%     -20.4%          0.4595%   2.40%
#      2,000    2.998%     -40.0%          0.2278%   2.60%
#     10,000    2.274%     -54.5%          0.0631%   2.95%
# 5단계 뜻: 코드가 찍는 해설이다. 강도는 이 계층 안에서 광고들이 얼마나 비슷한가로 정한다.
#
# → 강도가 약하면 평균은 진짜에 가깝지만 흔들림이 크다. 같은 광고가 운에 따라 크게 다르게 평가된다.
# → 강도가 세면 흔들림은 작아지지만 평균이 사전확률 쪽으로 눌린다. 좋은 광고를 오래 못 알아본다.
# → 노출을 못 받으면 데이터도 안 쌓이니, 과소평가는 스스로를 강화한다. 이게 콜드스타트의 덤이다.
# → 그래서 강도는 '이 계층 안에서 광고들이 얼마나 비슷한가'로 정한다. 비슷할수록 세게 빌려도 된다.
```

2단계 표의 날것 CTR 은 클릭 ÷ 노출로 앞에서 말한 관측 CTR 과 같고 수축 CTR 은 수축 공식으로 낸 추정값입니다. 수축 공식은 관측 CTR 과 사전 CTR 의 가중평균(값마다 무게를 곱해 더한 평균)과 같습니다. 이때 사전 CTR 에 붙는 무게가 사전 강도 ÷ (노출 + 사전 강도) 이고 표의 사전 비중이 이 무게입니다. 노출 0회에서는 이 광고의 데이터가 아직 없으니 수축 CTR 이 사전 CTR 그대로 2.000% 입니다. 노출 200회에서는 클릭 10번으로 관측 CTR 이 이미 5% 인데도 **사전 비중이 500 ÷ (200 + 500) = 71.4% 라 추정값의 대부분을 아직 사전 CTR 이 정하므로** 수축 CTR 은 (10 + 10) ÷ (200 + 500) 으로 계산한 2.86% 에 머뭅니다. 노출이 더 쌓이면 수축 CTR 은 5,000회에 4.73%, 10만 회에 4.99% 로 진짜 CTR 5% 에 가까워집니다.

**사전 강도 500 은 문턱 역할도 합니다.** 사전 비중 500 ÷ (노출 + 500) 은 노출이 500회일 때 정확히 절반이 되므로 3단계가 찍은 것처럼 노출이 사전 강도 500회를 넘으면 사전확률의 비중이 절반 아래로 떨어지고 이 광고 자신의 데이터가 추정을 주도합니다. 따라서 사전 강도를 정하면 「노출 몇 회부터 이 광고를 자기 데이터로 판단할지」도 함께 정해집니다.

2단계 표는 클릭이 늘 기대만큼 난다고 가정했지만 실제 클릭에는 운이 섞이므로 4단계는 진짜 CTR 5% 인 새 광고 2,000개에 노출을 1,000회씩 주고 노출마다 5% 확률로 클릭이 나도록 무작위로 뽑아 사전 강도마다 추정값 2,000개를 얻습니다. 표의 평균 추정은 이 2,000개의 평균입니다. 평균 오차는 그 평균이 진짜 CTR 5% 보다 몇 % 낮거나 높은지입니다. 흔들림(표준편차)은 진짜 CTR 이 같은 광고들이 운에 따라 얼마나 다르게 추정되는지를 나타냅니다. 최악은 2,000개 가운데 진짜 CTR 에서 가장 멀리 벗어난 추정이 몇 %p 떨어졌는지입니다. 양 끝의 두 강도를 보면 이렇습니다.

- **강도 50** 은 평균 추정이 4.851% 라 평균 오차가 -3.0% 로 진짜에 가깝지만 흔들림(표준편차)이 0.66%p(출력 0.6565%)로 커서 같은 광고라도 운에 따라 크게 다르게 평가됩니다.
- **강도 10,000** 은 흔들림이 0.06%p(출력 0.0631%)로 열 배 작아지지만 α 가 2% × 10,000 = 200 이라 클릭이 기대만큼 50번 나도 분자에 가상 클릭 200, 분모에 가상 노출 10,000 이 더해집니다. 그래서 평균 추정이 2.274% 로 진짜의 절반(-54.5%)까지 끌어당겨집니다.

평균 오차처럼 추정의 평균이 진짜 값에서 한쪽으로 벗어난 정도를 편향(bias)이라고 하고 흔들림처럼 같은 광고의 추정이 운에 따라 퍼지는 정도를 분산(variance)이라고 합니다. 사전 강도를 50 에서 10,000 으로 키우면 분산은 줄지만 편향이 커지므로 두 값을 함께 줄일 수 없습니다. 이 관계가 **편향과 분산의 상충**입니다.

그런데 광고에서는 이 상충의 두 쪽 가운데 사전 강도가 셀 때 생기는 과소평가가 더 위험합니다. 낮게 평가된 광고는 노출을 못 받으니 데이터가 쌓이지 않고 데이터가 없으니 추정이 계속 사전확률 쪽으로 끌어당겨진 채 남아서 **과소평가는 스스로를 강화합니다.** 이 고리를 끊는 일은 탐색이 맡습니다. 아직 잘 모르는 광고에 일부러 노출을 주는 탐색은 [탐색과 활용](post.html?id=exploration-exploitation) 편에서 다룹니다.

---

위의 수축 공식은 베타 분포(Beta distribution)에서 나옵니다. 베타 분포는 0 과 1 사이의 값(여기서는 CTR)이 어디쯤일지를 곡선으로 나타내는 확률분포이고 α 와 β 두 숫자가 곡선의 모양을 정합니다. 이 글의 용어로는 **α + β 가 사전 강도이고 분포의 평균 α / (α + β) 가 사전 CTR** 입니다. 노출과 클릭이 쌓이면 α 와 β 가 커지면서 분포의 폭이 좁아집니다. 아래 카드에서는 α 와 β 슬라이더를 움직이며 봉우리의 위치와 폭이 어떻게 바뀌는지 보면 됩니다.

## 3. 기존 광고의 흩어짐으로 구하는 사전 강도

**사전 강도는 사람이 임의로 정하지 않고 같은 계층 안 기존 광고들의 CTR 이 얼마나 흩어져 있는지로 계산합니다. 촘촘히 모여 있으면 세게 빌려도 되고 널찍이 흩어져 있으면 약하게 빌려야 합니다. 이 글의 데이터에서 소재가 비슷한 패션몰A 는 사전 강도가 42,744, 천차만별인 보험사C 는 213 으로 200배 차이가 납니다.**

2절의 코드는 사전 강도를 500, 2000처럼 임의로 넣었습니다. 실무에서는 이 숫자를 손으로 고르지 않고 같은 계층에 이미 쌓인 데이터에서 구합니다.

기준은 같은 계층 안 광고들의 CTR 이 얼마나 모여 있는지입니다. 어떤 광고주의 기존 광고 CTR 이 전부 2.3~2.5% 에 몰려 있다면 새 광고도 그 근처일 가능성이 높아 세게 빌려도 손해가 적습니다. 반대로 기존 광고 CTR 이 0.1% 부터 1.4% 까지 흩어져 있다면 새 광고가 어디쯤일지 전혀 알 수 없으므로 이때 세게 빌리면 추정이 엉뚱한 값 쪽으로 끌어당겨집니다. 아래 코드의 패션몰A 와 보험사C 가 이 두 경우입니다.

흩어짐을 측정해 사전 강도로 바꾸는 방법으로 적률법(method of moments)이 있습니다. 적률법은 분포의 평균과 분산을 데이터에서 계산한 평균, 분산과 같게 만드는 모수(분포의 모양을 정하는 숫자, 이 글에서는 α 와 β)를 찾는 방법입니다. 여기서는 베타 분포의 평균 $m$ 과 분산 $v$ 를 기존 광고들의 CTR 에서 계산한 평균과 분산에 맞춥니다.

$$m = \frac{\alpha}{\alpha+\beta}, \quad v = \frac{m(1-m)}{\alpha+\beta+1} \;\Rightarrow\; \alpha+\beta = \frac{m(1-m)}{v} - 1$$

왼쪽 두 식은 베타 분포의 평균과 분산을 α 와 β 로 쓴 식이고 두 식에서 α + β 를 구하면 오른쪽 식이 나옵니다. 오른쪽 식에서는 분산 $v$ 가 분모에 들어 있어서 기존 CTR 들의 분산이 작을수록 사전 강도가 커지고 분산이 클수록 작아집니다. 식이 앞의 기준과 정확히 같은 방향으로 움직입니다.

같은 계층의 데이터로 사전확률을 정하는 이런 방식을 경험적 베이즈(empirical Bayes)라고 부릅니다. 아래 코드는 이 계산을 광고주 3곳에 적용합니다. 1단계 함수는 기존 광고 CTR 목록에서 평균과 표본분산(평균과의 차이를 제곱해 더한 값을 광고 수 n 보다 1 작은 n-1 로 나눈 분산)을 구해 사전 강도를 계산합니다. 2단계는 광고주마다 기존 광고 CTR 5개로 평균, 흩어짐(표준편차), 사전 강도를 찍습니다. 3단계는 그 강도로 노출 500회에 클릭 25회를 받은 같은 새 광고를 광고주마다 평가합니다.

```python
# 하는 일: 광고주 3곳의 기존 광고 CTR 이 흩어진 정도로 사전 강도를 구하고(경험적 베이즈), 그 강도로 노출 500회에 클릭 25회인 새 광고를 평가한다.

# 1단계: CTR 목록에서 사전 평균과 강도를 구하는 함수를 만든다
# 앞에서 강도는 이 계층 안에서 광고들이 얼마나 비슷한가로 정한다고 했다. 같은 광고주의 기존 광고 CTR 이 촘촘히 모여 있으면 새 광고도 그 근처일 테니 세게 빌리고(강도 큼), 널찍이 흩어져 있으면 어디일지 모르니 약하게 빌린다(강도 작음). 베타 분포의 평균과 분산을 관측된 CTR 들에 맞추면(적률법) α, β 가 나온다.
def fit_strength(ctrs):
    """관측된 CTR 목록에서 사전 평균과 강도를 구한다."""
    n = len(ctrs)
    m = sum(ctrs) / n
    # 표본분산(자유도 n-1). 광고가 2개 미만이면 강도를 못 구한다.
    if n < 2:
        return m, None
    v = sum((c - m) ** 2 for c in ctrs) / (n - 1)
    if v <= 0:
        return m, None                      # 전부 같은 값 → 무한히 세게 빌려도 됨
    # 평균 m = α/(α+β), 분산 v = m(1-m)/(α+β+1) 이니 강도 s = α+β = m(1-m)/v - 1 이다.
    s = m * (1 - m) / v - 1
    return m, s

# 2단계: 광고주 3곳의 강도를 구해 찍는다
# 가상 데이터: 광고주 3곳의 기존 광고 CTR
GROUPS = {
    "패션몰A (소재가 다 비슷)":   [0.0244, 0.0231, 0.0250, 0.0238, 0.0246],
    "게임사B (장르가 섞임)":      [0.0097, 0.0180, 0.0042, 0.0131, 0.0068],
    "보험사C (상품마다 천차만별)": [0.0052, 0.0009, 0.0140, 0.0021, 0.0095],
}

print(f"{'광고주':<24}{'평균 CTR':>10}{'흩어짐(표준편차)':>18}{'구한 강도':>12}{'해석':>16}")
fitted = {}
for name, ctrs in GROUPS.items():
    m, s = fit_strength(ctrs)
    sd = (sum((c - m) ** 2 for c in ctrs) / (len(ctrs) - 1)) ** 0.5
    fitted[name] = (m, s)
    note = "세게 빌려도 됨" if s and s > 2000 else ("약하게" if s and s < 300 else "중간")
    print(f"{name:<24}{m:>9.3%}{sd:>17.4%}{s:>11,.0f}{note:>16}")
print()

# 3단계: 구한 강도로 새 광고를 평가한다
TRUE_NEW = 0.05          # 새 광고가 실제로는 아주 좋다고 하자
IMPS, CLICKS = 500, 25   # 노출 500회에 클릭 25회 (관측 CTR 5%)

print(f"새 광고: 노출 {IMPS}회, 클릭 {CLICKS}회 (관측 {CLICKS/IMPS:.1%}, 진짜 {TRUE_NEW:.0%})")
print(f"{'광고주':<24}{'추정 CTR':>10}{'진짜와 차이':>13}")
for name, (m, s) in fitted.items():
    a = m * s
    b = s - a
    est = (CLICKS + a) / (IMPS + a + b)
    print(f"{name:<24}{est:>9.3%}{(est/TRUE_NEW-1)*100:>+12.1f}%")

# 4단계: 읽는 법을 찍는다
print()
print("→ 소재가 비슷한 광고주(패션몰A)는 강도가 세게 나온다. 새 광고도 그 근처일 거라 믿는 것이다.")
print("→ 대신 이 광고주에서 진짜 튀는 광고가 나오면 알아보는 데 오래 걸린다.")
print("→ 상품마다 천차만별인 광고주(보험사C)는 강도가 약하게 나와 자기 데이터를 빨리 믿는다.")
print("→ 즉 강도를 손으로 찍을 필요가 없다. 기존 광고들의 흩어짐이 알려 준다.")

# 출력:
# 2단계 뜻: 패션몰A 는 CTR 이 2.418% 근처에 촘촘해 강도가 42,744 로 세고, 보험사C 는 흩어짐이 0.5421% 로 커서 213 으로 약하다.
# 광고주                         평균 CTR         흩어짐(표준편차)       구한 강도              해석
# 패션몰A (소재가 다 비슷)            2.418%          0.0743%     42,744        세게 빌려도 됨
# 게임사B (장르가 섞임)              1.036%          0.5407%        350              중간
# 보험사C (상품마다 천차만별)           0.634%          0.5421%        213             약하게
#
# 3단계 뜻: 같은 새 광고도 패션몰A 소속이면 2.448% 로 진짜 대비 -51.0%, 보험사C 소속이면 3.694%(-26.1%)로 평가된다. 강도가 셀수록 자기 데이터를 늦게 믿는다.
# 새 광고: 노출 500회, 클릭 25회 (관측 5.0%, 진짜 5%)
# 광고주                         추정 CTR       진짜와 차이
# 패션몰A (소재가 다 비슷)            2.448%       -51.0%
# 게임사B (장르가 섞임)              3.369%       -32.6%
# 보험사C (상품마다 천차만별)           3.694%       -26.1%
# 4단계 뜻: 코드가 찍는 해설이다. 강도를 손으로 찍지 않아도 기존 광고들의 흩어짐이 알려 준다.
#
# → 소재가 비슷한 광고주(패션몰A)는 강도가 세게 나온다. 새 광고도 그 근처일 거라 믿는 것이다.
# → 대신 이 광고주에서 진짜 튀는 광고가 나오면 알아보는 데 오래 걸린다.
# → 상품마다 천차만별인 광고주(보험사C)는 강도가 약하게 나와 자기 데이터를 빨리 믿는다.
# → 즉 강도를 손으로 찍을 필요가 없다. 기존 광고들의 흩어짐이 알려 준다.
```

2단계 표에서는 사전 강도가 기존 광고들의 CTR 에서 스스로 정해집니다. 표의 흩어짐(표준편차)은 기존 광고 CTR 들이 평균에서 얼마나 떨어져 있는지를 나타냅니다. 패션몰A 는 CTR 이 평균 2.418% 근처에 흩어짐 0.0743% 로 촘촘히 모여 분산이 아주 작으므로 사전 강도가 42,744 로 세게 나옵니다. 보험사C 는 평균이 0.634% 인데 흩어짐이 0.5421% 로 커서 사전 강도가 213 으로 약합니다. 게임사B 는 흩어짐이 0.5407% 로 보험사C 와 거의 같지만 평균이 1.036% 로 더 높아 앞의 식에서 분자 $m(1-m)$ 이 커지므로 사전 강도가 350 입니다. 해석 칸은 코드가 구한 강도가 2,000 을 넘으면 「세게 빌려도 됨」, 300 보다 작으면 「약하게」, 그 사이면 「중간」으로 적습니다. **사람이 손으로 정한 숫자로는 42,744 와 213 처럼 200배 벌어지는 차이를 낼 수 없습니다.**

3단계 표에는 사전 강도를 이렇게 정한 대가가 나옵니다. 노출 500회에 클릭 25회를 받아 관측 CTR 이 5% 인 같은 새 광고가 패션몰A 소속이면 가상 노출 42,744회가 실제 노출 500회보다 훨씬 많아 추정이 광고주 평균 2.418% 쪽으로 끌어당겨지므로 진짜 CTR 5% 의 절반인 2.45%(출력 2.448%, 진짜 대비 -51.0%)로 평가됩니다. 그래서 패션몰A 에서 평균과 크게 다른 광고가 진짜로 나오면 알아보는 데 오래 걸립니다. 반면 보험사C 소속이면 가상 노출이 213회뿐이라 실제 노출 500회가 추정을 더 크게 움직이므로 3.69%(출력 3.694%, -26.1%)로 훨씬 빨리 반응합니다. 사전 강도가 350 인 게임사B 소속이면 그 사이인 3.369%(-32.6%)가 나옵니다.

**패션몰A 에서 보이는 이 느린 반응은 버그가 아니라 설계입니다.** 소재가 비슷한 광고주에서 갑자기 2배 넘게(5% ÷ 2.418%) 좋은 광고가 나올 확률은 실제로 낮아서 그 낮은 확률을 의심하는 편이 통계적으로 맞습니다. 다만 의심이 틀렸을 때는 회복이 느리다는 점을 알고 써야 합니다.

### 계층을 쌓는 방식 [무대: 닫힌 생태계]

지금까지는 광고주 계층 하나에서만 빌렸지만 실무에서는 한 계층만 쓰지 않고 여러 층을 쌓습니다. 전체 → 카테고리 → 광고주 → 캠페인 순으로 범위를 좁혀 가면서 위 층에서 구한 값을 바로 아래 층의 사전확률로 쓰는 방식입니다.

담장 안(닫힌 생태계, walled garden)은 한 회사가 광고를 사는 쪽과 경매, 광고 자리를 모두 직접 운영하는 구조입니다. 네이버와 카카오가 여기에 속합니다. 담장 안에서는 광고주 계정과 캠페인 구조가 플랫폼 소유라서 **누가 무엇을 올렸는지에 따른 계층이 확실하게 갖춰져 있습니다.** 같은 광고주의 지난 1년 이력을 전부 볼 수 있고 업종 분류도 광고 심사 과정에서 이미 붙어 있습니다.

그래서 담장 안의 실무에서는 「계층을 어떻게 만들까」가 아니라 **「몇 층까지 내려갈까」** 를 고민합니다. 너무 좁히면 캠페인 하나에 광고가 두 개뿐인 경우처럼 표본이 없고 너무 넓히면 1절에서 본 4.6배 차이가 한 평균에 섞여 묻힙니다. 그 사이에서 대개 광고주 층이 표본과 유사성의 균형점입니다.

실무 함정도 하나 있습니다. 광고주가 계정을 새로 만들면 계층도 처음부터 다시 시작하므로 큰 광고주가 광고 대행사(광고주 대신 광고를 운영해 주는 회사)를 바꾸면서 계정을 옮기면 실제로는 이력이 풍부한데도 시스템에서는 콜드스타트가 됩니다. 이런 경우를 잡으려고 사업자번호나 브랜드명처럼 계정보다 위에서 광고주를 알아보는 상위 키를 따로 두기도 합니다.

## 4. 계층 대신 광고 피처로 하는 예측 [무대: 열린 RTB]

**모델이 광고의 생김새와 CTR 의 관계를 이미 배워 뒀다면 이력이 없는 새 광고도 생김새만 넣으면 예측이 나오므로 계층에 덜 기댈 수 있습니다. 계층이 부실한 열린 RTB(여러 회사가 노출마다 실시간으로 입찰하는 시장)는 이 방법에 훨씬 더 기대고 유저 정보 대신 도메인, 슬롯(광고 자리) 크기, 시간대처럼 노출이 나는 자리와 때의 정보로 옮겨 갑니다.**

지금까지는 「누구 소속인가」에 따라 계층을 골라 빌렸습니다. 그런데 **광고의 생김새로 예측하는 방법**도 있습니다.

이력이 없어도 광고에는 이미지 크기, 영상 길이, 제목 글자 수, 업종, 랜딩 페이지 종류, 할인율 표기 여부 같은 특징이 있습니다. 모델에 넣는 이런 입력값을 피처(feature)라고 하고 광고의 생김새와 내용에서 뽑은 피처를 콘텐츠 피처라고 부릅니다. 모델이 이 피처들과 CTR 의 관계를 이미 배워 뒀다면 **새 광고의 피처만 넣어도 예측이 나옵니다.**

그래서 딥러닝 CTR 모델(여러 층의 신경망으로 CTR 을 예측하는 모델)은 콜드스타트에 유리합니다. ID 임베딩은 광고 ID 마다 학습으로 정해 두는 숫자 벡터입니다. 광고 ID 임베딩만 쓰는 모델은 새 광고의 ID 를 학습 때 본 적이 없으므로 그 ID 에서 얻을 정보가 없습니다. 하지만 콘텐츠 피처를 함께 쓰면 ID 가 새것이어도 나머지 피처가 예측을 맡습니다. 어떤 피처를 어떻게 만드는지는 [CTR 피처 엔지니어링](post.html?id=ctr-feature-engineering) 편에서, 모델 구조는 [Deep CTR 모델](post.html?id=deep-ctr-models) 편에서 다룹니다.

열린 RTB 는 여러 회사가 각자 가진 광고 자리를 내놓고 노출이 생길 때마다 실시간 입찰(RTB, Real-Time Bidding)로 광고를 고르는 시장입니다. DSP(Demand-Side Platform)는 이 시장에서 광고주 편에 서서 입찰하는 시스템입니다. 열린 RTB 에서는 계층이 부실해 광고의 생김새로 예측하는 방법에 훨씬 더 기댑니다. DSP 는 남의 인벤토리에 입찰하므로 **유저 쪽 계층이 거의 없습니다.** 쿠키(브라우저에 저장해 두는 방문자 식별자)가 자주 바뀌어 「이 유저의 이력」을 길게 쌓을 수 없으므로 유저 콜드스타트가 예외가 아니라 기본값입니다.

그 대신 광고 쪽과 지면 쪽 계층은 있습니다. 그래서 열린 RTB 의 콜드스타트 대응은 유저 정보를 포기하고 **도메인, 슬롯 크기, 시간대 같은 문맥 피처**(지금 이 노출이 나는 자리와 때를 나타내는 피처)로 옮겨 갑니다. 담장 안이 「이 사람을 안다」로 푸는 문제를 열린 RTB 는 「이 자리를 안다」로 풉니다.

:::deep 더 깊이 — 베타 분포를 쓰는 까닭과 더하기 한 번으로 끝나는 갱신

베타 분포가 이항 분포의 **공액 사전분포**(conjugate prior)라서 수축 공식이 `(클릭 + α) / (노출 + α + β)` 처럼 단순해집니다. 공액 사전분포는 사전분포(데이터를 보기 전의 믿음을 나타낸 분포)에 데이터를 반영해 갱신한 뒤에도 같은 종류의 분포가 나오게 하는 사전분포입니다. 아래에서 그 과정을 식으로 따라갑니다.

CTR 을 확률 $p$ 라고 하면 노출 $n$ 회에서 클릭이 $k$ 번 관측될 확률은 이항 분포(성공 확률이 $p$ 인 시행을 $n$ 번 반복할 때 성공 횟수의 분포)를 따릅니다. 아래 식의 ∝ 는 왼쪽이 오른쪽에 비례한다는 기호입니다.

$$P(k \mid p) \propto p^{k} (1-p)^{n-k}$$

사전분포를 베타 분포 $\text{Beta}(\alpha, \beta)$ 로 두면 밀도는 다음과 같습니다.

$$P(p) \propto p^{\alpha-1} (1-p)^{\beta-1}$$

베이즈 정리(갱신한 분포가 사전분포와 데이터가 나올 확률의 곱에 비례한다는 정리)에 따라 두 식을 곱하면 밑이 같은 $p$ 끼리, $1-p$ 끼리 지수가 더해집니다.

$$P(p \mid k) \propto p^{k+\alpha-1} (1-p)^{n-k+\beta-1}$$

곱한 결과도 베타 분포 $\text{Beta}(\alpha + k,\; \beta + n - k)$ 입니다. **데이터를 반영해도 분포의 형태가 바뀌지 않는 성질이 공액의 뜻입니다.** 그래서 갱신은 α 에 클릭 수 $k$ 를, β 에 클릭이 나지 않은 노출 수 $n - k$ 를 더하는 것으로 끝납니다. 베타 분포의 평균은 $\frac{\alpha}{\alpha+\beta}$ 이므로 갱신한 분포의 평균 $\frac{\alpha + k}{\alpha + \beta + n}$ 이 그대로 수축 공식이 됩니다.

실무에서 이 성질이 값진 까닭은 계산 쪽에 있지 않습니다. **상태를 두 숫자로만 들고 있으면 된다는 점**이 값집니다. 광고 하나마다 (α, β) 두 개만 저장해 두고 노출과 클릭이 들어올 때마다 더하기만 하면 되므로 광고가 수백만 개여도 감당할 수 있습니다.

다만 이 모형은 CTR 이 시간에 따라 변하지 않는다고 가정하는데, 실제 CTR 은 계절성(철마다 되풀이되는 변화)이나 소재 피로(같은 소재를 오래 보여 줄수록 클릭이 줄어드는 현상)로 변합니다. 그래서 실무에서는 과거 관측에 감쇠(decay)를 걸어 오래된 데이터의 비중을 줄입니다. 감쇠를 거는 방법은 [Online Learning 과 지연 피드백](post.html?id=online-learning-delayed-feedback) 편에서 다룹니다.
:::

## 5. 정리 — 콜드스타트를 다루는 순서

**콜드스타트는 빌려 올 계층 선택, 그 계층의 흩어짐으로 계산하는 사전 강도, 수축 공식으로 만드는 pCTR 순서로 다룹니다.**

| 단계 | 무엇을 하나 | 이 글의 근거 |
|---|---|---|
| 1 | 빌려 올 계층을 고른다 (광고주 층이 대개 균형점) | 광고주별 CTR이 4.6배 차이 (1절) |
| 2 | 그 계층의 기존 광고 흩어짐으로 강도를 계산한다 | 42,744 vs 213, 200배 차이 (3절) |
| 3 | 수축 공식으로 pCTR을 만든다 | 분자, 분모에 더하기 한 번 (2절) |
| 4 | 콘텐츠 피처가 있으면 계층 의존을 줄인다 | ID가 새것이어도 나머지 피처가 일한다 (4절) |
| 5 | 노출이 강도를 넘으면 자기 데이터가 주도한다 | 사전 강도 = 문턱 (2절) |

표의 값은 가상 데이터 기준이고 실제 값은 인벤토리 구성에 따라 달라집니다.

표를 위에서 아래로 따라가면 단계마다 계산하는 때가 다르다는 점이 눈에 띕니다. **1번과 2번은 하루 한 번 배치(모아 둔 데이터를 정해진 때에 한꺼번에 처리하는 작업)로 계산해 두면 되고 3번은 요청마다 더하기 한 번**입니다. 광고마다 (α, β) 두 숫자만 들고 있으면 되므로 이 방법은 서빙 비용(요청이 올 때마다 예측값을 내는 데 드는 비용)이 거의 들지 않습니다.

그래서 콜드스타트에 대응하는 작업은 대개 모델 교체가 아니라 **계층과 강도 관리**입니다. 새 모델을 붙이기보다 「우리 계층이 지금 몇 층인지, 강도를 언제 갱신했는지」를 점검하는 편이 효과가 큽니다.

끝으로 이 글이 답하지 않은 질문을 밝혀 둡니다. 「**그래서 이 광고에 노출을 얼마나 줄까**」는 여기서 다루지 않았습니다. 수축은 지금 있는 정보로 최선의 숫자를 만드는 방법입니다. 노출을 배정하는 일은 그와 별개의 결정입니다.

수축과 탐색은 짝으로 움직입니다. 수축이 정확할수록 탐색이 덜 필요하고 탐색으로 노출을 주면 데이터가 쌓여 수축이 빨리 정확해집니다. 이 맞바꿈은 [탐색과 활용](post.html?id=exploration-exploitation) 편에서 원화로 계산했습니다.
