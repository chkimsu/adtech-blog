모델 팀 33주째 월요일, 지훈 씨는 지난주 표를 다시 열었습니다. 「러닝화 추천」의 광고 30개는 모델이 하나씩 읽고 맞는 정도를 정해, 맞는 광고가 위로 왔습니다. 그런데 한 번 정하는 데 2초가 넘게 걸렸고, 검색어와 광고는 날마다 새로 들어옵니다.

선배는 모델에게 1만 쌍만 맡기자고 했습니다. 그 답으로 숫자 여섯 개만 보는 작은 모델을 학습해, 날마다 들어오는 쌍을 맡기자는 것입니다. 서연 씨는 그렇게 정한 답이 사람들이 실제로 누른 광고와 같은지도 물었습니다.

**큰 모델의 판정을 작은 모델에 옮기면, 얼마나 같게 맞히고 얼마나 싸질까요?**

큰 모델이 붙인 라벨로 작은 모델을 학습하는 일을 증류(distillation)라고 부릅니다. 라벨을 붙이는 큰 모델이 교사(teacher), 그 라벨로 배우는 작은 모델이 학생(student)입니다. 학생이 교사를 잘 따라 할수록 판정을 싸게 맡길 수 있고, 학생이 교사와 다르게 답하는 자리에서는 노출되는 광고가 바뀝니다.

> **한 줄 요약:** 앞 글의 기록에서 qwen3.5:27b 의 판정 한 번은 입력 445.0 토큰과 출력 22.4 토큰이었습니다. 시간은 평균 2.73초, 중앙값 2.04초였습니다. 가상 단가로 라벨 1만 건은 작은 상용 모델 2,138원, 큰 상용 모델 22,275원입니다. 그 판정을 관련과 무관 둘로 보면 정답과 28/30 이 맞았습니다. 규칙으로 라벨을 붙이고 500건을 뒤집는 가짜 교사가 1만 쌍에 라벨을 붙였고, 피처 여섯의 로지스틱 회귀를 학생으로 배웠습니다. 학생은 시험 2,000쌍에서 교사와 92.0% 가 같았고, kappa 는 0.84 였습니다. 다른 161쌍은 뒤집은 라벨 102, 학생이 볼 수 없는 근거 없는 주장 48, 학습에 드문 조합 11 이었습니다. 라벨 100만 건은 교사에게 맡기면 213,800원과 2,227,467원이고, 학생은 CPU 서버 한 대로 465원입니다. 가짜 클릭은 교사의 라벨과 36.1% 가 달랐고, 가격과 브랜드에도 기댔습니다.

> **골라 읽는 법** — 절이 6개입니다. 절마다 표나 코드나 카드가 있어 그것만 보고 넘어가도 됩니다.
>
> - 진짜 교사의 기록으로 센 라벨 1만 건의 값 → 1절
> - 관련과 무관, 가짜 교사, 학생이 배운 가중치 → 2절
> - 학생과 교사의 일치와 다른 쌍의 까닭 → 3절
> - 라벨 100만 건을 교사와 학생이 붙이는 값과 시간 → 4절
> - 관련성 라벨과 클릭이 다른 자리 → 5절
> - 담장 안과 열린 RTB 에서 학생이 판정하는 쌍 → 6절

이 글의 질의와 광고 1만 쌍과 그 피처, 가짜 교사의 규칙, 가짜 클릭은 설명을 위해 만든 가상 데이터입니다. 블록이 `random.Random(7)` 로 만들어, 블록 셋을 차례로 돌리면 늘 같은 값이 나옵니다. 진짜 교사의 답과 토큰, 시간은 지어낸 값이 아닙니다. 앞 글이 2026-11-07 에 이 블로그를 쓰는 맥에서 Ollama 0.40.11 로 qwen3.5:27b 를 띄워 기록했습니다. 기록 파일은 `data/llm-records/llm-labels-code-ranker.json` 이고, 이 글은 새로 기록하지 않았습니다. 후보 30개와 정답 라벨도 앞 글의 것을 글자 그대로 옮겼습니다. 카드 속 파랑은 교사의 라벨, 벽돌색은 학생의 답, 먹색은 클릭입니다. 회색은 학생이 볼 수 없는 자리, 점선 상자는 가짜 교사의 규칙입니다.

    return 0.0 if expected == 1 else (observed - expected) / (1 - expected)

## 2. 교사 라벨로 학생을 학습합니다

**학생은 관련(1)과 무관(0)을 맞히는 로지스틱 회귀이고, 질의와 광고 쌍의 피처 여섯을 봅니다. 가짜 교사가 라벨을 붙인 1만 쌍 가운데 8,000쌍으로 경사 하강을 200번 돌렸습니다. 학생은 규칙이 점수를 준 카테고리 일치, 낱말 겹침, 브랜드 일치에만 큰 가중치를 주었습니다.**

학생이 맞힐 답은 관련(1)과 무관(0) 둘이고, 앞 글의 라벨로 high 와 mid 가 관련, low 와 exclude 가 무관입니다. 1절 블록의 4단계가 앞 글의 후보를 이렇게 바꿔, 진짜 교사의 답을 정답과 비교했습니다. 라벨 넷 그대로는 17/30 이 맞았고, 다른 답 13개 가운데 10개가 정답 low 를 exclude 로 본 답이었습니다. 둘로 보면 그 답들이 같은 무관이 되어 28/30 이 맞고, kappa 는 0.86 입니다. kappa 는 우연히 맞을 몫을 덜어 낸 일치의 크기이고, 26주째 [LLM-as-a-Judge](post.html?id=llm-as-a-judge) 편에서 보았습니다. 남은 둘은 GPS 시계(a07)와 러닝 반바지(a18)로, 정답 mid 를 교사가 exclude 로 본 답입니다.

진짜 교사의 기록은 30건뿐이고, 1만 건을 받으면 1절의 평균으로 7.6시간이 걸립니다. 이 글은 대신 규칙으로 라벨을 붙이는 가짜 교사를 씁니다. 가짜 교사는 광고 문장에 근거 없는 주장이 있으면 무관으로 봅니다. 주장이 없으면 카테고리가 맞을 때 2점, 겹친 낱말 하나에 1점, 브랜드가 맞을 때 1점을 더해 3점 이상이면 관련으로 봅니다. 그리고 그 가운데 500건을 골라 라벨을 뒤집어, 교사 라벨에 섞이는 흔들림을 흉내 냈습니다. 어느 라벨을 뒤집었는지 알고 있어서, 3절에서 학생과 교사가 다른 까닭을 하나씩 셀 수 있습니다.

학생이 보는 피처는 여섯입니다. 낱말 겹침은 질의와 광고 제목에 같이 든 낱말의 수이고, 카테고리 일치와 브랜드 일치는 맞으면 1 입니다. 가격대는 1 이 가장 싸고 5 가 가장 비쌉니다. pCTR 은 광고를 누를 확률을 광고 서버의 모델이 예측한 값으로, [pCTR](post.html?id=pctr-prediction) 편에서 풀었습니다. 이 글의 pCTR 은 겹침, 카테고리, 가격대, 브랜드를 따라 오르게 만들었고, 문장 길이는 광고 문장의 글자 수입니다. 근거 없는 주장이 있는지는 피처에 없어서 학생은 그것을 볼 수 없습니다.

1절 블록의 5단계를 보면 3점 이상인 쌍은 4,348쌍이고, 그 가운데 220쌍이 주장 때문에 무관이 되었습니다. 뒤집기까지 마친 가짜 교사의 관련은 4,212쌍입니다. 예로 찍은 쌍 가운데 112번은 점수가 높은데도 주장이 있어 무관이고, 10번은 0점인데 뒤집혀 관련이 되었습니다. 학생에게는 앞의 주장도, 뒤의 뒤집기도 보이지 않습니다.

학생은 [관심사 분류](post.html?id=interest-classification) 편 3절의 로지스틱 회귀입니다. 피처마다 가중치를 곱해 절편과 더하고, 그 합을 시그모이드로 0~1 사이의 점수로 옮깁니다. 피처는 학습 8,000쌍의 평균을 빼고 표준편차로 나눴고, 이 일을 표준화라고 부릅니다. 표준화하면 단위가 다른 여섯 피처의 가중치를, 피처가 표준편차 하나만큼 바뀔 때의 몫으로 서로 비교할 수 있습니다. 경사 하강은 그 편처럼 200번 돌리고, 학습률은 1 로 두었습니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 가짜 교사의 라벨로 학생 로지스틱 회귀를 학습 8,000쌍에서 200번 고쳐 배우고, 시험 2,000쌍에서 교사와 같은 답의 비율과 kappa 를 잰다.
import math
from collections import Counter

# 1단계: 학습과 시험을 나누고 피처를 표준화한다
# 앞 8,000쌍이 학습, 뒤 2,000쌍이 시험이다. 피처마다 학습 쌍의 평균을 빼고 표준편차로 나눠, 단위가 다른 여섯 값의 크기를 맞춘다.
train, test = pairs[:8_000], pairs[8_000:]
mean = [sum(p['x'][j] for p in train) / len(train) for j in range(6)]
sd = [math.sqrt(sum((p['x'][j] - mean[j]) ** 2 for p in train) / len(train)) for j in range(6)]


def features(p):
    return [(v - m) / s for v, m, s in zip(p['x'], mean, sd)]


print(f'뒤집은 라벨: 학습 {len(train):,}쌍에 {sum(p["flipped"] for p in train)}개, 시험 {len(test):,}쌍에 {sum(p["flipped"] for p in test)}개')


# 2단계: 경사 하강 200번으로 가중치 여섯과 절편을 배운다
# 점수는 가중치 합을 시그모이드로 0~1 사이에 옮긴 값이고, 정답은 가짜 교사의 라벨이다. 학습률은 1 이다.
# 로그 손실은 정답이 1 인 쌍의 점수가 작을수록, 0 인 쌍의 점수가 클수록 커진다. 200번 동안 얼마나 줄었는지 본다.
def sigmoid(z):
    return 1 / (1 + math.exp(-z))


def score(w, b, x):
    return sigmoid(b + sum(wj * xj for wj, xj in zip(w, x)))


def train_student(rows, labels, steps=200, lr=1.0):
    w, b, losses = [0.0] * 6, 0.0, []
    for _ in range(steps):
        gw, gb, loss = [0.0] * 6, 0.0, 0.0
        for x, y in zip(rows, labels):
            p = score(w, b, x)
            loss -= math.log(p if y else 1 - p)
            for j in range(6):
                gw[j] += (p - y) * x[j]
            gb += p - y
        losses.append(loss / len(rows))
        w = [wj - lr * g / len(rows) for wj, g in zip(w, gw)]
        b -= lr * gb / len(rows)
    return w, b, losses


w, b, losses = train_student([features(p) for p in train], [p['teacher'] for p in train])
print(f'로그 손실: 1번째 {losses[0]:.3f}, 50번째 {losses[49]:.3f}, 200번째 {losses[-1]:.3f}')
print('가중치: ' + ', '.join(f'{name} {wj:.2f}' for name, wj in zip(FEATURES, w)) + f', 절편 {b:.2f}')

# 3단계: 시험 2,000쌍에서 교사와 같은 답의 비율과 kappa 를 잰다
# 점수가 0.5 이상이면 관련(1)이다. kappa 는 1 블록에 옮겨 둔 cohen_kappa 로 잰다.
student = [1 if score(w, b, features(p)) >= 0.5 else 0 for p in test]
teacher = [p['teacher'] for p in test]
po, pe = agreement_parts(teacher, student)
print(f'같은 답 {sum(s == t for s, t in zip(student, teacher)):,}/{len(test):,} ({po:.1%}), 우연 일치 {pe:.2f}, kappa {cohen_kappa(teacher, student):.2f}')
both = Counter(zip(teacher, student))
print(f'  교사 1 학생 1 {both[(1, 1)]}, 교사 1 학생 0 {both[(1, 0)]}, 교사 0 학생 1 {both[(0, 1)]}, 교사 0 학생 0 {both[(0, 0)]:,}')

# 4단계: 학생과 교사가 다른 쌍을 까닭마다 센다
# 가짜 교사가 뒤집은 라벨, 학생이 볼 수 없는 주장, 나머지로 나눈다. 진짜 교사의 라벨이라면 이 까닭은 알 수 없다.
diff = [p for p, s, t in zip(test, student, teacher) if s != t]
flips = [p for p in diff if p['flipped']]
claims = [p for p in diff if p['claim'] and not p['flipped']]
rest = [p for p in diff if not p['claim'] and not p['flipped']]
print(f'다른 쌍 {len(diff)}: 뒤집은 라벨 {len(flips)}, 근거 없는 주장 {len(claims)}, 나머지 {len(rest)}')
combos = Counter((p['x'][1], p['x'][0], p['x'][4]) for p in rest)
for (category, overlap, brand), k in sorted(combos.items()):
    same = sum((p['x'][1], p['x'][0], p['x'][4]) == (category, overlap, brand) for p in train)
    print(f'  나머지 {k}쌍: 카테고리 {category}, 겹침 {overlap}, 브랜드 {brand} 로 {2 * category + overlap + brand}점, 학습 {len(train):,}쌍에 같은 조합 {same}쌍')
# 출력:
# 1단계 뜻: 뒤집은 라벨 500개 가운데 394개가 학습에, 106개가 시험에 들어갔다.
# 뒤집은 라벨: 학습 8,000쌍에 394개, 시험 2,000쌍에 106개
# 2단계 뜻: 손실은 50번째에 이미 0.303 이고, 규칙이 점수를 준 셋만 가중치가 크다.
# 로그 손실: 1번째 0.693, 50번째 0.303, 200번째 0.303
# 가중치: 낱말 겹침 1.08, 카테고리 일치 1.94, 가격대 0.06, pCTR 0.06, 브랜드 일치 0.42, 문장 길이 -0.03, 절편 -0.81
# 3단계 뜻: 학생은 시험 2,000쌍 가운데 1,839쌍에서 교사와 같은 답을 냈고, kappa 는 0.84 다.
# 같은 답 1,839/2,000 (92.0%), 우연 일치 0.51, kappa 0.84
#   교사 1 학생 1 783, 교사 1 학생 0 75, 교사 0 학생 1 86, 교사 0 학생 0 1,056
# 4단계 뜻: 다른 161쌍은 뒤집은 라벨, 학생이 볼 수 없는 주장, 학습에 27쌍뿐인 조합으로 나뉜다.
# 다른 쌍 161: 뒤집은 라벨 102, 근거 없는 주장 48, 나머지 11
#   나머지 11쌍: 카테고리 0, 겹침 2, 브랜드 1 로 3점, 학습 8,000쌍에 같은 조합 27쌍
```

로그 손실은 50번째에 이미 0.303 까지 줄고, 그 뒤로는 거의 그대로였습니다. 로그 손실은 정답과 먼 점수일수록 커지는 값이고, 식은 더 깊이 보기에 적었습니다. 가중치는 카테고리 일치 1.94, 낱말 겹침 1.08, 브랜드 일치 0.42 로, 규칙이 점수를 준 셋이 모두 양수입니다. 브랜드 일치가 작게 나온 것은 브랜드가 맞는 쌍이 열에 하나쯤이라 표준편차가 작기 때문이고, 브랜드가 덜 중요하다는 뜻은 아닙니다. 가격대 0.06, pCTR 0.06, 문장 길이 -0.03 은 점수에 거의 보태지 않습니다. pCTR 은 겹침과 카테고리를 따라 오르게 만들었지만, 학생은 그 피처를 직접 보아 pCTR 에서 더 얻을 것이 없었던 것으로 보입니다. 학생은 규칙을 본 적이 없는데도, 라벨만으로 규칙이 쓴 피처를 골라냈습니다.

## 3. 학생이 교사와 얼마나 맞는지 잽니다

**시험 2,000쌍에서 학생의 답은 가짜 교사의 라벨과 1,839쌍이 같았고, kappa 는 0.84 입니다. 다른 161쌍은 뒤집은 라벨 102, 학생이 볼 수 없는 근거 없는 주장 48, 학습에 드문 조합 11 입니다.**

시험 2,000쌍은 학습에 쓰지 않은 쌍이고, 학생은 점수가 0.5 이상이면 관련으로 답합니다. 같은 답은 1,839쌍, 92.0% 입니다. 교사와 학생 모두 절반 넘는 쌍을 무관으로 답해서, 우연히 맞을 몫이 0.51 로 큽니다. 그것을 덜어 낸 kappa 는 0.84 입니다. 이 일치율과 kappa 는 가짜 교사를 만든 방식, 곧 뒤집은 500건과 주장이 있는 쌍의 몫에 크게 기댑니다.

다른 161쌍은 교사만 관련으로 본 75쌍과 학생만 관련으로 본 86쌍입니다. 가짜 교사의 라벨은 어떻게 붙였는지가 데이터에 남아 있어서, 161쌍을 까닭마다 나눌 수 있습니다. 진짜 교사의 라벨이라면 다른 답의 수만 보이고 까닭은 보이지 않습니다. 아래 표는 2절 블록의 4단계가 나눈 셋입니다.

| 학생과 가짜 교사가 다른 까닭 | 시험 쌍 | 학생이 피처로 볼 수 있었나 |
|---|---|---|
| 가짜 교사가 뒤집은 라벨 | 102 | 아니요, 피처와 상관없이 뒤집었습니다 |
| 광고 문장의 근거 없는 주장 | 48 | 아니요, 피처 여섯에 없습니다 |
| 카테고리 0, 겹침 2, 브랜드 1 인 쌍 | 11 | 예, 배운 경계가 이 조합을 놓쳤습니다 |
| 합 | 161 | 시험 2,000쌍 가운데 |

첫째는 가짜 교사가 뒤집은 라벨 102쌍입니다. 시험 2,000쌍에 든 뒤집은 라벨은 106개이고, 학생은 그 가운데 102개에 규칙대로 답했습니다. 뒤집기는 피처와 상관없이 골랐기 때문에, 학생에게는 그 라벨을 맞힐 단서가 없습니다. 이 102쌍은 학생이 규칙을 따른 자리인데도, 일치율에서는 학생이 틀린 답으로 셉니다.

둘째는 근거 없는 주장이 있는 48쌍입니다. 3점 이상이라 학생은 관련으로 답했지만, 가짜 교사는 광고 문장의 주장을 보고 무관으로 보았습니다. 피처 여섯에는 주장을 나타내는 값이 없어서, 학생은 이런 광고를 늘 놓칩니다. 앞 글의 진짜 교사가 policy_risk 로 거른 광고 셋도 문장을 읽어야 알 수 있는 주장이었습니다. 그래서 정책 검사는 학생에게 맡기지 않고, 광고가 들어올 때 광고마다 한 번 따로 봅니다.

셋째는 11쌍이고, 모두 카테고리가 다른데 겹친 낱말 둘과 브랜드 일치로 3점을 채운 쌍입니다. 규칙은 이 쌍을 관련으로 보았고, 학생은 무관으로 답했습니다. 규칙 2×카테고리 + 겹침 + 브랜드 ≥ 3 은 피처의 가중 합을 기준값과 비교하는 선형 경계입니다. 로지스틱 회귀도 같은 경계를 배울 수 있지만, 학생이 배운 경계는 이 조합을 놓쳤습니다. 이 조합은 학습 8,000쌍에 27쌍뿐이고 그 라벨에도 뒤집기와 주장이 섞여 있어, 손실에서 차지하는 몫이 작습니다. 같은 비율로 쌍만 늘리면 손실의 모양이 그대로라 이 조합은 고쳐지지 않습니다. 이 쌍에 가중치를 더 주거나 조합을 따로 다루는 모델이 필요합니다.

셋 가운데 학생을 고쳐 줄일 수 있는 것은 11쌍뿐입니다. 뒤집은 라벨은 교사 쪽의 흔들림이고, 주장은 학생의 피처 밖에 있습니다. 그래서 일치율 92.0% 는 학생의 실수, 교사의 흔들림, 학생이 볼 수 없는 주장 48쌍이 섞인 수로 읽습니다. 이 정도로 맞는 학생에게 판정을 맡기면 값과 시간이 얼마나 주는지가 남은 물음입니다.

## 4. 서빙은 학생이 합니다

**라벨 100만 건을 교사에게 맡기면 가상 단가로 작은 상용 모델 213,800원, 큰 상용 모델 2,227,467원이 듭니다. 로컬 모델은 한 대에서 차례로 758.2시간이 걸립니다. 학생은 CPU 서버 한 대로 0.97시간, 465원입니다.**

서빙에서 라벨이 필요한 쌍은 학습 데이터보다 훨씬 많습니다. 앞 글처럼 자주 들어오는 쌍의 라벨을 미리 받아 두어도, 날마다 처음 보는 검색어와 광고 쌍이 생깁니다. 이 절은 그런 쌍 100만 건에 라벨을 붙이는 값과 시간을 교사와 학생으로 나눠 셉니다.

학생의 값은 [배치 추론과 실시간 추론](post.html?id=batch-vs-realtime-inference) 편의 CPU 서버로 셉니다. 그 편에서 CPU 서버 한 대는 요청을 1초에 287건(287 QPS) 받고, 한 시간에 480원입니다. 이 글은 학생의 판정 한 건을 그 요청 한 건으로 둡니다. 피처 여섯의 로지스틱 회귀는 곱셈과 덧셈 몇 번이라, 이렇게 두면 값을 넉넉히 잡는 쪽입니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 교사와 학생이 라벨 100만 건을 붙이는 값과 시간을 비교하고, 가짜 클릭으로 관련성 라벨과 성과 라벨이 얼마나 다른지 센다.

# 1단계: 라벨 100만 건의 값과 시간을 센다
# 교사는 1 블록이 기록에서 센 건당 평균이다. 학생은 CPU 서버 한 대가 1초에 287건을 처리하고 시간당 480원이라고 둔다.
CPU_QPS, CPU_WON_PER_HOUR = 287, 480
COUNT = 1_000_000
student_hours = COUNT / CPU_QPS / 3600
student_won = student_hours * CPU_WON_PER_HOUR
print(f'교사, 기록한 로컬 모델: 건당 평균 {mean_s:.2f}초(중앙값 {median_s:.2f}초), 100만 건을 한 대에서 차례로 {COUNT * mean_s / 3600:,.1f}시간, 토큰 값 0원')
for name, won in per_label.items():
    print(f'교사, {name}(가상 단가): 100만 건 {won * COUNT:,.0f}원')
print(f'학생, CPU 서버 한 대: 건당 {1000 / CPU_QPS:.2f}ms, 100만 건 {student_hours:.2f}시간, {student_won:,.0f}원')
print(f'건당 시간은 로컬 교사가 학생의 {mean_s * CPU_QPS:,.0f}배, 100만 건의 값은 작은 상용 모델이 학생의 '
      f'{per_label["작은 상용 모델"] * COUNT / student_won:,.0f}배, 큰 상용 모델이 {per_label["큰 상용 모델"] * COUNT / student_won:,.0f}배')

# 2단계: 가짜 클릭을 만든다
# 클릭 라벨은 쌍마다 한 주 동안의 노출에서 클릭이 한 번이라도 있었으면 1 이다. 값은 모두 가상이다.
# 클릭 확률은 0.10 에서 시작해, 규칙의 점수가 3점 이상이면 0.25, 가격대가 한 단계 쌀 때마다 0.06, 브랜드가 맞으면 0.30 을 더한다.
# 주장에 근거가 없는지는 광고만 보고 알 수 없다고 두어 확률에 넣지 않는다. 난수는 1 블록의 rng 를 이어서 쓴다.
for p in pairs:
    price, brand = p['x'][2], p['x'][4]
    chance = 0.10 + 0.25 * (p['points'] >= 3) + 0.06 * (5 - price) + 0.30 * brand
    p['click'] = 1 if rng.random() < chance else 0

# 3단계: 시험 2,000쌍에서 교사와 클릭, 학생과 클릭을 비교한다
# 교사와 클릭이 다른 쌍은 관련인데 클릭이 없는 쌍과 무관인데 클릭이 있는 쌍이다.
clicks = [p['click'] for p in test]
rel_no_click = sum(t == 1 and c == 0 for t, c in zip(teacher, clicks))
irr_click = sum(t == 0 and c == 1 for t, c in zip(teacher, clicks))
print(f'시험 {len(test):,}쌍: 클릭이 있었던 쌍 {sum(clicks)}, 교사가 관련으로 본 쌍 {sum(teacher)}')
print(f'교사와 클릭이 다른 쌍 {rel_no_click + irr_click} ({(rel_no_click + irr_click) / len(test):.1%}): 관련인데 클릭 없음 {rel_no_click}, 무관인데 클릭 {irr_click}')
for name, labels in (('교사와 클릭', teacher), ('학생과 클릭', student)):
    po, pe = agreement_parts(labels, clicks)
    print(f'{name}: 같은 답 {po:.1%}, kappa {cohen_kappa(labels, clicks):.2f}')

# 4단계: 가격대와 브랜드로 나눠 관련 비율과 클릭 비율을 본다
# 관련 비율은 가짜 교사의 라벨로 센다.
for lo, hi in ((1, 2), (3, 3), (4, 5)):
    group = [p for p in test if lo <= p['x'][2] <= hi]
    name = f'가격대 {lo}~{hi}' if lo < hi else f'가격대 {lo}'
    print(f'{name}: {len(group):,}쌍, 교사의 관련 {sum(p["teacher"] for p in group) / len(group):.1%}, 클릭 {sum(p["click"] for p in group) / len(group):.1%}')
for value, name in ((1, '브랜드 일치'), (0, '브랜드 불일치')):
    group = [p for p in test if p['x'][4] == value]
    print(f'{name}: {len(group):,}쌍, 교사의 관련 {sum(p["teacher"] for p in group) / len(group):.1%}, 클릭 {sum(p["click"] for p in group) / len(group):.1%}')
# 출력:
# 1단계 뜻: 라벨 100만 건은 학생이 465원이고, 건당 시간은 로컬 교사가 학생의 783배다.
# 교사, 기록한 로컬 모델: 건당 평균 2.73초(중앙값 2.04초), 100만 건을 한 대에서 차례로 758.2시간, 토큰 값 0원
# 교사, 작은 상용 모델(가상 단가): 100만 건 213,800원
# 교사, 큰 상용 모델(가상 단가): 100만 건 2,227,467원
# 학생, CPU 서버 한 대: 건당 3.48ms, 100만 건 0.97시간, 465원
# 건당 시간은 로컬 교사가 학생의 783배, 100만 건의 값은 작은 상용 모델이 학생의 460배, 큰 상용 모델이 4,795배
# 3단계 뜻: 교사의 라벨과 클릭은 723쌍이 다르고, 학생과 클릭은 교사와 클릭보다 조금 더 같다.
# 시험 2,000쌍: 클릭이 있었던 쌍 701, 교사가 관련으로 본 쌍 858
# 교사와 클릭이 다른 쌍 723 (36.1%): 관련인데 클릭 없음 440, 무관인데 클릭 283
# 교사와 클릭: 같은 답 63.8%, kappa 0.24
# 학생과 클릭: 같은 답 64.9%, kappa 0.27
# 4단계 뜻: 교사의 관련 비율은 가격대마다 비슷하지만, 클릭은 쌀수록 많고 브랜드가 맞으면 많다.
# 가격대 1~2: 772쌍, 교사의 관련 42.9%, 클릭 44.6%
# 가격대 3: 406쌍, 교사의 관련 42.1%, 클릭 34.7%
# 가격대 4~5: 822쌍, 교사의 관련 43.3%, 클릭 26.3%
# 브랜드 일치: 189쌍, 교사의 관련 68.8%, 클릭 74.1%
# 브랜드 불일치: 1,811쌍, 교사의 관련 40.2%, 클릭 31.0%
```

블록의 1단계는 교사와 학생의 차이를 배수로도 셉니다. 건당 시간은 로컬 교사가 학생의 783배이고, 100만 건의 값은 작은 상용 모델이 학생의 460배, 큰 상용 모델이 4,795배입니다. 아래 표는 그 값을 교사와 학생으로 모은 것이고, 상용 모델의 시간은 기록이 없어 비워 두었습니다.

| 누가 라벨을 붙이나 | 건당 시간 | 100만 건의 시간 | 100만 건의 값 |
|---|---|---|---|
| 교사, 기록한 로컬 모델 | 평균 2.73초, 중앙값 2.04초 | 758.2시간, 한 대에서 차례로 | 토큰 0원, GPU 시간 따로 |
| 교사, 작은 상용 모델 | 기록 없음 | 기록 없음 | 213,800원, 가상 단가 |
| 교사, 큰 상용 모델 | 기록 없음 | 기록 없음 | 2,227,467원, 가상 단가 |
| 학생, CPU 서버 한 대 | 3.48ms | 0.97시간 | 465원 |

그래서 일을 이렇게 나눕니다. 교사는 학습 데이터 1만 건을 한 번 붙이고, 작은 상용 모델이면 1절의 2,138원입니다. 학생은 그 뒤 날마다 들어오는 쌍을 붙이고, 100만 건에 465원입니다. 로컬 교사의 시간은 서버를 늘리면 나눠지지만, 상용 모델의 값은 건수만큼 그대로 늘어납니다. 판정 한 번에 2초가 넘는 교사는 응답 전체에 12ms 를 두는 [서빙 지연, 처리량과 Grafana](post.html?id=serving-latency-throughput) 편의 서비스에 들어갈 수 없습니다.

학생의 값에도 다시 드는 몫이 있습니다. 교사의 모델이나 프롬프트를 바꾸면 1만 건을 다시 받고 학생도 다시 학습해야 해서, 그때마다 1절의 값이 다시 듭니다. 학생이 보는 정답이 교사의 라벨뿐이기 때문입니다. 이 몫을 넣어도, 날마다 쌓이는 판정은 학생에게 맡기는 편이 값과 시간 모두 작습니다.

## 5. 관련성 라벨과 성과 라벨은 다릅니다

**가짜 클릭과 교사의 라벨은 시험 2,000쌍 가운데 723쌍(36.1%)이 달랐습니다. 교사가 관련으로 본 비율은 가격대마다 42.1~43.3% 로 비슷했지만, 클릭은 싼 쪽 44.6% 에서 비싼 쪽 26.3% 로 줄었습니다. 학생과 클릭의 같은 답은 64.9% 로, 교사와 클릭의 63.8% 와 비슷합니다.**

관련성 라벨은 광고가 검색어에 맞는지를 적은 값이고, 성과 라벨은 사람들이 실제로 한 행동을 적은 값입니다. 이 절은 클릭을 성과 라벨로 둡니다. 클릭 라벨은 쌍마다 한 주 동안의 노출에서 클릭이 한 번이라도 있었으면 1 입니다. 4절 블록의 2단계가 이 가짜 클릭을 만들었습니다.

클릭 확률은 0.10 에서 시작합니다. 규칙의 점수가 3점 이상이면 0.25, 가격대가 한 단계 쌀 때마다 0.06, 브랜드가 맞으면 0.30 을 더합니다. 관련성 말고 가격과 브랜드에도 클릭이 기대게 만든 것입니다. 주장에 근거가 없는지는 광고만 보고 알 수 없다고 두어, 클릭 확률에는 넣지 않았습니다.

시험 쌍에서 클릭이 있었던 쌍은 701, 교사가 관련으로 본 쌍은 858 입니다. 둘이 다른 723쌍 가운데 440쌍은 관련인데 클릭이 없었고, 283쌍은 무관인데 클릭이 있었습니다. 교사와 클릭의 같은 답은 63.8% 이고, kappa 는 0.24 입니다. 아래 표는 4절 블록의 4단계가 가격대와 브랜드로 나눠 센 비율입니다.

| 시험 쌍 | 쌍 수 | 교사가 관련으로 본 비율 | 클릭이 있었던 비율 |
|---|---|---|---|
| 가격대 1~2 | 772 | 42.9% | 44.6% |
| 가격대 3 | 406 | 42.1% | 34.7% |
| 가격대 4~5 | 822 | 43.3% | 26.3% |
| 브랜드 일치 | 189 | 68.8% | 74.1% |
| 브랜드 불일치 | 1,811 | 40.2% | 31.0% |

위 세 줄에서 교사의 관련 비율은 가격대와 상관없이 비슷하고, 클릭은 쌀수록 많습니다. 가짜 교사의 규칙이 가격을 보지 않았기 때문입니다. 아래 두 줄의 브랜드는 규칙도 1점을 주어 관련 비율이 오르지만, 클릭은 그보다 더 크게 오릅니다. 다만 관련인데 클릭이 없는 쌍과 무관인데 클릭이 있는 쌍은 클릭 확률에 가격과 브랜드가 없어도 생깁니다. 클릭은 확률로 일어나서, 관련인 쌍에도 클릭이 없을 수 있고 무관인 쌍에도 기본 확률 0.10 으로 클릭이 생기기 때문입니다. 가격과 브랜드는 그런 쌍이 어느 가격대와 브랜드에 몰리는지를 정하고, 표가 그 자리를 보여 줍니다.

학생과 클릭의 같은 답은 64.9% 이고 kappa 는 0.27 이라, 교사와 클릭보다 조금 높습니다. 학생과 교사의 답은 161쌍에서만 달랐으니, 이 차이도 그 161쌍에서 나왔습니다. 학생은 클릭이 아니라 교사를 따라 배웠기 때문에, 클릭과 맞는 정도도 교사와 비슷한 데 머뭅니다.

그래서 두 라벨은 쓰는 자리가 다릅니다. 관련성 라벨로 배운 학생은 검색어에 맞지 않는 광고를 거르고, 클릭으로 배운 pCTR 모델은 노출 한 번에 기대하는 돈을 셉니다. 앞 글의 순위가 라벨 가중치에 pCTR 과 입찰가를 곱한 것도 두 값을 따로 받아 섞기 위해서입니다. 이 글의 가짜 클릭으로 관련성 학생을 배우면, 학생은 가격과 브랜드를 관련성처럼 배우게 됩니다.

## 6. 학생이 판정하는 쌍이 무대마다 다릅니다

**교사가 학습 데이터를 붙이고 학생이 서빙을 맡는 나눔은 두 무대가 같습니다. 담장 안은 검색어와 광고 쌍을, 열린 RTB 의 DSP 는 지면의 글과 광고 쌍을 학생에게 맡깁니다. 클릭 라벨을 볼 수 있는 범위도 다릅니다.**

1~5절의 셈은 두 무대가 같습니다. 두 무대의 이름은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에서 풀었습니다. 다른 것은 학생이 판정하는 쌍과 학생의 점수가 들어가는 자리, 그리고 클릭 라벨이 남는 범위입니다.

### 담장 안에서는 학생의 점수를 경매 점수에 곱합니다 [무대: 닫힌 생태계]

검색 광고를 파는 플랫폼은 검색어와 광고와 경매를 모두 갖습니다. 교사는 자주 들어오는 검색어와 광고 쌍 1만 건에 라벨을 붙이고, 학생은 날마다 새로 생기는 쌍을 판정합니다. 학생의 점수는 앞 글의 라벨 가중치 자리에 들어가 pCTR 과 입찰가에 곱해집니다. 근거 없는 주장은 학생이 볼 수 없으니, 광고가 처음 들어올 때 광고마다 한 번 따로 검사합니다.

플랫폼은 자기 경매의 클릭 로그도 갖습니다. 그래서 5절처럼 관련성 라벨과 클릭이 다른 자리를 가격대와 브랜드로 나눠 볼 수 있습니다. 교사의 모델이나 프롬프트를 바꾸면 학생도 다시 학습하므로, 학생 모델에는 어느 교사가 붙인 라벨로 배웠는지를 같이 적어 둡니다.

### 열린 RTB 에서는 지면과 광고 쌍을 학생이 판정합니다 [무대: 열린 RTB]

열린 RTB 의 DSP 에는 검색어가 없고, 입찰 요청이 가리키는 지면의 글이 있습니다. 교사는 미리 모아 둔 지면의 글과 자기 광고의 쌍에 라벨을 붙이고, 학생은 입찰 요청이 올 때 그 쌍을 판정합니다. 지면의 글을 LLM 으로 분류하는 일은 17주째 [컨텍스추얼 타겟팅](post.html?id=contextual-targeting) 편에서 보았습니다. 입찰은 정해진 시간 안에 답해야 해서, 판정 한 번에 2초가 넘는 교사는 그 자리에 들어가지 못합니다.

클릭 라벨은 DSP 가 이긴 경매의 노출에만 남습니다. 진 경매의 지면에서는 광고가 뜨지 않았으니 클릭도 없습니다. 관련성 라벨은 띄우지 않은 쌍에도 교사가 붙일 수 있어서, DSP 는 학생의 학습 데이터를 클릭보다 넓게 잡을 수 있습니다. 띄운 광고만 학습 데이터가 되는 문제는 [피드백 루프 편향](post.html?id=feedback-loop-bias) 편에서 보았습니다. 아래 표는 가상 데이터가 아니라 두 무대의 설계 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 학생이 판정하는 쌍 | 검색어와 광고 | 지면의 글과 광고 |
| 교사가 라벨을 붙이는 쌍 | 자주 들어오는 쌍 1만 건 | 미리 모은 지면과 광고의 쌍 |
| 학생의 점수가 들어가는 곳 | 플랫폼 경매의 점수 | DSP 의 광고 선택과 입찰가 |
| 클릭 라벨이 남는 범위 | 자기 경매의 노출 | 이긴 경매의 노출 |

## 헷갈리기 쉬운 점

- **교사의 라벨로만 잰 학생은 교사를 넘어설 수 없습니다.** 학생이 배우는 정답도, 잘 배웠는지 재는 잣대도 교사의 라벨입니다. 진짜 교사는 GPS 시계와 러닝 반바지를 무관으로 보았고, 그 라벨로 배운 학생에게는 무관이 정답입니다. 이 글의 학생은 뒤집힌 라벨 106개 가운데 102개에 규칙대로 답했지만, 일치율에서는 그 102개가 틀린 답입니다. 학생이 교사보다 나은지는 사람 라벨처럼 교사 밖의 정답으로만 잽니다. Hsieh 외(2023)가 작은 모델이 LLM 과 같거나 낫다고 한 것도 벤치마크의 과제 성능으로 잰 결과입니다.
- **교사 라벨의 흔들림도 학습 데이터에 들어갑니다.** 가짜 교사가 뒤집은 500건 가운데 394개가 학습 8,000쌍에 들어갔습니다. 학생은 어느 라벨이 뒤집혔는지 모르고, 다른 라벨과 똑같이 배웁니다. 이 글의 뒤집기는 피처와 상관없이 고른 것이라 학생이 따라 하지 못했습니다. 진짜 LLM 의 흔들림은 한쪽으로 기울 수 있습니다. 앞 글의 모델은 low 를 한 번도 고르지 않았고, 그런 기울기는 학생이 그대로 배웁니다.
- **증류한 모델은 교사가 바뀌면 다시 학습합니다.** 학생이 아는 것은 라벨을 붙이던 때의 교사뿐입니다. 앞 글에서 같은 모델에게 30개를 한 번에 맡기자 판매 1위를 내세운 a13 을 high 로 올렸습니다. 하나씩 물었을 때는 exclude 였습니다. 그 목록의 라벨로 학생을 배우면, 학생에게는 a13 이 관련이 정답입니다. Thomas 외(2023)도 프롬프트를 바꿔 쓰기만 해도 정확도가 달라졌다고 적었습니다. 그래서 교사의 모델, 프롬프트, 날짜를 학생 모델과 함께 적어 두고, 교사가 바뀌면 1만 건을 다시 받아 학생을 다시 학습합니다.

## 더 깊이 보기

:::deep 로지스틱 회귀의 갱신 식
학생의 점수는 아래 식입니다. $x_j$ 는 표준화한 피처 $j$ 이고, $w_j$ 는 그 가중치, $b$ 는 절편입니다.

$$p(x) = \sigma\Big(b + \sum_{j=1}^{6} w_j\, x_j\Big), \qquad \sigma(z) = \frac{1}{1 + e^{-z}}$$

표준화는 학습 쌍의 평균 $\mu_j$ 를 빼고 표준편차 $s_j$ 로 나누는 일입니다. 시험 쌍과 서빙 쌍에도 학습 쌍에서 구한 $\mu_j$ 와 $s_j$ 를 그대로 씁니다.

$$x_j = \frac{x_j^{\mathrm{raw}} - \mu_j}{s_j}$$

손실은 학습 $n$ 쌍의 로그 손실이고, $y_i$ 는 교사의 라벨(1 또는 0)입니다.

$$L = -\frac{1}{n}\sum_{i=1}^{n} \Big[\, y_i \log p(x_i) + (1 - y_i)\log\big(1 - p(x_i)\big) \Big]$$

가중치 하나의 기울기는 점수와 라벨의 차이에 그 피처를 곱해 평균한 값입니다. 한 번에 학습률 $\eta$ 만큼 기울기의 반대쪽으로 옮깁니다.

$$\frac{\partial L}{\partial w_j} = \frac{1}{n}\sum_{i=1}^{n} \big(p(x_i) - y_i\big)\, x_{ij}, \qquad w_j \leftarrow w_j - \eta\, \frac{\partial L}{\partial w_j}$$

코드의 `p - y` 가 $p(x_i) - y_i$ 이고, $\eta$ 는 1 입니다. 블록에서 로그 손실은 50번째에 이미 0.303 이었고 200번째에도 같아, 200번은 이 데이터에 넉넉한 수입니다. 가중치는 표준화한 단위라, 원래 단위로 되돌린 가중치는 $w_j / s_j$ 입니다. 같은 식을 관심사 여덟에 따로 돌린 one-vs-rest 꼴은 [관심사 분류](post.html?id=interest-classification) 편의 더 깊이 보기에 있습니다.
:::

:::deep 소프트 라벨
이 글의 교사는 1 또는 0 을 줍니다. 이런 라벨을 하드 라벨이라고 부르고, 교사가 관련일 확률을 주는 라벨을 소프트 라벨이라고 부릅니다. Hinton 외(2015)는 큰 모델이 낸 클래스 확률을 소프트 타깃으로 두었습니다. 확률이 고르게 퍼진 소프트 타깃은 학습 한 건마다 하드 라벨보다 많은 정보를 준다고 적었습니다. softmax 의 온도를 높여 확률을 부드럽게 만들고, 학생도 같은 온도로 학습합니다. 위 로그 손실은 $y_i$ 가 0 과 1 사이의 확률이어도 그대로 쓸 수 있습니다. 다만 이 글의 기록은 라벨 글자만 남겨 소프트 라벨을 만들 수 없습니다. 같은 쌍을 temperature 0.7 로 여러 번 물어 관련으로 답한 비율을 쓰는 방법이 하나 있습니다.
:::

:::deep 실무의 학습 코드: LightGBM 발췌
실무에서는 같은 자리에 LightGBM 같은 나무 모델을 쓰기도 합니다. 아래는 같은 피처 여섯과 교사의 라벨로 LightGBM 을 학습하는 발췌이고, 이 글의 검사에서는 돌리지 않습니다. 함수와 파라미터 이름은 LightGBM 문서의 [Python 소개](https://lightgbm.readthedocs.io/en/latest/Python-Intro.html)와 [파라미터](https://lightgbm.readthedocs.io/en/latest/Parameters.html) 페이지에서 확인했습니다.

```python
# (발췌 — 그대로 실행되지 않습니다.)
# 하는 일: 피처 여섯과 교사의 라벨로 LightGBM 이진 분류 모델을 학습하고 시험 쌍에 점수를 매긴다.
import lightgbm as lgb

# 1단계: 학습과 검증 데이터를 만든다
# X_train, X_valid, X_test 는 피처 여섯의 표이고, y_train, y_valid 는 교사의 라벨(1 또는 0)이다. 검증 쌍은 학습 쌍에서 떼어 둔다.
train_data = lgb.Dataset(X_train, label=y_train)
valid_data = lgb.Dataset(X_valid, label=y_valid, reference=train_data)

# 2단계: 파라미터를 정하고 학습한다
# objective 가 binary 면 라벨은 0 과 1 이어야 한다. 검증 점수가 5번 안에 나아지지 않으면 학습을 멈춘다.
param = {'objective': 'binary', 'metric': 'binary_logloss', 'num_leaves': 31, 'learning_rate': 0.1}
bst = lgb.train(param, train_data, 200, valid_sets=[valid_data],
                callbacks=[lgb.early_stopping(stopping_rounds=5)])

# 3단계: 시험 쌍에 점수를 매기고 모델을 저장한다
# 서빙은 저장한 파일을 읽어 같은 피처 여섯으로 점수를 매긴다.
scores = bst.predict(X_test)
bst.save_model('student.txt')
```

문서는 objective binary 를 로지스틱 회귀와 같은 이진 로그 손실의 분류로 적었고, 라벨은 0 과 1 이어야 한다고 적었습니다. 소프트 라벨처럼 0 과 1 사이의 라벨은 objective cross_entropy 로 받습니다. num_leaves 31 과 learning_rate 0.1 은 문서의 기본값입니다. 나무 모델은 피처의 조합마다 가지를 나눌 수 있어서, 3절의 드문 조합을 다른 조합과 따로 다룰 수 있습니다. 다만 학습 쌍에 27쌍뿐인 조합은 나무 모델에게도 적은 데이터라, 그 쌍에 가중치를 더 주는 방법을 함께 봅니다.

실무로 옮길 때 이 글의 숫자로 말할 수 없는 것도 셋입니다. 가짜 교사는 규칙이라, 진짜 LLM 의 라벨로 배우면 학생과 교사의 일치율은 달라집니다. 가짜 클릭의 확률은 이 글이 정한 값이라, 36.1% 라는 차이도 그 값에 기댑니다. 진짜 교사의 시간은 이 맥에서 받은 30건이라, 다른 기계나 상용 모델의 시간은 알 수 없습니다.

## 참고문헌

- Hinton, G., Vinyals, O., Dean, J. (2015). *Distilling the Knowledge in a Neural Network*. NIPS 2014 Deep Learning Workshop. arXiv:1503.02531. [arxiv.org](https://arxiv.org/abs/1503.02531). 큰 모델이 낸 클래스 확률을 소프트 타깃으로 두고 작은 모델을 학습하는 방법을 증류라고 불렀습니다. softmax 의 온도를 높여 확률을 부드럽게 만들고, 작은 모델도 같은 온도로 학습합니다. 정답 라벨이 있으면 소프트 타깃과 정답 라벨의 두 손실을 가중 평균하는 편이 낫다고 적었습니다.
- Hsieh, C.-Y., Li, C.-L., Yeh, C.-K., et al. (2023). *Distilling Step-by-Step! Outperforming Larger Language Models with Less Training Data and Smaller Model Sizes*. Findings of ACL 2023. arXiv:2305.02301. [arxiv.org](https://arxiv.org/abs/2305.02301). LLM 이 라벨과 함께 쓴 풀이(rationale)를 작은 모델이 같이 배우게 하는 방법입니다. 벤치마크 4개에서 보통의 파인튜닝과 증류보다 적은 학습 데이터로 더 나은 성능을 냈다고 보고했습니다. 벤치마크 하나에서는 770M 의 T5 가 예시 몇 개로 답하는 540B PaLM 보다 나았다고 적었습니다. 라벨 없는 데이터만 있을 때도 작은 모델이 LLM 과 같거나 더 나았다고 적었습니다.
- Thomas, P., Spielman, S., Craswell, N., Mitra, B. (2023). *Large language models can accurately predict searcher preferences*. arXiv:2309.10621. [arxiv.org](https://arxiv.org/abs/2309.10621). Bing 에서 LLM 으로 관련성 라벨을 붙인 일을 적고, TREC 데이터로 보였습니다. 실제 검색자의 판단을 정답으로 두면 LLM 의 라벨이 외부 작업자보다 나았고 비용은 훨씬 적었다고 보고했습니다. 이 라벨로 학습한 랭커가 눈에 띄게 나아졌고, 프롬프트를 바꿔 쓰기만 해도 정확도가 달라졌다고 적었습니다.
