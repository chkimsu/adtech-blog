모델 팀 44주째 월요일, 지훈 씨는 23주째에 짠 짧은 코드를 다시 열었습니다. 상품 이름을 숫자 384개로 바꾸는 코드인데, 스니커즈와 운동화의 숫자는 여전히 멀었습니다. 두 낱말이 같은 글자를 하나도 나누지 않기 때문입니다.

선배는 검색 기록을 보여 주었습니다. 스니커즈를 찾은 사람이 운동화를 누르고, 운동화를 찾은 사람이 스니커즈를 누른 기록이 쌓여 있었습니다. 선배는 같이 눌린 낱말끼리 짝을 지어 모으면, 그 짝으로 숫자를 고칠 수 있다고 했습니다.

**같이 클릭된 낱말 쌍으로 숫자를 고치면, 한 번도 짝지은 적 없는 낱말끼리도 가까워질까요?**

지훈 씨는 짝의 일부를 떼어 두고, 나머지로만 숫자를 고쳐 보기로 했습니다. 떼어 둔 짝을 다시 찾으면, 고친 숫자가 처음 보는 짝에도 통한다는 뜻입니다. 검색 결과에 운동화가 나오지 않으면, 스니커즈를 찾은 사람은 운동화 광고를 보지 못합니다.

> **한 줄 요약:** 23주째의 장난감 임베딩은 글자 조각이 같은 칸에 떨어져야 두 낱말을 가깝다고 봅니다. 같은 묶음의 낱말 짝 100개 가운데 90개는 겹친 칸이 0 이고, 스니커즈와 운동화의 코사인은 0.000 입니다. 같은 묶음의 두 낱말을 양성 쌍으로 둔 가상 로그 200개를 학습 160개와 검증 40개로 나눴습니다. 384칸 위에 8차원 선형 사상 하나를 두고, 질의와 짝에 같은 사상을 씁니다. 배치 안의 다른 쌍을 음성으로 쓰는 in-batch negatives 와 온도 0.05 로 40에포크 학습했습니다. 검증 쌍의 짝이 낱말 49개 가운데 위 5개에 든 비율(recall@5)은 0.100 에서 0.675 로 올랐습니다. 스니커즈와 운동화의 코사인은 -0.397 에서 0.685 가 되었습니다. 온도를 0.2 와 1.0 으로 올리자 검증 쌍을 모두 찾았습니다. 온도 1.0 은 묶음 안의 낱말을 한 방향으로 모아, 묶음 안 코사인의 평균이 1.000 이 되었습니다.

> **골라 읽는 법** — 절이 7개입니다. 절마다 표나 코드나 카드가 있어 그것만 보고 넘어가도 됩니다.
>
> - 23주째 임베딩에서 같은 묶음의 낱말이 먼 모습 → 1절
> - 양성 쌍 200개와 검증 쌍 40개 → 2절
> - 배치 안의 다른 쌍을 음성으로 쓰는 손실과 학습 → 3절
> - 학습 전과 뒤의 recall@k → 4절
> - 온도 셋과 묶음 안의 코사인 → 5절
> - Sentence-BERT, InfoNCE, DPR, SimCSE 와 이 글의 장난감 → 6절
> - 담장 안과 열린 RTB 에서 양성 쌍을 얻는 곳 → 7절

이 글의 낱말 50개와 묶음 10개, 양성 쌍 200개는 설명을 위해 만든 가상 데이터입니다. 양성 쌍은 같은 묶음의 두 낱말이 서로의 검색에서 클릭되었다고 둔 가상 로그이고, 실제 검색 기록에서 뽑지 않았습니다. 블록이 `random.Random(7)` 로 검증 쌍을 뽑고 W 를 채워, 블록 셋을 차례로 돌리면 늘 같은 값이 나옵니다. 이 글은 모델을 부르지 않고, 숫자는 모두 블록 셋이 찍은 것입니다. 카드 속 파랑은 낱말과 양성 쌍, 벽돌색은 배치의 점수표, 먹색은 8차원 사상 W 입니다. 회색은 학습에 쓰지 않는 검증 쌍, 점선은 온도와 손실 식입니다.

## 1. 23주째의 장난감 임베딩은 뜻이 가까운 낱말을 모릅니다

**23주째 편의 `embed` 는 글자 두 개씩 자른 조각이 같은 칸에 떨어져야 두 낱말을 가깝다고 봅니다. 같은 묶음의 짝 100개 가운데 90개는 겹친 칸이 0 이고, 스니커즈와 운동화의 코사인은 0.000 입니다. 다른 묶음인데 칸을 함께 쓰는 짝은 17개였고, 그 가운데 13개는 해시 충돌이었습니다.**

23주째 [임베딩과 벡터 검색](post.html?id=embeddings-vector-search) 편은 상품 이름을 숫자 384개로 바꾸는 장난감 임베딩을 짰습니다. 이름을 글자 두 개씩 겹쳐 자르고, 조각마다 해시로 384칸 가운데 한 칸을 정해 1 을 더한 뒤 길이를 1 로 맞춥니다. 임베딩과 코사인, 해시 충돌은 그 편에서 풀었습니다. 블록 1 은 그 편의 `DIM` 과 `embed`, 조각이 떨어진 칸을 보는 `slots` 를 글자 그대로 옮깁니다.

그 편의 장난감은 학습한 모델이 아니라서, 가까움이 글자 조각이 떨어진 칸으로만 정해집니다. 그 편의 블록도 스니커즈와 운동화의 칸이 하나도 겹치지 않는다고 찍었습니다. 이 글은 낱말 50개를 묶음 10개에 다섯씩 두고, 같은 묶음의 낱말을 뜻이 가까운 낱말로 봅니다. 앞 여덟 묶음의 첫 셋은 그 편 `CATEGORIES` 의 낱말이고, 나머지는 이 글이 더했습니다.

블록 1 은 같은 묶음의 짝 100개와 다른 묶음의 짝 1,125개에서 두 낱말의 0 아닌 칸이 겹치는지 셉니다. 장난감 벡터에는 음수가 없어서, 겹친 칸이 0 이면 코사인도 0 입니다. 다른 묶음인데 칸이 겹친 짝은 같은 조각을 나눴는지, 다른 조각이 같은 칸에 떨어졌는지도 봅니다. 마지막 단계는 2절에서 쓸 양성 쌍을 학습과 검증으로 나눕니다.

```python
# 하는 일: 23주째의 장난감 임베딩으로 낱말 50개를 벡터로 바꿔 같은 묶음의 두 낱말이 칸을 함께 쓰는지 세고, 양성 쌍 200개를 학습 160개와 검증 40개로 나눈다.
import math
import random
import zlib

# 1단계: 23주째 편의 장난감 임베딩을 글자 그대로 옮긴다
# 띄어쓰기를 지운 글자를 두 개씩 겹쳐 자르고, 조각마다 zlib.crc32 로 0~383 칸 하나를 정해 1 을 더한 뒤 길이를 1 로 맞춘다.
# slots 는 그 편 3절의 함수로, 조각마다 떨어진 칸을 돌려준다. 이 글의 학습은 이 384칸을 고치지 않는다.
DIM = 384


def embed(text):
    chars = text.replace(' ', '').lower()
    vec = [0.0] * DIM
    for i in range(len(chars) - 1):
        vec[zlib.crc32(chars[i:i + 2].encode('utf-8')) % DIM] += 1.0
    norm = math.sqrt(sum(x * x for x in vec))
    return [x / norm for x in vec] if norm else vec


def slots(text):
    chars = text.replace(' ', '').lower()
    return [(chars[i:i + 2], zlib.crc32(chars[i:i + 2].encode('utf-8')) % DIM) for i in range(len(chars) - 1)]


def dot(a, b):
    # 같은 칸끼리 곱해 더한다. 이 글의 벡터는 모두 길이가 1 이라 내적이 곧 코사인이다.
    return sum(x * y for x, y in zip(a, b))


# 2단계: 낱말 50개를 묶음 10개에 두고, 두 낱말의 0 아닌 칸이 겹치는지 센다
# 묶음마다 낱말 다섯이다. 앞 여덟 묶음의 첫 셋은 23주째 편 CATEGORIES 의 낱말이고, 나머지는 이 글이 더했다.
# 장난감 벡터에는 음수가 없어서, 겹친 칸이 0 인 두 낱말은 코사인도 0 이다.
# 겹친 칸이 있는 다른 묶음 짝은 그 칸에 같은 조각이 떨어졌는지, 다른 조각이 떨어졌는지(해시 충돌)로 나눠 센다.
GROUPS = {
    '캠핑': ['캠핑의자', '캠핑테이블', '텐트', '타프', '랜턴'],
    '음향': ['헤드폰', '무선이어폰', '블루투스스피커', '헤드셋', '이어버드'],
    '신발': ['운동화', '스니커즈', '러닝화', '조깅화', '마라톤화'],
    '잡화': ['선글라스', '손목시계', '모자', '버킷햇', '스마트워치'],
    '가방': ['백팩', '크로스백', '여행가방', '캐리어', '배낭'],
    '주방': ['프라이팬', '전기포트', '텀블러', '냄비', '전기그릴'],
    '뷰티': ['선크림', '립밤', '핸드크림', '자외선차단제', '보습크림'],
    '육아': ['유모차', '아기띠', '젖병', '기저귀', '아기의자'],
    '운동복': ['운동복', '레깅스', '트레이닝복', '러닝셔츠', '요가복'],
    '전자': ['노트북', '태블릿', '무선마우스', '키보드', '모니터'],
}
WORDS = [w for words in GROUPS.values() for w in words]
GROUP_OF = {w: g for g, words in GROUPS.items() for w in words}
VEC = {w: embed(w) for w in WORDS}
NONZERO = {w: {j for j, x in enumerate(VEC[w]) if x} for w in WORDS}


def shared(a, b):
    return sorted(NONZERO[a] & NONZERO[b])


def pieces(word, slot):
    return [p for p, s in slots(word) if s == slot]


INNER = [(a, b) for words in GROUPS.values() for i, a in enumerate(words) for b in words[i + 1:]]
CROSS = [(a, b) for i, a in enumerate(WORDS) for b in WORDS[i + 1:] if GROUP_OF[a] != GROUP_OF[b]]
touch = [(a, b) for a, b in CROSS if shared(a, b)]
collide = [(a, b) for a, b in touch if not any(set(pieces(a, s)) & set(pieces(b, s)) for s in shared(a, b))]
print(f'낱말 {len(WORDS)}개, 묶음 {len(GROUPS)}개, 낱말마다 0 아닌 칸 '
      f'{min(len(NONZERO[w]) for w in WORDS)}~{max(len(NONZERO[w]) for w in WORDS)}개')
print(f'같은 묶음의 짝 {len(INNER)}개 가운데 겹친 칸이 0 인 짝 {sum(not shared(a, b) for a, b in INNER)}개')
print(f'다른 묶음의 짝 {len(CROSS):,}개 가운데 겹친 칸이 있는 짝 {len(touch)}개: '
      f'같은 조각 {len(touch) - len(collide)}개, 다른 조각(해시 충돌) {len(collide)}개')
for a, b in touch[:3]:
    print(f'  {a} / {b}: ' + ', '.join(f'칸 [{s}] 에 {"+".join(pieces(a, s))} / {"+".join(pieces(b, s))}' for s in shared(a, b)))
print(f'스니커즈와 운동화: 겹친 칸 {len(shared("스니커즈", "운동화"))}개, 코사인 {dot(VEC["스니커즈"], VEC["운동화"]):.3f}')

# 3단계: 양성 쌍 200개를 학습 160개와 검증 40개로 나눈다
# 양성 쌍은 같은 묶음의 두 낱말을 서로의 검색에서 클릭된 상품으로 둔 가상 로그이고, 묶음 안 순서쌍 전부(10 × 5 × 4)다.
# 묶음마다(차례대로) 짝(i < j) 10개에서 rng.sample 로 둘을 뽑고, 그 두 짝의 양쪽 방향 넷을 검증으로 뗀다.
rng = random.Random(7)
TRAIN, VALID = [], []
for g, words in GROUPS.items():
    combos = [(words[i], words[j]) for i in range(5) for j in range(i + 1, 5)]
    held = rng.sample(combos, 2)
    held += [(b, a) for a, b in held]
    for a in words:
        for b in words:
            if a != b:
                (VALID if (a, b) in held else TRAIN).append((a, b))
    print(f'  {g}: 검증 짝 ' + ', '.join(f'{a}-{b}' for a, b in held[:2]))
print(f'양성 쌍 {len(TRAIN) + len(VALID)}개: 학습 {len(TRAIN)}개, 검증 {len(VALID)}개. '
      f'묶음마다 짝 {len(combos)}개 가운데 둘을 양쪽 방향으로 떼어 학습 {len(TRAIN) // len(GROUPS)}, 검증 {len(VALID) // len(GROUPS)}')
blind = [(a, b) for a, b in VALID if not shared(a, b)]
print(f'검증 {len(VALID)}쌍 가운데 겹친 칸이 0 인 쌍 {len(blind)}개, 그 쌍들의 embed 코사인은 가장 커도 '
      f'{max(dot(VEC[a], VEC[b]) for a, b in blind):.3f}')
# 출력:
# 2단계 뜻: 같은 묶음의 짝 100개 가운데 90개는 칸을 하나도 나누지 않는다. 다른 묶음인데 칸이 겹친 17개 가운데 13개는 해시 충돌이다.
# 낱말 50개, 묶음 10개, 낱말마다 0 아닌 칸 1~6개
# 같은 묶음의 짝 100개 가운데 겹친 칸이 0 인 짝 90개
# 다른 묶음의 짝 1,125개 가운데 겹친 칸이 있는 짝 17개: 같은 조각 4개, 다른 조각(해시 충돌) 13개
#   캠핑의자 / 아기의자: 칸 [292] 에 의자 / 의자
#   랜턴 / 캐리어: 칸 [294] 에 랜턴 / 캐리
#   무선이어폰 / 무선마우스: 칸 [347] 에 무선 / 무선
# 스니커즈와 운동화: 겹친 칸 0개, 코사인 0.000
# 3단계 뜻: 묶음마다 짝 둘을 양쪽 방향으로 떼어 검증 40쌍을 둔다. 그 가운데 34쌍은 embed 의 코사인이 0 이다.
#   캠핑: 검증 짝 캠핑테이블-타프, 캠핑의자-타프
#   음향: 검증 짝 무선이어폰-이어버드, 헤드폰-무선이어폰
#   신발: 검증 짝 운동화-러닝화, 러닝화-마라톤화
#   잡화: 검증 짝 선글라스-모자, 손목시계-버킷햇
#   가방: 검증 짝 캐리어-배낭, 백팩-크로스백
#   주방: 검증 짝 텀블러-전기그릴, 프라이팬-전기그릴
#   뷰티: 검증 짝 선크림-립밤, 선크림-핸드크림
#   육아: 검증 짝 아기띠-아기의자, 기저귀-아기의자
#   운동복: 검증 짝 운동복-트레이닝복, 운동복-요가복
#   전자: 검증 짝 노트북-무선마우스, 무선마우스-모니터
# 양성 쌍 200개: 학습 160개, 검증 40개. 묶음마다 짝 10개 가운데 둘을 양쪽 방향으로 떼어 학습 16, 검증 4
# 검증 40쌍 가운데 겹친 칸이 0 인 쌍 34개, 그 쌍들의 embed 코사인은 가장 커도 0.000
```

같은 묶음의 짝 100개 가운데 90개는 겹친 칸이 0 이었습니다. 이 짝들은 코사인이 0 이라, 칸을 하나도 나누지 않는 다른 묶음의 낱말과 점수가 같습니다. 낱말마다 0 아닌 칸은 1개에서 6개뿐입니다.

다른 묶음의 짝 가운데 칸을 함께 쓰는 짝은 17개였습니다. 캠핑의자와 아기의자는 「의자」를, 무선이어폰과 무선마우스는 「무선」을 나눠 가졌습니다. 17개 가운데 13개는 랜턴과 캐리어처럼 다른 조각이 같은 칸에 떨어진 해시 충돌이었습니다. 검증으로 뗀 40쌍 가운데 34쌍은 겹친 칸이 0 이어서, 글자 조각만 보는 임베딩에는 이 쌍을 찾을 단서가 없습니다.

## 2. 양성 쌍 200개와 검증 쌍 40개를 나눕니다

**같은 묶음의 두 낱말을 「서로의 검색에서 클릭된 상품」으로 둔 가상 로그가 양성 쌍입니다. 묶음 안의 순서쌍을 모두 써서 200개이고, 묶음마다 짝 둘을 양쪽 방향으로 떼어 학습 160개와 검증 40개로 나눴습니다.**

양성 쌍은 가까워져야 할 두 항목의 짝이고, [Two-Tower 학습](post.html?id=two-tower-training) 편 2절에서 풀었습니다. 그 편에서는 회원과 그 회원이 클릭한 광고가 한 쌍이었습니다. 이 글에서는 스니커즈를 검색한 사람이 운동화를 클릭하면 (스니커즈, 운동화) 한 쌍이 됩니다. 앞이 질의이고 뒤가 짝이라, (운동화, 스니커즈) 는 다른 쌍으로 셉니다.

검증 쌍은 학습에 쓰지 않고 떼어 두는 쌍입니다. 블록 1 은 묶음마다 짝 10개에서 `rng.sample` 로 둘을 뽑아, 그 두 짝을 양쪽 방향으로 뗍니다. 한쪽 방향만 떼면 반대 방향이 학습에 남아, 검증 쌍의 두 낱말이 학습 쌍으로도 들어가기 때문입니다. 그래서 묶음마다 학습 16쌍, 검증 4쌍이 됩니다.

아래 표는 묶음마다 낱말 다섯과 검증으로 뗀 짝을 놓은 것입니다. 표의 짝은 블록 1 의 3단계가 찍은 차례 그대로이고, 나머지 짝은 양쪽 방향 모두 학습 쌍입니다. 검증 짝 40쌍 가운데 34쌍은 1절에서 본 것처럼 겹친 칸이 0 입니다.

| 잡화 | 선글라스, 손목시계, 모자, 버킷햇, 스마트워치 | 선글라스-모자, 손목시계-버킷햇 | 16 | 4 |

검증 짝의 두 낱말도 다른 낱말을 거치면 학습 쌍으로 이어집니다. 신발 묶음의 운동화와 러닝화는 검증 짝이지만, 운동화와 스니커즈, 스니커즈와 러닝화는 학습 쌍입니다. 학습이 묶음 안의 낱말을 함께 당긴다면, 짝지은 적 없는 운동화와 러닝화도 가까워질 수 있습니다. 4절은 이것을 검증 쌍의 recall@k 로 잽니다.

## 3. 배치 안의 다른 쌍이 음성이 됩니다

**배치는 묶음마다 학습 쌍 하나씩 10쌍입니다. 10 × 10 점수표의 대각선 10칸이 정답, 나머지 90칸이 음성이고, 손실은 Two-Tower 학습 편과 같은 식입니다. 학습 쌍의 평균 정답 칸 확률은 에포크 0 의 0.208 에서 에포크 39 의 0.991 이 되었습니다.**

이미 있는 모델을 새 데이터로 더 학습하는 것을 파인튜닝이라고 부릅니다. 이 글의 장난감은 23주째의 384칸을 그대로 두고, 그 위에 붙인 8차원 선형 사상 W 만 학습합니다. W 는 384줄 × 8칸이고, 낱말 벡터는 `embed` 의 0 아닌 칸 값을 W 의 그 줄에 곱해 더한 숫자 8개입니다. 이 8개를 길이 1 로 맞추면 두 낱말의 내적이 곧 코사인입니다. 학습은 배치에 든 낱말의 0 아닌 칸에 해당하는 W 의 줄만 고칩니다.

질의와 짝에는 같은 W 를 씁니다. Sentence-BERT 는 두 문장을 가중치를 함께 쓰는 BERT 둘에 넣었고, 이 꼴을 siamese 구조라고 불렀습니다. Two-Tower 학습 편의 두 타워는 회원과 광고를 서로 다른 신경망으로 바꿨습니다. 이 글은 질의도 짝도 같은 낱말 50개에서 나와서, 사상 하나로 둡니다.

점수표의 칸 [i][k] 는 i번째 쌍의 질의와 k번째 쌍의 짝의 코사인입니다. 줄마다 코사인을 온도 τ 로 나눠 소프트맥스를 걸고, 대각선 확률에 -log 를 씌워 평균한 것이 손실입니다. 배치 안의 남의 짝을 음성으로 쓰는 in-batch negatives 와 온도, 소프트맥스는 [Two-Tower 학습](post.html?id=two-tower-training) 편 3~4절에서 풀었습니다. 블록 2 는 그 편 3절의 `softmax` 와 `batch_loss` 를 글자 그대로 옮기고, 학습 뒤 손실을 그 함수로 한 번 잽니다. 학습은 τ 0.05, 학습률 0.02 로 40에포크이고, 에포크는 학습 쌍 160개를 배치 16개로 나눠 한 번씩 다 도는 단위입니다. 기울기가 길이 맞춤을 거치는 식은 더 깊이 보기에 있습니다.

Two-Tower 학습 편은 인기 광고 보정(logQ)과 accidental hit 제거를 꼭 넣었습니다. 이 글의 배치는 묶음마다 한 쌍이라, 같은 묶음의 낱말이 음성 칸에 앉지 않습니다. 정답을 음성으로 세는 칸이 생기지 않으니 accidental hit 제거는 필요 없습니다. 묶음도 배치마다 한 번씩 들어 묶음 사이에 자주 오는 쪽이 없어서, logQ 를 넣지 않습니다. 다만 낱말은 에포크마다 짝 자리에 2번에서 4번 오는 차이가 있고, 이 글은 그 차이를 보정하지 않았습니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 384칸 위에 8차원 선형 사상 W 하나를 두고, 학습 쌍 160개로 in-batch negatives 와 온도 0.05 의 손실을 40에포크 줄인다.

# 1단계: Two-Tower 학습 편 3절의 softmax 와 batch_loss 를 글자 그대로 옮긴다
# batch_loss 의 docstring 에 적힌 「네 줄」은 그 편의 배치가 네 줄이어서다. 함수는 줄 수로 나눠 평균하므로 10줄에도 맞다.
def softmax(xs):
    m = max(xs)                        # 큰 값을 빼고 지수를 취해야 넘치지 않는다
    e = [math.exp(x - m) for x in xs]
    s = sum(e)
    return [v / s for v in e]


def batch_loss(table, tau):
    """줄마다 점수를 tau 로 나눠 소프트맥스 → 정답 칸 확률에 -log → 네 줄 평균."""
    losses = []
    for i, row in enumerate(table):
        p = softmax([c / tau for c in row])
        losses.append(-math.log(p[i]))
    return sum(losses) / len(losses)


# 2단계: 낱말 벡터와 학습 한 걸음을 둔다
# 낱말 벡터는 embed 의 0 아닌 칸 값을 W 의 그 줄에 곱해 더한 숫자 8개를 길이 1 로 맞춘 것이다. 질의와 짝에 같은 W 를 쓴다.
# 점수표 칸 [i][k] 는 i번째 쌍의 질의와 k번째 쌍의 짝의 코사인이다. 줄마다 코사인 ÷ τ 에 소프트맥스를 걸고,
# 대각선 확률에 -log 를 씌워 평균한 것이 손실이다(학습 식). 점수 칸의 기울기 (확률 - 정답) / (10 × τ) 를
# 낱말 벡터로 보내고, 길이 맞춤을 거쳐 W 의 줄로 보낸다. 배치에 든 낱말의 0 아닌 칸에 해당하는 줄만 lr 로 고친다.
# lr 이 0 이면 고치지 않고 손실만 잰다.
ENTRIES = {w: [(j, x) for j, x in enumerate(VEC[w]) if x] for w in WORDS}


def project(W, word):
    u = [0.0] * 8
    for j, x in ENTRIES[word]:
        row = W[j]
        for d in range(8):
            u[d] += x * row[d]
    n = math.sqrt(sum(t * t for t in u))
    return [t / n for t in u], n


def step(W, batch, tau, lr):
    vec = {}
    for pair in batch:
        for w in pair:
            if w not in vec:
                vec[w] = project(W, w)
    B = len(batch)
    table = [[dot(vec[a][0], vec[b][0]) for _, b in batch] for a, _ in batch]
    loss, right = 0.0, 0.0
    grad = {w: [0.0] * 8 for w in vec}
    for i, row in enumerate(table):
        p = softmax([c / tau for c in row])
        loss += -math.log(p[i]) / B
        right += p[i] / B
        for k in range(B):
            g = (p[k] - (1.0 if k == i else 0.0)) / (B * tau)
            a, b = batch[i][0], batch[k][1]
            va, vb = vec[a][0], vec[b][0]
            ga, gb = grad[a], grad[b]
            for d in range(8):
                ga[d] += g * vb[d]
                gb[d] += g * va[d]
    if lr:
        rows = {}
        for w, gw in grad.items():
            v, n = vec[w]
            gv = dot(gw, v)
            gu = [(gw[d] - gv * v[d]) / n for d in range(8)]
            for j, x in ENTRIES[w]:
                r = rows.setdefault(j, [0.0] * 8)
                for d in range(8):
                    r[d] += x * gu[d]
        for j, r in rows.items():
            row = W[j]
            for d in range(8):
                row[d] -= lr * r[d]
    return loss, right, table


# 3단계: recall@k 를 둔다
# 쌍 (a, b) 마다 a 와 다른 낱말 49개를 a 와의 코사인이 큰 차례로 정렬하고(같으면 WORDS 의 차례), b 가 위 k 개에 든 비율이다.
def recall(W, pairs, k):
    vec = {w: project(W, w)[0] for w in WORDS}
    hit = 0
    for a, b in pairs:
        ranked = sorted((w for w in WORDS if w != a), key=lambda w: -dot(vec[a], vec[w]))
        hit += b in ranked[:k]
    return hit / len(pairs)


# 4단계: 학습 함수를 둔다
# 안에서 random.Random(seed) 를 만들어 W 384줄 × 8칸을 gauss(0, 0.3) 로 줄 차례대로 채운다.
# 에포크마다 묶음 차례대로 묶음의 학습 쌍 16개를 섞는다(앞 에포크의 차례를 이어서 섞는다).
# 배치 b 는 묶음마다 b번째 쌍 하나씩 10쌍이다. 배치마다 묶음이 몇 가지인지, 음성 칸에 같은 묶음 낱말이 앉았는지 센다.
# watch 에 든 에포크는 끝난 W 로 검증 recall@5, @10 과 학습 recall@5 를 잰다.
PER_GROUP = len(TRAIN) // len(GROUPS)


def train(tau, lr, epochs=40, seed=7, watch=()):
    rng = random.Random(seed)
    W = [[rng.gauss(0, 0.3) for _ in range(8)] for _ in range(DIM)]
    start = [row[:] for row in W]
    order = {g: [p for p in TRAIN if GROUP_OF[p[0]] == g] for g in GROUPS}
    run = {'start': start, 'log': [], 'batches': 0, 'once': 0, 'negative_cells': 0, 'same_group': 0}
    for epoch in range(epochs):
        for g in GROUPS:
            rng.shuffle(order[g])
        total, right = 0.0, 0.0
        for b in range(PER_GROUP):
            batch = [order[g][b] for g in GROUPS]
            if epoch == 0 and b == 0:
                run['first'] = batch
            run['batches'] += 1
            run['once'] += len({GROUP_OF[a] for a, _ in batch}) == len(GROUPS)
            for i, (a, _) in enumerate(batch):
                for k, (_, c) in enumerate(batch):
                    if i != k:
                        run['negative_cells'] += 1
                        run['same_group'] += GROUP_OF[a] == GROUP_OF[c]
            loss, p, _ = step(W, batch, tau, lr)
            total += loss / PER_GROUP
            right += p / PER_GROUP
        run['last'] = (total, right)
        if epoch in watch:
            run['log'].append((epoch, total, right, recall(W, VALID, 5), recall(W, VALID, 10), recall(W, TRAIN, 5)))
    run['W'] = W
    return run


# 5단계: τ 0.05, 학습률 0.02 로 40에포크 학습한다
# 평균 손실과 평균 정답 칸 확률은 그 에포크의 배치 16개에서 고치기 전에 잰 값의 평균이다.
TAU, LR, EPOCHS = 0.05, 0.02, 40
RUN = train(TAU, LR, epochs=EPOCHS, watch=(0, 8, 16, 24, 32, 39))
print(f'W {DIM} × 8 은 gauss(0, 0.3) 로 시작, 에포크마다 배치 {PER_GROUP}개 × {len(GROUPS)}쌍, {EPOCHS}에포크, τ {TAU}, 학습률 {LR}')
print(f'배치 하나의 점수표 {len(GROUPS)} × {len(GROUPS)}: 정답 {len(GROUPS)}칸, 음성 {len(GROUPS) * (len(GROUPS) - 1)}칸. '
      f'recall@k 는 질의 밖의 낱말 {len(WORDS) - 1}개에서 센다')
print(f'배치 {RUN["batches"]}개 가운데 묶음 {len(GROUPS)}개가 한 번씩 든 배치 {RUN["once"]}개, '
      f'음성 칸 {RUN["negative_cells"]:,}개 가운데 같은 묶음 낱말이 앉은 칸 {RUN["same_group"]}개')
partner = {w: sum(b == w for _, b in TRAIN) for w in WORDS}
print(f'낱말이 에포크마다 짝 자리에 오는 횟수: 가장 적은 낱말 {min(partner.values())}번, 가장 많은 낱말 {max(partner.values())}번')
for epoch, loss, p, v5, v10, t5 in RUN['log']:
    print(f'에포크 {epoch:2d}: 평균 손실 {loss:.3f}, 평균 정답 칸 확률 {p:.3f}, 검증 recall@5 {v5:.3f}, @10 {v10:.3f}, 학습 recall@5 {t5:.3f}')

# 6단계: 학습 전과 뒤를 비교하고, 손실을 Two-Tower 학습 편의 batch_loss 로 한 번 잰다
# 학습 전은 처음 W(start) 다. 운동화와 러닝화는 검증 쌍이고, 스니커즈와 운동화는 학습 쌍이다.
# 첫 배치는 에포크 0 의 배치 0 이다. log 10 은 열 칸에 확률을 똑같이 둘 때의 손실이다.
for name, W in (('학습 전', RUN['start']), ('학습 뒤', RUN['W'])):
    vec = {w: project(W, w)[0] for w in WORDS}
    r5, r10 = recall(W, VALID, 5), recall(W, VALID, 10)
    print(f'{name}: 검증 recall@5 {r5:.3f}({round(r5 * len(VALID))}/{len(VALID)}), '
          f'@10 {r10:.3f}({round(r10 * len(VALID))}/{len(VALID)}), 스니커즈와 운동화 {dot(vec["스니커즈"], vec["운동화"]):.3f}, '
          f'운동화와 러닝화 {dot(vec["운동화"], vec["러닝화"]):.3f}')
print('첫 배치: ' + ', '.join(f'{a}→{b}' for a, b in RUN['first']))
before = [step(RUN['start'], RUN['first'], tau, 0)[0] for tau in (TAU, 1.0)]
print(f'학습 전 W 로 잰 첫 배치의 손실: τ {TAU} 에서 {before[0]:.3f}, τ 1 에서 {before[1]:.3f}, '
      f'열 칸에 똑같이 두면 log 10 = {math.log(10):.3f}')
mine, _, table = step(RUN['W'], RUN['first'], TAU, 0)
row = [w for w, _ in RUN['first']].index('스니커즈')
prob = softmax([c / TAU for c in table[row]])
print(f'학습 뒤 첫 배치의 스니커즈 줄(정답 {RUN["first"][row][1]}) 코사인: ' + ' '.join(f'{c:+.2f}' for c in table[row]))

      + f', 정답 칸 {prob[row]:.3f}, 음성 9칸 합 {sum(prob) - prob[row]:.3f}')
theirs = batch_loss(table, TAU)
print(f'학습 뒤 W 로 잰 첫 배치: batch_loss(table, {TAU}) {theirs:.6f}, 학습 식 {mine:.6f}, 차이 1e-12 아래 {abs(theirs - mine) < 1e-12}')
FINAL = RUN['last'] + (recall(RUN['W'], VALID, 5), recall(RUN['W'], VALID, 10),
                       dot(project(RUN['W'], '스니커즈')[0], project(RUN['W'], '운동화')[0]))

# 배치 하나의 점수표 10 × 10: 정답 10칸, 음성 90칸. recall@k 는 질의 밖의 낱말 49개에서 센다
# 배치 640개 가운데 묶음 10개가 한 번씩 든 배치 640개, 음성 칸 57,600개 가운데 같은 묶음 낱말이 앉은 칸 0개
```

## 4. 학습 뒤 검증 쌍의 recall@k 가 오릅니다

**검증 쌍의 recall@5 는 학습 전 0.100 에서 학습 뒤 0.675, recall@10 은 0.200 에서 0.850 이 되었습니다. 학습 쌍인 스니커즈와 운동화의 코사인은 -0.397 에서 0.685, 검증 쌍인 운동화와 러닝화는 0.266 에서 0.465 가 되었습니다.**

이 글의 recall@k 는 검증 쌍 (a, b) 마다 a 와 다른 낱말 49개를 코사인으로 정렬해, b 가 위 k 개에 든 비율입니다. 코사인이 같으면 낱말 목록의 차례로 둡니다. 검증 쌍은 40개라, recall@5 0.675 는 40쌍 가운데 27쌍의 짝이 위 5개에 들었다는 뜻입니다. 23주째 편의 재현율@10 과는 다른 값이고, 헷갈리기 쉬운 점 첫째에서 다시 봅니다.

학습 전은 W 를 `gauss(0, 0.3)` 로 채운 처음 상태입니다. 그때 검증 recall@5 는 40쌍 가운데 4쌍인 0.100, recall@10 은 8쌍인 0.200 이었습니다. W 에는 음수도 있어서, 23주째의 장난감과 달리 코사인이 -1 과 1 사이에 놓입니다. 그래서 처음 W 에서 스니커즈와 운동화의 코사인은 -0.397 처럼 음수로도 나왔습니다.

| 시점 | 검증 recall@5 | 검증 recall@10 | 스니커즈와 운동화(학습 쌍) | 운동화와 러닝화(검증 쌍) |
|---|---|---|---|---|
| 학습 전(처음 W) | 0.100 (4/40) | 0.200 (8/40) | -0.397 | 0.266 |
| 학습 뒤(에포크 39) | 0.675 (27/40) | 0.850 (34/40) | 0.685 | 0.465 |

에포크별로 보면 학습 recall@5 는 에포크 8 에 0.969, 에포크 24 와 32, 39 에 1.000 이었습니다. 검증 recall@5 는 에포크 8 의 0.400 에서 0.475, 0.575, 0.600 을 거쳐 0.675 로 천천히 올랐습니다. 같은 사이 평균 손실은 0.267 에서 0.010 으로 줄었습니다. 학습 쌍은 일찍 다 맞혔고, 그 뒤에도 검증 쌍의 순위는 조금씩 올랐습니다.

스니커즈와 운동화는 학습 쌍이라, 손실이 직접 당긴 짝입니다. 운동화와 러닝화는 검증 쌍이라 한 번도 짝지어 학습하지 않았는데, 코사인이 0.266 에서 0.465 로 올랐습니다. 2절에서 본 것처럼 두 낱말은 스니커즈를 거쳐 학습 쌍으로 이어져 있어, 학습이 둘을 함께 당긴 것으로 보입니다. 그래도 검증 쌍의 짝이 모두 위 5개에 든 것은 아니어서, 5절은 같은 학습을 온도만 바꿔 다시 돌립니다.

## 5. 온도가 작을수록 좋은 것은 아닙니다

**τ 0.05 는 학습 쌍의 정답 칸 확률이 0.991 로 셋 가운데 가장 높았지만, 검증 recall@5 는 0.675 로 가장 낮았습니다. τ 0.2 와 1.0 은 검증 쌍을 모두 찾았습니다. τ 1.0 은 묶음 안의 낱말을 한 방향으로 모아, 묶음 안 코사인의 평균이 1.000 이 되었습니다.**

[Two-Tower 학습](post.html?id=two-tower-training) 편 4절은 τ 가 작을수록 정답 칸 확률이 1 에 가까워진다는 것을 찍었습니다. 그리고 온도는 정해진 값이 없어서 검증 재현율을 보고 고른다고 했습니다. 이 글에서 그 검증 재현율은 4절의 recall@k 입니다. 블록 3 은 같은 시드, 같은 차례로 τ 0.05, 0.2, 1.0 을 학습합니다.

학습률은 τ 마다 0.4τ 로 두었습니다. 점수를 τ 로 나누면 코사인 쪽 기울기도 1/τ 배가 되어, 같은 학습률이면 τ 가 작을수록 걸음이 커집니다. 학습률을 τ 에 비례하게 두면 코사인이 한 걸음에 움직이는 크기가 τ 와 상관없이 맞춰집니다. 식은 더 깊이 보기에 있습니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 온도 셋을 학습률 0.4τ 로 같은 차례에 학습해, 학습 쌍의 정답 칸 확률과 검증 쌍의 recall@k, 묶음 안과 밖의 코사인을 비교한다.

# 1단계: 학습한 W 로 묶음 안과 밖의 코사인을 센다
# 묶음 안 짝 100개는 학습 짝 80개와 검증 짝 20개로 나뉜다(검증 짝은 2블록에서 양쪽 방향으로 뗀 둘씩).
# 다른 묶음 짝 1,125개는 평균과 가장 큰 값을 본다. 스니커즈는 같은 묶음 넷과의 코사인을 본다.
HELD = {frozenset(p) for p in VALID}


def spread(W):
    vec = {w: project(W, w)[0] for w in WORDS}
    cos = {pair: dot(vec[pair[0]], vec[pair[1]]) for pair in INNER + CROSS}
    inner = [cos[p] for p in INNER]
    seen = [cos[p] for p in INNER if frozenset(p) not in HELD]
    held = [cos[p] for p in INNER if frozenset(p) in HELD]
    cross = [cos[p] for p in CROSS]
    mates = [(w, dot(vec['스니커즈'], vec[w])) for w in GROUPS['신발'] if w != '스니커즈']
    return {'inner': (sum(inner) / len(inner), min(inner)), 'seen': sum(seen) / len(seen), 'held': sum(held) / len(held),
            'cross': (sum(cross) / len(cross), max(cross)), 'mates': mates, 'n': (len(seen), len(held))}


# 2단계: 온도 셋을 학습한다
# 점수를 τ 로 나누면 코사인 쪽 기울기도 1/τ 배가 된다. 학습률을 0.4τ 로 두어 코사인이 한 걸음에 움직이는 크기를 맞춘다.
# 손실과 정답 칸 확률은 마지막 에포크(39)의 평균이다. 다른 것은 블록 2 와 같다(같은 시드, 같은 차례).
RUNS = {0.05: 0.02, 0.2: 0.08, 1.0: 0.4}
RESULT = {}
for tau, lr in RUNS.items():
    run = train(tau, lr, epochs=EPOCHS)
    s = spread(run['W'])
    RESULT[tau] = run['last'] + (recall(run['W'], VALID, 5), recall(run['W'], VALID, 10), s['mates'][0][1])
    loss, p, r5, r10, sneaker = RESULT[tau]
    print(f'τ {tau}(학습률 {lr}, 학습률 ÷ τ = {lr / tau:.1f}): 손실 {loss:.3f}, 정답 칸 확률 {p:.3f}, '
          f'검증 recall@5 {r5:.3f}, @10 {r10:.3f}, 스니커즈와 운동화 {sneaker:.3f}')
    print(f'  묶음 안 짝 {len(INNER)}개 평균 {s["inner"][0]:.3f}(가장 작은 값 {s["inner"][1]:.3f}), '
          f'학습 짝 {s["n"][0]}개 {s["seen"]:.3f}, 검증 짝 {s["n"][1]}개 {s["held"]:.3f}')
    print(f'  다른 묶음 짝 {len(CROSS):,}개 평균 {s["cross"][0]:.3f}, 가장 큰 값 {s["cross"][1]:.3f}')
    print('  스니커즈와 같은 묶음 넷: ' + ', '.join(f'{w} {c:.3f}' for w, c in s['mates']))
print(f'τ 0.05 의 다섯 값이 블록 2 의 마지막 값과 같음: {RESULT[0.05] == FINAL}')

# 3단계: 정답 칸 확률이 오를 수 있는 끝을 본다
# 코사인은 -1 과 1 사이다. 정답 칸이 1 이고 다른 9칸이 모두 -1 이면 τ 마다 정답 칸 확률이 가장 크다.
# 묶음 열 개가 한 방향씩에 모이면 다른 묶음 짝의 코사인 평균은 -1/9 보다 작아질 수 없다(더 깊이 보기).
# 그래서 다른 9칸이 모두 -1/9 인 점수표도 함께 잰다.
for others, name in ((-1.0, '-1'), (-1 / 9, '-1/9')):
    print(f'정답 칸 1, 다른 9칸 모두 {name}: ' + ', '.join(
        f'τ {tau} 에서 {softmax([1 / tau] + [others / tau] * 9)[0]:.3f}' for tau in RUNS))
# 출력:
# 2단계 뜻: τ 0.05 는 정답 칸 확률이 가장 높고 검증 recall@5 는 가장 낮다. τ 0.2 와 1.0 은 묶음 안의 가장 작은 코사인이 다른 묶음의 가장 큰 값보다 커서 검증 쌍을 모두 찾는다.
# τ 0.05(학습률 0.02, 학습률 ÷ τ = 0.4): 손실 0.010, 정답 칸 확률 0.991, 검증 recall@5 0.675, @10 0.850, 스니커즈와 운동화 0.685
#   묶음 안 짝 100개 평균 0.736(가장 작은 값 0.116), 학습 짝 80개 0.788, 검증 짝 20개 0.531
#   다른 묶음 짝 1,125개 평균 -0.063, 가장 큰 값 0.815
#   스니커즈와 같은 묶음 넷: 운동화 0.685, 러닝화 0.718, 조깅화 0.808, 마라톤화 0.753
# τ 0.2(학습률 0.08, 학습률 ÷ τ = 0.4): 손실 0.063, 정답 칸 확률 0.939, 검증 recall@5 1.000, @10 1.000, 스니커즈와 운동화 0.966
#   묶음 안 짝 100개 평균 0.957(가장 작은 값 0.790), 학습 짝 80개 0.971, 검증 짝 20개 0.899
#   다른 묶음 짝 1,125개 평균 -0.106, 가장 큰 값 0.307
#   스니커즈와 같은 묶음 넷: 운동화 0.966, 러닝화 0.967, 조깅화 0.992, 마라톤화 0.986
# τ 1.0(학습률 0.4, 학습률 ÷ τ = 0.4): 손실 1.388, 정답 칸 확률 0.250, 검증 recall@5 1.000, @10 1.000, 스니커즈와 운동화 1.000
#   묶음 안 짝 100개 평균 1.000(가장 작은 값 0.996), 학습 짝 80개 1.000, 검증 짝 20개 0.999
#   다른 묶음 짝 1,125개 평균 -0.111, 가장 큰 값 0.488
#   스니커즈와 같은 묶음 넷: 운동화 1.000, 러닝화 1.000, 조깅화 1.000, 마라톤화 1.000
# τ 0.05 의 다섯 값이 블록 2 의 마지막 값과 같음: True
# 3단계 뜻: τ 1.0 은 다른 9칸이 모두 -1 이어도 정답 칸 확률이 0.451 을 넘지 못하고, 모두 -1/9 이면 0.252 다.
```

τ 0.2 와 1.0 은 묶음 안의 가장 작은 코사인이 0.790 과 0.996 이었습니다. 두 값은 다른 묶음 짝의 가장 큰 값 0.307 과 0.488 보다 큽니다. 그래서 어느 낱말이든 같은 묶음 넷이 위 4개를 차지하고, 검증 쌍의 짝은 모두 위 5개 안에 들었습니다.

## 6. Sentence-BERT 에서 contrastive 학습으로 오기까지 논문 넷이 있습니다

**Sentence-BERT 는 코사인으로 비교할 문장 벡터를 얻으려고 가중치를 함께 쓰는 BERT 둘을 파인튜닝했습니다. InfoNCE 는 양성 하나를 음성 여럿 가운데서 고르는 손실이고, DPR 과 SimCSE 는 배치 안의 다른 쌍을 음성으로 썼습니다. 이 글의 장난감은 SimCSE 와 같은 꼴의 손실을 8차원 사상 하나에 건 것입니다.**

가까워야 할 쌍은 당기고 아닌 쌍은 밀어 벡터를 배우는 방법을 contrastive 학습이라고 부릅니다. SimCSE 논문은 이것을 의미가 가까운 이웃은 당기고, 이웃이 아닌 것은 밀어 효과적인 표현을 배우는 것이라고 적었습니다(2절). 아래 표는 이 글이 연 논문 넷과 이 글의 장난감을 같은 칸으로 놓은 것입니다.

| 방법 | 양성 쌍 | 음성 | 인코더 | 점수 |
|---|---|---|---|---|
| Sentence-BERT (2019) | NLI 문장 쌍과 라벨 셋(분류 목적) | 분류 목적에는 따로 없음, triplet 은 음성 문장 하나 | 가중치를 함께 쓰는 BERT 둘 | 분류는 두 벡터와 그 차이를 이은 소프트맥스, 비교는 코사인 |
| InfoNCE, CPC (2018) | 문맥과 그 뒤의 실제 표본 | 제안 분포에서 뽑은 N - 1개 | 인코더와 자기회귀 모델 | exp(zᵀ W c), 양성을 고르는 교차 엔트로피 |
| DPR (2020) | 질문과 정답 단락 | 배치 안의 다른 질문의 단락, BM25 단락 하나 | 질문용과 단락용 BERT 둘 | 내적 |
| SimCSE 비지도 (2021) | 같은 문장을 드롭아웃만 달리해 두 번 | 배치 안의 다른 문장 | 인코더 하나 | 코사인 ÷ τ |
| SimCSE 지도 (2021) | NLI 의 함의 쌍 | 배치 안의 다른 문장, 모순 문장 | 인코더 하나 | 코사인 ÷ τ |
| 이 글의 장난감 | 같은 묶음의 두 낱말 | 배치 안의 다른 묶음 낱말 | 8차원 사상 W 하나 | 코사인 ÷ τ, τ 0.05 |

Reimers 와 Gurevych(2019)의 Sentence-BERT 는 BERT 의 출력을 평균 풀링해 문장 하나를 벡터 하나로 바꿉니다. BERT 는 두 문장을 함께 넣어야 점수를 내서, 문장 10,000개에서 가장 비슷한 쌍을 찾으려면 추론이 49,995,000번 필요했습니다. 논문은 이것이 V100 GPU 로 약 65시간이라고 적었습니다. Sentence-BERT 는 같은 일을 문장 벡터 10,000개 계산 약 5초와 코사인 계산 약 0.01초로 줄였습니다(1절). 학습 목적은 분류, 회귀, triplet 셋이고, 셋 모두 배치 안의 다른 문장을 음성으로 쓰는 항은 없습니다. 기본 학습은 두 문장의 관계에 함의, 모순, 중립 라벨을 붙인 NLI 데이터로 라벨을 맞히는 분류였습니다.

van den Oord 외(2018)는 표본 N개 가운데 양성 하나를 맞히는 손실을 InfoNCE 라고 불렀습니다(2.3절, 식 4). N개에는 양성 표본 하나와 음성 표본 N - 1개가 듭니다. 논문은 이 손실이 양성 표본을 맞게 고르는 범주 교차 엔트로피라고 적었습니다. 이 글의 점수표 한 줄은 N 이 10 인 InfoNCE 이고, 점수는 코사인을 τ 로 나눈 값입니다.

Karpukhin 외(2020)의 DPR 은 질문과 단락(passage)을 서로 다른 BERT 둘로 바꾸고, 내적으로 점수를 냅니다. 질문 B 개의 배치에서 B × B 점수표의 대각선이 양성이고, 질문마다 B - 1개 단락이 음성입니다(3.2절). 주 실험의 DPR 은 배치 128 에 질문마다 BM25 음성 단락 하나를 더해 학습했습니다. 이 단락은 [Elasticsearch 하이브리드 검색](post.html?id=elasticsearch-hybrid-retrieval) 편의 BM25 가 높게 매겼지만 답이 없는 단락입니다. top-20 검색 정확도는 위 20개 단락에 답이 든 질문의 비율입니다(2절). 표 3 은 질의응답 데이터 Natural Questions 의 개발 세트에서 이 값을 비교했습니다. 배치 128 에서 배치 안 음성만 쓰면 73.0, BM25 단락 하나를 더하면 78.0 이었습니다.

Gao, Yao, Chen(2021)의 SimCSE 는 코사인을 온도 τ 로 나눈 같은 꼴의 손실에 배치 안 음성을 썼습니다(식 1). 비지도 판은 같은 문장을 드롭아웃만 달리해 두 번 넣은 것이 양성 쌍입니다. 드롭아웃은 학습 때 신경망 값의 일부를 무작위로 0 으로 두는 방법입니다. 지도 판은 NLI 의 함의 쌍이 양성이고, 모순 문장을 헷갈리는 음성(hard negative)으로 더합니다. 부록 D 는 문장 쌍의 의미가 비슷한 정도를 매긴 STS-B 의 개발 세트에서 온도를 바꿔 보았습니다. 그리고 잘 고른 τ = 0.05 에서 코사인이 내적보다 낫다고 적었습니다. 표 D.1 의 Spearman 순위 상관은 τ 0.05 에서 86.2, 내적에서 85.9, τ 1 에서 64.0 이었습니다. 이 글의 주 학습도 τ 0.05 이지만, 장난감 낱말 50개에서는 5절처럼 셋 가운데 검증 recall@5 가 가장 낮았습니다.

## 7. 양성 쌍을 얻는 곳이 무대마다 다릅니다

**양성 쌍으로 사상을 학습하는 셈은 두 무대가 같습니다. 담장 안은 검색 로그의 질의와 클릭이 양성 쌍이 되고, 열린 RTB 의 DSP 는 이긴 노출의 클릭으로만 쌍을 얻어 쌍이 적습니다.**

두 무대의 이름은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에서 풀었습니다. 1~5절의 셈은 두 무대가 같고, 양성 쌍을 어디서 얼마나 얻느냐가 다릅니다.

### 담장 안에서는 검색 로그가 양성 쌍을 줍니다 [무대: 닫힌 생태계]

검색 광고를 파는 플랫폼은 사용자가 친 검색어와 그 뒤의 클릭을 한 회사에 쌓습니다. 그래서 질의와 클릭한 상품을 바로 양성 쌍으로 쓰고, 같이 클릭된 상품끼리도 쌍을 만들 수 있습니다. 상품의 묶음을 알면 배치에 같은 묶음이 두 번 들지 않게 짜서, 정답을 음성으로 세는 칸을 막을 수 있습니다. 상품 벡터는 미리 만들어 색인에 두고, 다시 학습하면 같은 사상으로 색인을 다시 만듭니다.

### 열린 RTB 에서는 이긴 노출의 클릭만 쌍이 됩니다 [무대: 열린 RTB]

열린 RTB 의 DSP 는 경매에 이긴 노출에만 광고를 띄워서, 클릭도 그 노출에서만 봅니다. 23주째 편에서 본 것처럼 입찰 요청에는 검색어가 거의 없고, 지면의 주소와 카테고리 같은 맥락이 옵니다. 그래서 쌍은 지면 맥락과 클릭한 소재의 짝이 되고, 담장 안보다 쌍이 적습니다. 쌍이 적으면 검증 쌍을 떼어 두기도 빠듯해서, 온도를 고를 근거도 얇아집니다.

## 헷갈리기 쉬운 점

- **recall@k 는 23주째 편의 재현율@10 과 다른 값입니다.** [임베딩과 벡터 검색](post.html?id=embeddings-vector-search) 편의 재현율@10 은 근사 검색의 상위 10건 가운데 전수 검색의 10위 점수 이상인 상품의 몫입니다. [Two-Tower 학습](post.html?id=two-tower-training) 편의 Recall@500 은 다음 날 클릭한 광고가 상위 500 안에 든 비율입니다. 이 글의 recall@k 는 검증 쌍의 짝이 낱말 49개 가운데 위 k 개에 든 비율입니다. 셋은 무엇을 정답으로 보는지가 달라서, 숫자를 서로 비교하지 않습니다.
- **같은 묶음이 한 배치에 두 번 들면 정답이 음성 칸에 앉습니다.** 같은 묶음의 두 쌍이 한 배치에 들면, 한 쌍의 짝이 다른 쌍의 줄에서 음성 칸에 앉습니다. 그 낱말도 같은 묶음이라 양성인데, 손실은 그 칸의 확률을 낮추려 합니다. Two-Tower 학습 편의 accidental hit 와 같은 일입니다. 이 글은 배치를 묶음마다 한 쌍으로 짜서, 그런 칸이 0개였습니다.
- **학습 쌍의 recall 이 1 이어도 검증 쌍은 다릅니다.** τ 0.05 의 학습 recall@5 는 에포크 24 에 1.000 이었지만, 검증 recall@5 는 에포크 39 에도 0.675 였습니다. 학습 쌍만 보면 학습이 끝난 것처럼 보이는 동안에도, 검증 쌍의 순위는 계속 바뀌었습니다. 그래서 온도와 체크포인트는 학습에 쓰지 않은 쌍으로 고릅니다.

## 더 깊이 보기

:::deep 손실과 기울기의 식
배치의 쌍을 $(a_i, b_i)$, $i = 1, \dots, B$ 라고 두겠습니다. 낱말 $w$ 의 `embed` 칸 값을 $e_j(w)$, W 의 $j$ 번째 줄을 $W_j$ 라고 쓰면 낱말 벡터는 아래와 같습니다.

$$u(w) = \sum_j e_j(w)\, W_j, \qquad v(w) = \frac{u(w)}{\lVert u(w) \rVert}$$

점수표와 손실은 아래와 같습니다. 줄 하나가 InfoNCE 이고, SimCSE 의 식 1 과 같은 꼴입니다.

$$s_{ik} = \frac{v(a_i)^\top v(b_k)}{\tau}, \qquad p_{ik} = \frac{e^{s_{ik}}}{\sum_{k'} e^{s_{ik'}}}, \qquad L = -\frac{1}{B} \sum_{i} \log p_{ii}$$

손실을 점수 칸으로 미분하면 $(p_{ik} - \delta_{ik}) / B$ 이고, 코사인으로는 $\tau$ 로 한 번 더 나눕니다. 블록 2 의 `g` 가 이 값입니다. 이 값을 두 낱말 벡터로 보냅니다.

$$\frac{\partial L}{\partial v(a_i)} = \sum_k \frac{p_{ik} - \delta_{ik}}{B\tau}\, v(b_k), \qquad \frac{\partial L}{\partial v(b_k)} = \sum_i \frac{p_{ik} - \delta_{ik}}{B\tau}\, v(a_i)$$

길이 맞춤을 거치면, 벡터 쪽 기울기 $g$ 에서 $v$ 방향의 몫을 빼고 길이로 나눕니다. 블록 2 의 `gu` 가 이 값입니다.

$$\frac{\partial L}{\partial u} = \frac{g - (g^\top v)\, v}{\lVert u \rVert}$$

$W_j$ 의 기울기는 배치에 든 낱말 가운데 $e_j(w)$ 가 0 이 아닌 낱말에서만 모입니다. 그래서 그 줄만 학습률을 곱해 고치고, 나머지 줄은 그대로 둡니다. 질의와 짝이 같은 W 를 쓰므로, 질의 쪽 낱말과 짝 쪽 낱말의 기울기가 같은 W 에 함께 더해집니다.
:::

:::deep Sentence-BERT 의 원래 목적 셋
Reimers 와 Gurevych(2019) 3절은 학습 데이터에 따라 세 목적을 썼습니다. 문장 벡터는 $u$, $v$ 이고 $n$ 은 그 차원입니다.

- 분류: $o = \mathrm{softmax}(W_t (u, v, |u - v|))$ 로 라벨 $k$ 개를 맞히고, 교차 엔트로피를 줄입니다. $W_t$ 는 $3n \times k$ 입니다.
- 회귀: 두 벡터의 코사인을 정답 점수에 맞추고, 평균 제곱 오차를 줄입니다.
- triplet: 기준 문장의 벡터 $s_a$ 가 음성 문장의 $s_n$ 보다 양성 문장의 $s_p$ 에 $\epsilon$ 이상 가깝게 합니다. 거리는 유클리드 거리이고 $\epsilon = 1$ 입니다.

$$\max\big(\lVert s_a - s_p \rVert - \lVert s_a - s_n \rVert + \epsilon,\ 0\big)$$

3.1절의 기본 학습은 SNLI 570,000쌍과 MultiNLI 430,000쌍에서 라벨 셋(모순, 함의, 중립)을 맞히는 분류 목적입니다. 1에포크, 배치 16, Adam 학습률 2e-5, 학습 데이터의 10% 동안 학습률을 올리는 warm-up 을 썼습니다. 풀링의 기본값은 평균입니다. 추론 때는 분류기를 떼고 두 문장 벡터의 코사인만 씁니다(그림 2). 이 글의 장난감에는 라벨이 없고 양성 쌍만 있어서, 세 목적 대신 배치 안의 다른 쌍을 음성으로 씁니다.
:::

:::deep 학습률을 온도에 비례하게 두는 까닭
첫째 식에서 손실의 코사인 쪽 기울기는 $(p_{ik} - \delta_{ik}) / (B\tau)$ 입니다. 학습률을 $c\,\tau$ 로 두면 $\tau$ 가 지워집니다. 코사인 쪽의 한 걸음이 $c\,(p_{ik} - \delta_{ik}) / B$ 가 되기 때문입니다. 블록 3 은 $c = 0.4$ 입니다. 그래서 온도는 걸음의 크기가 아니라 소프트맥스가 얼마나 뾰족한지만 바꿉니다. 정답 칸이 받는 걸음은 $1 - p_{ii}$ 에 비례해서, 정답 칸 확률이 1 에 가까운 τ 0.05 는 남은 걸음이 작습니다.

묶음 10개의 방향을 길이 1 인 $d_1, \dots, d_{10}$ 이라고 두면 아래가 늘 성립합니다.

$$0 \le \Big\lVert \sum_{g} d_g \Big\rVert^2 = 10 + \sum_{g \ne h} d_g^\top d_h$$

그래서 서로 다른 두 묶음 방향의 코사인 90개의 평균은 $-1/9$ 보다 작아질 수 없습니다. 묶음 안의 낱말이 한 방향에 모이면 다른 묶음 짝의 코사인이 이 값들이라, 그 평균도 $-1/9$ 아래로 내려가지 않습니다. 블록 3 이 찍은 τ 1.0 의 다른 묶음 평균 -0.111 은 이 끝에 있습니다. 정답 칸이 1 이고 다른 9칸이 모두 $-1/9$ 인 줄의 정답 칸 확률은 아래와 같고, τ 1.0 에서 0.252 입니다.

$$p = \frac{e^{1/\tau}}{e^{1/\tau} + 9\, e^{-1/(9\tau)}}$$
:::

BERT 를 가중치를 함께 쓰는 siamese 구조와 triplet 구조로 파인튜닝해, 코사인으로 비교할 수 있는 문장 벡터를 만듭니다. 문장 10,000개에서 가장 비슷한 쌍을 찾는 일을 BERT 의 약 65시간에서 약 5초로 줄였다고 적었습니다.

[arxiv.org](https://arxiv.org/abs/2104.08821). 코사인을 온도로 나눈 점수와 배치 안 음성으로 문장 벡터를 학습합니다. 비지도 판은 드롭아웃이 다른 같은 문장을, 지도 판은 NLI 의 함의 쌍을 양성으로 씁니다. 부록 D 에서 τ = 0.05 일 때 코사인이 내적보다 나았다고 적었습니다.

- Karpukhin, V., Oğuz, B., Min, S. 외 (2020). *Dense Passage Retrieval for Open-Domain Question Answering*. EMNLP 2020. arXiv:2004.04906. [arxiv.org](https://arxiv.org/abs/2004.04906). 질문과 단락을 BERT 둘로 바꾸고, 배치 안의 다른 질문의 정답 단락과 BM25 단락 하나를 음성으로 씁니다.
