Tool use 카드 네 장

지훈 씨가 답 대신 도구를 불러 달라는 모델을 본 길을 카드 네 장으로 봅니다. 도구 셋을 정의하고, 가짜 LLM 이 고른 호출을 코드가 실행합니다. 끝나지 않는 과제는 멈춤 조건이 끊고, 20% 넘는 변경은 코드가 거부합니다. 캠페인 셋과 어제 통계는 가상 데이터입니다.

파랑 = 코드가 하는 일 벽돌색 = 모델이 고른 것 먹색 = 도구와 캠페인 회색 = 거부되거나 멈춘 것 점선 상자 = 가상 값 (캠페인 셋)

TOOLS

도구 셋의 정의

쉽게 말하면 모델에게 부를 수 있는 함수의 이름, 설명, 입력 꼴을 건넵니다. 모델은 이 셋 가운데서 고릅니다.

도구는 3개, 목표보다 낮은 캠페인은 ROAS 280% 인 러닝화 하나입니다.

LOOP

LLM 이 고르고 코드가 실행하는 한 바퀴

쉽게 말하면 모델이 tool_use 블록을 적으면 코드가 돌리고, 결과를 tool_result 로 다시 넣습니다.

첫 과제는 4단계, 도구 호출 5번에 end_turn 으로 끝났습니다.

STOP

멈춤 조건 셋

쉽게 말하면 모델이 끝내지 않아도 코드가 루프를 끊습니다. 같은 호출 반복과 단계 상한입니다.

반복 검사는 5단계, 단계 상한은 6단계에서 멈췄습니다.

GUARD

가드레일은 코드

쉽게 말하면 20% 상한은 설명 글이 아니라 실행 코드가 지킵니다. 거부도 결과로 돌려줍니다.

30% 변경은 2번 거부되었고, 20% 로 고친 호출은 통과했습니다.

현업에서는 이렇게 씁니다

  • 입찰가를 바꾸는 도구에는 한 번의 상한 말고도 하루 누적 한도나 사람의 확인을 함께 둡니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 Tool use 와 에이전트 루프 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 바로 앞 이야기는 RAG 편입니다.
