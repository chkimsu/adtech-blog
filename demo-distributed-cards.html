분산 학습 카드 네 장

학습 한 바퀴를 GPU 여러 장으로 나누는 자리 하나가 카드 한 장입니다. 점이 흐르는 방향이 데이터가 가는 방향이고, 점이 몰려서 지나가면 한 배치입니다. 숫자는 설명용 가상 값입니다.

파랑 = 놓여 있는 데이터 (학습 행, 임베딩 표) 벽돌색 = 문제가 되는 것 먹색 = GPU 와 서버 회색 = 만드는 작업 점 = 지금 가고 있는 데이터

DATA PARALLEL

같은 모델 넷, 데이터는 사등분

쉽게 말하면 GPU 마다 같은 모델을 한 벌씩 두고 학습 데이터만 넷으로 나눠 줍니다. 각자 계산한 기울기를 평균 내어 넷이 같은 모델을 유지합니다.

6시간 20분이 1시간 50분 으로 줍니다. 넷이니 네 배가 아니라 3.5배이고 효율은 86% 입니다. 계산은 나뉘지만 합치는 시간은 안 나뉘기 때문입니다.

EMBEDDING SHARD

임베딩만 따로 쪼갠다

쉽게 말하면 신경망은 작아서 GPU 안에 들어가는데 임베딩 표는 GPU 한 장보다 큽니다. 그래서 표만 따로 서버 여러 대에 나눠 두고 GPU 는 그때 쓰는 줄만 받아 옵니다.

신경망 38MB 는 들어가지만 임베딩은 Adam 기준 83.2GB 라 80GB 한 장에 안 들어갑니다. 배치 1,024건이 건드리는 줄은 유저 2억 줄의 0.0005% 뿐입니다.

SYNC VS ASYNC

기울기를 언제 합치나

쉽게 말하면 스텝마다 넷이 서로를 기다렸다 합칠지, 기다리지 않고 각자 갈지를 고르는 일입니다. 기다리면 느려지고 안 기다리면 낡은 값으로 배웁니다.

동기는 늦은 장 하나 때문에 스텝이 혼자 돌 때보다 13% 깁니다. 비동기는 기다림이 0 인 대신 기울기가 평균 3스텝 낡습니다. 실무는 둘을 섞습니다.

SPEEDUP

장수를 늘리면 얼마나 주나

쉽게 말하면 GPU 를 두 배로 늘려도 시간은 절반이 되지 않습니다. 장이 늘 때마다 합치기와 기다림이 붙어 효율이 내려갑니다.

4장에서 8장으로 가면 44분 줄고, 8장에서 16장으로 가면 22분 줍니다. 효율은 86%, 73%, 56% 로 내려갑니다. 어디서 멈출지는 GPU 값과 견줍니다.

현업에서는 이렇게 씁니다

  • 「GPU 를 몇 장 쓸까」를 정할 때 두 가지를 봅니다. 한 장에 들어가지 않는 것이 무엇인가, 그리고 장을 늘려 줄어드는 시간이 GPU 값만큼 값어치를 하나.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 분산 학습 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 임베딩 표의 크기 계산은 대규모 임베딩 테이블 운영 편입니다.
