광고 소재 2개가 있다. 하나는 진짜 클릭률이 2.0%, 다른 하나는 3.0%다. 다만 이 숫자는 우리가 미리 아는 값이 아니다. 이번 주 노출 10만 건을 이 둘에 나눠 쓰면서 알아내야 한다.

팀 회의에서 의견이 갈린다. 한쪽은 "반반 나눠서 일주일 다 채우고 그때 정하자"고 한다. 다른 쪽은 "일단 돌리면서 잘 나오는 쪽으로 옮기자"고 한다. 둘 다 "실험"이라 부르지만, 일주일 뒤 손에 쥐는 결과는 완전히 다르다.

앞의 방식이 A/B 테스트, 뒤의 방식이 멀티암드 밴딧(MAB)이다. 이 둘이 정확히 무엇이고 안에서 어떤 알고리즘이 도는지는 이미 다른 글이 다뤘다. 밴딧 문제 자체는 [알고리즘 계보](post.html?id=mab-summary)에서 다뤘다. 결정적·확률적 성격 차이는 [UCB vs 톰슨 샘플링](post.html?id=ucb-vs-ts)에서 다뤘다. 이 글은 그 안쪽 대신 **바깥의 질문 하나**에만 매달린다. 똑같은 상황에서 무엇을 고르면 무엇을 얻고 무엇을 잃는가.

> 한 줄 요약: A/B는 트래픽을 끝까지 고정해 두 소재 모두에 **깨끗한 성적표**를 남긴다. 밴딧은 트래픽을 옮겨 **클릭을 더** 번다. 대신 진 소재의 진짜 실력은 훨씬 흐릿하게 알게 된다. 무엇을 고를지는 목적에 달렸다 — 이 글은 그 갈림길만 본다.

## 1. 소재 둘, 노출 10만 건 — 같은 캠페인에 두 방식을 태워보면

**밴딧이 클릭을 더 벌지만, 진 소재에 대해서는 훨씬 흐릿하게 안다 — 표 ① 하나가 이 글의 결론을 미리 보여준다.**

소재A는 진짜 클릭률 2.0%, 소재B는 3.0%다. 노출 10만 건을 쓸 때 두 방식을 나란히 돌리면 아래 표가 나온다. 같은 시드로 돌린 결과라 두 방식이 겪은 우연은 최대한 맞춰 두었다.

**표 ① — 소재 2개, 노출 10만 건, 같은 시드로 두 방식을 비교하면**

| 항목 | A/B 테스트(50:50 고정) | 밴딧(적응형) |
|---|---|---|
| 트래픽 배분(소재A : 소재B) | 50,000 : 50,000 | 4,171 : 95,829 |
| 총 클릭 수 | 2,521클릭 | 2,980클릭 |
| 후회(이론상 최선 3,000클릭 대비) | 479.0 | 20.0 |
| 소재A 최종 추정 CTR | 2.06% (95% CI ±0.124%p) | 2.28% (95% CI ±0.453%p) |
| 소재B 최종 추정 CTR | 2.99% (95% CI ±0.149%p) | 3.01% (95% CI ±0.108%p) |

먼저 클릭 수를 보자. A/B는 2,521클릭, 밴딧은 2,980클릭이다. 밴딧이 459클릭, 약 18% 더 벌었다. 이론상 최선(전부 소재B에게 몰아줬을 때 3,000클릭) 대비 후회도 A/B는 479.0인데 밴딧은 20.0뿐이다. 여기까지만 보면 밴딧의 압승이다.

그런데 마지막 두 줄을 보자. 소재A의 최종 추정치는 A/B가 2.06%(±0.124%p), 밴딧이 2.28%(±0.453%p)다. 밴딧의 신뢰구간이 A/B보다 3.7배 넓다. 이유는 단순하다. A/B는 소재A에도 끝까지 5만 건을 태웠다. 밴딧은 초반에 승부를 걸고 4,171건만 태운 뒤 나머지를 전부 소재B로 옮겼다. **표본이 적으면 추정치는 흐릿해진다.** 밴딧은 이 흐릿함을 감수하고 클릭을 택한 셈이다.

반대로 소재B의 추정치는 밴딧(±0.108%p)이 A/B(±0.149%p)보다 오히려 더 좁다. 이긴 소재에 트래픽을 몰아준 만큼, 그 소재에 대해서는 밴딧이 A/B보다 더 정확히 안다. 결국 밴딧은 이긴 쪽은 아주 잘 알고 진 쪽은 잘 모르는 성적표를 남긴다. A/B는 둘 다 비슷하게 적당히 아는 성적표를 남긴다. 어느 쪽이 실무에 더 맞는지는 4절의 표에서 정리한다.

## 2. 파이썬으로 재현 — 총 클릭과 신뢰구간

**표 ①의 숫자는 손으로 지어낸 게 아니다. 아래 코드를 그대로 돌리면 같은 값이 나온다.**

함수는 두 개면 충분하다. `run_ab`는 짝수 번째 노출을 소재A에, 홀수 번째를 소재B에 기계적으로 배정한다. `run_bandit`은 톰슨 샘플링으로, 매 노출마다 베타 분포에서 표본을 뽑아 큰 쪽에 배정한다. 톰슨 샘플링이 왜 이렇게 작동하는지는 [UCB vs 톰슨 샘플링](post.html?id=ucb-vs-ts)에서 이미 다뤘다. 여기서는 "그런 밴딧이 있다"는 정도로만 쓴다.

```python
# 소재 2개(A: 진짜 CTR 2.0%, B: 3.0%)에 노출 10만 건을 A/B와 밴딧에 각각 태워
# 총 클릭·후회·소재별 최종 추정치(95% 신뢰구간)를 비교한다. 표준 라이브러리만 쓴다.
import random, math

N = 100_000
TRUE_CTR = {"A": 0.02, "B": 0.03}   # 우리는 이 값을 모른 채 실험을 시작한다
BEST_CTR = max(TRUE_CTR.values())

def run_ab(n, true_ctr, seed):
    """A/B 테스트: 끝까지 50:50 고정 배정."""
    rng = random.Random(seed)
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for i in range(n):
        arm = "A" if i % 2 == 0 else "B"
        imps[arm] += 1
        clicks[arm] += rng.random() < true_ctr[arm]
    return imps, clicks

def run_bandit(n, true_ctr, seed):
    """밴딧(톰슨 샘플링): 매번 베타 분포에서 표본을 뽑아 큰 쪽에 배정."""
    rng = random.Random(seed)
    alpha = {"A": 1, "B": 1}
    beta = {"A": 1, "B": 1}
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for _ in range(n):
        sample = {a: rng.betavariate(alpha[a], beta[a]) for a in true_ctr}
        arm = max(sample, key=sample.get)
        imps[arm] += 1
        if rng.random() < true_ctr[arm]:
            clicks[arm] += 1
            alpha[arm] += 1
        else:
            beta[arm] += 1
    return imps, clicks

def ci95(clicks, imps):
    """관측 CTR과 95% 신뢰구간 절반폭(정규근사, 퍼센트포인트)."""
    p = clicks / imps
    return p, 1.96 * math.sqrt(p * (1 - p) / imps) * 100

SEED = 3   # A/B와 밴딧 모두 같은 시드로 돌려 공정하게 비교한다
imps_ab, clicks_ab = run_ab(N, TRUE_CTR, SEED)
imps_bd, clicks_bd = run_bandit(N, TRUE_CTR, SEED)

total_ab, total_bd = sum(clicks_ab.values()), sum(clicks_bd.values())
best_possible = N * BEST_CTR

print(f"이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): {best_possible:,.0f}")
print(f"A/B   총 클릭 {total_ab:,}   후회 {best_possible - total_ab:6.1f}")
print(f"밴딧  총 클릭 {total_bd:,}   후회 {best_possible - total_bd:6.1f}")
print()

for label, imps, clicks in [("A/B", imps_ab, clicks_ab), ("밴딧", imps_bd, clicks_bd)]:
    for arm in ("A", "B"):
        p_hat, half_width = ci95(clicks[arm], imps[arm])
        print(f"  [{label}] 소재{arm}: n={imps[arm]:6,}   관측CTR={p_hat*100:5.2f}%   95%CI=±{half_width:.3f}pp")

# 출력:
# 이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): 3,000
# A/B   총 클릭 2,521   후회  479.0
# 밴딧  총 클릭 2,980   후회   20.0
#
#   [A/B] 소재A: n=50,000   관측CTR= 2.06%   95%CI=±0.124pp
#   [A/B] 소재B: n=50,000   관측CTR= 2.99%   95%CI=±0.149pp
#   [밴딧] 소재A: n= 4,171   관측CTR= 2.28%   95%CI=±0.453pp
#   [밴딧] 소재B: n=95,829   관측CTR= 3.01%   95%CI=±0.108pp
```

출력은 표 ①과 정확히 같은 숫자다. 밴딧은 노출 4,171건 만에 소재A를 사실상 포기했다. 나머지 95,829건은 전부 소재B에 몰아줬다. 그 대가로 소재A의 신뢰구간은 A/B의 3.7배로 벌어졌다.

이 코드에서 눈여겨볼 곳은 `ci95` 함수다. 정규근사로 95% 신뢰구간의 절반폭을 구하는데, 표본 수(`imps`)가 분모에서 제곱근 안에 들어간다. 표본이 4배 줄면 구간 폭은 2배로 벌어진다는 뜻이다. 밴딧이 소재A에 준 표본은 A/B의 약 12분의 1이었다. 구간이 3~4배 벌어진 건 우연이 아니라 이 계산의 당연한 결과다.

## 3. 효과가 작으면 밴딧도 헤맨다

**진짜 차이가 0.1%p로 작아지면, 밴딧은 트래픽을 엉뚱한 쪽에 몰아줄 수 있다.**

이번엔 소재A 2.0%, 소재B 2.1%로 놓고 같은 코드를 다시 돌린다. 함수는 그대로고 진짜 클릭률과 시드만 바꿨다.

```python
# 진짜 차이가 작을 때(A 2.0% vs B 2.1%, 0.1%p 차이) 밴딧이 어떻게 되는지 본다.
# 함수는 위 코드와 동일 — TRUE_CTR과 시드만 바꿔 같은 비교를 반복한다.
import random, math

N = 100_000
TRUE_CTR = {"A": 0.02, "B": 0.021}   # 이번엔 차이가 0.1%p뿐이다
BEST_CTR = max(TRUE_CTR.values())

def run_ab(n, true_ctr, seed):
    rng = random.Random(seed)
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for i in range(n):
        arm = "A" if i % 2 == 0 else "B"
        imps[arm] += 1
        clicks[arm] += rng.random() < true_ctr[arm]
    return imps, clicks

def run_bandit(n, true_ctr, seed):
    rng = random.Random(seed)
    alpha = {"A": 1, "B": 1}
    beta = {"A": 1, "B": 1}
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for _ in range(n):
        sample = {a: rng.betavariate(alpha[a], beta[a]) for a in true_ctr}
        arm = max(sample, key=sample.get)
        imps[arm] += 1
        if rng.random() < true_ctr[arm]:
            clicks[arm] += 1
            alpha[arm] += 1
        else:
            beta[arm] += 1
    return imps, clicks

def ci95(clicks, imps):
    p = clicks / imps
    return p, 1.96 * math.sqrt(p * (1 - p) / imps) * 100

SEED = 2
imps_ab, clicks_ab = run_ab(N, TRUE_CTR, SEED)
imps_bd, clicks_bd = run_bandit(N, TRUE_CTR, SEED)

total_ab, total_bd = sum(clicks_ab.values()), sum(clicks_bd.values())
best_possible = N * BEST_CTR

print(f"이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): {best_possible:,.0f}")
print(f"A/B   총 클릭 {total_ab:,}   후회 {best_possible - total_ab:6.1f}")
print(f"밴딧  총 클릭 {total_bd:,}   후회 {best_possible - total_bd:6.1f}")
print()
print(f"밴딧 최종 트래픽 배분 — 소재A(열세) {imps_bd['A']:,} : 소재B(우세) {imps_bd['B']:,}")
print()

for label, imps, clicks in [("A/B", imps_ab, clicks_ab), ("밴딧", imps_bd, clicks_bd)]:
    for arm in ("A", "B"):
        p_hat, half_width = ci95(clicks[arm], imps[arm])
        print(f"  [{label}] 소재{arm}: n={imps[arm]:6,}   관측CTR={p_hat*100:5.2f}%   95%CI=±{half_width:.3f}pp")

# 출력:
# 이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): 2,100
# A/B   총 클릭 2,085   후회   15.0
# 밴딧  총 클릭 2,022   후회   78.0
#
# 밴딧 최종 트래픽 배분 — 소재A(열세) 94,014 : 소재B(우세) 5,986
#
#   [A/B] 소재A: n=50,000   관측CTR= 2.05%   95%CI=±0.124pp
#   [A/B] 소재B: n=50,000   관측CTR= 2.12%   95%CI=±0.126pp
#   [밴딧] 소재A: n=94,014   관측CTR= 2.03%   95%CI=±0.090pp
#   [밴딧] 소재B: n= 5,986   관측CTR= 1.85%   95%CI=±0.342pp
```

결과가 앞 절과 정반대다. 밴딧은 노출의 94%(94,014건)를 소재A에 몰아줬다. 그런데 소재A는 진짜로는 더 나쁜 쪽(2.0%)이다. 총 클릭도 밴딧(2,022클릭)이 A/B(2,085클릭)보다 오히려 적다. 후회도 밴딧(78.0)이 A/B(15.0)의 5배가 넘는다. **아무것도 적응하지 않은 A/B가, 적응한다는 밴딧보다 결과가 더 좋았다.**

왜 이런 일이 생겼을까. 초반 노출 몇백 건에서 우연히 소재A의 클릭이 조금 더 몰렸다. 톰슨 샘플링은 그 우연한 우위를 진짜 우위로 착각했다. 그래서 트래픽을 계속 그쪽으로 더 보냈다. 차이가 0.1%p뿐이면 이런 우연이 진짜 신호와 잘 구별되지 않는다. 밴딧 알고리즘이 나쁜 게 아니다. **차이가 그 알고리즘이 구별할 수 있는 크기보다 작았을 뿐이다.**

더 불길한 대목은 밴딧 자신의 최종 관측치다. 소재A 2.03%, 소재B 1.85%로, 밴딧의 데이터만 보면 소재A가 이긴 것처럼 보인다. 방향 자체가 진실(B가 더 높음)과 반대다. 반면 A/B는 소재A 2.05%, 소재B 2.12%로 방향은 맞게 나왔다. 신뢰구간이 겹쳐서(둘 다 2.0%대 초반) "확실하다"고 말할 수는 없다. 그래도 최소한 방향은 뒤집히지 않았다. **효과가 작을 때는 밴딧도 못 찾는다** — 이게 이 절의 실무 감각이다.

## 4. 그래서 언제 무엇을 쓰나 — 결정 기준 여섯 가지

**여섯 가지 축에 우리 상황을 대입하면, A/B와 밴딧 중 무엇을 고를지 답이 나온다. 이 표가 이 글의 결론이다.**

앞의 두 시나리오를 종합하면 하나의 표로 정리된다. 1·3절에서 본 트레이드오프가 표의 각 줄에 그대로 깔려 있다.

| 판단축 | A/B 테스트가 낫다 | 밴딧이 낫다 |
|---|---|---|
| 목적 | 정말 효과가 있는지 검증해야 할 때 | 아는 동안 손해를 줄이며 수익을 내야 할 때 |
| 소재 수 | 2~5개 정도로 적을 때 | 수십 개 이상으로 많을 때 |
| 트래픽 규모 | 하루 방문자가 적어 표본이 빠듯할 때 | 트래픽이 커서 탐색할 여유가 있을 때 |
| 효과 크기 | 차이가 작아 "다르지 않다"고 정직하게 말해야 할 때 | 차이가 뚜렷해 빨리 확신할 수 있을 때 |
| 보고 대상 | 경영진·다른 팀·논문처럼 밖에 보고할 때 | 우리 팀 안의 운영 판단으로 그칠 때 |
| 비정상성 | 짧은 고정 기간 비교로 충분할 때 | 승자가 요일·시즌마다 바뀔 때 |

표의 네 번째 줄(효과 크기)이 3절과 바로 이어진다. 차이가 크면(2.0% vs 3.0%) 밴딧이 압도적으로 유리했다. 차이가 작으면(2.0% vs 2.1%) 밴딧은 오히려 A/B보다 못한 결과를 냈다. **그래서 "효과가 얼마나 클지 미리 감이 안 잡힌다"면, 밴딧보다 A/B로 시작하는 쪽이 안전하다.** 몇 주 지나 차이가 뚜렷해 보이면, 그때 밴딧으로 옮겨도 늦지 않다.

보고 대상 줄도 실무에서 자주 걸린다. 경영진에게 "이 기능이 전환율을 얼마나 올렸나"를 보고해야 한다면, 밴딧이 남긴 비대칭 표본으로는 깔끔한 답을 만들기 어렵다. 왜 그런지는 8절에서 다룬다. 반면 그냥 우리 팀 안에서 "이번 주는 어떤 배너를 더 밀까"를 정하는 정도라면, 밴딧의 흐릿한 신뢰구간은 큰 문제가 안 된다.

실무에서는 이 표의 두 칸을 섞어 쓰는 경우가 흔하다. 새 기능처럼 큰 의사결정은 A/B로 확실히 검증한다. 그 안의 소재·배너 최적화는 밴딧에 맡기는 식이다.

---

## 5. "전체 1등" 하나로는 부족할 때 — Contextual Bandit이 필요한 이유

**A/B도 밴딧도 결국 소재 하나로 수렴한다. 그런데 지면·유저마다 정답이 다르면, 승자 하나로는 손해를 본다.**

지금까지 표 ①과 2·3절의 코드는 전부 "전체 트래픽 기준 1등"을 찾는 이야기였다. A/B는 실험이 끝나면 승자 하나를 골라 그쪽에 전부 태운다. 밴딧은 실험 중에도 이미 그쪽으로 트래픽 대부분을 옮겨 둔다. 방식은 다르지만 목적지는 같다. **소재 하나로 수렴**하는 것이다.

그런데 지면이나 유저에 따라 정답이 다르면 이야기가 달라진다. 소재B가 전체 평균으로는 3.0%로 이겼다고 하자. 그런데 PC 상단 배너에서는 소재A가 더 잘 먹히고, 모바일 피드에서는 소재B가 훨씬 잘 먹히는 식으로 갈릴 수 있다.

| 지면 | 소재A 반응 | 소재B 반응 |
|---|---|---|
| PC 상단 배너 | 강함 | 약함 |
| 모바일 피드 | 약함 | 강함 |

이 표에서 "전체 평균 1등"만 믿고 소재B 하나만 모든 지면에 튼다면, PC 상단 배너에서는 계속 손해를 본다. A/B도 밴딧도 이 손해를 못 잡아낸다. 둘 다 "지면"이라는 정보를 애초에 안 보기 때문이다. 트래픽을 어떻게 나누든, 나누는 기준이 "전체"뿐이라는 한계는 그대로다.

이 지면·유저 정보를 **맥락(context)**이라 부른다. 맥락별로 다른 승자를 학습하는 밴딧을 **Contextual Bandit**이라 부른다. 맥락을 피처로 어떻게 넣고 학습하는지는 이 글의 범위를 넘는다. [UCB 계열](post.html?id=ucb-family)가 LinUCB로 확장하는 과정을 다룬다. [Disjoint LinUCB: 광고마다 계수를 따로 배우면 무엇이 달라지나](post.html?id=disjoint-linucb)이 점수 구성을 시각적으로 뜯어본다.

## 6. 담장 안에서는 트래픽을 마음대로 쪼갠다 [무대: 닫힌 생태계]

**노출을 직접 배정할 수 있는 닫힌 생태계에서는, A/B든 밴딧이든 원하는 대로 설계해 돌릴 수 있다.**

네이버·밴드처럼 노출·클릭·구매를 전부 자기 로그로 갖고 있는 플랫폼은 트래픽 배분권을 스스로 쥐고 있다. 이번 주 캠페인 노출을 반반 고정할지, 톰슨 샘플링으로 적응시킬지는 순전히 내부 판단이다. 이 글의 표 ①·2·3 시뮬레이션이 가정한 조건 그대로다.

그래서 이 무대에서는 4절의 표를 그대로 실무에 적용할 수 있다. 새 배너 기능을 켤지 말지처럼 밖에 보고해야 하는 결정은 A/B로 돌린다. 그 안에서 소재 몇 개를 계속 순환시키는 운영은 밴딧으로 돌리는 식이다. 두 실험을 동시에 여러 개 돌려도, 서로 트래픽을 침범하지 않도록 나누는 것 역시 플랫폼 내부에서 전부 통제할 수 있다.

다만 이 자유가 공짜는 아니다. 밴딧으로 트래픽을 몰아준 만큼, 진 소재에 대한 정보는 1절의 표 ①처럼 계속 흐릿하게 남는다. 나중에 "그때 소재A는 정말 얼마나 나빴나"를 다시 물으면, 밴딧 로그만으로는 좁은 표본 탓에 답하기 어렵다. 그래서 중요한 소재는 밴딧을 돌리는 동안에도 최소 표본을 보장하는 하한선을 둔다. 나중에 되짚어 볼 여지를 남겨 두는 실무 관행이 흔하다.

## 7. 열린 RTB에서는 실험이 매체 손 안에 있다 [무대: 열린 RTB]

**열린 RTB의 광고주는 노출 전체를 마음대로 나눌 수 없다. 자기 입찰·소재 범위 안에서만 실험이 가능하고, 그 결과에는 매체 쪽 알고리즘이 이미 섞여 있다.**

닫힌 생태계와 가장 다른 지점은 배분권이다. 광고주는 "이번 캠페인에 소재A와 소재B를 50:50으로 쓰겠다"고 정할 수 있다. 하지만 그 소재가 실제로 어떤 유저에게 얼마나 자주 노출될지는 거래소의 경매 로직과 매체의 인벤토리가 정한다. 광고주가 통제하는 건 "무엇을 입찰에 올릴까"까지다. "누가 그걸 보게 될까"는 매체의 몫이다.

게다가 매체 쪽도 가만히 있지 않는다. 대부분의 매체·거래소는 자기 지면에 어떤 광고를 보여줄지 이미 자체 랭킹 알고리즘으로 정하고 있고, 그 알고리즘도 일종의 밴딧이다. 광고주가 "우리는 A/B로 깔끔하게 비교하겠다"고 정해도 소용이 제한적이다. 매체가 소재A와 소재B의 노출 기회 자체를 성과에 따라 다르게 배분하면, 광고주의 50:50은 노출 단계에서 이미 깨져 있다.

그래서 열린 RTB에서 "우리 실험"의 결과는 우리 배분 결정과 매체 배분 결정이 겹친 결과다. 이 둘을 분리해서 보기 어렵다는 점이 담장 안과의 근본적 차이다. 광고주가 할 수 있는 최선은 소재별로 별도 캠페인·라인아이템을 만드는 것이다. 그렇게 매체 알고리즘의 개입을 최대한 줄이고, 노출·클릭 로그를 소재 단위로 세밀하게 쪼개 보는 정도가 현실적인 대응이다.

## 8. 밴딧 결과로 "A가 B보다 낫다"고 말해도 될까

**조심해야 한다. 밴딧이 스스로 트래픽을 옮기며 만든 표본은, 일반적인 유의성 검정이 가정하는 조건을 이미 깨고 있다.**

1절의 표 ①로 돌아가 보자. 밴딧이 남긴 소재A의 표본은 4,171건, 소재B는 95,829건이다. 이 표본 크기 자체가 "소재A가 초반에 밀렸다"는 관측 결과로 만들어진 값이다. 반면 A/B의 5만:5만은 결과와 무관하게 실험 전에 미리 정해 둔 값이다. 표본 크기·검정력 계산은 전부 이 전제 위에 서 있다. 표본 수를 결과와 무관하게 미리 고정한다는 전제다. 그 계산법 자체는 [랜덤 실험(RCT)](post.html?id=rct-randomized-experiment)에서 다뤘다.

밴딧은 이 전제를 정면으로 어긴다. 표본 수 자체가 결과의 함수이기 때문이다. 그래서 밴딧이 끝난 뒤 소재A·소재B의 관측 CTR에 곧바로 일반 z검정을 돌리면 문제가 생긴다. 신뢰구간이 실제보다 좁게, p값이 실제보다 작게 나온다. "우연히 유의해 보일 확률"을 5%로 맞춰 뒀다고 믿었는데, 실제로는 그보다 훨씬 자주 유의해 보이는 착시가 생긴다.

이 문제는 [랜덤 실험](post.html?id=rct-randomized-experiment)과 뿌리가 같다. 그 글의 "조기 중단(peeking)" 함정과 같은 종류다. 다만 밴딧은 실험 내내, 설계 자체로 이 짓을 계속한다는 점에서 훨씬 심하다.

:::deep 더 깊이 — 적응형 배정이 통계 검정을 어떻게 무너뜨리는가
일반 z검정이 성립하려면, 각 소재의 표본 수 $n_a$가 결과와 독립으로 미리 정해져 있어야 한다. 그래야 관측 CTR의 표준오차를 $\sqrt{p(1-p)/n_a}$로 계산하는 공식이 맞는다.

밴딧에서는 $n_a$ 자체가 그때까지의 클릭 여부에 의존한다. 소재가 초반에 운 좋게 클릭이 몰리면 $n_a$가 커진다. $n_a$가 커지면 그 우연한 우위가 더 많은 표본으로 "확인"된 것처럼 보인다. 표본과 결과가 서로를 강화하는 순환이 생기는 셈이다. 이 순환은 우연히 앞서가던 소재를 계속 더 유리하게 만든다. 그래서 최종 신뢰구간을 실제보다 좁게 착각하게 만든다.

이 문제에 대한 대응은 크게 두 갈래다. 하나는 **always-valid inference**다. 미리 정한 한 시점이 아니라 어느 시점에 멈추든 유효한 신뢰구간(confidence sequence)을 계산한다. 실험 중 아무 때나 들여다봐도 착시가 생기지 않도록 통계량 자체를 다시 설계하는 방법이다. 다른 하나는 **사후 보정(post-hoc correction)**이다. 밴딧이 만든 편향의 방향과 크기를 역으로 추정해 관측 CTR을 보정한다(예: 역확률 가중치, IPW). 혹은 실험 마지막에 일정 비율의 트래픽을 강제로 무작위 배정해, 그 구간만으로 별도 검정을 돌리는 방식도 있다.

실무에서 가장 흔한 절충은 후자다. 밴딧을 돌려 수익은 챙기되, 트래픽의 5~10%는 항상 무작위 홀드아웃으로 떼어 둔다. "A가 B보다 낫다"는 주장이 꼭 필요한 순간에는, 밴딧이 아니라 이 홀드아웃 조각으로만 검정한다.
:::

## 10. 헷갈리기 쉬운 점

- **"밴딧이 항상 낫다"는 틀렸다.** 3절에서 차이가 0.1%p로 작아지자 밴딧의 후회(78.0)가 A/B(15.0)보다 5배 넘게 컸다. 효과가 작을 때는 적응이 오히려 독이 될 수 있다.
- **밴딧 결과를 논문·보고서처럼 "A가 B보다 유의하게 낫다"고 쓰면 안 된다.** 8절에서 봤듯 적응형 배정은 표본 수 자체를 결과에 의존하게 만든다. 그래서 일반 유의성 검정의 전제를 깬다.
- **클릭이 많다고 더 잘 아는 게 아니다.** 표 ①에서 밴딧은 A/B보다 클릭은 더 벌었다. 하지만 진 소재(소재A)에 대한 신뢰구간은 오히려 3.7배 넓었다.
- **후회(regret) 숫자만 보고 우열을 매기면 안 된다.** 후회가 낮다는 건 그 시나리오에서 잘 적응했다는 뜻이다. 다음 시나리오(효과가 작은 경우)에서도 낮으리라는 보장은 아니다.
- **Contextual Bandit은 밴딧의 상위 호환이 아니라 다른 질문의 답이다.** "전체에서 뭐가 제일 좋나"에서 "이 지면·이 유저에게 뭐가 좋나"로 질문 자체가 바뀐다.
- **닫힌 생태계의 "마음대로"와 열린 RTB의 "매체 손 안"은 실험 설계의 자유도 차이다.** 같은 A/B·밴딧 알고리즘이라도, 열린 RTB에서는 매체의 자체 최적화가 이미 결과에 섞여 들어온다.
