새벽 3시에 알람이 울린다. 서버가 죽었다는 알람이다. 당직자가 재시작하면 5분 뒤 정상으로 돌아온다.

같은 새벽에 사고가 하나 더 있었다. 랭킹 모델이 쓰는 피처 하나가 어제부터 빈 값으로 들어온다. 모델은 오류를 내지 않는다. 200 OK로 답하고 그럴듯한 숫자를 내놓는데, 그 숫자가 틀렸다. 알람은 없고 대시보드는 초록색이다. 3주 뒤 리포트에서 매출이 8% 빠진 걸 발견한다.

> 한 줄 요약: 모델 장애는 비명을 지르지 않는다. 그래서 **입력·예측·라벨·비즈니스를 층으로 나눠 재고, 세그먼트로 쪼개 보고, 알람은 "몇 번 연달아 어긋났나"로 걸어야 한다.**

드리프트 종류와 재학습 전략은 [Online Learning과 지연 피드백](post.html?id=online-learning-delayed-feedback)에서 다뤘다. 이 글은 그 앞 단계, **버튼을 누를 때가 됐다는 걸 어떻게 아는지**만 본다.

## 1. 서버는 비명을 지르지만 모델은 조용히 나빠진다

**서버 장애는 실패로 드러나고, 모델 장애는 성공으로 위장한다.** 이 한 줄 차이가 감시 설계를 갈라놓는다.

서버가 죽으면 500 응답이 쏟아지고 큐가 쌓인다. 감시 도구는 원래 이런 "동작하지 않음"을 잡도록 만들어졌다. 반면 모델이 나빠질 때는 아무것도 실패하지 않는다. 요청은 다 성공하고 지연도 평소와 같고 예측값도 형식상 멀쩡하다. 숫자만 현실과 어긋나 있다.

그래서 모델 사고는 **돈으로 먼저 드러난다.** pCTR이 낮게 나오면 입찰가가 낮아지고 낙찰과 노출이 줄고 예산이 남는다. 높게 나오면 비싸게 사고 성과가 안 나온다. 어느 쪽이든 며칠 뒤 정산 리포트에서 발견하고, 그때는 손실이 확정된 뒤다. 게다가 모델은 **부분적으로만 나빠진다.** 전체 평균은 끝까지 멀쩡해 보인다(5절). 그러니 모델 감시는 **"어제와 같은 세상에서 어제와 같은 판단을 하고 있나"**를 묻는 일이다.

## 2. 네 층으로 나눠 재고, 빠른 층부터 본다 [무대: 공통]

**입력 → 예측 → 라벨 → 비즈니스. 사고는 이 순서로 번지고, 신호는 이 순서로 늦어진다.** 층으로 나누면 원인이 어느 층인지 좁혀지고, 어느 신호를 먼저 믿을지도 정해진다. 아래 표에서 가장 중요한 칸은 세 번째와 네 번째다. **라벨이 필요한 지표는 늦고, 필요 없는 지표는 즉시 나온다.**

| 층 | 무엇을 보나 | 라벨 필요 | 값이 굳는 시간 | 여기서 잡히는 사고 |
|---|---|---|---|---|
| 1층 입력 | 피처별 PSI, 결측률, 갱신 시각 | 아니오 | 즉시 | 피처 파이프라인 정지, 스키마 변경 |
| 2층 출력 | 예측 평균, 분위수, 양 끝 쏠림 | 아니오 | 즉시 | 모델 오배포, 피처 순서 어긋남 |
| 3층 라벨 | COPC, CTR, pCVR 편차 | 예 | 수십 분~수 일 | 랭킹 열화, 보정 붕괴, 전환 태그 유실 |
| 4층 비즈니스 | 노출량, 소진율, 매출 | 예 | 수 시간~1일 | 위 세 층의 결과가 모여 나타남 |

읽는 순서도 위에서 아래다. 1층이 흔들렸다면 원인은 데이터, 1층은 멀쩡한데 2층이 흔들렸다면 원인은 모델, 2층까지 멀쩡한데 3층이 흔들렸다면 세상이 변한 것이다. 이 순서를 지키면 반나절 걸릴 원인 추적이 10분에 끝난다. 반대로 매출부터 보는 팀이 많다. 하지만 4층은 모든 사고가 섞여 도착하는 하수구다. 매출이 5% 빠졌다는 사실만으로는 아무것도 알 수 없다.

## 3. PSI — 입력이 얼마나 달라졌나를 숫자 하나로

**PSI(Population Stability Index)는 "학습 때 보던 입력이 오늘도 같은 모양인가"를 한 숫자로 요약한다.** 라벨이 필요 없어서 가장 빠른 신호다. 값의 범위를 구간으로 나눠 학습 데이터와 오늘 데이터의 구간별 비율을 세고, 구간마다 두 비율의 차이를 로그비로 무게 달아 더한다.

$$\mathrm{PSI} = \sum_{i=1}^{k} (a_i - b_i)\,\ln\frac{a_i}{b_i}$$

$b_i$는 학습 때 $i$번 구간의 비율, $a_i$는 오늘의 비율이다. 아래는 **가상 데이터**로, 요청이 어느 지면에서 왔는지를 5구간으로 나눈 피처다.

| 지면 유형 | 학습 때 $b_i$ | 오늘 $a_i$ | $a_i - b_i$ | $\ln(a_i/b_i)$ | 항의 값 |
|---|---|---|---|---|---|
| 뉴스 피드 | 40% | 28% | -0.12 | -0.357 | 0.0428 |
| 검색 상단 | 25% | 22% | -0.03 | -0.128 | 0.0038 |
| 앱 배너 | 20% | 33% | +0.13 | +0.501 | 0.0651 |
| 동영상 | 10% | 12% | +0.02 | +0.182 | 0.0036 |
| 기타 | 5% | 5% | 0.00 | 0.000 | 0.0000 |
| **합** | 100% | 100% | | | **0.115** |

PSI는 0.115다. 앱 배너가 20%에서 33%로 늘고 뉴스 피드가 줄었다. 앱 배너 한 줄이 합의 절반을 넘겼다. 이렇게 **범인 구간까지 짚어 주는 것**이 PSI의 장점이다.

```python
# PSI(Population Stability Index): 학습 때 본 입력과 오늘 입력이 얼마나 다른지 한 숫자로.
import random
import math

random.seed(42)  # 돌릴 때마다 같은 결과가 나오게 고정

def make_edges(sample, n_bins=10):
    """학습 표본을 같은 개수씩 담는 십분위로 자르고 그 경계만 돌려준다."""
    s = sorted(sample)
    # 경계는 학습 때 한 번만 정하고 모델과 함께 저장한다. 매일 다시 자르면 PSI가 늘 0이 된다.
    return [s[len(s) * i // n_bins] for i in range(1, n_bins)]

def to_shares(sample, edges):
    """표본을 구간별 '비율'로 바꾼다. PSI는 개수가 아니라 비율로 잰다."""
    counts = [0] * (len(edges) + 1)
    for x in sample:
        k = 0
        while k < len(edges) and x >= edges[k]:
            k += 1                       # x가 몇 번째 구간인지 찾는다
        counts[k] += 1
    return [c / len(sample) for c in counts]

def psi(base, now, floor=1e-4):
    """구간마다 (오늘비율 - 학습비율) x ln(오늘비율/학습비율) 을 더한다."""
    total = 0.0
    for b, a in zip(base, now):
        b, a = max(b, floor), max(a, floor)   # 비율 0이면 로그가 발산하므로 바닥을 깐다
        total += (a - b) * math.log(a / b)
    return total

# 학습 때 본 피처 하나. '유저의 최근 7일 광고 반응 점수'라 하자(평균 0, 표준편차 1).
N = 200_000
train = [random.gauss(0.0, 1.0) for _ in range(N)]
edges = make_edges(train, 10)
base = to_shares(train, edges)

# 오늘 입력의 평균이 조금씩 밀린 네 경우를 '같은 경계'로 재 본다.
print("평균이동   PSI    구간별최대차이  10%에서 2%p 이상 벗어난 구간")
for shift in (0.10, 0.23, 0.40, 0.57):
    now = to_shares([random.gauss(shift, 1.0) for _ in range(N)], edges)
    max_gap = max(abs(a - b) * 100 for b, a in zip(base, now))   # PSI가 감추는 실제 차이
    off = sum(1 for a in now if abs(a - 0.10) > 0.02)            # 10%에서 크게 벗어난 구간 수
    print(f"  {shift:+.2f}   {psi(base, now):.3f}      {max_gap:4.1f}%p        {off}개 / 10개")

# 사고가 없어도 표본이 작으면 PSI가 저절로 올라간다. 임계값의 함정이 여기다.
print()
print("표본크기   사고가 없는데도 나오는 PSI (같은 분포에서 20번 뽑아 비교)")
for n in (100, 300, 1_000, 10_000, 200_000):
    vals = sorted(psi(base, to_shares([random.gauss(0.0, 1.0) for _ in range(n)], edges))
                  for _ in range(20))
    print(f"{n:7d}    평균 {sum(vals) / len(vals):.3f}   최댓값 {vals[-1]:.3f}")

# 출력:
# 평균이동   PSI    구간별최대차이  10%에서 2%p 이상 벗어난 구간
#   +0.10   0.009       1.7%p        0개 / 10개
#   +0.23   0.050       4.5%p        4개 / 10개
#   +0.40   0.149       8.7%p        6개 / 10개
#   +0.57   0.303      13.6%p        8개 / 10개
#
# 표본크기   사고가 없는데도 나오는 PSI (같은 분포에서 20번 뽑아 비교)
#     100    평균 0.098   최댓값 0.169
#     300    평균 0.029   최댓값 0.065
#    1000    평균 0.009   최댓값 0.019
#   10000    평균 0.001   최댓값 0.002
#  200000    평균 0.000   최댓값 0.000
```

**PSI 0.05는 구간별로 최대 4.5%p 차이**고 십분위 하나가 10%에서 14.5%가 된 정도다. **0.15는 8.7%p**, **0.30은 13.6%p**다. 흔히 쓰는 임계값은 **0.1과 0.25**다. 0.1 미만은 안정, 0.25 초과는 조치. 신용 스코어링 업계의 관행이고 통계적 유도가 있는 값은 아니다. 두 방향으로 틀린다. 첫째, 구간 수를 늘리면 같은 차이도 크게 나오니 임계값과 구간 수를 같이 못 박아야 한다. 둘째, **표본이 작으면 사고가 없어도 값이 올라간다.** 같은 분포끼리 비교했는데 100건에서 PSI 평균이 0.098이었다. 임계값 0.1이면 아무 일 없이 절반쯤 울린다. 세그먼트별 PSI에는 최소 표본 수 조건이 반드시 붙어야 한다.

### PSI가 못 잡는 것

**PSI는 "입력이 달라졌나"만 본다. "입력과 정답의 관계가 달라졌나"는 못 본다.** 경쟁사가 같은 지면에 더 좋은 소재를 붓기 시작했다고 하자. 우리 입력은 안 변했으니 PSI는 0에 가까운데, 모델은 예전 CTR을 계속 예측하고 COPC는 무너진다. PSI 하나로는 부족하다. 피처를 하나씩 따로 재니 **결합 분포도 못 본다.** 봇 트래픽처럼 "새벽에 PC로 들어오는 요청"만 10배가 되면 각 피처의 PSI는 조용하다.

## 4. 예측 분포 감시 — 라벨을 기다리지 않는다

**예측값의 평균과 분위수를 보는 것이 라벨을 기다리는 것보다 며칠 빠르다.** 라벨은 나중에 오지만 예측은 지금 있다.

볼 것은 다섯 개다. 예측 평균, 중위수, 상위 1%, 하위 1%, 기본값으로 대체된 요청의 비율. 분위수를 같이 보는 이유가 있다. 피처가 통째로 비면 모델은 거의 같은 숫자만 내놓아서, 평균은 멀쩡한데 분위수가 붕괴한다. 아래는 40일차에 피처가 깨져 예측 평균이 1.56%로, 진짜 전환율은 1.40%로 떨어진 상황이다.

```python
# 예측 분포 감시와 라벨 기반 감시 중 무엇이 사고를 먼저 잡는지 굴려 본다.
import random
import math

random.seed(42)

DAYS, INCIDENT, CLICKS = 60, 40, 20_000   # 60일 시뮬, 40일차에 사고, 하루 클릭 2만
CVR_OK, CVR_BAD = 0.0200, 0.0140          # 진짜 전환율 2.00% -> 1.40%
PRED_OK, PRED_BAD = 0.0200, 0.0156        # 모델 예측 평균 2.00% -> 1.56%
# 클릭 뒤 k일째 도착하는 전환 비율. 금·토 클릭은 결제가 주말 뒤로 밀려 앞쪽이 느리다.
DELAY_WEEKDAY = [0.37, 0.23, 0.15, 0.10, 0.06, 0.04, 0.03, 0.02]   # 합 1.00
DELAY_WEEKEND = [0.28, 0.18, 0.16, 0.13, 0.10, 0.07, 0.05, 0.03]   # 합 1.00
MATURITY_1D = 0.57      # 감시 코드가 쓰는 '하루 지나면 57%는 온다'는 고정 가정
BASELINE, TOL = 0.0200, 0.10   # 기준선 2.00%, 기준선보다 10% 이상 낮으면 그 창은 위반

def binom(n, p):
    """이항 표본을 정규근사로 뽑는다. numpy 없이 표본 노이즈만 흉내낸다."""
    return max(0, round(random.gauss(n * p, math.sqrt(n * p * (1 - p)))))

def curve(day):
    """그 날 클릭의 지연 곡선. 0=월요일이므로 금(4)·토(5)가 느린 곡선을 쓴다."""
    return DELAY_WEEKEND if day % 7 in (4, 5) else DELAY_WEEKDAY

# 날마다 진짜 전환 수를 뽑고, 지연 곡선에 따라 도착일로 흘려 놓는다.
arrived = [[0.0] * (DAYS + 8) for _ in range(DAYS)]    # arrived[클릭일][도착일]
pred_mean = [0.0] * DAYS
for d in range(DAYS):
    conv = binom(CLICKS, CVR_BAD if d >= INCIDENT else CVR_OK)
    for k, share in enumerate(curve(d)):
        arrived[d][d + k] = conv * share
    base = PRED_BAD if d >= INCIDENT else PRED_OK
    pred_mean[d] = base + random.gauss(0, 0.00008)      # 예측 평균은 흔들림이 아주 작다

def cum(click_day, upto):
    """click_day에 누른 클릭 중 upto 날까지 도착한 전환 수."""
    return sum(arrived[click_day][:upto + 1])

# 감시 방식 세 가지. 각 함수는 관측일 D에서 '지금 볼 수 있는 값'만 돌려준다.
def watch_pred(D):
    return pred_mean[D]                                # 라벨이 없어도 그날 값을 그날 본다

def watch_settled(D):
    d = D - 7                                          # 7일 지나 전환이 다 들어온 클릭일
    return None if d < 0 else cum(d, D) / CLICKS

def watch_corrected(D):
    d = D - 1                                          # 어제 클릭을 도착률로 나눠 되돌린다
    return None if d < 0 else cum(d, D) / (CLICKS * MATURITY_1D)

def run(name, fn):
    """최근 3창 중 2창이 위반이면 알람. 연달아 울린 것은 한 건으로 묶어 센다."""
    bad = []
    for D in range(DAYS):
        v = fn(D)
        bad.append(v is not None and v < BASELINE * (1 - TOL))
    fired = [D for D in range(2, DAYS) if sum(bad[D - 2:D + 1]) >= 2]
    after = [D for D in fired if D >= INCIDENT]
    false_events = sum(1 for D in fired if D < INCIDENT and (D - 1) not in fired)
    day = f"{after[0]}일차" if after else "-"
    lag = f"{after[0] - INCIDENT}일 뒤" if after else "못 잡음"
    print(f"{name:22s} {day:>7s}  {lag:>7s}   사고 전 오탐 {false_events}건")

print("감시 방식                 알람일   사고 후   (60일 시뮬, 사고는 40일차)")
run("예측 평균 (라벨 불필요)", watch_pred)
run("성숙도 보정 (어제 창)", watch_corrected)
run("확정 창 (7일 대기)", watch_settled)

# 같은 사고를 세 방식이 며칠차에 '숫자로' 어떻게 봤는지 나란히 찍어 본다.
print()
print("관측일  예측평균   보정CVR   확정CVR")
for D in (39, 40, 41, 45, 47, 48):
    s = watch_settled(D)
    print(f"{D:5d}   {watch_pred(D) * 100:6.3f}%   {watch_corrected(D) * 100:6.3f}%   "
          f"{'-' if s is None else format(s * 100, '6.3f') + '%'}")

# 출력:
# 감시 방식                 알람일   사고 후   (60일 시뮬, 사고는 40일차)
# 예측 평균 (라벨 불필요)            41일차     1일 뒤   사고 전 오탐 0건
# 성숙도 보정 (어제 창)             41일차     1일 뒤   사고 전 오탐 5건
# 확정 창 (7일 대기)              48일차     8일 뒤   사고 전 오탐 0건
#
# 관측일  예측평균   보정CVR   확정CVR
#    39    2.006%    2.205%    2.095%
#    40    1.558%    1.610%    2.005%
#    41    1.551%    1.081%    1.970%
#    45    1.567%    1.495%    2.095%
#    47    1.563%    1.150%    1.340%
#    48    1.560%    1.190%    1.245%
```

**예측 평균은 41일차에, 확정 라벨은 48일차에 잡았다. 7일 차이다.** 그 7일 동안 잘못된 입찰가로 광고를 계속 산다. 40일차에 예측 평균은 이미 1.558%인데 확정 CVR은 2.005%로 멀쩡하다. 확정 창은 7일 전 클릭을 보고 있어서다.

가운데 열이 세 번째 선택지다. **성숙도 보정**은 어제 클릭을 "하루면 57% 도착한다"로 나눠 되돌린다. 41일차에 잡았으니 빠르지만 사고 전 오탐이 5건이다. 지연 곡선이 요일마다 달라 금·토 클릭엔 평균 도착률이 안 맞는다. 그래서 실무는 **예측 분포를 1차 감시로, 확정 라벨을 최종 검산으로** 쓴다.

### 담장 안은 라벨이 빨리 오고 세그먼트가 확실하다 [무대: 닫힌 생태계]

담장 안 DSP는 노출·클릭·전환 로그가 모두 자사 안에 있다. 전환 유실이 사실상 없고 지연이 짧고, 로그인 기반이라 세그먼트 축이 흔들리지 않는다. 15분 창 COPC를 지면×기기로 걸고 전환도 6시간 성숙으로 판단한다. 대신 지면 수가 적어 **한 지면의 비중이 크다.** 큰 지면이 흔들리면 전체가 같이 흔들려 나머지 이상이 그 뒤에 숨는다.

### 열린 RTB는 대기 시간을 먼저 정해야 한다 [무대: 열린 RTB]

열린 RTB는 반대다. 전환은 광고주 서버나 MMP가 **포스트백**으로 알려 줘야 안다. 늦게 오고 일부는 안 온다. 그래서 알람을 걸기 전에 **성숙 대기 시간을 먼저 정해야 한다.** "클릭 후 며칠이면 믿는다"를 광고주 유형별로 못 박는 일이고, 게임 앱 설치는 하루, 보험 상담은 7일처럼 갈린다. **영구 유실률은 지연과 분리해 추정한다.** 안 오는 전환을 성숙도로 나누면 지표가 반대로 부푼다([Negative Sampling과 편향](post.html?id=negative-sampling-bias) 참고).

## 5. 전체는 멀쩡한데 한 지면만 무너진다

**전체 지표는 과대예측과 과소예측을 서로 지운다.** 그래서 전체 숫자만 보는 감시는 반쪽 사고를 통째로 놓친다.

COPC는 실제 클릭을 예측 클릭으로 나눈 값이고 1보다 크면 과소예측이다. 정의와 보정 기법은 [Calibration](post.html?id=calibration)에서 다뤘다. 여기서는 **어느 단위로 집계하나**만 본다. 아래는 **가상 데이터**다.

| 지면 | 노출 | 예측 CTR | 실제 CTR | COPC | 클릭 차이 |
|---|---|---|---|---|---|
| 뉴스 피드 | 4,000,000 | 2.00% | 1.90% | 0.950 | -4,000 |
| 검색 상단 | 1,500,000 | 5.00% | 5.73% | 1.146 | +10,950 |
| 앱 배너 | 2,000,000 | 1.00% | 0.62% | 0.620 | -7,600 |
| 동영상 인스트림 | 800,000 | 0.80% | 1.20% | 1.500 | +3,200 |
| 쇼핑 추천 | 1,200,000 | 3.00% | 3.15% | 1.050 | +1,800 |
| 신규 지면 X | 300,000 | 2.50% | 1.05% | 0.420 | -4,350 |
| **합계** | **9,800,000** | | | **1.000** | **0** |

전체 COPC 1.000은 완벽히 보정된 모델처럼 보인다. 그런데 지면별로는 0.420부터 1.500까지 흩어져 있다. 앱 배너에서는 클릭을 7,600건 과하게 기대했고 검색 상단에서는 10,950건을 놓쳤다. 두 오차가 서로를 지운 결과가 1.000이다. 심슨의 역설은 **방향이 뒤집히는** 반면 여기서는 **상쇄되어 사라진다.** 뒤집히면 이상함을 알아채는데, 사라지면 아무도 느끼지 못한다.

```python
# 전체 COPC는 1.000인데 지면별로는 0.42~1.50으로 흩어진 상황을 계산한다.
# COPC = 실제 클릭 / 예측 클릭. 1보다 크면 모델이 과소예측한 것이다.
import math

# 가상 데이터: (지면 이름, 노출 수, 예측 CTR, 실제 CTR)
placements = [
    ("뉴스 피드",     4_000_000, 0.0200, 0.0190),
    ("검색 상단",     1_500_000, 0.0500, 0.0573),
    ("앱 배너",       2_000_000, 0.0100, 0.0062),
    ("동영상 인스트림",  800_000, 0.0080, 0.0120),
    ("쇼핑 추천",     1_200_000, 0.0300, 0.0315),
    ("신규 지면 X",     300_000, 0.0250, 0.0105),
]
# 지면마다 (이름, 노출, 예측 클릭, 실제 클릭, COPC)로 펼친다.
rows = [(n, imp, imp * pc, imp * ac, ac / pc) for n, imp, pc, ac in placements]
total_pred = sum(r[2] for r in rows)
total_act = sum(r[3] for r in rows)

print("지면              예측클릭    실제클릭   COPC   차이(클릭)")
for name, imp, pred, act, copc in rows:
    print(f"{name:14s} {pred:9,.0f} {act:10,.0f}  {copc:5.3f}  {act - pred:+9,.0f}")
print(f"{'합계':14s} {total_pred:9,.0f} {total_act:10,.0f}  {total_act / total_pred:5.3f}")

# 합계가 멀쩡해 보이는 이유: 과대예측 몫과 과소예측 몫이 서로를 지운다.
over = sum(r[2] - r[3] for r in rows if r[4] < 1)      # 예측이 실제보다 많았던 클릭 수
under = sum(r[3] - r[2] for r in rows if r[4] > 1)     # 예측이 실제보다 적었던 클릭 수
print()
print(f"과대예측 합계 {over:,.0f} 클릭 / 과소예측 합계 {under:,.0f} 클릭")
print(f"전체 예측 클릭의 {over / total_pred * 100:.1f}%가 엉뚱한 지면에 얹혀 있다")

# 전체 지표 대신 올려야 하는 숫자들. 가중 절대 편차는 상쇄가 일어나지 않는다.
wmad = sum(r[2] / total_pred * abs(r[4] - 1) for r in rows)   # 예측 클릭으로 무게를 단다
worst = max(rows, key=lambda r: abs(r[4] - 1))
breach = [r for r in rows if abs(r[4] - 1) > 0.10]            # 10% 넘게 틀어진 지면
print()
print(f"전체 COPC 편차          : {abs(total_act / total_pred - 1) * 100:.1f}%  (알람 안 울림)")
print(f"가중 평균 절대 편차     : {wmad * 100:.1f}%  (알람 울림)")
print(f"최악 세그먼트           : {worst[0]} COPC {worst[4]:.3f}")
print(f"10% 넘게 틀어진 지면    : {len(breach)}개, "
      f"예측 클릭의 {sum(r[2] for r in breach) / total_pred * 100:.1f}%")

# 세그먼트를 잘게 쪼갤 때의 바닥 노이즈.
# 실제 클릭이 포아송이면 COPC의 표준편차는 대략 1/sqrt(예측 클릭 수)다.
print()
print("예측클릭   COPC 노이즈 폭(95%)   10% 임계값이 잡는 것")
for n in (100, 400, 10_000):
    band = 1.96 / math.sqrt(n)
    print(f"{n:8,d}   +-{band * 100:5.1f}%            {'노이즈' if band > 0.10 else '실제 이상'}")
print(f"임계값 10%가 노이즈에 안 걸리는 최소 클릭 수: {math.ceil((1.96 / 0.10) ** 2):,d}건")

# 출력:
# 지면              예측클릭    실제클릭   COPC   차이(클릭)
# 뉴스 피드             80,000     76,000  0.950     -4,000
# 검색 상단             75,000     85,950  1.146    +10,950
# 앱 배너              20,000     12,400  0.620     -7,600
# 동영상 인스트림           6,400      9,600  1.500     +3,200
# 쇼핑 추천             36,000     37,800  1.050     +1,800
# 신규 지면 X            7,500      3,150  0.420     -4,350
# 합계               224,900    224,900  1.000
#
# 과대예측 합계 15,950 클릭 / 과소예측 합계 15,950 클릭
# 전체 예측 클릭의 7.1%가 엉뚱한 지면에 얹혀 있다
#
# 전체 COPC 편차          : 0.0%  (알람 안 울림)
# 가중 평균 절대 편차     : 14.2%  (알람 울림)
# 최악 세그먼트           : 신규 지면 X COPC 0.420
# 10% 넘게 틀어진 지면    : 4개, 예측 클릭의 48.4%
#
# 예측클릭   COPC 노이즈 폭(95%)   10% 임계값이 잡는 것
#      100   +- 19.6%            노이즈
#      400   +-  9.8%            실제 이상
#   10,000   +-  2.0%            실제 이상
# 임계값 10%가 노이즈에 안 걸리는 최소 클릭 수: 385건
```

**전체 COPC 편차는 0.0%인데 가중 평균 절대 편차는 14.2%다.** 후자는 세그먼트별 편차의 절대값을 예측 클릭으로 무게 달아 평균한 값이라 상쇄가 없다. 전체 지표 하나만 올릴 수 있다면 이 숫자가 낫다.

**예측 클릭 385건 미만에 10% 임계값을 걸면 노이즈를 재는 것이다.** 100건짜리 COPC는 아무 일이 없어도 ±19.6% 안에서 흔들린다. 그래서 축은 3개까지만 쓰고, 조합은 트래픽 상위 30~50개만 감시하고, 세그먼트당 예측 클릭 1,000건 이상을 조건으로 둔다.

## 6. 알람을 설계하는 네 개의 손잡이

**너무 민감하면 아무도 안 보고, 너무 둔하면 늦게 안다.** 손잡이는 임계값, 연속 위반 규칙, 최소 표본 조건, 억제 규칙이다. 앞의 두 개로 교환비를 재 보자. 30일 동안 시간당 COPC를 보고, 그 사이 사고가 8건 있었다.

```python
# 알람 설계의 두 손잡이 — 임계값과 '연속 몇 번' 규칙 — 을 같은 데이터에 돌려 본다.
# 지표는 시간당 COPC(실제 클릭 / 예측 클릭). 정상이면 1.00 근처다.
import random
import math

random.seed(42)

DAYS, PER_DAY = 30, 24
N = DAYS * PER_DAY                       # 감시 창 720개 = 30일 x 시간당 1창
PRED_CLICKS = 4_000                      # 창 하나에 담기는 예측 클릭 수
MIX_SD = 0.030                           # 트래픽 믹스가 시간마다 흔들리는 폭(사고 아님)
SAMPLE_SD = 1 / math.sqrt(PRED_CLICKS)   # 클릭 수가 유한해서 생기는 표본 노이즈
# 실제로 일어난 사고 8건: (시작 창, 지속 창 수, COPC 낙폭). 절반은 -7%, 절반은 -16%다.
INCIDENTS = [(72, 6, 0.07), (180, 6, 0.16), (300, 6, 0.07), (408, 6, 0.16),
             (504, 6, 0.07), (576, 6, 0.16), (636, 6, 0.07), (684, 6, 0.16)]

truth = [1.0] * N                        # 사고가 없을 때의 진짜 COPC
incident_windows = set()
for start, length, drop in INCIDENTS:
    for i in range(start, start + length):
        truth[i] -= drop
        incident_windows.add(i)

# 대시보드에 찍히는 값 = 진짜 값 + 믹스 변동 + 표본 노이즈
observed = [truth[i] + random.gauss(0, MIX_SD) + random.gauss(0, SAMPLE_SD)
            for i in range(N)]

def score(th, need=1, span=1):
    """임계값 th, '최근 span창 중 need창 위반' 규칙일 때의 오탐·적발·감지 지연."""
    breach = [abs(v - 1.0) > th for v in observed]
    fired = [i for i in range(span - 1, N) if sum(breach[i - span + 1:i + 1]) >= need]
    fset = set(fired)
    # 사고 창이 아닌데 울린 것은 오탐. 연달아 울린 것은 한 건으로 묶는다.
    false_events = sum(1 for i in fired
                       if i not in incident_windows and (i - 1) not in fset)
    small = big = 0
    lags = []
    for start, length, drop in INCIDENTS:
        # 사고 창 안이나 끝난 뒤 2창 안에 울렸으면 그 사고를 잡은 것으로 본다.
        hit = [i for i in fired if start <= i < start + length + 2]
        if hit:
            lags.append(hit[0] - start)
            if drop < 0.10:
                small += 1               # 작은 사고(-7%)를 잡은 횟수
            else:
                big += 1                 # 큰 사고(-16%)를 잡은 횟수
    lag = f"{sum(lags) / len(lags):.1f}창" if lags else "-"
    return false_events, small, big, lag

print(f"창 {N}개(30일) · 사고 8건 · 사고 창 {len(incident_windows)}개")
print("임계값  오탐  하루알람   작은사고(-7%)  큰사고(-16%)  평균감지")
for th in (0.03, 0.05, 0.08, 0.10, 0.15, 0.20):
    fe, small, big, lag = score(th)
    print(f" {th:.2f}  {fe:4d}건  {fe / DAYS:5.2f}회   {small:6d}/4건      "
          f"{big:4d}/4건    {lag:>6s}")

# 이제 임계값을 5%로 고정하고 '몇 번 연달아 위반해야 부를까'만 바꿔 본다.
print()
print("임계값 5% 고정 · 알람 규칙만 교체")
print("규칙          오탐   작은사고  큰사고  평균감지")
for name, need, span in (("1창 즉시", 1, 1), ("3창 중 2창", 2, 3),
                         ("3창 연속", 3, 3), ("6창 중 4창", 4, 6)):
    fe, small, big, lag = score(0.05, need, span)
    print(f"{name:11s} {fe:4d}건   {small:4d}/4건  {big:3d}/4건  {lag:>6s}")

# 출력:
# 창 720개(30일) · 사고 8건 · 사고 창 48개
# 임계값  오탐  하루알람   작은사고(-7%)  큰사고(-16%)  평균감지
#  0.03   153건   5.10회        4/4건         4/4건      0.1창
#  0.05    80건   2.67회        4/4건         4/4건      0.2창
#  0.08    14건   0.47회        4/4건         4/4건      0.6창
#  0.10     1건   0.03회        3/4건         4/4건      0.4창
#  0.15     0건   0.00회        0/4건         4/4건      0.0창
#  0.20     0건   0.00회        0/4건         3/4건      2.7창
#
# 임계값 5% 고정 · 알람 규칙만 교체
# 규칙          오탐   작은사고  큰사고  평균감지
# 1창 즉시         80건      4/4건    4/4건    0.2창
# 3창 중 2창       26건      4/4건    4/4건    1.1창
# 3창 연속          0건      3/4건    4/4건    2.3창
# 6창 중 4창        1건      3/4건    4/4건    2.9창
```

**임계값 3%는 하루 5.1번 울린다.** 사고는 다 잡지만 한 달에 153번 울리는 알람을 볼 사람은 없다. **15%는 헛울리지 않는데 작은 사고 4건을 전부 놓친다.** 이 데이터에서는 8%가 균형이 가장 좋다. 하루 0.47번 울리고 사고 8건을 다 잡았다. 중요한 건 8%라는 숫자가 아니라 **이 표를 자기 데이터로 만들어 보는 습관**이다.

두 번째 표는 규칙만 바꾼 결과다. **1창 즉시는 오탐 80건, 3창 연속은 오탐 0건이다.** 대신 감지가 0.2창에서 2.3창으로 늘고 작은 사고 하나를 놓친다. 중간인 "3창 중 2창"이 가장 많이 쓰인다. 오탐이 3분의 1로 줄면서 사고 8건을 다 잡고 감지는 1.1창만 늦는다.

**최소 표본 조건**은 3·5절에서 계산한 그 조건이다. 표본이 모자란 창은 0으로 찍지 말고 "판정 불가"로 남긴다. **억제 규칙**은 울려도 부르지 않는 경우다. 배포 직후 30분은 지표가 원래 흔들리니 억제하고, 상위 지표가 울렸으면 하위 지표는 묶어 보낸다. 기준선은 같은 요일 같은 시간의 최근 4주 중위수로 잡는다. "전일 대비"는 요일 효과에 걸린다.

:::deep 지표 50개를 매일 보면 오탐은 반드시 난다
지표 12개에 세그먼트 20개를 곱하면 240칸, 여기에 시간당 창 24개를 곱하면 하루 5,760번 판정한다. 창 하나의 오탐 확률이 0.3%라 하자. 3시그마에 대응하는 흔한 값이다. 하루 기대 오탐은 **17.3건**이다. 사고가 없는 날에도 17번 울린다. 감시 품질 문제가 아니라 곱셈 문제다.

손잡이는 세 개다. **판정 수를 줄인다.** 호출까지 갈 지표는 3~5개로 제한한다. **임계값을 올린다.** 오탐 확률 0.03%면 하루 1.7건이다. **연속 규칙을 얹는다.** "3창 연속"이면 유효 오탐 확률이 세제곱으로 줄어 사실상 0이 된다. 본페로니 보정은 그대로 쓰기 어렵다. 지표들이 독립이 아니어서 같은 사고가 여러 지표를 함께 움직이기 때문이다. 그래서 실무는 계층을 나눈다. 호출은 비즈니스 영향이 확인된 소수만, 경고는 층별 대표 지표만, 나머지는 조회용이다.
:::

## 7. 감시 대시보드에 실제로 무엇을 올리나

**대시보드는 "모든 숫자"가 아니라 "당직자가 새벽에 3분 안에 읽을 수 있는 숫자"여야 한다.** 화면 세 장으로 나눈다.

첫 장은 **요약**이다. 예측 평균 변화율, 피처 PSI 최댓값, 최근 확정 창 COPC, 세그먼트 가중 평균 절대 편차, 노출량 변화율. 이 다섯 개만 크게 두고 세 색으로 칠한다. 빨강이 없으면 더 볼 필요가 없어야 한다. 둘째 장은 **층별 상세**로 2절의 네 층을 세로로 쌓고 최근 24시간 추이를 그린다. 어느 층에서 처음 꺾였는지 찾는 화면이다. 셋째 장은 **세그먼트 히트맵**으로 가로축 지면, 세로축 시간, 색은 COPC 편차다.

| 층 | 지표 | 집계 단위 | 갱신 | 시작 임계값 | 등급 |
|---|---|---|---|---|---|
| 입력 | 피처별 PSI | 지면 × 1시간 | 15분 | 0.10 / 0.25 | 경고·호출 |
| 입력 | 결측·기본값 대체율 | 피처 × 1시간 | 5분 | 평소의 3배 | 호출 |
| 출력 | 예측 평균·분위수 | 모델 × 15분 | 5분 | 평균 ±8% | 호출 |
| 라벨 | COPC | 지면 × 1시간 | 15분 | ±8%, 3창 중 2창 | 호출 |
| 라벨 | 가중 평균 절대 편차 | 전체 | 1시간 | 10% | 경고 |
| 비즈니스 | 노출량·소진율 | 캠페인 유형 × 1시간 | 15분 | -15% | 경고 |

무엇을 **안** 올릴지도 정해야 한다. AUC를 매시간 계산하는 대시보드는 대개 실패한다. 비용이 크고 한 시간 표본에서는 흔들림이 커서 읽히지 않는다. 마지막으로 주 1회 팀이 같이 훑는 시간을 두자. 알람에 안 걸린 느린 열화가 그때 눈에 걸린다.

## 한눈 정리

| 질문 | 답 | 근거가 되는 숫자 |
|---|---|---|
| 무엇을 먼저 보나 | 라벨이 필요 없는 입력·예측 층 | 확정 라벨보다 7일 빠름(4절) |
| PSI를 언제 믿을 수 없나 | 표본이 작을 때, 관계만 변했을 때 | 표본 100건이면 사고 없이도 0.098 |
| 전체 지표만 보면 왜 위험한가 | 과대·과소예측이 서로 지워지므로 | 전체 1.000, 지면별 0.42~1.50 |
| 세그먼트는 얼마나 쪼개나 | 예측 클릭 1,000건 이상만 | 385건 미만은 10% 임계값이 노이즈 |
| 오탐을 어떻게 줄이나 | 임계값과 연속 위반 규칙 | 3창 중 2창으로 오탐 80건 → 26건 |

## 헷갈리기 쉬운 점

**PSI가 낮으면 모델이 건강하다.** 아니다. PSI는 입력만 본다. 입력이 그대로인데 세상의 반응이 바뀌면 PSI는 0에 가깝고 모델은 틀린다. 필요조건이지 충분조건이 아니다.

**전체 지표가 정상이면 세그먼트도 정상이다.** 아니다. 5절가 반례다. 전체 COPC가 1.000인데 예측 클릭의 48.4%가 10% 넘게 틀어져 있었다.

**라벨 기반 지표가 정확하니 그것만 보면 된다.** 정확하지만 늦다. 4절에서 확정 라벨은 사고를 8일 뒤에 알렸다. 정확한 지표와 빠른 지표는 둘 다 필요하다.

**드리프트가 감지되면 바로 재학습하면 된다.** 재학습은 여러 조치 중 하나다. 피처 파이프라인 사고라면 재학습이 오염된 데이터를 학습에 넣는다. 원인 층을 먼저 확인한 뒤 롤백·재보정·재학습 중에서 고른다.
