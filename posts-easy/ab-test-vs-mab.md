광고 소재 2개가 있고 진짜 클릭률은 하나가 2.0%, 다른 하나가 3.0% 입니다. 소재(creative)는 광고로 화면에 실제로 나가는 광고물 하나를 가리킵니다. 노출(impression)은 광고가 유저 화면에 한 번 보이는 일을 1건으로 세는 단위입니다. 클릭률(CTR, Click-Through Rate)은 노출 가운데 클릭이 난 비율이라 높을수록 좋습니다. 다만 두 진짜 클릭률은 소재가 본래 가진 값일 뿐 팀이 미리 아는 값이 아니므로, 이번 주에 쓸 노출 10만 건을 두 소재에 나눠 보여 주면서 알아내야 합니다.

팀 회의에서는 노출을 어떻게 나눌지를 두고 의견이 두 가지로 나뉩니다. 한쪽은 "반반 나눠서 일주일 다 채우고 그때 정하자"고 하고 다른 쪽은 "일단 돌리면서 잘 나오는 쪽으로 옮기자"고 합니다. 두 방법 모두 "실험"이라고 부르지만 일주일 뒤 손에 쥐는 결과는 완전히 다릅니다.

처음 정한 반반의 비율을 끝까지 고정하는 앞의 방법이 A/B 테스트입니다. 결과를 보며 잘 나오는 소재로 노출을 옮기는 뒤의 방법은 멀티암드 밴딧(MAB, Multi-Armed Bandit)이라고 부릅니다. 두 방법이 정확히 무엇이고 그 안에서 어떤 알고리즘이 도는지는 이미 다른 글에서 다뤘는데, 밴딧이라는 문제 자체는 [알고리즘 계보](post.html?id=mab-summary)에서 설명했습니다. UCB 는 지금까지의 클릭률에 덜 보여 준 소재일수록 큰 가산점을 더해 소재를 고르는 알고리즘입니다. 같은 기록이면 UCB 는 늘 같은 소재를 고르는 결정적 알고리즘이지만 톰슨 샘플링은 고를 때마다 다른 소재가 나올 수 있는 확률적 알고리즘입니다. 이 성격 차이는 [UCB vs 톰슨 샘플링](post.html?id=ucb-vs-ts)에서 비교했습니다. 이 글은 알고리즘의 안쪽 대신 **바깥의 질문 하나**만 다룹니다. 똑같은 상황에서 A/B 테스트와 밴딧 가운데 무엇을 고르면 무엇을 얻고 무엇을 잃을까요?

> 한 줄 요약: A/B 테스트는 트래픽(광고를 보여 줄 노출)을 끝까지 같은 비율로 고정해 두 소재 모두에 **깨끗한 성적표**(오차 범위인 신뢰구간이 좁은 클릭률 추정치)를 남깁니다. 밴딧은 잘 나오는 소재로 트래픽을 옮겨 **클릭을 더** 법니다. 이 글의 노출 10만 건에서는 밴딧이 2,980클릭, A/B 가 2,521클릭이었습니다. 대신 밴딧은 진 소재의 진짜 실력을 훨씬 흐릿하게 알게 되는데, 이 글에서는 진 소재의 신뢰구간이 A/B 의 3.7배로 넓었습니다. 무엇을 고를지는 목적에 달렸습니다. 이 글은 그 선택만 봅니다.

## 1. 소재 2개와 노출 10만 건으로 비교한 A/B 테스트와 밴딧

**밴딧이 클릭을 더 벌지만 진 소재의 클릭률은 훨씬 흐릿하게 압니다. 이 글의 결론은 표 ① 하나에 미리 나와 있습니다.**

팀 회의의 두 의견이 일주일 뒤 무엇을 남기는지는 같은 캠페인에서 두 방식을 나란히 돌려 봐야 확인할 수 있습니다. 소재A 의 진짜 클릭률을 2.0%, 소재B 를 3.0% 로 두고 노출 10만 건을 A/B 테스트와 밴딧으로 각각 쓰면 아래 표 ①이 나옵니다. 두 방식은 같은 시드(난수를 만드는 출발값)로 돌렸으므로 두 방식이 겪은 우연은 최대한 맞춰 두었습니다.

**표 ① — 소재 2개, 노출 10만 건, 같은 시드로 비교한 두 방식**

| 항목 | A/B 테스트(50:50 고정) | 밴딧(적응형) |
|---|---|---|
| 트래픽 배분(소재A : 소재B) | 50,000 : 50,000 | 4,171 : 95,829 |
| 총 클릭 수 | 2,521클릭 | 2,980클릭 |
| 후회(이론상 최선 3,000클릭 대비) | 479.0 | 20.0 |
| 소재A 최종 추정 CTR | 2.06% (95% CI ±0.124%p) | 2.28% (95% CI ±0.453%p) |
| 소재B 최종 추정 CTR | 2.99% (95% CI ±0.149%p) | 3.01% (95% CI ±0.108%p) |

표의 첫 줄인 트래픽 배분은 노출 10만 건이 소재A 와 소재B 에 몇 건씩 나갔는지를 보여 줍니다. A/B 테스트는 처음 정한 50:50 그대로 50,000 : 50,000 을 지켰습니다. 밴딧은 결과를 보면서 배분을 바꾸는 적응형이라 소재A 에 4,171건, 소재B 에 95,829건을 보냈습니다.

먼저 총 클릭 수(많을수록 좋음)를 보면 A/B 는 2,521클릭, 밴딧은 2,980클릭이라 밴딧이 2,980 에서 2,521 을 뺀 459클릭, A/B 의 약 18% 만큼 더 벌었습니다. 이론상 최선은 진짜 클릭률이 높은 소재B 에 노출 10만 건을 전부 몰아줬을 때 기대하는 클릭으로, 10만 건에 3.0% 를 곱하면 3,000클릭이 나옵니다. 후회(regret)는 이 이론상 최선에서 실제로 얻은 클릭을 뺀 값이라 작을수록 최선에 가깝게 벌었다는 뜻입니다. 그래서 A/B 의 후회는 3,000 에서 2,521 을 뺀 479.0 인데 밴딧의 후회는 3,000 에서 2,980 을 뺀 20.0 뿐입니다. 여기까지만 보면 밴딧이 크게 이깁니다.

그런데 표의 마지막 두 줄은 다른 이야기를 합니다. 최종 추정 CTR 은 실험이 끝났을 때 소재마다 클릭 수를 노출 수로 나눠 얻은 관측 CTR 입니다. 괄호 안의 95% CI 는 그 추정치의 95% 신뢰구간(confidence interval)입니다. 신뢰구간은 관측 CTR 이 우연 때문에 흔들리는 폭을 계산해 추정치 양쪽으로 벌린 범위입니다. 그래서 신뢰구간이 좁을수록 그 소재의 클릭률을 정확히 압니다. 표의 ±0.124%p 는 추정치 2.06% 에서 위아래로 0.124%p 씩 벌린다는 뜻입니다. %p(퍼센트포인트)는 퍼센트로 적은 두 값의 차이를 나타내는 단위입니다.

소재A 의 추정치는 A/B 가 2.06%(±0.124%p), 밴딧이 2.28%(±0.453%p)입니다. 0.453 은 0.124 의 약 3.7배라 밴딧의 신뢰구간이 A/B 보다 3.7배 넓은데, 까닭은 단순합니다. A/B 는 소재A 에도 끝까지 5만 건을 보냈지만 밴딧은 초반에 승부를 걸어 소재A 에 4,171건만 보낸 뒤 나머지를 전부 소재B 로 옮겼으므로, 소재A 의 표본(그 소재의 CTR 을 계산하는 데 쓰인 노출)이 A/B 보다 훨씬 적었습니다. **표본이 적을수록 추정치는 흐릿해집니다.** 밴딧은 소재A 를 흐릿하게 아는 대가를 치르고 클릭을 골랐습니다.

반대로 소재B 의 신뢰구간은 밴딧(±0.108%p)이 A/B(±0.149%p)보다 오히려 좁습니다. 밴딧은 이긴 소재B 에 노출 95,829건을 몰아줘 A/B 의 50,000건보다 표본이 많았으므로 소재B 만큼은 A/B 보다 더 정확히 압니다. 실험이 끝났을 때 소재마다 남는 추정 CTR 과 그 신뢰구간을 성적표라고 부르면, 결국 밴딧은 이긴 쪽은 아주 잘 알고 진 쪽은 잘 모르는 성적표를 남기는 반면 A/B 는 두 소재를 비슷하게 적당히 아는 성적표를 남깁니다.

카드에서는 두 방식이 노출을 나눈 막대와 총 클릭, 그리고 소재A 의 95% 신뢰구간 폭(±0.124%p 와 ±0.453%p)을 나란히 보면 됩니다.

## 2. 파이썬으로 재현한 총 클릭과 신뢰구간

**표 ①의 숫자는 손으로 지어낸 값이 아니라 아래 코드를 그대로 돌려 나온 값입니다. 밴딧에서 소재A 의 신뢰구간이 넓어진 까닭도 코드의 신뢰구간 식에서 보입니다.**

표 ①만 봐서는 숫자가 어디서 나왔는지, 밴딧에서 소재A 의 신뢰구간이 왜 하필 그만큼 넓어졌는지 확인할 수 없으므로 같은 숫자를 코드로 다시 만들어 봅니다. 실험을 돌리는 함수는 2개면 충분합니다. `run_ab` 는 짝수 번째 노출을 소재A 에, 홀수 번째 노출을 소재B 에 기계적으로 배정하므로 결과가 어떻든 끝까지 50:50 을 지킵니다. `run_bandit` 은 톰슨 샘플링(Thompson Sampling)으로, 노출마다 소재별 베타 분포에서 값을 하나씩 뽑아 더 큰 값이 나온 소재에 배정합니다.

베타 분포(Beta distribution)는 0 과 1 사이의 값을 다루는 확률 분포로, 여기서는 소재마다 진짜 CTR 이 어디쯤일지를 나타냅니다. 코드는 소재마다 `alpha` 와 `beta` 를 1 에서 시작해 클릭이 나면 `alpha` 를, 안 나면 `beta` 를 1 늘립니다. 그래서 관측 CTR 이 높은 소재일수록 큰 값이 잘 뽑히고 노출이 쌓인 소재일수록 뽑히는 값이 덜 흔들립니다. 톰슨 샘플링이 왜 이렇게 작동하는지는 [UCB vs 톰슨 샘플링](post.html?id=ucb-vs-ts)에서 이미 다뤘으므로 여기서는 「그런 밴딧이 있다」는 정도로만 씁니다.

아래 코드는 진짜 CTR 을 정해 둔 두 소재에 노출 10만 건을 A/B 와 밴딧으로 각각 보내 4단계에서 총 클릭과 후회를, 5단계에서 소재별 추정치와 95% 신뢰구간을 찍습니다. 두 실험은 3단계에서 같은 시드 3 으로 돌립니다.

```python
# 하는 일: 진짜 CTR 2.0% 인 소재 A 와 3.0% 인 B 에 노출 10만 건을 A/B 와 밴딧으로 각각 태워, 총 클릭과 후회, 소재별 추정치와 95% 신뢰구간을 비교한다.
import random, math

# 1단계: 노출 수와 진짜 CTR 을 둔다
# 표준 라이브러리만 쓴다.
N = 100_000
TRUE_CTR = {"A": 0.02, "B": 0.03}   # 우리는 이 값을 모른 채 실험을 시작한다
BEST_CTR = max(TRUE_CTR.values())

# 2단계: A/B, 밴딧, 신뢰구간 함수를 만든다
# A/B 는 끝까지 50:50 으로 고정하고, 밴딧(톰슨 샘플링)은 매번 베타 분포 표본이 큰 쪽에 배정한다.
def run_ab(n, true_ctr, seed):
    """A/B 테스트: 끝까지 50:50 고정 배정."""
    rng = random.Random(seed)
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for i in range(n):
        arm = "A" if i % 2 == 0 else "B"
        imps[arm] += 1
        clicks[arm] += rng.random() < true_ctr[arm]
    return imps, clicks

def run_bandit(n, true_ctr, seed):
    """밴딧(톰슨 샘플링): 매번 베타 분포에서 표본을 뽑아 큰 쪽에 배정."""
    rng = random.Random(seed)
    alpha = {"A": 1, "B": 1}
    beta = {"A": 1, "B": 1}
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for _ in range(n):
        sample = {a: rng.betavariate(alpha[a], beta[a]) for a in true_ctr}
        arm = max(sample, key=sample.get)
        imps[arm] += 1
        if rng.random() < true_ctr[arm]:
            clicks[arm] += 1
            alpha[arm] += 1
        else:
            beta[arm] += 1
    return imps, clicks

def ci95(clicks, imps):
    """관측 CTR과 95% 신뢰구간 절반폭(정규근사, 퍼센트포인트)."""
    p = clicks / imps
    return p, 1.96 * math.sqrt(p * (1 - p) / imps) * 100

# 3단계: 같은 seed 로 두 실험을 돌린다
SEED = 3   # A/B와 밴딧 모두 같은 시드로 돌려 공정하게 비교한다
imps_ab, clicks_ab = run_ab(N, TRUE_CTR, SEED)
imps_bd, clicks_bd = run_bandit(N, TRUE_CTR, SEED)

total_ab, total_bd = sum(clicks_ab.values()), sum(clicks_bd.values())
best_possible = N * BEST_CTR

# 4단계: 총 클릭과 후회를 찍는다
print(f"이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): {best_possible:,.0f}")
print(f"A/B   총 클릭 {total_ab:,}   후회 {best_possible - total_ab:6.1f}")
print(f"밴딧  총 클릭 {total_bd:,}   후회 {best_possible - total_bd:6.1f}")
print()

# 5단계: 소재별 추정치와 신뢰구간을 찍는다
for label, imps, clicks in [("A/B", imps_ab, clicks_ab), ("밴딧", imps_bd, clicks_bd)]:
    for arm in ("A", "B"):
        p_hat, half_width = ci95(clicks[arm], imps[arm])
        print(f"  [{label}] 소재{arm}: n={imps[arm]:6,}   관측CTR={p_hat*100:5.2f}%   95%CI=±{half_width:.3f}pp")

# 출력:
# 4단계 뜻: 전부 B 에 몰아줬다면 클릭 3,000 을 기대한다. 밴딧은 2,980 으로 후회가 20.0 뿐이고, 끝까지 반반 나눈 A/B 는 후회가 479.0 이다.
# 이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): 3,000
# A/B   총 클릭 2,521   후회  479.0
# 밴딧  총 클릭 2,980   후회   20.0
#
# 5단계 뜻: A/B 는 두 소재를 50,000건씩 봐서 신뢰구간이 ±0.124pp 와 ±0.149pp 다. 밴딧은 A 를 4,171건만 봐서 A 의 신뢰구간이 ±0.453pp 로 넓다.
#   [A/B] 소재A: n=50,000   관측CTR= 2.06%   95%CI=±0.124pp
#   [A/B] 소재B: n=50,000   관측CTR= 2.99%   95%CI=±0.149pp
#   [밴딧] 소재A: n= 4,171   관측CTR= 2.28%   95%CI=±0.453pp
#   [밴딧] 소재B: n=95,829   관측CTR= 3.01%   95%CI=±0.108pp
```

찍힌 값은 표 ①과 숫자 하나까지 같습니다. 5단계 줄을 보면 밴딧은 노출 4,171건 만에 소재A 를 사실상 포기하고 나머지 95,829건을 전부 소재B 에 몰아줬는데, 그 대가로 소재A 의 신뢰구간이 ±0.453pp 로 A/B 의 ±0.124pp 보다 3.7배 넓어졌습니다. 출력의 pp 는 본문의 %p 와 같은 퍼센트포인트입니다.

신뢰구간의 폭은 `ci95` 함수가 정합니다. `ci95` 는 정규근사로 95% 신뢰구간의 절반폭(표에서 ± 뒤에 붙은 숫자)을 구합니다. 정규근사는 표본이 클 때 관측 CTR 이 진짜 CTR 근처에서 정규분포(평균을 중심으로 종 모양으로 퍼지는 분포)를 따라 흔들린다고 보고 구간을 계산하는 방법입니다. 식은 관측 CTR p 에 1 − p 를 곱해 표본 수 `imps` 로 나눈 뒤 제곱근을 계산합니다. 이 제곱근이 관측 CTR 이 우연 때문에 흔들리는 크기인 표준오차입니다. 1.96 은 정규분포에서 95% 구간을 만들 때 표준오차에 곱하는 값입니다. 마지막에 곱하는 100 은 비율을 퍼센트포인트로 바꿉니다.

표본 수가 분모에서 제곱근 안에 들어 있으므로 표본이 4배 줄면 제곱근 값이 2배가 되어 구간 폭도 2배로 벌어집니다. 밴딧이 소재A 에 준 표본 4,171건은 A/B 의 50,000건의 약 12분의 1 이었고 12 의 제곱근은 3 과 4 사이이므로, 구간 폭도 3~4배로 벌어집니다. 표 ①에서 소재A 의 구간이 3.7배로 벌어진 결과는 우연이 아니라 이 계산에서 당연히 나옵니다.

## 3. 효과가 작을 때 헤매는 밴딧

**두 소재의 진짜 차이가 0.1%p 로 작아지면 밴딧은 트래픽을 엉뚱한 쪽, 곧 진짜로는 더 나쁜 소재에 몰아줄 수 있습니다.**

1절의 두 소재는 진짜 클릭률이 2.0% 와 3.0% 로 차이가 컸습니다. 이번에는 소재A 를 2.0%, 소재B 를 2.1% 로 두어 차이를 0.1%p 로 줄이고 같은 코드를 다시 돌립니다. 함수는 그대로이고 바꾼 값은 진짜 클릭률과 시드뿐입니다.

아래 코드는 차이가 작을 때 밴딧이 어떻게 되는지 보려고 같은 비교를 시드 2 로 다시 돌려, 4단계에서 총 클릭, 후회, 밴딧의 최종 트래픽 배분을 찍고 5단계에서 소재별 추정치와 신뢰구간을 찍습니다.

```python
# 하는 일: 진짜 차이가 0.1%p 로 작을 때(A 2.0%, B 2.1%) 같은 비교를 다시 돌려 밴딧이 어떻게 되는지 본다.
import random, math

# 1단계: 노출 수와 진짜 CTR 을 둔다
# 이번에는 B 가 0.1%p 만 높다.
N = 100_000
TRUE_CTR = {"A": 0.02, "B": 0.021}   # 이번엔 차이가 0.1%p뿐이다
BEST_CTR = max(TRUE_CTR.values())

# 2단계: 앞 블록과 같은 함수를 둔다
# 함수는 위 코드와 같고, TRUE_CTR 과 시드만 바꿔 같은 비교를 반복한다.
def run_ab(n, true_ctr, seed):
    rng = random.Random(seed)
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for i in range(n):
        arm = "A" if i % 2 == 0 else "B"
        imps[arm] += 1
        clicks[arm] += rng.random() < true_ctr[arm]
    return imps, clicks

def run_bandit(n, true_ctr, seed):
    rng = random.Random(seed)
    alpha = {"A": 1, "B": 1}
    beta = {"A": 1, "B": 1}
    imps = {"A": 0, "B": 0}
    clicks = {"A": 0, "B": 0}
    for _ in range(n):
        sample = {a: rng.betavariate(alpha[a], beta[a]) for a in true_ctr}
        arm = max(sample, key=sample.get)
        imps[arm] += 1
        if rng.random() < true_ctr[arm]:
            clicks[arm] += 1
            alpha[arm] += 1
        else:
            beta[arm] += 1
    return imps, clicks

def ci95(clicks, imps):
    p = clicks / imps
    return p, 1.96 * math.sqrt(p * (1 - p) / imps) * 100

# 3단계: seed 2 로 두 실험을 돌린다
SEED = 2
imps_ab, clicks_ab = run_ab(N, TRUE_CTR, SEED)
imps_bd, clicks_bd = run_bandit(N, TRUE_CTR, SEED)

total_ab, total_bd = sum(clicks_ab.values()), sum(clicks_bd.values())
best_possible = N * BEST_CTR

# 4단계: 총 클릭과 후회, 밴딧의 배분을 찍는다
print(f"이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): {best_possible:,.0f}")
print(f"A/B   총 클릭 {total_ab:,}   후회 {best_possible - total_ab:6.1f}")
print(f"밴딧  총 클릭 {total_bd:,}   후회 {best_possible - total_bd:6.1f}")
print()
print(f"밴딧 최종 트래픽 배분 — 소재A(열세) {imps_bd['A']:,} : 소재B(우세) {imps_bd['B']:,}")
print()

# 5단계: 소재별 추정치와 신뢰구간을 찍는다
for label, imps, clicks in [("A/B", imps_ab, clicks_ab), ("밴딧", imps_bd, clicks_bd)]:
    for arm in ("A", "B"):
        p_hat, half_width = ci95(clicks[arm], imps[arm])
        print(f"  [{label}] 소재{arm}: n={imps[arm]:6,}   관측CTR={p_hat*100:5.2f}%   95%CI=±{half_width:.3f}pp")

# 출력:
# 4단계 뜻: 차이가 작으면 밴딧이 열세인 A 에 94,014건을 몰아줘, 후회가 78.0 으로 A/B 의 15.0 보다 크다.
# 이론상 최선(전부 B에게 몰아줬을 때 기대 클릭): 2,100
# A/B   총 클릭 2,085   후회   15.0
# 밴딧  총 클릭 2,022   후회   78.0
#
# 밴딧 최종 트래픽 배분 — 소재A(열세) 94,014 : 소재B(우세) 5,986
#
# 5단계 뜻: A/B 로는 B 가 2.12% 로 A 의 2.05% 보다 높게 나오지만, 밴딧은 B 를 5,986건만 봐서 1.85% 로 낮게 본다.
#   [A/B] 소재A: n=50,000   관측CTR= 2.05%   95%CI=±0.124pp
#   [A/B] 소재B: n=50,000   관측CTR= 2.12%   95%CI=±0.126pp
#   [밴딧] 소재A: n=94,014   관측CTR= 2.03%   95%CI=±0.090pp
#   [밴딧] 소재B: n= 5,986   관측CTR= 1.85%   95%CI=±0.342pp
```

찍힌 값을 보면 결과가 1절과 정반대입니다. 4단계의 최종 트래픽 배분을 보면 밴딧은 노출의 94%(94,014건)를 소재A 에 몰아줬는데, 출력이 열세라고 표시한 대로 소재A 는 진짜 클릭률이 2.0% 인 더 나쁜 쪽입니다. 이론상 최선은 노출 10만 건에 2.1% 를 곱한 2,100클릭입니다. 총 클릭은 밴딧이 2,022클릭으로 A/B 의 2,085클릭보다 오히려 적습니다.

후회는 밴딧이 2,100 에서 2,022 를 뺀 78.0, A/B 가 2,100 에서 2,085 를 뺀 15.0 입니다. 78.0 을 15.0 으로 나누면 5.2 라 밴딧의 후회가 A/B 의 5배가 넘습니다. **결과에 따라 배분을 전혀 바꾸지 않은 A/B 가 적응한다는 밴딧보다 더 나은 결과를 냈습니다.**

밴딧이 열세 소재에 몰아준 까닭은 실험 초반에 있습니다. 초반 노출 몇백 건에서 우연히 소재A 에 클릭이 조금 더 몰렸는데 톰슨 샘플링은 그 우연한 우위를 진짜 우위로 착각해 트래픽을 계속 소재A 쪽으로 더 보냈습니다. 두 소재의 진짜 차이가 0.1%p 뿐이면 이런 우연과 진짜 신호(실제 클릭률 차이)를 잘 구별할 수 없습니다. 그러니 밴딧 알고리즘이 나빠서 생긴 일이 아니라 **차이가 그 알고리즘이 구별할 수 있는 크기보다 작았던 탓입니다.**

밴딧이 마지막에 남긴 관측치는 더 걱정스럽습니다. 5단계 줄에서 밴딧의 관측 CTR 은 소재A 2.03%, 소재B 1.85% 라 밴딧의 데이터만 보면 소재A 가 이긴 것처럼 보이는데, 진실은 B 가 더 높으므로 방향 자체가 반대입니다. 5단계 뜻 줄의 말대로 밴딧은 소재B 를 5,986건만 봐서 1.85% 로 낮게 봤습니다. 반면 A/B 의 관측 CTR 은 소재A 2.05%, 소재B 2.12% 로 진실과 같은 방향입니다. 두 추정치가 둘 다 2.0%대 초반이라 신뢰구간(±0.124%p 와 ±0.126%p)이 겹치므로 「확실하다」고 말할 수는 없지만 최소한 방향은 뒤집히지 않았습니다. **효과가 작을 때는 밴딧도 못 찾습니다.** 이 절에서 실무로 가져갈 감각은 이 한 문장입니다.

아래 데모에서는 슬라이더로 소재별 클릭률을 직접 바꿔 가며 차이가 클 때와 작을 때 두 방식이 트래픽을 어떻게 나누고 누적 클릭이 어떻게 달라지는지 보면 됩니다.

## 4. A/B 테스트와 밴딧을 고르는 결정 기준 여섯 가지

**여섯 가지 기준에 우리 상황을 대입하면 A/B 테스트와 밴딧 가운데 무엇을 고를지 답이 나옵니다. 이 글의 결론은 아래 표입니다.**

1절에서는 밴딧이 클릭을 더 벌었지만 3절에서는 오히려 A/B 보다 못했으므로 어느 한쪽이 늘 낫다고 말할 수는 없습니다. 1절과 3절의 두 시나리오를 합치면 아래 표 하나가 됩니다. 트레이드오프는 클릭을 얻는 만큼 진 소재의 정보를 잃는 것처럼 하나를 얻으면 다른 하나를 잃는 관계입니다. 1, 3절에서 본 이 트레이드오프가 표의 각 줄에 그대로 깔려 있습니다.

| 판단 기준 | A/B 테스트가 낫다 | 밴딧이 낫다 |
|---|---|---|
| 목적 | 정말 효과가 있는지 검증해야 할 때 | 아는 동안 손해를 줄이며 수익을 내야 할 때 |
| 소재 수 | 2~5개 정도로 적을 때 | 수십 개 이상으로 많을 때 |
| 트래픽 규모 | 하루 방문자가 적어 표본이 빠듯할 때 | 트래픽이 커서 탐색할 여유가 있을 때 |
| 효과 크기 | 차이가 작아 "다르지 않다"고 정직하게 말해야 할 때 | 차이가 뚜렷해 빨리 확신할 수 있을 때 |
| 보고 대상 | 경영진, 다른 팀, 논문처럼 밖에 보고할 때 | 우리 팀 안의 운영 판단으로 그칠 때 |
| 비정상성 | 짧은 고정 기간 비교로 충분할 때 | 승자가 요일이나 시즌마다 바뀔 때 |

표는 판단 기준마다 A/B 테스트가 나은 경우와 밴딧이 나은 경우를 나란히 적었습니다. 첫 줄인 목적은 1절과 같은 이야기입니다. 정말 효과가 있는지 검증해야 하면 두 소재 모두에 깨끗한 성적표를 남기는 A/B 를 고르고 실험하는 동안에도 손해를 줄이며 수익을 내야 하면 클릭을 더 버는 밴딧을 고릅니다. 트래픽 규모 줄의 탐색은 아직 잘 모르는 소재에도 노출을 나눠 주며 클릭률을 확인한다는 뜻입니다. 비정상성(non-stationarity)은 소재의 진짜 클릭률이 시간에 따라 바뀌는 성질로, 표의 예처럼 승자가 요일이나 시즌마다 바뀌는 경우를 말합니다.

표의 네 번째 줄인 효과 크기(두 소재의 진짜 클릭률 차이)는 3절과 바로 이어집니다. 차이가 크면(2.0% 대 3.0%) 밴딧이 압도적으로 유리했지만 차이가 작으면(2.0% 대 2.1%) 밴딧은 오히려 A/B 보다 못한 결과를 냈습니다. 후회로 보면 1절에서는 밴딧이 20.0, A/B 가 479.0 이었는데 3절에서는 밴딧이 78.0, A/B 가 15.0 이었습니다. 그래서 **「효과가 얼마나 클지 미리 감이 안 잡힌다」면 밴딧보다 A/B 로 시작하는 쪽이 안전합니다.** 몇 주 지나 차이가 뚜렷해 보일 때 밴딧으로 옮겨도 늦지 않습니다.

다섯 번째 줄인 보고 대상도 실무에서 자주 문제가 됩니다. 전환율은 구매 같은 목표 행동까지 간 사람의 비율입니다. 경영진에게 「이 기능이 전환율을 얼마나 올렸나」를 보고해야 한다면 밴딧이 남긴 비대칭 표본(1절의 4,171 : 95,829 처럼 이긴 소재에 몰린 표본)으로는 깔끔한 답을 만들기 어려운데, 밴딧의 표본 수는 결과에 따라 정해져서 일반적인 통계 검정(차이가 우연인지 판정하는 계산)이 기대는 전제를 깨기 때문입니다. 자세한 내용은 8절에서 다룹니다. 반면 우리 팀 안에서 「이번 주는 어떤 배너를 더 밀까」를 정하는 정도라면 밴딧의 흐릿한 신뢰구간은 큰 문제가 되지 않습니다.

실무에서는 표의 두 칸을 함께 쓰는 일이 흔합니다. 새 기능처럼 큰 의사결정은 A/B 로 확실히 검증하고 그 안의 소재나 배너 최적화는 밴딧에 맡기는 식입니다.

## 5. 「전체 1등」 하나로 부족할 때 쓰는 Contextual Bandit

**A/B 테스트와 밴딧은 방식이 달라도 둘 다 결국 소재 하나로 수렴합니다. 지면(광고가 실리는 자리)과 유저마다 정답이 다르면 이 승자 하나로는 손해를 봅니다.**

지금까지 표 ①과 2, 3절의 코드는 전부 「전체 트래픽 기준 1등」을 찾는 이야기였습니다. A/B 는 실험이 끝나면 승자 하나를 골라 그쪽에 트래픽을 전부 보냅니다. 밴딧은 실험 중에도 이미 트래픽 대부분을 승자 쪽으로 옮겨 둡니다. 방식은 달라도 목적지는 같습니다. 두 방식 모두 **소재 하나로 수렴**하는데, 여기서 수렴은 트래픽이 점점 한 소재로 모여 가는 것을 말합니다.

지면이나 유저에 따라 정답이 달라지면 사정이 바뀝니다. 소재B 가 전체 평균으로는 3.0% 로 이겼다고 해도 PC 상단 배너에서는 소재A 의 반응이 더 좋고 모바일 피드에서는 소재B 의 반응이 훨씬 좋은 식으로 나뉠 수 있습니다.

| 지면 | 소재A 반응 | 소재B 반응 |
|---|---|---|
| PC 상단 배너 | 강함 | 약함 |
| 모바일 피드 | 약함 | 강함 |

표처럼 반응이 나뉘는데도 「전체 평균 1등」만 믿고 소재B 하나만 모든 지면에 내보내면 PC 상단 배너에서는 계속 손해를 봅니다. A/B 도 밴딧도 「지면」이라는 정보를 애초에 보지 않으므로 이 손해를 잡아내지 못합니다. 트래픽을 어떻게 나누든 나누는 기준이 「전체」 하나뿐이라는 한계는 그대로 남습니다.

지면과 유저 정보처럼 소재를 고를 때 함께 보는 정보를 **맥락**(context)이라 부릅니다. 맥락마다 다른 승자를 학습하는 밴딧이 **Contextual Bandit**입니다. 맥락을 피처(모델에 넣는 입력값)로 어떻게 넣고 학습하는지는 이 글의 범위를 넘습니다. [UCB 계열](post.html?id=ucb-family)이 UCB 를 맥락까지 쓰는 LinUCB 로 확장하는 과정을 다룹니다. [Disjoint LinUCB: 광고마다 계수를 따로 배우면 무엇이 달라지나](post.html?id=disjoint-linucb)는 LinUCB 의 점수가 어떻게 구성되는지 그림으로 뜯어봅니다.

## 6. 트래픽을 마음대로 쪼개는 담장 안 [무대: 닫힌 생태계]

**노출을 플랫폼이 직접 배정할 수 있는 닫힌 생태계에서는 A/B 테스트도 밴딧도 원하는 설계 그대로 돌릴 수 있습니다.**

제목의 담장 안(walled garden)은 닫힌 생태계를 가리키는 말입니다. 네이버, 밴드처럼 노출, 클릭, 구매를 전부 자기 로그로 남기는 플랫폼은 트래픽을 어느 소재에 얼마나 보낼지 정하는 배분권을 스스로 쥐고 있습니다. 그래서 이번 주 캠페인 노출을 반반 고정할지 톰슨 샘플링으로 적응시킬지는 순전히 플랫폼 내부의 판단입니다. 이 글의 표 ①, 2, 3절 시뮬레이션도 바로 이 무대의 조건을 가정했습니다.

그래서 이 무대에서는 4절의 표를 실무에 그대로 적용할 수 있습니다. 새 배너 기능을 켤지 말지처럼 밖에 보고해야 하는 결정은 A/B 로 돌리고 그 안에서 소재 몇 개를 계속 순환시키는 운영은 밴딧으로 돌리는 식입니다. A/B 와 밴딧 실험을 동시에 여러 개 돌려도 서로 트래픽을 침범하지 않도록 나누는 일 역시 플랫폼 안에서 전부 통제할 수 있습니다.

다만 이 자유에도 대가가 있습니다. 밴딧으로 트래픽을 몰아준 만큼 진 소재의 정보는 1절의 표 ①처럼(밴딧의 소재A 는 4,171건에 ±0.453%p) 계속 흐릿하게 남습니다. 나중에 「그때 소재A 는 정말 얼마나 나빴나」를 다시 물으면 밴딧 로그만으로는 표본이 적어 답하기 어렵습니다. 그래서 중요한 소재에는 밴딧을 돌리는 동안에도 최소 표본을 보장하는 하한선(그 소재에 반드시 보내는 최소 노출 수)을 두어 나중에 되짚어 볼 여지를 남기는 실무 관행이 흔합니다.

## 7. 매체 손 안에 있는 열린 RTB 의 실험 [무대: 열린 RTB]

**열린 RTB(실시간 경매로 노출을 사고파는 시장)에서 광고주는 노출 전체를 원하는 대로 나눌 수 없습니다. 실험은 자기 입찰과 소재의 범위 안에서만 할 수 있습니다. 그 결과에는 매체(광고 지면을 파는 웹사이트나 앱) 쪽 알고리즘이 이미 섞여 있습니다.**

열린 RTB 는 노출 한 번이 생길 때마다 여러 회사의 광고주가 그 순간 입찰해 낙찰된 광고를 내보내는 실시간 입찰(RTB, Real-Time Bidding) 시장입니다. 매체의 노출 기회를 경매에 부쳐 광고주의 입찰을 받는 곳은 거래소(ad exchange)라고 부릅니다. 닫힌 생태계와 가장 크게 다른 점은 노출을 나누는 권한인 배분권에 있습니다.

광고주는 「이번 캠페인에 소재A 와 소재B 를 50:50 으로 쓰겠다」고 정할 수 있습니다. 하지만 그 소재가 실제로 어떤 유저에게 얼마나 자주 노출될지는 거래소의 경매 로직과 매체의 인벤토리(매체가 팔 수 있는 광고 지면)가 정합니다. 광고주는 「무엇을 입찰에 올릴까」까지만 통제합니다. 「누가 그 소재를 보게 될까」는 매체의 몫입니다.

여기에 매체 쪽의 최적화도 개입합니다. 대부분의 매체와 거래소는 자기 지면에 어떤 광고를 보여 줄지를 이미 자체 랭킹 알고리즘(광고 후보에 순위를 매겨 보여 줄 광고를 고르는 알고리즘)으로 정하고 있습니다. 그 랭킹 알고리즘도 일종의 밴딧입니다. 매체가 소재A 와 소재B 의 노출 기회 자체를 성과에 따라 다르게 배분하면 광고주의 50:50 은 노출 단계에서 이미 깨져 있으므로, 광고주가 「우리는 A/B 로 깔끔하게 비교하겠다」고 정해도 소용이 제한적입니다.

그래서 열린 RTB 에서 「우리 실험」의 결과는 우리 배분 결정과 매체의 배분 결정이 겹친 결과입니다. 두 결정을 떼어 놓고 보기 어렵다는 점에서 열린 RTB 는 담장 안과 근본적으로 다릅니다. 광고주가 할 수 있는 최선은 소재별로 별도 캠페인이나 라인아이템(line item, 캠페인 안에서 예산과 입찰 조건을 따로 정해 집행하는 단위)을 만드는 정도입니다. 그렇게 매체 알고리즘의 개입을 최대한 줄이고 노출과 클릭 로그를 소재 단위로 세밀하게 쪼개 보는 방법이 현실적인 대응입니다.

## 8. 밴딧 결과로 「A 가 B 보다 낫다」고 말해도 되는지 여부

**조심해야 합니다. 밴딧이 스스로 트래픽을 옮기며 만든 표본은 일반적인 유의성 검정(관측한 차이가 우연으로 나올 만한 크기인지 판정하는 계산)이 가정하는 조건을 이미 깨고 있습니다.**

1절의 표 ①로 돌아가 보면 밴딧이 남긴 소재A 의 표본은 4,171건, 소재B 는 95,829건입니다. 4,171건과 95,829건을 더하면 노출 10만 건인데, 이 10만 건을 어떻게 나눌지는 밴딧이 실험 도중에 결과를 보며 정했습니다. 그래서 이 표본 크기 자체가 「소재A 가 초반에 밀렸다」는 관측 결과로 만들어진 값입니다. A/B 의 5만 대 5만은 그와 달리 결과와 상관없이 실험을 시작하기 전에 이미 정해 둔 값입니다.

표본 크기와 검정력 계산은 모두 표본 수를 결과와 무관하게 미리 고정한다는 전제 위에 서 있습니다. 검정력(power)은 진짜 차이가 있을 때 검정이 그 차이를 놓치지 않고 잡아낼 확률입니다. 표본 크기와 검정력을 계산하는 법은 [랜덤 실험(RCT)](post.html?id=rct-randomized-experiment)에서 다뤘습니다.

밴딧은 표본 수 자체가 결과에 따라 정해지는 값, 곧 결과의 함수라서 이 전제를 정면으로 어깁니다. 그래서 밴딧이 끝난 뒤 소재A, 소재B 의 관측 CTR 에 곧바로 일반 z검정을 돌리면 신뢰구간은 추정치가 실제로 흔들리는 폭보다 좁게, p값은 제대로 계산한 값보다 작게 나오는 문제가 생깁니다. z검정은 두 관측 CTR 의 차이를 표준오차(우연만으로 그 차이가 흔들리는 크기)로 나눈 z값으로 차이가 우연인지 판정하는 검정입니다. p값은 진짜 차이가 없을 때 그만큼 큰 차이가 우연히 나올 확률이고 이 값이 미리 정한 기준보다 작으면 차이가 우연이 아니라고 보고 유의하다고 말합니다. 밴딧의 표본에서는 p값이 제대로 계산한 값보다 작게 나오므로 「우연히 유의해 보일 확률」을 5% 로 맞춰 두었다고 믿어도 실제로는 그보다 훨씬 자주 유의해 보이는 착시가 생깁니다.

이 문제는 [랜덤 실험](post.html?id=rct-randomized-experiment)에서 본 「조기 중단(peeking)」 함정과 뿌리가 같습니다. 조기 중단은 실험 중간에 결과를 들여다보다가 유의해 보이는 순간 실험을 멈추는 것을 말합니다. 밴딧은 중간 결과에 따라 실험을 바꾸는 일을 설계 자체로 실험 내내 계속하므로 조기 중단보다 훨씬 심합니다.

:::deep 더 깊이 — 적응형 배정이 통계 검정의 전제를 깨는 과정
일반 z검정이 성립하려면 각 소재의 표본 수 $n_a$ 가 결과와 독립으로, 다시 말해 결과와 상관없이 미리 정해져 있어야 관측 CTR 의 표준오차를 $\sqrt{p(1-p)/n_a}$ 로 계산하는 공식이 맞습니다. 2절의 `ci95` 가 1.96 을 곱하기 전에 계산하는 값이 바로 이 표준오차입니다.

밴딧에서는 $n_a$ 자체가 그때까지 클릭이 났는지에 따라 달라집니다. 어떤 소재에 초반에 운 좋게 클릭이 몰리면 $n_a$ 가 커지고 그만큼 많은 표본이 그 우연한 우위를 「확인」한 것처럼 보입니다. 표본과 결과가 서로를 강화하는 이 순환은 우연히 앞서가던 소재를 계속 더 유리하게 만들어서 최종 신뢰구간을 실제 흔들림보다 좁게 착각하게 만듭니다.

이 문제에 대응하는 방법은 크게 두 갈래입니다. 하나는 **always-valid inference** 로, 미리 정한 한 시점이 아니라 어느 시점에 멈추든 유효한 신뢰구간(confidence sequence)을 계산합니다. 실험 중 아무 때나 결과를 들여다봐도 착시가 생기지 않도록 통계량 자체를 새로 설계한 방법입니다. 다른 하나는 **사후 보정**(post-hoc correction)으로, 밴딧이 만든 편향(추정치가 진짜 값에서 한쪽으로 치우친 정도)의 방향과 크기를 역으로 추정해 관측 CTR 을 보정합니다(예: 역확률 가중치, IPW). 역확률 가중치는 관측마다 그 소재가 배정될 확률의 역수를 곱해 덜 배정된 쪽의 관측을 더 크게 세는 방법입니다. 혹은 실험 마지막에 일정 비율의 트래픽을 강제로 무작위 배정해 그 구간만으로 별도 검정을 돌리는 방식도 있습니다.

두 갈래 가운데 실무에서 가장 흔히 쓰는 절충은 후자입니다. 밴딧을 돌려 수익은 챙기되 트래픽의 5~10% 는 늘 무작위 홀드아웃(밴딧과 상관없이 무작위로 배정하도록 따로 떼어 둔 트래픽)으로 남겨 둡니다. 「A 가 B 보다 낫다」는 주장이 꼭 필요한 순간에는 밴딧의 데이터가 아니라 이 홀드아웃 조각으로만 검정합니다.
:::

## 10. 헷갈리기 쉬운 점

- **「밴딧이 항상 낫다」는 틀렸습니다.** 3절에서 진짜 차이가 0.1%p 로 작아지자 밴딧의 후회(78.0)가 A/B(15.0)의 5배를 넘었습니다. 효과가 작을 때는 결과를 따라 트래픽을 옮기는 적응이 오히려 손해가 될 수 있습니다.
- **밴딧 결과를 논문이나 보고서에 「A 가 B 보다 유의하게 낫다」고 쓰면 안 됩니다.** 8절에서 봤듯 적응형 배정은 표본 수 자체가 결과에 따라 정해지게 만들어 일반 유의성 검정의 전제를 깹니다.
- **클릭이 많다고 더 잘 알지는 않습니다.** 표 ①에서 밴딧은 A/B 보다 클릭을 더 벌었지만(2,980 대 2,521) 진 소재(소재A)의 신뢰구간은 오히려 3.7배 넓었습니다.
- **후회(regret) 숫자만 보고 우열을 매기면 안 됩니다.** 후회가 낮다는 말은 그 시나리오에서 잘 적응했다는 뜻일 뿐 다음 시나리오(효과가 작은 경우)에서도 낮으리라고 보장하지는 않습니다.
- **Contextual Bandit 은 밴딧의 상위 호환(모든 경우에 더 나은 대체품)이 아니라 다른 질문의 답입니다.** 질문 자체가 「전체에서 뭐가 제일 좋나」에서 「이 지면, 이 유저에게 뭐가 좋나」로 바뀝니다.
- **닫힌 생태계의 「마음대로」와 열린 RTB 의 「매체 손 안」은 실험 설계의 자유도 차이입니다.** 같은 A/B 와 밴딧 알고리즘이라도 열린 RTB 에서는 매체의 자체 최적화가 이미 결과에 섞여 들어옵니다.
