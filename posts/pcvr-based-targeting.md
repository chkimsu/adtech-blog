모델 팀 16주째 월요일, 서연 씨가 지훈 씨에게 다음 러닝화 캠페인은 「살 사람에게만」 보여 달라고 했습니다. 지난 캠페인은 「보여 줄 사람」 칸에 세그먼트 317 을 적고 하루 300만 원을 걸었습니다.

선배는 317 이 「러닝에 관심 있다」는 번호이지 「살 것이다」는 번호가 아니라고 했습니다. 모델 팀에는 회원마다 광고를 보면 살 확률을 매기는 모델이 있어서, 그 순서로 같은 수를 고를 수 있습니다. 다만 그렇게 고르면 광고가 없어도 살 사람이 많이 섞인다고 덧붙였습니다.

**317 과 같은 수를 살 확률이 높은 순서로 고르면 구매는 몇 건 늘고, 그중 광고 덕분인 것은 몇 건일까요?**

광고를 본 사람이 사는 일을 전환이라고 부르고, 모델이 매긴 전환 확률을 pCVR 이라고 부릅니다. 기준을 번호에서 pCVR 로 바꾸면 하루 300만 원이 닿는 사람이 바뀝니다. 그 돈이 어차피 살 사람에게 가면, 리포트의 전환은 늘어도 광고가 만든 구매는 그만큼 늘지 않습니다.

> **한 줄 요약:** 세그먼트 317 은 조건이 맞나만 보는 번호라서, 그 안에도 살 확률이 낮은 회원이 많습니다. 가상 회원 20,000명에서 세그먼트와 같은 2,290명을 pCVR 순서로 고르면 1,390명이 세그먼트 밖 사람으로 바뀝니다. pCVR 을 더해 센 전환은 1.55배가 됩니다. 더 작게 자를수록 사람 가운데 사는 몫인 전환율은 오르고, 전환 수는 줄어듭니다. 그런데 pCVR 이 높을수록 광고 없이도 샀을 사람의 비율이 커진다고 두면, 광고가 늘린 전환인 증분은 차이가 줄어듭니다. 상위 5% 는 전환이 세그먼트보다 많은데 증분은 더 적어집니다. 어느 가정이 맞는지는 광고를 일부러 안 보인 대조군과 비교해야 압니다.

> **골라 읽는 법** — 절이 6개인 글이고, 절마다 표나 코드나 카드가 들어 있어 그것만 보고 넘어가도 됩니다.
>
> - 317 안과 밖의 pCVR 이 어떻게 퍼져 있나 → 1절
> - 같은 2,290명을 pCVR 순서로 고르는 자리 → 2절
> - 상위 5%, 1% 로 좁힐 때의 전환율과 비용 → 3절
> - 어차피 살 사람을 빼고 남는 증분 → 4절
> - pCVR 을 타겟에 쓸 때 학습 데이터에 생기는 두 문제 → 5절
> - 담장 안과 열린 RTB 에서 달라지는 것 → 6절

이 글의 회원, 행동, pCVR, 비용은 전부 설명을 위한 가상 데이터입니다. 회원 1,400만 명, 세그먼트 317 의 160만 명, 하루 예산 300만 원은 타겟팅 트랙과 같은 값입니다. 전체 회원 대신 들여다보는 가상 회원, 곧 표본(sample) 20,000명은 [Lookalike 계산](post.html?id=lookalike-computation) 편과 같은 코드로 만듭니다. 카드 속 파랑은 세그먼트 317, 벽돌색은 그 밖의 회원, 먹색은 pCVR 상위로 자른 집합이고, 회색은 광고 없이도 일어났을 전환입니다.

## 1. 서연 씨의 부탁 「살 사람에게만」

**세그먼트 317 은 조건 셋 중 하나가 맞으면 붙는 번호라서 살 확률을 보지 않습니다. 가상 pCVR 을 매기면 그 안의 평균은 0.60% 이지만, 1% 넘는 회원과 0.1% 아래인 회원이 함께 들어 있습니다. 세그먼트 밖에도 1% 넘는 회원이 191명 있습니다.**

서연 씨의 「살 사람에게만」은 조건이 아니라 확률에 대한 부탁입니다. [오디언스와 세그먼트](post.html?id=audience-and-segments) 편이 적은 317 의 조건은 러닝 글이나 영상 3번 이상, 러닝 앱을 켠 날 5일 이상, 러닝화 검색 셋입니다. 셋 중 하나만 맞으면 붙어서, 러닝 글을 3편 읽은 회원과 30편 읽은 회원이 똑같이 317 입니다. 누가 살지는 번호에 적혀 있지 않습니다.

그 확률을 매기는 것이 pCVR 모델입니다. pCVR 은 predicted conversion rate 의 줄임말입니다. 이 글에서는 회원이 이 광고를 보면 살 확률을 모델이 예측한 값을 뜻합니다. [후보풀 여덟 질문](post.html?id=candidate-pool-questions) 편의 서연 씨 캠페인 pCVR 3.0% 는 클릭한 사람이 살 확률입니다. 그래서 광고를 누를 확률인 pCTR 과 곱해 쓰고, 이 글의 pCVR 과는 다른 양입니다. 이 글의 pCVR 은 13주째의 8차원 벡터로 만든 가상 값이고, 만드는 식은 2절 코드에 있습니다.

아래 표는 2절 코드가 찍은 값으로, pCVR 을 다섯 구간으로 나눠 317 안과 밖의 회원을 셉니다. 기대 전환은 그 회원들의 pCVR 을 더한 값입니다. 같은 사람들에게 광고를 보이는 일을 여러 번 되풀이하면, 전환 수는 평균으로 그 값에 모입니다. [타겟팅 기초](post.html?id=targeting-basics) 편은 광고가 닿는 사람 수에 전환율을 곱해 예상 전환 수를 셌습니다. 전환율은 광고를 본 사람 가운데 산 사람의 몫이고, 기대 전환은 그 셈을 사람마다 따로 한 것입니다.

| 1~3% | 280명 | 4.45건 | 178명 | 2.55건 |
| 3% 이상 | 61명 | 3.30건 | 13명 | 0.56건 |

세그먼트 안의 pCVR 은 가장 낮은 구간부터 가장 높은 구간까지 퍼져 있습니다. 1% 넘는 341명이 세그먼트의 기대 전환 가운데 절반 넘게를 내고, 0.3% 아래인 1,174명은 열에 하나 남짓을 냅니다. 세그먼트 밖은 대부분 0.3% 아래이지만, 그보다 높은 회원도 2,158명 있습니다. 이들은 세그먼트 안의 아래쪽 회원보다 살 확률이 높습니다.

## 2. 같은 크기로 자르면 전환율이 어떻게 달라지나

**표본을 pCVR 이 큰 순서로 정렬해 세그먼트와 같은 2,290명을 자르면, 그 가운데 1,390명이 세그먼트 밖 사람입니다. 기대 전환은 1.55배가 되고, 전환율은 0.60% 에서 0.93% 가 됩니다.**

이 글의 pCVR 은 [유저 프로파일 피처](post.html?id=user-profile-features) 편의 벡터로 만듭니다. 벡터의 값은 행동마다 30일 기록을 최근일수록 크게 쳐서 더한 값을 표준화한 z 점수입니다. 표본 평균을 빼고 표준편차로 나눠서, 0 이 평균입니다. 러닝 쪽 넷인 러닝화 검색, 운동 앱 일수, 러닝 글, 운동 용품 구매의 z 에 0.3 을 곱해 더하고, 나머지 넷은 쓰지 않습니다. 드문 행동은 z 가 크게 튀어서(13주째 표본에서 회원 A 의 러닝화 검색이 8.65), 3 을 넘는 z 는 3 으로 둡니다. 이 가중치와 상한은 실제 모델이 배운 값이 아니라 설명을 위해 정한 값입니다.

실제 pCVR 모델은 이 벡터 말고도 많은 피처, 곧 입력 숫자를 읽어서 벡터가 같은 두 회원도 pCVR 이 다릅니다. 그 몫은 정규분포의 잡음으로 더하는데, 정규분포는 0 근처의 값이 가장 흔하고 멀어질수록 드문 분포입니다. 평균 0, 표준편차 1 도 설명을 위해 정한 값이고, 잡음을 더 작게 두면 317 밖에서 pCVR 상위에 드는 사람이 줄어듭니다. 더한 값은 로지스틱 함수로 확률이 되는데, 로지스틱은 큰 수일수록 1 에, 작은 수일수록 0 에 가까운 값으로 바꾸는 함수입니다. 그 앞에 더하는 상수인 절편은 세그먼트 안의 평균이 다른 글의 0.60% 가 되게, 범위를 반씩 줄여 가는 이분법으로 찾습니다.

이 글은 pCVR 이 실제 전환 확률과 같다고, 곧 모델이 맞다고 둡니다. 그래서 회원마다 pCVR 의 확률로 사는지 안 사는지를 한 번 뽑고, 그렇게 센 수를 뽑힌 전환이라고 부릅니다. 2,290명에 0.6% 면 14건 안팎이라, 한 번 뽑은 수는 기대 전환에서 몇 건씩 벗어납니다. 그 폭을 표준편차로 같이 찍고, 집합끼리는 기대 전환으로 비교합니다. 실제 모델은 광고를 본 회원이 샀는지 안 샀는지를 정답으로 배우는데, 이 정답을 라벨이라고 부르고 5절에서 다시 봅니다.

아래 코드는 표본과 벡터를 만들고 pCVR 을 매긴 뒤, 1절 표의 구간을 셉니다. 그다음 네 집합을 비교하는데, 세그먼트 317 과 pCVR 상위 같은 크기, 상위 5%, 상위 1% 입니다. 마지막 단계는 전체 회원으로 옮긴 값과 비용 지수를 셉니다. 잡음과 전환 뽑기에는 서로 다른 난수를 써서, 트랙의 다른 글이 쓰는 난수와도 겹치지 않습니다.

```python
# 하는 일: 표본 20,000명에 가상 pCVR 을 매기고, 세그먼트 317 과 pCVR 상위 셋의 기대 전환, 뽑힌 전환, 비용을 비교한다.
import math
import random
import statistics

# 1단계: 표본과 벡터를 만든다
# 유저 프로파일 피처 편의 생성기와 벡터 코드를 글자 그대로 옮긴다. 표본은 Lookalike 계산 편과 같은 20,000명이고, 평균과 표준편차도 이 20,000명에서 센다.
KEYS = ['search_running_shoes', 'sports_app_days', 'running_posts', 'sports_goods_buy',
        'travel_posts', 'cafe_posts', 'camping_posts', 'camping_search']
NAMES = ['검색어 러닝화', '운동 앱 실행 일수', '러닝 글', '운동 용품 구매',
         '여행 글', '카페 글', '캠핑 글', '캠핑 용품 검색']
MEMBER_A = {
    'search_running_shoes': [0, 1, 2, 3, 5, 7, 9, 12, 15, 18, 22, 27],
    'sports_app_days': [0, 2, 4, 6, 9, 11, 13, 16],      # 켠 날을 적으니 같은 날이 두 번 없다
    'running_posts': [0, 0, 1, 1, 2, 3, 4, 5, 6],
    'sports_goods_buy': [5],
    'travel_posts': [17, 19, 22, 26],
    'cafe_posts': [1, 10, 20],
    'camping_posts': [],
    'camping_search': [],
}
MEMBER_B = {k: [] for k in KEYS}                         # 캠핑 둘 말고는 30일 동안 한 일이 없다
MEMBER_B['camping_posts'] = [0, 1, 3, 4, 6, 8, 10, 12, 14, 16, 18, 21, 23, 26, 28]
MEMBER_B['camping_search'] = [1, 3, 6, 10, 15, 21]
# 합계는 사건 수다. 가중합은 사건마다 0.5 ** (경과일 / 7) 을 더한 값이라 7일 전 사건은 절반만 센다.
HALF_LIFE = 7


def counts(m):
    return {k: len(m[k]) for k in KEYS}


def weighted(m):
    return {k: sum(0.5 ** (d / HALF_LIFE) for d in m[k]) for k in KEYS}


SEGMENT_317 = {'running_posts': 3, 'sports_app_days': 5, 'search_running_shoes': 1}   # 셋 중 하나


def in_segment_317(m):
    c = counts(m)
    return any(c[k] >= at_least for k, at_least in SEGMENT_317.items())


def runner_count(n):
    return n * 229 // 2000                               # 러닝 성향 11.45%, 2,000명이면 229명


# 행동마다 (그 행동을 하는 사람 비율, 하는 사람의 30일 평균 횟수). 앞은 러닝 성향, 뒤는 나머지다.
TENDENCY = {
    'search_running_shoes': ((0.17, 11.0), (0.00, 0.0)),
    'sports_app_days':      ((0.26, 9.0), (0.25, 2.5)),
    'running_posts':        ((0.46, 8.0), (0.25, 1.5)),
    'sports_goods_buy':     ((0.30, 1.5), (0.10, 1.2)),
    'travel_posts':         ((0.30, 4.0), (0.30, 4.0)),
    'cafe_posts':           ((0.40, 4.0), (0.40, 4.0)),
    'camping_posts':        ((0.08, 7.0), (0.12, 7.0)),
    'camping_search':       ((0.05, 5.0), (0.08, 5.0)),
}


def make_members(n, seed=7):
    """회원 n 명의 30일 행동. 0번은 회원 A, 1번은 회원 B 다."""
    rng = random.Random(seed)
    n_run = runner_count(n)
    runner = [True] * (n_run - 1) + [False] * (n - n_run - 1)   # A 는 러닝 성향, B 는 나머지
    rng.shuffle(runner)
    members = [dict(MEMBER_A), dict(MEMBER_B)]
    for is_runner in runner:
        while True:     # 러닝 성향은 조건이 하나라도 맞을 때까지, 나머지는 하나도 안 맞을 때까지 다시 뽑는다
            m = {}
            for k in KEYS:
                share, mean = TENDENCY[k][0 if is_runner else 1]
                does = rng.random() < share                     # 이 행동을 하는 사람인가
                days = range(30) if does else []                # 안 하는 사람은 날마다 뽑지 않는다
                m[k] = [d for d in days if rng.random() < mean / 30]
            if in_segment_317(m) == is_runner:
                break
        members.append(m)
    return members


members = make_members(20000)
ws = [weighted(m) for m in members]
mean = {k: statistics.fmean(x[k] for x in ws) for k in KEYS}
std = {k: statistics.pstdev([x[k] for x in ws]) for k in KEYS}


def vector(m):
    x = weighted(m)
    return [(x[k] - mean[k]) / std[k] for k in KEYS]


vecs = [vector(m) for m in members]
seg = [in_segment_317(m) for m in members]
inside = [i for i in range(len(members)) if seg[i]]
outside = [i for i in range(len(members)) if not seg[i]]
print(f'표본 {len(members):,}명, 세그먼트 317 {len(inside):,}명 ({len(inside) * 1000 // len(members) / 10}%)')

# 2단계: 가상 pCVR 을 매긴다
# 러닝 쪽 넷의 z 에 0.3 을 곱해 더하고, 8개 밖의 피처가 아는 몫을 표준편차 1 의 잡음으로 더해 로지스틱에 넣는다. z 가 3 을 넘으면 3 으로 둔다. 절편은 317 안의 pCVR 평균이 0.60% 가 되게 이분법으로 찾는다.
WEIGHT = {k: 0.3 for k in KEYS[:4]}                 # 여행 글, 카페 글, 캠핑 둘은 0
rng = random.Random(7 + 5)                          # 7 + 1 부터 7 + 4 는 트랙의 다른 글이 쓴다
score = [sum(WEIGHT.get(k, 0) * min(z, 3) for k, z in zip(KEYS, v)) + rng.gauss(0, 1) for v in vecs]


def pcvr(b):
    return [1 / (1 + math.exp(-(b + s))) for s in score]


def mean_of(p, ids):
    return statistics.fmean(p[i] for i in ids)


lo, hi = -12.0, 0.0
for _ in range(50):                                 # 317 안의 평균이 0.60% 보다 작으면 절편을 올리고, 크면 내린다
    b = (lo + hi) / 2
    lo, hi = (b, hi) if mean_of(pcvr(b), inside) < 0.006 else (lo, b)
p = pcvr(b)
print('가중치 0.3:', ', '.join(NAMES[:4]), '/ 나머지 넷은 0')
print(f'절편 {b:.3f}, pCVR 평균: 317 안 {mean_of(p, inside):.2%}, 317 밖 {mean_of(p, outside):.3%}, '
      f'표본 전체 {statistics.fmean(p):.3%}')

# 3단계: pCVR 구간마다 센다
# 구간마다 317 안과 밖의 사람 수와 기대 전환을 센다. 기대 전환은 그 사람들의 pCVR 을 더한 값이다.
BINS = [(0, 0.001, '0.1% 미만'), (0.001, 0.003, '0.1~0.3%'), (0.003, 0.01, '0.3~1%'),
        (0.01, 0.03, '1~3%'), (0.03, 1, '3% 이상')]
print('317 안  기대 전환   317 밖  기대 전환  pCVR 구간')

    a = [p[i] for i in inside if low <= p[i] < high]

    print(f'{len(a):>6,}  {math.fsum(a):>9.2f}  {len(c):>7,}  {math.fsum(c):>9.2f}  {name}')

# pCVR 이 실제 전환 확률과 같다고 두고, 회원마다 그 확률로 사는지를 한 번 뽑는다. 표준편차는 뽑을 때마다 달라지는 폭이다.

          f'{sum(not seg[i] for i in ids):>6,}  {name}')
```

비용은 가상 가정으로 셉니다. [캠페인 설정](post.html?id=campaign-setup-flow) 편의 하루 예산 300만 원을 세그먼트의 회원 전부에게 보이는 데 쓴다고 두고, 다른 집합은 사람 수에 비례해 씁니다. 그 캠페인의 나이와 지역 조건은 이 셈에서 뺍니다. 전환 단가는 입찰 설정에 달려 있고 [후보풀 여덟 질문](post.html?id=candidate-pool-questions) 편의 서연 씨 캠페인은 전환 하나에 20,000원이 목표라, 여기서는 비율만 봅니다. 그래서 전환당 비용은 세그먼트를 1.00 으로 둔 비용 지수로 적습니다. 사람 수가 세그먼트의 몇 배인지를 기대 전환이 몇 배인지로 나눈 값입니다.

## 4. 어차피 살 사람을 빼면 남는 증분

**기대 전환에는 광고가 없어도 일어났을 전환이 섞여 있고, 그것을 빼고 남는 것이 광고가 늘린 증분입니다. 광고 없이도 살 확률을 pCVR 의 60% 로 두면 증분은 어느 집합이든 기대 전환의 40% 입니다. pCVR 이 높을수록 그 비율이 크다고 두면 증분은 20% 남짓이 되고, 상위 5% 의 증분이 세그먼트보다 적어집니다.**

광고를 본 뒤 산 사람 가운데에는 광고가 없었어도 샀을 사람이 있습니다. 그 사람들의 전환을 기저 전환(baseline)이라고 부릅니다. 기대 전환에서 기저 전환을 뺀 나머지가 증분(incrementality), 곧 광고가 늘린 전환입니다. 한 사람이 광고 없이 샀을지는 볼 수 없어서, 실무에서는 광고를 일부러 안 보인 무리, 곧 대조군의 전환율로 측정합니다. 대조군을 떼는 설계는 [Uplift 와 증분 전환](post.html?id=uplift-incrementality) 편에 있습니다.

이 표본에는 대조군이 없어서, 광고 없이도 살 확률을 두 가지로 가정합니다. 시나리오 1 은 누구나 자기 pCVR 의 60% 입니다. 시나리오 2 는 그 비율이 pCVR 순위 백분위에 따라 0.4 에서 0.8 로 오릅니다. 백분위는 표본에서 그 사람보다 pCVR 이 낮은 사람의 몫이라, 가장 낮은 사람이 0 이고 가장 높은 사람이 1 입니다. 살 확률이 높은 사람일수록 이미 살 마음을 먹은 사람의 비율이 크다는 가정입니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 광고 없이도 살 확률(기저)을 두 가지로 가정해, 네 집합의 기대 전환에서 기저 전환을 빼고 남는 증분을 센다.

# 1단계: 기저가 pCVR 의 60% 라면
# 사람마다 광고 없이도 살 확률을 그 사람 pCVR 의 0.6 배로 둔다. 증분은 기대 전환에서 그 확률의 합인 기저 전환을 뺀 값이고, 증분 몫은 증분을 기대 전환으로 나눈 값이다.
def report(title, share):
    print(f' 기대 전환     증분  증분 몫  집합 ({title})')
    out = {}
    for name, ids in SETS:
        e = math.fsum(p[i] for i in ids)
        out[name] = e - math.fsum(p[i] * share[i] for i in ids)
        print(f'{e:>10.3f}  {out[name]:>7.3f}  {out[name] / e:>7.3f}  {name}')
    return out


flat = report('기저 = pCVR × 0.6', [0.6] * len(members))

# 2단계: 위쪽일수록 어차피 살 사람의 비율이 크다면
# 기저 비율을 pCVR 순위 백분위에 따라 바꾼다. 가장 낮은 사람은 0.4, 가장 높은 사람은 0.8 이고, 그 사이는 순위에 비례한다.
pct = [0.0] * len(members)
for r, i in enumerate(reversed(order)):             # 가장 낮은 사람이 0, 가장 높은 사람이 1
    pct[i] = r / (len(members) - 1)
tilt = report('기저 = pCVR × (0.4 + 0.4 × 백분위)', [0.4 + 0.4 * q for q in pct])

# 3단계: 증분당 비용 지수
# 앞 블록 5단계의 비용 지수와 같은 셈을 기대 전환 대신 증분으로 한다. 세그먼트 317 의 겉보기 전환당 비용이 1.00 이다.
print(' 겉보기  시나리오 1  시나리오 2  집합 (비용 지수, 세그먼트 317 의 겉보기 = 1.00)')
for name, ids in SETS:
    size = len(ids) / len(inside)
    e = math.fsum(p[i] for i in ids)
    print(f'{size / (e / e_seg):>7.2f}  {size / (flat[name] / e_seg):>10.2f}  {size / (tilt[name] / e_seg):>10.2f}  {name}')

# 출력:
# 1단계 뜻: 기저를 pCVR 의 60% 로 두면 증분 몫이 모두 0.400 이라, 집합의 순서가 기대 전환과 같다.
#  기대 전환     증분  증분 몫  집합 (기저 = pCVR × 0.6)
#     13.740    5.496    0.400  세그먼트 317
#     21.305    8.522    0.400  pCVR 상위 같은 크기
#     14.721    5.889    0.400  pCVR 상위 5%
#      6.588    2.635    0.400  pCVR 상위 1%
# 2단계 뜻: 기저 비율이 위쪽일수록 크면 증분 몫이 0.227 에서 0.201 로 내려가고, 상위 5% 의 증분이 세그먼트보다 적어진다.
#  기대 전환     증분  증분 몫  집합 (기저 = pCVR × (0.4 + 0.4 × 백분위))
#     13.740    3.117    0.227  세그먼트 317
#     21.305    4.567    0.214  pCVR 상위 같은 크기
#     14.721    3.042    0.207  pCVR 상위 5%
#      6.588    1.327    0.201  pCVR 상위 1%
# 3단계 뜻: 증분으로 세면 비용 지수가 시나리오 1 에서 2.5배, 시나리오 2 에서 4배 넘게 오른다.
#  겉보기  시나리오 1  시나리오 2  집합 (비용 지수, 세그먼트 317 의 겉보기 = 1.00)
#    1.00        2.50        4.41  세그먼트 317
#    0.64        1.61        3.01  pCVR 상위 같은 크기
#    0.41        1.02        1.97  pCVR 상위 5%
#    0.18        0.46        0.90  pCVR 상위 1%
```

시나리오 1 로는 무엇을 고를지가 바뀌지 않습니다. 기대 전환 가운데 증분의 몫, 곧 증분 몫이 어느 집합이든 같아서, 기대 전환이 많은 집합이 증분도 많습니다. 바뀌는 것은 비용 지수입니다. 증분으로 세면 전환당 비용이 2.5배가 되어, 세그먼트의 지수 1.00 이 2.50 이 됩니다.

시나리오 2 에서도 같은 크기의 결정은 그대로입니다. pCVR 상위의 증분이 여전히 세그먼트보다 많고, 1.55배이던 차이가 1.47배로 줄 뿐입니다. 위쪽일수록 기저 비율이 커서 증분 몫이 집합마다 달라지기 때문입니다.

어느 시나리오가 맞는지는 실험 없이는 모릅니다. 집합마다 대조군을 떼어 광고를 안 보인 쪽의 전환율을 측정해야 기저가 나옵니다. [Uplift 와 증분 전환](post.html?id=uplift-incrementality) 편은 pCVR 상위를 그대로 고르면 예산 대부분이 어차피 살 사람에게 간다고 적었습니다. 그 말이 얼마나 맞는지도 대조군으로 측정합니다.

## 5. pCVR 을 타겟에 쓰면 생기는 두 문제: 노출된 사람만 라벨이 있고, 상위만 보이면 다음 학습이 고정됩니다

**1~4절은 pCVR 이 맞다고 두었지만, 실제 모델은 광고를 본 회원의 전환으로 배웁니다. 그래서 광고를 본 적 없는 회원의 pCVR 은 맞는지 확인할 데이터가 없습니다. 상위에게만 보이면 다음 학습 데이터도 상위에서만 나와 순서가 그대로 고정됩니다.**

모델이 정답으로 배우는 라벨, 곧 샀는지 안 샀는지는 과거에 광고를 본 회원에게서만 생깁니다. 지금까지 317 에만 보였다면 라벨은 317 회원에게만 있습니다. 그러면 pCVR 상위 같은 크기로 들어온 1,390명은 모델이 라벨 없이 짐작한 사람입니다. 라벨이 있는 무리와 모델을 쓰는 무리가 달라 생기는 이 문제를 표본 선택 편향(sample selection bias)이라고 부릅니다.

둘째 문제는 고른 사람만 다음 라벨이 된다는 것입니다. pCVR 상위 2,290명에게만 보이면 내일의 학습 데이터도 그 사람들에게서 나옵니다. 경계 0.392% 아래로 밀린 17,710명은 pCVR 이 낮게 잘못 매겨졌어도 고칠 라벨이 생기지 않습니다. 이 무리는 1절의 「317 밖」과 수만 같고, 세그먼트 회원 1,390명이 들어 있는 다른 무리입니다. 어제의 모델이 고른 사람이 오늘의 데이터가 되는 이 고리가 [피드백 루프 편향](post.html?id=feedback-loop-bias) 편의 주제입니다.

| 문제 | 왜 생기나 | 이 표본에서는 | 줄이는 방법 |
|---|---|---|---|
| 노출된 사람만 라벨이 있다 | 전환은 광고를 본 회원에게서만 기록된다 | 317 에만 보였다면, 들어온 1,390명은 라벨 없이 고른 사람이다 | 예산 일부로 넓게 보여 라벨을 모은다 |
| 상위만 보이면 다음 학습이 고정된다 | 고른 사람의 전환만 다음 학습 데이터가 된다 | 같은 크기로만 보이면, 경계 아래 17,710명(세그먼트 회원 1,390명 포함)은 새 라벨이 없다 | 무작위로 보인 몫으로 보일 확률을 알고 가중해 배운다 |

두 문제의 처방은 같은 쪽입니다. 예산 일부를 pCVR 과 상관없이 넓게 보여 라벨을 모으는 일을 탐색이라고 부르고, [탐색과 활용](post.html?id=exploration-exploitation) 편이 그 몫을 정하는 법을 다룹니다. 무작위로 보인 몫이 있으면 회원마다 보일 확률을 알 수 있어서, 그 역수로 가중해 배울 수 있습니다. [피드백 루프 끊기](post.html?id=feedback-loop-remedies) 편이 이런 처방 넷과 그 대가를 셉니다.

4절의 대조군도 값을 치르고 사는 정보입니다. 대조군은 고른 사람에게 일부러 안 보여 기저를 측정하고, 탐색은 고르지 않은 사람에게 보여 pCVR 을 고칩니다. 둘 다 그날의 전환 일부를 내놓고 얻는 것이라, 얼마를 떼어 둘지를 예산으로 미리 정합니다. 대조군을 몇 % 떼어야 차이를 잡아낼 수 있는지는 [Uplift 와 증분 전환](post.html?id=uplift-incrementality) 편이 셉니다.

## 6. 회원 목록과 전환 라벨이 한 곳에 모이나가 무대마다 다릅니다

**pCVR 순서로 고르는 셈은 두 무대가 같습니다. 담장 안에서는 플랫폼이 회원 전부의 pCVR 과 전환을 갖고 있어 광고주의 조건 밖까지 고를 수 있습니다. 열린 RTB 에서는 광고를 사는 쪽이 입찰 요청마다 pCVR 을 매기고, 이긴 경매의 전환만 라벨로 받습니다.**

1~5절은 회원 20,000명의 벡터, pCVR, 전환이 모두 한 회사 안에 있다는 전제 위에 있었습니다. 누가 회원 목록을 갖고 전환을 누가 받느냐가 무대마다 다릅니다.

### 담장 안에서는 광고주의 조건 밖까지 골라 줍니다 [무대: 닫힌 생태계]

한 회사가 앱과 광고 서버를 다 가진 담장 안에서는 회원 1,400만 명의 벡터와 pCVR 모델이 한 곳에 있습니다. 광고주 사이트의 전환 기록도 같은 회원 번호로 돌아옵니다. 그래서 광고주가 적은 조건을 출발점으로 두고, 조건 밖에서도 pCVR 이 높은 회원에게 보이는 상품을 만들 수 있습니다. Meta 의 Advantage+ audience 가 그런 상품입니다. 광고주의 타겟 조건은 제안으로 먼저 쓰고, 지역이나 최소 나이처럼 넘으면 안 되는 조건은 통제 조건으로 따로 받습니다.

남는 일은 4절의 증분입니다. 회원 번호로 대조군을 떼어 광고를 막을 수 있어서, 집합마다 증분을 측정할 수 있습니다. 2019년의 한 연구는 Facebook 의 광고 실험 15건을 기준으로 관측 데이터의 추정을 비교했습니다. 대조군 없이 맞춘 효과는 실험으로 측정한 효과와 다른 일이 많았고, 대부분 더 크게 나왔습니다.

### 열린 RTB 에서는 이긴 경매의 전환만 돌아옵니다 [무대: 열린 RTB]

열린 RTB 에서 광고를 사는 쪽의 시스템을 DSP 라고 부릅니다. DSP 는 회원 목록을 먼저 고르지 않고, 입찰 요청이 올 때마다 그 사람의 pCVR 로 입찰가를 정합니다. 그래서 「상위 N 명」을 고르는 대신 pCVR 이 높은 요청에 높게 부르는 꼴이 되고, 그 요청을 다른 DSP 에 지기도 합니다.

전환 라벨은 이긴 경매에서 보인 광고에만 붙어서, 5절의 첫째 문제가 더 커집니다. 남의 지면에서는 대조군에게 광고를 막기도 어렵습니다. 대신 대조군의 요청에도 입찰가는 평소처럼 계산하되 응찰은 하지 않습니다. 입찰했을 요청만 기록해 두는 이 방법을 유령 입찰(ghost bidding)이라고 부르고, 이렇게 증분을 측정합니다. 아래 표는 가상 데이터가 아니라 두 무대의 설계 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 고르는 단위 | 회원 목록의 상위 N 명 | 입찰 요청 한 건의 입찰가 |
| 전환 라벨 | 보인 노출 전부, 광고주 사이트의 전환이 회원 번호로 온다 | 이긴 경매에서 보인 노출만 |
| 조건 밖으로 넓히기 | 광고주 조건을 제안으로 두고 넓힌다 | DSP 가 가진 쿠키 기록 안에서만 |
| 증분 측정 | 회원 번호로 대조군을 떼어 광고를 막는다 | 유령 입찰로 입찰했을 요청만 기록한다 |

다음 편은 17주째의 컨텍스추얼 타겟팅입니다. 이 글은 회원마다 30일 기록이 있다는 전제로 pCVR 을 매겼습니다. 다음 편은 기록이 없는 사람에게 지면의 글로 광고를 고릅니다.

|---|---|---|
| 세그먼트 317 | 조건 셋 중 하나가 맞으면 번호를 붙인다 | 2,290명, pCVR 평균 0.60%, 기대 전환 13.740건 |
| 가상 pCVR | 러닝 쪽 z 넷에 0.3, 잡음 표준편차 1, 로지스틱 | 절편 -6.805, 표본 전체 평균 0.206% |
| 같은 크기 | pCVR 순서로 2,290명을 자른다 | 1,390명이 317 밖, 전환율 0.93%, 기대 전환 21.305건 |
| 상위 5%, 1% | 더 작게 자른다 | 전환율 1.47% 와 3.29%, 비용 지수 0.41 과 0.18 (세그먼트 = 1.00) |
| 증분, 시나리오 1 | 기저를 pCVR 의 60% 로 둔다 | 증분 몫 0.400, 순서는 기대 전환과 같다 |
| 증분, 시나리오 2 | 기저 비율이 백분위에 따라 0.4~0.8 | 증분 몫 0.201~0.227, 상위 5% 가 세그먼트 아래 |

## 헷갈리기 쉬운 점

- **전환율이 높은 집합이 전환 수도 많은 것은 아닙니다.** 상위 1% 는 전환율이 3.29% 로 세그먼트의 5배를 넘습니다. 그래도 전체로 옮긴 기대 전환은 약 4,600건으로, 세그먼트의 약 9,600건보다 적습니다. 전환율은 사람 가운데 사는 몫이고, 전환 수는 거기에 사람 수를 곱한 값입니다.
- **pCVR 상위와 Lookalike 는 순위를 매기는 기준이 다릅니다.** Lookalike 는 광고주가 건넨 고객 목록인 시드와 얼마나 닮았나로, pCVR 은 얼마나 살 것 같나로 순위를 매깁니다. 같은 표본에서 Lookalike 10% 2,000명은 러닝 성향, 곧 317 회원의 몫이 0.709 였습니다. pCVR 상위 같은 크기 2,290명에서는 900명이라 0.393 입니다. 13주째 글이 비교할 기준으로 적은 유사타겟 10% 의 0.90% 는 다른 글의 가상 표에서 왔습니다. 그래서 이 글의 0.93% 와 크기를 비교하지 않습니다.
- **이 글의 pCVR 은 광고를 본 사람이 살 확률입니다.** [후보풀 여덟 질문](post.html?id=candidate-pool-questions) 편의 서연 씨 캠페인 pCVR 3.0% 는 클릭한 사람이 살 확률이라, pCTR 1.2% 와 곱해 점수를 냅니다. 이 글의 0.60% 는 타겟팅 기초 편의 전환율처럼 광고를 본 사람 가운데 사는 몫이라, 3.0% 와 바로 비교하지 않습니다.
- **증분은 대조군 없이는 가정입니다.** 4절의 두 시나리오는 같은 pCVR 에서 증분 몫을 0.400 과 0.2 남짓으로 냈고, 상위 5% 와 세그먼트의 순서도 바꿨습니다. 어느 쪽이 맞는지는 광고를 안 보인 대조군의 전환율로만 측정합니다.

## 더 깊이 보기

:::deep 가상 pCVR 생성식과 절편을 찾는 이분법
회원 $i$ 의 가상 pCVR 은 아래와 같습니다. $R$ 은 러닝 쪽 넷이고, $z_{ik}$ 는 행동 $k$ 의 z 점수, $b$ 는 절편입니다.

$$p_i = \sigma\Big(b + 0.3 \sum_{k \in R} \min(z_{ik}, 3) + \varepsilon_i\Big), \qquad \sigma(x) = \frac{1}{1 + e^{-x}}, \qquad \varepsilon_i \sim N(0, 1)$$

가중치 0.3 은 z 가 1 오를 때 오즈가 $e^{0.3} \approx 1.35$ 배가 된다는 뜻입니다. 오즈는 살 확률을 안 살 확률로 나눈 값이고, 확률이 작으면 확률과 거의 같습니다. 넷이 모두 3 이면 더해지는 값은 $0.3 \times 3 \times 4 = 3.6$ 입니다. 오즈로는 $e^{3.6} \approx 37$ 배입니다. 잡음이 표준편차 하나만큼이면 한 회원의 오즈가 $e^{1} \approx 2.7$ 배 오르내린다는 뜻입니다.

절편은 317 안의 평균 $f(b)$ 가 0.006 이 되게 정합니다. $f$ 는 $b$ 가 커질수록 커집니다. 그래서 $[-12, 0]$ 의 가운데 값을 넣어 0.006 보다 작으면 아래 절반을, 크면 위 절반을 버립니다. 50번이면 구간의 폭이 $12 / 2^{50}$ 이라, 절편이 -6.805 로 정해집니다.

뽑힌 전환의 표준편차는 사람마다의 분산 $p_i(1 - p_i)$ 를 더해 제곱근을 씌운 값입니다.

$$\mathrm{SD} = \sqrt{\sum_{i} p_i \,(1 - p_i)}$$

세그먼트는 3.66건이라, 기대 전환 13.740건에서 표준편차 하나 안쪽이 대략 10~17건입니다. 실제 모델이 이 글처럼 맞는지는 예측의 합을 실제 전환과 비교하는 COPC(실제 ÷ 예측)로 확인합니다.
:::

:::deep 기저 가정 두 가지와, 순서가 바뀌는 조건
시나리오 1 의 기저 확률은 $0.6\,p_i$ 라서, 집합 $S$ 의 증분은 기대 전환 $E(S)$ 의 0.4 배입니다.

$$\mathrm{inc}_1(S) = \sum_{i \in S} (p_i - 0.6\,p_i) = 0.4\,E(S), \qquad E(S) = \sum_{i \in S} p_i$$

시나리오 2 의 기저 비율은 $0.4 + 0.4\,q_i$ 이고, $q_i$ 는 pCVR 순위 백분위입니다. 표본 $N$ 명 가운데 그 회원보다 pCVR 이 낮은 사람이 $r_i$ 명이면 $q_i = r_i / (N - 1)$ 입니다.

$$\mathrm{inc}_2(S) = \sum_{i \in S} p_i \,(0.6 - 0.4\,q_i) = 0.6\,E(S) - 0.4\,Q(S), \qquad Q(S) = \sum_{i \in S} p_i \, q_i$$

두 집합 $A$, $B$ 의 차이는 $0.6\,(E_A - E_B) - 0.4\,(Q_A - Q_B)$ 입니다. pCVR 상위는 $q$ 가 1 에 가까운 사람만 모여서, 기대 전환이 같아도 $Q$ 가 더 큽니다. 그래서 기대 전환의 차이가 작으면 뒤의 항이 앞의 항을 넘습니다.

상위 5% 는 기대 전환의 차이가 0.981 뿐이라 시나리오 2 에서 순서가 바뀌었습니다. 같은 크기는 차이가 7.565 라 바뀌지 않았습니다.

실무에서는 기저를 가정하는 대신 대조군으로 집합마다의 증분을 측정하는 일이 흔하고, 사람마다의 증분을 모델로 맞히는 곳도 있습니다. 광고를 본 쪽과 안 본 쪽의 전환 확률을 따로 배워 빼는 T-learner 같은 방법이 Uplift 와 증분 전환 편에 있습니다. 그 모델도 배우려면 대조군이 있어야 합니다.
:::
