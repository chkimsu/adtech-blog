광고주 에이전트 카드 네 장

서연 씨가 대화로 캠페인을 손보는 에이전트를 카드 네 장으로 봅니다. 도구는 MCP 서버가 내놓고, 쓰기는 광고주의 승인과 서버의 가드레일을 지나야 합니다. 캠페인 셋과 어제 통계는 가상 데이터입니다.

파랑 = 호스트와 클라이언트의 코드 벽돌색 = 모델이 고른 것 먹색 = MCP 서버 회색 = 막힌 호출 점선 상자 = 가상 값과 승인 기록

MCP

클라이언트와 서버

쉽게 말하면 모델은 호스트 안에 있고, 캠페인 도구는 서버가 내놓습니다. 호스트의 클라이언트와 서버는 JSON-RPC 메시지로만 주고받습니다.

요청은 셋입니다. 요청마다 _meta 에 버전 2026-07-28 과 클라이언트 기능을 적습니다.

TOOLS

읽기와 쓰기

쉽게 말하면 서버가 목록에 올린 도구만 모델이 고를 수 있고, 서버가 보여 주는 캠페인만 읽힙니다.

쓰기를 켠 서버는 도구 3개, 끈 서버는 읽기 도구 2개를 내놓습니다. 서연 씨의 서버는 c1 만 보여 줍니다.

APPROVAL

승인 단계

쉽게 말하면 읽기는 서버를 붙일 때 받은 허락으로 바로 돌고, 입찰가 변경은 서연 씨가 그 호출을 승인해야 서버로 갑니다.

서연 씨의 요청은 4단계에 끝났고, 입찰가는 20,000원에서 18,000원이 되었습니다.

GUARD

서버의 가드레일

쉽게 말하면 승인을 받아도 서버는 20% 상한을 다시 봅니다. 막힌 호출도 결과나 오류로 돌아옵니다.

막힌 길 셋은 막은 자리가 다릅니다. 호스트의 approve, 서버의 가드레일, 서버의 도구 목록입니다.

현업에서는 이렇게 씁니다

  • 입찰가를 바꾸는 도구에는 호스트의 승인과 서버의 상한을 함께 둡니다. 하루 누적 한도는 이 카드의 서버에도 없습니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 광고주 에이전트 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 도구 셋과 루프를 처음 다룬 글은 Tool use 와 에이전트 루프 편입니다.
