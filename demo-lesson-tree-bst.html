트리와 BST: 배열 입력, 높이 재귀, 중위 순회

LeetCode 의 트리 문제가 시작되는 세 장면을 한 단계씩 따라갑니다. 첫 탭은 층별 순서 배열이 트리가 되고 None 에서 오류가 나는 모습, 둘째 탭은 높이를 구하는 재귀 maxDepth 의 호출과 반환, 셋째 탭은 BST 에 값을 넣고 중위 순회로 정렬된 배열로 펼치는 모습입니다.

한 줄 요약
BST 를 중위 순회로 읽으면 작은 값부터 나오는 정렬된 배열이 되고, 비교 횟수는 트리의 높이가 정합니다. 값 7개를 50, 30, 70, 20, 40, 60, 80 순서로 넣으면 높이 3에 넣을 때 비교 10번이고, 20, 30, 40, 50, 60, 70, 80 순서로 넣으면 높이 7에 비교 21번입니다. 같은 값 7개라도 80을 찾을 때 비교는 각각 3번과 7번입니다.
보여 주는 장면과외에서 지훈 씨가 트리 문제를 풀며 막힌 세 장면입니다. LeetCode 가 주는 배열 [3, 9, 20, null, null, 15, 7] 이 어떻게 트리가 되는지, 높이를 구하는 재귀 maxDepth(LeetCode 104)가 어떤 순서로 부르고 돌려주는지, BST 를 중위 순회하면 왜 정렬된 배열이 되는지(LeetCode 230 의 바탕)를 봅니다. 입력은 노드 7개 이하라 단계를 모두 따라갈 수 있습니다. 층별 순회는 첫 탭의 「다음 층」이 보여 줍니다. LeetCode 배열이 층별 순서이기 때문이고, 층마다 퍼져 나가는 BFS 는 BFS 데모에서 이어서 봅니다.
목적첫 탭에서는 배열의 칸이 부모의 왼쪽, 오른쪽 자식으로 붙는 순서와 null 이 자식 없는 자리가 되는 것, 그리고 존재하지 않는 자식에서 .val 을 읽으면 오류가 나는 것을 확인합니다. 둘째 탭에서는 maxDepth 가 왼쪽 자식을 먼저 부르고 None 에서 0을 돌려받아 1 + max(왼쪽, 오른쪽)로 높이를 올려 가는 과정을 확인합니다. 셋째 탭에서는 넣는 순서에 따라 트리 높이가 3 또는 7이 되고 비교 횟수가 달라지는 것과, 어느 순서로 넣어도 중위 순회 결과가 같은 정렬된 배열인 것을 확인합니다. 입력은 다섯 가지입니다. 첫 탭과 둘째 탭은 [3, 9, 20, null, null, 15, 7](LeetCode 104 의 예제 1)과 [1, null, 2](예제 2), 셋째 탭은 균형 순서 [50, 30, 70, 20, 40, 60, 80], 정렬 순서 [20, 30, 40, 50, 60, 70, 80], LeetCode 230 의 예 [5, 3, 6, 2, 4, 1] 에 k = 3 입니다.
결과 읽는 법결과 칸은 첫 탭에서 경로를 따라간 값 또는 오류 문장, 둘째 탭에서 높이, 셋째 탭에서 펼친 배열(230 은 k번째로 작은 값)입니다. 아랫줄에는 층별 값, maxDepth 를 부른 횟수, BST 의 높이와 비교 횟수가 나옵니다. 점선 노드는 None 자식이고, 파란 테두리 노드가 지금 보는 노드, 연한 파란 노드가 방금 붙인 노드, 진한 파란 노드가 찾은 값이나 방문한 노드, 붉은 노드가 오류가 난 자리입니다. 둘째 탭의 노드 아래 작은 숫자는 그 노드가 돌려준 값입니다. 셋째 탭의 트리 밑 칸은 펼친 배열이고 같은 열의 노드가 그 칸의 값입니다. 파이썬 코드와 비용은 글에서 이어서 봅니다.
    따라 하는 순서
  1. 탭 배열 입력과 None에서 입력은 [3, 9, 20, null, null, 15, 7] 입니다. 「다음 층」을 한 번 누르면 3으로 루트를 만들고, 두 번째에는 9와 20이 붙고, 세 번째에는 배열 3, 4번 칸의 null 두 개가 9의 None 자식이 되고 15와 7이 20의 자식이 되어 층 셋이 모두 생깁니다. 네 번째에는 경로 root, root.right, root.right.left 를 끝까지 따라가 마지막 값 15가 진한 파란색이 됩니다(「한 칸」은 이 경로를 한 칸씩 따라갑니다). 결과 칸에 「root.right.left.val = 15」, 아랫줄에 층별 값 [[3], [9, 20], [15, 7]] 이 나옵니다.
  2. 같은 탭에서 입력 목록의 배열 [1, null, 2] 를 고르고 「끝까지」를 누릅니다. 루트 1의 왼쪽은 null 이라 None 자식이고 오른쪽에 2가 붙습니다. 같은 경로를 따라가면 root.right 는 2이고 root.right.left 는 2의 None 자식이라 붉게 칠해지고, 결과 칸에 AttributeError: 'NoneType' object has no attribute 'val' 이 붉은 글자로 나옵니다.
  3. 탭 높이를 구하는 재귀에서 입력은 [3, 9, 20, null, null, 15, 7] 입니다. 「다음 반환」을 한 번 누르면 루트 3, 9를 차례로 부르고 9의 두 None 자식에서 0, 0을 받아 1 + max(0, 0) = 1을 돌려주는 곳까지 넘어가며, 9 아래에 1이 나옵니다. 상태 칸의 호출 중에는 지금 쌓인 호출이 루트부터 칩으로 나옵니다. 「끝까지」를 누르면 결과 칸에 「높이 3」, 아랫줄에 「maxDepth 호출 11번(노드 5개, None 자식 6개)」이 나오고 노드 아래에 1, 1, 1, 2, 3 이 남습니다.
  4. 탭 BST 와 중위 순회에서 입력은 [50, 30, 70, 20, 40, 60, 80] 입니다. 「다음 값」을 한 번 누르면 50이 루트가 되고, 다섯 번째에는 40을 넣으며 「50보다 작아 왼쪽, 30보다 커서 오른쪽 빈자리에 둡니다」라고 적힙니다. 두 번 더 누르면 값 7개를 모두 넣고, 이후 한 번에 한 값씩 중위 순회로 방문해 트리 밑의 펼친 배열 칸이 왼쪽부터 채워집니다. 「끝까지」를 누르면 결과 칸에 「펼친 배열 [20, 30, 40, 50, 60, 70, 80]」, 아랫줄에 「높이 3, 넣을 때 비교 10번, 80을 찾으면 비교 3번」이 나옵니다.
  5. 입력 목록에서 [20, 30, 40, 50, 60, 70, 80] 을 고르고 「끝까지」를 누르면 트리가 오른쪽으로만 이어진 7층이 되고 아랫줄에 「높이 7, 21번, 7번」이 나옵니다. 펼친 배열은 균형 순서와 같습니다. 입력 목록에서 [5, 3, 6, 2, 4, 1], k = 3 을 고르고 「끝까지」를 누르면 방문 세 번 만에 멈추고 3이 진한 파란색이 되며 결과 칸에 「3번째로 작은 값 3」이 나옵니다. 탭이나 입력을 바꾸면 처음 상태로 돌아갑니다.
