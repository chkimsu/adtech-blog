한 줄 요약
UCB1 에 유저 정보를 더한 알고리즘입니다. UCB1 이 「어느 광고가 평균적으로 좋은가」를 배운다면, LinUCB 는 「이 유저 타입에는 어느 광고가 좋은가」를 배웁니다. 유저 취향 벡터(컨텍스트)와 광고 가중치 벡터(θ)의 내적이 추천 점수가 됩니다.
이 데모가 보여주는 것광고마다 "예측 점수(색깔 막대) + 불확실성 보너스(회색 막대)"를 합쳐 추천을 고르고, 클릭 피드백 한 번이 학습 가중치(θ)를 실시간으로 바꾸는 과정을 직접 만들어 봅니다.
왜 알아야 하나UCB1, 톰슨 샘플링은 모든 유저에게 같은 답을 주지만, 실제 광고는 유저마다 다른 답(개인화)이 필요합니다. LinUCB는 유저와 광고의 특징을 수식에 넣는 가장 기본적인 문맥형 밴딧이라, 실무 추천 시스템 공부의 출발점입니다.

  1. 유저 타입을 Tech로 선택 → 추천된 Ad A를 5번 Click → θ 행렬이 어떻게 업데이트되는지 관찰.
  2. 유저 타입을 Fashion으로 변경 → 같은 Ad A를 클릭해도 점수가 다른 이유 확인 (context가 다름).
  3. α 슬라이더로 탐색 강도 조정 → α↑ 시 새 광고도 자주 시도, α↓ 시 익숙한 광고에 집중.

작동 원리

이 데모는 LinUCB (Linear Upper Confidence Bound) 알고리즘을 브라우저에서 직접 실행합니다.

  • 컨텍스트 벡터 (x): 각 광고는 고정된 피처 벡터(예: 기술 점수, 패션 점수 등)를 갖습니다.
  • 가중치 벡터 (θ): 알고리즘이 각 광고에 대해 학습하는 믿음(belief)입니다. 클릭이 쌓일수록 정밀해집니다.
  • 광고 선택: 점수 = (예측 점수: xᵀθ) + (탐색 보너스: α × √(xᵀA⁻¹x)) 로 계산하여 가장 높은 광고를 추천합니다.
  • 모델 업데이트: 클릭 시 행렬 A와 벡터 b를 갱신하여 다음 추천을 더 정확하게 개선합니다.

Disjoint LinUCB 점수 읽기

이 데모는 Disjoint LinUCB 가 광고마다 점수를 매기는 과정을 막대그래프로 보여 줍니다.

아래에서 막대 하나가 무엇을 뜻하는지, 어떤 광고가 왜 추천되는지를 차례로 봅니다.

1. 광고마다 따로 배웁니다

이 데모의 코드는 this.A = [] 배열을 만들어 광고(Arm)마다 행렬 A 와 벡터 b 를 따로 둡니다.
그래서 막대 4개는 서로의 데이터를 쓰지 않고 각자 점수를 계산합니다. 이름의 Disjoint 가 이 뜻입니다.

  • Ad A 의 점수: Ad A 가 노출되고 클릭된 기록만 반영합니다.
  • Ad B 의 점수: Ad A 가 클릭되었는지와 상관없습니다.

2. 막대 하나 읽기

막대 하나는 LinUCB 의 점수 공식 「최종 점수 = 예측 점수(Exploitation) + 탐색 가산점(Exploration)」을 두 부분으로 쌓은 것입니다.

① 막대 전체 높이 = 최종 UCB 점수

  • 모델은 전체 높이가 가장 높은 광고를 유저에게 보여 줍니다.
  • 그 광고에 [Recommended] 표시가 붙습니다.

② 아래 색 막대 = 예측 점수 (Exploitation)

  • 뜻: 지금까지 배운 가중치로 계산한 xᵀθ 입니다. 이 유저가 이 광고를 클릭할 가능성을 지금 데이터로 추정한 값입니다.
  • 읽는 법: 색 막대가 높은 광고는 지금까지의 데이터로 이 유저에게 잘 맞는다고 추정된 광고입니다. 색 막대가 낮으면 이 유저의 클릭이 덜 나올 것으로 추정된 광고입니다.

③ 위 회색 막대 = 탐색 가산점 (Exploration)

  • 뜻: α × √(xᵀA⁻¹x) 입니다. 그 광고의 데이터가 적을수록 커집니다.
  • 읽는 법: 노출이 쌓일수록 회색 막대는 줄어듭니다. 회색 막대가 두꺼운 광고는 아직 데이터가 적어서 한 번 더 보여 줄 값어치가 크다고 계산된 광고입니다.

3. 순위를 읽는 예

네 막대의 순위는 두 부분을 더한 결과입니다. 예를 들면 이렇게 읽습니다.

  • 1등: 예측 점수가 높고, 탐색 가산점도 조금 남아 있어서 합이 가장 큽니다.
  • 2등: 예측 점수는 1등보다 낮지만, 데이터가 적어 탐색 가산점이 큽니다.
    • 1등을 계속 보여 주면? 1등의 회색 막대가 줄어들어 언젠가 2등과 순위가 바뀔 수 있습니다. 이것이 탐색입니다.
  • 3등: 예측 점수와 탐색 가산점이 둘 다 중간입니다.
  • 꼴찌: 예측 점수가 낮고, 노출이 이미 쌓여 탐색 가산점도 작습니다.

4. 요약

Disjoint LinUCB 는 지금 기대되는 클릭(색 막대)과 데이터를 더 모을 값어치(회색 막대)를 더해 광고를 고릅니다.

  • 유저가 추천된 광고를 클릭하면
    1. 그 광고의 색 막대(예측 점수)는 커집니다.
    2. 회색 막대(탐색 가산점)는 줄어듭니다. 그 광고의 데이터가 하나 더 쌓였기 때문입니다.

Feature Vector 설계

이 데모에서는 3개의 Feature(Matching Score, User Gender, Seasonality)를 사용합니다. 실무에서는 훨씬 다양한 Feature를 사용합니다:

  • 유저 Feature: 연령대, 성별, 관심사 세그먼트, 최근 검색어, 방문 이력
  • 광고 Feature: 카테고리, 브랜드, 크리에이티브 타입, 랜딩 페이지 품질
  • 컨텍스트 Feature: 시간대, 요일, 디바이스, 지면 카테고리

Disjoint vs Hybrid LinUCB

이 데모는 Disjoint LinUCB를 구현합니다. 각 광고가 독립적으로 학습하므로 광고 A의 학습 결과가 광고 B에 전이되지 않습니다. 신규 광고가 빈번한 환경에서는 Hybrid LinUCB로 확장하여 광고 간 공통 지식을 공유하는 것이 효과적입니다.

데모 실험 가이드

  • Ad A (Tech)를 5번 이상 Click하면: Prediction 점수가 상승하고 Uncertainty가 줄어드는 것을 관찰할 수 있습니다.
  • Ad D (Travel)를 Ignore하면: reward=0으로 학습되어 Prediction이 하락합니다.
  • 모든 광고를 균등하게 Click하면: Uncertainty가 균등하게 줄어들어 순수 Prediction 기반 경쟁이 됩니다.
  • 한 광고만 집중 Click하면: 해당 광고의 Uncertainty가 빠르게 줄지만, 나머지 광고는 Uncertainty 보너스로 여전히 경쟁력을 유지합니다.

현업에서는 이렇게 씁니다

기본 밴딧(UCB1, TS)이 "어떤 광고가 평균적으로 좋은가"를 풀었다면, 현업의 다음 질문은 "이 유저에게는 어떤 광고가 좋은가"입니다. LinUCB는 유저의 Context(검색어, 성별, 시간대 등)를 피처 벡터로 수식에 넣어, 평균 CTR만 보던 한계를 개인화로 넘어섭니다.

  • 개인화 추천의 고전: Yahoo! 뉴스 추천에 적용되며 유명해진 알고리즘입니다. 광고에서는 "이 지면, 이 유저 세그먼트에 어떤 소재를 내보낼까"를 고르는 데 같은 구조를 씁니다.
  • 신규 광고 콜드 스타트 완화: 광고 ID가 아니라 피처의 가중치를 학습하므로, 피처만 채워져 있으면 새 광고도 첫 노출부터 합리적인 점수로 출발합니다.
  • 탐색 강도 α의 운영: 트래픽이 많은 지면은 α를 낮춰 안정적으로, 데이터가 적은 신규 지면은 α를 높여 탐색 위주로 — 이 데모의 α 슬라이더가 실제 운영에서 돌리는 노브에 해당합니다.

이 데모에서 알게 된 3가지

  1. Context Vector로 학습 — 광고 ID가 아닌 피처(성별, 관심사, 시간대 등) 가중치를 학습하므로, 처음 보는 유저와 광고에도 일반화된다.
  2. 점수 = 예측(Exploitation) + 불확실성(Exploration) — θᵀx는 기댓값, √(xᵀA⁻¹x)는 불확실성 타원의 반지름. 둘의 합이 UCB 스코어다.
  3. Cold Start 거의 없음 — 피처만 괜찮다면 새 광고도 처음부터 합리적 점수로 시작해, 개별 UCB1, TS를 크게 앞지른다.
