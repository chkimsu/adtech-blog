새 배너 소재 5개를 한 캠페인에 한꺼번에 올리고 사흘이 지나자 클릭이 조금씩 쌓였지만 어느 소재가 진짜 좋은지는 아직 알 수 없습니다. 이 글에서 소재(creative)는 광고로 화면에 실제로 나가는 배너 하나를 가리킵니다.

이럴 때 먼저 떠오르는 방법은 두 가지입니다. 첫째는 5개를 계속 똑같이 나눠 보여 주는 방법인데, 공평해 보여도 성적이 나쁜 소재에까지 예산이 계속 나갑니다. 둘째는 지금까지 성적이 가장 좋아 보이는 소재 하나만 밀어주는 방법인데, 사흘치 클릭 수는 너무 적어서 운 좋게 클릭이 몇 번 몰렸을 뿐인 소재를 1등으로 믿고 나머지 4개를 꺼 버리면 사실은 더 좋았을 소재를 확인할 기회마저 영영 사라집니다.

**그럼 어떻게 나눠야 손해를 줄이면서도 진짜 좋은 소재를 놓치지 않을까요?**

이 질문을 다루는 문제를 멀티암드 밴딧(Multi-Armed Bandit, MAB)이라고 부릅니다. 이름은 카지노에서 왔습니다. 슬롯머신 손잡이 하나를 영어로 「외팔이 강도(one-armed bandit)」라고 부르는데, 손잡이 여러 개 가운데 어느 것을 당겨야 돈을 더 딸지 모르는 채로 계속 당겨야 하는 상황이라 「팔이 여러 개인 강도」라는 뜻의 멀티암드 밴딧이라는 이름이 붙었습니다. 이 글에서 손잡이(팔, arm) 하나는 소재 하나이므로 팔을 한 번 당기는 일은 그 소재를 골라 한 번 보여 주는 일입니다. 팔을 당겼을 때 나오는 보상(reward)은 클릭입니다. 아직 잘 모르는 팔도 한 번씩 당겨 보는 일을 탐색(Exploration), 지금까지 가장 좋아 보인 팔만 계속 당기는 일을 활용(Exploitation)이라고 부릅니다. 이 이름으로 말하면 앞의 첫째 방법은 탐색만 계속하는 방법, 둘째 방법은 활용만 하는 방법입니다.

> 한 줄 요약: 밴딧 문제는 **정보가 부족한 채로 계속 선택해야 할 때 탐색과 활용 사이의 균형을 알고리즘으로 정하는 문제**입니다. 이 글의 시뮬레이션에서는 처음 100회만 탐색하고 멈춘 그리디가 똑같이 나눠 보여 준 균등분배보다도 손해(누적 후회 99.2 대 86.0)가 컸지만 끝까지 조금씩 탐색한 밴딧 3종은 두 방법보다 손해가 적었습니다. 이 글은 정해진 확률로 무작위 탐색을 섞는 ε-greedy 에서 출발해 덜 확인한 소재에 가산점을 주는 UCB, 분포에서 뽑은 값으로 고르는 톰슨 샘플링, 사람과 상황에 따라 다르게 고르는 컨텍스추얼로 알고리즘이 어떻게 나뉘었는지 계보를 그립니다.

## 1. 소재 5개에 세 가지 전략을 1,000번씩 붙인 결과

**균등분배, 그리디, 밴딧을 같은 조건에서 1,000회씩 돌리면 손해(후회)와 총 클릭 수가 전략마다 크게 다릅니다.**

도입의 질문에 답하려면 여러 전략을 같은 소재와 같은 횟수에서 나란히 돌려 보고 결과를 비교해야 합니다. 이 글은 소재 5개의 진짜 클릭률(CTR, Click-Through Rate)을 시뮬레이션을 위해 미리 정해 두었지만 비교하는 세 전략은 모두 이 숫자를 모르는 채로 시작합니다. CTR 은 노출 수 가운데 클릭이 난 비율이라 CTR 이 15% 인 소재는 100번 보여 주면 평균 15번 클릭됩니다.

| 소재 | 진짜 CTR (알고리즘도 운영자도 모르는 값) |
|---|---|
| 소재1 | 3% |
| 소재2 | 15% |
| 소재3 | 8% |
| 소재4 | 1% |
| 소재5 | 5% |

표에서 진짜 1등은 CTR 15% 인 소재2 입니다. 하지만 알고리즘도 광고 운영자도 이 표를 볼 수 없으므로 소재를 노출한 뒤 클릭이 오는지 지켜보는 것만으로 어느 소재가 좋은지 짐작해야 합니다. 이 조건에서 비교한 전략은 다섯 가지이고 크게 세 가지로 나뉩니다.

- **균등분배**는 매번 5개 소재에 돌아가며 똑같이 배정하는 도입의 첫째 방법입니다.

- **그리디**는 도입의 둘째 방법 앞에 100회 탐색을 붙인 방법으로, 처음 100회만 골고루 보여 주고 나머지 900회는 그때까지 관측 CTR 이 가장 높은 1등만 계속 보여 줍니다. greedy 는 「욕심 많은」이라는 뜻으로, 당장 가장 좋아 보이는 것만 고르는 방식을 가리킵니다. 관측 CTR 은 지금까지 그 소재를 보여 준 횟수 가운데 클릭이 난 비율이며 표와 코드에서는 관측 평균이라고도 부릅니다.

- **밴딧** 3종은 탐색을 끝까지 조금씩 이어 갑니다. ε-greedy 는 매번 ε(엡실론)의 확률, 이 글에서는 10% 로 무작위 소재를 고르고 나머지 90% 는 지금까지의 1등을 고릅니다. UCB1 은 관측 평균에 불확실성 보너스(덜 보여 준 소재일수록 크게 붙는 가산점, 코드 주석에서는 탐색 보너스)를 더한 점수가 가장 큰 소재를 고릅니다. 이름의 UCB 는 Upper Confidence Bound(신뢰 상한)의 줄임말입니다. 톰슨 샘플링(Thompson Sampling, TS)은 소재마다 지금까지의 클릭과 비클릭으로 정해지는 베타 사후분포(그 소재의 CTR 이 어디쯤일지를 나타내는 확률 분포)에서 값을 하나씩 뽑아 가장 큰 값이 나온 소재를 고릅니다.

표의 총 클릭 수는 1,000회 동안 실제로 난 클릭 수라 많을수록 좋습니다. 누적 후회는 매 회 진짜 1등 소재를 골랐다면 얻었을 CTR 과 실제로 고른 소재의 CTR 의 차이를 1,000회 동안 더한 값이라 작을수록 좋습니다. 이 값의 뜻은 3절에서 자세히 봅니다. 최적 소재 선택률은 1,000회 가운데 최적 소재, 곧 진짜 1등인 소재2 를 고른 비율이라 높을수록 좋습니다.

| 전략 | 방식 | 총 클릭 수 (많을수록 좋음) | 누적 후회 (낮을수록 좋음) | 최적 소재 선택률 (높을수록 좋음) |
|---|---|---|---|---|
| 균등분배 | 매번 5개에 똑같이 돌아가며 배정 | 60회 | 86.0 | 20.0% |
| 그리디(100회 탐색 후 고정) | 처음 100회만 골고루, 이후 900회는 그때까지의 1등만 계속 | 37회 | 99.2 | 3.1% |
| 밴딧: ε-greedy | 매번 10% 확률로 무작위, 나머지는 지금까지 1등 | 81회 | 60.5 | 49.1% |
| 밴딧: UCB1 | 관측 평균 + 불확실성 보너스가 가장 큰 소재 | 96회 | 59.8 | 41.6% |
| 밴딧: 톰슨 샘플링 | 베타 사후분포에서 뽑은 표본이 가장 큰 소재 | 144회 | 19.3 | 80.8% |

가장 눈에 띄는 줄은 그리디입니다. 그리디는 처음 100회를 골고루 탐색했는데도 총 클릭이 37회로 다섯 전략 가운데 가장 적습니다. 아무 전략 없이 그냥 나눠 돌린 균등분배의 60회보다도 적고 누적 후회도 99.2 로 가장 큽니다. 100회 탐색은 소재마다 20회씩이라 클릭률이 몇 퍼센트대인 소재들의 실력 차를 구분하기에 너무 적었는데, 그 100회에서 실제로 무엇이 관측됐는지는 2절에서 숫자로 확인합니다.

밴딧 3종(ε-greedy, UCB1, 톰슨 샘플링)의 누적 후회는 60.5, 59.8, 19.3 으로 모두 균등분배의 86.0 과 그리디의 99.2 보다 낮습니다. 톰슨 샘플링은 그중에서도 후회가 19.3 으로 가장 낮고 최적 소재 선택률이 80.8% 로 가장 높았는데, 이 순위는 이번 시뮬레이션에서 나온 결과입니다. 세 밴딧이 서로 얼마나, 왜 다른지는 이 글에서 다루지 않고 [UCB vs Thompson Sampling](post.html?id=ucb-vs-ts) 편이 그 비교를 맡습니다. 이 글은 밴딧이라고 불리는 계열 전체가 순진한 두 전략(균등분배와 그리디)보다 낫다는 큰 그림만 봅니다.

## 2. 파이썬으로 직접 검증한 1절 표

**1절 표의 숫자는 손으로 지어낸 값이 아니라 아래 코드를 그대로 돌리면 똑같이 다시 나오는 값입니다.**

아래 코드는 1절 표의 숫자를 다시 만들어 보려고 돌립니다. 다섯 전략은 「다음에 어떤 소재를 고를지(select)」와 「결과를 보고 무엇을 기록해 둘지(update)」를 정하는 두 함수만 서로 다릅니다. 1,000번 반복하면서 클릭 여부를 뽑고 후회를 누적하고 최적 소재를 골랐는지 세는 나머지 실행 흐름은 다섯 전략 모두 같은 함수 `simulate` 를 씁니다. 코드를 읽을 때는 세 줄을 먼저 보면 됩니다.

- `reward = 1 if random.random() < TRUE_CTR[arm] else 0` 은 클릭 여부를 정합니다. 0 과 1 사이의 난수가 고른 소재의 진짜 CTR 보다 작으면 클릭(1)이므로 소재2 를 고르면 매번 15% 확률로 클릭이 납니다.

- `regret += BEST_CTR - TRUE_CTR[arm]` 은 누적 후회를 만듭니다. 최적 소재의 CTR 0.15 에서 고른 소재의 진짜 CTR 을 뺀 값을 매번 더합니다.

- 맨 위의 `random.seed(19)` 는 난수의 시작값(시드)을 19 로 고정합니다. 그래서 다시 돌려도 같은 난수가 나와 1절 표와 같은 숫자가 찍힙니다.

```python
# 하는 일: 광고 소재 5개에 다섯 가지 배정 방법을 같은 1,000회씩 붙여, 총 클릭 수, 누적 후회, 최적 소재 선택률을 비교한다.
import random
import math

random.seed(19)  # 재현 가능하도록 고정 — 위 표의 숫자가 이 시드에서 나온 값이다

# 1단계: 소재 5개의 진짜 CTR 을 둔다
# 진짜 CTR 은 이렇게 정해 두지만, 알고리즘은 이 값을 모른 채 시작한다.
TRUE_CTR = {"소재1": 0.03, "소재2": 0.15, "소재3": 0.08, "소재4": 0.01, "소재5": 0.05}
ARMS = list(TRUE_CTR)
BEST = max(ARMS, key=lambda a: TRUE_CTR[a])   # 소재2 — 우리는 이걸 모르는 채로 실험을 시작한다
BEST_CTR = TRUE_CTR[BEST]
ROUNDS = 1000

# 2단계: 공통 실행 루프를 만든다
# 전략마다 다른 건 고르는 법과 기록 갱신법뿐이다. 누적 후회는 최적 소재를 알았다면 얻었을 CTR 과의 차이를 더한 값이다.
def simulate(select_arm, update):
    """공통 실행 루프. 전략마다 다른 건 '고르는 법'과 '기록 갱신법'뿐이다."""
    clicks = regret = optimal = 0
    for t in range(1, ROUNDS + 1):
        arm = select_arm(t)
        reward = 1 if random.random() < TRUE_CTR[arm] else 0
        update(arm, reward)
        clicks += reward
        regret += BEST_CTR - TRUE_CTR[arm]        # 최적을 알았다면 얻었을 CTR과의 차이를 누적
        optimal += (arm == BEST)
    return clicks, regret, optimal / ROUNDS * 100

# 3단계: 다섯 가지 배정 방법을 만든다
# 균등분배, 그리디, 그리고 밴딧 셋(ε-greedy, UCB1, 톰슨 샘플링)이다.
def uniform_strategy():                            # 균등분배: 5개를 순서대로 그대로 반복
    return (lambda t: ARMS[t % len(ARMS)]), (lambda arm, r: None)

def greedy_strategy(explore=100):                   # 그리디: 첫 100회만 골고루, 이후 900회는 그때까지의 1등만 계속
    counts = {a: 0 for a in ARMS}
    sums = {a: 0 for a in ARMS}
    def select(t):
        if t <= explore:
            return ARMS[t % len(ARMS)]
        return max(ARMS, key=lambda a: sums[a] / counts[a] if counts[a] else 0)
    def update(arm, r):
        counts[arm] += 1
        sums[arm] += r
    return select, update

def epsilon_greedy_strategy(epsilon=0.1):           # 밴딧: 10% 확률로 무작위, 90%는 지금까지 1등
    counts = {a: 0 for a in ARMS}
    sums = {a: 0 for a in ARMS}
    def select(t):
        unseen = [a for a in ARMS if counts[a] == 0]
        if unseen:
            return unseen[0]
        if random.random() < epsilon:
            return random.choice(ARMS)
        return max(ARMS, key=lambda a: sums[a] / counts[a])
    def update(arm, r):
        counts[arm] += 1
        sums[arm] += r
    return select, update

def ucb1_strategy():                                # 밴딧: 관측 평균 + 탐색 보너스가 가장 큰 소재
    counts = {a: 0 for a in ARMS}
    sums = {a: 0 for a in ARMS}
    def select(t):
        unseen = [a for a in ARMS if counts[a] == 0]
        if unseen:
            return unseen[0]
        return max(ARMS, key=lambda a: sums[a] / counts[a] + math.sqrt(2 * math.log(t) / counts[a]))
    def update(arm, r):
        counts[arm] += 1
        sums[arm] += r
    return select, update

def thompson_strategy():                            # 밴딧: 베타 분포에서 뽑은 표본이 가장 큰 소재
    alpha = {a: 1 for a in ARMS}
    beta = {a: 1 for a in ARMS}
    def select(t):
        samples = {a: random.betavariate(alpha[a], beta[a]) for a in ARMS}
        return max(samples, key=lambda a: samples[a])
    def update(arm, r):
        if r:
            alpha[arm] += 1
        else:
            beta[arm] += 1
    return select, update

# 4단계: 같은 1,000회로 다섯 방법을 돌린다
strategies = {
    "균등분배":                 uniform_strategy(),
    "그리디(100회 탐색 후 고정)":   greedy_strategy(),
    "밴딧: ε-greedy":           epsilon_greedy_strategy(),
    "밴딧: UCB1":               ucb1_strategy(),
    "밴딧: 톰슨 샘플링":           thompson_strategy(),
}

print(f"실제 최적 소재: {BEST} ({BEST_CTR:.0%})")
print()
for name, (select, update) in strategies.items():
    clicks, regret, optimal_pct = simulate(select, update)
    print(f"{name:<22} 총 클릭 {clicks:3d}회   누적후회 {regret:5.1f}   최적소재 선택률 {optimal_pct:4.1f}%")

# 출력:
# 4단계 뜻: 진짜 최적은 CTR 15% 인 소재2 다. 톰슨 샘플링이 클릭 144회에 누적후회 19.3 으로 가장 낫고, 최적 소재를 80.8% 고른다. 100회 뒤로 탐색을 멈춘 그리디는 37회로 균등분배의 60회보다도 못하다.
# 실제 최적 소재: 소재2 (15%)
#
# 균등분배                   총 클릭  60회   누적후회  86.0   최적소재 선택률 20.0%
# 그리디(100회 탐색 후 고정)      총 클릭  37회   누적후회  99.2   최적소재 선택률  3.1%
# 밴딧: ε-greedy           총 클릭  81회   누적후회  60.5   최적소재 선택률 49.1%
# 밴딧: UCB1               총 클릭  96회   누적후회  59.8   최적소재 선택률 41.6%
# 밴딧: 톰슨 샘플링             총 클릭 144회   누적후회  19.3   최적소재 선택률 80.8%
```

출력 맨 위 줄은 실제 최적 소재가 CTR 15% 인 소재2 라고 알려 줍니다. 아래 다섯 줄은 1절 표와 같은 값이라 그리디는 총 클릭 37회, 누적 후회 99.2, 최적 소재 선택률 3.1% 인 반면 톰슨 샘플링은 총 클릭 144회, 누적 후회 19.3, 최적 소재 선택률 80.8% 입니다.

그리디가 이렇게 실패한 까닭은 처음 100회 탐색 구간의 관측값을 들여다보면 바로 보입니다. 100회를 5개 소재에 돌아가며 나누면 소재당 표본이 20회뿐이라 우연이 끼어들기 쉬운데, 이번 시드에서는 소재1, 소재2, 소재3, 소재5 가 공교롭게 모두 1번씩 클릭되어 관측 CTR 이 1 ÷ 20 = 5% 로 똑같은 동률이 났습니다(소재4 만 클릭 0번). 진짜 CTR 이 3%, 15%, 8%, 5% 로 전혀 다른 소재 4개가 20번 표본에서는 우연히 똑같아 보였습니다. 소재2 만 해도 20번 노출에서 평균 20 × 0.15 = 3번의 클릭이 기대되는 소재였지만 이번에는 1번에 그쳤습니다.

100회가 지나자 그리디는 관측 CTR 이 가장 높은 소재를 고르기 시작했는데, 파이썬 `max` 는 값이 같으면 목록에서 앞에 있는 소재를 돌려주므로 동률인 4개 가운데 맨 처음인 소재1 부터 골랐습니다. 그 뒤로는 고른 소재가 클릭 없이 노출될수록 관측 CTR 이 내려가므로, 관측 CTR 이 다른 소재 밑으로 떨어질 때마다 다음 소재로 옮겨 다녔습니다. 그렇게 옮겨 다닌 끝에 나머지 900회 가운데 776회를 진짜 CTR 5% 인 소재5 에 몰아줬고 진짜 1등 소재2 는 11회만 골랐습니다. 100회나 탐색하면 「충분히 탐색했다」는 안도감이 들지만 클릭률이 몇 퍼센트대에 머무는 소재들 사이의 실력 차는 소재당 20번의 표본으로 구분하지 못합니다.

세 밴딧 알고리즘은 100회가 지난 뒤에도 다른 소재를 계속 조금씩 시도한 덕분에 처음의 동률이 착시였다는 사실을 늦게라도 알아챌 기회가 남아 있었으므로 같은 표본으로도 이 함정에 걸리지 않았습니다. 이 차이를 측정하는 기준으로 총 클릭 수 대신 후회를 쓰는 까닭은 3절에서 봅니다.

## 3. 후회(Regret)를 좋은 알고리즘의 기준으로 쓰는 까닭

**그날 클릭이 몰리느냐 마느냐에는 운이 섞여 있어 총 클릭 수만으로는 전략을 공정하게 비교할 수 없으므로, 밴딧에서는 후회(Regret)라는 별도의 기준을 씁니다.**

후회는 매 라운드 「최적 소재를 알고 있었다면 얻었을 보상」과 「실제로 고른 소재가 준 보상」의 차이를 계속 더한 값입니다. 라운드는 소재를 한 번 골라 보여 주는 회차 하나로, 이 글의 시뮬레이션은 1,000라운드를 돌렸습니다. 2절 코드는 이 차이를 최적 소재인 소재2 의 CTR 0.15 에서 고른 소재의 진짜 CTR 을 뺀 값으로 세므로, 소재2 를 고른 라운드에는 0 이 더해지고 소재5 를 고른 라운드에는 0.15 - 0.05 = 0.1 이 더해집니다.

1절 표의 그리디 누적 후회 99.2 는 대부분 나머지 900번 가운데 776번을 소재5(5%)에 쓰는 동안 진짜 1등(15%)과의 10퍼센트포인트 차이, 곧 라운드마다 0.1 이 쌓인 결과입니다. 2절 코드의 후회에는 그 라운드에 클릭이 실제로 났는지(0 또는 1)가 들어가지 않고 고른 소재의 진짜 CTR 만 들어갑니다. 총 클릭 수는 그날그날 운에 따라 오르내리지만 후회는 「이 전략이 정보를 얼마나 낭비했는가」를 운에 덜 휘둘리며 측정하는 값입니다.

후회를 아예 0 으로 만드는 일은 좋은 밴딧 알고리즘의 목표가 아닙니다. 처음에는 어느 소재가 좋은지 몰라서 손해를 보는 게 당연합니다. 진짜 문제는 그 손해가 시간이 지나도 똑같은 속도로 계속 쌓이느냐입니다.

ε-greedy 는 매 라운드 정해진 확률 10%(2절 코드의 `epsilon=0.1`)로 무작위 탐색을 계속하므로, 최적 소재를 이미 다 알아낸 뒤에도 10% 확률로 나쁜 소재를 골라 손해를 영원히 되풀이합니다. 그래서 ε-greedy 의 후회는 전체 라운드 수 $T$ 에 거의 비례해 선형으로 계속 자랍니다.

반면 UCB1 과 톰슨 샘플링은 데이터가 쌓일수록 탐색이 저절로 줄어들도록 설계되어 있습니다. 2절 코드에서 UCB1 의 불확실성 보너스 `math.sqrt(2 * math.log(t) / counts[a])` 는 그 소재를 보여 준 횟수 `counts[a]` 가 분모에 있어서 많이 보여 준 소재일수록 작아집니다. 그래서 두 알고리즘의 후회는 $T$ 가 아니라 $\log T$ 속도로만 자라는데, $\log T$ 는 $T$ 가 10배가 될 때마다 같은 양만큼만 커지므로 라운드가 10배 늘어도 후회는 10배가 아니라 아주 조금만 늘어납니다.

:::deep 더 깊이 — 후회가 로그 속도로만 자라는 까닭
후회를 소재별로 나눠 보면 까닭이 보입니다. 소재 $a$ 의 격차 $\Delta_a = \mu^* - \mu_a$ 는 최적 CTR $\mu^*$ 에서 그 소재의 CTR $\mu_a$ 를 뺀 값입니다. 이 글에서는 소재5 의 격차가 0.15 - 0.05 = 0.1 입니다. 전체 누적 후회는 이 격차로 아래처럼 분해됩니다.

$$R_T = \sum_{a \neq a^*} \Delta_a \cdot \mathbb{E}[n_a(T)]$$

$a^*$ 는 최적 소재, $n_a(T)$ 는 $T$ 라운드 동안 소재 $a$ 를 고른 횟수이며 $\mathbb{E}$ 는 기댓값(같은 실험을 여러 번 돌렸을 때의 평균)입니다. 그러니 후회는 결국 소재마다 잘못 고른 횟수에 그 소재의 격차를 곱해 더한 합이라, 격차가 큰 소재를 자주 잘못 고를수록 커집니다.

이 식을 보면 좋은 알고리즘의 후회가 왜 로그 속도로만 자라는지 감이 옵니다. 나쁜 소재라도 표본이 적으면 관측값이 좋은 소재와 겹쳐 보일 수 있는데, 2절에서 소재당 20번 표본으로 소재 4개의 관측 CTR 이 모두 5% 로 같아진 그리디가 바로 이 경우였습니다. 다만 겹쳐 보일 확률은 시도 횟수가 늘수록 지수적으로 줄어듭니다(Hoeffding 부등식). Hoeffding 부등식은 관측 평균이 참값에서 크게 벗어날 확률에 상한을 주는 부등식입니다. 정확한 유도는 [UCB vs Thompson Sampling](post.html?id=ucb-vs-ts) 편의 심화 블록에 있습니다. 나쁜 소재를 걸러 내는 데 필요한 시도 횟수는 대략 $\ln T / \Delta_a^2$ 면 충분합니다(Lai & Robbins, 1985). 분모에 격차의 제곱이 있으므로 격차 $\Delta_a$ 가 작을수록 이 횟수는 커집니다. 이 횟수를 위 분해식의 $\mathbb{E}[n_a(T)]$ 자리에 넣으면 $\Delta_a \cdot \ln T / \Delta_a^2$ 에서 $\Delta_a$ 하나가 약분되어 아래 식이 됩니다.

$$R_T \approx \ln T \sum_{a \neq a^*} \frac{1}{\Delta_a}$$

합 기호 안의 $1/\Delta_a$ 는 소재마다 정해진 값이라 $T$ 와 상관이 없으므로, 후회는 $T$ 가 아니라 $\ln T$ 에 비례해서만 자랍니다. 고정된 $\epsilon$ 을 쓰는 ε-greedy 는 사정이 다릅니다. 데이터가 아무리 쌓여도 매 라운드 $\epsilon$ 의 확률로 무조건 무작위 소재를 고르므로 나쁜 소재를 고르는 횟수가 $T$ 에 비례해 계속 늘어나고 후회도 선형으로 자랍니다. 로그와 선형의 차이는 라운드가 늘어날수록 점점 크게 벌어집니다.
:::

1절 표는 시드 19 하나로 돌린 시뮬레이션의 결과입니다. 아래 데모에서는 라운드 버튼을 직접 눌러 UCB1 과 톰슨 샘플링이 라운드마다 어떤 소재를 고르는지, 두 알고리즘의 누적 후회 곡선이 시간이 지나며 어떻게 벌어지는지 보면 됩니다.

## 4. 밴딧 알고리즘의 계보 — ε-greedy 에서 컨텍스추얼까지

**밴딧 알고리즘은 한 뿌리에서 출발해 「탐색을 어떻게 할 것인가」라는 질문에 서로 다른 답을 내며 계보를 이뤘습니다.**

1절의 세 밴딧은 모두 순진한 두 전략보다 나았지만 세 알고리즘이 어떤 순서로 나왔고 각각 무엇을 고치려 했는지는 결과 표만으로 보이지 않습니다. 가장 먼저 나온 원시적인 답은 ε-greedy 입니다. 그다음 UCB 계열과 톰슨 샘플링 두 갈래가 각자 다른 방식으로 더 똑똑한 탐색을 시도했고 마지막으로 두 갈래 모두 「사람마다 다른 정답」을 반영하는 컨텍스추얼 버전으로 넓어졌습니다. 컨텍스트(context)는 유저, 지면(광고가 실리는 화면의 자리), 검색어처럼 소재를 보여 주는 순간의 상황 정보입니다. 컨텍스추얼 밴딧은 이 정보를 보고 사람과 상황마다 다른 소재를 고릅니다.

아래 표에 갈래마다 풀려던 문제를 중심으로 계보를 적었습니다. 자세한 수식과 구현은 표 오른쪽의 상세 글이 갈래마다 맡습니다.

| 갈래 | 풀려던 문제 | 방식 한 줄 | 남은 한계 | 상세 글 |
|---|---|---|---|---|
| ε-greedy | 탐색을 아예 안 하는 것보다는 낫게 만들자 | 정해진 확률로 무작위, 나머지는 지금까지 1등 | 탐색이 무차별적 — 잘 아는 소재도 전혀 모르는 소재도 같은 확률로 찔러본다 | 이 글 2절 코드 |
| UCB 계열 | 무차별한 탐색을 "덜 아는 순서"로 똑똑하게 하자 | 관측 평균 + 불확실성 보너스 점수로 결정 | 계산이 결정적이라 재현엔 좋지만, 유저, 상황을 구분 못 함 | [UCB 계열](post.html?id=ucb-family) |
| 톰슨 샘플링 | 점수 계산 대신 확률적으로 자연스럽게 탐색을 분산하자 | 베타 사후분포에서 표본을 뽑아 가장 큰 값이 승자 | 역시 유저, 상황을 구분 못 하고, 매번 다른 소재가 나올 수 있음 | [UCB vs Thompson Sampling](post.html?id=ucb-vs-ts) |
| 컨텍스추얼 — LinUCB | "이 사람에게는" 어떤 소재가 좋은지 반영하자 | UCB 점수에 유저, 지면 피처의 선형모델을 결합 | 신규 소재는 여전히 콜드스타트를 겪음 | [UCB 계열](post.html?id=ucb-family), [Disjoint LinUCB](post.html?id=disjoint-linucb) |
| 컨텍스추얼 — Linear TS | 톰슨 샘플링을 같은 방향으로 확장하자 | 가중치 자체를 가우시안 분포로 두고 표본을 뽑음 | Basic TS보다 계산, 튜닝 비용이 커짐 | [Thompson Sampling: 기본형부터 Linear TS까지](post.html?id=TS-linTS) |

표에서 눈여겨볼 자리는 ε-greedy 다음에 두 갈래로 나뉘는 대목입니다. ε-greedy 의 탐색은 잘 아는 소재와 전혀 모르는 소재를 같은 확률로 고르는 무차별 탐색이었는데, UCB 계열과 톰슨 샘플링은 이 무차별 탐색을 똑똑하게 만들자는 같은 목표를 전혀 다른 도구로 풀었습니다. UCB 계열은 점수를 계산하는 결정적(deterministic) 방법이라 같은 기록이면 몇 번을 계산해도 같은 소재를 고릅니다. 톰슨 샘플링은 분포에서 값을 뽑는 확률적(stochastic) 방법이라 같은 기록에서도 뽑을 때마다 다른 소재가 나올 수 있습니다. 2절 코드에서도 UCB1 의 `select` 에는 난수가 없는 반면 톰슨 샘플링의 `select` 는 `random.betavariate` 로 매번 난수를 뽑습니다. 이 차이가 재현성(같은 입력에서 같은 결과를 다시 얻는 성질), 동시 요청 처리, 피드백 지연 대응에서 실무 선택을 정합니다. 그 비교가 [UCB vs Thompson Sampling](post.html?id=ucb-vs-ts) 편의 주제입니다.

검색 광고나 개인화 피드는 유저와 검색어에 따라 최적 소재가 달라져 모두에게 같은 순위를 매기는 방식만으로는 한계가 뚜렷하므로, 두 갈래 모두 「사람마다 다른 정답」이 필요해지는 순간 컨텍스추얼로 확장됩니다. 표의 LinUCB 는 UCB 점수에 유저와 지면 피처(모델에 넣는 입력값)의 선형모델(피처마다 가중치를 곱해 더하는 모델)을 결합했습니다. Linear TS 는 그 가중치 자체를 가우시안 분포(정규분포)로 두고 표본을 뽑습니다. 남은 한계도 서로 달라서 LinUCB 는 신규 소재에서 여전히 콜드스타트(데이터가 거의 없는 새 소재를 처음 다룰 때 추정이 부정확한 문제)를 겪습니다. Linear TS 는 기본형 톰슨 샘플링(Basic TS)보다 계산과 튜닝 비용이 커집니다. 이 확장이 왜 필요한지는 [A/B 테스트 vs 멀티암드 밴딧](post.html?id=ab-test-vs-mab) 편에서 다룹니다. 탐색과 활용 사이의 딜레마라는 배경은 [탐색과 활용](post.html?id=exploration-exploitation) 편에서 볼 수 있습니다.

## 5. 교과서 밴딧에 가장 가까운 무대, 닫힌 생태계 [무대: 닫힌 생태계]

**플랫폼이 노출을 직접 배정하는 닫힌 생태계는 밴딧 알고리즘이 원래 전제하는 조건에 가장 가까운 현실 무대입니다.**

네이버, 밴드처럼 노출과 클릭 기록을 전부 자기 로그로 남기는 서비스는 사용자가 지면에 들어올 때마다 후보 소재 가운데 하나를 직접 골라 보여 줍니다. 이처럼 플랫폼이 노출을 직접 배정하고 그 결과도 자기 로그로 보는 무대를 닫힌 생태계라고 부릅니다. 이 무대의 특징은 세 가지입니다.

- **시도와 피드백이 분리되지 않습니다.** 무엇을 노출했는지와 클릭이 났는지 안 났는지가 항상 관측되므로, 2절 코드가 매 라운드 고른 소재의 클릭 여부(`reward`)를 빠짐없이 `update` 에 넣는 것과 같은 조건입니다.

- **탐색 비용을 플랫폼이 스스로 감당합니다.** 아직 데이터가 적은 소재를 시험 삼아 보여 줘서 생기는 손해는 이번 한 번의 노출이 최적 대비 조금 덜 벌었다는 정도에서 끝납니다. 3절의 후회로 말하면 그 라운드의 후회에 최적 소재와의 CTR 차이만큼이 더해지는 정도입니다.

- **실험 설계의 자유도가 높습니다.** 어떤 유저에게 어떤 소재를 보여 줄지 플랫폼이 모두 정하므로 1절처럼 여러 전략을 나란히 비교하는 실험도 깔끔하게 짤 수 있습니다.

이 세 가지 덕분에 닫힌 생태계에서는 이 글에서 다룬 다섯 전략이 모두 그대로 작동합니다. 다만 교과서가 은근히 깔고 가는 전제가 광고 현실에서는 몇 군데 깨지므로 밴딧이 광고의 모든 문제를 풀지는 못합니다. 그 자리들은 6절에서 봅니다.

---

## 6. 그래도 안 통하는 지점 3가지 — 지연 보상, 비정상성, 예산 제약

**밴딧 알고리즘은 보상이 바로 오고 소재 실력이 변하지 않으며 시도가 거의 공짜라고 가정하는데, 광고 현실은 이 세 가지 가정을 자주 깹니다.**

2절 코드도 이 세 가정 위에서 돌아갑니다. 클릭 여부는 소재를 고른 바로 그 라운드에 `update` 로 들어갑니다. `TRUE_CTR` 은 1,000라운드 내내 같은 값입니다. 코드에는 예산이라는 값이 아예 없어 나쁜 소재를 보여 주는 탐색은 후회만 늘립니다.

첫째는 지연 보상(delayed reward)입니다. 지연 보상은 선택에 대한 보상이 바로 오지 않고 한참 뒤에 확정되는 일인데, 광고에서는 클릭은 즉시 관측되지만 광고주가 진짜 원하는 결과인 전환(구매나 가입처럼 광고주가 바라는 행동)은 며칠 뒤에나 확정됩니다. 알고리즘이 방금 고른 소재가 정말 좋았는지는 한참 지나야 알 수 있는데, 그사이에도 다음 노출을 계속 결정해야 합니다. 보상을 이 글처럼 클릭으로만 세어 최적화하면 클릭은 잘 받지만 전환은 낮은 소재가 높은 보상을 받아 과대평가되기 쉽습니다. 이 시차는 온라인 학습(데이터가 들어오는 대로 모델을 계속 고쳐 가는 학습) 전반이 겪는 오래된 난제이기도 합니다(더 깊이 보기 참고).

둘째는 비정상성(non-stationarity)입니다. 여기서 정상(stationary)은 「정상적이다」가 아니라 「시간이 지나도 성질이 그대로다」라는 뜻이라, 비정상성은 소재의 진짜 CTR 같은 값이 시간에 따라 바뀌는 성질을 가리킵니다. 밴딧은 소재의 진짜 CTR 이 2절의 `TRUE_CTR` 처럼 고정된 값이라고 가정하지만 실제로는 요일, 시즌, 경쟁 소재 교체에 따라 어제 좋았던 소재가 오늘 나빠집니다. 더 큰 문제는 데이터가 충분히 쌓여 확신이 커질수록 알고리즘이 역설적으로 새로운 변화에 더 둔감해진다는 점입니다. 활용 비중이 높아질수록 탐색이 줄고 탐색이 줄면 소재가 변했다는 신호를 늦게 알아채므로, 3절에서 본 UCB1 과 톰슨 샘플링의 「데이터가 쌓일수록 탐색이 줄어드는 설계」도 광고 현실에서는 변화를 늦게 알아채게 만들 수 있습니다.

셋째는 예산 제약입니다. 탐색도 결국 광고주의 돈으로 이뤄지므로 하루 예산이 정해진 캠페인에서 「혹시 몰라서」 예산의 30% 를 탐색에 쓸 수는 없습니다. 그래서 실무에서는 탐색 비율에 상한을 두거나 최소 품질 기준을 넘는 소재만 탐색 대상에 넣어 밴딧 이론이 말하는 최적 탐색량을 그대로 쓰지 못하고 깎아서 씁니다.

## 7. 패찰하면 데이터 자체가 없는 열린 RTB [무대: 열린 RTB]

**열린 RTB 에서는 시도와 피드백이 아예 분리되어 입찰에서 이겨야만 비로소 무슨 일이 일어났는지 알 수 있습니다.**

열린 RTB 는 노출 한 번이 생길 때마다 여러 회사의 광고주가 그 순간 입찰해 낙찰자의 광고를 내보내는 실시간 입찰(RTB, Real-Time Bidding) 시장입니다. 광고주 쪽에서 입찰을 대신 넣는 플랫폼인 DSP(Demand-Side Platform)가 초 단위로 들어오는 수많은 입찰 요청 가운데 어디에 응찰(입찰에 참여)할지 정하는 문제도 밴딧으로 푸는데, 이때는 1절의 소재 자리에 입찰 기회나 세그먼트(비슷한 특성으로 나눈 사용자 그룹)가 들어가 팔 하나가 입찰 기회나 세그먼트 하나가 됩니다.

열린 RTB 에서는 팔을 당겨도, 다시 말해 응찰해도 결과가 안 나올 수 있습니다. 닫힌 생태계는 노출을 직접 배정하므로 결과가 항상 관측되지만 열린 RTB 에서 응찰했는데 다른 광고주에게 낙찰이 넘어가면(패찰) 그 라운드에는 노출도 클릭도 생기지 않습니다. 2절 코드로 말하면 `select` 로 팔을 골랐는데 `update` 에 넣을 `reward` 자체가 없는 라운드입니다. 6절의 지연 보상은 「늦게라도 온다」는 뜻이지만 패찰은 「영영 안 올 수도 있다」는 뜻이라 성격이 다릅니다.

비용 구조도 다릅니다. 닫힌 생태계에서 데이터가 적은 소재를 한 번 보여 주는 탐색은 최적 대비 손해를 조금 감수하는 정도입니다. 열린 RTB 에서는 입찰에서 이겨야 광고비를 쓰고 데이터도 얻으므로 패찰에는 비용이 전혀 들지 않습니다. 져 봤자 돈도 안 나가고 데이터도 없으니 얼핏 밑질 게 없어 보이지만 그만큼 시도 횟수 자체를 늘리기도 쉽지 않습니다. 인기 있는 입찰 기회일수록 경쟁이 치열해 패찰이 잦고 패찰한 라운드에는 데이터가 남지 않으므로, 정보가 잘 모이는 세그먼트와 안 모이는 세그먼트의 격차가 닫힌 생태계보다 훨씬 크게 벌어집니다.

## 8. 한눈 정리

|---|---|---|---|
| 멀티암드 밴딧 | 정보 부족 속에서 탐색, 활용 균형을 정하는 문제 | 소재 5개, 진짜 CTR 1~15% | 탐색을 안 해도, 탐색만 해도 손해 |

| 그리디(100회 후 고정) | 초반만 탐색, 이후 그때까지의 1등만 계속 | 후회 99.2 — 균등분배보다도 나쁨 | 표본이 적으면 동률, 역전이 흔해 위험 |
| 밴딧(ε-greedy, UCB1, TS) | 계속 조금씩 탐색 비중을 조절 | 후회 60.5, 59.8, 19.3 | 셋 다 순진한 두 전략보다 후회가 낮음 |

| 알고리즘 계보 | ε-greedy → UCB, TS → LinUCB, LinTS | 4개 갈래 표 | 갈래마다 풀려던 문제, 남은 한계가 다름 |

| 열린 RTB | 패찰하면 데이터 자체가 없음 | — | 시도해도 피드백이 안 올 수 있음 |

## 9. 헷갈리기 쉬운 점

- **「100회나 탐색했으니 안전하다」는 생각은 착각입니다.** 소재당 표본이 적으면(이 글에서는 20회) 관측 CTR 의 동률과 역전이 흔합니다. 이 글의 시뮬레이션에서도 그리디는 소재 4개의 관측 CTR 이 모두 5% 로 같아진 100회 탐색 뒤에 탐색을 멈춰 균등분배의 누적 후회 86.0 보다도 나쁜 99.2 를 냈습니다.

- **총 클릭 수만으로 전략을 비교하면 안 됩니다.** 총 클릭 수에는 그날의 운이 섞여 있으므로 운에 덜 휘둘리는 후회(Regret)를 기준으로 씁니다.

- **후회 0 은 목표가 아닙니다.** 처음에는 몰라서 손해를 보는 게 정상입니다. 그 손해가 로그 속도로 느려지는지, 아니면 라운드 수에 비례해 계속 자라는지가 관건입니다.

- **UCB 와 톰슨 샘플링은 상하관계가 아니라 같은 문제를 다른 도구로 푼 두 갈래입니다.** 어느 한쪽이 항상 이기지 않으며 재현성, 동시 요청, 피드백 지연 같은 실무 조건에 따라 유리한 쪽이 달라집니다.

- **컨텍스추얼은 Non-Contextual 의 업그레이드가 아니라 다른 질문에 대한 답입니다.** Non-Contextual 은 1절의 밴딧 3종처럼 컨텍스트를 보지 않고 모든 사람에게 같은 기준으로 고르는 밴딧입니다. 컨텍스추얼로 가면 질문 자체가 「전체적으로 무엇이 가장 좋은가」에서 「이 사람에게는 무엇이 좋은가」로 바뀝니다.

- **닫힌 생태계와 열린 RTB 는 둘 다 밴딧을 쓰지만 시도하면 피드백이 항상 오는지가 근본적으로 다릅니다.** 닫힌 생태계에서는 노출할 때마다 결과가 관측됩니다. 열린 RTB 에서는 패찰한 라운드에 노출도 클릭도 생기지 않습니다. 이 차이가 탐색 전략 자체보다 더 큰 실무 제약이 될 때가 많습니다.
