지훈은 앞 세 편으로 배열 문제를 넘겼습니다. 그런데 이번 문제는 입력이 배열이 아니었습니다. "각 사원의 상사 번호가 주어진다"로 시작했습니다.

배열로 옮겨 보려 했지만 잘 안 됐습니다. 사원 하나에 부하가 여럿이고 그 부하에게도 또 부하가 있어서 순서대로 늘어놓을 수가 없는 모양이었습니다.

**한 줄로 늘어놓을 수 없는 자료는 어떻게 다룰까요?**

이런 모양을 **트리**라고 합니다. 이 글은 먼저 트리를 코드로 담는 법과 순회하는 법을 다룹니다. 순회는 트리의 값을 빠짐없이 한 번씩 방문하는 일입니다. 이어서 트리 모양을 배열 하나에 담은 **힙**이 왜 "가장 작은 것 하나"에 강한지를 봅니다. 힙은 가장 작은 값이 언제나 맨 앞에 오도록 유지하는 자료구조입니다.

> **한 줄 요약:** 트리는 부모가 하나뿐인 갈래 구조입니다. 순회하는 방법은 네 가지이고 그중 세 가지는 재귀(함수가 자기 자신을 다시 부르는 방법) 코드의 줄 순서만 다릅니다. 힙은 트리처럼 생겼지만 실제로는 배열이며 전체를 정렬하지 않고 최솟값 하나만 꺼내는 데 씁니다.

> **골라 읽는 법** — 절이 10개인 글입니다.
>
> - 트리를 코드로 담고 순회하는 법 → 앞의 네 절
> - 이진 탐색 트리와 그 함정 → 다섯째, 여섯째 절
> - 힙만 → 일곱째 절부터
> - 실무에서 바로 쓰는 것 → 아홉째 절

## 1. 트리 — 부모는 하나, 자식은 여럿

**트리는 자기 위에 부모가 하나뿐이고 아래로만 갈라지는 구조입니다.**

사원과 상사 관계가 그렇습니다. 사원 하나에 상사는 한 명이고 상사 밑에는 부하가 여럿일 수 있습니다. 맨 위에는 상사가 없는 사람이 하나 있는데 이 사람을 **뿌리**(root)라 부릅니다. 아래에 아무도 없는 사람은 **잎**(leaf)입니다.

**높이**는 뿌리에서 가장 먼 잎까지 내려가는 층의 수입니다. 위 그림에서 뿌리 8 은 0층이고 가장 먼 잎 4, 7, 13 은 3층에 있으니 높이가 3 입니다. 높이가 왜 중요한지는 다섯째 절에서 나옵니다.

코드로 담는 방법은 간단합니다. 마디(Node, 트리의 점 하나)마다 값 `val` 과 왼쪽, 오른쪽 자식을 가리킬 자리 `left`, `right` 를 두고 부모 마디의 `left` 와 `right` 에 자식 마디를 넣어 잇습니다. 아래 코드는 그림의 트리를 이렇게 이어 만든 뒤 뿌리와 두 자식의 값을 찍습니다.

```python
# 하는 일: 값 9개로 이진 트리 하나를 만들고 뿌리와 두 자식을 찍는다.
# 1단계: 마디를 만든다
# 마디 하나는 값 하나와, 왼쪽과 오른쪽 자식을 가리킬 자리 둘을 갖는다.
class Node:
    def __init__(self, val):
        self.val, self.left, self.right = val, None, None

# 2단계: 그림의 트리를 잇고 뿌리를 찍는다
# 뿌리 8 의 왼쪽은 3, 오른쪽은 10 이다. 3 아래에 1 과 6, 6 아래에 4 와 7 이 있고, 10 의 오른쪽에 14, 14 의 왼쪽에 13 이 있다.
def build():
    n = {v: Node(v) for v in (8, 3, 10, 1, 6, 14, 4, 7, 13)}
    n[8].left,  n[8].right  = n[3], n[10]
    n[3].left,  n[3].right  = n[1], n[6]
    n[6].left,  n[6].right  = n[4], n[7]
    n[10].right = n[14]
    n[14].left  = n[13]
    return n[8]

root = build()
print(f"뿌리 {root.val}, 왼쪽 {root.left.val}, 오른쪽 {root.right.val}")

# 출력:
# 2단계 뜻: 뿌리 8 의 왼쪽 자식이 3, 오른쪽 자식이 10 이다.
# 뿌리 8, 왼쪽 3, 오른쪽 10
```

출력 `뿌리 8, 왼쪽 3, 오른쪽 10` 은 그림의 맨 위 두 층과 같습니다. `left` 나 `right` 가 `None` 이면 그쪽으로는 자식이 없다는 뜻이라서 `left` 와 `right` 가 둘 다 `None` 인 1 은 잎입니다.

## 2. 순회 순서 세 가지

**트리를 순회하는 코드는 세 줄인데, 그 세 줄의 순서만 바꾸면 세 가지 순서가 나옵니다.**

배열은 왼쪽에서 오른쪽으로 한 가지로만 순회하지만 트리는 갈래가 있으니 순서를 정해야 합니다. 세 순서 모두 왼쪽을 오른쪽보다 먼저 보므로 지금 보고 있는 마디(아래 목록의 「나」)를 언제 처리하느냐만 정하면 나머지는 따라옵니다.

- 나 먼저, 그다음 왼쪽, 그다음 오른쪽 → **전위**(preorder)
- 왼쪽 먼저, 그다음 나, 그다음 오른쪽 → **중위**(inorder)
- 왼쪽, 오른쪽 먼저, 나는 마지막 → **후위**(postorder)

1절의 트리를 이 세 순서로 순회해 값이 나오는 차례를 찍어 보겠습니다. 함수마다 나를 적기(`out.append`), 왼쪽 순회, 오른쪽 순회 세 줄을 세미콜론(;)으로 이어 한 줄에 적었습니다. 세 함수는 이 세 줄의 순서만 다릅니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 1절의 트리를 전위, 중위, 후위 세 순서로 순회해 값을 찍는다.
# 1단계: 세 순서를 만든다
# 세 함수는 나를 적기, 왼쪽 순회하기, 오른쪽 순회하기 세 일의 순서만 다르다.
def 전위(t, out):
    if t: out.append(t.val); 전위(t.left, out); 전위(t.right, out)

def 중위(t, out):
    if t: 중위(t.left, out); out.append(t.val); 중위(t.right, out)

def 후위(t, out):
    if t: 후위(t.left, out); 후위(t.right, out); out.append(t.val)

# 2단계: 1절의 트리를 세 순서로 순회한다
for 이름, fn in (("전위 (뿌리 먼저)", 전위), ("중위 (왼쪽 먼저)", 중위), ("후위 (뿌리 나중)", 후위)):
    out = []
    fn(root, out)
    print(f"{이름:<18}{out}")

# 출력:
# 2단계 뜻: 중위 결과만 정렬돼 있다. 뿌리 8 이 전위에서는 맨 앞에, 후위에서는 맨 뒤에 온다.
# 전위 (뿌리 먼저)        [8, 3, 1, 6, 4, 7, 10, 14, 13]
# 중위 (왼쪽 먼저)        [1, 3, 4, 6, 7, 8, 10, 13, 14]
# 후위 (뿌리 나중)        [1, 4, 7, 6, 3, 13, 14, 10, 8]
```

세 결과는 같은 값 9개를 담고 있지만 차례가 모두 다릅니다. 전위는 나를 먼저 적으므로 뿌리 8 이 맨 앞에 옵니다. 반대로 후위는 나를 마지막에 적으므로 8 이 맨 뒤에 옵니다. **중위 결과 `[1, 3, 4, 6, 7, 8, 10, 13, 14]` 는 정렬돼 있습니다.** 중위 순회가 정렬된 순서를 내는 것이 우연이 아닌 이유는 다섯째 절에서 다룹니다.

세 순서는 쓰임도 다릅니다. 전위는 뿌리부터 나오므로 결과를 차례로 읽으면서 위에서 아래로 다시 만들 수 있어서 트리를 그대로 복사하거나 파일로 저장할 때 씁니다. 후위는 자식을 다 처리해야 부모를 처리할 수 있는 일에 쓰는데, 폴더 크기 계산과 트리 삭제가 그런 일입니다.

:::deep 재귀가 부담스러우면 — 스택으로 바꾸기

위 코드는 자기 자신을 부르는 **재귀**입니다. 파이썬은 재귀를 깊게 하지 못하므로(넷째 절) 같은 일을 스택으로 바꿔 쓰기도 합니다. 스택은 앞 편에서 본, 마지막에 넣은 것부터 꺼내는 자료구조입니다.

전위 순회를 스택으로 쓰면 아래와 같습니다. 마지막에 넣은 것이 먼저 나오므로 오른쪽 자식을 먼저 넣고 왼쪽 자식을 나중에 넣어야 왼쪽이 먼저 나옵니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 1절의 트리를 재귀 없이 스택 하나로 전위 순서로 순회한다.
def 전위_스택(root):
    out, 스택 = [], [root]
    while 스택:
        t = 스택.pop()
        if not t: continue
        out.append(t.val)
        스택.append(t.right)      # 오른쪽을 먼저 넣어야
        스택.append(t.left)       # 왼쪽이 먼저 나온다
    return out

print(전위_스택(root))

# 출력:
# 뜻: 재귀로 순회한 전위 결과와 같다. 오른쪽을 먼저 넣어야 왼쪽이 먼저 나온다.
# [8, 3, 1, 6, 4, 7, 10, 14, 13]
```

출력 `[8, 3, 1, 6, 4, 7, 10, 14, 13]` 은 재귀로 순회한 전위 결과와 같습니다. 사실 재귀도 속으로는 함수 호출을 쌓아 두는 스택을 쓰는데 그 스택을 파이썬이 대신 관리해 줄 뿐입니다. 재귀를 스택으로 바꾸면 그 관리를 내가 맡습니다.

중위와 후위도 스택으로 쓸 수 있지만 코드가 눈에 띄게 복잡해집니다. 코딩 테스트에서는 대체로 재귀 한계를 올리는 편이 빠르고 안전합니다.
:::

## 3. 층별 순회 — 큐를 쓰는 너비 우선 탐색

**"몇 층인가", "각 층에 무엇이 있나"를 물으면 재귀가 아니라 큐를 씁니다.**

앞의 세 순회는 한 갈래를 끝까지 파고든 다음 옆 갈래로 가기 때문에 같은 층에 있는 값들이 결과에서 흩어집니다. 전위 결과 `[8, 3, 1, 6, 4, 7, 10, 14, 13]` 에서는 1층인 3 과 10 사이에 2층의 1, 6 과 3층의 4, 7 이 끼어 있습니다.

층별로 보려면 **먼저 본 것부터 처리**해야 합니다. 큐는 먼저 넣은 것부터 꺼내는 자료구조이고 파이썬에서는 앞 편에서 본 `deque` 로 씁니다. 지금 층을 전부 꺼내면서 그 자식들을 뒤에 넣으면 다음 회차에는 자연히 다음 층만 큐에 남습니다. 아래 코드는 층마다 큐에서 꺼낸 것, 넣은 것, 남은 큐 상태를 찍습니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 1절의 트리를 큐로 한 층씩 순회하며, 층마다 꺼낸 것과 넣은 것과 큐 상태를 찍는다.
from collections import deque

큐, 층 = deque([root]), 0
print(f"{'층':<4}{'큐에서 꺼낸 것':<16}{'큐에 넣은 것':<16}{'큐 상태'}")
while 큐:
    이번층, 넣은것 = [], []
    for _ in range(len(큐)):          # 지금 큐에 있는 만큼만 꺼낸다 = 한 층
        t = 큐.popleft()
        이번층.append(t.val)
        for c in (t.left, t.right):
            if c:
                큐.append(c); 넣은것.append(c.val)
    print(f"{층:<4}{str(이번층):<16}{str(넣은것):<16}{[x.val for x in 큐]}")
    층 += 1

# 출력:
# 뜻: 반복문에 들어가기 전의 큐 길이가 그 층의 크기다. 그만큼만 꺼내니 층마다 한 줄씩 나온다.
# 층   큐에서 꺼낸 것        큐에 넣은 것         큐 상태
# 0   [8]             [3, 10]         [3, 10]
# 1   [3, 10]         [1, 6, 14]      [1, 6, 14]
# 2   [1, 6, 14]      [4, 7, 13]      [4, 7, 13]
# 3   [4, 7, 13]      []              []
```

표는 층마다 한 줄씩 나왔습니다. 0층에서는 큐에 `[8]` 만 있어서 8 하나를 꺼내고 자식 3 과 10 을 넣었습니다. 1층에 들어갈 때는 큐 길이가 2 라서 3 과 10 두 개만 꺼내므로 그사이에 넣은 자식 1, 6, 14 는 다음 층 몫으로 남습니다. **반복문에 들어가기 전의 큐 길이가 곧 지금 층의 크기입니다.** 층을 나누는 일은 `for _ in range(len(큐))` 한 줄이 다 하는데, 이 줄이 없으면 층 경계가 사라져서 전체가 한 줄로 나옵니다.

이 방식을 **너비 우선 탐색**(BFS)이라고 합니다. 한 층을 다 본 뒤 다음 층으로 가는 탐색이라는 뜻입니다. 다음 편의 그래프에서도 같은 코드를 다시 쓰는데, 트리는 갈래가 되돌아오지 않는 그래프라서 방문 표시를 안 해도 된다는 점만 다릅니다.

## 4. 재귀 깊이 — 파이썬의 기본 한계 1000

**트리가 깊으면 재귀가 오류로 죽습니다. 코딩 테스트에서 원인을 못 찾고 헤매기 쉬운 오류입니다.**

재귀 깊이는 끝나지 않고 쌓여 있는 자기 호출의 수입니다. 파이썬은 이 깊이에 한계를 두는데, 기본 한계는 1000 이고 넘으면 `RecursionError` 가 납니다. 순회 재귀는 한 층 내려갈 때마다 호출이 하나씩 쌓이므로 트리의 높이가 이 한계만큼 깊으면 2절의 순회 코드가 그대로 죽습니다. 기본 한계를 찍은 뒤 한계 안의 깊이 900 과 한계 밖의 깊이 3000 을 돌린 다음 한계를 10,000 으로 올려 3000 을 다시 돌려 보겠습니다.

```python
# 하는 일: 파이썬의 재귀 한계를 확인하고, 깊이 900 과 3000 의 재귀를 기본 한계에서 돌린 뒤, 한계를 올려 3000 을 다시 돌려 본다.
import sys

print("파이썬 기본 재귀 한계", sys.getrecursionlimit())

# 1단계: 깊이 n 까지 재귀하는 함수를 만든다
def 깊이(n):
    if n == 0: return 0
    return 1 + 깊이(n - 1)

# 2단계: 기본 한계에서 900 과 3000 을 돌린다
for n in (900, 3000):
    try:
        print(f"깊이 {n:>5} → {깊이(n)}")
    except RecursionError:
        print(f"깊이 {n:>5} → RecursionError")

# 3단계: 한계를 10,000 으로 올려 다시 돌린다
sys.setrecursionlimit(10_000)
print("한계를 10,000 으로 올린 뒤")
print(f"깊이  3000 → {깊이(3000)}")

# 출력:
# 뜻: 기본 한계는 1000 이다.
# 파이썬 기본 재귀 한계 1000
# 2단계 뜻: 깊이 900 은 한계 안이라 돌고, 3000 은 한계를 넘어 RecursionError 가 난다.
# 깊이   900 → 900
# 깊이  3000 → RecursionError
# 3단계 뜻: 한계를 올리면 같은 깊이 3000 이 돈다.
# 한계를 10,000 으로 올린 뒤
# 깊이  3000 → 3000
```

첫 줄에 찍힌 기본 한계는 1000 입니다. 깊이 900 은 이 한계 안이라 끝까지 돌아 900 이 찍히지만 깊이 3000 은 한계를 넘어 `RecursionError` 가 납니다. 한계를 10,000 으로 올리자 같은 깊이 3000 이 돌아 3000 이 찍혔습니다.

값이 십만 개인 문제에서 트리가 한 줄로 늘어지면 재귀 깊이가 십만이 되므로, 코딩 테스트에서는 `sys.setrecursionlimit(10**6)` 을 코드 맨 위에 적어 두는 것이 관행입니다.

한계를 올린다고 재귀를 무한정 깊게 돌릴 수 있지는 않습니다. 재귀는 부를 때마다 실제 메모리를 쓰기 때문에 너무 깊으면 오류 대신 프로그램 전체가 죽습니다. **깊이가 수십만을 넘길 것 같으면 아예 스택으로 바꾸는 편이 안전합니다.**

## 5. 이진 탐색 트리 — 왼쪽은 작은 값, 오른쪽은 큰 값

**모든 마디에서 "왼쪽 갈래는 전부 나보다 작고 오른쪽 갈래는 전부 나보다 크다"가 성립하면 이진 탐색 트리입니다.**

여기서 왼쪽 갈래는 왼쪽 자식 하나가 아니라 왼쪽 자식과 그 아래에 달린 마디 전부입니다. 이 글의 트리가 이 규칙을 지킵니다. 뿌리 8 을 보면 왼쪽 갈래에 1, 3, 4, 6, 7 이 있고 오른쪽 갈래에 10, 13, 14 가 있습니다. 3 을 봐도 왼쪽에 1, 오른쪽에 4, 6, 7 이 있습니다.

이 규칙 하나가 두 가지를 공짜로 줍니다. 하나는 2절에서 본 대로 **중위로 순회하면 정렬된 순서가 나온다**는 점입니다. 중위는 왼쪽 갈래를 다 본 뒤 나를 보고 그다음 오른쪽 갈래를 보므로, 뿌리 8 에서는 8 보다 작은 1, 3, 4, 6, 7 이 먼저 다 나오고 8 다음에 8 보다 큰 10, 13, 14 가 나옵니다. 모든 마디에서 같은 일이 일어나서 결과 전체가 작은 것부터 나옵니다.

다른 하나가 본론입니다. 값을 찾을 때 **한 번 비교할 때마다 갈래 하나를 전부 버릴 수 있습니다.** 13 을 찾으면서 뿌리 8 과 비교하면 13 이 더 크므로, 8 보다 작은 값만 있는 왼쪽 갈래의 1, 3, 4, 6, 7 은 볼 필요가 없습니다. 앞 편의 이분 탐색은 정렬된 배열의 가운데 값과 비교해 찾을 범위를 절반씩 줄이는 방법입니다. 이진 탐색 트리의 찾기는 같은 일을 배열이 아니라 트리 위에서 합니다.

아래 코드는 같은 값 9개를 두 가지 순서로 넣어 트리 2개를 만들고 각 트리에서 13 을 찾을 때까지 몇 번 비교하는지(코드의 「회차」) 찍습니다. 하나는 1절의 그림과 같은 순서로, 다른 하나는 정렬된 순서로 넣습니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 같은 값 9개를 두 순서로 이진 탐색 트리에 넣고, 13 을 찾는 데 몇 회 걸리는지 비교한다.
# 1단계: 넣기와 찾기를 만든다
# 작으면 왼쪽, 크면 오른쪽으로 내려간다. 찾기는 회차마다 지금 마디와 갈 방향을 찍는다.
def 넣기(t, v):
    if t is None: return Node(v)
    if v < t.val: t.left  = 넣기(t.left, v)
    else:         t.right = 넣기(t.right, v)
    return t

def 찾기(t, v):
    회차 = 0
    while t:
        회차 += 1
        방향 = "찾음" if v == t.val else ("왼쪽" if v < t.val else "오른쪽")
        기호 = '=' if v == t.val else ('<' if v < t.val else '>')
        print(f"  {회차}회  지금 {t.val:>2}  {v} {기호} {t.val}  → {방향}")
        if v == t.val: return 회차
        t = t.left if v < t.val else t.right
    print(f"  {회차}회  더 갈 곳이 없다 → 없음")
    return -1

# 2단계: 같은 값을 두 순서로 넣는다
# 하나는 1절의 그림과 같은 순서로, 하나는 정렬된 순서로 넣는다.
균형 = None
for v in (8, 3, 10, 1, 6, 14, 4, 7, 13):
    균형 = 넣기(균형, v)

한줄 = None
for v in (1, 3, 4, 6, 7, 8, 10, 13, 14):       # 정렬된 순서로 넣는다
    한줄 = 넣기(한줄, v)

# 3단계: 두 트리에서 13 을 찾는다
print("균형 잡힌 트리에서 13 찾기")
a = 찾기(균형, 13)
print("\n정렬된 순서로 넣어 한 줄이 된 트리에서 13 찾기")
b = 찾기(한줄, 13)
print(f"\n같은 값 아홉 개인데 {a}회 vs {b}회")

# 출력:
# 3단계 뜻: 균형 잡힌 트리에서는 비교할 때마다 갈래 하나를 버려 4회 만에 찾는다.
# 균형 잡힌 트리에서 13 찾기
#   1회  지금  8  13 > 8  → 오른쪽
#   2회  지금 10  13 > 10  → 오른쪽
#   3회  지금 14  13 < 14  → 왼쪽
#   4회  지금 13  13 = 13  → 찾음
# 3단계 뜻: 정렬된 순서로 넣으면 오른쪽으로만 이어진 한 줄이 되어, 앞에서부터 스캔하듯이 8회가 걸린다.
#
# 정렬된 순서로 넣어 한 줄이 된 트리에서 13 찾기
#   1회  지금  1  13 > 1  → 오른쪽
#   2회  지금  3  13 > 3  → 오른쪽
#   3회  지금  4  13 > 4  → 오른쪽
#   4회  지금  6  13 > 6  → 오른쪽
#   5회  지금  7  13 > 7  → 오른쪽
#   6회  지금  8  13 > 8  → 오른쪽
#   7회  지금 10  13 > 10  → 오른쪽
#   8회  지금 13  13 = 13  → 찾음
# 3단계 뜻: 같은 값인데 넣은 순서만 달라 회차가 두 배가 됐다.
#
# 같은 값 아홉 개인데 4회 vs 8회
```

1절의 트리처럼 갈래가 양쪽으로 고르게 퍼진 트리를 **균형 잡힌** 트리라고 합니다. 찾기는 뿌리에서 한 층 내려갈 때마다 한 번 비교하므로 트리의 높이가 낮을수록 빨리 끝납니다. 값이 n개일 때 균형 잡힌 트리의 높이는 대략 log n 이지만 한 줄로 늘어진 트리의 높이는 n - 1 입니다. 값 9개로 만든 두 트리의 높이도 그림 위에 적힌 대로 3 과 8(= 9 - 1)입니다. **이진 탐색 트리가 O(log n)이라는 말은 균형이 잡혀 있을 때만 참입니다.**

실무 데이터베이스나 표준 라이브러리는 값을 넣을 때마다 트리의 균형을 스스로 다시 맞추는 **자가 균형** 트리를 씁니다. 레드-블랙 트리와 AVL 트리가 이런 자가 균형 트리의 예입니다. 원리는 "한쪽이 너무 깊어지면 회전시켜 낮춘다"인데, 구현이 길어서 코딩 테스트에서 직접 짜는 일은 거의 없습니다.

**그래서 코딩 테스트에서는 이진 탐색 트리를 직접 만들지 않습니다.** 정렬된 상태에서 찾는 일은 앞 편의 `bisect` 로, 넣고 빼면서 최솟값만 필요한 일은 다음 절의 힙으로 풉니다. `bisect` 는 정렬된 리스트에서 값이 들어갈 자리를 이분 탐색으로 찾는 파이썬 모듈입니다. 이진 탐색 트리는 `bisect` 와 힙의 배경으로 알아 두는 편이 실속 있습니다.

## 7. 힙 — 최솟값 하나를 빨리 꺼내는 구조

**전체를 정렬하지 않고 최솟값 하나만 꺼내는 구조가 힙입니다.**

값이 계속 들어오는데 그때마다 "지금까지 중 가장 작은 것"을 꺼내야 하는 문제가 있습니다. 매번 정렬하면 값 하나가 들어올 때마다 O(n log n) 이 들어서 감당이 안 됩니다.

힙은 이 일만 합니다. 넣기와 최솟값 빼기는 각각 O(log n) 입니다. 다음 절에서 칸 번호로 그 까닭을 따라갑니다. 최솟값은 언제나 맨 앞인 `힙[0]` 에 있으므로 **최솟값을 보기만 할 때는 O(1)** 입니다. 대신 다른 것은 잘 못합니다. "세 번째로 작은 값"을 물으면 힙은 답을 모르는데, 힙이 지키는 규칙은 맨 앞이 최솟값이라는 것 하나뿐이라 둘째와 셋째로 작은 값이 어디 있는지는 정해져 있지 않기 때문입니다.

값 8개를 하나씩 넣으며 힙 안쪽 리스트와 맨 앞 값을 찍은 뒤 마지막에 작은 것부터 모두 꺼내 정렬한 것과 비교해 보겠습니다.

```python
# 하는 일: 값 8개를 힙에 하나씩 넣으며 힙 안쪽과 맨 앞을 찍고, 작은 것부터 모두 꺼내 정렬한 것과 비교한다.
import heapq

# 1단계: 값을 하나씩 힙에 넣는다
값 = [23, 5, 38, 2, 45, 8, 16, 12]
힙 = []
print(f"{'넣는 값':<8}{'힙 안쪽(리스트 그대로)':<34}{'맨 앞(가장 작은 값)'}")
for v in 값:
    heapq.heappush(힙, v)
    print(f"{v:<8}{str(힙):<34}{힙[0]}")

# 2단계: 작은 것부터 모두 꺼낸다
print()
print("작은 것부터 꺼내기")
꺼낸것 = []
while 힙:
    꺼낸것.append(heapq.heappop(힙))
print(" ", 꺼낸것)
print(" 정렬한 것과 같나:", 꺼낸것 == sorted(값))

# 출력:
# 1단계 뜻: 힙 안쪽은 정렬돼 있지 않지만 맨 앞은 늘 가장 작은 값이다. 2 가 들어온 뒤로 맨 앞은 2 다.
# 넣는 값    힙 안쪽(리스트 그대로)                     맨 앞(가장 작은 값)
# 23      [23]                              23
# 5       [5, 23]                           5
# 38      [5, 23, 38]                       5
# 2       [2, 5, 38, 23]                    2
# 45      [2, 5, 38, 23, 45]                2
# 8       [2, 5, 8, 23, 45, 38]             2
# 16      [2, 5, 8, 23, 45, 38, 16]         2
# 12      [2, 5, 8, 12, 45, 38, 16, 23]     2
# 2단계 뜻: 하나씩 꺼내면 작은 것부터 나와 정렬한 것과 같다.
#
# 작은 것부터 꺼내기
#   [2, 5, 8, 12, 16, 23, 38, 45]
#  정렬한 것과 같나: True
```

표의 가운데 열을 보면 힙 안쪽 리스트는 **정렬돼 있지 않습니다.** 마지막 줄의 `[2, 5, 8, 12, 45, 38, 16, 23]` 에서 45 가 38 보다 앞에 있습니다. 그래도 오른쪽 열의 맨 앞 값은 언제나 그때까지의 최솟값이라서 2 가 들어오자 5 에서 2 로 바뀌었고 그 뒤로 45, 8, 16, 12 가 들어와도 2 그대로였습니다. 작은 것부터 모두 꺼낸 결과도 `[2, 5, 8, 12, 16, 23, 38, 45]` 로 정렬한 것과 같았습니다(`True`).

힙의 값어치는 완전한 정렬과 아무 정리도 없는 상태의 중간이라는 데 있습니다. 값이 들어올 때마다 다시 정렬하면 앞에서 본 대로 한 번에 O(n log n) 이 들어 비쌉니다. 반대로 아무 정리도 안 하면 최솟값을 꺼낼 때마다 처음부터 찾아야 합니다. 힙은 **"맨 앞만 최솟값"이라는 약한 규칙만 지키고 그 대가로 넣기와 빼기를 O(log n) 으로 싸게 합니다.**

## 8. 배열로 담은 힙 — 칸 번호로 찾는 부모와 자식

**힙이 트리처럼 보이지만 코드에는 연결선이 없습니다. 칸 번호로 부모와 자식을 계산합니다.**

그래서 앞 절의 출력이 리스트였습니다. 여기서 칸 번호는 0 부터 세는 리스트 인덱스를 말합니다. 칸 `i` 의 왼쪽 자식은 `2i+1` 칸, 오른쪽 자식은 `2i+2` 칸, 부모는 `(i-1)//2` 칸입니다. 여기서 `//` 는 나머지를 버리는 나눗셈입니다. 이 계산만 있으면 `Node` 클래스도 `left`, `right` 자리도 필요 없습니다. 아래 코드는 7절의 힙 8칸에서 칸마다 부모와 자식 칸을 계산해 찍고 부모 값이 내 값 이하인지도 확인합니다.

```python
# 하는 일: 7절의 힙 8칸에서 칸 번호로 부모와 자식 칸을 계산해 찍고, 부모 값이 내 값 이하인지 본다.
힙 = [2, 5, 8, 12, 45, 38, 16, 23]

print(f"{'칸':<4}{'값':<5}{'부모 칸':<9}{'왼쪽 자식':<11}{'오른쪽 자식':<12}{'부모 값 ≤ 내 값'}")
for i, v in enumerate(힙):
    부모 = (i - 1) // 2 if i > 0 else None
    왼, 오 = 2*i + 1, 2*i + 2
    왼 = 왼 if 왼 < len(힙) else None
    오 = 오 if 오 < len(힙) else None
    지킴 = "-" if 부모 is None else ("예" if 힙[부모] <= v else "아니오")
    print(f"{i:<4}{v:<5}{str(부모):<9}{str(왼):<11}{str(오):<12}{지킴}")

print("\n칸 번호만으로 부모, 자식을 계산하니 연결선을 따로 안 들고 있어도 된다.")

# 출력:
# 뜻: 칸 i 의 자식은 2i+1, 2i+2 이고 부모는 (i-1)//2 다. 뿌리인 0번 칸을 뺀 모든 칸에서 부모 값이 내 값 이하라 힙 규칙을 지킨다.
# 칸   값    부모 칸     왼쪽 자식      오른쪽 자식      부모 값 ≤ 내 값
# 0   2    None     1          2           -
# 1   5    0        3          4           예
# 2   8    0        5          6           예
# 3   12   1        7          None        예
# 4   45   1        None       None        예
# 5   38   2        None       None        예
# 6   16   2        None       None        예
# 7   23   3        None       None        예
# 뜻: 연결선 없이 계산만으로 트리를 오간다.
#
# 칸 번호만으로 부모, 자식을 계산하니 연결선을 따로 안 들고 있어도 된다.
```

## 9. 실전 heapq — 최대 힙, 튜플, 상위 K

**파이썬 `heapq` 는 최소 힙(작은 것부터 꺼내는 힙)만 줍니다. 나머지는 넣는 값을 바꿔서 해결합니다.**

부호를 뒤집으면 가장 큰 값이 가장 작은 값이 되므로, 큰 것부터 꺼내야 하면 부호를 뒤집어 넣고 꺼낼 때 다시 뒤집습니다. 값에 딸린 정보가 있으면 튜플로 묶어 넣는데, 튜플은 앞 원소부터 비교하니 첫 원소가 정렬 기준이 됩니다. 아래 코드는 값 5개를 큰 것부터 꺼내고 순위와 이름을 묶은 작업 4개를 급한 것부터 꺼냅니다.

```python
# 하는 일: heapq 로 값 5개를 큰 것부터 꺼내고, 순위와 이름을 묶은 작업 4개를 급한 것부터 꺼낸다.
import heapq

값 = [23, 5, 38, 2, 45]

# 1단계: 부호를 뒤집어 큰 것부터 꺼낸다
# 파이썬 heapq 는 작은 것부터만 꺼낸다. 큰 것부터 꺼내려면 부호를 뒤집는다.
최대힙 = []
for v in 값:
    heapq.heappush(최대힙, -v)
print("큰 것부터", [-heapq.heappop(최대힙) for _ in range(len(값))])

# 2단계: 튜플로 묶어 급한 것부터 꺼낸다
# 값 말고 딸린 정보도 같이 넣으려면 튜플로 묶어 넣는다. 튜플은 앞 원소부터 비교하니 맨 앞에 순위를 둔다.
작업 = [(2, "리포트"), (1, "장애 대응"), (3, "회의"), (1, "배포 롤백")]
h = []
for 순위, 이름 in 작업:
    heapq.heappush(h, (순위, 이름))
print("급한 것부터")
while h:
    순위, 이름 = heapq.heappop(h)
    print(f"  {순위}순위  {이름}")

# 출력:
# 1단계 뜻: -v 로 넣고 꺼낼 때 다시 뒤집으니 큰 것부터 나온다.
# 큰 것부터 [45, 38, 23, 5, 2]
# 2단계 뜻: 튜플은 앞 원소부터 비교하니 순위 숫자가 작은 것부터 나온다. 순위가 같은 둘은 이름의 가나다순으로 배포 롤백이 먼저다.
# 급한 것부터
#   1순위  배포 롤백
#   1순위  장애 대응
#   2순위  리포트
#   3순위  회의
```

첫 줄에는 `[45, 38, 23, 5, 2]` 가 큰 것부터 찍혔습니다. 가장 큰 45 는 부호를 뒤집어 넣으면 넣은 값 가운데 가장 작은 값이 되어 맨 먼저 나오고 꺼낼 때 부호를 다시 뒤집어 45 로 찍힙니다. 급한 것부터 꺼낸 작업에서는 1순위가 2개인데, 순위가 같으면 튜플의 둘째 원소인 이름으로 넘어가 가나다순으로 비교하므로 "배포 롤백"이 "장애 대응"보다 먼저 나왔습니다. **순서를 넣은 차례대로 유지하고 싶으면 `(순위, 들어온 번호, 이름)` 처럼 원소를 하나 더 둡니다.** 들어온 번호는 서로 달라서 비교가 이름까지 가지 않지만 둘째 원소를 빼면 이름 비교로 넘어가 버립니다.

"값이 아주 많은데 큰 것 K개만 필요한" 경우가 가장 흔합니다. 값 20만 개에서 큰 것 10개를 전부 정렬, 직접 짠 힙, `heapq.nlargest` 세 방법으로 구해 걸린 시간을 측정하고 세 답이 같은지 보겠습니다. 직접 짠 힙은 10칸만 들고 있다가 11개가 되면 가장 작은 것을 버립니다.

```python
# 하는 일: 값 20만 개에서 큰 것 10개를 전부 정렬, 직접 짠 힙, heapq.nlargest 세 방법으로 구해 걸린 시간을 비교한다.
import heapq, random, time

random.seed(7)
값 = [random.randint(1, 1_000_000) for _ in range(200_000)]
K = 10

# 1단계: 세 방법을 만든다
# 직접 짠 힙은 10칸만 들고 있다가 11개가 되면 가장 작은 것을 버린다.
def 측정(fn):
    t = time.perf_counter()
    r = fn()
    return (time.perf_counter() - t) * 1000, r

def 전부정렬():
    return sorted(값, reverse=True)[:K]

def 힙K칸():
    h = []
    for v in 값:
        heapq.heappush(h, v)
        if len(h) > K:
            heapq.heappop(h)       # 가장 작은 것을 버린다
    return sorted(h, reverse=True)

def nlargest():
    return heapq.nlargest(K, 값)

# 2단계: 세 방법을 측정하고 답을 비교한다
print(f"값 {len(값):,}개 중 큰 것 {K}개")
print(f"{'방법':<16}{'시간(ms)':>10}{'들고 있는 칸':>14}")
답 = []
for 이름, fn, 칸 in (("전부 정렬", 전부정렬, f"{len(값):,}"),
                    ("힙 K칸 직접", 힙K칸, str(K)),
                    ("heapq.nlargest", nlargest, str(K))):
    ms, r = 측정(fn)
    답.append(r)
    print(f"{이름:<16}{ms:>10.1f}{칸:>14}")
print(f"\n세 답이 모두 같나 {답[0] == 답[1] == 답[2]}")

# 출력 (시간은 돌릴 때마다 다르다):
# 2단계 뜻: 직접 짠 힙은 10칸만 들고도 31.9밀리초로, 200,000칸을 들고 전부 정렬한 21.9밀리초보다 느리다. nlargest 는 2.2밀리초로 셋 가운데 가장 빠르고, 세 답은 같다.
# 값 200,000개 중 큰 것 10개
# 방법                  시간(ms)       들고 있는 칸
# 전부 정렬                 21.9       200,000
# 힙 K칸 직접               31.9            10
# heapq.nlargest         2.2            10
#
# 세 답이 모두 같나 True
```

이번에 찍힌 시간은 전부 정렬 21.9밀리초, 직접 짠 힙 31.9밀리초, `nlargest` 2.2밀리초입니다. 세 답은 모두 같았습니다(`True`). 밀리초는 기계마다 다릅니다. **직접 짠 힙이 전부 정렬보다 느립니다.** 힙은 10칸만 들고 계산 횟수도 적으니 더 빠를 것 같지만 결과는 반대라 놀랄 만한데, 이유가 있습니다. 파이썬의 `sorted` 는 C 로 짜여 있는데 직접 짠 반복문은 파이썬으로 한 줄씩 돌아서 계산 횟수는 힙이 적어도 계산 한 번의 비용이 훨씬 비쌉니다.

`nlargest` 가 2.2밀리초로 압도적으로 빠른 까닭은 다릅니다. `nlargest` 도 파이썬으로 짠 함수지만 값마다 지금 고른 K개 가운데 가장 작은 값과 한 번만 비교해서 그 값보다 크지 않은 대부분의 값은 힙에 넣지 않고 그냥 지나갑니다. 반면 직접 짠 힙은 값 200,000개를 모두 힙에 넣고 11개가 될 때마다 가장 작은 것을 하나 뺍니다.

여기서 두 가지를 가져가면 됩니다. **첫째, 파이썬에서는 표준 라이브러리 함수가 거의 항상 직접 짠 반복문보다 빠릅니다.** 둘째, 그래도 직접 짠 힙에는 값어치가 있습니다. 표의 「들고 있는 칸」 열에서 전부 정렬은 200,000칸을 들고 있어야 하지만 직접 짠 힙은 `nlargest` 와 같이 10칸이라 **들고 있는 칸이 K개뿐입니다.** 값이 파일에서 한 줄씩 들어와 전부 담을 수 없을 때 이 점이 쓸모가 있습니다.

## 10. 자료구조를 고르는 순서

**어느 자료구조를 쓸지는 입력의 모양과 문제가 무엇을 묻는지로 정해집니다.**

먼저 입력이 트리 모양인지 봅니다. "부모", "상사", "폴더", "조상"처럼 위아래 관계가 있으면 트리입니다. 이때 층을 물으면 큐로 층별 순회를, 자식을 다 처리해야 부모를 처리할 수 있으면 후위 순회를 씁니다.

값이 정렬된 상태에서 찾는 일이라면 이진 탐색 트리를 직접 만들지 말고 **앞 편의 `bisect`** 를 씁니다. 파이썬 리스트는 가운데 삽입이 O(n)이라 넣기가 잦으면 불리하지만 코딩 테스트 범위에서는 대체로 통과합니다.

값이 계속 들어오면서 **최솟값이나 최댓값 하나만** 반복해서 필요하면 힙입니다. "가장 급한 작업", "가장 가까운 점", "지금까지 중 K번째"가 전부 이 꼴입니다. 다음 편의 최단 경로 알고리즘도 속에 힙을 씁니다.

마지막으로 재귀를 쓸 때는 깊이를 먼저 생각합니다. **입력 크기가 만을 넘으면 `sys.setrecursionlimit` 을 맨 위에 적어 두는 것이 습관이 되어야 합니다.**

## 한눈 정리

| 상황 | 쓸 것 | 왜 |
|---|---|---|
| 트리를 그대로 저장하거나 복사한다 | 전위 순회 | 뿌리부터 나와 위에서 아래로 다시 만든다 |
| 이진 탐색 트리를 정렬된 순서로 본다 | 중위 순회 | 왼쪽, 나, 오른쪽 순서가 곧 크기 순서 |
| 자식을 다 처리해야 부모를 처리한다 | 후위 순회 | 폴더 크기, 트리 삭제 |
| "몇 층인가", "각 층에 무엇이" | 큐로 층별 순회 | 반복문 전의 큐 길이가 그 층의 크기 |
| 재귀가 깊어질 것 같다 | `sys.setrecursionlimit` | 기본 한계가 1000뿐 |
| 정렬된 값에서 찾기, 넣기 | `bisect` | 이진 탐색 트리를 직접 안 짜도 된다 |
| 최솟값 하나만 반복해서 꺼낸다 | `heapq` | 넣기, 빼기 O(log n), 최솟값 보기 O(1) |
| 큰 것부터 꺼낸다 | 부호를 뒤집어 넣는다 | 파이썬은 최소 힙만 준다 |
| 값에 정보를 붙여 넣는다 | 튜플 `(기준, 순번, 값)` | 앞 원소부터 비교하니 둘째 원소를 빼면 안 된다 |
| 아주 많은 값 중 상위 K개 | `heapq.nlargest` | 값 대부분을 한 번 비교하고 지나가 직접 짠 힙보다 빠르다 |

## 헷갈리기 쉬운 점

- **이진 탐색 트리가 항상 O(log n)은 아닙니다.** 정렬된 순서로 넣으면 한 줄이 되어 O(n)이 됩니다. 같은 값 9개인데도 13 을 찾는 데 4회와 8회가 걸렸습니다.
- **중위 순회는 이진 탐색 트리일 때만 정렬된 순서를 줍니다.** 이진 탐색 트리가 아닌 이진 트리를 중위로 순회하면 그냥 뒤섞인 순서가 나옵니다.
- **힙 안쪽은 정렬돼 있지 않습니다.** 맨 앞만 최솟값이고 둘째로 작은 값이 어디 있는지는 정해져 있지 않습니다.
- **파이썬 `heapq` 는 최대 힙이 없습니다.** 그래서 부호를 뒤집는데 값이 문자열이면 부호를 뒤집을 수 없으니 정렬 기준을 따로 만들어야 합니다.
- **튜플로 넣을 때 둘째 원소인 들어온 번호를 빼지 마십시오.** 첫 원소가 같으면 둘째 원소를 비교하는데, 들어온 번호를 빼서 그 자리에 비교할 수 없는 값이 오면 오류가 납니다.
- **직접 짠 힙이 `sorted` 보다 빠르다고 단정하지 마십시오.** 파이썬에서는 반대인 경우가 흔합니다. 힙의 값어치는 속도보다 **들고 있는 칸이 K개뿐**이라는 점입니다.
- **재귀 한계는 올려도 무한이 아닙니다.** 너무 깊으면 오류 대신 프로그램 전체가 죽습니다.
