Semantic ID 카드 네 장

상품 300건의 벡터를 세 단의 코드북으로 양자화해 코드 셋을 붙이고, 코드 트리에서 빔 탐색으로 상품을 꺼내는 자리를 한 장씩 봅니다. 3단 코드북, 코드 트리, 단마다 고르기, 새 상품입니다. 상품과 회원 A 가 본 상품 셋, 새 상품 10건은 설명용 가상 값입니다.

파랑 = 상품과 코드북 벽돌색 = 회원 A 의 질의와 빔이 고른 것 먹색 = 트리의 노드와 상품이 받은 코드 회색 = 빔에서 빠진 것과 비교할 기준값 점선 상자 = 가상 값 (회원 A 가 본 상품, 새 상품)

CODEBOOK

3단 코드북

쉽게 말하면 상품 벡터에 가장 가까운 중심의 번호를 고르고, 그 중심을 뺀 나머지로 다음 단의 번호를 고릅니다.

상품 0 은 코드 셋 (8, 6, 9) 를 받았습니다. 잔차 길이 평균은 1.000 에서 0.748 로 줄었고, 3단은 코드 9 에 284건이 몰렸습니다.

CODE TREE

코드 트리

쉽게 말하면 앞자리가 같은 코드 셋을 한 가지에 모으고, 맨 아래 리프에 상품을 넷째 자리 차례로 답니다.

코드 셋 147가지 가운데 73개를 상품 둘 이상이 함께 씁니다. 넷째 자리를 붙이면 id 300개가 모두 다릅니다.

BEAM SEARCH

단마다 고르기

쉽게 말하면 단마다 점수가 좋은 코드 셋 3개만 남기고 다음 단으로 내려가, 마지막 리프에서 상품을 꺼냅니다.

빔은 상품 10건을 꺼냈습니다. 전수 코사인 상위 10건과 겹친 상품은 1건이고, 6건은 빔의 1단에서 빠졌습니다.

COLD START

새 상품

쉽게 말하면 새 상품은 이름의 벡터만 있으면 학습해 둔 코드북으로 바로 코드를 받습니다.

새 상품 10건이 모두 코드를 받았고, 8건은 있던 리프에 들어갔습니다. 회원 A 의 빔은 그 가운데 2건을 바로 꺼냈습니다.

현업에서는 이렇게 씁니다

  • Semantic ID 를 쓸 때는 세 가지를 묻습니다. 코드가 무엇을 묶는가, 한 코드에 상품이 몰리지 않는가, 코드북을 바꾸면 생성 모델도 다시 학습하는가.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 생성형 검색과 Semantic ID 편에 이 카드들이 절마다 들어 있습니다. 상품과 장난감 임베딩은 임베딩과 벡터 검색 편에서 왔습니다.
