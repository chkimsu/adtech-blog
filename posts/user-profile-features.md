모델 팀에 온 지 13주째 되는 월요일, 지훈 씨는 세그먼트 317 의 정의 코드를 열었습니다. 서연 씨의 러닝화 캠페인이 「보여 줄 사람」 칸에 적어 둔 그 번호입니다. 코드는 회원마다 최근 30일의 행동 기록을 읽고, 조건 셋 중 하나가 맞으면 번호를 붙이는 것이 전부였습니다.

같은 기록을 읽는 모델 팀의 학습 코드는 번호 대신 행동마다 날짜를 따져, 회원 한 명에게 숫자 8개를 남겼습니다. 선배는 그 8개가 닮은 회원을 찾는 계산의 재료라고 했습니다.

**같은 30일 기록에서 번호가 붙는 것은 알겠는데, 숫자 8개는 무엇을 어떻게 세어 만들까요?**

회원의 행동을 모델이 읽을 숫자로 바꿔 둔 것을 유저 프로파일 피처(user profile feature)라고 부릅니다. 번호는 광고주가 조건에 적는 이름이고 숫자 8개는 모델의 입력이라, 잘못 세면 닮은 회원을 찾는 계산이 엉뚱한 사람을 고릅니다. 서연 씨가 「보여 줄 사람」을 닮은 회원으로 바꾸면 하루 300만 원이 그 사람들에게 쓰입니다.

> **한 줄 요약:** 회원의 30일 행동 기록 한 벌에서 조건에 대 보면 세그먼트 317 같은 번호가 붙고, 숫자로 세면 8차원 벡터가 됩니다. 벡터는 사건마다 7일에 절반씩 덜 쳐서 더한 값에서, 행동마다 전체 대신 보는 표본 2,000명의 평균을 빼고 표준편차로 나눈 것입니다. 이번 주에 읽은 러닝 글 9편은 7.21 이고, 같은 9편이 모두 2주 전이었다면 1.80 입니다. 표본 2,000명 중에서는 229명(11.4%)에게 317 이 붙습니다.

> **골라 읽는 법** — 절이 6개인 글이고, 절마다 카드 한 장이나 표 하나가 들어 있어 그것만 보고 넘어가도 됩니다.
>
> - 행동 기록이 표 한 장이 되는 자리 → 1절
> - 날짜를 보는 합계, 최근성 가중 → 2절
> - 숫자 8개를 벡터로 놓고 표준화하기 → 3절
> - 세그먼트 317 의 조건 셋과 표본 2,000명 → 4절
> - 다음 글들에서 이 벡터가 쓰이는 자리 → 5절
> - 담장 안과 열린 RTB 에서 달라지는 것 → 6절

이 글의 행동 기록과, 전체 회원 대신 들여다보는 표본(sample)은 전부 설명을 위한 가상 데이터입니다. 회원 1,400만 명과 세그먼트 317 의 160만 명은 타겟팅 트랙과 같은 값입니다. 맞춤타겟 8만 명과 유사타겟 10% 의 140만 명도 [타겟팅 기초](post.html?id=targeting-basics)에서 시작한 그 트랙의 값입니다. 회원 A, 회원 B, 비로그인 C 는 [후보풀](post.html?id=candidate-pool-basics) 편에 나온 세 사람 그대로입니다. 카드 속 파랑은 회원 A, 벽돌색은 회원 B, 회색은 날짜만 옮겨 본 가정이고, 점선 상자는 적어 둔 조건입니다.

## 1. 회원 A 의 30일 행동은 표 한 장입니다

**회원 A 의 최근 30일에는 행동 8종으로 센 일이 37번 있습니다. 러닝화 검색 12회, 운동 앱 8일, 러닝 글 9편이 날짜와 함께 남아 있고, 이 표 한 장이 세그먼트 번호와 숫자 8개의 공통 재료입니다.**

회원이 앱에서 한 일은 회원 번호, 시각, 한 일을 담은 한 줄로 남고, 이것을 행동 로그(behavior log)라고 부릅니다. 이 글은 그 한 줄이 가리키는 일 하나를 사건이라고 부르는데, 회원 A 가 오늘 아침 러닝화를 검색하면 그 검색이 사건 하나입니다. 로그가 앱에서 분석용 저장소까지 가는 길은 [광고 시스템 로그 파이프라인](post.html?id=ad-log-pipeline) 편에 있습니다.

이 글은 행동을 8종만 세는데, 러닝 쪽이 넷이고 다른 관심사가 넷입니다. 러닝 쪽은 검색어 러닝화, 운동 앱 실행 일수, 러닝 글, 운동 용품 구매입니다. 다른 넷은 여행 글, 카페 글, 캠핑 글, 캠핑 용품 검색입니다. 운동 앱은 켠 횟수가 아니라 켠 날을 세서, 하루에 10번 켜도 1일로 칩니다.

아래 표는 회원 A 의 30일을 행동마다 주 단위로 묶은 것입니다. 날짜는 경과일로 적는데, 경과일은 그 일이 며칠 전에 있었나이고 0일 전이 오늘입니다.

| 행동 | 30일 합계 | 0~6일 전 | 7~13일 전 | 14~20일 전 | 21~29일 전 |
|---|---|---|---|---|---|
| 검색어 러닝화 | 12회 | 5 | 3 | 2 | 2 |
| 운동 앱 실행 일수 | 8일 | 4 | 3 | 1 | 0 |
| 러닝 글 | 9편 | 9 | 0 | 0 | 0 |
| 운동 용품 구매 | 1회 | 1 | 0 | 0 | 0 |
| 여행 글 | 4편 | 0 | 0 | 2 | 2 |
| 카페 글 | 3편 | 1 | 1 | 1 | 0 |
| 캠핑 글 | 0편 | 0 | 0 | 0 | 0 |
| 캠핑 용품 검색 | 0회 | 0 | 0 | 0 | 0 |

러닝 쪽 넷은 이번 주에 몰려 있고, 그중 러닝 글은 9편이 모두 이번 주입니다. 여행 글 4편은 모두 2주 넘게 전이고, 카페 글 3편은 주마다 한 편씩 고르게 있습니다. 같은 30일 안이라도 줄마다 시간이 놓인 모양이 이렇게 다릅니다.

회원 B 의 표는 캠핑 두 줄만 차 있고, 캠핑 글 15편과 캠핑 용품 검색 6회가 30일에 고르게 퍼져 있습니다. 운동 앱을 포함한 나머지 6줄은 모두 0 입니다. 회원 B 는 후보풀 편에서 세그먼트 77 캠핑 하나만 가진 부산의 회원입니다.

이 표를 회원 1,400만 명 모두에게 날마다 새로 만드는데, 합계 칸만 남기면 한 명에 숫자 8개라 가볍습니다. 그런데 합계 칸만 보면 회원 A 는 여행 글 4편이 카페 글 3편보다 큰 관심으로 보입니다. 여행 글은 2주 넘게 전이고 카페 글은 이번 주에도 있는데도 그렇게 보입니다.

## 2. 합계만 보면 오래된 관심과 지금 관심을 구분하지 못합니다

**합계는 30일 안의 날짜를 보지 않습니다. 사건을 7일마다 절반으로 덜 쳐서 더하면 이번 주에 읽은 러닝 글 9편은 7.21 입니다. 같은 9편이 모두 2주 전이었다면 1.80 입니다.**

합계는 29일 전의 글 한 편과 오늘의 글 한 편을 똑같이 1 로 셉니다. 회원 A 의 여행 글 4편은 2~4주 전에 읽은 것인데도, 합계로는 카페 글 3편보다 큰 관심이 됩니다. 이 숫자로 여행사 캠페인의 후보를 고르면, 여행 계획이 끝난 사람에게 하루 500만 원 예산을 쓰게 됩니다.

그래서 사건마다 가중치, 곧 그 사건을 얼마만큼 칠지 정하는 수를 곱해 더합니다. 날짜로 가중치를 주는 이 방법을 최근성 가중(recency weighting)이라고 부릅니다. 이 글은 7일이 지날 때마다 가중치가 절반이 되게 두고, 절반이 되는 데 걸리는 이 7일을 반감기(half-life)라고 부릅니다. 식으로는 사건마다 0.5 를 (경과일 ÷ 7) 번 곱하니, 오늘의 사건은 1 로, 14일 전 사건은 0.25 로 칩니다. 이렇게 곱해 더한 값을 가중합이라고 부르겠는데, 30일이 지난 사건이 아예 빠지는 것은 합계와 같습니다.

아래 코드가 회원 A 의 행동 8종을 합계와 가중합으로 세고, 3단계에서 다음 절의 표준화까지 합니다. 표준화하려면 비교할 회원들이 먼저 있어야 해서 표본 2,000명을 만드는 생성기가 같이 들어 있고, 생성기의 뜻은 4절에서 봅니다.

```python
# 하는 일: 회원 A 의 30일 행동을 합계와 최근성 가중 합으로 집계해 8차원 벡터로 만든다.
import random
import statistics

# 1단계: 행동 표를 둔다
# 행동마다 사건의 경과일을 적는다. 0 은 오늘, 29 는 29일 전이고, 같은 날 두 번이면 두 번 적는다.
KEYS = ['search_running_shoes', 'sports_app_days', 'running_posts', 'sports_goods_buy',
        'travel_posts', 'cafe_posts', 'camping_posts', 'camping_search']
NAMES = ['검색어 러닝화', '운동 앱 실행 일수', '러닝 글', '운동 용품 구매',
         '여행 글', '카페 글', '캠핑 글', '캠핑 용품 검색']
MEMBER_A = {
    'search_running_shoes': [0, 1, 2, 3, 5, 7, 9, 12, 15, 18, 22, 27],
    'sports_app_days': [0, 2, 4, 6, 9, 11, 13, 16],      # 켠 날을 적으니 같은 날이 두 번 없다
    'running_posts': [0, 0, 1, 1, 2, 3, 4, 5, 6],
    'sports_goods_buy': [5],
    'travel_posts': [17, 19, 22, 26],
    'cafe_posts': [1, 10, 20],
    'camping_posts': [],
    'camping_search': [],
}
MEMBER_B = {k: [] for k in KEYS}                         # 캠핑 둘 말고는 30일 동안 한 일이 없다
MEMBER_B['camping_posts'] = [0, 1, 3, 4, 6, 8, 10, 12, 14, 16, 18, 21, 23, 26, 28]
MEMBER_B['camping_search'] = [1, 3, 6, 10, 15, 21]

# 2단계: 합계와 가중합을 센다
# 합계는 사건 수다. 가중합은 사건마다 0.5 ** (경과일 / 7) 을 더한 값이라 7일 전 사건은 절반만 센다.
HALF_LIFE = 7


def counts(m):
    return {k: len(m[k]) for k in KEYS}


def weighted(m):
    return {k: sum(0.5 ** (d / HALF_LIFE) for d in m[k]) for k in KEYS}


c, w = counts(MEMBER_A), weighted(MEMBER_A)
print('합계  가중합  회원 A 의 행동')
for k, name in zip(KEYS, NAMES):
    print(f'{c[k]:>4}  {w[k]:>6.2f}  {name}')
run_days = MEMBER_A['running_posts']
moved = [sum(0.5 ** ((d + s) / HALF_LIFE) for d in run_days) for s in (7, 14)]   # 날짜만 앞으로 옮긴다
print(f'러닝 글 9편의 가중합: 지금 {w["running_posts"]:.2f}, '
      f'모두 7일 전이면 {moved[0]:.2f}, 14일 전이면 {moved[1]:.2f}')

# 3단계: 표준화한다
# 표준화하려면 비교할 표본이 먼저 필요하다. 생성기는 4절에서 자세히 보고, 여기서는 2,000명을 만들어 쓴다.
SEGMENT_317 = {'running_posts': 3, 'sports_app_days': 5, 'search_running_shoes': 1}   # 셋 중 하나


def in_segment_317(m):
    c = counts(m)
    return any(c[k] >= at_least for k, at_least in SEGMENT_317.items())


def runner_count(n):
    return n * 229 // 2000                               # 러닝 성향 11.45%, 2,000명이면 229명


# 행동마다 (그 행동을 하는 사람 비율, 하는 사람의 30일 평균 횟수). 앞은 러닝 성향, 뒤는 나머지다.
TENDENCY = {
    'search_running_shoes': ((0.17, 11.0), (0.00, 0.0)),
    'sports_app_days':      ((0.26, 9.0), (0.25, 2.5)),
    'running_posts':        ((0.46, 8.0), (0.25, 1.5)),
    'sports_goods_buy':     ((0.30, 1.5), (0.10, 1.2)),
    'travel_posts':         ((0.30, 4.0), (0.30, 4.0)),
    'cafe_posts':           ((0.40, 4.0), (0.40, 4.0)),
    'camping_posts':        ((0.08, 7.0), (0.12, 7.0)),
    'camping_search':       ((0.05, 5.0), (0.08, 5.0)),
}


def make_members(n, seed=7):
    """회원 n 명의 30일 행동. 0번은 회원 A, 1번은 회원 B 다."""
    rng = random.Random(seed)
    n_run = runner_count(n)
    runner = [True] * (n_run - 1) + [False] * (n - n_run - 1)   # A 는 러닝 성향, B 는 나머지
    rng.shuffle(runner)
    members = [dict(MEMBER_A), dict(MEMBER_B)]
    for is_runner in runner:
        while True:     # 러닝 성향은 조건이 하나라도 맞을 때까지, 나머지는 하나도 안 맞을 때까지 다시 뽑는다
            m = {}
            for k in KEYS:
                share, mean = TENDENCY[k][0 if is_runner else 1]
                does = rng.random() < share                     # 이 행동을 하는 사람인가
                days = range(30) if does else []                # 안 하는 사람은 날마다 뽑지 않는다
                m[k] = [d for d in days if rng.random() < mean / 30]
            if in_segment_317(m) == is_runner:
                break
        members.append(m)
    return members


ws = [weighted(m) for m in make_members(2000)]
mean = {k: statistics.fmean(x[k] for x in ws) for k in KEYS}
std = {k: statistics.pstdev([x[k] for x in ws]) for k in KEYS}


def vector(m):
    x = weighted(m)
    return [(x[k] - mean[k]) / std[k] for k in KEYS]


va, vb = vector(MEMBER_A), vector(MEMBER_B)
print('평균  표준편차  회원 A  회원 B  행동 (표본 2,000명의 가중합으로 잰다)')
for i, (k, name) in enumerate(zip(KEYS, NAMES)):
    print(f'{mean[k]:.2f}  {std[k]:>8.2f}  {va[i]:>6.2f}  {vb[i]:>6.2f}  {name}')

# 출력:
# 2단계 뜻: 여행 글은 합계 4 로 카페 글 3 보다 많지만 가중합은 0.53 대 1.42 로 뒤집힌다. 러닝 글 9편을 7일 앞으로 옮기면 가중합이 절반, 14일 앞으로 옮기면 4분의 1 이 된다.
# 합계  가중합  회원 A 의 행동
#   12    5.87  검색어 러닝화
#    8    4.27  운동 앱 실행 일수
#    9    7.21  러닝 글
#    1    0.61  운동 용품 구매
#    4    0.53  여행 글
#    3    1.42  카페 글
#    0    0.00  캠핑 글
#    0    0.00  캠핑 용품 검색
# 러닝 글 9편의 가중합: 지금 7.21, 모두 7일 전이면 3.60, 14일 전이면 1.80
# 3단계 뜻: 회원 A 는 러닝 쪽 넷이 평균보다 표준편차 2.85~8.65개만큼 크고, 회원 B 는 캠핑 둘만 크다. 한 번도 안 한 행동은 0 이 아니라 0 아래로 나온다.
# 평균  표준편차  회원 A  회원 B  행동 (표본 2,000명의 가중합으로 잰다)
# 0.11      0.67    8.65   -0.17  검색어 러닝화
# 0.29      0.74    5.36   -0.38  운동 앱 실행 일수
# 0.30      0.82    8.44   -0.36  러닝 글
# 0.05      0.20    2.85   -0.24  운동 용품 구매
# 0.37      0.73    0.22   -0.51  여행 글
# 0.52      0.82    1.09   -0.64  카페 글
# 0.28      0.83   -0.34    6.91  캠핑 글
# 0.13      0.51   -0.26    5.43  캠핑 용품 검색
```

가중합으로 세면 회원 A 의 줄 순서가 바뀌어서, 여행 글 4편과 카페 글 3편이 가중합으로는 0.53 대 1.42 가 됩니다. 2주 넘게 전의 관심보다 이번 주에도 이어진 관심이 크게 잡힌 것입니다. 러닝 글처럼 이번 주에 몰린 줄은 가중합이 합계에 가깝게 남습니다.

반감기는 데이터에서 나오는 값이 아니라 정해서 쓰는 값이라, 짧게 잡으면 어제 한 일이 거의 전부가 되고 길게 잡으면 합계와 비슷해집니다. 며칠 안에 사는 상품이면 짧은 쪽이, 몇 주를 고민하는 상품이면 긴 쪽이 맞고, 이 글은 8종 모두에 7일 하나를 씁니다. 다만 합계도 가중합도 기간 안에서 모아 세는 순간 사건의 순서는 버립니다. Meta 는 2024년 엔지니어링 글에서 이 한계를 적고, 사건의 순서를 그대로 읽는 모델로 옮겼다고 밝혔습니다.

## 3. 8개 숫자가 벡터 하나가 되고 표준화로 단위가 맞춰집니다

**가중합 8개를 정해 둔 순서로 놓으면 회원 A 의 벡터 하나입니다. 그대로는 검색 횟수와 구매 횟수의 단위가 달라 비교할 수 없습니다. 행동마다 표본 2,000명의 평균을 빼고 퍼진 정도로 나누면 8개가 같은 단위로 맞춰집니다.**

벡터는 숫자를 정해진 순서대로 늘어놓은 것이고, 차원은 그 숫자의 개수입니다. 회원 A 의 가중합 8개를 검색어 러닝화부터 캠핑 용품 검색까지 놓으면 8차원 벡터가 되고, 회원 B 도 같은 순서로 8개를 놓습니다. 순서가 바뀌면 다른 벡터가 되니, 순서는 코드의 KEYS 한 곳에서만 정합니다.

그대로 쓰면 값이 큰 줄이 결과를 거의 다 정합니다. 회원 A 의 가중합은 러닝 글이 7.21 이고 운동 용품 구매가 0.61 입니다. 두 회원이 얼마나 닮았나를 거리로 재면 러닝 글 줄이 거리를 거의 다 정하게 됩니다. 그런데 운동 용품을 산 것은 드문 일이고 글을 읽는 것은 흔한 일이라, 값의 크기가 아니라 다른 회원과 비교해 얼마나 드문가로 재야 합니다.

그래서 행동마다 표본 전체의 평균과, 값들이 평균에서 얼마나 퍼져 있나를 재는 표준편차를 셉니다. 회원의 값에서 평균을 빼고 표준편차로 나누는 것을 표준화(standardization)라고 부릅니다. 나온 값이 0 이면 평균이고 1 이면 평균보다 표준편차 하나만큼 많은 것이라, 이 값을 z 점수(z-score)라고도 부릅니다. 아래 표는 2절 코드의 3단계가 찍은 값을 옮긴 것입니다.

|---|---|---|---|---|---|

| 여행 글 | 0.37 | 0.73 | 0.53 | 0.22 | -0.51 |

벡터는 한 명에 숫자 8개라서, 값 하나를 4바이트로 두면 한 명에 32바이트이고 회원 1,400만 명이면 448MB 입니다. [배치 추론과 실시간 추론](post.html?id=batch-vs-realtime-inference) 편의 유저 벡터 64차원 3.58GB 보다 훨씬 작습니다. 그래서 새벽 배치가 같은 저장소에 함께 만들어 두고, 요청 때 회원 번호로 꺼내 씁니다.

평균과 표준편차는 표본이 바뀌면 같이 바뀌므로, 학습 때 센 값을 적어 두고 서빙 때도 그 값으로 나눕니다. 서빙 때 그날 회원들로 다시 세면 같은 회원 A 가 학습 때와 다른 벡터를 받게 됩니다. 학습과 서빙이 다른 값을 쓰면 무엇이 틀어지는지는 [Feature Store](post.html?id=feature-store-serving) 편에 있습니다. 그러면 그 평균과 표준편차를 낸 표본 2,000명이 누구인지가 남습니다.

## 4. 세그먼트 317 은 규칙 셋이고 표본 2,000명 중 229명에게 붙습니다

**세그먼트 317 의 조건 셋은 오디언스와 세그먼트 편에 적힌 그대로입니다. 러닝 글이나 영상 3번 이상, 러닝 앱을 켠 날 5일 이상, 러닝화 검색 중 하나라도 맞으면 붙습니다. 표본 2,000명 중에서는 229명(11.4%)이 맞습니다.**

[오디언스와 세그먼트](post.html?id=audience-and-segments) 편은 이 세그먼트에 들어오는 조건을 셋으로 적었습니다. 최근 30일에 러닝 글이나 영상을 3번 이상 봤다, 러닝 앱을 켠 날이 5일 이상이다, 러닝화를 검색했다입니다. 이 글은 그 문턱을 그대로 가져와 러닝 글 3편 이상, 운동 앱 실행 일수 5일 이상, 검색어 러닝화 1회 이상으로 셉니다. 이 글의 행동 로그는 러닝 앱을 운동 앱으로 묶어 남기므로, 앱 조건은 운동 앱 실행 일수로 봅니다. 영상은 이 글이 세는 행동 8종에 없어서 글만 셉니다.

규칙이 내는 답은 「맞나, 안 맞나」 하나라서, 러닝 글 3편을 읽은 회원과 30편을 읽은 회원이 똑같이 317 입니다. 그 편에는 90일 동안 셋 다 없으면 뺀다는 나가는 조건도 있지만, 30일 기록으로는 볼 수 없어 이 글에서는 뺐습니다.

회원 전부를 만들 수는 없어서, 전체 대신 들여다보는 일부인 표본 2,000명을 씁니다. 이 표본은 생성기가 만든 가상 회원이고, 생성기는 먼저 표본을 러닝 성향 229명과 나머지 1,771명으로 나눕니다. 러닝 성향은 러닝에 관심이 있게 만든 가상 회원이고, 229명은 160만 ÷ 1,400만 = 11.4% 를 표본 크기에 옮긴 수입니다.

러닝 성향은 조건이 하나라도 맞을 때까지, 나머지는 하나도 안 맞을 때까지 다시 뽑습니다. 행동마다 「그 행동을 하는 사람의 비율」과 「하는 사람의 30일 평균 횟수」를 정해 두고, 날마다 그 행동을 했는지 뽑습니다. 그래서 사건마다 경과일이 붙어 2절의 가중합을 표본에도 똑같이 셀 수 있습니다. 회원 A 는 0번, 회원 B 는 1번에 1절의 기록 그대로 들어갑니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 표본 2,000명을 만들어 세그먼트 317 규칙을 적용하고 몇 명에게 붙는지 센다.
# 1단계: 생성기
# 앞 블록의 make_members 를 다시 부른다. 시드가 7 로 같아 표준화에 쓴 2,000명이 그대로 나온다.
members = make_members(2000)
n_run = runner_count(len(members))
print(f'표본 {len(members):,}명: 러닝 성향 {n_run}명, 나머지 {len(members) - n_run:,}명')
print(f'0번 회원 A 의 30일 합계 {list(counts(members[0]).values())}')
print(f'1번 회원 B 의 30일 합계 {list(counts(members[1]).values())}')

# 2단계: 규칙
# 오디언스와 세그먼트 편의 조건 셋을 하나씩 대 본다. 한 사람이 둘 이상에 맞기도 해서 그냥 더하면 실제보다 많다.
# 조건 셋 SEGMENT_317 은 앞 블록의 3단계에 적어 두었다.
LABELS = {'running_posts': '러닝 글 3편 이상', 'sports_app_days': '운동 앱 켠 날 5일 이상',
          'search_running_shoes': '러닝화 검색 1회 이상'}
total = 0
for k, at_least in SEGMENT_317.items():
    hit = sum(counts(m)[k] >= at_least for m in members)
    total += hit
    print(f'{hit:>5,}명  {LABELS[k]}')
print(f'{total:>5,}명  셋을 그냥 더하면')
for name, m in (('회원 A', members[0]), ('회원 B', members[1])):
    met = sum(counts(m)[k] >= at_least for k, at_least in SEGMENT_317.items())
    print(f'{name}: 조건 {met}개가 맞는다')

# 3단계: 센다
# 하나라도 맞는 사람을 한 번씩만 센다. 비율은 소수 둘째 자리를 버린다(229 ÷ 2,000 = 11.45%).
hits = sum(in_segment_317(m) for m in members)
print(f'세그먼트 317: {hits:,}명 ({hits * 1000 // len(members) / 10}%)')
big = make_members(20000)
big_hits = sum(in_segment_317(m) for m in big)
print(f'표본을 20,000명으로 키우면: {big_hits:,}명 ({big_hits * 1000 // len(big) / 10}%)')

# 출력:
# 1단계 뜻: 생성기가 2,000명을 러닝 성향 229명과 나머지 1,771명으로 먼저 나누고, 0번과 1번에 회원 A 와 B 의 30일을 그대로 넣었다.
# 표본 2,000명: 러닝 성향 229명, 나머지 1,771명
# 0번 회원 A 의 30일 합계 [12, 8, 9, 1, 4, 3, 0, 0]
# 1번 회원 B 의 30일 합계 [0, 0, 0, 0, 0, 0, 15, 6]
# 2단계 뜻: 조건마다 맞는 사람은 러닝 글, 앱, 검색 순으로 많다. 셋을 그냥 더한 312명은 둘 이상에 맞는 사람을 여러 번 센 수이고, 회원 A 는 셋 다, 회원 B 는 하나도 맞지 않는다.
#   162명  러닝 글 3편 이상
#    87명  운동 앱 켠 날 5일 이상
#    63명  러닝화 검색 1회 이상
#   312명  셋을 그냥 더하면
# 회원 A: 조건 3개가 맞는다
# 회원 B: 조건 0개가 맞는다
# 3단계 뜻: 하나라도 맞는 사람은 생성기가 나눈 러닝 성향 수와 같은 229명이고, 표본을 20,000명으로 키워도 2,290명으로 비율이 그대로다.
# 세그먼트 317: 229명 (11.4%)
# 표본을 20,000명으로 키우면: 2,290명 (11.4%)
```

조건마다 맞는 사람을 세면 러닝 글이 가장 많고 검색이 가장 적습니다. 그 편의 전체 회원 수인 글 110만, 앱 62만, 검색 41만과 같은 순서입니다. 셋을 그냥 더하면 312명이지만 둘 이상에 맞는 사람이 있어서 실제로는 229명입니다. 그 편에서도 셋을 더한 213만 명이 겹침을 빼면 160만 명이었습니다.

## 5. 이 벡터가 다음 글들에서 쓰이는 자리

**번호는 「들어 있나」에만 답하고, 벡터는 「얼마나 닮았나」와 「얼마나 살 것 같나」를 셀 재료가 됩니다. 다음 세 편이 이 글의 생성기와 벡터와 행동 8종을 그대로 가져다 씁니다.**

세 편은 이 글에서 같은 것을 가져가 다른 일을 하니, 먼저 이름 셋을 풉니다. Lookalike 는 광고주가 고른 회원들(시드)과 닮은 회원을 찾아 목록을 넓히는 방식입니다. 이 트랙의 시드는 광고주가 올린 구매자 목록을 회원과 맞춘 맞춤타겟 8만 명입니다. 전환 예측은 회원이 광고를 보고 살 확률을 모델이 맞히는 것이고, 그 확률을 pCVR 이라고 부릅니다. 자연어 오디언스는 광고주가 문장으로 쓴 조건을 코드가 읽을 조건으로 바꾸는 일입니다.

| 다음 글 | 이 글에서 가져가는 것 | 그 글이 하는 일 |
|---|---|---|
| 15주째, Lookalike 계산 | 8차원 벡터, 생성기 20,000명 | 시드(맞춤타겟 8만 명)의 벡터 평균과 가까운 순서로 회원을 정렬해 앞 10% 를 자릅니다. 전체로는 140만 명, 세그먼트 6001 입니다 |
| 16주째, 전환 예측으로 고르기 | 8차원 벡터를 모델 입력으로, 세그먼트 317 의 조건 셋 | 317 과 같은 수를 pCVR 이 높은 순서로 고르면 전환이 몇 건 달라지나 셉니다 |
| 18주째, 자연어 오디언스 | 행동 8종의 30일 합계와 키 이름 | 「러닝화 살 사람」 같은 문장을 `search_running_shoes >= 1` 같은 조건으로 바꿔 표본에서 몇 명이 남나 셉니다 |

Lookalike 에서 쓰는 것은 벡터 사이의 거리라서, 시드 8만 명의 벡터 평균 하나를 구하고 회원마다 그 평균과 얼마나 가까운지를 잽니다. 표준화를 안 하면 가중합이 큰 러닝 글 줄이 거리를 다 정하는 3절의 문제가 그대로 돌아옵니다. 그래서 3절의 표준화가 Lookalike 계산의 전제입니다.

전환 예측은 벡터 8개를 모델의 입력으로 넣습니다. 유저와 광고의 과거 정보를 담은 피처가 광고 예측에서 가장 중요하다는 것은 Facebook 의 2014년 논문이 낸 결론입니다. 비교할 기준은 타겟 방식별 전환율로, 관심사 타겟(317)이 0.60%, 유사 10% 가 0.90% 입니다. 이 값은 [카카오는 무엇으로 광고를 고르나](post.html?id=kakao-ads-prediction-targeting) 편과 같습니다. 같은 사람 수를 번호 대신 확률로 고르면 이 차이가 어떻게 바뀌는지가 16주째의 질문입니다.

자연어 오디언스는 벡터가 아니라 30일 합계를 쓰는 쪽입니다. 「러닝화 살 사람」을 받으면 LLM 이 그 문장을 키 이름과 문턱으로 된 조건으로 바꿉니다. LLM 은 사람의 문장을 읽고 글을 써 내는 큰 언어 모델이고, 바뀐 조건으로 표본에서 맞는 사람을 세는 일은 코드가 합니다. 이 글의 키 이름이 그대로 그 조건의 필드 이름이 됩니다.

이 글에서 정한 셋, 곧 행동 8종의 키 이름과 순서, 생성기의 시드 7, 러닝 성향 비율 11.45% 는 뒤 글에서 바꾸지 않습니다. 하나라도 바뀌면 뒤 글의 숫자가 이 글의 숫자와 어긋나기 때문입니다.

## 6. 30일 기록이 한 사람에게 모이나가 무대마다 다릅니다

**벡터의 재료는 한 사람의 30일입니다. 담장 안에서는 로그인한 회원의 행동이 회원 번호 하나에 30일 내내 쌓입니다. 열린 RTB 에서는 쿠키가 바뀌어 같은 사람의 기록이 며칠 만에 끊깁니다.**

1~5절은 회원 A 의 30일이 한 표에 다 모여 있다는 전제 위에 있었는데, 그 전제가 무대에 따라 다릅니다. 같은 셈을 해도 셀 기록이 있느냐가 다르기 때문입니다.

### 담장 안에서는 회원 번호 하나에 30일이 쌓입니다 [무대: 닫힌 생태계]

한 회사가 앱과 광고 서버를 다 가진 담장 안에서는 회원이 로그인한 채로 움직입니다. 그래서 폰에서 한 검색과 PC 에서 읽은 글이 같은 회원 번호로 남고, 30일 동안 기기를 바꿔도 한 표에 모입니다. 이 글의 벡터를 회원 1,400만 명 거의 전부에게 셀 수 있는 것도 그 덕분입니다.

남는 문제는 하루만큼의 낡음인데, 집계를 새벽 배치가 하루 한 번 돌리기 때문입니다. 회원 A 가 오늘 오후에 러닝화를 검색해도 오늘의 벡터에는 없고 내일 새벽에 들어갑니다. 몇 분 안에 반영해야 하는 행동은 [스트림 집계](post.html?id=stream-window-aggregation) 편의 방식으로 따로 셉니다.

### 열린 RTB 에서는 쿠키가 바뀌어 집계 창이 짧습니다 [무대: 열린 RTB]

열린 RTB 에서 광고를 사는 쪽의 시스템을 DSP 라고 부릅니다. DSP 가 남의 지면에서 받는 입찰 요청에는 회원 번호 대신 쿠키나 기기의 광고 ID 가 담겨 옵니다. 쿠키는 브라우저가 사이트마다 남겨 두는 작은 식별 값이라 브라우저마다 다르고 지워지기도 합니다. Safari 는 2019년부터 스크립트로 쓴 쿠키의 수명을 7일로 묶었고, 쿠키가 바뀐 사람은 기록이 처음부터 다시 쌓입니다.

그래서 30일 창을 잡아도 실제로 모인 날이 며칠뿐인 사람이 많고, 처음 보는 쿠키는 행동이 아예 비어 있습니다. 이쪽의 세그먼트는 데이터 관리 플랫폼(DMP)이 쿠키로 만든 익명 목록인 경우가 많습니다. 광고 업계의 표준 단체인 IAB Tech Lab 은 그런 세그먼트마다 갱신 주기와 집계 창을 적어 내게 하는 데이터 라벨을 정해 두었습니다. 비어 있는 사람에게는 지면, 시간, 기기 같은 요청 안의 정보로 광고를 고르고, 그 방식이 17주째의 컨텍스추얼 타겟팅입니다. 아래 표가 두 무대의 차이인데, 가상 데이터가 아니라 설계의 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 기록을 묶는 키 | 로그인한 회원 번호, 기기를 바꿔도 같다 | 쿠키나 기기의 광고 ID, 바뀌고 지워진다 |
| 30일 집계 | 회원 1,400만 명 거의 전부 | 같은 쿠키로 다시 온 사람만, 며칠로 끊긴다 |
| 기록이 빈 사람 | 갓 가입한 회원 | 처음 보는 쿠키 전부 |
| 벡터가 없을 때 | 드물다 | 지면, 시간, 기기 같은 요청 안의 정보로 고른다 |

다음 편은 14주째의 관심사 분류이고, 이 글이 「러닝 글」을 이미 아는 것처럼 센 자리에서 시작합니다. 글 한 편이 러닝 글인지 캠핑 글인지는 누군가 라벨을 붙여야 알 수 있습니다. 그 라벨을 규칙과 모델과 LLM 으로 붙여 보는 것이 다음 편입니다.

| 벡터 | 표준화한 가중합 8개를 정해 둔 순서로 놓는다 | 한 명 32바이트, 1,400만 명 448MB |

| 세그먼트 317 | 조건 셋 중 하나라도 맞으면 번호를 붙인다 | 표본 229명 (11.4%), 전체로는 160만 명 |

## 헷갈리기 쉬운 점

- **세그먼트 번호와 피처 벡터는 다른 물건입니다.** 번호는 「맞나, 안 맞나」 하나이고 광고주가 캠페인 조건에 적습니다. 벡터는 「얼마나」 8개이고 모델이 읽습니다. 러닝 글을 3편 읽은 회원과 9편 읽은 회원은 같은 317 이지만 벡터는 다릅니다.
- **집계 창 30일과 반감기 7일은 다른 값입니다.** 30일은 어디까지 세나를 정하고, 7일은 그 안에서 얼마나 빨리 덜 세나를 정합니다. 29일 전의 사건도 0.06 으로 남고, 30일 전의 사건은 0 입니다. 반감기를 바꿔도 집계 창은 그대로입니다.
- **비로그인 C 는 행동이 없습니다.** 회원 번호가 없어 30일 기록을 모을 자리가 없습니다. 가중합 8개가 다 0 이면 벡터는 30일 동안 아무것도 안 한 회원과 같은 값이 됩니다. 그래서 C 에게는 벡터 대신 요청 안의 정보로 광고를 고릅니다.
- **표준화한 값이 크다고 많이 한 것은 아닙니다.** 드문 행동은 표준편차가 작아서 한 번만 해도 값이 커집니다. 회원 A 의 운동 용품 구매 1회가 카페 글 3편보다 큰 값을 받는 이유입니다.

## 더 깊이 보기

:::deep 반감기 식과, 날마다 30일을 처음부터 다시 읽지 않는 방법
경과일이 $d$ 인 사건의 가중치는 아래와 같고, $h$ 는 반감기라서 이 글에서는 7일입니다.

$$w(d) = 0.5^{d/h} = e^{-\lambda d}, \qquad \lambda = \frac{\ln 2}{h} \approx 0.099$$

한 행동의 가중합은 30일 안의 사건마다 이 값을 더한 것입니다.

$$S = \sum_{i \,:\, d_i \le 29} 0.5^{d_i / 7}$$

그렇다고 날마다 30일을 처음부터 다시 읽어 셀 필요는 없습니다. 하루가 지나면 모든 사건의 경과일이 1 씩 늘어서 가중합 전체에 $0.5^{1/7} \approx 0.906$ 이 곱해지기 때문입니다. 그래서 어제의 가중합에 0.906 을 곱하고 오늘의 사건 수 $n_0$ 를 더하면 오늘의 가중합이 됩니다.

30일 창을 지키려면 오늘로 30일 전이 된 사건 수 $n_{30}$ 에 $0.5^{30/7} \approx 0.051$ 을 곱해 뺍니다.

$$S_t = 0.906 \, S_{t-1} + n_0 - 0.051 \, n_{30}$$

창을 아예 없애고 이 곱셈만 되풀이하면 날짜별 사건 수를 30일치 들고 있을 필요도 없어집니다. 대신 오래된 사건은 0 에 가까워질 뿐 빠지지 않아서, 규칙이 보는 「최근 30일」과 같은 기간을 보지 않게 됩니다.
:::

:::deep 표준화 식과, 학습과 서빙이 같은 평균을 쓰는 이유
행동 $k$ 의 표본 평균과 표준편차는 표본 $n$ 명의 가중합 $x_{ik}$ 로 셉니다.

$$\mu_k = \frac{1}{n}\sum_{i=1}^{n} x_{ik}, \qquad \sigma_k = \sqrt{\frac{1}{n}\sum_{i=1}^{n} (x_{ik} - \mu_k)^2}, \qquad z_{ik} = \frac{x_{ik} - \mu_k}{\sigma_k}$$

표준편차는 $n-1$ 이 아니라 $n$ 으로 나눴습니다. 코드의 `statistics.pstdev` 가 그렇고, scikit-learn 의 `StandardScaler` 도 같은 쪽입니다. 표본이 2,000명이면 두 방식의 차이는 0.03% 가 안 됩니다.

표본에서 아무도 안 한 행동은 $\sigma_k = 0$ 이라 나눌 수 없습니다. `StandardScaler` 는 그때 나누는 값을 1 로 두고, 이 글의 표본은 8종 모두 한 사람 이상이 해서 그런 일이 없습니다.

드문 행동은 $\sigma_k$ 가 작아서 한 사람의 $z$ 가 크게 튀는데, 회원 A 의 러닝화 검색이 8.65 인 것이 그 예입니다. 실무에서는 가중합에 $\log(1 + x)$ 를 먼저 씌우거나 $z$ 에 상한을 두기도 합니다. 이 글은 식을 짧게 두려고 둘 다 하지 않았습니다.

$\mu_k$ 와 $\sigma_k$ 는 학습 표본에서 한 번 세어 모델과 같이 적어 둡니다. 서빙 때 그날 회원들로 다시 세면 같은 회원이 학습 때와 다른 $z$ 를 받습니다. 모델은 학습 때의 $z$ 에 맞춰져 있어서, 그때부터 오류 없이 조용히 틀립니다.
:::
