## 1. 왜 고치나

사용자가 읽고 내린 진단은 "ML 글보다 어렵다 · 내용이 안 이어진다 · 독자가 궁금한 걸 못 찾는다"입니다. 실제로 세어 보니 원인이 넷 있었고, 넷 다 사람 취향이 아니라 구조 문제였습니다.

| 문제 | 지금 상태 | 근거 |
|---|---|---|
| 주인공이 셋 | 지훈(API 3편) · 장바구니 손님(1편) · `r-8f21` 광고 클릭(4편) | `grep 지훈` 3편, `pipeline-push-and-pull.md` 1행, `kafka-log-pipeline.md` 1행 |
| 같은 말이 다른 뜻 | `api-basics` 8절 "두 로그"=접속/이벤트, **9절 "두 로그"=부르는 쪽/받는 쪽** | 8절 368행, 9절 423행 |
| 분량 | 8편 평균 47.3KB. 저장소가 스스로 정한 기준자는 27.0KB | `MARKDOWN_GUIDE.md` 95~103행 실측표 |

`MARKDOWN_GUIDE.md` 의 자체 실측이 이미 같은 결론을 냈습니다 — 어려운 글은 **문장이 더 짧고(33자 대 48자)**, **숫자 밀도가 1.7배**이고, **"그래서 무슨 결정이 바뀌나"가 3~30배 부족**했습니다. 약어 수는 기준자와 차이가 없었습니다. 즉 어려움의 원인은 용어가 아니라 **맥락 없이 던져진 숫자**입니다.

## 2. 확정된 결정 넷 (2026-08-16 사용자)

1. **범위** — Kafka·파이프라인 5편 + API 2편 + 게이트웨이 1편 = **8편**
2. **구조** — 글 8편을 그대로 두고 **제자리에서 다시 씀**. 읽는 순서만 새로 짬. URL·검색색인·기존 링크 보존
3. **예시** — **지훈 한 사람이 순서대로 겪는 이야기**로 8편을 관통
4. **덜어내기** — 실무 대화에 필요한 것만 남김. 멱등성·지터·Avro 바이트·서비스 메시 등은 빼거나 한 문단

## 5. 8편 공통 규칙

### 5.1 존댓말

- `~합니다` / `~입니다` / `~합니다만` 로 통일. `~하죠` · `~네요` 는 안 씁니다.
- 굵은 요약 한 줄, 표 캡션, figcaption, SVG 라벨까지 전부 존댓말. **표 안의 짧은 라벨은 명사구 그대로** 둡니다.
- 문장이 자연히 길어집니다. 목표 평균 **44~56자**(`MARKDOWN_GUIDE.md` 표준 7). 지금 이 8편은 33자라 오히려 사실 나열로 읽힙니다.

### 5.2 파이썬 19블록 → 무엇으로 바꾸나

빼기만 하면 근거가 사라집니다. 블록마다 아래 넷 중 하나로 **대체**합니다.

| 그 파이썬이 하던 일 | 대체 |
|---|---|
| 표 하나를 계산해 출력 | **마크다운 표** + 바로 위에 "가정 한 줄 · 계산식 한 줄" |
| 한 줄 공식을 보임 | 본문에 그대로 — "partition 최소치 = 초당 들어오는 줄 ÷ 한 명의 초당 처리량 = 2,639 ÷ 800 → 4개" |
| 절차를 단계별로 보임 | **SVG 그림 하나** 또는 before/after 두 블록 |
| 실제 산출물을 만들어 보임 | **그 산출물을 그냥 붙임** |

**마지막 칸이 이번 개편의 핵심입니다.** 사용자가 원하는 "실제 예시·실제 데이터값"이 바로 이것입니다. 파이썬을 빼는 대신 **아래 것들은 늘립니다**:

- nginx 액세스 로그 한 줄 (실제 포맷 그대로)
- HTTP 요청 원문 / 응답 원문 (헤더 포함)
- 이벤트 JSON 한 건 (변환 전 · 변환 후)
- `logstash.conf` · Ingress yaml · Kafka 설정값
- 로그가 안 맞을 때 양쪽 줄을 나란히

즉 **코드 블록 수는 줄지 않고, 파이썬이 실물로 바뀝니다.**

### 5.3 그림 규칙

`MARKDOWN_GUIDE.md` 124행 — **표가 있으면 같은 걸 그리는 SVG는 뺍니다.** 실측에서 본문 SVG 19개 중 9개가 옆 표를 다시 그린 것이었습니다. 새로 그리는 그림은 **표로 못 그리는 것**만입니다:

- 자리와 자리 사이의 **방향**(밀기 ↔ 가지러 가기)
- 한 요청이 **갈라져 두 줄이 되는** 지점
- 부품이 **하나씩 늘어나는** 과정(로드밸런서 → Ingress → Gateway)

### 5.4 절 리듬

한 절 = 굵은 요약 1줄 + 문단 4~6개 + (표 1개 **또는** 코드 1개). 둘 다 필요하면 절을 쪼갭니다. 절 끝 두 문장은 **결정 하나 + 다음 절로 넘기는 다리 하나**입니다.

### 6.1 `api-basics` (46KB → 약 28KB)

**사용자가 직접 지적한 곳이 여기입니다.** 8절과 9절이 둘 다 "두 로그"라고 부르는데 짝이 서로 다릅니다.

| 절 | 지금 | 바꿈 |
|---|---|---|
| 8 | "그 로그는 누가 남기나" — 두 로그 = 접속/이벤트 | **"로그가 남는 두 자리 — 서버가 저절로 남기는 줄, 앱이 보내야 남는 줄"**. 같은 클릭 한 건의 **실제 두 줄을 나란히** 붙임 |

### 6.4 `pipeline-push-and-pull` (21KB → 약 26KB)

지훈 셋째 주. **이 글은 8편 중 글쓰기가 가장 잘된 글이라 형식은 그대로 두고 이야기만 광고 클릭으로 바꿉니다.** 다른 7편의 문체 본보기로 삼습니다.

- 절 9개 · "밀기/가지러 가기" 뼈대 · 단계 위젯 유지
- 장바구니(`cart_add` · `SKU-4417` · 재고 · 창고) → 클릭(`click` · 광고 번호 · 정산 · 광고주 리포트)
- 소비자 넷: 대시보드 2초 · 정산 · 광고주 리포트 5분 · 학습 다음 날 03:00
- 파이썬 1블록(보존 기간) → 표 2개
- **딸린 데모도 같이 고칩니다** (8절)

### 6.5 `log-hops-to-kafka` (89KB → 약 30KB) — 가장 크게 줄어듦

같은 클릭 한 건이 **자리마다 어떻게 생겼나**만 봅니다. Kafka 안쪽은 다음 글로 넘깁니다.

| 절 | 처리 |
|---|---|
| 1 앱 SDK | 유지 |
| 2 HTTP 전송 | 유지 |
| 3 수집 서버 — 타입 없는 텍스트 한 줄 | 유지. `'204'`도 `'0.002'`도 글자라는 것이 이 글의 핵심 |
| 4 파일이냐 직행이냐 (61.7시간 대 10.4분) | 유지. 파이썬 → 표 2개 |
| 5 수집 에이전트 (Filebeat) | 유지 |
| 6 변환기 다섯 단계 (169B/8필드 → 308B/17필드) | 유지. 파이썬 → **단계별 before/after 블록** |
| **7 Kafka 안 바이트 (Avro · zigzag varint · 스키마 레지스트리)** | **뺍니다.** "압축해서 배치로 묶이면 훨씬 작아집니다" 한 문단 |
| **8 읽는 쪽 (`poll()` 객체 · 조인)** | **`kafka-log-pipeline` 6절로 옮깁니다** |
| 9 한 표로 + 지뢰 다섯 | 7·8절로. 유지 |

8절을 옮기면 이 글이 "Kafka 문 앞에서 끝나고" 다음 글이 "문 안에서 시작"합니다. 지금 이 글이 `kafka-log-pipeline` 을 10번 참조하는 앞뒤 뒤엉킴이 여기서 풀립니다.

### 6.6 `kafka-log-pipeline` (77KB → 약 30KB)

| 절 | 처리 |
|---|---|
| 1 Kafka 없이 하면 (방법 셋) | ①(직접 부르기)만 자세히. ②③은 표 한 줄씩 |
| **2 producer · `acks` · `min.insync.replicas`** | 3절 안 **한 문단**으로. "보내고 안 기다립니다. 몇 대가 받아야 성공으로 칠지를 정합니다" |
| 3 topic · partition | 2절로. 유지. **partition 재배치 해시 계산(50% 이동)은 결론 한 줄만** |
| 4 consumer group | 3절로. 유지 — 네 팀이 같은 줄을 각자 읽는 그림이 이 글의 심장 |
| 5 offset (commit 전/후 · at-most/at-least-once) | 4절로. **표 2줄 + 문단 하나.** 영어 이름은 괄호 안에만 |
| 6 보존 기간 | 5절로. 디스크 표는 남기고 **브로커 대당 % 계산은 뺌** |
| 7 학습 데이터 만들기 | 6절로. `log-hops` 8절(읽는 쪽)을 여기 흡수 |
| 8 지뢰 다섯 | 7절로. 유지 |

파이썬 4블록 → 표 5개.

### 6.7 `data-pipeline-design` (35KB → 약 28KB)

지훈이 올린 티켓("이 로그를 운영자 검색 창에도")에서 시작합니다. 절 6개 구성은 좋으니 유지합니다.

- 1절 파이썬(마감에서 거꾸로 예산 계산) → **표 1개**. "마감 2초 − Kafka까지 1,112 ms = 남는 예산 888 ms" 는 본문 한 줄
- 4절 파이썬(스트림 2,202,480 대 배치 2,273,160) → 표 2개. **이 대비는 이 글의 핵심이라 숫자를 그대로 살림**
- 5절 스키마 레지스트리 호환 설정 → **"필드를 지운 배포가 사흘 뒤 학습을 나빠지게 한 경로"** 사례만. 백필은 한 문단

### 6.8 `data-distribution-layer` (19KB → 약 24KB)

- 파이썬 1블록(연결 30 → 11) → 표 2개

## 7. 읽는 순서 바꾸기

`js/posts.js` 의 `engineering-foundations.posts` 배열을 이렇게 바꿉니다.

```
지금: git, arch, k8s, gateway, api-basics, api-kinds, push-pull, kafka, log-hops, design, distribution
새로: git, arch, k8s, api-basics, api-kinds, gateway, push-pull, log-hops, kafka, design, distribution
```

두 군데가 움직입니다.

트랙 설명(`desc`)도 새 순서에 맞춰 다시 씁니다.

## 10. 진행 순서

**`api-basics` 한 편을 먼저 끝내고 확인받은 뒤** 나머지 7편을 갑니다. 존댓말 리듬·파이썬 대체 형태·절 길이를 한 편에서 맞춰 놓고 복제하는 편이, 8편을 다 쓰고 나서 되돌리는 것보다 쌉니다.

| 차수 | 글 | 왜 이 순서 |
|---|---|---|
| 1 | `api-basics` | 사용자가 직접 지적한 8·9절이 여기 있음. 본보기 |
| 2 | `api-kinds-and-contracts`, `gateway-ingress-router` | 지훈 아크 앞부분 |
| 3 | `pipeline-push-and-pull` + 데모 | 7~9편 표준 데이터를 여기서 확정 |
| 4 | `log-hops-to-kafka`, `kafka-log-pipeline` | 절 이동이 걸려 있어 같이 |
| 5 | `data-pipeline-design`, `data-distribution-layer` | 마무리 |
| 6 | `js/posts.js` 순서·제목·excerpt, 가이드, 검색색인 | 전체 반영 |

커밋은 차수마다 하나씩, `chkimsu` 계정으로. push 전 `git fetch` + `merge` (CI가 sitemap·feed를 되커밋합니다).
