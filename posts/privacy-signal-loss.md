지훈은 어제 아침 이 캠페인의 소재 하나를 껐다. 웹 지면 리포트에는 전환 3,120건이 줄마다 사람에 붙어 있어, 어느 소재가 밑지는지 한눈에 보였다. 같은 리포트의 iOS 앱 지면 칸은 940건인데 그 줄에는 사람이 없다. 415건은 산 금액까지 비었고, 나머지도 어제가 아니라 나흘 전 설치분이다.

**같은 캠페인 같은 하루인데, 왜 한쪽 칸에서만 사람이 지워져 있나?**

브라우저와 스마트폰이 사람을 이어 주던 번호를 걷어 갔기 때문이다. 그 번호가 빠져 광고 모델의 재료가 줄어드는 일이 **신호 소실**이다. 지훈이 오늘 결정할 것은 하루 예산을 ₩8,000,000에서 ₩12,000,000으로 올릴지다. 웹 칸은 올리라 하고 앱 칸은 아무 말이 없다.

> **한 줄 요약:** 식별자가 빠지면 피처보다 라벨이 먼저 부서진다. 사람마다 붙던 정답이 칸마다의 합계로 바뀐다. 학습은 되지만 같은 정밀도까지 데이터가 11배 든다. 노이즈는 예산이 작은 광고부터 지운다.

절 제목 뒤 대괄호는 무대 표시다. **열린 RTB**는 남의 거래소에 입찰만 넣는 자리, **닫힌 생태계**는 우리가 경매를 직접 돌리는 자리, **공통**은 둘 다다. 숫자는 지어냈고 파이썬 출력만 돌려 붙였다.

## 1. 무엇이 사라졌고 그 자리에 무엇이 왔나 [무대: 공통]

**사라진 것은 "이 사람이 아까 그 사람"이라고 말해 주던 번호 하나다. 그 자리에 온 것은 번호가 아니라 API 다.**

광고 모델이 기대던 번호는 셋이었다. 웹의 서드파티 쿠키, iOS 의 광고 식별자(IDFA), 안드로이드의 광고 ID 다. 셋 다 사이트와 앱을 건너다녀도 같은 사람을 묶어 주던 값이다.

| 신호 | 어디 | 지금 상태 | 그 자리에 온 것 |
|---|---|---|---|
| 서드파티 쿠키 | 웹 (Safari·Firefox) | 기본으로 차단된다 | Topics · Protected Audience 같은 API |
| 서드파티 쿠키 | 웹 (Chrome) | 폐지 시점이 여러 번 미뤄졌다 | 위와 같음. API 별로 존폐가 갈렸다 |
| 광고 식별자 (IDFA) | iOS 앱 | 동의를 받아야 읽는다 | SKAdNetwork, 그 뒤 AdAttributionKit |
| 광고 ID | 안드로이드 앱 | 초기화·삭제할 수 있다 | Privacy Sandbox on Android |
| 로그인 ID | 자사 서비스 | 그대로 남아 있다 | 대체물이 필요 없다 |
| 광고주 1st-party ID | 광고주 서버 | 그대로 남아 있다 | 서버끼리 직접 잇는다 |

표의 이름 셋은 성격이 다르다. **앱 추적 동의(ATT)** 는 식별자를 읽기 전에 사용자에게 물으라는 규칙이다. **SKAdNetwork** 는 규칙이 아니라 대체 경로라, 동의를 못 받아도 설치 성과는 재 준다. 줄여서 **SKAN** 이라 쓴다.

**Privacy Sandbox** 는 브라우저 안에서 같은 일을 하려는 API 묶음이다. 사용자에게 직접 받은 값은 **1st-party**, 비용을 치르고 사 오던 값은 **3rd-party** 다. 사라지는 것은 뒤쪽뿐이다.

광고주 계약서에 "3rd-party 세그먼트로 타겟팅"이라 적혀 있다면 그 줄부터 다시 써야 한다. 무엇을 얼마나 잃었는지 모르면 예산을 옮길 곳도, 중단할 캠페인도, 새는 비용도 못 찾는다.

## 2. 피해는 세 곳에 나뉘어 온다 — 그리고 첫 층부터 재 본다 [무대: 공통]

**번호 하나가 빠지면 세 군데가 동시에 상한다. 모델에 들어가는 것, 모델이 배우는 것, 모델이 내보낸 뒤의 제어다.**

"신호가 사라졌다"는 말만으로는 어디에 비용을 쓸지 알 수 없다. 잃는 것이 한 종류가 아니어서 피해를 세 층으로 갈라 부른다. 1층은 타겟팅 피처, 2층은 전환 라벨, 3층은 내보낸 뒤에 거는 빈도 제어다.

| 층 | 무엇을 잃나 | 모델의 어디가 상하나 | 메울 수 있나 |
|---|---|---|---|
| 1층 타겟팅 피처 | 사이트·앱을 건너다닌 행동 | 모델에 들어가는 값이 줄어든다 | 문맥 신호로 일부 메운다 |
| 2층 전환 라벨 | 전환이 누구 것인지 | 정답이 들어가던 칸의 모양이 바뀐다 | 학습 방법을 바꿔야 한다 |
| 3층 빈도 제어 | 같은 사람인지 판정 | 모델 밖의 규칙이 안 돈다 | 거의 못 메운다 |

먼저 아픈 것은 1층이 아니라 2층이다. 피처가 빠지면 성능이 조금 내려가지만, 라벨의 모양이 바뀌면 학습 코드가 아예 안 돈다.

### 1층 — 피처가 빠지면 순위 점수가 얼마나 내려가나

재는 값은 **AUC** 다. 순위 능력을 숫자 하나로 나타낸 값이고, 0.5 는 아무 정보가 없는 상태다. 클릭 확률 모델(pCTR)을 두 무대에서 따로 학습해 피처군을 하나씩 빼며 쟀다.

| 뺀 피처군 | 열린 RTB AUC | 변화 | 담장 안 AUC | 변화 |
|---|---|---|---|---|
| (안 뺀 상태) | 0.762 | — | 0.771 | — |
| 3rd-party 관심사 세그먼트 | 0.741 | -0.021 | 0.767 | -0.004 |
| 사이트를 건너다닌 리타겟 목록 | 0.722 | -0.019 | 0.764 | -0.003 |
| 앱을 건너다닌 최근 행동 | 0.706 | -0.016 | 0.761 | -0.003 |
| 식별자로 세던 노출 횟수 | 0.694 | -0.012 | 0.759 | -0.002 |
| **넷을 다 뺐을 때** | **0.694** | **-0.068** | **0.759** | **-0.012** |

낙폭이 다른 이유는 빼고 남는 것에 있다. 열린 RTB 의 유저 신호는 대부분 비용을 치르고 사 온 것이라, 끊기면 문맥만 남는다. 담장 안은 로그인 ID 에 붙은 자사 행동이 그대로다.

오해 하나는 끊어 둔다. AUC 가 0.068 내려간 것은 큰 손실이지만 매출이 그만큼 준다는 뜻은 아니다. 경쟁자도 같은 신호를 같이 잃는다. 매출 영향은 [증분 실험](post.html?id=rct-randomized-experiment)으로만 잰다.

1층에서 내릴 결정은 문맥 피처에 사람을 몇 명 붙일지 하나다. 담장 안이라면 비용을 크게 쓸 이유가 없고, 열린 RTB 라면 몇 달짜리 예산이 붙는다.

## 3. 전환이 사람 단위에서 칸 단위로 바뀐다 [무대: 공통]

여기서 학습 파이프라인이 처음 걸린다. 같은 설치 한 건이 최대 세 번 도착하니, 포스트백을 그대로 세면 매출 성과가 부푼다. 그 숫자로 예산을 올리면 돈은 손해다. 늦은 라벨은 [지연 피드백](post.html?id=online-learning-delayed-feedback)에서 다뤘다.

**얼마나 자세히 오느냐는 규모에 달렸다.** 애플은 설치가 적은 조합에 값을 덜 준다. 같은 값을 받은 사람이 많아야 개인이 숨는다는 논리이고, 이것을 **군중 익명성**이라 부른다.

| 조합의 하루 전환 | 조합 수 | 전환 합 | 받는 값 |
|---|---|---|---|
| 0~9건 | 217개 | 415건 | 값 없음 |
| 10~29건 | 18개 | 270건 | 세 단계 값 |
| 30~99건 | 4개 | 155건 | 세 단계 값 |
| 100건 이상 | 1개 | 100건 | 세밀한 값 64칸 |
| **합계** | **240개** | **940건** | |

첫 줄이 도입부의 그 415건이고, 전환의 44% 가 얼마짜리인지 모르는 채로 온다. 값이 오는 조합은 아래 세 줄뿐이다. **규모가 작으면 해상도가 낮아진다.**

그래서 소재를 240개로 늘리는 결정은 대부분을 값 없이 굴리겠다는 결정이다. 예산을 아래 세 줄에 몰아 규모를 키우거나, 값이 안 오는 조합은 중단하는 편이 낫다.

## 4. 칸 64개에 무엇을 넣을까 [무대: 공통]

**64칸이 모자란 것이 아니다. 칸을 어디에 두느냐가 총매출 추정을 -2.5% 와 -0.1% 로 갈랐다.**

세밀한 전환값은 **6비트**여서 0부터 63까지 칸이 64개다. 무엇을 담을지는 광고주가 정한다. 설치 여부만 담으면 한 칸으로 끝나고, 설치 후 매출을 담으면 64칸이 빠듯하다.

이 선택이 곧 라벨의 해상도이고 전환 확률 모델(pCVR)이 그 라벨로 배운다. 5,000원 간격으로 자르는 선형 방식과, 금액이 커질수록 간격이 넓어지는 로그 방식을 대 본다.

```python
# 구매 금액을 64칸(6비트)에 접으면 얼마가 남고 얼마가 뭉개지나.
import random, math, statistics

random.seed(3)
N = 200000
MU, SIGMA = math.log(28000), 1.0          # 중앙값 28,000원짜리 구매 분포

amounts = [random.lognormvariate(MU, SIGMA) for _ in range(N)]

def linear(a):
    """5,000원 간격 64칸. 315,000원 이상은 전부 63번 칸."""
    b = min(int(a // 5000), 63)
    return b, b * 5000 + 2500

LO, HI = 1000.0, 1000000.0
STEP = (math.log(HI) - math.log(LO)) / 64

def logscale(a):
    """1,000원~1,000,000원을 로그 간격 64칸으로. 복원값은 칸의 기하 중앙."""
    b = min(max(int((math.log(max(a, LO)) - math.log(LO)) / STEP), 0), 63)
    return b, math.exp(math.log(LO) + (b + 0.5) * STEP)

true_sum = sum(amounts)
cut = sorted(amounts)[int(N * 0.99)]        # 상위 1% 경계
print(f"구매 {N:,}건 · 실제 총매출 {true_sum/1e8:.2f}억원 · "
      f"평균 {true_sum/N:,.0f}원 · 상위 1% 경계 {cut:,.0f}원")

for name, f in (("선형 5천원", linear), ("로그 간격", logscale)):
    est = [f(a)[1] for a in amounts]
    rel = [abs(e - a) / a for e, a in zip(est, amounts)]
    top = [(e, a) for e, a in zip(est, amounts) if a >= cut]
    full = sum(1 for a in amounts if f(a)[0] == 63)
    print(f"{name}: 총매출 {sum(est)/1e8:>5.2f}억원 "
          f"({(sum(est)/true_sum-1)*100:+5.1f}%) · 건당 오차 중앙값 "
          f"{statistics.median(rel)*100:>4.1f}% · 상위 1% 매출 "
          f"{(sum(e for e, _ in top)/sum(a for _, a in top)-1)*100:+6.1f}% · "
          f"마지막 칸 {full/N*100:.2f}%")

# 비교: 전환 여부 1비트만 받는 경우 — 금액은 학습 시점에 하나로 가정할 수밖에 없다
flat = true_sum / N
print(f"1비트(전환 여부)만: 건당 오차 중앙값 "
      f"{statistics.median([abs(flat - a) / a for a in amounts])*100:.1f}%")

# 출력:
# 구매 200,000건 · 실제 총매출 92.29억원 · 평균 46,145원 · 상위 1% 경계 284,231원
# 선형 5천원: 총매출 90.01억원 ( -2.5%) · 건당 오차 중앙값  3.8% · 상위 1% 매출  -26.5% · 마지막 칸 0.77%
# 로그 간격: 총매출 92.18억원 ( -0.1%) · 건당 오차 중앙값  2.7% · 상위 1% 매출   -1.8% · 마지막 칸 0.03%
# 1비트(전환 여부)만: 건당 오차 중앙값 76.4%
```

같은 64칸인데 결과가 갈렸고 범인은 마지막 칸이다. 선형 방식에서는 315,000원이 넘는 구매가 전부 63번 칸에 들어가, 백만원짜리 매출도 317,500원으로 되돌아온다.

마지막 칸에 들어간 구매는 0.77% 뿐인데, 상위 1% 구매가 매출의 9.2% 를 진다. 그 몫을 26.5% 깎으면 총매출도 따라 내려간다. **큰 구매 몇 건이 매출을 지면 상한선의 위치가 곧 리포트의 정확도다.**

전환 여부만 1비트로 받으면 건당 오차 중앙값이 76.4% 까지 벌어진다. 무엇을 전환으로 셀지는 [전환 정의](post.html?id=conversion-definition)에서 다뤘다.

칸 배치를 고치는 일은 코드 한 줄이고 광고주 승인도 필요 없다. 반면 매출 리포트가 2.5% 틀린 채 몇 달이 흐르면 그만큼의 예산이 엉뚱한 캠페인으로 간다. 비용 없이 효과가 확실한 자리다.

## 5. 칸 합계만 있을 때 어떻게 배우나 [무대: 공통]

**칸 합계로도 계수는 제자리를 찾는다. 다만 흔들림이 3.3배라 같은 정밀도까지 데이터가 11배 필요하다.**

라벨이 칸 합계로 와도 학습은 된다. 줄마다의 정답 대신 **칸마다의 합계**를 맞히게 하면 되고, 손실 함수만 바꾸는 일이다. 이것이 **칸 합계로 배우기**(learning from label proportions)다.

핵심은 **칸마다 피처 구성비가 달라야 계수가 되살아난다**는 점이다. 칸 하나가 주는 것은 "노출 500건에 전환 12건"이라는 등식 하나뿐이다. 그 칸의 리타겟 비율과 지면 비율은 우리 로그에 있지만, 알아내야 할 값은 셋이다.

등식 하나에 미지수가 셋이면 답이 없다. 칸을 백 개 모아도 구성비가 같으면 같은 등식을 백 번 적는 셈이다. 구성비가 다르면 다른 등식이 생기고, 등식이 미지수보다 많아지면 계수가 한 점으로 좁혀진다.

아래 실험은 같은 데이터를 두 방식으로 학습해 흔들림을 잰다. 참값은 절편 -3.0 과 계수 1.2, 0.8 이고, 칸 40개에 500줄씩 넣어 30번 반복한다.

```python
# 집계 라벨(캠페인 합계)만으로 배운 계수는 개인 라벨로 배운 계수보다 얼마나 흔들리나.
import random, math, statistics

random.seed(7)
TRUE = (-3.0, 1.2, 0.8)          # 절편, x1(리타겟 여부), x2(고관여 지면)
CELLS = [(0, 0), (0, 1), (1, 0), (1, 1)]

def sigmoid(z):
    return 1.0 / (1.0 + math.exp(-z))

def make_bags(n_bags=40, per_bag=500):
    """칸 하나 = 캠페인 하루치. 칸마다 피처 구성비가 다르다."""
    bags = []
    for _ in range(n_bags):
        r1, r2 = random.uniform(0.1, 0.9), random.uniform(0.1, 0.9)
        cnt = {c: 0 for c in CELLS}
        pos = {c: 0 for c in CELLS}
        for _ in range(per_bag):
            x1 = 1 if random.random() < r1 else 0
            x2 = 1 if random.random() < r2 else 0
            p = sigmoid(TRUE[0] + TRUE[1] * x1 + TRUE[2] * x2)
            cnt[(x1, x2)] += 1
            pos[(x1, x2)] += 1 if random.random() < p else 0
        bags.append((cnt, pos))
    return bags

def fit_individual(bags, steps=800, lr=4.0):
    """개인 라벨: 줄마다 y가 있다. 표준 로지스틱 회귀."""
    w = [0.0, 0.0, 0.0]
    n = sum(sum(c.values()) for c, _ in bags)
    for _ in range(steps):
        g = [0.0, 0.0, 0.0]
        for cnt, pos in bags:
            for (x1, x2) in CELLS:
                p = sigmoid(w[0] + w[1] * x1 + w[2] * x2)
                e = p * cnt[(x1, x2)] - pos[(x1, x2)]
                g[0] += e; g[1] += e * x1; g[2] += e * x2
        for j in range(3):
            w[j] -= lr * g[j] / n
    return w

def fit_aggregate(bags, steps=8000, lr=4.0):
    """집계 라벨: 칸마다 전환 '합계'만 있다. 합계를 맞추도록 민다."""
    w = [0.0, 0.0, 0.0]
    nb = len(bags)
    for _ in range(steps):
        g = [0.0, 0.0, 0.0]
        for cnt, pos in bags:
            m = sum(cnt.values())
            s = sum(sigmoid(w[0] + w[1] * x1 + w[2] * x2) * cnt[(x1, x2)]
                    for (x1, x2) in CELLS)
            d = (s - sum(pos.values())) / m          # 칸 하나의 오차(비율)
            for (x1, x2) in CELLS:
                p = sigmoid(w[0] + w[1] * x1 + w[2] * x2)
                q = d * p * (1 - p) * cnt[(x1, x2)] / m
                g[0] += q; g[1] += q * x1; g[2] += q * x2
        for j in range(3):
            w[j] -= lr * g[j] / nb
    return w

ind, agg = [], []
for _ in range(30):                                  # 같은 실험을 30번
    bags = make_bags()
    ind.append(fit_individual(bags))
    agg.append(fit_aggregate(bags))

for name, res in (("개인 라벨", ind), ("집계 라벨", agg)):
    for j, label in enumerate(("절편", "x1", "x2")):
        col = [r[j] for r in res]
        print(f"{name} {label}: 평균 {statistics.mean(col):+.3f} "
              f"(참값 {TRUE[j]:+.1f}) · 표준편차 {statistics.pstdev(col):.3f}")

r = [statistics.pstdev([a[j] for a in agg]) / statistics.pstdev([i[j] for i in ind])
     for j in range(3)]
print("표준편차 배수(집계÷개인):", " ".join(f"{x:.1f}배" for x in r))
print("같은 흔들림까지 줄이려면 데이터가:", " ".join(f"{x*x:.0f}배" for x in r))

# 출력:
# 개인 라벨 절편: 평균 -2.999 (참값 -3.0) · 표준편차 0.036
# 개인 라벨 x1: 평균 +1.210 (참값 +1.2) · 표준편차 0.040
# 개인 라벨 x2: 평균 +0.795 (참값 +0.8) · 표준편차 0.045
# 집계 라벨 절편: 평균 -3.015 (참값 -3.0) · 표준편차 0.120
# 집계 라벨 x1: 평균 +1.219 (참값 +1.2) · 표준편차 0.132
# 집계 라벨 x2: 평균 +0.808 (참값 +0.8) · 표준편차 0.117
# 표준편차 배수(집계÷개인): 3.3배 3.3배 2.6배
# 같은 흔들림까지 줄이려면 데이터가: 11배 11배 7배
```

읽을 것은 두 줄이다. 칸 합계로 배운 계수의 평균도 참값과 맞아 x1 은 1.219 이고 참값은 1.2 다. **칸 합계는 계수를 비틀지 않는다.** 다만 표준편차가 0.040 에서 0.132 로 커졌다.

그 3.3배가 왜 11배가 되나. 흔들림은 데이터 양의 제곱근에 반비례해서, 네 배를 모으면 절반이 되고 아홉 배면 3분의 1로 준다.

거꾸로 흔들림을 되돌리려면 데이터가 3.3을 제곱한 만큼 필요하고, 그것이 출력의 11배다. 하루치를 11일치 모아야 하는데, 11일이면 소재도 예산도 이미 바뀐다.

:::deep 더 깊이 — 칸 합계 손실의 식
칸 $b$ 안의 노출을 $i \in b$, 관측된 전환 합계를 $K_b$ 라 하자. 칸 손실은 예측 $\sigma(w^\top x_i)$ 의 합과 관측 합의 차이를 제곱한 것이다.

$$\mathcal{L}(w) = \sum_{b} \Big( \sum_{i \in b} \sigma(w^\top x_i) - K_b \Big)^2$$

로그 손실은 줄마다 항이 하나이고 칸 손실은 칸마다 항이 하나라, 위 코드에서 항이 2만 개에서 40개로 줄었다.
:::

그래서 실무의 결정은 SKAN 라벨로 모델을 학습하는 것이 아니다. 개인 라벨로 본체를 학습하고 칸 합계는 캠페인 단위 보정에만 쓴다. 어느 캠페인의 예산을 줄이고 어느 것을 중단할지도 그 숫자로 정한다.

## 6. 노이즈는 예산이 작은 광고부터 지운다 [무대: 공통]

**노이즈는 칸 크기와 상관없이 같은 양이 붙는다. 그래서 전환 40건짜리는 상대 오차 70.7%, 4,000건짜리는 0.7% 다.**

개인을 숨기는 두 번째 장치가 노이즈다. 칸마다 무작위 값을 더해 내보내고, 이것을 **차등 프라이버시 노이즈**라 부른다. '차등'은 두 리포트의 차이에서 온 이름이다.

어떤 사람이 들어간 리포트와 빠진 리포트의 차이를 노이즈가 덮으면, 그 사람이 있었는지 알 수 없다. 얼마나 덮을지 정하는 값이 **프라이버시 예산**이고, 조이면 리포트가 흐려진다.

여기서는 평균 절대 오차 20건, 표준편차 28.3건짜리 노이즈가 붙고, 그 값이 50 미만이면 칸을 지운다고 두었다.

| 하루 참 전환 | 평균 오차 | 상대 표준편차 | 칸이 지워지는 날 | 이레치를 합치면 |
|---|---|---|---|---|
| 10건 | 200.3% | 282.8% | 93.6% | 106.9% |
| 40건 | 50.1% | 70.7% | 69.5% | 26.6% |
| 120건 | 16.6% | 23.6% | 1.6% | 8.9% |
| 400건 | 5.1% | 7.1% | 0.0% | 2.7% |
| 4,000건 | 0.5% | 0.7% | 0.0% | 0.3% |

셋째 열이 규모의 벽이다. 예산이 작아 전환이 40건인 광고의 리포트는 실제 값의 절반에서 갑절 사이로 오고, 4,000건짜리는 소수점 아래에서만 흔들린다.

넷째 열이 두 번째 문제다. 40건짜리 칸은 열흘에 이레꼴로 지워져 온다. **빈칸을 0 으로 채우면 안 된다.** 0 으로 넣으면 전환율이 낮게 잡혀 멀쩡한 소재를 중단하는 결정이 나온다.

다섯째 열이 대응책이다. 이레치를 합치면 신호는 일곱 배가 되고 노이즈는 제곱근 배만 커지지만, 어제 소재의 매출을 일주일 뒤에 알게 된다.

제일 아픈 것은 두 칸을 견줄 때다. 차이에 붙는 표준편차가 40.0건이라, 전환 40건 규모의 5% 차이는 두 건뿐이라 묻힌다. 4,000건 규모면 같은 차이가 노이즈의 다섯 배다.

**작은 캠페인은 최적화가 느려지는 것이 아니라 멈춘다.** 결정은 둘이다. 칸을 합치고 예산을 몰아 규모를 키우거나, 성과 판정을 [실험](post.html?id=model-ab-testing)으로 넘기거나다.

## 7. 빈도 상한과 중복 제거는 아예 못 돈다 [무대: 공통]

**같은 사람인지 모르면 노출의 47.6% 가 이미 다섯 번 넘게 본 사람에게 간다.**

3층은 모델 밖의 규칙이다. 빈도 상한은 하루 다섯 번까지만 보여 주고, 중복 제거는 같은 구매를 두 번 세지 않으며, 제외 목록은 이미 산 사람을 뺀다. 셋 다 "아까 그 사람인가"를 판정해야 돈다.

이 캠페인의 iOS 앱 지면 노출을 사람별로 세어 봤다고 하자. 순 사용자는 60만 명이고 한 사람이 하루 평균 일곱 번 본다.

| 하루 노출 횟수 | 사용자 수 | 노출 합 | 상한 다섯 번을 걸면 |
|---|---|---|---|
| 1~2회 | 180,000명 | 270,000 | 270,000 |
| 3~5회 | 168,000명 | 672,000 | 672,000 |
| 6~10회 | 132,000명 | 1,056,000 | 660,000 |
| 11~20회 | 90,000명 | 1,260,000 | 450,000 |
| 21~40회 | 24,000명 | 648,000 | 120,000 |
| 41회 이상 | 6,000명 | 294,000 | 30,000 |
| **합계** | **600,000명** | **4,200,000** | **2,202,000** |

마지막 두 열을 견주면 상한 다섯 번에 노출의 47.6% 가 잘린다. 식별자가 없으면 그 47.6% 를 그대로 내보낸다. 같은 돈으로 새 사람에게 갈 수 있었던 노출이니 곧 낭비된 예산이다.

표 아래쪽 두 줄이 더 아프다. 하루 스무 번 넘게 보는 3만 명이 노출의 22.4% 를 가져간다. 리포트에는 노출 수가 채워지지만 도달은 늘지 않아 그 비용이 그대로 샌다.

중복 제거도 무너진다. 접는 열쇠인 사용자 식별자와 주문번호가 SKAN 포스트백에는 둘 다 없다. 그래서 포스트백 두 건이 한 사람의 재구매인지 다른 두 사람인지 가릴 수 없다.

**3층은 대체 신호로 못 메운다.** 판정이 되거나 안 되거나 둘 중 하나다. 그래서 결정은 대체가 아니라 이동이고, 로그인 지면과 자사 앱처럼 판정이 되는 구간으로 예산을 옮긴다.

## 8. 담장 안의 사정과, 그래서 바꿀 것 [무대: 닫힌 생태계]

**담장 안이 덜 다치는 이유는 하나다. 쓰는 식별자가 남의 것이 아니라 우리 것이기 때문이다.**

로그인 ID 는 사용자가 우리 서비스에 직접 준 값이라 1st-party 다. 브라우저가 차단하지도 않고 동의 팝업의 대상도 아니라, 2절 표의 담장 안 열이 -0.012 에 그쳤다.

**하지만 전환 라벨은 다르다.** 전환의 상당수가 담장 밖에서 끝난다. 광고주 앱의 전환은 설치를 대신 재 주는 회사, 곧 측정 파트너(MMP)를 거쳐 온다.

| 전환이 끝나는 곳 | 건수 | 어떻게 알게 되나 | 신호 상태 |
|---|---|---|---|
| 자사 서비스 안 (앱 내 구매) | 1,950건 | 우리 로그에 그대로 남는다 | 온전하다 |
| 광고주 사이트 (픽셀 경유) | 780건 | 쿠키와 픽셀로 잇는다 | 좁아지는 중 |
| 광고주 앱 (측정 파트너 경유) | 270건 | 포스트백으로 온다 | 집계로 바뀐다 |
| 오프라인 매장 | 120건 | 광고주가 나중에 올린다 | 늦고 일부만 온다 |
| **합계** | **3,120건** | | |

첫 줄만 온전하고 나머지 세 줄은 열린 RTB 와 같은 문제를 겪는다. 우리 안에서 끝나는 전환이 62.5%, 담장 밖이 37.5% 다. 자사 완결 전환으로 매출을 내는 광고주만 멀쩡하다.

담장 안이 유리해지는 것도 남이 더 많이 잃기 때문이지, 우리 매출이 늘어서가 아니다. 이 구조는 [담장 안 생태계](post.html?id=walled-garden)에서 다뤘다.

### 그래서 바꿀 것 넷 [무대: 공통]

**문맥 피처를 잘게 판다.** 지면·시간·소재를 더 잘게 나눠 1층을 메운다. 비용은 싸지만 피처가 늘어 서빙 지연과 서버 비용이 는다.

**모델링 단위를 사람에서 요청으로 내린다.** "이 사람이 최근 30일에 본 카테고리" 자리에 "이 지면의 최근 한 시간 클릭률"을 넣는다. 개인화는 얕아져도 계속 돈다.

**1st-party 결합은 값이 가장 크고 느리다.** 광고주가 자기 서버에서 전환을 우리 서버로 직접 보내면 쿠키 정책과 무관해지지만, 계약과 보안 승인이 오래 걸린다.

**증분 실험이 마지막 안전망이다.** 광고를 안 보여 준 집단과 견줘 매출 차이를 잰다. 리포트는 못 믿게 되어도 [무작위 실험](post.html?id=causal-inference-101)은 식별자 없이 성립한다.

먼저 할 일은 대응이 아니라 계측이다. 어느 층이 얼마나 상했는지 모르면 엉뚱한 곳에 비용을 쓴다. 2절 AUC 표, 3절 조합 표, 6절 노이즈 표를 채우고 나면 지훈의 ₩12,000,000 결정도 근거를 갖는다.

## 한눈 정리

| 층 | 크기 (이 글의 지어낸 값) | 대응 | 회복 정도 |
|---|---|---|---|
| 1층 타겟팅 피처 | 열린 RTB AUC -0.068, 담장 안 -0.012 | 문맥 피처·1st-party | 부분 회복 |
| 2층 라벨 (해상도) | 같은 64칸으로 총매출 -2.5% 또는 -0.1% | 칸을 로그 간격으로 | 거의 회복 |
| 2층 라벨 (개인성) | 계수 흔들림 3.3배, 데이터 11배 필요 | 칸 합계로 배우기 | 데이터로 메움 |
| 2층 라벨 (노이즈) | 40건에서 상대 오차 70.7%, 지워지는 날 69.5% | 칸 합치기·기간 합산 | 시간과 맞바꿈 |
| 2층 라벨 (지연) | 창 1 도 사나흘, 창 3 은 최대 마흔하루 | 창별로 갈라 세기 | 못 회복 |
| 3층 빈도 제어 | 상한 다섯 번이면 노출의 47.6% 가 초과분 | 판정 되는 지면으로 예산 이동 | 거의 못 회복 |

## 헷갈리기 쉬운 점

- **노이즈는 치우침이 아니다.** 칸 합계로 배운 계수의 평균은 참값과 맞았다. 틀어지는 것은 흔들림이라 보정으로 못 되돌리고, 데이터를 더 모아야 줄어든다.
- **값이 비는 것과 칸이 지워지는 것은 다르다.** SKAN 은 포스트백을 보내되 전환값을 비우고, 집계 리포트는 칸 자체를 지운다.
- **빈칸을 0 으로 채우면 안 된다.** 전환율이 낮게 잡혀 멀쩡한 소재를 중단하는 결정이 나온다. 빈칸은 "모른다"로 다뤄야 한다.
- **포스트백 수는 설치 수가 아니다.** 창이 셋이라 같은 설치가 최대 세 번 오고, 창 구분 없이 세면 매출 성과가 부푼다.
- **"담장 안은 안전하다"는 층마다 갈린다.** 8절 표에서 자사 완결 전환만 온전하다.
