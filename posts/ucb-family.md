배너 소재 하나를 놓고 UCB1이 몇 주째 같은 답을 낸다. "이 소재가 제일 낫다."

담당자가 로그를 지면별로 나눠 보니 이상하다. 뉴스 지면 오전에는 그 소재가 확실히 1등이 맞다. 그런데 커뮤니티 지면 오전에는 다른 소재가 클릭을 훨씬 더 받고 있었다. 저녁 시간대로 나눠 보면 순위가 또 한 번 뒤집힌다.

UCB1은 이 차이를 볼 방법이 없다. 지금이 뉴스 지면인지 커뮤니티 지면인지, 오전인지 저녁인지 아예 입력받지 않기 때문이다. 노출과 클릭만 세어서, 전체 평균이 제일 높은 소재 하나를 계속 밀 뿐이다.

**지면·시간대·유저마다 정답이 다르다는 걸 알고리즘에 알려주려면 무엇이 필요할까?**

이 질문 하나가 UCB1에서 LinUCB로, 다시 Hybrid LinUCB로 이어지는 계보 전체를 만든다.

> 한 줄 요약: UCB1은 컨텍스트가 없어 '평균적으로 좋은 소재' 하나만 밀어붙인다. LinUCB는 그 컨텍스트를 점수에 섞어 '이 상황에 맞는 소재'를 고른다. 다만 소재마다 배움을 따로 쌓아서, 신규 소재는 매번 처음부터 다시 배운다. Hybrid LinUCB는 그 배움 일부를 소재끼리 공유해, 새 소재도 조금은 아는 상태로 출발시킨다.

## 1. 가데이터: UCB1이 막히는 순간

**UCB1은 지면·시간대라는 입력 자체가 없다. 그래서 상황마다 다른 정답을 평균 하나로 뭉개 버린다.**

소재 A와 소재 B, 지면 두 종류(뉴스·커뮤니티), 시간대 두 종류(오전·저녁)를 가정하자. 조합마다 진짜 클릭률이 아래처럼 다르다고 해 보자. 이 숫자는 알고리즘도 운영자도 미리 볼 수 없는 가상의 진짜 값이다.

| 지면 | 시간대 | 소재 A | 소재 B | 이 조합의 승자 |
|---|---|---|---|---|
| 뉴스 | 오전 | 8% | 3% | A |
| 뉴스 | 저녁 | 2% | 6% | B |
| 커뮤니티 | 오전 | 3% | 7% | B |
| 커뮤니티 | 저녁 | 6% | 4% | A |
| **전체 평균(UCB1이 보는 값)** | — | 4.75% | **5.0%** | B |

네 조합을 보자. 승자가 A·B·B·A로 계속 바뀐다. 지면과 시간대가 다르면 최선의 소재도 함께 바뀐다는 뜻이다. 그런데 UCB1은 이 표의 위 네 줄을 볼 수 없다. 노출을 모두 합쳐 계산한 마지막 줄, 딱 그 평균만 본다.

문제는 그 평균에서 B가 A를 근소하게 이긴다는 점이다(5.0% 대 4.75%). UCB1은 이 차이를 계속 학습해 결국 어디서나 B를 민다. 그런데 뉴스 오전에서 실제로는 A가 8%로 B(3%)의 두 배 이상이다. 이 조합에서만 매번 절반 이상의 클릭을 놓치는 셈이다.

만약 조합마다 맞는 소재를 골랐다면 평균 클릭률은 6.75%다(8·6·7·6의 평균). 어느 한 소재만 계속 미는 경우(4.75~5.0%)보다 35~42% 높다. 이 차이, 즉 컨텍스트를 아는 것과 모르는 것 사이의 격차가 LinUCB가 존재하는 이유의 전부다.

## 2. 파이썬으로 확인 — 컨텍스트를 무시한 대가

**말로 설명한 손해를 코드로 재현해 보자. 컨텍스트를 아예 무시하는 UCB1과, 컨텍스트별로 UCB1을 따로 돌리는 방식을 겨룬다.**

두 방식 모두 UCB1 그대로다. 차이는 통계를 어떻게 나눠 쌓느냐뿐이다. 하나는 소재별로 통계를 딱 하나만 쌓는다. 다른 하나는 (지면, 시간대) 조합마다 통계를 따로 쌓는다. 행렬 역행렬 같은 선형대수는 전혀 필요 없다. 컨텍스트마다 독립된 카운터를 두는 것만으로도 충분하다. LinUCB가 풀려는 문제의 핵심을 그대로 흉내 낼 수 있다.

아래 코드는 1절의 표와 같은 진짜 클릭률로 4,000회를 시뮬레이션한다. 시드를 고정했으니 그대로 복붙해 돌리면 같은 결과가 나온다.

```python
# UCB1을 '컨텍스트 무시'와 '컨텍스트별 분리' 두 방식으로 돌려 누적 클릭을 비교한다.
# 표준 라이브러리만 쓴다 — 행렬 역행렬 없이, 컨텍스트별 카운터 분리만으로 충분하다.
import random
import math

random.seed(3)

# 1절 표와 같은 '진짜' 클릭률. 지면 2종 x 시간대 2종, 소재 2개.
TRUE_CTR = {
    ("뉴스", "오전"):    {"A": 0.08, "B": 0.03},
    ("뉴스", "저녁"):    {"A": 0.02, "B": 0.06},
    ("커뮤니티", "오전"): {"A": 0.03, "B": 0.07},
    ("커뮤니티", "저녁"): {"A": 0.06, "B": 0.04},
}
CONTEXTS = list(TRUE_CTR)
ARMS = ["A", "B"]
ROUNDS = 4000

def ucb1_pick(counts, sums, t):
    unseen = [a for a in ARMS if counts[a] == 0]
    if unseen:
        return unseen[0]
    return max(ARMS, key=lambda a: sums[a] / counts[a] + math.sqrt(2 * math.log(t) / counts[a]))

# (a) 컨텍스트를 무시한다 — 소재별 통계를 딱 하나만 쓴다.
blind_counts = {a: 0 for a in ARMS}
blind_sums = {a: 0 for a in ARMS}
blind_clicks = 0

# (b) 컨텍스트별로 UCB1을 따로 돌린다 — 조합마다 독립된 통계.
sep_counts = {c: {a: 0 for a in ARMS} for c in CONTEXTS}
sep_sums = {c: {a: 0 for a in ARMS} for c in CONTEXTS}
sep_clicks = 0

for _ in range(1, ROUNDS + 1):
    ctx = random.choice(CONTEXTS)

    t_blind = sum(blind_counts.values()) + 1
    arm_b = ucb1_pick(blind_counts, blind_sums, t_blind)
    reward_b = 1 if random.random() < TRUE_CTR[ctx][arm_b] else 0
    blind_counts[arm_b] += 1
    blind_sums[arm_b] += reward_b
    blind_clicks += reward_b

    t_sep = sum(sep_counts[ctx].values()) + 1
    arm_s = ucb1_pick(sep_counts[ctx], sep_sums[ctx], t_sep)
    reward_s = 1 if random.random() < TRUE_CTR[ctx][arm_s] else 0
    sep_counts[ctx][arm_s] += 1
    sep_sums[ctx][arm_s] += reward_s
    sep_clicks += reward_s

gain = (sep_clicks / blind_clicks - 1) * 100
print(f"{ROUNDS}회 후 누적 클릭 — 컨텍스트 무시: {blind_clicks}회, 컨텍스트별 분리: {sep_clicks}회")
print(f"분리 방식이 {sep_clicks - blind_clicks}회 더 많음 ({gain:.1f}% 더 많음)")
print(f"컨텍스트 무시 방식의 소재 선택 횟수: {blind_counts}")

# 출력:
# 4000회 후 누적 클릭 — 컨텍스트 무시: 192회, 컨텍스트별 분리: 245회
# 분리 방식이 53회 더 많음 (27.6% 더 많음)
# 컨텍스트 무시 방식의 소재 선택 횟수: {'A': 1943, 'B': 2057}
```

결과를 보면 분리 방식이 4,000회 동안 245번 클릭을 받았다. 컨텍스트를 무시한 방식(192번)보다 53번, 27.6% 더 많다. 이 정도 규모의 시뮬레이션에서도 차이가 눈에 띈다. 컨텍스트 하나를 반영하는 것만으로 성능이 갈린다.

더 흥미로운 건 컨텍스트를 무시한 방식의 소재 선택 횟수다. A가 1,943번, B가 2,057번으로 거의 반반이다. 전체 평균 차이가 4.75%와 5.0%로 워낙 작다. 그래서 4,000번을 겪고도 어느 쪽이 나은지 확신하지 못한 것이다. 반면 컨텍스트별로 쪼개면 문제마다 격차가 훨씬 크다(뉴스 오전은 8% 대 3%). 그래서 각 조각은 훨씬 빨리, 훨씬 자신 있게 정답을 찾는다.

## 3. LinUCB — 컨텍스트를 점수에 섞어 넣다

**LinUCB는 지면·시간대 같은 컨텍스트를 숫자 벡터로 만들어, 소재마다 그 벡터에 대한 반응을 따로 학습한다.**

UCB1의 점수는 "평균 + 보너스" 딱 두 숫자로 끝난다. 입력이 없으니 결과도 하나뿐이다. LinUCB는 여기에 컨텍스트 벡터 $x$를 끼워 넣는다. 지면(뉴스=0, 커뮤니티=1), 시간대(오전=0, 저녁=1) 같은 정보를 숫자로 바꿔 늘어놓은 것이 $x$다. 점수는 이렇게 바뀐다.

$$\text{Score}_a = \underbrace{x^T\theta_a}_{\text{이 컨텍스트에서의 예측}} + \underbrace{\alpha\sqrt{x^T A_a^{-1}x}}_{\text{방향별 탐색 보너스}}$$

$\theta_a$는 소재 $a$가 지금까지 배운 가중치다. "이 소재는 뉴스에서 강하고 저녁엔 약하더라" 같은 패턴이 여기 쌓인다. $A_a$는 그 배움이 어느 방향에서 왔는지를 기록한 행렬이다. 이 행렬이 왜 필요한지는 7절에서 따로 뜯어본다. 지금은 "소재마다 컨텍스트에 반응하는 자기만의 작은 모델을 가진다" 정도만 기억하면 된다.

이 구조 덕분에 1절의 문제가 풀린다. 소재 A와 B를 하나의 평균으로 뭉치는 대신, 컨텍스트별로 다르게 배운다. "뉴스에서는 A, 커뮤니티에서는 B"처럼, 조합마다 다른 패턴이 남는다. 2절에서 컨텍스트별로 UCB1을 나눠 돌렸을 때 27.6%의 이득이 났다. 이게 바로 LinUCB가 실제로 만들어 내려는 효과다. 다만 $A_a$ 갱신 방법과 $\alpha$를 정하는 기준은 여기서 다루지 않는다. 역행렬 계산이 가벼워지는 원리도 이 글에서는 다루지 않는다. 구현 디테일은 [Disjoint LinUCB 모델 상세 해석](post.html?id=disjoint-linucb)에 있다.

## 4. Disjoint의 대가 — 소재마다 따로 배우면 신규 소재가 헤맨다

**Disjoint LinUCB는 소재마다 $\theta_a$와 $A_a$를 따로 갖는다. 그래서 신규 소재는 데이터가 0인 채로 혼자 다시 시작한다.**

"Disjoint"는 "따로 떨어진"이라는 뜻 그대로다. 소재 A가 배운 것과 소재 B가 배운 것은 서로 전혀 섞이지 않는다. 소재 A에서 "20대는 오전에 잘 누른다"는 패턴을 확실히 배웠다고 하자. 그래도 그 지식은 소재 A의 $\theta_A$ 안에만 남는다. 소재 B의 $\theta_B$는 여전히 아무것도 모르는 채다.

이게 실무에서 문제가 되는 지점은 신규 소재가 들어올 때다. 오늘 등록된 소재 E를 생각해 보자. 노출도 클릭도 아직 0건이다. $A_E$는 초기값(단위행렬)이고 $\theta_E$도 0이다. 그러면 어떤 컨텍스트가 와도 소재 E의 예측 점수는 0이다. 뉴스든 커뮤니티든, 오전이든 저녁이든 구분이 안 된다는 뜻이다.

물론 보너스 항은 크다. 데이터가 없으니 탐색하라고 알고리즘이 등을 떠민다. 하지만 그 탐색이 유효한 신호로 바뀌려면 소재 E 자신의 노출과 클릭이 쌓여야 한다. 다른 소재 수천 번의 경험은 소재 E에게 한 톨도 전달되지 않는다. 광고 소재가 하루에도 수십~수백 개씩 새로 올라오는 환경을 생각해 보자. 이 콜드스타트를 매번 처음부터 반복하는 비용이 만만치 않다.

**그렇다면 다른 소재가 이미 배운 것을, 새 소재가 조금이라도 물려받을 방법은 없을까?**

## 5. Hybrid LinUCB — 배움을 나눠 콜드스타트를 줄이다

**Hybrid LinUCB는 소재 전용 파라미터 $\theta_a$에 더해, 모든 소재가 함께 쓰는 공유 파라미터 $\beta$를 하나 둔다.**

점수식은 이렇게 늘어난다.

$$\text{Score}_a = \underbrace{z_a^T\beta}_{\text{공통 지식}} + \underbrace{x^T\theta_a}_{\text{개별 지식}} + \text{보너스}_a$$

$z_a$는 소재 자체의 특징이다. 카테고리(운동화), 브랜드(나이키), 가격대 같은 정보를 담는다. $\beta$는 이 특징들이 클릭에 미치는 영향을, 모든 소재의 데이터를 모아서 배운다. 소재 A가 클릭을 받을 때마다 $\theta_A$뿐 아니라 $\beta$도 함께 갱신된다. "운동화 카테고리는 오전에 반응이 좋다"는 패턴을 생각해 보자. 이 패턴은 소재 하나의 것이 아니라 전체의 공통 자산이 된다.

이제 신규 소재 E가 등록되는 순간을 다시 보자. $\theta_E$는 여전히 0에서 시작한다. 하지만 $z_E$ = [운동화, 나이키, 신상] 같은 특징은 있다. 이 특징을 $\beta$에 넣으면, 다른 나이키 운동화 소재에서 배운 패턴이 그대로 적용된다. 그래서 첫 노출부터 그럴듯한 점수가 나온다. 완전히 낯선 신입은 아니다. 선배들이 정리해 둔 요령을 어느 정도 물려받고 시작하는 셈이다. 이게 실무에서 말하는 콜드스타트 완화다.

물론 공짜는 아니다. 저장해야 할 파라미터가 소재별 $\theta_a$·$A_a$에 공유 $\beta$까지 늘어난다. 점수를 계산할 때도 공통 부분과 개별 부분을 같이 풀어야 한다. 소재 수가 적고 새 소재 유입도 드문 환경이라면 얘기가 다르다. 이런 환경에서는 이 복잡도가 아낄 수 있는 비용이 된다. 반대로 신규 소재가 끊임없이 쏟아지는 검색광고·커머스 환경도 있다. 이런 환경에서는 추가 비용을 감수할 가치가 충분하다.

## 6. 셋을 나란히 — UCB1 vs Disjoint LinUCB vs Hybrid LinUCB

**세 알고리즘은 "얼마나 많은 정보를 쓰느냐"의 사다리다. 위로 올라갈수록 정교해지지만 계산도 무거워진다.**

| 축 | UCB1 | Disjoint LinUCB | Hybrid LinUCB |
|---|---|---|---|
| 쓰는 정보 | 소재별 평균·노출 횟수 | 컨텍스트 벡터 + 소재별 가중치 | 컨텍스트 벡터 + 소재별 가중치 + 공유 가중치 |
| 파라미터 수 | 소재당 2개 | 소재당 $d\times d$ 행렬 1개 | 위에 더해 공유 $k\times k$ 행렬 1개 |
| 새 arm 대응 | 몇 번만 보여줘도 곧 따라잡음 | 콜드스타트 — 처음부터 다시 학습 | 공유 파라미터 덕에 첫 노출부터 합리적 |
| 계산 비용 | 덧셈·나눗셈뿐 | 소재마다 행렬 역산 1회 | 소재 역산 + 공유 역산, 더 무거움 |
| 언제 쓰나 | 소재 수 적고 컨텍스트가 안 중요할 때 | 컨텍스트 있고 소재 구성이 안정적일 때 | 신규 소재가 계속 들어오는 대규모 환경 |

표를 위에서 아래로 읽으면 계보가 보인다. UCB1은 컨텍스트 자체가 없어 가장 가볍다. Disjoint LinUCB는 3절에서 본 대로 컨텍스트를 반영한다. 대신 소재마다 행렬을 하나씩 짊어진다. Hybrid LinUCB는 5절의 콜드스타트 문제를 풀려고 한다. 그래서 공유 행렬을 하나 더 얹는다.

셋 중 뭐가 "제일 좋은 알고리즘"이냐고 묻는다면 질문이 잘못됐다. 소재가 서너 개뿐이고 유저 차이도 별 의미가 없다면 UCB1로 충분하다. 굳이 행렬을 돌릴 이유가 없다. 컨텍스트가 확실히 있고 소재 구성도 잘 안 바뀐다면 얘기가 다르다. 이때는 Disjoint LinUCB가 딱 맞는 자리다. 반면 신규 소재가 하루에도 수십 개씩 쏟아지는 검색광고·커머스 지면도 있다. 이런 곳에서는 콜드스타트 비용이 계산 비용보다 훨씬 아프다. 이때는 Hybrid LinUCB 쪽으로 무게가 실린다.

## 7. 보너스의 정체 — 횟수에서 방향으로

**UCB1의 보너스도 LinUCB의 보너스도 같은 직관에서 나온다. "아직 잘 모르는 만큼 여유를 준다"는 생각이다.**

UCB1은 이 직관을 가장 단순하게 구현한다. 소재를 몇 번 봤는지, 그 숫자 하나로 모르는 정도를 잰다. 적게 볼수록 여유(보너스)가 커진다.

LinUCB는 같은 직관을 컨텍스트까지 확장한다. 소재를 전체적으로 많이 봤어도, 지금 이 컨텍스트 방향으로는 거의 못 봤을 수 있다. LinUCB의 보너스는 이 "방향별로 모르는 정도"를 잰다.

두 보너스가 실제로 어떻게 연결되는지는 수식으로 보면 가장 깔끔하다. 아래 접이 블록에서 이어서 본다.

:::deep 더 깊이 — UCB1의 보너스와 LinUCB의 보너스는 같은 식의 두 얼굴이다
UCB1의 보너스는 $\sqrt{2\ln t / n_a}$다. 이 식에서 $n_a$는 그냥 숫자다.

소재 $a$를 몇 번 봤는지, 그 횟수 하나만 담고 있다.

LinUCB의 보너스는 $\alpha\sqrt{x^T A_a^{-1} x}$다. 언뜻 훨씬 복잡해 보인다.

하지만 컨텍스트가 없다고 가정하면 정확히 같은 모양이 나온다.

컨텍스트 $x$가 늘 1이라는 상수뿐이라고 해 보자. 그러면 $A_a$는 $n_a$번 관측한 $1^2$을 더한 값, 즉 $n_a+1$이 된다(+1은 정칙화 항). 역행렬은 $A_a^{-1} = 1/(n_a+1)$이 되고, 보너스는 $\alpha/\sqrt{n_a+1}$로 정리된다. UCB1의 $\sqrt{2\ln t/n_a}$와 형태가 사실상 같다. 분자가 $\alpha$라는 고정값이냐, $\sqrt{2\ln t}$라는 서서히 커지는 값이냐만 다르다.

차이는 컨텍스트가 실제로 있을 때 드러난다. $A_a$는 $n_a$처럼 숫자 하나가 아니다. 지금까지 본 컨텍스트 벡터들의 방향까지 함께 쌓은 행렬이다. 그래서 $x^T A_a^{-1} x$는 "몇 번 봤나"를 넘어선다. "지금 이 컨텍스트 방향으로 얼마나 봤나"를 잰다.

예를 들어 소재 D가 노출 1,000번을 채웠다고 하자. 그런데 그게 전부 '커뮤니티·저녁' 조합에서만 나온 데이터라면 얘기가 다르다. 오늘 요청이 '뉴스·오전'이면 그 방향엔 데이터가 거의 없는 것과 같다. $n_a$만 보는 UCB1은 이 소재를 "이미 많이 안다"고 오판해 보너스를 작게 준다. 반면 LinUCB는 $x^T A_a^{-1} x$가 커진다. "이 방향은 아직 낯설다"며 제대로 보너스를 키운다.

즉 UCB1의 $n_a$는 LinUCB의 $x^T A_a^{-1} x$의 특수한 경우다. 컨텍스트가 늘 같다고 가정하면, LinUCB의 보너스가 UCB1의 보너스로 정확히 줄어든다. 횟수라는 1차원짜리 잣대가, 방향까지 담는 다차원 잣대로 넓어진 것뿐이다.
:::

## 8. 닫힌 생태계 — 컨텍스트가 풍부해야 LinUCB류가 힘을 쓴다 [무대: 닫힌 생태계]

**LinUCB와 Hybrid LinUCB가 실제로 이득을 보려면, 애초에 쓸 만한 컨텍스트 피처가 있어야 한다. 닫힌 생태계는 그 조건을 가장 잘 채운다.**

네이버·밴드처럼 로그인 기반의 닫힌 생태계는 유저 정보를 이미 갖고 있다. 나이대·성별·과거 클릭 이력·지금 보는 지면 같은 피처가 있다. 이런 피처를 그 자리에서 컨텍스트 벡터로 만들 수 있다. 1절의 지면·시간대 예시가 바로 이런 피처다. 컨텍스트가 이렇게 풍부해야 LinUCB의 $\theta_a$가 배울 거리가 생긴다.

만약 컨텍스트 피처가 빈약하다면 얘기가 달라진다. 지면 정보 하나만 있고 유저 정보가 전혀 없다고 하자. 그러면 LinUCB든 UCB1이든 성능 차이가 크지 않다. 7절의 논리를 뒤집어 보면 이유가 보인다. $x$가 다양하지 않으면 $A_a^{-1}$가 사실상 $n_a$와 다를 게 없어지기 때문이다. 그래서 닫힌 생태계에서도 순서가 있다. "피처가 몇 개나 있고 얼마나 다양한가"부터 먼저 확인해야 한다.

Hybrid LinUCB는 여기에 소재 피처 $z_a$까지 필요하다. 카테고리·브랜드·가격대 같은 메타데이터가 소재마다 정리돼 있어야 한다. 그래야 공유 파라미터 $\beta$가 의미 있게 학습된다. 닫힌 생태계의 광고 플랫폼은 이 메타데이터를 대개 갖고 있다. 광고주가 소재를 등록하는 단계에서부터 쌓이기 때문이다. 그래서 5절의 콜드스타트 완화가 이론이 아니라 실제로 작동한다.

## 9. 열린 RTB — 컨텍스트는 오지만 학습은 느리다 [무대: 열린 RTB]

**열린 RTB에서도 요청마다 컨텍스트는 따라온다. 하지만 패찰하면 그 컨텍스트에 대한 결과 자체를 못 본다.**

DSP가 받는 입찰 요청에는 대개 컨텍스트가 딸려 있다. 매체·지면·유저 세그먼트 같은 정보가 매 요청마다 함께 온다. 그래서 LinUCB의 $x$를 채우는 재료 자체는 부족하지 않다. 문제는 그다음이다. 입찰에서 이겨야 노출이 나가고, 노출이 나가야 클릭 여부를 알 수 있다. 패찰하면 이 소재가 통했을지 알 방법이 없다. 그 컨텍스트에 대한 데이터 자체가 생기지 않는 것이다.

이 결측은 4절의 콜드스타트보다 한 겹 더 나쁘다. 닫힌 생태계의 신규 소재는 노출만 시키면 데이터가 쌓인다. 열린 RTB에서는 노출을 시키고 싶어도 경매에서 계속 질 수 있다. 그러면 $A_a$가 아예 자라지 않는다. 인기 있는 세그먼트일수록 경쟁이 치열해 패찰이 잦다. 그만큼 그 방향의 데이터가 더디게 쌓인다. 정보가 잘 모이는 세그먼트와 안 모이는 세그먼트의 격차가 벌어진다. 그 격차는 닫힌 생태계보다 훨씬 크다.

게다가 열린 RTB에서는 arm 구성 자체도 자주 바뀐다. 캠페인이 시작되고 끝나면서 소재 후보군이 계속 들고 난다. Disjoint든 Hybrid든 $\theta_a$·$A_a$를 arm마다 붙여 관리해야 한다. arm이 수시로 생기고 사라지면 이 저장·정리 비용도 함께 늘어난다. 그래서 열린 RTB의 컨텍스추얼 밴딧은 알고리즘 선택만으론 부족하다. 언제 arm을 등록하고 언제 폐기할지 정하는 운영 규칙이 실무의 절반을 차지한다.

## 11. 헷갈리기 쉬운 점

- **UCB1이 "나쁜 소재"를 고르는 게 아니다.** 컨텍스트를 아예 못 보니, 평균적으로 나은 소재 하나만 어디서나 반복해서 미는 것뿐이다.
- **LinUCB의 $\theta_a$는 "정답"이 아니라 "지금까지 배운 추정치"다.** 데이터가 적으면 얼마든지 틀릴 수 있고, 그래서 보너스 항이 따로 붙어 있다.
- **Disjoint LinUCB의 "Disjoint"는 알고리즘 이름이 아니라 구조를 가리키는 말이다.** 소재끼리 배움을 전혀 안 섞는다는 뜻이지, 성능이 나쁘다는 뜻이 아니다.
- **Hybrid LinUCB가 항상 더 좋은 상위 호환은 아니다.** 신규 소재가 드문 환경에서는 공유 파라미터를 관리하는 비용만 늘어난다.
- **UCB1의 $n_a$와 LinUCB의 $x^TA_a^{-1}x$는 다른 개념이 아니라 같은 개념의 두 버전이다.** 컨텍스트가 상수 하나뿐이라고 가정하면 둘은 정확히 같은 식이 된다.
- **닫힌 생태계·열린 RTB 둘 다 LinUCB류를 쓸 수 있지만, "컨텍스트가 있다"와 "그 컨텍스트로 학습이 잘 된다"는 다른 이야기다.** 열린 RTB는 패찰 때문에 후자가 훨씬 느리다.
