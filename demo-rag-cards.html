RAG 카드 네 장

지훈 씨가 모델이 모르는 상품 질문에 답을 붙인 길을 카드 네 장으로 봅니다. 문서를 문장 두 개씩 조각내고, 질문과 가까운 조각 셋을 찾습니다. 조각을 넣어 답하게 한 뒤, 답의 값이 조각에 있는지 코드로 대조합니다. 상품 문서 100건과 질문 20개는 가상 데이터입니다.

파랑 = 코드가 하는 일 벽돌색 = 질문과 모델의 답 먹색 = 문서와 조각 회색 = 정답 문서가 아닌 조각 점선 상자 = 가상 값 (상품 문서)

CHUNK

문서 한 건이 조각 둘이 되는 길

쉽게 말하면 문서를 문장 두 개씩 잘라 조각으로 만듭니다. 조각마다 문서 id 와 벡터를 붙여 둡니다.

문서 100건, 문장 348개가 조각 200개가 되었습니다.

RETRIEVE

질문 벡터와 가까운 조각 셋

쉽게 말하면 질문도 같은 함수로 벡터로 바꿉니다. 조각 200개와 코사인을 측정해서 큰 셋을 고릅니다.

정답 문서가 상위 3 에 든 질문은 15/20, Context Precision 은 0.47 입니다.

PROMPT

조각 셋을 넣은 프롬프트

쉽게 말하면 찾은 조각 셋을 질문 앞에 붙여 보냅니다. 답은 값과 문서 id 를 담은 JSON 한 줄입니다.

입력은 262~304 토큰, 출력은 13~21 토큰이었습니다.

GROUNDING

답과 조각의 대조, recall 과 precision

쉽게 말하면 답의 값이 그 답이 가리킨 조각에 정말 있는지 코드가 봅니다. 검색 값과 답 값은 따로 셉니다.

근거 대조 통과 15개, 근거 없는 답 0개, 맞힌 답 20/20 입니다.

현업에서는 이렇게 씁니다

  • 문서 조각과 벡터는 미리 만들어 색인에 넣고, 질문 벡터만 요청 때 만듭니다. 문서가 바뀌면 그 문서의 조각만 다시 만듭니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 RAG 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 바로 앞 이야기는 임베딩과 벡터 검색 편입니다.
