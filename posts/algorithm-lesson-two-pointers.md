지훈 씨는 지난 시간에 Two Sum(더해서 target 이 되는 두 값을 찾는 문제)을 dict(키로 값을 바로 찾는 파이썬 자료구조)로 풀었고 이번 과외를 시작하며 정렬 이야기를 꺼냈습니다. 「정렬이 되어 있을 때 쓰는 방법이랑 안 되어 있을 때 쓰는 방법이 따로 있어요?」

따로 있습니다. 배열이 작은 값부터 정렬돼 있으면 같은 Two Sum 을 dict 없이 배열의 양 끝을 가리키는 인덱스 두 개만 옮기며 풉니다. 인덱스 두 개를 옮기며 배열을 순회하는 방법을 투 포인터(two pointers)라고 부르는데, 이 글은 그 가운데 양 끝에서 마주 보며 좁혀 오는 꼴을 다룹니다.

**양 끝에서 한 칸씩 좁혀 오면 더해 보지 않고 넘어가는 짝이 대부분인데, 어떻게 답을 놓치지 않을까요?**

이 글은 왼쪽 인덱스를 L, 오른쪽 인덱스를 R 이라고 부릅니다. 값이 10,000개면 짝은 10,000 × 9,999 / 2 = 49,995,000개지만 정렬된 배열에서 L 과 R 은 많아야 10,000 - 1 = 9,999번 비교하고 끝납니다. 같은 규칙을 정렬하지 않은 배열에 쓰면 답을 버릴 수 있어서 문제를 읽을 때 정렬 여부부터 봐야 합니다.

> **한 줄 요약:** 정렬된 배열에서 합이 target 인 두 값을 찾을 때 L 은 맨 왼쪽, R 은 맨 오른쪽 칸에서 출발해 두 값의 합이 target 보다 크면 R 을 왼쪽으로, 작으면 L 을 오른쪽으로 한 칸 옮기고 같으면 멈춥니다. 합이 크면 R 의 값은 L 부터 R 바로 앞까지의 어느 값과 더해도 target 보다 커서 R 이 들어간 짝은 답이 될 수 없으므로 비교 한 번에 짝 여러 개를 버려도 답을 놓치지 않습니다. 정렬하지 않은 배열에는 이 근거가 없어서 nums = [11, 3, 8, 1, 6, 4], target = 10 의 답을 첫 비교에서 버립니다.

> **골라 읽는 법** — 절이 8개인 긴 글입니다. 처음부터 다 읽지 않아도 됩니다.
>
> - 정렬 여부에 따라 바뀌는 도구 → 1절
> - 양 끝에서 좁히는 순서와 답을 놓치지 않는 이유 → 2~3절
> - 정렬하지 않은 배열, 정렬 비용과 해시 맵 → 4~5절
> - 같은 틀로 푸는 LeetCode 문제 3개 → 6~8절

## 1. 정렬 여부로 바뀌는 도구

**배열이 정렬돼 있으면 쓸 수 있는 도구가 바뀝니다. 같은 Two Sum 도 정렬되지 않은 배열에서는 해시 맵으로, 정렬된 배열에서는 투 포인터로 풉니다. 값 하나 찾기와 세 값의 합 찾기도 정렬 여부에 따라 푸는 방법이 달라집니다.**

지훈 씨의 질문을 다시 말하면 「같은 문제라도 배열이 정렬돼 있으면 다른 방법을 쓰는가」입니다. 그렇습니다. 작은 값부터 정렬돼 있으면 왼쪽 칸의 값이 오른쪽 칸의 값보다 크지 않습니다. 이 성질이 있으면 값 하나를 비교한 결과로 다른 후보 여러 개를 함께 버릴 수 있어서 쓸 수 있는 방법이 달라집니다. 해시 맵 편에서 지훈 씨가 Two Sum 이 슬라이딩 윈도우냐고 물었을 때 저는 해시 맵, 투 포인터, 슬라이딩 윈도우를 표로 비교했고 이번 과외에서는 문제마다 정렬 여부에 따라 쓰는 방법을 표로 보였습니다. 아래 표는 두 표를 정렬 여부를 기준으로 합쳐 고쳤습니다.

선형 탐색(linear search)은 앞에서부터 값을 하나씩 비교해 찾는 방법입니다. 이진 탐색(binary search, 이분 탐색이라고도 부릅니다)은 정렬된 배열의 가운데 값과 비교해 찾는 값이 있을 수 없는 절반을 한 번에 버리는 방법입니다. 3Sum 은 더해서 0 이 되는 세 값을 찾는 문제입니다. 슬라이딩 윈도우(sliding window)는 붙어 있는 구간을 한 칸씩 밀며 그 구간의 합 같은 값을 구하는 방법입니다.

| 문제 | 정렬되지 않은 배열 | 정렬된 배열 | 다루는 곳 |
|---|---|---|---|
| 값 하나 찾기 | 선형 탐색 O(N). 여러 번 찾으면 set 에 넣어 두고 평균 O(1) 로 확인하지만 메모리 O(N) | 이진 탐색 O(log N), 추가 메모리 O(1) | [이분 탐색과 스택](post.html?id=algorithm-binary-search-stack) 편 1절 |
| Two Sum | 해시 맵 O(N), 메모리 O(N) | 투 포인터 O(N), 추가 메모리 O(1) | [해시 맵](post.html?id=algorithm-lesson-hash-map) 편, 이 글 2~6절 |
| 3Sum | 값 하나를 고정하고 나머지 두 값을 해시로 찾기 O(N²) | 정렬한 뒤 값 하나를 고정하고 투 포인터 O(N²). 같은 값을 건너뛰기 쉬움 | 이 글 8절 |
| 붙어 있는 구간의 합 | 슬라이딩 윈도우 | 슬라이딩 윈도우. 정렬 여부와 상관없음 | [슬라이딩 윈도우](post.html?id=algorithm-lesson-sliding-window) 편 |

과외에서 저는 정렬하지 않은 3Sum 을 이중 for 문과 해시 맵으로 풀면 O(N²) 에 복잡하다고 했는데, 정렬한 풀이도 고정한 값마다 투 포인터를 한 번씩 돌려 O(N²) 이라 두 방법의 시간 복잡도는 같습니다. 정렬하면 같은 값이 서로 붙어서 같은 조합을 두 번 담지 않도록 건너뛰기가 쉬워지고 이 차이는 8절의 코드에서 봅니다. 마지막 행의 붙어 있는 구간은 값이 놓인 순서 자체가 답의 일부라서 정렬하면 다른 문제가 됩니다.

같은 과외에서 저는 문제에 「배열이 오름차순으로 정렬되어 있다」는 문장이 보이면 이진 탐색이나 투 포인터를 쓰라는 힌트라고 하며 비율을 붙였는데, 출처가 없는 숫자라 이 글에서는 지웁니다. 정렬돼 있다는 조건은 두 방법이 기대는 성질을 문제가 보장한다는 뜻이라 두 방법을 먼저 떠올릴 근거는 됩니다. 표의 Two Sum 행에서 정렬된 배열 칸의 투 포인터를 2절부터 한 단계씩 따라갑니다.

## 2. 양 끝에서 좁히는 순서

**정렬된 배열에서 L 은 맨 왼쪽 칸, R 은 맨 오른쪽 칸에서 출발해 두 값의 합을 target 과 비교합니다. 합이 target 보다 크면 R 을 왼쪽으로, 작으면 L 을 오른쪽으로 한 칸 옮기고 같으면 L 과 R 을 답으로 돌려줍니다.**

설명을 위해 만든 정렬된 배열 `nums = [1, 3, 4, 6, 8, 11]` 과 `target = 10` 으로 따라갑니다. 답은 2번 칸의 4 와 3번 칸의 6 입니다. L 은 0번 칸, R 은 5번 칸에서 출발합니다. 아래 표에 비교할 때마다 두 포인터의 자리, 두 값의 합, 판정, 옮길 포인터를 적었습니다.

| 비교 | L | R | nums[L] + nums[R] | target 10 과 비교 | 옮길 포인터 |
|---|---|---|---|---|---|
| 1 | 0 | 5 | 1 + 11 = 12 | 큼 | R 을 4 로 |
| 2 | 0 | 4 | 1 + 8 = 9 | 작음 | L 을 1 로 |
| 3 | 1 | 4 | 3 + 8 = 11 | 큼 | R 을 3 으로 |
| 4 | 1 | 3 | 3 + 6 = 9 | 작음 | L 을 2 로 |
| 5 | 2 | 3 | 4 + 6 = 10 | 같음 | 옮기지 않고 (2, 3) 을 돌려줌 |

첫 비교의 합 12 는 target 10 보다 커서 합을 줄여야 합니다. 정렬된 배열에서 R 을 왼쪽으로 옮기면 nums[R] 이 같거나 작은 값으로 바뀌어 합이 커지지 않고 L 을 오른쪽으로 옮기면 nums[L] 이 같거나 큰 값으로 바뀌어 합이 작아지지 않습니다. 그래서 어느 포인터를 옮길지는 비교 결과로 항상 정해집니다.

과외에서 저는 합이 크면 R 을 왼쪽으로 옮겨 합이 무조건 작아진다고 설명했는데, 같은 값이 이어진 배열에서는 R 을 옮겨도 합이 그대로일 수 있어서 「작아지거나 그대로」가 맞습니다. 합이 그대로여도 R 을 옮겨도 되는 까닭은 3절에서 봅니다. 아래 코드는 이 규칙을 함수로 만들어 비교마다 한 줄씩 찍고 같은 값 5 가 두 칸 있는 `[1, 2, 5, 5]`, `target = 3` 도 돌립니다. 코드는 L 을 `left`, R 을 `right` 라는 변수로 둡니다.

```python
# 하는 일: 정렬된 [1, 3, 4, 6, 8, 11] 에서 합이 10 인 두 칸을 양 끝에서 좁혀 오며 찾아 비교마다 L, R, 합, 옮길 포인터를 찍고, 같은 값이 이어진 [1, 2, 5, 5] 에서 R 을 옮겨도 합이 그대로인 단계를 본다.

# 1단계: 투 포인터 함수를 만든다
# nums 는 작은 값부터 정렬돼 있어야 한다. 합이 크면 R 을, 작으면 L 을 한 칸 옮기고 같으면 멈춘다.
def two_pointer(nums, target):                             # 두 인덱스나 None 을 돌려준다
    left, right = 0, len(nums) - 1                         # L 은 맨 왼쪽, R 은 맨 오른쪽 칸에서 출발한다
    count = 0                                              # 비교한 횟수
    while left < right:                                    # L 과 R 이 만나기 전까지 비교한다
        total = nums[left] + nums[right]                   # 두 값의 합
        count += 1                                         # 비교를 하나 센다
        head = f'비교 {count}: L = {left}, R = {right}, {nums[left]} + {nums[right]} = {total}'   # 찍을 줄의 앞부분
        if total == target:                                # 합이 target 과 같으면
            print(f'{head}, 같음 → 멈춘다')                 # 멈추는 비교를 찍는다
            return (left, right)                           # 두 인덱스를 돌려준다
        if total > target:                                 # 합이 target 보다 크면
            print(f'{head}, 큼 → R 을 왼쪽으로')            # R 을 옮기는 비교를 찍는다
            right -= 1                                     # R 을 왼쪽으로 한 칸 옮긴다
        else:                                              # 합이 target 보다 작으면
            print(f'{head}, 작음 → L 을 오른쪽으로')        # L 을 옮기는 비교를 찍는다
            left += 1                                      # L 을 오른쪽으로 한 칸 옮긴다
    return None                                            # 만날 때까지 짝이 없으면 None

# 2단계: 정렬된 배열에서 target 10 을 찾는다
# 설명을 위해 만든 입력이다. 답은 2번 칸의 4 와 3번 칸의 6 이다.
nums = [1, 3, 4, 6, 8, 11]                                 # 작은 값부터 정렬된 값 6개
answer = two_pointer(nums, 10)                             # 비교마다 한 줄씩 찍는다
print(f'답 {answer}, {nums[answer[0]]} + {nums[answer[1]]} = 10')   # 찾은 두 칸과 그 값

# 3단계: 같은 값이 이어진 배열에서 R 을 옮긴다
# 5 가 두 칸이라 R 을 3 에서 2 로 옮겨도 합이 그대로다.
print(f'답 {two_pointer([1, 2, 5, 5], 3)}')                 # target 3 의 답은 0번 칸과 1번 칸

# 출력:
# 2단계 뜻: 위 표와 같은 다섯 번의 비교로 합이 12, 9, 11, 9, 10 이 되고 2번 칸과 3번 칸에서 멈춘다.
# 비교 1: L = 0, R = 5, 1 + 11 = 12, 큼 → R 을 왼쪽으로
# 비교 2: L = 0, R = 4, 1 + 8 = 9, 작음 → L 을 오른쪽으로
# 비교 3: L = 1, R = 4, 3 + 8 = 11, 큼 → R 을 왼쪽으로
# 비교 4: L = 1, R = 3, 3 + 6 = 9, 작음 → L 을 오른쪽으로
# 비교 5: L = 2, R = 3, 4 + 6 = 10, 같음 → 멈춘다
# 답 (2, 3), 4 + 6 = 10
# 3단계 뜻: R 을 3 에서 2 로 옮겨도 합이 6 그대로라 한 번 더 옮기고, 세 번째 비교에서 0번 칸과 1번 칸을 찾는다.
# 비교 1: L = 0, R = 3, 1 + 5 = 6, 큼 → R 을 왼쪽으로
# 비교 2: L = 0, R = 2, 1 + 5 = 6, 큼 → R 을 왼쪽으로
# 비교 3: L = 0, R = 1, 1 + 2 = 3, 같음 → 멈춘다
# 답 (0, 1)
```

출력의 첫 다섯 줄은 위 표와 같습니다. 값 6개로 만들 수 있는 짝은 6 × 5 / 2 = 15개인데 그 가운데 5개만 더해 봤습니다. 셋째 단계는 R 을 3 에서 2 로 옮긴 뒤에도 합이 6 그대로라 R 을 한 번 더 옮겼고 세 번째 비교에서 (0, 1) 을 찾았습니다.

[1, 3, 4, 6, 8, 11] 의 짝 15개 가운데 더해 보지 않은 15 - 5 = 10개는 비교 한 번마다 지금 더해 본 짝과 함께 버려졌습니다. 그 10개에 답이 없다는 근거는 비교한 합 하나에서 바로 나옵니다. 같은 입력을 비교 하나씩 누르며 보는 데모는 그 근거를 설명하는 3절에 있습니다.

## 3. 좁혀도 답을 놓치지 않는 이유

**정렬된 배열에서 합이 target 보다 크면 R 의 값은 L 부터 R 바로 앞까지의 어느 값과 더해도 target 보다 크므로 R 이 들어간 짝은 답이 될 수 없습니다. 합이 작으면 같은 까닭으로 L 이 들어간 짝이 답이 될 수 없어서 비교 한 번에 짝 여러 개를 버려도 답 짝은 남습니다.**

첫 비교를 다시 봅니다. L = 0, R = 5 에서 합 1 + 11 = 12 가 10 보다 큽니다. 배열이 정렬돼 있어 0번부터 4번 칸의 값은 모두 nums[L] 인 1 이상이고 11 과 더한 합도 12, 14, 15, 17, 19 로 모두 12 이상이라 target 10 이 될 수 없습니다. 그래서 11 이 들어간 짝 (0, 5) 부터 (4, 5) 까지 5개를 버린 뒤 R 을 4 로 옮깁니다. 이 5개 가운데 실제로 더해 본 짝은 지금 비교한 (0, 5) 하나입니다. 두 번째 비교의 합 1 + 8 = 9 는 작으므로 같은 까닭으로 1 이 들어간 남은 짝 4개를 버리고 L 을 1 로 옮깁니다.

행 i, 열 j(i < j)의 칸에 nums[i] + nums[j] 를 적은 표를 이 글은 짝 표라고 부릅니다. 짝 표로 보면 합이 클 때는 R 열에서 L 행부터 R - 1 행까지의 칸을, 작을 때는 L 행에서 L + 1 열부터 R 열까지의 칸을 버립니다. L 보다 앞의 행과 R 보다 뒤의 열은 이전 비교에서 이미 버렸으므로 한 번 버리고 나면 옮긴 포인터가 들어간 짝은 하나도 남지 않습니다. 비교 한 번에 R - L 개를 버리고 R - L 은 비교마다 1씩 줄어서 답이 없는 입력이라도 값 N개에서 L 과 R 이 만날 때까지 많아야 N - 1 번 비교합니다.

아래 코드는 비교마다 버린 짝을 찍고 버린 짝 가운데 합이 10 인 짝이 있었는지 확인합니다.

```python
# 하는 일: 정렬된 [1, 3, 4, 6, 8, 11], target 10 에서 비교마다 버린 짝을 찍고, 버린 짝 가운데 합이 10 인 짝이 없는 것을 확인한다.

# 1단계: 비교마다 버린 짝을 모으는 투 포인터를 만든다
# 합이 크면 R 이 들어간 남은 짝 (L, R) 부터 (R - 1, R) 까지를, 작으면 L 이 들어간 남은 짝 (L, L + 1) 부터 (L, R) 까지를 버린다.
def discard_log(nums, target):                             # 비교마다 (L, R, 합, 버린 짝) 을 모은다
    left, right = 0, len(nums) - 1                         # 양 끝에서 출발한다
    log = []                                               # 비교마다 한 줄
    while left < right:                                    # L 과 R 이 만나기 전까지
        total = nums[left] + nums[right]                   # 두 값의 합
        if total == target:                                # 답이면
            log.append((left, right, total, []))           # 버리는 짝 없이 적고
            break                                          # 멈춘다
        if total > target:                                 # 합이 크면 R 이 들어간 짝을 버린다
            gone = [(i, right) for i in range(left, right)]          # L 행부터 R - 1 행까지
        else:                                              # 합이 작으면 L 이 들어간 짝을 버린다
            gone = [(left, j) for j in range(left + 1, right + 1)]   # L + 1 열부터 R 열까지
        log.append((left, right, total, gone))             # 옮기기 전의 자리와 버린 짝을 적는다
        if total > target:                                 # 합이 컸으면
            right -= 1                                     # R 을 왼쪽으로
        else:                                              # 합이 작았으면
            left += 1                                      # L 을 오른쪽으로
    return log                                             # 비교마다 적은 줄

# 2단계: 비교마다 버린 짝을 찍는다
nums, target = [1, 3, 4, 6, 8, 11], 10                     # 2절과 같은 입력
log = discard_log(nums, target)                            # 비교 기록
for k, (l, r, total, gone) in enumerate(log, 1):           # 비교 하나씩
    if gone:                                               # 버린 짝이 있으면
        print(f'비교 {k}: ({l}, {r}) 합 {total}, 버린 짝 {len(gone)}개 {gone}')   # 버린 짝을 찍는다
    else:                                                  # 답을 찾은 비교면
        print(f'비교 {k}: ({l}, {r}) 합 {total}, 답')        # 답이라고 찍는다
all_gone = [pair for step in log for pair in step[3]]      # 버린 짝을 한 목록으로 모은다
n = len(nums)                                              # 값의 개수
print(f'비교 {len(log)}번, 버린 짝 {len(all_gone)}개 + 답 1개 = 짝 {n} × {n - 1} / 2 = {n * (n - 1) // 2}개')   # 짝이 모두 한 번씩 정해졌는지

# 3단계: 버린 짝 가운데 답이 있었는지 본다
hits = [(i, j) for i, j in all_gone if nums[i] + nums[j] == target]   # 합이 target 인 버린 짝
print(f'버린 짝 가운데 합이 {target} 인 짝 {len(hits)}개')   # 0개면 답을 놓치지 않았다

# 출력:
# 2단계 뜻: 비교마다 R - L 개의 짝을 버려 5개, 4개, 3개, 2개를 버리고 다섯 번째 비교가 답이다.
# 비교 1: (0, 5) 합 12, 버린 짝 5개 [(0, 5), (1, 5), (2, 5), (3, 5), (4, 5)]
# 비교 2: (0, 4) 합 9, 버린 짝 4개 [(0, 1), (0, 2), (0, 3), (0, 4)]
# 비교 3: (1, 4) 합 11, 버린 짝 3개 [(1, 4), (2, 4), (3, 4)]
# 비교 4: (1, 3) 합 9, 버린 짝 2개 [(1, 2), (1, 3)]
# 비교 5: (2, 3) 합 10, 답
# 비교 5번, 버린 짝 14개 + 답 1개 = 짝 6 × 5 / 2 = 15개
# 3단계 뜻: 버린 짝 14개 가운데 답은 없다.
# 버린 짝 가운데 합이 10 인 짝 0개
```

출력의 마지막 두 줄처럼 짝 15개가 버린 짝 아니면 답으로 한 번씩 정해졌습니다. 버린 짝 가운데 합이 10 인 짝이 없으니 답을 놓치지 않았습니다. 버린 짝 14개 가운데 더해 본 짝은 앞의 네 비교에서 고른 4개뿐이고 나머지 10개는 더해 보지 않고도 비교한 합 하나로 target 과 같을 수 없다고 정해졌습니다.

아래 데모는 같은 입력을 비교 하나씩 보여 줍니다. 짝 표의 행과 열 머리는 nums 의 값이고 칸에는 두 값의 합이 적혀 있습니다. 「한 칸」을 처음 누르면 배열의 두 끝 칸이 지금 비교하는 칸으로 표시되고 이번 단계 칸이 「11과 짝이 되는 5개를 버립니다.」로 끝나며, 짝 표에서 열 머리가 11 인 열의 칸 5개가 버린 짝으로 흐려집니다. 누를 때마다 결과 아랫줄이 「지금까지 비교 2번, 버린 짝 9개」처럼 비교 수와 버린 짝의 수를 셉니다.

「끝까지」를 누르면 결과 아랫줄에 「짝 15개 가운데 비교 5번」이 나오고 짝 표에는 버린 짝 14칸과 답 (2, 3) 한 칸이 남습니다. 비교한 짝 칸 아래의 근거 문장은 합이 크면 R 이, 작으면 L 이 들어간 짝을 버려도 되는 까닭을 적다가 끝에서 「버린 짝은 지금까지 14개입니다. 버린 짝 가운데 합이 target 인 짝은 없어서 답을 놓치지 않았습니다.」가 됩니다.

당연해 보이는 다른 방법으로 두 포인터를 모두 왼쪽에 두고 출발해 봅니다. L = 0, R = 1 에서 합 1 + 3 = 4 가 작아 옮길 수 있는 R 을 2 로 옮기면 (0, 2) 의 합은 5 입니다. 아래 코드는 양 끝 (0, 5) 와 이렇게 온 (0, 2) 에서 포인터를 한 칸씩 옮겨 본 합을 찍습니다.

```python
# 하는 일: 정렬된 [1, 3, 4, 6, 8, 11] 에서 양 끝 (0, 5) 와 왼쪽에서 함께 출발해 온 (0, 2) 에서 포인터를 한 칸 옮긴 합을 비교한다.

# 1단계: 지금 합과 포인터를 한 칸 옮긴 뒤의 합을 찍는 함수를 만든다
# 양 끝 (0, 5) 에서는 R 을 왼쪽으로, L 을 오른쪽으로 옮길 수 있다. 왼쪽에서 함께 출발해 (0, 2) 에 온 두 포인터는 둘 다 오른쪽으로만 옮길 수 있다.
nums = [1, 3, 4, 6, 8, 11]                                 # 2절과 같은 입력
def show(name, l, r, moves):                               # moves 는 (옮기는 방법, 새 L, 새 R) 목록
    after = ', '.join(f'{how} ({a}, {b}) 합 {nums[a] + nums[b]}' for how, a, b in moves)   # 옮긴 뒤의 합
    print(f'{name} ({l}, {r}) 합 {nums[l] + nums[r]}: {after}')   # 지금 합과 옮긴 뒤의 합

# 2단계: 두 자리에서 찍는다
show('양 끝', 0, 5, [('R 을 왼쪽으로', 0, 4), ('L 을 오른쪽으로', 1, 5)])        # 하나는 작아지고 하나는 커진다
show('왼쪽 출발', 0, 2, [('R 을 오른쪽으로', 0, 3), ('L 을 오른쪽으로', 1, 2)])   # 둘 다 커진다

# 출력:
# 2단계 뜻: 양 끝에서는 두 이동 가운데 하나는 합이 작아지고 하나는 커지며, 왼쪽에서 출발하면 둘 다 커진다.
# 양 끝 (0, 5) 합 12: R 을 왼쪽으로 (0, 4) 합 9, L 을 오른쪽으로 (1, 5) 합 14
# 왼쪽 출발 (0, 2) 합 5: R 을 오른쪽으로 (0, 3) 합 7, L 을 오른쪽으로 (1, 2) 합 7
```

왼쪽에서 출발한 (0, 2) 에서는 두 포인터를 모두 오른쪽으로만 옮길 수 있고 어느 쪽을 옮겨도 합이 7 로 커집니다. 그래서 합이 작다는 사실만으로는 어느 포인터를 옮길지 고를 수 없습니다. 양 끝에서는 R 을 옮기면 합이 9 로 작아지고 L 을 옮기면 14 로 커져서 합이 크냐 작냐에 따라 옮길 포인터가 하나로 정해집니다.

이 근거는 「L 과 R 사이의 값이 모두 nums[L] 이상이고 nums[R] 이하」라는 정렬의 성질 하나에 기대고 있습니다. 배열이 정렬돼 있지 않으면 같은 규칙이 답까지 버립니다.

## 4. 정렬하지 않으면 놓치는 이유

**같은 규칙을 정렬하지 않은 배열에 쓰면 L 과 R 사이에 nums[L] 보다 작은 값이 있을 수 있어서 합이 크다는 사실만으로 R 이 들어간 짝을 모두 버리면 답까지 버립니다. 2절의 값을 섞은 nums = [11, 3, 8, 1, 6, 4], target = 10 은 첫 비교에서 답 (4, 5) 를 버리고 짝을 찾지 못합니다.**

2절의 값 6개를 섞은 `nums = [11, 3, 8, 1, 6, 4]` 와 `target = 10` 에 같은 규칙을 씁니다. 합이 10 인 짝은 4번 칸의 6 과 5번 칸의 4 하나입니다. 첫 비교에서 L = 0 의 11 과 R = 5 의 4 를 더한 15 가 10 보다 크므로 규칙대로 R 을 옮기며 4 가 들어간 짝 5개를 버리는데, 답 (4, 5) 가 그 5개 안에 있습니다.

3절의 근거는 L 과 R 사이의 값이 모두 nums[L] 이상이라는 성질이었습니다. 이 배열에서 nums[L] 은 11 이고 4번 칸의 6 은 11 보다 작아서 6 + 4 = 10 이 11 + 4 = 15 보다 작습니다. 합 15 가 크다는 사실로는 4 가 들어간 짝이 모두 크다고 말할 수 없는데 규칙은 그 짝들을 버립니다. 이번 과외에서 저는 정렬이 안 돼 있으면 합이 컸을 때 어느 값을 골라야 합이 작아질지 알 수 없다고 설명했습니다. 아래 출력에서도 R 을 옮길 때마다 합이 17, 12, 19, 14 로 커졌다 작아졌다 합니다.

```python
# 하는 일: 2절의 값을 섞은 [11, 3, 8, 1, 6, 4], target 10 에 같은 투 포인터를 써서 짝을 놓치는 것을 보고, 모든 짝을 더해 실제 답을 찾은 뒤, 그 답을 몇 번째 비교에서 버렸는지 찍는다.

# 1단계: 비교마다 합과 버린 짝을 남기는 투 포인터를 만든다
# 2절, 3절과 같은 규칙이다. 배열이 정렬돼 있는지는 보지 않는다.
def two_pointer_log(nums, target):                         # (답이나 None, 비교 기록) 을 돌려준다
    left, right = 0, len(nums) - 1                         # 양 끝에서 출발한다
    log = []                                               # 비교마다 (L, R, 합, 버린 짝)
    while left < right:                                    # L 과 R 이 만나기 전까지
        total = nums[left] + nums[right]                   # 두 값의 합
        if total == target:                                # 합이 target 과 같으면
            log.append((left, right, total, []))           # 버리는 짝 없이 적고
            return (left, right), log                      # 답을 돌려준다
        if total > target:                                 # 합이 크면
            log.append((left, right, total, [(i, right) for i in range(left, right)]))   # R 이 들어간 짝을 버린다
            right -= 1                                     # R 을 왼쪽으로
        else:                                              # 합이 작으면
            log.append((left, right, total, [(left, j) for j in range(left + 1, right + 1)]))   # L 이 들어간 짝을 버린다
            left += 1                                      # L 을 오른쪽으로
    return None, log                                       # 만날 때까지 짝이 없으면 None

# 2단계: 섞은 배열에 쓴다
# 설명을 위해 2절의 값을 섞은 입력이다. 4번 칸의 6 과 5번 칸의 4 가 답이다.
nums, target = [11, 3, 8, 1, 6, 4], 10                     # 정렬하지 않은 값 6개
answer, log = two_pointer_log(nums, target)                # 투 포인터를 그대로 쓴다
for k, (l, r, total, gone) in enumerate(log, 1):           # 비교 하나씩
    move = 'R 을 왼쪽으로' if total > target else 'L 을 오른쪽으로'   # 옮긴 포인터
    print(f'비교 {k}: L = {l}, R = {r}, {nums[l]} + {nums[r]} = {total} → {move}, 버린 짝 {len(gone)}개')   # 합과 버린 짝 수
print(f'투 포인터의 답 {answer}')                           # 끝까지 짝을 찾지 못한다

# 3단계: 모든 짝을 더해 실제 답을 찾는다
n = len(nums)                                              # 값의 개수
real = [(i, j) for i in range(n) for j in range(i + 1, n) if nums[i] + nums[j] == target]   # i < j 인 짝을 모두 더한다
print(f'실제 짝 {real}')                                    # 합이 target 인 짝

# 4단계: 실제 답을 버린 비교를 찾는다
for k, (l, r, total, gone) in enumerate(log, 1):           # 비교 하나씩
    if real[0] in gone:                                    # 이 비교에서 답 짝을 버렸으면
        i, j = real[0]                                     # 답 짝의 두 인덱스
        print(f'답 {real[0]} 는 비교 {k} 에서 버렸다. 그 비교의 합 {nums[l]} + {nums[r]} = {total}, 답 짝의 합 {nums[i]} + {nums[j]} = {target}')   # 버린 비교와 답의 합

# 출력:
# 2단계 뜻: 합이 모두 10 보다 커서 R 만 다섯 번 옮기고 L 과 R 이 만나 None 이 나온다.
# 비교 1: L = 0, R = 5, 11 + 4 = 15 → R 을 왼쪽으로, 버린 짝 5개
# 비교 2: L = 0, R = 4, 11 + 6 = 17 → R 을 왼쪽으로, 버린 짝 4개
# 비교 3: L = 0, R = 3, 11 + 1 = 12 → R 을 왼쪽으로, 버린 짝 3개
# 비교 4: L = 0, R = 2, 11 + 8 = 19 → R 을 왼쪽으로, 버린 짝 2개
# 비교 5: L = 0, R = 1, 11 + 3 = 14 → R 을 왼쪽으로, 버린 짝 1개
# 투 포인터의 답 None
# 3단계 뜻: 모든 짝을 더해 보면 4번 칸과 5번 칸이 답이다.
# 실제 짝 [(4, 5)]
# 4단계 뜻: 답 짝은 합 15 가 크다는 이유로 첫 비교에서 버렸다.
# 답 (4, 5) 는 비교 1 에서 버렸다. 그 비교의 합 11 + 4 = 15, 답 짝의 합 6 + 4 = 10
```

투 포인터는 L 과 R 이 만날 때까지 짝을 찾지 못해 None 을 돌려줬습니다. 모든 짝을 더해 찾은 실제 짝 (4, 5) 는 합이 10 인데 첫 비교에서 합 15 가 크다는 이유로 버려졌습니다. 이 배열을 정렬하면 2절의 배열이 되어 투 포인터가 (2, 3) 을 찾지만 그 인덱스는 정렬한 배열의 자리라 원래 배열에서 6 과 4 가 있던 4번 칸과 5번 칸이 아닙니다.

아래 데모는 정렬하지 않은 입력에서 같은 규칙을 보여 줍니다. 「한 칸」을 한 번 누르면 이번 단계 칸이 「4와 짝이 되는 5개를 버립니다.」로 끝나고 짝 표에서 합이 10 인 (4, 5) 칸이 첫 단계부터 버린 짝으로 흐려집니다. 「끝까지」를 누르면 결과 칸에 「짝을 찾지 못했습니다」, 그 아랫줄에 「인덱스 4와 5(6 + 4)가 답인데 첫 비교에서 버렸습니다.」가 나옵니다. 비교한 짝 칸 아래에는 정렬된 입력과 달리 「정렬돼 있지 않아 L 보다 오른쪽 값이 L 의 값보다 작을 수 있습니다.」로 시작하는 근거가 나옵니다.

정렬하면 짝을 찾지만 자리가 바뀌므로 원래 자리를 돌려줘야 하는 문제는 정렬 비용 말고도 원래 인덱스를 지킬 메모리가 더 듭니다.

## 5. 정렬 비용과 해시 맵

**정렬되지 않은 배열에 투 포인터를 쓰려면 먼저 정렬해야 해서 시간은 정렬 O(N log N) 에 순회 O(N) 이 더해집니다. LeetCode 1 처럼 원래 인덱스를 돌려줘야 하면 정렬하기 전에 (값, 인덱스) 쌍 N개를 만들어야 해서 메모리가 O(N) 듭니다. 메모리가 같다면 O(N) 시간에 끝나는 해시 맵이 낫습니다.**

[해시 맵](post.html?id=algorithm-lesson-hash-map) 편 6절에서 해시의 비용을 이야기하며 저는 추가 메모리를 쓸 수 없으면 배열을 정렬한 뒤 투 포인터로 푼다고 덧붙였습니다. 이 말은 두 값만 돌려주면 되는 문제를 추가 메모리 O(1) 로 정렬할 때만 맞습니다. 파이썬의 `list.sort()` 는 정렬하며 임시 배열을 따로 쓰고, 원래 인덱스를 돌려줘야 하는 문제는 정렬하기 전에 원래 인덱스를 적어 둘 메모리가 더 듭니다. LeetCode 1 의 Two Sum 은 원래 배열의 인덱스를 돌려 달라고 하는데, 4절에서 보았듯이 정렬하면 값의 자리가 바뀌어 정렬한 배열의 인덱스로는 답을 만들 수 없습니다. 그래서 정렬하기 전에 값마다 원래 인덱스를 붙인 (값, 인덱스) 쌍을 만들고 그 쌍을 정렬해야 하며 쌍 N개가 메모리 O(N) 을 씁니다.

아래 코드는 LeetCode 1 의 첫 예제 [2, 7, 11, 15] 를 섞은 `[11, 2, 15, 7]`, `target = 9` 를 이 방식으로 풉니다. 값 2 와 7 은 이 배열의 1번 칸과 3번 칸에 있습니다. `trace` 는 단계를 찍으려고 이 글이 붙인 인자라 LeetCode 에 낼 때는 지워도 됩니다.

```python
# 하는 일: LeetCode 1 처럼 원래 인덱스를 돌려줘야 할 때 (값, 인덱스) 쌍을 정렬한 뒤 투 포인터로 [11, 2, 15, 7], target 9 의 원래 인덱스를 찾는다.
from typing import List                                    # LeetCode 화면의 List[int] 주석에 쓴다

# 1단계: (값, 인덱스) 쌍을 정렬하는 풀이를 만든다
# 정렬하면 값의 자리가 바뀌므로 원래 인덱스를 쌍에 함께 적어 둔다.
class Solution:                                            # LeetCode 가 정해 둔 클래스 이름 그대로 둔다
    def twoSum(self, nums: List[int], target: int, trace: bool = False) -> List[int]:   # trace 는 이 글이 붙인 인자
        pairs = sorted((num, i) for i, num in enumerate(nums))   # (값, 원래 인덱스) 쌍을 값 순서로 정렬한다
        if trace:                                          # 따라가기를 켰으면
            print(f'정렬한 쌍 {pairs}')                     # 정렬한 쌍을 찍는다
        left, right = 0, len(pairs) - 1                    # L 과 R 은 쌍 목록의 양 끝
        while left < right:                                # L 과 R 이 만나기 전까지
            total = pairs[left][0] + pairs[right][0]       # 두 쌍의 값을 더한다
            if trace:                                      # 따라가기를 켰으면
                print(f'L = {left}, R = {right}, {pairs[left][0]} + {pairs[right][0]} = {total}')   # 비교 하나를 찍는다
            if total == target:                            # 합이 target 과 같으면
                return [pairs[left][1], pairs[right][1]]   # 쌍에 적어 둔 원래 인덱스를 돌려준다
            if total > target:                             # 합이 크면
                right -= 1                                 # R 을 왼쪽으로
            else:                                          # 합이 작으면
                left += 1                                  # L 을 오른쪽으로
        return []                                          # 짝이 없으면 빈 목록

# 2단계: 섞은 입력을 푼다
answer = Solution().twoSum([11, 2, 15, 7], 9, trace=True)  # 단계를 찍으며 푼다
print(f'답 {answer}')                                       # 원래 배열의 인덱스

# 출력:
# 2단계 뜻: 정렬한 쌍에서 합 17, 13, 9 로 세 번 비교해 값 2 와 7 을 찾고 쌍에 적어 둔 원래 인덱스 1 과 3 을 돌려준다.
# 정렬한 쌍 [(2, 1), (7, 3), (11, 0), (15, 2)]
# L = 0, R = 3, 2 + 15 = 17
# L = 0, R = 2, 2 + 11 = 13
# L = 0, R = 1, 2 + 7 = 9
# 답 [1, 3]
```

정렬한 쌍에서 세 번 비교해 값 2 와 7 을 찾았고 쌍에 적어 둔 원래 인덱스 1 과 3 을 돌려줬습니다. 시간은 정렬 O(N log N) 에 순회 O(N) 이 더해져 O(N log N) 이고 쌍을 담는 메모리는 O(N) 입니다. 해시 맵 편의 seen 풀이는 같은 문제를 O(N) 시간, O(N) 메모리로 풀므로 원래 인덱스를 돌려줘야 하면 메모리는 같고 시간 복잡도는 해시 맵이 O(N) 으로 낮습니다.

두 값만 돌려주면 되는 문제라면 쌍을 만들지 않고 `nums.sort()` 로 배열 자체를 정렬한 뒤 투 포인터를 씁니다. 투 포인터의 순회가 쓰는 추가 메모리는 L 과 R 두 변수라 O(1) 이지만 정렬이 쓰는 메모리는 따로 셉니다. CPython(python.org 에서 내려받아 쓰는 표준 파이썬 구현) 3.9 의 `list.sort()` 는 제자리에서 정렬하면서도 정렬된 두 구간을 합칠 때 임시 배열을 씁니다. 소스 문서 [listsort.txt](https://github.com/python/cpython/blob/3.9/Objects/listsort.txt) 는 그 임시 배열이 많아야 N//2 개의 포인터이고 무작위 데이터를 정렬할 때는 그만큼 쓴다고 적고 있습니다. 그래서 `list.sort()` 로 정렬하면 추가 메모리가 O(N) 까지 듭니다. 투 포인터의 추가 메모리가 O(1) 이라는 말은 6절의 LeetCode 167 처럼 정렬된 배열이 처음부터 주어지거나 힙 정렬처럼 추가 메모리 O(1) 로 정렬하는 방법을 직접 짜서 쓸 때 맞습니다.

값이 10,000개면 투 포인터의 비교는 많아야 10,000 - 1 = 9,999번이고 이중 for 문이 더해 보는 짝은 10,000 × 9,999 / 2 = 49,995,000개입니다. 해시 맵도 seen 확인이 많아야 10,000번이라 정렬되지 않은 배열에서 원래 인덱스를 돌려줄 때는 해시 맵을, 정렬된 배열이 주어지면 추가 메모리가 O(1) 인 투 포인터를 고릅니다.

## 6. Two Sum II (LeetCode 167, Medium)

**LeetCode 167 은 작은 값부터 정렬된 배열에서 합이 target 인 두 값의 위치를 1부터 센 번호로 돌려 달라고 하고 추가 메모리는 상수만 쓰게 합니다. 이미 정렬돼 있으므로 2절의 투 포인터를 그대로 쓰고 답을 돌려줄 때만 두 인덱스에 1씩 더합니다.**

[LeetCode 167. Two Sum II - Input Array Is Sorted](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/) 는 작은 값부터 정렬된 정수 배열 `numbers` 와 정수 `target` 을 주고 더해서 `target` 이 되는 두 값의 위치를 `[index1, index2]` 로 돌려 달라고 합니다. 위치는 1부터 세고 index1 이 index2 보다 작습니다. 답은 정확히 하나이고 같은 칸을 두 번 쓸 수 없습니다. 첫 예제 `numbers = [2, 7, 11, 15]`, `target = 9` 는 2 + 7 = 9 라서 0부터 센 인덱스 0 과 1 에 1씩 더한 `[1, 2]` 가 답입니다. 과외에서 정렬된 Two Sum 으로 다룬 문제입니다.

이 문제에 투 포인터를 쓰는 까닭은 두 가지입니다. 배열이 처음부터 정렬돼 있어 3절의 근거가 그대로 성립합니다. 또 추가 메모리를 상수만 쓰라는 조건 때문에 숫자를 N개까지 적는 해시 맵의 seen 을 쓸 수 없습니다.

1. L 을 0, R 을 마지막 인덱스에 둡니다.
2. 두 값의 합을 `target` 과 비교합니다.
3. 같으면 L + 1 과 R + 1 을 돌려줍니다.
4. 크면 R 을 왼쪽으로, 작으면 L 을 오른쪽으로 한 칸 옮기고 2번으로 돌아갑니다.

```python
# 하는 일: LeetCode 167 을 투 포인터로 풀어 세 예제에서 1부터 센 답과 비교 횟수를 찍는다.
from typing import List                                    # LeetCode 화면의 List[int] 주석에 쓴다

# 1단계: 풀이를 만든다
# 2절의 투 포인터와 같고 답을 돌려줄 때만 두 인덱스에 1을 더한다.
class Solution:                                            # LeetCode 가 정해 둔 클래스 이름 그대로 둔다
    def twoSum(self, numbers: List[int], target: int) -> List[int]:   # LeetCode 가 부르는 함수
        self.comparisons = 0                               # 비교한 횟수. 세려고 이 글이 붙인 값
        left, right = 0, len(numbers) - 1                  # L 은 맨 왼쪽, R 은 맨 오른쪽
        while left < right:                                # L 과 R 이 만나기 전까지
            total = numbers[left] + numbers[right]         # 두 값의 합
            self.comparisons += 1                          # 비교를 하나 센다
            if total == target:                            # 합이 target 과 같으면
                return [left + 1, right + 1]               # 1부터 센 번호로 돌려준다
            if total > target:                             # 합이 크면
                right -= 1                                 # R 을 왼쪽으로
            else:                                          # 합이 작으면
                left += 1                                  # L 을 오른쪽으로
        return []                                          # 답이 꼭 있다는 조건이지만 함수가 끝나도록 둔다

# 2단계: 세 예제를 돌린다
for numbers, target in (([2, 7, 11, 15], 9), ([2, 3, 4], 6), ([-1, 0], -1)):   # LeetCode 의 세 예제
    s = Solution()                                         # 풀이 객체
    answer = s.twoSum(numbers, target)                     # 1부터 센 답
    print(f'{numbers}, target {target} → {answer}, 비교 {s.comparisons}번')   # 답과 비교 횟수

# 출력:
# 2단계 뜻: 세 예제 모두 0부터 센 두 인덱스에 1을 더한 답이 나온다.
# [2, 7, 11, 15], target 9 → [1, 2], 비교 3번
# [2, 3, 4], target 6 → [1, 3], 비교 1번
# [-1, 0], target -1 → [1, 2], 비교 1번
```

첫 예제는 합 17 과 13 이 커서 R 을 두 번 옮긴 뒤 세 번째 비교에서 2 + 7 = 9 를 찾았고 0부터 센 0 과 1 에 1씩 더해 `[1, 2]` 를 돌려줬습니다. 둘째 예제는 양 끝의 합이 바로 답이고 셋째 예제는 값이 2개뿐이라 둘 다 비교 한 번으로 끝납니다. 시간 복잡도는 비교가 많아야 N - 1 번이라 O(N), 공간 복잡도는 L 과 R 만 쓰므로 O(1) 입니다.

[전체 데모](demo-lesson-two-pointers.html)에서 「입력」을 nums [2, 7, 11, 15], target 9 로 고르고 「끝까지」를 누르면 결과 칸에 0부터 센 「2 + 7 = 9, 인덱스 0과 1」과 그 아랫줄 「짝 6개 가운데 비교 3번」이 나옵니다. 데모와 2절의 코드는 0부터 센 인덱스를 보이므로 LeetCode 에 낼 답은 여기에 1씩 더한 `[1, 2]` 입니다.

## 7. Valid Palindrome (LeetCode 125, Easy)

**문자열에서 글자와 숫자만 남기고 대문자를 소문자로 바꿨을 때 앞에서 읽으나 뒤에서 읽으나 같으면 True 입니다. 양 끝에 포인터를 두고 글자와 숫자가 아닌 문자는 건너뛰며 두 문자를 비교하고 같으면 두 포인터를 함께 안쪽으로 옮깁니다. 이 문제의 투 포인터는 정렬이 필요 없습니다.**

[LeetCode 125. Valid Palindrome](https://leetcode.com/problems/valid-palindrome/) 은 문자열 `s` 를 주고 대문자를 소문자로 바꾸고 글자와 숫자가 아닌 문자를 모두 뺀 문자열이 회문(palindrome, 앞에서 읽으나 뒤에서 읽으나 같은 문자열)이면 True, 아니면 False 를 돌려 달라고 합니다. 첫 예제 `"A man, a plan, a canal: Panama"` 는 글자만 남기면 `"amanaplanacanalpanama"` 라 True 입니다. 공백 하나뿐인 `" "` 는 남는 문자가 없어 빈 문자열이 되고 빈 문자열은 회문이라 True 입니다.

회문인지는 앞에서 k번째 문자와 뒤에서 k번째 문자가 모두 같은지로 정해지므로 왼쪽 끝과 오른쪽 끝에서 출발해 안쪽으로 좁혀 오는 투 포인터가 그 비교 순서와 같습니다. Two Sum 과 달리 어느 포인터를 옮길지 고를 일이 없어서 정렬이 필요 없습니다. 두 문자가 같으면 둘 다 옮기고 다르면 그 자리에서 False 를 돌려줍니다.

1. L 을 0, R 을 마지막 인덱스에 둡니다.
2. L 의 문자가 글자나 숫자가 아니면 L 을 오른쪽으로, R 의 문자가 글자나 숫자가 아니면 R 을 왼쪽으로 옮기고 다시 봅니다.
3. 두 문자를 소문자로 바꿔 비교해 다르면 False 를 돌려줍니다.
4. 같으면 L 을 오른쪽으로, R 을 왼쪽으로 한 칸씩 옮깁니다. L 과 R 이 만나면 True 를 돌려줍니다.

`cleaned = ''.join(c.lower() for c in s if c.isalnum())` 로 글자만 남긴 뒤 `cleaned == cleaned[::-1]` 로 비교하는 한 줄 풀이도 같은 답을 냅니다. 다만 이 풀이는 남긴 문자열과 뒤집은 문자열을 새로 만들어 메모리 O(N) 을 씁니다. 아래 코드는 세 예제를 두 풀이로 돌리고 투 포인터가 문자를 몇 번 비교했는지 셉니다.

```python
# 하는 일: LeetCode 125 를 투 포인터로 풀어 세 예제에서 답과 문자 비교 횟수를 찍고, 글자만 남겨 뒤집어 보는 한 줄 풀이와 답이 같은지 본다.

# 1단계: 풀이를 만든다
# 글자와 숫자가 아닌 문자는 건너뛰고, 남은 두 문자를 소문자로 바꿔 비교한다.
class Solution:                                            # LeetCode 가 정해 둔 클래스 이름 그대로 둔다
    def isPalindrome(self, s: str) -> bool:                # LeetCode 가 부르는 함수
        self.comparisons = 0                               # 문자를 비교한 횟수. 세려고 이 글이 붙인 값
        left, right = 0, len(s) - 1                        # L 은 맨 앞, R 은 맨 뒤 문자
        while left < right:                                # L 과 R 이 만나기 전까지
            if not s[left].isalnum():                      # L 의 문자가 글자나 숫자가 아니면
                left += 1                                  # 건너뛴다
                continue                                   # 다시 본다
            if not s[right].isalnum():                     # R 의 문자가 글자나 숫자가 아니면
                right -= 1                                 # 건너뛴다
                continue                                   # 다시 본다
            self.comparisons += 1                          # 두 문자를 비교한다
            if s[left].lower() != s[right].lower():        # 소문자로 바꿔도 다르면
                return False                               # 회문이 아니다
            left += 1                                      # 같으면 L 을 안쪽으로
            right -= 1                                     # R 도 안쪽으로
        return True                                        # 끝까지 같았으면 회문이다

# 2단계: 세 예제를 두 풀이로 돌린다
for s in ("A man, a plan, a canal: Panama", "race a car", " "):   # LeetCode 의 세 예제
    sol = Solution()                                       # 풀이 객체
    answer = sol.isPalindrome(s)                           # 투 포인터 풀이
    cleaned = ''.join(c.lower() for c in s if c.isalnum())  # 글자와 숫자만 소문자로 남긴다
    print(f'{s!r} → {answer}, 문자 비교 {sol.comparisons}번, 한 줄 풀이 {cleaned == cleaned[::-1]} ({cleaned!r})')   # 두 답과 남긴 문자열

# 출력:
# 2단계 뜻: 두 풀이의 답이 같고, 투 포인터는 다른 문자를 만나면 그 자리에서 멈춘다.
# 'A man, a plan, a canal: Panama' → True, 문자 비교 10번, 한 줄 풀이 True ('amanaplanacanalpanama')
# 'race a car' → False, 문자 비교 4번, 한 줄 풀이 False ('raceacar')
# ' ' → True, 문자 비교 0번, 한 줄 풀이 True ('')
```

세 예제의 답은 True, False, True 이고 한 줄 풀이도 같습니다. 첫 예제는 남긴 문자 21개에서 가운데 문자를 뺀 (21 - 1) / 2 = 10쌍을 모두 비교했습니다. 둘째 예제는 네 번째 비교에서 `'e'` 와 `'a'` 가 달라 바로 False 를 돌려줬습니다. 셋째 예제는 문자가 하나뿐이라 L 과 R 이 처음부터 같은 자리에 있어 한 번도 비교하지 않고 True 를 돌려줍니다. 시간 복잡도는 문자마다 많아야 한 번씩 보므로 O(N), 공간 복잡도는 L 과 R 만 쓰므로 O(1) 이고 한 줄 풀이는 O(N) 입니다.

## 8. 3Sum (LeetCode 15, Medium)

**배열을 정렬한 뒤 첫째 값을 하나씩 고정하고 고정한 값 뒤의 구간에서 합이 고정한 값의 음수가 되는 두 값을 투 포인터로 찾습니다. 정렬돼 붙어 있는 같은 값은 고정할 때와 답을 찾은 뒤에 건너뛰어 같은 조합을 두 번 담지 않습니다.**

[LeetCode 15. 3Sum](https://leetcode.com/problems/3sum/) 은 정수 배열 `nums` 에서 서로 다른 세 칸의 값을 더해 0 이 되는 조합을 모두 돌려 달라고 합니다. 값이 같은 조합은 한 번만 담습니다. 조합의 순서와 조합 안 값의 순서는 상관없습니다. 첫 예제 `[-1, 0, 1, 2, -1, -4]` 의 답은 `[-1, -1, 2]` 와 `[-1, 0, 1]` 두 조합입니다. 0번 칸의 -1 과 4번 칸의 -1 이 각각 0 과 1 을 만나 만드는 `[-1, 0, 1]` 은 하나로 셉니다.

값 하나를 고정하면 남은 두 값은 더해서 고정한 값의 음수가 되어야 하므로 Two Sum 과 같은 문제가 됩니다. 배열을 정렬해 두면 그 Two Sum 을 투 포인터로 풀 수 있고 같은 값이 서로 붙어 있어서 앞 칸과 같은 값만 건너뛰면 같은 조합을 다시 만들지 않습니다.

1. 배열을 작은 값부터 정렬합니다.
2. i 를 0 부터 끝에서 세 번째 칸까지 옮기며 `nums[i]` 를 고정합니다. 앞 칸과 같은 값이면 건너뜁니다.
3. L 을 i + 1, R 을 마지막 칸에 두고 세 값의 합이 0 보다 작으면 L 을, 크면 R 을 옮깁니다.
4. 합이 0 이면 조합을 담고 L 과 R 을 한 칸씩 안쪽으로 옮긴 뒤, L 의 값이 바로 앞 칸과 같은 동안 L 을 더 옮깁니다.

아래 코드의 `trace` 는 고정한 값마다 찾은 조합을 찍으려고, `skip_same` 은 같은 값 건너뛰기를 끄고 돌려 보려고 이 글이 붙인 인자입니다. LeetCode 에 낼 때는 둘 다 지워도 됩니다.

```python
# 하는 일: LeetCode 15 를 정렬과 투 포인터로 풀어 첫 예제에서 고정한 값마다 찾은 조합을 찍고, 세 예제의 답을 찍은 뒤, 같은 값 건너뛰기를 끄면 같은 조합이 두 번 담기는 것을 본다.
from typing import List                                    # LeetCode 화면의 List[int] 주석에 쓴다

# 1단계: 풀이를 만든다
# 정렬한 뒤 nums[i] 를 고정하고 i 뒤의 구간에서 L 과 R 로 합이 -nums[i] 인 두 값을 찾는다.
class Solution:                                            # LeetCode 가 정해 둔 클래스 이름 그대로 둔다
    def threeSum(self, nums: List[int], trace: bool = False, skip_same: bool = True) -> List[List[int]]:   # trace, skip_same 은 이 글이 붙인 인자
        nums.sort()                                        # 작은 값부터 제자리에서 정렬한다
        if trace:                                          # 따라가기를 켰으면
            print(f'정렬한 배열 {nums}')                    # 정렬한 배열을 찍는다
        result = []                                        # 찾은 조합
        for i in range(len(nums) - 2):                     # 끝에서 세 번째 칸까지 고정한다
            if skip_same and i > 0 and nums[i] == nums[i - 1]:   # 앞 칸과 같은 값이면
                if trace:                                  # 따라가기를 켰으면
                    print(f'i = {i}, 고정 {nums[i]}: 앞 칸과 같은 값이라 건너뜀')   # 건너뛴 것을 찍는다
                continue                                   # 같은 조합을 다시 만들지 않는다
            found = []                                     # 이 고정 값에서 찾은 조합
            left, right = i + 1, len(nums) - 1             # L 은 고정한 값 바로 뒤, R 은 맨 끝
            while left < right:                            # L 과 R 이 만나기 전까지
                total = nums[i] + nums[left] + nums[right] # 세 값의 합
                if total == 0:                             # 0 이면
                    found.append([nums[i], nums[left], nums[right]])   # 조합을 담는다
                    left += 1                              # L 을 안쪽으로
                    right -= 1                             # R 도 안쪽으로
                    while skip_same and left < right and nums[left] == nums[left - 1]:   # L 이 방금 쓴 값과 같으면
                        left += 1                          # 같은 값을 건너뛴다
                elif total < 0:                            # 합이 작으면
                    left += 1                              # L 을 오른쪽으로
                else:                                      # 합이 크면
                    right -= 1                             # R 을 왼쪽으로
            if trace:                                      # 따라가기를 켰으면
                print(f'i = {i}, 고정 {nums[i]}: 찾은 조합 {found}')   # 이 고정 값의 결과를 찍는다
            result.extend(found)                           # 전체 답에 더한다
        return result                                      # 찾은 조합 전부

# 2단계: 첫 예제를 따라간다
print(f'답 {Solution().threeSum([-1, 0, 1, 2, -1, -4], trace=True)}')   # 고정한 값마다 찍는다

# 3단계: 나머지 두 예제를 돌린다
print(f'[0, 1, 1] → {Solution().threeSum([0, 1, 1])}')     # 합이 0 인 조합이 없다
print(f'[0, 0, 0] → {Solution().threeSum([0, 0, 0])}')     # 0 세 개가 조합 하나

# 4단계: 같은 값 건너뛰기를 끄고 첫 예제를 돌린다
print(f'건너뛰기를 끄면 {Solution().threeSum([-1, 0, 1, 2, -1, -4], skip_same=False)}')   # 같은 조합이 두 번 담긴다

# 출력:
# 2단계 뜻: i = 1 의 -1 을 고정했을 때 두 조합을 찾고, 같은 값인 i = 2 의 -1 은 건너뛴다.
# 정렬한 배열 [-4, -1, -1, 0, 1, 2]
# i = 0, 고정 -4: 찾은 조합 []
# i = 1, 고정 -1: 찾은 조합 [[-1, -1, 2], [-1, 0, 1]]
# i = 2, 고정 -1: 앞 칸과 같은 값이라 건너뜀
# i = 3, 고정 0: 찾은 조합 []
# 답 [[-1, -1, 2], [-1, 0, 1]]
# 3단계 뜻: [0, 1, 1] 은 합이 0 인 조합이 없고 [0, 0, 0] 은 조합 하나다.
# [0, 1, 1] → []
# [0, 0, 0] → [[0, 0, 0]]
# 4단계 뜻: 건너뛰기를 끄면 i = 2 의 -1 이 [-1, 0, 1] 을 다시 만든다.
# 건너뛰기를 끄면 [[-1, -1, 2], [-1, 0, 1], [-1, 0, 1]]
```

정렬한 배열은 [-4, -1, -1, 0, 1, 2] 이고 i = 1 의 -1 을 고정했을 때 두 조합을 모두 찾았습니다. i = 2 의 -1 은 앞 칸과 같은 값이라 건너뛰었는데, 넷째 단계처럼 건너뛰기를 끄면 이 -1 이 0 과 1 을 다시 만나 `[-1, 0, 1]` 이 두 번 담깁니다. 정렬하지 않고 해시로 풀면 같은 조합을 거르려고 조합마다 세 값을 정렬해 set 에 넣는 식으로 걸러야 하지만 정렬해 두면 앞 칸과 값만 비교해서 거릅니다.

시간 복잡도는 정렬 O(N log N) 뒤에 고정한 값 N개마다 투 포인터가 O(N) 이라 O(N²) 이고 1절에서 본 대로 정렬하지 않고 해시로 풀어도 O(N²) 입니다. 공간 복잡도는 답 목록을 빼면 정렬이 쓰는 임시 배열뿐이라 5절의 CPython 3.9 기준으로 많아야 N//2 개의 포인터, O(N) 입니다.

## 한눈 정리

| 문제 | 쓰는 방법 | 시간 | 추가 메모리 | 이 글의 예 |
|---|---|---|---|---|
| 정렬된 배열의 Two Sum (167) | 양 끝에서 투 포인터 | O(N) | O(1) | `[1, 3, 4, 6, 8, 11]`, 10 → 0부터 센 (2, 3) |
| 정렬되지 않은 배열, 두 값만 돌려줌 | 정렬한 뒤 투 포인터 | O(N log N) | 정렬이 쓰는 임시 배열 | `[11, 3, 8, 1, 6, 4]` 를 정렬하면 4 와 6 |
| 정렬되지 않은 배열, 원래 인덱스를 돌려줌 (1) | 해시 맵. 투 포인터면 (값, 인덱스) 쌍을 정렬 | O(N), 쌍을 정렬하면 O(N log N) | O(N) | `[11, 2, 15, 7]`, 9 → `[1, 3]` |
| Valid Palindrome (125) | 양 끝에서 투 포인터, 정렬하지 않음 | O(N) | O(1) | `"race a car"` → False |
| 3Sum (15) | 정렬, 값 하나 고정, 투 포인터 | O(N²) | 정렬이 쓰는 임시 배열 | `[-1, 0, 1, 2, -1, -4]` → 조합 2개 |

투 포인터를 쓰는 경우는 모두 L 과 R 을 구간의 양 끝에 두고 안쪽으로만 옮기므로 한 번 좁혀 오는 동안 비교는 많아야 N - 1 번입니다. 3Sum 은 고정한 값마다 그 뒤의 구간에서 한 번씩 좁혀 와서 O(N²) 입니다. Two Sum 과 3Sum 에서 포인터를 하나만 골라 옮겨도 답을 놓치지 않는 근거는 배열이 정렬돼 있다는 것 하나입니다. 회문은 양 끝의 두 문자를 비교하는 문제라 정렬 없이 씁니다.

## 헷갈리기 쉬운 점

- **투 포인터는 정렬된 배열에서만 짝을 놓치지 않습니다.** 합이 크면 R 이 들어간 짝을 모두 버리는 근거가 L 과 R 사이의 값이 모두 nums[L] 이상이라는 정렬의 성질입니다. `[11, 3, 8, 1, 6, 4]`, target 10 에서는 첫 비교에서 답 (4, 5) 를 버립니다.
- **합이 크면 R 을 옮겨도 합이 늘 작아지지는 않습니다.** `[1, 2, 5, 5]` 처럼 같은 값이 이어지면 합이 그대로입니다. R 을 옮겨도 되는 까닭은 합이 작아져서가 아니라 R 이 들어간 짝이 모두 답이 될 수 없어서입니다.
- **비교는 많아야 N - 1 번입니다.** 비교마다 R - L 이 1 줄기 때문입니다. 값 10,000개면 10,000 - 1 = 9,999번이고 이중 for 문의 짝은 10,000 × 9,999 / 2 = 49,995,000개입니다.
- **LeetCode 167 의 답은 1부터 셉니다.** 데모와 2절의 코드는 인덱스를 0부터 세므로 `[2, 7, 11, 15]`, target 9 의 답이 (0, 1) 이고 LeetCode 에 내는 답은 `[1, 2]` 입니다.
- **정렬하면 원래 인덱스가 사라집니다.** LeetCode 1 처럼 원래 인덱스를 돌려줘야 하면 (값, 인덱스) 쌍을 정렬해야 해서 메모리 O(N) 이 들고 그때는 O(N) 시간의 해시 맵을 씁니다.
- **`list.sort()` 로 직접 정렬하면 추가 메모리가 O(1) 이 아닙니다.** CPython 3.9 의 `list.sort()` 는 임시 배열을 많아야 N//2 개의 포인터만큼 쓰고 무작위 데이터에서는 그만큼 씁니다. 투 포인터의 추가 메모리 O(1) 은 정렬된 배열이 주어지거나 추가 메모리 O(1) 로 정렬할 때 맞습니다.
- **이 글의 투 포인터와 슬라이딩 윈도우는 인덱스가 움직이는 방향이 다릅니다.** 둘 다 인덱스 두 개를 옮기며 배열을 순회하지만 이 글의 투 포인터는 양 끝에서 출발해 마주 보며 안쪽으로 좁혀 옵니다. 두 인덱스가 같은 방향으로 움직이며 그 사이의 붙어 있는 구간을 보는 꼴은 따로 슬라이딩 윈도우라고 부릅니다. 슬라이딩 윈도우는 이 시리즈의 [슬라이딩 윈도우](post.html?id=algorithm-lesson-sliding-window) 편에서 다루고 [복잡도와 배열 순회](post.html?id=algorithm-complexity-array) 편 8절에도 짧게 있습니다.
- **3Sum 은 정렬해도 O(N²) 입니다.** 정렬은 시간 복잡도를 줄이지 않고 같은 값을 앞 칸과 비교해 건너뛰게 해 줍니다.
