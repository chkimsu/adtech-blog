지훈은 앞 편에서 배운 대로 리스트를 집합(같은 값을 두 번 담지 않고 값이 들어 있는지 확인할 때 쓰는 자료형)으로 바꿔 시간 초과를 넘겼습니다. 그런데 다음 문제에서 다시 막혔습니다. 이번에는 값이 있는지가 아니라 **몇 번 칸에 있는지**를 물었습니다.

집합은 값을 넣어 두기만 할 뿐 자리를 기억하지 않습니다. 그렇다고 리스트로 되돌리면 다시 느려집니다. 지훈에게는 빠르면서 자리도 같이 기억하는 자료형이 필요했습니다.

**값 하나로 다른 값을 즉시 꺼내려면 무엇이 필요할까요?**

답은 딕셔너리(값 하나에 다른 값 하나를 짝지어 담아 두는 자료형)이고 딕셔너리가 빠른 이유는 **해시**입니다. 이 글은 해시가 무엇인지, 왜 가끔 느려지는지, 그리고 해시로 안 되는 문제를 정렬로 어떻게 넘기는지를 다룹니다.

> **한 줄 요약:** 딕셔너리는 값을 스캔(앞에서부터 하나씩 비교)하지 않고 값에서 자리를 계산합니다. 그래서 20만 개 가운데서 값을 찾을 때 리스트보다 만 배 넘게 빠릅니다. 정렬(값을 기준에 따라 순서대로 늘어놓는 일)은 이 계산이 안 통할 때 쓰는 두 번째 도구입니다.

> **골라 읽는 법** — 절이 열 개인 글입니다. 순서대로 읽지 않아도 됩니다.
>
> - 딕셔너리가 왜 빠른지, 언제 느려지는지 → 앞의 세 절
> - 무엇을 키로 쓸 수 있나 → 키 절
> - 문제 풀이에 바로 쓰는 것 → 두 수의 합부터 집합 연산까지
> - 정렬 이야기만 → 뒤의 세 절

## 1. 리스트와 딕셔너리의 찾기 속도

**리스트는 값을 찾을 때 앞에서부터 하나씩 비교합니다.**

리스트(값을 번호 붙은 칸에 차례로 담는 자료형)는 첫 칸부터 차례로 비교하는 스캔으로 값을 찾으므로 담긴 값이 많을수록 비교할 칸도 늘어납니다. 지훈이 리스트로 되돌리면 다시 느려지는 까닭도 이 스캔에 있습니다. 앞 편에서 리스트와 집합으로 이 차이를 한 번 봤는데, 여기서는 같은 값 20만 개를 리스트와 딕셔너리에 담아 두고 2천 개를 찾는 데 걸린 시간을 측정해 그 차이가 얼마나 벌어지는지 확인합니다. 코드의 `as_dict` 에는 값마다 그 값이 리스트의 몇 번 칸에 있는지를 짝지어 담았습니다.

```python
# 하는 일: 값 20만 개를 리스트와 딕셔너리에 담아 두고, 2천 개를 찾는 데 걸린 시간을 비교한다.
import time, random

# 1단계: 담을 값 20만 개와 찾을 값 2천 개를 뽑는다
# 같은 값 20만 개를 리스트와 딕셔너리 두 곳에 담는다.
random.seed(42)
haystack = random.sample(range(1, 1_000_000), 200_000)
needles  = random.sample(range(1, 1_000_000), 2_000)

as_list = haystack
as_dict = {v: i for i, v in enumerate(haystack)}

# 2단계: 두 곳에서 2천 번씩 찾는다
# 리스트는 앞에서부터 스캔하고, 딕셔너리는 자리를 계산한다.
t = time.perf_counter()
for x in needles:
    x in as_list
list_ms = (time.perf_counter() - t) * 1000

t = time.perf_counter()
for x in needles:
    x in as_dict
dict_ms = (time.perf_counter() - t) * 1000

# 3단계: 걸린 시간과 배수를 찍는다
print(f"{'담은 곳':<10}{'2,000번 찾기(ms)':>18}")
print(f"{'리스트':<10}{list_ms:>18.1f}")
print(f"{'딕셔너리':<9}{dict_ms:>18.3f}")
print(f"\n딕셔너리가 {list_ms/dict_ms:,.0f}배 빠르다")

# 출력 (시간은 돌릴 때마다 다르다):
# 3단계 뜻: 같은 2천 번 찾기에 리스트는 7초 가까이, 딕셔너리는 0.4밀리초쯤 걸린다. 배수는 돌릴 때마다 만 배 안팎에서 오르내린다.
# 담은 곳           2,000번 찾기(ms)
# 리스트                   6902.2
# 딕셔너리                  0.381
#
# 딕셔너리가 18,140배 빠르다
```

같은 2천 번 찾기에 리스트는 6902.2밀리초(7초 가까이)가 걸렸고 딕셔너리는 0.381밀리초가 걸려 18,140배 차이가 났습니다. 채점 서버의 제한 시간이 보통 1초에서 2초이니 리스트 쪽 코드는 그대로 떨어집니다. 절대 시간은 기계마다 다르고 배수도 실행할 때마다 만 배 안팎에서 오르내립니다. 그래도 리스트는 하나씩 비교하고 딕셔너리는 자리를 계산하므로 출력의 리스트 줄과 딕셔너리 줄이 다른 종류라는 결론은 어디서 돌려도 같습니다.

두 줄의 차이는 코드가 아니라 자료형에서 나왔습니다. 찾는 코드는 둘 다 `x in` 한 줄로 같고 값을 리스트에 담았느냐 딕셔너리에 담았느냐만 다른데 만 배가 넘게 벌어졌습니다. **그래서 알고리즘 문제에서는 어떤 자료형을 고르느냐가 어떤 알고리즘을 고르느냐만큼 실행 시간을 좌우합니다.**

## 2. 해시 — 값에서 자리를 계산하는 방식

**딕셔너리는 값을 하나씩 비교해 찾지 않고 값에서 자리를 계산한 뒤 그 자리만 확인합니다.**

딕셔너리 안에는 값을 넣는 자리인 빈 슬롯(slot)이 여러 개 늘어서 있습니다. 값을 넣을 때 파이썬은 먼저 그 값을 정수 하나로 바꿉니다. 이 정수가 **해시값**이고 `hash()` 로 직접 볼 수 있습니다. 해시값을 슬롯 개수로 나눈 나머지가 그 값을 넣을 슬롯 번호입니다. 이렇게 값에서 자리를 계산해 넣고 찾는 방식을 **해시**라고 합니다.

## 3. 충돌 — 같은 슬롯에 몰리는 값

**서로 다른 값이 같은 슬롯을 가리키는 일을 충돌이라고 합니다. 충돌이 심해지면 딕셔너리도 리스트처럼 느려집니다.**

슬롯은 유한하고 넣을 값은 무한하므로 충돌은 반드시 생깁니다. 충돌이 나면 파이썬은 그 슬롯에 이미 있던 값과 새 값이 진짜 같은지를 `==` 로 한 번 비교한 뒤 다른 값이면 다음 빈 슬롯을 찾아 옮겨 담습니다. 충돌이 몇 번 안 되면 이 추가 비교도 몇 번뿐이라 느려진 것이 눈에 띄지 않습니다.

문제는 모든 값이 같은 슬롯으로 몰릴 때입니다. 그러면 새 값을 넣을 때마다 그 슬롯에 몰린 앞의 값들을 전부 지나쳐야 하니 결국 리스트에서 스캔하는 것과 같아집니다. 딕셔너리가 짝지어 담는 두 값 가운데 자리를 계산하는 데 쓰는 앞의 값을 키(key)라고 합니다. 코드로 쓰면 `d[k]` 의 `k` 가 키입니다. 얼마나 느려지는지 보려고 키를 두 가지로 만들어 5천 개씩 담아 보겠습니다. 좋은 키는 해시값이 값마다 다릅니다. 나쁜 키는 해시값을 일부러 7 로 고정해서 모든 값이 한 슬롯에 몰립니다.

```python
# 하는 일: 해시값이 값마다 다른 키와 늘 7 인 키를 만들어 딕셔너리에 5천 개씩 담고, 담는 데 걸린 시간을 비교한다.
import time

# 1단계: 좋은 키와 나쁜 키를 만든다
# 나쁜 키는 해시값을 일부러 7 로 고정해서 모든 값이 한 슬롯에 몰리게 만든다.
class GoodKey:
    def __init__(self, v): self.v = v
    def __hash__(self):    return hash(self.v)      # 값마다 다른 번호
    def __eq__(self, o):   return self.v == o.v

class BadKey:
    def __init__(self, v): self.v = v
    def __hash__(self):    return 7                 # 전부 같은 번호
    def __eq__(self, o):   return self.v == o.v

# 2단계: 키마다 5천 개를 담으며 시간을 측정한다
print(f"{'키':<8}{'담는 데 걸린 시간(ms)':>22}")
for name, K in (("좋은", GoodKey), ("나쁜", BadKey)):
    t = time.perf_counter()
    d = {K(i): i for i in range(5_000)}
    ms = (time.perf_counter() - t) * 1000
    print(f"{name:<8}{ms:>22.1f}")

# 출력 (시간은 돌릴 때마다 다르다):
# 2단계 뜻: 같은 5천 개인데 나쁜 키는 수백 배 오래 걸린다. 넣을 때마다 한 슬롯에 몰린 앞의 값들을 전부 지나치기 때문이다.
# 키               담는 데 걸린 시간(ms)
# 좋은                         1.6
# 나쁜                       701.9
```

같은 5천 개를 담는 데 좋은 키는 1.6밀리초면 끝났지만 나쁜 키는 701.9밀리초가 걸려 수백 배 느렸고 0.7초를 더 썼습니다. 나쁜 키는 값을 넣을 때마다 한 슬롯에 몰린 앞의 값들을 전부 지나치므로 전체가 O(n²)로 돌아갑니다. O(n²)은 입력이 커질 때 시간이 늘어나는 모양을 적는 앞 편의 빅오 표기로, 값 개수가 두 배가 되면 시간이 네 배가 된다는 뜻입니다. 따라서 값 개수를 두 배로 하면 이 0.7초 차이도 네 배가 됩니다.

**그래서 "딕셔너리는 O(1)"이라는 말에는 조건이 붙습니다.** O(1)은 값이 몇 개든 한 번 넣고 찾는 시간이 거의 같다는 뜻입니다. 딕셔너리는 해시값이 고르게 흩어질 때만 O(1)이고 모든 값이 한 슬롯에 몰리는 최악의 경우에는 값 개수에 비례해 시간이 늘어나는 O(n)입니다. 다행히 파이썬 기본 자료형의 해시는 잘 흩어지도록 만들어져 있습니다. 코딩 테스트에서 이 최악을 만나는 일은 `__hash__` 를 직접 잘못 짜지 않는 한 거의 없습니다.

:::deep 슬롯이 모자라면 어떻게 되나 — 재배치와 amortized

슬롯 개수는 고정이 아닙니다. 값이 늘어 슬롯의 3분의 2 정도가 차면 파이썬은 슬롯 개수를 키웁니다. 그리고 이미 들어 있던 값을 전부 다시 계산해 새 자리에 옮깁니다. 이 과정을 재배치(rehash)라고 합니다.

재배치가 일어나는 그 한 번은 값 개수만큼 걸리니 O(n)입니다. 그래도 "딕셔너리 넣기는 O(1)"이라는 말은 거짓이 아닙니다.

슬롯 수를 일정 배수로 키우므로 키울 때마다 다음 재배치까지 넣을 수 있는 값도 그만큼 늘어나 재배치는 점점 드물게 일어납니다. 값을 n개 넣는 동안 재배치에 드는 시간을 다 합쳐도 n에 비례하는 수준입니다. 그래서 넣기 한 번당 평균은 상수로 남습니다. 이렇게 "가끔 비싸지만 평균 내면 싸다"를 **amortized O(1)** 이라 부릅니다.

같은 구조가 파이썬 리스트의 `append` 에도 있습니다. 리스트도 자리가 모자라면 더 큰 자리를 잡아 전부 옮깁니다. 하지만 이때도 일정 비율로 여유를 잡아 늘리니 `append` 한 번의 평균은 상수입니다. 면접에서 "리스트 append 는 왜 O(1) 인가"를 물으면 이 이야기를 하면 됩니다.
:::

## 4. 키로 쓸 수 있는 자료형

**딕셔너리는 키에서 자리를 계산해 넣으므로 키는 넣은 뒤에 바뀌면 안 됩니다.**

좌표처럼 여러 값을 묶어 키로 쓰고 싶을 때 리스트를 쓰면 파이썬이 막습니다. 리스트는 나중에 내용을 바꿀 수 있고 내용이 바뀌면 해시값도 같이 바뀌어서 처음 넣은 슬롯에서 영영 못 찾게 되기 때문입니다. 튜플(여러 값을 순서대로 묶은 자료형)은 한 번 만들면 내용을 못 바꾸니 키로 쓸 수 있습니다. 코드의 2단계는 정수 3 과 실수 3.0 을 같은 딕셔너리에 키로 넣어 봅니다.

```python
# 하는 일: 튜플과 리스트를 딕셔너리 키로 넣어 보고, 3 과 3.0 을 같은 딕셔너리에 넣으면 무슨 일이 생기는지 본다.
# 1단계: 튜플과 리스트를 키로 넣어 본다
# 키는 넣은 뒤에 바뀌면 안 된다. 튜플은 못 바꾸니 되고, 리스트는 바꿀 수 있으니 막힌다.
좌표 = {}
좌표[(3, 5)] = "가"          # 튜플은 된다
print("튜플 키 ", 좌표)

try:
    좌표[[3, 5]] = "나"      # 리스트는 안 된다
except TypeError as e:
    print("리스트 키", type(e).__name__, "-", e)

# 2단계: 3 과 3.0 을 키로 넣는다
print()
print("hash(3) =", hash(3), " hash(3.0) =", hash(3.0), " 3 == 3.0 :", 3 == 3.0)
d = {3: "정수로 넣음"}
d[3.0] = "실수로 덮어씀"
print("d =", d, " 항목 수", len(d))

# 출력:
# 1단계 뜻: 튜플 키는 들어가고, 리스트 키는 해시값을 못 구해 TypeError 가 난다.
# 튜플 키  {(3, 5): '가'}
# 리스트 키 TypeError - unhashable type: 'list'
# 2단계 뜻: 3 과 3.0 은 같고 해시값도 같아서 같은 키로 본다. 3.0 으로 넣은 값이 3 의 값을 덮어써 항목이 하나만 남는다.
#
# hash(3) = 3  hash(3.0) = 3  3 == 3.0 : True
# d = {3: '실수로 덮어씀'}  항목 수 1
```

1단계에서 튜플 키 `(3, 5)` 는 들어갔고 리스트 키는 해시값을 구할 수 없어 `TypeError - unhashable type: 'list'` 가 났습니다. 2단계가 더 재미있습니다. 출력에서 `hash(3)` 과 `hash(3.0)` 이 둘 다 3 이고 `3 == 3.0` 도 True 이듯 정수 3과 실수 3.0은 파이썬에서 서로 같다고 판정되고 해시값도 같아서 딕셔너리는 3 과 3.0 을 **같은 키**로 봅니다. 그래서 3.0 으로 넣은 값이 3 으로 넣은 값을 덮어쓰고 찍힌 `d` 에는 키 3 하나에 '실수로 덮어씀' 만 남아 항목 수가 1 입니다.

같은 키로 덮어써지는 일은 나눗셈 결과를 키로 쓸 때 실제로 문제가 됩니다. 나눗셈 결과는 실수라서 정수로 넣은 키와 뒤섞이면 아무 오류 없이 덮어써집니다. **키로 쓸 값은 자료형을 하나로 통일해 두는 편이 안전합니다.**

| 키로 쓸 수 있나 | 자료형 | 이유 |
|---|---|---|
| 된다 | 정수, 실수, 문자열, 튜플, `frozenset` | 만든 뒤 못 바꿉니다 |
| 안 된다 | 리스트, 딕셔너리, 집합 | 내용이 바뀌면 해시값도 바뀝니다 |
| 조건부 | 직접 만든 클래스 | `__hash__` 와 `__eq__` 를 짝 맞춰 정의해야 합니다 |

격자 문제에서 계속 나오는 `방문[(x, y)] = True` 가 좌표를 튜플로 감싸 키로 쓴 꼴입니다. 이름 조합처럼 여러 값을 묶어 키로 쓸 때도 튜플로 감싸면 됩니다.

## 5. 두 수의 합 — 한 번 순회로 찾는 짝

**"두 수를 더해 목표가 되는 짝을 찾아라"는 문제는 딕셔너리를 쓰면 값을 한 번 지나가는 것으로 끝납니다.**

값이 n개일 때 짝을 전부 만들어 보면 비교가 n²에 비례하니 느립니다. 그런데 지금 보는 값이 정해지면 필요한 짝도 하나로 정해집니다. 목표가 10이고 지금 값이 7이면 3 하나만 찾으면 됩니다.

그러면 남은 일은 "3을 이미 봤나"를 묻는 것 하나인데, 값이 있는지는 딕셔너리가 2절처럼 자리를 계산해 바로 답하는 물음입니다. 값을 처음부터 끝까지 하나씩 차례로 보는 일을 순회라고 합니다. **지금까지 본 값을 딕셔너리에 적어 두면서 한 번만 순회하면 됩니다.**

```python
# 하는 일: 값 6개에서 더해 10 이 되는 두 칸을, 지금까지 본 값을 딕셔너리에 적어 두며 한 번만 순회해서 찾는다.
ARR, TARGET = [8, 3, 11, 7, 2, 15], 10

print("칸  값   지금까지 본 값→칸        찾는 짝    있나")
seen = {}
for i, v in enumerate(ARR):
    need = TARGET - v
    hit  = need in seen
    print(f"{i}  {v:>3}   {str(seen):<24} {need:>4}    {'있다 → 답 ' + str((seen.get(need), i)) if hit else '없다'}")
    if hit:
        break
    seen[v] = i

# 출력:
# 뜻: 칸마다 짝(10 에서 지금 값을 뺀 수)이 이미 적혀 있는지 본다. 3번 칸의 7 에서 짝 3 이 1번 칸에 적혀 있어 멈춘다.
# 칸  값   지금까지 본 값→칸        찾는 짝    있나
# 0    8   {}                          2    없다
# 1    3   {8: 0}                      7    없다
# 2   11   {8: 0, 3: 1}               -1    없다
# 3    7   {8: 0, 3: 1, 11: 2}         3    있다 → 답 (1, 3)
```

코드는 칸마다 짝(10 에서 지금 값을 뺀 수)이 이미 적혀 있는지 보고 없으면 지금 값과 칸 번호를 적어 둔 뒤 다음 칸으로 갑니다. 0번 칸의 8 은 짝 2 를, 1번 칸의 3 은 짝 7 을, 2번 칸의 11 은 짝 -1 을 찾지만 그때까지 적어 둔 값 가운데 없습니다. 3번 칸의 7 에서는 짝 3 이 1번 칸으로 적혀 있어 반복을 멈추는데, 3 + 7 = 10 이니 답 (1, 3) 은 1번 칸과 3번 칸입니다.

## 6. 세는 일 — get, defaultdict, Counter

**무엇이 몇 번 나왔는지 세는 코드는 `get`, `defaultdict`, `Counter` 세 가지 가운데 하나로 씁니다.**

세는 코드를 짜는 초보는 없는 키를 읽다가 가장 많이 틀립니다. `count[w] += 1` 은 1 을 더하기 전에 `count[w]` 를 먼저 읽으므로 `w` 가 처음 나오면 읽을 키가 없어 `KeyError` 로 죽습니다. 처음인지 아닌지를 매번 `if` 로 확인하면 코드가 지저분해지므로 파이썬은 이 확인을 짧게 쓰는 방법을 세 가지 줍니다. `get` 은 키가 없을 때 정해 준 기본값을 돌려주는 딕셔너리 메서드입니다. 코드의 `count.get(w, 0)` 은 처음 나온 낱말에 0 을 내주므로 `if` 없이 1 을 더할 수 있습니다. `defaultdict` 는 없는 키를 읽는 순간 기본값을 저절로 만들어 넣는 딕셔너리입니다. `Counter` 는 세는 일 전용으로 만든 딕셔너리입니다.

```python
# 하는 일: 낱말 6개를 담은 목록에서 낱말마다 몇 번 나왔는지를 get 과 Counter 로 세고, defaultdict 로는 나온 칸 번호를 모은다.
from collections import Counter, defaultdict

WORDS = ["사과", "배", "사과", "귤", "배", "사과"]

# 1단계: get 으로 센다
# 처음 나온 낱말은 get 이 0 을 돌려주니 if 로 따로 확인하지 않는다.
count = {}
for w in WORDS:
    count[w] = count.get(w, 0) + 1
print("get 으로     ", count)

# 2단계: defaultdict 로 칸 번호를 모은다
# 처음 나온 낱말에는 빈 리스트가 저절로 생긴다.
bag = defaultdict(list)
for i, w in enumerate(WORDS):
    bag[w].append(i)
print("defaultdict ", dict(bag))

# 3단계: Counter 로 센다
c = Counter(WORDS)
print("Counter     ", dict(c))
print("가장 많은 둘 ", c.most_common(2))

# 출력:
# 1단계 뜻: 사과 3번, 배 2번, 귤 1번이다.
# get 으로      {'사과': 3, '배': 2, '귤': 1}
# 2단계 뜻: 낱말마다 나온 칸 번호를 모았다. 사과는 0, 2, 5번 칸에 있다.
# defaultdict  {'사과': [0, 2, 5], '배': [1, 4], '귤': [3]}
# 3단계 뜻: get 으로 센 것과 같다. most_common(2) 는 가장 많이 나온 둘을 개수와 함께 준다.
# Counter      {'사과': 3, '배': 2, '귤': 1}
# 가장 많은 둘  [('사과', 3), ('배', 2)]
```

세 방법은 같은 낱말 6개를 다뤘습니다. `get` 과 `Counter` 는 사과 3번, 배 2번, 귤 1번을 똑같이 셌고 `most_common(2)` 는 그 가운데 가장 많이 나온 두 낱말인 사과와 배를 `[('사과', 3), ('배', 2)]` 처럼 개수와 함께 돌려줬습니다. `defaultdict` 는 센 것이 아니라 낱말마다 나온 칸 번호를 모았는데, 사과는 0번, 2번, 5번 칸, 배는 1번과 4번 칸, 귤은 3번 칸에 있었습니다.

세 방법의 쓰임이 조금씩 다릅니다. `get` 은 따로 불러오지(import) 않고 쓸 수 있으니 세는 일 하나뿐이면 `get` 으로 충분합니다. `defaultdict` 는 처음 나온 키에도 빈 리스트가 이미 생겨 있어 `append` 를 바로 부를 수 있으므로 키마다 리스트나 집합을 모아야 할 때 편합니다. 위 예처럼 "이 값이 몇 번 칸들에 있었나"를 모으는 데 자주 씁니다.

`Counter` 는 세는 일 전용이라 세는 코드가 가장 짧고 `most_common` 처럼 딸린 기능이 있습니다. 두 `Counter` 를 빼면 개수의 차도 바로 나옵니다. 애너그램(글자 순서만 바꿔 만든 낱말)이나 문자 개수를 비교하는 문제는 `Counter` 로 한 줄에 끝나는 경우가 많습니다.

> **주의 한 가지** — `defaultdict` 는 없는 키를 **읽기만 해도** 그 키를 만들어 버립니다. `if bag[w]:` 같은 확인이 조용히 키를 늘리니, 확인할 때는 `if w in bag:` 를 씁니다.

## 7. 집합 연산 — 겹치는 것과 빠진 것

**두 목록을 비교하는 문제는 반복문 대신 집합 연산 한 줄이 답인 경우가 많습니다.**

집합 연산은 두 집합의 겹침이나 차이를 `&`, `-`, `|`, `^` 같은 기호 하나로 구하는 계산입니다. "어제 왔는데 오늘 안 온 사람"을 찾는다고 해 보겠습니다. 어제 온 사람마다 오늘 명단을 처음부터 비교하는 이중 반복문으로 짜면 O(n²)이고 코드도 깁니다. 집합으로 바꾸면 `어제 - 오늘` 기호 하나면 됩니다. 아래 코드는 어제 온 4명과 오늘 온 4명을 연산 다섯 가지로 비교합니다.

```python
# 하는 일: 어제 온 4명과 오늘 온 4명을 집합 연산 다섯 가지로 비교하고, 어제 왔다가 오늘 안 온 비율을 구한다.
어제 = {"지훈", "민서", "서연", "도윤"}
오늘 = {"민서", "서연", "하준", "지우"}

print("둘 다 왔다 (교집합)  ", sorted(어제 & 오늘))
print("어제만 (차집합)      ", sorted(어제 - 오늘))
print("오늘 새로 온 사람     ", sorted(오늘 - 어제))
print("한 번이라도 (합집합) ", sorted(어제 | 오늘))
print("한쪽에만 (대칭차)    ", sorted(어제 ^ 오늘))
print()
print("이탈률", f"{len(어제 - 오늘) / len(어제):.1%}")

# 출력:
# 뜻: 기호 하나가 질문 하나다. & 는 둘 다, - 는 이쪽에만, | 는 한 번이라도, ^ 는 한쪽에만 있는 사람이다.
# 둘 다 왔다 (교집합)   ['민서', '서연']
# 어제만 (차집합)       ['도윤', '지훈']
# 오늘 새로 온 사람      ['지우', '하준']
# 한 번이라도 (합집합)  ['도윤', '민서', '서연', '지우', '지훈', '하준']
# 한쪽에만 (대칭차)     ['도윤', '지우', '지훈', '하준']
# 뜻: 어제 온 4명 가운데 지훈과 도윤 2명이 오늘 안 왔다.
#
# 이탈률 50.0%
```

`어제 & 오늘` 은 둘 다 온 민서와 서연, `어제 - 오늘` 은 어제만 온 도윤과 지훈, 순서를 바꾼 `오늘 - 어제` 는 오늘 새로 온 지우와 하준, `어제 | 오늘` 은 한 번이라도 온 6명, `어제 ^ 오늘` 은 한쪽에만 온 4명입니다. 이탈률은 어제 온 사람 가운데 오늘 안 온 사람의 비율이라, 어제 온 4명 가운데 지훈과 도윤 2명이 빠진 이번 값은 50.0% 입니다.

기호 다섯 개가 각각 흔한 질문에 대응합니다. 교집합은 "둘 다", 차집합은 "이쪽에만", 합집합은 "한 번이라도", 대칭차는 "한쪽에만"입니다. 문제 지문을 읽다가 이 표현이 나오면 집합 연산을 떠올리면 됩니다.

광고 쪽에서 이 연산을 그대로 쓰는 자리가 오디언스 세그먼트(광고를 보여 줄 대상으로 나눈 사용자 그룹)입니다. 두 세그먼트가 얼마나 겹치는지는 교집합의 크기이고 한쪽에만 있는 사용자가 몇 명인지는 차집합의 크기입니다. 자세한 것은 [오디언스 세그멘테이션](post.html?id=audience-segmentation) 편에 있습니다.

## 8. 정렬 — key 로 정하는 기준

**해시가 안 통하는 문제에서는 정렬을 꺼냅니다.**

해시는 "이 값이 있나"에는 강하지만 "이 값보다 큰 것 중 가장 작은 것"에는 아무 도움이 안 되는데, 값을 흩어 놓는 것이 목적이라 순서를 아예 버리기 때문입니다. 순서가 필요한 순간 정렬이 등장합니다.

파이썬의 `sorted` 와 `list.sort` 는 O(n log n)이라 비교 횟수가 값 개수 n 에 log n 을 곱한 것에 비례합니다. 값이 십만 개면 십만에 log₂ 십만(약 17)을 곱한 대략 170만 번쯤 비교하므로 채점 서버가 충분히 견딥니다. **입력이 십만 개까지라면 "일단 정렬"은 거의 항상 안전한 선택입니다.**

정렬에서는 알고리즘 대신 `key` 사용법을 배웁니다. `key` 는 각 원소를 무엇으로 볼지 정하는 함수입니다. 파이썬은 원소를 직접 비교하지 않고 `key` 가 돌려준 값을 비교합니다. 아래 코드는 (이름, 반, 점수)로 된 학생 4명을 점수 오름차순과 내림차순으로 정렬합니다.

```python
# 하는 일: 학생 4명을 점수 오름차순과 내림차순으로 정렬해 이름 순서를 찍는다.
학생 = [("지훈", 3, 88), ("민서", 1, 92), ("서연", 3, 92), ("도윤", 1, 88)]
# (이름, 반, 점수)

print("원본        ", [s[0] for s in 학생])
print("점수만 정렬  ", [s[0] for s in sorted(학생, key=lambda s: s[2])])
print("점수 내림차순", [s[0] for s in sorted(학생, key=lambda s: -s[2])])

# 출력:
# 뜻: sorted 는 key 가 돌려준 점수로 비교한다. 내림차순은 key 에서 점수에 - 를 붙여 만들었다.
# 원본         ['지훈', '민서', '서연', '도윤']
# 점수만 정렬   ['지훈', '도윤', '민서', '서연']
# 점수 내림차순 ['민서', '서연', '지훈', '도윤']
```

원본은 지훈, 민서, 서연, 도윤 순입니다. 점수만 정렬하면 88점인 지훈과 도윤이 앞으로 오고 92점인 민서와 서연이 뒤로 가는데, `sorted` 는 `key` 가 돌려준 점수로 비교하기 때문입니다. 내림차순은 `key` 에서 점수에 `-` 를 붙여 만들었는데, `-` 를 붙이면 92점이 88점보다 작은 값이 되므로 오름차순으로 정렬해도 92점인 민서와 서연이 앞으로 옵니다.

여기서 내림차순을 `reverse=True` 가 아니라 `-s[2]` 로 쓴 데는 까닭이 있습니다. `reverse=True` 를 써도 되지만 기준이 두 개 이상이 되면 이야기가 달라지는데, 그 차이를 다음 절에서 다룹니다.

## 9. 안정 정렬과 두 겹 기준

**파이썬 정렬은 값이 같은 원소들의 원래 순서를 그대로 지킵니다. 이런 정렬을 안정 정렬이라 합니다.**

기준이 하나면 신경 쓸 일이 없습니다. 문제는 "점수 높은 순으로, 점수가 같으면 반 번호 작은 순으로" 같은 두 겹 기준입니다. 두 겹 기준은 기준마다 따로 두 번 정렬해도 되고 두 기준을 튜플로 묶어 `key` 로 한 번에 정렬해도 됩니다. 아래 코드는 같은 학생 4명을 두 방법으로 정렬해 결과를 비교합니다.

```python
# 하는 일: 「점수 높은 순, 점수가 같으면 반 번호 작은 순」을 두 번 나눠 정렬하는 방법과 튜플 key 로 한 번에 정렬하는 방법으로 만들어 비교한다.
학생 = [("지훈", 3, 88), ("민서", 1, 92), ("서연", 3, 92), ("도윤", 1, 88)]

print("반 먼저 정렬 후 점수로 다시 정렬:")
tmp = sorted(학생, key=lambda s: s[1])
print("  1단계 반   ", [(s[0], s[1]) for s in tmp])
tmp = sorted(tmp, key=lambda s: -s[2])
print("  2단계 점수 ", [(s[0], s[2], s[1]) for s in tmp])
print()
print("한 번에 (점수 내림, 반 오름):")
one = sorted(학생, key=lambda s: (-s[2], s[1]))
print("            ", [(s[0], s[2], s[1]) for s in one])

# 출력:
# 뜻: 반으로 먼저 정렬한 뒤 점수로 다시 정렬했다. 점수가 같은 학생끼리는 첫 정렬에서 만든 반 순서를 그대로 지킨다.
# 반 먼저 정렬 후 점수로 다시 정렬:
#   1단계 반    [('민서', 1), ('도윤', 1), ('지훈', 3), ('서연', 3)]
#   2단계 점수  [('민서', 92, 1), ('서연', 92, 3), ('도윤', 88, 1), ('지훈', 88, 3)]
# 뜻: 기준 둘을 튜플로 묶어 한 번에 정렬해도 결과가 글자 하나까지 같다.
#
# 한 번에 (점수 내림, 반 오름):
#              [('민서', 92, 1), ('서연', 92, 3), ('도윤', 88, 1), ('지훈', 88, 3)]
```

1단계 줄에서는 반 번호로 정렬해 1반인 민서와 도윤이 앞에, 3반인 지훈과 서연이 뒤에 왔습니다. 2단계 줄에서 점수로 다시 정렬하자 92점인 민서와 서연, 88점인 도윤과 지훈이 각각 1단계에서 만든 반 순서를 그대로 지켜서 점수가 같으면 반 번호가 작은 학생이 앞에 있습니다. 두 번 정렬하는 방법은 이렇게 2단계가 1단계의 순서를 지키는 안정성 덕분에 성립합니다. 튜플 `key` 로 한 번에 정렬한 결과도 민서, 서연, 도윤, 지훈 순으로 글자 하나까지 같은데, 튜플은 앞 원소인 점수부터 비교하고 점수가 같을 때만 반 번호를 보므로 이 방법은 안정성에 의존하지 않습니다.

실무에서는 튜플 `key` 한 번으로 끝내는 편이 낫습니다. 정렬을 한 번만 하니 더 빠르고 기준이 코드 한 줄에 다 적혀 있어서 읽기도 쉽습니다. 두 번 정렬하는 방법은 기준을 **문자열 오름차순과 숫자 내림차순처럼 섞어야 해서** 튜플로 못 묶을 때 씁니다.

여기서 `reverse=True` 의 함정이 나옵니다. `reverse=True` 는 같은 값끼리의 순서까지 뒤집지는 않습니다. 다만 `reverse=True` 는 기준 전체를 내림차순으로 바꾸므로 두 겹 기준을 `reverse=True` 로 처리하려 들면 두 번째 기준의 방향이 의도와 반대가 되기 쉽습니다. **내림차순이 필요하면 숫자에는 음수 부호를 붙이는 편이 안전합니다.**

광고에서 이 두 겹 기준이 매일 돌아가는 자리가 eCPM(광고의 예상 수익을 비교하는 값) 순위 매기기입니다. 예상 수익 순으로 광고를 정렬하되 같은 값이면 다른 기준으로 나눕니다. 그 구조는 [eCPM 랭킹](post.html?id=ecpm-ranking) 편에서 다룹니다.

## 10. 정렬 후 한 번 순회 — 구간 병합과 세 수의 합

**정렬의 진짜 값어치는 정렬 그 자체가 아니라, 정렬한 뒤에 한 번만 순회하면 끝나는 문제로 바뀐다는 데 있습니다.**

겹치는 구간을 합치는 문제를 보겠습니다. 구간은 (시작, 끝) 튜플로 적고 (1, 4) 는 1 에서 4 까지입니다. 정렬하지 않은 채로는 모든 구간 쌍을 비교해야 하니 O(n²)입니다. 시작점 순으로 정렬하면 겹칠 수 있는 구간끼리 옆에 붙으므로 **바로 앞에서 합친 구간 하나만 보면 됩니다.** 지금 구간의 시작이 그 구간의 끝보다 작거나 같으면 두 구간이 겹치므로 끝을 늘려 하나로 합치고 크면 떨어져 있으므로 새 구간을 엽니다.

```python
# 하는 일: 구간 5개를 시작점 순으로 정렬한 뒤 한 번만 순회하며 겹치는 구간을 합친다.
구간 = [(13, 15), (1, 4), (9, 12), (3, 6), (14, 18)]

# 1단계: 시작점 순으로 정렬한다
# 튜플은 앞 원소부터 비교하니 sorted 한 번이면 시작점 순서가 된다.
정렬 = sorted(구간)
print("정렬 전", 구간)
print("정렬 후", 정렬)
print()

# 2단계: 마지막으로 합친 구간 하나와만 비교하며 합친다
# 지금 구간의 시작이 마지막으로 합친 구간의 끝보다 작거나 같으면 겹친 것이라 끝을 늘린다. 크면 새 구간을 연다.
merged = [정렬[0]]
print(f"{'보는 구간':<10}{'마지막 구간':<12}{'판정':<22}{'결과'}")
for s, e in 정렬[1:]:
    ls, le = merged[-1]
    if s <= le:
        merged[-1] = (ls, max(le, e))
        판정 = f"{s} ≤ {le} 겹친다"
    else:
        merged.append((s, e))
        판정 = f"{s} > {le} 떨어졌다"
    print(f"{str((s,e)):<10}{str((ls,le)):<12}{판정:<22}{merged}")
print()
print("답", merged)

# 출력:
# 1단계 뜻: 정렬하면 겹칠 수 있는 구간끼리 옆에 붙는다.
# 정렬 전 [(13, 15), (1, 4), (9, 12), (3, 6), (14, 18)]
# 정렬 후 [(1, 4), (3, 6), (9, 12), (13, 15), (14, 18)]
#
# 2단계 뜻: 네 번 비교해 겹친 두 곳을 합쳤다. 구간 5개가 3개로 합쳐진다.
# 보는 구간     마지막 구간      판정                    결과
# (3, 6)    (1, 4)      3 ≤ 4 겹친다             [(1, 6)]
# (9, 12)   (1, 6)      9 > 6 떨어졌다            [(1, 6), (9, 12)]
# (13, 15)  (9, 12)     13 > 12 떨어졌다          [(1, 6), (9, 12), (13, 15)]
# (14, 18)  (13, 15)    14 ≤ 15 겹친다           [(1, 6), (9, 12), (13, 18)]
#
# 답 [(1, 6), (9, 12), (13, 18)]
```

정렬은 앞 편의 투 포인터(정렬된 배열의 양 끝에서 좁혀 오는 방법)와도 짝을 이룹니다. 세 수를 더해 0이 되는 조합을 찾는 문제가 대표적입니다. 값 하나를 고정해 놓고 나머지 두 수를 양 끝에서 좁히면, 고정을 n 번 하고 그때마다 양 끝이 만날 때까지 많아야 n 번 움직이므로 전체가 O(n²)로 내려갑니다.

```python
# 하는 일: 정렬한 값 6개에서 하나를 고정하고 나머지 둘을 양 끝에서 좁혀, 더해서 0 이 되는 세 수를 모두 찾는다.
ARR = [-4, -1, -1, 0, 1, 2]
ARR.sort()
답, n = [], len(ARR)
for i in range(n - 2):
    if i > 0 and ARR[i] == ARR[i-1]:
        print(f"i={i} 값 {ARR[i]:>2}  앞과 같아서 건너뜀")
        continue
    L, R = i + 1, n - 1
    while L < R:
        s = ARR[i] + ARR[L] + ARR[R]
        기호 = "=" if s == 0 else ("<" if s < 0 else ">")
        움직임 = "찾음" if s == 0 else ("L을 민다" if s < 0 else "R을 당긴다")
        print(f"i={i} 값 {ARR[i]:>2}  L={L}({ARR[L]:>2}) R={R}({ARR[R]:>2})  합 {s:>2} {기호} 0  {움직임}")
        if s == 0:
            답.append((ARR[i], ARR[L], ARR[R]))
            L += 1; R -= 1
            while L < R and ARR[L] == ARR[L-1]: L += 1
        elif s < 0: L += 1
        else:       R -= 1
print("\n답", 답)

# 출력:
# 뜻: i 로 하나를 고정하고 L, R 을 양 끝에서 좁힌다. i=2 는 앞 값과 같아 건너뛰어서 같은 조합이 두 번 나오지 않는다.
# i=0 값 -4  L=1(-1) R=5( 2)  합 -3 < 0  L을 민다
# i=0 값 -4  L=2(-1) R=5( 2)  합 -3 < 0  L을 민다
# i=0 값 -4  L=3( 0) R=5( 2)  합 -2 < 0  L을 민다
# i=0 값 -4  L=4( 1) R=5( 2)  합 -1 < 0  L을 민다
# i=1 값 -1  L=2(-1) R=5( 2)  합  0 = 0  찾음
# i=1 값 -1  L=3( 0) R=4( 1)  합  0 = 0  찾음
# i=2 값 -1  앞과 같아서 건너뜀
# i=3 값  0  L=4( 1) R=5( 2)  합  3 > 0  R을 당긴다
# 뜻: 합이 0 인 세 수는 두 조합이다.
#
# 답 [(-1, -1, 2), (-1, 0, 1)]
```

i 는 고정한 값의 칸이고 L 과 R 은 양 끝에서 좁혀 오는 나머지 두 수의 칸입니다. 값이 작은 것부터 늘어서 있어 L 을 오른쪽으로 밀면 합이 커지거나 그대로이고 R 을 왼쪽으로 당기면 합이 작아지거나 그대로이므로, 합이 0보다 작으면 L 을 밀고 0보다 크면 R 을 당기며 0 이면 답에 넣습니다. i=0 에서 -4 를 고정하면 합이 -3 → -3 → -2 → -1 로 끝까지 0보다 작아 L 만 네 번 밉니다. i=1 에서 -1 을 고정하면 합이 0 인 (-1, -1, 2) 와 (-1, 0, 1) 을 찾는데, 답에 든 조합도 이 두 개뿐입니다.

정렬해 두면 중복 제거도 공짜로 따라옵니다. 같은 값이 붙어 있으니 "앞과 같으면 건너뛴다" 한 줄이면 되고 위 출력에서 `i=2` 가 그렇게 넘어갔습니다. `i=2` 의 -1 은 바로 앞 `i=1` 의 -1 과 같아 건너뛰었으므로 같은 조합이 두 번 나오지 않았습니다. **집합으로 중복을 거르려 하면 튜플로 감싸야 하고 순서까지 맞춰야 해서 오히려 번거롭습니다.**

## 한눈 정리

| 상황 | 쓸 것 | 이유 |
|---|---|---|
| 값이 있는지 반복해서 묻는다 | 집합 | 값에서 자리를 계산해 한 번에 갑니다 |
| 값에 딸린 정보가 필요하다 | 딕셔너리 | 자리와 값을 같이 들고 있습니다 |
| 지금 값의 짝이 하나로 정해진다 | 딕셔너리 + 한 번 순회 | 짝을 전부 만들 필요가 없습니다 |
| 몇 번 나왔는지 센다 | `Counter` | `most_common` 까지 딸려 옵니다 |
| 키마다 여러 개를 모은다 | `defaultdict(list)` | 첫 등장을 따로 처리 안 해도 됩니다 |
| 두 목록을 비교한다 | 집합 연산 | 이중 반복문이 기호 하나가 됩니다 |
| 순서, 크기 비교가 필요하다 | 정렬 | 해시는 순서를 버립니다 |
| 기준이 두 개 이상이다 | 튜플 `key` | 한 번만 정렬하고 기준이 한눈에 보입니다 |
| 겹침, 중복을 다룬다 | 정렬 후 한 번 순회 | 같은 것끼리 붙어 있게 됩니다 |

## 헷갈리기 쉬운 점

- **딕셔너리가 항상 O(1)은 아닙니다.** 해시값이 한 슬롯으로 몰리면 O(n)까지 떨어집니다. 기본 자료형을 쓰면 걱정할 일이 거의 없지만 `__hash__` 를 직접 짜면 이야기가 달라집니다.
- **`3` 과 `3.0` 은 같은 키입니다.** 나눗셈 결과를 키로 쓰면 정수로 넣은 것과 섞여 조용히 덮어써집니다.
- **리스트는 키가 못 됩니다.** 여러 값을 묶어 키로 쓰려면 튜플로 감쌉니다.
- **`defaultdict` 는 읽기만 해도 키가 생깁니다.** 있는지 확인할 때는 `in` 을 씁니다.
- **집합은 순서가 없습니다.** 출력 순서가 채점에 영향을 주는 문제라면 마지막에 `sorted` 를 한 번 붙입니다.
- **`reverse=True` 와 음수 부호는 다릅니다.** 기준이 두 개 이상이면 음수 부호 쪽이 헷갈릴 여지가 적습니다.
- **정렬은 원본을 바꿀 수도 있습니다.** `list.sort()` 는 원본을 바꾸고 `sorted()` 는 새 리스트를 만듭니다. 원본이 나중에 다시 필요하면 `sorted` 를 씁니다.
