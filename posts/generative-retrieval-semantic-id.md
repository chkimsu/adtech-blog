모델 팀 39주째 월요일, 지훈 씨는 선배가 보낸 논문의 그림 한 장을 열었습니다. 그림 속 상품마다 긴 번호 대신 작은 숫자 셋이 붙어 있었습니다. 비슷한 상품끼리는 앞의 숫자가 같았습니다.

선배는 모델이 그 숫자를 한 자리씩 써 내려가며 회원에게 보일 상품을 고른다고 했습니다. 지난주에 들어온 새 상품 10건도 등록하자마자 숫자를 받는다고 했습니다. 지훈 씨는 숫자 셋이 상품 300건을 어떻게 나누는지부터 보기로 했습니다.

**상품마다 숫자 셋을 붙이면, 회원에게 보일 상품을 그 숫자로 어떻게 꺼내고 새 상품은 어떻게 될까요?**

상품마다 붙이는 짧은 코드 묶음을 Semantic ID 라고 부릅니다. 모델이 그 코드를 한 자리씩 생성해 후보를 꺼내는 방법은 생성형 검색(generative retrieval)입니다. 후보에서 빠진 광고는 뒤에서 점수를 아무리 잘 매겨도 회원에게 보이지 않습니다.

> **한 줄 요약:** 상품마다 붙이는 짧은 코드 묶음을 Semantic ID 라고 부릅니다. 이 글은 상품 300건의 384차원 벡터를 단마다 중심 16개의 k-means 로 나눕니다. 고른 중심을 뺀 나머지인 잔차는 다음 단에서 다시 나눕니다. 세 단을 거친 잔차의 길이 평균은 1.000 에서 0.748 로 줄었습니다. 이 글의 k-means 는 단마다 같은 상품 16건에서 출발합니다. 그 규칙 탓에 셋째 단에서는 길이 0 인 초기 중심(initial centroid) 하나에 284건이 몰렸습니다. 그래서 코드 셋은 147가지에 그쳤습니다. 코드 셋이 같은 상품은 묶음 안의 차례인 넷째 자리로 구분했습니다. 회원 A 가 본 상품 셋의 평균 벡터로 단마다 코드를 3개씩 남기는 빔 탐색을 돌려, 코드 트리에서 상품 10건을 꺼냈습니다. 같은 벡터의 전수 코사인 상위 10건과 겹친 상품은 1건이었고, 6건은 빔의 1단에서 빠졌습니다. 새 상품 10건은 노출 기록 없이 내용 벡터만으로 바로 코드를 받았고, 그 가운데 2건은 회원 A 의 빔이 꺼냈습니다.

> **골라 읽는 법** — 절이 6개입니다. 절마다 표나 코드나 카드가 있어 그것만 보고 넘어가도 됩니다.
>
> - 상품을 id, 벡터, 코드 셋으로 적는 차이 → 1절
> - k-means 로 코드북 세 단을 만드는 잔차 양자화 → 2절
> - 코드 트리와 빔 탐색으로 상품을 꺼내는 방법 → 3절
> - 전수 코사인 상위 10건과 겹치는 수 → 4절
> - 새 상품 10건이 노출 전에 코드를 받는 까닭 → 5절
> - 담장 안과 열린 RTB 에서 코드를 만드는 재료 → 6절

이 글의 상품 300건은 23주째 [임베딩과 벡터 검색](post.html?id=embeddings-vector-search) 편의 가상 상품 3,000건 가운데 앞 300건입니다. 이름 틀에 낱말을 끼워 만든 가상 데이터이고, 벡터도 그 편의 장난감 임베딩 그대로입니다. 첫 블록은 그 편의 `make_products` 와 `embed` 를 글자 그대로 옮겼습니다. 회원 A 가 본 상품 셋과 새 상품 10건도 이 글에서 정한 가상 값입니다. 이 글은 LLM 을 부르지 않았고, 기록한 답도 없습니다. 카드의 파랑은 상품과 코드북, 벽돌색은 회원 A 의 질의와 빔이 고른 것입니다. 먹색은 트리의 노드와 상품이 받은 코드, 회색은 빔에서 빠진 것과 비교할 기준값, 점선 상자는 가상 값입니다.

## 1. 광고를 코드 셋으로 적습니다

**Semantic ID 는 상품마다 붙이는 짧은 코드 묶음이고, 상품의 내용 벡터에서 만듭니다. 비슷한 상품은 앞자리 코드를 나눠 갖습니다. 이 글의 코드는 세 단이고, 단마다 16개 가운데 하나입니다.**

광고 시스템은 상품과 광고를 id 로 부릅니다. id 는 서로 다르기만 하면 되는 번호라, 번호가 이웃한 두 상품이 비슷하다는 뜻은 없습니다. 그래서 id 로 후보를 고르는 모델은 id 마다 벡터 한 행을 두고, 노출과 클릭 기록으로 그 값을 학습합니다. 이 벡터를 id 임베딩이라고 부릅니다. id 마다 행을 두는 큰 표는 [대규모 임베딩 테이블 운영](post.html?id=embedding-table-ops) 편에서 보았습니다.

상품의 이름이나 설명으로 만든 벡터는 이 글에서 내용 벡터라고 부릅니다. 23주째의 장난감 임베딩이 그런 벡터였고, 이름의 글자가 많이 겹칠수록 코사인이 컸습니다. 내용 벡터는 새 상품도 이름만 있으면 바로 만들 수 있습니다. 대신 상품마다 실수 384개를 들고 있어야 하고, 가까운 상품을 찾으려면 벡터끼리 거리를 재야 합니다.

Semantic ID 는 그 둘 사이에 있습니다. TIGER 논문(Rajput 외 2023)은 Semantic ID 를 코드 몇 개의 묶음으로 정의했습니다. 묶음의 코드는 저마다 다른 코드북에서 옵니다. 코드북은 코드 번호마다 벡터 하나를 둔 표입니다. 논문은 비슷한 상품이 앞자리 코드를 나눠 가져야 한다고 적었습니다. (10, 21, 35) 는 (10, 23, 32) 보다 (10, 21, 40) 과 더 비슷해야 한다는 예도 들었습니다.

코드는 내용 벡터를 양자화해 만듭니다. 양자화는 연속된 값을 정해 둔 몇 개의 값 가운데 하나로 바꾸는 일입니다. TIGER 는 상품의 제목이나 설명을 Sentence-T5 같은 학습된 인코더로 벡터로 바꾼 뒤 양자화했습니다. 이 글은 23주째의 장난감 임베딩을 그대로 쓰고, 2절에서 k-means 로 양자화합니다.

코드를 단마다 하나씩 정하면 첫째 코드가 큰 묶음이 되고, 뒤의 코드가 그 안을 잘게 나눕니다. TIGER 의 그림에서도 첫째 코드는 굵은 범주와, 둘째와 셋째 코드는 더 잘게 나눈 범주와 맞았습니다. 단이 셋이고 단마다 코드가 16개면 코드 셋은 16 × 16 × 16 = 4,096가지입니다. 상품 300건에는 넉넉해 보이지만, 코드 셋이 같은 상품이 생기면 넷째 자리를 붙여 구분합니다. 아래 표는 상품을 적는 네 가지 방법을 비교한 것입니다.

| 상품을 적는 법 | 생김새 | 비슷한 상품끼리 | 새 상품이 들어오면 |
|---|---|---|---|
| id | 번호 하나 | 번호로는 알 수 없다 | 번호는 바로 받는다 |
| id 임베딩 | id 마다 학습한 벡터 한 행 | 노출과 클릭이 비슷하면 가깝다 | 기록이 쌓여 다시 학습할 때까지 행이 없다 |
| 내용 벡터 | 이름에서 만든 실수 384개 | 이름이 비슷하면 코사인이 크다 | 이름으로 바로 만든다 |
| Semantic ID | 코드 셋과 넷째 자리 | 앞자리 코드가 같다 | 내용 벡터로 바로 코드를 받는다 |

표의 위 둘은 번호와 노출 기록에서 오고, 아래 둘은 상품의 내용에서 옵니다. 그래서 새 상품을 처음부터 비슷한 상품 곁에 둘 수 있는 것은 아래 둘입니다. Semantic ID 는 내용 벡터를 코드 몇 개로 줄인 것입니다. 코드 하나하나가 생성 모델의 토큰이 되어, 모델이 코드를 하나씩 생성할 수 있습니다. 2절은 그 코드를 실제로 붙여 봅니다.

## 2. 잔차 양자화를 한 번 돌립니다

**상품 300건의 벡터를 k-means 로 16개 묶음에 나누고, 고른 중심을 뺀 잔차를 다음 단에서 다시 나눴습니다. 잔차 길이의 평균은 1.000 에서 0.837, 0.778, 0.748 로 줄었습니다. 이 글의 초기값 규칙 탓에 셋째 단이 상품을 거의 나누지 못해, 코드 셋은 147가지였고 226건이 코드 셋을 다른 상품과 함께 썼습니다.**

k-means 는 벡터들을 k 개의 묶음으로 나누는 방법입니다. 묶음을 군집, 군집마다 두는 대표 벡터를 중심(centroid)이라고 부릅니다. 먼저 벡터마다 가장 가까운 중심에 배정하고, 다음에 중심을 배정된 벡터의 평균으로 옮깁니다. 배정이 더는 바뀌지 않을 때까지 이 둘을 되풀이합니다. 처음 배정에 쓰는 초기 중심은 `random.Random(7)` 로 고른 상품 16건의 벡터입니다.

한 단을 마친 중심 16개가 그 단의 코드북이고, 중심의 번호 0~15 가 코드입니다. 상품의 첫째 코드는 그 벡터에 가장 가까운 1단 중심의 번호입니다. 벡터에서 그 중심을 뺀 나머지를 잔차(residual)라고 부릅니다. 2단은 상품 300건의 잔차로 k-means 를 다시 돌려 둘째 코드를 정하고, 3단은 2단의 잔차로 셋째 코드를 정합니다.

앞 단이 맞추지 못한 나머지를 다음 단이 이어서 맞추는 이 방법을 잔차 양자화(residual quantization)라고 부릅니다. 상품 벡터는 단마다 고른 중심 셋의 합으로 근사됩니다. Lee 외(2022)의 RQ-VAE 는 이미지 생성 논문입니다. 이미지를 줄인 특징 맵(feature map)의 위치마다 잔차 양자화로 코드를 쌓아 적었습니다. 그 논문은 모든 단에 코드북 하나를 함께 썼습니다. TIGER 는 단마다 코드북을 따로 두었고, 단이 깊을수록 잔차의 길이가 줄어서라고 적었습니다. 이 글도 단마다 코드북을 따로 두고, 배정이 앞 반복과 같아지면 반복 20번을 다 채우지 않고 멈춥니다.

```python
# 하는 일: 상품 300건의 벡터를 단마다 중심 16개의 k-means 로 3단 잔차 양자화해, 상품마다 코드 셋을 붙인다.
import math
import random
import zlib
from collections import Counter

# 1단계: 가상 상품 300건을 만들고 벡터로 바꾼다
# 아래 목록 넷과 make_products, DIM, embed 는 임베딩과 벡터 검색 편의 코드를 글자 그대로 옮겼다.
# 그 편은 3,000건을 만들었고, 이 글은 같은 함수로 앞 300건만 만든다. 이름의 난수는 시드 7 이다.
CATEGORIES = {
    '캠핑': ['캠핑의자', '캠핑테이블', '텐트'],
    '음향': ['헤드폰', '무선이어폰', '블루투스스피커'],
    '신발': ['운동화', '스니커즈', '러닝화'],
    '잡화': ['선글라스', '손목시계', '모자'],
    '가방': ['백팩', '크로스백', '여행가방'],
    '주방': ['프라이팬', '전기포트', '텀블러'],
    '뷰티': ['선크림', '립밤', '핸드크림'],
    '육아': ['유모차', '아기띠', '젖병'],
}
BRANDS = ['하이라이프', '온팩토리', '아틀라이프', '별랩', '윤라이프', '숲결', '모노웍스', '다온']
STYLES = ['슬림', '와이드', '베이직', '프로', '라이트', '접이식', '방수', '심플']
COLORS = ['블랙', '화이트', '그레이', '브라운', '카키', '네이비']


def make_products(n=3000, seed=7):
    rng = random.Random(seed)
    names = list(CATEGORIES)
    products = []
    for i in range(n):
        category = names[i % len(names)]
        noun = rng.choice(CATEGORIES[category])
        model = rng.choice('ABCDEFGHKLMRSTX') + rng.choice('ABCDEFGHKLMRSTX') + str(rng.randint(100, 999))
        name = ' '.join([rng.choice(BRANDS), rng.choice(STYLES), rng.choice(COLORS), noun, model])
        products.append({'id': i, 'name': name, 'category': category})
    return products


DIM = 384


def embed(text):
    chars = text.replace(' ', '').lower()
    vec = [0.0] * DIM
    for i in range(len(chars) - 1):
        vec[zlib.crc32(chars[i:i + 2].encode('utf-8')) % DIM] += 1.0
    norm = math.sqrt(sum(x * x for x in vec))
    return [x / norm for x in vec] if norm else vec


products = make_products(300)
vecs = [embed(p['name']) for p in products]
print(f'상품 {len(products)}건, 벡터 {DIM}차원, 길이 평균 '
      f'{sum(math.sqrt(sum(x * x for x in v)) for v in vecs) / len(vecs):.3f}, 첫 상품: {products[0]["name"]}')

# 2단계: k-means 를 둔다
# 중심 k 개를 벡터 k 개로 놓고, 배정과 갱신을 되풀이한다. 처음 고르는 벡터는 random.Random(7) 이 정한다.
# kmeans 를 부를 때마다 random.Random(7) 을 새로 만들어, 단마다 같은 자리의 벡터에서 출발한다.
# 배정은 벡터마다 거리 제곱이 가장 작은 중심을 고른다. 거리가 같으면 번호가 작은 중심이다.
# 갱신은 중심을 배정된 벡터의 평균으로 옮긴다. 배정된 벡터가 없는 빈 군집은 중심을 그대로 둔다.
# 배정이 앞 반복과 같으면 중심도 더 바뀌지 않으므로, iters 를 다 채우지 않고 멈춘다.
def sqdist(a, b):
    return sum((x - y) * (x - y) for x, y in zip(a, b))


def nearest(v, centers):
    dists = [sqdist(v, c) for c in centers]
    return dists.index(min(dists))


def kmeans(points, k, iters):
    rng = random.Random(7)
    start = rng.sample(range(len(points)), k)
    centers = [list(points[i]) for i in start]
    assign, rounds, first = None, 0, None
    while rounds < iters:
        new = [nearest(p, centers) for p in points]
        rounds += 1
        if first is None:
            first = new
        if new == assign:
            break
        assign = new
        for j in range(k):
            members = [p for p, a in zip(points, assign) if a == j]
            if members:
                centers[j] = [sum(col) / len(members) for col in zip(*members)]
    return centers, rounds, start, first


# 3단계: 잔차 양자화로 코드 셋을 붙인다
# 1단은 벡터를, 2단과 3단은 앞 단의 중심을 뺀 나머지인 잔차를 k-means 로 묶는다.
# 단마다 가장 가까운 중심의 번호가 그 단의 코드이고, 그 중심을 뺀 나머지가 다음 단의 잔차다.
# 단마다 배정 횟수, 쓰인 코드 수, 잔차 길이의 평균, 상품이 하나뿐인 코드 수(세 개 이하면 그 상품)를 찍는다.
# 상품이 가장 많이 몰린 코드는 첫 배정에서 받은 수와, 그 코드의 초기 중심이 어느 상품의 잔차였고
# 길이가 얼마였는지도 찍는다.
# 길이 0 인 초기 중심이 있는 단에서는 두 가지를 더 찍는다. 하나는 그 중심보다 가까운 초기 중심이
# 하나라도 있는 상품 수다. 2 × (r 과 c 의 내적) > (c 의 길이 제곱) 이면 c 가 길이 0 인 중심보다 가깝다.
# 다른 하나는 그 코드 안과 밖의 상품이 이 단에서 잔차 길이를 평균 얼마나 줄였는지와 그 코드의 마지막 중심 길이다.
def quantize(r, centers):
    c = nearest(r, centers)
    return c, [x - y for x, y in zip(r, centers[c])]


def rq_codes(vectors, levels=3, k=16, iters=20):
    resid = [list(v) for v in vectors]
    codes = [() for _ in vectors]
    books, starts = [], []
    for level in range(levels):
        centers, rounds, start, first = kmeans(resid, k, iters)
        start_len = [math.sqrt(sum(x * x for x in resid[i])) for i in start]
        before = [math.sqrt(sum(x * x for x in r)) for r in resid]
        zero = [j for j in range(k) if start_len[j] == 0]
        if zero:
            init = [resid[i] for i in start if any(resid[i])]
            init_sq = [sum(y * y for y in c) for c in init]
            beat = sum(1 for r in resid
                       if any(2 * sum(x * y for x, y in zip(r, c)) > cc for c, cc in zip(init, init_sq)))
        books.append(centers)
        starts.append(start)
        for i, r in enumerate(resid):
            c, resid[i] = quantize(r, centers)
            codes[i] += (c,)
        size = Counter(code[level] for code in codes)
        big, n = size.most_common(1)[0]
        alone = [i for i, code in enumerate(codes) if size[code[level]] == 1]
        after = [math.sqrt(sum(x * x for x in r)) for r in resid]
        print(f'{level + 1}단: 배정 {rounds}번, 쓰인 코드 {len(size)}개, 잔차 길이 평균 {sum(after) / len(after):.3f}')
        print(f'  상품이 하나뿐인 코드 {len(alone)}개'
              + (', 그 상품: ' + ', '.join(map(str, alone)) if 0 < len(alone) <= 3 else ''))
        print(f'  가장 큰 코드 {big} 에 {n}건 (첫 배정 {first.count(big)}건), '
              f'그 코드의 초기 중심은 상품 {start[big]} 의 잔차, 길이 {start_len[big]:.3f}')
        if zero:
            z = zero[0]
            ins = [i for i, code in enumerate(codes) if code[level] == z]
            outs = [i for i, code in enumerate(codes) if code[level] != z]
            gain = lambda ids: sum(before[i] - after[i] for i in ids) / len(ids) if ids else 0.0
            print(f'  길이 0 인 초기 중심은 코드 {z}, 그보다 가까운 초기 중심이 하나라도 있는 상품 {beat}건')
            print(f'  잔차 길이 평균의 감소: 코드 {z} 의 {len(ins)}건 {gain(ins):.3f}, 나머지 {len(outs)}건 {gain(outs):.3f}, '
                  f'코드 {z} 의 마지막 중심 길이 {math.sqrt(sum(x * x for x in centers[z])):.3f}')
    print(f'초기 중심이 된 상품 {k}건: ' + ', '.join(map(str, starts[0])))
    print(f'단마다 초기 중심이 같은 상품인가: {all(s == starts[0] for s in starts)}')
    return codes, books


codes, books = rq_codes(vecs)
print(f'코드북 벡터 {sum(len(b) for b in books)}개 (3단 × 16개), 상품 0 의 코드 셋 {codes[0]}')

# 코드 셋마다 상품 id 를 작은 것부터 모은다. 묶음 안의 차례 0, 1, 2 … 가 넷째 자리다.
leaves = {}
for pid, code in enumerate(codes):
    leaves.setdefault(code, []).append(pid)
shared = [ids for ids in leaves.values() if len(ids) > 1]
largest = max(leaves, key=lambda code: len(leaves[code]))
print(f'코드 셋 {len(leaves)}가지, 앞 두 코드 {len({code[:2] for code in codes})}가지')
print(f'코드 셋을 다른 상품과 함께 쓰는 상품 {sum(len(ids) for ids in shared)}건, '
      f'묶음 {len(shared)}개, 가장 큰 묶음 {len(leaves[largest])}건')
for n, pid in enumerate(leaves[largest]):
    print(f'  {largest + (n,)} {products[pid]["name"]}')
full = [code + (leaves[code].index(pid),) for pid, code in enumerate(codes)]
print(f'넷째 자리까지 붙인 id {len(full)}개 가운데 서로 다른 id {len(set(full))}개, 상품 0 의 id {full[0]}')

# 단마다 초기 중심이 같은 상품인가: True

# 4단계 뜻: 코드 셋은 147가지라 226건이 다른 상품과 겹치고, 넷째 자리를 붙이면 id 300개가 모두 다르다.
# 코드 셋 147가지, 앞 두 코드 138가지
# 코드 셋을 다른 상품과 함께 쓰는 상품 226건, 묶음 73개, 가장 큰 묶음 7건
#   (2, 7, 9, 0) 별랩 심플 그레이 블루투스스피커 AM119
#   (2, 7, 9, 1) 다온 방수 그레이 유모차 AH797

#   (2, 7, 9, 3) 별랩 와이드 그레이 러닝화 KK744

#   (2, 7, 9, 5) 온팩토리 와이드 그레이 블루투스스피커 FC536
#   (2, 7, 9, 6) 숲결 방수 그레이 립밤 BB231
# 넷째 자리까지 붙인 id 300개 가운데 서로 다른 id 300개, 상품 0 의 id (8, 6, 9, 0)
```

잔차 길이의 평균은 1.000 에서 0.837, 0.778, 0.748 로 줄었습니다. 1단과 2단은 배정을 5번과 7번 하고 멈췄고, 가장 큰 코드는 34건과 55건이었습니다. 3단은 달랐습니다. 배정 2번 만에 멈췄고, 300건 가운데 284건이 코드 9 하나에 들어갔습니다. 코드 9 를 뺀 나머지 코드 가운데 14개는 상품이 1건뿐이었습니다. 3단에서 잔차 길이 평균이 0.778 에서 0.748 로 준 것은 거의 코드 9 밖의 16건에서 나왔습니다. 코드 9 의 284건은 잔차 길이가 평균 0.000 줄었고, 나머지 16건은 0.571 줄었습니다.

코드 9 의 초기 중심은 상품 29 의 잔차였고, 그 길이가 0 이었습니다. 첫 배정에서 이미 284건이 코드 9 로 갔고, 끝까지 그대로였습니다. 2단에서 상품이 하나뿐인 코드는 하나였고, 그 상품이 29 였습니다. 묶음에 상품이 하나뿐이면 중심이 그 상품의 잔차가 되어, 상품 29 의 잔차는 2단 뒤 0 이 됩니다. 이 글은 단마다 같은 상품 16건에서 출발하므로, 3단의 코드 9 도 상품 29 의 잔차에서 출발했습니다. 잔차 $r$ 에 길이 0 인 중심보다 초기 중심 $c$ 가 가까울 조건은 $2 r \cdot c > \lVert c \rVert^2$ 입니다. 3단에서 이 부등식을 채우는 초기 중심이 하나라도 있는 상품은 16건뿐이었고, 나머지 284건이 코드 9 로 갔습니다.

그래서 셋째 코드는 상품을 거의 나누지 못했습니다. 앞 두 코드의 조합이 138가지였는데, 셋째 코드까지 붙여도 147가지였습니다. 코드 셋을 다른 상품과 함께 쓰는 상품은 226건, 그런 묶음은 73개, 가장 큰 묶음은 7건이었습니다. 이 충돌의 대부분은 셋째 단이 앞 두 코드의 조합을 거의 나누지 못한 데서 왔습니다. TIGER 는 코드 셋이 같은 상품의 끝에 코드 하나를 더 붙여 구분했고, 충돌이 없는 상품에도 넷째 코드 0 을 붙였습니다. (12, 24, 52) 를 함께 받은 두 상품은 (12, 24, 52, 0) 과 (12, 24, 52, 1) 이 됩니다. 묶음 안에서 id 가 작은 상품부터 0, 1, 2 를 주는 차례는 이 글이 정한 것이고, 넷째 자리까지 붙이자 id 300개가 모두 달랐습니다.

## 3. 코드 트리에서 생성해 꺼냅니다

**코드 셋을 첫째 코드부터 가지로 나누면 트리가 됩니다. 회원 A 가 본 상품 셋의 평균 벡터에서 출발해 단마다 코드를 3개씩 남기며 내려가, 리프 셋에서 상품 10건을 꺼냈습니다.**

코드 셋을 첫째, 둘째, 셋째 코드 차례로 가지에 달면 트리가 됩니다. 앞자리가 같은 코드 셋은 같은 가지를 나눠 씁니다. 이런 트리를 trie, 또는 접두사 트리라고 부르고, 이 글은 코드 셋으로 만든 trie 를 코드 트리라고 부릅니다. 맨 아래 노드인 리프(leaf) 하나가 코드 셋 하나입니다. 리프에는 그 코드 셋을 받은 상품이 넷째 자리 차례로 달립니다.

TIGER 는 회원이 본 상품들의 Semantic ID 를 차례로 이어 Transformer 에 넣습니다. 모델은 다음에 볼 상품의 Semantic ID 를 코드 하나씩 생성하도록 학습합니다. [LLM 호출 한 번](post.html?id=llm-first-call) 편에서 본 다음 토큰 생성과 같은 꼴이고, 토큰 자리에 코드가 들어갑니다. 생성한 코드 셋으로 표를 찾아 상품을 꺼냅니다. 검색을 생성으로 바꾸는 생각은 문서 검색에서 먼저 나왔습니다. Tay 외(2022)의 DSI 는 질의를 넣으면 관련 문서의 id 를 바로 생성했습니다.

이 글은 학습한 생성 모델 대신 규칙으로 코드를 고릅니다. 회원 A 가 본 상품 셋의 벡터를 평균하고, 단마다 그 평균에서 지금까지 고른 중심을 뺀 잔차와 가장 가까운 코드를 고릅니다. 진짜 생성 모델은 이 자리에서 회원이 본 상품들의 코드를 읽고 다음 코드를 스스로 고릅니다. 회원 A 가 본 상품 셋은 가상 값입니다. 회원 A 의 관심사인 러닝과 여행에 맞춰, 러닝화 가운데 id 가 가장 작은 둘과 여행가방 가운데 가장 작은 하나를 골랐습니다.

빔 탐색(beam search)은 단마다 가장 좋은 하나만 고르지 않고, 점수가 좋은 몇 개를 남겨 다음 단으로 가는 방법입니다. 남기는 개수를 빔 폭이라고 부르고, 이 글은 3 입니다. 점수는 고른 중심들을 뺀 뒤 남은 잔차의 거리 제곱이고, 작을수록 좋습니다. 빔은 트리에 있는 가지만 펼치므로, 상품이 없는 코드 셋은 고르지 않습니다. 마지막에 남은 코드 셋 3개의 리프에서 상품을 꺼내고, 회원 A 가 이미 본 상품은 뺍니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 회원 A 가 본 상품 셋의 평균 벡터로 단마다 코드를 빔 3 으로 골라 코드 트리에서 상품을 꺼내고, 전수 코사인 상위와 겹치는 수를 센다.

# 1단계: 코드 트리를 만든다
# 첫째 코드 아래에 둘째 코드, 그 아래에 셋째 코드를 달고, 셋째 코드에 상품 id 목록을 둔다.
tree = {}
for (c1, c2, c3), ids in leaves.items():
    tree.setdefault(c1, {}).setdefault(c2, {})[c3] = ids
print(f'1단 노드 {len(tree)}개, 2단 노드 {sum(len(t) for t in tree.values())}개, 리프 {len(leaves)}개')
print(f'코드 셋 16 × 16 × 16 = {16 ** 3:,}가지 가운데 상품이 있는 것 {len(leaves)}가지')

# 2단계: 회원 A 가 본 상품 셋을 둔다
# 가상 값이다. 회원 A 의 관심사 러닝과 여행에 맞춰, 러닝화 가운데 id 가 가장 작은 둘과
# 여행가방 가운데 id 가 가장 작은 하나를 고른다. 이름의 첫 낱말이 상표, 넷째 낱말이 품목이다.
noun = {p['id']: p['name'].split()[3] for p in products}
brand = {p['id']: p['name'].split()[0] for p in products}
HISTORY = [pid for pid in noun if noun[pid] == '러닝화'][:2] + [pid for pid in noun if noun[pid] == '여행가방'][:1]
for pid in HISTORY:
    print(f'  본 상품 {pid} {products[pid]["name"]} 코드 셋 {codes[pid]}')


# 3단계: 빔 탐색으로 단마다 코드를 고른다
# 본 상품 셋의 평균 벡터에서 출발해, 단마다 트리에 있는 코드만 하나씩 붙여 본다.
# 점수는 고른 중심들을 뺀 뒤 남은 잔차의 거리 제곱이고, 작을수록 좋다. 점수가 같으면 코드가 작은 쪽이 앞이다.
# 단마다 점수가 작은 width 개만 남기고 다음 단으로 간다. 마지막에 남은 코드 셋의 상품을 꺼낸다.
def mean(vs):
    return [sum(col) / len(vs) for col in zip(*vs)]


def beam(history, width=3):
    paths = [((), mean([vecs[i] for i in history]))]
    kept = []
    for level in range(3):
        cands = []
        for path, r in paths:
            node = tree
            for c in path:
                node = node[c]
            for c in sorted(node):
                rest = [x - y for x, y in zip(r, books[level][c])]
                cands.append((sum(x * x for x in rest), path + (c,), rest))
        cands.sort(key=lambda t: (t[0], t[1]))
        paths = [(path, rest) for _, path, rest in cands[:width]]
        kept.append([path for path, _ in paths])
        print(f'{level + 1}단: 후보 {len(cands)}개 가운데 ' +
              ', '.join(f'{path} {score:.3f}' for score, path, _ in cands[:width]))
    return kept


kept = beam(HISTORY)
got = []
for c1, c2, c3 in kept[-1]:
    ids = tree[c1][c2][c3]
    got += [pid for pid in ids if pid not in HISTORY]
    print(f'  {(c1, c2, c3)} 상품 {len(ids)}건: ' + ', '.join(f'{pid} {brand[pid]} {noun[pid]}' for pid in ids))
print(f'꺼낸 상품 {len(got)}건 (본 상품은 뺐다)')

# 4단계: 같은 평균 벡터로 전수 코사인 상위 k 를 찾고 겹치는 수를 센다
# cosine 은 임베딩과 벡터 검색 편의 코드 그대로다. 본 상품 셋은 빼고, 점수가 같으면 id 가 작은 쪽이 앞이다.
# k 는 빔이 꺼낸 상품 수와 같게 둔다. 전수 상위 상품마다 빔이 그 상품의 앞자리 코드를 몇 단에서 버렸는지 본다.
def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))
    return dot / (na * nb) if na and nb else 0.0


def dropped(pid):
    for level in range(3):
        if codes[pid][:level + 1] not in kept[level]:
            return level + 1
    return 0

top = ranked[:k]

for n, pid in enumerate(top, 1):
    where = f'{dropped(pid)}단에서 빠짐' if dropped(pid) else '빔도 꺼냄'
    print(f'  전수 {n}위 {score[pid]:.3f} {products[pid]["name"]} {codes[pid]} {where}')

      f'3단에서 빠짐 {gone[3]}건, 빔도 꺼냄 {gone[0]}건')

def path_score(code):
    r = q
    for level, c in enumerate(code):
        r = [x - y for x, y in zip(r, books[level][c])]
    return sum(x * x for x in r)
```

## 4. 전수 검색과 겹치는 수를 셉니다

**같은 평균 벡터로 상품 297건과 코사인을 모두 쟀습니다. 상위 10건 가운데 빔이 꺼낸 상품은 1건이었습니다. 나머지 9건 가운데 6건은 빔의 1단에서, 3건은 2단에서 빠졌습니다.**

전수 검색은 질의 벡터와 모든 상품의 코사인을 재서 큰 순서로 고르는 방법이고, 23주째 편 3절에서 보았습니다. 이 글은 회원 A 가 본 상품 셋을 빼고 297건과 쟀습니다. 비교할 상위의 수는 빔이 꺼낸 수에 맞춰 k = 10 으로 두었습니다. 점수가 같으면 id 가 작은 상품을 앞에 둡니다.

겹친 상품은 1건으로, 전수 7위의 여행가방이었습니다. 전수 상위 10건 가운데 6건은 러닝화였고, 빔이 꺼낸 10건에는 러닝화가 없었습니다. 빔이 꺼낸 10건 가운데 9건은 온팩토리 상품이었고, 회원 A 가 본 여행가방도 온팩토리입니다. 아래 표는 전수 상위 10건이 빔의 어느 단에서 빠졌는지 적은 것입니다.

빔은 코드의 중심들이 평균 벡터에 얼마나 가까운지로 고르고, 전수 검색은 상품 하나하나의 벡터로 고릅니다. 2절에서 세 단을 거친 잔차의 길이 평균이 0.748 이었습니다. 코드 셋이 가리키는 중심의 합은 상품 벡터의 일부만 맞춥니다. 그래서 같은 리프 (13, 6, 9) 의 다섯 상품도 전수 순위가 7위에서 122위까지 흩어져 있었습니다. 코드가 가까운 리프의 상품이 꼭 코사인이 큰 상품은 아닙니다. 블록의 5단계는 리프 147개를 빔과 같은 점수로 모두 셌습니다. 전수 상위 10건이 든 리프는 겹친 상품의 2위를 빼면 6위부터 88위였습니다.

코드가 무엇을 묶는지는 내용 벡터가 정합니다. 장난감 임베딩은 글자 조각마다 1 을 더할 뿐이라, 상표와 색의 글자도 품목의 글자와 같은 무게로 셉니다. 2절의 가장 큰 묶음 (2, 7, 9) 에는 블루투스스피커, 유모차, 캠핑테이블, 러닝화가 함께 있었습니다. 품목은 제각각이고, 이름에는 모두 그레이가 들어 있습니다. 빔이 처음 고른 코드 13 의 리프에서는 온팩토리 상품이 나왔습니다. 회원 A 가 본 러닝화 둘도 첫째 코드가 10 과 6 이라 서로 다른 가지에 있었습니다.

실무의 생성형 검색은 이 차이를 두 곳에서 줄입니다. 하나는 뜻이 비슷한 상품을 가까이 두도록 학습한 인코더의 내용 벡터입니다. 다른 하나는 회원의 행동 시퀀스로 다음 상품을 맞히도록 학습한 생성 모델입니다. 이 글의 규칙에는 둘 다 없어서, 겹친 1건은 장난감의 한계를 보여 줍니다. TIGER 는 회원이 실제로 다음에 본 상품을 맞혔는지를 Recall@K 와 NDCG@K 로 쟀습니다. Recall@K 는 정답이 상위 K 안에 든 몫이고, NDCG@K 는 정답이 위에 있을수록 점수를 더 주는 지표입니다. 두 지표는 [Two-Tower Retrieval](post.html?id=two-tower-retrieval) 편 7절에 있습니다. 이 글에는 다음에 본 상품이 없어서, 같은 질의의 전수 상위와 비교했습니다.

## 5. 새 상품은 노출 전에 코드를 받습니다

**새 상품 10건은 코드북을 다시 학습하지 않고 내용 벡터만으로 코드 셋을 받았습니다. 8건은 있던 리프에, 2건은 새 리프에 들어갔고, 회원 A 의 빔은 그 가운데 2건을 바로 꺼냈습니다. id 임베딩 표에는 새 상품 10건의 행이 하나도 없었습니다.**

노출 기록이 없는 새 상품과 광고를 어떻게 다룰지를 콜드 스타트(cold start) 문제라고 부릅니다. [Cold Start](post.html?id=cold-start-pctr) 편은 이력이 없는 광고에 비슷한 광고의 숫자를 빌려 왔습니다. 후보를 고르는 단계에도 같은 문제가 있습니다. id 임베딩으로 후보를 고르는 모델에서, 새 상품의 행은 노출과 클릭이 쌓이고 모델을 다시 학습하기 전까지 비어 있습니다. TIGER 도 무작위 id 로 상품을 적는 모델은 학습 데이터에 노출이 없는 새 상품을 후보로 꺼내지 못한다고 적었습니다.

Semantic ID 는 상품의 이름만 있으면 코드를 줍니다. 새 상품의 벡터를 만들고, 학습해 둔 코드북으로 단마다 가장 가까운 중심을 고르면 코드 셋이 나옵니다. 코드북은 그대로이고 k-means 를 다시 돌리지 않습니다. 블록은 먼저 학습한 300건을 같은 방법으로 다시 적어, 1번 블록의 코드 셋과 같은지 봅니다. 새 상품 10건은 같은 `make_products` 로 310건을 만들어 뒤의 10건을 씁니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 새 상품 10건에 내용 벡터만으로 코드 셋을 붙여 트리에 넣고, 회원 A 의 빔이 바로 꺼내는지 본다. id 임베딩 표에는 새 상품의 행이 없는 것도 본다.

# 1단계: 새 상품 10건을 만든다
# 같은 make_products 로 310건을 만들어 뒤 10건을 쓴다. 앞 300건은 1번 블록의 상품과 같다.
more = make_products(310)
new = more[300:]
print(f'310건의 앞 300건이 1번 블록과 같은가: {more[:300] == products}, 새 상품 id {new[0]["id"]}~{new[-1]["id"]}')


# 2단계: 코드북은 그대로 두고 코드 셋을 붙인다
# encode 는 단마다 quantize 를 한 번씩 부른다. k-means 를 다시 돌리지 않는다.
# 학습한 300건을 같은 encode 로 다시 적어, 1번 블록의 코드 셋과 같은지 먼저 본다.
# 새 상품은 코드 셋의 리프 끝에 들어가고, 그 리프 안의 차례가 넷째 자리다.
def encode(v, books):
    code, r = (), list(v)
    for centers in books:
        c, r = quantize(r, centers)
        code += (c,)
    return code


print(f'학습한 300건 가운데 encode 의 코드 셋이 1번 블록과 같은 상품 {sum(encode(v, books) == code for v, code in zip(vecs, codes))}건')
joined = 0
for p in new:
    code = encode(embed(p['name']), books)
    ids = tree.setdefault(code[0], {}).setdefault(code[1], {}).setdefault(code[2], [])
    joined += bool(ids)
    state = f'상품 {len(ids)}건이 있던 리프' if ids else '새 리프'
    ids.append(p['id'])
    print(f'  {p["id"]} {p["name"]} {code + (len(ids) - 1,)} {state}')
print(f'있던 리프에 들어간 새 상품 {joined}건, 새 리프를 만든 상품 {len(new) - joined}건')
keep = sum(code + (tree[code[0]][code[1]][code[2]].index(pid),) == full[pid] for pid, code in enumerate(codes))
print(f'있던 300건 가운데 넷째 자리까지의 id 가 그대로인 상품 {keep}건')

# 3단계: 회원 A 의 빔을 다시 돌린다
# 코드북을 다시 학습하지 않아 가지마다 점수는 앞과 같다. 새 상품이 빔이 남긴 코드 아래에
# 새 가지를 만들었다면 후보가 늘었을 것이다. 후보 수와 고른 코드 셋이 2번 블록과 같은지 본다.
kept = beam(HISTORY)
fresh = [pid for c1, c2, c3 in kept[-1] for pid in tree[c1][c2][c3] if pid >= 300]
print(f'빔이 꺼낸 새 상품 {len(fresh)}건: ' + ', '.join(f'{pid} {more[pid]["name"]}' for pid in fresh))

# 4단계: 상품 id 임베딩 표에서 새 상품을 찾는다
# id 임베딩 방식은 상품 id 마다 노출과 클릭으로 학습한 벡터 한 행을 둔다. 여기서는 표의 키만 흉내 낸다.
# 학습 데이터에 있던 상품 300건만 행이 있다. 새 상품의 id 로 찾으면 행이 없다.
id_rows = {p['id'] for p in products}
missing = [p['id'] for p in new if p['id'] not in id_rows]
print(f'id 임베딩 표의 행 {len(id_rows)}개, 새 상품 {len(new)}건 가운데 행이 없는 상품 {len(missing)}건')
# 출력:
# 1단계 뜻: 새 상품 10건은 id 300~309 이고, 앞 300건은 1번 블록과 같다.
# 310건의 앞 300건이 1번 블록과 같은가: True, 새 상품 id 300~309
# 2단계 뜻: 코드북을 그대로 두고도 새 상품 10건이 모두 코드를 받았고, 8건은 있던 리프에 들어갔다.
# 학습한 300건 가운데 encode 의 코드 셋이 1번 블록과 같은 상품 300건
#   300 아틀라이프 프로 브라운 백팩 SH454 (11, 1, 9, 3) 상품 3건이 있던 리프
#   301 온팩토리 라이트 화이트 텀블러 CL804 (13, 6, 9, 5) 상품 5건이 있던 리프
#   302 온팩토리 심플 네이비 립밤 RD643 (13, 7, 9, 2) 상품 2건이 있던 리프
#   303 모노웍스 프로 화이트 유모차 KB370 (4, 4, 9, 0) 새 리프
#   304 다온 심플 화이트 캠핑테이블 HK159 (6, 7, 9, 5) 상품 5건이 있던 리프
#   305 아틀라이프 슬림 화이트 블루투스스피커 HD610 (11, 11, 9, 3) 상품 3건이 있던 리프
#   306 다온 라이트 브라운 스니커즈 HR676 (11, 8, 9, 0) 새 리프
#   307 온팩토리 베이직 네이비 손목시계 GG792 (13, 0, 9, 4) 상품 4건이 있던 리프
#   308 하이라이프 슬림 네이비 크로스백 MM129 (0, 6, 9, 3) 상품 3건이 있던 리프
#   309 온팩토리 심플 브라운 텀블러 XF928 (13, 12, 9, 1) 상품 1건이 있던 리프
# 있던 리프에 들어간 새 상품 8건, 새 리프를 만든 상품 2건
# 있던 300건 가운데 넷째 자리까지의 id 가 그대로인 상품 300건
# 3단계 뜻: 빔은 같은 코드 셋을 골랐고, 그 리프에 들어간 새 상품 2건을 꺼냈다.
# 1단: 후보 16개 가운데 (13,) 0.343, (6,) 0.357, (10,) 0.386
# 2단: 후보 31개 가운데 (13, 0) 0.317, (13, 6) 0.325, (6, 0) 0.336
# 3단: 후보 3개 가운데 (13, 0, 9) 0.320, (13, 6, 9) 0.328, (6, 0, 9) 0.336
# 빔이 꺼낸 새 상품 2건: 307 온팩토리 베이직 네이비 손목시계 GG792, 301 온팩토리 라이트 화이트 텀블러 CL804
# 4단계 뜻: 학습한 id 로만 행을 만든 표에는 새 상품 10건의 행이 없다.
# id 임베딩 표의 행 300개, 새 상품 10건 가운데 행이 없는 상품 10건
```

학습한 300건은 다시 적어도 300건 모두 같은 코드 셋이었습니다. 새 상품 10건 가운데 8건은 상품이 있던 리프에 들어가, 그 리프의 다음 차례를 넷째 자리로 받았습니다. 303 유모차와 306 스니커즈는 새 리프를 만들었습니다. 새 상품을 넣은 뒤에도 있던 300건의 넷째 자리는 그대로였습니다. 회원 A 의 빔은 앞과 같은 후보 수에서 같은 코드 셋 3개를 골랐습니다. 그 리프에 들어간 307 손목시계와 301 텀블러가 노출 기록 없이 후보로 나왔습니다.

| 무엇 | Semantic ID (3번 블록) | 상품 id 임베딩 (설명) |
|---|---|---|
| 새 상품에게 필요한 것 | 상품 이름의 내용 벡터 | 그 상품의 노출과 클릭 기록 |
| 코드나 벡터가 생기는 때 | 등록하자마자, 10건 모두 | 기록이 쌓이고 다시 학습한 뒤 |
| 다시 학습하는 것 | 없음, 코드북 그대로 | 새 행을 넣어 모델을 다시 학습 |
| 회원 A 의 후보에 | 2건이 바로 나옴 | 행이 없어 나오지 않음 |

표의 오른쪽 칸은 블록이 잰 것이 아니라 id 임베딩 방식의 설명입니다. 블록은 학습한 300건의 id 로만 행을 만든 표를 흉내 내, 새 상품 10건의 id 로 찾으면 행이 없다는 것만 보였습니다. 노출이 얼마나 쌓여야 쓸 만한 행이 되는지는 이 글이 재지 않았습니다.

TIGER 의 콜드 스타트 실험도 같은 구조였습니다. Amazon 리뷰의 Beauty 데이터에서 시험 상품의 5% 를 학습 데이터에서 빼 새 상품으로 두었습니다. 학습한 RQ-VAE 로는 새 상품에도 Semantic ID 를 붙였습니다. 모델이 생성한 코드와 앞의 셋이 같은 새 상품을 후보에 넣었고, 후보 가운데 새 상품의 몫은 ε 로 상한을 두었습니다. 논문은 이 Beauty 데이터에서 ε 가 0.1 이상일 때 내용 벡터로 가까운 이웃을 찾는 방법보다 나았다고 적었습니다.

다만 새 상품이 받은 것은 이웃과 같은 코드입니다. 리프의 다른 상품과 다른 것은 넷째 자리뿐이라, 빔은 새 상품이 잘 팔릴지를 모릅니다. 그래서 랭킹 단계가 비슷한 상품의 숫자를 빌려 오고, 노출을 조금씩 주며 기록을 쌓는 일은 그대로 남습니다.

## 6. 두 무대는 코드를 받는 대상과 생성 모델이 읽을 기록이 다릅니다

**코드 셋을 만들고 빔으로 꺼내는 셈은 두 무대가 같습니다. 다른 것은 코드를 받는 대상과 생성 모델이 읽을 기록입니다. 담장 안은 상품과 광고와 회원의 기록을 한곳에서 학습하고, 열린 RTB 의 DSP 는 자기 캠페인의 소재로 코드를 만듭니다.**

1~5절의 셈은 두 무대가 같습니다. 두 무대의 이름은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에서 풀었습니다.

### 담장 안에서는 상품과 회원의 기록이 한곳에 있습니다 [무대: 닫힌 생태계]

쇼핑과 광고를 함께 운영하는 플랫폼은 상품 목록, 광고 소재, 회원이 본 상품을 같은 회원 번호로 갖고 있습니다. 상품 이름과 설명, 이미지로 내용 벡터를 만들고 코드북을 학습한 뒤, 상품이 들어올 때마다 코드 셋을 붙입니다. 생성 모델은 로그인한 회원이 본 상품들의 코드 시퀀스로 학습합니다. 새 광고는 등록하는 날 코드를 받아, 5절처럼 같은 리프의 후보로 바로 나올 수 있습니다.

코드북을 다시 학습하면 상품의 코드가 바뀔 수 있습니다. TIGER 도 충돌을 찾아 넷째 코드를 붙이는 일은 RQ-VAE 를 학습한 뒤 한 번만 한다고 적었습니다. 그래서 코드북과 그 코드로 학습한 생성 모델은 한 버전으로 묶어 내보냅니다. 코드북을 바꾸면 생성 모델도 새 코드로 다시 학습합니다.

### 열린 RTB 에서는 회원의 기록이 짧습니다 [무대: 열린 RTB]

열린 RTB 에서 광고를 사는 DSP 가 코드를 붙일 수 있는 것은 자기 캠페인의 광고 소재입니다. 소재의 글과 이미지, 랜딩 페이지의 범주로 내용 벡터를 만들면, 새 소재도 캠페인에 올리는 날 코드를 받습니다. 매체의 상품 목록이나 다른 DSP 의 소재는 보지 못합니다.

생성 모델이 읽을 기록은 쿠키나 기기의 광고 ID 에 쌓인 입찰 요청입니다. 쿠키가 지워지면 기록이 처음부터 다시 쌓여, 회원 A 처럼 본 상품 셋을 이을 수 있는 요청이 적습니다. 그런 요청에서는 지면의 글을 내용 벡터로 바꿔 질의로 쓰는 방법을 함께 둡니다. 입찰 요청에는 답할 시간이 정해져 있어서, 빔 탐색과 생성 모델도 그 시간 안에 끝나야 합니다. 아래 표는 가상 데이터가 아니라 두 무대의 설계 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 코드를 받는 것 | 플랫폼의 상품과 광고 | DSP 가 가진 캠페인의 소재 |
| 내용 벡터의 재료 | 상품 이름, 설명, 이미지 | 소재의 글과 이미지, 랜딩 페이지 |
| 생성 모델이 읽는 기록 | 로그인한 회원이 본 상품의 코드 | 쿠키나 광고 ID 의 짧은 기록, 지면의 글 |
| 새 소재가 들어오면 | 등록하는 날 코드를 받는다 | 캠페인에 올리는 날 코드를 받는다 |

| id 임베딩 (설명) | 학습한 id 에만 행이 있다 | 새 상품 10건 모두 행 없음 |

## 헷갈리기 쉬운 점

- **Semantic ID 는 임베딩을 버리는 것이 아닙니다.** 코드는 내용 벡터를 양자화해 만들고, 코드북의 중심도 벡터입니다. 바뀌는 것은 상품마다 두던 벡터를 코드마다 둔다는 점입니다. TIGER 는 생성 모델의 임베딩 표에 상품마다 한 행이 아니라, 코드마다 한 행씩 256 × 4 = 1,024행을 둔다고 적었습니다. 이 글의 코드북도 상품 300건을 중심 48개로 적었습니다. 내용 벡터를 만드는 인코더를 바꾸면 코드북과 코드도 다시 만듭니다.

- **코드 충돌은 넷째 자리로 풉니다.** 이 글에서 코드 셋을 다른 상품과 함께 쓰는 상품은 226건이었습니다. 대부분은 셋째 단이 앞 두 코드의 조합 138가지를 147가지로밖에 나누지 못한 탓입니다. 묶음 안의 차례를 넷째 자리로 붙이자 id 300개가 모두 달라졌습니다. 새 상품은 그 리프의 다음 차례를 받았고, 있던 300건의 넷째 자리는 그대로였습니다. 코드북을 다시 학습하면 차례도 처음부터 다시 매깁니다.

- **생성형 검색도 후보를 고르는 단계입니다.** 빔이 꺼낸 10건은 순위가 아니라 후보입니다. 그 뒤에 pCTR 을 매기는 랭킹과 경매가 이어집니다. OneRec 의 초록은 지금의 생성형 검색이 대개 검색 단계에서 후보를 고르는 자리에만 쓰인다고 적었습니다. OneRec 은 검색과 랭킹을 이어 붙인 구조를 생성 모델 하나로 바꾸려는 시도입니다. 그런 구조의 단계마다 하는 일은 [Ad Serving Flow](post.html?id=ad-serving-flow) 편에 있습니다.

## 더 깊이 보기

:::deep k-means 의 배정과 갱신, 이 글의 규칙
한 단의 잔차를 $r_1, \dots, r_n$, 중심을 $c_1, \dots, c_k$ 라고 둡니다. 상품 $i$ 가 배정된 중심의 번호는 $a(i)$ 입니다. k-means 는 아래 $J$ 를 줄이는 방법입니다.

$$J = \sum_{i=1}^{n} \lVert r_i - c_{a(i)} \rVert^2$$

배정은 $a(i) = \arg\min_j \lVert r_i - c_j \rVert^2$ 이고, 거리가 같으면 번호가 작은 중심을 고릅니다. 갱신은 중심을 배정된 잔차의 평균 $c_j = \frac{1}{|S_j|} \sum_{i \in S_j} r_i$ 로 옮깁니다. $S_j$ 는 중심 $j$ 에 배정된 상품의 모임입니다. 두 걸음 모두 $J$ 를 늘리지 않고 배정의 가짓수는 유한해서, 언젠가 배정이 바뀌지 않는 때가 옵니다. 블록은 그때 멈추거나, 배정을 20번 하면 멈춥니다. $S_j$ 가 비면 나눌 수 없어서 그 중심은 그대로 둡니다.

초기 중심은 `kmeans` 를 부를 때마다 새로 만든 `random.Random(7)` 이 상품 16건을 골라 정합니다. 시드가 같아서 세 단 모두 같은 상품 16건의 잔차에서 출발하고, 블록이 그것을 찍었습니다. 3단의 코드 9 가 상품 29 의 잔차, 곧 길이 0 인 벡터에서 출발한 것도 이 규칙 때문입니다. 길이 0 인 중심과 잔차 $r$ 의 거리 제곱은 $\lVert r \rVert^2$ 입니다. 다른 중심 $c$ 와의 거리 제곱은 $\lVert r \rVert^2 - 2\, r \cdot c + \lVert c \rVert^2$ 입니다. 그래서 $2\, r \cdot c > \lVert c \rVert^2$ 일 때만 $c$ 가 더 가깝습니다. 3단의 첫 배정에서 이 부등식을 채우는 초기 중심이 하나라도 있는 상품은 16건이었고, 나머지 284건은 코드 9 로 갔습니다.

k-means 의 결과는 초기 중심에 따라 달라집니다. 한 코드에 상품이 몰리는 일은 논문들도 다뤘습니다. TIGER 는 대부분의 입력이 코드 몇 개에만 배정되는 일을 codebook collapse 라고 적었습니다. 그것을 막으려고 첫 학습 배치에 돌린 k-means 의 중심으로 코드북을 시작했습니다. OneRec 은 RQ-VAE 로 만든 코드는 분포가 고르지 않다는 점(hourglass 현상)을 들었습니다. 그래서 군집마다 상품을 같은 수만큼 넣는 balanced k-means 로 단마다 코드북을 만들었습니다.

DSI 의 문서 id 도 k-means 로 만들지만 방식이 다릅니다. 문서 임베딩을 10개 군집으로 나누고, 문서가 100건보다 많은 군집은 그 안의 문서끼리 다시 10개로 나눕니다. 100건 이하인 군집에서는 문서마다 0~99 가운데 번호 하나를 붙여 id 끝에 답니다. 이 글의 넷째 자리와 같은 구실입니다. 군집마다 다음 단을 따로 나누는 계층적 k-means 라서, 잔차를 나누는 이 글과 달리 같은 단의 코드북이 군집마다 다릅니다. TIGER 는 계층적 k-means 가 서로 다른 군집 사이의 뜻을 잃는다고 적었습니다.
:::

:::deep 빔 탐색의 점수와 셈
평균 벡터를 $q$, $d$ 단의 코드북을 $C_d$ 라고 둡니다. 코드 $(c_1, \dots, c_l)$ 까지 고른 경로의 점수는 아래와 같고, 작을수록 좋습니다.

$$s(c_1, \dots, c_l) = \Big\lVert\, q - \sum_{d=1}^{l} C_d[c_d] \,\Big\rVert^2$$

$l$ 단에서는 남은 경로마다 트리에 있는 자식 노드를 하나씩 붙여 점수를 세고, 점수가 작은 셋을 남깁니다. 점수가 같으면 코드가 작은 경로를 앞에 둡니다. 빔 폭이 1 이면 단마다 가장 좋은 하나만 남기는 탐색이 되고, 블록이 찍은 점수대로면 (13, 0, 9) 하나만 꺼냈을 것입니다.

블록은 1단에서 16개, 2단에서 31개, 3단에서 3개의 점수를 셌습니다. 코드 셋 4,096가지를 모두 세지 않고, 상품 297건의 코사인도 세지 않았습니다. 상품이 많아질수록 이 차이가 커집니다. 상품이 수억 건이어도 빔이 세는 점수는 빔 폭과 단마다 코드 수로 정해지기 때문입니다.

빔은 점수가 좋은 경로만 남기므로 가장 좋은 코드 셋을 놓칠 수 있습니다. 1단에서 버린 코드 아래에 더 가까운 리프가 있어도 다시 보지 않기 때문입니다. 이 글의 빔은 놓치지 않았습니다. 블록이 리프 147개를 같은 점수로 모두 세어 보니 상위 3개가 빔이 남긴 코드 셋과 같았습니다. 4절의 전수 상위 10건 가운데 1단에서 빠진 6건은 리프 점수 순위가 23~88위였습니다. 그 6건은 빔이 가지를 버려서가 아니라 코드의 점수에서 졌습니다. TIGER 는 상품이 없는 코드 셋이 나오면 빔을 넓혀 거르면 된다고 적었습니다. 앞자리만 맞춰 비슷한 상품을 꺼내는 방법은 다음 연구로 남겼습니다.
:::
