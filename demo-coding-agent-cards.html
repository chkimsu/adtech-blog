코딩 에이전트 카드 네 장

코딩 에이전트에게 맡긴 실험 하나가 계획, 구현, 실행, 보고를 지나는 자리를 한 장씩 봅니다. 네 단계, 스킬이 정하는 순서, 훅이 막는 것, 장부와 보고입니다. 숫자는 31주째 관심사 사전 편을 만든 Claude Code 세션의 발췌에서 셌습니다.

파랑 = 저장소에 놓인 파일 벽돌색 = 에이전트가 보낸 도구 호출 먹색 = Claude Code 와 검사 스크립트 회색 = 막힌 호출과 기록이 도는 시간 점선 상자 = 적어 둔 규칙과 사람의 승인

STEPS

계획, 구현, 실행, 보고

쉽게 말하면 실험 하나를 글로 적고, 코드를 고치고, 돌리고, 숫자를 다시 세어 적는 네 단계로 나눕니다.

시작에서 커밋까지 약 44분이었습니다. 실행 단계는 12분 25초, 보고 단계는 27분 20초였습니다. 모델 기록 셋은 기록 도구가 잰 662초였습니다.

SKILL

스킬이 정하는 순서

쉽게 말하면 계획서를 쓰는 스킬이 칸을 정하고, Task 를 맡기는 스킬이 구현자와 검토자를 부르는 차례를 정합니다.

Task 4 의 검토는 spec 통과, Critical 0, Important 0, Minor 6 이었습니다. 사람의 승인은 계획서와 병합, push 의 두 자리에만 있었습니다.

HOOK

훅이 막는 것

쉽게 말하면 도구가 실행되기 전에 그 입력을 코드로 읽고, 규칙을 어기면 종료 코드 2 로 막습니다.

예시 다섯 가운데 둘은 종료 코드 0, 셋은 2 를 받았습니다. 브랜치 이름이 없는 git push 와 bash -c 안의 명령은 놓쳤습니다.

LEDGER

장부와 보고

쉽게 말하면 구현자는 보고서를, 컨트롤러는 장부를 남기고, 검사기와 검토자가 그 숫자를 다시 셉니다.

발췌의 도구 호출 23번 가운데 gen-ads-data.py 가 10번이었습니다. 구현자의 사건에 사람의 승인은 0번이었습니다.

현업에서는 이렇게 씁니다

  • 코딩 에이전트에게 실험을 맡길 때는 세 가지를 정해 둡니다. 순서를 적은 계획서, 규칙을 막는 코드, 결과를 다시 세는 검사입니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 코딩 에이전트로 실험 돌리기 편에 이 카드들이 절마다 들어 있습니다. 발췌의 실험은 관심사 사전 만들기 편입니다.
