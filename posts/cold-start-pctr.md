오늘 아침 광고주가 새 소재를 열 개 올렸습니다. 노출도 클릭도 없습니다. 그런데 이 광고들을 랭킹에 넣으려면 pCTR이 있어야 합니다. eCPM은 pCTR × 입찰가로 계산되고, pCTR이 없으면 순위를 매길 수가 없습니다.

"모르니까 0"으로 두면 이 광고는 영원히 노출을 못 받습니다. 노출이 없으니 데이터도 안 쌓이고, 데이터가 없으니 계속 0입니다. **모르는 상태가 스스로를 유지합니다.**

그럼 뭐라고 줘야 할까요. 이 글은 그 숫자를 만드는 방법을 다룹니다.

> 한 줄 요약: 이력이 0인 광고의 pCTR은 **남의 이력을 빌려서** 만든다. 얼마나 세게 빌릴지는 손으로 찍지 않고, **같은 묶음 안 광고들이 얼마나 비슷한가**에서 계산해 낸다.

이 글의 자리를 먼저 밝혀 둡니다. 콜드스타트에는 두 갈래 질문이 있습니다. **"이 광고에 얼마나 노출을 줘서 알아볼까"**(탐색)와 **"지금 당장 이 광고에 어떤 숫자를 줄까"**(예측)입니다. 앞의 질문은 [탐색과 활용](post.html?id=exploration-exploitation)에서 다룹니다 — 탐색에 얼마를 쓰는지, ε-greedy와 밴딧이 어떻게 답하는지가 그 글에 있습니다.

**이 글은 뒤의 질문만 봅니다.** 노출을 얼마나 줄지와 무관하게, 랭킹에 넣을 숫자는 지금 있어야 합니다. 그 숫자를 만드는 계산이 여기 있습니다.

## 1. 새 광고에는 무엇이 있고 무엇이 없나

새 광고에 없는 것은 하나뿐입니다. **이 광고 자신의 성과 이력**입니다.

그런데 없는 것만 세다 보면 착각하게 됩니다. 실제로는 꽤 많은 것이 있습니다.

- **누가 올렸는지** 압니다. 같은 광고주의 다른 광고들은 이력이 있습니다.
- **어떤 업종인지** 압니다. 같은 카테고리의 광고들도 이력이 있습니다.
- **어떻게 생겼는지** 압니다. 이미지 크기, 영상 길이, 제목 글자 수, 랜딩 페이지 종류.
- **어디에 나갈지** 압니다. 타겟 지면과 세그먼트가 캠페인 설정에 있습니다.

즉 완전한 무지가 아닙니다. **비슷한 것들의 이력을 빌려 오면 됩니다.** 사람도 그렇게 판단합니다. 처음 가 본 식당이라도 "이 골목 국수집들은 대개 괜찮다"는 감각으로 기대치를 정합니다.

빌려 올 수 있는 계층이 여러 개라는 게 핵심입니다. **가까운 쪽이 더 정확하지만, 가까울수록 표본이 적습니다.** 이 저울이 이 글 전체의 주제입니다.

| 빌려 올 계층 | 표본 크기 | 새 광고와의 유사성 | 언제 쓰나 |
|---|---|---|---|
| 전체 평균 | 매우 큼 (수억 노출) | 낮음 | 아무 정보도 없을 때의 최후 수단 |
| 카테고리 평균 | 큼 (수천만) | 중간 | 광고주가 처음 들어왔을 때 |
| **광고주 평균** | 중간 (수십만~수백만) | 높음 | **대개 여기가 균형점** |
| 캠페인 평균 | 작음 (수만) | 매우 높음 | 같은 캠페인에 소재가 여러 개일 때 |
| 소재 그룹 평균 | 매우 작음 (수천) | 가장 높음 | 표본이 부족해 오히려 불안정 |

가상 데이터 기준이고, 값은 인벤토리 규모에 따라 달라집니다. 표를 아래에서 위로 읽으면 저울이 보입니다. **내려갈수록 비슷해지지만 표본이 마르고, 올라갈수록 표본은 넉넉하지만 남의 얘기가 됩니다.**

### 계층마다 얼마나 다른가 — 숫자로 보기

말로는 "가까운 쪽이 정확하다"가 당연해 보입니다. 실제로 얼마나 다른지 재 봅시다. 가상 데이터입니다.

```python
# 이력이 0인 광고에 pCTR을 얼마로 줄까 — 남의 이력을 빌려 온다.
#
# 새 광고는 노출도 클릭도 없다. 그런데 랭킹에 넣으려면 숫자가 있어야 한다.
# "모르니까 0" 은 영원히 노출을 못 받는다는 뜻이고, "모르니까 평균" 은 너무 거칠다.
# 실무의 답은 계층을 타고 빌려 오는 것이다: 전체 → 카테고리 → 광고주 → 이 광고.

# 가상 데이터: 광고주 3곳, 각자 광고 여러 개. (노출, 클릭)
DATA = {
    "패션몰A": [("A-1", 50_000, 1_250), ("A-2", 30_000, 690), ("A-3", 20_000, 500)],
    "게임사B": [("B-1", 80_000, 800), ("B-2", 40_000, 360)],
    "보험사C": [("C-1", 60_000, 300), ("C-2", 25_000, 150), ("C-3", 15_000, 75)],
}

# 계층별 평균 CTR을 구한다.
def ctr(imp, clk):
    return clk / imp if imp else 0.0

total_imp = total_clk = 0
adv_stats = {}
for adv, ads in DATA.items():
    i = sum(a[1] for a in ads)
    c = sum(a[2] for a in ads)
    adv_stats[adv] = (i, c)
    total_imp += i
    total_clk += c
global_ctr = ctr(total_imp, total_clk)

print(f"전체 평균 CTR  {global_ctr:.3%}  (노출 {total_imp:,} · 클릭 {total_clk:,})")
print("\n광고주별 평균 CTR")
for adv, (i, c) in adv_stats.items():
    print(f"  {adv:<8} {ctr(i, c):.3%}  (광고 {len(DATA[adv])}개)")
print()

# ── 새 광고가 들어왔다 ──
# 같은 광고주의 다른 광고들이 얼마나 비슷한지가 '빌려도 되는가'를 결정한다.
print("새 광고에 줄 사전 CTR (계층별로 빌릴 때)")
print(f"{'새 광고':<14}{'전체에서':>10}{'광고주에서':>12}{'차이':>10}")
for adv in DATA:
    a_ctr = ctr(*adv_stats[adv])
    print(f"{adv + '의 새 광고':<14}{global_ctr:>9.3%}{a_ctr:>11.3%}{(a_ctr/global_ctr - 1)*100:>+9.1f}%")
print()
print("→ 광고주마다 CTR이 2.5%와 0.5%로 5배 차이 난다.")
print("→ 전체 평균을 주면 보험사 새 광고는 5배 과대평가, 패션몰 새 광고는 과소평가된다.")
print("→ 그래서 가능한 한 가까운 계층에서 빌려야 한다.")

# 출력:
# 전체 평균 CTR  1.289%  (노출 320,000 · 클릭 4,125)
#
# 광고주별 평균 CTR
#   패션몰A     2.440%  (광고 3개)
#   게임사B     0.967%  (광고 2개)
#   보험사C     0.525%  (광고 3개)
#
# 새 광고에 줄 사전 CTR (계층별로 빌릴 때)
# 새 광고                전체에서       광고주에서        차이
# 패션몰A의 새 광고       1.289%     2.440%    +89.3%
# 게임사B의 새 광고       1.289%     0.967%    -25.0%
# 보험사C의 새 광고       1.289%     0.525%    -59.3%
#
# → 광고주마다 CTR이 2.5%와 0.5%로 5배 차이 난다.
# → 전체 평균을 주면 보험사 새 광고는 5배 과대평가, 패션몰 새 광고는 과소평가된다.
# → 그래서 가능한 한 가까운 계층에서 빌려야 한다.
```

광고주 세 곳의 평균 CTR이 2.44%, 0.97%, 0.53%입니다. **가장 높은 곳과 낮은 곳이 4.6배 차이 납니다.**

이 차이가 곧 계층 선택의 값입니다. 전체 평균(1.29%)을 새 광고에 그대로 주면, 보험사 새 광고는 실제보다 2.5배 높게, 패션몰 새 광고는 절반 가까이 낮게 시작합니다.

높게 주는 게 낫다고 생각할 수도 있습니다. 노출을 많이 받아 빨리 배우니까요. 그런데 그 노출은 **다른 광고가 받을 자리를 빼앗은 것**입니다. 과대평가된 광고가 노출을 먹는 동안 진짜 좋은 광고는 밀립니다. 그리고 광고주는 성과 없는 노출에 돈을 냅니다.

## 2. 빌려 온 숫자에서 자기 숫자로 — 수축 [무대: 공통]

빌려 온 사전 CTR로 시작했다고 합시다. 노출 100회에 클릭 4번이 왔습니다. 이제 CTR을 4%로 바꿔야 할까요.

100회는 너무 적습니다. 진짜 CTR이 2%인 광고도 100번 중 4번 눌릴 수 있습니다. **관측값을 그대로 믿으면 운을 실력으로 착각합니다.**

그래서 실무는 두 숫자를 섞습니다. 빌려 온 사전 CTR과 이 광고의 관측 CTR입니다. 노출이 적을 때는 사전 쪽에 무게를 두고, 노출이 쌓이면 관측 쪽으로 무게를 옮깁니다. 이걸 **수축(shrinkage)** 이라고 부릅니다. 관측값을 사전값 쪽으로 끌어당긴다는 뜻입니다.

계산은 놀랄 만큼 간단합니다. 분자와 분모에 가상의 숫자를 더하면 끝입니다.

$$\hat{p} = \frac{\text{클릭} + \alpha}{\text{노출} + \alpha + \beta}$$

여기서 $\alpha$와 $\beta$는 사전확률을 **가상의 노출·클릭으로 바꿔 놓은 값**입니다. 사전 CTR이 2%이고 "노출 500회쯤 본 셈으로 치자"면 $\alpha = 10$, $\beta = 490$입니다. 실제로 노출 500회를 관측하기 전까지는 이 가상 노출이 절반 이상의 발언권을 갖습니다.

$\alpha + \beta$를 **사전 강도**라고 부르겠습니다. 이 숫자 하나가 "자기 데이터를 언제부터 믿을지"를 정합니다.

### 노출이 쌓이는 과정을 따라가 보기

```python
# 노출이 쌓이면 언제부터 이 광고의 자기 데이터를 믿나 — 수축(shrinkage) 계산.
#
# 새 광고에 노출 100회를 주고 클릭 4번을 받았다. CTR 4%인가?
# 표본이 100회면 우연히 4번 눌릴 수도 있다. 그래서 사전확률 쪽으로 끌어당긴다.
# 이걸 수축이라 하고, 베타-이항 모형으로 한 줄에 담긴다:
#
#   추정 CTR = (클릭 + α) / (노출 + α + β)
#
# 여기서 α, β는 사전확률을 "가상의 노출·클릭"으로 바꾼 값이다.
#   사전 CTR = α / (α + β),   사전 강도 = α + β  (가상 노출 수)

PRIOR_CTR = 0.02        # 광고주 평균에서 빌린 사전 CTR 2%
STRENGTH = 500          # 사전 강도 = 가상 노출 500회로 치겠다

alpha = PRIOR_CTR * STRENGTH
beta = STRENGTH - alpha
print(f"사전 CTR {PRIOR_CTR:.1%} · 사전 강도 {STRENGTH}회  →  α={alpha:.0f}, β={beta:.0f}")
print("  (\"노출 500회에 클릭 10번 본 셈으로 시작한다\"는 뜻)\n")

def shrunk(clicks, imps, a=alpha, b=beta):
    return (clicks + a) / (imps + a + b)

# 진짜 CTR이 5%인 좋은 광고가 들어왔다고 하자. 노출이 쌓이는 과정을 본다.
TRUE = 0.05
print(f"진짜 CTR {TRUE:.0%}인 광고가 들어왔을 때")
print(f"{'노출':>8}{'클릭':>6}{'날것 CTR':>11}{'수축 CTR':>11}{'사전 비중':>11}")
for imps in (0, 50, 200, 1_000, 5_000, 20_000, 100_000):
    clicks = round(imps * TRUE)                    # 딱 기대만큼 눌렸다고 가정
    raw = clicks / imps if imps else float('nan')
    s = shrunk(clicks, imps)
    prior_weight = STRENGTH / (imps + STRENGTH)    # 추정값에서 사전확률이 차지하는 몫
    raw_txt = f"{raw:.3%}" if imps else "   —"
    print(f"{imps:>8,}{clicks:>6,}{raw_txt:>11}{s:>10.3%}{prior_weight:>10.1%}")
print()

# 언제부터 자기 데이터가 절반을 넘나 = 노출이 사전 강도를 넘는 순간
print(f"사전확률의 비중이 절반으로 떨어지는 지점  노출 {STRENGTH:,}회")
print("  → 사전 강도가 곧 '자기 데이터를 믿기 시작하는 문턱'이다.\n")

# ── 사전 강도를 잘못 잡으면 ──
# 위 표는 "딱 기대만큼 눌렸다"고 가정했다. 실제로는 운이 섞인다.
# 그래서 새 광고 2,000개를 굴려 오차의 크기와 흔들림을 함께 본다.
import random
random.seed(42)

TRIALS = 2_000
IMPS = 1_000            # 새 광고마다 노출 1,000회를 준다

print(f"새 광고 {TRIALS:,}개를 노출 {IMPS:,}회씩 굴렸을 때 (진짜 CTR {TRUE:.0%})")
print(f"{'사전 강도':>10}{'평균 추정':>11}{'평균 오차':>11}{'흔들림(표준편차)':>18}{'최악':>9}")
for st in (50, 200, 500, 2_000, 10_000):
    a = PRIOR_CTR * st
    b = st - a
    ests = []
    for _ in range(TRIALS):
        clicks = sum(1 for _ in range(IMPS) if random.random() < TRUE)
        ests.append(shrunk(clicks, IMPS, a, b))
    mean = sum(ests) / TRIALS
    var = sum((e - mean) ** 2 for e in ests) / TRIALS
    sd = var ** 0.5
    worst = max(abs(e - TRUE) for e in ests)
    print(f"{st:>10,}{mean:>10.3%}{(mean/TRUE-1)*100:>+10.1f}%{sd:>17.4%}{worst:>8.2%}")
print()
print("→ 강도가 약하면 평균은 진짜에 가깝지만 흔들림이 크다. 같은 광고가 운에 따라 크게 다르게 평가된다.")
print("→ 강도가 세면 흔들림은 작아지지만 평균이 사전확률 쪽으로 눌린다. 좋은 광고를 오래 못 알아본다.")
print("→ 노출을 못 받으면 데이터도 안 쌓이니, 과소평가는 스스로를 강화한다. 이게 콜드스타트의 덤이다.")
print("→ 그래서 강도는 '이 계층 안에서 광고들이 얼마나 비슷한가'로 정한다. 비슷할수록 세게 빌려도 된다.")

# 출력:
# 사전 CTR 2.0% · 사전 강도 500회  →  α=10, β=490
#   ("노출 500회에 클릭 10번 본 셈으로 시작한다"는 뜻)
#
# 진짜 CTR 5%인 광고가 들어왔을 때
#       노출    클릭     날것 CTR     수축 CTR      사전 비중
#        0     0          —    2.000%    100.0%
#       50     2     4.000%    2.182%     90.9%
#      200    10     5.000%    2.857%     71.4%
#    1,000    50     5.000%    4.000%     33.3%
#    5,000   250     5.000%    4.727%      9.1%
#   20,000 1,000     5.000%    4.927%      2.4%
#  100,000 5,000     5.000%    4.985%      0.5%
#
# 사전확률의 비중이 절반으로 떨어지는 지점  노출 500회
#   → 사전 강도가 곧 '자기 데이터를 믿기 시작하는 문턱'이다.
#
# 새 광고 2,000개를 노출 1,000회씩 굴렸을 때 (진짜 CTR 5%)
#      사전 강도      평균 추정      평균 오차         흔들림(표준편차)       최악
#         50    4.851%      -3.0%          0.6565%   2.24%
#        200    4.513%      -9.7%          0.5780%   2.25%
#        500    3.980%     -20.4%          0.4595%   2.40%
#      2,000    2.998%     -40.0%          0.2278%   2.60%
#     10,000    2.274%     -54.5%          0.0631%   2.95%
#
# → 강도가 약하면 평균은 진짜에 가깝지만 흔들림이 크다. 같은 광고가 운에 따라 크게 다르게 평가된다.
# → 강도가 세면 흔들림은 작아지지만 평균이 사전확률 쪽으로 눌린다. 좋은 광고를 오래 못 알아본다.
# → 노출을 못 받으면 데이터도 안 쌓이니, 과소평가는 스스로를 강화한다. 이게 콜드스타트의 덤이다.
# → 그래서 강도는 '이 계층 안에서 광고들이 얼마나 비슷한가'로 정한다. 비슷할수록 세게 빌려도 된다.
```

위 표를 따라가면 수축이 무엇인지 손에 잡힙니다.

노출 0회에서는 추정값이 사전 CTR 2%와 똑같습니다. 아직 자기 데이터가 없으니 당연합니다. 노출 200회에서 관측 CTR은 5%인데 추정은 2.86%입니다. **아직 사전확률이 71.4%의 발언권을 갖고 있습니다.** 노출 5,000회에서 4.73%, 10만 회에서 4.99%로 진짜 값에 붙습니다.

눈여겨볼 지점은 **사전 강도 500이 곧 문턱**이라는 것입니다. 노출이 500회를 넘는 순간 사전확률의 비중이 절반 아래로 떨어집니다. 사전 강도를 정하는 일은 곧 "노출 몇 회부터 이 광고를 스스로 판단하게 할까"를 정하는 일입니다.

아래쪽 시뮬레이션이 그 선택의 대가를 보여 줍니다. 새 광고 2,000개를 굴려 보면 이렇게 갈립니다.

- **강도 50** — 평균 오차 -3.0%로 정확하지만, 흔들림(표준편차)이 0.66%p입니다. 같은 광고가 운에 따라 크게 다르게 평가됩니다.
- **강도 10,000** — 흔들림이 0.06%p로 열 배 작아지지만, 평균이 진짜의 절반(-54.5%)까지 눌립니다.

이게 편향과 분산의 상충입니다. 그런데 광고에서는 한쪽이 더 위험합니다. **과소평가는 스스로를 강화합니다.** 낮게 평가된 광고는 노출을 못 받고, 노출이 없으니 데이터가 안 쌓이고, 데이터가 없으니 계속 사전확률에 눌려 있습니다. 이 고리를 끊는 게 탐색의 역할이고, 그 이야기는 [탐색과 활용](post.html?id=exploration-exploitation)에 있습니다.

## 3. 사전 강도를 손으로 찍지 않는 법

앞 절에서 강도를 500, 2000처럼 임의로 넣었습니다. 실무에서 이 숫자를 어떻게 정할까요.

답은 데이터에 있습니다. **같은 묶음 안 광고들이 촘촘히 모여 있으면 세게 빌려도 되고, 널찍이 흩어져 있으면 약하게 빌려야 합니다.**

직관은 이렇습니다. 어떤 광고주의 기존 광고 CTR이 전부 2.3~2.5%에 몰려 있다면, 새 광고도 그 근처일 가능성이 높습니다. 세게 빌려도 손해가 적습니다. 반대로 기존 광고가 0.1%부터 1.4%까지 흩어져 있다면, 새 광고가 어디일지 전혀 모릅니다. 이때 세게 빌리면 엉뚱한 값에 붙잡힙니다.

이 '흩어짐'을 재서 강도로 바꾸는 방법이 있습니다. 베타 분포의 평균과 분산을 관측된 CTR들에 맞추면 됩니다(적률법).

$$m = \frac{\alpha}{\alpha+\beta}, \quad v = \frac{m(1-m)}{\alpha+\beta+1} \;\Rightarrow\; \alpha+\beta = \frac{m(1-m)}{v} - 1$$

분산 $v$가 작으면 강도가 커지고, 크면 작아집니다. 식이 정확히 우리 직관대로 움직입니다.

```python
# 사전 강도를 손으로 찍지 않고 데이터에서 구하는 법 — 경험적 베이즈.
#
# 앞에서 "강도는 이 계층 안에서 광고들이 얼마나 비슷한가로 정한다"고 했다.
# 그 '비슷함'을 실제로 재 보자. 같은 광고주의 기존 광고들의 CTR이
#   촘촘히 모여 있으면 → 새 광고도 그 근처일 것이다 → 세게 빌린다(강도 큼)
#   널찍이 흩어져 있으면 → 새 광고는 어디일지 모른다 → 약하게 빌린다(강도 작음)
#
# 베타 분포의 평균과 분산을 관측된 CTR들에 맞추면 α, β가 나온다(적률법).
#   평균 m = α/(α+β),  분산 v = m(1-m)/(α+β+1)
#   → 강도 s = α+β = m(1-m)/v - 1

def fit_strength(ctrs):
    """관측된 CTR 목록에서 사전 평균과 강도를 구한다."""
    n = len(ctrs)
    m = sum(ctrs) / n
    # 표본분산(자유도 n-1). 광고가 2개 미만이면 강도를 못 구한다.
    if n < 2:
        return m, None
    v = sum((c - m) ** 2 for c in ctrs) / (n - 1)
    if v <= 0:
        return m, None                      # 전부 같은 값 → 무한히 세게 빌려도 됨
    s = m * (1 - m) / v - 1
    return m, s

# 가상 데이터: 광고주 3곳의 기존 광고 CTR
GROUPS = {
    "패션몰A (소재가 다 비슷)":   [0.0244, 0.0231, 0.0250, 0.0238, 0.0246],
    "게임사B (장르가 섞임)":      [0.0097, 0.0180, 0.0042, 0.0131, 0.0068],
    "보험사C (상품마다 천차만별)": [0.0052, 0.0009, 0.0140, 0.0021, 0.0095],
}

print(f"{'광고주':<24}{'평균 CTR':>10}{'흩어짐(표준편차)':>18}{'구한 강도':>12}{'해석':>16}")
fitted = {}
for name, ctrs in GROUPS.items():
    m, s = fit_strength(ctrs)
    sd = (sum((c - m) ** 2 for c in ctrs) / (len(ctrs) - 1)) ** 0.5
    fitted[name] = (m, s)
    note = "세게 빌려도 됨" if s and s > 2000 else ("약하게" if s and s < 300 else "중간")
    print(f"{name:<24}{m:>9.3%}{sd:>17.4%}{s:>11,.0f}{note:>16}")
print()

# ── 구한 강도로 새 광고를 평가하면 ──
TRUE_NEW = 0.05          # 새 광고가 실제로는 아주 좋다고 하자
IMPS, CLICKS = 500, 25   # 노출 500회에 클릭 25회 (관측 CTR 5%)

print(f"새 광고: 노출 {IMPS}회 · 클릭 {CLICKS}회 (관측 {CLICKS/IMPS:.1%}, 진짜 {TRUE_NEW:.0%})")
print(f"{'광고주':<24}{'추정 CTR':>10}{'진짜와 차이':>13}")
for name, (m, s) in fitted.items():
    a = m * s
    b = s - a
    est = (CLICKS + a) / (IMPS + a + b)
    print(f"{name:<24}{est:>9.3%}{(est/TRUE_NEW-1)*100:>+12.1f}%")
print()
print("→ 소재가 비슷한 광고주(패션몰A)는 강도가 세게 나온다. 새 광고도 그 근처일 거라 믿는 것이다.")
print("→ 대신 이 광고주에서 진짜 튀는 광고가 나오면 알아보는 데 오래 걸린다.")
print("→ 상품마다 천차만별인 광고주(보험사C)는 강도가 약하게 나와 자기 데이터를 빨리 믿는다.")
print("→ 즉 강도를 손으로 찍을 필요가 없다. 기존 광고들의 흩어짐이 알려 준다.")

# 출력:
# 광고주                         평균 CTR         흩어짐(표준편차)       구한 강도              해석
# 패션몰A (소재가 다 비슷)            2.418%          0.0743%     42,744        세게 빌려도 됨
# 게임사B (장르가 섞임)              1.036%          0.5407%        350              중간
# 보험사C (상품마다 천차만별)           0.634%          0.5421%        213             약하게
#
# 새 광고: 노출 500회 · 클릭 25회 (관측 5.0%, 진짜 5%)
# 광고주                         추정 CTR       진짜와 차이
# 패션몰A (소재가 다 비슷)            2.448%       -51.0%
# 게임사B (장르가 섞임)              3.369%       -32.6%
# 보험사C (상품마다 천차만별)           3.694%       -26.1%
#
# → 소재가 비슷한 광고주(패션몰A)는 강도가 세게 나온다. 새 광고도 그 근처일 거라 믿는 것이다.
# → 대신 이 광고주에서 진짜 튀는 광고가 나오면 알아보는 데 오래 걸린다.
# → 상품마다 천차만별인 광고주(보험사C)는 강도가 약하게 나와 자기 데이터를 빨리 믿는다.
# → 즉 강도를 손으로 찍을 필요가 없다. 기존 광고들의 흩어짐이 알려 준다.
```

결과를 보면 강도가 스스로 정해집니다. 소재가 비슷한 패션몰A는 42,744, 천차만별인 보험사C는 213입니다. **200배 차이입니다.** 손으로 찍어서는 이런 차이를 낼 수 없습니다.

그 대가도 표에 나옵니다. 노출 500회에 클릭 25회(관측 5%)인 새 광고를 넣으면, 패션몰A 소속이면 2.45%로 평가됩니다. 진짜의 절반입니다. 이 광고주에서 진짜 튀는 광고가 나오면 알아보는 데 오래 걸립니다. 반면 보험사C 소속이면 3.69%로 훨씬 빨리 반응합니다.

**이건 버그가 아니라 설계입니다.** 소재가 비슷한 광고주에서 갑자기 5배 좋은 광고가 나올 확률은 실제로 낮습니다. 그 낮은 확률을 의심하는 것이 통계적으로 맞습니다. 다만 그 의심이 틀렸을 때 회복이 느리다는 걸 알고 써야 합니다.

### 계층을 어떻게 쌓나 [무대: 닫힌 생태계]

실무에서는 한 계층만 쓰지 않고 여러 층을 쌓습니다. 전체 → 카테고리 → 광고주 → 캠페인 순으로 좁혀 가며, 각 층에서 아래 층의 사전확률로 쓰는 식입니다.

담장 안(네이버·카카오 같은)에서는 이 계층이 잘 서 있습니다. 광고주 계정과 캠페인 구조가 플랫폼 소유라 **누가 무엇을 올렸는지 계층이 확실합니다.** 같은 광고주의 지난 1년 이력을 전부 볼 수 있고, 업종 분류도 심사 과정에서 이미 붙어 있습니다.

그래서 담장 안의 실무 관심사는 "계층을 어떻게 만들까"가 아니라 **"몇 층까지 내려갈까"** 입니다. 너무 좁히면 표본이 없고(캠페인 하나에 광고 두 개), 너무 넓히면 앞서 본 4.6배 차이에 묻힙니다. 대개 광고주 층이 표본과 유사성의 균형점입니다.

한 가지 실무 함정을 덧붙입니다. 광고주가 계정을 새로 만들면 계층도 새로 시작합니다. 큰 광고주가 대행사를 바꿔 계정을 옮기면, 실제로는 이력이 풍부한데 시스템에서는 콜드스타트가 됩니다. 이런 경우를 잡으려고 사업자번호나 브랜드명 같은 상위 키를 따로 두기도 합니다.

## 4. 피처가 있으면 계층을 안 타도 된다 [무대: 열린 RTB]

지금까지는 "누구 소속인가"로 빌렸습니다. 그런데 다른 방법이 있습니다. **광고의 생김새로 예측하는 것**입니다.

이력이 없어도 광고에는 특징이 있습니다. 이미지 크기, 영상 길이, 제목 글자 수, 업종, 랜딩 페이지 종류, 할인율 표기 여부. 모델이 이 특징들과 CTR의 관계를 이미 배워 뒀다면, **새 광고의 특징만 넣어도 예측이 나옵니다.**

이게 딥러닝 CTR 모델이 콜드스타트에 유리한 이유입니다. 광고 ID 임베딩만 쓰는 모델은 새 ID에 아무 정보가 없습니다. 하지만 콘텐츠 피처를 함께 쓰면 ID가 새것이어도 나머지 피처가 일을 합니다. 어떤 피처를 어떻게 만드는지는 [CTR 피처 엔지니어링 실전](post.html?id=ctr-feature-engineering)에서, 모델 구조는 [Deep CTR 모델의 진화](post.html?id=deep-ctr-models)에서 다룹니다.

열린 RTB에서는 이 방법에 훨씬 더 기댑니다. 이유는 계층이 부실하기 때문입니다. DSP는 남의 인벤토리에 입찰하므로 **유저 쪽 계층이 아예 없습니다.** 쿠키가 매번 달라 "이 유저의 이력"을 쌓을 수 없고, 그래서 유저 콜드스타트가 예외가 아니라 기본값입니다.

대신 광고·지면 쪽 계층은 있습니다. 그래서 열린 RTB의 콜드스타트 대응은 유저를 포기하고 **도메인·슬롯 크기·시간대 같은 문맥 피처**로 옮겨갑니다. 담장 안이 "이 사람을 안다"로 푸는 문제를, 열린 RTB는 "이 자리를 안다"로 푸는 셈입니다.

:::deep 더 깊이 — 왜 베타 분포이고, 왜 더하기 한 번으로 끝나는가

수축 공식이 `(클릭 + α) / (노출 + α + β)`처럼 단순한 이유가 있습니다. 베타 분포가 이항 분포의 **공액 사전분포**이기 때문입니다.

CTR을 확률 $p$라 하면, 노출 $n$회에 클릭 $k$번이 관측될 확률은 이항 분포입니다.

$$P(k \mid p) \propto p^{k} (1-p)^{n-k}$$

사전분포를 베타 $\text{Beta}(\alpha, \beta)$로 두면 그 밀도는 이렇습니다.

$$P(p) \propto p^{\alpha-1} (1-p)^{\beta-1}$$

베이즈 정리로 곱하면 지수끼리 더해집니다.

$$P(p \mid k) \propto p^{k+\alpha-1} (1-p)^{n-k+\beta-1}$$

이건 다시 베타 분포입니다 — $\text{Beta}(\alpha + k,\; \beta + n - k)$. **형태가 안 바뀌는 게 공액의 뜻입니다.** 그래서 갱신이 "더하기"로 끝납니다. 베타 분포의 평균이 $\frac{\alpha}{\alpha+\beta}$이므로, 갱신 후 평균이 곧 수축 공식이 됩니다.

실무에서 이 성질이 값진 이유는 계산이 아닙니다. **상태를 두 숫자로만 들고 있으면 된다는 점**입니다. 광고 하나당 (α, β) 두 개만 저장하면 되고, 노출·클릭이 올 때마다 더하기만 하면 됩니다. 광고가 수백만 개여도 감당이 됩니다.

한 가지 주의할 점이 있습니다. 이 모형은 CTR이 시간에 따라 변하지 않는다고 가정합니다. 실제로는 변합니다(계절성, 소재 피로). 그래서 실무에서는 과거 관측에 감쇠를 걸어 오래된 데이터의 발언권을 줄입니다. 그 이야기는 [Online Learning & Delayed Feedback](post.html?id=online-learning-delayed-feedback)에 있습니다.
:::

| 단계 | 무엇을 하나 | 이 글의 근거 |
|---|---|---|
| 1 | 빌려 올 계층을 고른다 (광고주 층이 대개 균형점) | 광고주별 CTR이 4.6배 차이 (§1) |
| 2 | 그 계층의 기존 광고 흩어짐으로 강도를 계산한다 | 42,744 vs 213, 200배 차이 (§3) |
| 3 | 수축 공식으로 pCTR을 만든다 | 분자·분모에 더하기 한 번 (§2) |
| 4 | 콘텐츠 피처가 있으면 계층 의존을 줄인다 | ID가 새것이어도 나머지 피처가 일한다 (§4) |
| 5 | 노출이 강도를 넘으면 자기 데이터가 주도한다 | 사전 강도 = 문턱 (§2) |

가상 데이터 기준입니다. 값은 인벤토리 구성에 따라 달라집니다.

표를 위에서 아래로 따라가면 한 가지가 눈에 걸립니다. **1번과 2번은 하루 한 번 배치로 계산해 두면 되고, 3번은 요청마다 더하기 한 번**입니다. 즉 이 방법은 서빙 비용이 거의 들지 않습니다. 광고마다 (α, β) 두 숫자를 들고 있으면 되니까요.

그래서 콜드스타트 대응은 대개 모델을 바꾸는 일이 아니라 **계층과 강도를 관리하는 일**이 됩니다. 새 모델을 붙이는 것보다 "우리 계층이 지금 몇 층인지, 강도를 언제 갱신했는지"를 점검하는 편이 효과가 큽니다.

마지막으로 이 글이 답하지 않은 것을 밝혀 둡니다. **"그래서 이 광고에 노출을 얼마나 줄까"** 는 여기서 다루지 않았습니다. 수축은 지금 있는 정보로 최선의 숫자를 만드는 일이고, 노출을 배정하는 일은 별개의 결정입니다.

둘은 짝으로 움직입니다. 수축이 정확하면 탐색을 덜 해도 되고, 탐색을 하면 수축이 빨리 정확해집니다. 그 저울은 [탐색과 활용](post.html?id=exploration-exploitation)에서 원화로 계산해 뒀습니다.
