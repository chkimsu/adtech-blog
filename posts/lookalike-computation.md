모델 팀 15주째 월요일, 지훈 씨는 매일 밤 도는 작업 하나를 넘겨받았습니다. 서연 씨가 건넨 고객 목록과 닮은 회원을 골라, 그 회원들의 프로필에 번호 6001 을 적는 일입니다. 목록은 새 러닝화를 산 8만 명이고, 러닝 글을 많이 읽고 운동 앱을 자주 켜는 「우수 고객」이 대부분입니다.

선배의 설명은 짧았습니다. 목록 사람들의 숫자를 평균해 하나로 만들고, 회원마다 그 평균과 같은 쪽을 보는 정도로 줄을 세워 앞에서 자른다고 했습니다. 다만 줄의 앞을 넓게 자를수록 닮지 않은 사람이 섞인다고 덧붙였습니다.

**목록 한 장으로 1,400만 명의 줄을 세우면, 앞에서 자른 140만 명 가운데 몇 명이 정말 닮은 사람일까요?**

고객 목록과 닮은 회원을 찾아 넓히는 일을 Lookalike 라고 부르고, 넘겨받은 목록을 시드라고 부릅니다. 줄을 잘못 세우거나 너무 넓게 자르면 러닝에 관심 없는 회원이 140만 명 안에 섞입니다. 서연 씨의 하루 300만 원은 그 회원들에게도 똑같이 쓰입니다.

> **한 줄 요약:** 회원마다 행동을 숫자 8개로 적은 벡터가 있고, 시드 114명의 벡터를 평균하면 중심 벡터 하나가 됩니다. 회원마다 중심 벡터와 방향이 얼마나 같은지를 코사인 유사도로 재서 줄을 세웁니다. 앞 1% 를 자르면 러닝에 관심 있게 만든 러닝 성향 회원의 몫이 0.985 이고, 10% 는 0.709 입니다. 줄의 뒤로 갈수록 중심과 방향이 덜 맞는 회원이 들어오기 때문입니다. 구매자 가운데 아무나 시드로 고르면 중심이 운동 용품 구매 쪽으로 쏠려, 운동 용품만 산 회원이 줄의 앞으로 옵니다. 회원을 미리 번호로 나눠 두고 중심과 같은 번호의 회원만 재면 계산이 줄어들지만, 다른 번호로 간 가까운 회원을 놓칩니다.

> **골라 읽는 법** — 절이 6개인 글이고, 절마다 표나 코드나 카드가 들어 있어 그것만 보고 넘어가도 됩니다.
>
> - 시드 114명이 누구이고 앞 글의 8만 명과 어떻게 견주나 → 1절
> - 중심 벡터와 코사인 유사도로 줄을 세우는 자리 → 2절
> - 모두와 재는 방법과 일부만 재는 방법의 계산 횟수 → 3절
> - 1, 5, 10% 에서 잘랐을 때 러닝 성향의 몫 → 4절
> - 번호 6001 이 적히는 두 자리 → 5절
> - 담장 안과 열린 RTB 에서 달라지는 것 → 6절

이 글의 회원, 행동, 나이는 전부 설명을 위한 가상 데이터입니다. 회원 1,400만 명, 세그먼트 317 의 160만 명, 맞춤타겟 8만 명은 타겟팅 트랙과 같은 값입니다. 유사타겟 10% 의 140만 명과 번호 6001 도 그 트랙의 값입니다. 전체 회원 대신 들여다보는 가상 회원, 곧 표본(sample)을 만드는 생성기와 벡터는 [유저 프로파일 피처](post.html?id=user-profile-features) 편의 코드를 그대로 옮겼습니다. 카드 속 파랑은 러닝 성향, 벽돌색은 러닝 성향이 아닌 회원, 회색은 거리를 잰 횟수이고, 점선은 앞 글에 적힌 시드 평균입니다.

## 1. 시드 8만 명은 어떤 사람들인가

**시드는 서연 씨가 건넨 「우수 고객」 목록이고, 표본 20,000명에서는 8만 명과 같은 몫인 114명을 고릅니다. 이들의 러닝 글은 앞 글이 적은 8만 명 평균의 4분의 3 수준이고, 운동 앱 일수는 거의 같습니다.**

시드(seed)는 닮은 사람을 찾는 출발점이 되는 회원 목록입니다. [Lookalike 기초](post.html?id=lookalike-basics) 편에서 서연 씨는 러닝화를 산 회원 8만 명을 시드로 정했고, 그 목록이 맞춤타겟 5051 입니다. 그 편이 적은 8만 명의 평균은 러닝 글 12회, 운동 앱 8일로 높아서, 러닝을 많이 하는 「우수 고객」이 대부분입니다. 시드는 고객 전부보다 가장 좋은 고객으로 채우라는 것이 흔한 권고입니다. [Lookalike Modeling](post.html?id=lookalike-modeling) 편도 전환의 질로 시드를 거르는 것을 가장 먼저 할 일로 꼽습니다.

회원을 다 만들 수는 없어서, 전체 대신 들여다보는 일부인 표본 20,000명을 씁니다. 13주째 글인 [유저 프로파일 피처](post.html?id=user-profile-features) 편의 생성기를 그대로 쓰고, 사람 수만 열 배로 키웠습니다. 러닝 성향은 생성기가 러닝에 관심 있게 만든 회원이고, 세그먼트 317 의 조건 셋 중 하나가 맞는 사람과 같습니다. 표본의 러닝 성향 2,290명은 11.4% 로, 317 의 160만 명이 회원 가운데 차지하는 몫과 같습니다.

시드도 표본에 맞춰 줄입니다. 8만 ÷ 1,400만 = 0.57% 를 20,000명에 곱한 114명이 앞 글의 시드를 대신하는 표본입니다. 표본에서 30일 안에 운동 용품을 산 러닝 성향은 578명이라 그보다 많습니다. 그래서 서연 씨의 목록처럼 그중 활동이 많은 사람을 고릅니다.

회원 A 는 이 578명에 들지만 서연 씨의 구매자 목록에 없는 사람이라 뺍니다. 다른 글들에서 A 는 맞춤타겟 5051 이 없는 회원입니다. 남은 577명 가운데 러닝 글 수와 운동 앱 실행 일수를 더한 값이 큰 사람부터 114명을 고릅니다. 값이 같으면 회원 번호가 앞인 사람을 먼저 둡니다. 아래 표의 둘째 줄부터는 2절 코드가 찍은 평균이고, 운동 용품 구매는 세는 기간을 칸마다 적었습니다.

표의 첫 두 줄을 견주면, 표본의 시드는 러닝 글이 8만 명 평균의 4분의 3 수준이고 운동 앱 일수는 거의 같습니다. 두 쪽 모두 가상 값이라 이 정도로 맞췄고, 운동 용품 구매는 앞 글이 90일, 이 글이 30일 동안 센 값이라 같은 양이 아닙니다. 아래 두 줄과 견주면 시드는 러닝 성향 평균보다도 러닝 글을 많이 읽고, 표본 전체보다는 10배 넘게 읽습니다. 나이는 벡터에 넣지 않고 시드가 어떤 사람인지 보려고만 붙였습니다. 줄을 세우는 기준이 이 차이이고, 다음 절은 이 차이를 숫자 8개의 방향 하나로 줄입니다.

## 2. 중심 벡터 하나와 거리로 줄을 세웁니다

**시드 114명의 8차원 벡터를 행동마다 평균하면 중심 벡터 하나가 됩니다. 회원마다 이 벡터와 방향이 얼마나 같은지를 코사인 유사도로 재서 큰 순서로 세웁니다. 회원 A 는 0.744 로 162번째이고, 회원 B 는 -0.086 으로 6,252번째입니다.**

13주째 글은 회원마다 행동 8종의 기록을 숫자로 바꿨습니다. 사건마다 7일에 절반씩 덜 쳐서 더한 가중합을 구하고, 행동마다 표본의 평균을 빼고 표준편차로 나눈 값입니다. 이 값들을 정해 둔 순서로 놓은 것이 8차원 벡터이고, 0 이 표본의 평균입니다. 평균과 표준편차는 이번에는 2,000명이 아니라 표본 20,000명에서 다시 셉니다.

중심 벡터(centroid)는 시드 114명의 벡터를 행동마다 평균한 벡터입니다. 시드가 대체로 어떤 행동을 평균보다 많이 하는지를 숫자 8개로 줄인 것입니다. 시드 가운데 이 벡터와 똑같은 사람은 없을 수 있지만, 방향은 시드가 많이 하는 행동 쪽을 가리킵니다.

닮음은 코사인 유사도(cosine similarity)로 잽니다. 두 벡터가 가리키는 방향이 같으면 1, 직각이면 0, 반대면 -1 이 되는 값입니다. 길이는 보지 않고 방향만 보므로, 평균에서 얼마나 멀리 있나보다 어느 쪽으로 떨어져 있나를 잽니다. Lookalike 기초 편은 원리를 보이려고 항목마다 평균과의 차이를 더했습니다. Walmart 의 2023년 논문은 고객을 벡터로 바꾸고, 두 고객의 거리를 코사인으로 잽니다. 이 글에서도 거리를 잰다고 하면 이 코사인을 재는 것을 말합니다.

줄이 잘 섰는지는 정밀도(precision)로 봅니다. 줄의 앞에서 자른 사람 가운데 러닝 성향인 사람의 몫입니다. 표본은 누가 러닝 성향인지 생성기가 알고 있어서 이 값을 셀 수 있고, 실제 회원에게는 이런 정답이 없습니다. 그래서 정밀도는 타겟팅 트랙의 전환율과 다른 양이고, 4절에서 둘이 같은 쪽으로 움직이는지만 견줍니다. 아래 코드는 13주째의 생성기와 벡터로 시작해, 나이와 시드를 붙이고 중심 벡터와 코사인을 잰 뒤 줄을 세워 1, 5, 10% 에서 자릅니다. 마지막 단계는 같은 구매자에서 시드를 무작위로 뽑아 견줍니다. 나이는 표본을 만든 난수와 따로 뽑으므로, 나이를 붙여도 생성기 결과는 바뀌지 않습니다.

```python
# 하는 일: 표본 20,000명에서 시드 114명을 골라 중심 벡터를 만들고, 코사인 유사도로 줄을 세워 1, 5, 10% 의 정밀도를 센다.
import math
import random
import statistics

# 1단계: 표본과 벡터를 만든다
# 유저 프로파일 피처 편의 생성기와 벡터 코드를 글자 그대로 옮긴다. 표본만 20,000명으로 키우고, 평균과 표준편차도 이 20,000명에서 다시 센다.
KEYS = ['search_running_shoes', 'sports_app_days', 'running_posts', 'sports_goods_buy',
        'travel_posts', 'cafe_posts', 'camping_posts', 'camping_search']
NAMES = ['검색어 러닝화', '운동 앱 실행 일수', '러닝 글', '운동 용품 구매',
         '여행 글', '카페 글', '캠핑 글', '캠핑 용품 검색']
MEMBER_A = {
    'search_running_shoes': [0, 1, 2, 3, 5, 7, 9, 12, 15, 18, 22, 27],
    'sports_app_days': [0, 2, 4, 6, 9, 11, 13, 16],      # 켠 날을 적으니 같은 날이 두 번 없다
    'running_posts': [0, 0, 1, 1, 2, 3, 4, 5, 6],
    'sports_goods_buy': [5],
    'travel_posts': [17, 19, 22, 26],
    'cafe_posts': [1, 10, 20],
    'camping_posts': [],
    'camping_search': [],
}
MEMBER_B = {k: [] for k in KEYS}                         # 캠핑 둘 말고는 30일 동안 한 일이 없다
MEMBER_B['camping_posts'] = [0, 1, 3, 4, 6, 8, 10, 12, 14, 16, 18, 21, 23, 26, 28]
MEMBER_B['camping_search'] = [1, 3, 6, 10, 15, 21]
# 합계는 사건 수다. 가중합은 사건마다 0.5 ** (경과일 / 7) 을 더한 값이라 7일 전 사건은 절반만 센다.
HALF_LIFE = 7


def counts(m):
    return {k: len(m[k]) for k in KEYS}


def weighted(m):
    return {k: sum(0.5 ** (d / HALF_LIFE) for d in m[k]) for k in KEYS}


SEGMENT_317 = {'running_posts': 3, 'sports_app_days': 5, 'search_running_shoes': 1}   # 셋 중 하나


def in_segment_317(m):
    c = counts(m)
    return any(c[k] >= at_least for k, at_least in SEGMENT_317.items())


def runner_count(n):
    return n * 229 // 2000                               # 러닝 성향 11.45%, 2,000명이면 229명


# 행동마다 (그 행동을 하는 사람 비율, 하는 사람의 30일 평균 횟수). 앞은 러닝 성향, 뒤는 나머지다.
TENDENCY = {
    'search_running_shoes': ((0.17, 11.0), (0.00, 0.0)),
    'sports_app_days':      ((0.26, 9.0), (0.25, 2.5)),
    'running_posts':        ((0.46, 8.0), (0.25, 1.5)),
    'sports_goods_buy':     ((0.30, 1.5), (0.10, 1.2)),
    'travel_posts':         ((0.30, 4.0), (0.30, 4.0)),
    'cafe_posts':           ((0.40, 4.0), (0.40, 4.0)),
    'camping_posts':        ((0.08, 7.0), (0.12, 7.0)),
    'camping_search':       ((0.05, 5.0), (0.08, 5.0)),
}


def make_members(n, seed=7):
    """회원 n 명의 30일 행동. 0번은 회원 A, 1번은 회원 B 다."""
    rng = random.Random(seed)
    n_run = runner_count(n)
    runner = [True] * (n_run - 1) + [False] * (n - n_run - 1)   # A 는 러닝 성향, B 는 나머지
    rng.shuffle(runner)
    members = [dict(MEMBER_A), dict(MEMBER_B)]
    for is_runner in runner:
        while True:     # 러닝 성향은 조건이 하나라도 맞을 때까지, 나머지는 하나도 안 맞을 때까지 다시 뽑는다
            m = {}
            for k in KEYS:
                share, mean = TENDENCY[k][0 if is_runner else 1]
                does = rng.random() < share                     # 이 행동을 하는 사람인가
                days = range(30) if does else []                # 안 하는 사람은 날마다 뽑지 않는다
                m[k] = [d for d in days if rng.random() < mean / 30]
            if in_segment_317(m) == is_runner:
                break
        members.append(m)
    return members


members = make_members(20000)
ws = [weighted(m) for m in members]
mean = {k: statistics.fmean(x[k] for x in ws) for k in KEYS}
std = {k: statistics.pstdev([x[k] for x in ws]) for k in KEYS}


def vector(m):
    x = weighted(m)
    return [(x[k] - mean[k]) / std[k] for k in KEYS]


vecs = [vector(m) for m in members]
cnt = [counts(m) for m in members]
runner = [in_segment_317(m) for m in members]
print(f'표본 {len(members):,}명, 러닝 성향 {sum(runner):,}명 ({sum(runner) * 1000 // len(members) / 10}%)')

# 2단계: 나이를 붙이고 시드 114명을 고른다
# 시드 수는 맞춤타겟 8만 ÷ 회원 1,400만 = 0.57% 를 표본에 옮긴 수다. 러닝 성향 구매자 가운데 러닝 글과 운동 앱 일수의 합이 큰 순서로 고른다.
def ages(members, seed=7):
    """회원마다 나이 하나. 표본을 만든 난수와 따로 뽑아 표본 순서를 건드리지 않는다."""
    rng = random.Random(seed + 1)
    out = []
    for m in members:
        age = round(rng.gauss(33, 6) if in_segment_317(m) else rng.gauss(38, 10))
        out.append(min(70, max(18, age)))
    return out


age = ages(members)
age[0] = 32                                         # 회원 A 는 다른 글과 같게 32세

      f'러닝 글 + 운동 앱 일수가 큰 순서로. 첫 사람 {busy(seeds[0])}, 마지막 사람 {busy(seeds[-1])}')

    print(f'{avg[0]:>6.2f}  {avg[1]:>6.2f}  {avg[2]:>8.2f}  {statistics.fmean(age[i] for i in ids):>5.1f}  '

# 3단계: 중심 벡터와 코사인 유사도
# 중심 벡터는 시드 114명의 벡터를 행동마다 평균한 것이다. 코사인 유사도는 두 벡터의 방향이 같으면 1, 직각이면 0, 반대면 -1 이다.
def centroid(ids):
    return [statistics.fmean(vecs[i][d] for i in ids) for d in range(len(KEYS))]


def cosine(u, v):
    dot = math.fsum(a * b for a, b in zip(u, v))
    return dot / math.sqrt(math.fsum(a * a for a in u) * math.fsum(b * b for b in v))

# 4단계: 줄을 세워 1, 5, 10% 에서 자른다
# 시드는 줄에서 뺀다. 자르는 수의 분모는 전체 회원이고, 정밀도는 뽑힌 사람 가운데 러닝 성향의 몫이다.

    score = {i: cosine(vecs[i], c) for i in range(len(members)) if i not in skip}
    return sorted(score, key=lambda i: (-score[i], i))

print(f'회원 A 는 {order.index(0) + 1}번째, 회원 B 는 {order.index(1) + 1:,}번째')

# 5단계: 구매자를 무작위로 고르면
# 같은 577명에서 활동과 상관없이 114명을 뽑아 똑같이 줄을 세운다. 러닝 성향이 아닌 구매자가 두 중심과 얼마나 가깝고 앞 1,000명에 몇 명 드는지 견준다.
others = random.Random(7 + 3).sample(pool, n_seed)
c2, order2 = centroid(others), line_up(others)
top = max(range(len(KEYS)), key=lambda d: c2[d])
print('무작위 시드의 정밀도 1, 5, 10%:', ', '.join(f'{sum(runner[i] for i in order2[:n]) / n:.3f}' for n in (200, 1000, 2000)))
print(f'무작위 시드의 중심: {NAMES[top]} {c2[top]:.2f} 이 가장 크고, 러닝 글 {c2[2]:.2f}, 운동 앱 실행 일수 {c2[1]:.2f}')
odd = [i for i in range(len(members)) if not runner[i] and cnt[i]['sports_goods_buy'] >= 1]
for name, c, o in (('무작위 시드', c2, order2), ('활동 순 시드', center, order)):
    print(f'러닝 성향이 아닌 구매자 {len(odd):,}명: {name} 중심과의 코사인 평균 '
          f'{statistics.fmean(cosine(vecs[i], c) for i in odd):.3f}, 앞 1,000명에 {len(set(odd) & set(o[:1000]))}명')

# 러닝 성향이 아닌 구매자 1,258명: 활동 순 시드 중심과의 코사인 평균 0.230, 앞 1,000명에 151명
```

## 3. 전수로 재면 1,400만 × 8 이고 근사 검색은 그중 일부만 봅니다

**2절의 줄은 시드를 뺀 19,886명 모두와 코사인을 재서 세웠습니다. 회원을 미리 번호로 나눠 두고 중심과 같은 번호의 회원만 재면 거리 계산이 2,678번으로 줄어듭니다. 대신 그 줄의 앞 2,000명 가운데 0.383 만 찾고, 가까운 번호까지 넓혀 보면 9,955번에 0.782 를 찾습니다.**

모든 회원과 하나씩 재는 것을 전수 검색(brute-force search)이라고 부릅니다. 코사인의 분자는 두 벡터의 같은 자리 값을 곱해 더하는 내적이라, 한 번에 곱셈이 8번 듭니다. 회원 1,400만 명이면 시드 하나에 곱셈 1억 1,200만 번입니다. 광고주마다 시드가 다르니 Lookalike 목록 하나마다 이 계산이 한 번씩 돕니다. Faiss 의 2024년 논문은 작은 데이터에는 전수 검색이 가장 낫고, 큰 데이터에서는 너무 느려진다고 적었습니다.

그래서 회원을 미리 나눠 두고 중심 근처의 일부만 재는 근사 검색(approximate nearest neighbor search)을 씁니다. 다 재지 않으니 정말 가까운 사람을 놓칠 수 있고, 얼마나 놓치는지는 재현율(recall)로 봅니다. 이 글의 재현율은 전수 검색의 앞 2,000명, 곧 10% 가운데 근사 검색이 찾은 몫입니다.

나누는 방법은 랜덤 투영 해시(random projection hashing)입니다. 해시는 값을 정해 둔 규칙으로 짧은 번호로 바꾸는 것이고, 여기서는 벡터를 번호 하나로 바꿉니다. 8차원에 방향 6개를 난수로 뽑아 두고, 벡터와 각 방향의 내적이 0 이상이면 1, 아니면 0 을 비트로 적습니다. 비트 6개를 이어 붙이면 0 부터 63 까지의 번호가 되고, 같은 번호를 받은 회원의 묶음을 버킷이라고 부릅니다. 방향이 비슷한 두 벡터는 비트가 같기 쉬워서 같은 버킷에 모입니다.

버킷 번호마다 그 버킷의 회원 목록을 적어 둔 표가 해시 테이블입니다. 방향 6개를 한 번만 뽑으면 가까운 사람이 운 나쁘게 다른 버킷에 들어갑니다. 그래서 방향 6개를 네 번 따로 뽑아 테이블을 4개 만들고, 하나라도 같은 버킷이면 후보로 둡니다. 더 넓게 보려면 비트 하나만 다른 이웃 버킷 6개까지 봅니다. 두 번호에서 다른 비트의 수를 해밍 거리(Hamming distance)라고 부르니, 이웃 버킷은 해밍 거리가 1 인 버킷입니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 회원 벡터를 랜덤 투영 해시로 버킷에 나눠 두고, 중심 벡터 근처의 버킷만 재서 전수 검색의 상위 2,000명과 견준다.

# 1단계: 해시 테이블 4개를 만든다
# 테이블마다 방향 6개를 난수로 뽑고, 벡터와 방향의 내적이 0 이상이면 1 을 비트로 적는다. 비트 6개가 버킷 번호라 테이블마다 버킷이 64개다.
BITS, TABLES = 6, 4


def bucket(planes, v):
    return sum(1 << b for b, p in enumerate(planes) if math.fsum(x * y for x, y in zip(p, v)) >= 0)


def make_index(seed):
    rng = random.Random(seed)
    planes = [[[rng.gauss(0, 1) for _ in KEYS] for _ in range(BITS)] for _ in range(TABLES)]
    tables = [{} for _ in range(TABLES)]
    for i in order:                                 # 시드를 뺀 19,886명을 테이블마다 한 번씩 넣는다
        for t in range(TABLES):
            tables[t].setdefault(bucket(planes[t], vecs[i]), []).append(i)
    return planes, tables


planes, tables = make_index(7 + 4)                  # 표본, 나이, 무작위 시드와 다른 난수
print(f'테이블 {TABLES}개 × 버킷 {2 ** BITS}개에 회원 {len(order):,}명')
print('중심 벡터가 떨어진 버킷의 회원 수:',
      ', '.join(f'{len(tables[t].get(bucket(planes[t], center), [])):,}명' for t in range(TABLES)))

# 2단계: 버킷 안만 재고 전수 검색과 견준다
# 후보는 테이블 4개에서 중심과 같은 버킷에 든 회원을 합친 것이고, 이웃 버킷은 비트 하나만 다른 버킷 6개다. 재현율은 전수 검색의 앞 2,000명 가운데 찾은 몫이다.
truth = set(order[:2000])                           # 전수 검색의 상위 2,000명, 곧 10%


def search(planes, tables, near):
    cand = set()
    for t in range(TABLES):
        home = bucket(planes[t], center)
        for key in [home] + ([home ^ (1 << b) for b in range(BITS)] if near else []):
            cand.update(tables[t].get(key, []))
    found = sorted(cand, key=lambda i: (-cosine(vecs[i], center), i))[:2000]   # 거리는 후보만 잰다
    return len(cand), found


print('찾는 자리            거리 계산  재현율  러닝 성향 비율 (뽑힌 2,000명)')
rows = [('전수', len(order), order[:2000])]
rows += [(name, *search(planes, tables, near)) for name, near in (('해시 버킷 하나', False), ('해시 이웃 버킷까지', True))]
for name, n_calc, found in rows:
    print(f'{name:<12}  {n_calc:>8,}  {len(truth & set(found)) / 2000:.3f}  {sum(runner[i] for i in found) / len(found):.3f}')

# 3단계: 같은 버킷에 들 확률
# 중심과 각 θ 를 이루는 벡터는 비트 하나가 같을 확률이 1 - θ/π 다. 비트 6개가 다 같아야 같은 버킷이고, 비트 하나까지 달라도 되면 이웃 버킷이다.
print('줄의 순번  코사인  같은 버킷 (테이블 1개, 4개 중 하나)  이웃 버킷까지 (1개, 4개 중 하나)')
for rank in (1, 200, 1000, 2000):
    c = cosine(vecs[order[rank - 1]], center)
    p = 1 - math.acos(c) / math.pi
    same, near = p ** BITS, p ** BITS + BITS * p ** (BITS - 1) * (1 - p)
    print(f'{rank:>7,}  {c:.3f}  {same:.3f}, {1 - (1 - same) ** TABLES:.3f}  {near:.3f}, {1 - (1 - near) ** TABLES:.3f}')

# 4단계: 방향을 다른 난수로 뽑으면
# 난수 11 부터 20 까지로 열 번 다시 만들어, 거리 계산 횟수와 재현율이 얼마나 흔들리는지 본다. 11 은 1단계의 것이다.
runs = {False: [], True: []}
for s in range(11, 21):
    index = make_index(s)
    for near in runs:
        n_calc, found = search(*index, near)
        runs[near].append((n_calc, len(truth & set(found)) / 2000))
for name, near in (('해시 버킷 하나', False), ('해시 이웃 버킷까지', True)):
    calc, rec = zip(*runs[near])
    print(f'{name}: 거리 계산 {min(calc):,}~{max(calc):,}, 재현율 {min(rec):.3f}~{max(rec):.3f} (열 번)')

# 출력:
# 1단계 뜻: 중심이 떨어진 버킷의 크기는 테이블마다 다르고, 작은 것은 255명, 큰 것은 1,933명이다.
# 테이블 4개 × 버킷 64개에 회원 19,886명
# 중심 벡터가 떨어진 버킷의 회원 수: 1,933명, 552명, 377명, 255명
# 2단계 뜻: 더 볼수록 재현율이 오르고 거리 계산이 는다. 놓친 자리를 다음 후보가 채워, 러닝 성향 비율은 재현율보다 덜 내려간다.
# 찾는 자리            거리 계산  재현율  러닝 성향 비율 (뽑힌 2,000명)
# 전수              19,886  1.000  0.709
# 해시 버킷 하나         2,678  0.383  0.473
# 해시 이웃 버킷까지       9,955  0.782  0.657

# 줄의 순번  코사인  같은 버킷 (테이블 1개, 4개 중 하나)  이웃 버킷까지 (1개, 4개 중 하나)
#       1  0.891  0.378, 0.850  0.777, 0.998

# 해시 버킷 하나: 거리 계산 556~2,678, 재현율 0.183~0.600 (열 번)
```

더 볼수록 재현율이 오르고 계산이 늡니다. 1단계에서 만든 해시로는 버킷 하나만 볼 때 계산이 전수의 7분의 1 쯤입니다. 이웃 버킷까지 보면 계산이 전수의 절반으로 늘고, 찾는 몫은 두 배 넘게 오릅니다. 줄의 뒤쪽 회원일수록 중심과의 각이 커서 같은 버킷에 들기 어려운데, 그 확률은 더 깊이 보기에 있습니다.

이 값은 방향 6개를 어떻게 뽑았느냐에도 달려 있습니다. 난수를 바꿔 열 번 다시 만들면 버킷 하나는 거리 계산 556~2,678번에 재현율 0.183~0.600 입니다. 이웃 버킷까지는 2,509~9,955번에 0.553~0.978 입니다. 1단계의 2,678번과 9,955번은 열 번 가운데 계산이 가장 많았던 경우입니다. 그래서 근사 검색의 재현율과 계산은 한 번 재서 정하지 않고, 설정을 바꿔 가며 여러 번 잽니다.

## 4. 확장 비율을 올리면 도달은 늘고 정밀도는 내려갑니다

**줄의 앞 1% 를 자르면 러닝 성향이 0.985 이고, 10% 를 자르면 0.709 입니다. 회원 전체로는 광고가 닿는 사람 수, 곧 도달이 14만 명에서 140만 명으로 10배가 되는 동안 정밀도가 내려갑니다.**

확장 비율은 줄의 앞에서 몇 퍼센트까지 가져오느냐이고, 분모는 시드가 아니라 전체 회원입니다. 표본 20,000명의 1% 는 200명이고, 표본 한 명이 회원 700명이라 1,400만 명으로 옮기면 14만 명입니다. 아래 표는 2절 코드가 찍은 값입니다. 마지막 칸의 전환율은 [Lookalike 기초](post.html?id=lookalike-basics) 편의 가상 값이고 정밀도와 다른 양이라, 같은 쪽으로 움직이는지만 견줍니다.

| 확장 비율 | 뽑힌 사람 (표본 20,000명 중) | 그중 러닝 성향 | 정밀도 | 1,400만 명으로 옮기면 | 앞 글의 전환율 (다른 양) |
|---|---|---|---|---|---|
| 1% | 200명 | 197명 | 0.985 | 14만 명 | 3.20% |
| 5% | 1,000명 | 793명 | 0.793 | 70만 명 | 1.50% |
| 10% | 2,000명 | 1,417명 | 0.709 | 140만 명 | 0.90% |

정밀도는 줄을 넓게 자를수록 내려가고, 앞 글의 전환율도 같은 방향입니다. 줄은 중심과 방향이 가까운 순서라, 뒤로 갈수록 시드와 덜 닮은 회원이 들어옵니다. 3절 코드를 보면 코사인이 200번째 회원은 0.728, 2,000번째는 0.382 입니다.

정밀도는 「뽑힌 사람이 러닝 성향인가」이고, 전환율은 「광고를 본 사람이 샀나」입니다. 러닝 성향이어도 사지 않는 사람이 많아서, 정밀도 0.985 가 전환율 98.5% 가 되지는 않습니다. 두 값이 같은 방향으로 내려가는 까닭이 같을 뿐입니다.

10% 의 140만 명 가운데 러닝 성향은 1,417 × 700 = 99만 1,900명인 셈입니다. 나머지는 러닝 성향이 아니고, 표본에서 러닝 성향은 세그먼트 317 이 붙은 사람과 같습니다. 그래서 140만 명 가운데에는 317 이 있는 사람도 있고 없는 사람도 있습니다. [캠페인 설정](post.html?id=campaign-setup-flow) 편이 6001 을 두고 적은 그대로입니다.

어디서 자를지는 정밀도만으로 정하지 않습니다. Lookalike 기초 편은 도달에 전환율을 곱해, 10% 가 전환 12,600건으로 가장 많다고 셌습니다. 서연 씨는 그 셈으로 10% 를 골랐고, 그 140만 명에 붙는 번호가 6001 입니다.

## 5. 번호 6001 이 적히는 두 자리

**앞 10% 를 자르면 배치의 마지막 일은 번호를 적는 것입니다. 번호 6001 은 회원 프로필과 캠페인 조건 두 곳에 적히고, 광고 요청 때 둘이 같은 번호로 만납니다.**

표본에서 회원 A 는 162번째라 앞 10% 안에 들고 6001 을 받습니다. 회원 B 는 6,252번째라 2,000번째 밖이고, 번호는 77 하나 그대로입니다. 캠페인 설정 편에서 A 의 번호가 이 밤을 지나며 셋에서 넷이 된 자리가 이 계산입니다.

| 자리 | 적히는 것 | 누가, 언제 | 예시 |
|---|---|---|---|
| 회원 프로필 | 그 회원이 든 세그먼트 번호의 목록 | 이 글의 배치가 매일 밤 | 회원 A: 317, 402, 905 에 6001 이 더해진다 |
| 캠페인 조건 | 「보여 줄 사람」 칸의 번호 | 서연 씨가 캠페인 화면에서 한 번 | 서연 씨 러닝화: 317 대신 6001 |

프로필은 회원마다 붙은 번호의 목록이고, 캠페인 조건은 광고주가 고른 번호입니다. 광고 요청이 오면 광고 서버는 회원 A 의 프로필에서 6001 을 읽습니다. 그리고 미리 만들어 둔 캠페인 조건 표에서 6001 을 조건으로 적은 캠페인을 찾아, 서연 씨 캠페인을 후보에 올립니다. 캠페인 조건 표는 번호로 캠페인 목록을 바로 찾게 만든 표이고, [후보풀](post.html?id=candidate-pool-basics) 편에 그 표가 있습니다.

두 자리는 바뀌는 때가 다릅니다. 프로필의 6001 은 배치가 매일 밤 다시 정해서, 시드 목록이나 회원의 30일 기록이 바뀌면 다음 날 든 사람이 바뀝니다. 캠페인 조건의 6001 은 서연 씨가 고치기 전까지 그대로입니다. 비율을 5% 로 옮기면 70만 명이 든 다른 번호가 생기고, 조건 칸의 번호가 그 번호로 바뀝니다.

그래서 배치가 틀리면 캠페인 화면에는 아무것도 바뀌지 않은 채로 다른 사람이 광고를 봅니다. 실제 회원에게는 러닝 성향이라는 정답이 없으니, 시드가 바뀐 날에는 중심 벡터와 앞쪽 회원의 평균을 어제와 견줘 봅니다. 여기까지는 시드와 회원 1,400만 명의 벡터가 한 회사 안에 있다는 전제였고, 그 전제가 무대마다 다릅니다.

## 6. 시드와 회원의 기록이 한 곳에 모이나가 무대마다 다릅니다

**중심 벡터와 코사인으로 줄을 세우는 셈은 두 무대가 같습니다. 담장 안에서는 시드를 로그인한 회원 번호로 맞추고, 1,400만 명 모두의 벡터로 줄을 세웁니다. 열린 RTB 에서는 시드를 맞추는 키가 바뀌고 지워져 일부를 놓치고, 줄에 설 사람의 기록도 짧습니다.**

1~5절은 시드 114명과 회원 19,886명의 벡터가 모두 손에 있다는 전제 위에 있었습니다. 시드를 회원과 맞추는 키와 벡터의 재료가 어디 있느냐가 무대마다 다릅니다.

### 담장 안에서는 로그인한 회원 번호로 시드를 맞춥니다 [무대: 닫힌 생태계]

한 회사가 앱과 광고 서버를 다 가진 담장 안에서는 시드를 로그인한 회원 번호로 맞춥니다. 서연 씨가 올린 8만 8천 명 가운데 8만 명이 확정으로 맞은 것이 그 결과입니다. 회원 1,400만 명의 벡터도 새벽 배치가 한 저장소에 만들어 두므로, 이 글의 계산을 그대로 돌리면 됩니다.

남는 일은 계산의 양입니다. 광고주마다 시드가 다르면 목록 하나마다 1,400만 명과의 계산이 돕니다. 회원을 미리 나눠 적어 둔 표, 곧 색인을 만드는 데도 계산이 듭니다. 앞의 해시라면 회원마다 테이블 4개에서 방향 6개와 내적을 재니, 19,886 × 4 × 6 = 477,264번입니다. 그래서 색인은 하루 한 번 만들어 두고, 여러 광고주의 시드가 중심 벡터 하나씩으로 같은 색인을 찾습니다. 실무에서는 무작위 방향의 해시보다 데이터에 맞춰 나누는 색인을 씁니다. Faiss 논문도 무작위 해시가 데이터에 맞춘 분할보다 크게 뒤진다고 적었습니다. 군집으로 나눠 몇 개만 보는 IVF 와, 이웃을 이은 그래프를 따라가는 HNSW 가 대표적입니다. 둘은 [Two-Tower Retrieval](post.html?id=two-tower-retrieval) 편에 나옵니다.

### 열린 RTB 에서는 쿠키로 맞춰 시드부터 잡음이 섞입니다 [무대: 열린 RTB]

열린 RTB 에서 광고를 사는 쪽의 시스템인 DSP 는 회원 번호 대신 쿠키나 기기의 광고 ID 로 사람을 봅니다. 쿠키는 브라우저가 사이트마다 남겨 두는 작은 식별 값입니다. 광고주의 구매자 목록을 쿠키와 맞추면 Lookalike 기초 편의 표처럼 60~70% 만 맞고, 일부는 다른 사람입니다. 쿠키는 바뀌고 지워져서, 줄에 설 사람의 30일 기록도 며칠로 끊기기 쉽습니다.

닮은 사람을 찾는 계산은 데이터 관리 플랫폼(DMP)이나 데이터 회사가 쿠키 기록으로 하는 일이 많습니다. 결과는 쿠키 목록인 세그먼트로 DSP 에 넘어가고, DSP 는 입찰 요청이 오면 그 쿠키가 목록에 있는지만 봅니다. 시드부터 잡음이 섞이므로 비율을 낮게 잡고, 광고를 보인 쪽과 안 보인 쪽을 나눠 효과를 따로 잽니다. 아래 표는 가상 데이터가 아니라 두 무대의 설계 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 시드를 회원과 맞추는 키 | 로그인한 회원 번호, 8만 8천 명 중 8만 명 | 쿠키나 기기의 광고 ID, 60~70% 만 맞는다 |
| 줄에 서는 사람 | 회원 1,400만 명, 벡터가 한 저장소에 있다 | 쿠키 기록이 있는 사람, 기록이 며칠로 끊기기 쉽다 |
| 닮은 사람을 세는 곳 | 플랫폼의 밤 배치 | DMP 나 데이터 회사, 결과는 쿠키 목록 |
| 광고 요청 때 보는 것 | 프로필의 번호 6001 | 쿠키가 목록에 있나 |

다음 편은 16주째의 전환 예측으로 타겟 고르기입니다. 이 글은 「시드와 닮았나」로 줄을 세웠고, 다음 편은 같은 표본 20,000명을 「살 것 같나」로 세웁니다. 같은 수를 고를 때 세그먼트 317 과 무엇이 달라지는지가 그 편의 질문입니다.

## 한눈 정리

| 자리 | 무엇을 하나 | 숫자 (표본 20,000명) |
|---|---|---|
| 표본 | 1,400만 명 대신 생성기가 만든 회원 | 러닝 성향 2,290명 (11.4%) |
| 시드 | 러닝 성향 구매자 577명 중 활동이 많은 순서로 고른다 | 114명 (0.57%), 러닝 글 8.98회, 운동 앱 7.84일 |
| 중심 벡터 | 시드 114명의 벡터를 행동마다 평균한다 | 러닝 글 3.53, 운동 앱 3.18, 운동 용품 3.09 |
| 코사인 유사도 | 회원마다 중심과 방향이 얼마나 같은지 잰다 | 회원 A 0.744 (162번째), 회원 B -0.086 |
| 전수 검색 | 시드를 뺀 모든 회원과 잰다 | 거리 계산 19,886번, 재현율 1.000 |
| 해시 근사 검색 | 중심 근처의 버킷만 잰다 | 2,678번에 0.383, 이웃 버킷까지 9,955번에 0.782 |
| 자르기 | 줄의 앞 1, 5, 10% 를 가져온다 | 정밀도 0.985, 0.793, 0.709 |
| 번호 6001 | 앞 10% 의 프로필과 캠페인 조건에 적는다 | 1,400만 명이면 140만 명 |

## 헷갈리기 쉬운 점

- **분모는 전체 회원입니다.** 1% 는 시드 114명의 1% 가 아니라 표본 20,000명의 1% 인 200명입니다. 회원 1,400만 명이면 14만 명입니다. 시드는 줄을 세우는 기준이고, 줄에서는 뺍니다.
- **중심 하나로 되는 시드와 안 되는 시드가 있습니다.** 활동 순으로 고른 114명의 중심은 러닝 글, 운동 앱, 운동 용품이 비슷하게 큽니다. 같은 577명에서 무작위로 뽑으면 운동 용품 구매 2.90 이 가장 크고, 러닝 성향이 아닌 구매자가 앞 1,000명에 541명 듭니다. 그래서 5% 의 정밀도 0.459 가 10% 의 0.633 보다 낮습니다. 시드가 서로 다른 무리로 나뉘면 Lookalike Modeling 편처럼 중심을 여러 개 둡니다.
- **근사 검색의 재현율은 품질이 아니라 누락을 잽니다.** 재현율은 전수 검색의 앞 2,000명 가운데 찾은 몫이고, 놓친 자리는 다음으로 가까운 후보가 채웁니다. 이웃 버킷까지 보면 재현율은 1.000 에서 0.782 로 내려가도, 러닝 성향 비율은 0.709 에서 0.657 로 조금만 내려갑니다. 목록이 얼마나 좋은지는 정밀도로 따로 봅니다.
- **정밀도는 전환율이 아닙니다.** 정밀도는 뽑힌 사람이 러닝 성향인가이고, 전환율은 광고를 본 사람이 샀나입니다. 1% 의 정밀도 0.985 와 전환율 3.20% 는 같은 방향으로 움직일 뿐, 크기를 견주는 값이 아닙니다.

## 더 깊이 보기

:::deep 코사인 유사도의 식과, 중심 벡터와 견주는 뜻
회원 벡터 $u$ 와 중심 벡터 $c$ 의 코사인 유사도는 아래와 같습니다. $v_i$ 는 시드 $i$ 의 벡터이고 $n$ 은 114 입니다.

$$\cos(u, c) = \frac{u \cdot c}{\lVert u \rVert \, \lVert c \rVert}, \qquad c = \frac{1}{n}\sum_{i=1}^{n} v_i$$

분자의 내적을 풀면 $u \cdot c = \frac{1}{n}\sum_i u \cdot v_i$ 입니다. 그래서 중심과의 코사인은 시드 114명과의 내적을 평균하고 두 길이로 나눈 값입니다. 시드마다의 코사인을 평균한 것과는 달라서, 벡터가 긴 시드, 곧 평균에서 멀리 떨어진 시드가 더 크게 들어갑니다. $\lVert c \rVert$ 는 회원마다 같으므로 줄의 순서는 $u \cdot c / \lVert u \rVert$ 가 정합니다.

0 이 표본의 평균이라, 코사인은 평균 회원에서 본 방향을 잽니다. 회원 B 처럼 러닝 쪽 값이 평균보다 조금 아래인 회원은 중심과 거의 직각이 되어, 코사인이 -0.086 처럼 0 을 조금 밑돕니다. 표준화하지 않은 횟수는 모두 0 이상이라, 그대로 재면 코사인이 0 아래로 내려가는 일이 없습니다. 값이 큰 행동이 방향을 거의 다 정하는 13주째 글 3절의 문제도 그대로 돌아옵니다.

Faiss 같은 라이브러리는 벡터를 미리 길이 1 로 나눠 두고 내적으로 코사인을 셉니다. 길이가 1 이면 분모가 1 이라 내적이 곧 코사인이고, 회원 벡터는 하루에 한 번만 나누면 됩니다.
:::

:::deep 랜덤 투영 해시의 충돌 확률
방향 $r$ 을 정규분포로 뽑으면, 두 벡터 $u$, $c$ 의 각이 $\theta$ 일 때 비트 하나가 같을 확률은 아래와 같습니다. Charikar 의 2002년 논문이 정리한 성질입니다.

$$p = P\big[\operatorname{sign}(r \cdot u) = \operatorname{sign}(r \cdot c)\big] = 1 - \frac{\theta}{\pi}, \qquad \theta = \arccos\big(\cos(u, c)\big)$$

비트 6개가 모두 같아야 같은 버킷이니, 한 테이블에서 같은 버킷에 들 확률은 $p^6$ 입니다. 테이블 4개 중 하나 이상이면 $1 - (1 - p^6)^4$ 입니다. 이웃 버킷까지 보면 비트가 하나까지 달라도 되므로, 한 테이블에서 $p^6 + 6p^5(1 - p)$ 입니다.

3절 코드가 줄의 순번마다 이 값을 찍었습니다. 가장 앞의 회원은 코사인 0.891 로, 네 테이블 중 하나 이상에서 같은 버킷에 들 확률이 0.850 입니다. 2,000번째 회원은 코사인 0.382 로 0.218 이고, 이웃 버킷까지 보면 0.722 로 오릅니다.

줄의 뒤쪽일수록 이 확률이 낮아서, 앞 2,000명을 다 찾으려면 비트를 줄이거나 테이블을 늘려야 합니다. 비트를 줄이면 버킷이 커져 거리 계산이 늘고, 테이블을 늘리면 회원마다 넣는 자리가 늘어 표가 커집니다. 어느 쪽이든 재현율을 얻는 값으로 계산이나 메모리를 냅니다.
:::
