지훈은 이분 탐색(binary search)을 알고 코드도 외워서 씁니다. 이분 탐색은 정렬된 배열에서 가운데 칸의 값과 찾는 값을 비교해 답이 있을 수 없는 절반을 버리는 일을 되풀이하는 방법입니다. 그런데 지훈이 그렇게 외운 코드를 제출하면 절반쯤은 틀렸다는 결과가 돌아옵니다.

지훈이 막힌 곳은 알고리즘이 아니었습니다. 이분 탐색 코드의 `lo` 와 `hi` 는 답이 될 수 있는 자리(칸 번호, 인덱스) 범위의 왼쪽 끝과 오른쪽 끝입니다. 지훈은 반복 조건을 어떤 날은 `while lo <= hi` 로, 어떤 날은 `while lo < hi` 로 썼지만 왜 그렇게 쓰는지는 몰랐습니다. 그래서 같은 값이 여러 칸에 들어 있는 배열(중복이 있는 배열)에서 답이 한 칸 차이로 틀리면 코드의 어디를 고쳐야 할지 감이 오지 않았습니다.

**같은 알고리즘인데 왜 부등호 하나로 답이 달라질까?**

이분 탐색 코드는 5줄뿐이라 배우기는 쉽지만 틀리지 않게 짜기는 어렵습니다. 이 글은 그 5줄의 **경계 조건**을 네 가지 변형으로 나눠 살펴봅니다. 여기서 경계는 조건을 만족하는 칸과 만족하지 않는 칸이 바뀌는 자리입니다. 경계 조건은 `hi` 의 처음 값, `while` 의 부등호, 가운데 칸 번호 `mid` 를 구하는 식처럼 탐색 범위를 어디까지 남기고 언제 멈출지 정하는 부분입니다. 글의 뒷부분에서는 마지막에 넣은 것부터 꺼내는 스택(stack)과 양끝에서 넣고 뺄 수 있는 덱(deque)을 다루는데, 이분 탐색까지 세 도구 모두 "지금 볼 후보를 어떻게 줄이느냐"라는 같은 물음에 저마다 다른 답을 냅니다.

> **한 줄 요약:** 이분 탐색으로 찾는 대상은 값 자체가 아니라 **경계**입니다. 경계를 어디까지 남길지는 `hi` 의 처음 값과 `while` 의 부등호가 정합니다. 이 두 가지만 정확히 알면 변형마다 코드를 따로 외울 필요가 없습니다.

> **골라 읽는 법** — 이 글은 절 10개로 이루어져 있습니다.
>
> - 이분 탐색의 경계 조건만 보려면 → 앞의 세 절
> - 배열이 아닌 것에 이분 탐색을 쓰는 방법은 → 파라메트릭 서치와 회전 배열
> - 스택만 보려면 → 여섯째 절부터
> - 윈도우 최댓값을 O(n)으로 구하는 방법은 → 마지막 두 절

## 1. 절반씩 지우는 탐색

**배열이 정렬돼 있으면 가운데 칸의 값 하나만 보고도 남은 후보의 절반을 한꺼번에 버릴 수 있습니다.**

맨 앞 칸부터 하나씩 비교하는 앞에서부터 스캔은 값이 많을수록 비교 횟수도 그만큼 늘어납니다. 정렬된 배열이라면 이렇게 모든 칸을 열어 볼 필요가 없습니다. 값 12개가 정렬된 배열에서 38 을 찾는다고 해 봅시다. 가운데 칸을 열어 보니 23 이 들어 있었습니다. 배열이 정렬돼 있으니 23 의 왼쪽 칸에는 23 이하인 값만 들어 있습니다. 그 값들은 38 일 수 없으므로 왼쪽 절반은 한 칸도 열어 보지 않고 후보(아직 답일 수 있는 칸)에서 지워도 됩니다.

이 과정을 회차(반복 한 번)마다 되풀이하면서 가운데 칸의 값과 남은 후보 수를 찍어 봅니다. 코드의 `mid` 는 남은 범위의 가운데 칸 번호로, 두 끝 번호를 더해 2 로 나눈 몫 `(lo + hi) // 2` 입니다.

```python
# 하는 일: 정렬된 값 12개에서 38 을 이분 탐색으로 찾으며, 회차마다 가운데 값과 남은 후보 수를 찍는다.
ARR = [2, 5, 8, 12, 16, 23, 38, 45, 56, 72, 91, 100]
TARGET = 38

# 1단계: 가운데를 보고 절반을 지운다
# 가운데 값이 찾는 값보다 작으면 왼쪽 절반을, 크면 오른쪽 절반을 버린다.
print(f"찾는 값 {TARGET}, 값 {len(ARR)}개")
print(f"{'회차':<5}{'lo':>4}{'hi':>4}{'mid':>5}{'ARR[mid]':>10}   {'판정':<12}{'남은 후보'}")
lo, hi, k = 0, len(ARR) - 1, 0
while lo <= hi:
    k += 1
    mid = (lo + hi) // 2
    v = ARR[mid]
    if v == TARGET:
        print(f"{k:<5}{lo:>4}{hi:>4}{mid:>5}{v:>10}   {'같다 → 찾음':<12}-")
        break
    elif v < TARGET:
        lo = mid + 1
        판정 = "작다 → 오른쪽"
    else:
        hi = mid - 1
        판정 = "크다 → 왼쪽"
    print(f"{k:<5}{lo:>4}{hi:>4}{mid:>5}{v:>10}   {판정:<12}{hi-lo+1}개")
# 2단계: 앞에서부터 스캔할 때와 회차를 비교한다
print(f"\n{len(ARR)}개를 {k}회에 찾았다, 앞에서부터 스캔했다면 {ARR.index(TARGET)+1}회")

# 출력:
# 1단계 뜻: 값 12개에서 3회 만에 38 을 찾는다. 회차마다 남은 후보가 6개, 2개로 준다. 표의 lo 와 hi 는 그 회차의 판정에 따라 옮긴 뒤의 값이다.
# 찾는 값 38, 값 12개
# 회차     lo  hi  mid  ARR[mid]   판정          남은 후보
# 1       6  11    5        23   작다 → 오른쪽    6개
# 2       6   7    8        56   크다 → 왼쪽     2개
# 3       6   7    6        38   같다 → 찾음     -
# 2단계 뜻: 38 은 7번째 값이라 앞에서부터 스캔하면 7회가 걸린다.
#
# 12개를 3회에 찾았다, 앞에서부터 스캔했다면 7회
```

표의 `lo` 와 `hi` 는 그 회차의 판정을 마치고 옮긴 뒤의 값입니다. 1회차에는 0번부터 11번까지 12칸이 후보라 `mid` 가 (0 + 11) // 2 = 5 입니다. 5번 칸의 23 이 38 보다 작으므로 `lo` 를 6 으로 옮기면 후보는 6~11번 칸의 6개로 줄어듭니다. 2회차의 `mid` 는 (6 + 11) // 2 = 8 이고 8번 칸의 56 이 38 보다 커서 이번에는 `hi` 를 7 로 당기므로 6번과 7번 칸의 2개만 남습니다. 3회차에 `mid` 가 (6 + 7) // 2 = 6 이 되어 6번 칸에서 38 을 만나면 탐색이 끝납니다. 38 은 배열의 7번째 값이라 앞에서부터 스캔했다면 7회가 걸렸을 텐데 이분 탐색은 3회 만에 찾았습니다.

값이 200만 개로 늘면 두 방법의 차이가 커집니다. 앞에서부터 스캔하면 최악의 경우 200만 번을 비교해야 하지만 이분 탐색은 회차마다 후보가 절반 이하로 줄고 200만을 2 로 나눠 몫만 남기는 일을 21번 되풀이하면 0 이 되므로 21번이면 끝납니다.

다음 코드는 0 부터 1999999 까지 200만 개의 값이 정렬된 배열에서 맨 끝, 가운데, 맨 앞 값을 두 방법으로 찾아 걸린 시간을 측정합니다. 마지막 줄에는 이분 탐색이 넘지 않는 회차를 `N.bit_length()` 로 찍는데, `N.bit_length()` 는 N 을 2진수로 썼을 때의 자릿수입니다.

```python
# 하는 일: 값 200만 개에서 맨 끝, 가운데, 맨 앞 값을 앞에서부터 스캔과 이분 탐색으로 찾아 걸린 시간을 비교한다.
import time

N = 2_000_000
ARR = list(range(N))
찾을것 = [N - 1, N // 2, 0]

# 1단계: 두 방법을 만든다
# 스캔은 앞에서부터 하나씩 비교하고, 이분은 남은 구간의 가운데를 보고 절반을 버린다.
def 스캔(a, t):
    for i, v in enumerate(a):
        if v == t: return i
    return -1

def 이분(a, t):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if   a[mid] == t: return mid
        elif a[mid] <  t: lo = mid + 1
        else:             hi = mid - 1
    return -1

# 2단계: 세 값을 두 방법으로 찾으며 시간을 측정한다
print(f"{'찾는 값':>10}{'스캔(ms)':>12}{'이분(ms)':>12}")
for t in 찾을것:
    s = time.perf_counter(); 스캔(ARR, t); a = (time.perf_counter()-s)*1000
    s = time.perf_counter(); 이분(ARR, t); b = (time.perf_counter()-s)*1000
    print(f"{t:>10}{a:>12.1f}{b:>12.4f}")
# 3단계: 이분 탐색이 넘지 않는 회차를 찍는다
print(f"\n값 {N:,}개 → 이분은 최대 {N.bit_length()}회면 끝난다")

# 출력 (시간은 돌릴 때마다 다르다):
# 2단계 뜻: 찾는 값이 맨 끝이면 스캔이 가장 오래 걸리고, 맨 앞이면 스캔이 오히려 빠르다. 이분은 어디에 있든 비슷하다.
#       찾는 값      스캔(ms)      이분(ms)
#    1999999        40.1      0.0041
#    1000000        20.2      0.0048
#          0         0.0      0.0044
# 3단계 뜻: 값 200만 개도 이분 탐색은 21회를 넘지 않는다.
#
# 값 2,000,000개 → 이분은 최대 21회면 끝난다
```

밀리초 값은 돌리는 기계마다 다르게 나오므로 자릿수만 비교하면 됩니다. 스캔은 찾는 값이 맨 끝(1999999)이면 40.1 밀리초, 가운데(1000000)면 20.2 밀리초로 값이 뒤에 있을수록 오래 걸립니다. 표의 마지막 줄처럼 찾는 값이 맨 앞(0)이면 스캔이 0.0 밀리초라서 이분 탐색의 0.0044 밀리초보다 오히려 빠릅니다. 반면 이분 탐색은 0.0041, 0.0048, 0.0044 밀리초로 찾는 값이 어디에 있든 걸리는 시간이 비슷합니다. **이분 탐색의 값어치는 평균 속도에서 나오지 않고 가장 운이 나쁜 경우에도 21회를 넘지 않는다는 보장에서 나옵니다.** 채점 서버는 평균이 아니라 최악의 경우를 측정하므로 합격선을 넘을지는 이 보장이 정합니다.

## 2. 경계 조건과 네 가지 변형

**이분 탐색의 변형은 네 가지이고 변형마다 `hi` 의 처음 값, `while` 의 부등호, `mid` 를 구하는 식이 서로 짝이 맞아야 합니다.**

1절의 코드는 찾는 값과 같은 칸을 만나는 순간 멈추는 "값 자체를 찾는" 변형입니다. 그런데 실제 문제는 값이 든 칸보다 **경계**를 더 자주 묻습니다. "이 값 이상이 처음 나오는 자리", "이 값 이하인 마지막 자리"를 묻는 문제가 그런 예입니다. 묻는 자리가 달라지면 코드도 조금씩 달라지는데, 도입에서 지훈이 헷갈린 `while lo <= hi` 와 `while lo < hi` 도 이 차이에서 나옵니다.

같은 배열에 네 변형을 나란히 돌리면 차이가 한눈에 보입니다. 다음 코드는 3 이 1, 2, 3번 칸에 들어 있는 `[1, 3, 3, 3, 7]` 에 찾는 값 0, 3, 5, 7, 9 를 하나씩 넣고 네 변형이 내는 칸 번호를 한 표로 찍습니다.

```python
# 하는 일: 배열 [1, 3, 3, 3, 7] 에서 이분 탐색 네 변형을 찾는 값 다섯 개로 돌려, 같은 값에 답이 어떻게 다른지 비교한다.
ARR = [1, 3, 3, 3, 7]

# 1단계: 네 변형을 만든다
# 하나는 값 자체를 찾고 셋은 경계를 찾는다. hi 의 처음 값, while 의 부등호, mid 의 올림과 내림이 서로 맞물린다.
def 정확히(a, t):                       # 값 자체를 찾는다
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if   a[mid] == t: return mid
        elif a[mid] <  t: lo = mid + 1
        else:             hi = mid - 1
    return -1

def 왼쪽경계(a, t):                     # t 이상이 처음 나오는 자리
    lo, hi = 0, len(a)                  # hi 가 len 인 것에 주의
    while lo < hi:
        mid = (lo + hi) // 2            # 내림
        if a[mid] < t: lo = mid + 1
        else:          hi = mid
    return lo

def 오른쪽경계(a, t):                   # t 초과가 처음 나오는 자리
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] <= t: lo = mid + 1
        else:           hi = mid
    return lo

def 마지막으로작거나같은(a, t):          # t 이하인 마지막 자리
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi + 1) // 2        # 올림 — 이게 없으면 무한 루프
        if a[mid] <= t: lo = mid
        else:           hi = mid - 1
    return lo

# 2단계: 찾는 값 다섯 개로 네 변형을 돌린다
print("배열", ARR)
print(f"{'찾는 값':>7}{'정확히':>8}{'왼쪽경계':>9}{'오른쪽경계':>11}{'≤ 마지막':>10}")
for t in (0, 3, 5, 7, 9):
    print(f"{t:>7}{정확히(ARR,t):>8}{왼쪽경계(ARR,t):>9}{오른쪽경계(ARR,t):>11}{마지막으로작거나같은(ARR,t):>10}")

# 출력:
# 2단계 뜻: 3 처럼 같은 값이 여럿이면 네 변형이 서로 다른 칸(2, 1, 4, 3)을 낸다. 서로 다른 질문에 답하기 때문이다.
# 배열 [1, 3, 3, 3, 7]
#    찾는 값     정확히     왼쪽경계      오른쪽경계     ≤ 마지막
#       0      -1        0          0         0
#       3       2        1          4         3
#       5      -1        4          4         3
#       7       4        4          5         4
#       9      -1        5          5         4
```

찾는 값 3 의 줄을 보면 3 이 1, 2, 3번 칸에 들어 있는데 네 변형이 낸 답은 2, 1, 4, 3 으로 모두 다릅니다. **배열과 찾는 값이 같아도 변형에 따라 답은 4개로 나뉩니다.** 네 변형이 서로 다른 질문에 답하므로 이 가운데 틀린 답은 없습니다. 3 을 찾을 때 코드가 움직이는 차례를 따라가 보면 변형마다 어떤 질문에 답하는지 알 수 있습니다.

- **정확히 찾기**는 "3 이 있는가, 있다면 어느 칸인가"에 답합니다. 첫 회차의 `mid` 가 (0 + 4) // 2 = 2 이고 2번 칸이 3 이라 그 자리에서 2 를 돌려주므로, 3 이 여러 칸에 있으면 그중 아무 칸이나 나옵니다. 배열에 없는 0, 5, 9 에는 -1 을 냅니다.
- **왼쪽 경계**는 "3 이상이 처음 나오는 자리"에 답합니다. 찾는 값을 `t` 라 할 때 `a[mid] < t` 이면 `lo` 를 `mid + 1` 로 넘기고 3 이상인 칸은 `hi = mid` 로 후보에 남기므로, 반복이 끝났을 때 `lo` 는 3 보다 작은 1 이 든 0번 칸의 바로 다음인 1번 칸에 있습니다.
- **오른쪽 경계**는 "3 초과가 처음 나오는 자리"에 답합니다. 코드는 왼쪽 경계와 같은데 비교만 `a[mid] <= t` 로 바뀌어 3 과 같은 칸에서도 `lo` 를 넘기므로, 마지막 3 이 든 3번 칸을 지나 4번 칸(값 7)에서 멈춥니다. 부등호에 `=` 하나가 붙었을 뿐인데 답이 1 에서 4 로 바뀝니다.
- **이하인 마지막**은 "3 이하인 마지막 자리"처럼 조건을 만족하는 가장 큰 자리에 답합니다. 3 이하인 칸을 `lo = mid` 로 후보에 남기며 범위를 오른쪽으로 좁혀 가므로 3 이하인 마지막 칸인 3번에서 멈춥니다.

| 변형 | `hi` 초기값 | `while` | `mid` | 답의 뜻 |
|---|---|---|---|---|
| 정확히 찾기 | `len - 1` | `lo <= hi` | 내림 | 값이 있는 아무 칸, 없으면 -1 |
| 왼쪽 경계 | `len` | `lo < hi` | 내림 | 그 값 이상이 처음 나오는 자리 |
| 오른쪽 경계 | `len` | `lo < hi` | 내림 | 그 값 초과가 처음 나오는 자리 |
| 이하인 마지막 | `len - 1` | `lo < hi` | **올림** | 그 값 이하인 마지막 자리, 없어도 0 |

표를 보면 `while lo <= hi` 를 쓰는 변형은 정확히 찾기 하나뿐입니다. 정확히 찾기는 `lo` 와 `hi` 가 같아 후보가 1칸 남았을 때도 그 칸을 확인해야 하므로 `lo <= hi` 인 동안 돌다가, 후보가 하나도 없어 `lo` 가 `hi` 를 넘어서면 -1 을 냅니다. 경계를 찾는 세 변형은 `while lo < hi` 라서 `lo` 와 `hi` 가 같아지는 순간 멈추고 그 자리 `lo` 를 답으로 돌려줍니다. 그중 왼쪽 경계와 오른쪽 경계는 `hi` 를 `len`(이 배열에서는 5)에서 시작하므로 마지막 칸 4번의 다음 자리인 5 까지 답이 될 수 있어서 찾는 값 9 처럼 모든 값보다 크면 실제로 5 를 냅니다. 이하인 마지막은 정확히 찾기처럼 `len - 1` 에서 시작하지만 `while` 은 다른 두 경계 변형과 같은 `lo < hi` 입니다.

이하인 마지막 변형은 조건을 만족하는 칸이 없어도 0 을 돌려준다는 점을 조심해야 합니다. 출력에서 찾는 값 0 의 줄을 보면 배열에 0 이하인 값이 하나도 없는데도 0번 칸이 나왔는데, `lo` 가 0 에서 출발해 `lo = mid` 로 옮겨 갈 칸을 끝내 찾지 못하면 0 이 그대로 남기 때문입니다. 그래서 이 변형이 낸 `lo` 는 `a[lo] <= t` 가 참인지 확인한 뒤에 답으로 씁니다.

이하인 마지막 변형은 표의 마지막 줄처럼 `mid` 를 **올림**으로 구합니다. 파이썬의 `//` 는 나눈 몫의 소수점 아래를 버리므로 `(lo + hi) // 2` 는 가운데 칸이 2개일 때 왼쪽 칸을 고르는 내림입니다. `(lo + hi + 1) // 2` 는 1 을 더한 뒤 나누므로 같은 경우에 오른쪽 칸을 고르는 올림입니다. 조건을 만족한 칸을 `lo = mid` 로 후보에 남기는 변형도 네 변형 가운데 이하인 마지막 하나인데, `mid` 를 내림으로 두면 `lo` 와 `hi` 가 붙었을 때 `mid` 가 늘 `lo` 와 같아 `lo = mid` 로 가는 순간 `lo` 가 움직이지 않고 무한 루프에 빠지므로 1 을 더해 올림으로 구합니다.

`mid` 만 내림으로 바꾸고 찾는 값을 7 로 둔 코드로 이 무한 루프를 확인해 봅니다. 배열의 값이 모두 7 이하라 회차마다 `lo = mid` 쪽으로 가는데, 이대로는 반복이 끝나지 않으므로 코드는 `k < 6` 조건으로 6회에서 끊습니다.

```python
# 하는 일: 「이하인 마지막 자리」 변형에서 mid 를 내림으로 두면 lo 와 hi 가 멈춰 버리는 것을 6회만 돌려 본다.
ARR = [1, 3, 3, 3, 7]
lo, hi, k = 0, len(ARR) - 1, 0
print("mid 를 내림으로 두고 lo = mid 를 쓰면:")
while lo < hi and k < 6:
    k += 1
    mid = (lo + hi) // 2          # 내림 — 여기가 함정
    if ARR[mid] <= 7: lo = mid    # lo 가 mid 그대로
    else:             hi = mid - 1
    print(f"  {k}회차  lo={lo} hi={hi} mid={mid}")
print(f"  ... {k}회를 돌아도 lo 와 hi 가 그대로다 (무한 루프)")

# 출력:
# 뜻: 3회차부터 lo=3, hi=4, mid=3 이 그대로 되풀이된다. lo 와 hi 가 붙으면 내림으로 구한 mid 가 늘 lo 라서 lo = mid 가 아무것도 바꾸지 않는다.
# mid 를 내림으로 두고 lo = mid 를 쓰면:
#   1회차  lo=2 hi=4 mid=2
#   2회차  lo=3 hi=4 mid=3
#   3회차  lo=3 hi=4 mid=3
#   4회차  lo=3 hi=4 mid=3
#   5회차  lo=3 hi=4 mid=3
#   6회차  lo=3 hi=4 mid=3
#   ... 6회를 돌아도 lo 와 hi 가 그대로다 (무한 루프)
```

찍힌 줄을 차례로 보면 1회차에는 `mid` 가 (0 + 4) // 2 = 2 라서 `lo` 가 2 로, 2회차에는 (2 + 4) // 2 = 3 이라서 `lo` 가 3 으로 옮겨 갑니다. 3회차부터는 `lo` 3 과 `hi` 4 가 붙어 있어 내림으로 구한 `mid` 가 (3 + 4) // 2 = 3 으로 `lo` 와 같으므로, `lo = mid` 가 `lo` 를 3 그대로 두어 6회차까지 `lo=3, hi=4, mid=3` 이 되풀이됩니다. 같은 자리에서 올림을 썼다면 `mid` 가 (3 + 4 + 1) // 2 = 4 라서 `lo` 가 4 로 움직이고 `hi` 와 만나 반복이 끝납니다. 그래서 규칙은 한 줄로 끝납니다. **`lo = mid` 를 쓰는 코드에서는 `mid` 를 올림으로 구합니다.**

:::deep `(lo + hi) // 2` 와 정수 오버플로

면접에서는 가끔 `mid = (lo + hi) // 2` 대신 `mid = lo + (hi - lo) // 2` 를 쓰라는 조언이 왜 나왔는지를 묻습니다. 답은 정수 오버플로(정수형이 담을 수 있는 크기의 한계를 넘는 일)입니다.

`lo` 와 `hi` 가 각각 20억쯤이면 두 값을 더한 40억은 32비트 정수가 담을 수 있는 한계를 넘습니다. 자바나 C 에서는 이때 값이 음수로 뒤집혀 `mid` 가 엉뚱한 칸을 가리키는데, 자바 표준 라이브러리의 이분 탐색에도 실제로 이 버그가 9년 동안 남아 있었습니다.

**파이썬에서는 이 문제가 생기지 않습니다.** 파이썬 정수는 크기에 제한이 없어 값이 아무리 커져도 그만큼 커질 뿐입니다. 그래도 두 형태를 모두 알아 두면 코딩 테스트를 자바나 C++ 로 보는 사람과도 말이 통하고 면접에서 이 질문을 받았을 때 답할 수 있습니다.

덧붙이면 `lo + (hi - lo) // 2` 는 넘침을 막을 뿐 아니라 읽히는 방식도 다릅니다. "`lo` 에서 출발해 남은 폭의 절반만큼 간다"로 읽히므로 식 안에 구간 길이 `hi - lo` 가 그대로 보입니다.
:::

## 3. 표준 라이브러리 bisect

**왼쪽 경계와 오른쪽 경계를 찾는 함수는 파이썬 표준 라이브러리에 이미 들어 있습니다.**

2절의 네 변형을 문제마다 손으로 짜면 짤 때마다 경계에서 틀릴 기회가 새로 생깁니다. 파이썬 표준 라이브러리(파이썬을 설치하면 함께 들어 있는 기본 모듈들)의 `bisect` 를 쓰면 같은 일이 두 줄로 끝나는데, 이미 검증된 구현이라 경계에서 틀리지 않습니다. `bisect_left` 는 2절의 왼쪽 경계처럼 그 값 이상이 처음 나오는 칸을, `bisect_right` 는 오른쪽 경계처럼 그 값 초과가 처음 나오는 칸을 돌려줍니다.

다음 코드는 20 이 3칸에 들어 있는 `[10, 20, 20, 20, 30, 40]` 에서 찾는 값 5, 20, 25, 40, 50 마다 두 함수가 내는 칸을 찍은 뒤, 20 을 두고 개수와 20 보다 큰 첫 값 같은 자주 쓰는 값을 구해 봅니다.

```python
# 하는 일: 값 6개가 든 배열에서 bisect_left 와 bisect_right 로 값의 개수, 넣을 자리, 작은 것과 이하인 것의 개수를 구한다.
from bisect import bisect_left, bisect_right

# 1단계: 값마다 bisect_left 와 bisect_right 를 구한다
# 두 함수의 차가 그 값의 개수다. 값이 없으면 둘이 같은 칸을 내고, 그 칸이 정렬을 깨지 않고 넣을 자리다.
ARR = [10, 20, 20, 20, 30, 40]
print("배열", ARR, " 칸 번호", list(range(len(ARR))))
print()
print(f"{'찾는 값':>7}{'bisect_left':>13}{'bisect_right':>14}   {'뜻'}")
for t in (5, 20, 25, 40, 50):
    l, r = bisect_left(ARR, t), bisect_right(ARR, t)
    뜻 = f"{t} 이 {r-l}개 있다" if r > l else f"{t} 은 없다, {l}번 칸에 넣으면 된다"
    print(f"{t:>7}{l:>13}{r:>14}   {뜻}")
# 2단계: 20 을 두고 자주 쓰는 네 가지를 구한다
print()
print("20 의 개수      ", bisect_right(ARR, 20) - bisect_left(ARR, 20))
print("20 미만 개수    ", bisect_left(ARR, 20))
print("20 이하 개수    ", bisect_right(ARR, 20))
print("20 보다 큰 첫 값 ", ARR[bisect_right(ARR, 20)])

# 출력:
# 1단계 뜻: 20 은 1번 칸부터 3번 칸까지 3개 있다. 25 처럼 없는 값은 두 함수가 같은 칸 4 를 낸다.
# 배열 [10, 20, 20, 20, 30, 40]  칸 번호 [0, 1, 2, 3, 4, 5]
#
#    찾는 값  bisect_left  bisect_right   뜻
#       5            0             0   5 은 없다, 0번 칸에 넣으면 된다
#      20            1             4   20 이 3개 있다
#      25            4             4   25 은 없다, 4번 칸에 넣으면 된다
#      40            5             6   40 이 1개 있다
#      50            6             6   50 은 없다, 6번 칸에 넣으면 된다
# 2단계 뜻: bisect_left 는 그 값보다 작은 것의 개수이고, bisect_right 는 이하인 것의 개수다.
#
# 20 의 개수       3
# 20 미만 개수     1
# 20 이하 개수     4
# 20 보다 큰 첫 값  30
```

출력의 아래쪽 네 줄은 실전에서 자주 쓰는 계산입니다. 20 은 1번부터 3번 칸까지 들어 있어 `bisect_left` 가 1, `bisect_right` 가 4 를 냈고 두 함수의 차 4 - 1 = 3 이 **20 이 몇 개인지**를 알려 줍니다. 두 함수 모두 이분 탐색으로 자리를 찾으므로 배열을 스캔하지 않고도 이 개수가 나옵니다. `bisect_left` 가 낸 1 은 20 이상이 처음 나오는 칸 번호이고 그 앞 칸에는 20 보다 작은 값만 있으므로, `bisect_left` 는 그 자체로 **그 값보다 작은 것의 개수**(20 미만 1개)입니다. 같은 이유로 `bisect_right` 가 낸 4 는 20 초과가 처음 나오는 칸 번호라 그 앞에 10, 20, 20, 20 의 4개가 있으므로 **그 값 이하인 것의 개수**(20 이하 4개)입니다. 그래서 20 보다 큰 첫 값은 `bisect_right` 가 가리키는 4번 칸의 30 입니다.

값이 없을 때 두 함수가 같은 칸을 낸다는 점도 쓸모가 있습니다. 25 는 배열에 없으므로 25 이상이 처음 나오는 칸도, 25 초과가 처음 나오는 칸도 30 이 든 4번 칸입니다. 이 4번 칸이 **정렬을 깨지 않고 값을 끼워 넣을 칸**이라 25 를 넣으면 20 과 30 사이에 들어갑니다. 50 처럼 모든 값보다 크면 두 함수 모두 배열 길이와 같은 6 을 내므로 맨 뒤에 넣으면 됩니다. `insort` 는 이렇게 자리를 찾는 일과 그 자리에 값을 넣는 일을 한 번에 합니다.

> **주의** — `bisect` 는 배열이 정렬돼 있는지 확인하지 않고 정렬돼 있다고 **믿은 채** 자리를 계산합니다. 그래서 정렬되지 않은 배열에 쓰면 오류 없이 엉뚱한 자리를 돌려주는데, 이렇게 조용히 틀리는 코드는 오류를 내며 멈추는 코드보다 잘못된 곳을 찾기가 더 어렵습니다.

## 4. 파라메트릭 서치 — 답의 범위를 이분하는 방법

**이분 탐색은 배열이 있어야만 쓰는 도구가 아닙니다. 답이 될 수 있는 값의 범위를 반씩 좁혀도 됩니다.**

다음 문제를 봅시다. 길이가 802, 743, 457, 539 인 나무 4그루를 절단기로 같은 높이에서 잘라 그 위로 올라온 부분만 가져간다고 할 때, 1000 만큼을 얻으려면 절단기 높이를 최대 얼마로 둘 수 있을까요?

높이를 하나씩 올려 보면 최대 802번을 시도해야 합니다. 그런데 이 문제에는 **단조성**이 있습니다. 단조성(monotonicity)은 한 값을 키울 때 다른 값이 한 방향으로만 움직이는 성질입니다. 이 문제에서는 높이를 올리면 얻는 양이 반드시 줄어듭니다. 그래서 "이 높이로 1000 을 얻을 수 있나"라는 예, 아니오 질문의 답이 어느 높이까지는 예이고 그보다 높으면 아니오가 되어 한 지점을 경계로 딱 나뉩니다.

예, 아니오가 바뀌는 경계가 있으면 이분 탐색이 통합니다. 찾는 대상만 배열의 칸에서 **높이 그 자체**로 바뀌었습니다. 이렇게 답이 될 수 있는 값의 범위를 이분해(반으로 나눠 한쪽을 버리며) 경계를 찾는 방법을 파라메트릭 서치(parametric search)라고 부릅니다. 코드는 높이 0 부터 가장 긴 나무의 길이 802 까지를 범위로 두고 1000 이상을 얻는 가장 높은 높이를 찾습니다. 높이 `h` 에서 얻는 양은 `h` 보다 긴 나무마다 `h` 위로 올라온 길이(나무 길이 `x` 에서 `h` 를 뺀 `x - h`)를 모두 더한 값입니다.

```python
# 하는 일: 나무 4그루를 같은 높이에서 잘라 1000 이상을 얻을 수 있는 가장 높은 높이를, 높이를 반씩 좁혀 찾는다.
길이 = [802, 743, 457, 539]
목표 = 1000

# 1단계: 높이 h 에서 얻는 양을 구하는 함수를 만든다
# 높이를 올리면 얻는 양은 줄기만 한다. 이 단조성이 있어서 이분 탐색이 통한다.
def 얻는양(h):
    return sum(x - h for x in 길이 if x > h)

# 2단계: 1000 이상을 얻는 가장 높은 높이를 찾는다
# 조건을 만족하는 가장 큰 값을 찾으니 mid 를 올림으로 구한다.
lo, hi, k = 0, max(길이), 0
print(f"{'회차':<5}{'lo':>6}{'hi':>6}{'mid':>6}{'얻는 양':>9}   판정")
while lo < hi:
    k += 1
    mid = (lo + hi + 1) // 2
    양 = 얻는양(mid)
    if 양 >= 목표:
        lo = mid
        판정 = f"{목표} 이상 → 더 높여 본다"
    else:
        hi = mid - 1
        판정 = f"{목표} 미만 → 낮춰야 한다"
    print(f"{k:<5}{lo:>6}{hi:>6}{mid:>6}{양:>9}   {판정}")
print(f"\n답 {lo}, 이때 얻는 양 {얻는양(lo)}")

# 출력:
# 2단계 뜻: 높이 0~802 를 10회 만에 좁힌다. 1000 이상이면 더 높여 보고, 미만이면 낮춘다. 표의 lo 와 hi 는 그 회차의 판정에 따라 옮긴 뒤의 값이다.
# 회차       lo    hi   mid     얻는 양   판정
# 1         0   400   401      937   1000 미만 → 낮춰야 한다
# 2       200   400   200     1741   1000 이상 → 더 높여 본다
# 3       300   400   300     1341   1000 이상 → 더 높여 본다
# 4       350   400   350     1141   1000 이상 → 더 높여 본다
# 5       375   400   375     1041   1000 이상 → 더 높여 본다
# 6       375   387   388      989   1000 미만 → 낮춰야 한다
# 7       381   387   381     1017   1000 이상 → 더 높여 본다
# 8       384   387   384     1005   1000 이상 → 더 높여 본다
# 9       384   385   386      997   1000 미만 → 낮춰야 한다
# 10      385   385   385     1001   1000 이상 → 더 높여 본다
# 2단계 뜻: 높이 385 에서 얻는 양이 1001 로 1000 을 넘는다. 한 칸 더 높은 386 에서는 997 이다.
#
# 답 385, 이때 얻는 양 1001
```

높이 0 에서 802 까지 803가지 후보를 10회 만에 좁혔습니다. 1회차에는 0 과 802 의 가운데를 올림으로 구한 401 에서 얻는 양이 937 로 1000 에 못 미쳐 `hi` 를 400 으로 낮춥니다. 2회차에는 200 에서 1741 을 얻으므로 `lo` 를 200 으로 올립니다. 이렇게 좁혀 가다 9회차에는 386 에서 얻는 양이 997 이라 `hi` 가 385 로 내려옵니다. 10회차에는 385 에서 1001 을 얻어 `lo` 도 385 가 되므로 `lo` 와 `hi` 가 만나 반복이 끝납니다. 385 에서는 1001 로 1000 이상이지만 한 칸 더 높은 386 에서는 997 로 1000 에 못 미치므로 385 가 1000 이상을 얻는 가장 높은 높이입니다.

이 코드도 `mid` 를 올림으로 구합니다. "조건을 만족하는 **가장 큰** 값"을 찾으므로 1000 이상을 얻은 높이를 `lo = mid` 로 후보에 남기는데, 2절의 이하인 마지막 변형과 같은 꼴이라 올림이 필요합니다. 9회차가 끝난 뒤처럼 `lo` 384 와 `hi` 385 가 붙어 있을 때 내림을 쓰면 `mid` 가 (384 + 385) // 2 = 384 가 되는데, 384 에서 얻는 양 1005 가 1000 이상이라 `lo = mid` 로 가도 `lo` 는 384 그대로이므로 2절에서 본 무한 루프가 생깁니다.

파라메트릭 서치를 쓸 수 있는지는 물음 하나로 판단합니다. **"답을 x라 두었을 때, x가 되면 되고 x보다 크면 안 되는가"** 를 물어 그렇다는 답이 나오면 통합니다. 나무 문제에서는 385 가 되고 그보다 높은 386 부터는 안 되므로 이 물음에 그렇다고 답할 수 있습니다. 문제 지문의 "최소의 최대", "최대의 최소" 같은 표현은 이 꼴의 문제라는 신호입니다.

광고 입찰가를 정할 때도 같은 구조를 씁니다. 입찰가를 올리면 경매에서 이길 확률은 오르지만 이겼을 때 남는 이익은 줄어드는데, 이 단조 관계를 바탕으로 최적점을 찾습니다. 자세한 내용은 [Bid Shading](post.html?id=bid-shading-censored) 편 4절의 황금 비율 탐색에 있습니다.

## 5. 회전된 배열과 정렬된 반쪽

**정렬된 배열을 어느 지점에서 잘라 앞뒤를 바꾸더라도 이분 탐색은 여전히 통합니다.**

1절의 이분 탐색은 배열이 정렬돼 있어야 절반을 버릴 수 있었습니다. 정렬된 배열 `[2, 5, 8, 12, 16, 30, 38, 45, 56]` 을 30 이 맨 앞에 오도록 회전시키면 `[30, 38, 45, 56, 2, 5, 8, 12, 16]` 이 되는데, 이처럼 정렬된 배열을 한 지점에서 잘라 앞뒤를 바꾼 배열을 회전된 배열이라 합니다. 회전된 배열은 전체로 보면 정렬이 깨져 있습니다. 그런데 가운데를 기준으로 반으로 나누면 값이 작아지는 자리(56 다음에 2 가 오는 곳)가 든 쪽만 정렬이 깨지므로 **다른 한쪽은 반드시 정렬돼 있습니다.**

정렬된 반쪽에서는 모든 값이 양 끝 값 사이에 있으므로 찾는 값이 그 안에 있는지는 양 끝만 보면 알 수 있습니다. 찾는 값이 그 반쪽 안에 있으면 그쪽으로 가고 없으면 반대쪽으로 가므로 어느 쪽으로 가든 후보는 절반으로 줄어듭니다.

다음 코드는 이 배열에서 5 를 찾으면서 회차마다 어느 반쪽이 정렬돼 있는지를 먼저 보고 갈 쪽을 정합니다. `ARR[lo] <= ARR[mid]` 이면 왼쪽 반이, 아니면 오른쪽 반이 정렬된 반쪽입니다.

```python
# 하는 일: 회전된 배열 9칸에서 5 를 찾으며, 회차마다 어느 반쪽이 정렬돼 있는지 먼저 보고 갈 쪽을 정한다.
ARR, TARGET = [30, 38, 45, 56, 2, 5, 8, 12, 16], 5

print("배열", ARR, " 찾는 값", TARGET)
print(f"{'회차':<5}{'lo':>4}{'hi':>4}{'mid':>5}{'값':>5}   {'정렬된 반쪽':<12}{'판정'}")
lo, hi, k = 0, len(ARR) - 1, 0
while lo <= hi:
    k += 1
    mid = (lo + hi) // 2
    if ARR[mid] == TARGET:
        print(f"{k:<5}{lo:>4}{hi:>4}{mid:>5}{ARR[mid]:>5}   {'-':<12}찾음")
        break
    if ARR[lo] <= ARR[mid]:                        # 왼쪽 반이 정렬돼 있다
        반쪽 = f"왼쪽 {ARR[lo]}~{ARR[mid]}"
        if ARR[lo] <= TARGET < ARR[mid]:
            hi = mid - 1; 판정 = "그 안에 있다 → 왼쪽"
        else:
            lo = mid + 1; 판정 = "그 안에 없다 → 오른쪽"
    else:                                          # 오른쪽 반이 정렬돼 있다
        반쪽 = f"오른쪽 {ARR[mid]}~{ARR[hi]}"
        if ARR[mid] < TARGET <= ARR[hi]:
            lo = mid + 1; 판정 = "그 안에 있다 → 오른쪽"
        else:
            hi = mid - 1; 판정 = "그 안에 없다 → 왼쪽"
    print(f"{k:<5}{lo:>4}{hi:>4}{mid:>5}{ARR[mid]:>5}   {반쪽:<12}{판정}")

# 출력:
# 뜻: 1회차에 lo 가 0 일 때 ARR[lo] 30 이 ARR[mid] 2 보다 커서 오른쪽 반이 정렬된 쪽이다. 5 가 그 범위 2~16 안이라 lo 를 5 로 옮기고, 3회차에 찾는다.
# 배열 [30, 38, 45, 56, 2, 5, 8, 12, 16]  찾는 값 5
# 회차     lo  hi  mid    값   정렬된 반쪽      판정
# 1       5   8    4    2   오른쪽 2~16    그 안에 있다 → 오른쪽
# 2       5   5    6    8   왼쪽 5~8      그 안에 있다 → 왼쪽
# 3       5   5    5    5   -           찾음
```

1회차에는 `lo` 0 과 `hi` 8 의 가운데인 4번 칸의 2 를 봅니다. `ARR[lo]` 30 이 `ARR[mid]` 2 보다 크므로 왼쪽 반은 정렬이 깨진 반쪽이고 오른쪽 반 2~16 이 정렬된 반쪽입니다. 찾는 값 5 가 2~16 범위 안에 있으므로 `lo` 를 5 로 옮겨 오른쪽으로 갑니다. 2회차에는 5번부터 8번 칸의 가운데인 6번 칸의 8 을 봅니다. 이번에는 `ARR[lo]` 5 가 8 보다 크지 않아 왼쪽 반 5~8 이 정렬된 반쪽입니다. 5 가 그 범위에 들어 있으므로 `hi` 를 5 로 당겨 왼쪽으로 갑니다. 3회차에는 `lo` 와 `hi` 가 모두 5 라서 5번 칸을 보고 5 를 찾습니다.

**먼저 어느 반쪽이 정렬됐는지 판정하고 그다음에 찾는 값이 그 반쪽 안에 있는지 봅니다.** 찾는 값이 안에 있는지를 양 끝 값만으로 알 수 있는 곳은 정렬된 반쪽뿐이라 이 두 단계의 순서를 뒤집으면 틀립니다. 회전 배열 문제에서 헤매는 경우도 대부분 이 순서를 섞어서 생깁니다.

## 6. 스택 — 마지막에 넣은 것을 먼저 꺼내는 자료구조

**이분 탐색이 정렬된 후보를 반씩 지우는 도구였다면 스택은 아직 짝을 찾지 못한 것을 쌓아 두는 도구입니다.**

스택은 마지막에 넣은 것을 가장 먼저 꺼내는 자료구조입니다. 파이썬에서는 리스트를 그대로 스택으로 쓰는데, `append` 로 넣고 `pop` 으로 마지막에 넣은 것을 빼면 됩니다. O(1) 은 값이 아무리 많아도 한 번 하는 데 드는 시간이 일정하다는 뜻입니다. `append` 와 `pop` 이 모두 O(1) 이므로 스택을 위한 자료형을 따로 만들 필요가 없습니다.

스택이 답이 되는 문제에는 **"가장 최근 것과 짝을 맞춘다"** 는 신호가 있습니다. 괄호 문제가 대표적인데, 닫는 괄호를 만났을 때 그 짝은 맨 처음 열린 괄호가 아니라 언제나 가장 최근에 열린 괄호입니다. 그래서 여는 괄호를 스택에 쌓아 두면 짝을 맞춰 볼 괄호가 늘 맨 위에 있습니다.

다음 코드는 `([]{})` 와 `([)]` 를 한 글자씩 읽으며 여는 괄호는 쌓고 닫는 괄호를 만나면 맨 위와 짝이 맞는지 확인해 빼면서 글자마다 바뀌는 스택을 찍습니다.

```python
# 하는 일: 괄호 문자열 두 개가 짝이 맞는지 스택으로 확인하며, 글자마다 스택이 어떻게 바뀌는지 찍는다.
쌍 = {")": "(", "]": "[", "}": "{"}

# 1단계: 괄호를 한 글자씩 보며 스택에 쌓고 뺀다
# 닫는 괄호의 짝은 늘 가장 최근에 연 괄호다. 끝까지 본 뒤 스택이 비어 있어야 맞다.
def 확인(s):
    스택 = []
    print(f"  {'글자':<5}{'하는 일':<22}{'스택'}")
    for c in s:
        if c in "([{":
            스택.append(c)
            print(f"  {c:<5}{'여는 괄호 → 쌓는다':<20}{스택}")
        else:
            if not 스택 or 스택[-1] != 쌍[c]:
                print(f"  {c:<5}{'짝이 안 맞는다 → 실패':<19}{스택}")
                return False
            스택.pop()
            print(f"  {c:<5}{'짝이 맞는다 → 뺀다':<20}{스택}")
    return not 스택

# 2단계: 두 문자열을 확인한다
for s in ("([]{})", "([)]"):
    print(f"'{s}'")
    r = 확인(s)
    print(f"  → {'맞다' if r else '틀리다'}\n")

# 출력:
# 2단계 뜻: 여는 괄호를 쌓고, 닫는 괄호를 만나면 맨 위의 짝을 뺀다. 끝에 스택이 비어 맞다.
# '([]{})'
#   글자   하는 일                  스택
#   (    여는 괄호 → 쌓는다         ['(']
#   [    여는 괄호 → 쌓는다         ['(', '[']
#   ]    짝이 맞는다 → 뺀다         ['(']
#   {    여는 괄호 → 쌓는다         ['(', '{']
#   }    짝이 맞는다 → 뺀다         ['(']
#   )    짝이 맞는다 → 뺀다         []
#   → 맞다
#
# 2단계 뜻: ) 를 만났을 때 맨 위가 [ 라 짝이 안 맞는다. 괄호 개수는 맞아도 틀린 문자열이다.
# '([)]'
#   글자   하는 일                  스택
#   (    여는 괄호 → 쌓는다         ['(']
#   [    여는 괄호 → 쌓는다         ['(', '[']
#   )    짝이 안 맞는다 → 실패      ['(', '[']
#   → 틀리다
```

첫 문자열 `([]{})` 은 `]`, `}`, `)` 를 만날 때마다 맨 위가 그 짝이라 하나씩 빠지므로 마지막 `)` 를 뺀 뒤 스택이 `[]` 로 비어 맞다고 나옵니다. 두 번째 문자열 `([)]` 는 여는 괄호 2개와 닫는 괄호 2개로 개수는 맞습니다. 그런데 `(` 와 `[` 를 쌓아 스택이 `['(', '[']` 인 채로 `)` 를 만났을 때 가장 최근에 열린 맨 위가 `)` 의 짝인 `(` 가 아니라 `[` 라서 그 자리에서 실패하므로, 괄호 개수만 세는 코드로는 이 문자열의 잘못을 잡지 못합니다.

스택에 괄호가 남아 있다면 열기만 하고 닫지 않은 괄호가 있다는 뜻이므로 끝까지 읽은 뒤의 `return not 스택` 으로 스택이 비었는지도 확인합니다. `"((("` 는 닫는 괄호가 없어 짝 검사를 한 번도 거치지 않고 `(` 3개를 스택에 남기므로, **닫는 괄호에서만 검사하는 코드는 `"((("` 같은 입력도 통과시킵니다.**

## 7. 단조 스택 — 다음에 오는 더 큰 값

**아직 답을 찾지 못한 칸 번호를 스택에 쌓아 두면 이중 반복문이 필요해 보이는 문제도 한 번 순회로 끝납니다.**

날마다 기온이 있을 때 날짜마다 "며칠 뒤에 처음으로 더 더워지는가"를 구하는 문제를 봅시다. 날짜마다 그 뒤의 날과 하나씩 비교해 짝을 전부 만들면 O(n²) 인데, O(n²) 은 걸리는 시간이 날짜 수 n 의 제곱에 비례한다는 뜻입니다.

관찰 하나가 이 문제의 풀이를 바꿉니다. **어제 28도였던 기온이 오늘 33도로 올랐다면 어제의 답은 오늘입니다.** 28도 앞에 30도인 날이 있었다면 그날은 다음 날이 28도라 아직 더 더운 날을 만나지 못했으므로 30도의 답도 오늘입니다. 이렇게 아직 답을 찾지 못한 날 가운데 오늘 기온보다 낮은 날들은 한꺼번에 답을 얻습니다.

그래서 아직 답을 찾지 못한 날의 칸 번호를 스택에 쌓아 두었다가 새 날이 올 때마다 그날보다 낮은 날들을 꺼내며 답을 적으면 됩니다. 새 날을 쌓기 전에 그보다 낮은 날을 모두 꺼내므로 스택에는 아래에서 위로 기온이 내림차순으로 남습니다. 이렇게 값이 한 방향으로 정렬된 상태를 유지하는 스택을 **단조 스택**(monotonic stack)이라 부릅니다.

7일치 기온 `[30, 28, 33, 31, 29, 35, 32]` 를 이 방법으로 처리하며 칸마다 스택이 어떻게 바뀌는지 찍어 봅니다. 꺼낸 칸 `j` 의 답은 오늘 칸 번호 `i` 에서 `j` 를 뺀 `i - j` 일입니다.

```python
# 하는 일: 7일치 기온에서 날마다 며칠 뒤에 처음으로 더 더워지는지를 단조 스택으로 구한다.
기온 = [30, 28, 33, 31, 29, 35, 32]
답 = [0] * len(기온)
스택 = []                       # 아직 답을 못 찾은 칸 번호를 쌓아 둔다

# 1단계: 날마다 그보다 낮은 날들을 스택에서 꺼낸다
# 스택에는 아직 답을 못 찾은 날의 칸 번호가 기온이 내려가는 순서로 남는다. 새 날이 더 더우면 꺼내며 답을 적는다.
print(f"{'칸':<4}{'기온':<6}{'하는 일':<34}{'스택(칸번호)'}")
for i, t in enumerate(기온):
    뺀것 = []
    while 스택 and 기온[스택[-1]] < t:
        j = 스택.pop()
        답[j] = i - j
        뺀것.append(f"{j}번은 {i-j}일 뒤")
    스택.append(i)
    설명 = ", ".join(뺀것) if 뺀것 else "더 높은 게 없다 → 쌓기만"
    print(f"{i:<4}{t:<6}{설명:<34}{스택}")

# 2단계: 기온과 답을 나란히 찍는다
print(f"\n기온 {기온}")
print(f"답   {답}   (0 은 끝까지 더 높은 날이 없다는 뜻)")

# 출력:
# 1단계 뜻: 5번 칸의 35도가 세 날을 한꺼번에 꺼낸다. 칸마다 스택에 한 번 들어가고 많아야 한 번 나오니 전체는 O(n) 이다.
# 칸   기온    하는 일                              스택(칸번호)
# 0   30    더 높은 게 없다 → 쌓기만                   [0]
# 1   28    더 높은 게 없다 → 쌓기만                   [0, 1]
# 2   33    1번은 1일 뒤, 0번은 2일 뒤                [2]
# 3   31    더 높은 게 없다 → 쌓기만                   [2, 3]
# 4   29    더 높은 게 없다 → 쌓기만                   [2, 3, 4]
# 5   35    4번은 1일 뒤, 3번은 2일 뒤, 2번은 3일 뒤      [5]
# 6   32    더 높은 게 없다 → 쌓기만                   [5, 6]
# 2단계 뜻: 칸마다 며칠 뒤에 처음 더 더워지는지다. 끝까지 더 높은 날이 없는 칸은 0 이다.
#
# 기온 [30, 28, 33, 31, 29, 35, 32]
# 답   [2, 1, 3, 2, 1, 0, 0]   (0 은 끝까지 더 높은 날이 없다는 뜻)
```

2번 칸에 33도가 오면 스택에 있던 1번(28도)과 0번(30도)이 모두 33도보다 낮아 각각 1일 뒤, 2일 뒤라는 답을 얻고 스택은 `[2]` 가 됩니다. 4번 칸까지 스택은 `[2, 3, 4]`(33도, 31도, 29도)로 아래에서 위로 기온이 내려가다가, 5번 칸에 35도가 오면 맨 위의 4번부터 3번, 2번 칸까지 차례로 꺼내 각각 1일, 2일, 3일 뒤라는 답을 적습니다. 끝까지 스택에 남은 5번(35도)과 6번(32도)은 더 더운 날이 없어 처음에 넣어 둔 0 이 그대로 남으므로 답은 `[2, 1, 3, 2, 1, 0, 0]` 입니다.

5번 칸에서는 3개를 한꺼번에 꺼냈고 `for` 반복 안에 `while` 이 또 있으니 O(n²) 처럼 보입니다. 그런데 **각 칸은 스택에 한 번 들어가고 많아야 한 번 나옵니다.** 전체 `pop` 횟수가 칸 개수를 넘지 못하므로 전체는 O(n) 입니다. O(n) 은 걸리는 시간이 칸 개수 n 에 비례한다는 뜻입니다. 이 예에서도 꺼낸 횟수는 2번 칸에서 2개, 5번 칸에서 3개로 모두 5개라 칸 개수 7 을 넘지 않습니다.

투 포인터(two pointers)는 정렬된 배열의 양 끝에 포인터 두 개를 두고 안쪽으로 좁혀 오는 방법입니다. 이 절의 논증은 앞 편에서 본 투 포인터의 논증과 같은 꼴이라 두 경우 모두 반복문이 겹쳐 보여도 **전체 이동 횟수를 세면** 답이 나옵니다. 면접에서 "여기 `while` 이 있는데 왜 O(n)인가"라는 질문을 받으면 칸마다 들어가고 나오는 횟수를 세어 이렇게 답하면 됩니다.

## 8. 덱 — 양끝에서 넣고 빼는 자료구조

**파이썬 리스트는 맨 앞에서 값을 빼는 일이 비싸므로 양끝을 모두 써야 하는 코드에는 `deque` 를 씁니다.**

앞 편에서 본 대로 `리스트.pop(0)` 은 맨 앞을 뺀 뒤 뒤에 있는 값을 전부 한 칸씩 앞으로 당기므로 한 번 할 때마다 O(n) 이 걸립니다. 그래서 `pop(0)` 을 십만 번 반복하면 그 반복만으로 시간 초과가 납니다. `collections.deque` 는 양끝에서 넣고 빼도록 만들어진 자료구조라 맨 앞을 빼는 `popleft` 도 O(1) 입니다.

| 하는 일 | 리스트 | `deque` |
|---|---|---|
| 뒤에 넣기 | O(1) | O(1) |
| 뒤에서 빼기 | O(1) | O(1) |
| 앞에 넣기 | O(n) | O(1) |
| 앞에서 빼기 | O(n) | O(1) |
| 가운데 칸 읽기 | O(1) | O(n) |

표의 마지막 줄은 두 자료구조의 맞바꿈(trade-off)을 보여 줍니다. 가운데 칸 읽기는 리스트가 O(1), `deque` 가 O(n) 이라 `deque` 는 양끝이 빠른 대신 `d[5]` 같은 가운데 칸 접근이 느리므로 번호로 아무 칸이나 골라 읽는 코드에는 맞지 않습니다. **양끝만 쓰는 코드는 `deque` 로, 가운데 칸을 번호로 골라 읽는 코드는 리스트로 씁니다.**

너비 우선 탐색(BFS)은 시작점에서 가까운 곳부터 차례로 방문하는 탐색입니다. BFS 에서는 큐(queue)로 `deque` 를 쓰는데, 큐는 뒤에 넣고 앞에서 빼는 일만 하므로 `deque` 의 빠른 양끝 동작만 쓰기 때문입니다. BFS 는 그래프 편에서 다시 나옵니다.

## 9. 단조 덱 — 슬라이딩 윈도우 최댓값

**단조 스택의 방법을 양끝에서 넣고 빼는 덱으로 넓히면 슬라이딩 윈도우(한 칸씩 옮겨 가는 고정 크기 구간)마다 최댓값을 한 번 순회로 구할 수 있습니다.**

앞 편에서는 슬라이딩 윈도우(sliding window)로 구간의 **합**을 구했는데, 합은 윈도우를 옮길 때 빠지는 값을 빼고 들어오는 값을 더하면 됐습니다. 그런데 **최댓값**은 지금의 최댓값이 윈도우 밖으로 나가면 남은 값들 가운데에서 다시 찾아야 해서 그렇게 구할 수 없습니다.

여기에도 쓸 만한 관찰이 하나 있습니다. **새로 들어온 값보다 작고 그보다 왼쪽에 있는 값은 이후 어떤 윈도우에서도 최댓값이 될 수 없습니다.** 윈도우가 옆으로 옮겨 가면 그 값이 새로 들어온 값보다 먼저 윈도우 밖으로 나가므로, 윈도우에 남아 있는 동안에는 늘 자기보다 큰 값과 함께 있어 최댓값이 될 기회가 없습니다. 그러니 이런 값은 버려도 됩니다. 4번 칸에 5 가 들어올 때 덱에 있던 1, 2, 3번 칸의 3, -1, -3 이 이런 값입니다.

그래서 덱에는 칸 번호를 넣되 그 칸들의 값이 앞에서 뒤로 내림차순이 되게 유지합니다. 새 값이 들어오면 그보다 작거나 같은 값의 칸을 뒤에서 버리고 윈도우 밖으로 나간 칸은 앞에서 버리므로, 덱에 남은 칸은 모두 지금 윈도우 안에 있고 값은 앞에서 뒤로 줄어들어 **덱의 맨 앞이 언제나 지금 윈도우의 최댓값**입니다. 이렇게 값의 순서를 한 방향으로 유지하는 덱을 단조 덱(monotonic deque)이라 합니다.

값 8개 `[1, 3, -1, -3, 5, 3, 6, 7]` 에서 크기 3 인 윈도우를 한 칸씩 옮기며 윈도우마다 최댓값을 구하고 덱에 남은 칸 번호도 함께 찍어 봅니다.

```python
# 하는 일: 값 8개에서 크기 3 인 윈도우를 한 칸씩 옮기며, 단조 덱으로 윈도우마다 최댓값을 구한다.
from collections import deque

ARR, K = [1, 3, -1, -3, 5, 3, 6, 7], 3
덱, 답 = deque(), []

# 1단계: 칸마다 덱을 고치고 윈도우 최댓값을 읽는다
# 새 값보다 작은 것은 뒤에서 버리고, 윈도우 밖으로 나간 것은 앞에서 버린다. 그러면 덱의 맨 앞이 늘 지금 윈도우의 최댓값이다.
print(f"{'칸':<4}{'값':<5}{'덱(칸번호)':<18}{'윈도우':<16}{'최댓값'}")
for i, v in enumerate(ARR):
    while 덱 and ARR[덱[-1]] <= v:
        덱.pop()                       # 뒤에서 작은 것들을 버린다
    덱.append(i)
    if 덱[0] <= i - K:
        덱.popleft()                   # 윈도우 밖으로 나간 것을 버린다
    if i >= K - 1:
        답.append(ARR[덱[0]])
        윈도우 = ARR[i-K+1:i+1]
        print(f"{i:<4}{v:<5}{str(list(덱)):<18}{str(윈도우):<16}{ARR[덱[0]]}")
    else:
        print(f"{i:<4}{v:<5}{str(list(덱)):<18}{'아직 윈도우가 안 참':<14}-")
# 2단계: 윈도우마다 구한 최댓값을 찍는다
print(f"\n답 {답}")

# 출력:
# 1단계 뜻: 덱에는 칸 번호가 값이 줄어드는 순서로 남고, 맨 앞 칸의 값이 그 윈도우의 최댓값이다. 4번 칸의 5 가 들어오며 덱에 있던 셋을 모두 버린다.
# 칸   값    덱(칸번호)            윈도우             최댓값
# 0   1    [0]               아직 윈도우가 안 참   -
# 1   3    [1]               아직 윈도우가 안 참   -
# 2   -1   [1, 2]            [1, 3, -1]      3
# 3   -3   [1, 2, 3]         [3, -1, -3]     3
# 4   5    [4]               [-1, -3, 5]     5
# 5   3    [4, 5]            [-3, 5, 3]      5
# 6   6    [6]               [5, 3, 6]       6
# 7   7    [7]               [3, 6, 7]       7
# 2단계 뜻: 윈도우 6개의 최댓값이다.
#
# 답 [3, 3, 5, 5, 6, 7]
```

출력의 덱 칸에는 칸 번호가 값이 줄어드는 순서로 남아 있습니다. 3번 칸까지 처리한 덱은 `[1, 2, 3]`(값 3, -1, -3)이라 맨 앞 1번 칸의 3 이 윈도우 `[3, -1, -3]` 의 최댓값입니다. 4번 칸에서 5 가 들어오면 덱에 있던 1, 2, 3번 칸의 값이 모두 5 보다 작아 뒤에서부터 차례로 버려지므로 덱에는 `[4]` 만 남고 윈도우 `[-1, -3, 5]` 의 최댓값은 5 입니다. 같은 식으로 윈도우 6개의 최댓값 `[3, 3, 5, 5, 6, 7]` 이 차례로 나옵니다.

## 10. 도구를 고르는 기준

**어느 도구를 쓸지는 문제 지문에 나온 표현이 거의 알려 줍니다.**

문제를 받으면 먼저 입력이 정렬돼 있는지를 봅니다. 이분 탐색은 정렬된 배열에서 가운데 값 하나로 절반을 지우므로 입력이 정렬돼 있거나 정렬해도 답이 바뀌지 않으면 이분 탐색이 후보입니다. 지문에 "이상인 첫", "이하인 마지막", "몇 개인가" 같은 표현이 보이면 3절의 `bisect` 두 줄로 끝납니다.

입력이 정렬돼 있지 않아도 **답이 단조로우면** 파라메트릭 서치가 통합니다. "최소의 최대", "최대의 최소", "가능한 가장 큰 값" 같은 표현이 신호입니다. 이때는 4절에서 높이 0~802 를 이분했듯이 배열이 아니라 답의 범위를 이분합니다.

배열을 왼쪽에서 오른쪽으로 지나가며 **가장 최근 것과 짝을 맞추는** 문제는 스택으로 풉니다. 괄호, 수식, 되돌리기가 이런 문제입니다. 짝을 맞추는 기준이 7절의 기온 문제처럼 "나보다 큰 첫 값" 같은 크기 비교라면 단조 스택을 씁니다.

마지막으로 **양끝을 모두 쓰는** 문제에는 덱을 씁니다. 큐가 필요한 BFS 가 대표적입니다. 슬라이딩 윈도우에서 최댓값이나 최솟값을 물으면 단조 덱으로 풉니다.

이분 탐색, 스택, 덱 세 가지 도구를 이렇게 정리해 두면 배열 계열 문제의 상당 부분을 다룰 수 있습니다. 트리와 그래프라는 남은 큰 갈래는 다음 편에서 이어 갑니다.

## 한눈 정리

| 지문에 이런 말이 나오면 | 쓸 것 | 왜 |
|---|---|---|
| 정렬된 배열에서 값 찾기 | 이분 탐색 | 가운데 하나로 절반을 지운다 |
| "이상인 첫", "이하인 마지막" | `bisect_left` / `bisect_right` | 직접 짜면 경계에서 틀린다 |
| "그 값이 몇 개인가" | 두 `bisect` 의 차 | 스캔하지 않고 개수가 나온다 |
| "최소의 최대", "최대의 최소" | 파라메트릭 서치 | 답의 범위를 이분한다 |
| 회전된 정렬 배열 | 반쪽 판정 후 이분 | 한쪽은 반드시 정렬돼 있다 |
| 가장 최근 것과 짝 맞추기 | 스택 | 괄호, 되돌리기가 이 꼴 |
| "나보다 큰 첫 값" | 단조 스택 | 각 칸이 한 번 들어가고 많아야 한 번 나온다 |
| 앞뒤로 넣고 빼기 | `deque` | 리스트는 앞이 O(n) |
| 윈도우 안의 최댓값, 최솟값 | 단조 덱 | 될 수 없는 값을 미리 버린다 |

## 헷갈리기 쉬운 점

- **`lo = mid` 로 후보를 남기는 코드는 `mid` 를 올림으로 구합니다.** 내림으로 구하면 `lo` 와 `hi` 가 이웃한 칸일 때 `mid` 가 늘 `lo` 가 되어 `lo = mid` 로 가는 순간 `lo` 가 제자리에 머물므로 무한 루프에 빠집니다.
- **`hi` 의 처음 값이 `len` 이냐 `len - 1` 이냐가 변형을 정합니다.** `hi` 를 `len` 에서 시작하는 변형은 `while lo < hi` 와 짝을 이루고 `len - 1` 에서 시작하는 정확히 찾기는 `while lo <= hi` 와 짝을 이룹니다.
- **`bisect` 는 배열이 정렬돼 있는지 확인하지 않습니다.** 정렬되지 않은 배열에 쓰면 오류를 내지 않은 채 틀린 답을 돌려줍니다.
- **파라메트릭 서치는 단조성이 있어야 쓸 수 있습니다.** 나무 문제라면 "높이를 올리면 얻는 양이 준다"가 성립해야 하며 성립하지 않으면 예와 아니오가 바뀌는 경계 자체가 생기지 않습니다.
- **회전 배열에서는 판정 순서를 지켜야 합니다.** 어느 반쪽이 정렬됐는지를 먼저 보고 찾는 값이 그 범위 안에 있는지는 그다음에 봅니다.
- **괄호 문제는 끝까지 읽은 뒤 스택이 비었는지도 확인해야 합니다.** 닫는 괄호를 만날 때만 검사하면 `"((("` 도 맞는 문자열로 통과합니다.
- **반복문 안에 `while` 이 겹쳐 있다는 것만으로 O(n²) 이 되지는 않습니다.** 각 칸이 한 번 들어가고 많아야 한 번 나온다면 전체는 O(n) 입니다.
- **`deque` 는 가운데 칸을 읽는 일이 느립니다.** 번호로 아무 칸이나 골라 읽어야 하는 코드라면 리스트를 씁니다.
