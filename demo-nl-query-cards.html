자연어 → 타겟 조건 카드 네 장

광고주가 쓴 요청 한 문장을 판정과 조건 두 번으로 나눠 묻고, 쿼리와 답은 코드가 씁니다. 네 단계의 차례, 판정 셋의 혼동표, 코드가 쓴 쿼리와 회원 수, 판정과 reason_code 로 고르는 템플릿을 한 장씩 봅니다. 회원 표본과 정답은 설명용 가상 값이고, LLM 의 답은 한 번 기록한 값입니다.

벽돌색 = LLM 이 쓴 답 (판정, 조건) 파랑 = 코드가 하는 일과 회원 표본 회색 = 명단을 만들지 않는 답과 쓰지 않은 조건 점선 상자 = 사람이 미리 적어 둔 글 (템플릿)

STEPS

요청 한 문장이 판정, 조건, 쿼리, 명단을 지나는 차례

쉽게 말하면 LLM 은 받을 요청인지 정하는 판정과, 문장을 필드와 값으로 옮기는 조건 추출만 합니다. 쿼리와 회원 수, 광고주에게 가는 문장은 코드가 씁니다.

「자동차가 있는 40대 여행 글 독자」는 판정 partial 을 지나 조건 셋이 되고, 표본 163명이 남습니다. 1,400만 명으로 늘리면 1,141,000명입니다.

VERDICT

판정 셋의 혼동표. 줄은 정답, 칸은 LLM 의 답이다

쉽게 말하면 대각선은 맞은 답이고, 대각선 밖은 어느 쪽으로 틀렸는지입니다. 정답보다 덜 받은 답은 만들 수 있던 명단을 막고, 더 받은 답은 막아야 할 요청을 받습니다.

판정과 조건을 한 번에 물은 oneshot 은 25/30, 판정만 물은 verdict 는 24/30 입니다. 틀린 답은 모두 일부 지원을 불가로 본 답이고, 더 받은 답은 0개입니다.

QUERY

조건 JSON 을 코드가 허용 목록으로 확인하고 쿼리를 쓴다

쉽게 말하면 코드는 필드 이름과 비교가 미리 적어 둔 목록에 있을 때만 쿼리를 씁니다. 목록에 없는 이름이나 이상한 값이 오면 쿼리를 쓰지 않고 멈춥니다.

「러닝화 살 사람」은 조건 단계가 더한 구매 조건 하나로 표본 63명이 12명이 되었습니다. 가상으로 만든 지역 값은 쿼리가 되지 않습니다.

REPLY

판정과 reason_code 의 짝마다 정해 둔 템플릿

쉽게 말하면 광고주에게 가는 글은 LLM 이 쓰지 않습니다. 사람이 미리 적어 둔 여섯 문장 가운데 코드가 하나를 고르고, 회원 수 자리만 코드가 채웁니다.

답 30개가 모두 템플릿으로 나갔고 담당자에게 간 답은 0개입니다. 노출 이력의 일부 지원 문장은 판정이 그 짝을 내지 않아 한 번도 쓰이지 않았습니다.

현업에서는 이렇게 씁니다

  • 자연어로 타겟을 만드는 워크플로를 보면 세 가지를 묻습니다. 판정과 조건을 따로 채점하나, 쿼리를 코드가 허용 목록으로 쓰나, 광고주에게 가는 문장은 누가 정했나.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 자연어 → 타겟 조건 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 판정과 조건을 한 번에 받던 자리는 자연어 오디언스 편입니다.
