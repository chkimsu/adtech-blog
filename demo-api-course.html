API 한 건을 직접 만들어 보기

보내고, 받고, 로그가 남기까지. 값을 바꿔 가며 눌러 보면 무엇이 달라지는지 그 자리에서 보입니다.

골라 읽는 법 — 절이 6개인 긴 페이지입니다. 처음부터 다 볼 필요 없습니다.
  • API 한 건이 어떻게 생겼는지만 → 1~2절
  • 로그를 누가 남기는지만 → 3절
  • 앱이 부를 때와 서버가 부를 때의 차이만 → 4절
  • 주소 이름 짓는 법만 → 5절

1. 요청 한 건은 이렇게 생겼습니다

조각은 넷뿐입니다. 무엇을 하려는지(메서드), 무엇에 대해서인지(주소), 곁들이는 정보(헤더), 실어 보내는 내용(본문)입니다. 아래에서 값을 바꾸면 오른쪽 원문이 그 자리에서 바뀝니다.

          그리고 누가 남기느냐가 그 줄에 무엇을 적을 수 있는지를 정합니다.

4. 부르는 쪽이 앱이냐 다른 서버냐

        

          같은 일을 하는데 부르는 쪽이 달라지면 요청도, 인증도, 검사도, 남는 로그도 달라집니다.
          아래 스위치를 바꾸면 위의 1~3절이 통째로 그에 맞게 바뀝니다.
        

        

        

        

          위 표의 사용자 토큰은 앱이 부를 때 흔히 쓰는 인증 방식입니다. 이 페이지의 /v1/events
          주소는 예외로, 자격증명을 아예 받지 않고 앱이 보낸 값을 전부 다시 검사합니다. 2절에서 사용자
          토큰을 골라 401을 받은 것은 이 때문입니다.
