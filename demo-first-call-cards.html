LLM 호출 한 번 카드 네 장

지훈 씨가 노트북의 공개 모델에 보낸 요청 하나를 카드 네 장으로 봅니다. 요청 JSON 의 필드, 프롬프트가 되는 토큰, 응답 JSON 의 필드, thinking 을 켠 답입니다. 캠페인 한 줄은 설명용 가상 값이고, 답과 토큰 수와 시간은 한 번 기록한 값입니다.

벽돌색 = 이번 요청과 답 (사용자 메시지, 답 한 줄) 먹색 = 모델과 서버, 서버가 붙이는 표시 파랑 = 기록에 남은 값 회색 = 기록에 옮기지 않는 응답 필드 점선 상자 = 사람이 미리 적어 둔 글 (시스템 메시지)

REQUEST

이 요청의 맨 위 필드 다섯과 필드마다 하는 일

쉽게 말하면 요청은 JSON 한 덩이입니다. 어느 모델에게, 무엇을, 어떤 방식으로 물을지를 필드 다섯에 나눠 적습니다.

두 요청은 think 하나만 다릅니다. 시스템 메시지와 사용자 메시지는 messages 목록에 차례대로 들어갑니다.

TOKENS

두 메시지가 역할 표시와 함께 프롬프트 하나가 된다

쉽게 말하면 모델은 JSON 이 아니라 메시지를 이은 글 하나를 받습니다. 그 글을 토큰이라는 조각으로 읽고, 몇 조각인지는 서버가 셉니다.

사용자 문장을 자른 조각 경계는 그림일 뿐입니다. 기록에 남은 것은 프롬프트 전체의 토큰 수 78개와 76개뿐입니다.

RESPONSE

응답 JSON 의 필드와 기록 도구가 옮겨 적는 다섯 값

쉽게 말하면 응답에는 답 한 줄과 함께 몇 토큰을 읽고 썼는지, 얼마나 걸렸는지가 담겨 옵니다. 기록 도구는 그 가운데 다섯 값만 적습니다.

thinking 을 끈 답은 프롬프트 78토큰, 출력 6토큰, 1,114ms 입니다. 답 27자가 출력 토큰 6개라 토큰은 글자가 아닙니다.

THINKING

thinking 을 끈 답과 켠 답의 출력 토큰과 시간

쉽게 말하면 thinking 을 켜면 모델이 답 앞에 풀이를 먼저 씁니다. 풀이도 출력 토큰이라 답이 같아도 토큰과 시간이 늡니다.

답은 둘 다 conversion 입니다. 출력 토큰은 6개에서 505개로, 시간은 1.1초에서 32.0초로 늘었습니다.

현업에서는 이렇게 씁니다

  • LLM 을 처음 붙일 때는 답과 함께 토큰 수와 걸린 시간을 기록합니다. 요청 한 건의 값과 기다리는 시간이 거기서 나옵니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 LLM 호출 한 번 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 바로 앞 이야기는 자연어 오디언스 편입니다.
