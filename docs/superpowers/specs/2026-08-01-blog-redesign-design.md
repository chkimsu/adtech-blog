# 애드테크 블로그 전면 개편 설계 (2026-08-01)

초심자용 한국어 애드테크 기술 블로그의 전면 개편 설계 문서.
브레인스토밍 세션에서 사용자와 합의된 결정만 담는다. 구현 계획은 별도 문서(writing-plans 산출물)로.

## 1. 사이트 골격

① **네비게이션 (전 페이지 공통)**: `로고 | Posts · Ecosystem · 데모 · ▸ML 트랙(벽돌 필 강조) | 검색 · 테마`.
'홈'·'소개' 텍스트 메뉴 제거. 로고 클릭 = 표지(index.html).

② **표지(index.html)**: §2의 승인된 시안으로 전면 교체.

③ **좌측 카테고리 레일**: 목록성 페이지(index, home, posts-browse, ml-track)에 공통 적용. sticky.
내용: 카테고리 목록(색 점 + 글 수) → ML 엔지니어 트랙 CTA 블록(벽돌) → 무대 범례(3색 점 + 한 줄 설명).
카테고리는 하드코딩하지 않고 **taxonomy.json 전체(현재 7개 — 승인 목업은 6개로 그렸으나 구현은 동적)** 를 posts.js 글 수와 함께 렌더.
모바일(<768px): 레일이 상단 가로 스크롤 칩 행으로 접힘.
글 상세(post.html)는 기존 목차(TOC) 사이드바 유지 — 레일 미적용.

④ **home.html(글 피드)**: 유지. 표지와 중복되는 생태계 배너(eco-showcase) 제거. '시작하기 · 이어 읽기 · 최신 글 · 시리즈' 유지. 레일 적용.

⑤ **about.html 제거**: 모든 내부 링크(네비·푸터) 제거. 파일은 meta refresh로 표지로 자동 이동. sitemap 생성기에서 제외.

⑥ **읽기시간 전면 제거**:
- `js/posts.js`: 모든 `readTime` 필드 삭제
- 렌더: 카드 메타 · 글 헤더 · 이어읽기(continue-reading) · 검색 결과 등 모든 `min read` 표기 제거 (main.js, browse.js — **주의: main.js에 NUL 바이트, grep은 `-a` 필수**)
- `scripts/compute-read-time.js` 삭제, `scripts/new-post.js`·`scripts/validate-posts.js`에서 readTime 로직 제거
- README의 새 글 추가 절차 갱신

## 2. 표지 (index.html) — '살아있는 지도'

승인된 목업: `docs/superpowers/specs/2026-08-01-cover-mockup-approved.html` (브라우저로 열면 애니메이션 포함 확인 가능)

구성 (위→아래):
1. **네비** (§1-①)
2. **레일 + 히어로 2컬럼**:
   - 히어로: kicker "한국어로 읽는 애드테크" → serif 대형 헤드라인 "0.1초 안에 벌어지는 광고 한 편의 여정" → 데크(pCTR/pCVR이 심장임을 명시) → CTA 2개(30분 입문 가이드 / 글 전체 둘러보기)
3. **살아있는 미니 지도 패널** (표지의 강렬함 담당):
   - **두뇌 층**: Feature Store → **pCTR/pCVR(심장, 맥박 애니메이션)** → Calibration
   - **세로 연결선**: 두뇌 층 ↔ DSP (점이 위아래로 오감)
   - **거래 층**: 사용자 → Publisher·SSP → Ad Exchange → **DSP(강조 테두리)** → 광고주. 와이어 위로 색 점 3개가 계속 흐름 (CSS 애니메이션, JS 불필요)
   - 하단 흐름 칩 5개(▶ 100ms RTB 등) — 클릭 시 ecosystem.html의 해당 흐름으로 이동
   - 패널 전체 클릭 = ecosystem.html
4. **지금 읽을거리**: 최신/추천 3카드 (무대 점 + 카테고리 + 제목 + 발췌. 시간 표기 없음)
5. 푸터 (소개 링크 없음)

기존 표지의 '왜 이 블로그' 콜아웃 · 6개 주제 카드 섹션은 삭제 (레일과 지도가 그 역할을 대체).

## 3. 글 페이지 (post.html) — 무대 시스템 · 코드 블록

### ① 상단 '무대 카드' (기존 worldNote 박스 대체)
세 무대가 시각적으로 보이는 카드:
- 3개 무대 칩: `열린 RTB(벽돌)` / `닫힌 생태계(청동)` / `공통(세이지)` — 해당 무대만 활성, 나머지는 흐리게
- "이 글은 어디 이야기?" 한 줄 (기존 worldNote 텍스트 재사용)
- 신규 필드 `worldPractical` (선택): "네이버·카카오 같은 담장 안에서 일한다면 —" 실무 독해 안내 한 줄
- `world: 'na'`(광고 경매 무관, 현재 3편)인 글은 무대 카드·배지 생략 — 기존 관례 유지

### ② 본문 '무대 전환 배지'  ← 혼동 포인트 2-1의 핵심 해결책
마크다운 헤딩에 마커를 쓰면 렌더 시 색 배지로 치환:
```
## 3. 헤더비딩의 원리 [무대: 열린 RTB]
```
→ 제목 옆에 색 배지 렌더. 지원 값: `열린 RTB` / `닫힌 생태계` / `공통`.
구현: main.js 마크다운 후처리(헤딩 텍스트 패턴 치환). TOC·검색 인덱스에는 마커 텍스트가 새지 않게 처리.
MARKDOWN_GUIDE.md에 문법 추가.

### ③ 코드 블록 개선
- **주석 색**: highlight.js 테마 위에 오버라이드 — 주석을 세이지 그린 이탤릭으로 (라이트 `#5d7052`, 다크는 밝은 세이지). 흐린 회색 금지.
- **언어 라벨 + 복사 버튼**: 코드 블록 우상단.

### ④ '더 깊이' 접이 블록
심화(수식·구현 디테일·논문 참조)는 `<details>` 기반 접이 블록으로. 마크다운 관례:
```
:::deep 더 깊이 — Shapley value 기반 기여 배분
(내용)
:::
```
초심자는 건너뛰고, 실무자는 펼쳐 본다. 구현: 마크다운 전처리 → `<details class="deep-dive"><summary>…</summary>…</details>`.

### ⑤ 데모 임베드 — P2 (후순위)
`:::demo demo-attribution-window.html` → iframe 임베드. 문법과 CSS만 준비하고 적용은 콘텐츠 배치 후.

### ⑥ 글 헤더 메타
날짜 + 카테고리 + 무대 배지. (읽기시간·저자 없음)

## 4. 콘텐츠 표준 — 46편 보강의 기준자

### ① 표준 글 구조
```
도입 장면(일상 예시, 민지 등 기존 등장인물 유지)
→ 한 줄 요약 (blockquote 콜아웃)
→ 무대 카드 (§3-①, posts.js 메타)
→ 본문 h2 섹션들 (아래 ② 규칙)
→ 한눈 정리 표
→ 헷갈리기 쉬운 점
→ 더 깊이 보기 (관련 글·데모 링크)
```
기존 관례(정리 표·헷갈 포인트·더 깊이 보기)는 유지 — 이미 좋은 틀.

### ② 섹션 규칙 (빈약함 해결의 핵심)
- 모든 h2 섹션 = **요약 한 줄(굵게) + 상세 2~4문단**. 한두 줄로 끝나는 섹션 금지.
- 상세의 전개 순서: 비유/그림 → 구체 숫자 예시 → 왜 그런가 → 실무에선 어떤가.
- 톤: "요약집"이 아니라 "읽는 글". 문장은 짧게, 설명은 충분히.

### ③ 가데이터 규칙
- 글마다 **최소 1개의 작은 가상 데이터셋(5~10행 표)** 을 보여주고, 그 숫자로 개념을 직접 계산해 보인다.
  (예: 어트리뷰션 — 터치포인트 로그 6행 → 4가지 규칙별 성적표가 어떻게 갈리는지 계산)
- 등장인물·시나리오는 기존 세계관(민지 등) 재사용. 난수는 시드 고정 컨셉으로 서술.

### ④ 코드 규칙
- 코드를 넣을 수 있는 글엔 **파이썬 예제 20~60줄**: 가데이터 생성 포함 self-contained, 복붙 실행 가능.
- **모든 코드에 상세 주석 의무**: 블록 첫머리에 "무엇을 하는 코드인지", 주요 줄마다 무엇+왜, 마지막에 `# 출력:` 예시.
- 주석이 §3-③ 덕에 뚜렷한 색으로 보인다.

### ⑤ 분량 가이드
얇은 글(현 3~9KB)은 **15KB+ 수준으로 재작성**. (현재 잘 된 글들이 20~30KB.)
분량 자체가 목표가 아니라 ②·③·④를 채우면 자연히 도달하는 수준.

### ⑥ 시범 배치 (기준 확정 절차)
1. **attribution-basics** (사용자 지목 최악 케이스) + **pctr-prediction** + **header-bidding** 3편을 새 표준으로 재작성
2. 사용자 승인 → 표준 확정
3. 나머지 43편을 배치(묶음)로 진행. 우선순위: 분량 하위 순 + ML 트랙 소속 글 우선.

### 참고 — attribution-basics 재작성 아웃라인 (기준 예시)
- 도입: 민지의 2주 터치포인트 타임라인 (표)
- 왜 어려운가: 여정 로그가 실제로 어떻게 생겼나 (가데이터 6행) + 기기·채널 조각남 문제 상세
- 규칙들: 라스트클릭/퍼스트/선형/시간감쇠/U자형 각각 상세 문단 + 같은 가데이터에 5규칙 적용한 성적표 계산 표 + **파이썬 코드**(규칙별 크레딧 계산 함수, 상세 주석)
- 윈도우: 7일→1일로 바꾸면 위 성적표가 어떻게 변하는지 재계산 + 데모 링크
- 누가 재나: MMP·픽셀 상세 + `[무대: 닫힌 생태계]` 섹션 — 네이버·카카오는 자기 로그로 어떻게 잇는가
- 증분 ≠ 어트리뷰션: 미니 시뮬레이션 코드 (어차피 살 사람 예시)
- 더 깊이(접이): 데이터 주도 어트리뷰션(Shapley) 
- 정리 표 · 헷갈 포인트 · 더 깊이 보기

## 5. 생태계(ecosystem.html) 2층 개편

① **지도 재구성 — 2층 구조** (표지 미니 지도와 같은 문법):
- **두뇌 층 (상단, 확대)**: 로그 수집 → Feature Store → 학습(Training) → Model Serving → **pCTR/pCVR (심장 — 가장 크게, 맥박)** → Calibration → 모니터링 (7~8개 모듈, 기존 4개에서 확대)
- **거래 층 (하단)**: 사용자 → Publisher·SSP·Header Bidding → Ad Exchange·Auction → DSP·DCO·DMP/CDP → 광고주·Brand + 측정(Log Pipeline·MMP)·User/Privacy 모듈 — 기존 지도 재배치
- 두 층은 **DSP ↔ pCTR 세로 연결선**으로 이어짐 (질문—답 왕복 애니메이션)

② **새 대표 흐름**: ▶ **"모델러의 눈으로 보는 0.1초"** — 입찰 요청 1건이 들어왔을 때 두뇌 층의 일:
피처 조회(수 ms) → 모델 추론 → Calibration → 입찰가 계산(가치×pCTR×pCVR) → 응답.
기존 5개 흐름(100ms RTB·모델 학습·어트리뷰션·HB·타겟팅) 유지, 새 흐름이 **첫번째·기본 선택**.

③ **ML 모듈 클릭**: 정의 + 관련 글(ML 트랙 연결) + 데모 — 기존 인터랙션 패턴 유지. 신규 모듈(로그 수집·학습·모니터링)은 신규 글 로드맵과 연결.

④ **ecosystem-easy · ecosystem-terms**: 유지. 새 모듈 반영하는 가벼운 업데이트만.

⑤ **히어로 문구 중복 해소**: 표지가 "0.1초 안에 벌어지는 광고 한 편의 여정"을 가져갔으므로, 생태계 페이지 히어로는 지도 조작에 초점을 둔 문구로 조정 (예: "한 장 지도 — 흐름을 직접 재생하며 따라가기").

## 6. ML 엔지니어 트랙 (ml-track.html) + 신규 글 로드맵

### ① ml-track.html 신설 — "pCTR/pCVR 실무 커리큘럼"
- 3단계 배치, 단계마다 "이 단계를 마치면 알게 되는 것" 명시:
  - **1단계 입문**: pctr-prediction → ecpm-ranking → calibration → pCVR-modeling → deep-ctr-models
  - **2단계 실무**: ad-log-pipeline → feature-store-serving → model-serving-architecture → negative-sampling-bias → online-learning-delayed-feedback → position-bias-ultr → multi-task-learning → two-tower-retrieval
  - **3단계 심화**: 신규 12편이 채움 (아래 ②) + exploration-exploitation·밴딧 트랙 연결
- 읽음 체크: 기존 reading-state.js(localStorage) 재활용해 카드에 읽음 표시
- 진입점: 네비 벽돌 필 · 레일 CTA 블록 · 표지
- 일반 독자에게도 "커리큘럼 지도"로 읽히게 — 단계 설명은 쉬운 말로

### ② 신규 글 12편 로드맵
콘텐츠 표준(§4) 적용 + 실무 디테일은 닫힌 생태계(네이버·카카오) 관점 명시.

| 묶음 | 글 | 요지 |
|---|---|---|
| 피처·데이터 | 1. CTR 피처 엔지니어링 실전 | ID 임베딩·해싱 트릭·시퀀스 피처 — 무엇을 모델에 넣나 |
| 피처·데이터 | 2. 학습 데이터 만들기 | 노출·클릭 로그 → 학습셋: 라벨 정의, 다운샘플링과 보정 |
| 피처·데이터 | 3. 학습-서빙 스큐 | 오프라인 피처와 온라인 피처가 어긋나면 생기는 일 |
| 지표·실험 | 4. 오프라인 vs 온라인 지표 | AUC 올랐는데 매출 그대로인 이유 — LogLoss·COPC |
| 지표·실험 | 5. 모델 모니터링 | PSI·피처 드리프트·예측 분포 알람 |
| 지표·실험 | 6. 모델 온라인 A/B 설계 | 트래픽 스플릿·가드레일 지표·최소 실험 기간 |
| 랭킹 구조 | 7. 랭킹 캐스케이드 | retrieval → pre-rank → rank → re-rank, 왜 층층인가 |
| 랭킹 구조 | 8. Cold Start | 신규 광고·신규 유저의 pCTR — 탐색과 사전확률 |
| 랭킹 구조 | 9. 대규모 임베딩 테이블 운영 | 수억 ID 임베딩을 학습·서빙하는 법 |
| pCVR 심화 | 10. ESMM 계열 | 클릭→전환을 함께 배우기 — SSB·희소성 문제 |
| pCVR 심화 | 11. Delayed Feedback 실전 | 전환은 며칠 늦게 온다 — 기존 글의 실전 후속편 |
| pCVR 심화 | 12. 전환 정의와 라벨 지연 | 어디까지가 '전환'인가, 라벨은 언제 확정하나 |
