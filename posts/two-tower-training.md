지훈 씨는 후보 추리기 모델을 다시 학습하는 일을 처음 맡았습니다. 받은 것은 지난 30일 치 클릭 로그와 학습 스크립트 하나였습니다. 스크립트 어디에도 「안 누른 광고」를 따로 모으는 코드가 없었습니다. 점수를 매기는 줄 바로 다음에는 점수표 전체에서 무언가를 빼는 줄이 있었습니다.

평가 칸에는 늘 보던 값 대신 「다음 날 클릭이 상위 500 안에 든 비율」 하나만 적혀 있었습니다. 노출마다 클릭할지를 맞히는 모델만 다뤄 본 지훈 씨는, 이 모델이 무엇을 맞히는지부터 헷갈렸습니다.

**클릭 로그 한 줄이 어떻게 두 타워의 학습이 되고, 무엇을 보정해서 무엇으로 평가하나요?**

답은 배치 하나 안에 있습니다. 클릭 한 건이 정답 짝 한 줄이고, 같은 배치에 든 다른 회원의 광고가 음성(negative)입니다. 점수표의 줄마다 자기 광고 칸을 고르게 하는 것이 손실이고, 인기 광고 쪽 쏠림을 푸는 보정 둘을 꼭 넣습니다. 이것을 알면 재현율이 떨어졌을 때 데이터, 음성, 보정, 판 번호 가운데 어디부터 볼지가 정해집니다.

> **한 줄 요약:** 클릭 한 건이 정답 짝 한 줄이고, 음성은 같은 배치에 든 다른 회원의 광고입니다. 배치 B줄로 B×B 점수표를 만들어 줄마다 소프트맥스로 대각선을 고르게 하고, 인기 광고 보정(logQ)과 같은 광고 칸 지우기를 꼭 넣습니다. 평가는 다음 날 클릭이 상위 500 안에 드는 비율(Recall@500)입니다. 배포는 광고 벡터를 미리 색인에 넣고 회원 타워를 요청마다 돌립니다.

> **골라 읽는 법** — 절이 11개인 글입니다. 1절 앞에 이 글의 예시를 푼 표가 먼저 있습니다.
>
> - 두 타워의 모양과 학습 데이터 → 1~2절
> - 점수표와 손실, 온도 → 3~4절
> - 꼭 넣는 보정 둘과 무작위 섞기 → 5~7절
> - 평가와 배포 → 8~9절
> - pCTR 모델과 다른 점, 정답이나 음성을 바꾸는 갈래 → 10~11절

이 글의 회원, 광고, 숫자는 전부 설명을 위한 가상 값입니다. 그림 속 색은 넷입니다. 파랑은 회원 쪽(회원 정보, 회원 타워, 회원 벡터)이고 벽돌색은 광고 쪽입니다. 먹색은 점수와 손실, 회색은 무작위로 더한 광고입니다. 점선 상자는 광고 벡터를 넣어 둔 목록입니다. 학습 방법은 두 무대가 같아서, 글 전체를 공통으로 읽으면 됩니다.

회원 쪽 신경망을 회원 타워, 광고 쪽 신경망을 광고 타워라고 부릅니다. 회원 타워는 나이대, 기기, 시간대 같은 속성과 최근 검색어, 최근 클릭한 광고 같은 행동을 받습니다. 광고 타워는 광고 번호, 카테고리, 광고주, 소재 문구를 받습니다. 둘 다 끝에서 숫자 64개를 내고, 이 숫자 묶음을 벡터라고 부릅니다.

내적은 두 벡터의 같은 자리 숫자끼리 곱해 모두 더한 값입니다. 두 벡터의 길이를 1로 맞춰 두면 내적이 −1과 1 사이에 들어오고, 이 값을 코사인이라고도 부릅니다. 회원 A 와 러닝화 광고의 내적이 0.81 이면 둘이 거의 같은 쪽을 가리킨다는 뜻입니다.

두 타워는 내적 전까지 서로의 정보를 보지 않습니다. 그래서 광고 벡터 100만 개를 회원과 상관없이 미리 계산해 둘 수 있습니다. 요청이 오면 회원 타워만 한 번 돌리고, 미리 만든 광고 벡터 가운데 가까운 것을 찾으면 됩니다.

대신 「이 회원이 이 광고주 광고를 몇 번 눌렀나」처럼 회원과 광고를 섞은 정보는 넣을 수 없습니다. 이런 값은 회원과 광고가 둘 다 정해져야 계산되는데, 광고 벡터는 회원을 모른 채 만들기 때문입니다. 그 정보는 뒤에 오는 pCTR 모델이 씁니다.

학습이 하는 일은 하나입니다. (회원, 클릭한 광고)의 점수는 올리고 (회원, 다른 광고)의 점수는 내리도록 두 타워를 함께 고칩니다. 그러려면 먼저 「클릭한 광고」의 짝이 있어야 하고, 그것이 다음 절의 학습 데이터입니다.

회원 A 가 저녁 8시 14분 2초에 앱을 열면 광고 요청이 갑니다. 1초 뒤 러닝화 광고가 화면에 뜨고, 6초 뒤 회원 A 가 그 광고를 누릅니다. 이 클릭 한 건이 학습 데이터 한 줄이 됩니다. 줄에는 요청 때의 회원 정보와 클릭한 광고의 정보가 짝으로 들어가고, 이 짝을 양성(positive) 또는 정답 짝이라고 부릅니다.

회원 정보는 광고를 요청한 시각의 값을 씁니다. 클릭 1초 뒤에 「최근 클릭 수」가 하나 늘어나는데, 그 값을 쓰면 이 클릭이 이미 들어간 정보로 학습하게 됩니다. 모델은 그 칸만 보고 정답을 맞히는 법을 배웁니다. 서빙 때는 클릭이 아직 일어나지 않아 그 값이 없으니, 학습 때 좋던 점수가 실제로는 나오지 않습니다.

음성, 곧 「이 회원에게는 아닌 광고」는 로그에 따로 남기지 않습니다. 학습할 때 같은 배치에 든 다른 줄의 광고를 음성으로 씁니다. 그래서 데이터 준비는 정답 짝을 모으는 데서 끝납니다. 노출됐는데 안 누른 광고를 음성으로 모으면 어떻게 되는지는 11절에서 봅니다.

학습 기간과 평가 기간은 시간순으로 나눠, 예를 들어 30일 치 클릭으로 학습하고 바로 다음 날 클릭으로 평가합니다. 배치를 만들 때는 회원과 시각을 섞습니다. 같은 회원의 클릭 여러 줄이 한 배치에 들면, 그 회원이 실제로 누른 다른 광고가 음성 칸에 들어가기 때문입니다.

## 3. 배치 한 번: 줄마다 자기 광고 칸을 고릅니다

회원 타워가 회원 벡터 넷을, 광고 타워가 광고 벡터 넷을 냅니다. 둘을 서로 곱하면 회원 넷과 광고 넷의 점수표가 되고, 줄이 회원이고 열이 광고입니다. 회원 A 의 줄에서는 러닝화 칸이 정답이고 나머지 세 칸이 음성입니다. 음성은 다른 회원 B, C, D 가 누른 광고입니다. 배치 안의 남의 정답을 음성으로 쓰는 이 방법을 in-batch negative 라고 부릅니다.

줄마다 점수를 온도 τ 로 나누고 소프트맥스를 겁니다. 소프트맥스는 네 점수를 합이 1인 네 확률로 바꾸는 계산입니다. 그림 아래 칸이 회원 A 줄을 손으로 계산한 것입니다. 점수를 0.1 로 나누면 칸 사이 차이가 열 배로 벌어지고, 소프트맥스를 거치면 러닝화 칸 확률이 0.989 가 됩니다.

손실은 정답 칸 확률에 −log 를 씌운 값입니다. 회원 A 줄의 손실은 −log 0.989 = 0.011 이고, 정답 칸 확률이 1에 가까울수록 0에 가까워집니다. 네 줄의 손실을 평균한 것이 배치 하나의 손실입니다. 이 계산 전체를 소프트맥스 교차 엔트로피(softmax cross-entropy)라고 부릅니다.

처음에는 두 타워가 아무것도 몰라서 τ = 0.1 에서 손실이 1.390 입니다. 네 칸을 똑같이 찍을 때 값인 log 4 = 1.386 과 거의 같습니다. 역전파 한 번이 두 타워를 같이 고쳐, 정답 칸 점수를 올리고 음성 칸 점수를 내립니다. 학습 뒤에는 정답 칸 확률이 0.979~0.998 로 올라 손실이 0.009 가 됩니다. 아래 코드가 이 숫자를 그대로 냅니다.

```python
import math

# 설명을 위한 가상 점수표. 줄은 회원 A~D, 열은 러닝화, 캠핑 의자, 커피 머신, 요가 매트.
# 칸의 값은 길이를 1로 맞춘 두 벡터의 내적이고, 대각선이 그 회원이 클릭한 광고다.
START = [[0.08, 0.11, -0.03, 0.05], [0.02, 0.06, 0.09, -0.04],
         [-0.05, 0.10, 0.04, 0.07], [0.12, -0.02, 0.01, 0.03]]
AFTER = [[0.81, 0.12, -0.10, 0.35], [0.15, 0.77, 0.05, -0.08],
         [-0.12, 0.09, 0.74, 0.02], [0.40, -0.06, 0.03, 0.79]]


def softmax(xs):
    m = max(xs)                        # 큰 값을 빼고 지수를 취해야 넘치지 않는다
    e = [math.exp(x - m) for x in xs]
    s = sum(e)
    return [v / s for v in e]


def batch_loss(table, tau):
    """줄마다 점수를 tau 로 나눠 소프트맥스 → 정답 칸 확률에 -log → 네 줄 평균."""
    losses = []
    for i, row in enumerate(table):
        p = softmax([c / tau for c in row])
        losses.append(-math.log(p[i]))
    return sum(losses) / len(losses)


for name, table in [('처음', START), ('학습 뒤', AFTER)]:
    print(f'{name:4}  평균 손실 {batch_loss(table, 0.1):.3f}')
print(f'네 칸을 똑같이 찍으면  log 4 = {math.log(4):.3f}')

p = softmax([c / 0.1 for c in AFTER[0]])    # 회원 A 줄, 학습 뒤
print('회원 A 줄 확률', ' '.join(f'{v:.3f}' for v in p), f' 손실 {-math.log(p[0]):.3f}')

# 출력:
# 처음    평균 손실 1.390
# 학습 뒤  평균 손실 0.009
# 네 칸을 똑같이 찍으면  log 4 = 1.386
# 회원 A 줄 확률 0.989 0.001 0.000 0.010  손실 0.011
```

## 4. 온도 τ: 코사인의 좁은 차이를 키웁니다

**길이 1 벡터의 내적은 −1과 1 사이라 칸 사이 차이가 작습니다. 온도 τ 로 나눠 차이를 키워야 소프트맥스 확률이 벌어집니다.**

3절 그림에서 τ = 1 을 눌러 보면 이 차이가 보입니다. 학습 뒤 점수표를 그대로 두고 온도만 1로 바꾸면 정답 칸 확률이 0.389~0.411 에 머뭅니다. 네 줄 모두 대각선이 가장 큰데도 평균 손실이 0.915 로 남습니다. 순서는 맞혔는데 손실은 0.9 아래로 잘 내려가지 않는 것입니다.

배치가 커지면 더 심해집니다. 4,096줄 배치에서 정답 칸 내적이 1이고 나머지 4,095칸이 모두 −1 인, 가장 잘 배운 경우를 생각해 봅니다. τ = 1 이면 정답 칸 확률이 0.0018 을 넘지 못합니다. 남은 칸이 너무 많아서 작은 차이로는 정답 하나가 확률을 다 가져올 수 없기 때문입니다. τ = 0.1 이면 같은 점수표에서 0.99999 까지 갑니다.

τ 가 작을수록 점수가 높은 음성, 곧 정답과 헷갈리는 광고에 손실이 몰립니다. 너무 작으면 그 몇 칸에 끌려다녀 학습이 흔들립니다. 정해진 값이 없어서 검증 재현율을 보고 고르고, 이 글은 0.1 을 씁니다. 온도를 바꿔도 칸의 순서는 그대로이고, 확률이 얼마나 벌어지느냐만 바뀝니다.

```python
import math

AFTER = [[0.81, 0.12, -0.10, 0.35], [0.15, 0.77, 0.05, -0.08],
         [-0.12, 0.09, 0.74, 0.02], [0.40, -0.06, 0.03, 0.79]]


def softmax(xs):
    m = max(xs)
    e = [math.exp(x - m) for x in xs]
    s = sum(e)
    return [v / s for v in e]


# 같은 학습 뒤 점수표를 온도만 바꿔 다시 잰다. 순서(대각선이 가장 큼)는 셋 다 같다.
for tau in (1, 0.1, 0.05):
    ps = [softmax([c / tau for c in row])[i] for i, row in enumerate(AFTER)]
    loss = sum(-math.log(p) for p in ps) / 4
    print(f'tau {tau:<4}  정답 칸 확률 {min(ps):.3f}~{max(ps):.3f}  평균 손실 {loss:.3f}')

# 배치가 4,096줄일 때 가장 잘 배운 경우: 정답 칸 내적 1, 나머지 4,095칸이 모두 -1
B = 4096
for tau in (1, 0.1):
    best = 1 / (1 + (B - 1) * math.exp((-1 - 1) / tau))
    print(f'B {B}, tau {tau:<4}  정답 칸 확률의 위쪽 끝 {best:.5f}')

# 출력:
# tau 1     정답 칸 확률 0.389~0.411  평균 손실 0.915
# tau 0.1   정답 칸 확률 0.979~0.998  평균 손실 0.009
# tau 0.05  정답 칸 확률 1.000~1.000  평균 손실 0.000
# B 4096, tau 1     정답 칸 확률의 위쪽 끝 0.00180
# B 4096, tau 0.1   정답 칸 확률의 위쪽 끝 0.99999
```

## 5. 인기 광고 보정 (logQ): 자주 오는 광고는 작게 셉니다

**인기 광고는 배치에 자주 들어와 음성 자리에도 자주 앉습니다. 학습 때 점수표 각 칸에서 그 열 광고의 log q 를 빼서 이 쏠림을 되돌립니다.**

광고마다 클릭 점유율 q 가 다릅니다. 러닝화가 전체 클릭의 2% 이고 요가 매트가 0.1% 라고 해 봅니다. 4,096줄 배치에 러닝화는 평균 81.9번, 요가 매트는 4.1번 들어옵니다. 배치에 들어온 만큼 다른 회원 줄의 음성 칸에도 앉으니, 러닝화는 「이 회원에게는 아니다」라는 신호를 스무 배 더 받습니다.

보정 없이 끝까지 배우면 점수가 광고마다 −log q 만큼 밀립니다. 요가 매트는 +6.9, 러닝화는 +3.9 라 드문 광고가 3.0 더 올라갑니다. 인기 광고가 상대적으로 깎이는 것입니다. 후보 500개를 뽑을 때 실제로 잘 맞는 인기 광고가 빠질 수 있습니다.

그래서 학습 때 점수표 각 칸에서 그 열 광고의 log q 를 뺍니다. log q 는 음수라 빼면 더하는 셈이고, 드문 광고일수록 크게 더합니다. 배치에 가끔 오는 광고는 한 번 왔을 때 오지 않은 많은 광고의 몫까지 세야 합니다. 그래야 배치 4,096줄로 한 계산이 광고 100만 개 전체로 한 계산에 가까워집니다. 밀리는 몫을 보정값이 떠안으니 모델 점수에는 남지 않습니다.

서빙 때는 빼지 않고, 회원 벡터와 광고 벡터의 내적을 그대로 씁니다. q 는 광고별 클릭 점유율이면 충분한데, 배치 크기를 곱해도 한 줄의 모든 칸에 같은 값이 더해져 결과가 같기 때문입니다. 클릭이 계속 들어오는 학습에서는 점유율을 흐르는 데이터에서 세는 방법을 씁니다(Yi 외, 2019). 보정 전후로 광고 여덟 개의 순위가 바뀌는 계산은 [Two-Tower Retrieval](post.html?id=two-tower-retrieval)의 학습 절에 있습니다.

## 6. 같은 광고 칸 지우기: 정답을 음성으로 세지 않습니다

**같은 광고를 두 회원이 누르면, 한 회원 줄에 정답인 광고를 음성으로 세는 칸이 생깁니다. 그 칸은 소프트맥스에서 뺍니다.**

이번에는 회원 D 도 러닝화를 눌렀다고 해 봅니다. 회원 A 줄의 넷째 열은 D 가 누른 러닝화입니다. A 의 정답도 러닝화이니, 같은 광고를 한 줄에서 정답으로 한 번, 음성으로 한 번 세게 됩니다. 모델은 러닝화 점수를 올리라는 신호와 내리라는 신호를 동시에 받습니다.

그 칸의 점수를 −∞ 로 두면 소프트맥스에서 확률이 0 이 되어 계산에서 빠집니다. 대각선의 정답 칸은 그대로 둡니다. 같은 광고인지는 광고 번호로 판단하고, 번호가 같으면 지우고 다르면 둡니다.

인기 광고일수록 자주 일어납니다. 4,096줄 배치에 러닝화가 82번 들어오면 러닝화 줄마다 이런 칸이 81개씩 생깁니다. 지우지 않으면 5절에서 본 인기 광고 깎임 위에 깎임이 한 번 더 겹칩니다. 그래서 logQ 와 같은 광고 칸 지우기는 늘 같이 넣습니다.

## 7. 무작위 광고 섞기: 배치에 안 드는 광고도 음성으로 봅니다

**배치 안 음성은 최근에 클릭된 광고뿐입니다. 전체 광고에서 무작위로 뽑은 광고를 열로 더 붙여, 모든 줄이 같이 음성으로 씁니다.**

클릭이 없던 새 광고나 드문 광고는 배치에 거의 들어오지 않습니다. 음성으로 나온 적이 없으니 「이 회원에게는 아니다」를 배운 적도 없습니다. 서빙 때는 광고 100만 개를 전부 놓고 찾으니, 그런 광고가 상관없는 회원에게 높은 점수를 받을 수 있습니다.

그래서 전체 100만 개에서 무작위로 뽑은 광고를 점수표의 열로 더 붙입니다. 이 열은 어느 회원의 정답도 아니고, 모든 줄의 음성입니다. 4,096줄 배치에 무작위 1,024개를 붙이면 점수표가 4,096 × 5,120 이 됩니다. 배치 안 음성과 무작위 음성을 섞는다고 해서 mixed negative sampling 이라고 부릅니다. 앱 추천에서 쓴 방법입니다(Yang 외, 2020).

이 방법은 5절과 6절의 둘과 달리 꼭 넣는 것이 아니라 자주 더하는 것입니다. 클릭이 쌓이지 않은 광고가 많을수록, 이 열이 없으면 그 광고들이 음성으로 나올 기회가 없습니다. 무작위 열은 배치 크기와 따로 정할 수 있어서, 메모리가 남는 만큼 늘립니다.

:::deep PyTorch 로 옮기면 — 학습 반복과 평가
1~8절의 계산을 PyTorch 로 옮긴 것입니다. 광고 200개와 회원 정보를 가짜로 만들어 바로 돌아가게 했고, 인기는 순위의 역수로 쏠리게 두었습니다. 숫자는 이 가짜 데이터에서 나온 값이라 본문의 예시 값과 다릅니다. 처음 손실이 log 256 = 5.55 보다 큰 것은 인기 보정이 칸마다 다른 값을 더한 뒤이기 때문입니다.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
N_ADS, D_IN, D = 200, 16, 32                     # 광고 수, 정보 칸 수, 벡터 길이 (가상 값)
ad_x = torch.randn(N_ADS, D_IN)                  # 광고 정보
pop = 1 / torch.arange(1, N_ADS + 1).float()     # 인기를 순위의 역수로 쏠리게 둔다
pop = pop / pop.sum()                            # 광고별 클릭 점유율 q
W = torch.randn(D_IN, D_IN) / 4                  # 회원 정보와 광고 정보를 잇는 숨은 관계


def clicks(n):
    ad = torch.multinomial(pop, n, replacement=True)        # 누른 광고
    member_x = ad_x[ad] @ W + 1.0 * torch.randn(n, D_IN)     # 그 광고를 누를 법한 회원 정보
    return member_x, ad


class Tower(nn.Module):
    def __init__(self):
        super().__init__()
        self.mlp = nn.Sequential(nn.Linear(D_IN, 64), nn.ReLU(), nn.Linear(64, D))

    def forward(self, x):
        return F.normalize(self.mlp(x), dim=-1)              # 길이를 1로 맞춘다


member_tower, ad_tower = Tower(), Tower()
opt = torch.optim.Adam([*member_tower.parameters(), *ad_tower.parameters()], lr=3e-3)
tau, log_q, B = 0.1, pop.log(), 256

for step in range(301):
    member_x, ad = clicks(B)                                         # 클릭 B건 = 정답 짝 B줄
    logits = member_tower(member_x) @ ad_tower(ad_x[ad]).T / tau     # (B, B) 점수표
    logits = logits - log_q[ad][None, :]                             # 인기 광고 보정. 학습 때만
    same = (ad[:, None] == ad[None, :]) & ~torch.eye(B, dtype=torch.bool)
    logits = logits.masked_fill(same, float('-inf'))                 # 같은 광고 칸 지우기
    loss = F.cross_entropy(logits, torch.arange(B))                  # 줄마다 정답은 대각선
    opt.zero_grad()
    loss.backward()                                                  # 두 타워를 같이 고친다
    opt.step()
    if step % 100 == 0:
        print(f'step {step:3d}  손실 {loss.item():.3f}')

with torch.no_grad():                            # 학습에 안 쓴 클릭 2,000건으로 평가
    member_x, ad = clicks(2000)
    top10 = (member_tower(member_x) @ ad_tower(ad_x).T).topk(10).indices   # 보정 없이 내적 그대로
    recall = (top10 == ad[:, None]).any(1).float().mean()
    base = torch.isin(ad, pop.topk(10).indices).float().mean()             # 클릭 많은 순 10개
print(f'Recall@10  two-tower {recall:.3f}  클릭 많은 순 {base:.3f}')

# 출력 (torch 2.7, CPU):
# step   0  손실 8.245
# step 100  손실 1.950
# step 200  손실 1.847
# step 300  손실 1.692
# Recall@10  two-tower 0.932  클릭 많은 순 0.496
```

라이브러리를 쓰면 같은 일을 인자로 켭니다. TensorFlow Recommenders 에서는 `tfrs.tasks.Retrieval` 이 이 일을 합니다. 같은 광고 칸은 `remove_accidental_hits=True` 로 지웁니다. 인기 보정은 호출할 때 `candidate_sampling_probability` 를 넘겨 넣습니다.
:::

다음 날 회원 A 가 러닝화를 누른 기록이 있다고 해 봅니다. 그날 회원 A 의 정보로 회원 벡터를 만들고, 광고 벡터 100만 개와 내적을 구해 상위 500개를 뽑습니다. 러닝화가 그 안에 있으면 1, 없으면 0 입니다. 다음 날 클릭 10,000건에 이것을 하고 평균을 내면 Recall@500 이고, 6,200건이 들었다면 0.62 입니다.

기준선도 같이 잽니다. 가장 단순한 기준선은 클릭 많은 순 500개를 모든 회원에게 똑같이 주는 것입니다. 이 기준선이 0.31 이라면 모델은 회원마다 다른 500개를 골라 두 배를 맞힌 셈입니다. 모델이 기준선을 넘지 못하면 두 타워를 쓸 이유가 없습니다. 0.62 와 0.31 은 설명을 위한 예시 값입니다.

pCTR 모델처럼 AUC 를 보지 않는 데는 까닭이 있습니다. 무작위로 고른 광고는 대부분 회원과 상관이 없어서 너무 쉽게 구분됩니다. 그래서 AUC 는 높게 나오고, 모델 사이 차이는 잘 드러나지 않습니다. 후보 모델이 하는 일은 100만 개 중 위쪽 500개에 정답을 올리는 것이고, Recall@500 은 그 일을 그대로 잽니다.

오프라인 재현율에도 한계가 있습니다. 평가에 쓰는 클릭은 지금 서비스 중인 시스템이 보여 준 광고에서만 나옵니다. 새 모델이 찾은 좋은 광고도 보여 준 적이 없으면 클릭이 없어서 놓친 것으로 셉니다. 그래서 마지막 판단은 온라인 실험으로 합니다.

광고 벡터 100만 개는 숫자 6,400만 개입니다. 숫자 하나가 4바이트면 256MB 이고, 이 벡터를 근사 검색 색인에 넣습니다. 근사 검색 색인은 100만 개를 하나씩 다 비교하지 않고 가까운 것을 빠르게 찾는 목록입니다. HNSW 나 IVF 같은 방식이 있고, 상위 500개를 몇 ms 안에 찾습니다. 방식끼리의 비교는 [Two-Tower Retrieval](post.html?id=two-tower-retrieval)에 있습니다.

요청이 오면 회원 타워가 그 순간의 회원 정보로 회원 벡터 하나를 만듭니다. 그 벡터로 색인에서 가까운 광고 500개를 꺼내 pCTR 모델로 넘깁니다. 이때 점수는 보정 없는 내적 그대로입니다. 5절의 log q 는 학습 손실에만 들어갑니다.

두 타워는 같은 판이어야 합니다. 13판 회원 벡터로 12판 광고 색인을 찾으면, 두 벡터가 서로 다른 학습에서 나와 내적에 뜻이 없습니다. 다시 학습하면 새 광고 타워로 색인을 다시 만들고, 색인이 준비된 뒤 회원 타워를 같은 판으로 바꿉니다.

새 광고는 다시 학습하지 않고, 광고 타워에 넣어 만든 벡터를 색인에 더하면 됩니다. 다만 광고 번호에 붙은 숫자는 클릭이 쌓여야 배워집니다. 막 들어온 광고는 이 숫자가 비어 있어서, 카테고리와 소재 문구 같은 내용 정보가 점수를 받칩니다.

## 10. pCTR 모델 학습과 다른 점

**pCTR 모델은 노출 한 건마다 클릭 확률을 맞힙니다. Two-tower 는 배치 안 광고들 가운데 클릭한 광고를 고릅니다. 아래 차이는 모두 여기서 나옵니다.**

| 무엇 | pCTR 랭킹 모델 | Two-tower 후보 모델 |
|---|---|---|
| 학습 한 줄 | 노출 1건. 클릭했으면 1, 아니면 0 | 클릭 1건. (회원, 클릭한 광고) 짝 |
| 음성 | 노출됐는데 안 누른 것 | 같은 배치의 다른 회원 광고, 무작위 광고 |
| 손실 | 줄마다 이진 교차 엔트로피 | 줄마다 B개 가운데 정답 고르기 (소프트맥스) |
| 출력 | 클릭 확률. 입찰가에 곱하므로 값 자체가 맞아야 합니다 | 점수. 순서만 맞으면 됩니다 |
| 회원과 광고를 섞은 정보 | 넣을 수 있습니다 | 넣을 수 없습니다. 마지막 내적에서만 만납니다 |
| 평가 | AUC, LogLoss | Recall@K |
| 요청 한 건에서 | 후보 수백 개를 하나씩 계산합니다 | 회원 타워 한 번과 근사 검색 한 번 |

가장 큰 차이는 출력의 쓰임입니다. pCTR 은 입찰가와 곱해 경매 순서를 정하므로, 2% 라고 내면 실제로 100번에 2번 눌려야 합니다. two-tower 점수는 후보 500개를 고르는 데만 쓰고 바로 버려지므로 순서만 맞으면 됩니다. 그래서 two-tower 점수에는 확률 보정이 필요 없습니다.

음성을 고르는 기준도 다릅니다. pCTR 모델에게는 「노출됐는데 안 누른 광고」가 좋은 음성입니다. 이미 앞 단계를 통과한 광고 사이에서 순서를 정하는 것이 그 모델의 일이기 때문입니다. two-tower 는 100만 개 전부에서 고르니, 대부분이 상관없는 광고라는 것부터 배워야 합니다. 이 차이가 다음 절 첫 갈래의 출발점입니다.

## 11. 같은 자리에 다른 것을 넣는 갈래

**흐름은 1절부터 9절까지 그대로입니다. 바뀌는 것은 정답, 음성, 손실 가운데 한 자리뿐입니다.**

| 바꾸는 자리 | 무엇으로 | 알아 둘 것 |
|---|---|---|
| 정답 | 클릭 대신 전환 | 짝 수가 크게 줄어듭니다. 학습 순서와 보정은 같습니다 |
| 음성 | 헷갈리는 음성 더하기 | 노출 후 안 누른 것만 쓰면 재현율이 떨어집니다. 아래 두 문단에서 봅니다 |
| 손실 | 소프트맥스 대신 triplet | 정답 점수가 음성 점수보다 정한 간격 이상 높게 만듭니다 |

헷갈리는 음성(hard negative)은 정답과 비슷해서 모델이 높은 점수를 주는 비정답입니다. 흔히 「노출됐는데 안 누른 광고」를 떠올리지만, 후보 모델에서는 그것만 음성으로 쓰면 오히려 나빠집니다. Facebook 검색 팀은 노출 후 안 누른 것만 음성으로 써 보았습니다(Huang 외, 2020). 사람 검색 모델의 재현율이 절대값 55% 떨어졌다고 보고했습니다.

같은 논문에서 헷갈리는 음성만으로는 무작위 음성을 이기지 못했습니다. 가장 좋았던 것은 지금 모델이 101~500위로 올린 비정답을 뽑아 섞는 방법이었습니다. 쉬운 음성을 늘려 갈수록 재현율이 올랐고, 쉬운 음성 100개에 헷갈리는 음성 1개꼴에서 더 오르지 않았습니다. 노출된 광고는 이미 앞 단계를 통과한 그럴듯한 광고라, 그것만 보면 전혀 상관없는 광고를 밀어내는 법을 배우지 못하기 때문입니다.

triplet 손실은 정답 하나와 음성 하나를 짝지어, 정답 쪽 점수가 정한 간격 이상 높도록 합니다. 같은 Facebook 검색 논문이 코사인 거리로 이 손실을 썼습니다. 소프트맥스는 배치의 모든 음성을 한 번에 보고, triplet 은 짝 하나씩 봅니다. 어느 쪽이든 데이터, 보정, 평가, 배포는 1~9절 그대로입니다.

## 한눈 정리

| 단계 | 하는 일 | 이 글의 숫자 |
|---|---|---|
| 모델 모양 | 회원과 광고를 각자 숫자 64개로 바꾸고 내적으로 점수를 낸다 | 회원 A 와 러닝화 0.81 |
| 학습 데이터 | 클릭 한 건이 정답 짝 한 줄. 회원 정보는 요청 때 값 | 30일 학습, 다음 날 평가 |
| 배치 한 번 | B×B 점수표에서 줄마다 대각선을 고르게 한다 | 손실 1.390 → 0.009 |
| 온도 | 점수를 τ 로 나눠 칸 사이 차이를 키운다 | τ = 1 이면 0.915 에서 멈춘다 |
| 인기 광고 보정 | 학습 때 각 열에서 log q 를 뺀다 | 러닝화 81.9번, 요가 매트 4.1번 |
| 같은 광고 칸 지우기 | 정답과 같은 광고 칸을 소프트맥스에서 뺀다 | 러닝화 줄마다 81칸 |
| 무작위 섞기 | 전체에서 뽑은 광고를 열로 더한다 | 4,096 × 5,120 |
| 평가 | 다음 날 클릭이 상위 500 안에 드는 비율 | 0.62, 기준선 0.31 |
| 배포 | 광고 벡터는 미리 색인에, 회원 타워는 요청마다, 같은 판으로 | 256MB |

## 헷갈리기 쉬운 점

- **음성은 저장하지 않습니다.** 로그에는 정답 짝만 남기고, 음성은 학습할 때 배치 안에서 만듭니다.
- **logQ 는 학습 때만 뺍니다.** 서빙 점수는 두 벡터의 내적 그대로입니다. 서빙에서도 빼면 드문 광고가 다시 부풀어 오릅니다.
- **노출됐는데 안 누른 광고는 후보 모델의 좋은 음성이 아닙니다.** pCTR 모델에는 좋은 음성이지만, 후보 모델은 상관없는 광고를 밀어내는 법부터 배워야 합니다.
- **AUC 가 높다고 후보 모델이 좋은 것은 아닙니다.** 무작위 광고와 견주면 너무 쉽습니다. 상위 K 안에 정답이 드는 비율로 봅니다.
- **두 타워의 판 번호가 다르면 점수에 뜻이 없습니다.** 다시 학습하면 색인과 회원 타워를 같이 바꿉니다.
- **온도는 작을수록 좋은 것이 아닙니다.** 너무 작으면 헷갈리는 몇 칸에 끌려다닙니다. 검증 재현율을 보고 고릅니다.
