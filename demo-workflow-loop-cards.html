워크플로와 자율 루프 카드 네 장

목표 ROAS 아래 캠페인의 입찰가를 내리는 일을 두 방식으로 10번씩 돌린 결과를 카드 네 장으로 봅니다. 자율 루프는 모델이 다음 도구를 고르고, 워크플로는 코드가 순서를 정합니다. 캠페인 셋과 어제 통계는 가상 데이터입니다.

파랑 = 코드가 정한 일 벽돌색 = 모델이 고른 것 먹색 = 서버와 에이전트 회색 = 막힌 호출과 멈춘 run 점선 상자 = 가상 값과 승인 기록

TWO WAYS

두 방식

쉽게 말하면 자율 루프는 모델이 단계마다 다음 할 일을 고르고, 워크플로는 코드가 순서를 정한 뒤 모델에게 요약만 맡깁니다.

두 방식 모두 같은 서버와 같은 approve 를 지납니다. 미리 승인한 범위는 c1 상한 20,000원입니다.

CALLS

호출 수와 시간

쉽게 말하면 자율 루프는 다음 할 일을 정할 때마다 모델의 답을 기다립니다. run 의 시간은 LLM 호출 수와 각 호출에 대응시킨 기록의 값으로 정해지고, 중앙값은 자율 루프가 깁니다.

LLM 호출은 자율 루프 3~5번, 워크플로 1번입니다. 빌려 온 호출 시간으로 센 run 하나의 시간은 중앙값 7,236.5ms 와 1,712.5ms 입니다.

VARIANCE

10번의 결과

쉽게 말하면 같은 일을 10번 맡겨도 자율 루프는 내리는지와 얼마나 내리는지가 run 마다 달랐습니다.

최종 입찰가는 자율 루프 세 가지, 워크플로 한 가지입니다. 자율 루프에서 러닝화를 내린 run 은 5번입니다.

A2A

오케스트레이터와 상태

쉽게 말하면 다른 팀의 에이전트에게 일을 맡기면, 결과는 작업 상태와 함께 돌아옵니다. 종료 상태의 작업은 메시지를 더 받지 않습니다.

성공 길의 두 작업은 COMPLETED, 실패 길은 REJECTED 로 끝났습니다. 종료 상태의 작업에 다시 보낸 메시지는 -32004 입니다.

현업에서는 이렇게 씁니다

  • 순서가 늘 같은 일은 코드가 순서를 정하는 워크플로로 두고, 다음에 무엇을 할지 모르는 일만 모델이 고르게 합니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 워크플로와 자율 루프 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 서버와 승인 코드를 처음 다룬 글은 광고주 에이전트 편입니다.
