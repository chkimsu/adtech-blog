Hadoop, Hive, Spark 자리 카드 여섯 장

세 이름은 프로그램이고, 노드는 그 프로그램이 도는 자리입니다. 워커 노드 한 대를 세로로 잘라 보면 저장, 자리 배분, 실행 세 층이 있고, Hive 와 Spark 는 맨 위층에 나란히 앉습니다. 이름과 숫자는 설명용 예시입니다.

파랑 = 저장 (HDFS) 벽돌색 = 자리 배분 (YARN) 먹색 = Hive 와 Tez 회색 = Spark 와 다른 엔진 점 = 지금 가고 있는 요청, 데이터

NODES

노드는 넷으로 나뉜다

쉽게 말하면 노드는 서버 한 대입니다. 내가 앉는 엣지, 목록과 자원을 쥔 마스터, SQL 을 받는 서비스, 데이터를 갖고 계산하는 워커 넷으로 나뉩니다.

워커가 가장 많고, 워커 한 대에는 저장(DN)과 자리 배분(NM) 두 역할이 같이 있습니다. Hadoop, Hive, Spark 는 이 노드들 위에서 도는 프로그램 이름입니다.

LAYERS

워커 한 대의 단면은 층이 셋

쉽게 말하면 맨 아래 디스크에 데이터 조각이 있고, 그 위에서 YARN 이 CPU 와 메모리 자리를 내주고, 맨 위에서 Hive 조각과 Spark 조각이 그 자리를 받아 돕니다.

Hive 와 Spark 의 차이는 3층의 프로그램뿐입니다. 1층과 2층은 같이 씁니다. 그래서 같은 워커가 두 엔진의 조각을 동시에 돌립니다.

HIVE PATH

SQL 한 건이 지나는 길

쉽게 말하면 늘 켜져 있는 HiveServer2 에 SQL 을 보내면, 그 서버가 목록을 묻고 자리를 받아 워커에 Tez 조각을 띄우고 결과를 모아 줍니다.

SQL 을 받는 자리는 HiveServer2 하나이고 여러 사람이 같이 씁니다. 계산은 워커의 Tez 컨테이너에서 일어납니다.

SPARK PATH

작업 한 건이 지나는 길

쉽게 말하면 Spark 는 내 작업마다 driver 라는 계획 담당을 하나 띄우고, driver 가 자리를 받아 워커에 executor 를 띄운 뒤 조각을 시키고 결과를 모읍니다.

HiveServer2 처럼 늘 켜진 서버 대신 작업마다 driver 하나입니다. 계산은 워커의 executor 에서 일어나고, 중간 결과를 메모리에 둡니다.

SHARED

셋이 만나는 자리는 목록과 파일

쉽게 말하면 Hive, Spark, Trino 는 같은 Metastore 목록을 보고 같은 HDFS 파일을 읽습니다. 그래서 「Hive 테이블」을 Spark 로도 Trino 로도 읽을 수 있습니다.

실선은 목록을 묻는 길이고 점선은 조각을 읽는 길입니다. Trino 만 YARN 자리를 받지 않고 자기 워커에서 돕니다.

NAMES

이름표를 층으로 쌓으면

쉽게 말하면 Hadoop 은 아래 두 층(HDFS 저장, YARN 자리 배분)의 이름입니다. Tez 와 Spark 는 그 위의 엔진이고, Hive 와 Spark SQL 은 사람이 쓰는 맨 위층입니다.

「Hadoop 위에서 Hive 를 쓴다」와 「Spark 를 YARN 에서 돌린다」가 같은 그림의 다른 칸을 가리키는 말입니다. Metastore 는 옆에서 세 엔진의 공통 목록을 듭니다.

현업에서는 이렇게 씁니다

  • 「그 쿼리는 Spark 로 돌리세요」는 3층의 프로그램만 바꾸라는 말입니다. 테이블 이름도 파일도 그대로이고, 자리를 받는 곳도 같은 YARN 입니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 자주 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 Hadoop, Hive, Spark 글에 이 카드들이 절마다 한 장씩 들어 있습니다. 상자 그림 판은 하둡 상자 그림 여섯 장입니다.
