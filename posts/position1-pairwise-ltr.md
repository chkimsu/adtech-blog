# Position 1 추론과 Pairwise LTR: 순서는 맞는데 점수 크기가 틀리는 이유

지훈 씨는 검색광고 pCTR 모델이 하루 동안 낸 점수를 실제 클릭과 맞춰 보고 있었습니다. 같은 검색 안의 광고 순서를 얼마나 잘 맞혔는지 보는 AUC 는 높았습니다. 그런데 점수로 센 예상 클릭은 실제보다 많았고, 2위와 3위 광고일수록 차이가 컸습니다.

옆자리 팀원은 클릭된 광고와 안 된 광고를 쌍으로 묶어 학습하는 방식을 시험하고 있었습니다. 검색 단위로 잰 순위 지표는 이 방식이 가장 높았습니다. 그런데 입찰가를 곱해 다시 줄을 세워 보니 클릭률이 낮은 광고가 1위로 올라왔습니다.

**순서를 잘 맞히는 점수가 왜 돈을 셀 때는 틀릴까요?**

앞의 일은 서빙 때 모든 후보를 1위로 두고 점수를 내는 Position 1 추론에서 생깁니다. 뒤의 일은 쌍으로 배우는 Pairwise LTR(Learning to Rank) 에서 생깁니다. 두 점수 모두 순서는 맞지만 크기가 맞지 않습니다. 광고는 이 점수에 입찰가를 곱해 순위를 정하고, 같은 점수로 예상 클릭과 광고비를 셉니다. 그래서 크기가 틀리면 순위와 돈이 같이 틀립니다.

> **한 줄 요약:** pCTR 은 랭커가 순서를 정하기 전에 불려 위치를 모르므로, 모든 후보를 1위로 두고 추론합니다. 순서 비교는 공평하지만 값은 1위 기준이라, 이 글의 가상 데이터에서 2위 광고는 1.3배, 3위 광고는 2배 부풀어 나옵니다. 예상 클릭과 광고비를 셀 때는 정해진 위치의 효과를 곱해 되돌립니다. Pairwise LTR 은 같은 검색 안의 순서만 배우고 점수 크기는 정하지 않습니다. 점수에 입찰가를 곱하는 광고에서는 그 크기 때문에 순위가 뒤집힐 수 있어, 크기가 맞는 pointwise 확률이나 보정 함수가 필요합니다.

> **골라 읽는 법:** 절이 12개인 긴 글입니다. 앞 여섯 절과 뒤 여섯 절은 따로 읽어도 됩니다.
>
> - 모든 후보를 1위로 두고 추론하는 이유와 그 값이 부푸는 정도 → 1~3절
> - 부푼 값을 되돌리는 법 → 4절
> - 1위 가정이 순서까지 바꾸는 경우와 1위에 가 본 적 없는 광고 → 5~6절
> - Pairwise LTR 이 점수 크기를 정하지 않는 이유와 입찰가를 곱할 때 생기는 일 → 7~9절
> - 쌍을 만드는 데이터가 기우는 자리 → 10~11절
> - 담장 안과 열린 RTB → 12절

## 1. 학습 때는 노출 로그에 위치가 있습니다

**노출 로그 한 줄에는 광고가 몇 위에 나왔는지가 적혀 있습니다. 그래서 pCTR 모델은 위치를 피처로 넣어 학습하고, 광고 품질과 위치 효과를 나눠 배웁니다.**

검색 결과에 광고가 여러 개 줄을 서면, 같은 광고라도 몇 위에 놓였느냐에 따라 눌리는 정도가 다릅니다. 위에 있을수록 사람 눈에 먼저 닿기 때문입니다. [Position Bias](post.html?id=position-bias-ultr) 편은 이것을 자리 편향이라고 부르고, 위치마다 눈길이 닿을 확률을 Examination 확률이라고 불렀습니다. 이 글은 1위를 1.0 으로 둔 그 비율을 위치 효과라고 부르겠습니다.

설명을 위해 아래 가상 데이터를 둡니다. 위치 효과는 앞 글의 가상 값과 같게 2위 0.75, 3위 0.5 로 두었습니다. 광고 A, B, C 는 1위에 있을 때 클릭률이 각각 5%, 4%, 3% 인 광고이고, 이 글은 그 1위 클릭률을 광고의 품질이라고 부릅니다. 광고 D 는 늘 4위 아래에만 나온 광고입니다.

| 위치 | 위치 효과 | 놓인 광고 | 광고 품질 (1위일 때 클릭률) | 그 위치에서의 클릭률 |
|---|---|---|---|---|
| 1위 | 1.0 | A | 5.0% | 5.0% |
| 2위 | 0.75 | B | 4.0% | 3.0% |
| 3위 | 0.5 | C | 3.0% | 1.5% |
| 4위 | 0.3 | D | 1위 기록 없음 | 0.6% |
| 5위 | 0.15 | 없음 | | |

로그만 보면 B 는 3.0%, C 는 1.5% 라서 B 가 C 의 두 배쯤 좋은 광고처럼 보입니다. 하지만 표의 둘째 줄이 말하듯 B 의 3.0% 는 품질 4.0% 에 2위 위치 효과 0.75 가 곱해진 값입니다. 위치를 피처로 넣고 학습하면 모델은 이 곱을 품질 몫과 위치 몫으로 나눠 배웁니다. 아래 카드가 그 흐름입니다.

위치를 빼고 학습하면 이 나눔이 일어나지 않습니다. 2위와 3위에서 덜 눌린 몫이 광고 ID 와 광고별 집계 피처로 새어 들어가, B 와 C 가 실제보다 나쁜 광고로 학습됩니다. 늘 1위에 나오던 광고는 반대로 좋아 보이고, 다음 날 랭킹이 그 광고를 또 1위에 올립니다. 그래서 위치는 학습에 넣는 것이 기본이고, 집계 피처도 위치를 감안한 비율로 만듭니다.

여기까지는 학습 이야기입니다. 문제는 이 모델을 서빙에 올려 점수를 물을 때 생깁니다. 그때는 위치 피처에 넣을 값이 없습니다.

## 2. 서빙 때는 위치를 모르므로 모두 1위로 둡니다

**pCTR 은 랭커가 광고 순서를 정하기 전에 불립니다. 순서를 정해야 위치가 생기는데 순서를 정하려면 점수가 필요하므로, 모든 후보에게 같은 위치 1 을 넣고 점수를 묻습니다.**

사용자가 검색어를 입력하면 랭커는 후보 광고를 모아 pCTR 모델에 점수를 묻습니다. 랭커는 광고의 순서를 정하는 서버입니다. 받은 점수에 입찰가를 곱해 순서를 정하고, 그 순서대로 1위, 2위, 3위 자리에 광고를 놓습니다. 위치는 이 마지막 단계에서야 생기므로, 점수를 묻는 시점에는 어느 광고가 몇 위에 갈지 아무도 모릅니다.

그래서 실무에서는 모든 후보의 위치 피처를 같은 값으로 채웁니다. 가장 흔한 값이 1 입니다. 1위는 가장 잘 보이는 자리라 그 자리의 클릭률을 광고의 품질로 읽기 쉽습니다. 위치 효과도 1위를 1.0 으로 두고 재기 때문에, 뒤에서 위치 효과를 곱할 때 계산이 간단해집니다.

모든 후보가 같은 위치를 가정하니 비교는 공평합니다. 위치 효과가 모든 광고에 같은 비율로 붙는다면, 위치를 몇으로 두든 점수의 순서는 같습니다. 그래서 점수 5.0%, 4.0%, 3.0% 로 정한 순서 A, B, C 는 어느 위치를 넣어 물어도 바뀌지 않습니다.

랭커가 남기는 로그로 나중에 점수를 다시 낼 때도 같습니다. 랭커 로그에는 노출되지 않은 후보까지 남는데, 노출되지 않은 후보에게는 위치가 없습니다. 새 랭킹 규칙을 시뮬레이션하거나 오프라인에서 정책을 평가하려고 랭커 로그를 다시 추론할 때도 위치를 1 로 고정합니다.

순서는 이렇게 맞게 나옵니다. 다음 절은 같은 점수를 크기로 읽을 때 생기는 일을 봅니다.

## 3. 1위 기준 점수는 아래 위치에서 부풉니다

**위치 1 로 낸 점수는 1위에 있을 때의 클릭률입니다. 2위와 3위로 간 광고는 그만큼 클릭되지 않으므로, 점수를 그대로 확률로 읽으면 아래 위치일수록 크게 부풉니다.**

B 의 점수는 4.0% 인데 B 는 2위에 가서 3.0% 만 클릭됩니다. C 의 점수는 3.0% 인데 3위에 가서 1.5% 만 클릭됩니다. B 는 1.3배, C 는 2배 부풀어 있는 셈입니다. 1위에 간 A 만 점수와 실제가 같습니다.

순서를 매길 때는 이 차이가 드러나지 않습니다. AUC 는 점수의 순서만 보기 때문에, 점수가 모두 같은 비율로 부풀어도 값이 그대로입니다. 크기는 예측한 클릭의 합을 실제 클릭의 합과 견줘 봐야 보입니다. [Calibration](post.html?id=calibration) 편이 다룬 예측 대비 실제 비율이 바로 이것입니다.

크기를 쓰는 계산은 생각보다 많습니다. 광고주에게 보여 주는 예상 클릭과 예상 광고비가 점수의 크기를 씁니다. 목표 클릭당 비용에 맞춰 입찰가를 정하는 자동입찰과, 랭킹 규칙을 바꿨을 때의 매출 시뮬레이션도 마찬가지입니다. 아래 코드는 광고마다 하루 1만 번 노출될 때 예상 클릭과 광고비가 얼마나 어긋나는지를 셉니다.

```python
# 하는 일: 모든 후보를 1위로 두고 낸 pCTR 과 실제로 간 위치의 클릭률을 견주고, 하루 예상 클릭과 광고비가 얼마나 어긋나는지 센다.
# 1단계: 가상 데이터를 둔다
# 광고마다 1위에 있을 때의 클릭률(품질)과 실제로 간 위치를 적는다. 위치 효과는 1위를 1.0 으로 둔 상대값이다.
quality = {'A': 0.050, 'B': 0.040, 'C': 0.030}     # 가상 값
placed = {'A': 1, 'B': 2, 'C': 3}
pos_effect = {1: 1.00, 2: 0.75, 3: 0.50, 4: 0.30, 5: 0.15}
imps, cpc = 10_000, 500                            # 광고마다 하루 노출, 클릭당 광고비(원)
# 2단계: 위치 1 점수와 그 위치의 클릭률을 나란히 찍는다
# 서빙에서 받는 점수는 position=1 로 추론한 값이라 품질 그대로다.
print('광고 위치 pCTR(1위 기준) 그 위치 클릭률 부푼 배수')
for ad, q in quality.items():
    real = q * pos_effect[placed[ad]]
    print(f'{ad}    {placed[ad]}    {q:6.1%}        {real:6.1%}        {q / real:4.2f}')
# 3단계: 하루 예상 클릭과 광고비를 견준다
# 이 가상 세계는 클릭률을 품질 × 위치 효과로 만들었으므로, 위치 효과를 곱한 값이 실제와 같다.
for ad, q in quality.items():
    raw = imps * q
    fixed = imps * q * pos_effect[placed[ad]]
    print(f'{ad}: 점수 그대로 {raw:,.0f}번 {raw * cpc:,.0f}원 / 위치 효과를 곱하면 {fixed:,.0f}번 {fixed * cpc:,.0f}원')

# 출력:
# 2단계 뜻: 1위 A 만 점수와 그 위치의 클릭률이 같고, 2위 B 는 1.33배, 3위 C 는 2배 부풀어 있다.
# 광고 위치 pCTR(1위 기준) 그 위치 클릭률 부푼 배수
# A    1      5.0%          5.0%        1.00
# B    2      4.0%          3.0%        1.33
# C    3      3.0%          1.5%        2.00
# 3단계 뜻: 점수를 그대로 쓰면 B 의 하루 광고비가 20만 원으로 잡혀, 위치 효과를 곱한 15만 원보다 5만 원 많다.
# A: 점수 그대로 500번 250,000원 / 위치 효과를 곱하면 500번 250,000원
# B: 점수 그대로 400번 200,000원 / 위치 효과를 곱하면 300번 150,000원
# C: 점수 그대로 300번 150,000원 / 위치 효과를 곱하면 150번 75,000원
```

B 를 보면 점수를 그대로 쓴 예상은 클릭 400번에 광고비 20만 원입니다. 위치 효과를 곱한 값은 300번에 15만 원입니다. 광고주에게 하루 20만 원어치 클릭이 날 것이라 보여 주고 15만 원만 쓰게 되면, 광고주는 예산과 기대 성과를 잘못 잡습니다. 3위 C 는 두 값이 두 배 차이라 어긋남이 더 큽니다.

그렇다고 위치 1 점수를 버릴 수는 없습니다. 순서는 맞기 때문입니다. 다음 절은 둘을 같이 쓰는 법입니다.

## 4. 크기가 필요한 계산에는 정해진 위치의 효과를 곱합니다

**같은 점수를 두 곳에 나눠 씁니다. 순서를 정할 때는 위치 1 점수를 그대로 쓰고, 순서가 정해진 뒤 돈을 셀 때는 그 위치의 효과를 곱합니다.**

B 는 2위로 정해졌으니 예상 클릭률은 4.0% × 0.75 = 3.0% 입니다. 이 값으로 예상 클릭, 예상 매출, 광고비를 셉니다. 순서를 정하는 단계와 돈을 세는 단계가 나뉘어 있어서, 위치 효과는 순서가 정해진 뒤에만 곱할 수 있습니다. 거꾸로 말하면 순서를 정하는 단계에서는 위치 효과를 곱할 필요가 없습니다.

위치 효과 표는 하나로 끝나지 않습니다. 광고가 3개 나올 때와 5개 나올 때 2위의 위치 효과가 다를 수 있고, 모바일과 PC 도 다릅니다. 그래서 위치 효과는 지면별로, 노출된 광고 수별로 나눠 둡니다. 값은 같은 광고를 여러 위치에 보여 준 기록으로 다시 잽니다. 재는 법은 [Position Bias](post.html?id=position-bias-ultr) 편 4절에 있습니다.

광고 수가 바뀌는 시뮬레이션에서는 1위를 1.0 으로 둔 상대값만으로는 부족할 때가 있습니다. 광고를 3개에서 5개로 늘리면 1위가 받던 클릭 일부가 아래 위치로 나뉘는데, 상대값 표는 1위를 늘 1.0 으로 둬서 이 이동을 담지 못합니다. 이럴 때는 광고 수별로 위치마다 클릭이 나뉘는 비율을 따로 재 둡니다.

지금까지는 위치 효과가 모든 광고에 같은 비율로 붙는다고 뒀습니다. 이 가정이 깨지면 순서까지 바뀝니다.

## 5. 위치와 광고를 함께 배우는 모델은 순서도 바꿉니다

**위치 효과가 광고마다 다르면, 모두를 1위로 둔 순서와 실제 위치에서의 순서가 다를 수 있습니다. DCN 처럼 피처끼리 곱해 배우는 모델은 이런 조합을 배웁니다.**

C 가 큰 이미지 광고라서 3위에서도 잘 보인다고 해 봅니다. 보통 광고인 A 의 3위 위치 효과는 0.5 인데, C 는 0.9 입니다. 둘 다 1위라면 A 가 5.0%, C 가 3.0% 로 A 가 앞섭니다. 둘 다 3위라면 A 는 2.5%, C 는 2.7% 라서 C 가 앞섭니다.

모델이 위치를 다른 피처와 따로 더하기만 한다면 이런 일은 없습니다. 위치가 점수에 같은 값을 더하거나 같은 비율을 곱할 뿐이라, 위치를 몇으로 두든 순서가 같습니다. 그런데 [Deep CTR 모델](post.html?id=deep-ctr-models) 편의 DCN 처럼 피처끼리 곱해 배우는 모델은, 이미지 광고는 아래 위치에서 덜 떨어진다는 조합까지 배웁니다. 그러면 위치에 넣는 고정값에 따라 순서가 달라집니다.

이 경우 위치 1 점수로 정한 순서가 최선이 아닐 수 있습니다. 후보가 적다면 위치마다 점수를 따로 내서 가장 나은 배치를 고를 수 있지만, 추론 횟수가 위치 수만큼 늘어납니다. 그래서 보통은 처음부터 위치 몫이 다른 피처와 섞이지 않도록 모델을 짭니다. 그 구조는 다음 절에서 같이 봅니다.

이 조합 문제는 1위에 한 번도 가 본 적 없는 광고에서 가장 크게 나옵니다.

## 6. 1위에 가 본 적 없는 광고의 점수는 짐작입니다

**학습 데이터의 1위 자리에는 기존 랭킹이 1위로 올린 광고만 있습니다. 한 번도 1위에 가 본 적 없는 광고를 1위로 두고 물으면, 모델은 본 적 없는 경우를 짐작합니다.**

1절 표의 D 는 늘 4위 아래에만 나온 광고입니다. 4위에서 0.6% 가 클릭됐으니 위치 효과 0.3 으로 나누면 품질은 2.0% 쯤입니다. 이 계산은 D 의 위치 효과가 다른 광고와 같다는 가정 위에 서 있습니다. D 가 1위에서 실제로 얼마나 클릭될지는 기록이 없어서 아무도 모릅니다.

데이터를 더 모으는 것으로는 풀리지 않습니다. 기존 랭킹이 D 를 1위에 올리지 않는 한 D 의 1위 기록은 생기지 않기 때문입니다. 그래서 두 가지를 씁니다. 하나는 트래픽 일부에서 순서를 섞어 보여 주는 탐색이고, 다른 하나는 위치를 따로 배우는 모델 구조입니다.

위치를 따로 배우는 구조의 대표가 PAL 입니다. 클릭 확률을 위치에만 달린 확률과 위치와 상관없는 광고의 확률로 나누고, 둘을 곱한 값으로 학습한 뒤 서빙에서는 뒤쪽만 씁니다. YouTube 의 추천 모델은 위치를 얕은 별도 층에만 넣고 서빙 때 그 층을 뺍니다. 둘 다 위치 피처에 고정값을 넣는 대신 위치 몫을 처음부터 떼어 둡니다. 학습 쪽의 다른 보정 방법은 [Position Bias](post.html?id=position-bias-ultr) 편 3~5절에 있습니다.

여기까지가 Position 1 추론입니다. 다음 절부터는 학습 방식을 바꿨을 때 같은 문제가 다른 모습으로 나오는 경우를 봅니다.

## 7. Pairwise LTR 은 같은 검색 안의 쌍으로 배웁니다

**pointwise 학습은 광고마다 눌렸는지를 맞히고, pairwise 학습은 같은 검색 안에서 눌린 광고가 안 눌린 광고보다 높게 나오도록 배웁니다. 서빙에서는 둘 다 광고 하나에 점수 하나를 냅니다.**

검색 한 번에서 1위 A 만 눌리고 B 와 C 는 안 눌렸다고 하겠습니다. pointwise 학습은 이 검색을 A 1, B 0, C 0 의 세 줄로 씁니다. pairwise 학습은 같은 검색을 A 가 B 보다 위, A 가 C 보다 위라는 두 쌍으로 씁니다. 손실도 다릅니다. pointwise 는 한 줄마다 확률과 정답의 차이를 보고, pairwise 는 한 쌍마다 두 점수의 차이를 봅니다.

pairwise 를 쓰는 이유는 경쟁을 배우기 때문입니다. 광고가 6개 나온 검색에서 받은 클릭은 다른 다섯 광고를 이긴 결과인데, pointwise 는 이것을 광고 2개짜리 검색의 클릭과 같은 한 줄로 셉니다. pairwise 는 이긴 상대마다 쌍을 만들어 경쟁이 센 검색의 클릭을 더 세게 반영합니다. 같은 검색 안의 순서를 재는 요청 단위 AUC 가 pairwise 쪽에서 높게 나오기 쉬운 이유입니다.

학습 방식만 바꾸고 서빙 구조는 그대로 둘 수 있다는 점도 실무에서 쓰기 좋습니다. 학습할 때는 같은 모델을 쌍의 양쪽에 두 번 태우고, 서빙할 때는 광고 하나씩 한 번 태웁니다. 대표적인 손실이 RankNet 의 로지스틱 손실이고, 검색 전체의 순서를 한 번에 보는 listwise 손실도 같은 갈래입니다.

문제는 이 손실이 무엇을 보지 않느냐에 있습니다.

## 8. Pairwise 손실은 점수 크기를 정하지 않습니다

**pairwise 손실은 두 점수의 차이만 봅니다. 모든 점수에 같은 값을 더해도 손실이 그대로라서, 학습이 끝나도 점수의 크기는 정해지지 않은 채 남습니다.**

모델 갑은 A 에 2, B 에 0 을 주고, 모델 을은 A 에 0, B 에 -2 를 준다고 하겠습니다. 점수는 시그모이드를 거치기 전의 로짓입니다. 두 모델 모두 A 와 B 의 차이가 2 라서 pairwise 손실이 똑같습니다. 학습은 둘 중 어느 쪽이 나은지 구분하지 못합니다.

그런데 시그모이드로 확률을 만들면 모델 갑은 A 를 88%, 모델 을은 50% 로 봅니다. 실제 클릭률이 5% 라면 둘 다 틀렸고, 어느 쪽이 덜 틀렸는지도 학습이 정해 주지 않습니다. 아래 코드는 두 모델의 손실과 확률을 찍고, 다음 절의 입찰 계산까지 이어서 봅니다.

```python
# 하는 일: pairwise 손실이 두 점수의 차이만 본다는 것을 확인하고, 손실이 같은 두 모델이 확률과 입찰 순위에서 얼마나 다른지 찍는다.
import math


# 1단계: 손실과 확률을 정한다
# 클릭된 광고 점수가 안 클릭된 광고 점수보다 클수록 손실이 작다(RankNet 의 로지스틱 손실).
def pairwise_loss(s_click, s_skip):
    return math.log(1 + math.exp(-(s_click - s_skip)))


def prob(score):
    return 1 / (1 + math.exp(-score))      # 로짓 점수를 확률로 바꾼다


# 2단계: 차이가 같은 두 모델을 견준다
# 점수는 로짓이다. 갑과 을은 A 와 B 의 차이가 똑같이 2 다.
models = {'갑': (2.0, 0.0), '을': (0.0, -2.0)}
for name, (a, b) in models.items():
    print(f'모델 {name}: 손실 {pairwise_loss(a, b):.4f}, A {prob(a):.0%}, B {prob(b):.0%}')

# 3단계: 입찰가를 곱해 순위를 매긴다
# X 와 Y 는 같은 검색에 함께 나온 적이 없어, pairwise 가 둘의 크기를 맞춘 적이 없다.
bids = {'X': 1000, 'Y': 600}
cases = [('맞는 크기', {'X': 0.02, 'Y': 0.04}), ('pairwise 점수', {'X': 0.03, 'Y': 0.04})]
for label, ctr in cases:
    score = {ad: bids[ad] * ctr[ad] for ad in bids}
    first = max(score, key=score.get)
    print(f'{label}: X {score["X"]:.0f}, Y {score["Y"]:.0f}, 1위 {first}')

# 출력:
# 2단계 뜻: 두 모델은 손실이 0.1269 로 같지만, A 의 확률은 88% 와 50% 로 다르다.
# 모델 갑: 손실 0.1269, A 88%, B 50%
# 모델 을: 손실 0.1269, A 50%, B 12%
# 3단계 뜻: X 의 점수가 2% 에서 3% 로 부풀면 순위 점수가 20 에서 30 이 되어, 1위가 Y 에서 X 로 바뀐다.
# 맞는 크기: X 20, Y 24, 1위 Y
# pairwise 점수: X 30, Y 24, 1위 X
```

그래서 pairwise 점수를 확률로 쓰려면 점수를 클릭률로 바꾸는 함수를 따로 맞춰야 합니다. 보통 시그모이드 안에 기울기와 절편 두 값을 두고, 절편은 전체 클릭률에 맞추고 기울기는 검증 데이터로 맞춥니다. 이 함수는 데이터가 바뀔 때마다 다시 맞춰야 해서, 학습이 확률을 직접 맞추는 pointwise 보다 관리할 것이 하나 늘어납니다.

크기가 정해지지 않은 점수가 가장 크게 문제 되는 자리는 입찰가와 곱하는 순간입니다.

## 9. 입찰가를 곱하면 검색 밖 비교가 생깁니다

**검색광고의 순위는 입찰가에 클릭 점수를 곱한 값으로 정합니다. pairwise 는 같은 검색 안의 순서만 맞췄는데, 입찰가를 곱하는 순간 서로 다른 검색에서 학습된 광고끼리 크기를 비교하게 됩니다.**

광고 X 는 입찰가 1,000원에 실제 클릭률 2%, 광고 Y 는 입찰가 600원에 4% 입니다. 크기가 맞는 점수라면 X 는 20, Y 는 24 라서 Y 가 1위입니다. 그런데 X 와 Y 는 그동안 같은 검색에 함께 나온 적이 없어서, pairwise 는 둘의 크기를 서로 맞춰 본 적이 없습니다.

오프라인 지표도 이 차이를 잘 보지 못합니다. 요청 단위 AUC 는 같은 검색 안의 순서만 재서 pairwise 에 유리하게 나옵니다. 입찰가를 곱해 쓰는 점수라면 아래 세 지표를 같이 봐야, 요청 단위 AUC 는 높은데 온라인에서 지는 모델을 미리 걸러 낼 수 있습니다.

| 지표 | 무엇을 재나 | pairwise 점수에서는 |
|---|---|---|
| 요청 단위 AUC | 같은 검색 안의 순서 | 잘 나옵니다 |
| 전체 AUC | 검색을 섞은 순서 | 크기가 어긋나면 떨어집니다 |
| 예측 합 대비 실제 합 | 점수의 크기 | 보정 함수 없이는 맞지 않습니다 |

그래서 입찰가와 곱하는 광고 점수는 크기가 맞는 pointwise 확률을 기본으로 둡니다. pairwise 의 장점을 함께 쓰고 싶으면 pointwise 손실에 순위 손실을 더하거나, pairwise 점수 뒤에 보정 함수를 붙입니다. 다음 두 절은 pairwise 학습 데이터 자체가 기우는 자리입니다.

## 10. 쌍을 만들 수 있는 검색만 남습니다

**쌍을 만들려면 한 검색 안에 눌린 광고와 안 눌린 광고가 함께 있어야 합니다. 그래서 아무도 누르지 않은 검색은 버려지고, 광고가 많은 검색의 클릭은 쌍을 더 많이 만듭니다.**

클릭률이 낮은 검색광고에서는 대부분의 검색이 클릭 없이 끝납니다. 검색 100번 중 클릭이 난 검색이 5번이라면 쌍은 그 5번에서만 나오고, 나머지 95번은 학습에서 빠집니다. 데이터가 크게 줄어 학습이 빨라지는 것은 장점입니다.

남은 검색 안에서도 가중이 같지 않습니다. 광고 6개 검색의 클릭 하나는 쌍 5개가 되고, 광고 2개 검색의 클릭 하나는 쌍 1개가 됩니다. 경쟁이 센 검색을 세게 배우는 것이 pairwise 의 장점인데, 거꾸로 보면 광고가 많은 검색 쪽으로 학습이 기운다는 뜻입니다.

광고가 한두 개뿐인 지면에서는 비교할 쌍이 거의 없어 pairwise 의 장점이 사라집니다. 그런 지면에서는 요청 단위 AUC 도 재기 어렵습니다. 광고 수가 지면마다 크게 다르면 쌍의 가중치를 검색마다 쌍 수로 나눠 맞추기도 합니다. 다만 그러면 경쟁이 센 검색을 세게 배우던 장점도 같이 줄어듭니다.

## 11. 쌍에 위치가 섞입니다

**클릭된 광고보다 아래에 있던 광고는 사용자가 아예 보지 않았을 수 있습니다. 그런 광고와 만든 쌍은 광고의 차이가 아니라 위치의 차이를 배웁니다.**

한 사람이 2위 B 를 눌렀다고 하겠습니다. 사람은 대개 위에서 아래로 읽으므로, B 를 누른 사람은 1위 A 를 보고 지나간 것이 확실합니다. 그래서 B 가 A 보다 위라는 쌍은 두 광고를 다 보고 고른 결과입니다. 3위 C 는 다릅니다. B 를 누르고 페이지를 떠났다면 C 는 보지도 않았을 수 있습니다.

B 가 C 보다 위라는 쌍을 그대로 학습하면, 모델은 사용자가 C 를 보고도 안 누른 것으로 배웁니다. 실제로는 C 가 아래에 있어 눈에 닿지 않았을 뿐이니, 이 쌍은 광고 품질 대신 위치 차이를 담습니다. 1절에서 위치를 피처로 넣어 걸러 내려던 착시가 쌍을 만드는 단계에서 다시 들어오는 것입니다.

그래서 클릭보다 위에서 건너뛴 광고만 음성으로 쓰는 방법이 있습니다. Joachims 가 검색 클릭 로그로 순위를 학습하며 쓴 방식이라 skip-above 라고 부릅니다. 쌍 수는 줄지만, 남는 쌍은 두 광고를 다 본 사람의 선택입니다. 위치 효과를 알고 있다면 아래 광고와 만든 쌍을 그 위치의 Examination 확률로 가중해 쓰는 방법도 있습니다.

이런 치우침이 얼마나 문제가 되는지는 광고가 줄을 서는 지면이냐에 달렸습니다.

## 12. 무대가 바뀌면 무엇이 달라집니까

**광고가 여러 개 줄을 서는 담장 안 지면에서는 두 문제가 매일 나옵니다. 지면 하나에 광고 하나가 많은 열린 RTB 에서는 위치 문제가 덜한 대신, 확률의 크기가 곧 입찰가입니다.**

### 담장 안에서는 위치를 알고 섞어 볼 수도 있습니다 [무대: 닫힌 생태계]

검색과 피드에 광고가 여러 개 줄을 서는 닫힌 생태계에서는 이 글의 두 문제가 매일 나옵니다. 위치 로그가 정확하고 트래픽 일부에서 순서를 섞는 실험도 직접 할 수 있습니다. 그래서 위치 효과를 재고 위치 1 점수를 되돌리는 일을 스스로 할 수 있습니다. 거꾸로 말하면 위치 효과를 곱하지 않은 예상 광고비는 잴 수 있는데 재지 않은 값이 됩니다.

### 열린 RTB 에서는 확률의 크기가 곧 입찰가입니다 [무대: 열린 RTB]

열린 RTB 의 DSP 는 지면 하나에 광고 하나를 넣는 경우가 많아 위치 문제는 덜합니다. 대신 입찰가를 클릭 확률에 클릭 하나의 가치를 곱해 정하므로, 확률이 1.3배 부풀면 입찰가도 1.3배 부풉니다. pairwise 처럼 크기를 정하지 않는 점수는 그대로 입찰에 쓸 수 없고, 쓰려면 반드시 보정 함수를 거칩니다.

## 한눈 정리

| 질문 | 한 줄 답 |
|---|---|
| 서빙 때 위치를 왜 1 로 두나 | 점수를 물을 때는 순서가 정해지기 전이라 위치가 없습니다. 모두 같은 1위로 두면 비교가 공평합니다 |
| 1위로 둔 점수의 문제는 | 1위 기준 클릭률이라 아래 위치에서 부풉니다. 이 글의 예시에서 2위 1.3배, 3위 2배 |
| 어떻게 되돌리나 | 순서가 정해진 뒤 그 위치의 효과를 곱합니다. 4.0% × 0.75 = 3.0% |
| 순서도 바뀌나 | 위치 효과가 광고마다 다르고 모델이 그 조합을 배우면 바뀔 수 있습니다 |
| 1위에 가 본 적 없는 광고는 | 점수가 짐작입니다. 탐색 트래픽과 위치를 떼어 배우는 구조로 줄입니다 |
| pairwise LTR 은 무엇을 배우나 | 같은 검색 안의 순서입니다. 점수의 크기는 정하지 않습니다 |
| 광고에서 왜 문제가 되나 | 입찰가를 곱하는 순간 다른 검색의 광고와 크기를 비교합니다 |
| 오프라인에서 무엇을 보나 | 요청 단위 AUC 와 함께 전체 AUC, 예측 합 대비 실제 합 |
| 쌍 데이터의 치우침은 | 클릭 난 검색만 남고, 광고가 많은 검색이 세게 배우고, 아래 광고와의 쌍에 위치가 섞입니다 |

## 헷갈리기 쉬운 점

- **Position 1 추론이 틀린 방법은 아닙니다.** 순서를 정하는 데는 맞는 방법이고, 틀리는 것은 그 점수를 그대로 확률로 읽을 때입니다.
- **AUC 가 그대로라고 크기가 맞는 것은 아닙니다.** AUC 는 순서만 재서, 점수가 모두 같은 비율로 부풀어도 값이 같습니다.
- **위치를 아예 빼고 학습하면 더 나빠집니다.** 위치 몫이 광고 ID 로 새어 들어가 위에 자주 나온 광고가 좋아 보입니다.
- **pairwise 점수에 시그모이드를 씌웠다고 확률이 되지 않습니다.** 숫자는 0과 1 사이로 나오지만 그 크기는 학습이 정한 것이 아닙니다.
- **Pairwise LTR 이 나쁜 방법은 아닙니다.** 검색 결과나 피드 순서를 다시 정하는 단계처럼 순서만 중요한 자리에는 맞습니다. 입찰가와 곱하는 자리에서만 보정이 따로 필요합니다.
- **listwise 손실도 같습니다.** LambdaRank 나 softmax 손실도 검색 안의 순서를 배우고, 점수의 크기는 정하지 않습니다.
