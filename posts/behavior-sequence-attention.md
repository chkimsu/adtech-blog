민지는 아침에 러닝화 두 켤레를 눌러 봤고, 점심에는 커피 원두를 샀습니다. 저녁에는 러닝 양말을 하나 더 눌러 봤습니다. 밤 9시 14분에 뉴스앱을 열자 기사 사이에 광고 한 칸이 열립니다.

그 순간 DSP 에는 이 칸에 낼 수 있는 후보 광고가 800개 있습니다. 클릭률 모델은 10ms 안에 광고마다 민지가 누를 확률을 매겨야 합니다. 후보 중에는 러닝화 광고도 있고 커피머신 광고도 있습니다.

**모델은 숫자만 받는데, 민지의 하루 행동 네 개를 어떤 숫자로 넣어야 두 광고를 모두 제대로 매길까요?**

행동 기록을 시간 순서로 이은 것을 행동 시퀀스라고 부르고, 그것을 숫자 묶음 하나로 바꾸는 일을 시퀀스 임베딩이라고 부릅니다. 지금 광고 클릭률 모델은 대부분 이 일을 attention 으로 합니다. 두 광고에 같은 숫자를 넣으면 한쪽은 늘 낮게 매겨지고, 그 차이가 입찰가와 매출로 그대로 이어집니다.

> **한 줄 요약:** 행동 하나는 상품, 카테고리, 시간 간격의 숫자를 이어 붙인 벡터가 됩니다. 평균은 광고를 모른 채 벡터 하나를 만들고, target attention 은 광고마다 행동에 다른 무게를 매겨 더합니다. 이력이 수만 개면 관련 있는 행동을 먼저 고르고 같은 계산을 하는데, 고르는 점수가 attention 과 다르면 중요한 행동이 빠집니다.

> **골라 읽는 법** — 절이 여덟 개인 글입니다. 2~5절이 계산의 본체이고, 나머지는 그 앞과 뒤입니다.
>
> - 시퀀스가 요청 한 건 안에서 쓰이는 자리 → 1절
> - 행동 하나가 벡터가 되는 법 → 2절
> - 평균이 잃는 것 → 3절
> - 광고마다 다른 무게, target attention → 4절
> - 행동끼리 서로 보기, self-attention → 5절
> - 이력이 수만 개일 때 먼저 고르기, SIM → 6절
> - 고르는 점수가 다를 때 생기는 일, TWIN → 7절
> - 사용자 벡터가 가는 곳과 학습 → 8절

이 글의 임베딩, 무게, 이력 수는 전부 설명을 위한 가상 값입니다. 후보 800개, Model Serving 의 10ms, 원 pCTR 2.1% 는 [생태계 지도](ecosystem.html?flow=dspinside)의 「DSP 안의 순서」 흐름과 같은 값입니다. 논문에서 가져온 숫자는 그 자리에 논문 이름을 적습니다.

## 1. 시퀀스는 요청 한 건 안에서 Model Serving 이 받습니다

**입찰 요청이 오면 DSP 는 후보 광고를 800개로 추리고, 그 후보와 민지의 행동 기록을 함께 Model Serving 에 넘깁니다.**

요청 한 건이 지나는 순서부터 보겠습니다. 거래소에서 입찰 요청이 들어오면 DSP 는 먼저 후보 추출을 합니다. 타겟 조건과 남은 예산과 빈도 제한으로 거르고, 광고 1만 2천 개를 800개로 줄입니다. 그다음 Feature Store 가 후보마다 피처를 붙이고, Model Serving 이 후보마다 클릭 확률을 계산합니다. 클릭 확률은 pCTR 이라고 부릅니다.

행동 기록은 Feature Store 가 붙이는 피처 가운데 하나입니다. 민지의 오늘 기록을 꺼내 보면 이렇습니다.

```text
회원 8812, 2026-10-04 21:14 뉴스앱 320×100 요청
시각    행동    상품        카테고리     요청까지
09:02  클릭    러닝화 A     러닝화       12시간 12분
09:05  클릭    러닝화 B     러닝화       12시간 9분
12:40  구매    커피 원두    커피         8시간 34분
19:30  클릭    러닝 양말    러닝 용품    1시간 44분
```

이 네 줄이 **행동 시퀀스**입니다. 지금 확률을 매기는 광고 하나는 **후보 광고**라고 부릅니다. 시퀀스를 줄여 만든 숫자 묶음은 **사용자 벡터**라고 부릅니다. 상품 번호 같은 이름을 숫자 몇 개로 바꾸는 표는 **임베딩**이라고 부르는데, 이 표의 숫자도 학습으로 정해집니다.

문제는 길이입니다. 민지는 오늘 행동이 네 개지만 평생 이력은 수만 개일 수 있고, 다른 회원은 오늘 하나도 없을 수 있습니다. 그런데 모델 윗부분의 신경망은 입력 칸 수가 정해져 있습니다. 그래서 길이가 제각각인 기록을 칸 수가 정해진 벡터 하나로 줄여야 합니다. 먼저 행동 하나를 숫자로 바꾸는 데서 시작합니다.

## 2. 행동 하나는 숫자 네 칸이 됩니다

**상품 번호, 카테고리, 시간 간격을 각각 임베딩 표에서 찾아 이어 붙이면 행동 하나가 벡터 하나가 됩니다.**

설명을 위해 표를 아주 작게 잡겠습니다. 상품 번호마다 숫자 두 개, 카테고리마다 숫자 하나, 시간 간격 구간마다 숫자 하나입니다. 실제 모델은 칸마다 32개나 64개를 쓰지만 계산 방법은 같습니다. 시간 간격은 2시간 안, 10시간 안, 30일 안, 그보다 오래, 이렇게 네 구간으로 나눴습니다.

가정: 표의 숫자는 학습이 끝났다고 치고 정한 값입니다. 계산: 행동 벡터 = [상품 2칸, 카테고리 1칸, 시간 1칸].

| 행동 | 상품 칸 | 카테고리 칸 | 시간 칸 | 이어 붙인 벡터 |
|---|---|---|---|---|
| 러닝화 A 클릭 | 0.9, 0.1 | 러닝화 0.8 | 12시간 전 0.2 | [0.9, 0.1, 0.8, 0.2] |
| 러닝화 B 클릭 | 0.8, 0.2 | 러닝화 0.8 | 12시간 전 0.2 | [0.8, 0.2, 0.8, 0.2] |
| 커피 원두 구매 | 0.1, 0.9 | 커피 -0.7 | 9시간 전 0.5 | [0.1, 0.9, -0.7, 0.5] |
| 러닝 양말 클릭 | 0.7, 0.1 | 러닝 용품 0.6 | 2시간 전 0.9 | [0.7, 0.1, 0.6, 0.9] |
| 러닝화 광고 (후보) | 0.85, 0.15 | 러닝화 0.8 | 지금 0.9 | [0.85, 0.15, 0.8, 0.9] |
| 커피머신 광고 (후보) | 0.15, 0.8 | 커피 -0.7 | 지금 0.9 | [0.15, 0.8, -0.7, 0.9] |

더하지 않고 이어 붙이는 데는 이유가 있습니다. 상품 칸과 카테고리 칸을 더해 버리면 어느 숫자가 상품에서 왔는지 모델이 알 수 없습니다. 이어 붙이면 칸마다 출처가 정해져 있어서, 뒤의 신경망이 상품은 비슷한데 카테고리가 다른 경우를 따로 배울 수 있습니다.

후보 광고도 같은 표로 벡터를 만듭니다. 광고 상품의 번호와 카테고리를 찾고, 시간 칸에는 지금을 뜻하는 2시간 안 구간의 값 0.9 를 넣습니다. 그래야 행동과 광고가 같은 칸끼리 비교됩니다. 시간 칸 덕분에 최근 행동일수록 광고와 시간 칸이 비슷해집니다.

실제 학습된 칸에는 이름이 붙지 않습니다. 여기서는 읽기 쉽게 상품 칸의 첫 숫자는 러닝 쪽으로, 둘째 숫자는 커피 쪽으로 기울게 골랐습니다. 이제 벡터 네 개를 사용자 벡터 하나로 줄일 차례입니다. 가장 쉬운 방법은 평균입니다.

## 3. 평균은 어떤 광고를 채점하든 같은 벡터를 냅니다

**네 벡터를 칸마다 평균하면 [0.625, 0.325, 0.375, 0.45] 하나가 나옵니다. 이 값은 러닝화 광고를 채점할 때나 커피머신 광고를 채점할 때나 똑같습니다.**

평균은 칸마다 네 숫자를 더해 4로 나눈 것입니다. 이것을 mean pooling 이라고 부릅니다. DIN 논문이 출발점으로 삼은 Embedding 과 MLP 구조도 행동 피처를 이렇게 합이나 평균으로 묶었습니다. 아래 코드는 2절의 표로 벡터를 다시 만들고 평균을 냅니다. 그리고 사용자 벡터와 광고 벡터의 내적으로 둘이 얼마나 맞는지 봅니다.

```python
# 행동 네 개를 벡터로 만들고 평균을 낸다. 평균은 어떤 광고를 채점하든 같은 벡터다.
# 숫자는 설명을 위해 정한 가상의 임베딩이다. 실제로는 클릭 로그로 학습된다.
# 표준 라이브러리만 쓴다.

ITEM = {                      # 상품 id 표: 상품마다 숫자 두 개
    "러닝화 A": [0.9, 0.1], "러닝화 B": [0.8, 0.2],
    "커피 원두": [0.1, 0.9], "러닝 양말": [0.7, 0.1],
    "러닝화 C": [0.85, 0.15], "커피머신": [0.15, 0.8],   # 광고 상품 둘
}
CATEGORY = {"러닝화": 0.8, "러닝 용품": 0.6, "커피": -0.7}    # 카테고리 표: 숫자 하나
TIME = [(2, 0.9), (10, 0.5), (24 * 30, 0.2), (float("inf"), 0.05)]   # 시간 간격 표: 몇 시간 안이면 이 값

def time_value(hours):
    return next(v for limit, v in TIME if hours <= limit)

def to_vector(item, category, hours):
    """행동 하나 = 상품 숫자 2개 + 카테고리 숫자 1개 + 시간 숫자 1개를 이어 붙인 4칸."""
    return ITEM[item] + [CATEGORY[category], time_value(hours)]

# 21시 14분 요청. 오늘 행동 네 개와 요청까지 남은 시간
behaviors = [("러닝화 A", "러닝화", 12.2), ("러닝화 B", "러닝화", 12.15),
             ("커피 원두", "커피", 8.57), ("러닝 양말", "러닝 용품", 1.73)]
E = [to_vector(*b) for b in behaviors]
ads = {"러닝화 광고": to_vector("러닝화 C", "러닝화", 0),     # 광고는 '지금'이라 시간 간격 0
       "커피머신 광고": to_vector("커피머신", "커피", 0)}

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

for (name, _, _), e in zip(behaviors, E):
    print(f"{name:6} → {e}")
mean = [sum(col) / len(E) for col in zip(*E)]
print("평균 사용자 벡터 →", [round(x, 3) for x in mean])

for ad, v in ads.items():
    best = max(E, key=lambda e: dot(e, v))
    print(f"{ad}: 평균과의 점수 {dot(mean, v):.3f}"
          f" / 가장 맞는 행동 하나와의 점수 {dot(best, v):.3f}"
          f" ({dot(mean, v) / dot(best, v) * 100:.0f}% 만 남음)")

# 출력:
# 러닝화 A  → [0.9, 0.1, 0.8, 0.2]
# 러닝화 B  → [0.8, 0.2, 0.8, 0.2]
# 커피 원두  → [0.1, 0.9, -0.7, 0.5]
# 러닝 양말  → [0.7, 0.1, 0.6, 0.9]
# 평균 사용자 벡터 → [0.625, 0.325, 0.375, 0.45]
# 러닝화 광고: 평균과의 점수 1.285 / 가장 맞는 행동 하나와의 점수 1.900 (68% 만 남음)
# 커피머신 광고: 평균과의 점수 0.496 / 가장 맞는 행동 하나와의 점수 1.675 (30% 만 남음)
```

내적은 모델이 내는 pCTR 이 아니라, 두 벡터가 얼마나 같은 쪽을 향하는지 보는 간단한 잣대입니다. 러닝화 광고에서는 평균의 점수가 1.285 이고, 가장 맞는 행동 하나인 러닝 양말과의 점수는 1.900 입니다. 평균이 맞는 신호의 68% 를 남깁니다.

커피머신 광고에서는 사정이 훨씬 나쁩니다. 커피 원두 구매 하나와의 점수는 1.675 인데 평균의 점수는 0.496 입니다. 30% 만 남았습니다. 커피 원두 구매가 러닝 행동 세 개와 같은 무게로 섞이면서 묻힌 것입니다.

평균은 광고를 모른 채 한 번 계산되므로, 어느 광고 앞에서나 이력 전체를 똑같이 대표합니다. 그래서 이력의 대부분과 다른 관심일수록 손해를 봅니다. 민지가 정말로 커피를 사는 사람이어도 커피머신 광고의 pCTR 은 구조적으로 낮게 나오고, 그 광고는 입찰에서 덜 이깁니다. 다음 절은 광고를 보고 나서 무게를 정하는 방법입니다.

## 4. Target attention 은 광고마다 행동에 다른 무게를 줍니다

**후보 광고와 행동 하나를 작은 신경망에 넣어 무게 하나를 내고, 무게를 곱해 더하면 그 광고만을 위한 사용자 벡터가 나옵니다.**

이 방법은 Alibaba 가 2018년에 낸 DIN(Deep Interest Network)에서 시작했습니다. 행동 $e_j$ 와 후보 광고 $v_A$ 가 있을 때 사용자 벡터를 이렇게 만듭니다.

$$v_U(A) = \sum_{j=1}^{H} a(e_j, v_A)\, e_j, \qquad a(e_j, v_A) = \mathrm{MLP}\left(e_j,\ v_A,\ e_j - v_A,\ e_j \odot v_A\right)$$

무게를 내는 신경망을 activation unit 이라고 부릅니다. 입력은 행동 벡터, 광고 벡터, 둘의 차이, 칸끼리의 곱을 이어 붙인 것입니다. 2절의 벡터라면 4칸씩 네 덩어리라 16칸이 됩니다. 신경망은 이 16칸을 받아 숫자 하나를 냅니다.

중요한 점이 하나 있습니다. **DIN 논문은 이 무게를 softmax 로 나누지 않습니다.** 무게의 합이 1이어야 한다는 제약을 일부러 풀었습니다. 그래야 관련 행동이 많은 광고일수록 사용자 벡터가 커져서, 관심이 얼마나 센지가 벡터에 남습니다. 아래 코드는 학습이 끝난 신경망의 무게를 가정해 두 광고의 무게와 사용자 벡터를 계산합니다.

```python
# Target attention(DIN): 후보 광고마다 행동 네 개에 무게를 따로 매겨 더한다.
# activation unit = 작은 MLP. 입력은 [행동, 광고, 행동-광고, 행동×광고] 16칸이다.
# 무게는 학습이 끝났다고 치고 정한 가상의 값이다. 표준 라이브러리만 쓴다.
import math

E = {"러닝화 A": [0.9, 0.1, 0.8, 0.2], "러닝화 B": [0.8, 0.2, 0.8, 0.2],
     "커피 원두": [0.1, 0.9, -0.7, 0.5], "러닝 양말": [0.7, 0.1, 0.6, 0.9]}   # 2절의 벡터
ADS = {"러닝화 광고": [0.85, 0.15, 0.8, 0.9], "커피머신 광고": [0.15, 0.8, -0.7, 0.9]}

# 숨은 칸 하나짜리 MLP. 실제 모델은 16칸 전부에 학습된 무게가 붙고 숨은 칸이 수십 개다.
# 여기서는 '곱 네 칸의 합이 0.3 을 넘는 만큼 1.5배'를 내도록 배웠다고 가정한다.
W1 = [0.0] * 12 + [1.0] * 4      # 앞 12칸(행동, 광고, 차이)은 0, 곱 4칸만 1
B1, W2, B2 = -0.3, 1.5, 0.0

def activation_unit(e, v):
    x = e + v + [a - b for a, b in zip(e, v)] + [a * b for a, b in zip(e, v)]  # 16칸
    h = max(0.0, sum(w * xi for w, xi in zip(W1, x)) + B1)                     # ReLU
    return W2 * h + B2                                     # 무게 하나. 나누지 않는다

for ad, v in ADS.items():
    w = {name: activation_unit(e, v) for name, e in E.items()}
    user = [sum(w[n] * E[n][k] for n in E) for k in range(4)]     # 무게를 곱해 더한다
    print(f"[{ad}]")
    print("  무게:", {n: round(x, 3) for n, x in w.items()}, f"합 {sum(w.values()):.2f}")
    print("  사용자 벡터:", [round(x, 3) for x in user])
    exp = {n: math.exp(x) for n, x in w.items()}                  # 비교용 softmax
    tot = sum(exp.values())
    print("  softmax 였다면:", {n: round(x / tot, 3) for n, x in exp.items()}, "합 1.00")

# 출력:
# [러닝화 광고]
#   무게: {'러닝화 A': 1.95, '러닝화 B': 1.845, '커피 원두': 0.0, '러닝 양말': 2.4} 합 6.20
#   사용자 벡터: [4.911, 0.804, 4.476, 2.919]
#   softmax 였다면: {'러닝화 A': 0.277, '러닝화 B': 0.249, '커피 원두': 0.039, '러닝 양말': 0.434} 합 1.00
# [커피머신 광고]
#   무게: {'러닝화 A': 0.0, '러닝화 B': 0.0, '커피 원두': 2.062, '러닝 양말': 0.413} 합 2.48
#   사용자 벡터: [0.495, 1.897, -1.196, 1.403]
#   softmax 였다면: {'러닝화 A': 0.088, '러닝화 B': 0.088, '커피 원두': 0.691, '러닝 양말': 0.133} 합 1.00
```

러닝화 광고 앞에서는 러닝 행동 세 개가 무게 1.95, 1.845, 2.4 를 받고 커피 원두는 0 을 받습니다. 커피머신 광고 앞에서는 반대로 커피 원두가 2.062 를 받고 러닝화 둘은 0 입니다. 같은 기록에서 사용자 벡터가 두 개 나왔습니다. 러닝화 광고용은 첫 칸이 4.911 로 크고, 커피머신 광고용은 둘째 칸이 1.897 로 큽니다.

무게의 합도 다릅니다. 러닝화 광고는 6.20, 커피머신 광고는 2.48 입니다. 민지의 기록에서 러닝 관련 행동이 더 많고 더 최근이라 러닝화 광고가 이력을 더 많이 활성화한 것입니다. softmax 로 나눴다면 둘 다 합이 1이 되어 이 차이가 사라집니다. 또 softmax 는 0 을 만들지 못해서, 러닝화 광고 앞에서도 커피 원두가 3.9% 를 가져갑니다.

대신 값이 듭니다. 사용자 벡터가 광고마다 다르니 미리 하나를 계산해 둘 수 없습니다. 후보가 800개면 요청 한 건에 이 계산을 800번 합니다. 이력이 길어질수록 이 비용이 문제가 되고, 그것이 6절의 출발점입니다.

:::deep 더 깊이 — 논문의 activation unit 과 공개 구현, 그리고 학습 요령 둘
DIN 논문(arXiv 1706.06978)의 4.3절은 사용자 벡터를 위 식처럼 정의합니다. 그리고 무게의 합이 1이라는 제약을 풀어 softmax 정규화를 버린다고 적습니다. 이유로 든 것은 사용자 관심의 세기를 남기는 것이고, 티셔츠 광고가 휴대폰 광고보다 옷 관련 이력을 더 많이 활성화한다는 예를 듭니다.

activation unit 의 입력은 논문 그림에서 두 임베딩과 외적(outer product)입니다. 널리 쓰이는 공개 구현인 DeepCTR 은 이 자리에 [광고, 행동, 광고-행동, 광고×행동] 을 이어 붙입니다. DeepCTR 의 attention 풀링 층은 softmax 정규화를 `weight_normalization` 옵션으로 둡니다. 기본값은 끈 쪽(False)입니다.

논문은 학습 요령도 둘 냅니다. 하나는 Dice 라는 활성 함수로, PReLU 의 꺾이는 점을 0 에 고정하지 않고 입력 분포의 평균에 맞춰 움직입니다. 다른 하나는 미니배치 단위 정규화로, L2 정규화를 수십억 개 파라미터 전부가 아니라 그 미니배치에 나온 피처의 파라미터에만 계산합니다.
:::

## 5. Self-attention 은 행동들이 서로를 보고 자기 벡터를 다시 씁니다

**행동마다 행렬 세 개를 곱해 Q, K, V 벡터를 만들고, Q 와 K 의 내적만큼 다른 행동의 V 를 섞어 자기 벡터를 새로 씁니다.**

Target attention 은 행동마다 무게만 매기고 행동 벡터 자체는 그대로 둡니다. 그런데 행동의 뜻은 앞뒤에 따라 달라집니다. 러닝화를 두 번 본 뒤의 러닝 양말 클릭은 혼자 있는 러닝 양말 클릭과 다른 신호입니다. self-attention 은 이 앞뒤를 행동 벡터 안에 넣는 계산입니다.

Alibaba 가 2019년에 낸 BST(Behavior Sequence Transformer)가 이 방식을 광고 추천에 썼습니다. 클릭한 상품 20개 시퀀스 끝에 후보 상품을 한 칸 붙이고, Transformer 블록 하나를 지나게 합니다. 위치 정보로는 추천 시각과 클릭 시각의 차이를 피처로 넣었고, 이것이 Transformer 의 사인 코사인 위치 값보다 나았다고 보고합니다. 2절의 시간 칸이 바로 이 역할입니다.

Q, K, V 는 행동 벡터에 서로 다른 학습 행렬을 곱해 만든 벡터 셋입니다. 행동 $i$ 의 Q 와 행동 $j$ 의 K 의 내적이 둘 사이의 점수가 되고, 줄마다 softmax 를 거쳐 합이 1인 무게가 됩니다. 그 무게로 V 들을 섞은 것이 행동 $i$ 의 새 벡터입니다.

$$\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^{\top}}{\sqrt{d}}\right)V$$

```python
# Self-attention(BST 방식): 행동들이 서로를 보고 각자의 벡터를 다시 쓴다.
# BST 처럼 후보 광고도 시퀀스 끝에 한 칸으로 붙인다. 시간 칸(4번째)이 위치 신호 역할을 한다.
# W_Q, W_K, W_V 는 학습되는 행렬인데, 여기서는 W_Q = 2I, W_K = W_V = I 로 둔 가정이다.
# 표준 라이브러리만 쓴다.
import math

names = ["러닝화 A", "러닝화 B", "커피 원두", "러닝 양말", "커피머신 광고"]
X = [[0.9, 0.1, 0.8, 0.2], [0.8, 0.2, 0.8, 0.2], [0.1, 0.9, -0.7, 0.5],
     [0.7, 0.1, 0.6, 0.9], [0.15, 0.8, -0.7, 0.9]]          # 2절의 벡터 + 광고 한 칸
d = len(X[0])

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

Q = [[2 * x for x in row] for row in X]          # Q = X W_Q
K, V = X, X                                      # K = X W_K, V = X W_V

A = []                                           # 줄 i = i번째 칸이 누구를 얼마나 보나
for q in Q:
    s = [dot(q, k) / math.sqrt(d) for k in K]    # scaled dot-product
    m = max(s)
    e = [math.exp(x - m) for x in s]
    A.append([x / sum(e) for x in e])            # Transformer 는 softmax 를 쓴다

tags = ["b1", "b2", "b3", "b4", "ad"]          # 한글은 칸 폭이 달라 표에는 짧은 이름을 쓴다
print("      " + "".join(f"{t:>6}" for t in tags))
for t, row in zip(tags, A):
    print(f"{t:>6}" + "".join(f"{x:6.2f}" for x in row))
print("(" + ", ".join(f"{t} {n}" for t, n in zip(tags, names)) + ")")

out = [[sum(A[i][j] * V[j][k] for j in range(len(X))) for k in range(d)] for i in range(len(X))]
for i in (2, 4):
    print(f"{names[i]}: {X[i]} → {[round(x, 3) for x in out[i]]}")

# 출력:
#           b1    b2    b3    b4    ad
#     b1  0.32  0.30  0.05  0.26  0.06
#     b2  0.31  0.29  0.06  0.26  0.07
#     b3  0.06  0.06  0.37  0.09  0.41
#     b4  0.24  0.22  0.08  0.34  0.12
#     ad  0.05  0.06  0.33  0.11  0.45
# (b1 러닝화 A, b2 러닝화 B, b3 커피 원두, b4 러닝 양말, ad 커피머신 광고)
# 커피 원두: [0.1, 0.9, -0.7, 0.5] → [0.268, 0.692, -0.395, 0.667]
# 커피머신 광고: [0.15, 0.8, -0.7, 0.9] → [0.271, 0.684, -0.391, 0.69]
```

러닝 행동 셋은 서로를 크게 봅니다. 러닝화 A 의 줄을 보면 자기에게 0.32, 러닝화 B 에 0.30, 러닝 양말에 0.26 을 줍니다. 커피 원두의 줄은 자기에게 0.37, 커피머신 광고에 0.41 을 줍니다. 광고 칸의 줄은 커피 원두에 0.33 을 주어서, 광고의 새 벡터에 민지가 커피 원두를 샀다는 사실이 들어갑니다.

BST 가 후보 상품을 시퀀스에 넣는 이유가 여기 있습니다. 광고 칸이 행동들을 보는 줄은 target attention 과 같은 일을 하되, softmax 로 합이 1이 되게 나눕니다. BST 는 이렇게 다시 쓴 벡터들을 다른 피처와 이어 붙여 위층 신경망에 넣습니다. 다른 모델은 다시 쓴 행동 벡터 위에 4절의 target attention 을 한 번 더 얹기도 합니다.

BST 논문은 블록을 하나만 쌓았을 때 가장 좋았고, 타오바오에서 클릭률이 7.57% 올랐다고 보고합니다. 다만 self-attention 은 행동 수의 제곱만큼 점수를 계산합니다. 20개면 400칸이지만 2만 개면 4억 칸입니다. 그래서 긴 이력은 다른 길로 갑니다.

## 6. 이력이 수만 개면 먼저 고르고 같은 계산을 합니다

**평생 이력 2만 개 전부에 target attention 을 하면 요청 한 건에 곱셈이 5,434억 번 듭니다. 그래서 광고와 관련 있는 200개를 먼저 고르고, 그 안에서만 4절의 계산을 합니다.**

담장 안에서는 로그인 계정에 몇 해 치 검색, 클릭, 구매가 쌓입니다. Alibaba 의 SIM 논문(2020)은 사용자 이력을 최대 5만 4천 개까지 썼습니다. 이력이 길면 몇 달 전 커피 용품 구매처럼 오늘 기록에 없는 관심까지 쓸 수 있습니다. 문제는 계산량입니다.

```python
# 이력이 2만 개인 사용자 한 명에게 후보 광고 800개가 왔다. 전부에 attention 을 하면
# activation unit 의 곱셈이 몇 번 필요한가. 숨은 층은 널리 쓰이는 구현(DeepCTR)의
# 기본값 (80, 40) 을, 행동 벡터는 상품 32 + 카테고리 32 + 시간 32 = 96칸을 가정한다.
# 이력 수와 카테고리 분포는 가상 값이다. 표준 라이브러리만 쓴다.

HISTORY = 20_000          # 이 사용자의 평생 이력
CANDIDATES = 800          # Model Serving 에 오는 후보 수(생태계 지도의 값)
K = 200                   # 고르는 단계가 남기는 수(SIM 논문이 카테고리마다 자른 길이)
D = 96
LAYERS = [4 * D, 80, 40, 1]          # [행동, 광고, 차이, 곱] → 80 → 40 → 무게 하나

macs_per_pair = sum(a * b for a, b in zip(LAYERS, LAYERS[1:]))
full = CANDIDATES * HISTORY * macs_per_pair
picked = CANDIDATES * K * macs_per_pair
soft = CANDIDATES * HISTORY * 32     # soft search 를 인덱스 없이: 상품 임베딩 32칸 내적
print(f"행동 하나와 광고 하나: 곱셈 {macs_per_pair:,}번")
print(f"이력 전부에 attention: {full:,}번")
print(f"고른 {K}개에만: {picked:,}번 ({full // picked}분의 1)")
print(f"soft search 로 고르는 데 드는 곱셈: {soft:,}번")

by_category = {"러닝화": 6000, "러닝 용품": 3000, "전자기기": 4000, "여행": 2500,
               "커피": 900, "주방가전": 400, "외식": 1200, "기타": 2000}
assert sum(by_category.values()) == HISTORY
coffee = by_category["커피"]
print(f"커피머신 광고의 hard search: 커피 카테고리 {coffee}개 중 최근 {min(K, coffee)}개,"
      f" 그 밖의 {HISTORY - coffee:,}개는 보지 않는다")

# 출력:
# 행동 하나와 광고 하나: 곱셈 33,960번
# 이력 전부에 attention: 543,360,000,000번
# 고른 200개에만: 5,433,600,000번 (100분의 1)
# soft search 로 고르는 데 드는 곱셈: 512,000,000번
# 커피머신 광고의 hard search: 커피 카테고리 900개 중 최근 200개, 그 밖의 19,100개는 보지 않는다
```

행동 하나와 광고 하나에 activation unit 을 한 번 돌리면 곱셈이 3만 4천 번쯤 듭니다. 이력 2만 개와 후보 800개를 곱하면 5,434억 번이 되어, 10ms 예산과는 자릿수가 맞지 않습니다. 200개로 고르면 54억 번으로 100분의 1 이 됩니다.

SIM 은 이것을 두 단계로 나눴습니다. 앞 단계인 GSU(General Search Unit)는 긴 이력에서 후보 광고와 관련 있는 행동을 고릅니다. 뒤 단계인 ESU(Exact Search Unit)는 고른 행동에만 target attention 을 합니다. ESU 는 여러 head 의 attention 에 광고와 행동 사이의 시간 간격까지 넣습니다.

GSU 가 고르는 방법은 둘입니다. hard search 는 후보 광고와 같은 카테고리의 행동만 꺼냅니다. soft search 는 임베딩의 내적이 큰 행동을 위에서부터 꺼냅니다. 논문은 soft search 가 조금 더 좋았지만, 비용을 따져 실제 서비스에는 hard search 를 썼다고 적습니다.

hard search 는 카테고리 색인만 보면 되니 거의 공짜입니다. soft search 는 색인 없이 하면 이력 전부와 내적을 해야 하지만, 그래도 attention 전부보다는 1,000분의 1 수준입니다. 고르는 비용을 정했으면 다음 질문은 고른 것이 맞느냐입니다.

:::deep 더 깊이 — SIM 논문의 숫자와 TWIN 의 비용 줄이기
SIM 논문(arXiv 2006.05639)에서 확인한 숫자입니다. 이력은 최대 5만 4천 개로, 앞선 모델 MIMN 의 1,000개보다 54배 깁니다. GSU 가 고른 카테고리별 시퀀스는 200개에서 자르고, 원래 길이는 대개 150개 아래였습니다. hard search 가 남긴 행동은 soft search 가 남긴 행동의 75% 를 덮었습니다.

이력은 사용자별 카테고리 트리 구조(User Behavior Tree)에 넣어 두고, 분산 저장소 크기가 22TB 에 이릅니다. 1만 개 넘는 이력으로 서빙해도 지연은 MIMN 보다 5ms 늘었습니다. 2019년부터 Alibaba 디스플레이 광고에 쓰여 클릭률 7.1%, RPM 4.4% 를 올렸다고 보고합니다.

TWIN(arXiv 2302.02352)은 고르는 단계에서도 attention 과 같은 점수를 쓰려고 두 가지로 비용을 줄입니다. 행동 피처를 둘로 나눠서, 상품에 딸린 피처의 선형 변환은 미리 계산해 캐시합니다. 사용자와 상품을 엮은 교차 피처는 attention 점수에 더하는 숫자 하나로 줄여 넣습니다.
:::

## 7. 고르는 점수가 attention 과 다르면 중요한 행동이 빠집니다

**커피 그라인더 클릭은 attention 이라면 두 번째로 큰 무게를 받을 행동입니다. 이 행동이 카테고리로도, 따로 학습한 임베딩으로도 안 걸리면 사용자 벡터의 점수가 9.18 에서 5.19 나 6.16 으로 떨어집니다.**

민지의 더 긴 이력에서 커피머신 광고와 엮일 만한 행동을 열 개 꺼내 봅니다. 오늘 행동 네 개에, 어제의 커피 그라인더 클릭과 커피 머그 클릭이 있습니다. 사흘 전 카페 쿠폰 저장, 40일 전 드립백 커피 클릭, 그리고 노트북과 여행 가방도 있습니다. 고르는 단계가 세 개만 남긴다고 하고, 세 가지 기준을 나란히 봅니다.

```python
# 긴 이력에서 K개를 먼저 고르고 그 안에서만 target attention 을 한다.
# 고르는 기준이 셋일 때 사용자 벡터가 어떻게 달라지나: 카테고리(hard search),
# 따로 학습한 임베딩의 내적(soft search), attention 과 같은 점수(TWIN 방식).
# 이력 10개와 모든 숫자는 설명을 위한 가상 값이다. 표준 라이브러리만 쓴다.

ITEM = {"러닝화 A": [0.9, 0.1], "러닝화 B": [0.8, 0.2], "커피 원두": [0.1, 0.9],
        "러닝 양말": [0.7, 0.1], "커피 그라인더": [0.2, 0.9], "카페 쿠폰": [0.1, 0.7],
        "드립백 커피": [0.15, 0.85], "노트북": [0.0, 0.1], "여행 가방": [0.3, 0.2],
        "커피 머그": [0.2, 0.6], "커피머신": [0.15, 0.8]}
CATEGORY = {"러닝화": 0.8, "러닝 용품": 0.6, "커피": -0.7, "주방가전": -0.6,
            "외식": -0.3, "전자기기": 0.1, "여행": 0.2, "주방용품": -0.2}
TIME = [(2, 0.9), (10, 0.5), (24 * 30, 0.2), (float("inf"), 0.05)]
# soft search 가 쓰는 임베딩은 본 모델과 따로 학습됐다. 그라인더를 주방가전 쪽으로 본다.
SOFT = {"러닝화 A": [0.9, 0.05], "러닝화 B": [0.9, 0.05], "커피 원두": [0.1, 0.95],
        "러닝 양말": [0.8, 0.1], "커피 그라인더": [0.6, 0.3], "카페 쿠폰": [0.2, 0.7],
        "드립백 커피": [0.15, 0.9], "노트북": [0.5, 0.0], "여행 가방": [0.4, 0.1],
        "커피 머그": [0.3, 0.5], "커피머신": [0.1, 0.9]}

def vec(item, cat, hours):
    return ITEM[item] + [CATEGORY[cat], next(v for h, v in TIME if hours <= h)]

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def weight(e, v):                    # 4절의 activation unit 과 같은 손 계산
    return 1.5 * max(0.0, dot(e, v) - 0.3)

history = [("러닝화 A", "러닝화", 12.2), ("러닝화 B", "러닝화", 12.15),
           ("커피 원두", "커피", 8.57), ("러닝 양말", "러닝 용품", 1.73),
           ("커피 그라인더", "주방가전", 23), ("카페 쿠폰", "외식", 72),
           ("드립백 커피", "커피", 960), ("노트북", "전자기기", 48),
           ("여행 가방", "여행", 240), ("커피 머그", "주방용품", 25)]
ad, ad_cat = "커피머신", "커피"
v = vec(ad, ad_cat, 0)
W = {h[0]: weight(vec(*h), v) for h in history}
full_total = sum(W.values())
K = 3

picks = {
    "hard (같은 카테고리)": [h[0] for h in history if h[1] == ad_cat][:K],
    "soft (따로 학습한 임베딩)": sorted(W, key=lambda n: -dot(SOFT[n], SOFT[ad]))[:K],
    "TWIN (attention 과 같은 점수)": sorted(W, key=lambda n: -W[n])[:K],
}
full_user = [sum(W[h[0]] * vec(*h)[k] for h in history) for k in range(4)]
print(f"전체 10개로 낸 사용자 벡터: {[round(x, 2) for x in full_user]}, 점수 {dot(full_user, v):.2f}")
for name, chosen in picks.items():
    kept = sum(W[n] for n in chosen)
    user = [sum(W[h[0]] * vec(*h)[k] for h in history if h[0] in chosen) for k in range(4)]
    print(f"{name}: {chosen}")
    print(f"   남은 무게 {kept / full_total * 100:.1f}%, 사용자 벡터 {[round(x, 2) for x in user]},"
          f" 점수 {dot(user, v):.2f}")

# 출력:
# 전체 10개로 낸 사용자 벡터: [1.28, 5.69, -3.58, 2.15], 점수 9.18
# hard (같은 카테고리): ['커피 원두', '드립백 커피']
#    남은 무게 47.9%, 사용자 벡터 [0.42, 3.05, -2.43, 1.1], 점수 5.19
# soft (따로 학습한 임베딩): ['커피 원두', '드립백 커피', '카페 쿠폰']
#    남은 무게 61.6%, 사용자 벡터 [0.52, 3.75, -2.73, 1.3], 점수 6.16
# TWIN (attention 과 같은 점수): ['커피 원두', '커피 그라인더', '드립백 커피']
#    남은 무게 69.6%, 사용자 벡터 [0.73, 4.47, -3.37, 1.42], 점수 7.32
```

hard search 는 커피 카테고리인 원두와 드립백 두 개만 남깁니다. 그라인더는 주방가전이라 빠지고, 이력 10개로 낸 무게의 47.9% 만 남습니다. soft search 는 따로 학습한 임베딩에서 그라인더를 주방가전 쪽으로 보고 있어서 카페 쿠폰을 대신 고릅니다. 남은 무게는 61.6% 입니다.

TWIN 방식은 attention 과 같은 점수로 고르니, attention 이 가장 크게 볼 셋인 원두, 그라인더, 드립백이 남습니다. 남은 무게는 69.6% 이고 사용자 벡터의 점수는 7.32 입니다. 세 개만 남길 때 남는 무게가 이보다 클 수는 없습니다. 고르는 기준이 뒤 단계와 같으면 뒤 단계가 원했을 행동을 앞 단계가 버리지 않습니다.

Kuaishou 의 TWIN 논문(2023)이 짚은 것이 이 어긋남입니다. 앞 단계가 뒤 단계와 다른 관련도를 쓰면, 뒤 단계가 크게 볼 행동은 놓치고 무관하게 볼 행동을 가져옵니다. TWIN 은 앞 단계가 뒤 단계의 target attention 과 똑같은 관련도를 쓰게 해서 두 단계를 맞춥니다. 이렇게 해서 이력 길이를 1만에서 10만 자릿수까지 늘렸습니다.

다른 길도 있습니다. Meituan 의 SDIM(2022)은 행동마다 무게를 계산하지 않습니다. 여러 해시 함수로 후보 광고와 행동의 해시 값을 만들고, 광고와 해시 값이 같은 행동만 모읍니다. 논문은 attention 모델과 비슷한 정확도를 훨씬 짧은 시간에 낸다고 보고합니다. 어느 쪽이든 고르는 기준을 바꾸면 같은 모델의 사용자 벡터가 달라지므로, 이력을 늘리기 전에 고르는 점수부터 봅니다.

## 8. 사용자 벡터는 pCTR 로 이어지고, 클릭이 전부를 함께 학습시킵니다

**[사용자 벡터 4칸, 광고 4칸, 문맥 2칸] 을 위층에 넣으면 러닝화 광고의 pCTR 이 2.10% 로 나옵니다. 클릭 하나의 손실은 위층과 activation unit 과 임베딩 표를 함께 고칩니다.**

사용자 벡터는 그 자체로 답이 아닙니다. 후보 광고의 벡터, 그리고 시간대와 지면 같은 문맥 피처와 이어 붙여 위층 신경망에 들어갑니다. 위층이 낸 값에 시그모이드를 씌운 것이 pCTR 입니다. 아래 코드는 위층을 로지스틱 하나로 줄여서 이 흐름을 계산합니다.

같은 코드로 두 가지를 더 봅니다. 하나는 노출 6분 뒤인 21시 20분의 러닝화 C 구매가 시퀀스에 섞였을 때입니다. 다른 하나는 이 노출이 클릭됐을 때와 안 됐을 때, 학습 한 걸음이 숫자들을 어떻게 움직이는지입니다.

```python
# 사용자 벡터가 가는 곳: [사용자 벡터, 광고 벡터, 문맥] 을 이어 붙여 위층에 넣고 pCTR 을 낸다.
# 클릭 하나가 들어오면 같은 손실이 위층, activation unit, 임베딩까지 함께 고친다.
# 그리고 노출 뒤의 행동이 시퀀스에 섞이면 무슨 일이 생기는지 본다.
# 위층은 설명을 위해 로지스틱 하나로 줄였고, 모든 무게는 가상 값이다. 표준 라이브러리만 쓴다.
import math

ITEM = {"러닝화 A": [0.9, 0.1], "러닝화 B": [0.8, 0.2], "커피 원두": [0.1, 0.9],
        "러닝 양말": [0.7, 0.1], "러닝화 C": [0.85, 0.15]}
CATEGORY = {"러닝화": 0.8, "러닝 용품": 0.6, "커피": -0.7}
TIME = [(2, 0.9), (10, 0.5), (24 * 30, 0.2), (float("inf"), 0.05)]
LOG = [("09:02", "러닝화 A", "러닝화"), ("09:05", "러닝화 B", "러닝화"),
       ("12:40", "커피 원두", "커피"), ("19:30", "러닝 양말", "러닝 용품"),
       ("21:20", "러닝화 C", "러닝화")]          # 마지막 줄은 노출 6분 뒤의 구매
IMPRESSION = "21:14"
W_TOP = [0.12, 0.05, 0.10, 0.08] + [0.2, 0.1, 0.1, 0.0] + [0.3, 0.2]   # 사용자 4, 광고 4, 문맥 2
CONTEXT = [0.9, 0.3]                              # 저녁 시간대, 뉴스앱 320×100

def hours(t):
    h, m = map(int, t.split(":"))
    return h + m / 60

def predict(p, leak=False):
    seq = [r for r in LOG if leak or r[0] < IMPRESSION]       # 노출 전 행동만 넣는다
    item = dict(ITEM, **{"러닝 양말": [p["양말0"], 0.1]})
    vec = lambda name, cat, gap: item[name] + [CATEGORY[cat], next(v for h, v in TIME if gap <= h)]
    ad = vec("러닝화 C", "러닝화", 0)
    user = [0.0] * 4
    for t, name, cat in seq:
        e = vec(name, cat, max(0.0, hours(IMPRESSION) - hours(t)))
        w = p["W2"] * max(0.0, sum(a * b for a, b in zip(e, ad)) + p["B1"])   # activation unit
        user = [u + w * x for u, x in zip(user, e)]
    x = user + ad + CONTEXT
    z = sum(a * b for a, b in zip(W_TOP, x)) + p["b"]
    return 1 / (1 + math.exp(-z))

params = {"W2": 1.5, "B1": -0.3, "b": -5.75, "양말0": 0.7}
print(f"pCTR {predict(params) * 100:.2f}% (노출 전 행동 4개)")
print(f"pCTR {predict(params, leak=True) * 100:.2f}% (노출 뒤 구매까지 섞으면)")

for label in (1, 0):                             # 이 노출이 클릭됐을 때와 안 됐을 때
    loss = lambda p, y=label: -math.log(predict(p) if y else 1 - predict(p))
    grad = {}
    for k in params:                             # 숫자로 미분: 조금 올렸을 때와 내렸을 때
        up, down = dict(params), dict(params)
        up[k] += 1e-5; down[k] -= 1e-5
        grad[k] = (loss(up) - loss(down)) / 2e-5
    new = {k: params[k] - 0.05 * grad[k] for k in params}    # 학습률 0.05 로 한 걸음
    moved = ", ".join(f"{k} {params[k]:.3f}→{new[k]:.3f}" for k in params)
    print(f"라벨 {label}: {moved} | pCTR {predict(new) * 100:.2f}%")

# 출력:
# pCTR 2.10% (노출 전 행동 4개)
# pCTR 4.31% (노출 뒤 구매까지 섞으면)
# 라벨 1: W2 1.500→1.543, B1 -0.300→-0.254, b -5.750→-5.701, 양말0 0.700→0.728 | pCTR 2.42%
# 라벨 0: W2 1.500→1.499, B1 -0.300→-0.301, b -5.750→-5.751, 양말0 0.700→0.699 | pCTR 2.09%
```

노출 뒤의 구매까지 넣으면 pCTR 이 2.10% 에서 4.31% 로 뜁니다. 학습할 때 이런 시퀀스를 쓰면 모델은 미래의 행동에 기대는 법을 배웁니다. 서빙할 때는 그 행동이 아직 없으니, 오프라인 지표는 좋은데 실제 성과는 나쁜 모델이 됩니다. 그래서 시퀀스에는 노출 시각보다 앞선 행동만 넣고, 학습과 서빙에서 같은 코드로 시퀀스를 만듭니다.

클릭이 들어오면 위층의 절편만 바뀌는 것이 아닙니다. activation unit 의 W2 는 1.500 에서 1.543 으로, B1 은 -0.300 에서 -0.254 로 움직입니다. 러닝 양말 임베딩의 첫 칸도 0.700 에서 0.728 로 러닝화 광고 쪽으로 움직입니다. 한 손실의 기울기가 attention 의 무게와 임베딩 표까지 거슬러 올라가는 것을 end-to-end 학습이라고 부릅니다.

클릭이 없을 때는 같은 숫자들이 반대쪽으로 아주 조금 움직이고 pCTR 은 2.09% 가 됩니다. 손실의 기울기가 클릭일 때는 1−p, 안 클릭일 때는 p 에 비례하기 때문입니다. p 가 2.1% 면 클릭 한 번이 안 클릭 한 번보다 46배쯤 세게 밉니다. 실제 학습은 대부분 클릭이 없는 노출 수억 건으로 이 균형을 맞춥니다.

:::deep 더 깊이 — 서빙 예산, 늦게 오는 라벨, 두 무대
서빙에서는 사용자 쪽 계산을 미리 해 둘 수 있는 만큼 해 둡니다. 행동 벡터와 상품 쪽 선형 변환은 요청 전에 만들어 캐시하고, 요청 안에서는 후보 800개와의 attention 만 합니다. 생태계 지도의 흐름에서 Model Serving 이 받는 10ms 가 이 계산의 예산입니다.

라벨은 늦게 옵니다. 클릭은 몇 분 안에 오지만 구매는 며칠 뒤에 오기도 합니다. 학습 데이터를 너무 일찍 자르면 아직 안 온 클릭과 구매가 0 으로 들어가니, 라벨을 기다리는 창을 정합니다([지연 피드백](post.html?id=online-learning-delayed-feedback) 편).

담장 안에서는 로그인 계정에 이력이 길게 쌓여 6~7절의 고르는 단계가 실제로 값을 합니다. 열린 RTB 의 DSP 는 입찰 요청에 지면과 기기 정보 정도만 오고 쿠키가 자주 바뀌어, 붙일 수 있는 이력이 몇 개에 그칩니다. 그때는 target attention 이 평균과 거의 같아지고, 고르는 단계는 쓸 일이 없습니다.
:::

## 한눈 정리

| 방법 | 사용자 벡터가 광고마다 다른가 | 무게의 합 | 무엇이 비싼가 | 언제 쓰나 |
|---|---|---|---|---|
| 평균 (mean pooling) | 같다 | 행동마다 똑같이 | 거의 없다 | 이력이 몇 개뿐일 때 |
| Target attention (DIN) | 다르다 | 1이 아니다 | 후보마다 행동 수만큼 신경망 | 이력 수십에서 수백 개 |
| Self-attention (BST) | 광고를 시퀀스에 넣으면 다르다 | 줄마다 1 | 행동 수의 제곱 | 짧은 이력, 행동 사이 관계가 중요할 때 |
| 고르고 attention (SIM) | 다르다 | 고른 행동 안에서 | 고르기와 고른 수만큼 신경망 | 이력 수천에서 수만 개 |
| 같은 점수로 고르기 (TWIN) | 다르다 | 고른 행동 안에서 | 고르는 점수를 attention 과 맞추는 비용 | 고르는 단계가 놓치는 행동이 많을 때 |
| 해시로 모으기 (SDIM) | 다르다 | 해시가 같은 행동끼리 | 해시 계산 | attention 비용을 더 줄여야 할 때 |

## 헷갈리기 쉬운 점

- **DIN 의 무게는 확률이 아닙니다.** 논문은 softmax 로 나누지 않아서 합이 1이 아닙니다. 반면 self-attention 은 줄마다 softmax 를 써서 합이 1입니다.
- **target attention 을 쓰는 모델은 사용자 벡터를 하나만 미리 만들어 둘 수 없습니다.** 후보 광고마다 다시 계산하니, 후보가 800개면 800번입니다.
- **시퀀스에는 노출보다 앞선 행동만 넣습니다.** 학습과 서빙이 같은 코드로 시퀀스를 만들어야 미래의 행동이 섞이지 않습니다.
- **고르는 단계가 버린 행동은 뒤의 attention 이 되살리지 못합니다.** 뒤 단계가 아무리 정확해도 받은 행동 안에서만 무게를 매깁니다.
- **임베딩 칸에는 이름이 없습니다.** 이 글의 러닝 쪽 칸, 커피 쪽 칸은 읽기 쉽게 고른 예이고, 학습된 칸은 여러 뜻이 섞여 있습니다.
