지훈 씨는 앞 편에서 배운 대로 리스트를 집합으로 바꿔 시간 초과(코드가 채점 서버의 제한 시간 안에 끝나지 않아 떨어지는 일)를 피했습니다. 집합은 같은 값을 한 번씩만 담아 두고 어떤 값이 들어 있는지를 빠르게 확인할 때 쓰는 자료형이라, 「이 값이 있나」만 묻던 그 문제는 집합으로 풀렸습니다.

그런데 다음 문제는 값이 들어 있는지가 아니라 **그 값이 몇 번 칸에 있는지**를 물었고 지훈 씨는 여기서 다시 막혔습니다. 집합은 값을 넣어 두기만 할 뿐 그 값이 몇 번 칸에 있었는지는 기억하지 않아서 이 물음에 답할 수 없습니다. 그렇다고 칸 번호를 아는 리스트로 되돌리면 앞 편에서 본 대로 다시 느려지므로, 지훈 씨에게는 빠르면서 값마다 자리도 함께 기억하는 자료형이 필요했습니다.

**값 하나로 다른 값을 즉시 꺼내려면 무엇이 필요할까요?**

답은 딕셔너리입니다. 딕셔너리는 값 하나에 다른 값 하나를 짝지어 담아 두는 자료형이라, 값마다 그 값이 있던 칸 번호를 함께 넣어 두면 값 하나로 칸 번호를 바로 꺼낼 수 있습니다. 딕셔너리가 빠른 까닭은 **해시**입니다. 이 글은 해시가 무엇인지, 해시를 쓰는 딕셔너리가 왜 가끔 느려지는지, 해시로 풀리지 않는 문제는 정렬로 어떻게 푸는지를 차례로 다룹니다.

> **한 줄 요약:** 리스트는 찾는 값과 담긴 값을 앞에서부터 하나씩 비교하지만 딕셔너리는 찾는 값에서 들어 있을 자리를 계산해 그 자리로 바로 가므로, 값 20만 개 가운데서 찾을 때 딕셔너리가 리스트보다 만 배 안팎으로 빠릅니다. 이 계산으로 풀리지 않는 문제에는 두 번째 도구인 정렬을 씁니다.

> **골라 읽는 법** — 이 글의 절 10개는 순서대로 읽지 않아도 됩니다.
>
> - 딕셔너리가 빠른 까닭과 느려지는 경우 → 1절부터 3절까지
> - 딕셔너리의 키로 쓸 수 있는 자료형 → 4절
> - 문제 풀이에 바로 쓰는 방법 → 5절 두 수의 합부터 7절 집합 연산까지
> - 정렬만 → 8절부터 10절까지

## 1. 리스트에서 찾기가 느린 까닭

**리스트는 값을 찾을 때 첫 칸부터 하나씩 비교하므로 담긴 값이 많을수록 오래 걸립니다.**

리스트는 값을 0번 칸부터 번호가 붙은 칸에 차례로 담는 자료형입니다. `x in 리스트` 로 값을 찾으면 파이썬은 0번 칸부터 하나씩 꺼내 `x` 와 같은지 비교합니다. 이렇게 앞에서부터 차례로 비교해 나가는 일을 스캔이라고 부릅니다. 찾는 값이 리스트에 없으면 마지막 칸까지 다 비교한 뒤에야 없다는 것을 알 수 있으므로, 담긴 값이 많을수록 한 번 찾는 데 드는 비교도 늘어납니다.

앞 편에서는 리스트와 집합의 찾기 속도 차이를 한 번 봤습니다. 이번에는 같은 값 20만 개를 리스트와 딕셔너리에 담아 두고 그 안에서 값 2천 개를 찾아보며 차이가 얼마나 벌어지는지 확인합니다.

아래 코드의 1단계는 담을 값(`haystack`)과 찾을 값(`needles`)을 무작위로 뽑은 뒤 `haystack` 을 리스트 `as_list` 와 딕셔너리 `as_dict` 에 똑같이 담습니다. `as_dict` 는 값마다 그 값이 리스트의 몇 번 칸에 있는지를 짝지어 담은 딕셔너리라 지훈 씨가 원하던 「값으로 칸 번호 꺼내기」를 그대로 해 줍니다. 2단계는 같은 2천 개를 두 곳에서 `x in` 으로 찾으며 걸린 시간을 따로 측정합니다. 3단계에서 두 시간과 함께 리스트 시간이 딕셔너리 시간의 몇 배인지를 찍습니다.

```python
# 하는 일: 값 20만 개를 리스트와 딕셔너리에 담아 두고, 2천 개를 찾는 데 걸린 시간을 비교한다.
import time, random

# 1단계: 담을 값 20만 개와 찾을 값 2천 개를 뽑는다
# 같은 값 20만 개를 리스트와 딕셔너리 두 곳에 담는다.
random.seed(42)
haystack = random.sample(range(1, 1_000_000), 200_000)
needles  = random.sample(range(1, 1_000_000), 2_000)

as_list = haystack
as_dict = {v: i for i, v in enumerate(haystack)}

# 2단계: 두 곳에서 2천 번씩 찾는다
# 리스트는 앞에서부터 스캔하고, 딕셔너리는 자리를 계산한다.
t = time.perf_counter()
for x in needles:
    x in as_list
list_ms = (time.perf_counter() - t) * 1000

t = time.perf_counter()
for x in needles:
    x in as_dict
dict_ms = (time.perf_counter() - t) * 1000

# 3단계: 걸린 시간과 배수를 찍는다
print(f"{'담은 곳':<10}{'2,000번 찾기(ms)':>18}")
print(f"{'리스트':<10}{list_ms:>18.1f}")
print(f"{'딕셔너리':<9}{dict_ms:>18.3f}")
print(f"\n딕셔너리가 {list_ms/dict_ms:,.0f}배 빠르다")

# 출력 (시간은 돌릴 때마다 다르다):
# 3단계 뜻: 같은 2천 번 찾기에 리스트는 7초 가까이, 딕셔너리는 0.4밀리초쯤 걸린다. 배수는 돌릴 때마다 만 배 안팎에서 오르내린다.
# 담은 곳           2,000번 찾기(ms)
# 리스트                   6902.2
# 딕셔너리                  0.381
#
# 딕셔너리가 18,140배 빠르다
```

찍힌 값을 보면 같은 2천 번 찾기에 리스트는 6902.2밀리초(7초 가까이)가 걸렸지만 딕셔너리는 0.381밀리초로 끝나서 마지막 줄의 배수가 18,140배입니다. 채점 서버의 제한 시간은 보통 1초에서 2초라서 리스트를 쓴 코드는 이 찾기만으로도 시간 초과로 떨어집니다.

밀리초 값은 돌리는 기계에 따라 달라지고 배수도 돌릴 때마다 만 배 안팎을 오르내립니다. 그래도 리스트는 값을 하나씩 비교하고 딕셔너리는 자리를 계산한다는 방식의 차이는 기계와 상관이 없으므로, 두 줄이 서로 다른 종류라는 결론은 어디서 돌려도 같습니다.

찾는 코드는 두 곳 모두 `x in` 한 줄로 같고 값을 담은 자료형만 리스트와 딕셔너리로 달랐는데 시간이 만 배가 넘게 벌어졌으니, 두 줄의 차이는 코드가 아니라 자료형이 만들었습니다. **그래서 알고리즘 문제에서는 어떤 자료형에 값을 담느냐가 어떤 알고리즘을 쓰느냐만큼 실행 시간을 좌우합니다.**

## 2. 해시 — 값에서 자리를 계산하는 구조

**딕셔너리는 값을 하나씩 비교해 찾지 않고 그 값에서 자리를 계산한 다음 그 자리 하나만 확인합니다.**

1절에서 본 딕셔너리의 속도는 값을 넣고 찾는 방식이 리스트와 전혀 다른 데서 나옵니다. 딕셔너리 안에는 값을 넣어 둘 빈자리가 여러 개 줄지어 있는데 이 자리 하나하나를 슬롯(slot)이라고 부릅니다. 값을 넣을 때 파이썬은 먼저 그 값을 정수 하나로 바꿉니다. 이 정수를 **해시값**이라 부르며 `hash()` 함수로 직접 확인할 수 있습니다. 슬롯 번호는 이 해시값을 슬롯 개수로 나눈 나머지로 정합니다. 이렇게 값에서 해시값을 구하고 그 해시값으로 자리를 정해 넣고 찾는 방식을 **해시**라고 합니다.

아래 그림처럼 슬롯이 8개이고 값 17 의 해시값도 17 이라고 해 보겠습니다. 17 을 8 로 나누면 몫이 2 이고 나머지가 1 이므로 17 은 1번 슬롯에 들어갑니다. 나중에 17 을 찾을 때도 같은 계산으로 1번 슬롯을 구해 그 슬롯 하나만 열어 보면 되므로 다른 슬롯 7개는 볼 필요가 없습니다. **값을 하나씩 비교하는 스캔이 없으니 담긴 값이 20만 개든 2천만 개든 값 하나를 찾는 시간은 거의 같습니다.**

아래 그림에서는 값 4개를 같은 계산으로 슬롯 8개에 넣었습니다. 가운데 열의 `%` 는 나눗셈의 나머지를 구하는 파이썬 연산자로, `42 % 8 = 2` 는 42 를 8 로 나눈 나머지가 2 라는 뜻입니다.

## 3. 충돌 — 같은 슬롯에 두 값이 몰리는 경우

**서로 다른 값이 같은 슬롯을 가리키는 일을 충돌이라 하는데, 충돌이 심해지면 딕셔너리도 리스트처럼 느려집니다.**

2절의 그림에서는 17 과 9 가 같은 1번 슬롯을 가리켰습니다. 슬롯 수는 유한한데 넣을 수 있는 값은 끝이 없으니 이런 충돌은 피할 수 없습니다. 충돌이 나면 파이썬은 그 슬롯에 이미 있던 값이 새 값과 정말 같은 값인지 `==` 로 한 번 비교하고 다른 값이면 다음 빈 슬롯을 찾아 옮겨 담습니다. 충돌이 몇 번뿐이면 이렇게 더 하는 `==` 비교도 몇 번에 그쳐 걸리는 시간은 거의 늘지 않습니다.

그러나 모든 값이 한 슬롯으로 몰리면 사정이 달라집니다. 새 값을 넣을 때마다 그 슬롯에서 출발해 앞서 넣은 값들을 하나씩 `==` 로 비교하며 전부 지나쳐야 빈 슬롯에 닿으므로, 값을 넣는 일이 결국 리스트를 앞에서부터 스캔하는 것과 같아집니다.

딕셔너리는 `d[k] = v` 처럼 두 값을 짝지어 담습니다. 이 가운데 해시값을 구해 자리를 정하는 앞쪽 값 `k` 를 키(key)라고 부릅니다. 1절과 2절에서 자리를 계산한다고 한 「값」이 딕셔너리에서는 이 키입니다.

얼마나 느려지는지는 직접 만들어 보면 숫자로 보입니다. 아래 코드는 키를 두 가지로 만들어 각각 5천 개씩 딕셔너리에 넣고 넣는 데 걸린 시간을 비교합니다. `__hash__` 는 파이썬이 그 키의 해시값을 구할 때 부르는 메서드이고 `__eq__` 는 `==` 로 비교할 때 부르는 메서드입니다. 클래스에 이 두 메서드를 직접 정의하면 해시값과 비교 방법을 원하는 대로 정할 수 있습니다. 좋은 키(`GoodKey`)는 담은 숫자의 해시값을 그대로 돌려주므로 키마다 해시값이 다릅니다. 나쁜 키(`BadKey`)는 어떤 숫자를 담든 해시값으로 늘 7 을 돌려주므로 5천 개가 모두 같은 슬롯을 가리킵니다. 두 클래스 모두 `__eq__` 는 담은 숫자 `v` 가 같은지를 비교하므로 숫자가 다른 키끼리는 서로 다른 키로 남습니다.

```python
# 하는 일: 해시값이 값마다 다른 키와 늘 7 인 키를 만들어 딕셔너리에 5천 개씩 담고, 담는 데 걸린 시간을 비교한다.
import time

# 1단계: 좋은 키와 나쁜 키를 만든다
# 나쁜 키는 해시값을 일부러 7 로 고정해서 모든 값이 한 슬롯에 몰리게 만든다.
class GoodKey:
    def __init__(self, v): self.v = v
    def __hash__(self):    return hash(self.v)      # 값마다 다른 번호
    def __eq__(self, o):   return self.v == o.v

class BadKey:
    def __init__(self, v): self.v = v
    def __hash__(self):    return 7                 # 전부 같은 번호
    def __eq__(self, o):   return self.v == o.v

# 2단계: 키마다 5천 개를 담으며 시간을 측정한다
print(f"{'키':<8}{'담는 데 걸린 시간(ms)':>22}")
for name, K in (("좋은", GoodKey), ("나쁜", BadKey)):
    t = time.perf_counter()
    d = {K(i): i for i in range(5_000)}
    ms = (time.perf_counter() - t) * 1000
    print(f"{name:<8}{ms:>22.1f}")

# 출력 (시간은 돌릴 때마다 다르다):
# 2단계 뜻: 같은 5천 개인데 나쁜 키는 수백 배 오래 걸린다. 넣을 때마다 한 슬롯에 몰린 앞의 값들을 전부 지나치기 때문이다.
# 키               담는 데 걸린 시간(ms)
# 좋은                         1.6
# 나쁜                       701.9
```

찍힌 시간을 보면 같은 5천 개를 넣는 데 좋은 키는 1.6밀리초면 끝났지만 나쁜 키는 701.9밀리초로 수백 배 오래 걸려 0.7초쯤 더 썼습니다. 나쁜 키 가운데 첫 키는 지나칠 키가 없지만 두 번째 키는 앞의 키 1개를, 세 번째 키는 2개를 지나치는 식으로 넣을수록 지나칠 키가 하나씩 늘어나므로, 5천 개를 다 넣는 동안의 `==` 비교 횟수는 키 개수의 제곱에 비례합니다.

입력이 커질 때 시간이 어떤 모양으로 늘어나는지만 남겨 적는 방법을 빅오 표기라고 합니다. 앞 편에서 다룬 이 표기로는 개수의 제곱에 비례해 늘어나는 모양을 O(n²) 으로 적습니다. O(n²) 에서는 개수가 두 배가 되면 시간이 2의 제곱인 네 배가 되므로, 값 개수를 두 배로 늘리면 0.7초였던 이 차이도 네 배로 커집니다.

**그래서 「딕셔너리는 O(1)」이라는 말 뒤에는 조건이 하나 붙습니다.** O(1) 은 값이 몇 개든 넣기나 찾기 한 번에 드는 시간이 그대로라는 뜻입니다. 딕셔너리는 해시값이 슬롯 전체에 고르게 흩어질 때만 O(1) 이고 위의 나쁜 키처럼 모든 값이 한 슬롯에 몰리는 최악의 경우에는 한 번에 드는 시간이 값 개수에 비례해 늘어나는 O(n) 입니다. 다행히 파이썬 기본 자료형은 해시값이 잘 흩어지도록 만들어져 있어서 `__hash__` 를 직접 잘못 짜지 않는 한 코딩 테스트에서 이런 최악을 만날 일은 거의 없습니다.

:::deep 슬롯이 모자랄 때 — 재배치와 amortized

딕셔너리의 슬롯 개수는 고정되어 있지 않습니다. 들어 있는 값이 슬롯 수의 3분의 2 정도에 이르면 파이썬은 슬롯 개수를 늘립니다. 슬롯 개수가 바뀌면 해시값을 슬롯 개수로 나눈 나머지도 달라지므로 이미 들어 있던 키의 자리를 전부 다시 구해 새 자리로 옮기는데, 이 작업을 재배치(rehash)라고 합니다. 이때 해시 함수를 다시 부르지는 않고 키를 넣을 때 적어 둔 해시값을 씁니다.

재배치가 일어나는 그 한 번은 들어 있던 값을 모두 옮겨야 해서 값 개수에 비례하는 O(n) 이 걸리지만 「딕셔너리에 넣기는 O(1)」이라는 말이 그 때문에 틀리지는 않습니다. 파이썬은 슬롯 수를 늘릴 때마다 일정한 배수로 키우므로 한 번 키운 뒤에는 다음 재배치까지 넣을 수 있는 값도 그만큼 많아져 재배치가 갈수록 드물어집니다.

값을 n개 넣는 동안 재배치에 쓴 시간을 모두 더해도 n 에 비례하는 정도라서 넣기 한 번의 평균 시간은 상수로 남습니다. 이렇게 가끔은 비싸도 평균을 내면 싼 경우를 **amortized O(1)** 이라고 부릅니다.

파이썬 리스트의 `append` 도 같은 구조입니다. 리스트도 칸이 모자라면 더 큰 공간을 새로 잡아 값을 전부 옮기지만 늘릴 때마다 일정한 비율로 여유를 두므로 `append` 한 번의 평균 시간은 상수입니다. 면접에서 「리스트 append 는 왜 O(1) 인가」를 물으면 이 amortized 이야기로 답하면 됩니다.
:::

## 4. 키로 쓸 수 있는 자료형

**딕셔너리는 키에서 자리를 계산해 넣으므로 키는 넣은 뒤에 바뀌면 안 됩니다.**

격자 문제(가로세로로 나뉜 칸 위를 움직이는 문제)에서는 좌표 `(x, y)` 처럼 값 두 개를 하나의 키로 써야 할 때가 자주 있는데, 이때 리스트로 묶어 키로 쓰면 파이썬이 막습니다. 리스트는 만든 뒤에도 내용을 바꿀 수 있습니다. 내용으로 해시값을 구한다면 내용이 바뀔 때 해시값도 따라 바뀌어 처음 넣을 때와 나중에 찾을 때 계산하는 슬롯이 달라지므로, 파이썬은 리스트에 해시값을 아예 주지 않습니다. 튜플은 값 여러 개를 순서대로 묶은 자료형으로, 한 번 만들면 내용을 바꿀 수 없어서 키로 쓸 수 있습니다.

아래 코드의 1단계는 튜플 `(3, 5)` 와 리스트 `[3, 5]` 를 각각 키로 넣어 봅니다. 2단계에서는 정수 3 과 실수 3.0 을 같은 딕셔너리에 차례로 키로 넣습니다.

```python
# 하는 일: 튜플과 리스트를 딕셔너리 키로 넣어 보고, 3 과 3.0 을 같은 딕셔너리에 넣으면 무슨 일이 생기는지 본다.
# 1단계: 튜플과 리스트를 키로 넣어 본다
# 키는 넣은 뒤에 바뀌면 안 된다. 튜플은 못 바꾸니 되고, 리스트는 바꿀 수 있으니 막힌다.
좌표 = {}
좌표[(3, 5)] = "가"          # 튜플은 된다
print("튜플 키 ", 좌표)

try:
    좌표[[3, 5]] = "나"      # 리스트는 안 된다
except TypeError as e:
    print("리스트 키", type(e).__name__, "-", e)

# 2단계: 3 과 3.0 을 키로 넣는다
print()
print("hash(3) =", hash(3), " hash(3.0) =", hash(3.0), " 3 == 3.0 :", 3 == 3.0)
d = {3: "정수로 넣음"}
d[3.0] = "실수로 덮어씀"
print("d =", d, " 항목 수", len(d))

# 출력:
# 1단계 뜻: 튜플 키는 들어가고, 리스트 키는 해시값을 못 구해 TypeError 가 난다.
# 튜플 키  {(3, 5): '가'}
# 리스트 키 TypeError - unhashable type: 'list'
# 2단계 뜻: 3 과 3.0 은 같고 해시값도 같아서 같은 키로 본다. 3.0 으로 넣은 값이 3 의 값을 덮어써 항목이 하나만 남는다.
#
# hash(3) = 3  hash(3.0) = 3  3 == 3.0 : True
# d = {3: '실수로 덮어씀'}  항목 수 1
```

1단계에서 튜플 키는 `{(3, 5): '가'}` 로 들어갔지만 리스트 키는 해시값을 구할 수 없어 `TypeError - unhashable type: 'list'` 오류가 났습니다. unhashable 은 해시값을 구할 수 없다는 뜻입니다.

2단계가 더 재미있습니다. 찍힌 줄에서 `hash(3)` 과 `hash(3.0)` 은 둘 다 3 이고 `3 == 3.0` 은 True 입니다. 해시값이 같아서 3.0 은 3 이 들어 있는 슬롯을 가리키는데 3절에서 본 `==` 비교에서도 두 값이 같다고 나오므로, 딕셔너리는 3 과 3.0 을 **같은 키**로 봅니다. 그래서 `d[3.0] = "실수로 덮어씀"` 은 새 항목을 만들지 않고 키 3 의 값만 덮어씁니다. 찍힌 `d` 를 보면 키는 처음 넣은 정수 3 그대로이고 값만 '실수로 덮어씀' 으로 바뀌어 항목 수가 1 입니다.

같은 키로 덮어써지는 일은 나눗셈 결과를 키로 쓸 때 실제로 문제가 됩니다. 나눗셈 결과는 실수라서 정수로 넣어 둔 키와 섞이면 오류 하나 없이 앞의 값이 덮어써집니다. **그래서 키로 쓸 값은 자료형을 하나로 맞춰 두는 편이 안전합니다.**

| 키로 쓸 수 있나 | 자료형 | 이유 |
|---|---|---|
| 된다 | 정수, 실수, 문자열, 튜플, `frozenset` | 만든 뒤 못 바꿉니다 |
| 안 된다 | 리스트, 딕셔너리, 집합 | 내용이 바뀔 수 있어 해시값이 없습니다 |
| 조건부 | 직접 만든 클래스 | `__hash__` 와 `__eq__` 를 짝 맞춰 정의해야 합니다 |

표의 `frozenset` 은 만든 뒤에 바꿀 수 없는 집합입니다. 격자 문제에서 계속 나오는 `방문[(x, y)] = True` 는 칸 `(x, y)` 에 이미 가 봤다고 적어 두는 코드로, 좌표 두 개를 튜플로 감싸 키로 쓴 꼴입니다. 좌표가 아니라 이름 여러 개를 조합해 키로 쓰고 싶을 때도 똑같이 튜플로 감싸면 됩니다.

## 5. 두 수의 합 — 딕셔너리를 쓴 한 번 순회

**더해서 목표가 되는 두 수를 찾는 문제는 지금까지 본 값을 딕셔너리에 적어 두면 값을 한 번만 지나가며 풀 수 있습니다.**

값 두 개씩 고른 짝을 전부 만들어 더해 보는 방법은 값이 n개일 때 비교 횟수가 n² 에 비례하므로 3절의 나쁜 키와 같은 O(n²) 입니다. 그런데 지금 보는 값이 정해지면 그 값과 더해 목표가 되는 짝도 하나로 정해집니다. 목표가 10 이고 지금 값이 7 이면 필요한 짝은 10 에서 7 을 뺀 3 하나뿐입니다.

그러면 남은 일은 3 이 앞에 이미 나왔는지 확인하는 것 하나인데, 이 확인은 2절에서 본 대로 딕셔너리가 자리를 계산해 바로 해 줍니다. 값을 처음부터 끝까지 하나씩 차례로 보는 일을 순회라고 합니다. **지금까지 본 값을 딕셔너리에 적어 두면 지금 값의 짝이 앞에 있었는지를 바로 확인할 수 있으므로 값을 한 번만 순회하면 됩니다.**

아래 코드는 값 6개 `[8, 3, 11, 7, 2, 15]` 에서 더해 10 이 되는 두 칸을 찾습니다. `seen` 은 지금까지 본 값마다 그 값이 있던 칸 번호를 짝지어 적어 두는 딕셔너리입니다. 출력의 「지금까지 본 값→칸」 열에 그때까지 적힌 내용이 찍힙니다. 칸마다 짝 `need` 를 `TARGET - v` 로 구해 `seen` 에 있는지 묻고 없으면 지금 값과 칸 번호를 `seen` 에 적은 뒤 다음 칸으로 갑니다.

```python
# 하는 일: 값 6개에서 더해 10 이 되는 두 칸을, 지금까지 본 값을 딕셔너리에 적어 두며 한 번만 순회해서 찾는다.
ARR, TARGET = [8, 3, 11, 7, 2, 15], 10

print("칸  값   지금까지 본 값→칸        찾는 짝    있나")
seen = {}
for i, v in enumerate(ARR):
    need = TARGET - v
    hit  = need in seen
    print(f"{i}  {v:>3}   {str(seen):<24} {need:>4}    {'있다 → 답 ' + str((seen.get(need), i)) if hit else '없다'}")
    if hit:
        break
    seen[v] = i

# 출력:
# 뜻: 칸마다 짝(10 에서 지금 값을 뺀 수)이 이미 적혀 있는지 본다. 3번 칸의 7 에서 짝 3 이 1번 칸에 적혀 있어 멈춘다.
# 칸  값   지금까지 본 값→칸        찾는 짝    있나
# 0    8   {}                          2    없다
# 1    3   {8: 0}                      7    없다
# 2   11   {8: 0, 3: 1}               -1    없다
# 3    7   {8: 0, 3: 1, 11: 2}         3    있다 → 답 (1, 3)
```

찍힌 표를 위에서부터 따라가 보겠습니다. 0번 칸의 8 이 찾는 짝 2 는 `seen` 이 아직 비어 있어 찾지 못합니다. 1번 칸의 3 이 찾는 짝 7 은 그때 적혀 있던 `{8: 0}` 에 없고 2번 칸의 11 이 찾는 짝 -1 도 `{8: 0, 3: 1}` 에서 찾지 못합니다. 3번 칸의 7 에 와서야 찾는 짝 3 이 `seen` 에 1번 칸으로 적혀 있어 반복을 멈추는데, 3 + 7 = 10 이므로 답 `(1, 3)` 은 1번 칸과 3번 칸을 가리킵니다.

<figcaption style="margin-top:0.75rem; font-size:0.9rem; color:var(--text-muted)">회차마다 뺄셈 한 번으로 필요한 짝을 구하고 그 짝이 적어 둔 값 안에 있는지 한 번 묻습니다. 두 일 모두 값 개수와 상관없이 일정한 시간(상수 시간)이 걸리므로 값 n개를 한 번 순회하는 전체 시간은 O(n) 입니다.</figcaption>
</figure>

이 구조를 한 번 익혀 두면 두 수의 합이 아닌 문제에도 쓸 수 있습니다. **「지금 보는 값에 필요한 짝이 하나로 정해지는가」를 물어 그렇다는 답이 나오면 이 방법이 통합니다.** 두 수의 차가 K 인 짝을 찾는 문제(짝 후보가 지금 값보다 K 큰 수와 K 작은 수 두 개라 둘 다 묻습니다), 합이 0 인 짝을 찾는 문제, 나머지가 같은 짝을 찾는 문제도 같은 꼴이라 같은 방법으로 풉니다.

## 6. 세는 일 — get, defaultdict, Counter

**값마다 몇 번 나왔는지 세는 코드는 파이썬이 주는 `get`, `defaultdict`, `Counter` 세 가지 가운데 하나로 짧게 씁니다.**

세는 코드에서 초보가 가장 자주 내는 오류는 아직 딕셔너리에 없는 키를 읽다가 나는 `KeyError` 입니다. `count[w] += 1` 은 1 을 더하기 전에 `count[w]` 의 지금 값을 먼저 읽으므로, `w` 가 처음 나온 낱말이면 읽을 키가 없어 `KeyError` 를 내고 멈춥니다. 처음 나온 낱말인지를 매번 `if` 로 확인하면 피할 수 있지만 그러면 코드가 지저분해지므로, 파이썬은 이 확인을 짧게 쓰는 방법을 세 가지 줍니다.

`get` 은 딕셔너리에 원래 있는 메서드로, 키가 없을 때 정해 준 기본값을 돌려줍니다. 코드의 `count.get(w, 0)` 은 처음 나온 낱말에 0 을 내주므로 `if` 없이 1 을 더할 수 있습니다. `defaultdict` 는 `collections` 모듈에 있는 딕셔너리로, 없는 키를 읽으면 오류를 내지 않고 정해 둔 기본값을 그 자리에서 만들어 줍니다. `defaultdict(list)` 는 기본값이 빈 리스트라서 처음 나온 낱말에도 `append` 를 바로 부를 수 있습니다. `Counter` 도 `collections` 모듈에 있는 딕셔너리로, 목록을 넣으면 값마다 개수를 한 번에 세어 줍니다.

아래 코드는 낱말 6개 `["사과", "배", "사과", "귤", "배", "사과"]` 를 세 방법으로 다룹니다. 1단계는 `get` 으로 세고 2단계는 `defaultdict` 로 낱말마다 나온 칸 번호를 모으며 3단계는 `Counter` 로 다시 세어 가장 많이 나온 두 낱말까지 찍습니다.

```python
# 하는 일: 낱말 6개를 담은 목록에서 낱말마다 몇 번 나왔는지를 get 과 Counter 로 세고, defaultdict 로는 나온 칸 번호를 모은다.
from collections import Counter, defaultdict

WORDS = ["사과", "배", "사과", "귤", "배", "사과"]

# 1단계: get 으로 센다
# 처음 나온 낱말은 get 이 0 을 돌려주니 if 로 따로 확인하지 않는다.
count = {}
for w in WORDS:
    count[w] = count.get(w, 0) + 1
print("get 으로     ", count)

# 2단계: defaultdict 로 칸 번호를 모은다
# 처음 나온 낱말에는 빈 리스트가 저절로 생긴다.
bag = defaultdict(list)
for i, w in enumerate(WORDS):
    bag[w].append(i)
print("defaultdict ", dict(bag))

# 3단계: Counter 로 센다
c = Counter(WORDS)
print("Counter     ", dict(c))
print("가장 많은 둘 ", c.most_common(2))

# 출력:
# 1단계 뜻: 사과 3번, 배 2번, 귤 1번이다.
# get 으로      {'사과': 3, '배': 2, '귤': 1}
# 2단계 뜻: 낱말마다 나온 칸 번호를 모았다. 사과는 0, 2, 5번 칸에 있다.
# defaultdict  {'사과': [0, 2, 5], '배': [1, 4], '귤': [3]}
# 3단계 뜻: get 으로 센 것과 같다. most_common(2) 는 가장 많이 나온 둘을 개수와 함께 준다.
# Counter      {'사과': 3, '배': 2, '귤': 1}
# 가장 많은 둘  [('사과', 3), ('배', 2)]
```

1단계의 `get` 과 3단계의 `Counter` 는 둘 다 사과 3번, 배 2번, 귤 1번으로 셌습니다. `most_common(2)` 는 그 가운데 가장 많이 나온 낱말 2개를 개수와 함께 `[('사과', 3), ('배', 2)]` 로 돌려줬습니다. 2단계의 `defaultdict` 는 개수가 아니라 칸 번호를 모았는데, 사과는 0번과 2번과 5번 칸에, 배는 1번과 4번 칸에, 귤은 3번 칸에 있었습니다.

세 방법은 쓰임이 조금씩 다릅니다. `get` 은 `from collections import` 같은 가져오기 줄 없이 바로 쓸 수 있으므로 세는 일 하나만 할 때는 `get` 으로 충분합니다. `defaultdict` 는 키마다 리스트나 집합에 여러 값을 모아야 할 때 편합니다. 위 2단계처럼 「이 값이 몇 번 칸들에 있었나」를 모을 때 자주 씁니다.

`Counter` 는 세는 일 전용이라 세는 코드가 가장 짧고 `most_common` 같은 기능이 딸려 있습니다. 두 `Counter` 를 빼면 낱말마다 개수의 차이도 바로 나옵니다. 애너그램(글자의 순서만 바꿔 만든 낱말)이나 문자 개수를 비교하는 문제는 `Counter` 를 쓰면 한 줄로 끝나는 경우가 많습니다.

> **주의 한 가지** — `defaultdict` 는 없는 키를 **읽기만 해도** 그 키가 생깁니다. 그래서 `if bag[w]:` 처럼 키가 있는지 보려고 쓴 코드도 키를 조용히 늘리므로, 확인할 때는 키를 만들지 않는 `if w in bag:` 를 씁니다.

## 7. 집합 연산 — 두 목록의 겹침과 차이

**두 목록을 비교하는 문제는 반복문을 짜지 않아도 집합 연산 한 줄로 답이 나오는 경우가 많습니다.**

「어제 왔는데 오늘 안 온 사람」을 찾는다고 해 보겠습니다. 어제 온 사람마다 오늘 명단을 처음부터 확인하는 이중 반복문(반복문 안에 반복문을 넣은 코드)으로 짜면 O(n²) 이고 코드도 길어집니다. 집합 연산은 두 집합 사이의 겹침이나 차이를 `&`, `-`, `|`, `^` 같은 기호 하나로 구하는 계산입니다. 두 명단을 집합으로 바꾸면 이 물음은 `어제 - 오늘` 하나로 끝납니다.

아래 코드는 어제 온 4명과 오늘 온 4명을 집합으로 담고 기호 4개로 연산 다섯 가지를 해 본 뒤 어제 왔다가 오늘 안 온 사람의 비율인 이탈률을 구합니다. 집합에는 순서가 없으므로 코드는 결과마다 `sorted` 를 붙여 이름을 가나다순으로 늘어놓아 찍습니다.

```python
# 하는 일: 어제 온 4명과 오늘 온 4명을 집합 연산 다섯 가지로 비교하고, 어제 왔다가 오늘 안 온 비율을 구한다.
어제 = {"지훈", "민서", "서연", "도윤"}
오늘 = {"민서", "서연", "하준", "지우"}

print("둘 다 왔다 (교집합)  ", sorted(어제 & 오늘))
print("어제만 (차집합)      ", sorted(어제 - 오늘))
print("오늘 새로 온 사람     ", sorted(오늘 - 어제))
print("한 번이라도 (합집합) ", sorted(어제 | 오늘))
print("한쪽에만 (대칭차)    ", sorted(어제 ^ 오늘))
print()
print("이탈률", f"{len(어제 - 오늘) / len(어제):.1%}")

# 출력:
# 뜻: 기호 하나가 질문 하나다. & 는 둘 다, - 는 이쪽에만, | 는 한 번이라도, ^ 는 한쪽에만 있는 사람이다.
# 둘 다 왔다 (교집합)   ['민서', '서연']
# 어제만 (차집합)       ['도윤', '지훈']
# 오늘 새로 온 사람      ['지우', '하준']
# 한 번이라도 (합집합)  ['도윤', '민서', '서연', '지우', '지훈', '하준']
# 한쪽에만 (대칭차)     ['도윤', '지우', '지훈', '하준']
# 뜻: 어제 온 4명 가운데 지훈과 도윤 2명이 오늘 안 왔다.
#
# 이탈률 50.0%
```

찍힌 줄을 차례로 보면 `어제 & 오늘` 은 둘 다 온 민서와 서연이고 `어제 - 오늘` 은 어제만 온 도윤과 지훈입니다. `-` 는 앞에 쓴 집합에만 있는 사람을 남기므로 빼는 순서를 바꾼 `오늘 - 어제` 는 오늘 새로 온 지우와 하준입니다. `어제 | 오늘` 은 한 번이라도 온 6명 전부이고 `어제 ^ 오늘` 은 어제와 오늘 가운데 한쪽에만 온 4명입니다.

코드는 이탈률을 `len(어제 - 오늘) / len(어제)` 로 구합니다. 어제 온 4명 가운데 지훈과 도윤 2명이 오늘 오지 않았으므로 2 를 4 로 나눈 50.0% 가 찍혔습니다.

기호 4개는 문제 지문에 흔히 나오는 질문과 하나씩 대응합니다. 교집합(`&`)은 「둘 다」, 차집합(`-`)은 「이쪽에만」, 합집합(`|`)은 「한 번이라도」, 대칭차(`^`)는 「한쪽에만」에 해당하므로 지문을 읽다가 이런 표현이 나오면 집합 연산을 먼저 떠올리면 됩니다.

광고에서는 오디언스 세그먼트를 다룰 때 이 연산을 그대로 씁니다. 오디언스 세그먼트는 광고를 보여 줄 대상으로 골라 묶은 사용자 그룹입니다. 두 세그먼트가 얼마나 겹치는지는 교집합의 크기이고 이쪽 세그먼트에만 있는 사용자가 몇 명인지는 차집합의 크기입니다. 자세한 이야기는 [오디언스 세그멘테이션](post.html?id=audience-segmentation) 편에 있습니다.

## 8. 정렬 — key 로 정하는 기준

**해시로 풀리지 않는 문제도 있는데 그런 문제에는 정렬을 꺼냅니다.**

해시는 「이 값이 있나」에는 강하지만 「이 값보다 큰 것 가운데 가장 작은 것」을 묻는 데는 아무 도움이 되지 않는데, 값을 슬롯 전체에 흩어 놓는 것이 목적이라 값의 크기 순서를 아예 버리기 때문입니다. 2절의 그림에서도 30 은 42 보다 작은데 42 가 들어간 2번 슬롯보다 뒤인 6번 슬롯에 들어갔고 9 는 17 보다 작은데 17 과 같은 1번 슬롯을 가리키므로, 슬롯 순서만 봐서는 값의 크기 순서를 알 수 없습니다.

값을 정한 기준에 따라 작은 것부터 또는 큰 것부터 차례로 늘어놓는 작업을 정렬이라고 합니다. 순서가 필요한 순간에는 이 정렬을 씁니다. 파이썬에서 `sorted` 는 정렬한 새 리스트를 만들어 돌려주는 함수이고 `list.sort` 는 리스트 자체를 정렬해 바꾸는 메서드입니다. 둘 다 O(n log n) 입니다. O(n log n) 은 비교 횟수가 값 개수 n 에 log n 을 곱한 값에 비례한다는 뜻으로, 값이 십만 개면 대략 170만 번쯤 비교합니다. 이 정도는 채점 서버가 충분히 견디는 양이라 **입력이 십만 개까지라면 「일단 정렬」은 거의 항상 안전한 선택입니다.**

정렬에서 따로 익혀 둘 부분은 알고리즘이 아니라 `key` 사용법입니다. `key` 는 원소마다 무엇을 기준으로 비교할지 정하는 함수로, 파이썬은 원소 자체를 비교하지 않고 `key` 가 그 원소에 돌려준 값을 비교합니다. 아래 코드의 `lambda s: s[2]` 는 원소 `s` 를 받아 `s[2]` 를 돌려주는 짧은 함수라 학생 `(이름, 반, 점수)` 에서 세 번째 원소인 점수를 기준으로 삼습니다. 코드는 학생 4명을 점수 오름차순(작은 점수부터)과 내림차순(큰 점수부터)으로 정렬해 이름 순서를 찍습니다.

```python
# 하는 일: 학생 4명을 점수 오름차순과 내림차순으로 정렬해 이름 순서를 찍는다.
학생 = [("지훈", 3, 88), ("민서", 1, 92), ("서연", 3, 92), ("도윤", 1, 88)]
# (이름, 반, 점수)

print("원본        ", [s[0] for s in 학생])
print("점수만 정렬  ", [s[0] for s in sorted(학생, key=lambda s: s[2])])
print("점수 내림차순", [s[0] for s in sorted(학생, key=lambda s: -s[2])])

# 출력:
# 뜻: sorted 는 key 가 돌려준 점수로 비교한다. 내림차순은 key 에서 점수에 - 를 붙여 만들었다.
# 원본         ['지훈', '민서', '서연', '도윤']
# 점수만 정렬   ['지훈', '도윤', '민서', '서연']
# 점수 내림차순 ['민서', '서연', '지훈', '도윤']
```

원본은 지훈, 민서, 서연, 도윤 순입니다. 「점수만 정렬」 줄은 `sorted` 가 학생을 직접 비교하지 않고 `key` 가 돌려준 점수 88 과 92 를 비교했으므로 88점인 지훈과 도윤이 앞에, 92점인 민서와 서연이 뒤에 왔습니다. 점수가 같은 학생끼리는 원본의 순서가 그대로 남아 지훈이 도윤보다, 민서가 서연보다 앞에 있습니다. 이 성질은 다음 절에서 안정 정렬이라는 이름으로 다시 다룹니다.

「점수 내림차순」 줄은 `key` 에서 점수에 마이너스 부호를 붙여 만들었습니다. 부호를 붙이면 92점이 88점보다 작은 값이 되므로 작은 값부터 늘어놓는 정렬을 그대로 해도 92점인 민서와 서연이 앞에 옵니다. `reverse=True` 를 넘겨도 내림차순은 되지만 여기서 일부러 `-s[2]` 로 쓴 데는 까닭이 있습니다. 기준이 두 개 이상이 되면 두 방법의 결과가 달라질 수 있는데, 그 차이를 다음 절에서 봅니다.

## 9. 안정 정렬 — 기준이 두 개 이상인 경우

**파이썬의 정렬은 기준값이 같은 원소끼리 정렬 전의 순서를 그대로 지키는 안정 정렬입니다.**

기준이 하나뿐이면 같은 값끼리의 순서를 신경 쓸 일이 없지만 「점수 높은 순으로, 점수가 같으면 반 번호 작은 순으로」처럼 기준이 두 겹이 되면 점수가 같은 학생끼리의 순서까지 맞춰야 합니다. 두 겹 기준은 기준마다 따로 두 번 정렬하거나 두 기준을 튜플로 묶어 `key` 로 한 번에 정렬하면 맞출 수 있습니다. 두 번 정렬할 때는 덜 중요한 기준인 반 번호로 먼저 정렬하고 그 결과를 더 중요한 기준인 점수로 다시 정렬합니다. 튜플 `key` 는 정렬이 안정 정렬이 아니어도 성립하지만 두 번 정렬하는 방법은 안정 정렬일 때만 성립합니다.

아래 코드는 같은 학생 4명을 두 방법으로 정렬해 결과를 나란히 찍습니다. 두 번 정렬하는 방법은 1단계(반 번호)와 2단계(점수 내림차순)의 결과를 한 줄씩 보여 줍니다. 한 번에 정렬하는 방법은 `key` 가 `(-s[2], s[1])` 로 마이너스 점수와 반 번호를 묶은 튜플을 돌려줍니다.

```python
# 하는 일: 「점수 높은 순, 점수가 같으면 반 번호 작은 순」을 두 번 나눠 정렬하는 방법과 튜플 key 로 한 번에 정렬하는 방법으로 만들어 비교한다.
학생 = [("지훈", 3, 88), ("민서", 1, 92), ("서연", 3, 92), ("도윤", 1, 88)]

print("반 먼저 정렬 후 점수로 다시 정렬:")
tmp = sorted(학생, key=lambda s: s[1])
print("  1단계 반   ", [(s[0], s[1]) for s in tmp])
tmp = sorted(tmp, key=lambda s: -s[2])
print("  2단계 점수 ", [(s[0], s[2], s[1]) for s in tmp])
print()
print("한 번에 (점수 내림, 반 오름):")
one = sorted(학생, key=lambda s: (-s[2], s[1]))
print("            ", [(s[0], s[2], s[1]) for s in one])

# 출력:
# 뜻: 반으로 먼저 정렬한 뒤 점수로 다시 정렬했다. 점수가 같은 학생끼리는 첫 정렬에서 만든 반 순서를 그대로 지킨다.
# 반 먼저 정렬 후 점수로 다시 정렬:
#   1단계 반    [('민서', 1), ('도윤', 1), ('지훈', 3), ('서연', 3)]
#   2단계 점수  [('민서', 92, 1), ('서연', 92, 3), ('도윤', 88, 1), ('지훈', 88, 3)]
# 뜻: 기준 둘을 튜플로 묶어 한 번에 정렬해도 결과가 글자 하나까지 같다.
#
# 한 번에 (점수 내림, 반 오름):
#              [('민서', 92, 1), ('서연', 92, 3), ('도윤', 88, 1), ('지훈', 88, 3)]
```

1단계 줄은 반 번호로만 정렬해 1반인 민서와 도윤이 앞에, 3반인 지훈과 서연이 뒤에 놓였습니다. 2단계 줄에서 점수로 다시 정렬하자 92점인 민서와 서연이 앞으로, 88점인 도윤과 지훈이 뒤로 갔습니다. 점수가 같은 학생끼리는 1단계의 반 순서가 그대로 남아 민서가 서연보다, 도윤이 지훈보다 앞에 있습니다. 2단계 정렬이 안정 정렬이라 1단계에서 만든 반 순서를 지켰기 때문에 「점수가 같으면 반 번호 작은 순」이 따로 손대지 않아도 맞았습니다.

튜플 `key` 로 한 번에 정렬한 줄도 민서, 서연, 도윤, 지훈 순으로 2단계 줄과 글자 하나까지 같습니다. 튜플은 앞 원소부터 비교하고 앞 원소가 같을 때만 다음 원소를 비교하므로, `(-s[2], s[1])` 은 점수가 높은 학생을 먼저 놓고 점수가 같을 때만 반 번호가 작은 학생을 앞에 놓습니다.

아래 그림에는 원본과 1단계와 2단계가 한 줄씩 있습니다. 화살표는 92점인 민서와 서연이 1단계의 앞뒤 순서 그대로 2단계에 놓였음을 나타냅니다.

실무에서는 정렬을 한 번만 해서 더 빠르고 기준이 코드 한 줄에 모두 적혀 있어 읽기도 쉬운 튜플 `key` 가 낫습니다. 숫자 기준은 `-s[2]` 처럼 마이너스 부호를 붙여 방향을 뒤집으면 튜플 하나로 정렬할 수 있지만 문자열에는 부호를 붙일 수 없으므로, 두 번 정렬하는 방법은 **문자열 기준 두 개를 서로 반대 방향으로 정렬해야 해서** 튜플로 묶을 수 없을 때 씁니다.

`reverse=True` 에는 헷갈리기 쉬운 점이 있습니다. `reverse=True` 로 정렬해도 기준값이 같은 원소끼리의 순서는 뒤집히지 않습니다. 다만 `reverse=True` 는 `key` 가 돌려준 값 전체의 순서를 뒤집으므로 두 겹 기준에 쓰면 두 번째 기준의 방향까지 뒤집혀 의도와 반대가 되기 쉽습니다. 예를 들어 `key` 로 `(점수, 반)` 튜플을 주고 `reverse=True` 로 정렬하면 점수는 높은 순이 되지만 반 번호도 큰 순이 되어 92점끼리는 3반인 서연이 1반인 민서보다 앞에 옵니다. **그래서 내림차순이 필요하면 숫자 기준에는 음수 부호를 붙이는 편이 안전합니다.**

광고에서는 eCPM 으로 광고 순위를 매길 때 이 두 겹 기준이 매일 돌아갑니다. eCPM 은 광고마다 계산한 예상 수익입니다. 광고를 이 예상 수익 순으로 정렬하되 값이 같으면 다른 기준으로 순서를 나눕니다. 이 순위 매기기의 구조는 [eCPM 랭킹](post.html?id=ecpm-ranking) 편에서 자세히 다룹니다.

## 10. 정렬한 뒤의 한 번 순회 — 구간 병합과 세 수의 합

**정렬이 주는 이득은 정렬 그 자체보다, 정렬해 두면 한 번만 순회해도 풀리는 문제로 바뀐다는 데 있습니다.**

겹치는 구간을 하나로 합치는 구간 병합 문제부터 보겠습니다. 구간은 `(시작, 끝)` 튜플로 적고 `(1, 4)` 는 1 부터 4 까지를 뜻합니다. 정렬하지 않은 채로는 어느 구간이 어느 구간과 겹칠지 알 수 없어 모든 구간 쌍을 비교해야 하므로 O(n²) 입니다.

구간을 시작점 순으로 정렬해 두면 겹칠 수 있는 구간끼리 옆에 붙으므로 **바로 앞에서 합친 구간 하나만 보면 됩니다.** 지금 보는 구간의 시작이 마지막으로 합친 구간의 끝보다 작거나 같으면 두 구간은 겹친 것이므로 마지막 구간의 끝을 늘려 하나로 합칩니다. 시작이 그 끝보다 크면 두 구간은 떨어져 있으므로 새 구간을 엽니다.

아래 코드는 구간 5개를 1단계에서 시작점 순으로 정렬하고 2단계에서 한 번 순회하며 합칩니다. 1단계의 `sorted(구간)` 은 9절에서 본 대로 튜플을 앞 원소부터 비교하므로 `key` 를 주지 않아도 앞 원소인 시작점 순서가 됩니다. 2단계가 찍는 표에서 「보는 구간」은 지금 보는 구간, 「마지막 구간」은 마지막으로 합친 구간, 「판정」은 두 구간을 비교한 식, 「결과」는 그때까지 합친 구간들입니다.

```python
# 하는 일: 구간 5개를 시작점 순으로 정렬한 뒤 한 번만 순회하며 겹치는 구간을 합친다.
구간 = [(13, 15), (1, 4), (9, 12), (3, 6), (14, 18)]

# 1단계: 시작점 순으로 정렬한다
# 튜플은 앞 원소부터 비교하니 sorted 한 번이면 시작점 순서가 된다.
정렬 = sorted(구간)
print("정렬 전", 구간)
print("정렬 후", 정렬)
print()

# 2단계: 마지막으로 합친 구간 하나와만 비교하며 합친다
# 지금 구간의 시작이 마지막으로 합친 구간의 끝보다 작거나 같으면 겹친 것이라 끝을 늘린다. 크면 새 구간을 연다.
merged = [정렬[0]]
print(f"{'보는 구간':<10}{'마지막 구간':<12}{'판정':<22}{'결과'}")
for s, e in 정렬[1:]:
    ls, le = merged[-1]
    if s <= le:
        merged[-1] = (ls, max(le, e))
        판정 = f"{s} ≤ {le} 겹친다"
    else:
        merged.append((s, e))
        판정 = f"{s} > {le} 떨어졌다"
    print(f"{str((s,e)):<10}{str((ls,le)):<12}{판정:<22}{merged}")
print()
print("답", merged)

# 출력:
# 1단계 뜻: 정렬하면 겹칠 수 있는 구간끼리 옆에 붙는다.
# 정렬 전 [(13, 15), (1, 4), (9, 12), (3, 6), (14, 18)]
# 정렬 후 [(1, 4), (3, 6), (9, 12), (13, 15), (14, 18)]
#
# 2단계 뜻: 네 번 비교해 겹친 두 곳을 합쳤다. 구간 5개가 3개로 합쳐진다.
# 보는 구간     마지막 구간      판정                    결과
# (3, 6)    (1, 4)      3 ≤ 4 겹친다             [(1, 6)]
# (9, 12)   (1, 6)      9 > 6 떨어졌다            [(1, 6), (9, 12)]
# (13, 15)  (9, 12)     13 > 12 떨어졌다          [(1, 6), (9, 12), (13, 15)]
# (14, 18)  (13, 15)    14 ≤ 15 겹친다           [(1, 6), (9, 12), (13, 18)]
#
# 답 [(1, 6), (9, 12), (13, 18)]
```

1단계에서 정렬하자 서로 겹치는 `(1, 4)` 와 `(3, 6)`, `(13, 15)` 와 `(14, 18)` 이 각각 옆자리에 놓였습니다. 2단계 표를 위에서부터 따라가면 `(3, 6)` 은 시작 3 이 마지막 구간 `(1, 4)` 의 끝 4 보다 작거나 같아 겹치므로 끝을 6 으로 늘려 `(1, 6)` 이 됩니다. `(9, 12)` 는 시작 9 가 `(1, 6)` 의 끝 6 보다 커서 새 구간으로 열리고 `(13, 15)` 도 13 이 12 보다 커서 새 구간으로 들어갑니다. 끝으로 `(14, 18)` 은 14 가 15 보다 작거나 같아 겹치므로 `(13, 15)` 의 끝을 18 로 늘립니다. 이렇게 네 번 비교하는 동안 겹친 두 곳을 합쳐 구간 5개가 답 `[(1, 6), (9, 12), (13, 18)]` 의 3개로 줄었습니다.

지금 구간이 마지막 구간 안에 모두 들어 있으면 끝을 줄이면 안 되므로, 코드는 끝을 늘릴 때 `max(le, e)` 로 마지막 구간의 끝 `le` 와 지금 구간의 끝 `e` 가운데 큰 값을 남깁니다. 아래 그림의 위쪽은 정렬한 구간 5개를 막대로, 아래쪽은 합친 결과 3개를 굵은 막대로 그렸습니다.

정렬은 앞 편에서 본 투 포인터와도 함께 쓰입니다. 투 포인터는 정렬된 배열의 양 끝에 포인터(칸 번호를 가리키는 변수) 두 개를 두고 합에 따라 한쪽씩 안으로 좁혀 오는 방법입니다. 세 수를 더해 0 이 되는 조합을 모두 찾는 세 수의 합 문제가 대표적인데, 값 하나를 고정해 두고 나머지 두 수를 투 포인터로 양 끝에서 좁히면 전체가 O(n²) 으로 내려갑니다. 고정할 값을 n 번 고르고 고를 때마다 두 포인터가 만날 때까지 많아야 n 칸쯤 움직이므로 n × n 에 비례하는 시간이 듭니다.

아래 코드는 정렬한 값 6개 `[-4, -1, -1, 0, 1, 2]` 에서 `i` 로 값 하나를 고정하고 `L` 은 `i` 바로 다음 칸에서, `R` 은 마지막 칸에서 출발시킵니다. 값이 작은 것부터 놓여 있으므로 `L` 을 오른쪽으로 한 칸 밀면 합이 커지거나 그대로이고 `R` 을 왼쪽으로 한 칸 당기면 합이 작아지거나 그대로입니다. 그래서 합이 0 보다 작으면 `L` 을 밀고 0 보다 크면 `R` 을 당깁니다. 합이 0 이면 답에 넣고 두 포인터를 함께 안쪽으로 옮깁니다. 고정할 값이 바로 앞 값과 같으면 같은 조합이 다시 나오지 않도록 그 값은 건너뜁니다. 답을 찾은 뒤 옮긴 `L` 이 앞 칸과 같은 값이면 같은 까닭으로 앞 칸과 다른 값이 나올 때까지 더 밉니다.

```python
# 하는 일: 정렬한 값 6개에서 하나를 고정하고 나머지 둘을 양 끝에서 좁혀, 더해서 0 이 되는 세 수를 모두 찾는다.
ARR = [-4, -1, -1, 0, 1, 2]
ARR.sort()
답, n = [], len(ARR)
for i in range(n - 2):
    if i > 0 and ARR[i] == ARR[i-1]:
        print(f"i={i} 값 {ARR[i]:>2}  앞과 같아서 건너뜀")
        continue
    L, R = i + 1, n - 1
    while L < R:
        s = ARR[i] + ARR[L] + ARR[R]
        기호 = "=" if s == 0 else ("<" if s < 0 else ">")
        움직임 = "찾음" if s == 0 else ("L을 민다" if s < 0 else "R을 당긴다")
        print(f"i={i} 값 {ARR[i]:>2}  L={L}({ARR[L]:>2}) R={R}({ARR[R]:>2})  합 {s:>2} {기호} 0  {움직임}")
        if s == 0:
            답.append((ARR[i], ARR[L], ARR[R]))
            L += 1; R -= 1
            while L < R and ARR[L] == ARR[L-1]: L += 1
        elif s < 0: L += 1
        else:       R -= 1
print("\n답", 답)

# 출력:
# 뜻: i 로 하나를 고정하고 L, R 을 양 끝에서 좁힌다. i=2 는 앞 값과 같아 건너뛰어서 같은 조합이 두 번 나오지 않는다.
# i=0 값 -4  L=1(-1) R=5( 2)  합 -3 < 0  L을 민다
# i=0 값 -4  L=2(-1) R=5( 2)  합 -3 < 0  L을 민다
# i=0 값 -4  L=3( 0) R=5( 2)  합 -2 < 0  L을 민다
# i=0 값 -4  L=4( 1) R=5( 2)  합 -1 < 0  L을 민다
# i=1 값 -1  L=2(-1) R=5( 2)  합  0 = 0  찾음
# i=1 값 -1  L=3( 0) R=4( 1)  합  0 = 0  찾음
# i=2 값 -1  앞과 같아서 건너뜀
# i=3 값  0  L=4( 1) R=5( 2)  합  3 > 0  R을 당긴다
# 뜻: 합이 0 인 세 수는 두 조합이다.
#
# 답 [(-1, -1, 2), (-1, 0, 1)]
```

`i=0` 에서 -4 를 고정하면 합이 -3 → -3 → -2 → -1 로 끝까지 0 보다 작아 `L` 만 네 번 밀다가 두 포인터가 만나 끝납니다. `i=1` 에서 -1 을 고정하면 첫 합 (-1) + (-1) + 2 가 0 이라 `(-1, -1, 2)` 를 찾습니다. 두 포인터를 안쪽으로 한 칸씩 옮긴 다음의 합 (-1) + 0 + 1 도 0 이라 `(-1, 0, 1)` 이 두 번째 답으로 들어갑니다. `i=2` 의 -1 은 바로 앞 `i=1` 의 -1 과 같아서 건너뛰었습니다. `i=3` 에서 0 을 고정하면 0 + 1 + 2 = 3 으로 0 보다 커서 `R` 을 한 번 당기자 두 포인터가 만나 반복이 끝납니다. 그래서 합이 0 인 세 수는 `[(-1, -1, 2), (-1, 0, 1)]` 의 두 조합입니다.

정렬해 두면 중복 제거도 따로 손대지 않고 따라옵니다. 같은 값이 서로 붙어 있으므로 「앞과 같으면 건너뛴다」 한 줄이면 됩니다. 위 출력에서는 `i=2` 가 이 한 줄로 넘어가서 `(-1, 0, 1)` 이 답에 두 번 들어가지 않았습니다. **집합으로 중복을 거르려고 하면 조합을 튜플로 감싸야 하고 같은 세 수가 다른 순서로 담기지 않게 순서까지 맞춰야 해서 오히려 번거롭습니다.**

## 한눈 정리

| 상황 | 쓸 것 | 왜 |
|---|---|---|
| 값이 있는지 반복해서 묻는다 | 집합 | 값에서 자리를 계산해 한 번에 갑니다 |
| 값에 딸린 정보가 필요하다 | 딕셔너리 | 자리와 값을 같이 들고 있습니다 |
| 지금 값의 짝이 하나로 정해진다 | 딕셔너리 + 한 번 순회 | 짝을 전부 만들 필요가 없습니다 |
| 몇 번 나왔는지 센다 | `Counter` | `most_common` 까지 딸려 옵니다 |
| 키마다 여러 개를 모은다 | `defaultdict(list)` | 첫 등장을 따로 처리 안 해도 됩니다 |
| 두 목록을 비교한다 | 집합 연산 | 이중 반복문이 기호 하나가 됩니다 |
| 순서, 크기 비교가 필요하다 | 정렬 | 해시는 순서를 버립니다 |
| 기준이 두 개 이상이다 | 튜플 `key` | 한 번만 정렬하고 기준이 한눈에 보입니다 |
| 겹침, 중복을 다룬다 | 정렬 후 한 번 순회 | 같은 것끼리 붙어 있게 됩니다 |

## 헷갈리기 쉬운 점

- **딕셔너리가 언제나 O(1) 이지는 않습니다.** 해시값이 한 슬롯에 몰리면 넣고 찾는 시간이 O(n) 까지 떨어집니다. 파이썬 기본 자료형을 키로 쓰면 걱정할 일이 거의 없지만 `__hash__` 를 직접 짤 때는 사정이 다릅니다.
- **`3` 과 `3.0` 은 같은 키로 취급됩니다.** 나눗셈 결과를 키로 쓰면 정수로 넣은 키와 섞여 오류 없이 값이 덮어써집니다.
- **리스트는 딕셔너리의 키가 될 수 없습니다.** 값 여러 개를 하나의 키로 쓰려면 튜플로 감쌉니다.
- **`defaultdict` 는 없는 키를 읽기만 해도 그 키를 만듭니다.** 키가 있는지 확인할 때는 `in` 을 씁니다.
- **집합에는 순서가 없습니다.** 출력 순서가 채점 결과에 영향을 주는 문제라면 마지막에 `sorted` 를 한 번 붙여 순서를 정해 줍니다.
- **`reverse=True` 와 음수 부호는 같지 않습니다.** 기준이 두 개 이상이면 `reverse=True` 보다 숫자 기준에 음수 부호를 붙이는 방법이 헷갈릴 여지가 적습니다.
- **정렬이 원본 리스트를 바꾸기도 합니다.** `list.sort()` 는 원본을 그 자리에서 정렬해 바꾸고 `sorted()` 는 정렬한 새 리스트를 만들어 돌려주므로, 원본을 나중에 다시 써야 하면 `sorted` 를 씁니다.
