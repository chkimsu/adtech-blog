LLM 모델 고르기 카드 네 장

지훈 씨가 모델을 고르며 본 네 가지를 카드 네 장으로 봅니다. 상용 API 와 공개 가중치, 크기와 활성 파라미터, thinking 을 켠 답, 요청 한 건의 값입니다. 문제 20개와 단가는 설명용 가상 값이고, 맞힘과 토큰과 시간은 한 번 기록한 값입니다.

먹색 = 모델과 서버, 모델 계열 이름 파랑 = thinking 을 끈 답, 입력 토큰, 활성 파라미터 벽돌색 = thinking 을 켠 답, 출력 토큰 회색 = 문서에 없는 값 점선 상자 = 가상 값 (단가와 요청 크기)

LANDSCAPE

상용 API 세 계열과 공개 가중치 네 계열

쉽게 말하면 모델은 만든 회사의 서버로만 부르는 쪽과, 가중치를 받아 내 서버에서 돌리는 쪽으로 나뉩니다. 가중치를 받으면 요청이 회사 밖으로 나가지 않습니다.

같은 회사가 둘 다 내기도 합니다. Gemini 는 API 로 열고, Gemma 는 가중치를 공개했습니다.

SIZE

전체 파라미터, 활성 파라미터, 메모리, 컨텍스트 길이

쉽게 말하면 전체 크기는 메모리를, 활성 파라미터는 토큰 하나의 계산을 정합니다. 토큰마다 일부만 계산하는 MoE 모델도 메모리는 전체만큼 듭니다.

26B A4B 는 25.2B 중 3.8B 만 계산합니다. 그래도 4비트 메모리는 14.4GB 로 31B 의 17.5GB 와 가깝습니다.

THINKING

hard 10개의 맞힘, 출력 토큰, 시간

쉽게 말하면 thinking 을 켜면 모델이 답 앞에 풀이를 씁니다. 이 기록에서는 맞힘이 늘었고, 풀이도 출력 토큰이라 토큰과 시간이 크게 늘었습니다.

맞힘은 4개에서 10개, 출력 토큰은 83개에서 7,713개, 시간은 11.3초에서 493.4초가 되었습니다.

COST

요청 한 건과 하루 100만 요청의 값, 가상 단가

쉽게 말하면 값은 입력 토큰과 출력 토큰에 각자의 단가를 곱해 더한 것입니다. 출력 단가가 비싸서 출력 토큰이 값을 크게 움직입니다.

하루 100만 요청이면 작은 모델 720,000원, 큰 모델 7,800,000원입니다. 캐시를 쓴 큰 모델은 4,200,000원입니다.

현업에서는 이렇게 씁니다

  • 모델을 고를 때는 이름보다 네 칸을 먼저 봅니다. 어디서 도는지, 크기, 컨텍스트 길이, thinking 입니다.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 LLM 모델 고르기 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 바로 앞 이야기는 LLM 호출 한 번 편입니다.
