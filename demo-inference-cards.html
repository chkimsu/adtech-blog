추론 서버 카드 네 장

학습이 남긴 모델 파일이 요청 하나에 답하는 서버가 되기까지, 자리 하나가 카드 한 장입니다. 점이 흐르는 방향이 데이터가 가는 방향입니다. 이름과 숫자는 모델 운영 트랙의 설명용 가상 값입니다.

파랑 = 놓여 있는 것 (모델 파일, 임베딩 표, 설정) 벽돌색 = 지금 오는 것 (요청, 후보) 먹색 = 모델과 서버 회색 = 만드는 작업 (변환, 웜업, 추론) 점선 = 적어 둔 것 (설정, 준비 조건) 점 = 지금 가고 있는 데이터

MODEL FORMAT

학습 파일을 서빙 포맷으로

쉽게 말하면 학습이 남긴 파일은 그 학습 프레임워크와 파이썬 코드가 있어야 열립니다. ONNX 로 바꾸면 그래프와 가중치만 남아서, 서버는 작은 런타임 하나만 있으면 파일을 열어 답할 수 있습니다.

가중치 38MB 는 그대로입니다. 서버가 같이 실어야 하는 것이 프레임워크 1.2GB 와 코드에서 런타임 0.8GB 로 줄고, 적재는 9초에서 3초가 됩니다(가상 값).

SERVER STARTUP

서버가 뜨는 41초

쉽게 말하면 새 서버는 켜지자마자 답할 수 없습니다. 이미지가 켜지고, 모델 파일을 내려받아 올리고, 가짜 요청 200건으로 몸을 푼 뒤에야 준비 신호를 켭니다. 게이트웨이는 그 신호가 켜진 서버에만 요청을 보냅니다.

이미지 시작 12초, 내려받기 6초, 적재 3초, 웜업 20초로 41초입니다. 웜업 20초를 빼고 열면 첫 30초가 2.5배 느립니다.

ONE TENSOR

후보 800건을 한 번에

쉽게 말하면 요청 하나에 후보 800건이 실려 옵니다. 하나씩 800번 모델을 부르면 부를 때마다 고정 비용이 붙어 96ms 가 되고, 800줄을 한 덩어리로 한 번에 넣으면 3.0ms 입니다. 예산 8ms 안에 드는 것은 한 번에 넣는 쪽뿐입니다.

호출 한 번의 고정 비용은 0.116ms, 후보 한 건의 계산은 0.0036ms 입니다. 800번 부르면 고정 비용만 93ms 입니다.

TWO VERSIONS

두 버전을 동시에 싣는다

쉽게 말하면 운영 중인 v417 과 새 v418 을 한 서버에 같이 올려 두고, 어느 쪽이 답할지는 설정 한 줄로 정합니다. 바꾸는 것도 되돌리는 것도 그 한 줄이라 몇 초면 됩니다. 값은 임베딩 표가 하나 더 드는 27.7GB 입니다.

신경망 38MB 는 둘을 실어도 싸지만, 임베딩 서비스는 27.7GB 가 55.4GB 가 됩니다. 두 버전을 같이 두는 값이 여기서 듭니다.

현업에서는 이렇게 씁니다

  • 새 모델을 서버에 올린다는 말을 들으면 네 가지를 묻습니다. 어떤 포맷으로 싣나, 준비 신호는 무엇을 보고 켜나, 후보를 몇 건씩 한 번에 넣나, 옛 버전은 어디에 남아 있나.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 글로 이어 읽으려면 추론 서버 편에 이 카드들이 절마다 한 장씩 들어 있습니다. 이미지가 어떻게 만들어지는지는 Docker 와 CI 카드 네 장입니다.
