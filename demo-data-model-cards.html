데이터와 모델 카드 여덟 장

로그가 학습 데이터가 되고 모델이 후보를 고르는 자리 하나가 카드 한 장입니다. 점이 흐르는 방향이 데이터가 가는 방향이고, 점이 몰려서 지나가면 배치입니다. 숫자는 각 글의 가상 데이터 값이고 여기서 새로 만든 값은 없습니다.

파랑 = 놓여 있는 데이터 (로그, 표, 인덱스, 목록) 벽돌색 = 지금 오는 것 (요청, 이벤트, 클릭) 먹색 = 모델과 서버 회색 = 만드는 작업 (조인, 평균, 집계) 점선 = 적어 둔 것 (규칙, 계수) 점 = 지금 가고 있는 데이터

LOG JOIN

로그 셋이 학습 데이터가 되는 자리

쉽게 말하면 노출 로그, 클릭 로그, 전환 로그를 요청 번호로 맞춰 붙여야 「이 노출이 클릭됐나, 전환됐나」라는 정답이 생깁니다. 전환은 며칠 뒤에 오니 언제 붙이느냐가 정답의 정확도를 정합니다.

전환은 클릭 뒤 수 시간에서 수 일 뒤에 옵니다. 너무 일찍 조인하면 아직 안 온 전환이 전부 「안 샀다」가 됩니다. 기다리기와 먼저 쓰고 고치기 중 하나를 고르고, 언제까지의 로그로 만들었는지를 데이터에 적어 둡니다.

RANK ONE

자리를 모른 채 채점하는 문제

쉽게 말하면 광고를 어디에 놓을지 정하려면 점수가 필요한데, 점수를 매기려면 자리가 필요합니다. 그래서 후보 전부를 1번 자리에 놓은 셈 치고 한 번에 채점합니다. 순서는 맞지만 확률은 부풉니다.

학습 때 1번 자리 5%, 3번 자리 1.5% 를 배운 모델이 추론 때는 전부 1번 기준으로 예측합니다. 3번에 놓일 광고는 계수 0.40 을 곱해 내려 잡습니다.

FAN-OUT

처리 잡 다섯이 목적지 여섯으로

쉽게 말하면 처리 잡마다 목적지마다 보내는 코드를 두면 연결이 5 × 6 = 30개입니다. 가운데에 나눠 보내는 층을 하나 두면 잡은 한 곳에만 쓰고 연결이 5 + 6 = 11개가 됩니다.

목적지를 하나 더 붙일 때 층이 없으면 잡 5개를 고치고 층이 있으면 0개입니다. 목적지가 늘 것 같으면 층을 먼저 세웁니다.

FEATURE WINDOW

피처 창이 라벨 날과 겹치면

쉽게 말하면 「이 광고의 클릭률」 피처를 오늘 로그로 만들면 그 안에 오늘의 클릭 결과가 들어 있습니다. 모델은 정답을 보고 맞히는 셈이라 오프라인 점수만 오르고 실서빙에서는 떨어집니다.

같은 날 로그로 만든 피처 A 는 오프라인 AUC 0.894 에서 실서빙 0.779 로 떨어집니다. 과거 7일로 만든 C 는 0.777 에서 0.798 입니다. 창은 D-1 자정에서 자릅니다.

ATTENTION BY CANDIDATE

후보 광고에 따라 이력의 무게가 달라진다

쉽게 말하면 유저가 최근에 본 상품 5개가 있습니다. 러닝화 광고를 채점할 때는 운동 관련 이력에, 노트북 광고를 채점할 때는 노트북 이력에 무게가 실립니다. 같은 유저인데 광고마다 유저 표현이 달라집니다.

러닝화 광고에서는 운동 관련 3개가 가중치의 91.3% 를, 노트북 광고에서는 9.1% 를 가져갑니다. 평균으로 뭉개면 어느 광고든 60% 로 고정입니다.

EXACT VS ANN

전수 비교 대 근사 검색

쉽게 말하면 광고 100만 개와 유저 벡터를 하나하나 다 비교하면 128.8ms 로 예산을 넘습니다. 근사 검색은 가까울 법한 2% 만 훑어 3.4ms 에 끝냅니다. 대신 진짜 1위를 가끔 놓칩니다.

광고 벡터는 미리 계산해 인덱스에 두고, 서빙 때는 유저 타워만 돌려 검색합니다. 100만 개 전수 내적 128.8ms 대 근사 검색 3.4ms, 재현율 90~99% 입니다.

SEED CENTROID

씨앗 평균 하나에서 닮은 사람을 찾는다

쉽게 말하면 씨앗 유저의 벡터를 평균 내 중심점 하나를 만들고, 전체 유저 중 그 점에 가까운 순서로 줄을 세워 앞에서 자릅니다. 어디서 자르느냐가 확장 비율입니다.

유사도 0.87, 0.82, 0.78 순으로 세우고 임계값 아래는 뺍니다. 임계값을 높이면 소수만 남고 낮추면 넓어집니다. 씨앗이 이질적이면 평균이 빈 자리에 놓여 중심점을 여럿 둡니다.

REAL-TIME SEGMENT

이벤트가 초 안에 세그먼트가 되는 길

쉽게 말하면 검색, 장바구니, 구매 이벤트가 Kafka 로 들어오면 Flink 가 규칙 셋으로 세그먼트를 붙였다 떼고, 그 결과를 Redis 에 두어 pCTR 모델이 요청마다 읽습니다. 배치보다 훨씬 빠릅니다.

1시간에 검색 3회면 활성 검색자, 담고 10분 안 미구매면 장바구니 이탈, 구매하면 전환자입니다. 배치 세그먼트와 부딪히면 스트리밍이 이깁니다.

현업에서는 이렇게 씁니다

  • 오프라인 점수와 실서빙 점수가 다르면 이 여덟 자리 중 셋부터 봅니다. 피처 창이 라벨 날과 겹쳤나, 조인을 너무 일찍 돌렸나, 자리=1 로 채점한 확률을 보정 없이 썼나.
  • 카드를 누르면 위 해설 칸에 그 자리에서 헷갈리는 것 하나가 더 나옵니다.
  • 이어서 볼 것은 학습 데이터 카드 여섯 장과 서빙 카드 다섯 장입니다. 이 여덟 장은 그 두 판 사이의 자리를 채웁니다.
