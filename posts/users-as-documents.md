모델 팀 29주째 월요일, 서연 씨가 지훈 씨에게 검색어 목록 하나를 보냈습니다. 러닝화 광고를 검색창에 낼 때 사 오던 「러닝화」, 「런닝화」, 「러닝양말」 같은 말들입니다. 이 말을 검색한 사람에게 피드에서도 광고를 보이고 싶다고 했습니다.

지금 캠페인은 번호 317 로 사람을 고릅니다. 러닝 글을 3편 이상 읽었거나, 운동 앱을 5일 이상 켰거나, 러닝화를 한 번이라도 검색한 사람입니다. 선배는 회원마다 30일 동안 한 일을 글 한 편으로 적고, 서연 씨의 검색어로 그 글을 검색해 보라고 했습니다.

**광고의 검색어로 사람을 검색하면, 번호 317 이 고른 사람과 얼마나 같은 사람이 나올까요?**

회원 한 명의 행동을 이어 쓴 글을 유저 문서라고 부르고, 광고 쪽 낱말로 사람을 찾는 이 방향을 역방향 검색이라고 부릅니다. 보통의 검색은 사람이 낱말로 상품을 찾지만, 여기서는 광고가 낱말로 사람을 찾습니다. 하루 300만 원이 누구에게 먼저 갈지가 이 검색의 순위로 정해집니다.

> **한 줄 요약:** 회원 2,000명의 30일 행동을 회원마다 문서 한 편으로 적었습니다. 검색어는 그 말을, 행동은 「러닝글」 같은 낱말 하나를 횟수만큼 이었습니다. 서연 씨 러닝화 광고의 키워드를 전략 셋으로 나눠 BM25 로 검색하자 142명, 231명, 76명이 맞았습니다. 세 목록을 RRF 로 합친 322명에서 앞 200명을 잘랐습니다. 러닝화를 12번 검색한 회원 A 는 direct 목록에서 49위였습니다. 러닝화 하나만 맞은 회원 가운데 문서가 더 짧은 26명이 앞섰고, 회원 A 의 문서는 행동 낱말 때문에 평균의 두 배가 넘게 길었습니다. 회원 A 는 세 목록 가운데 direct 에만 들어 합친 순위가 171위였습니다. 캠핑만 한 회원 B 는 어느 목록에도 없었습니다. 검색 200명은 세그먼트 317 의 229명과 165명이 겹쳤고, 다음 30일 구매자 비율은 20.5% 와 20.1% 로 비슷했습니다. 세그먼트 317 의 회원 가운데 17명은 질의 낱말을 한 번도 검색하지 않아 검색이 찾지 못했습니다. 키워드 120개와 회원의 검색 기록, 회원의 문서는 이 트랙의 뒤 글 셋이 다시 씁니다.

> **골라 읽는 법** — 절이 7개입니다. 절마다 표나 코드나 카드가 있어 그것만 보고 넘어가도 됩니다.
>
> - 세그먼트와 키워드 검색이 사람을 고르는 기준 → 1절
> - 회원 한 명이 문서가 되는 코드와 문서 길이 → 2절
> - BM25 점수와 회원 A 의 순위 → 3절
> - RRF 로 합치고 앞 200명을 자르기 → 4절
> - 세그먼트 317 과의 겹침과 다음 30일 구매 → 5절
> - 키워드와 문서를 다시 쓰는 뒤 글 셋 → 6절
> - 담장 안과 열린 RTB 에서 달라지는 것 → 7절

이 글의 회원, 행동, 키워드, 구매는 모두 설명을 위해 만든 가상 데이터입니다. 회원 2,000명과 키워드 120개는 `scripts/gen-ads-data.py` 가 만들고, 첫 블록은 그 코드를 글자 그대로 옮겼습니다. 회원의 30일 행동은 [유저 프로파일 피처](post.html?id=user-profile-features) 편의 생성기 그대로라, 세그먼트 317 이 붙는 회원도 같은 229명입니다. 이 글은 LLM 을 부르지 않습니다. 문서를 검색할 수 있게 모아 둔 것을 색인이라고 부르고, Elasticsearch 에서는 인덱스라고 부릅니다. 이 글은 사람을 검색할 색인을 세우고, 뒤 글들은 같은 키워드와 회원으로 LLM 이 고른 키워드와 오디언스를 만듭니다. 카드 속 파랑은 세그먼트 317 쪽, 벽돌색은 광고 키워드로 검색한 쪽입니다. 회색은 질의에 맞지 않는 낱말과 목록 밖의 회원이고, 점선 상자는 회원 한 명의 문서 원문입니다.

## 1. 세그먼트는 규칙이고 검색은 낱말입니다

**세그먼트 317 은 행동 횟수에 문턱 셋을 둔 규칙이라, 회원마다 「든다」와 「안 든다」 둘뿐입니다. 키워드 검색은 광고의 낱말이 회원의 문서에 얼마나 들었는지로 점수를 매기고, 그 점수로 회원의 순위를 매깁니다.**

세그먼트 317 의 규칙은 13주째 [유저 프로파일 피처](post.html?id=user-profile-features) 편에서 보았습니다. 30일 동안 러닝 글을 3편 이상 읽었거나, 운동 앱을 5일 이상 켰거나, 검색어 「러닝화」를 1번 이상 검색했으면 붙습니다. 표본 2,000명 가운데 229명이 여기에 들고, 회원 1,400만 명으로 옮기면 약 160만 명입니다. 이 번호를 회원 프로필에 적는 일은 매일 새벽 배치가 합니다.

규칙의 답은 둘뿐입니다. 러닝 글을 3편 읽은 회원과 30편 읽은 회원이 똑같이 317 을 받고, 2편 읽은 회원은 받지 못합니다. 229명 안에서는 누가 러닝화를 더 살 것 같은지 순서가 없습니다. 캠페인이 바뀌면 누군가 새 규칙을 쓰고, 새 번호를 만들고, 배치를 다시 돌립니다.

서연 씨에게는 이미 낱말 목록이 있습니다. 검색창에 광고를 낼 때 사던 키워드입니다. 회원마다 30일 동안 한 일을 문서 한 편으로 적어 두면, 그 키워드로 문서를 검색할 수 있습니다. 검색은 문서마다 점수를 매기고 점수 순으로 회원을 정렬하니, 예산만큼 앞에서 잘라 쓰면 됩니다. 12주째 [Elasticsearch 하이브리드 검색](post.html?id=elasticsearch-hybrid-retrieval) 편에서는 사람이 쓴 질의로 상품 이름을 찾았습니다. 여기서는 광고의 키워드가 질의이고, 찾는 대상이 회원의 문서입니다.

둘이 보는 것도 다릅니다. 규칙은 행동 8종 가운데 셋의 횟수를 보고, 검색은 문서에 든 낱말을 봅니다. 문서에는 회원이 검색창에 쓴 검색어와, 「러닝글」처럼 행동을 낱말로 바꾼 것이 함께 들어갑니다. 질의는 광고 키워드라서, 질의와 맞을 수 있는 낱말은 검색어뿐입니다. 이 차이가 3절에서 회원 A 의 순위를 바꿉니다.

아래 표는 두 방식을 한 줄씩 놓은 것입니다. 문서가 실제로 어떻게 생겼는지는 2절에서, 앞에서 자르는 수는 4절에서 숫자로 봅니다.

| 무엇 | 세그먼트 317 | 키워드 검색 |
|---|---|---|
| 고르는 기준 | 행동 횟수의 문턱 셋. 러닝 글 3편, 운동 앱 5일, 검색어 러닝화 1번 가운데 하나 이상 | 광고 키워드가 회원의 문서에 든 횟수와 그 낱말이 얼마나 드문지 |
| 보는 것 | 행동 8종 가운데 셋의 30일 횟수 | 검색어와 행동 낱말을 이은 문서 한 편 |
| 답의 꼴 | 든다, 안 든다 | 점수와 순위 |
| 명단 크기를 정하는 것 | 규칙의 문턱 | 앞에서 자르는 수 |
| 새 캠페인 | 규칙을 새로 쓰고 배치를 돌린다 | 키워드 목록을 바꿔 다시 검색한다 |

## 2. 회원 한 명을 글 한 편으로 씁니다

**회원 A 의 30일은 검색어 러닝화 12번과 행동 낱말 다섯 가지를 이은 37낱말의 문서가 됩니다. 문서 2,000편의 길이는 평균 15.7낱말이라, 회원 A 의 문서는 평균의 두 배가 넘습니다.**

문서는 회원 한 명의 30일 기록을 낱말로 바꿔 공백으로 이은 글입니다. 검색 기록은 검색어를 검색한 횟수만큼 적습니다. 행동은 필드마다 낱말 하나를 정해 두고 횟수만큼 적습니다. 운동 앱을 켠 날은 「운동앱」, 러닝 글은 「러닝글」, 운동 용품 구매는 「운동용품구매」이고, 여행 글, 카페 글, 캠핑 글도 같은 꼴입니다. 검색어 러닝화와 캠핑 용품 검색은 검색 기록에 이미 검색어로 들어 있어서 낱말을 따로 두지 않습니다.

검색 기록은 생성기의 extend 가 붙입니다. 운동 앱이나 러닝 글 같은 행동 하나에, 같은 주제의 검색이 정해 둔 확률로 따라옵니다. 육아, 재테크, 게임, 뷰티처럼 행동 필드가 없는 주제는 검색하는 사람의 비율과 평균 횟수를 따로 정했습니다. 날씨, 뉴스 같은 말은 모두가 한 달에 몇 번씩 찾습니다. 키워드는 후보 가운데 하루 검색 수에 비례해 뽑습니다. 회원 A 와 B 에게는 정해 둔 행동에서 나온 검색만 적고 다른 검색을 더하지 않습니다.

```python
# 하는 일: 회원 2,000명에게 30일 검색 기록을 붙이고, 회원마다 행동을 낱말로 이어 쓴 문서 한 편을 만든다.
import random
from collections import Counter

# 1단계: 회원 2,000명의 30일 행동을 만든다
# 유저 프로파일 피처 편의 생성기를 글자 그대로 옮긴다. scripts/gen-ads-data.py 와 같고, 0번이 회원 A, 1번이 회원 B 다.
# 행동마다 사건의 경과일을 적는다. 0 은 오늘, 29 는 29일 전이고, 같은 날 두 번이면 두 번 적는다.
KEYS = ['search_running_shoes', 'sports_app_days', 'running_posts', 'sports_goods_buy',
        'travel_posts', 'cafe_posts', 'camping_posts', 'camping_search']
MEMBER_A = {
    'search_running_shoes': [0, 1, 2, 3, 5, 7, 9, 12, 15, 18, 22, 27],
    'sports_app_days': [0, 2, 4, 6, 9, 11, 13, 16],      # 켠 날을 적으니 같은 날이 두 번 없다
    'running_posts': [0, 0, 1, 1, 2, 3, 4, 5, 6],
    'sports_goods_buy': [5],
    'travel_posts': [17, 19, 22, 26],
    'cafe_posts': [1, 10, 20],
    'camping_posts': [],
    'camping_search': [],
}
MEMBER_B = {k: [] for k in KEYS}                         # 캠핑 둘 말고는 30일 동안 한 일이 없다
MEMBER_B['camping_posts'] = [0, 1, 3, 4, 6, 8, 10, 12, 14, 16, 18, 21, 23, 26, 28]
MEMBER_B['camping_search'] = [1, 3, 6, 10, 15, 21]


def counts(m):
    return {k: len(m[k]) for k in KEYS}


SEGMENT_317 = {'running_posts': 3, 'sports_app_days': 5, 'search_running_shoes': 1}   # 셋 중 하나


def in_segment_317(m):
    c = counts(m)
    return any(c[k] >= at_least for k, at_least in SEGMENT_317.items())


def runner_count(n):
    return n * 229 // 2000                               # 러닝 성향 11.45%, 2,000명이면 229명


# 행동마다 (그 행동을 하는 사람 비율, 하는 사람의 30일 평균 횟수). 앞은 러닝 성향, 뒤는 나머지다.
TENDENCY = {
    'search_running_shoes': ((0.17, 11.0), (0.00, 0.0)),
    'sports_app_days':      ((0.26, 9.0), (0.25, 2.5)),
    'running_posts':        ((0.46, 8.0), (0.25, 1.5)),
    'sports_goods_buy':     ((0.30, 1.5), (0.10, 1.2)),
    'travel_posts':         ((0.30, 4.0), (0.30, 4.0)),
    'cafe_posts':           ((0.40, 4.0), (0.40, 4.0)),
    'camping_posts':        ((0.08, 7.0), (0.12, 7.0)),
    'camping_search':       ((0.05, 5.0), (0.08, 5.0)),
}


def make_members(n, seed=7):
    """회원 n 명의 30일 행동. 0번은 회원 A, 1번은 회원 B 다."""
    rng = random.Random(seed)
    n_run = runner_count(n)
    runner = [True] * (n_run - 1) + [False] * (n - n_run - 1)   # A 는 러닝 성향, B 는 나머지
    rng.shuffle(runner)
    members = [dict(MEMBER_A), dict(MEMBER_B)]
    for is_runner in runner:
        while True:     # 러닝 성향은 조건이 하나라도 맞을 때까지, 나머지는 하나도 안 맞을 때까지 다시 뽑는다
            m = {}
            for k in KEYS:
                share, mean = TENDENCY[k][0 if is_runner else 1]
                does = rng.random() < share                     # 이 행동을 하는 사람인가
                days = range(30) if does else []                # 안 하는 사람은 날마다 뽑지 않는다
                m[k] = [d for d in days if rng.random() < mean / 30]
            if in_segment_317(m) == is_runner:
                break
        members.append(m)
    return members


behaviors = make_members(2000)
print(f'회원 {len(behaviors):,}명, 세그먼트 317 은 {sum(in_segment_317(m) for m in behaviors)}명')

# 2단계: 키워드 120개로 30일 검색 기록을 붙인다
# extend 는 행동 사건마다 그 주제의 검색을 확률로 붙이고, 다음 30일의 러닝화 구매(가상 정답)도 붙인다. 구매는 5절에서 쓴다.
# 키워드 120개. (id, 검색어, 주제, 전략, 하루 검색 수) 이고 값은 모두 가상이다.
# 주제는 관심사 라벨 8개와 health(민감 정보라 거를 말), noise(날씨, 뉴스처럼 상업 의도가 없는 말)다.
# 전략은 서연 씨 러닝화 광고를 기준으로 정한 가상 정답이고, 러닝 주제가 아닌 말은 none 이다. 차례는 로그에 쌓인 차례처럼 섞었다.
KEYWORDS = [
    ("k001", "러닝화", "running", "direct", 52000), ("k002", "감성카페", "cafe", "none", 3200), ("k003", "유모차", "parenting", "none", 8600),
    ("k004", "맞춤법검사기", "noise", "none", 12000), ("k005", "게임패드", "game", "none", 3100), ("k006", "조깅화", "running", "direct", 3300),
    ("k007", "버스시간표", "noise", "none", 3500), ("k008", "숙소추천", "travel", "none", 6100), ("k009", "무릎통증", "health", "problem_goal", 9600),
    ("k010", "발목보호대", "running", "problem_goal", 4200), ("k011", "런닝화", "running", "direct", 18000), ("k012", "발목염좌", "health", "problem_goal", 2600),
    ("k013", "러닝반바지", "running", "co_purchase", 2500), ("k014", "택배조회", "noise", "none", 24000), ("k015", "캐리어", "travel", "none", 7800),
    ("k016", "게임모니터", "game", "none", 3600), ("k017", "트레이닝화", "running", "category", 1700), ("k018", "디저트카페", "cafe", "none", 3700),
    ("k019", "트레일러닝화", "running", "category", 4500), ("k020", "런솔", "running", "brand", 3100), ("k021", "버너", "camping", "none", 4600),
    ("k022", "글램핑", "camping", "none", 16000), ("k023", "호텔예약", "travel", "none", 12000), ("k024", "향수", "beauty", "none", 16000),
    ("k025", "원두", "cafe", "none", 6900), ("k026", "텐트", "camping", "none", 22000), ("k027", "콘솔게임", "game", "none", 2000),

def make_pool():
    """뽑는 후보. 주제마다 (키워드 id, 하루 검색 수) 목록이고, camping_goods 는 캠핑 용품 검색의 후보다.

def buy_chance(m):
    """다음 30일에 러닝화를 살 확률(가상 정답). 러닝 성향이면 최근 7일의 러닝 사건 하나마다 0.05 씩 올라

    recent = sum(d < 7 for k in RUNNING for d in m[k])
    return min(0.8, 0.05 + 0.05 * recent)

    """회원마다 searches(키워드 id → 30일 검색 횟수)와 buys_next_30d(다음 30일 러닝화 구매, 0 이나 1)를 붙인 새 목록.
    표본을 만든 난수와 따로 뽑는다. 0번 회원 A 와 1번 회원 B 는 정해 둔 행동만 옮기고 검색을 더하지 않는다."""
    rng = random.Random(seed)

    def pick(topic):
        ids, daily = zip(*POOL[topic])
        return rng.choices(ids, weights=daily)[0]

                        found[pick(topic)] += 1
            for topic, pair in OTHER_TOPICS.items():

                if rng.random() < share:                             # 이 주제를 검색하는 사람인가
                    for _ in range(30):                              # 30일 동안 날마다 검색할지 뽑는다
                        if rng.random() < mean / 30:
                            found[pick(topic)] += 1
        searches = {kid: found[kid] for kid in TEXT if found[kid]}
        out.append(dict(m, searches=searches, buys_next_30d=int(rng.random() < buy_chance(m))))
    return out
```

## 3. 광고 키워드로 BM25 검색을 합니다

**질의는 전략마다 정답으로 정해 둔 키워드의 검색어입니다. BM25 는 질의 낱말마다 그 낱말이 얼마나 드문지와, 문서에 든 횟수와 문서 길이로 정한 값을 곱해 더합니다. 러닝화를 12번 검색한 회원 A 는 direct 목록 142명 가운데 49위였습니다.**

키워드 120개에는 서연 씨 러닝화 광고를 기준으로 붙여 둔 전략이 있습니다. 가상 정답이고, 러닝 주제의 키워드마다 전략 일곱 가운데 하나가 붙어 있습니다. 이 글은 그중 셋을 질의로 씁니다. direct 는 상품을 바로 부르는 말(러닝화, 마라톤화), category 는 상품이 속한 넓은 갈래(운동화, 워킹화)입니다. co_purchase 는 러닝화와 같이 사는 물건(러닝양말, 스포츠워치)입니다. 나머지 넷은 다음 주 키워드 확장 편이 다룹니다. 세 전략의 키워드는 모두 러닝 주제라서 건강 키워드는 질의에 들어가지 않습니다.

BM25 는 12주째 Elasticsearch 편 2절에서 본 그 점수입니다. 그 글은 질의 토큰이 많이 들수록, 드문 토큰일수록, 이름이 짧을수록 점수가 높다고만 적었습니다. 이 글은 그 셋을 식의 부분으로 나눠 봅니다. 질의 낱말 하나의 점수는 idf 와 TF 항의 곱입니다. TF 는 term frequency, 곧 낱말이 문서에 든 횟수입니다. 문서의 점수는 질의 낱말마다 그 곱을 더한 값입니다. idf 는 원어로 inverse document frequency 이고, 한국어로는 역문서 빈도라고 부릅니다. 그 낱말이 든 문서가 적을수록 커져서, 흔한 낱말보다 드문 낱말이 맞을 때 점수를 더 줍니다.

TF 항은 횟수를 「횟수 + k1 × 길이 정규화 값」으로 나눈 값입니다. 횟수가 늘수록 1 에 다가가지만 1 을 넘지 않아서, 12번째 검색은 첫 검색만큼 점수를 올리지 못합니다. Robertson 과 Zaragoza 는 이 성질을 포화(saturation)라고 불렀습니다. 길이 정규화(length normalization)는 문서 길이를 평균과 비교해 TF 항을 줄이는 부분입니다. 그 값은 문서가 평균 길이면 1 이고, 길수록 커집니다. k1 은 TF 항이 얼마나 빨리 1 에 다가가는지, b 는 길이를 얼마나 보는지 정합니다. Elasticsearch 의 문서는 기본 유사도가 BM25 이고 k1 의 기본값이 1.2, b 의 기본값이 0.75 라고 적었습니다. 이 글도 그 값을 씁니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 전략 셋의 키워드로 문서 2,000편을 BM25 로 검색하고, 세 목록을 RRF 로 합쳐 앞의 200명을 자른다.
import math

# 1단계: 전략 셋의 질의를 만든다
# 질의는 KEYWORDS 에서 그 전략이 정답인 키워드의 검색어다. 셋 다 러닝 주제라 건강 키워드는 들어가지 않는다.
QUERIES = {s: [text for kid, text, topic, strategy, daily in KEYWORDS if strategy == s]
           for s in ('direct', 'category', 'co_purchase')}
for s, q in QUERIES.items():
    print(f'{s} {len(q)}낱말: ' + ', '.join(q))

# 2단계: BM25 점수를 매기는 함수를 둔다
# 질의 낱말마다 idf × TF 항을 더한다. idf 는 드문 낱말일수록 크고, TF 항은 0 과 1 사이라 아무리 많이 나와도 1 을 넘지 않는다.
# TF 항의 분모에 길이 정규화 값이 들어가서 평균보다 긴 문서는 TF 항이 줄어든다. k1 1.2 와 b 0.75 는 Elasticsearch 의 기본값이다.
def bm25_scores(query_terms, docs, k1=1.2, b=0.75):
    """문서마다 BM25 점수. docs 는 문서마다 낱말 목록이고, 질의 낱말이 하나도 없는 문서는 0점이다."""
    n = len(docs)
    avgdl = sum(len(d) for d in docs) / n                         # 문서 길이의 평균
    tf = [Counter(d) for d in docs]
    scores = [0.0] * n
    for term in query_terms:
        df = sum(1 for c in tf if term in c)                      # 그 낱말이 든 문서 수
        if df == 0:
            continue
        idf = math.log(1 + (n - df + 0.5) / (df + 0.5))           # 드문 낱말일수록 크다. 0 아래로 내려가지 않는다
        for i, c in enumerate(tf):
            if term in c:
                norm = 1 - b + b * len(docs[i]) / avgdl           # 평균 길이면 1, 더 길면 1 보다 크다
                scores[i] += idf * c[term] / (c[term] + k1 * norm)
    return scores


def ranked(scores):
    """점수가 0 보다 큰 회원 번호를 점수 순으로 정렬한다. 점수가 같으면 번호가 작은 회원이 앞이다."""
    return sorted((i for i, s in enumerate(scores) if s > 0), key=lambda i: (-scores[i], i))


df = {t: sum(t in d for d in docs) for t in QUERIES['direct']}
cells = [f'{t} {df[t]}편 {math.log(1 + (len(docs) - df[t] + 0.5) / (df[t] + 0.5)):.2f}' for t in QUERIES['direct']]
print('direct 낱말이 든 문서 수와 idf: ' + ', '.join(cells[:4]))
print('  ' + ', '.join(cells[4:]))

# 3단계: 목록마다 맞은 회원을 점수 순으로 정렬한다
# 질의 낱말이 하나라도 든 문서만 목록에 든다. 상위 5명은 점수, 문서 길이, 문서에 든 질의 낱말과 그 횟수를 찍는다.
scores = {s: bm25_scores(q, docs) for s, q in QUERIES.items()}
lists = {s: ranked(scores[s]) for s in QUERIES}
for s, q in QUERIES.items():
    print(f'{s}: 맞은 회원 {len(lists[s])}명')
    for r, i in enumerate(lists[s][:5], 1):
        c = Counter(docs[i])
        print(f'  {r}위 회원 {i:>4}  {scores[s][i]:.2f}점  문서 {len(docs[i]):>2}낱말  ' + ', '.join(f'{t} {c[t]}' for t in q if c[t]))

# 4단계: 회원 A 의 direct 점수를 나눠 본다
# 회원 A 가 검색한 direct 낱말은 러닝화 하나다. 앞선 회원을 맞은 낱말 수로 나누고, b 를 0 으로 두어 길이를 뺀 점수도 센다.
avgdl = sum(len(d) for d in docs) / len(docs)
rank_a = lists['direct'].index(0) + 1
print(f'회원 A: 러닝화 {Counter(docs[0])["러닝화"]}번, 문서 {len(docs[0])}낱말(평균 {avgdl:.1f}낱말), '
      f'{scores["direct"][0]:.2f}점, {len(lists["direct"])}명 중 {rank_a}위')
flat = bm25_scores(QUERIES['direct'], docs, b=0)
print(f'  b 를 0 으로 두어 길이를 보지 않으면 {flat[0]:.2f}점, {ranked(flat).index(0) + 1}위')


def matched(i, q):
    return [t for t in q if t in docs[i]]


above = lists['direct'][:rank_a - 1]
alone = [i for i in above if matched(i, QUERIES['direct']) == ['러닝화']]
many = [i for i in above if len(matched(i, QUERIES['direct'])) > 1]
print(f'  앞선 {len(above)}명: direct 낱말 둘 이상 {len(many)}명, 러닝화 하나 {len(alone)}명, '
      f'다른 낱말 하나 {len(above) - len(many) - len(alone)}명')
print(f'  러닝화 하나로 앞선 {len(alone)}명 중 문서가 회원 A 보다 짧은 회원 {sum(len(docs[i]) < len(docs[0]) for i in alone)}명')
fewest = min(alone, key=lambda i: (Counter(docs[i])['러닝화'], i))
print(f'  그중 러닝화를 가장 적게 검색한 회원 {fewest}: {Counter(docs[fewest])["러닝화"]}번, '
      f'문서 {len(docs[fewest])}낱말, {scores["direct"][fewest]:.2f}점')
print(f'회원 A 의 문서에 든 category, co_purchase 낱말 {sum(t in docs[0] for t in QUERIES["category"] + QUERIES["co_purchase"])}개')

# 5단계: 세 목록을 RRF 로 합치고 앞의 200명을 자른다
# 회원마다 목록별로 1 / (60 + 순위) 를 더하고, 목록에 없으면 0 을 더한다. 점수가 같으면 회원 번호가 작은 쪽이 앞이다.
# 200명은 표본 2,000명의 10% 다. Lookalike 6001 이 회원 1,400만 명에서 가져간 140만 명과 같은 몫이다.
def rrf(ranked_lists, k=60):
    """순위 목록 여러 개를 합쳐 회원 번호를 RRF 점수 순으로 돌려준다."""
    total = {}
    for one in ranked_lists:
        for rank, i in enumerate(one, 1):
            total[i] = total.get(i, 0) + 1 / (k + rank)
    return sorted(total, key=lambda i: (-total[i], i))


merged = rrf([lists[s] for s in QUERIES])
picked = merged[:200]
place = {s: {i: r for r, i in enumerate(lists[s], 1)} for s in QUERIES}


def rrf_score(i, k=60):
    return sum(1 / (k + place[s][i]) for s in QUERIES if i in place[s])


def n_lists(i):
    return sum(i in place[s] for s in QUERIES)


print(f'합친 회원 {len(merged)}명. 앞 5명:')
for r, i in enumerate(merged[:5], 1):
    print(f'  {r}위 회원 {i:>4}  {rrf_score(i):.4f}  ' + ', '.join(f'{s} {place[s][i]}위' for s in QUERIES if i in place[s]))
inside = Counter(n_lists(i) for i in picked)
outside = Counter(n_lists(i) for i in merged[200:])
print(f'200명 안: 목록 셋에 든 회원 {inside[3]}명, 둘 {inside[2]}명, 하나 {inside[1]}명')
print(f'200명 밖: 목록 셋에 든 회원 {outside[3]}명, 둘 {outside[2]}명, 하나 {outside[1]}명')
singles = [next(place[s][i] for s in QUERIES if i in place[s]) for i in picked if n_lists(i) == 1]
print(f'  목록 하나뿐인 회원은 그 목록의 {max(singles)}위까지 200명 안에 들었다')
print(f'회원 A: direct {place["direct"][0]}위 하나라 1 / (60 + {place["direct"][0]}) = {rrf_score(0):.4f}, '
      f'합친 순위 {merged.index(0) + 1}위')
for i in merged:
    if i != 0 and rrf_score(i) == rrf_score(0):
        where = ', '.join(f'{s} {place[s][i]}위' for s in QUERIES if i in place[s])
        print(f'  점수가 같은 회원 {i}({where})은 번호가 커서 {merged.index(i) + 1}위')
print(f'회원 B: 세 목록에 든 수 {n_lists(1)}, 합친 {len(merged)}명에 ' + ('있음' if 1 in merged else '없음'))

# direct 7낱말: 러닝화, 조깅화, 런닝화, 런닝슈즈, 러닝슈즈, 달리기신발, 마라톤화
```

2단계가 찍은 idf 는 문서 63편에 든 러닝화가 3.45, 3편에만 든 달리기신발이 6.35 입니다. 목록에는 질의 낱말이 하나라도 든 문서만 들어서, direct 142명, category 231명, co_purchase 76명이 맞았습니다. 세 목록의 1위는 모두 질의 낱말을 둘 이상 가졌습니다. direct 1위 회원은 러닝화 12번에 조깅화와 런닝슈즈를 한 번씩 더 검색해 5.95점입니다. TF 항이 1 을 넘지 않으니, 이미 여러 번 검색한 낱말을 몇 번 더 검색하는 것보다 다른 낱말 하나가 점수를 크게 올립니다.

회원 A 는 러닝화 12번에 문서가 37낱말이라 2.87점, 142명 가운데 49위입니다. 앞선 48명 가운데 19명은 direct 낱말을 둘 이상 검색했습니다. 28명은 회원 A 처럼 러닝화 하나만 맞았는데, 그중 26명은 문서가 회원 A 보다 짧습니다. 러닝화를 7번만 검색한 회원 201 도 문서가 19낱말이라 2.88점으로 회원 A 를 앞섰습니다. b 를 0 으로 두어 길이를 보지 않으면 회원 A 는 3.14점, 40위가 됩니다.

회원 A 의 문서를 길게 만든 것은 러닝글 9번, 운동앱 8번, 여행글 4번 같은 행동 낱말입니다. 이 낱말은 어떤 키워드 질의와도 맞지 않아서 점수는 더하지 않고 길이만 늘립니다. 러닝 글과 운동 앱은 회원 A 를 세그먼트 317 에 넣은 행동인데, 키워드 검색에서는 순위를 낮췄습니다. 회원 A 의 문서에는 category 와 co_purchase 의 낱말이 하나도 없어서 그 두 목록에는 들지 않았습니다.

## 4. 전략별 목록을 RRF 로 합치고 200명에서 자릅니다

**RRF 는 목록마다 1 ÷ (60 + 순위) 를 더해 세 목록을 하나로 합칩니다. 합친 322명에서 앞 200명을 자르면 목록 둘 이상에 든 회원은 모두 들고, 목록 하나뿐인 회원은 그 목록의 75위까지 듭니다. 회원 A 는 171위로 200명 안에 있고, 회원 B 는 어느 목록에도 없습니다.**

세 목록을 BM25 점수 그대로 합칠 수는 없습니다. 질의마다 낱말 수와 idf 가 달라서 direct 1위는 5.95점, co_purchase 1위는 4.67점입니다. 두 점수의 크기를 비교할 근거가 없습니다. Elasticsearch 편 4절의 RRF 는 이럴 때 점수를 버리고 순위만 씁니다. 그 글의 rrf 는 순위 두 개를 받아 더했고, 이 글의 rrf 는 순위 목록 여러 개를 받아 회원 번호를 점수 순으로 돌려줍니다. 목록에 없는 회원은 그 목록에서 0 을 받습니다.

합친 1위는 direct 에서 맨 끝인 142위였던 회원입니다. category 4위, co_purchase 10위로 세 목록에 모두 들어 0.0349 를 받았습니다. 한 목록에서 1위여도 1 ÷ 61 하나만 받으니, 여러 목록에 고루 든 회원이 앞섭니다. 합친 순위 5위 안의 회원은 모두 목록 둘 이상에 들었습니다.

200명은 표본 2,000명의 10% 입니다. 15주째 [Lookalike 계산](post.html?id=lookalike-computation) 편의 6001 이 회원 1,400만 명에서 140만 명을 가져간 몫과 같습니다. 아래 표는 3절 코드의 5단계가 찍은 값으로, 합친 322명을 든 목록 수와 앞 200명 안팎으로 나눈 것입니다.

| 든 목록 수 | 앞 200명 | 200명 밖 |
|---|---|---|
| 셋 | 23명 | 0명 |
| 둘 | 81명 | 0명 |
| 하나 | 96명 | 122명 |

목록 둘 이상에 든 회원은 모두 200명 안에 들었습니다. 남은 자리는 목록 하나뿐인 회원이 그 목록의 순위대로 채웠고, 그 목록의 75위까지 들었습니다. 200명 밖에 남은 122명은 모두 목록 하나에만 든 회원입니다. 이 표본에서는 여러 전략의 낱말을 함께 검색한 회원이 모두 자르는 선 안쪽에 있습니다.

회원 A 는 direct 49위 하나라 1 ÷ (60 + 49) = 0.0092 를 받고, 합친 순위는 171위입니다. co_purchase 49위 하나인 회원 126 도 점수가 같습니다. 이 글의 rrf 는 점수가 같으면 회원 번호가 작은 쪽을 앞에 두어, 회원 A 가 171위, 회원 126 이 172위가 됩니다. 자르는 선에 동점이 걸리면 이 규칙이 누가 들지를 정하므로, 규칙을 코드에 적어 둡니다.

회원 B 는 세 목록 어디에도 없어서 합친 322명에도 없습니다. 회원 B 의 문서는 캠핑글과 캠핑 용품 검색어뿐이라 러닝화 광고의 질의 낱말이 하나도 없습니다. 러닝화 광고가 캠핑만 한 사람을 찾지 않은 것은 맞는 결과입니다. 문제는 반대쪽, 러닝 글을 읽고도 질의 낱말을 검색하지 않은 회원입니다. 그 회원은 5절에서 셉니다.

## 5. 세그먼트 317 과 나란히 봅니다

**검색 200명과 세그먼트 317 의 229명은 165명이 겹칩니다. 다음 30일 러닝화 구매자 비율은 검색 20.5%, 세그먼트 20.1% 로 비슷했고, 겹친 165명이 24.2% 로 가장 높았습니다.**

다음 30일 구매는 extend 가 붙인 가상 정답입니다. 세그먼트 317 에 드는 러닝 성향 회원은 살 확률이 0.05 에서 시작합니다. 최근 7일의 러닝 사건 하나마다 0.05 씩 올라 0.8 에서 멈춥니다. 나머지 회원은 0.01 입니다. 러닝 사건은 러닝화 검색, 운동 앱, 러닝 글, 운동 용품 구매 넷입니다. 아래 코드는 두 명단의 크기와 겹침, 구매자를 셉니다.

```python
# (앞 블록에 이어서 돌린다.)
# 하는 일: 세그먼트 317 의 229명과 검색으로 자른 200명을 나란히 놓고, 겹치는 수와 다음 30일 러닝화 구매자를 센다.

# 1단계: 두 명단의 크기와 구매자를 센다
# 세그먼트 317 은 규칙 셋 가운데 하나라도 맞는 회원이고, 검색 명단은 앞 블록에서 자른 200명이다.
# 구매는 extend 가 붙인 가상 정답이다. 표본 한 명은 회원 7,000명이라 1,400만 명으로 옮길 때 7,000을 곱한다.
segment = {i for i, m in enumerate(members) if in_segment_317(m)}
search = set(picked)
SCALE = 14000000 // len(members)


def buyers(ids):
    return sum(members[i]['buys_next_30d'] for i in ids)


for name, ids in (('세그먼트 317', segment), ('검색 200명', search)):
    print(f'{name}: {len(ids)}명, 1,400만 명으로 옮기면 {len(ids) * SCALE:,}명, '
          f'다음 30일 구매자 {buyers(ids)}명 ({buyers(ids) / len(ids):.1%})')
print(f'겹치는 회원 {len(segment & search)}명. 표본 전체의 구매자 {buyers(range(len(members)))}명')

# 2단계: 겹침의 안과 밖을 나눠 본다
# 세그먼트에만 있는 회원 가운데 세 목록 어디에도 없는 회원은 질의 낱말을 한 번도 검색하지 않은 사람이다.
for name, ids in (('겹친 회원', segment & search), ('세그먼트에만', segment - search), ('검색에만', search - segment)):
    print(f'{name} {len(ids)}명: 구매자 {buyers(ids)}명 ({buyers(ids) / len(ids):.1%})')
silent = [i for i in segment if i not in merged]
print(f'  세그먼트에만 있는 회원 중 세 목록 어디에도 없는 회원 {len(silent)}명, 구매자 {buyers(silent)}명')
only_search = search - segment
print(f'  검색에만 있는 {len(only_search)}명이 든 목록 수: 하나 {sum(n_lists(i) == 1 for i in only_search)}명, '
      f'둘 이상 {sum(n_lists(i) > 1 for i in only_search)}명')

# 3단계: 자르는 수를 바꿔 본다
# 같은 합친 순위에서 앞의 몇 명을 가져가느냐만 바꾼다. 마지막 줄은 합친 회원 전부다.
for cut in (100, 200, len(merged)):
    ids = set(merged[:cut])
    print(f'앞 {cut}명: 세그먼트 317 과 겹침 {len(ids & segment)}명, 구매자 {buyers(ids)}명 ({buyers(ids) / cut:.1%})')

# 출력:
# 1단계 뜻: 두 명단은 165명이 겹치고, 다음 30일 구매자 비율은 검색 20.5%, 세그먼트 20.1% 로 비슷하다.
# 세그먼트 317: 229명, 1,400만 명으로 옮기면 1,603,000명, 다음 30일 구매자 46명 (20.1%)
# 검색 200명: 200명, 1,400만 명으로 옮기면 1,400,000명, 다음 30일 구매자 41명 (20.5%)
# 겹치는 회원 165명. 표본 전체의 구매자 63명

# 3단계 뜻: 적게 자를수록 구매자 비율이 높고, 많이 자를수록 구매자 수가 늘어난다.
```

## 6. 이 글의 키워드와 문서는 뒤 글 세 편이 다시 씁니다

30주째 키워드 확장 편은 키워드 120개와 거기 붙은 정답 전략을 가져갑니다. 이 글은 그 정답 가운데 전략 셋의 키워드를 질의로 썼습니다. 그 글에서는 LLM 이 광고주의 상품 설명을 읽고, 키워드 120개 가운데에서 전략 일곱의 키워드를 고릅니다. 고른 키워드는 정답 전략과 비교해 채점합니다.

31주째 관심사 사전 편은 같은 키워드 120개와 회원의 검색 기록에서 시작합니다. 건강 키워드와 날씨, 뉴스 같은 말을 거르고, 남은 키워드를 묶어 이름 붙은 오디언스로 만듭니다. 오디언스마다 회원이 너무 적으면 쓰지 않도록 최소 크기도 정합니다.

34주째 유저 임베딩 편은 회원 2,000명과 그 문서를 가져가, 회원을 낱말 대신 숫자 벡터로 적습니다. 그 벡터는 날마다 미리 계산해, 모델이 읽을 값을 모아 두는 피처 스토어에 둡니다. 광고 랭커가 클릭 확률 pCTR 을 낼 때 그 값을 읽습니다. BM25 는 질의와 글자가 같은 낱말만 찾지만, 벡터로 적으면 글자가 달라도 가까운 회원을 찾을 수 있습니다. 벡터 검색이 무엇인지는 23주째 [임베딩과 벡터 검색](post.html?id=embeddings-vector-search) 편에 있습니다.

이 글의 검색이 찾지 못한 세그먼트 회원 17명에게 닿으려면, 질의 쪽이나 문서 쪽 가운데 하나를 바꿔야 합니다. 광고 쪽 낱말을 넓히는 일은 키워드 확장 편이, 회원을 낱말 대신 벡터로 적는 일은 유저 임베딩 편이 다룹니다. 아래 표는 세 글이 이 글에서 가져가는 것과 그 글이 하는 일을 한 줄씩 적은 것입니다.

| 뒤 글 | 이 글에서 가져가는 것 | 그 글이 하는 일 |
|---|---|---|
| 30주째 키워드 확장 전략 | 키워드 120개와 정답 전략 | LLM 이 상품 설명을 읽고 사전에서 전략 일곱의 키워드를 고른다 |
| 31주째 관심사 사전 만들기 | 키워드 120개와 회원 2,000명의 검색 기록 | 키워드를 걸러 묶어 이름 붙은 오디언스를 만들고 최소 크기를 정한다 |
| 34주째 LLM 유저 임베딩을 pCTR 피처로 | 회원 2,000명과 문서 | 회원을 벡터로 적어 피처 스토어에 두고 랭커가 읽는 자리를 본다 |

## 7. 사람을 문서로 적을 기록이 무대마다 다릅니다

**문서를 쓰고 키워드로 검색하는 셈은 두 무대가 같습니다. 다른 것은 회원의 검색어와 행동을 누가 같은 번호로 갖고 있느냐입니다. 담장 안은 검색창과 피드를 한 회사가 다 갖고, 열린 RTB 의 DSP 는 자기가 받은 입찰 요청만 압니다.**

1~6절의 셈은 두 무대가 같습니다. 담장 안과 열린 RTB 의 뜻은 18주째 [자연어 오디언스](post.html?id=natural-language-audience) 편 8절에서 풀었습니다.

### 담장 안에서는 검색어와 행동이 한 회원 번호에 모입니다 [무대: 닫힌 생태계]

담장 안의 플랫폼은 검색창, 피드, 앱을 함께 운영해서, 회원이 쓴 검색어와 읽은 글이 같은 회원 번호로 로그에 쌓입니다. 그래서 이 글처럼 회원마다 문서를 쓰고 매일 밤 색인을 새로 만들 수 있습니다. 광고주는 문서를 보지 않고 키워드만 건넵니다. 검색이 고른 명단은 Lookalike 6001 처럼 번호 하나가 되어 회원 프로필에 적힙니다.

검색어에는 민감한 말도 섞입니다. 이 글의 키워드 120개에도 건강 키워드가 있고, 그 검색은 회원의 문서에 남습니다. 이 글은 건강 키워드를 질의에 넣지 않았지만, 문서에서는 빼지 않았습니다. 문서에서 무엇을 뺄지와 어떤 키워드를 질의로 받지 않을지는 플랫폼의 광고 정책과 함께 정합니다. 걸러 낼 기준은 31주째 관심사 사전 편이 다룹니다.

### 열린 RTB 에서는 DSP 가 받은 입찰 요청으로만 문서를 씁니다 [무대: 열린 RTB]

열린 RTB 에서 광고를 사는 쪽의 DSP 는 사람의 검색창을 보지 못합니다. 입찰 요청에는 사용자의 검색어가 거의 없고, 지면의 주소, 카테고리, 앱 이름 같은 맥락이 옵니다. 그래서 DSP 가 쿠키나 기기의 광고 ID 마다 문서를 쓴다면, 낱말은 검색어가 아니라 그 사람이 본 지면의 카테고리와 앱 이름이 됩니다.

쿠키가 지워지거나 광고 ID 가 바뀌면 그 사람의 문서도 처음부터 다시 쌓입니다. 질의도 광고주의 키워드를 그대로 쓰기보다, 지면 카테고리에 맞춘 말로 바꿔야 맞는 낱말이 생깁니다. 그래서 열린 RTB 에서는 광고 키워드를 사람의 기록보다, 입찰 요청이 가리키는 지면의 글과 맞춰 보는 편이 쉽습니다. 지면의 글로 광고를 고르는 방법은 17주째 [컨텍스추얼 타겟팅](post.html?id=contextual-targeting) 편에서 보았습니다.

아래 표는 가상 데이터가 아니라 두 무대의 설계 차이를 적은 것입니다.

| 무엇 | 담장 안 | 열린 RTB |
|---|---|---|
| 문서의 낱말 | 회원이 쓴 검색어, 읽은 글, 켠 앱 | DSP 가 받은 입찰 요청의 지면 카테고리와 앱 이름 |
| 사람을 알아보는 값 | 로그인한 회원 번호 | 쿠키나 기기의 광고 ID |
| 질의 | 광고주의 키워드 | 지면 카테고리에 맞춘 말 |
| 검색이 고른 명단이 가는 곳 | 회원 프로필에 적는 세그먼트 번호 | DSP 의 오디언스 목록 |

## 헷갈리기 쉬운 점

- **문서는 사람이 쓴 글이 아니라 행동을 이은 낱말입니다.** 차례와 문법이 없고, 검색은 낱말이 든 횟수와 문서 길이만 봅니다. 「러닝글」 같은 행동 낱말은 키워드 질의와 맞지 않아 점수를 더하지 않고 길이만 늘립니다. 회원 A 가 러닝화를 12번 검색하고도 direct 49위였던 까닭이 여기 있습니다.

- **BM25 점수는 같은 질의 안에서만 비교합니다.** direct 1위의 5.95점과 co_purchase 1위의 4.67점은 질의의 낱말 수와 idf 가 달라 크기를 비교할 수 없습니다. 같은 질의라도 문서가 바뀌면 평균 길이와 idf 가 바뀌어서, 어제 색인과 오늘 색인의 점수도 비교하지 않습니다. 그래서 세 목록은 점수 대신 순위로 합쳤습니다.

- **자르는 수는 예산과 도달로 정합니다.** 이 글의 200명은 Lookalike 6001 과 같은 10% 로 맞춘 값입니다. 앞 100명은 구매자 비율이 23.0% 로 높지만 구매자는 23명이고, 합친 322명 전부는 47명이지만 14.6% 입니다. 하루 300만 원으로 몇 명에게 몇 번 보일 수 있는지가 먼저이고, 비율과 구매자 수는 그다음에 봅니다.

## 더 깊이 보기

:::deep BM25 식과 이 글이 고른 꼴
이 글의 bm25_scores 가 쓰는 식입니다. 질의 Q 의 낱말 t 마다 더하고, f(t, D) 는 문서 D 에 t 가 든 횟수, |D| 는 문서의 낱말 수입니다.

$$\mathrm{score}(D, Q) = \sum_{t \in Q} \mathrm{idf}(t) \cdot \frac{f(t, D)}{f(t, D) + k_1 \left(1 - b + b \cdot \frac{|D|}{\mathrm{avgdl}}\right)}$$

$$\mathrm{idf}(t) = \ln\left(1 + \frac{N - n(t) + 0.5}{n(t) + 0.5}\right)$$

N 은 문서 수 2,000 이고, n(t) 는 t 가 든 문서 수, avgdl 은 문서 길이의 평균 15.7 입니다. 회원 A 의 direct 점수에 넣으면 아래와 같고, 3.45 는 러닝화의 idf 입니다.

$$3.45 \times \frac{12}{12 + 1.2 \times (0.25 + 0.75 \times 37 / 15.7)} = 2.87$$

Robertson 과 Zaragoza 의 2009년 정리는 TF 항을 이 꼴로 적었습니다. 분자에 (k1 + 1) 을 곱하는 꼴도 흔하다고 덧붙였습니다. 모든 낱말에 같은 수를 곱하는 것이라 순위는 바뀌지 않습니다. 그 정리의 idf 는 log 안에 1 이 없는 log((N − n + 0.5) ÷ (n + 0.5)) 입니다. 이 꼴은 낱말이 문서의 절반 넘게 들면 0 아래로 내려갑니다. Elasticsearch 가 쓰는 검색 라이브러리 Lucene 의 문서는 log 안에 1 을 더한 꼴을 적었고, 이 글도 그 꼴을 씁니다.

b 는 1 이면 길이로 횟수를 완전히 나누고, 0 이면 길이를 보지 않습니다. 같은 정리는 여러 실험에서 b 는 0.5~0.8, k1 은 1.2~2 사이가 대체로 괜찮았다고 적었습니다. 회원 A 의 문서는 평균의 두 배가 넘게 길어서, b 를 0 으로 두면 49위에서 40위로 올라갑니다.
:::

:::deep RRF 식과 동점을 정하는 규칙
RRF 의 식은 Cormack, Clarke, Büttcher 의 2009년 논문에 있습니다. R 은 합칠 순위 목록의 모음이고, r(d) 는 목록 r 에서 회원 d 의 순위입니다.

$$\mathrm{RRF}(d) = \sum_{r \in R} \frac{1}{k + r(d)}$$

논문은 k = 60 을 시험 삼아 돌린 실험에서 정했고, 그 뒤 검증에서는 바꾸지 않았다고 적었습니다. 그 실험에서 60 이 최적에 가까웠지만, 값을 고르는 일이 크게 중요하지는 않았다고도 적었습니다. 논문의 목록은 문서 전부의 순위인데, 이 글의 목록은 질의 낱말이 든 회원만 담습니다. 그래서 목록에 없는 회원은 그 목록에서 0 을 받습니다.

이 글에서 합친 순위가 정해지는 차례는 셋입니다. 목록마다 1 ÷ (60 + 순위) 를 구하고, direct, category, co_purchase 차례로 더합니다. 그다음 점수가 큰 순서로 정렬합니다. 점수가 같으면 회원 번호가 작은 쪽이 앞입니다. 회원 A 와 회원 126 은 둘 다 1 ÷ 109 를 받아 이 규칙으로 171위와 172위가 되었습니다. 같은 순위를 다른 프로그램으로 다시 계산할 때도 더하는 차례와 동점 규칙을 같게 두어야 같은 순위가 나옵니다.
:::
